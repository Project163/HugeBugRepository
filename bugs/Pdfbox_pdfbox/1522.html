Title

PDPage.getAnnotations() modifies the PDF

Description
I stumbled across this bug while using PDFDebugger. 

 PDPage.getAnnotations() writes to the Page's COSDictionary, adding a new Annots entry if it is missing. 

 This violates one of the rules which we introduced for 2.0, that reading from a PDF file should not result in the file's COS model being modified.
Discussion
- I fixed this in  [URL]
- Note that this isn't a breaking change from an API point of view, but semantically it is. I think we're ok to ship this in 2.1 but I would not want to ship it in 2.0.x. 

 I've used an unmodifiable list to make sure that anyone trying to modify the returned list in the empty-case will get an exception rather than a silent failure. 

 I wish we'd caught this in 2.0 but I think this change is better late than never.
