Title

3.x: __debugInfo() should not cause any fatal errors

Description
I am using 3.0.12 with PHP5.6. And I am using [Link: Vdebug] (Xdebug client for Vim) for debugging.
When I am debugging with Vdebug, I get a fatal error caused by __debugInfo() sometime.
For example, when a thread execution suspends in the constructor of `Cake\ORM\Table`, 

```
php
   122 class Table implements RepositoryInterface, EventListenerInterface, EventDispatcherInterface
   123 {
   ...
   242     public function __construct(array $config = [])
... [Log Snipped] ...
   287         $this->dispatchEvent('Model.initialize');
   288     }
```

Vdebug shows me the context variables by using [Link: Xdebug's context_get commmand]. Then Xdebug seems to execute `var_dump()` internally. Therefore `Cake\ORM\Table::__debugInfo()` will be called, and the method calls `$this->_associations->keys()` at [Link: line 2198], but `$this->_associations` is not initialized yet in this case. As a result, I get a fatal error and Vdebug crashes.

```
Error: [Cake\Error\FatalErrorException] Call to a member function keys() on null
```

As far as I know, `Cake\ORM\Query` causes a similar issue.
I am happy if `__debugInfo()`s cause no fatal errors.
