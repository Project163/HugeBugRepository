Title

Closing InputStream on response body obtained from reactive client blocks until full response is read

Description
### Describe the bug

Calling `close()` on an input stream on a large response body (e.g. file download) obtained using the reactive client from
```
 io.quarkus 
 quarkus-rest-client 
 3.20.3 
```
blocks until the whole response is read.

### Expected behavior

`close()` should return immediately and not wait for reading the whole response.

### Actual behavior

`close()` apparently blocks until the whole response is read, although no bytes are read from the input stream anymore manually.

### How to Reproduce?

main.java
```
import java.io.InputStream;

import jakarta.ws.rs.client.ClientBuilder;
import jakarta.ws.rs.core.MediaType;

... [Log Snipped] ...
    }
}
```
pom.xml dependencies
```
 
	 
		 io.quarkus 
		 quarkus-rest-client 
		 3.20.3 
	 
 
```

1. Set `downloadUri` to an url of a large file
2. Run main
3. See that one byte is read, then `close()` blocks until the whole file is downloaded
