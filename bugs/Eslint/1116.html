Title

no-multi-spaces ignores multiple spaces before inline comments

Description
**Tell us about your environment**

* **ESLint Version:** v3.10.2
* **Node Version:** v7.2.0
* **npm Version:** 4.0.2

**What parser (default, Babel-ESLint, etc.) are you using?**
default

**What did you do? Please include the actual source code causing the issue.**
```bash
$ eslint --no-eslintrc foo.js
```
```js
/*eslint no-multi-spaces: "error"*/
console.log('hello',  'world');  // comment
```
**What did you expect to happen?**
Two problems should be reported (`'world'`, `// comment`)
**What actually happened? Please include the actual, raw output from ESLint.**
```

foo.js
  2:23  error  Multiple spaces found before ''world''  no-multi-spaces

✖ 1 problem (1 error, 0 warnings)
```
Discussion
- Confirmed. It does seem like a bug that this rule doesn't check inline comments.

This also doesn't warn:

```js
console.log('hello',     /* comment */ 'world');
```
- Another test case (may already be covered):

```js
console.log(/* comment followed by multiple spaces */         foo);
```
- ... [Middle Discussions Snipped for Brevity] ...
- Seems reasonable assuming `false` is the default
- I would prefer an option name like `ignoreEOLComments` rather than `exceptEOLComments`.

@minj I think the default behavior would be the same as the current behavior, to avoid breaking peoples' builds.
