Title

ActiveRelationTrait::filterByModels prefix issue with composite key

Description
When using a composite key in a relation that include a join, the filterByModels method calls the prefixKeyColumns method that add relate table alias to the attribute.

Then it generates the values array indexed by attributes names without including the table alias added previously.

This cause a missmatch between attributes and values when the "in" condition is builded and produce a null query.

Here is a sample relation that produce the issue : 

``` php
public function getItemsWithCategories()   {
     return $this->hasOne(Items::className(), [
            'a_id' => 'a_id',
            'b_id' => 'b_id'
        ])
        ->joinWith('categories');
    }
```

Using this relation, filterByModels calls the andWhere method with this parameters : 

``` php
$attributes = [0 => 'items.a_id', 1 =>' items.b.id' ] ;
$values = [[ 'a_id' => '1', 'b_id' => '5' ] , ..];
```

Final query looks like this : 

``` sql
SELECT * FROM items LEFT JOIN categories ON items.id_category = categories.id WHERE items.a_id IS NULL and items.id_b IS NULL
```
