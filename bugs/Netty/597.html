Title

DnsNameResolver regression for IPv4-only domains

Description
### Steps to reproduce

We have a domain which yields the following `dig` result for an `AAAA` question:

```
$ dig -t AAAA some.internal.domain.com

;  > DiG 9.9.5-9+deb8u10-Debian  > -t AAAA some.internal.domain.com
;; global options: +cmd
;; Got answer:
... [Log Snipped] ...

;; Query time: 105 msec
```

... and the following response for an `A` question:

```
$ dig -t A some.internal.domain.com

;  > DiG 9.9.5-9+deb8u10-Debian  > -t A some.internal.domain.com
;; global options: +cmd
;; Got answer:
... [Log Snipped] ...

;; Query time: 50 msec
```

When the response for the `AAAA` question is received sooner than that of the `A` question, a user will see `UnknownHostException("Unable to find correct name server for some.internal.domain.com")`, even if the DNS server will respond a correct answer for the `A` question.

### Expected behavior

`DnsNameResolverContext` should not fail the resolution request until all A/AAAA responses are received and evaluated.

### Actual behavior

`DnsNameResolveContext` fails the promise too soon when handling a redirect.

### Minimal yet complete reproducer code (or URL to code)

N/A since it involves a proper DNS server setup.

### Netty version

4.1.9.Final

### Workaround

Diable IPv6 explicitly using the JVM system property.
