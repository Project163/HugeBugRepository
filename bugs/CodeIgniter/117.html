Title

Uncaught exceptions don't set HTTP status 500 when display_errors is "off"

Description
I'm using CI 3.1.0 and recently noticed that when display_errors is set to "off", an uncaught exception won't set the HTTP status to 500.

I checked the CI source code, and noticed that in the `_error_handler()` function, the `set_status_header(500)` call is before the condition to display errors (system/core/Common.php:611). This is so we'll get an error 500 status regardless of the display_errors ini setting.

However, when handling uncaught exceptions, the `set_status_header(500)` call is inside the `show_exception()` function (system/core/Exceptions.php:210). This means we'll only get an error 500 if the display_errors setting is "on" and hence `show_exception()` is called (not usually the case in production).

As uncaught exceptions halt script execution, I think the call to `set_status_header(500)` should be in the `_exception_handler()` function, just like it is inside the `_error_handler()` function.
