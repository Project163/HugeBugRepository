Title

Native compilation failure using some extensions and bean validation

Description
### Describe the bug

Hi,

I try to build a native executable of a project with those 3 extensions:
- quarkus-cxf
- quarkus-mongodb-client
- quarkus-hibernate-validator

But the build fails.
It seems that the failure appears only when `@Valid` is set on a property of type List (I didn't try other collection classes), such as:
```
    @NotNull
    @Size(min = 0)
    @Valid // commenting this made the build succeed
    private List  fields;
```

Removing one of the 3 extensions or commenting `@valid` result to a build success.

Note that a `@Valid` on an Object (not a collection) does not fails the build.

I build the native executable using Docker:
```
mvn clean package -Dnative -Dmaven.test.skip=true -Dquarkus.native.container-build=true
```

Thanks.

### Expected behavior

The native build passes using the 3 extensions and `@Valid` on List properties.

I have no idea what's going on. `org.eclipse.angus.activation.nativeimage.AngusActivationFeature` is a simple GraalVM feature that is referenced in a `native-image.properties`, I fail to see how it could create this issue. To be honest, I haven't seen this issue much, the message seems to imply the class only popped up at runtime and wasn't around at static init.

I checked the dependency tree in both deployment and runtime modes and things look fine.
- The `org.eclipse.angus.activation.nativeimage.AngusActivationFeature` feature (any GraalVM feature) is supposed to only be used during build-time and not end up in the native image. For some reason this one ends up being referenced by a heap object.
