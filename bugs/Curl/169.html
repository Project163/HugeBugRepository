Title

curl 7.75: -c /dev/null deletes character device

Description
### I did this

curl -c /dev/null -C - --retry 5 -k -L [URL] -o file.tar

### I expected the following

curl would not delete the /dev/null character device, but write/read the cookie jar to/from it

### what happened instead
```
# la /dev/null 
-rw-r--r--    1 root     root            68 Apr 10 10:24 /dev/null
```
i needed to fix the character device afterwards using `rm /dev/null ; mknod /dev/null c 1 3 ; chmod 666 /dev/null`

### curl/libcurl version

[curl -V output]
curl 7.75.0 (x86_64-pc-linux-musl) libcurl/7.75.0 LibreSSL/[redacted]

### operating system
linux

- The current method is done to make sure the creation of the file is atomic when multiple processes write to the same file.

- What semantics do you want for the cookie jar exactly?

If you want to keep the current semantics (one process wins, overwriting all the other changes), it can be achieved with a
sequence of open, blocking lock, write all you need, ftruncate to the current size, close (which unlocks). It does not matter if several processes open the file at the same time: all but one will block on the lock, and the last one to unblock will "win" because it will write() and ftruncate() last.
