Title

Session's reset! is causing a new browser to launch if the browser has already been quit.

Description
Currently session's reset! is as follows:

```
ruby
def reset!
      if @touched
        driver.reset!
        assert_no_selector :xpath, "/html/body/*"
... [Log Snipped] ...
      @server.reset_error! if @server
    end
```

If driver.quit has been called sometime during the test, the call to assert_no_selector will eventually cause the browser to get initialized again.  This is causing an additional Saucelabs session to open during the rspec.rb's config.after method.
It seems to me that the reset! method should be something like:

``` ruby
def reset!
      if @touched && driver.browser_initialized?
      ...
```

- Hmm, this is tricky. Breaks the driver API which is never great :(
- I guess we could add browser_initialized? to Driver::Base and just have it return true by default -- that would then maintain the current behavior for any driver that hasn't added support for it
