- Quick fix idea is to make org.apache.ignite.internal.processors.hadoop.SecondaryFileSystemProvider pluggable: this way user can substitute it with anything he needs just via Spring configuration.
- Attached an implementation of  HadoopFileSystemFactory  for a kerberised environment. The implementation was already tested in production. Lets contribute it to Apache Ignite.

- Ivan, my comments: 
1) SecureHadoopFileSystemFactorySelfTest.checkSerialization - keytab is not checked. 

 2) "SecureHadoopFileSystemFactorySelfTest extends TestCase" - unit tests should derive from GridCommonAbstractTest as per our conventions. 

 3) As we target specific kerberos use case, lets name factory "KerberosHadoopFileSystemFactory", so that it's use case is more clear. 

 4) "implements HadoopFileSystemFactory, Externalizable, LifecycleAware" should be removed as BasicHadoopFileSystemFactory already implements all these interfaces. 

 5) SecureHadoopFileSystemFactory docs: "The factory spawns a dedicated thread ..." - this is not the case. 

 6) Docs for "keyTabPrincipal" - remove "hdfs-Sandbox" as this is a misleading hint for users. 

 7) DFLT_RELOGIN_INTERVAL should be public - we did that for all other defaults. 

 8) reloginIfNeeded(): lastReloginTime is updated only if (reloginInterval != 0). Is it normal? As potential implementor of derived class I would be surprised that this field (which is protected) is not updated. 

 9) Looks like we can get rid of all code duplication in create0() and getFileSystem() methods. The only thing you need is a method to obtain the file system. 

  BasicHadoopFileSystemFactory : 
  
  return  FileSystem.get(uri, cfg, usrName);
 
  
  KerberosHadoopFileSystemFactory : 
  
 UserGroupInformation proxyUgi = UserGroupInformation.createProxyUser(userName, UserGroupInformation.getLoginUser());

 return  proxyUgi.doAs( new  PrivilegedExceptionAction<FileSystem>() {
    @Override  public  FileSystem run()  throws  Exception {
         return  getFileSystem(fullUri, cfg);
    }
});
 
  

 10) Detailed docs about keytab, keytabPrincipal and relogin interval must be places to corresponding getters, not to fields. Setters, in turn must refer to getters. See BasicHadoopFileSystemFactory.setUri() as example. 

 11) reloginInterval is not validated. What if user pass negative value? Test is needed for this as well. 

 12) I would remove synchronization on UserGroupInformation.class because it doesn't add any valuable protection. Anyone is able to overwrite configuration later causing subsequent call to checkTGTAndReloginFromKeytab() to fail. We have no control of it.
- all comments addressed.
