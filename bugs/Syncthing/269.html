Title

Forced rescan doesn't happen when the file to be overwritten is new (not present in the index)

Description
On server 1 I typed:  echo 1 >> test
On server 2 I typed: echo 2 >> test
On server 1 I typed:  echo 3 >> test
On server 2 I typed: echo 4 >> test
On server 1 I typed:  echo 5 >> test
On server 2 I typed: echo 6 >> test
On server 1 I typed:  echo 7 >> test
On server 2 I typed: echo 8 >> test
On server 1 I typed: echo 9 >> test
I then waited for them to sync and then did a "cat test" which contained:
2
4
6
8
9
and there was no conflict files generated.
I did it a second time and got 2,4,6,8 and a third time and got 1,3,5,7,9 again with no conflict files
and both servers still saying that they are in sync and up to date.
If a local file has been modified since last sync, shouldn't it generate a conflict instead
of silently dropping data?

Also, it doesn't even seem to care what the "latest" file is as the "9" doesn't even always appear in the file.

Thanks.
