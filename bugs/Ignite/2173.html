Title

Client node should not start rest processor

Description

    
Discussion

    
- Why client should not start REST processor? Looks weird to me. This is normal use case to use client nodes as a gateway for various external activities. E.g. to listen for ODBC requests and start queries, collect data for web-console, start tasks for REST, etc..
- Agree. But I think that management endpoints (e.g. for Visor) should only be started on servers.
- ... [Middle Discussions Snipped for Brevity] ...
- Also a good point. Actually, I don't think it's a very common use case and a regular user would expect that REST will connect to server nodes. Having said that, ideally REST should be disabled on clients by default with an option to enable it. But this is an incompatible change, so probably it's better to do it in 2.0.

- Guys, 
I've implemented the following approach ( [URL]
 
	 By default REST processor does not start on clinet nodes; 
	 For start REST processor on client node need to add envirement property IGNITE_REST_START_ON_CLIENT; 
	 When REST processor does not start on client in logs prints message "REST protocols have not been started. For start the protocols on a client node add -DIGNITE_REST_START_ON_CLIENT=true";
