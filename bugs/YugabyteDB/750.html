Title

[CDCSDK] Reset the column count after creating update record in the context of single record update

Description
Jira Link: [Link: DB-3714]
As part of logic to identify if a new record needs to be created, various conditions are checked.

If the primary key of the current intent differs with the earlier one.
If the column count exceeds the total number of columns.
If it is delete record.
If the intent corresponds to a different statement altogether.
With this logic, the column count was not being reset correctly when an update record is generated. As a result, the subsequent records are broken without packing all of the corresponding columns appropriately.

Following is an example.
create table test(key int primary key, value1 int, value2 int);
insert into test values(1,2,3);

With the above statements we just have created a table and inserted a row. Everything goes well till this point. Now,

begin;
update test set value1=value1+2, value2=value2+3 where key>0; column count: 2, with the two intents corresponding to value1 and value2
update test set value1=value1+2, value2=value2+3 where key>0; column count: 4, same as above, but since the count is not reset it goes to 4.
commit;

After encountering 2 intents, there is a new statement, so a new record is created. But, the column count remains to be 2. As a result, after the 3rd intent, column count becomes equal to total number of columns and again a new record is generated, and as part of the existing logic column count is reset to zero. In case of any delete or update operations in between this issue will not crop up as we are setting the column count to total number of columns.

As a fix, we are resetting the column count, when a new record is being generated.
