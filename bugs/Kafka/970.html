Title

Improve error handling on invalid requests

Description
We should include the request id in the error message if parsing of `RequestHeader` fails and we should not try to mute the selector after closing the connection due to an error (as it causes a second exception to be thrown).
Discussion

       KAFKA-3341  : Improve error handling on invalid requests 

 
	 Include request id when parsing of request header fails 
	 Don't mute selector on a connection that was closed due to an error (otherwise a second exception is thrown) 
	 Throw appropriate exception from `ApiKeys.fromId` if invalid id is passed 
 

     I ran into the top two issues while trying to figure out why a connection from a producer to a broker was failing (and it made things harder than necessary). While fixing them, I noticed the third issue.
