Title

stringify fails if token.toString() returns undefined

Description

**Current behavior**
We had a working Angular2 application running on Angular 2.2.0. 
Since we needed some new features we tried to upgrade to a newer Angular, but then our tests started failing. Seems to fail from Angular 2.3.0 and forward. 

The tests are UI tests creating our components in the TestBed and using mocks of the objects provided to our component. 

It seems that if the mocks, e.g. an object provided to a component during construction, returns undefined when calling .toString() on it - Angular throws an exception and stops working. 

The issue is only seen in test, as our production dependencies return something on toString(). 

I have attached a sample application exposing the error.
[Link: StringifyBug.zip]

Run 'ng test' to see the two tests. One test fakes a toString() result, the other dont. 

It seems to boil down to [URL] where the result from toString() is used directly in indexOf call. 

Current workaround is to fake toString() on all our mocks so the test can run cleanly.

**Expected behavior**
The stringify method should be more defensive, and not break down if token.toString() returns null or undefined. 

**Minimal reproduction of the problem with instructions**
See the sample provided. 

- A component that takes something as constructor injection
- A test class, that using TestBed injects a fake object that returns null/undefined when calling toString() on it.
- Boom, it breaks.  

**What is the motivation / use case for changing the behavior?**
Stable framework, where it is possible to inject fake classes instead of e.g. Router, ActivatedRoute etc in test, without having to figure out internals.
