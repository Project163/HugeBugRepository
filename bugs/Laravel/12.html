Title

Method `set` in cache repository does not honor the PSR-16 SimpleCache contract

Description
- Laravel Version: 5.7
- PHP Version: 7.2

### Description:

Class `Repository` implements the [Link: `set` method] whose contract is defined in [Link: `Psr\SimpleCache\CacheInterface`]. By the contract, return value should be a boolean (true on success and false on failure). Yet, the implementation in the [Link: Repository] does not return any value.

Normally, this doesn't cause any problems in Laravel, but it does when using Laravel's cache repository as a dependency in third-party libraries. To illustrate the problem, take a look at the following 
code excerpt (part of the `Manager` class) from [Link: jeremykendall/php-domain-parser] package:

```
php
/**
 * Returns true if the refresh was successful
 * @param string     $url the Public Suffix List URL
 * @param null|mixed $ttl the cache TTL
... [Log Snipped] ...
    return $this->cache->set($this->getCacheKey('PSL', $url), $data, $this->filterTtl($ttl) ?? $this->ttl);
}
```
Injecting Laravel's SimpleCache implementation to the `Manager` class, and calling this method results in a type error because the `set` method's return value is always void, when the expected value is a boolean.

I've checked all the implemented cache stores in Laravel and all of them have the ability to return a success status as a boolean:
- `ApcStore`: uses [URL] which returns a bool.
- `ArrayStore`: can just return true.
- `DatabaseStore`: uses [URL] which returns a bool.
- `FileStore`: uses [URL] which returns int on success or false on failure.
- `MemcachedStore`: uses [URL] which returns a bool.
- `RedisStore`: uses [URL] which returns string "OK" on success.

Ignoring the fact that these return values don't give enough info about the nature of failures when they occur, is there another reason why a return value for methods `set`, `put`, `setMultiple`, `forever` is not a boolean?
