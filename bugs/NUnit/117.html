Title

Disambiguate error messages from EqualConstraint

Description
Although we try to avoid it, EqualConstraint occasionally fails with an error message like

```
Expected: some_value
 But was: some_value <== Same value in both messages
```

Issue #1778 illustrates such a case, producing the message

```
Expected: 0
 But was: 0
```

It is proposed that we append the type in such a case.,.

```
Expected: 0 (System.Int32)
 But was: 0 (System.IntPtr)
```

Note this has to be done somewhere in the code where **both** the expected and the actual values are available and after the string representations have already been determined. Finding the right spot may be slightly tricky.

Notes:
1. We should only do this if the types are actually different, otherwise, do not bother.
2. If a tolerance or other constraint modifier is in effect, we should investigate whether to enable this feature. The best course may be different for each modifier.
