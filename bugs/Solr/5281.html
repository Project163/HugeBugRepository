Title

OpenJ9 can't compile solr: No method HotSpotDiagnosticMXBean.dumpHeap

Description
Every jenkins build (of both main and 9x) using openJ9 fails during compilation due to.. 
  
 > Task :solr:benchmark:compileJava
/home/jenkins/workspace/Solr-main-Linux/solr/benchmark/src/java/org/apache/solr/bench/BaseBenchState.java:153: error: cannot find symbol
        mxBean.dumpHeap(dumpFile.toAbsolutePath().toString(), true);
              ^
  symbol:   method dumpHeap(String,boolean)
  location: variable mxBean of type HotSpotDiagnosticMXBean
Discussion
- The code in question has existed since  2021 , and I know we've had several had other Jira's fix problems running solr in OpenJ9 since then, so i can't imagine this compilation failure has existed since 2021 – my best guess is that this code  use  to compile with OpenJ9, but at some point OpenJ9 removed methods from their definition/implementation of  com.sun.management.HotSpotDiagnosticMXBean  (since it was never meant for direct consumption) and they started offering their own MBeans for accessing JVM internals... 
 
	  [URL]
	  [URL]
	  [URL]
 

 While it may be possible to write some more complex code to introspect the JVM to figure out what MBean to use and how to use it to take a heapdump, i would suggest that first and foremost we stop trying to use  com.sun.management.HotSpotDiagnosticMXBean  directly, and instead use the  MBeanServer.invoke  abstraction – something like... 
  
 
 final   String  mbeanName =  "com.sun.management:type=HotSpotDiagnostic" ;
 try  {
  MBeanServer server = ManagementFactory.getPlatformMBeanServer();
  ObjectName hotSpot = ObjectName.getInstance(mbeanName);
  server.invoke(
    hotSpot,
     "dumpHeap" ,
     new   Object [] { dumpFile.toAbsolutePath().toString(),  true  }, 
     new   String []{  "java.lang. String " ,  " boolean "  });
}  catch  (Exception e) {
   throw   new  RuntimeException( "Your JVM's imple of "  + mbeanName +  " does not support dumpHeap" , e)
}
 
  
 ...but i don't really understand  solr/benchmark  enough to even know how i would go about testing this.
