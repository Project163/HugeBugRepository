Discussion
- @trustin @fredericBregier any idea ?
- After digging a bit on the web (various RFC and blogs), I found the following:
- one particular blog very detailed: 
  
  [URL]
- RFC 2109 said (http://www.faqs.org/rfcs/rfc2109.html) that not allowed cookie names are (shortly)
  - "[Cookie] NAMEs that begin with $ are reserved for other uses and must not be used by applications."
  - In section 4.1 it states that attribute values pairs where the attributes must be a token confirming to RFC 2068.
  - RFC 2068 (http://www.faqs.org/rfcs/rfc2068.html) says a token is 1 or more characters that are anything BUT CTLs or tspecials. CTLs = tspecials = "(" | ")" | " " | "@" | "," | ";" | ":" | "\" |  
    HT =  
  - Futhermore, " The NAME=VALUE attribute-value pair must come first in each cookie. "
  - And, "When [the server] receives a Cookie header, the origin server should treat cookies with NAMEs whose prefix is $ specially, as an attribute for the adjacent . The value for such a NAME is to be interpreted as applying to the lexically (left-to-right) most recent cookie whose name does not have the $ prefix."

This list of reserved names comes from Sun JVM implementation of Cookie class, but seems in fact wrong.

```
public  [More ...] Cookie(String name, String value) {
     if (!isToken(name)
        || name.equalsIgnoreCase("Comment") // rfc2019
        || name.equalsIgnoreCase("Discard") // 2019++
        || name.equalsIgnoreCase("Domain")
... [Log Snipped] ...
        || name.startsWith("$")
     )
```

They should only test the "$" in front... 
And by the way 2019 is in fact 2109 since:
- RFC 2019 - Transmission of IPv6 Packets Over FDDI
- RFC 2109 - HTTP State Management Mechanism

For the particular "expires", it comes from old Netscape specification:

   [URL]

It could be allow also without issue (still old, but still apparently used in some countries).

Therefore the Reserved Names list should be... empty except checking that it does not start by "$" or special character.

The issue is after that, the code should check about the reserved words usage. But I think this is out of concern in this codec, and it should be left to the upper code (full http code made by the user) to handle those specific cookies (see the RFC and the Netscape spec to know what to do).

So my proposal could be:
- Replace the RESERVED_NAMES part by just checking the first char to not be '$', since the rest is done before in the code.
