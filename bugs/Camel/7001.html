Title

Global Error Handler does not take effect when a source Kamelet fails "Timer Example" Period Message

Description
I found a faulty behavior when configuring a global error handler and the failure is caused by the execution of a Kamelet. 

 The following route works correctly: 
  
 
- route:
    errorHandler:
      deadLetterChannel:
        deadLetterUri: kamelet:log-sink/errorHandler
    from:
      uri: timer:tick
      steps:
        - setBody:
            constant:  "fail!" 
        - setBody:
            simple:  "${mandatoryBodyAs( Boolean )}" 
        - log:  "${body}" 
 
  

 It intercept the failing execution and forward the failure to the DLC. However, if the producer URI contains a failing Kamelet, then, the global error handler is not working. Wrapping the same failing logic in a local Kamelet like: 

  
 
apiVersion: camel.apache.org/v1
kind: Kamelet
metadata:
  name: my-err-source
  labels:
    camel.apache.org/kamelet.type:  "source" 
spec:
  definition:
"Produces periodic events with a custom payload" 
    required:
      - message
    properties:
      period:
The time interval between two events
        type: integer
         default : 1000
      message:
The message to generate
        type: string
  types:
    out:
      mediaType: text/plain
  template:
    from:
      uri: timer:tick
      parameters:
        period:  "{{period}}" 
      steps:
        - setBody:
            constant:  "{{message}}" 
        - setBody:
            simple:  "${mandatoryBodyAs( Boolean )}" 
        - setHeader:
            name:  "Content-Type" 
            constant:  "text/plain" 
        - to:  "kamelet:sink" 
 
  

 And executing a new route as: 

  
 
- route:
    errorHandler:
      deadLetterChannel:
        deadLetterUri: kamelet:log-sink/errorHandler
    from:
      uri:  "kamelet:my-err-source/source" 
      parameters:
        message:  "fail!" 
      steps:
        - log:  "${body}" 
 
  

 Will act as no error handler is set at all
