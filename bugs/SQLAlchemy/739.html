Title

`MySQL server has gone away` when raising DisconnectionError in checkout

Description
**Migrated issue, originally created by Sylvain Duchesne ([Link: @Wyzzcow])**

The following code should trigger the error:

```
import logging
logging.basicConfig(level=logging.DEBUG)
import time
from sqlalchemy import create_engine
from sqlalchemy.exc import DisconnectionError
... [Log Snipped] ...
r = e.execute("select 1")
del r
```

Executing the last execute should yield the following output:

```
INFO:root:checking out
INFO:root:connection expired
... [Log Snipped] ...
OperationalError: (2006, 'MySQL server has gone away')
```

I traced the error back to the `weakref` 
[URL]
which has its callback bound with the `dbapi connection` that will be closed.
When the gc passes and the callback gets called, 
[URL]
the `dbapi connection` happens to be closed.

Due to a lack of time (and having already spent quite a bit debugging), I am not able to create a PR. Also, better let the experts tackle the issue (I would verify if the connection is already closed prior to calling `reset`).
