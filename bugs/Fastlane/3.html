Title

gym: When output_name contains "/" (directory character), export fails

Description
### New Issue Checklist
- [x] Updated fastlane to the latest version
- [Link: x] I have read the [Contribution Guidelines]
### Issue Description

When the value of output_name contains a slash(/), xcodebuild will create directories underneath the archive path. Then when gym attempts to export the archive and dSYM, it will potentially fail if any of the directories do not exist under the export path.
##### Complete output when running fastlane, including the stack trace and command used

```
+----------------------+------------------------------+
|                Summary for gym 1.7.0                |
+----------------------+------------------------------+
| output_name          | feature/some_feature         |
| scheme               | feature-dev                  |
... [Log Snipped] ...
[11:22:38]: ▸ zip I/O error: No such file or directory
[11:22:38]: ▸ zip error: Could not create output file (/Users/user/export/feature/some_feature.app.dSYM.zip)
```

The work around is to ensure the output_name does not contain any slash characters. However, should gym either:
1. Convert any slashes(/) to dash(-) or underscore(_) in output_name, before passing archive path to xcodebuild.
2. Attempt to create any directories under export_path, if any directories were created under archive_path.

fastlane version (run `fastlane -v`): fastlane 1.101.0
