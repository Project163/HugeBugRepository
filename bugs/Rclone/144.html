I have a very slow and unstable internet connection. when I try to upload large files (>500MB ) I usually get  an Authentication Error after the file is being upload for a large period of time.
I guess this is because it takes so long the authentication tokens are invalid.

When this error occurs rclone reauthenticates but skip the file and does not resume the upload.
This is not only very frustrating (when it happens at 97%) but make it impossible to upload very large files (> 1,5G) since with my connection speed they will always eventually fail.

I'm not sure if onedrive (and other services) allows to re authenticate and continue the upload (or if it possible to somehow refresh the token before it happens) but it would be a great improvement to have.

- Ok I think I figured it out.
It seems like if uploading a part started but token has expired during the upload one drive will reject the part since the token is expired this error will stop the upload from being retried and the multipart session will be destroyed.

I submited a pull request but its my first time writing go code so there might be some improvements.
Instead of only checking the error code I'm checking that the error explicitly mention the token is expired I guess this can be simplified by retrying on any 401 error but then if the auth has a more serious error it will take it longer to fail.

I also found a bug that upload will not be able to actually retried since after the first attempt the Reader index will be at the end of the buffer and it need to be reseted
