Title

[YSQL] CBO selectivity estimates on tight upper bound conditions are inaccurate

Description
Jira Link: [Link: DB-6556]
### Description

Consider the following trace
```
CREATE TABLE t1 (k int, primary key(k asc));
INSERT INTO t1 SELECT i FROM generate_series(1,1000000) i;
ANALYZE t1;
set yb_enable_optimizer_statistics = true;
explain select * from t1 where k <= 50000;
... [Log Snipped] ...
   Index Cond: (k <= 50000)
(2 rows)
```
This implies that the computed selectivity of `k <= 50000` was 0.0001 even though the actual selectivity is 0.05 which is 2 orders of magnitude off. Postgres would normally be expected to [Link: compute] this selectivity to be around 0.05 itself. The reason why this selectivity value is coming out to be this off in this case can be seen by looking at the histogram bounds for `k`.

```
select histogram_bounds from pg_stats where tablename = 't1';
......
```

Note that our filter's upper bound, 50000 is below 672100 which according to the histogram table is the minimum of `t1`. Seeing this, YSQL [Link: clamps the selectivity value] to 0.01/(num_buckets - 1) = 0.0001.

It is also worth noting that the rest of the histogram bounds seem awfully close together, suggesting a skew in its calculation.
