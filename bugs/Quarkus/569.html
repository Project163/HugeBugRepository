Title

Using the REST Client with Multipart not working in all cases

Description
**Describe the bug**
(Describe the problem clearly and concisely.)
Proxying multipart call using `@RestClient` is not working with only GET resource, you have to have at least one POST.

**Expected behavior**
(Describe the expected behavior clearly and concisely.)
Expected behavior is successful multipart call toward another service even when there is only GET resource.

**Actual behavior**
(Describe the actual behavior clearly and concisely.)
Results is:
RESTEASY003215: could not find writer for content-type multipart/form-data type: org.acme.rest.client.multipart.MultipartBody

Discussion
- I explained it to @irenakezic on Zulip.

The thing is that it never works. The `@POST` is missing a `@Consumes` annotation so all the providers are registered. That's why it works.

The `@GET` doesn't need a `@Consumes` so it doesn't trigger the registration of all the providers.

I gave @irenakezic some guidance on how to debug this.
- Debugging the issue I came to the conclusion that reader providers are registered correctly for all `@Consumes` annotations. However, when invoking the Rest client service from MultipartClientResource class in the example the writer provider is needed as well.
A solution might be to search for the `@RestClient `annotation when registering providers. In case `@RestClient` annotation is found register writer providers (in addition to reader) for all `@Consumes` annotations in the client service.
@gsmet what do you think?
