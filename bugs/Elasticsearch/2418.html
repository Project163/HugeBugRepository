Title

[ML] lat_long should be more tolerant to missing data

Description
Reported in 7.6 (and would exist earlier).

With a `lat_long` detector, if the `field_name` value is missing, the datafeed stops and the job closes. The following error is reported `Datafeed is encountering errors extracting data: Unexpected values for a geo_point field: []`.

This could occur on the first bucket, or part way through the job, depending on the timestamp of the doc (or docs) with the missing geo value.

Other anomaly detector functions e.g. `sum(bytes)` are tolerant of missing values. Therefore we should also be tolerant of missing values for `geo_point` and `geo_shape`.

To workaround, use `exists: geo.field_name` on the datafeed query for `lat_long` functions.
