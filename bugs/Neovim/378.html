Title

No completion event is triggered when popup just disappeared but completion is active

Description
There is no completion event triggered when doing the following:
- Initialize completion popup.
- Type to the point when popup just disappeared after most recent character. In this case completion is still active (if delete previous character, popup reappears).

**Edit**: latest Vim (8.2, patches 1-2815) also has the same behavior, but as Neovim has the initial implementation of `CompleteChanged`, I decided to open issue here.

Setup information:
- `nvim --version`: NVIM v0.5.0, Build type: RelWithDebInfo, LuaJIT 2.1.0-beta3
- Operating system/version: Ubuntu 18.04
- Terminal name/version: Gnome Terminal
- `$TERM`: xterm-256color

### Steps to reproduce

- Create the following configuration file (for example, under 'completion-event.vim')

```
vim
let g:count_changed = 0
function TrackCompleteChanged()
  let g:count_changed = g:count_changed + 1
  echo 'CompleteChanged #' . g:count_changed
... [Log Snipped] ...
set shortmess+=c
set noshowmode
```

- Run `nvim -u completion-event.vim`.
- Type `aaa bbb `.
- Initialize complete with ` ` (`CompleteChanged` is triggered).
- Empty completion suggestion with ` ` (`CompleteChanged` is triggered).
- Type `a` (`CompleteChanged` is triggered) and then type `c` (**no** event is triggered).
- Type ` ` to see that completion is still active (`CompleteChanged` is triggered).

### Actual behaviour

No completion event is triggered.

Animation of behavior:

[Image: neovim_completion-event-issue]

### Expected behaviour

Some completion event is triggered. More intuitively, it should be `CompleteChanged` as it does trigger when no item is selected.

**Edit**: Maybe even more intuitive would be to stop completion at this point (and thus trigger both `CompleDonePre` and `CompleteDone`). But this is probably too drastical. Is this behavior (not stopping completion when typing one character beyond all suggestions) intentional, because I couldn't find any reference?
