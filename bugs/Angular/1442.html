Title

JsonP.get() not using headers passed in with options

Description
- **I'm submitting a ...**
- [x] bug report
- [ ] feature request
- [ ] support request => Please do not submit support request here, see note at the top of this template.

**Current behavior**

Setting options like this:

```
        this.headers = new Headers({ 'accept': "application/json;odata=verbose" });
        this.options = new RequestOptions({ headers: this.headers });
```

It works if I use http:

```
return this._http.get(url, this.options)
  .map((res: Response) => res.json());
```

I look at the headers in Fiddler I see:
`accept: application/json;odata=verbose`

If I try the same thing with JsonP:

```
return this._jsonp.get(url, this.options)
  .map((res: Response) => res.json()); 
```

Then in the Fiddler I see this header:
`Accept: */*`

**Expected/desired behavior**

Headers from options passed to JsonP.get() are not used.
- **What is the motivation / use case for changing the behavior?**

I am trying to access a SharePoint oData source.  The bad news is that http.get() gets a CORS violation error.  The good news is that jsonp.get() gets a document, but it's XML.  

I am trying to pass accept headers with JsonP and they are not getting set.
