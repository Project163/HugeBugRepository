Title

Liskov is not rechecked in fine grained if an attribute type is updated

Description
This test doesn't show show any errors on the second run
```
[case testLiskovRechecked]
import b
class A(b.B):
    x: str
def f(x: b.B) -> None:
... [Log Snipped] ...
    x: int
[out]
```
Although it is not safe, in particular, `A.x` is incompatible with `B.x`. This actually looks hard, because I don't see yet how to fix this without a visible performance regression.

_UPDATE:_ Simplified the test case.
Discussion
- Here the idea is to add a dependency like `  -> m` to just recheck the assignment without recursing into methods. We need however to check that Liskov is also verified for methods after an update, this may require different dependency targets depending on whether this is an attribute or method. (We need to be especially careful with decorators, Liskov should be checked in the outer scope for them, i.e. after decorating.)
