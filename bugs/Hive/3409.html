Title

Beeline requires newline at the end of each query in a file

Description
Beeline requires newline at the end of each query in a file.
Discussion
- I am still able to reproduce the issue in master as of 4/29/2015 on my mac shell (Darwin localhost 12.5.0 Darwin Kernel Version 12.5.0).
- It looks like a bug from jline (jline-2.1.2.jar), class jline.console.ConsoleReader.java method: 
public String readLine(String prompt, final Character mask) throws IOException 
  
                  int  c = pushBackChar.isEmpty() ? readCharacter() : pushBackChar.pop ();
                 if  (c == -1) {
                     return   null ;
                }
 
  
 When reaching the end of line without \n, readCharacter returns -1 and readLine discard what it has read and return null. so the last command in sql script passed via -f will be ignored.  
It can be worked around by append a newline after the last sql command.
- ... [Middle Discussions Snipped for Brevity] ...
- Does this need to be documented?
- I think it is not needed. Before, without this patch the last statement in the Beeline sql script was ignored and needed a newline in order to be executed. It is a bug and the workaround by appending a newline was not documented. This JIRA fixes this issue.
