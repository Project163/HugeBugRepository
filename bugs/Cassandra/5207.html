Title

nodetool status "Load" columns has wrong width

Description
Using Cassandra 3.11.2 on FreeBSD, I get: 
  
 
Status=Up/Down
|/ State=Normal/Leaving/Joining/Moving
--  Address            Load       Tokens       Owns (effective)  Host ID ...
UN  server1.andxor.it  11.11 MiB  256          39.6%             ...
UN  server2.andxor.it  32.04 MiB  256          41.8%             ...
UN  server3.andxor.it  519.33 KiB  256          40.0%             ...
UN  server4.andxor.it  10.95 MiB  256          40.3%             ...
UN  server5.andxor.it  11.03 MiB  256          38.4%             ...
 
  
 AFAICT this is caused by  "%-9s"  in  Status.java:292  which should be probably a 10 instead of 9.
Discussion
- The same cluster gives a "correct" answer when called from a different host with LANG environment (and others?) are set to Italian: 
  
 
Status=Up/Down
|/ State=Normal/Leaving/Joining/Moving
--  Address            Load       Tokens       Owns (effective)  Host ID ...
UN  server1.andxor.it  11.11 MiB  256          39,6%             ...
UN  server2.andxor.it  32.04 MiB  256          41,8%             ...
UN  server3.andxor.it  519.3 KiB  256          40,0%             ...
UN  server4.andxor.it  10.95 MiB  256          40,3%             ...
UN  server5.andxor.it  11.03 MiB  256          38,4%             ...
- Today I have had even an 11 columns result:  1010.18 KiB .
- The offset should be from the max width instead of hard coded since it can vary so much. The other nodetool outputs have been moving to use  TableBuilder  so that it always aligns properly. Perhaps this table can be changed to use it as well.
- Using  TableBuilder  in latest patch.
