# Issue description

I encounter unreliable sourcemap debugging when using Next. 

See below for detail of the Monorepo case, but I have found there are problems even in a standalone case, as per the followup comment in this issue which provides probably a simpler test case.

# Monorepo case

Some files mounted from my local filesystem source folder show that they are loaded and bound, others are not. The application is successfully bundled and runs, but cannot be reliably debugged. The results seem worse since the Webpack 5 upgrade, and now almost no files successfully bind breakpoints.

Breakpoints in visibly loaded and bound files (with a green circle) work OK. Breakpoints in files without the green circle silently fail.

The below screenshot shows the running app which includes all the files shown in the window, but `util.ts` and `view.tsx` ARE bound, while `domain.ts` and `game.ts` are mysteriously unbound and breakpoints placed in those files (like the one in the screenshot) are ignored.
