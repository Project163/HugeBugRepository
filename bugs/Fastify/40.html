Title

Connection closed on bad request in reused connection

Description

### Operating system version (i.e. 20.04, 11.3, 10)

Fedora release 34 (Thirty Four)

### Description

When fastify server receives request with invalid url in a reused connection, it closes the connection instead of `400 Bad Request` reply. 

The closed connection is then propagated by load balancer (ALB) as `502` error. This turns client errors into closely monitored  server errors. 

The problem is not reproducible when invalid url is received on new connection.

Further context:
- reproducible in express
- not reproducible in hapi
- not reproducible in fastify over http2


### Steps to Reproduce

Program:
```js
// file: server.js
const fastify = require("fastify")({logger: true});
const route = fastify.get("/ping", async () => "Hello world\n");
fastify.listen({ port: 3000 });
```

Run server:
```
$ node server.js
```

Run client invoking 2 requests over reused connection
* the first request is correct and keeps the connection alive
* the second request has invalid character `' '` in the query. Server closes the connection instead of replying `400 Bad Request`. 
```
$ curl '[URL] '[URL] b' -v
*   Trying  :3000...
* Connected to localhost ( ) port 3000 (#0)
... [Log Snipped] ...
* Closing connection 0
...
```

Not reproducible when the bad request is sent to new connection. Curl retries in new connection and correctly gets 400 response.
