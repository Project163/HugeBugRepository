Title

Unintended change to ambient lighting

Description
## Bevy version

main, since #17482

## Relevant system information

SystemInfo { os: "macOS 15.3.1 Sequoia", kernel: "24.3.0", cpu: "Apple M4 Max", core_count: "16", memory: "64.0 GiB" }    
AdapterInfo { name: "Apple M4 Max", vendor: 0, device: 0, device_type: IntegratedGpu, driver: "", driver_info: "", backend: Metal }

## What you did

Observed >100 changes to example lighting in [Link: the example report].

`cargo run --example 3d_scene`
`cargo run --example load_gltf`

## What went wrong

Generally, I believe that two things are happening:

- The new "default ambient light" is somehow brighter than the old one.
  (See `3d_scene`, which is brighter than it used to be)
- Cameras with `EnvironmentMapLight` are no longer *also* getting ambient light applied.
  (See `load_gltf`, where the scene is now very dark and it is difficult to see the plaque)

## Additional information

I was initially confused by this, because it was caught when the PR was [Link: tested] by the example runner. There wasn't any discussion about the changes, so I thought this might be intentional. After consulting `#rendering-dev`, it seems that this was not intentional, but if it is was, we would want some sort of mention in the migration guide.
Discussion
- unless we have a fix soon, I would like to revert #17482 so that it can be fixed outside of main
- I think this change is intentional since AmbientLight is not physically accurate so any examples that previously used it are lit "incorrectly". I think the solution would be to increase the affected examples EnvironmentMapLight's intensity to an appropriate level?
