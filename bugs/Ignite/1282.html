Discussion
- Also was reproduced with 
IgniteCacheClientQueryReplicatedNodeRestartSelfTest.testRestarts
- Reproduced on 
GridCacheClientNodePortableMetadataMultinodeTest.testFailoverOnStart for IgniteGridGain configuration
- Merged to the master.
- The assertion arose because sometimes a node, that was joining a topology, sent to its previous node order equal to 0. That previous node considered this as an error, however this node had "node add finished message" for that joining node that had to be sent to it.  

 Now if a node receives 0 as an order from its next node it checks its pending messages queue before failing the next node. 

 Reviewed by Yakov, merged to the main development branch.
