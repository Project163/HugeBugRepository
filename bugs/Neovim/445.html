Title

`autocmd!` speed regression with api-autocmds

Description
### Neovim version (nvim -v)

NVIM v0.7.0-dev+1155-g991e47288

### Vim (not Nvim) behaves the same?

N/A

### Operating system/version

Ubuntu 20.04

### Terminal name/version

GNOME Terminal 3.36.2 using VTE 0.60.3 +BIDI +GNUTLS +ICU +SYSTEMD

### $TERM environment variable

tmux-256color

### Installation

build from repo

### How to reproduce the issue

Startup time:
```
nvim --clean --startuptime log --cmd 'filetype plugin indent on'
```

Profile:
```
nvim --clean --cmd 'profile start profile.log' --cmd 'profile func *' --cmd 'profile file *' --cmd 'filetype plugin indent on' -c 'profdel func *' -c 'profdel file *' -c 'qa!'
```

### Expected behavior

Before #14661
* startup time 15.923 seconds
* `autocmd` 0.00697 seconds, `autocmd!` **0.000242** seconds

The raw data is here: [URL]

### Actual behavior

#14661
* startup time 039.874 seconds
* `autocmd` 0.005301 seconds, `autocmd!` **0.024399** seconds
Discussion
- Note that `filetype plugin indent on` is already the default, event with `--clean`. adding it explicitly will force the deletion and recreation of a lot of autocmds. I'll suggest to try the same commands for timing and profiling before and after #14661, but **without** `--cmd 'filetype plugin indent on'`, and report the results here.
- `--clean` doesn't run `filetype plugin indent on` (not sure if it's a feature or a bug), and IIUC even if `filetype plugin indent on` is run twice, it won't redo the autocmds due to `'did_load_filetypes'`.

Without `filetype plugin indent on`, the slowdown is less dramatic (about 15x). The output of `:au` is 291 lines. With `filetype plugin indent on`, the output of `:au` is 3852 lines (100x slowdown).
