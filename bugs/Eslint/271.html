Title

no-space-before-semi doesn’t check for all semicolons

Description
There are several cases where a semicolon can occur which is not checked by `no-space-before-semi`.

Here are a few failing tests for this rule which should have an error:

```
js
invalid: [ 
      { code: "while (true) { break ; }", errors: 1},
      { code: "while (true) { continue ; }", errors: 1},
      { code: "debugger ;", errors: 1},
... [Log Snipped] ...
      // ...
]
```

Result:

```
1) no-space-before-semi while (true) { break ; }:
     AssertionError: Should have 1 errors but had 0: []: expected 0 to equal 1

  2) no-space-before-semi while (true) { continue ; }:
     AssertionError: Should have 1 errors but had 0: []: expected 0 to equal 1
... [Log Snipped] ...
  6) no-space-before-semi for (var i = 0 ; i < 10 ; i++) {}:
     AssertionError: Should have 2 errors but had 0: []: expected 0 to equal 2
```
Discussion
- I also suggest to change to error message of this rule.

At the moment there are different messages related the node where the extra space before the semicolon appears:
- `"Variable declared with trailing whitespace before semicolon"`
- `"Expression called with trailing whitespace before semicolon"`

I suggest a simple error message like `"Unexpected space before semicolon"`.
