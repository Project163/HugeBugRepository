Title

Binding is not passed to the script if the parsed script text contains no statements

Description
This looks like a very exotic use case. But if you do a lot of automatic script generation, this is a real nuisance. You have to always put some dummy statement into the text to make things work.
Discussion
- I'm not sure I follow in what way it is really a problem, as you don't use the variables from the binding if your script is empty?
- I have the following use case. For the build dsl I'm developing I have a hierarchical folder structure. Each folder may contain a normal script, or an empty script or an commented out script.  

 
	 folder
	 
		 script1 
		 childfolder
		 
			 script2 
			 childchildfolder
			 
				 script3 
			 
			 
		 
		 
	 
	 
 

 The scripts of the subfolder are initialized with the bindings of the parent folders. In the example above this means, even if script2 is empty, it needs to be a container for the bindings of script1, as script3 needs access to all the bindings of the hierarchy. I'm not saying that this is the best solution to the problem, but it is a valid approach. And the groovy behavior described in my attached test case is I think surprising. 

 I think the principle of least surprise should be the guide here, even though this is not a major use case.
- Have you got a patch to fix that behaviour?
