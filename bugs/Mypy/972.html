Discussion
- Thanks for reporting! I am curious what is the purpose of using `attrs` with protocols, is it to autogenerate default implementations for methods?

The crash itself is caused by the dummy type variable used for self-types in methods. I am not sure what is the best fix here. A simple possible solution is to ignore nor `FuncBase`/`Decorator`/`Var` nodes when collecting protocol attributes (especially if they are underscored). Maybe we should also emit an error if such node (e.g. a `TypeVarExpr`) appears in protocol namespace under non-private name.
- We uses attrs for basically all of our classes. So this was discovered because I was porting some of our abstract classes over to be protocols instead and had not removed the `@attrs` line. 

This specific example doesn't have a lot of it, but some of our abstracts have instead variables like `a: int` defined on them, and it saves having to copy and paste that code into the concrete implementation.
- Note this can happen even with non-generic protocols, see example in [URL]
