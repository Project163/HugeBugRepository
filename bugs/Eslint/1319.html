Title

arrow-parens "as-needed" documentation is misleading

Description
[URL]

Documentation states:


However, it then gives an example of invalid syntax when using "as-needed":


**What did you expect to happen?**
Because the documentation says _allows_ omitting parens, it should not disallow parens around a single argument. So the following should both be valid:

```js
a.then((foo) => {});
a.then(foo => {});
```

While this is not valid:

```js
a.then(foo, bar => {});
```

**What actually happened? Please include the actual, raw output from ESLint.**

The rule _requires_ the parens to be omitted with a single argument.

```
Unexpected parentheses around single function argument (arrow-parens)
```

**Are you willing to submit a pull request to fix this bug?**

Yes, subject to the project desires. My recommendation is to change the `as-needed` rule to _allow_ omitting parens, as described, and add another option (name to be determined) that required omitting the parens for single-argument functions.
