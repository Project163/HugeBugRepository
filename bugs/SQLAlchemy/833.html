Title

names generated by func are not quoted for case sensitive names, special characters

Description
Through the use of `func` sql statements can be executed. Something like
```py
table = sa.Table(...)
fn = getattr(sa.func, '1; drop table other_table; select max')
sa.select([fn(table.c.id)])
fn = getattr(sa.func, '(select count(*) from other_table), max')
sa.select([fn(table.c.id)])
```
executes the valid statements
```
SELECT 1; drop table other_table; select max(table.id) AS "1; drop table other_table; select max_1" 
FROM table
SELECT (select count(*) from other_table), max(table.id) AS "(select count(*) from other_table), max_1" 
FROM table
```

These are just two examples, but it seems that the name of function is taken as is, without executing any sort of validation.

Maybe `func` should validate that the name of the function is a valid database identifier?

I was thinking about letting an consumer of an api I'm writing on specify a function name and wanted to check if I needed to validate it against a list of allowed functions.
Discussion
- hi there -

database identifiers can actually have a wide variety of characters in them, they just need to be quoted.

in this case it seems like we don't apply quoting as we normally do:

```
SELECT MyFunction() AS "MyFunction_1"

```

it's likely that it hasnt been an issue since most SQL functions are using case-insensitive names but I suppose it's possible that custom SQL functions might not.   So that's a more ordinary issue we can fix, here is a patch that can serve as the basis for the fix:

```
diff
diff --git a/lib/sqlalchemy/sql/compiler.py b/lib/sqlalchemy/sql/compiler.py
index b703c59f23..a841433fb3 100644
--- a/lib/sqlalchemy/sql/compiler.py
+++ b/lib/sqlalchemy/sql/compiler.py
... [Log Snipped] ...
     def visit_next_value_func(self, next_value, **kw):
         return self.visit_sequence(next_value.sequence)
```

so we have:

```python
from sqlalchemy import select, func

print(select([func.MyFunction()]))


print(select([func.MyPackage.MyToken.MyFunction()]))

```

```sql
SELECT "MyFunction"() AS "MyFunction_1"
SELECT "MyPackage"."MyToken"."MyFunction"() AS "MyFunction_1"

```

as for the original claim, using that special word "arbitrary", which IMO does not apply as a concern here since it is not appropriate to use untrusted user input as a python attribute name any more than it would be to use untrusted user input as the name of a SQL table (they could change it to read from private tables) or for one to send untrusted user input into the `text()` function, which also allows arbitrary SQL to be executed not to mention `connection.execute()`, the quoting routine quotes double quotes so you can't break out:

```python
from sqlalchemy import select, func

fn = getattr(func, '" delete from table "foo')
print(select([fn()]))

```

`SELECT """ delete from table ""foo"() AS """ delete from table ""foo_1"
`
