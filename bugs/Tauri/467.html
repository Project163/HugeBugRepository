Title

[bug] Tauri 2: iOS app's bundle identifier does not use tauri.conf.json

Description
### Describe the bug

The `project.pbxproj` file generated by tauri 2 does not seem to be using the productName from tauri.conf.json, instead using the package name from Cargo.toml. 

Here's a repo that reproduces the issue: [URL]

I'd be happy to take a shot at fixing this if we can agree on what the correct behavior should be

### Reproduction

1. Create a tauri 2 project with mobile capability using create-tauri-app --beta
2. Change `tauri.conf.json` to put identifiable names in both productName and identifier
3. run `cargo tauri ios init`
4. Open the generated project with xcode and go to signing and capabilities
5. -> Product Name is the name of the package in Cargo.toml and the identifier has been stripped to append it to the first part of the identifier provided in tauri.conf.json

### Expected behavior

There are multiple ways to go about this, none of which in my opinion includes using the Cargo.toml package name

1. Use the "productName" from tauri.conf.json and append it to the first part of the "identifier" from tauri.conf.json -> this is not ideal, but follows that same stripping and append logic that happens today.
2. Use "identifier" as the Bundle id without any modifications. -> This I think is preferrable, although I don't quite know if it makes sense on platforms other than apple's.

Both of those would mean a breaking change, since it could change the bundle ids of deployed apps
