Title

[bug] passing command-line arguments to `yarn tauri dev` are passed to cargo, not the application

Description
### Describe the bug

[URL] describes how to pass command-line arguments to your application in a development environment for testing using `yarn tauri dev -- [args]`. However, when attempting to pass command line arguments to `yarn tauri dev`, `cargo build` captures the arguments and terminates the environment launch.

### Reproduction

1. `yarn tauri dev -- test123` or `cargo-tauri dev -- test123` or `cargo tauri dev -- test123`
2. `cargo build` incorrectly captures the arguments

### Expected behavior

The arguments should be passed to the Tauri application and not captured by cargo.

### Additional context

Discussion
- This was changed this year, the arguments after the first `--` are passed to `cargo build`, and to pass it to the application you must add a second `--`, like this:

`yarn tauri dev -- -- test123`

This was introduced #3431 but I agree the documentation isn't clear, I'll update it.
