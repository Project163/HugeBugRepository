Title

Imported module is undefined in development

Description
**Describe the bug**

Importing a npm package returns undefined in development but not in production.

```
 
    import marked from 'marked'
    // marked is undefined
 
```

This bug does not seem to be isolated to `marked`. I've encountered it with `markdown-it`, `snarkdown`, and several of my own npm packages.

**Logs**

```

    at async render_page (file:///path/to/repo/node_modules/.pnpm/@sveltejs/kit@1.0.0-next.61_svelte@3.35.0+vite@2.1.3/node_modules/@sveltejs/kit/dist/ssr.js:2472:19)
```

**To Reproduce**

Minimal reproduction (created from steps below): [URL]

```
pnpm init svelte@next
pnpm i
pnpm i marked
```

Then, in the `src/routes/index.svelte` file, just add this to the ` ` tag:

```js
import marked from 'marked'

marked.setOptions({
    smartypants: true,
})
```

```
pnpm dev
```

Then, you'll get the error when you visit the site.

_However…_

If you build the project then start the production server, everything works correctly.

```
pnpm build
pnpm start
```

**Expected behavior**
No error in development. Should get same results as in production.

I can only imagine something about CommonJS conversion changed recently in Vite, or esbuild, or something? But I can't seem to figure out what exactly
- Since you can't replicate it in this monorepo but you can with new projects, I'm assuming the bug is from a dependency update. Though even weirder, I don't think it's a direct update to Vite or ESBuild—but perhaps one of their dependencies.

- cheap-watch

In short, if it is a dependency issue, it's not going to be obvious.
