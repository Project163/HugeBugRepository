Title

Generic type arguments are not encoded properly

Description

1. Create a unit-test project targeting latest .netcoreapp supported by xunit.
2. Create the following test class:
```

- Result from running with the .NET Framework console runner:

[Image: image]

The .NET Framework results are probably what you expected: one passes (T), one fails (U).

Result from running with the .NET Core VSTest runner:

[Image: image]

The VSTest results are probably not what you expected, because the argument serialization inherent in VSTest ended up with two identical unique IDs for T and U. While I sort of expected this result, it could be argued that it is a bug (that we might not be able to fix).

The specific R# runner behavior that you're showing as a bug is actually a bug in the R# runner, because it discovered tests it shouldn't be able to run. So there are two bugs here: one ours (the T and U versions have identical IDs), one Resharpers (it shows you tests it can't run).

I will leave this bug open here in the even that maybe we can find/fix our issue, but the R# issue should be reported separately to the R# team.
- I believe you incorrectly identified the root cause. Yes, the IDs are the same. (I actually did not check that, but it is a different problem, and it should not matter in this case. It might have been a single test case, thus having a unique id, the result would have still been the same). But whatever the IDs are, there are two test cases reported by the xUnit adapter, when an IDE executes a discovery for the project. Here I am talking about `dotnet vstest` and [Link: DiscoveryRequestPayload]. 

Here comes an error.

If the IDE then tries to execute any of those test cases by specifying them explicitly in [Link: TestRunRequestPayload.TestCases], the xUnit adapter will fail to deserialize that test case (and abort execution completely, too, even if it is not the only test case in the run).

It is different from running tests using `dotnet test` command in your example, because (as I understand it) the latter discovers and runs in the same process at about the same moment in time, thus eliminating the need to deserialize test cases.

I disagree that it is a bug of R#. All R# does is shows the test cases xUnit adapter reports. But when R# tries to feed the same test cases back to xUnit adapter, telling it to run them, the adapter crushes in deserialization. And it only those types of tests (ones with types of generic arguments passed as arguments) that are causing the problem. All others can be executed just fine.

Hope this helps.
