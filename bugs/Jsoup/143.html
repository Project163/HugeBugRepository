Reading encoded emojis in HTML attributes

Description
I'm using jsoup to parse images that link to emoji images. These images have the actual emoji characters encoded in the alt attributes:

Discussion

    
- The provided Parser.unescapeEntities util has similar issues

```
    @Test
    void parseHtmlEncodedEmoji() {
        String emoji = Parser.unescapeEntities("��", false);
        assertNotEquals("\uFFFD\uFFFD", emoji, "UTF-8 replacement characters");
        assertEquals("\uD83D\uDCAF", emoji, "Invalid emoji");

- Thanks for the clear report, fixed!

This was failing to decode and returning the replacement character due to an explicit range check it was hitting: (>=   &&  ). That check has been there since [URL] (12 years ago!) when I reimplemented to follow the HTML5 spec. But I can't see why that range was explicitly excluded - perhaps it was previously reserved in Unicode and then opened later.

The single-point version (`💯`) worked OK originally.

Have fixed by removing that range as it is now valid and not excluded in the current spec.

I note that Chrome seemingly treats this as we previously did; `��` in Chrome renders as two replacement characters. The single point renders correctly.
