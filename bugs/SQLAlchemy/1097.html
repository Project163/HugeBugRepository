Title

psycopg2.errors.DatatypeMismatch when using array of enum and with_variant

Description
**Describe the bug**
Using a type `ARRAY(Enum(enum_class)).with_variant(...)` on PostgreSQL, when inserting values, the array is not cast as it is without the `with_variant(...)`, resulting in the following error: 

```
sqlalchemy.exc.ProgrammingError: (psycopg2.errors.DatatypeMismatch) column "items" is of type myenum[] but expression is of type text[]
```

It won't check the existance of the type either.

This issue is only present in SQLAlchemy > 1.3.23

**Expected behavior**
Emitted queries should be the same as the one without `with_variant`
 
**To Reproduce**

Note that in this example the `with_variant` doesn't make any sens at all, but that was to simplify the example. Same issue is observed no matter what we have in the `with_variant` arguments.

```
py
import enum

from sqlalchemy import create_engine, Column, Integer, Enum, ARRAY
from sqlalchemy.ext.declarative import declarative_base
... [Log Snipped] ...
session.add(obj)
session.commit()
```
**Emitted query:**

```sql
INSERT INTO my_model (items) VALUES (%(items)s) RETURNING my_model.id
```

**Emitted query without the `with_variant()` call**

```sql
INSERT INTO my_model (items) VALUES (%(items)s::myenum[]) RETURNING my_model.id
```
