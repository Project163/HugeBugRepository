Title

3.0 Alpha 2 - Unit testing, mocking controller with Auth has session problems

Description
I've been trying to make unit tests for the blog tutorial in the cookbook for 3.x version. When I tried to test editing another users article, which should be denied, I ran into problems with sessions not working. Here is the code of the test: [URL]

The error it causes is: Fatal error: Call to a member function delete() on a non-object in C:\...\cakephp\src\Controller\Component\AuthComponent.php on line 660.

On the line 660, in a function _getUser(), there is: $this->session->delete('Auth.redirect');

Adding "Session" in the mocked components didn't help.

Workaround seemed to be calling this before running the action in the test:
$articles->Auth->session = new \Cake\Network\Session();
After that, the session problems disappeared. Then I ran into other problems though, but that's another topic and probably caused by my own inexperience.
Discussion
- `AuthController`'s constructor receives a controller instance and `AuthController::$session` is set to `$controller->request->session();`. So if the required object chain is not available the error is expected.

I don't see any real issue here as you can directly set the public property. Often when mocking during testing you have to directly assign properties.
- This is a known problem. We have decided to deprecate the ControllerTestCase class and replace it with another solution, more oriented towards integration testing.
- Closing as there is a pull request open
