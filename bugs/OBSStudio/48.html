Title

Changing Global Audio Devices settings can produce sources with duplicate names if manually added to scenes

Description
### Operating System Info

Windows 10

### Other OS

_No response_

### OBS Studio Version

27.1.3

### OBS Studio Version (Other)

_No response_

### OBS Studio Log URL

[URL]

### OBS Studio Crash Log URL

_No response_

### Expected Behavior

Changing the Global Audio Devices options in Settings shouldn't produce name conflicts.

### Current Behavior

Changing the Global Audio Devices options in Settings can produce name conflicts if the underlying source has been added to a scene using "Add Existing".

### Steps to Reproduce

1. Set a Global Audio Device to some valid device and hit OK/Apply.
2. Add an Audio Input/Output Capture source and use add existing to pick the Global Audio Device.
3. Go back to Global Audio Device settings, change the device to disabled, then hit Apply.
4. Set the Global Audio Device back to some valid device and hit OK/Apply.
5. Repeat.

- The root cause of name conflicts in the scene item list probably lies in the fact that scene item uses name of its source as its name while scene items are allowed to have the same source. It should be noted that sources themselves have checked unique names, but more than one scene items are using the name of one source. 

The simplest approach is to prevent scene items from using the same source, as it was in my last pr. But it is pointed out that users will not expect this, while you cannot duplicate sources directly sometimes, so the only approach is to add independent
name property for scene items. But this involves bunches of parts in, like releasing memory usage, which may cause further problems, and i'm confusing about it. 

In the current version, name of scene item is name of its source. So in most cases, when you get name of scene item, `obs_source_get_name(item->source)` is used. When you rename scene item, you rename the source, then other scene items using the same source. Adding independent name property for scene items means you leave name of sources away, which is nonsense.
- I didn't expect that name conflicts in source list would be intentional, so i totally mistook the point last time. The problem is specific to global audio sources.
