Title

mitmdump crashes when mutating recorded responses with the kill flag

Description
##### Steps to reproduce the problem:
1. Record a website using `mitmdump --anticache -w out.tmp`.
   
   For the sake of the example, record the JSON file at [URL]
2. Replay the website using `mitmdump --anticache -S out.tmp -s proxy.py --no-pop --kill`, where `proxy.py` mutates some responses from the recording.
   
   For the sake of the example, use the following `proxy.py` file, that pretty prints JSON files:
   
   ```
import json
   
   from mitmproxy.script import concurrent
   
   def prettyjson(input):
... [Log Snipped] ...
       flow.response.content = prettyjson(flow.response.content)
     print('finish response: %s%s' % (flow.request.host, flow.request.path))
```
##### What is the expected behavior?

The JSON file in the recording gets pretty printed when visiting [URL]
##### What went wrong?

A crash occurs:

```
start request: users-cs.au.dk/cqa/mitmproxy.json
finish response: users-cs.au.dk/cqa/mitmproxy.json
  GET [URL]
[replay]  << 200 OK 34B
start request: users-cs.au.dk/favicon.ico
... [Log Snipped] ...
    self._list.remove(f)
ValueError: list.remove(x): x not in list
```
##### Any other comments?

The bug only manifests when using `@concurrent` and `--kill` at the same time, and therefore may be related to #1061.

Mitmproxy Version: [Link: master] (0.18)
Operating System: Ubuntu 14.03.3
Discussion
- Update: it is not necessary to mutate the response, the following script suffices to make it crash:

```
from mitmproxy.script import concurrent

@concurrent
def request(context, flow):
    print('start request: %s%s' % (flow.request.host, flow.request.path))

def response(context, flow):
    print('finish response: %s%s' % (flow.request.host, flow.request.path))
```

It seems that visiting any website that is not available in the recording provided using `-S` makes mitmproxy crash, when `@concurrent`, `-s` and `--kill` are all used at the same time.
- I just commited a fix for this on master. :tada:
