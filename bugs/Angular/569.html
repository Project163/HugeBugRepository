Title

Template Parse errors in templates are missing the error message itself

Description
**Reproduction**
```
  
```
Leads to the error message:
```
Error at /Users/tbosch/projects/repro/issue-19485/src/index.html(1,11):  (" ]let-x> ")
```

Expected:
```
Error at /Users/tbosch/projects/repro/issue-19485/src/index.html(1,11): "let-" is only supported on ng-template elements. (" ]let-x> ")
```

**Note: HTML errors are reported correctly**
E.g.
```
  
```
Results in
```
Error: Template parse errors:
Void elements do not have end tags "input" (" [ERROR ->] "): /Users/tbosch/projects/repro/issue-19485/src/index.html@0:7
```

(b/68742933)

**Analysis**
This bug has been there since we used the new transformer based compiler.

In `ParseError.contextualMessage` [Link: see parse_util.ts] we don't include `this.msg`. However, this method is used in [Link: program.ts] to create diagnostics.

**Proposed solution**
Change `ParseError.contextualMessage` to include `this.msg` as a prefix.
