Discussion
- Caused by a bug in `CatalogManager::CleanupHiddenTables`. This function can pass `TableInfo` objects to the `DoMutateItem` API without first acquiring a write lock on them if a race is triggered. The `DoMutateItem` API segfaults when performing a write op on an object that doesn't have a write lock taken on it.
- Some ideas for longer term fixes to lurking segfaults caused by improper use of the sys catalog mutation API:

- refactor to take a `WriteLock` instead of the COW object. Lots of work.
- just skip writes to objects that don't have a `WriteLock` on them instead of crashing.
