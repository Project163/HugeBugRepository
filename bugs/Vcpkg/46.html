Title

VTK does not compile

Description
```
-- CURRENT_INSTALLED_DIR=C:/Libs/vcpkg/installed/x64-windows
-- DOWNLOADS=C:/Libs/vcpkg/downloads
-- CURRENT_PACKAGES_DIR=C:/Libs/vcpkg/packages/vtk_x64-windows
-- CURRENT_BUILDTREES_DIR=C:/Libs/vcpkg/buildtrees/vtk
-- CURRENT_PORT_DIR=C:/Libs/vcpkg/ports/vtk/.
... [Log Snipped] ...

Error: Building package vtk:x64-windows failed with: BUILD_FAILED
```
*-rel-out.log contains: `LINK : fatal error LNK1181: cannot open input file 'hdf5-shared.lib'`. Indeed, file `hdf5-shared.lib` does not exist on my computer, but rather `hdf5.lib`.

@RobertSpir Did you test VTK installation with shared libraries or only static libraries?
Discussion
- hdf5's CMake configure files provide a target named "hdf5-shared" which _should_ cause linking against `hdf5.lib` and inclusion of the appropriate header directory. I've done some initial debugging and it looks like the target is defined as expected (VTK does pick up the CMake files, etc).

However, somehow, the actual link process is resolving `hdf5-shared` as a library name instead of a target.
- The problem is in the `FindHDF5.cmake` under C:\vcpkg\buildtrees\vtk\src\VTK-7.1.0\CMake:

```
# include the default FindHDF5.cmake.
if(CMAKE_VERSION VERSION_LESS 3.6.1)
  include(${CMAKE_CURRENT_LIST_DIR}/NewCMake/FindHDF5.cmake)
else()
  include(${CMAKE_ROOT}/Modules/FindHDF5.cmake)
endif()
```

Since the version of CMake that comes with VS2017 is a fork of CMake 3.6 with version number 3.6.20160606-g0391f-MSVC, the lines above pick the `Modules/FindHDF5.cmake` from this version, which causes this behaviour.

It should pick the `FindHDF5.cmake` that comes with vtk in the NewCMake folder, that will put together the right library path and names for hdf5.

To solve this issue I just commented the if-else-clause out and included the `NewCMake/FindHDF5.cmake` version directly. ~~Though I'm not sure why the default `FindHDF5.cmake` was included in the first place.~~ This seems to be related to a bug [Link: here] and a fix [Link: here], but I don't think those apply to vcpkg.
- I ran into the same problem and @phsucharee 's temporary fix works for me.
