Title

Final result ignored when chord is the penultimate task (using apply_async)

Description
When a chain contains a chord as its penultimate task, such as

``` python
my_chord = group(task1.s(),task1.s()) | task2.s() 
my_chain = my_chord | task3.s()
result = my_chain.apply_async().get()
```

The result returned is the result of my_chord, not my_chain.  Note that this bug only shows up when using apply_async.  Synchronous application works fine.  I saw this bug with celery 3.1.13 using the redis backend.
