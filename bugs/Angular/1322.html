Title

`RouteConfigLoadEnd` event emitted multiple times

Description
## I'm submitting a...
  
[X] Bug report
  

## Current behavior
When lazy-loaded modules are being preloaded (using `PreloadAllModules` strategy or a custom strategy) and a navigation starts to a module that is currently being preloaded, `RouteConfigLoadEnd` event is emitted twice because `RouterConfigLoader.load` is called twice and it calls `onLoadEndListener` twice ([Link: code here]).

## Expected behavior
`Router` emits `RouteConfigLoadEnd` event only once for a lazy-loaded route.

## Minimal reproduction of the problem with instructions
Use `PreloadAllModules` strategy and after `RouteConfigLoadStart` even is emitted, but before `RotueConfigLoadEnd` happens, call `router.navigate` or `router.navigateByUrl` to the currently pre-loaded module. If you enable tracing, you will see two `RouteConfigLoadEnd` event is being logged in the console.

## What is the motivation / use case for changing the behavior?
When listening to `Router` events, it is not expected that this event is emitted multiple times for the same route. In our case, we need to create a lookup for route config and without having an extra safe-check in our code-base, items will be added multiple times.


## Environment

  
Angular version: 5.2.8
Chrome (desktop) version 65
