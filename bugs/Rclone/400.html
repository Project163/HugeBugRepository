Title

ncdu listing failed: strconv.ParseInt: parsing "1.54854926086E 12": invalid syntax

Description
#### What is the problem you are having with rclone?

I am trying to run `rclone ncdu` on a Backblaze B2 bucket. It starts listing files and directories inside of the bucket but then after about 5 seconds, it consistently fails with the following error message:

```
Failed to ncdu: ncdu directory listing: ncdu listing failed: strconv.ParseInt: parsing "1.54854926086E 12": invalid syntax
```

#### What is your rclone version (output from `rclone version`)

```
rclone v1.46
- os/arch: darwin/amd64
- go version: go1.11.5
```

#### Which OS you are using and how many bits (eg Windows 7, 64 bit)

Apple macOS Mojave 10.14.3 (18D109) [64-bit]

####  Which cloud storage system are you using? (eg Google Drive)

Backblaze B2

#### The command you were trying to run (eg `rclone copy /tmp remote:tmp`)

```
rclone ncdu b2: 
```

#### A log from the command with the `-vv` flag (eg output from `rclone -vv copy /tmp remote:tmp`)

```
2019/03/22 16:39:57 DEBUG : rclone: Version "v1.46" starting with parameters ["rclone" "-vv" "ncdu" "b2: "]
2019/03/22 16:39:57 DEBUG : Using config file from "~/.config/rclone/rclone.conf"
2019/03/22 16:40:03 Failed to ncdu: ncdu directory listing: ncdu listing failed: strconv.ParseInt: parsing "1.54854926086E 12": invalid syntax
```
Discussion
- What that means is that the JSON info backblaze is sending back has a floating point number in it where rclone is expecting an integer.  That particular floating point number looks malformed too which makes me wonder if this is a b2 bug...

1.5E12 would be 1.5 TB - do you have any files that big? If you do then just running `rclone ls b2:bucket/path/to/file` will probably provoke the bug.

I'd really like to see the request and response from b2.  You can get this by adding `-vv --log-file b2.log --dump bodies` to your `rclone ncdu` command.

Can you attach (or email me at nick@craig-wood.com with a link to this issue) that log?  Or maybe you can figure out which one the bad response is and just post that and the corresponding request (you can match them up with the hex number).

If it is a b2 bug I know the right people to report it to :-)
- Thanks for your help! Yes, I do believe this is a Backblaze B2 bug because, as you said, the JSON response appears to have a malformed value for `src_last_modified_millis` (i.e. space character between "E" and "12"). Here is the relevant excerpt of the debug info you requested:

