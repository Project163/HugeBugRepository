Title

IIFE format does not expose named defaults when moduleName contains multiple parts

Description
If you go to [URL] select the _Named Exports_ example, switch the format to `iife`, and add a `.` to the module name (e.g. `myModule.subModule`), the `return exports;` statement at the end of the generated bundle is removed.

This is not an issue if there is only a `default export`, but shows up when named exports are in use (whether there is a `default export` or not).

An example is [URL]
Discussion
- This appears to be related to #1472 @Andarist . If you use the `extend` option, it should work correctly (but the REPL does not give you the opportunity to do this so you'll have to verify with a local project). I believe that there are a couple possible ways to approach fixing this:

1. Modify [Link: this `if` statement] to throw when using a name spaced `moduleName`, but not `extends`.
```js
if ( name && (possibleVariableAssignment && !isLegal(name)) || (isNamespaced && !extend) ) {
```
2. Make `extends` true by default when using a name spaced `moduleName`. Does that defeat the purpose of the option, though?
3. Modify `extends` to be the extended string instead of a boolean.
```
js
{
  moduleName: 'myModule',
  extends 'subModule'
}
... [Log Snipped] ...
  extends: 'one.two.three'
}
```
