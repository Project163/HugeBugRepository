Title

using dependent as destroy, destroy do not fails if associated objects fails the destroy

Description
Example:

``` ruby
class Category   :destroy
end
```

```
ruby
class Post   "Category A")
Post.create!(:category => Category.first, :title => "Post A")

Category.first.destroy
... [Log Snipped] ...
Post.first
#=> # 
```

My real scenario is a bit more complex due to foreign keys, dependent restrict and others models before the model that fails the destroy due to a complex restriction.

Anyway, that code reproduce the issue :)

- @carlosantoniodasilva Any updates on this issue? It seems I have the same problem...
- From what I see, it seems that the issue has to do with the way Rails handles transactions.
When `ActiveRecord::Rollback` is raised it is rescued silently by the closest transaction block. However since in case of dependent destroy the two transaction blocks (initial destroy, and dependent destroy) the exception is rescued  from the inner transaction block and the rollback never happens (for details on this one you can check the section Nested Transactions in [URL] I am not sure if it is an easy fix, but it seems that the solution should be to re-raise `ActiveRecord::Rollback` transactions in case the transaction block is running within another block. /cc @carlosantoniodasilva
