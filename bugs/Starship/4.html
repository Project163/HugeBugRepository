Title

Starship panics if pwd does not have read permission

Description
## Bug Report

#### Current Behavior

If pwd has permission `--x` (no read but allow navigation), starship panics with "Unable to read current directory". cd into these dirs works, though ls also fails with `
ls: cannot open directory '.': Permission denied`

#### Expected Behavior

No error.

#### Additional context/Screenshots

```
❯ cd /var/lib/docker
thread 'main' panicked at 'Unable to read current directory: /var/lib/docker', src/context.rs:57:17                          
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace.
ls -alh
ls: cannot open directory '.': Permission denied
... [Log Snipped] ...
❯ ls -alh
drwx--x--x 1 root         root          188 Jun 30 15:51 docker
```

#### Environment
- Starship version: starship 0.17.0
- Shell type: zsh
- Shell version: zsh 5.7.1 (x86_64-pc-linux-gnu)
- Shell plugin manager: oh-my-zsh
- Terminal emulator: kitty
- Operating system: Arch
Discussion
- Duplicated #204.

The error will be generated when executing std::env::current_dir(). [Link: See the docs]
- Not really the same issue as in this case the directory exists, it is just not readable. But I guess it's caused by the same function call.
- Yes, as the doc notes, the function will throw the error in the following conditions

- Current directory does not exist.
- There are insufficient permissions to access the current directory.

Should also be fixed if the error got properly handled.
