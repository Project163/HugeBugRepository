Discussion
- I don't think those were meant to be public. 
possibly we want parquet.hadoop.metadata to be blacklisted in the semver plugin.
- I'm currently testing a fix where parquet-common defines parquet.common.internal.ColumnPath, and both ColumnPath and Canonicalizer are added back to parquet.hadoop.metadata for compatibility. I agree that we want to limit what we're going to expose in this package after the next breaking API change, but for now I think we should go with the compatibility guarantee.
- Adding PR #166 with the fix. This required moving the classes back into parquet.hadoop.metadata. The subclass strategy doesn't work because ColumnPath is final so that it can be canonicalized. 

 Canonicalization allows code to determine equivalence using equality, which means there can be no subclasses. The ColumnPath implementation is correctly marked final to prevent bad behavior, but it precludes options for compatible migrations.
