Discussion
- Documentation [Link: states that `lenient` parameter is supported], but the update by query api doesn't support this. Either the documentation should be changed or support for `lenient` should be added to this api.
- Pinging @elastic/es-distributed (Team:Distributed)
- I tried to find the source of the lenient option. It looks like it is also stated in the [Link: search explain docs] as well as in [Link: search.json]. It was removed from search docs in #55884. I am guessing that it was an option for search in general in the past, which has later been removed, but I have not been able to find the change for this. I hope someone from @elastic/es-search can help confirm that the option was intentionally removed (I can take care of removing it from all these places afterwards).
- AFAICS, the `lenient` option is only available as a URL parameter for query string queries that are specified as URL parameter (i.e., searches where the query is specified as a URL parameter, using `?q=...`, see [URL] and also the corresponding code in `RestActions.urlParamsToQueryBuilder`)

Without query string present (i.e. `?q=`), use of this parameter will fail (so will others such as `default_operator`, `analyze_wildcard`, `analyzer`, and `df`). We should amend the docs.
