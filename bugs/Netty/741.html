Title

HttpMessages implementing HttpContent types too aren't handled correctly

Description
Changes due to #12709 have added a code path where `HttpMessage` types that implement `HttpContent` types too are handled in their separate code paths while handled as just `HttpMessage` right after too.

The fact that CI doesn't fail there means that there are no types like that (and it's not impacting existing users using default types too).
Discussion
- All subclasses of `io.netty.handler.codec.http.FullHttpMessage` was affected. In our case it is `AggregatedFullHttpRequest`.
