Title

Client does not correctly close QueueBrowsers.

Description
Summary: 

 QueueBrowsers are sent an unsolicited CancelOK from the Java broker automatically when there are no more messages. Currently we don't handle this correctly. What needs to occur is that the Browser needs to wait for all messages in the _synchronousQueue AND any potentially pending message in the dispatcher queue OR that the dispatcher is currently processing to be delivered. 

 One approach for this is to add a special CloseConsumer message to the dispatcher queue so it can cleanly close the browser when all messages have been processed.
Discussion
- This was a faily large change that ended up putting a new message type on the dispatcher queue so we know when all msgs have been processed for a give consumer(browser). When that is reached the consumer can self close.
