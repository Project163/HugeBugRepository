Title

3.0 Error loading plugin controllers -> actions in the browser

Description
After the last update trying to visit the following address in my project return a not found exception

```
/users/manage
```

```
Error: Create the class UsersController below in file: src\Controller\UsersController.php
```

users is a plugin called Users and manage the Controller
before the update all worked well, already upgrade the app and the new routes too, but I still receiving the same exception. Cake try to find in src\Controllers instead of inside the plugin

Now I try with a blank Project with the last update of app and vendor and creating a plugin with bake, but does not work. However the following code

``` php
debug(Plugin::loaded());
```

return fine the list of all loaded plugins, including the plugin  "Users"

that I can be doing wrong?
Discussion
- Router no longer generates fallback routes for applications, have you made sure to connect routes for your plugin?
- routes for plugin should be declared manually under scope? I note now that the files routes.php under the cake/Config has been deleted and that  contain these statements to load all plugin routes, I understand now that the goal is to force set plugin routes. :+1:  that's it? 

as enhancement, maybe the plugins loaded with [ routes => true ] should be generate these routes automatically too
- Yes, the goal is to require all routes to be explicit. A number of times people have been very confused about how routes are connected, and where they come from. Having people define them removes all the magic and makes it really clear how routes are connected.

The `cake bake plugin` task has already been updated to generate a routes file for each new plugin going forward.
