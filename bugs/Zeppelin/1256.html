- If you experience this problem on docker container image, a workaround is set  HOME  environtment variable to  /zeppelin . 

 For example 
  
 
 docker run -p8080:8080 --rm -e HOME=/zeppelin -e ZEPPELIN_HELIUM_REGISTRY=helium,https: //s3.amazonaws.com/helium- package /helium.json apache/zeppelin:0.9.0

- I've also run into this problem with the kubernetes zeppelin deploy. 

 For the 0.9.0 image the home has to be set to '/opt/zeppelin/' as that's the only directory the default 'zeppelin' user has write access on.
- I moved to the newer version 0.10.0 and setting the home dir to /opt/zeppelin/ helped fixing the issue
