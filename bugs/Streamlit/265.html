Title

Enter to submit forms: submit instructions do not always show, even if Enter will submit the form

Description
### Checklist

- [Link: X] I have searched the [existing issues] for similar issues.
- [X] I added a very descriptive title to this issue.
- [X] I have provided sufficient information below to help reproduce this issue.

### Summary

With Streamlit 1.25.0 you can now Enter to submit a from from `st.text_input`, `st.text_area`, and `st.number_input`.

Submit instructions appear in those widgets mentioned above when a user makes a change to them. However, if a user leaves and returns to the widget without submitting the form, the submit instructions no longer appear. Nevertheless, Enter will still submit the form. This may be confusing and result in unintentional submissions.

Similarly, if a user makes no change to one any of the widgets in a form, the submit instructions do not appear when active in one of the widgets, but the form can still be submitted with Enter from such a widget.

### Reproducible Code Example

```
Python
import streamlit as st

col1, col2 = st.columns(2)

... [Log Snipped] ...
col2.write('Text input: ' + inside_text)
col2.write('Text area: ' + inside_area)
```

### Steps To Reproduce

1. Change the value in a widget within the form
2. See submission instructions
3. Click out of the widget
4. Click back into the widget
5. See there are no submission instructions
6. Press enter (or Cmd/Ctrl+Enter) and see that the form still submits

[Image: Forms]

### Expected Behavior

Since the Enter-to-submit functionality is always active when active/focused in `st.text_input`, `st.text_area`, or `st.number_input` in a form, the submission instructions should always display when active/focused in those widgets within a form.

### Current Behavior

The Enter-to-submit instructions only display if you have edited that widget and haven't left the active/focus state for it. This is likely a carryover effect since widgets outside of forms will not trigger a rerun if submitted (Enter) when containing the same value as they had on the last rerun.
