Title

Incorrect comment assigned to function expression

Description
With the change in  , an incorrect comment block may be assigned to a function expression.

This used to pass `valid-jsdoc`, now it generates `Missing JSDoc @returns for function`:

```
js
/* eslint valid-jsdoc: [2, {requireReturn: false}] */

/**
 * Create a new thing.
... [Log Snipped] ...
  }
});
```
Discussion
- And this was working before that commit was merged?
- I should say, what did it do before? (Please note the instructions in [URL] for reporting a bug
- This looks like a regression introduced by  

Here is the source code and complete config (same as in the original description):

```
/* eslint valid-jsdoc: [2, {requireReturn: false}] */

/**
 * Create a new thing.
 */
... [Log Snipped] ...
  }
});
```

```
$ git checkout  
$ node bin/eslint.js --no-eslintrc script.js

/Users/tschaub/projects/eslint/script.js
  3:1  error  Missing JSDoc @returns for function  
```

I would expect the above code to be valid according to `valid-jsdoc`.  The documentation block is not associated with the function expression.

Prior to  , the `valid-jsdoc` rule treated this code as valid (as it should):

```
$ git checkout  ^
$ node bin/eslint.js --no-eslintrc script.js
$
```

The issue is that the `sourceCode.getJSDocComment()` traverses up to the assignment expression, finds the leading comments, and returns these as the comment associated with the function expression.
- @nzakas let me know if the description above is still not clear.  The change in #4926 corrects this particular case.
