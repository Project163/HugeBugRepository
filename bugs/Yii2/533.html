Title

ActiveRecord tries to 'get' write-only properties marked as 'safe' when validating

Description
I wish to massively assign a write-only property, for example password:

```
// In ActiveRecord extension
...

public function rules(){
    return [...
... [Log Snipped] ...

... no getter ...
```

When validating I get `Exception: Getting write-only property`. It appears that the validation function is attempting to retrieve the attribute `password` unnecessarily, perhaps even creating a superfluous Validator.
Discussion
- It's not a bug. Attribute getting is required for validation (see [Link: Validator::validateAttributes():251]

You can implement null-returning getter, if you do not want to expose password after it was set.
- Well, I could add a null-returning getter.. but that isn't really appropriate, doesn't really make sense and has an effect on other areas of the code. I'd much rather the AR kept throwing the exception if an attempt is made to access the attribute.

'Attribute getting is required for validation', isn't really an answer. Safe write-only attributes don't need to be validated or ever retrieved. I think this a product of the design decision to use an extra special 'validator' to mark an attribute safe or unsafe for massive assignment. 

I suppose I can always overwrite the `safeAttributes()` function to something more flexible....

- Okay, I see that overriding validateAttribute**s**() would work.
