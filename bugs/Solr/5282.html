Title

"Global" Circuit Breakers can trigger ConcurrentModificationException on Solr startup

Description
On startup, each Solr process will attempt to load each of the cores that it hosts (potentially in parallel).  Each core gets its own "CircuitBreakerRegistry".  And on creation, these registries attempt to initialize some static state representing any global circuit-breakers. 

 This can lead to a race where multiple loading cores attempt to modify the same static state, resulting in a ConcurrentModificationException. 

 We should either have CircuitBreakerRegistry use a ConcurrentHashMap, or put some other locking in place to make the global CB state more resilient to races.
