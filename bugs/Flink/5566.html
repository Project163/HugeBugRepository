Title

There is some mismatches between the current translation and the latest English version on the Flink-Architecture page

Description
There is some mismatches between the current translation and the latest English version on the Flink-Architecture page 

   

   

 The original English text is as follows( [URL]

  ​ 
  
 
A Flink Application is any user program that spawns one or multiple Flink
 jobs from its ``main()`` method. The execution of these jobs can happen in a
 local JVM (``LocalEnvironment``) or on a remote setup of clusters with multiple
 machines (``RemoteEnvironment``). For each program, the `ExecutionEnvironment`
 provides methods to control the job execution (e.g. setting the parallelism) and to interact with
 the outside world (see [Link: Anatomy of a Flink Program]).
 ​
 The jobs of a Flink Application can either be submitted to a  long -running
 [Link: Flink Session Cluster], a dedicated [Flink Job
 Cluster](< ref  "docs/concepts/glossary"  >#flink-job-cluster), or a
 [Link: Flink Application Cluster]. The difference between these options is mainly related to the cluster’s lifecycle and to resource
 isolation guarantees.

 Flink 应用程序 是从其 ``main()`` 方法产生的一个或多个 Flink 作业的任何用户程序。这些作业的执行可以在本地 JVM（`LocalEnvironment``）中进行，或具有多台机器的集群的远程设置（``RemoteEnvironment``）中进行。对于每个程序，[Link: ``ExecutionEnvironment``] 提供了一些方法来控制作业执行（例如设置并行度）并与外界交互（请参考 [Link: Flink 程序剖析] ）。
 ​
 Flink 应用程序的作业可以被提交到长期运行的 [Link: Flink Session 集群]、专用的 [Link: Flink Job 集群] 或 [Link: Flink Application 集群]。这些选项之间的差异主要与集群的生命周期和资源隔离保证有关。
