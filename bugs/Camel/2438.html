Title

camel-blueprint - Using and referrring to SSLContextParameters with property placeholders can lead to CircularDependencyException

Description
Configuring a blueprint xml file with 
  
     <endpoint id= "myNettyServer"  uri= "netty-http:http: // :{{port}}/foo?ssl= true &amp;sslContextParameters=#mySsl" />

Discussion
- The problem is only when you define a SSLContextParameters which you refer to from <endpoint> 

  
   <camel:sslContextParameters id= "mySsl" >
    <camel:serverParameters clientAuthentication= "REQUIRE" />
    <camel:keyManagers keyPassword= "changeit" >
      <camel:keyStore resource= "etc/localhost.ks"  password= "changeit" />
    </camel:keyManagers>
    <camel:trustManagers>
      <camel:keyStore resource= "etc/localhost.ks"  password= "changeit" />
    </camel:trustManagers>
  </camel:sslContextParameters>
 
  

 And with endpoint 
  
     <endpoint id= "myNettyServer"  uri= "netty-http:http: // :{{port}}/foo?ssl= true &amp;sslContextParameters=#mySsl" />
