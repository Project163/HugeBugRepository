Title

Factory Configuration may get corrupted

Description
The Configuration Admin service implementation internally keeps a Factory objects which in turn refers to the PIDs belonging to the factory. This reference to the PIDs may get lost when a Factory object is loaded. 

 The problem is, that the constructor calls the setBundleLocation method which stores the object but looses the PID references.
Discussion
- The constructor setting the bundle location field is called when the Factory object is loaded, therefore storing the bundle location is of no use there. Hence, the field is just set, as is the set of PIDs belonging to the Factory. 

 Fixed in Rev. 530358 

 Also deployed snapshot
- Seems to fix the issue.
