Title

ILM policies with searchable_snapshot and allocate in the cold phase will get stuck

Description
**Elasticsearch version** (`bin/elasticsearch --version`): 7.14.1

**Description of the problem including expected versus actual behavior**:

If an ILM policy uses both `searchable_snapshot` and `allocate` in the cold phase, then the `allocate` action won't work right, and in fact will get wedged permanently (see workaround below for how to unstick it).

**Steps to reproduce**:

```
PUT _cluster/settings
{
  "transient": {
    "indices.lifecycle.poll_interval": "30s"
  }
... [Log Snipped] ...
  "field1": "someValue2"
}
```

Once the policy gets to the `allocate` action & step, it'll just sit there forever:

```
GET test-index-1/_ilm/explain
{
  "indices" : {
    "restored-test-index-1" : {
      "index" : "restored-test-index-1",
... [Log Snipped] ...
  }
}
```

**Workaround**:

For any stuck indices, if you manually move the stuck index to complete, then everything will pick back up.

```
POST /_ilm/move/restored-test-index-1
{
  "current_step": {
    "phase": "cold",
    "action": "allocate",
... [Log Snipped] ...
  }
}
```
Discussion
- Pinging @elastic/es-data-management (Team:Data Management)
- Notes for myself from a previous conversation about this issue -- in terms of the underlying details, this happens because `SearchableSnapshotAction` has code like this:

```
        CopyExecutionStateStep copyMetadataStep = new CopyExecutionStateStep(copyMetadataKey, copyLifecyclePolicySettingKey,
            (index, executionState) -> getRestoredIndexPrefix(copyMetadataKey) + index, nextStepKey);
```

but in this case the first step of the `AllocateAction` (which the `nextStepKey` above would be referencing in this case) is an `UpdateSettingsStep`:

```
        UpdateSettingsStep allocateStep = new UpdateSettingsStep(allocateKey, allocationRoutedKey, client, newSettings.build());
        AllocationRoutedStep routedCheckStep = new AllocationRoutedStep(allocationRoutedKey, nextStepKey);
```

and an `UpdateSettingsStep` is an `AsyncActionStep`:

```
public class UpdateSettingsStep extends AsyncActionStep {
```

Every `AsyncActionStep` needs to be invoked (once) via a call to `org.elasticsearch.xpack.ilm.IndexLifecycleRunner#maybeRunAsyncAction`, but we don't currently have code to do this associated with all possible routes through ILM where a new concrete index is created (for example, with the `searchable_snapshot` and `shrink` actions, which are the current callers of `CopyExecutionStateStep`).
