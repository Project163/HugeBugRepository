Title

Chunk missing from runtime with `splitChunks.chunks: 'all'`.

Description
**Do you want to request a *feature* or report a *bug*?**
bug
 
 

**What is the current behavior?**
With `splitChunks.chunks: all` and the runtime chunk enabled, webpack attempts to load a chunk with id `1` that does not exist in the runtime. This causes the browser to make a request for a file with `undefined` in the file name.

**If the current behavior is a bug, please provide the steps to reproduce.**
excerpt from runtime chunk (notice a value for `1` is missing)
```
c.src = n.p + "buyer-mobile-" + ({
                    0: "vendors~AddToFolderModalWrapper~MultiRequestModal~PdpSharedCallDealerModalWrapper~PdpSharedDealerDet~a4eb5b0f",
                    2: "vendors~AddToFolderModalWrapper~MultiRequestModal~PdpSharedCallDealerModalWrapper~PdpSharedDealerDet~0160e5e7",
                    3: "SendToFriendModal",
                    4: "vendors~AuthModal",
... [Log Snipped] ...
                    23: " "
                }[e] + ".js";
```
The browser tries to load `buyer-mobile- .undefined.js`

Full stats are here: [URL]

**What is the expected behavior?**
Browser should successfully load the chunk

**Please mention other relevant information such as the browser version, Node.js version, webpack version, and Operating System.**
webpack 4.4.1, node v8.9.3, linux
Discussion
- Can you create a minimum reproducible test repo?
- I have not been able to create a minimum reproducible test repo yet as I have not yet figured out what specifically in my compilation is triggering this issue. I have debugged enough to understand the basic reason for this problem.

#### EntryPoint
* `pdp-mobile`
* * does not contain `chunkId 1`
* `sb-mobile`
* * contains `chunkId 1`

#### ChunkGroups
* `MultiRequestModal`
* * contains `chunkId 1`

When the `MultiRequestModal` async chunk is loaded on the `pdp-mobile` page, webpack attempts to load `chunkId 1` because it is a requirement of that chunk and not already loaded. However, the runtime `chunkMap` does not contain `chunkId 1` because it is excluded by `Chunk#getAllAsyncChunks` when it is generated (because it is part of the sb-mobile EntryPoint). 

Is it normal for a chunk to be a dependency of both an entry point and an async chunk?
- @Legends I was able to create a minimum reproducible test repo here: [URL]
- This looks like a bug to me.

The app  works fine in `--mode development`.
In `--mode production` it only works when `runtimeChunk` is set to:

```
optimization: {
        runtimeChunk: "multiple" | true  // <-- "single" fails here!
```

```
optimization: {
runtimeChunk: {
            name: `my-runtime`,  // <-- fails
        },
```
