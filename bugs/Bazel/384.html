Title

bazel 0.4.5 extra actions broken with sandboxing

Description
Please provide the following information. The more we know about your system and use case, the more easily and likely we can help.

### Description of the problem / feature request / question:

Running extra actions fails in bazel 0.4.5. Things were working in bazel 0.4.3.

In the below example, "--config=tidy" adds --experimental_action_listener to run a clang-tidy-3.8 wrapper program.

```
bazel build --config=tidy -- //foo:bar
ERROR: /foo/BUILD:6:1: Executing extra_action //build/clang_tidy:clang_tidy_action on //foo:bar failed: Process exited with status 1 [sandboxed].
error: error reading '/.../ /bazel-sandbox/d83eb7c2-495e-4025-9d4f-ffadff309d35-13/execroot/foo/foo/bar.cc' [clang-diagnostic-error]
1 error generated.
Error while processing /.../ /bazel-sandbox/d83eb7c2-495e-4025-9d4f-ffadff309d35-13/execroot/foo/foo/bar.cc.
clang_tidy_runner: ERROR: Build error. See [URL] for details
Use --strategy=clang_tidy_action=standalone to disable sandboxing for the failing actions.
WARNING: Cannot delete sandbox directory after action execution: /.../ /bazel-sandbox/d83eb7c2-495e-4025-9d4f-ffadff309d35-24 (java.io.IOException: /.../ /bazel-sandbox/d83eb7c2-495e-4025-9d4f-ffadff309d35-24/execroot/foo (Device or resource busy)).
```

The suggested workaround of using standalone seems to work.
