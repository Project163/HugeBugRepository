Title

valid-jsdoc: Throws exception when @returns has no type

Description
Given `test.js`:

```
/**
 * @returns something
 */
function foo() {

}
```

When I run `eslint --rule 'valid-jsdoc: 1' test.js`:

Then:

```
node_modules/eslint/lib/rules/valid-jsdoc.js:69
        return tag.type.name === "void" || tag.type.type === "UndefinedLiteral";
                       ^

TypeError: Cannot read property 'name' of null
```

If the JSDoc comment instead reads:

```
/**
 * @returns {string} something
 */
```

Then ESLint runs as expected with no output. 

Run with ESLint 1.9.0, Node v4.1.2 and NPM 3.4.0.
Discussion
- I have not checked with `doctrine` but could be bug in the parser.
- Looks like we are assuming that the return always has a type, but it doesn't have to. This is an ESLint bug.
