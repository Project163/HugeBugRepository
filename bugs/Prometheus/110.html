Title

NHCB conversion corrupts data

Description
### What did you do?

I configured prometheus 3.5.0 to convert all classic histograms to NHCB and send them to mimir 2.17

### What did you expect to see?

I expected all histograms to be converted and reach mimir

### What did you see instead? Under which circumstances?

Some time series were not converted properly, and mimir refused them with the following error message:

```
time=2025-09-03T12:29:40.728Z level=ERROR source=queue_manager.go:1668 msg="non-recoverable error" component=remote remote_name=a5a23e url=[URL] failedSampleCount=1932 failedHistogramCount=68 failedExemplarCount=0 err="server returned HTTP status 400 Bad Request: send data to ingesters: failed pushing to ingester mimir-testing-ingester-zone-a-0: user=anonymous: err: custom buckets: only 0 custom bounds defined which is insufficient to cover total span length of 5: histogram custom bounds are too few. timestamp=2025-09-03T12:29:40.452Z, series=[{__name__ cortex_request_message_bytes} {cluster global-testing} {container ingester} {endpoint http-metrics} {garden global} {instance  :8080} {job mimir-testing/ingester} {method gRPC} {namespace mimir-testing} {pod mimir-testing-ingester-zone-a-1} {prometheus monitoring-testing/clustermon-global-testing-prometheus} {prometheus_replica prometheus-clustermon-global-testing-prometheus-0} {route /cortex.Ingester/QueryExemplars} {service mimir-testing-ingester-zone-a}] (err-mimir-native-histogram-custom-buckets-mismatch) (sampled 1/10)\n"   
```

This happened with multiple services, the jobs hitting this error included mimir-testing/ingester, kubelet, loki-testing/ingester, apiserver, traefik

These specific timeseries were never converted properly, there were no datapoints in mimir in the 25 minutes while this configuration running. Other timeseries for the same metric name went through fine.

the problem is that Remote-Write 1.0 does not actually support NHCB, but doesn't drop and log NHCB samples which is very misleading.

For now I'll add a PR to drop NHCB and log this. 

Long term we can depend on Remote-Write 2.0 will make NHCB fully usable. Or possibly we could do RW 1.1 if that takes too long.
