Title

Azure blob integration tests broken by context propagation

Description
Eg [URL]

See [URL] for the most recent

[Image: image]

These all appear to have something to do with renaming directories...

According to git bisect this was the commit which broke it  

This added context into the interface and passed the context on to the AzureBlob SDK which doesn't look as if it should have broken anything.

The error is this

```
$ ( cd fs/operations && go test -v -remote TestAzureBlob: -run TestDirMove -verbose )
=== RUN   TestDirMove
2019/06/28 14:53:16 DEBUG : A1/B2: Making directory
2019/06/28 14:53:16 DEBUG : A1/B1/C3: Making directory
2019/06/28 14:53:16 INFO  : A1/B1/three: Copied (server side copy)
... [Log Snipped] ...
exit status 1
FAIL	github.com/ncw/rclone/fs/operations	0.475s
```

Making this very small change (stopping the context propagation into the Azure SDK) fixes the problem

```
diff
diff --git a/backend/azureblob/azureblob.go b/backend/azureblob/azureblob.go
index 92c6893ec..0c54057fb 100644
--- a/backend/azureblob/azureblob.go
+++ b/backend/azureblob/azureblob.go
... [Log Snipped] ...
 	deleted := f.containerDeleted
 	f.containerOKMu.Unlock()
```

Any ideas @sandeepkru or @ajankovic ?
