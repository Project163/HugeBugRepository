Discussion
- The problem with the approach so far is that for files in subdirectories, it relies on the parent being trashed too.

However that isn't necessarily the case when a file has been trashed but the directory it is in hasn't.  In this case the file won't appear in the listings whereas drive does show it in the trash.

Instead of `trashed=true` this maybe needs a more complicated boolean such as

    (mimeType='application/vnd.google-apps.folder' or trashed=true)

This means that all directories will show in the listing which is unfortunate.  This does work, but is rather clumsy compared to the drive trash listing. 

Showing the trash is likely to show duplicate directories also.

Drive shows any trashed files directly in the trash which are in a a non-trashed directory.

Ideas

  * Can we do this with a query... Not easily...
  * Could maybe just list all files?
  * Could do a list with no parents and `trashed=true` and store it.?
    * use --fast-list
