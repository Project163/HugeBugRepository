Title

Functions that mutate exports in closure are removed

Description
If I have two files that look like this, `src/index.js`:

```
import array from './module';
array[Link: 0];
```

and `src/module.js`:

```
const array = [];
for (let i = 0; i   i);
}
export default array;
```

then run
`mkdir -p tmp && babel src -b es6.modules,strict -d tmp && rollup -f iife -i tmp/index.js -o bundle.js`

Now, `tmp/module.js` looks like this:

```
var array = [];

var _loop = function (i) {
    array.push(function () {
        return i;
... [Log Snipped] ...
}
export default array;
```

But the output in `bundle.js` does not include the loop at all:

```
(function () { 'use strict';

    var array = [];

    array[Link: 0];

})();
```

If I change the loop in `module.js` to simply `push(i)`, it works though. It seems that Rollup is not able to detect that the function Babel creates to get correct scoping for `i` will mutate `array`.

The only way I found to deal with this is to do something like this:

```
const array = [];
(function (array) {
    for (let i = 0; i   i);
    }
})(array);
export default array;
```

Any chance that Rollup will be able to handle this without workarounds?
