Title

Startup options parsing is brittle

Description
Currently, this:

`bazel test //a:a --test_arg --arg --test_output=streamed`

passes `--arg` to the test as intended. However, this:

`bazel test //a:a --test_arg --bazelrc --test_output=streamed`

Parses the argument as a `--bazelrc` startup option. This is clearly wrong.

In a wider perspective, startup option parsing contains a lot of hand-written code that needs to be kept in sync between Java and C++. Maybe we are better off generating the C++ parsing code from BlazeServerStartupOptions.java ?
