Title

JavaBinaryLauncher::CreateClasspathJar() fails on Windows if manifest_jar_path or jar_manifest_file_path contain spaces

Description
### Description of the bug:

Windows escaping was forgotten in `JavaBinaryLauncher::CreateClasspathJar()`. As result, incorrect arguments were passed to `BinaryLauncherBase::LaunchProcess`.

### Which category does this issue belong to?

_No response_

### What's the simplest, easiest way to reproduce this bug? Please provide a minimal example if possible.

Run a scenario where classpath JAR is required on Windows and the corresponding path contains spaces. 

The easiest way to reach it - create a Java project which will be compiled with Bazel on the path with spaces and try to build and to launch it via Bazel. 
It can be non-trivial to create a test project which will require classpath jar creation, so the easiest way to check the problem is getting rid of `if (classpath_str.length() > this->classpath_limit)` condition at [URL]

### Which operating system are you running Bazel on?

Windows

### What is the output of `bazel info release`?

development version
