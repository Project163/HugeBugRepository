Title

Discovering new files in a deleted directory does not resurrect the directory

Description
So for some unknown reason the puller gets stuck on some directory being unable to delete it. The directory was deleted on the remote device (don't know when exactly, maybe yesterday) but can't be removed on the local one. Here's the log:

The sync progress is stuck seemingly forever. Of course I can remove the directory, rescan and it'll work again for some days or weeks only to get stuck on another directory again. This happens regularly but I see no pattern as that happens to another Syncthing user, I only provide the server. The directories and files are renamed and deleted pretty often, not always there's a connection to the server, sometimes Syncthing disconnects and never reconnects again though Internet is working fine (subject to other issue). It's pretty long-standing now, I remember this happening even a year ago.

- Please read the docs about ignore file and it's effect on ability to remove directories.
- The .stignore file isn't used anywhere on the clients. Or am I missing something?

- This is #114 which I seem to have thought was resolved at some point. Might as well make this the new one instead.

As for solving it, I'm not sure. I guess the bug is that we don't see the dependency between the directory and it's contents. Bumping the version (and making sure things like deleted flags are set/cleared correctly) of parents on change sounds reasonable, although expensive.
- A cheaper way would be to check for the reason of a dir deletion failure: If it is due to files existing below it in the database, bump the version of the dir instead of deleting, if it is due to ignored files, give a more descriptive error message (#4476). Does that sound reasonable?
