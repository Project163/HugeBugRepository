Title

X_VCPKG_APPLOCAL_DEPS_INSTALL does not work with CMAKE_INSTALL_PREFIX without drive letter

Description
**How to reproduce**
Consider the example project in [Link: reproducer.zip]:

```
# CMakeLists.txt
cmake_minimum_required(VERSION 3.16)
project(vcpkg_prefix_issue)
find_package(fmt REQUIRED)
add_executable(myapp main.cpp)
target_link_libraries(myapp PRIVATE fmt::fmt)
install(TARGETS myapp)
```

```
// vcpkg.json
{
  "name": "myapp",
  "version-string": "1.2.3",
  "dependencies": [
    "fmt"
  ]
}
```

```
// main.cpp
#include  

int main(int argc, char *argv[])
{
    fmt::print("the magic number is {}\n", 192837);
    return 0;
}
```

configured with
```
cmake -G Ninja -DCMAKE_INSTALL_PREFIX=/my-install-root -DX_VCPKG_APPLOCAL_DEPS_INSTALL=ON -DVCPKG_TARGET_TRIPLET=x64-windows -DCMAKE_TOOLCHAIN_FILE=D:/dev/vcpkg/scripts/buildsystems/vcpkg.cmake ${source-dir}"
```

Note that `CMAKE_INSTALL_PREFIX` is specified without drive letter.

built and installed with
```
cmake --build . && cmake --install .
```

The installation directory's content is after the last step:
```
D:\MY-INSTALL-ROOT
└───bin
        myapp.exe
```

The fmt DLL is missing.

**Configuring with drive letter works**

Configuring with `CMAKE_INSTALL_PREFIX` starting with a drive letter fixes the issue:
```
cmake -G Ninja -DCMAKE_INSTALL_PREFIX=d:/my-install-root -DX_VCPKG_APPLOCAL_DEPS_INSTALL=ON -DVCPKG_TARGET_TRIPLET=x64-windows -DCMAKE_TOOLCHAIN_FILE=D:/dev/vcpkg/scripts/buildsystems/vcpkg.cmake ${source-dir}"
```

After build and installation:
```
D:\MY-INSTALL-ROOT
└───bin
        fmtd.dll
        myapp.exe
```

Enabling verbose output in `scripts/buildsystems/msbuild/applocal.ps1` suggests that dependencies of the executable cannot be resolved. 

**Why don't I just specify the drive letter then?**

Our (Qt's) CI uses the `DESTDIR` environment variable to divert the install root. That only works reliably on Windows if there's no drive letter in the install root specified.

- OS: Windows

- Have you tried:
`-DCMAKE_INSTALL_PREFIX=my-install-root` ?

paths with leading `/` are commonly regarded as absolute paths.
- That won't work, because this will result in a `CMAKE_INSTALL_PREFIX` that is under `CMAKE_BINARY_DIR`.
Rerooting this via `DESTDIR` will install in `$ENV{DESTDIR}/${CMAKE_BINARY_DIR}/${CMAKE_INSTALL_PREFIX}`.
