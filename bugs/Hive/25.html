Title

Ql java source copied to build/gen-java

Description
Since   HIVE-98  , the build process copies the contents of the ql/src/java directory to build/gen-java where the code generated from Hive.g is located. This makes it a bit more difficult to work on the project in Eclipse, since one has to add the build/gen-java folder to the project and not ql/src/java. This means we'll edit the ql java files in the wrong location. Adding both of these directories will of course result in duplicate entries.
Discussion
- A few alternatives: 
 
	 If we'd want to make the handling of generated code a bit more consistent we could put the code from Hive.g into svn under ql/src/gen-java much like the thrift generated code in other modules. 
	 Copy ql/src/java into build/ql/java or a similar directory that is not build/gen-java 
 

 Personally I'd vote for the first option.
- hmm... 

 the reason that these files are copied there is to support pre processing as that is needed due to differences in the hadoop APIs. Consequently, the files in ql/src/java are preprocessed and then copied to build/gen-java where everything is built. 

 Agreed though, that if this breaks eclipse then we need to figure out a way to make pre-processing work with eclipse. What are the standard practices to deal with pre processing in eclipse?

- Updated patch for option 2. It just copies the preprocessed data into a folder that is different from the one containing the Hive.g generated code. 
With the arguments above taken into consideration I agree that it's the best option.
