Title

groovy scripts file path name containing "e-n" raises "java.io.IOException: Invalid argument"

Description
Reproducing steps: 
1. Create a groovy script named "e-n.groovy" (contents doesn't matter) 
2. Run "groovy.bat e-n.groovy", bang! 

  
 Caught: java.io.IOException: Invalid argument
java.io.IOException: Invalid argument
Discussion
- Did some debugging on this and the problem appears to be having "-n" somewhere in the path to the script. In startGroovy.bat, there is this code: 

  
 rem horrible roll your own arg processing inspired by jruby equivalent

rem escape minus (-d), quotes (-q), star (-s).
set _ARGS=%*
if not defined _ARGS goto execute
set _ARGS=%_ARGS:-=-d%
set _ARGS=%_ARGS:"=-q%
set _ARGS=%_ARGS:?=-n%
 
  

 and then later on there is this: 
  
 rem now unescape -q, -s, -d
set _ARG=%_ARG:-s=*%
set _ARG=%_ARG:-q="%
set _ARG=%_ARG:-d=-%
set _ARG=%_ARG:-n=?%
 
  

 So I think the problem would also be exposed by having a script named "anything-s.groovy" "anything-d.groovy" or "anything-q.groovy" or "anything-n.groovy". I also experienced the problem when I passed a fully qualified path to a script that had a "-n" in it, like this: 

  
 groovy.bat c:\test-new\script.groovy
- Those are the relevant lines of code, though you did not describe exactly what is going wrong. The very first replacement changes all dashes into "-d" to prevent them from interfering with any of the other conversions. The second block then converts instances of "-d" back into dashes: 

  
 "anything-s.groovy" -> "anything-ds.groovy" -> "anything-s.groovy" 
  

 The issue is that "-n" is converted into a question mark  after  the "-d" to dash replacement: 

  
 "anything-n.groovy" -> "anything-dn.groovy" -> "anything-n.groovy" -> "anything?.groovy" 
  

 It is simply a matter of swapping those last two lines. I have submitted a  pull request  that does just that.
- Thanks for raising the issue. It should be fixed in the next release. And thanks to Jonathan for the PR.
