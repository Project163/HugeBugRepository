Title

Infer_schema! generates joinable for composite Foreign Key

Description
## Setup
The following repository was used to setup and reproduce the problem: [URL]

The problem is reproduced just by running the migration with the print_schema enabled.

### Versions

- **Rust**: 1.65
- **Diesel**: 2.0.2
- **Database**: Postgresql
- **Operating System**: Fedora 37

### Feature Flags

- **diesel:**["32-column-tables", "chrono", "numeric", "postgres", "r2d2", "without-deprecated"]

## Problem Description
According to [Link: the documentation]  we didn't expect to have a joinable being created between the second and third tables, since the only relationship between them is the composite foreign key.

A more dangerous implication of this problem is that it seems that diesel chooses the first column to be the joinable which could lead to wrong joining strategies. This can be verified by changing the order of the columns in the definition of the foreign key, in the migration file, which generates a different join strategy.

### What are you trying to accomplish?
I'm trying to be sure that the infer_schema only creates joinables that are correct, and in that case the joinable created could not be correct.

### What is the expected output?
I expect to don't have a joinable between those tables, according to the documentation provided.

### What is the actual output?
See the schema.rs file in the [Link: setup repository].

### Are you seeing any additional errors?
No.

### Steps to reproduce
1. clone the repository
2. configure a postgres database_url in the .env file
3. Run `diesel setup` .
4. See the outputed schema.rs file
