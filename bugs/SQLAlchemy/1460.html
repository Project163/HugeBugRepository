Title

DeclarativeBaseNoMeta with abstract classes?

Description
### Discussed in [URL]

 

 Originally posted by **pamelafox** May 30, 2023 
I am running some tests in Flask-SQLAlchemy with the new Declarative bases, and I ran into an issue that I can also replicate with a tweak of the documentation example:

```
from sqlalchemy.orm import DeclarativeBase, DeclarativeBaseNoMeta
from sqlalchemy.orm import Mapped
from sqlalchemy.orm import mapped_column
from sqlalchemy import Integer, String

... [Log Snipped] ...
    name = mapped_column(String(50))
    engineer_info = mapped_column(String(40))
```

That code works fine for `DeclarativeBase`, but produces this error with `DeclarativeBaseNoMeta`:

```
AttributeError: type object 'Employee' has no attribute '__mapper__'
```

That error comes from map_declaratively attempting to return `cls.__mapper__`. As far as I can tell from my tracing of the code, it should be expected that the Employee class doesn't have `__mapper__`, since it's abstract, and the issue is just that the particular line of code doesn't account for that. In the `DeclarativeBase` flow, it is accounted for. The error goes away when I add a check for abstract before attempting to return `__mapper__`.

So I think this is an issue, but wanted to post as a discussion before filing.
