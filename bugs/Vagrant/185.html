Title

`read_dhcp_servers` function is not compatible with Virtualbox 6.1

Description
We've been encountering similar issues as in #3083 and we've traced the DHCP server creation in the Vagrant codebase. It seems that the `read_dhcp_servers` function parses the output of `VBoxManage list dhcpservers` which has changed between VirtualBox 6.0 and 6.1.

**VirtualBox 6.0 output:**
```
NetworkName:    HostInterfaceNetworking-vboxnet0
IP:              
NetworkMask:     
lowerIPAddress:  
upperIPAddress:  
Enabled:        Yes
Global options:
   1: 

```

**VirtualBox 6.1 output:**
```
NetworkName:    HostInterfaceNetworking-vboxnet0
Dhcpd IP:        
LowerIPAddress:  
UpperIPAddress:  
NetworkMask:     
... [Log Snipped] ...
Groups:               None
Individual Configs:   None
```

It is obvious that the output is different and this line for example will not match the new output from VirtualBox 6.1: [URL]

### Vagrant version
```
$ vagrant --version
Vagrant 2.2.7
```

### Host operating system
```
Manjaro Linux
Release:	18.1.5
Codename:	Juhraya
```
But this also occurs on Ubuntu 18.04 and Windows 10 with the same version of Vagrant and VirtualBox 6.1

### Guest operating system
Ubuntu 16.04 (although this seems irrelevant) 

### Vagrantfile
It appears to affect any Vagrantfile that uses DHCP and not a fixed IP address.
```ruby
Vagrant.configure("2") do |config|
...
  config.vm.network "private_network", type: "dhcp"
...
end
```

[URL]

### Expected behavior
Vagrant should not try to create a new DHCP server when one already exists, or properly increment the counter in the dhcpserver name.
