Title

`popstate` triggers `beforeNavigate`/`afterNavigate` for hash changes

Description
### Describe the bug

If you click a ` ` link, `beforeNavigate` and `afterNavigate` callbacks are not called, which I think is correct, since clicking on a hash link doesn't constitute a navigation as far as SvelteKit is concerned.

But if you then click the back button, the callbacks _are_ called. In fact we execute a full navigation — it's just that most of the steps are a no-op, since the code is already loaded and the data is guaranteed to remain valid.

Bailing out of the navigation in `popstate` if the URL is the same, apart from the the hash, would save SvelteKit from doing a bunch of unnecessary work, but more importantly it would fix the inconsistency. The alternative way to solve the inconsistency would be to _also_ trigger callbacks when the link is clicked, but I think consistently _not_ calling them is preferable.
