- These `member` objects are generated by other parts of the dgeni system (primarily by parsing the TS code and JSDOC comments - but also modified by other dgeni processors).

The good news is that any `member` that is marked as deprecated with have a property on them: `member.deprecated`. You can then use this in the templates to render them appropriately.

For example:

```
{%- macro renderMembers(doc) -%}
  {%- for member in doc.staticProperties %}{% if not member.internal %}
   {$ renderMemberSyntax(member, 1) $} {% endif %}{% endfor -%}
  {% for member in doc.staticMethods %}{% if not member.internal %}
   {$ renderMemberSyntax(member, 1) $} {% endif %}{% endfor -%}
... [Log Snipped] ...
  // inherited from  {$ ancestor.doc.id $} {$ renderMembers(ancestor.doc) $}{% endif %}{% endfor -%}
{%- endmacro -%}
```

Note here that I have added `{% if member.deprecated %} deprecated-api-item{% endif %}` to cause the `deprecated-api-item` CSS class to be added to any of the members that have this `member.deprecated` property.  This will fix the "overview" section:
