- Thanks for the report and the easy reproducer. I can confirm I see the same issue.
- Ok, on closer investigation this is not a bug: OtherName value must be a DER payload. I'll send a PR making this error message clearer.
- The issue here is that we require OtherName to be valid DER, not an arbitrary byte string. We should improve this error msg on parse, but we could also validate when creating an `OtherName` object.

For your case the actual bytes you likely want to be encoding are b"\x0c\rAdministrator" which is DER for UTF8 string of length 13. You can confirm this by seeing if the DER output of your working example (using the OpenSSL specific string) contains that byte sequence 😄
