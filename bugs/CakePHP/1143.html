Title

Cookie::createFromHeaderString can cause a warning on empty value string

Description
### Description

When the response header from a Http/Client::get request is eventually parsed by Http/Cookie/Cookie::createFromHeaderString, the method can cause a warning saying "undefined array key 1" in some situations . This happens for example when the response header contains Set-Cookie with an empty value string.

Code snippet to reproduce this:
```
php
// NOTE: The url used is just an example url that contains to a src example, 
// the actual url contained privacy sensitive data and has been replaced
// by an example src that leads to the same results as the real world data.

... [Log Snipped] ...
    ['headers' => ['User-Agent' => $fakeUseragent]]
);
```
It can be prevented in this particular case by adding an additional check to the CookieCollection::createFromHeader method, that will skip any empty values. I am however unsure if this would solve the issue permanently since the problem actually exists in the Cookie::createFromHeaderString method.

### CakePHP Version

4.4.17

### PHP Version

8.2
