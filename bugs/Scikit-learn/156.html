Title

regression in ColumnTransformer in in 0.20.1 with columns=pd.Index

Description
```python
from sklearn.preprocessing import OneHotEncoder
ct = make_column_transformer((cat_features, OneHotEncoder(sparse=False)),
                             remainder=StandardScaler())
ct.transformers
```
```
pytb
---------------------------------------------------------------------------
ValueError                                Traceback (most recent call last)
  in  ()
      6 
... [Log Snipped] ...

ValueError: The truth value of an array with more than one element is ambiguous. Use a.any() or a.all()
```

This came up in one of my teaching notebooks actually (and might be in my book as well).
This is very natural because columns are of type pd.Index, and so if you take some subset of columns from ``DataFrame.columns`` you'll now run into this error.
So... 0.20.2?
Discussion
- ```python
ct = make_column_transformer((OneHotEncoder(sparse=False), cat_features),
                             remainder=StandardScaler())
```
i.e. the new attribute order, works, though.
But that means we botched the deprecation - in a case that I care about because it's now out there on paper ;)
- Want me to check it, or is @jorisvandenbossche or somebody else on it?
- The bug actually also exists "in the future" for numpy arrays:

```
In [14]: cat_features= np.array([1, 2, 3])   

In [15]: ct = make_column_transformer((cat_features, OneHotEncoder(sparse=False)), 
    ...:                              remainder=StandardScaler()) 
    ...: ct.transformers 
... [Log Snipped] ...
         dtype= , handle_unknown='error',
         n_values=None, sparse=False), array([1, 2, 3]))]
```

So for numpy arrays, the check of `t in ('drop', 'passthrough')` still gives a warning, but in the future it will also raise. Pandas Series / Index already has the future behaviour (always had I think).

Just as a side note, as the fix is already there I see :)
