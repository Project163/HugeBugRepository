Title

NoSuchFieldError when defining a field named "metaClass"

Description
The following script causes a NoSuchFieldError. It would be better if all Groovy-internal members started with "$", or at least caused a sensible compile error. 

  
  class  Foo {
   private   String  metaClass
}
  
  
 new  Foo()
Discussion
- Attaching a patch that makes the compiler throw an error when it sees a metaClass field defined that is of the wrong type. It doesn't try to do any mass changes to rename all groovy-internal members to start with '$'.
- In general I agree with the patch, but maybe CompileableSupport should be used and a test case with shouldCompile and shouldNotCompile be provided instead the manual usage of like in the current test case
