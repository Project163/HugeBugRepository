Title

Exceptions in a class fixture's Dispose method are silently swallowed with UseMicrosoftTestingPlatformRunner

Description
I'd like to use xUnit v3 with the new Testing Platform runner. I noticed that, with this setup, exceptions thrown from a class fixture's `Dispose` method don't cause the test run to fail.

This affects both `dotnet run` (with `UseMicrosoftTestingPlatformRunner`) and `dotnet test` (with `TestingPlatformDotnetTestSupport`). I'm not sure whether it's an issue with xunit or with the testing platform itself - please let me know if I should file this issue with the testing platform team.

1. Make a new project with the following settings.


2. Add a test with an `IClassFixture` whose `Dispose` method throws.

```
csharp

using Xunit;

... [Log Snipped] ...
    }
}
```

3. Run it with `dotnet run`. Output shows the test run passed when it should have failed.

Discussion
- Yes, this has always been the case.

Class fixture throws in Dispose cause TestClassCleanupFailure messages, but can't be reported as test failures because the tests have long since been reported with whatever status they have.

It actually **_doesn't_** say that. It says there was one **_error_**, not one **_test failure_**.

I'll look to see how these are reported to MTP and see what can be done to improve the situation here.
- The ask from me is simply to not swallow the `Dispose` exception. It should report that the test _run_ failed, one way or another. I personally don’t particularly mind how that’s reported; eg I’m not asking specifically for any individual test(s) to be reported as failing, though I also wouldn’t mind if it did end up working that way. I just want red on the screen 😉 .
