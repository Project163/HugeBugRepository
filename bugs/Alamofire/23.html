Title

NilEncoding always dropKey when encoding an Encodable object with optional properties

Description
* [Link: x] I've read, understood, and done my best to follow the [*CONTRIBUTING guidelines].

## What did you do?

I am using `URLEncodedFormEncoder` with the option `NilEncoding.dropValue` to encode an object that has optional string properties.

## What did you expect to happen?

Assuming the following struct : 

```swift
struct MyStruct: Encodable {
    let p1: String
    let p2: String?
}
```

If I encode myStruct I expect to get the following query `p1=string&p2=`.

```
swift
do {
    let myStruct = MyStruct(p1: "string", p2: nil)
    let formEncoder = URLEncodedFormEncoder(nilEncoding: .dropValue)
    let query: String = try formEncoder.encode(myStruct)
... [Log Snipped] ...
    print(error)
}
```

## What happened instead?

Got `p1=string`.


## Alamofire Environment

**Alamofire Version:** 5.7.1
**Dependency Manager:** Cocoapods 1.12.1
**Xcode Version:** Xcode 14.3.1
**Swift Version:** 5.7
**Platform(s) Running Alamofire:** iOS
**macOS Version Running Xcode:** Ventura 13.3.1

## Demo Project

Code above is sufficient to reproduce the issue.

## Suggestion

Digging into Alamofire I think the issue might by in `extension _URLEncodedFormEncoder.KeyedContainer: KeyedEncodingContainerProtocol {`.

In fact when the encoder found a nil value it seems to prefer using the `encodeIfPresent` method instead of `encodeNil`.

Using this rather naive implementation I managed to get my Struct encoded properly :

```
swift
func encodeIfPresent(_ value: String?, forKey key: Key) throws {
    if let value {
        try encode(value, forKey: key)
    } else {
... [Log Snipped] ...
    }
}
```
