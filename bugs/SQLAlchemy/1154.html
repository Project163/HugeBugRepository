Title

Bug while parsing URL in URL.create

Description
**Describe the bug**
It seems to me that URL parsing has a bug when there is not `/` before the query parameters

**Expected behavior**
URL should be parsed as expected.

**To Reproduce**

```py
from sqlalchemy.engine import make_url

url = make_url("mysql://user:pass@ ?charset=utf8mb4")
assert url.host == " "  # raises, url.host is ' ?charset=utf8mb4'
assert url.query == {"charset": "utf8mb4"}  # also raises, it's an empty dict
```

**Error**

```
  File "/Users/youtux/Library/Application Support/JetBrains/PyCharm2021.1/scratches/scratch.py", line 18, in  
    assert url.host == " "  # raises, url.host is ' ?charset=utf8mb4'
AssertionError
```

**Versions.**
 - OS: macos 11.2.1
 - Python: 3.6.12
 - SQLAlchemy: 1.4.10
 - Database: irrelevant
 - DBAPI: irrelevant

**Additional context**
I found this problem when I was manipulating the URL string. I started with a quey string that contains the `/`, and then I remove the database part of the query, and it's SQLAlchemy itselfs that removes the `/` from the string. Still, the resulting string should be parsed just fine.
```py
original_url = make_url("mysql://user:pass@ /testdb?charset=utf8mb4")

stringified_url = str(original_url._replace(database=None))
# stringified_url is now "mysql://user:pass@ ?charset=utf8mb4"
```
