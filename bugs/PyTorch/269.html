Title

Inconsistent Error Handling Between CPU and CUDA for `cosine_similarity`

Description
### 🐛 Describe the bug

## Bug Description
There's an inconsistency in how PyTorch handles type conversions in the torch.cosine_similarity() function between CPU and CUDA implementations.

- The CPU implementation correctly throws a RuntimeError: "value cannot be converted to type at::Half without overflow"
- The CUDA implementation silently continues execution and returns NaN values instead of raising an error

## Code to Reproduce
```
python
import torch

print(torch.__version__)

... [Log Snipped] ...
except RuntimeError as e:
    print("CUDA error:", e)
```

## Actual Behavior
```
2.7.0+cu126
CPU error: value cannot be converted to type at::Half without overflow
CUDA result: tensor([[[nan, nan, nan, nan, nan, nan],
         [nan, nan, nan, nan, nan, nan]],

... [Log Snipped] ...
         [nan, nan, nan, nan, nan, nan]]], device='cuda:0',
       dtype=torch.float64)
```

## Expected Behavior
Both CPU and CUDA implementations should handle type conversion errors consistently.
