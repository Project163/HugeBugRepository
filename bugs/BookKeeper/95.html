Title

BenchBookie doesn't run correctly

Description
Bench bookie tests latency of addEntry to a single bookie. Currently it simply writes to a specified ledger id. If this ledger id doesn't exist in zookeeper, the ledger is GC'd from the bookie and errors occur in the bench.
Discussion
- Fix makes the benchmark create a ledger to write to. This prevents GC from interfering.
- It looks mostly good, I just have one small question. In trunk, we refer to ledger+1 and ledger+2, which seems to imply that we are writing to different ledgers. Your patch makes it uniform. Is it the right behavior?
