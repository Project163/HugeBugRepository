Title

st.rerun reruns the entire page instead of just escaping the fragment resulting in other widgets loosing their state (since v.1.37)

Description
### Checklist

### Summary

**Following scenario:**

I have a widget that takes user input. Depending on that user input, different content is shown to the user. One option, for instance, is a dynamic form using `st.fragment`.

Before the last update, I would save the user input in the `st.session_state` and call `st.rerun` when the user submits the dynamic form. In the next run of the app , I would check if there was anything in the session state and access the data.

This worked fine in version 1.36. However, now in version 1.37, the widget that controls what content is shown (e.g., the dynamic form) loses its state as well when `st.rerun` is called.

In the example code below I have created a widget to choose between two forms:
1) A static form (using `st.forms`)
2) A dynamic form.

Using the dynamic form works fine with version 1.36 but not with 1.37. 
The submitted data should be display under the form.

Update:
I dug deeper into this and I _believe_ I have found the change / cause for this:
In the session_state `_remove_stale_widgets` function, we use the `fragment_ids_this_run` [Link: here] to determine what widgets are stale. However, the new behavior in commit   is that the _new_ `fragment_ids` are used, based on the current `script_requests` object that was updated with the latest `RerunData` in `app_session.request_rerun` (btw. this is empty for the example app because the `st.rerun()` triggers a full-app rerun).
In the code before this change, e.g. in  , the `fragment_ids` from the run _before_ the latest `RerunRequest` are used to remove stale widgets. The `remove_stale_widgets` code is triggered via `self._on_script_finished` [Link: here]. But the `ctx.current_fragment_ids` is reset based on the latest `rerun_data` [Link: here] in the new loop-iteration _after_ the `remove_stale_widgets` call is made.

So TLDR:
- new (false) behavior: `remove_stale_widget` with latest `RerunData.fragment_ids` is made
- old (correct) behavior: `remove_stale_widget` with the previous `RerunData.fragment_ids` is made

To check this, I have added following line in [Link: script_runner#471]:
```python
ctx.clean_up_fragment_ids = fragment_ids_this_run
```

and in [Link: session_state#582-585]:
```
python
        # fragment_ids_this_run = (
        #     set(ctx.script_requests.fragment_id_queue)
        #     if ctx.script_requests and len(ctx.script_requests.fragment_id_queue) > 0
        #     else None
... [Log Snipped] ...
            ctx.clean_up_fragment_ids if ctx.clean_up_fragment_ids else None
        )
```

and with these changes, the example from the issue works again as expected.
