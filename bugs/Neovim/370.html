### Steps to reproduce using `nvim -u NORC`
A strange interaction between the `number` option and `nvim_open_term` causes Neovim to crash when the buffer used in `nvim_open_term` is not active in the window.

```
:set number

# Paste into buffer and run with :luafile %
local buf_id = vim.api.nvim_create_buf(true, true)
vim.api.nvim_win_set_option(0, "number", false)
... [Log Snipped] ...
vim.fn.chansend(chan_id, lines)
vim.api.nvim_win_set_buf(0, buf_id)
```

### Actual behaviour
Neovim crashes with error:
```
E317: pointer block id wrong
```

### Expected behaviour
No crash.

- Doesn't seem to crash if `:redraw` is used just after `nvim_win_set_option()`.

Seems without the redraw, `buf->b_ml.ml_line_count` may be less than the `height` from `vterm_get_size()` which causes `buf_index` to be a negative line number, which is then used in `ml_append()`.

I'm not too familiar with the memline parts, but I'm guessing `ml_append()` probably doesn't like negative line numbers?
