Title

[3.1] $query->cleanCopy() does not clone 'where' statements

Description
When trying to clone a query object, it seems that the 'where' statements are not cloned properly:

```
$query1 = $Articles
        ->find()
        ->select('id')
        ->where(['created >' => new DateTime('-10 days')])
        ->order(['publication_date' => 'DESC']);
... [Log Snipped] ...
    // $query1:  SELECT [...] WHERE (created > '2015-10-02 18:38:02' AND title = 'First' AND title = 'Second') ORDER BY publication_date DESC
    // $query2:  SELECT [...] WHERE (created > '2015-10-02 18:38:02' AND title = 'First' AND title = 'Second')
```

The only way I found to get around this is to overwrite the previous 'where' statements by setting the third parameter of the where() function to true, but all the previous conditions are lost.

I'm not entirely sure whether this is an issue or a wanted behavior, but it seemed odd to me.
Discussion
- Cloning/cleaning the where clause is not [Link: part of the documented behavior]. However, given that `__clone` has the same behavior, it would be nice to have a quick way to clone a query.

Perhaps `__clone` should do a recursive deep clone, while `cleanCopy()` can do the quicker/shallow clone we rely on for count() operations.
- I think `__clone` can be changed to be a deep clone
