Title

LOCALE_ID is being set before APP_INITIALIZER runs

Description
# 🐞 bug report

### Affected Package
The issue is caused by package `@angular/core`.


### Is this a regression?

Yes, the previous version in which this bug was not present was: `7.2.15`


### Description

Angular is trying to set the `LOCALE_ID` before the `APP_INITIALIZER` runs to set the runtime i18n value for Ivy. This does not allow the application to fetch the locale from a backend. This is happening without Ivy mode activated.

`setLocaleId` is only used for ivy code, and this piece of code is only there temporarily to allow runtime i18n (for ivy) to work with the current view engine code until we have the new i18n service available.
That being said, we could update `_localeFactory` in application_module (that is set after `APP_INITIALIZER`) so that it defines the locale for ivy as well
