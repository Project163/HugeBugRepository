Title

Test failure with more recent github.com/stretchr/testify

Description
The currently vendored version of `github.com/stretchr/testify` in the `rclone` repository is at commit [URL] (2017-01-30).

In the meantime, `github.com/stretchr/testify` has gained commit [URL] which breaks your tests:
```
% go test github.com/ncw/rclone/fs       
--- FAIL: TestSetDefaults (0.00s)             
	Error Trace:	http_test.go:27
	Error:      	Invalid operation: (func(string, string) (net.Conn, error))(nil) == (func(string, string) (net.Conn, error))(nil) (cannot take func type as argument)
	Messages:   	when checking .Dial
	Error Trace:	http_test.go:28
	Error:      	Invalid operation: (func(string, string) (net.Conn, error))(nil) == (func(string, string) (net.Conn, error))(nil) (cannot take func type as argument)
	Messages:   	when checking .DialTLS
```

Please fix the test.

Also, in the future, please regularly update the vendored versions of your dependencies (using e.g. `dep ensure -update`) :)

I noticed this when investigating why the Debian packaging for `rclone` fails to build (Debian’s `github.com/stretchr/testify` is more recent than your vendored version, and Debian un-vendors everything).
Discussion
- I re-vendor everything at the start of the release cycle for rclone.  SInce I just released 1.37 that will be shortly!


That policy is bound to cause problems with projects like rclone with lots of dependencies.  I didn't used to use vendoring with rclone and people were always complaining that the rclone build was broken.
- I've fixed this now - see above for the commit.
