Title

Invalid bytecode generation in BeanContainerListener recorded code

Description
In the #945 PR, I made a change to include two config root objects in a callback to a bean in the unit test app and I started to see this ExceptionInInitializerError:

```
INFO: Shamrock augmentation completed in 365ms

	at org.jboss.shamrock.deployment.steps.TestProcessor$configureBean5.deploy(Unknown Source)

To see this comment out the @Disabled on the ConfiguredBeanTest.
Discussion
- So here is the generated bytecode of the TestProcessor$configureBean5.deploy method:

```
asm
 0 new #14

... [Log Snipped] ...

The problem is the attempt to load the org.jboss.shamrock.runtime.generated.ConfigRoot#testBuildTime field, but there is no such field:

```
java
//
// Source code recreated from a .class file by IntelliJ IDEA
// (powered by Fernflower decompiler)

... [Log Snipped] ...
    }
}
```

Apparently this has to do with the phase associated with the @ConfigRoot objects. The testBuildTime field is of type org/jboss/shamrock/extest/TestBuildTimeConfig which is a phase = ConfigPhase.BUILD_TIME object. Apparently this is being filtered out, so wherever that is happening, an error should be generated rather than an invalid reference to a field that will not exist.
- Yeah this validation needs improvement.  The error is likely happening because the `ConfigPhase` should be `BUILD_AND_RUN_TIME_FIXED` which makes it visible to run time code... theoretically.
- The issue is that block of code that generates the ConfigRoot.class checks if the config root phase is available at runtime, while the ObjectLoader code that deserializes the config root does not. The following change to the latter:

```
java
        objectLoaderConsumer.accept(new BytecodeRecorderObjectLoaderBuildItem(new ObjectLoader() {
            public ResultHandle load(final BytecodeCreator body, final Object obj) {
                final ConfigDefinition.RootInfo rootInfo = configDefinition.getInstanceInfo(obj);
                if (rootInfo == null) return null;

            }
        }));
```
  Check runtime availability

catches the problem and lets the user know about it:
