Title

Router: strict route validation, but not for lazy-loaded modules

Description
## I'm submitting a...
 
  [X] Bug report   
[X] Documentation issue or request
  

## Current behavior

When a `Route` only contains a CanActivate guard:
```typescript
const routes = [
  {
    path: '',
    canActivate: [MyRedirectGuard] // always does a dynamic redirect
  }
];
```
You will get a validation error: 
```
Error: Invalid configuration of route ''. One of the following must be provided: component, redirectTo, children or loadChildren
```

However, when this route is in a lazy-loaded module it works perfectly fine.

## Expected behavior
I expect routes in lazy-loaded modules to have the same validation. However, I wish this validation rule to be less strict, because we use CanActivate guards for dynamic redirects.

If the rule is valid, there should be another way to have dynamic redirects on component-less routes, e.g. a new type of guard:

```
typescript
const routes = [
  {
    path: '',
    redirect: MyRedirectGuard
... [Log Snipped] ...
  }
}
```

## Minimal reproduction of the problem with instructions
[URL]

Uncomment the first route in app.module.ts to trigger the error. However, in feature.module.ts it works fine.

## What is the motivation / use case for changing the behavior?

We use `CanActivate` guards to do dynamic redirects whenever we need to. We only want them to trigger for specific urls, so we have component-less routes:

```
typescript
const routes = [
  {
    path: 'feature',
    component: FeatureComponent,
... [Log Snipped] ...
  }
];
```
With this construction, when a user navigates to `/feature`, it automatically goes to `/feature/foo` or `/feature/bar`.

We want to be able to do the same in modules that are not lazy-loaded, without the need to provide some kind om "dummy" component.

## Environment

  Angular version: 6.1.0
