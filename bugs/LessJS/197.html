Title

Aliasing Ruleset Lookups for Additional Lookups

Description
I have these variables defined:

```
@color-schemes: {
    @primary: {
        @color: blue;
        ...
    };
    ...
}
```

And I am iterating over a variable to retrieve some of the rulesets in @color-schemes and use them:

```
each(@theme-color-names, .(@color-name) {
    @scheme: @color-schemes[@@color-name]; // e.g. @color-name = primary
    color: @scheme[@color];
});
```

I get this error:

```
Could not evaluate variable call @scheme at ...
```

As far as I can tell the issue is that LESS thinks `@color-schemes[Link: @@color-name]` is ambiguous like `#library.colors` from the documentation is because it doesn't end with parentheses. But there's no way I can see to make it unambiguous because `@color-schemes[@@color-name]` doesn't seem to be valid syntax.
Discussion
- Hmm... looks like a bug. In the meantime, you can actually write:

```less
each(@theme-color-names, .(@color-name) {
    color: @color-schemes[@@color-name][@color];
});
```
The way you wrote it should be equivalent, but for some reason it isn't.
- I was able to circumvent the issue by moving my scheme rulesets to the root and aliasing them without a lookup:

