- I think it would be good if we could add a few flags to tune the exact behavior here, for example `--experimental_remote_cache_expected_throughput` (so that we can abort when a file hasn't been downloaded in a "reasonable" amount of time), `--experimental_remote_cache_blobstore_retry_backoff` (implement exponential backoff, possibly with a lower bound of 0.1s and an upper bound of 1s) and `--experimental_remote_cache_blobstore_retry_jitter` (in order not to overload GCS when doing many retries at the exact same millisecond).
