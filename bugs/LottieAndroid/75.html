Title

Dynamic Properties don't survive composition change

Description
**Steps To Reproduce**
Steps to reproduce the behavior:

1. Create a composition from a lottie file with named layers.
2. Use `rememberLottieDynamicProperties` to configure dynamic colors for named layers.
3. Add some action that recomposes and **changes the remembered composition**.

**Expected Result**
Dynamic properties are applied after the composition is updated.

**Actual Result**
Dynamic properties are no longer applied to the new composition.

**Analysis**
When a `LottieAnimation` is rendered, [Link: dynamicProperties are applied] to the underlying `LottieDrawable` only once, via [Link: addValueCallbacks()], which adds the callbacks to the `compositionLayer`. However, when the composition of a `LottieDrawable` is updated, the [Link: existing compositionLayer is destroyed and a new one is created]. This means that any callbacks previously applied by dynamic properties are lost.

I **think** an approach to fix this might be to simply add the composition as a key to the [Link: setDynamicProperties remember] statement.

**Repro**

The following sample reproduces the issue using an interactive preview. Clicking on the buttons switches the displayed animation, and you can see that the dynamically colored layers are no longer dynamically colored after the composition is changed.

```
kotlin
@Composable
fun Illustration(
    @RawRes resId: Int,
    modifier: Modifier = Modifier,
... [Log Snipped] ...
    }
}
```

**Workaround**
Adding a bogus dynamic property that takes the resId into account causes the remembered dynamic properties to be updated with the composition, fixing the issue.

```
diff
 @Composable
-private fun rememberDefaultDynamicProperties(): LottieDynamicProperties {
+private fun rememberDefaultDynamicProperties(resId: Int): LottieDynamicProperties {
     return rememberLottieDynamicProperties(
... [Log Snipped] ...
    )
 }
```
