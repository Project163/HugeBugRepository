Title

[DocDB] [Table locks] Regression in deadlocked transaction abortion with object locking

Description
Jira Link: [Link: DB-18398]
### Description

Version -  -b587

I’m seeing a difference in how deadlocked transactions are aborted on the latest master. Maybe a regression ?  Have we recently modified anything in the deadlock detection logic? Consider the below scenario ; only with DMLs and No DDLs
```
session 1              										session 2

CREATE TABLE _15_t_123 (
id INT PRIMARY KEY,
balance DECIMAL(10,2)
... [Log Snipped] ...
 	
															UPDATE _15_t_123 SET balance = balance + 100 WHERE id = 1;
```

till  **b569**, session 2’s update would be aborted with a deadlock detected error, and session 1’s update would succeed.
On the latest master, however, session 1’s update is aborted, and session 2’s update succeeds.
