Title

[3.6.0-beta1] Regression in TimestampBehavior

Description
This is a bug.

* CakePHP Version: 3.6.0-beta1
* Platform and Target: PHP 7.1 / MacOS X / No DB.

### What you did

Bind the TimestampBehavior on a table that does not have either one (or none) of the `created` or `modified` fields.
When saving the entity, an exception `Unknown type ""` is thrown by the `Cake\Database\Type::build()` method.

Extract of the stack-trace :

```
⟩ Cake\Database\Type::build
CORE/src/ORM/Behavior/TimestampBehavior.php, line 202

⟩ Cake\ORM\Behavior\TimestampBehavior->_updateField
CORE/src/ORM/Behavior/TimestampBehavior.php, line 108
```

I tested the same code on a last 3.5 release which works fine.
Discussion
- I think the right thing to do would be throw a meaningful error. Don't see how silently setting value for non-existent field like 3.5 does would be useful.
- Even though I think it's better to throw the error, this will definitely break apps for people like me who add the behavior to our main table class so all tables inherit it.

- Pull request open now to fix the break. I'm open to making missing columns an error, but would prefer that error to not be emitted during save, and instead at configuration time.
