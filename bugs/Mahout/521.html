Discussion
- The MR version of Streaming KMeans seems to be failing (the sequential mode passes), the reason being that the reducer is reading zero intermediate centroids; need to investigate as to what's going on.
- The issue happens when the ReduceStreamingKMeans (-rskm) flag is set to True. Setting this to False has resolved the issue. We are lacking adequate code coverage tests for Streaming KMeans when the -rskm flag is set. This is something that needs to be fixed post 0.9 Release.
- Removed the -rskm flag from the script to fix this, will have to investigate the implementation behavior when -rskm flag is specified for the next release.
