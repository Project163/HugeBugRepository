Title

Cookie is not set during script authentication when following redirect

Description
What steps will reproduce the problem?
1. Choose a test site using redirects during authentication such as WebGoat
2. Create a context with a Script-based Authentication method and a Cookie-based Session Management method
3. In the script (for example, a Javascript one), use the function: "helper.sendAndReceive(msg, true);" (notice the second parameter is set to true) to send the authentication request and follow redirects
4. Use a network analyzer to see the content of request/response packets (because ZAP doesn't display in his history the redirect requests/responses when authenticating, maybe I'll raise another issue)
5. Use the User Forced Mode to test authentication and session management

What is the expected output? What do you see instead?
The server sends a Set-Cookie header with a Location header. ZAP process the Location header in order to follow redirect but ignore the Set-Cookie header and doesn't set the cookie in the HTTP State. The session is not setup, the User Forced mode fail to authenticate.

What version of the product are you using?
2.4.3

Please provide any additional information below.
After a quick research, the problem seams to come from the processRedirectResponse() method in org.apache.commons.httpclient.HttpMethodDirector class.

I would like to work on this issue, if you agree.
