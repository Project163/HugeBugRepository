Title

Accept underscores in hostnames

Description
Having a browser configured to use ZAP as a proxy, the browser sends an HTTP (proxy) request like:
```
GET [URL] HTTP/1.1
Host: hive_test_00.example.com:30001
User-Agent: Mozilla/5.0
```
ZAP tries to connect to [URL]  on default **Port 80** instead of the requested **30001**
```
GET / HTTP/1.1
User-Agent: Mozilla/5.0
Host: hive_test_00.example.com
```

OWASP ZAP-2.5.0
Discussion
- That's caused by the underscores in the hostname. Anyway, ZAP should handle that better.
- I spent a lot debugging time on this as well yesterday, just to find out the underscore issue myself.

Are there any plans to maybe replace the Apache http client with another stack, like OkHttp? I know it would be a bigger deal because the API is not quite compatible, but maybe it's worth it?
