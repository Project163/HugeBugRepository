Title

ChannelInitializer does not propagate Exceptions

Description
Netty version: 5.0.0.Alpha2 (but others as well)

Context:
When an exception occurs in a user defined initChannel, it is not propagated through the framework so that it can be handled with exceptionCaught. Instead, channelRegistered logs a warning and dumps a stack trace.

Steps to reproduce:
Throw a generic exception in an initChannel from the netty examples should do the trick.
Discussion
- @zoowar the question is how we should propagate here as if initChannel(...) throws an exception chances are good that you will not have an handler in the pipeline that can handle the exception.
- @normanmaurer When there is no exceptionCaught implemented by any of the pipeline handlers, the framework handles the exception by logging the following message:

It seems to me that ChannelInitializer/channelRegistered could log the specialized message ""Failed to initialize a channel." and throw the exception, which will be handled by the default handler or the user defined handler.

I'm not a java programmer, so the only question in my mind is how does the context get closed when an exception occurs in ChannelInitializer? Does it get closed in the default exceptionCaught path? If it doesn't, then ChannelInitializer could override exceptionCaught and close the context. Then document that users who wish to override ChannelInitializer/exceptionCaught must close the context.
