### Steps to reproduce using `nvim -u NORC`

```
nvim -u NORC
:set fdm=marker
:set fillchars=fold:─
i{{{
hello
}}} 
za
```

Please note that this is not happening for all non-ASCII characters. It seems to me that it's happening for characters that ends with '00':

- ─ (U+2500): **buggy**
- ━ (U+2501): works
- ┰ (U+2530): works
- ╀ (U+2540): works
- ▀ (U+2580): works
- ☀ (U+2600): **buggy**
- ☁ (U+2600): works
- ✀ (U+2700): **buggy**
- ✁ (U+2701): works
- ⤀ (U+2900): **buggy**
- ⤁ (U+2901): works

### Actual behaviour

The fold chars are all spaced between each other with sometimes wild appearances of some junk chars.

Forcing a redraw removes those junk characters.

- Since you pointed out correlation with least significant byte and used pretty old characters, all having ambiguous width this looks like yet another 0x80 byte issue (UTF-8 representation of those U+xx00 characters end with `0x80`). The 0x80 byte is used internally for encoding some special keys like ` `.
- It looks like some unmerged Vim patch: vim-8.0.0 also has the same problem.
