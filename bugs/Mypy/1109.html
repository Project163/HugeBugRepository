Title

Crash on nested unpacking of next() call

Description
**Crash Report**

Mypy crashes with the following traceback. Small reproducer below. Tested with version 0.991 (compiled) and mypy master (not compiled).

**Traceback**

```
$ mypy --show-traceback t.py
t.py:3: error: INTERNAL ERROR -- Please try using mypy master on GitHub:
[URL]
Please report a bug at [URL]
version: 1.0.0+dev. 
... [Log Snipped] ...
AssertionError:
t.py:3: : note: use --pdb to drop into pdb
```

**To Reproduce**

```console
$ cat t.py
def mypy_crash() -> None:
    d: dict[int, tuple[str, int, str]] = {}
    k, (v1, *_) = next(iter(d.items()))  #  

- Mypy version used: `mypy 1.0.0+dev.  (compiled: no)` (installed with `pip install git+[URL]
- Mypy command-line flags: `mypy t.py`
- Mypy configuration options from `mypy.ini` (and other config files): None
- Python version used: `Python 3.10.6 (main, Nov  2 2022, 18:53:38) [GCC 11.3.0]`
- Operating system and version:
  - OS: `Ubuntu 22.04.1 LTS on Windows 10 x86_64`
  - Kernel: ` -microsoft-standard-WSL2`
  - Also crashes on Debian Bullseye native (non WSL)
Discussion
- Looks like this has crashed since at least mypy 0.620! [URL]
- Note that if the same two lines are not in a function, the crash disappears and the file checks successfully

```console
$ cat t.py
d: dict[int, tuple[str, int, str]] = {}
k, (v1, *_) = next(iter(d.items()))

$ mypy t.py
Success: no issues found in 1 source file
```
