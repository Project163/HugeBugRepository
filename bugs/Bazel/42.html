Title

`'test.log' was not created error` when running Rust example test

Description
The code in `hello_lib/src/lib.rs` doesn't compile:

Specifically the line `assert_eq!("Hi Rust", hello.greeting("Rust"));` is wrong, since `Greeter::greet` doesn't have a return value, it prints.
Discussion
- Thanks for reporting this, @alex!

I don't think the problem is caused by this line:

``` rust
assert_eq!("Hi Rust", hello.greeting("Rust"));
```

In this line, `Greeter::greeting()` is called, which returns a `String`. The only test that is known to fail currently is the `rust_bench_test` in `examples/rust/fibonacci` since `Bencher` in `libtest` is unstable. Perhaps I should disable that test for now.

What's curious is that when I run `bazel test //examples/rust/hello_lib:all` on Linux, the tests all pass:

```
❯❯❯ bazel test //examples/rust/hello_lib:all
.....
INFO: Found 2 targets and 3 test targets...
INFO: Elapsed time: 18.917s, Critical Path: 2.23s
//examples/rust/hello_lib:greeting_test                                  PASSED in 0.1s
... [Log Snipped] ...
Executed 3 out of 3 tests: 3 tests pass.
There were tests whose specified size is too big. Use the --test_verbose_timeout_warnings command line option to see which ones these are.
```

However, on OS X, there are a number of build errors:

```
❯❯❯ bazel clean --expunge && bazel test //examples/rust/hello_lib:all
INFO: Starting clean (this may take a while). Consider using --expunge_async if the clean takes more than several minutes.
......
INFO: Found 2 targets and 3 test targets...
INFO: From Compiling Rust library hello_lib (2 files):
... [Log Snipped] ...

Executed 1 out of 3 tests: 2 fail to build and 1 fails locally.
```

Though, when I run `bazel test //examples/rust/...` on Linux, I also see the error where `test.log` is not getting created but only intermittently.

This seems to be a problem in the rule implementation. I will investigate further.

+@laurentlb for FYI.
- I checked the rule implementation, and the `.deps` dirs are `rm -rf`'ed before they are created. However, it looks like there is some kind of permission issue:

```
rm: bazel-out/local_darwin-fastbuild/bin/examples/rust/hello_lib/hello_lib.deps: Operation not permitted
ERROR: /Volumes/Ocean/Projects/google/bazel/examples/rust/hello_lib/BUILD:19:1: error executing shell command: 'set -e; rm -rf bazel-out/local_darwin-fastbuild/bin/examples/rust/hello_lib/hello_lib.deps; mkdir bazel-out/local_darwin-fastbuild/bin/examples/rust/hello_lib/hello_lib.deps
```

@laurentlb - Have you seen this issue before?
- Isn't the output directory non-writable?  Your rules shouldn't be putting stuff there directly (afaik).  working_dir != output_dir.
- It turns out the cause of this is that some of the `.deps` dirs created by the test targets have conflicting names and were trying to overwrite each other.

I have a fix for this currently in review.
