Title

WWW-Authenticate is missing for expired access tokens

Description
When sending a request with an invalid/non-existing authentication token to a REST service written in Yii2, no WWW-Authentication header is send in the 401 response. This seems not to be RFC conform.

### What steps will reproduce the problem?
Access any protected resource in Yii2 using HttpBearerAuth, sending a non-existing authentication token in the HTTP request.

### What is the expected result?
According to [Link: OAuth 2.0 RFC], a web service must always respond with WWW-Authenticate if an access token is missing or invalid.

credentials or does not contain an access token that enables access
to the protected resource, the resource server MUST include the HTTP
"WWW-Authenticate" response header field;

### What do you get instead?
You get a 401 error without any authentication challenge.

### Additional info
The missing authentication challenge is especially a problem for clients when session tokens expire. Clients cannot refresh a session token when they receive 401, because there is no authentication challenge.
