Title

consider removing lambda query use from ORM

Description
looking into issues like #6887 and #6881, the use of lambdas makes working on these internals **extremely** difficult.   if we look at the cases where we are building up these lambda queries, we might consider that the overhead of building up a select() is very low, **If** we can bypass the coercions step.   I would propose trying a branch where we build up straight select() objects, making use of direct population of elements to bypass coercions.   I'm really suspecting that we are not getting any real performance bump from lambdas to justify the complexity here.
Discussion
- the most expensive coercion is the "binary" coercion we do when we create a WHERE clause; for a lazy loader, we aren't doing this coercion in any case.

in the perf suite, I get the same performance from both of these runs, this is not even trying to be very optimized:
