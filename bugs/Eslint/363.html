Title

"no-use-before-define" not catching any violations when env=node

Description
Hey all, I just realized that eslint wasn't picking up a "no-use-before-define" rule violation in my codebase. I created a small test file based and eslint was still unable to catch it:

``` js
// test.js
console.log(a);
var a = 'abcdefg';
```

```
$ eslint -v
v0.19.0
$ eslint --reset --rule 'no-use-before-define: 2' test.js
$ echo $?
0
```

It looks like this rule is heavily tested in eslint itself, any idea why this wouldn't be catching? All other rules seem to be working fine.
Discussion
- I'm unable to reproduce. Is it possible you're turning off the rule in a config file or elsewhere?
- Oh interesting, I didn't realize that --reset doesn't reset any rules enabled/disabled by the `env` your .eslintrc defines. 

So it looks like it has something to do with env=node, when I remove "env=node" from my .eslintrc (or retry in my home directory without any .eslintrc) I cannot reproduce either. Are you able to reproduce these results?

```
$ eslint --reset --rule 'no-use-before-define: 2' test.js

test.js
  2:12  error  a was used before it was defined  no-use-before-define

✖ 1 problem (1 error, 0 warnings)
```

```
$ eslint --reset --env "browser" --rule 'no-use-before-define: 2' test.js

test.js
  2:12  error  a was used before it was defined  no-use-before-define

✖ 1 problem (1 error, 0 warnings)
```

```
$ eslint --reset --env "node" --rule 'no-use-before-define: 2' test.js
```
