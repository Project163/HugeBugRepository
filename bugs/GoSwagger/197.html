Title

swagger generate spec -m gives inconsistent json every other run

Description
We have models like following definitions which are composed. Where the `MyBase` might reside in another package not directly related to api package.

```
go
// MyBase holds the base attributes
type MyBase struct {
    AttributeA string `json:"attributeA"`
    AttributeB string `json:"attributeB"`
... [Log Snipped] ...
    AttributeC string `json:"attributeC"`
}
```

Now when running the following command we do see inconsistent results in the generate json.

```bash
swagger generate spec -m -o docs/swagger.json && git diff
```

One time it contains the MyBase and the other time we see it is getting removed again. We have this for a bunch of definitions. So one run it removes MyBaseA next time it adds it and removes another one etc. To me this looks like a bug which is not properly traversing composed structs to include those attributes as part of the MyBaseResponse. The behavior is also random as sometimes nothing changes.

using above bash command using `git diff` it is easy to detect the changes. For us this is really a blocking issue as `goreleaser` project does not allow dirty state to make a release, which is pretty logical as your release might be jeopardized when generated code changed during a build compared to the committed code.
