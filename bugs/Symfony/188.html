Title

[Security][5.2.0 only] Call to a member function getUserLoader() on null

Description
**Symfony version(s) affected**: 5.2.0
*5.2-RC2 was not affected*

**Description**  

Using the new authenticator-based security,
and a custom authenticator (which extends `AbstractAuthenticator`),
users get this error after login: `Call to a member function getUserLoader() on null`

[Image: image]

This is caused by `PasswordMigratingListener`, being triggered automatically since #39213, to assume than every Passport contains an UserBadge. This is nor documented ([Link: here]) nor enforced by `UserPassportInterface`, so I believe it should be tested.

Discussion
- Actually, the `UserBadge` should be the new way to go in 5.2 (See [URL] But we haven't documented it yet and it appears like my BC layer is no good:  [URL]

(it should instead initialize a `UserBadge` if a `UserInterface` was passed)
- This issue is that this BC layer is within `Passport` ; nothing forbids a developer from implementing its own Passport (actually, I did), and then nothing in `UserPassportInterface` guides him. IMO, `UserPassportInterface` should be modified to enforce properly required badges.

Right now, I still think #39263 is the proper way to go. Until the deprecation/migration path regarding `UserPassportInterface` is done.
- Yes, #39263 is the way to go no matter what other things we do imho. 

(fyi, this BC layer only lasts one minor version, in the 5.3 release we remove it and switch to `UserBadge` completely. So I would suggest you to update your own passport to use `UserBadge`)
