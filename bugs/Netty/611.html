Title

Missing netty-transport-native-* entries in the bom can lead to mismatched versions

Description
### Expected behavior

Netty's bom provides dependency management for all of Netty's modules, thereby ensuring that a consistent version is used.

### Actual behavior

Netty's bom does not include dependency management for:

- `netty-transport-native-epoll`
- `netty-transport-native-kqueue`
- `netty-transport-native-unix-common`

This can lead to mismatched version of Netty's modules when using the bom to control their versions

### Steps to reproduce

1. Depend on something that uses Netty, including one of the `transport-native` modules listed above
2. Import Netty's bom to control the version of Netty that's used

### Minimal yet complete reproducer code (or URL to code)

```
xml
 
 4.0.0 
... [Log Snipped] ...

 
```
 
This pom yields the following dependencies:

```
[INFO] The following files have been resolved:
[INFO]    io.netty:netty-common:jar:4.1.11.Final:compile
[INFO]    io.netty:netty-handler:jar:4.1.11.Final:compile
[INFO]    io.projectreactor:reactor-core:jar:3.0.7.RELEASE:compile
[INFO]    org.reactivestreams:reactive-streams:jar:1.0.0:compile
... [Log Snipped] ...
[INFO]    io.netty:netty-handler-proxy:jar:4.1.11.Final:compile
[INFO]    io.netty:netty-resolver:jar:4.1.11.Final:compile
```

Note that all of the Netty's modules are 4.1.11.Final except for `io.netty:netty-transport-native-epoll` which is 4.1.9.Final

### Netty version

4.1.11.Final (earlier versions are also affected)
