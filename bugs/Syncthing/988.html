Title

cli subcommand does not use STHOMEDIR env var

Description
In the docker container, it seems that the `syncthing cli` subcommand does not use the `STHOMEDIR` environment variable added in 1.23.7 (#8957). On the other hand, the `serve` subcommand works as expected with the new environment variable.

In the session below, I would expect the `syncthing cli` command without the explicit `--home` parameter to output the same as the one with the parameter set, instead it uses the default value:

```
# podman run --name bug --rm -d docker.io/syncthing/syncthing:1.23.7
# podman exec bug sh -c 'export | grep STHOMEDIR'
export STHOMEDIR='/var/syncthing/config'
# podman exec bug sh -c 'syncthing cli show version'
reading device ID: open /var/syncthing/.config/syncthing/cert.pem: no such file or directory
... [Log Snipped] ...
  "version": "v1.23.7"
}
```
Discussion
- It seems that `syncthing cli` has the same behavior with the environment variables `STGUIADDRESS` and `STGUIAPIKEY`, i.e. it doesn't use them when available, and instead `--gui-address` and `--gui-apikey` must be provided explicitly.

As far as I know, those two have been available for some time already to `syncthing serve`, so maybe the fact that those environment variables don't work for `syncthing cli` is not a bug proper?

The fact that #8957 (linked in the release notes) mentions:


I just assumed that the env vars were meant to be available for all subcommands that have those arguments.
- I agree they should, it's just a historic bug/oversight that they are not.
- I see syncthing uses two cli frameworks: kong and urfave/cli. Should one be migrated to another?
- Ideally, yes. It's the `cli` subcommand that does different magic for historical reasons.
