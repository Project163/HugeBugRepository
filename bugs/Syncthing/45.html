Title

Syncthing 0.8.1 does not like / in repository IDs

Description
I added a repository and named it "Programs/Mine". Syncthing didn't seem to like this; it failed to read any of the files in the pointed-to folder. If / isn't allowed in repo IDs (which is reasonable) then the GUI should disallow it.
Discussion
- Yeah. This should work (i.e. the slash should not be magic). I'll investigate. Any console output of interest, errors or otherwise?
- Nothing in the console unexpected at all, as far as I could tell. The / being the problem is pure speculation and I might be wholly wrong; all I have to go on is that syncthing didn't seem to register the existence of any files in that repo locally (note: this is not about syncing); when creating a repo named Programs/Mine in the GUI, the GUI said that there were 0 files in it locally (when there were not) and never updated from that. Deleting and recreating with a slashless name made everything work.
- Ah. I found it. It's a GUI bug. The repo itself works (and syncs), but the GUI checks the the status by getting the URL `/rest/model/ ` which ends up being `/rest/model/Programs/Mine` and doesn't match the expected URL pattern, so the GUI keeps saying zero files and status Unknown.
- Bah. Apologies; I should have mentioned that I was using the gui for this!
