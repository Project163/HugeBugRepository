Title

rclone rcd unmount triggers sd-notify STOPPING notification

Description
#### The associated forum post URL from `[URL]
n/a


#### What is the problem you are having with rclone?
rclone rcd creates sd-notify notifications for each mount / unmount operation.  
In case rclone rcd is started as a systemd service this behavior puts the systemd service into the ' deactivating' state and subsequently triggers a SIGABRT by systemd after the stop timeout because the service is not actually stopping.

The culprit is most probably: [URL]

mountlib should not propagate systemd notifications, but only commands should propagate them.

Discussion
- This is because the rcd calls `daemon.SdNotify(false, daemon.SdNotifyReady)` and so does the mount. The calls don't nest apparently!

I think we probably need to reference count the SdNotify calls. So increment a counter and call 
`daemon.SdNotify(false, daemon.SdNotifyReady)` when the counter goes from 0->1 and 
`daemon.SdNotify(false, daemon.SdNotifyStopping)` when the counter goes from 1->0 and otherwise do nothing.

@darthShadow you were the last to touch this code - what do you think?
- Ideally, we shouldn't be calling the SDNotify API at all if it's not the main process. I think this would have worked fine if the mount was started in the daemon mode. @Syquel Can you please confirm if you see the same issue with the daemon option specified for the mount?

If that works, perhaps we should make that the default (or even the only option) for mounts started via rc or is there a use-case for non-daemon mounts via rc?
- It seems that rcd does not support the daemon option.
