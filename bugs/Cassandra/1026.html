Title

Saved row cache continues to be read past max cache size

Description
Scenario: 
 
	 Node has a saved row cache of size n 
	 node OOMs 
	 Make row cache size = .5n to prevent OOM while we debug, restart node. 
	 n items are still read from the row cache, making startup take twice as long as needed. 
 

 (This is intended as a straightforward bug, not as a hackish   CASSANDRA-1966  .)
Discussion
- Note that the second patch applies on top of   CASSANDRA-1966  .
- Committed since the code involved is small, but I note that the applicability is limited because you can't change the cache setting via schema or JMX until the node has started successfully.  So it's only useful if you notice memory pressure and change the setting before the node OOMs.
- Integrated in Cassandra #975 (See  [URL]
