Title

SQLite primary keys are 64 bit but AR treats them as 32 bit

Description
SQLite documentation for an autoincrement column states:

" In SQLite, a column with type INTEGER PRIMARY KEY is an alias for the ROWID (except in WITHOUT ROWID tables) which is always a 64-bit signed integer. "

[URL]

I can then do:

 
sqlite> create table tests (a integer primary key);
sqlite> insert into tests (a) values ( );
sqlite> select * from tests;
 
 

However, trying to set the same field in an active record model fails:

 
irb(main):002:0> class Test   nil
irb(main):003:0> Test.new(a:  ).save!
   (0.1ms)  begin transaction
   (0.1ms)  rollback transaction
RangeError:   is out of range for ActiveRecord::Type::Integer with limit 4
...
 

I initially ran into this issue while trying to use [URL]
Discussion
- I fixed by setting limit to 8 thusly: [URL]
- There's a "default limit" in `activemodel/lib/active_model/type/integer.rb`. Comments imply that changing it might cause problems in MySQL or Postgres. Any ideas?

```
# Column storage size in bytes.
# 4 bytes means a MySQL int or Postgres integer as opposed to smallint etc.
DEFAULT_LIMIT = 4
```
- Default limit should take into account the column type and the database engine.
