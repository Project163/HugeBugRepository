Title

Config uses tox file even when no flake8 config in it

Description
In GitLab by @adamchainz on Nov 21, 2016, 03:51

*Please describe how you installed Flake8*

```
$ pip install flake8
```

*Please provide the exact, unmodified output of `flake8 --bug-report`*

```
$ flake8 --bug-report
{
  "dependencies": [
    {
      "dependency": "setuptools",
... [Log Snipped] ...
  "version": "3.2.0"
}
```

*Please describe the problem or feature*

I have a project with many subprojects each using `tox`. I'd like to define my lint rules at the top level in a `setup.cfg` and have individual `tox.ini` files for each subproject.

Currently the existence of `tox.ini`, without a `flake8` header, causes `flake8` to consider itself 'configured' with just the defaults, and the search for the config stops. I would expect it to find the flake8 config in my `setup.cfg` instead.

It's also non-deterministic based upon the current directory when `flake8` is run.

My current workaround is to always invoke `flake8` with `--config` pointed to the absolute path of the config file, which isn't ideal.

*If this is a bug report, please explain with examples (and example code) what you expected to happen and what actually happened.*

```
$ tree .
.
├── setup.cfg
└── subproj
    ├── test.py
... [Log Snipped] ...
$ flake8  # fails
./test.py:1:80: E501 line too long (98 > 79 characters)
```
