Title

bigint column type being parsed as regular integer in sqlite3

Description
I am trying to create an sqlite table on which one of the columns is a bigint. However, this is always getting parsed as a normal integer and creation of records is failing with the following error
`RangeError: 70026099423600 is out of range for ActiveRecord::Type::Integer with limit 4
`
Here is a reproduction script:

```
ruby
# Activate the gem you are reporting the issue against.
gem 'activerecord', '4.2.0'
require 'active_record'
require 'minitest/autorun'
... [Log Snipped] ...
  end
end
```
Discussion
- One could argue that it is more correct to set `limit: 8` to **all** SQLite3 `Integer` types, as per: [URL]

That means that `INT`, `INTEGER`, `TINYINT`, `SMALLINT`, `MEDIUMINT`, `BIGINT`, `UNSIGNED BIG INT`, `INT2`, `INT8` all result in the datatype `INTEGER` and automatic limit up to 8 bytes.
**NB!**: the documentation does not mention `int4` but it is actually supported in a similar manner.

I would suggest that all integer types that do not explicitly state lower limit (i.e. `int`, `integer`, `int8` and `bigint`) should result in `limit: 8` as otherwise it might break expectations from the field type (with regards to the SQLite3 documentation).

This is relevant especially in the case where AR is not the creator of the database, thus the type definition might differ from what AR would assume.
- Is there any way to disable range checking?  It doesn't appear to be documented anywhere.

The feature seems quite prone to bugs, for example "smallint(5)" in a mysql database is read as "limit 2" for some reason.  The normal size for a smallint is 6, but I'm only storing zip-codes in it so it was 5.  Fixing the database isn't very easy with 20m rows...
- ... [Middle Discussions Snipped for Brevity] ...
- Also to answer your original question, there is no way to disable range checking, but using the attributes in Rails 5, you could set a larger range manually by adding

```
attribute :zip_code, :integer, limit: 8
```

In Rails 4.2 you could do the same (using a private, internal API, and standard warnings about doing that apply) with:

```
attribute :zip_code, Type::Integer.new(limit: 8)
```
- I have also had problems with Postgres. The migration with `t.integer :foo, limit: 2` ran fine but the schema generated was only `integer`. I'm using Rails 4.2.3.
