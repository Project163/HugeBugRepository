Title

Can't find Catch::rngSeed anymore in Catch2

Description
## Description

My CI just broke tonight because it can't apparently find `Catch::rngSeed()` anymore. Wherever I used it, I've now got the following error with MinGW-w64 g++7.1:

    error: 'rngSeed' is not a member of 'Catch'

It seems weird considering that the function seems to remain in the source.

### Steps to reproduce

Just try to compile anything with `Catch::rngSeed()`.

### Extra information

It's also worth nothing that the header `internal/catch_random_number_generator.h` even though it looks harmless. It doesn't seem to be causing the problem.

* Catch version: **v2.0.1**
* Operating System: **Ubuntu & Windows**
* Compiler+version: **MinGW-w64 g++ 7.1, g++5, clang++3.8**
Discussion
- I want to say that this is why you shouldn't clone ToT of dependency, but that is not really helpful. The crux of the issue is that at some point `rngSeed` was no longer dependency of Catch's main interface, and so the stitching script moved it into non-interface part of Catch. This means that it is only provided in the file that defines `CATCH_CONFIG_RUNNER` or `CATCH_CONFIG_MAIN`.

I will have to check if we promised `Catch::rngSeed` as a part of our external interface, if yes we will move it back. In the meantime, you can work around the issue by calling `Catch::getCurrentContext().getConfig()->rngSeed()`.
- Ok, I will work around it for now, thanks :)

EDIT: welp, looks like `getCurrentContext` is just as unavailable as `rngSeed` when `CATCH_CONFIG_RUNNER` and `CATCH_CONFIG_MAIN` aren't defined, so the workaround sin't working either, unless Im missing something.

I don't think that `Catch::rngSeed` was ever actually promised as part of the interface. IIRC I found about it while reading an issue, but the ability to give a seed from the command line, use it wherever I want to, and get it logged when an error occurs was too good not to use it.
- Sorry, I expected context to be part of what we leak to the outside world.

Anyway, we will try to establish more firm external API in the future (`rngSeed` will likely end up being part of it).
