Title

S3 file download does not gracefully handle connection errors

Description
When downloading large object from S3, it's not uncommon to get a ConnectionClosedException or something else similar. We should be able to handle this gracefully and restart the download from the last place we have recorded.
Discussion
- I've tried a custom "ResumableInputStream" implementation that submits a new GetObject request with the already-read-bytes offset, and it outperforms the  S3 TransferManager  significantly. The TransferManager is about 5x slower than just doing it ourselves. So that's probably the best way forward, since the TransferManager also requires that we use the AsyncClient for AWS, which we don't currently.
