Title

NgModule syntax with Ivy turned on

Description
### Description

When having a simple Angular 9 app and do some logic in `NgModule` I can not build/serve the app successfully.

## 🔬 Minimal Reproduction
1. ng new \ 
2. Be on Angular 9
3. Change `app.module` to:
  
import { BrowserModule } from '@angular/platform-browser';
import { NgModule } from '@angular/core';

import { AppComponent } from './app.component';

function getNgModuleData(){
  return {
    declarations: [AppComponent],
    imports: [BrowserModule],
    providers: [],
    bootstrap: [AppComponent]
  }
}

const { declarations, imports, providers, bootstrap } = getNgModuleData();

@NgModule({ declarations, imports, providers, bootstrap })
export class AppModule { }
  

## 🔥 Exception or Error
  
▶ yarn build      
yarn run v1.13.0
$ ng build

ERROR in src/app/app.module.ts:17:13 - error NG1010: Expected array when reading the NgModule.declarations of AppModule

17 @NgModule({ declarations, imports, providers, bootstrap })
               ~~~~~~~~~~~~

error Command failed with exit code 1.
info Visit [URL] for documentation about this command.


  

What's more: `bootstrap` property is underlined with red line in my IDE saying that:  `Expression does not resolve to an array of class types or a class type `

##  Workaround
  

import { BrowserModule } from '@angular/platform-browser';
import { NgModule } from '@angular/core';

import { AppComponent } from './app.component';

function getNgModuleData(){
  return {
    declarations: [AppComponent],
    imports: [BrowserModule],
    providers: [],
    bootstrap: [AppComponent]
  }
}

const declarations = getNgModuleData().declarations;
const imports = getNgModuleData().imports;
const providers = getNgModuleData().providers;
const bootstrap = getNgModuleData().bootstrap;

@NgModule({ declarations, imports, providers, bootstrap })
export class AppModule { }

- Hi @mikolaj-leszczynski,

I can do better than that!

Ivy places certain requirements on the arguments to Angular decorators (a la `NgModule`):

1. They must be statically understandable
2. They must be object literals, not expressions such as references to other variables.

Currently our static interpreter does not understand the destructuring syntax in your example:
```typescript
const { declarations, imports, providers, bootstrap } = getNgModuleData();
```

I suspect that we resolve `declarations` in `@NgModule({declarations, ...})` to this variable declaration, but in a way that our interpreter doesn't know how to evaluate. This should be pretty easily fixable. :)
