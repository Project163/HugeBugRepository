Title

ClassCastException in Qute BuiltinTemplateExtensions.map on a TreeMap with {#for entry in map.entrySet}

Description
**Describe the bug**
BuiltinTemplateExtensions.map() tries to call map.get(String), which is not safe for a TreeMap with a Comparator, as it will try to cast the String to the expected type for the Comparator.
This results in an Internal Server Error due to ClassCastException.

**Expected behavior**
doing {#for entry in map.entrySet} should work equally well for a HashMap and a TreeMap (only the iteration order should differ).

**Actual behavior**
With a HashMap, {#for entry in map.entrySet} works as expected.
With a TreeMap (where key type is NOT a String), this results in an Internal Server Error due to ClassCastException.

See gist for simple example of foo.html template and a FooResource.java class, and the output thereof

 - Quarkus version: 1.2.0.Final

- So the problem here is that whenever we find an identifier that resolves to a map we do consider the next part of the expression a map key and try to lookup the value. Which of course does not make sense for `map.entrySet` but is very useful in many other use cases.

Well, the idea comes from the mustache/javascript world where an object is basically a collection of name-value pairs (speaking of properties). I personally like it because `Map.get()` is 90% what users do when working with maps in templates and so it's quite convenient.
- I've decided to align `BuiltinTemplateExtensions.map()` with `ValueResolvers.mapResolver()`, ie. add a special case for `entrySet()` and try `get()` last.
