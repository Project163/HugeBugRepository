Title

`import { ... } 'library'` syntax in `pkg.module` target leads to "Cannot read property '0' of undefined"

Description
**Do you want to request a *feature* or report a *bug*?**

I am reporting a bug.  (Ping @kkainu @auramo @afhole)

 
 

**What is the current behavior?**

When trying to import from a `pkg.module` using ES2015 module syntax (but otherwise ES5 syntax) and the module contains an `import { entry1, ... } from 'library'` declaration, WebPack crashes.

**If the current behavior is a bug, please provide the steps to reproduce.**

Clone [Link: this repository] and follow the instructions in the README.

 
 
 

**What is the expected behavior?**

The expected behavior would be for WebPack to run to completion without crashing.

If the `import { ... } from 'lib'` syntax is replaced with `import * as Lib from 'lib'` syntax, WebPack runs to completion.  Specifically, after running `npm i`, replace the first line of `node_modules/partial.lenses/dist/partial.lenses.es.js`, which is

```js
import { acyclicEqualsU, always, applyU, arityN, array0, assocPartialU, constructorOf, curry, curryN, dissocPartialU, hasU, id, identicalU, isDefined, isFunction, isObject, isString, keys, object0, pipe2U, sndU } from 'infestines';
```

with the following:

```
js
import * as I from 'infestines';
var acyclicEqualsU = I.acyclicEqualsU;
var always = I.always;
var applyU = I.applyU;
... [Log Snipped] ...
var pipe2U = I.pipe2U;
var sndU = I.sndU;
```

and then run `npm run test` and WebPack will run to completion.
