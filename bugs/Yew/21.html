Title

Licensing issue: ssri is not permissively-licensed!

Description
**Problem**
 
Yew is [Link: using ssri as one of its dependencies]. That's great! The problem is that ssri@6 uses a [Link: non-permissive Parity license], which means that while Yew can keep being licensed the way it is, people using Yew in proprietary situations would not be compliant with this license because they're pulling in ssri as a _dependency_ anyway.

The good news: because of this, and because I don't want to cause any trouble for anyone who may have accidentally used ssri like this, I've released [Link: ssri@7.0.0], which changes the Parity-licensed code to be `Apache-2.0` instead, which is 100% compatible.

As an additional thing: I hereby grant usage of `ssri@6.0.0` and below to anyone using it through Yew, as if it had been licensed to them under `Apache-2.0`. Hopefully this declaration also means that previously-released Yew versions are not "vulnerable" to this licensing situation. Please let me know if there's anything I can do to solidify this promise, as I have no intention on jumping on anyone over this. I just want Rust hacks to be good and positive
