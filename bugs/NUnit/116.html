Title

TestResult class needs to be thread-safe

Description
As any test finishes, on its own thread, it updates its own test result and adds that result to the parent Result. This is an obvious point where different threads can come into conflict, so the Children property of TestSuiteResult needs to be thread-safe. For the last child test of a parent, additional updates are done, which can ripple up the result hierarchy all the way to the top.

Additionally, the SetResult method should be examined since it is called on other occasions in addition to a call from within AddResult.

If it's reasonably easy, the whole class could be made thread-safe, but the above items seem to represent the minimum.

I'm calling this a bug, even though we have not had problems reported, since it's obvious that threading conflicts can occur. This should be fixed before we attempt to run test cases in parallel within a fixture, since that would increase the probability of a collision significantly.
