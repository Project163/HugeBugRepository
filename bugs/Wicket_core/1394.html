Title

OSGi-Manifest: wicket does not declare BSN

Description
I try to upgrade a project to OSGi and encountered the issue that the current 8.0.0-M6 build seem to have no valid (OSGi-) Manifest 
 [org.apache.wicket/wicket-util/8.0.0-M6]  is not a valid bundle (bundleSymbolicName and bundleName are null) 

 It seems that OSGi-Manifest information is lost on all jar files.
Discussion
- wicket-util's META-INF/MANIFEST.MF contains "Bundle-SymbolicName: org.apache.wicket.util" 
hat exactly is wrong with it ? And how to fix it ? 

 No one from us uses OSGi, so please suggest what changes have to be applied to improve the OSGi experience!

The manifest looks like this: 

  
 Manifest-Version: 1.0
Implementation-Title: Wicket Core

Specification-Title: Wicket Core

Specification-Version: 8.0
Implementation-URL: [URL]

 So no BSN, no Export/Import headers... Maybe something changed in the packaging between 7 and 8? 
One option to easily improve OSGi-Experience would be to use the felix-bundle plugin  [URL] and packaging "bundle" that will compute all headers automatically. For a frist start teh configuration can be as simple as (it could be tweaked later on): 

  
  <plugin>
    <groupId>org.apache.felix</groupId>
    <artifactId>maven-bundle-plugin</artifactId>
    <extensions>true</extensions>
    <configuration>
      <instructions>
        <Export-Package>*</Export-Package>
        <Import-Package>
          org.apache.wicket.*,
          *;resolution:=optional
        </Import-Package>
      </instructions>
    </configuration>
  </plugin>
 
  
 This produces a good starting point and you can even use this to check semantic versioning between releases (if you are interested)
