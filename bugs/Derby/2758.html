- Attaching derby-6189-01-aa-invalidateTable.diff. This patch eliminates the NPE. I will run regression tests. 

 The NPE occurs in a method which doesn't expect to be called on a non-existent temp table. Derby falls into this code because the test case sets up the following sequence of events: 

 1) AutoCommit is turned off. 

 2) A temp table is created. 

 3) An insert into the temp table is prepared. 

 4) The transaction is rolled back. Here Derby deletes the temp table because it was declared in the transaction which is rolled back. But the language layer is not notified that PreparedStatements involving the temp table are now invalid. 

 5) Then the PreparedStatement is executed. This causes Derby to fall into logic which expects the temp table to exist and this trips an NPE. 

 The fix is to invalidate PreparedStatements involving the temp table in step (4).
