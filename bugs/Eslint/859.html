Title

constructor-super - super() must be called even if the class extends null

Description
**What version of ESLint are you using?**
**What configuration and parser (Espree, Babel-ESLint, etc.) are you using?**

I'm using the online demo with the default configuration (+ `es6`).

**What did you do? Please include the actual source code causing the issue.**

``` js
class A extends null {
    constructor() {
        super();
    }
}

new A();
```

``` js
class B extends null {
    constructor() {}
}

new B();
```

**What did you expect to happen?**

The first code should be fine, in the second ESLint should warn `2:2 - Expected to call 'super()'.`

**What actually happened? Please include the actual, raw output from ESLint.**

ESLint warns `3:3 - Unexpected 'super()'.` for the first code, while the second is considered fine.

**Specification:**
- In a class definition, if _ClassHeritage_ is present (so even if it is `extends null`), the class' _[Link: [ConstructorKind]]_ internal slot is set to `"derived"`.  [14.5.14] - step 15 
- When instantiating a new class [Link: 9.2.2 - [[Construct]]] , _OrdinaryCallBindThis_ [Link:  ]  (which sets _envRec.[Link: [thisBindingStatus]]_ to `"initialized"` by calling the _BindThisValue_ [ .1] ) is only called if `[Link: [ConstructorKind]]` is `"base"` [9.2.2] - Steps 4 and 8 , so _envRec.[[thisBindingStatus]]_ remains `"uninitialized"` even if the class `extends null`.
- The _[Link: [Construct]]_ function [9.2.2] - step 15  returns the result of calling the _envRec.GetThisBinding()_ function, which throws if _envRec.[Link: [thisBindingStatus]]_ is `"uninitialized"` [ .4] - Step 3 .
