Title

Documents in a data stream can be deleted via the bulk API

Description
**Elasticsearch version** (`bin/elasticsearch --version`): 7.9.1

**Plugins installed**: none

**JVM version** (`java -version`): irrelevant

**OS version** (`uname -a` if on a Unix-like system): irrelevant

**Description of the problem including expected versus actual behavior**:

In the docs we state that [Link: only `create` is allowed as action in bulk requests] for data streams. However, it is possible to use other actions as well with Elasticsearch 7.9.1.

* Expectation: Any bulk item with an operation type other than `create` fails with an `IllegalArgumentException` with a message "only write ops with an op_type of create are allowed in data streams".
* Actual behavior: The bulk request succeeds

**Steps to reproduce**:

In the following example we setup a data stream according to the docs:

```
curl -X PUT "localhost:9200/_ilm/policy/my-data-stream-policy?pretty" -H 'Content-Type: application/json' -d'
{
  "policy": {
    "phases": {
      "hot": {
... [Log Snipped] ...
}
'
```

Once it is setup, we will index a single document into it. This requires `jq` so we can extract the document id automatically.

```
DOC_ID=$(curl -s -X POST "localhost:9200/my-data-stream/_doc?pretty" -H 'Content-Type: application/json' -d'
{
  "@timestamp": "2020-12-06T11:04:05.000Z",
  "user": {
    "id": "vlb44hny"
... [Log Snipped] ...
}
' | jq -r ._id)
```

Attempting to delete a single document via the data stream will fail (as expected):

```
curl -X DELETE "localhost:9200/my-data-stream/_doc/$DOC_ID?pretty"

# response:

{
... [Log Snipped] ...
  "status" : 400
}
```

However, if we attempt to do the same via the bulk API, the request succeeds:

```
curl -X PUT "localhost:9200/my-data-stream/_bulk?refresh&pretty" -H 'Content-Type: application/json' -d"
{\"create\":{ }}
{ \"@timestamp\": \"2020-12-08T11:06:07.000Z\", \"user\": { \"id\": \"8a4f500d\" }, \"message\": \"Login successful\" }
{ \"delete\" : { \"_id\" : \"$DOC_ID\
...[Description Truncated]...
Discussion
- Pinging @elastic/es-core-features (:Core/Features/Data streams)
- Actually the bug is worse. The validation that checks that only create ops are allowed to go into a data stream is skipped for all bulk items after the first create operation in a data stream.
