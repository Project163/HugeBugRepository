[4.0.0-rc.3] Error loading BrowserAnimationsModule via UMD bundle global variables

**Current behavior**
I'm using webpack with externals to load modules via global variables. In @4.0.0-rc.2 the UMD bundle for the BrowserAnimationsModule (platform-browser-animations.umd.js) was adding an animations variable to ng.platformBrowser (ng.platformBrowser.animations). This is not happening in rc.3 now. Simply adding "ng.platformBrowser.animations = exports;" to the bottom of the UMD bundle fixes it. Is this just referenced via a different global variable now, or is this an actual bug?

After that error is fixed I get another error occurring due to the bundle referencing the wrong global variable for the animations module in the factory function. It is currently referencing "global._angular_animations" and that needs to be set to "global.ng.animations" for it to be provided to the module correctly.

**Expected behavior**
No errors about missing BrowserAnimationsModule.
