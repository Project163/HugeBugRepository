Title

coerce str objects to the String datatype, not Unicode

Description
when we make an expression like this:


`literal('some string')`

the datatype should be String and not Unicode.  All DBAPIs accept Python string objects for VARCHAR etc. which are now all unicode.   The only difference that remains between String and Unicode is for big vendor DBs mssql and Oracle which imply NVARCHAR, NCLOB, etc.  These datatypes are known to be highly problematic when used in WHERE criteria etc. as they tend to cause indexes to be skipped and such.    

now that we are py3k only, the Unicode datatype should become a lesser used construct that's only required for the case when one wants to force "national" datatypes like NVARCHAR to be used, which is usually not the case.
