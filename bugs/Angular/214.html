Title

bug(forms): controlgroup add/remove control doesn't trigger change detection properly

Description
- **I'm submitting a ...**
- [x] bug report
- [ ] feature request
- [ ] support request => Please do not submit support request here, see note at the top of this template.

**Current behavior**

Change detection seems not to work properly when calling addControl or removeControl from a ControlGroup after the form has been initialized.

When a control is added or removed from the control group, the form's value and validation is not re-evaluated in the template.  This can lead to cases where the form becomes unsubmitable or requires the user to do some janky workaround.

**Expected/desired behavior**

Adding or removing controls from a ControlGroup should trigger change detection that re-evaluates the form state based on the new control state.
- **If the current behavior is a bug, please provide the steps to reproduce and if possible a minimal demo of the problem** via

[URL]

This plunk demonstrates a form that can mutate based on values of its controls.  When the select box has the value 'yes', another input control is added to the form.  When the select box has the value 'no' the input control should be removed from the form.

Currently, adding the control works, but removing the control doesn't show the control removed in the interpolated form value.  The button also remains disabled if the text box is empty and the select value changes to 'no'.

When I inspect the value of the controlgroup, I can see that the control is actually removed/added to the group, as expected.  It just seems that the template does not pick up on the changes, correctly.
- **What is the expected behavior?**

When the textbox is empty and the select value changes from 'yes' to 'no', the button should become enabled based on the validity of the select control.

When the select value changes from 'yes' to 'no', the interpolated value of the form should show that the input control has been removed from the form's ControlGroup.
