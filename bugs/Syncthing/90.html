- It seems almost as if the best solution is if Syncthing can notify the user of this issue, and offer to rename it. Otherwise, it would simply have to ignore it. If files exist on other nodes, they will want to sync with the Linux computer. Unless the Linux computer refuses to sync the file, itll take the file with the standard encoding set anyway. Even ignoring it won't really work. I suspect the user will have to take action in this case.

In fact, this is basically how I have worked around this problem, was just to simply change the character to one where Syncthing does sync the file properly. I suspect users will simply do this if they are notified to, if they are paying attention.
- IMHO, a simple solution would be to detect issues with strange normalizations, show a warning, and then also refuse to accept files with alternate encodings.  If this would prevent a repository from reaching 100% sync, it would also be a good way of exposing the problem to other nodes in the system.
