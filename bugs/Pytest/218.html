Discussion
- interesting find - i believe the pass-over of stack-level has gotten messed up
the error originates in the fact that our wrapper has args/kwargs and sets up a stacklevel argument

now if someone passes stacklevel as positional argument (which is valid but really bad use of the api) we have more than was bargained for
- Ok, I understand now: The new code in pytest 3.9.2 added the handling of the `stacklevel` argument, but only when passed as keyword argument. See `_pytest/recwarn.py` line 159 (in 3.9.2).

On passing stacklevel as positional argument: The Python `warnings.warn()` method is documented as follows (see [URL]
```
warnings.warn(message[, category[, stacklevel]])
```

How should I gather from this api that passing `stacklevel` as a positional argument is a "really bad use of the api"?
- Use keyword argument instead:

```python
def issue_warning():
   warnings.warn(
        "Setting the xyz property is deprecated",
        DeprecationWarning, stacklevel=2)
```

It makes for more readable code.
