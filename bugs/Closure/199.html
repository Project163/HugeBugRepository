Title

--flagfile option does not treat quoted strings as single tokens

Description
Flag file entries such as: --js='/usr/my project/app.js' are split on whitespace such that "/usr/my" and "project/app.js" are treated as separate tokens.

The attached patch corrects this issue using a custom tokenizer method tokenizeKeepingQuotedStrings(). The following JUnit test was used in a separate project to test this method:

@Test public void tokenizeKeepingQuotedStrings() {
  String data = "t1 \"t2\" t3='quoted string' --t4=\"/my project/app.js\" "
      + String.format("%n") + "'adjacent content't5 t6='single'";
  List<String> tokens = StringUtil.tokenizeKeepingQuotedStrings(data);
  List<String> expected = ImmutableList.of("t1", "\"t2\"", "t3='quoted string'",
      "--t4=\"/my project/app.js\"", "'adjacent content't5", "t6='single'");
  assertEquals(expected, tokens);
}

The patch has been tested on a small project using a flag file. In addition, "ant test" ran successfully.
