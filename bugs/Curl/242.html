Title

--aws-sigv4 does not behave well with AWS VPC Lattice services

Description
### I did this

Downloaded curl curl-8.0.1, patched like:

```
~/environment/curl-8.0.1 $ diff lib/http_aws_sigv4.c*
350c350
<   if(false) {
---
... [Log Snipped] ...
---
```

So I could run:

```
$ ./src/curl --aws-sigv4 "aws:amz:eu-west-1:vpc-lattice-svcs" --user "${ACCESS_KEY_ID}:${SECRET_ACCESS_KEY}" -H "x-amz-security-token: $SESSION_TOKEN" [URL] 
yes this is patrick
```

### I expected the following

Same thing without the patch :)

### More details

Our of the box, a `curl --aws-sigv4 "aws:amz:eu-west-1:vpc-lattice-svcs" --user "${ACCESS_KEY_ID}:${SECRET_ACCESS_KEY}" -H "x-amz-security-token: $SESSION_TOKEN" [URL] gave me the following error:

```
IncompleteSignatureException: Missing the 'x-amz-content-sha256' in canonical headers
```

Upon reading [URL] I modified just the `strcasecompare` so vpc-lattice-svcs would get the same logic for signature than s3. It was not enough, as `curl` gave me `InvalidSignatureException: Signed payloads are not supported` (which is correct [Link: according to this service's documentation: "VPC Lattice does not support payload signing, therefore you must send x-amz-content-sha256 header with value set to "UNSIGNED-PAYLOAD"."]), hence my dirty bypass with the `if(false)` to the payload signing block.
