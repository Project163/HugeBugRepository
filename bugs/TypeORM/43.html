I get 500 a Internal Server Error without a message.
the  best approach should be updating the mssql?

finally I update to mssql 2016 and found that if you use a primary key type string in this query:
```javascript
let post = await postRepository
                .createQueryBuilder("p")
                .setFirstResult(0)
                .setMaxResults(10)
                .getMany();
```
It will give you a error in the query generated in:
```
sql
// this works fine
executing query: 
SELECT DISTINCT("distinctAlias"."u_stringID") as ids_entity 
FROM (
... [Log Snipped] ...
WHERE "u"."stringID" 
IN (stringID1, stringID2, stringID3, stringID4, stringID5, stringID6, stringID7, stringID8, stringID9, stringID10 )
```
It seems it fails because treats as a number, without quotes.
but in my entity class a declare as:
```typescript
@PrimaryColumn('string', {length:'32'})
    stringID: string;
```
Discussion
- Why when I use setFirstResult and setMaxResult use a DISTINCT?
```
typescript
let posts = await postRepository
                .createQueryBuilder('p')
                .select(['p.name', 'p.deletedAt'])
                .from(Post,'p')
... [Log Snipped] ...
                .setMaxResults(10)
                .getMany();
```
DISTINCT is unnecessary for pagination:
```sql
SELECT DISTINCT("distinctAlias"."p_id") as ids_post, "distinctAlias"."p_name" 
FROM (SELECT "p"."name", "p"."deletedAt" FROM "post" "p" WHERE "p"."deletedAt" IS NULL) "distinctAlias" 
ORDER BY "distinctAlias"."p_name" ASC 
OFFSET 0 ROWS FETCH NEXT 10 ROWS ONLY
``` 
Just want to use this query for pagination:
```sql
SELECT "p"."name", "p"."deletedAt" 
FROM "post" "p"
WHERE "p"."deletedAt" IS NULL
ORDER BY "p"."name" ASC 
OFFSET 0 ROWS FETCH NEXT 10 ROWS ONLY;
```
Or something I'm doing wrong
- pagination is not a simple process once you get more complicated data returned by a database for you such as joins. It makes two queries to resolve related issues and make pagination really correct. If you don't want this complexity and you simply need to execute:

```sql
SELECT "p"."name", "p"."deletedAt" 
FROM "post" "p"
WHERE "p"."deletedAt" IS NULL
ORDER BY "p"."name" ASC 
OFFSET 0 ROWS FETCH NEXT 10 ROWS ONLY;
```

then simply use `setLimit(...).setOffset(...)` instead of setFirstResult and setMaxResults methods.
