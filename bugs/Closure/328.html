Title

Source map locations are wrong when using goog.scope

Description
What version of the product are you using? On what operating system? 
Closure Compiler (http://code.google.com/closure/compiler)
Version: v20140110
Built on: 2014/01/14 16:25

Debian GNU/Linux Xfce

 Please provide any additional information below. 
Consider this simple assert module:

  goog.provide("log")

  log.assert = function (x) {
    if (!x) {
      throw new Error("Assertion failed")
    }
  }

Now consider this simple program that uses the assert module:

  goog.provide("foo")
  goog.require("log")

  foo.init = function () {
    log.assert(false)
    log.assert(false)
  }

  foo.init()

If you compile the above with ADVANCED_OPTIMIZATIONS and generate a source map, the error will correctly point to foo.js, line 5. Now, if you shorten the assert form, like so...

  goog.provide("foo")
  goog.require("log")

  var assert = log.assert

  foo.init = function () {
    assert(false)
    assert(false)
  }

  foo.init()

It correctly shows foo.js, line 7. But if you wrap it in goog.scope...

  goog.provide("foo")
  goog.require("log")

  goog.scope(function () {
    var assert = log.assert
  
    foo.init = function () {
      assert(false)
      assert(false)
    }
  })

  foo.init()

It then INCORRECTLY shows foo.js, line 5.

It appears that when the compiler does the goog.scope aliasing, it uses the line/column of the "var assert = ..." rather than the "assert(...)"
