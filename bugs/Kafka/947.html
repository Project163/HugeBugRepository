- rajiv@signalfx.com  Looks like these EOFExceptions are avoidable by checking whether the underlying buffer has data remaining. However, I'm still a bit puzzled by the number reported. In the current implementation, I would expect to see at most one EOFException for each partition in every fetch response. If there are about 64 partitions and "fetch.max.wait.ms" is 1000, then we should see about 64 exceptions raised each second (when there is not much data to fetch). Perhaps most of the exceptions occurred during a load spike or maybe when it was catching up initially?
- However, I do see significantly more exceptions when the topic has been compressed (I tried snappy locally). Are you sure that the topic is not compressed?
