Title

[YSQL] test problem in TestAlterTableWithConcurrentTxn and TestDropTableWithConcurrentTxn

Description
Jira Link: [Link: DB-18451]
### Description

The tests TestAlterTableWithConcurrentTxn and TestDropTableWithConcurrentTxn verifies that DDL effect is seen or not seen by a DML on another connection. For example, if DML connections starts a BEGIN transaction, then DDL connection alters a table, then DML connection makes a query on the table. Depending on whether the DML connection has already cached the table or not, the expected result is verified by these two tests.

However I have identified two cases (one in each test) where the DML connection is meant to test the scenario where the table is not cached, but in reality the DML connection has actually cached the table. The reason that the DML connection has cached the table is because the DML connection happens to be the first connection after a previous DDL statement that incremented the catalog version. Therefore the DML connection during its establishment needed to rebuild the relcache init file. As part of that it preloaded the catalog caches and therefore has accidentally cached the test table. So in these two scenarios the test is not doing what it meant to test.

We can fix these two scenarios by making a temp connection prior to the DML connection so that the temp connection is responsible for rebuilding relcache init file, and the DML connection becomes a "subsequent" connection that does not need to rebuild relcache init file, and therefore avoids caching the table accidentally.
