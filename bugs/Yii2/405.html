Title

FragmentCache storing empty content causes problem with PageCache

Description
Assuming PageCache is enabled for an action:
- In case of an exception, `ob_get_clean()` in `FragmentCache::run()` returns `false` (since the error handler cleared it), but it will still be cached. Usually not a problem because `getCachedContent()` returns `false` if content is `false`. But if we had dynamic content in the view, `getCachedContent()` will return an empty string instead (because of call to `updateDynamicPlaceholders()`). This means on next page load we get a white page.

Fix: Check whether `false` is returned and just `return;` in this case: [URL]
- When doing `return $this->redirect(...);`, `ob_get_clean()` in `FragmentCache::run()` will return an empty string which will be stored in cache. If `PageCache::$cacheHeaders` is enabled, this is not a problem, because we get a redirect instead of white page. If `$cacheHeaders` is disabled though, we get a white page again.

Fix A: Same as fix on top, but instead also check for empty string.
Fix B: Clear output buffer in `Response::redirect()` so that `ob_get_clean()` in `FragmentCache` returns `false` instead of empty string.

A or B? I tend to A, but it would mean caching empty strings with fragment cache is not possible anymore. Also caching redirects would not be possible anymore in either case, but it's not expected behaviour anyway imo. Let me know so I can make PR.

Another issue is that page cache will store headers even if fragment cache did not store anything. This is part of bigger problem (page cache does not know about fragment cache). Not harmful though, just unnecessary. Related: [URL]
