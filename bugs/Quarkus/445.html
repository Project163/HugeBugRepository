Title

Kubernetes: liveness and readiness probes ignore the `quarkus.http.root-path` setting

Description
**Describe the bug**

When I configure `quarkus.http.root-path`, the `/health` endpoint is moved under it (as well as `/metrics`, but that is irrelevant here). That seems to be intentional, per [URL] The generated Kubernetes probes don't reflect that, however.

**Expected behavior**

Autogenerated liveness and readiness probes point to the real health endpoint, even if `quarkus.http.root-path` is defined.

**Actual behavior**

If `quarkus.http.root-path` is defined, the autogenerated liveness and readiness probes point to a non-existing path and the pod never starts successfully.

**To Reproduce**

```properties
quarkus.http.root-path=/api
```

The generated Kubernetes YAML looks like:

```
yaml
apiVersion: "apps/v1"
kind: "Deployment"
metadata:
  ...
... [Log Snipped] ...
            scheme: "HTTP"
          ...
```

The OpenShift YAML is identical in this regard.

However, the health endpoint is at `/api/health`.
