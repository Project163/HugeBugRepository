Title

MongoDB-Liquibase does not pick up children ChangeLogs in native mode when using includeAll

Description
### Describe the bug

When defining a changelog with a relative path linking to other changelogs, they are not found when launching a native application.

Given this hierarchy
```
.
└── resources/
    ├── db/
    │   ├── changeLogs/
    │   │   └── my-changeSet.yaml
    │   └── main-changeLog.yaml
    └── application.properties
```
where the `application.properties` defines `quarkus.liquibase-mongodb.change-log=db/main-changeLog.yaml` and where `main-changeLog.yaml` asks to retrieve changelogs from the `changeLogs/` directory
```
databaseChangeLog:
  - includeAll:
      relativeToChangelogFile: true
      path: changeLogs
      maxDepth: 1
```

`my-changeSet.yaml` will be correctly applied in JVM mode, while in native mode Liquibase will throw an error on startup
```
2025-03-25 19:05:58,595 ERROR [io.qua.run.Application] (main) Failed to start application: java.lang.RuntimeException: Failed to start quarkus
        at io.quarkus.runner.ApplicationImpl.doStart(Unknown Source)
        at io.quarkus.runtime.Application.start(Application.java:101)
        at io.quarkus.runtime.ApplicationLifecycleManager.run(ApplicationLifecycleManager.java:121)
        at io.quarkus.runtime.Quarkus.run(Quarkus.java:77)
... [Log Snipped] ...
        at liquibase.parser.core.yaml.YamlChangeLogParser.parse(YamlChangeLogParser.java:92)
        ... 23 more
```

I also added `quarkus.native.resources.includes = db/**`, but to no avail. As I understand it this is not important since the path resolution is done at build time.

Weirdly enough using `include` instead of `includeAll` to reference the file explicitly will work as expected in native mode:
```
databaseChangeLog:
  - include:
      file: changeLogs/changeSet.yaml
      relativeToChangelogFile: true
```
