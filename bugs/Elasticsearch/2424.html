Title

InternalEngine#releaseIndexCommit may fail with AlreadyClosedException

Description
If the engine is closed while we hold an index commit (e.g. responding to shard fetching) then the release of that commit will throw an `AlreadyClosedException` since it calls `IndexWriter#deleteUnusedFiles`. This can happen if, for instance, a node leaves and rejoins the cluster since shard fetching may occur concurrently with the shard shutting down. This seems unnecessarily harsh: we already obtained the store snapshot so we should just return it. It doesn't seem to matter if `IndexWriter#deleteUnusedFiles` fails here, the files will be cleaned up when the engine restarts.

I didn't see an obvious reason for throwing `AlreadyClosedException` from `InternalEngine#releaseIndexCommit` so I think a simple fix would be to catch and suppress that exception there. WDYT?
