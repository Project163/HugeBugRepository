Title

remote client sorts strings by UTF-16 representation rather than code point

Description
The REAPI generally mandates repeated string fields in its protobuf messages be sorted by code point or equivalently UTF-8 representation. Bazel tends to use the natural ordering of `String` in Java to sort, which is not equivalent to ordering by code point.

For example, this test demonstrates that `Command.output_paths` are sorted improperly:
```
@Test
  public void buildRemoteAction_SMP() throws Exception {
    var one = "path/ﾐ";
    var oneF = execRoot.getRelative(unicodeToInternal(one)).asFragment();
    var two = "path/🔥";
... [Log Snipped] ...
        .inOrder();
  }
```
Indeed, ﾐ (U+FF90) < 🔥 (U+1F525).
Discussion
- There's also `Command.environment_variables`, `Directory.files`, `Directory.directories`, and `Directory.symlinks` with the same issue.
