Title

Error: EMFILE: too many open files, open..

Description
**I'm submitting a bug report**

**Webpack version:**
1.10.x/2.x

**Please tell us about your environment:**
OSX 10.x / Linux / Windows 10

**Current behavior:**
Obtaining too many open files when using the copy-webpack-plugin. 

**Expected/desired behavior:**
Not to reach the limit of open files and therefore have the build succeed.

@tallaxes suggested a fix which lies within Compiler.js. [URL]

```
require("async").forEach(Object.keys(compilation.assets), function(file, callback) {
```

to

```
require("async").forEachLimit(Object.keys(compilation.assets), 2000,
  require("async").ensureAsync(function(file, callback) {
```

One issue with this fix is the number is different per machine and depending on what else is running on the machine. One possible solution is to use an environment variable and fall back to a default value anyway.

```
require("async").forEachLimit(Object.keys(compilation.assets), process.env.WEBPACK_FILE_LIMIT || 100,
  require("async").ensureAsync(function(file, callback) {
```

There has also been mentions about using graceful-fs. However I had no luck when monkey patching it. This was the only thing that solved the issue for me. [URL]
