Title

isInclusive and boundsAsComposites in Restriction take bounds in different order

Description
After we've upgraded our cluster to version 2.1.11, we started getting the bellow exceptions for some of our queries. Issue seems to be very similar to   CASSANDRA-7284  .

        execute( "insert into %s (a, b) values ( 'a' , 2)" );
        execute( "SELECT * FROM %s WHERE a =  'a'  AND b > 0" );

Discussion
- We managed to reproduce the bug using Cassandra 2.2.5 with the following table schema (unset parameters use default values): 
  
  CREATE   TABLE  mytable (
    u  text ,
    t timeuuid,
     PRIMARY   KEY  (u, t)
)  WITH  COMPACT  STORAGE 
     AND  CLUSTERING  ORDER   BY  (t  DESC )
     AND  compaction = { 'min_threshold' :  '2' ,  'class' :  'org.apache.cassandra.db.compaction.DateTieredCompactionStrategy' ,  'base_time_seconds' :  '1' }
     AND  compression = { 'sstable_compression' :  'org.apache.cassandra.io. compress .LZ4Compressor' }
     AND  dclocal_read_repair_chance = 0.0
     AND  default_time_to_live = 10
     AND  gc_grace_seconds = 0
     AND  read_repair_chance = 0.0;
 
  
 And the following query: 
  
  SELECT   COUNT (1)  as  cnt
 FROM  mytable
 WHERE  u = : user   AND  t > : timestamp 
 ORDER   BY  t  DESC 
 LIMIT  110;
 
  
 Removing  COMPACT STORAGE  definitely helps, so it is somehow connected.
- I've tested it with  2.2  branch and was able to reproduce it with unit tests (updated summary).  3.x  is unaffected.

- kohlisankalp  It was decided since some time to only push fixes for critical issues to 2.1. The problem becoming do decide what is a critical issue and what is not. 
In this case, the description is suggesting that the problem is a new one but the location of the problem made us believe that the issue had always been there. Are you also facing the same issue?
- The issue was not reproducible on  2.1 . The tests are passing. Problem was related to bounds being taken in different order on different stages of query, because of  EOCs , which seems not be the case on 2.1.
