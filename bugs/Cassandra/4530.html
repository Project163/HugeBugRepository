Discussion
- This doesn't really reproduce locally but given the error message, and give the file in question has 2 different test that name their index  c_index , I believe this is a relatively simple name clash. Especially since while both test will clean after themselves, that cleaning is done asynchronously (the table used by the test is different, so the asynchronous part is not supposed to be an issue, but index names are checked for conflict globally), which also explain why this is an intermittent failure. 

 Assuming I'm correct, as one of those test don't really use the name of the index, the simplest fix is to just remove the name on that test, letting the index name being generated automatically. That trivial fix is  here . I tested this locally (to make doubly sure the test was indeed not relying on the index name) but I don't feel it's worth wasting CI ressource on this, unless someone has an issue with that. Also, the patch is on trunk since that where the report is from, but it seems this should be fixed from 3.0 onwards, so I'll commit there if we're good with the patch.
