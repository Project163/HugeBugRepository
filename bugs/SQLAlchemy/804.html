Title

Single table inheritance conflict resolution breaks for primary keys

Description
**Migrated issue, originally created by Tom Manderson ([Link: @TRManderson])**

Single table inheritance has a conflict resolution method for columns that appear in multiple subclasses. When the column that appears in multiple subclasses is a primary key, the conflict resolution procedure is skipped and an error is thrown.

This makes sense when the primary key isn't on the base class to start with, but if it is (eg. in my use case the primary key is added with `declared_attr.cascading`) then we should allow it.

There's an [Link: existing PR] including the code below as a test case:

```
class TestBase(Base):
            __abstract__ = True

            @declared_attr.cascading
            def id(cls):
... [Log Snipped] ...
        class Manager(Person):
            """ single table inheritance, no extra cols """
```
