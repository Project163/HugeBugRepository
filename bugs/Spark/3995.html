Discussion
- It seems that it is a network I/O timeout, because there is one entry sleeps too long and the connection is reset by remote. Is it a configuration problem? If you run it locally, it works fine.
- It is with the default configuration settings, and this worked fine with spark 1.6.0. Still, it's not unthinkable to me that the default configurations have changed since 1.6.  
It should happen with any wait time greater than the spark.locality.wait setting (forcing the task to be launched on a different node than the one the data was cached on). 

 The initial workload we came across this in had each task taking ~20 seconds, and this error would consistently happen near the end of the stage, as soon as tasks began being executed non-locally. That workload also ran fine in spark 1.6.
