Title

3.0 Routes & Resources

Description
Most of my default routes work using the following:

``` php
$routes->connect('/:controller', ['action' => 'index'], ['routeClass' => 'InflectedRoute']);
$routes->connect('/:controller/:action/*', [], ['routeClass' => 'InflectedRoute']);
```

However, when I want to map resources it breaks for that controller (actions other than `index()`):

``` php
$routes->resources('Clients');
```

Works:

``` php
/clients
/projects/add
```

Doesn't:

``` php
/clients/add
/clients/edit
```

---

[Link: Gist of my code]
Discussion
- Resource routes do not connect the same route templates as the default routes do. When using resources() the following routes are connected (assuming Clients is your controller):
- `/clients`\+ GET -> index
- `/clients` + POST -> add
- `/clients/:id` + GET -> view
- `/clients/:id` + PUT -> edit
- `/clients/:id` + DELETE -> delete

The resource based routes are intended for building REST-ful webservices, and don't work super well for HTML based apps. I'm still doing some work on resource routing, and am considering adding routes similar to what rails uses for resource routing:

| HTTP Verb | Path | Controller#Action |
| --- | --- | --- |
| GET | /clients | clients::index |
| GET | /clients/add | clients::add |
| POST | /clients | clients::add |
| GET | /clients/:id | clients::show |
| GET | /clients/:id/edit | clients::edit |
| PATCH/PUT | /clients/:id | clients::update |
| DELETE | /clients/:id | clients::delete |

I think the extra GET routes will help make HTML based applications easier to work with and still offer the same routes for RESTful webservices.
- Thanks for the response :)

I understand they do not connect the default routes, but that's why I have the default

``` php
$routes->connect('/:controller', ['action' => 'index'], ['routeClass' => 'InflectedRoute']);
$routes->connect('/:controller/:action/*', [], ['routeClass' => 'InflectedRoute']);
```

I assumed they would work together, is that wrong?
- Ah I see what you are saying. The fallback routes will often get ignored when there are more specific routes and you are generating URLs. However, both should work from the request URL.
