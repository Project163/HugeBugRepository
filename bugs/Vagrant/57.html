Title

Ansible Provisioning doesn't put quotes on the value of '-o IdentityFile='

Description
using `ansible.verbose` in my VagrantFile I can see that ssh is being called with `-o IdentityFile=/Users/greg/Google Drive/Projects/MyProject/.vagrant/machines/default/virtualbox/private_key`

Because this doesn't have any quotes around the path the ssh client is then trying to connect to host drive/projects/passwordmanager/.vagrant/machines/default/virtualbox/private_key giving the following error

```
SSH Error: ssh: Could not resolve hostname drive/projects/passwordmanager/.vagrant/machines/default/virtualbox/private_key: nodename nor servname provided, or not known
```
Discussion
- Hi @grh2g46 

I believe this has been fixed in master, but I'd like to verify. Can you please share your Vagrantfile?
- Vagrant File:

```
##################################################
# Generated by phansible.com
##################################################

#If your Vagrant version is lower than 1.5, you can still use this provisioning
... [Log Snipped] ...
    config.vm.synced_folder "/Users/greg/Google Drive/Projects/PasswordManager", "/vagrant", type: "nfs"
end
```

I initially got a ControlPath too long error which I only got past by creating a ansible.cfg containing

```
[ssh_connection]
control_path = /dev/null
```

Only after that did I get the error in the issue
- In #6209 the path to the private key file was fixed in the generated inventory, but with a static inventory file (`inventory_path` option) the OpenSSH command line argumens were still not enclosed with single quotes.

Note that simply adding quotes to `-o IdentityFile='...'` was not fixing the bug (see cd93721 and ddbd2a4 for full details)

This is now fixed in master. Thanks for the problem report @grh2g46 :)
