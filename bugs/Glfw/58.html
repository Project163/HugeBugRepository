Title

Stuttering full screen graphics with non-zero swap interval

Description
The latest workaround for vsync'ed buffer swapping on systems with compositing enabled leads to stuttering when in fullscreen mode. In windowed mode it's working fine.

1) XP with a Radeon 9250
2) Vista with an ATI Mobility Radeon HD 2400 XT
3) Windows 7 with an AMD Radeon HD 6450

On machine 1 it's working correctly in both windowed and fullscreen mode. On machines 2 and 3 only windowed mode is good. In fullscreen mode the movement is clearly not smooth and there's some stuttering / refresh artifacts.

- If Aero is disabled then WGL swap interval is used.
- In case this can't be solved I am proposing to implement a workaround that sleeps until the next vertical refresh. IMHO this is a better solution that just doing nothing as it is currently. The current implementation is not really portable because on Linux & Mac OS glfwSwapInterval(1) will correctly synchronize with the vertical refresh while on Windows it does nothing, thus causing projects to run at lightning speed. I've already played around with a workaround that waits until the next vertical refresh and it's working quite well but of course there is the disadvantage that it will hog the CPU because you need to poll the performance counter because Win32's Sleep() function is not precise enough for this kind of task. See here for some more elaborations on this topic by me: [URL]

Of course I'm still hoping that you can come up with a nice solution which works everywhere and doesn't hog the CPU but in case it's not possible, I'd suggest to use a polling timer to do the vertical refresh synchronization for portability's and consistency's sake.
