Title

Matrix webhook doesn't send access token in Authorization header on replay

Description
### Description

If a Matrix webhook fails and it is replayed, the access token is not sent in the Authorization header. The resulting header sent is `Authorization: Bearer`

Discussion
- From a quick analysis, here is what I think happens:
- the original (insecure) payload is generated, with the `access_token` and saved as `HookTask`
- on first try, the `HookTask` is fetch from the database and the `access_token` is taken from the payload and the payload is replaced with a *safe* payload (without the token):
[URL]

- after every try the `HookTask` is saved
[URL]

- hence on retry, the payload does not contain the token anymore

There is a PR to better manage such Authorization header, which should fix this: [URL] (the PR is initially aimed only for gitea webhooks, but I hope that it will be reconsidered :)
- FYI, the PR should be included in the 1.19 release (in a couple of months).
