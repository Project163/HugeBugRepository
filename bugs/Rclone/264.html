Title

dropbox: getting "Couldn't move: move failed: from_lookup/not_found/" errors with --backup-dir and changed modtime

Description
#### What is the problem you are having with rclone?

See [Link: the forum] for background.

When using dropbox with `--backup-dir` if a file has only changed modtime, then in the first pass rclone deletes it then returns the error "Couldn't move: move failed: from_lookup/not_found/".

#### What is your rclone version (eg output from `rclone -V`)

```
rclone v1.39-233-g383feca6
- os/arch: linux/amd64
- go version: go1.10
```


#### Which OS you are using and how many bits (eg Windows 7, 64 bit)

Linux 64 Bit

####  Which cloud storage system are you using? (eg Google Drive)

Dropbox

#### The command you were trying to run (eg `rclone copy /tmp remote:tmp`)

    rclone -vv copy file.txt --backup-dir dropbox:test/test2 dropbox:test/test1

#### A log from the command with the `-vv` flag (eg output from `rclone -vv copy /tmp remote:tmp`)

Here is a reproduction of the problem with log

```
$ echo "hello" > file.txt
$ rclone -v copy file.txt dropbox:test/test1
2018/03/13 09:37:30 INFO  : Dropbox root 'test/test1': Modify window is 1s
2018/03/13 09:37:30 INFO  : Dropbox root 'test/test1': Waiting for checks to finish
2018/03/13 09:37:30 INFO  : Dropbox root 'test/test1': Waiting for transfers to finish
... [Log Snipped] ...
$ ls -l --full-time file.txt
-rw-rw-r-- 1 ncw ncw 6 2018-03-13 09:37:38.652019585 +0000 file.txt
```

#### Solution

I think in an ideal world we'd like rclone to put the incorrectly dated `file.txt` into the `--backup-dir`, but at minimum we want rclone to transfer the file straight away and not wait for the retry.
