Title

[YSQL] read operations within SQL statement should use a consistent read snapshot

Description
The read operations within SQL statement should use a consistent read snapshot.

For example, the select portion of insert-select operation should read rows as of the start of SQL statement.
Test case below shows the issue where insert-select ends up with more than 2x the number of the rows.

```
sql
create table test2 (a text, b int);

insert into test2 values ('abc', 1);

... [Log Snipped] ...
 abc | 1
(4 rows)
```

Sometimes it may take a few repeated insert..select before the bug manifests (due to the nature of internally generated OIDs that determines tablet mappings).
Discussion
- Discussing this with @spolitov. We need to introduce the notion of read time within a transaction, based on the hybrid time of the provisional record. A read operation within one statement (e.g. INSERT ... SELECT or an UPDATE that modifies the primary key) should include this read time (in addition to its usual read time for committed records), and ignore all records written by the same transaction that have provisional record hybrid time greater than or equal to the start-of-statement hybrid time. Note that provisional record hybrid time must not be confused with commit time of the transaction, as we are talking about reads of uncommitted records that only the current transaction can see.
