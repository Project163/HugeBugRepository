Discussion
- I do suspect it is because of how  Runtime.getRuntime().maxMemory()  is calculated, cause effectively we compare this value retrieved in  TaskExecutor  container with what we assume should be set as  -Xmx  while starting this container. 
Thanks to this answer:  [URL] depending on the jvm implementation it might happen that  maxMemory  will return value decreased by the size of one Survivor space. Final values for each space are also aligned with page sizes, which makes the whole calculation even harder. 

 Usually the value of 10% difference is enough but as it turned out not always. I would suggest to just increase the error threshold to e.g. 15%. Any other suggestions  pnowojski   till.rohrmann ?
