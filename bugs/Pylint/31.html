Title

Deprecated CLI calls need to be accepted w/o error

Description
Originally reported by: **BitBucket: [Link: phiro], GitHub: @phiro?**

---

Some of the tools that use pylint are using -i as a fixed argument when invoking pylint; in pylint 1.1.0 using -i throws a fatal error that -i is an unrecognized argument. If you're going to deprecate a function, it's a best practice to gracefully accept (and ignore) the option. Maybe throw an informational bit of text, but not an outright error.
Please accept -i as an argument again, even if it's ignored. 

This is a critical error for us, because the dev teams have upgraded to 1.1 and the automatic analysis tools are broken (because their changes to pylintrc for 1.0/1.1 aren't compatible with ~.25, which is the latest version on the Ubuntu 12.04lts PPA). We upgraded our build servers to 1.1 and that's when we saw -i breaks pylint now. The workaround is to disable all pylint rules so pylint isn't being invoked anymore. Completely disabling the product as the work around seems to fall under "critical" priority. 

The fine people over at Sonar even have a jira issue to remove pylint :/
