Title

Why does require return an empty object?

Description
I was trying to use [Link: showdown] with webpack.

Showdown has [Link: this node specific code], and it failed as webpack returned an empty object for the `var fs = require('fs');` call. Why is that so? Shouldn't it return null or undefined?

I can appreciate that Showdown wasn't written with webpack in mind, but I imagine there is lot's of code out there, doing the same exact thing.

So, do I need to patch showdown, or is there some change in webpack that will solve this? Thanks!
Discussion
- To be honest, both behaviors do not make sense :grinning:.

Agreed, `require("fs")` should not return an empty object. But to test the availability of the `fs`-module I think it's most common to use try-catch:

``` javascript
var fs;

try {
    fs = require("fs");
} catch(err) {
    // fs not available in this environment
}
```
