Title

Mounting "/" routes to a sub-path removes trailing slash from route

Description
**Description**

Mounting a `#[get("/")]` route to a sub-path removes the trailing slash, which leads to unexpected behavior.

**To Reproduce**

Create a `src/main.rs` : 
```
rust
#[macro_use] extern crate rocket;

#[get("/")]
fn index() -> &'static str { 
... [Log Snipped] ...
    rocket::build().mount("/test/", routes![index])
}
```

and `Cargo.toml`

```toml
[package]
name = "rocket-example"
version = "0.1.0"
edition = "2021"

[dependencies]
rocket = { git = '[URL] rev = ' ' }
```

Run `cargo run` and check difference of calling `curl [URL] (which works) and `curl [URL] (404).

```
Finished dev [unoptimized + debuginfo] target(s) in 0.06s
     Running `target/debug/rocket-example`
🔧 Configured for debug.
... [Log Snipped] ...
```

**Expected Behavior**

After   I expected the resource to be available only under the route `/test/` (which is also what the logs say where the route lives) but it appears the loaded route is `/test`.

**Environment:**

 - OS Distribution and Kernel: Arch Linux 6.2.12-arch1-1
 - Rocket Version: master@
