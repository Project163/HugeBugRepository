Title

Descriptors are not resolved within type unions

Description
It appears that mypy does not properly resolve descriptors when used within type unions.  If I have an object (e.g. `Test` below) that makes use of descriptors for properties (e.g. `StringDescriptor` and `ListDescriptor` below) in `Union`s mypy returns errors.  If the descriptors are used directly without any `Union` type mypy resolves the type.

I believe this is a mypy bug.  I would expect that descriptors are resolved the same both within and without type unions.

There are likely better, and less contrived, examples but if I have the following code:

```
from typing import Optional, List, Any, Union


class StringDescriptor(object):
    """Type descriptor for `Optional[str]`"""
... [Log Snipped] ...
            return [str(element) for element in self.list_param]
        return []
```

When I run mypy I see the following errors:

```
descriptor_test.py:45: error: Incompatible return value type (got "Union[str, StringDescriptor]", expected "Optional[str]")
descriptor_test.py:57: error: Iterable expected
descriptor_test.py:57: error: Item "ListDescriptor" of "Union[List[Any], ListDescriptor]" has no attribute "__iter__"
```

The descriptor is resolved to the expected type by itself but not when it is part of a Union.
Discussion
- Thanks for reporting! What you show here is not a good repro, it is hard to imagine code that does this:
```python
self.string_union_param = 'this is a string'  # type: Union[str, StringDescriptor]
```
TBH I would say we should just prohibit such code :-) A more realistic, and a simpler repro is below:
```
python
class String:
    def __get__(self, inst, owner) -> str:
        ...

... [Log Snipped] ...

reveal_type(x.attr) # Revealed type is 'Union[builtins.str, tstd.String]'
```
While the latter should be just `builtins.str`. The reason is trivial, unions are just ignored in `analyze_descriptor_access`:
```python
        if not isinstance(descriptor_type, Instance):
            return descriptor_type
```
Instead this function just should map the rest of the logic over the elements of the union. Thus this is easy to fix.
