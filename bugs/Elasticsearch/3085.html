Title

[ML] StartTrainedModelDeploymentAction does not return a response by the timeout value

Description
### Description

Can pretty consistently repro with:
1. `eland_import_hub_model --url [URL] --hub-model-id intfloat/multilingual-e5-large --task-type text_embedding --start`
2. `POST _ml/trained_models/intfloat__multilingual-e5-large/deployment/_start?deployment_id=intfloat__multilingual-e5-large33`

The timeout error message shows up if we add the `timeout=15s` option.  The call also succeeds if we use `waitFor=starting` which is a decent workaround, though I don't believe Kibana uses that from the UI.

Kibana is retrying the request after 30s, which is why we see the `Could not start model deployment because an existing deployment with the same id` error from Kibana.

```
[2024-06-05T16:06:37,730][INFO ][o.e.x.m.a.TransportStartTrainedModelDeploymentAction] [runTask-0] [intfloat__multilingual-e5-large] received deploy request for model [intfloat__multilingual-e5-large] and timeout [30s]
[2024-06-05T16:06:44,063][INFO ][o.e.x.m.i.d.DeploymentManager] [runTask-0] [intfloat__multilingual-e5-large] Starting model deployment of model [intfloat__multilingual-e5-large]
[2024-06-05T16:07:07,732][INFO ][o.e.x.m.a.TransportStartTrainedModelDeploymentAction] [runTask-0] [intfloat__multilingual-e5-large] received deploy request for model [intfloat__multilingual-e5-large] and timeout [30s]
```

I'm thinking:
1. we always want an error response to show up when the call times out
2. we want the error message to include something like "it's still running" or the current status
3. kibana may or may not use the `waitFor=starting` when deploying a model, I think for now we can try to make sure we finish by the `timeout` value or return a response before then, and Kibana will not retry
