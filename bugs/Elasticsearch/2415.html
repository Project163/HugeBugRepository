Title

Specifying a negative `from` value in a Search returns different hard-to-interpret error messages

Description
**Elasticsearch version** (`bin/elasticsearch --version`): 7.6.2

**Description of the problem including expected versus actual behavior**:

When specifying a negative `from` value in a search request, the exceptions do not contain a proper hint, of what is wrong, same for the `size` value. Also, specifying different values returns different exceptions:

**Steps to reproduce**:

```
DELETE foo

PUT foo/_doc/1?refresh
{
  "foo" : "bar"
... [Log Snipped] ...
  "from": -1
}
```

```
GET foo/_search
{
  "from": -2
}
```

This returns

```
{
  "error" : {
    "root_cause" : [
      {
        "type" : "array_index_out_of_bounds_exception",
... [Log Snipped] ...
  "status" : 500
}
```

```
GET foo/_search
{
  "from": -10
}
```

This returns

```
{
  "error" : {
    "root_cause" : [
      {
        "type" : "illegal_argument_exception",
... [Log Snipped] ...
  "status" : 400
}
```

This does not contain any concrete information what could be culprit (think of an autogenerated search request from an app, that accidentally uses a negative value - this will be hard to track down.

Original issue reported via the forum at [URL]

Discussion
- Pinging @elastic/es-search (:Search/Search)
- This behaviour suprised me since we already [Link: check for negative from values] in our SearchSourceBuilder setters and even have [Link: rest tests] for this -2 that check for the right exception message. 

Turns out that test sets the request parameter, not the "from" value in the search body, so this:
```
GET foo/_search?from=-2
```
throws "illegal_argument_exception", "reason" : "[from] parameter cannot be negative" as expected.
