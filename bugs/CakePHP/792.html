Title

Notices and warnings in the query builder

Description
This is a (multiple allowed):
- [x] bug
- [ ] enhancement
- [ ] feature-discussion (RFC)
- CakePHP Version: 3.2.8
- Platform and Target: Apache 2.4, MySQL 5.5
### What you did

``` php
$c = \Cake\Datasource\ConnectionManager::get('default');
$q = $c->newQuery();
$q->into('table'); // Similar problem with $q->insert(['field']);
```
### Expected Behavior

No PHP messages.
### Actual Behavior

The code works as expected but there are PHP messages:

```
PHP Notice:  Undefined offset: 1 in /home/bernat/work/wip-roomsday/vendor/cakephp/cakephp/src/Database/QueryCompiler.php on line 301
PHP Stack trace:
PHP   1. {main}() /home/bernat/work/wip-roomsday/bin/cake.php:0
PHP   2. Cake\Console\ShellDispatcher::run() /home/bernat/work/wip-roomsday/bin/cake.php:33
PHP   3. Cake\Console\ShellDispatcher->dispatch() /home/bernat/work/wip-roomsday/vendor/cakephp/cakephp/src/Console/ShellDispatcher.php:127
... [Log Snipped] ...
   14.0918   16052440  31. Cake\Database\QueryCompiler->_buildInsertPart() /home/bernat/work/wip-roomsday/vendor/cakephp/cakephp/src/Database/QueryCompiler.php:137
   14.0932   16052968  32. Cake\Database\QueryCompiler->_stringifyExpressions() /home/bernat/work/wip-roomsday/vendor/cakephp/cakephp/src/Database/QueryCompiler.php:301
```

The query builder is trying to compile the query while we are still constructing it and it doesn't check for missing query parts. This is an inconvenience because it outputs warning messages while the API is being correctly used.
Discussion
- You're in an interactive console environment. Each return value attempts to output the 'debug' representation of the query, which involves compiling the SQL.

Given that we have to show _something_ when outputting the query, what would you expect to see?
- I was guessing that would be the case, it's not a problem on most cases but still not nice showing errors on valid operations. I was doing some tests in the console and these errors are confusing at first and still annoying when aware of them.

Couldn't we avoid compiling the query in `__debugInfo()` while the query isn't complete?

Another solution could be that query compilation checked for the existence of the indexes in arrays before using them.
- Detecting 'done enough' is the tricky part :smile:
