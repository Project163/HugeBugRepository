Title

IP Range Aggregation CIDR masks are exclusive of end of range

Description
**Elasticsearch version**: 5.0

**Description of the problem including expected versus actual behavior**:

If I have a document with an ip address field with value of  , I can query for it using CIDR  /24, and get a hit on the document:
```
{
  "query": {
    "term": { "address": " /24" }
  }
}

```
However, if I do an IP range aggregation on that subnet, then this document is not included, i.e.:
```
{
  "size": 0,
  "aggregations" : {
    "networks": {
      "ip_range": {
... [Log Snipped] ...
  }
}
```

That is because on generic range aggregations the `to` value is exclusive, as documented here:
[URL]

In fact, if you aggregate using a /32 CIDR, you'll never get a hit on the IP address itself, which is even more poignant, i.e.,   address value will not be aggregated inside  /32. The same holds if you aggregate for range from   to  ; such an aggregation will always have a count of 0.

I suppose I can understand that `to` is exclusive for other types of ranges, but for a CIDR range I would not expect that behavior.   is definitely in the  /24 subnet. I would also expect consistent behavior for querying and aggregating a subnet.

Thanks.
