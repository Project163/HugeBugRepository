Title

vagrant ssh exits with status 0 when not running

Description
Running `vagrant ssh` exits with status 0 when the VM isn't running. This is a problem for scripts that call `vagrant ssh -- some command` and inspect the exit status to determine if the command executed successfully.

### Vagrant version
1.8.5

### Host operating system
Fedora

### Guest operating system
Debian

### Vagrantfile
```
ruby
Vagrant.configure("2") do |config|
  config.vm.provider :docker do |docker, override|
    docker.image = ENV.fetch("VAGRANT_DOCKER_IMAGE", "jesselang/debian-vagrant:jessie")
    docker.has_ssh = true
... [Log Snipped] ...
  config.vm.provision :shell, path: "provision.bash"
end
```

### Debug output
[URL]

### Expected behavior
It should have returned a non-zero exit status, because it wasn't able to run the command. Compare to `ssh no-such-hostname.example.com echo hi` which returns exit status 255

### Actual behavior
It displayed an error (on stdout!) and returned a zero exit status

### Steps to reproduce
1. vagrant halt
2. vagrant ssh (or vagrant ssh -- echo hi)
3. echo $?

- @chrisroberts Hey, thanks for looking into this. The two providers I have handy are docker and libvirt. It seems to be a problem on libvirt too.

```
$ vagrant status
Current machine states:

default                   shutoff (libvirt)

==> default: Domain is not running. Please run `vagrant up` or `vagrant resume` first.

```
- @agriffis So after getting it reproduced locally and comparing the implementation difference between the docker provider and the virtualbox provider I see that where the virtualbox provider will raise an exception if the requested machine is not running, the docker provider only makes a note and allows continuation. This "note only" behavior is also implemented in the hyperv provider. I'll look at getting both the docker and hyperv providers updated to make the behavior expected and consistent.
