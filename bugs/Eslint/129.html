Title

Severity of rule should be stored in message

Description
Discovered while investigating #983.

With latest master, if I run `eslint --reset test.js` with no .eslintrc and test.js being the following:

``` js
/*eslint wrap-iife:2 */
(function(){})();
```

I get this error:

```
/Users/jrajav/Development/eslint/lib/cli.js:132
        severity = config.rules[message.ruleId][0] ||
                                               ^
TypeError: Cannot read property '0' of undefined
    at errors (/Users/jrajav/Development/eslint/lib/cli.js:132:48)
... [Log Snipped] ...
    at processFiles (/Users/jrajav/Development/eslint/lib/cli.js:154:5)
    at Object.cli.execute (/Users/jrajav/Development/eslint/lib/cli.js:238:22)
```

This seems to be due to this code in cli.processFile ... 
[URL]
... in which it seems to be assumed that any rules that have messages will also have their severity accessible in the base config. However, when eslint.verify gets the config on line 112 above, it immediately copies it to extend, so this function won't get any changes from comment configs. Two possible solutions:
- Make sure cli.processFile gets the comment config rules in its config somehow.
- Pass the severity along with messages instead of reading them from the config.

I think the second would be cleaner overall, it sidesteps any current and future issues with config extending and takes the severity at the time the message is generated.
Discussion
- This looks like the root cause of #983, so we should only keep one of these open. 

Passing the severity along with the messages may be the best way to go, however, this has ripple effects. All of the Formatters currently use the config to figure out error vs. warning, so they'd need to be updated as well.
