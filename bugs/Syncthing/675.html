Title

Race condition in restarting folder

Description
`TestIntroducer` triggers this:

```

... [Log Snipped] ...
	/opt/tcagent/syncthing-4-work/src/github.com/syncthing/syncthing/lib/config/wrapper.go:231 +0x28e
FAIL	github.com/syncthing/syncthing/lib/model	3.693s
```

Theoretically there should be a file set but apparently it's nil (deleted). There's no locking to prevent this as we release the lock in RestartFolder between creating the set and calling startFolderLocked.
Discussion
- Weird. The set is added to the model in `addFolderLocked` and `fmut` is held while calling that and `startFolderLocked` and neither of those drops the lock until that panic. The set created in `RestartFolder` outside of the lock is local, so I don't see how anybody can mess with that until it "enters the lock".  

I have only seen failures from builds of #6107. I assume the problem is that the db has been closed while `RestartFolder` was in progress, thus `NewFileSet` now returns nil without an error. A solution would be to ensure in `model.Stop` that no more `CommitConfiguration` etc is going on.
