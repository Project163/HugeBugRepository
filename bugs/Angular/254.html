Title

When `inject` is before `fakeAsync` (and probably async), tests do not use the expected zone

Description
When calling `TestBed.createComponent` or `TestCombponentBuilder.createAsync`, [Link: the function uses `injector.get` to retrieve the `NgZone`]. Any tasks (microTasks or macroTasks) that occur as part of the `createComponent` are added to this zone (and not to `Zone.current`). 

The `NgZone` is instantiated when `inject` is called, using whatever zone is `Zone.current` when the [Link: constructor] is run.

This means that when `inject` is called _outside_ of a `fakeAsync` or `async`, then `Zone.current` will be `"angular"` (direct child of `" "`).

As a result of this, any tasks spawned from calling `createComponent` will be added to the `"angular"` zone _instead_ of the testing zone when the test uses either `async` or `fakeAsync`.

Example:

```
ts
beforEach(inject((tcb: TestComponentBuilder) => {
  builder = tcb;
}));

... [Log Snipped] ...
  expect(appFixture).toBeTruthy(); // FAIL, appFixture is undefined
}));
```

Here, the call to `flushMicrotasks` will _not_ cause the `then`'ed function to execute because the task for the `createAsync` was added to the `"angular"` zone and _not_ the `fakeAsyncTestZone`.

As a workaround, you can write:

``` ts
  beforeEach(fakeAsync(inject([TestComponentBuilder], (tcb: TestComponentBuilder) => {
    builder = tcb;
  })));
```

When the function returned from `fakeAsync` is called, the current zone is forked into the `fakeAsyncTestZone`, so that `Zone.current` is the expected zone when `inject` runs and instantiates the `NgZone`, which is then consumed by `createAsync`, causing the microtasks to be added to the expected zone.
