Title

[xCluster]Failure to update replication map causes crash + core dump

Description
**Issue**
When there is a Master node change initiated by a user in any given environment with xCluster replication, the `masterAddrs` under the `producerMap` fails to update, and any subsequent `alter_universe_replication` will crash with a cored dump file: 

```
#0    in yb::RefCntBuffer::size (this= ) at ../../src/yb/util/ref_cnt_buffer.h:61
#1  yb::rpc::YBInboundCall::Serialize (this= , output= ) at ../../src/yb/rpc/yb_rpc.cc:446

**Steps to reproduce**
-    Setup xCluster replication
-    From the Yugaware platform UI, stop all services on the MasterLeader/Tserver node
-    Start the Master process on a TServer node
-    From the CLI - issue, change the master - where the new masterLeader is the node that was only a tserver prior.

```
yb-admin -master_addresses   master_leader_stepdown [   ]
```

-   Attempt to add bidirectional-replication for a new table

```
yb-admin master_addresses   alter_universe_replication   { set_master_addresses   |  add_table  [,  ...] | remove_table  [,  ...] }
```
