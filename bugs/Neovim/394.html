Title

Overriding signs in the new diagnostic namespace?

Description
### Feature already in Vim?

N/A

### Feature description

Wasn't sure whether to report as a bug (could call it a regression 🙈) or feature request (it's something I'd like to be able to), but here we are.

After #15585 was merged, I am no longer able to redefine the signs used for diagnostics (I like setting the text so I don't have a signcolumn, having a diagnostic just causes the linenumber to change color). The signs are defined whenever the diagnostics are displayed for the first time, so overriding it is very tricky.

I'm using a weird workaround for now:

Override the handler for publishDiagnostics so it:

1. Calls vim.lsp.diagnostic.on_publish_diagnostics
2. Checks whether there are any diagnostics in the result
3. If so, redefine the signs, call vim.diagnostic.reset and call vim.lsp.diagnostic.on_publish_diagnostics again (yes, it's awful)

Here is the code if anyone is interested: [URL]

I imagine some other plugins will want to override the signs too (with emojis and what not), so this is probably a legit use-case?

Perhaps I'm missing something though, so please feel free to tell I'm just wrong :)
