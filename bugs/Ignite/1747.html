Title

SkipStore flag is not overridden for a transaction entry

Description
Consider the following code snippet:  
  
  try  (Transaction tx = ignite.transactions().txStart()) {
    cache.withSkipStore().get(key);

    cache.put(key, value);

    tx.commit();
}
 
  

 Transaction commit will not trigger store write because  skipStore  flag is set to  true  for the transaction entry and is not overridden on put() operation (see IgniteTxLocalAdapter:3780).
Discussion
- Attached a patch that adds a test reproducing the issue and a suggested fix. Need to verify TC.
- After additional debugging it turned out that  get()  inside a pessimistic transaction and OFFHEAP_TIERED memory mode will always trigger a cache store load. Added corresponding test and fixed in the same PR.
- Reviewed, looks good, but I think it makes sense to add similar test for 'keepBinary' flag.
- Added the test. Merged to master (commit  )
