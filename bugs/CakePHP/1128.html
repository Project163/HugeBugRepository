Title

$_SESSION null when written to

Description
### Description

Im upgrading our project from cakePHP 4.2 -> 4.3
On first write to Session.php $_SESSION is null. This warning is suppressed in [Link: Session::write call to _overwrite], but because _overwrite() parameters are typed the call throws a type error
`protected function _overwrite(array &$old, array $new): void`

Session::write -> Session::start does not start our Session because we are using SSL (`session.use_cookies = true`) and our headers have been sent 
[URL]

$_SESSION is sometimes allowed to be null. In the above situation $_SESSION is allowed to be null, but throws a typeError downstream. 
Why is the warning [Link: here] suppressed?
Is $_SESSION allowed to be null in calls to Session::write? Where/how does $_SESSION get set?

### CakePHP Version

4.3.11

### PHP Version

8.0
Discussion
- How can someone reproduce the issue you're running into?


We have to work around `$_SESSION` being null during writes because the session can fail to start but application code will still be doing writes.


PHP initializes this variable when the session is started. You mentioned your sessions are not starting because of SSL + headers being sent already. Have you tried resolving that problem as it seems closely related to why your sessions are not working correctly.
- You can reproduce my issue by writing to Session before it has been started but after headers have been sent (and with SSL on)
This is not an issue we see in our current environment (running on CakePHP 4.2.12), only after trying to upgrade to 4.3.x, indicating that we _should not_ need to force start the session

An unstarted session ($_SESSION = null) in 4.2 does not error in the call to Session::_overwrite. The parameter $old is auto-converted to empty array
However in 4.3 the call immediately fails before the function code is attempted

This aligns with the fact that the 'PossibleNullArgument' error is suppressed when Session::_overwrite is called from Session::write. Why is this error suppressed if _overwrite errors with null params in 4.3? Why does this fail in 4.3 but not 4.2?
