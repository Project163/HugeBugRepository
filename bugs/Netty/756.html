Title

HttpMessageEncoder violates OneToOneEncoder contract when encoding the last chunk of streamed messages

Description
[URL]
HttpMessageEncoder returns null when HttpChunk.isLast() == true && chunked == false.

This breaks the contract defined by OneToOneEncoder
[URL]

and means that the HttpChunk's future will never make it to Worker.write where it's future is closed.
[URL]
Therefore, ChannelFutureListener's attached to that future will never receive their events and fire operationComplete()

Should HttpMessageEncoder be returning EMPTY_BUFFER instead of null as specified in the OneToOneEncoder comment?
Discussion
- Also of note, since the last HttpChunk should have ChannelBuffers.EMPTY_BUFFER as it's content anyways
[URL]

The code may simply be reduced to something like
if (chunked) {
   ...
} else {
   return chunk.getContent();
}
