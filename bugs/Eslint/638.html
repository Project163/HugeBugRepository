Title

valid-jsdoc rule and return prefered form bug

Description
I want to use the `valid-jsdoc` rule to ensure the JSdoc `@return` tag are `@return` and not `@returns`. I've use this configuration: 

```
{
  "rules": {
    "valid-jsdoc": [2, {
        "prefer": { "return": "return" }, // Here the issue
        "requireParamDescription": false,
... [Log Snipped] ...
  }
}
```

But eslint trigger false positive error on all my files. It said: `Use @return instead` but I'm already using it.

Here a file example: 

```
javascript
'use strict';

/**
 * @param {Number} productId
... [Log Snipped] ...

```


I use the last eslint version (v1.7.2).
