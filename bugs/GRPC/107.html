Title

Fix edge cases in XdsClient watcher behavior

Description
One edge case is the one described here:

[URL]

We should solve that by having the newly started watcher receive first the cached resource and then the error, so that it has the same view as the watcher that was started earlier.

Another edge case is the following: if we get a valid resource, then an invalid resource, then the original valid resource again, we should re-deliver the valid resource to the watcher so that it knows the error is gone (today, C-core inhibits the update because it's identical to the cached value).
Discussion
- I think that case doesn't actually exist, because if we deliver the error to `OnResourceChanged()`, then we also drop the resource from the cache, so the duplicate check will never kick in in the first place.
