Title

Can't view more than 1000 actions of a coordinator and paging does not work

Description
Currently the coordinator popup lists 1000 actions of a coordinator. We have more customers reporting this issue now with cases where they have 5 min coordinator frequency.
Discussion
- Can solve this in two ways.  
 
	 Have a more option which when clicked on fetches another 1000 actions. Need to also get paging working properly for this. Related jira -   OOZIE-891   
	 Show the coordinator actions in descending order with latest coordinator action on the top. This will be more efficient and is what users actually would need and use in 99% of the cases. Only very rarely would they want to go back to the first coordinator action which is more than 1000 actions away. 
 

 My choice is 2. Thoughts?
- I also agree with 2 to show the latest 1000 actions first to cover common user access pattern. 
so, first page --> latest 1000, 2nd page --> next latest 1000...   
inside page, if user want to change order, user can click "nominal time" tab. (btw, it seems current sorting based on string, not time, need to fix this as well) 
some coord job may have so many actions (way more than 1000),  considering memory usage, we still want to do 1000 batch both on UI and backend, instead of loading all actions in one shot. so preferably, at initial load, show only first page, then when user proceeds to next page, do another AJAX call to fetch next 1000, so on.
