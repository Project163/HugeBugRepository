Title

[YSQL] Restarted portal fields are allocated within wrong memory context

Description
When restarting portal (e.g. on restart read error), fields `query_string` and `command_tag` in the new portal were assigned without being copied to the portal context. This leads to those fields becoming dangling pointers after freeing `CurrentMemoryContext` - e.g. when dropping a previous portal to process the next statement.
This execution flow does not use either of the fields, so it doesn't currently lead to any observable issues. 
This bug was initially introduced in #2216 (commit  ) and found during the work on #3091
