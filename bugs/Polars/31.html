Title

`thread ' ' panicked at 'attempt to subtract with overflow'` when attempting to parse date

Description
### Polars version checks

- [X] I have checked that this issue has not already been reported.

- [Link: X] I have confirmed this bug exists on the [latest version] of Polars.


### Issue description

Attempting to parse dates of the form `\d{4}-\d{1,2}-\d{1,2}` leads to a crash, `thread ' ' panicked at 'attempt to subtract with overflow'`.

### Reproducible example

Features: `["lazy", "temporal", "strings", "concat_str"]`.

MRE:
```
rust
let df = df![
    "year"=> &[2020, 2021, 2022],
    "month"=> &[1, 2, 3],
    "day"=> &[1, 2, 3],
... [Log Snipped] ...

println!("{:?}", df.collect()?);
```

### Expected behavior

Either this should fail to parse or should succeed (mostly a `chrono` issue), but it definitely shouldn't panic.

Discussion
- FYI you have an extra underscore in your format: `%Y-%m-%_d` should be `%Y-%m-%d`.
- Chrono’s [Link: docs] say that `%_d` is the same as `%e`. I still think the format string would be wrong because months need to be padded to two digits, but the format string is valid as far as chrono is concerned.

Edit: I realize now that `%_d` doesn't parse a one-digit date, but instead pads with spaces instead of zeroes. But even so, the format string is valid, just a bit less appropriate for parsing the dates I was giving it than I thought. The correct format string would be `%Y-%-m-%-d`, which suppresses all padding. But that also causes a panic.
