Title

Support to cancel asynchronous query job based on the asynchronous query id

Description
Issues 

 Currently, Kylin has no open APIs to cancel/kill the asynchronous running query, users have to dig into the log and find out the Spark process, then to kill the process manually. 

 Without the entrypoint to kill the running asynchronous queries, the server will lose control of resources, finally enter into a unstable state. 

 So I think it's great for Kylin to supply such an open API, to cancel/kill the asynchronous submitted queries. 
   Proposal changes 

 Supply a  DELETE  REST API  /async_query/stop/{query_id:.+ } to kill the submitted asynchronous query by the  query id .
