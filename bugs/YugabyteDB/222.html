Title

[YSQL] Statement taking too long corrupts current session

Description
When trying to use debugger and breakpoints in PG processing code I discovered this:
```
sql
00:37 $ ./bin/ysqlsh
ysqlsh (11.2)
Type "help" for help.

... [Log Snipped] ...
The connection to the server was lost. Attempting reset: Succeeded.
postgres=#
```
After that session becomes usable again.

However, there is no explicit transaction and thus there should be no `current transaction is aborted` when using `ysqlsh` like this.
