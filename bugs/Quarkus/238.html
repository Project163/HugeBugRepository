Title

Stuck Quarkus process when port 8080 is already assigned, kill -9 needs to be used, user not informed about used port

Description
Stuck Quarkus process when port 8080 is already assigned, `kill -9` needs to be used, user not informed about used port.

This is regression comparing to 0.22.0 when user is informed via `Caused by: java.net.BindException: Address already in use` and user can press Ctrl+C to stop the process.

Master based app doesn't react to Ctrl+C and `kill -9` needs to be used.
Stacktrace informs just about NPE, nothing about already used port.

```
java -jar getting-started-two/target/getting-started-two-1.0-SNAPSHOT-runner.jar
2019-09-20 09:37:26,984 SEVERE [io.ver.cor.imp.ContextImpl] (vert.x-eventloop-thread-15) Unhandled exception: java.lang.NullPointerException
	at io.quarkus.vertx.http.runtime.VertxHttpRecorder$WebDeploymentVerticle.lambda$start$0(VertxHttpRecorder.java:382)
	at io.vertx.core.http.impl.HttpServerImpl.lambda$null$5(HttpServerImpl.java:277)
	at io.vertx.core.impl.ContextImpl.executeTask(ContextImpl.java:369)
... [Log Snipped] ...

Killed: 9
```

Steps to reproduce:
```
mvn io.quarkus:quarkus-maven-plugin:999-SNAPSHOT:create \
    -DprojectGroupId=org.acme \
    -DprojectArtifactId=getting-started-one \
    -DclassName="org.acme.quickstart.GreetingResource" \
    -Dpath="/hello"
... [Log Snipped] ...
java -jar getting-started-one/target/getting-started-one-1.0-SNAPSHOT-runner.jar &
java -jar getting-started-two/target/getting-started-two-1.0-SNAPSHOT-runner.jar
```

Run following command in new terminal to kill the stuck process
```
jps -l | grep started-two | cut -d" " -f1 | xargs kill -9
```

Don't forget to stop the first app
```
jps -l | grep started-one | cut -d" " -f1 | xargs kill
```
