Title

Cookie::$sameSite must be set by default

Description
[URL] It's MUST be replaces to
`public $sameSite = self::SAME_SITE_LAX;`
and fix PhpDoc in any case because `Response::sendCookies()` contain:
~~~php
if (PHP_VERSION_ID >= 70300) {
    setcookie($cookie->name, $value, [
        'expires' => $cookie->expire,
        'path' => $cookie->path,
        'domain' => $cookie->domain,
        'secure' => $cookie->secure,
        'httpOnly' => $cookie->httpOnly,
        'sameSite' => !empty($cookie->sameSite) ? $cookie->sameSite : null,
    ]);
} else {
    // Work around for setting sameSite cookie prior PHP 7.3
    // [URL]
    if (!is_null($cookie->sameSite)) {
        $cookie->path .= '; samesite=' . $cookie->sameSite;
    }
    setcookie($cookie->name, $value, $cookie->expire, $cookie->path, $cookie->domain, $cookie->secure, $cookie->httpOnly);
}
~~~
Why MUST? Because browsers now generate a warning(security) and will block cookies without the `sameSite` attribute in future + we don't have tech troubles to do it.
Discussion
- Which browsers? I don't see any warnings at [URL] in latest Chrome.
- I can see Firefox (86, Linux) is setting `sameSite` to `None` when it's not set manually (although docs say it should be autoset to `Lax` in that case).

[Image: image]

IIRC Chrome has the policy of setting `Lax` when `sameSite` is not set so it looks like having `Lax` on default should be save.
