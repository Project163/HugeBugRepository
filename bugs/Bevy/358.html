Discussion
- A quick glance makes it seem like it's binding the animations to the wrong bones or the wrong mesh. This could be an issue with the way we're extracting the hierarchy or the animations from the GLTF file.
- it looks like the model is using morph animation which are not supported in Bevy yet
- Can confirm it's because it's using morph targets. I tested it with #8158 and the dragon gloriously flaps. This requires support for 50 targets (#8158 supports 64), which would be unreasonable for a game asset, the dragon asset is about 50 times larger than if it was animated with skeletal animations. Caveat: the rider doesn't bob in sync with the dragon, I assume this is because they are two different animations you are supposed to run together.
