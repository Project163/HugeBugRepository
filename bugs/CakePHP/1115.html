Discussion
- This looks like a problem between service mocking and dynamically generated container services. The existing code already attempts to 'extend or set' [URL]

However, it seems that the ReflectionContainer will say it 'has' services but not let you extend them :cry:
- @markstory this lil hack seems to resolve it:

```php
# ContainerStubTrait::modifyContainer()
try {
    $container->extend($key)->setConcrete($factory);
} catch (NotFoundException $e) {
    $container->add($key, $factory);
    $container->extend($key)->setConcrete($factory);
}
```

I must be in a very extreme minority to have been the first to uncover this haha. No one else using auto-wiring reflection container and writing coverage I guess. If you're okay with I can kick up a PR. IDK of another way to solve this unless there is a way to determine if the service came from reflection first?
- I've not used reflection auto-wiring personally, but your changes look good to me and a pull request would be great to have 🙇
