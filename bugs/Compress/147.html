Title

ArchiveStreamFactory throws "No Archiver found for the stream signature" on 7z files

Description
Apache Tika makes use of ArchiveStreamFactory to handle a wide range of archive formats (Zip, AR, CPIO, Tar etc) 

 We've just upgraded to Commons Compress 1.7, and tried to make use of the new 7z support to add in 7z handling too. However, when you try to call: 

             ArchiveStreamFactory factory = new ArchiveStreamFactory(); 
            ArchiveInputStream ais = factory.createArchiveInputStream(stream); 

 With a 7z file it fails with: 

     new ArchiveException("No Archiver found for the stream signature");
Discussion
- The reason is we don't provide any ArchiveInputStream for 7z, it can only work on Files (it needs RandomAccessFile under the covers). 

 In the absence of a streaming implementation I don't see any way to resolve this. 

 The current sketch for Compress2 would cover such a case but is still a long way to go.
- Ah, pesky. Any chance of a specific exception for this, which we could catch in Tika, eg NoStreamingSupportException("7z") ?
- ... [Middle Discussions Snipped for Brevity] ...
- I think for general users, it'd be good to get a more detailed exception that lets them know that Compress knows what it is and can't help, as opposed to Compress not knowing what it is 

 For Tika, we can either catch a 7z specific exception and call the File, or use our own magic string, or catch a general exception + check a helper method, any could work!
