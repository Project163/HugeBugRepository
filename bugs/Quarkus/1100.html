Title

Dev UI does not use embedded.html when extension module is in same project as application

Description
## Describe the bug
When a Quarkus app is in the same project as a local extension, the extension's embedded.html will be ignored in Dev UI

### Expected behavior
The extension's embedded.html will be shown in Dev UI

### Actual behavior
The extension's embedded.html is not shown in Dev UI


## To Reproduce

Link to a small reproducer (preferably a Maven project if the issue is not Gradle-specific).
[URL]

Steps to reproduce the behavior:
1. `cd my-ext/integration-tests/`
2. `mvn quarkus:dev`
3. Navigate to the Quarkus Dev UI at localhost:8080/q/dev
4. Note that the embedded.html of the extension was ignored (the extension's tile should have the String "Custom embedded.html is being used!" in it.)

Note this is only for local extensions; performing the above steps in the `/external-app` directory results in the `embedded.html` being used.

Discussion
- It seems that Dev UI only considers templates located in jar files: [URL]

In this particular case, the URL points to a directory, .e.g. the `file://` protocol is used.
- The problem is that we can't easily read the `groupId` and `artifactId` from the file path of a `-deployment` module, e.g. `/my/source/my-ext/deployment/target/classes/dev-templates`.

@FroMage WDYT?
- This seems like a pretty edge case, running dev mode inside an extension. If there's a quick hack we can do to make it work, then why not, but it doesn't seem to be a very useful requirement, no?
- It also occurs when the extension in in the same project (note the root of my reproducer doesn't have a pom for this reason). I sometime create one-off extensions for projects (ex: an irc-bot extension that read annotations and automatically sets up the bot). I came into this issue when trying to test the Dev UI for my extension; at the very least, a warning should be shown that Dev UI won't be available for local extensions (if it can't be easily fixed).
