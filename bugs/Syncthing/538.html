Title

cmd/stdiscosrv: Not enough traffic breaks replication between discovery servers

Description
### Environment:

Two discovery servers, one running v0.14.46@armhf/Raspbian, the other running on v0.14.49@x86_64/Centos7. I occasionally see in the logs:
```
stdiscosrv[11974]: Replication read size: read tcp  :19200-> :50316: i/o timeout
```
or
```
stdiscosrv[12505]: Replication write: write tcp  :40726-> :19200: write:broken pipe
stdiscosrv[12505]: Supervisor main: main: Failed service 'replicationSender(" :19200")' (1.000000 failures of 5.000000), restarting: true, error: "{replicationSender(\" :19200\") replicationSender(\" :19200\")} returned unexpectedly", stacktrace: [unknown stack trace]
```
After closer investigation, it seem that the culprit is this line: [URL]

Namely, unless there is enough traffic on the wire, the replication connection will be torn down. What is more, the is no reconnect on the other side: [URL]

So basically, if there is not enough traffic in the replication servers, the replication will not work.

I think the solution would be to not to set a read timeout in [URL] - i.e. wait indefinitely (preferable), or handle reconnects on the sending side (more work), or implement heartbeats in the replication protocol (quite a bit of work).

Let me know if this sounds reasonable. I can prepare a patch.

### Version Information
```
stdiscosrv v0.14.46-ds1 (go1.10rc2 linux-arm)
stdiscosrv v0.14.49 (go1.9.4 linux-amd64)
```
