Title

`global` aggregation breaks with `terms` filter in filtered alias

Description
### Elasticsearch Version

8.8.2 - 8.9.0

### Installed Plugins

None

### Java Version

_bundled_

### OS Version

ESS

### Problem Description

Note: This is broken in at least both 8.8.2 and 8.9.0. However, I have an instance running with 8.5.x and it does not fail there.

While using a `global` aggregation against a filtered alias that uses a `terms` filter, all search requests fail (see request below with `error_trace` enabled) with a cryptic error:

```
http
POST /test-filtered/_search
{
  "aggs": {
    "all_docs": {
... [Log Snipped] ...
  }
}
```

Response:

```
json
{
  "error": {
    "root_cause": [
      {
... [Log Snipped] ...
  "status": 500
}
```

### Workaround

You can workaround this by changing the `terms` filter into a `terms_set` filter (with a scripted parameter to return `1` for the required number of matches) _or_ a more verbose, unscripted `bool` / `should` filter without a minimum should match of `1`.

### Steps to Reproduce

```
http
DELETE /test

PUT /test
{
... [Log Snipped] ...
  }
}
```

### Logs (if relevant)

```
{
  "error": {
    "root_cause": [
      {
        "type": "unsupported_operation_exception",
... [Log Snipped] ...
    "reason": "all shards failed",
    "phase": "query",
```
Discussion
- `GlobalAggregator` doesn't call `rewrite()` when building its internal Weight.  This wasn't a problem in the past for TermsQuery, which had a no-op rewrite method; but TermsQuery has now been re-implemented as a MultiTermQuery, which *does* need a rewrite.

It's a pretty simple fix, I will pick this up tomorrow.
