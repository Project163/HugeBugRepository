Title

The color() function improperly processes a variable variable color value

Description
See [Link: this StackOvervflow answer for use case example]. 

Consider that this seems to work fine:

```
@original-color: #ff0000;
@pre: original;

.test() {
  .test {
... [Log Snipped] ...

.test();
```

Producing:

```
.test {
  color: #ff0000;
}
```

But then add the `color()` function in the mixin:

```
@original-color: #ff0000;
@pre: original;

.test() {
  .test {
... [Log Snipped] ...

.test();
```

And it gives this output:

```
.test {
  color: #NaNNaNNaNNaNNaNNaNNaNaaNaNNaNccNaNNaNNaNNaNNaN;
}
```

So that means inside that mixin, one cannot use the other color functions that require a color object. So `lighten(color(~'@{@{pre}-color}'), 15%)` will either throw a compiling error (that's what it did in the StackOverflow situation) or it also produces invalid color output (as in this small test case):

```
.test {
  color: #NaNNaNNaN;
}
```

Both this small test case and the SO answer were compiled on less2css.org.


comes out as

```
test: @{original-color};
```

basically we don't allow multi lookups in strings. The solution is to do this

```
 @var: "@{pre}-color";
 @color: color(@@var);
```

I can't imagine alot of uses cases for this (this is our first request I believe), so I am not going to just implement it - things get complicated otherwise.
