Title

doc.go fails to compile when passed a certain invalid mime-type

Description
## Problem statement

This is a relatively small issue, but it's something I wanted to point out.

I was running the `generate server` command on a spec that had a (probably invalid) mime-type value in the `produces` field. The value was `*/*`. See spec below.

Upon generation, the generated comment block in the `doc.go` was escaped by an asterisk in the mentioned `*/*` value. Meaning,
```
/*
  This comment block is now broken because of */*
*/
```

It doesn't seem like `*/*` is a valid mime-type definition. Should this be handeled in the validation command?

## Swagger specification

swagger.json
```
json
{
  "swagger": "2.0",
  "info": {
    "description": "From the todo list tutorial on goswagger.io",
... [Log Snipped] ...
  }
}
```

## Steps to reproduce

`swagger generate server -A example -f swagger.json`

## Environment
swagger version: 0.16.0  
go version: 1.10.3 
OS:   OsS Sierra 10.12.6
Discussion
- I'm having this exact problem as well with `*/*. I have to manually edit the generated code each time.. 

Is there alternative to this mime type? I need it for downloading files of arbitrary types
- Update: it seems that `application/*` or `application/octet-stream` does the job
