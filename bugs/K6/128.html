Title

open does not recognize that `file://` is an absolute URL prefix

Description
### Brief summary

`open(import.meta.resolve(path))` crashes. open does not recognize the `file://` protocol.
I can see why it's like that, but the docs instruct to use `open(import.meta.resolve(path))`...

**UPDATED:**
BTW - this works: `open( import.meta.resolve( './tmp.txt' ).replace(/^file:\/\//,'') )`

### k6 version

compiled with yaml extension using latest.

### OS

Ubuntu WSL  over Win 10

### Docker version and image (if applicable)

_No response_

### Steps to reproduce the problem

tmp.txt
```
aha
```

script.js
```
console.log( open( import.meta.resolve( './tmp.txt' ) ) );

export default function() {}
```

### Expected behaviour

should log the content of tmp.txt

### Actual behaviour

results with:
```
 GoError: stat /home/usr/ws/k6/file:/home/usr/k6/tmp.txt: no such file or directory
```

-------------------

BTW, it works with

```
console.log( open( import.meta.resolve( './tmp.txt' ).replace(/^file:\/\//,'') ) );

export default function() {}
```
which was a wild guess that works against the documentation
