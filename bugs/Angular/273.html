Title

Do not alter headers cases

Description
Hi all,

In the latest RC7, there is a surprising update regarding the header: [URL]
All headers are now lowercased.
Argument for this modification is IEFTF's HTTP/1.1 specifications.

As far I understand, header case-insensitive support is a server side concerns, not client side.
It is stated "Field names are case-insensitive.", making server more tolerant.
It is not stated "headers sent by the client should be lowercased", making client library deciding what to do with your header.

This change is a breaking one.
Consequence are immediate by broken server-side compatibility.
For exemple, a server-side expected "Authorization" header, which is now lowercased by client in "authorization", is not recognised anymore by the server.

Thank you for your support.

- I just had a look the `HttpHeaders` implementation of Spring Framework. It uses a `LinkedCaseInsensitiveMap`.

It's got basically 3 methods: `add`, `set` and `get`:
- `set` enforces that there's only a single value. It is **case insensitive**
- `add` appends the given value (see examples). You can call this after `set` or `add` or if there's no equivalent header set to add another value. Also **case insensitive**
- `get` always returns a `List` and is **case insensitive**

Example 1:

```
headers.set("x", "foo")
headers.set("X", "bar")
// headers = {"X":["bar"]}
// headers["x"] = ["bar"]
// headers["X"] = ["bar"]
```

Example 2:

```
headers.set("X", "foo")
headers.set("x", "bar")
// headers = {"x":["bar"]}
// headers["x"] = ["bar"]
// headers["X"] = ["bar"]
```

Example 3:

```
headers.add("X", "foo")
headers.add("x", "bar")
// headers = {"X":["foo", "bar"]}
// headers["x"] = ["foo", "bar"]
// headers["X"] = ["foo", "bar"]
```

Example 4:

```
headers.add("x", "foo")
headers.add("X", "bar")
// headers = {"x":["foo", "bar"]}
// headers["x"] = ["foo", "bar"]
// headers["X"] = ["foo", "bar"]
```

I think this is a pretty nice solution.

EDIT: I just figured out that the Spring implementation doesn't `trim()` the header names. I.e. `WHITESPACEX` and `xWHITESPACE` are different headers. Does this make sense? Never saw HTTP Headers with spaces at the beginning or end.
