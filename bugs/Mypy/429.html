Title

dmypy issue with `mypy.ini`

Description
In [URL] we've been running `dmypy` with this commit from master: [URL]

Generally, it's been great, but we've been prevented from turning it on by default because I've been seeing it throw occasional errors like this (generally shows up after a lot of rebasing; I switch branches dozens of times a day as part of merging things):

```
(zulip-py3-venv) tabbott@zaset:~/zulip$ ./tools/run-mypy -d
zproject/test_settings.py:22: error: Need type annotation for 'REALM_HOSTS'
zproject/test_settings.py:43: error: Incompatible types in assignment (expression has type "None", variable has type "str")
zproject/test_settings.py:61: error: Incompatible types in assignment (expression has type "Tuple[str, ...]", variable has type "Tuple[str, str, str, str]")
zproject/test_settings.py:80: error: Dict entry 2 has incompatible type "str": "int"; expected "str": "Union[Dict[str, int], str, None]"
zproject/test_settings.py:80: error: Dict entry 3 has incompatible type "str": "int"; expected "str": "Union[Dict[str, int], str, None]"
zproject/test_settings.py:152: error: Need type annotation for 'PUSH_NOTIFICATION_BOUNCER_URL'
```

but this shouldn't be happening, since we have this in our `mypy.ini`:

```
[mypy-zproject.test_settings]                                                                                                            
ignore_errors = True                                                                                                                     
```

I have it reproduced currently in my laptop, so if there's something I can do to dump data from `dmypy` or otherwise help debug, I'd love to do that.

As a sidenote, why `dmypy` instead of `mypyd`?  I feel like the latter is the traditional UNIX name :)
