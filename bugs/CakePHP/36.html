Title

Weird problem with FormHelper and CacheHelper

Description
In my app controller in beforeFilter I have:

``` PHP
if (($newarticles = Cache::read('newarticles', 'short')) == null) {
 $this->loadModel('Article');
 $this->Article->recursive = -1;
 $newarticles = $this->Article->find('all', array(...some conditions...);
 Cache::write('newarticles', $newarticles, 'short');
 }
```

this loads some articles in a sidebar.
On another form I have a checkbox for the user if he wants to be informed about new articles on the site. So in users/edit I load the user model which hasOne UserDetail. UserDetail has a field newarticles.
When I use :

``` PHP
 echo $this->Form->input('UserDetail.newarticles', array(
    'type'  => 'checkbox',
    'label' => 'new articles?',
    'div'   => array('class' => 'checkbox'))) . "\n";
```

a select box appears with data from $newarticles in AppController.  Isn't this a bug?

PS: in AppController I renamed $newarticles to $newarticles1 and everything is fine.
Discussion
- It is the way the form helper works. If it can find an array variable matching the input name, then it will change the input to a select and show the values from that array as options. What probably should not have happened is that it changed your input to select despite setting `type => checkbox`
- You mean it will read ANY variable named newarticles?

- I must check it again because I am pretty sure UserDetail.newarticles had value of 0 when loaded from DB and passed to request->data. If so shouldn't it be set to 0 (unchecked) rather then show newrticles from cache?
- Formhelper should not be changing input types when an explicit type is set. But like @lorenzo said, it will detect types based on view variables.
