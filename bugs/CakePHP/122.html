Title

3.0 Cookies - The data to decrypt cannot be empty.

Description
```
The data to decrypt cannot be empty. 
```

the code

``` php
$this->Cookie->write('hello','world!');
```

Trying to write a cookie I got the above error, debug in into this I note that this happen when I have another cookies written in javascript without encryption

ex:
view:

```
$.cookie("test", 1);
```

controller

```
echo $this->request->cookie('test');
```

I have a similar statement to the above to read some javascript cookies, at this point the cookie are written in the view with jquery and read in the controller using the request, all works fine, but if I need write another cookie using only the cookie component in order to store some information encrypted and safely

```
$this->Cookie->write('hello','world!');
```

then the above error happen (The data to decrypt cannot be empty.)

I see that the cookie component try to decrypt all cookies included non encrypted by him. is a bug or I'm doing something wrong
Discussion
- All cookies handled by the cookie component are expected to be encrypted by default. You can disable encryption using the config() method.
- I really need the encryption to work with some cookies, like remember me feature in the login, disable the encryption is not the best option, but I need other cookies only to share with jquery, only that I need is fix the error message, in order to do this, I dont need read or write these cookies using cookie component. I use a php statement to do this, but the cookie component always try to decrypt an non encrypted cookie. 
Now it is impossible to use cookies with Cookie component and other cookies in javascript or another way, as I was saying the component does not need to read those other cookies, but should not have conflict with them. The developer should know that if he wrote the cookie using the component this is encrypted and only can read using the component and vice versa
