Title

"no-unused-vars" reports only the last function parameter

Description
With the following code:

``` javascript
const func = (req, res, next) => {};
```

only `next` is reported with the rule `no-unused-vars`.

This would not be an big issue but this actually triggers another bigger issue.

With the following code:

``` javascript
const func = (req, res, _next) => {};
```

and the following configuration:

```
"no-unused-vars": [ 2, { "argsIgnorePattern": "^_" }]
```

nothing is reported at all ! Which is IMO more serious.
Discussion
- Thanks for the issue report. I believe this rule is behaving as intended. It only warns on the last function parameter because you might have to define the previous parameters to be able to access it in the function body (so the last parameter defined should always be used when this rule is enabled). 

It looks to me like `argsIgnorePattern` is also working as intended, as it then ignores any cases that match the regex (which, in your example, `_next` does). Does that make sense?
- @kaicataldo I'm not sure I agree. In the first example, next is unused, so req and res should not be "protected" by the (non-)use of next. In the second example, ignoring a parameter isn't the same as using it (or at least shouldn't be), so I wouldn't want req and res to be passed over in that case either.

Both of those seem like potential bugs to me, especially the second.
