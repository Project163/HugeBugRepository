Title

camel-github component possible OOM due to only adding elements to an unbuonded map

Description
I think there is a potential for OOM errors here:  [URL]

 basically each commit sha is added to an in memory list of already processed commits used as an idempotent inmemory repository, but elements in the map are never removed.
Discussion
- Okay sounds like it should have a pluggable idempotent repository (like file component etc) where you can set an upper limit of entries to keep. 

 OOM will take a very long time as a sha is not a big object.
- It looks like we can use  

 	public List<RepositoryCommit> getCommits(IRepositoryIdProvider repository, 
			String sha, String path) throws IOException { 

 Where sha is the last known sha, then the commit service should not start from the beginning for each poll.
