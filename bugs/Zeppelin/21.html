- Yeah, that'll be fixed with   ZEPPELIN-46  .  
As a workaround you may go to zeppelin/conf/ and update interpreter.json a little. 
There is a line spark.cores.max with empty value, just put some number there, depending on your cluster size. Be aware, though that Zeppelin will use specified number of cores. F.e. I have 8 cores cluster (2 workers with 2 cores per worker) and I cannot specify spark.cores.max=8, because nobody could use spark-shell in this case - while Zeppelin is running, there is no available resources for any other tasks. 
It's actually even better. With such  configuration you could get a little fun =)  
It's possible to use %sh in zeppelin and submit something to Spark using shell-submit right from Zeppelin. Then this submit would wait until timeout, because all cores are dedicated to the Zeppelin itself. =)
