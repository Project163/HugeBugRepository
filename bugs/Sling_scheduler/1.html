Title

Registered quartz scheduler should use unique name

Description
The registered quartz scheduler always uses the default scheduler name - which results in problems if - for whatever reason - the deactivate method (and therefore the unregistering) hasn't been called or if the bundle is running more than once. 
Quartz does not allow to register the same scheduler name more than once. It seems - although the library is embedded in the bundle - that this name is registered somewhere outside of the bundle scope which therefore causes these problems.
Discussion
- The scheduler is now registered with a unique run id. 
In revision 778362 I've also updated to the latest available quartz version
