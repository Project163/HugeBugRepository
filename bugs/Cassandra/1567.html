Title

Looks like Serializing cache broken in 1.1

Description
I get the following error while setting the row cache to be 1500 MB 

 INFO 23:27:25,416 Initializing row cache with capacity of 1500 MBs and provider org.apache.cassandra.cache.SerializingCacheProvider 
java.lang.OutOfMemoryError: Java heap space 
Dumping heap to java_pid26402.hprof ... 

 havent spend a lot of time looking into the issue but looks like SC constructor has  

 .initialCapacity(capacity) 
.maximumWeightedCapacity(capacity) 

  which 1500Mb
Discussion
- attached fixes this issue... changes to ConcurrentLinkedHashCache is not needed but thought the default was good instead of setting it to 0.
- Wouldn't that instead crash with OOM later in some unpredictable moment (e.g. when cache is read from disk) or when cache resizing is done?
- initialCapacity here is the number of elements in the hashmap and not the size. Size should be controlled by maximumWeightedCapacity (yes the names are confusing through) 
We are running OOM because we where trying to allocate 1500 * 1024 *1024 elements. 

 the intial capacity is used to create the ConcurrentHashMap 
  
  new  ConcurrentHashMap<K, Node>(builder.initialCapacity, 0.75f, concurrencyLevel);
