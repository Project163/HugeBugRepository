Title

500 on ActionTemplate "no implicit conversion of nil into Array" when error near bottom of file

Description

 edit an arbitrary template add ` ` to the end of the file. Create a web request that renders that template.

  $bundle/ruby/XXX/bundler/gems/rails-XXX/actionpack/lib/action_dispatch/middleware/debug_exceptions.rb:151:in `block in log_error'

- I had a 👀 into this and found a deeper issue going on here. 

When we find a syntax error in the template, such as a missing `'` in ` `, we wrap the `SyntaxError` into a `SyntaxErrorInTemplate` exception and raise that one: 

[URL]

The issue here is that the `SyntaxErrorInTemplate` constant hasn't gotten required yet. So this line ends up raising a `NameError: unitialized constant ActionView::Template::SyntaxErrorInTemplate` in actuality. 

Later on within the debug exceptions middleware we catch this exception and go to render it, at the point of logging the exception as @Dkendal pointed out the `annotated_source_code` method returns `nil` which causes the type error: `TypeError: no implicit conversion of nil into Array` to be raised. 

What the developer ends up seeing is this page on the first request: 
  
    Something Went Wrong Page  
 

Later on the `SyntaxErrorInTemplate` is required by this check that occurs after the attempt to render: 
[URL]

So on the second request the we see the desired exception page: 
 
    Exception View  
 

The reason the `annotated_source_code` method returns nil is because when its extracting the source code it will look for the occurrence of the template file name in the backtrace: 
[URL]

However in this case the exception was a `NameError` that happened before the evaluation of the template and so the template file name won't be in the backtrace and thus the method returns nil. 

The fix for this is implemented in this PR: [URL]  this will resolve the issue of the `TypeError: no implicit conversion of nil into array`. 

It won't however resolve the issue of line numbers however, but that is a separate issue.
