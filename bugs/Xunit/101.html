Title

Breaking change in XunitException constructors

Description
The cleanup of `XunitException` constructors in [URL] breaks anyone using `Activator.CreateInstance` to call the message-only overload.

For example, [Link: Fluent Assertions uses this] and so a recent Xunit preview results in (given a failing assertion):

```
Message: 
System.MissingMethodException : Constructor on type 'Xunit.Sdk.XunitException' not found.

  Stack Trace: 
RuntimeType.CreateInstanceImpl(BindingFlags bindingAttr, Binder binder, Object[] args, CultureInfo culture)
... [Log Snipped] ...
TrackedObjectPersistenceTestsBase`2.CanAddQueryUpdateAndRemove()
TrackedObjectPersistenceTestsBase`2.CanAddQueryUpdateAndRemove()
```
