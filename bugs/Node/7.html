Title

undefined is passed as hostname to tls.checkServerIdentity

Description
Hi all,

When using `tls.connect(options)` with no `options.host` I get this:

I tried to track this and it seems [Link: tls.checkServerIdentity] get called with `hostname` as `undefined`.

Examining the stack, it gets called by [Link: _tls_wrap.js:913] and `hostname` is defined in [Link: _tls_wrap.js:859].

As you can see, `hostname` is `undefined` because neither `options.servername`, `options.host` nor `options.socket` are set.

The tls.connect doc says: "If host is omitted, it defaults to localhost", so shouldn't it actually set `options.host` to `"localhost"` in this case?

Adding it to [Link: defaults] may solve this, but I have very little understanding of this part of the code to be sure.

Is it a bug or intended?

Best regards
