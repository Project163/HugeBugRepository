Title

http codec request encoder can cause http request lines to contain invalid uri

Description
I wonder if there is a bug in this code
[URL]

If the request uri has uri parameters or fragments, then that slash is appended last.

An example, request.uri returns

```
[URL]
```

Then there is non context-path and according to that RFC and the code, netty want's to insert that missing slash, so the url should become

```
[URL]
```

But as there is maybe a bug in the code, it appends the slash at the end, so the url becomes:

```
[URL]
```

Though I have looked and read in the RFC and many of the examples are without query parameters. Though section 3.2 and 3.2.1 talks about uri general syntax, and 3.2.1 about the http URL.
