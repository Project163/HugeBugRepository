Title

Intermitent failure (NPE) in metrics endpoint test

Description
**Describe the bug**
We are experiencing intermitent failures in a test that checks the metrics endpoint.

**Expected behavior**
The test is successful.

**Actual behavior**
The test fails with the following error:

```
2020-11-18 15:28:03,089 ERROR [io.qua.ver.htt.run.QuarkusErrorHandler] (vert.x-eventloop-thread-3) HTTP Request to /metrics failed, error id: d8b6415c-3a39-424b-a974-9667983941d6-1: java.lang.NullPointerException

	at io.quarkus.narayana.jta.runtime.CDIDelegatingTransactionManager.commit(CDIDelegatingTransactionManager.java:93)
	at org.keycloak.transaction.JtaTransactionWrapper.commit(JtaTransactionWrapper.java:92)
	at org.keycloak.services.DefaultKeycloakTransactionManager.commit(DefaultKeycloakTransactionManager.java:136)
... [Log Snipped] ...

```

Discussion
- I don't have much insight into Keycloak, but from the stack trace, it looks like Keycloak is wrapping the call to the `/metrics` endpoint into a transaction, and the failure seems to be related to committing the transaction (or maybe there's a `commit` call when actually no transaction was started, hence the NullPointerException?). 
Is that transaction handling needed? (Obtaining metrics generally doesn't require it).
- @jmartisk Yes, I suspect this is something on our side. Transactions should only be managed within a blocking thread and not in an event loop thread.

I'll check why this is happening.
- I have opened [URL] to improve the error message, but I think the root cause is something in the Keycloak TX filter.
