Title

404 error page not working when navigating to an unknown route in Vercel with `adapter-vercel`

Description
### Describe the bug

With a SvelteKit app that is deployed to Vercel using `adapter-vercel`, any request to pages that are not found in routes will not render the `+error.svelte` page, but instead will throw a 500 error on the server. The expected behaviour would to show the `+error.svelte` page when navigating to an unknown route. The expected behaviour works with on a local environment and StackBlitz, but doesn't work when deployed to Vercel.

### Reproduction

Main difference between the default SvelteKit template and this code is the use of `adapter-vercel`.

1. Navigate to [URL] and see that a regular SvelteKit application is running in Vercel
2. Navigate to [URL] and see a 500 error instead of the `+error.svelte`

Steps to Reproduce on StackBlitz
1. Navigate to [URL] and see that a regular SvelteKit application is running in StackBlitz
2. Within StackBlitz navigate to the `/foo` route and see that the `+error.svelte` page does render due to an unknown route.

Cloning the repo and running locally has the same behaviour as in StackBlitz, the issue occurs when deployed to Vercel.

Discussion
- Investigation so far: This is _not_ an issue with `adapter-vercel`, but is an issue with `builder.generateManifest`. The issue reproduces using `pnpm preview` for both `adapter-vercel` and `adapter-node`. The reason behind the issue is that the server manifest looks like this:

```
const manifest = (() => {

return {
	appDir: "_app",
	appPath: "_app",
... [Log Snipped] ...
export { base, manifest, prerendered };
//# sourceMappingURL=manifest.js.map
```

Note the empty `nodes` and `routes` 😬
- Further investigation: This appears to happen when the entire app is prerendered. When prerendered, we end up with empty `nodes` and `routes`, but if there's at least one page not prerendered, `nodes[0]` exists and can display our custom error page.

(Side note: This actually means the `+error.svelte` in the template is broken in production as well, because the whole app is prerendered 😬)
