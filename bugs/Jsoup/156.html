Title

Custom Data or RcData tags with hyphens don't close correctly

Description
In version **1.20.1** of `jsoup`, the newly introduced `TagSet` class allows defining custom element behaviors. However, when configuring a custom element as `Tag.Data`, the parser fails to detect the correct closing of the element, resulting in malformed HTML output.

This issue affects both the **HTML parser** (`Parser.htmlParser()`) and the **XML parser** (`Parser.xmlParser()`), which behave similarly and incorrectly in this context.

#### **Expected Behavior:**

The input HTML or XML should be preserved as-is, treating the content of custom elements defined as `Tag.Data` as raw data (similar to ` ` or ` `), and not parsing it as nested HTML/XML.

#### **Actual Behavior:**

The parser misinterprets the contents of the `custom-style` element, incorrectly closing the tag and generating an invalid document structure.

#### **Reproducible Example:**

```
java
@Test
void testHtmlCustomElementsAsData() {

  var tags = TagSet.Html();
... [Log Snipped] ...
  assertThat(doc.html()).isEqualToNormalizingNewlines(html);
}
```

#### **Actual Output:**

```
html
 
  
    a > p {color: #0000; }  
  
... [Log Snipped] ...
  
 
```

The same output pattern is observed when using `Parser.xmlParser()` with a corresponding `TagSet` configuration.

- Hi there,

It works correctly with the tag "custom", but not "custom-style"; will need to review the transition rules for exiting the Data state. Those were built for the known tags which are always `[a-z]{1,}`.
- OK, have fixed the Tokenizer to look for tag name, not letter sequence, to close these tags.

I left the flow for the known `script` tag to look for letter sequence only, as there are more specific rules around that.

Thanks for the report!
- BTW @sparra-inmoba, I'd be interested to understand what you're planning on using this new feature for.
- Thank you very much @jhy  for your quick response and for implementing this improvement.

We're using jsoup to process MJML, which includes custom tags like mj-style for defining CSS styles. We initially tried extending XmlTreeBuilder or HtmlTreeBuilder to support these tags, but ran into limitations due to the visibility of classes like Token.

With this new TagSet functionality, we can now handle these tags properly without needing to modify the parser internally.
