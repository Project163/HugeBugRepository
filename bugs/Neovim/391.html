Title

[LSP] `start` & `end` in `range` of `vim.lsp.diagnostic.get` are always empty tables

Description
### Neovim version (nvim -v)

NVIM v0.6.0-dev+284-gc2a65921d

### Vim (not Nvim) behaves the same?

doesn't apply

### Operating system/version

Arch Linux x86_64 

### Terminal name/version

kitty 0.23.1

### $TERM environment variable

xterm-kitty

### Installation

AUR: neovim-git

### How to reproduce the issue

Open files with LSP attached that produce diagnostics for the opened file
Do `:lua print(vim.inspect(vim.lsp.diagnostic.get(0)))`

### Expected behavior

`start` and `end` in `range` of a diagnostic should not be empty tables which they seemingly are for any diagnostic (tested on Pyright and Sumneko). This does not apply to `vim.lsp.diagnostic.get_all`.

### Actual behavior

Populate `range` adequately such that plugins levering `vim.lsp.diagnostic.get` like telescope do not break. Thanks in advance for taking a look :)
Discussion
- That is a bug (although these functions are deprecated; Telescope should probably move to using functions from `vim.diagnostic` if that is not `nil`.)

The issue is in this block: [URL]
