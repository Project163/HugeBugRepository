Title

Indent rule, continuation indentation and jasmine tests

Description
Please consider the following:

``` javascript
it('should... some lengthy test description that is forced to be' +
  'wrapped into two lines since the line length limit is set', () => {
  expect(true).toBe(true);
});
```

on eslint 1.4.1 (and maybe on some later releases as well - I haven't checked) this is lint-free when one uses the following settings:

```
/* eslint-env es6,jasmine */
/* eslint indent: [2, 2] */
```

However in 1.6.0 (current) it triggers errors:

```
3:3 - Expected indentation of 4 space characters but found 2. (indent)
4:1 - Expected indentation of 2 space characters but found 0. (indent)
```

After using `--fix` this is what is considered correct in terms of the rule:

``` javascript
it('should... some lengthy test description that is forced to be' +
  'wrapped into two lines since the line length limit is set', () => {
    expect(true).toBe(true);
  });
```

Apart from whether it's correct or not (all indentation-related statements about correctness are arguable) it changes a lot of lines in the VCS history when applied.

As I analysed the problem it is because the first argument of `it` (the lengthy string) continuation is indented with 2 spaces (one step).
If one removes the continuation indentation like this:

``` javascript
it('should... some lengthy test description that is forced to be' +
'wrapped into two lines since the line length limit is set', () => {
  expect(true).toBe(true);
});
```

it becomes lint-free again. I'd go for it if it was possible to set IDE autoformatting rules like this. Sadly - it's not.

If I understand how the rule works then function body is expected to be indented with one step more than the line where function body block begins.
