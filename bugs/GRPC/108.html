Title

[Ruby] [1.58.0 regression] Segfault in channel constructor on Windows

Description
gRPC for Ruby on Windows (x64-mingw-ucrt) segfaults in the `GRPC::Core::Channel` constructor when the protobuf library is loaded *before* grpc.

Environment:
* OS: Windows Server 2022 version 10.0.20348 (the "windows-latest" OS on GitHub Actions as of 2023-09-09)
* Language: Ruby (versions 3.2.2 and 2.7.8 tested)
* GRPC 1.58.0 (Gem version `grpc-1.58.0-x64-mingw-ucrt` along with dependencies `google-protobuf-3.24.3-x64-mingw-ucrt` and `googleapis-common-protos-types-1.8.0`)

Reproduction steps:

```sh
gem install grpc:1.58.0
```

Then run the following Ruby script:

```
ruby
# This is a test of a grpc 1.58.0 segfault on Windows.

# This must be required BEFORE grpc to reproduce the segfault
require "google/protobuf"
... [Log Snipped] ...
# Never gets here
puts "Never gets here"
```

Other notes:

* I have not been able to reproduce this on any OS except Windows. (Tried ubuntu and macos.)

* Does not reproduce in grpc 1.57.0. This seems to be a regression in 1.58.0.

* Ruby version does not seem to have an impact. I'm seeing a basically identical segfault on both Ruby 3.2 and 2.7.

* This may have something to do with an interaction with the protobuf library, because the segfault does *not* occur if we omit `require "google/protobuf"`, nor if we swap the order of `require "google/protobuf"` and `require "grpc"`.
