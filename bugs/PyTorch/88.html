Title

Segmentation fault in embedding_bag

Description
### 🐛 Describe the bug

Segmentation fault in `embedding_bag`, `_embedding_bag` and `_embedding_bag_forward_only`.

### Example to reproduce

```
python
import torch

tensor_0 = torch.full((8, 8, 0, 0, 0,), 1.5e+300, dtype=torch.float64, requires_grad=False)
tensor_1 = torch.full((8, 8, 0, 0, 0,), 1, dtype=torch.int64, requires_grad=False)
... [Log Snipped] ...
padding_idx = 0
torch._embedding_bag_forward_only(weight, indices, offsets, scale_grad_by_freq, mode, sparse, per_sample_weights, include_last_offset, padding_idx)
```

### Result
```segmentation fault```

### Expected behavior
Graceful termination or a RuntimeError to be thrown.

This bug was discovered using fuzz testing.

`offsets` is supposed to either be `None` or have only one dimension, according to the docs [Link: here]. Also, `input` is supposed to only be 1D or 2D. So these cases should be throwing errors about invalid argument shapes.

The reason this causes a segfault is that, since `offsets` is assumed to be 1D if it is not `None`, before it checks that the values in `offsets` are correct, it checks `offsets.size(0) > 0` to avoid trying to access invalid memory. But in this case, `offsets.size(0)` is greater than 0, but `offsets.numel()` is 0 since there are zeros in the higher dimensions of `offsets.shape`.

I'll add the shape checks.
- Some relevant details:

`torch.nn.functional.embedding_bag` already performs the dimensionality checks here: [URL]

`torch.nn.functional.embedding_bag` ends up calling `torch.embedding_bag`. `torch.embedding_bag` is not in the documentation, and it's not being called anywhere else, aside from a benchmark test in `benchmarks/static_runtime/test_static_runtime.cc`. It seems like users aren't really supposed to use it, and they should use `torch.nn.functional.embedding_bag` instead.

Since `torch._embedding_bag` and `torch._embedding_bag_forward_only` begin with underscores, users aren't supposed to call it. And they are only called within `at::embedding_bag` here: [URL]

It would be nice to refactor this stuff to be a bit simpler. We might be able to move the whole definition of `torch.nn.functional.embedding_bag` to C++. But I imagine there would be some backward compatibility issues with that. And I don't know the reasons why things are set up this way, so maybe refactoring wouldn't be a good idea anyway.

So for now, I guess the best solution is still to just duplicate dimensionality checks into `at::_embedding_bag_forward_only` and `at::_embedding_bag`. Since `at::embedding_bag` just calls into one of those, it will pick up the checks as well. The checks aren't expensive anyway, so duplication shouldn't noticeably change performance
