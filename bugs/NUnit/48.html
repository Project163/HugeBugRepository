Title

Generic Test Method cannot determine type arguments for fixture when passed as IEnumerable

Description
Having test written like:

```
csharp
using System.Collections.Generic;
using System.Linq;
using NUnit.Framework;

... [Log Snipped] ...
    }
}
```

fails with:

```
SequenceEquality (System.Int32[],System.Int32[]) ignored: Unable to determine type arguments for fixture
```
Discussion
- As a workaround, try moving your test case data to a separate (maybe nested) class. The class should implement IEnumerable and return your test case data items.

Meanwhile, we'll investigate the issue.
- Ok, I tried to go with your suggestion (tried both separate class and nested class):

```
csharp
using System.Collections;
using System.Collections.Generic;
using System.Linq;
using NUnit.Framework;
... [Log Snipped] ...
    }
}
```

However test results were the same:

```
SequenceEquality (System.Int32[],System.Int32[]) ignored: Unable to determine type arguments for fixture
```
- ... [Middle Discussions Snipped for Brevity] ...
- No matter if I run tests thru resharper (my prefered way of running tests) or via console I still get the same result above.

Console run:

```
c:\utils\NUnit-2.6.4\bin>nunit-console.exe Test.dll
NUnit-Console version 2.6.4.14350

2) NotRunnable : Test.GenericsEnumerableTests.SequenceEquality (System.Int32[],System.Int32[])
   Unable to determine type arguments for fixture
```

Also I tried different versions of frameworks: net-3.5, net-4.0, net-4.5, net-4.6, same results.
- Turns out to be quite a serious problem. We only recognize the simplest of cases, where the actual argument exactly matches expected generic type. Even something like SomeMethod (List  c) is not handled correctly and interfaces are compeltely ignored.

@cuiviemen Good you found this! It has apparently been a bug for a long time but not reported because generic methods are not used that often and users simply assumed that any error was their own fault.
