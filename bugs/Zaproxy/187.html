Title

History tab cleared when session persisted

Description
Start using ZAP without persisting the session.
Persist it.
The Site tree remains (as it should) but the History disappears.
If you close ZAP and open the session is does appear correctly.
Discussion
- Note you don't even have to close ZAP to get the history repopulate, you can just re-open the session.
- This seems to be a purely UI issue. I made a lame stand alone script as follows, which causes the table to be redrawn (dunno what better terminology to use). [Obviously you can also just click the 'show only in scope' bullseye button twice.]

```javascript
extHist = org.parosproxy.paros.control.Control.getSingleton().
    getExtensionLoader().getExtension(
        org.parosproxy.paros.extension.history.ExtensionHistory.NAME) 
if (extHist != null) {
    extHist.setShowJustInScope(true);
    extHist.setShowJustInScope(false);
}
```

I tried getting the table or the model and doing a `fireTableDataChanged()`, I also tried looping and notifying (like the [Link: source tagger] script in the community repo does), neither of which seemed to help.

Lastly, you can also script accessing history items even when they aren't displayed.
- Yes, this is just about the History tab (updated the title to be more clear), it's caused by the different order of session/context events when saving/opening a session.
