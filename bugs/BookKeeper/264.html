Title

Filtered Messages Require ACK from Client Causes User Being Throttled Incorrectly Forever

Description
In current FIFODeliveryManager, once a message is filtered in ActiveSubscriberState#messageScanned(), it just call ActiveSubscriberState#sendingFinished() and wait client's acknowledgement. However, the message isn't being delivered to client side, and once the number of such filtered messages larger than the delivery window size, the user cannot receive messages anymore!
Discussion
- the issue would also affect cross region delivery. we need to track the filtered msg id range and last consumed seq id to address the sequence id gap introduced by filter out messages.
- please ignore my previous comment. this fix would be pretty straightforward, just one line: modify the consume seq id in ActiveSubscriberState when #sendingFinished for a filtered out message.
