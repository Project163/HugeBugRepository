Title

`retry_wget` appears to retry on success?

Description
[Link: This build] failed thusly:

```
|  ---> f83d1a60c1c3
	| Step 8/44 : RUN function retry_wget() {       local URL="$1" ;       local DEST="$2" ;       for iter in {1..10}; do         wget "$URL" -O "$DEST" &&         exit_code=0 && break ||           exit_code=$? && echo "wget error: retry $iter in 10s" && sleep 10;       done;       return $exit_code ;     } ;     retry_wget "[URL] "curl-gpg.pub" &&     retry_wget "${TARBALL_URL}.asc" "${TARBALL_PATH}.asc" &&     retry_wget "${TARBALL_URL}" "${TARBALL_PATH}"
	|  ---> Running in 9083154b848f
	| Connecting to daniel.haxx.se ( :443)
	| saving to 'curl-gpg.pub'
... [Log Snipped] ...
	| wget error: retry {1..10} in 10s
	| The command '/bin/sh -c function retry_wget() {       local URL="$1" ;       local DEST="$2" ;       for iter in {1..10}; do         wget "$URL" -O "$DEST" &&         exit_code=0 && break ||           exit_code=$? && echo "wget error: retry $iter in 10s" && sleep 10;       done;       return $exit_code ;     } ;     retry_wget "[URL] "curl-gpg.pub" &&     retry_wget "${TARBALL_URL}.asc" "${TARBALL_PATH}.asc" &&     retry_wget "${TARBALL_URL}" "${TARBALL_PATH}"' returned a non-zero code: 1	%
```

Seems suspicious, we apparently succeeded to get the key but then tried a second time and it failed which failed the build?

Relates #63615
Discussion
- Pinging @elastic/es-delivery (Team:Delivery)
- It probably failed fetching the next file, the `.asc` file. However this failure shows that the retry mechanism doesn't work in Alpine Linux, because its default shell interprets `{1..10}` as a literal value, unlike `bash` which expands the sequence. I'll prepare a fix for this.
