Title

Problem with JAXB if the bcel classloader is used

Description

Discussion
- Can you please provide some testcase or code snippet?
- The most likely cause for this is because the bcel Classloader does not follow the Java 2 classloader delegation pattern. 
Depending on the setup, it might use a SyntheticRepository to load the class from the classpath (which also includes the system classes, and org.xml.sax.InputSource is part of them) instead of using the bootstrap classloader to load system classes. 

 Furthermore the bcel ClassLoader does not correctly call definePackage, so clazz.getPackage() might be null and cause problems in some cases.
