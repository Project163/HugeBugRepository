Title

select().fetch() behaves differently in core and ORM

Description
### Discussed in [URL]

 

 Originally posted by **kdwyer** June  3, 2022 
On Postgresql, `select().fetch()` behaves correctly in core, but not in the ORM.

Versions:

- PostgreSQL 13.7 on x86_64-suse-linux-gnu, compiled by gcc (SUSE Linux) 7.5.0, 64-bit
- psycopg2-binary        2.9.3
- SQLAlchemy             1.4.37

Given this initial setup:

```
python
import sqlalchemy as sa
from sqlalchemy import orm

Base = orm.declarative_base()
... [Log Snipped] ...
with Session.begin() as s:
    s.add_all([Model() for _ in range(6)])
```

This core code

```
python
with engine.connect() as conn:
    models = Model.__table__
    q = sa.select(models).order_by(models.c.id).fetch(2)
    for model in conn.execute(q):
... [Log Snipped] ...
    for model in conn.execute(q):
        print(model.id)
```
generates the output that I would expect:
```
none
2022-06-03 08:15:28,847 INFO sqlalchemy.engine.Engine SELECT tbl.id 
FROM tbl ORDER BY tbl.id
 FETCH FIRST (%(param_1)s) ROWS ONLY
2022-06-03 08:15:28,847 INFO sqlalchemy.engine.Engine [generated in 0.00064s] {'param_1': 2}
... [Log Snipped] ...
4
5
```

However this ORM code
```python
with Session() as s:
    q = sa.select(Model).order_by(Model.id).fetch(2)
    for model in s.scalars(q):
        print(model.id)
    q = sa.select(Model).order_by(Model.id).offset(3).fetch(2)
    for model in s.scalars(q):
        print(model.id)
```
omits the `FETCH` when no `OFFSET` is present, returning all rows, and emits `LIMIT ALL` when `OFFSET` is present.
```
none
2022-06-03 08:15:28,852 INFO sqlalchemy.engine.Engine SELECT tbl.id 
FROM tbl ORDER BY tbl.id
2022-06-03 08:15:28,852 INFO sqlalchemy.engine.Engine [generated in 0.00019s] {}
1
... [Log Snipped] ...
5
6
```
I didn't find anything in the docs to explain why `select().fetch()` would behave differently in the ORM in the docs.  Am I missing something?
