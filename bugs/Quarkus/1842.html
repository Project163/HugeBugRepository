Title

OIDC Challenge response has JSON content type without body

Description
### Describe the bug

## Background

I configured my quarkus service for our SPA as described:

[URL]

When I send a request with the header " X-Requested-With: JavaScript", the response has all the expected characteristics from the article.

## Bug

The response includes a header `Content-Type` but no body. That is a conflict.

For example, the fetch API [URL] does not provide introspection methods to identify this case, and calling `json()` leads to the error: `JSON.parse: unexpected end of data at line 1 column 1 of the JSON data`





### Expected behavior

The `Content-Type` should not be included in the response when there is no content.

### Actual behavior

This the a typical response in the browser:

```
HTTP/1.1 499 Client Error (499)
access-control-allow-origin: [URL]
access-control-allow-credentials: true
Content-Type: application/json
WWW-Authenticate: OIDC
content-length: 0
```

### How to Reproduce?

Use reproducer: [URL]

OR

Follow the described instructions in [URL]

1. Add the extension `quarkus-oidc`
2. Disable redirects for javascript calls
```properties
quarkus.oidc.authentication.java-script-auto-redirect=false
```
3. Declare a protected resource
4. Access the protected resource as a JavaScript client. Here using curl:

```
curl '[URL] -H 'Accept: application/json' -H 'x-requested-with: JavaScript' -v
*   Trying  :8080...
* Connected to   ( ) port 8080 (#0)
... [Log Snipped] ...
  left intact
```
