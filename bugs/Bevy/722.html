Title

Children not updated correctly when spawning ChildOf components using World::spawn_batch

Description
## Bevy version

Tested on 0.16.0 and the main branch ( )

## What you did

I tried to spawn a batch of children with the following code

```rust
let mut world: World = World::new();
let root = world.spawn_empty().id();
world.spawn_batch((0..10).map(|_| ChildOf(root)));
assert_eq!(world.entity(root).get:: ().unwrap().len(), 10);
```

## What went wrong

I was expecting the root entity to have 10 children, (or possibly zero if I need to call `World::flush`). Instead it has 1 child (the last child entity returned by `spawn_batch`. Only the last entity in the batch has a `ChildOf` component too.
Discussion
- I've found the bug.
`spawn_batch` flushes once after having spawned all entities. Each spawned entity runs its `ChildOf`'s `on_insert` hook.
Here is the relevant [Link: part] of that hook
```
Rust
            if let Some(mut relationship_target) =
                target_entity_mut.get_mut:: ()
            {
                relationship_target.collection_mut_risky().add(entity);
... [Log Snipped] ...
                world.commands().entity(target_entity).insert(target);
            }
```
Since we are not flushing in between spawns, hooks wont find any `Children` component and they will branch on else which creates a new `Children` component with a single entity and defers its insertion. Finally when we flush, each insertion of the `Children` component after the first will trigger the `on_replace` hook of `Children` which will remove the corresponding `ChildOf` component. That is how we end up in that state of having just the last entity with a `ChildOf` component.

I see two ways of fixing this:
1) We flush after every spawn;
2) We defer the whole aforementioned part of the hook.

I don't know enough but 1) feels bad if we can do otherwise and 2) seems good to me. I've tested and both work.
I've never written a PR but I would gladly do one for this.
