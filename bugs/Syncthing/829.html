Title

Local host header check is too restrictive

Description
When doing the host check, syncthing calls addressIsLocalHost(), which appears to be too restrictive.  There are valid localhost addresses that are failing this test.  For example,  .  In fact  /8 is defined as being local to the machine.

My use case is this:

To avoid more and more obscure local port forwarding when I SSH to a remote box (e.g. ssh -L 28384:localhost:8384), I put specific localhost entries in /etc/hosts, such as
      myremotehost.lo 
and then I can put this in my ~/.ssh/config:
    Host myremotehost.com
        LocalForward myremotehost.lo:8384 localhost:8384
and then navigate to
    [URL]

This breaks because addressIsLocalHost() doesn't think   is a valid local host, and I get the Host Check Error.

I can disable the check, but that weakens security.  It would be better to have the function fixed.

I'm not a Go programmer.  I can see in GitHub where the code is called, and where the test function is.  Perhaps it's a standard library function.  I tried googling and searching the golang API site, but I can't find it.  Sorry I can't be more help.

Syncthing Version: v0.14.32
OS Version: Debian 7
Browser Version: Firefox 58.0.2 (Ubuntu)
Discussion
- However, this won't solve your problem.


With the fix, we will consider   a local address and do the check on the host header. "myremotehost.lo" is not one of the allowed host headers, looks like a DNS rebinding attack, and will be denied by the host check. This is the desired outcome.

But since you are hitting the check today, my guess is that your Syncthing is already bound to   and this entire change is a no-op for you.
