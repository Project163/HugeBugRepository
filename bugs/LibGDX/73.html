Title

HttpResponseListener.handleHttpResponse is called if no internet connection on gwt

Description
#### Issue details
If client no internet connection, method `Gdx.net.sendHttpRequest(request, listener)` not call failed or cancelled. Exception not thrown.
Only for GWT. On desktop and android failed method called.

#### Reproduction steps/code
Send request multiple time (every 5 sec).
Turn off internet, responce listener not called failed or cancelled. Exception print in console.

#### Version of LibGDX and/or relevant dependencies
1.9.10

#### Stacktrace
```java
net::ERR_INTERNET_DISCONNECTED
```
of infinity time with timeout.

#### Please select the affected platforms
- [ ] Android
- [ ] iOS
- [x] HTML/GWT
- [ ] Windows
- [ ] Linux
- [ ] MacOS
Discussion
- I'm not sure I understand. What do you mean by `of infinity time with timeout` ? If you give an infinite amount of time to attempt to make a connection, I think it will attempt to connect until the internet is enabled again, and it can make the request. The console here is the JavaScript console in the browser, right? That would explain why it doesn't give a typical Java stacktrace. I know @MrStahlfelge is great with GWT, but I don't know how much networking he does with GWT. I think someone will be able to answer if you can wait.
- I do HTTP requests, but they work for me. I just tested with `HttpRequestExample` (a hidden test), and indeed failed/cancelled is not called, but `handleHttpResponse` is called with status code 0 and I handle that in my game as a fail.

I didn't debug if we could handle this better (`GwtNet` uses code provided by GWT which looked sophisticated), but I doubt the browser will report detailed errors to the request callback. So if there is no error/exception to handle, one could argue if `failed` should be called
