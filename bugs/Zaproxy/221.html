Title

Break tab is not automatically shown in full layout when breakpoint is hit

Description
**Describe the bug**

When the "full layout" is active, the Break tab is not yet added and global break is enabled, the Break tab is not shown when a breakpoint is hit. This means that users are not aware that there's an HTTP request still waiting for interaction, it's just hanging there.

Manually adding the Break tab then shows the hanging request so users can decide what to do with it.

**To Reproduce**
Steps to reproduce the behavior:
1. Start ZAP
1. Activate "full layout" by clicking on the icon in the icon list
1. Break tab should not be added already
1. Activate global break
1. Make an HTTP request
1. Nothing happens, Break tab does not appear
1. Add the Break tab manually via the + sign in the tab bar
1. Intercepted HTTP request is shown

**Expected behavior**

Break tab should appear automatically in "full layout" mode.

**Software versions**
 - ZAP: 2.7.0
 - OS: Debian stable 9.4 ("stretch")
 - Java: openjdk 1.9, Debian version number: `9~b181-4~bpo9+1`, package `openjdk-9-jre`
