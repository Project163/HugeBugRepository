Title

crypt + b2: 400 sha mismatch

Description
I'm using rclone 1.33 on Linux x64, trying to upload a local file to Backblaze B2 using the new Crypt remote type.

Here are the errors I'm getting:

```
$ cat ~/.rclone.conf
[b2-plaintext]
type = b2
account = ...
key = ...
... [Log Snipped] ...
2016/08/25 16:02:17 Attempt 3/3 failed with 1 errors and: Sha1 did not match data received (400 bad_request)
2016/08/25 16:02:17 Failed to copy: Sha1 did not match data received (400 bad_request)
```
Discussion
- I've fixed this in the beta below.

Note that this has the unfortunate consequence that all B2 uploads with crypt will be buffered to disk first.  This is because B2 require the SHA1 of the object before it is uploaded.  They are planning to allow you to supply it afterwards in an update of the API which will fix this.

[URL]
- I've confirmed that v1.33-2 fixes the issue. Thanks for the fast turnaround!

When uploading "Large Files" via B2's large file API, will only chunks need to be buffered, on the entire file?
- Thanks for confirming that.

When uploading large files ( > `--b2-upload-cutoff`) the file won't be buffered to disk.  The individual chunks are buffered in memory as they were before.
