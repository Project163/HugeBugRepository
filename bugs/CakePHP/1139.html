Title

The `Example` alias has already been loaded. The `className` was not defined in the previous configuration data.

Description
### Description

```
The `Second` alias has already been loaded. The `className` was not defined in the previous configuration data.
CORE/src/Core/ObjectRegistry.php at line 160
```

Issue relate to loading custom Plugin View Helpers.

How to reproduce:
1. Create 2 custom helpers inside a plugin, first plugin needs to load and use the second one using the `Plugin.Helper` style Helper dependency.
2. Use use both plugins from Plugin Template without setting those plugins in Plugin View (so they will be loaded by the cake autoloader.

The issue is due miss match load logic between [Link: HelperRegistry] and [Link: Helper] or rather [Link: ObjectRegistry]


Loading the Helper directly from View goes over normalization and in turn gets a generated config of ['enabled' => false, 'className' => 'PluginName']
While loading Helper thru Helper dependency goes thru HelperRegistry that is not setting the 'className' for plugin helpers.

`Helper dependency`:

```
class FirstHelper extends Helper
{
    /**
     * Other helpers used by FormHelper
     *
     * @var array
     */
    protected array $helpers = ['PluginName.Second'];
```


I think the fix would be to set className while doing a fallback into plugin in [Link: HelperRegistry] by changing it from 
```
$this->load($plugin . '.' . $helper);
```
to
```
$this->load($helper, ['className' => $plugin . '.' . $helper]);
```


(Yes, I could initialize that helper in Plugin View and provide the className, but I would really like to still have the autoload function working, unless it's deprecated and could get removed in the near future)


This issue could also affect CakePHP 4.x (untested)

### CakePHP Version

5.0.0

### PHP Version

8.2
