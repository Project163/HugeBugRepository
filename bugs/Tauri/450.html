Title

[bug] beta autogenerate permissions for plugins

Description
### Describe the bug

The autogenerate permissions only appears to work with snake case command names, this is fine for any custom commands but is incompatible when trying to call out to the mobile `Plugin` class methods (ios & android base class). These are all camel case `checkPermissions` `requestPermissions` etc.

in order to solve this for now I had to first populate the `build.rs` with

```
rust
const COMMANDS: &[&str] = &["get_location", "check_permissions", "request_permissions"];

fn main() {
    tauri_plugin::Builder::new(COMMANDS)
... [Log Snipped] ...
        .build();
}
```

then run `cargo build` to generate the permissions, then remove the commands to prevent the autogenerated files from being overwritten

```rust
const COMMANDS: &[&str] = &[];
```

then I manually changed the autogenerated `permissions/autogenerated/commands/check_permissions.toml`

```
toml
# Automatically generated - DO NOT EDIT!

"$schema" = "../../schemas/schema.json"

... [Log Snipped] ...
description = "Denies the check_permissions command without any pre-configured scope."
commands.deny = ["checkPermissions"] <- change to camelcase
```

### Expected behavior

remove the snake case requirement and be more flexible in how the permissions are generated OR provide a detailed guide on how users can create their own permissions without using the autogenerate.
