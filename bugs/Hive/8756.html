Title

Query result is cached in case of IOWD if the subquery is not trivial

Description
HIVE-25907   fixed a case when an insert overwrite directory didn't write the data to the final path when the query results cache was enabled. The solution was implemented by checking the QB.parseInfo at a certain point in the semantic analysis and writing/reading a flag to a QB instance. The problem is that depending on the query (which produces the data to be inserted) can be of different complexity, and   HIVE-25907   only took care of queries like: 
  
 
INSERT OVERWRITE DIRECTORY  "<destination directory>"  SELECT * FROM iowd;
 
  
 but for queries like this: 
  
 
 EXPLAIN EXTENDED INSERT OVERWRITE DIRECTORY  '/tmp'   select a13.CATEGORY_ID CATEGORY_ID, max(a14.CATEGORY_DESC) CATEGORY_DESC,a12.SUBCAT_ID  SUBCAT_ID,max(a13.SUBCAT_LONG_DESC)  SUBCAT_DESC,avg((a11.QTY_SOLD * (a11.UNIT_PRICE - a11.DISCOUNT)))  WJXBFS1,sum((a11.QTY_SOLD * a11.UNIT_COST)) WJXBFS2 from ORDER_DETAIL a11 join LU_ITEM a12 on  (a11.ITEM_ID = a12.ITEM_ID) join LU_SUBCATEG a13 on  (a12.SUBCAT_ID = a13.SUBCAT_ID) join LU_CATEGORY a14 on  (a13.CATEGORY_ID = a14.CATEGORY_ID) group by a13.CATEGORY_ID, a12.SUBCAT_ID;
 
  
 it doesn't work. The root cause is that the flag is set in  one QB instance , but during the plan generation, genPlan is recursively called, moreover, this.qb doesn't refer to the main/root QB all the time, as  setQB  is called at every step, so when iterating and reaching the file sink generation plan, the QB instance is used is not the same as the one on which the isInsertOverwriteDirectory flag was set. 

 When this issue is present, an EXPLAIN EXTENDED can reveal the strange strategy of a query when result cache is enabled, here is a snippet: 
  
 
|         Reducer 5                                  |
...
|                   File Output Operator             |
|                     bucketingVersion: 2            |
|                     compressed:  false               |
|                     GlobalTableId: 0               |
|                     directory: file:/efs
