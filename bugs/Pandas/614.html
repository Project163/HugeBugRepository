Title

diff() behavior causes memory problems

Description
diff(n) with a negative n used to be a recipe for obtaining a forward-looking diff. Now it causes memory problems. 

The change was introduced in commit   and "improved" in commit 0d6fb1b381ef3882ceb766fecb0e28a5d5c2bd2bw . The first commit produces unexpected results silently. The second commit causes an outright coredump with 

**\* glibc detected **\* /usr/bin/python: double free or corruption (out):   ***

This is a simple script to trigger this bug:

import pandas
import numpy as np
x = np.sin(np.arange(24))
x = x.reshape((4,6))
df = pandas.DataFrame(x,columns=['a','b','c','d','e','f'])
print df
df2 = -df.diff(-1)
print df2
