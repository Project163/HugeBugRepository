Title

Empty ignore patterns on startup

Description
syncthing v0.10.6 (go1.3.3 linux-amd64 default)

The REST API returns empty ignore patterns on startup, I guess this happens before Syncthing has performed its initial scan. Is the best way to check for the /rest/model state before retrieving the ignore patterns again?
Discussion
- It seems that the patterns are only populated after a first scan.
I guess we should populate the patterns upon adding the folder to the model which should solve the problem.

I assume the `ignores` are still there, it's only the `patterns` that are missing?

Alternatively, you could do a dummy scan on an non-existing path to populate it, but that's just avoiding an issue which we should fix.

I'll get this fixed over the weekend.
