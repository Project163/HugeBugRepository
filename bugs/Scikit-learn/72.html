Title

BUG: KNeighborsClassifier & KNeighborsRegressor **kwargs

Description
`KNeighborsClassifier` and `KNeighborsRegressor` (and any others?) handle unspecified `**kwargs` in their initialization: this means they will not work correctly with `clone()` in, e.g. cross validation.  The API needs to be changed so that kwargs are passed explicitly as a dictionary.

The good news is that these keyword arguments are used only for obscure metrics, so there is likely very little code out in the wild that uses the current problematic API.
Discussion
- I just want to clarify: in place of doing unpacking, the constructor should accept a dictionary itself? We would also need to fix it in the parent class NeighborBase since it is accepting **kwargs as well. Is that correct?
- Yeah, that's correct. Any classifier that accepts **kwargs will break the cloning API.

I don't think the utility routine in `NeighborsBase` needs to be changed, because it's not an outward-facing `__init__` method.

I'd do it this way: in `KNeighborsClassifier` and `KNeighborsRegressor`, add a `metric_params` dictionary argument (default = None) and keep the **kwargs for now; if the user passes anything to kwargs, raise a suitable DeprecationWarning and populate `metric_params` with those values.
- @jakevdp, should this sort of issue be subject to a common test?
- I think it would be nice to have a baseline check for this, but I am not sure _how_ you would actually do it. I can say that there are other corners of the codebase where **kwargs are lurking
