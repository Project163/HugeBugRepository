Title

Metrics extension causes issues with Resteasy in native runtime

Description
**Describe the bug**
I followed the [Link: Creating Your First Application] guide and created a simple JAX-RS/Resteasy app. I have my code uploaded on [Link: Github]. The app runs fine doing a JVM based build. However if I do a native build using the [Link: multi stage Dockerfile], I start getting MethodNotFoundException errors. After some debugging it looks like the issue is inclusion of the metrics extension. Creating the app as is with the exception of adding the metrics stuff causes the native app to behave just fine.

**Expected behavior**
Runtime of native app behaves the way runtime of the jvm app does.

**Actual behavior**
Any HTTP requests (including readiness health check) results in a MethodNotFoundException in the runtime of the native app.


**To Reproduce**
Steps to reproduce the behavior:
1. Clone [Link: my repo]
2. Build native executable for the app (e.g. `./mvnw clean package -Pnative -Dquarkus.native.container-runtime=podman`)
3. Run the app (will run on port 8080) - `./target/sample-quarkus-app-1.0-SNAPSHOT-runner &`
4. Consume the app's endpoints:
    - curl localhost:8080/api/values (causes exception - see [Link: relevant code])
    - curl localhost:8080/health/ready (causes exception - see [Link: relevant code])
    - curl curl localhost:8080/health/live (works OK - see [Link: relevant code])

- Hm, it seems that the `NoSuchMethodException` occurs during `InMemoryStorageService` injection, but only if that bean contains a method annotated with `@Gauge`. If I remove the gauge, it works. But right now I have no idea why that happens, especially since it's in native mode only.
At build time, we dynamically attach an interceptor binding (`MetricsBinding`) to beans that contain a Gauge, but that's basically all that happens specifically to such beans at build (we don't actually register/initialize the gauge until the bean is instantiated). Perhaps it has something to do with that.

Anyway if it is necessary to fix quickly, I have a workaround for now: remove the `@Gauge` annotation from the `size()` method and instead register the gauge by including this in `InMemoryStorageService`:

```
@Inject
MetricRegistry metricRegistry;

@PostConstruct
public void sizeGauge() {
	metricRegistry.register(this.getClass().getName() + ".size", (org.eclipse.microprofile.metrics.Gauge ) this::size);
}
```

It should be pretty much equivalent.
