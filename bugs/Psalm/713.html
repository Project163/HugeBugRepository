Title

The possibility that template parameter can be instantiated with type, narrower than its constraint, is not taken into account

Description
Look at this snippet: [URL]

here function `usesCollection (Collection  $col)` is allowed to add arbitrary value to the collection, even though it's type T is not known. To demonstrate the possibility of bugs, i've created a collection of strings, and via this function added an integer to it. Psalm noticed no errors.

Such behavior is disallowed in TypeScript:

```
ts
class Collection  {
    constructor(private col: T[]) {}

    add(element: T): void {
... [Log Snipped] ...
    col.add(123);
}
```
Discussion
- BTW, i noticed that in this snippet it is also possible to instantiate the `$collection` as follows:
`$collection = new Collection([ 1, 2, 3 ]);` even though i stated it's collection of strings in `@var` annotation. I don't know whether `@var` annotation must take precendence over actual type inferred from code, so I do not call it a bug.
- Yeah, `@var` always takes precedence. But the first is a bug.
