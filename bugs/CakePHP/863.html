Title

ServerRequest::getRequestTarget() does not return query string when using IntegrationTestCase

Description
According to the [Link: API docs of ServerRequest::getRequestTarget()], the function should also return the query string.


I was just testing a middleware which checks the request target for some given strings.
While my middleware worked fine when I checked through the browser, the related integration test using **IntegrationTestCase** failed.

I found out, that **ServerRequest::getRequestTarget()** returns the query string just fine normally, but does not when using **IntegrationTestCase**.

URL = /servlet/com.piso.xyz.ecom.gui.DispatcherServlet?function=ReturnxyzContent&language=de&agency=AGENCY

Normal Request through Browser
$path = /servlet/com.piso.xyz.ecom.gui.DispatcherServlet?function=ReturnxyzContent&language=de&agency=AGENCY
$request instanceOf \Cake\Http\ServerRequest
$request->uri->path = /servlet/com.piso.xyz.ecom.gui.DispatcherServlet
$request->uri->query = function=ReturnxyzContent&language=de&agency=AGENCY

Integraton Test
$path = /servlet/com.piso.xyz.ecom.gui.DispatcherServlet
$request instanceOf \Cake\Http\ServerRequest
$request->uri->path = /servlet/com.piso.xyz.ecom.gui.DispatcherServlet
$request->uri->query = _empty_

I traced it down:
IntegrationTestCase::_url()
- $parameter & $query are OK

IntegrationTestCase::_buildRequest()
- $tokenUrl = /servlet/com.piso.xyz.ecom.gui.DispatcherServlet?function=ReturnxyzContent&%3Blanguage=de&%3Bagency=AGENCY
- $url = /servlet/com.piso.xyz.ecom.gui.DispatcherServlet

It seems the changes in [URL] from [URL] changed this behavior, though at the time focusing on fixing a similar but reversed problem with the legacy ``$request::here()``.
