Title

Sleeping thread prevents test runner from exiting

Description
Yesterday I stumbled upon an issue with our tests not finishing. I hunted it down to the fact, that, as long as a non-background thread is running, the test runner does not stop. Here is a minimal repro test. Maybe this is similar to #3447.

```
csharp
[Fact]
public void Test()
{
    // arrange
... [Log Snipped] ...
    // assert
}
```

I am using xunit.v3 in version 3.2.0 with the runner in version 3.1.5.
Discussion
- I can mostly fix this, but a full fix requires a new major version.

I can fully fix the problem of the process being hung forever. The part I can't fully fix is that it should show up a test process failure. In practical terms, it means that sometimes this will be considered an error condition, and sometimes it will be considered a success condition.

The fix works like this: At the entry points, before returning the result value, we schedule a background task that will end up waiting for 1 second, and then printing a message which says it's waiting for foreground threads to exit. If they don't exit after 10 seconds, then we forcefully shut the process down with exit code `1`. Since the background task uses a thread pool thread, it will not stop the process from exiting by itself, so without any other foreground threads running, the test application just exits immediately (as it should).

This works for `dotnet run` in xUnit.net UX mode:

and `dotnet run` in Microsoft.Testing.Platform mode:

and `dotnet test` in Microsoft.Testing.Platform mode:

_Note in all three of these that the screenshots show the process exited with error code `1`._

However, it appears to pass in `dotnet test` in VSTest mode:

As well as using our first party console runner:

_Note in these two screenshots there is no exit code shown, which means it exited with `0` (no error)._

When you run these things interactively, the only hint you have that something is wrong is that you will see the `Finished` message, and then approximately 11 seconds of seeming to be hung, then actually exiting successfully.

The breaking change that has to happen is in `xunit.v3.runner.utility`, which is the library that our first runners use, including `xunit.v3.runner.console` and `xunit.runner.visualstudio` (our VSTest adapter). We need to be able to propagate out the exit code of the test process so that the runners can in turn report the failure.

I can make this change for 4.0.0 (which will then need to be consumed by all our runners), but that currently does not have a scheduled release date. I would also like to investigate whether there's anything I can to fix the fact that we are sending additional diagnostic messages and failure messages that are currently being ignored (you don't see either of the "waiting" or "fatal error" messages).

Strangely enough it doesn't correctly fail the tests in Test Explorer, regardless of MTP vs. VSTest mode:

Just like on the command line, here you see all the tests pass, and then about 11 seconds of "spinning wheel" (MTP mode) or "status bar not finished" (VSTest mode) while we wait for the process to exit. There are no error messages shown in either mode. I would've expected this to properly fail in MTP mode, but it does not, so I will need to do more investigation here to see if there's anything I can do about that.
