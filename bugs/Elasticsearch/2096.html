Title

MockTransportService throws AssertionError: still open connections

Description
This is a failure I have seen recently on the `zen2` branch (quite rarely, and unable to reproduce on `master`). For instance on commit   I ran this in a loop:

```
./gradlew :server:integTest -Dtests.class=org.elasticsearch.action.admin.indices.stats.IndicesStatsBlocksIT -Dtests.iters=200 -Dtests.failfast=true
```

On the 7th time round one of the tests failed with the following stack trace:

```
2> REPRODUCE WITH: ./gradlew :server:integTest -Dtests.seed=  -Dtests.class=org.elasticsearch.action.admin.indices.stats.IndicesStatsBlocksIT -Dtests.method="testIndicesStatsWithBlocks {seed=[ : ]}" -Dtests.security.manager=true -Dtests.locale=ig-NG -Dtests.timezone=Africa/Freetown -Dcompiler.java=11 -Druntime.java=11
FAILURE 1.40s | IndicesStatsBlocksIT.testIndicesStatsWithBlocks {seed=[ : ]}  :37253}` and not its real name.

[URL]

As far as I can tell there is machinery in place to prevent this from happening so I don't think it's specifically a Zen2 issue; in Zen2 we create a bunch of new connections when a node shuts down, and Zen1 does not do this, which might be why this doesn't reproduce so easily on `master`.

@tbrooks8 my main question to you is whether you think this is a problem in the networking infrastructure or a problem with how we're using it in Zen2.
Discussion
- Pinging @elastic/es-distributed
- @DaveCTurner I think this is a bug in `MockTransportService`. We're removing the channels from the `openConnections` map in close listeners. If we're not doing a blocking close when calling `super.doClose()`, then there's a chance those don't finish before we assert that the map is empty. I'll see if I can find a fix :)
- The blocking listener is not guaranteed to be called after the listener that removes the connection. So it might be a race in the order of listeners called. I don't know. But that is something to look at. A. possible fix (if that is the issue) is to do some type assert loop for a few seconds to wait for all connections to be removed.
