Title

Migration Generator ignores the "bigPrimaryKey" decorator

Description
### What steps will reproduce the problem?

Use Migrations Generator with the "bigPrimaryKey" decorator:
`yii migrate/create create_post_table --fields="id:bigPrimaryKey,title:string,body:text"`
### What is the expected result?

```
php
public function up()
{
    $this->createTable('post', [
        'id' => $this->bigPrimaryKey(),
... [Log Snipped] ...
    ]);
}
```
### What do you get instead?

The "bigPrimaryKey" decorator is ignored and an extra PK is added:

```
php
public function up()
{
    $this->createTable('post', [
        'id' => $this->primaryKey(),
... [Log Snipped] ...
    ]);
}
```
### Additional info

Could be solved by adding the "bigPrimaryKey()" to the condition in the addDefaultPrimaryKey() method of the MigrateController class:

```
php
protected function addDefaultPrimaryKey(&$fields)
{
    foreach ($fields as $field) {
        if ($field['decorators'] === 'primaryKey()' || $field['decorators'] === 'bigPrimaryKey()') {
... [Log Snipped] ...
    array_unshift($fields, ['property' => 'id', 'decorators' => 'primaryKey()']);
}
```
