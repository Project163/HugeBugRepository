Title

Misleading error message for multiple defined function

Description
Consider this code:

```
def f() -> int: return 1
def f() -> int: return 2
```

The type checker gives this type error:

```
t.py, line 2: Name 'f' already defined (overload variants 
must be next to each other)
```

This is misleading, since the functions are next to each other and this is not a case of overloading but redefinition.
Discussion
- What would the ideal error message be in this case? This is what Haskell does:

``` haskell
foo :: Int
foo = 1
foo = 2
```

```
$ ghc Foo.hs 
[1 of 1] Compiling Main             ( Foo.hs, Foo.o )

Foo.hs:3:1:
    Multiple declarations of ‘foo’
    Declared at: Foo.hs:2:1
                 Foo.hs:3:1
```
- This is what Elm does (a high standard to pursue):

```
Detected errors in 1 module.

-- DUPLICATE DEFINITION --------------------------------------------------------

Naming multiple top-level values `foo` makes things ambiguous. When you say
... [Log Snipped] ...
Find all the top-level values named `foo` and do some renaming. Make sure the
names are distinct!
```

TypeScript says

```
tmp.ts(4,10): error TS2393: Duplicate function implementation.
tmp.ts(7,10): error TS2393: Duplicate function implementation.
```
- ... [Middle Discussions Snipped for Brevity] ...
- It looks to me like this error message is never actually used for multiply defined functions (because those don't exist in user code) or for overloads being out of order (I get different bad errors when I try that), so all there is to this issue is changing the message. I'm not familiar with the project at all though, can anyone confirm?
- My theory is now that the part about overload in the error message is a relic from long ago when the `@overload` decorator did not exist.
