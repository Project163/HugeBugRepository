- Ok, I might have figured it out. I don't think it was actually a static initialization issue at all. While it's true that a GlyphList is conceptually read-only, nameToUnicode was actually being written to as a cache by toUnicode(code). So if one thread is copying a GlyphList via the copy constructor and another is writing to the cache during a toUnicode(code) call, then there is a concurrent access. 

 This problem can be solved without synchronization by introducing a separate, non-shared map for per-instance caching.
