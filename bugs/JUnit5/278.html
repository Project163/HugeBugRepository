Title

Invalid `ParallelExecutionConfiguration` results in silent fallback to Java 8 constructor for `ForkJoinPool`

Description
## Steps to reproduce

Using JUnit Jupiter 5.9.1 on Java 9+ with 

```properties
junit.jupiter.execution.parallel.enabled=true
junit.jupiter.execution.parallel.config.strategy=custom
junit.jupiter.execution.parallel.config.custom.class=com.example.BadConfig
```

```
java
package com.example;

import org.junit.platform.engine.ConfigurationParameters;
import org.junit.platform.engine.support.hierarchical.ParallelExecutionConfiguration;
... [Log Snipped] ...

}
```

Will cause the constructor of the `ForkJoinPool` to throw an `IllegalArgumentException`:

```java
        int p = parallelism;
        if (p   MAX_CAP || p > maximumPoolSize || keepAliveTime <= 0L)
            throw new IllegalArgumentException();
```            

That will in turn trigger the fallback for Java 8 because any an all exceptions are caught indiscriminately.

[URL]

## Deliverables

Either:
- [x] Validate and report invalid values in the `ParallelExecutionConfiguration`.

Or:
- Be more discerning when using the fall back to Java 8. Perhaps using the multi-release jar feature.
