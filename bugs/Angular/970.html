Title

Ivy: after initial build error, takes two builds to emit all files

Description
# 🐞 bug report

### Affected Package
 
  The issue is caused by package @angular/compiler-cli


### Is this a regression?

 
  I don't know


### Description

If an initial build has an error, fixing that error results in two rebuilds instead of one. The first rebuild will only emit the changed files, and the second rebuild will emit the remaining files.

This only happens if there are no emitted files on disk. Using `ngc` this isn't a problem, but it is a problem for the programmatic API consumers like `@ngtools/webpack` that Angular CLI uses.


## 🔬 Minimal Reproduction
- `npm install -g @angular/cli@next`
- `ng new ivy-rebuild-project && cd ivy-rebuild-project`
- update Angular Framework versions to `9.0.0-next.2`
- set `angularCompilerOptions.enableIvy` to `true` in `tsconfig.json` if it's not there
- make sure you don't have the `out-tsc` directory, if you do then delete it
- introduce an AOT error by replacing `selector: 'app-root',` with `selector: (() => 'app-root')(),` in `src/app/app.component.ts`
- run `yarn ngc -p tsconfig.app.json -w`
- wait for the build error message
- remove the AOT error and save the file
- see two incremental builds triggered

Discussion
- I suspect this has something to do with the way we track incremental state after we encounter an error. I will look into it!
- In [URL] I am seeing a more severe version of this problem. 

That issue contains a more complex app than the one I mentioned in this repository. To debug what was being emitted, I manually edited the `writeFile` method of the `compilerHost`.

When there's a build error, no files are emitted. Fixing the error emits some of the files, but not all:
```
# /D/sandbox/Angular-Communication/APM-Final v8/src/app/products/product-list.component.js.map
# /D/sandbox/Angular-Communication/APM-Final v8/src/app/products/product-list.component.js
# /D/sandbox/Angular-Communication/APM-Final v8/src/app/products/product-detail.component.js.map
# /D/sandbox/Angular-Communication/APM-Final v8/src/app/products/product-detail.component.js
# /D/sandbox/Angular-Communication/APM-Final v8/src/app/products/edit/product-edit.component.js.map
... [Log Snipped] ...
# /D/sandbox/Angular-Communication/APM-Final v8/src/app/products/product.module.js.map
# /D/sandbox/Angular-Communication/APM-Final v8/src/app/products/product.module.js
```

This was a partial emit where the entry point (`main.ts`) wasn't emitted. Even if it had been, a full dependency graph from the entry point down to the emitted files wasn't present. So this rebuild will still fail.

Saving the entry point will only cause it to be emitted, and no other files.
```
# /D/sandbox/Angular-Communication/APM-Final v8/src/main.js.map
# /D/sandbox/Angular-Communication/APM-Final v8/src/main.js
```
