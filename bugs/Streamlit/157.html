Title

st.metric without delta doesn't have correct margin

Description
### Summary

@willhuang1997 Another super small bug with st.metric I just realized: If `delta=None`, the margin at the bottom is a lot larger than if delta has a value (see screenshot below). I assume this is because the delta is still rendered, just empty. Super small thing and we can fix this for the next release!

[Image: image]
Discussion
- Is there a way to enforce the initial behavior? To make multiple metrics in two columns align, it would be very helpful if the height would be the same. Passing an empty string as delta would be a nice solution.
- Agreed with @BigBerny -- especially in the case where a metric (and thus its delta) can sometimes be missing/None, it'd be nice to keep its height consistent with its non-None siblings.
- Agree with @BigBerny and @dadamson. I'm using metrics where sometimes delta is defined, sometimes its not, and the resulting unevenness of how they get displayed is bummer. It would be nice if the ones without delta defined were the same size.
