Title

XMLPropertyListConfiguration cannot save arrays in the correct plist form

Description
groovy>  import  org.apache.commons.configuration.plist.* 
groovy> def config =  new  XMLPropertyListConfiguration() 
groovy> config.addProperty( "things" , [ 'chair' ,  'hat' ,  'door' ])  
groovy> config.save( System .out) 
 
  

 results in 

  
  <?xml version= "1.0" ?> 
 <!DOCTYPE plist SYSTEM  "file://localhost/System/Library/DTDs/PropertyList.dtd" > 
 <plist version= "1.0" > 
     <dict> 
         <key> things </key> 
         <string> chair </string> 

         <key> things </key> 
         <string> hat </string> 

         <key> things </key> 
         <string> door </string> 
     </dict> 
 </plist> 
 
  

 expecting 

  
  <?xml version= "1.0" ?> 
 <!DOCTYPE plist SYSTEM  "file://localhost/System/Library/DTDs/PropertyList.dtd" > 
 <plist version= "1.0" > 
     <dict> 
         <key> things </key> 
         <array> 
           <string> chair </string> 
           <string> hat </string> 
           <string> door </string> 
       </array> 
     </dict> 
 </plist>
Discussion
- Nested array structures are also flattened. 

 For example: 

  
 XMLPropertyListConfiguration config =  new  XMLPropertyListConfiguration();
config.addProperty( "array" ,  new   String [][]{{ "element1" ,  "element2" },{ "element3" ,  "element4" }});
 
  

 turns into: 

  
  <plist version= "1.0" > 
     <dict> 
         <key> array </key> 
         <string> element1 </string> 

         <key> array </key> 
         <string> element2 </string> 

         <key> array </key> 
         <string> element3 </string> 

         <key> array </key> 
         <string> element4 </string> 
     </dict> 
 </plist>
- The array structure is lost for two reasons: 
 
	 adding an array of values is done by adding the values separately 
	 in a hierarchical configuration, a new node is created for each value 
 

 That means that adding an array like  ['element1', 'element2']  results in the creation of two nodes for the same key. This is correct for an XMLConfiguration, it isn't for a plist. 

 A solution is to change how the nodes are added and ensure that paths are unique. I've implemented that for XMLPropertyListConfiguration and it works fine for the case reported. However it doesn't solve the issue with multidimensional arrays, this one is not specific to plist configuration.
