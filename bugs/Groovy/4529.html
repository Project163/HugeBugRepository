Title

logback-classic 1.3.0 and 1.4.0 breaks on Groovy

Description
Logging is not working when using logback version 1.3.0 or 1.4.0. The slf4j version is 2.0.0. This error is emitted. 

  
 SLF4J: Failed to load class "org.slf4j.impl.StaticLoggerBinder".
SLF4J: Defaulting to no-operation (NOP) logger implementation
SLF4J: See [URL] for further details.
 
  

 I searched the logback-user mailing lists and found a thread on Sep 1 and it had a link to this github issue for Spring ( [URL] which also has a similar issue. The link to the thread is here ( [URL]

 Test logback.xml 
  
 
 <configuration> 
   <appender name= "STDOUT"  class= "ch.qos.logback.core.ConsoleAppender" > 
     <encoder> 
       <pattern> %d{HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n </pattern> 
     </encoder> 
   </appender> 
   <root level= "debug" > 
     <appender-ref ref= "STDOUT" /> 
   </root> 
 </configuration> 
 
  

 Sample groovy test code. Changing version 1.3.0 to 1.2.11 will work. Also tested with 1.4.0 and it does not work. 

  
 
@Grab( 'org.slf4j:slf4j-api:2.0.0' )
@Grab( 'ch.qos.logback:logback-classic:1.3.0' )

 import  org.slf4j.*
 import  groovy.util.logging.*

@Slf4j(category= "hello" )
 class  Hello {
     def  useLogger() {
        log.info  'logging works' 
        log.debug  'debugging!!!' 
    }
}

 new  Hello().useLogger()
 
  

 To run: 
  
 groovy -Dlogback.configurationFile=/path/to/logback.xml /path/to/script.groovy
Discussion
- You need to delete the slf4j-api-1.7.32.jar in your Groovy install's lib directory since you can't mix slf4j 1.x and 2.x. That jar is in the standard distribution to support TestNG, so if you delete it, you will need to add some @Grab statements to any TestNG tests that you want to run in the Groovy console. 

 Alternatively, you can use a Maven/Gradle build for your project and ensure that old slf4j dependencies aren't included. 

 We should probably look at bumping the TestNG slf4j dependency to 2.0 since that seems to cause less problems even with 1.x slf dependencies explicitly added.
- Thank you. That seems be a good workaround my tests pass. However, as you pointed out upgrading the slf4j dependency to 2.0 would be a good permanent fix.
- This should be fixed in the next release. Thanks for spotting the issue.
