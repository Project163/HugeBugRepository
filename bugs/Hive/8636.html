Title

Fix the missing partitions judgement in drop_partitions_req

Description
When call  drop_partitions_req  by partition expressions, HMS determine if there are missing partitions by the fetched partitions number, which is not correct. 

 For example, assuming that we have a table  tbl  with partition names: 
  
 
dt=20231129/hr=10
dt=20231129/hr=11
 
  

 Then we try to drop partitions by sql: 
  
 
 alter   table  tbl  drop   partition  (dt= '20231129' ),  partition  (dt= '20231130' );
 
  

 It should throw `NoSuchObjectException` because filter  dt='20231130'  can not match any partitions.
