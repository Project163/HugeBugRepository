RCE via Backup/Restore APIs - Fix for all file extensions

Description
Before an 8.11.3 release,  [URL] needs to be backported, thus creating this as a blocker. 

 Here I am assuming that 8.x is vulnerable to the same attack, which should be investigated.
Discussion
- See attached patch. It is not a back port of   SOLR-16480   and is not for branch_8_11, but for main. 
It adds a file content MAGIC check for each location where we today call  ZkMaintenanceUtils.isFileForbiddenInConfigSets() . 

 I.e. it will peek inside each file and use "libmagic" style detection based on a config file in resources/magic folder. There exists thousands of matching rules for all kid of file formats (see  [URL] but I copied rules for ZIP, TAR and CLASS, and made a simple regex rule for shell scripts. 

 As an alternative to using the  [URL] library (which is not super well maintained) would be to write our own detection rules in Java, which would not be too hard for JAR and CLASS which are the most important.
- This is definitely not a requirement for the change, but we should get rid of the file type extension stuff that I added in. 

   

 Otherwise that looks like a really good patch, thanks for the awesome work here Jan!
