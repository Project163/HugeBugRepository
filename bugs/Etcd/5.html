Title

etcd uses almost 100% of CPU when user is not the data dir owner

Description
When running etcd 0.4.4 with a user that has no permission to data dir, etcd emits a few warnings and uses almost 100% of CPU. I'm running on Centos 6.5 x64 under VirtualBox.

Shouldn't those errors be treat like fatal errors? Can etcd run without a proper Standby server? Anycase, it must not leak like this.

etcd output:

```
[etcd] Jul  3 14:21:51.020 WARNING   | Failed to statfs: permission denied
[etcd] Jul  3 14:21:51.020 WARNING   | error load standby info file: open /tmp/localhost-etcd/standby_info: permission denied
[etcd] Jul  3 14:21:51.020 INFO      | localhost-etcd is starting a new cluster
[etcd] Jul  3 14:21:51.021 INFO      | etcd server [name localhost-etcd, listen on :4001, advertised url [URL]
[etcd] Jul  3 14:21:51.021 INFO      | peer server [name localhost-etcd, listen on :7001, advertised url [URL]
[etcd] Jul  3 14:21:51.021 INFO      | localhost-etcd starting in peer mode
```

Top output:

```
 PID USER      PR  NI  VIRT  RES  SHR S %CPU %MEM    TIME+  COMMAND
16072 vagrant   20   0 15708 4144 3180 S 99.3  0.9   0:20.05 etcd
15254 vagrant   20   0 15028 1276  984 R  0.3  0.3   0:03.22 top
```
Discussion
- Yup, ran into this issue as well.
- This issues has been resolved on master and in 0.5.0 alpha release.

etcd does not start if the data dir is not writable. You'll now get errors like these:

```
2014/10/27 16:17:16 etcdserver: cannot create snapshot directory: mkdir data/snap: permission denied
```
