Title

Exception triggered on filter when setting composite agg after key

Description
Requests using composite aggs with `afterKey` set to a missing field end up throwing an exception due to what looks like incorrect mapping.

And two entries inside "index-a" and no entries in "index-b":

```
POST index-a/_doc
{
  "bool" : true
}

... [Log Snipped] ...
POST index-b/_doc
{}
```
which results in the following mappings:

```
{
  "index-b" : {
    "mappings" : { }
  },
  "index-a" : {
... [Log Snipped] ...
  }
}
```

Run a composite agg against it:
```
POST index-*/_search
{
  "size" : 0,
  "_source" : false,
  "aggregations" : {
... [Log Snipped] ...
  }
}
```

This works and should return something like:

```
{
  "took" : 0,
  "timed_out" : false,
  "_shards" : {
    "total" : 2,
... [Log Snipped] ...
  }
}
```

Ask for the next composite agg page:
```
{
  "size" : 0,
  "_source" : false,
  "aggregations" : {
    "groupby" : {
... [Log Snipped] ...
  }
}
```

this results in:
```
{
  "took" : 0,
  "timed_out" : false,
  "_shards" : {
    "total" : 2,
... [Log Snipped] ...
  },
  ...
```

The full underlying exception is:

```

... [Log Snipped] ...
	at org.elasticsearch.common.util.concurrent.AbstractRunnable.run(AbstractRunnable.java:26)
	... 6 more"
```

This appears to have worked in 7.8 but occurs currently in master and 7.11.1
