Title

Connectivity issue from Syncthing V2 (2.0.0) to V1 (1.30.0)

Description
### What happened?

I run a star network with Syncthing. I updated one client to Syncthing version 2.0.0 and it could no longer connect to my server running version 1.30.0. It showed Disconnected is the server header and no such host for the local address and ports (tcp, quic on IPv4 and IPv6).

On my other devices running Syncthing 1.30.0 (Windows) or Syncthing   (Android) connection remain fine.

All of my tests are on a local subnet with IPv4 and IPv6 available.

In my system I use a nonstandard port address for my connections that I specify under Advanced/Addresses when editing the remote device panel on the client. And the remote device specifies "tcp://host:port, quic://host:port" for the listen addresses. I don't use any NAT Traversal, Global Discovery, Local Discovery or Relay options (all four options unchecked). I support remote connections with a public domain address, DDNS and port forwards and/or firewall rules.

I can make it work in two ways:

1) Enable Local Discovery on both the client (V2) and server machine, and setting the server address to dynamic in the client machine.

2) Enable Local Discovery on both the client (V2) and server machine, and setting the server address to "tcp://host:port, quic://host:port, tcp://public-host:port, quic://public-host:port".

Interestingly, with method (2), I still get a local area network connection from the client to the server.

Please advise and/or let me know what additional information you need.

Thanks.

### Syncthing version

V2.0.0 and V1.30.0

### Platform & operating system

Windows 10 client, Windows 11 server
