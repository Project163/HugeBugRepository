Title

[YSQL][PG15] Failed assertion running a complex SQL statement

Description
Jira Link: [Link: DB-8285]
### Description

This issue is not 100% repro, and so far I haven't been able to find a simpler repro, though I've tried. In particular, how can step #4 make any difference? Yet I haven't noticed it happen without step #4, and it happens with step #4 for me much of the time. Also, there is some chance it happens only/more frequently on an M1MBP.

I originally discovered it when running `ysql_dump`, but at the moment there are other issues preventing people from just running that tool. This repro worked for me even on the trunk build.

Steps to repro:
1. Sync to latest pg15 (there have been fixes recently) & build
2. `bin/yb-ctl wipe_restart --tserver_flags="ysql_pg_conf_csv=checkpoint_timeout=1d"`
   * (The flag works around another bug.)
3. `bin/ysqlsh   d1.objid JOIN pg_class c2 ON c2.oid = d2.refobjid AND c2.relkind IN ('m','v') WHERE d1.classid = 'pg_class'::regclass UNION SELECT w.objid, d3.refobjid, c3.relkind FROM w JOIN pg_rewrite r3 ON r3.ev_class = w.refobjid JOIN pg_depend d3 ON d3.classid = 'pg_rewrite'::regclass AND d3.objid = r3.oid AND d3.refobjid <> w.refobjid JOIN pg_class c3 ON c3.oid = d3.refobjid AND c3.relkind IN ('m','v') ) SELECT 'pg_class'::regclass::oid AS classid, objid, refobjid FROM w WHERE refrelkind = 'm';
```

Result:
```
server closed the connection unexpectedly
	This probably means the server terminated abnormally
	before or while processing the request.
The connection to the server was lost. Attempting reset: Succeeded.
```

On Mac, the postgres log shows a [Link: regular stack trace]. On a Linux dev server the stack trace is strange-looking, but that's another issue.

The failed assertion looks like this:
```
TRAP: FailedAssertion("ItemPointerIsValid(&scan->xs_heaptid)", File: "../../../../../../../src/postgres/src/backend/access/index/indexam.c", Line: 604, PID: 9034)
```
