Title

[BUG] VFS issue. Google Cloud can not create new (empty directory) on mount

Description
### What is the problem you are having with rclone?
Google Cloud can not create new (empty directory) on mount
This problem likely extends to other backends that don't treat folders as objects as well.
NCW mentioned this was likely a bug in the VFS layer

#### What is your rclone version (output from `rclone version`)
rclone v1.49.4-003-gb5ea6af6-v1.49-fixes-beta
- os/arch: windows/amd64
- go version: go1.12.10

But the problem has been observed all the way back to 1.48 I believe.

#### Which OS you are using and how many bits (eg Windows 7, 64 bit)
Win10-64
Linux replication not tested yet, but assumed to also be affected.

####  Which cloud storage system are you using? (eg Google Drive)
GCP / Google Cloud bucket

#### The command you were trying to run (eg `rclone copy /tmp remote:tmp`)
Right click - create new folder. Input name => "The file or folder does not exist"

Discussion
- I see what is causing the problem...

When you do right click and "make new folder" windows actually makes the folder called "New Folder".  When you type in a name for it (eg "New Name"), then windows renames that folder to "New Name".

It is some part of this directory rename process which is causing the empty folder to drop out of the directory cache on a bucket based remote.

This is perfectly reproducable on Linux using mount (instead of cmount) which indicates that it is a problem in the VFS layer

```
$ ls /mnt/tmp/
file2.txt  file3.txt  file4.txt  one.txt  ONE.txt  potato.txt
$ mkdir /mnt/tmp/"New Folder"
$ ls /mnt/tmp/
 file2.txt   file4.txt     one.txt   potato.txt
... [Log Snipped] ...
file2.txt  file3.txt  file4.txt  one.txt  ONE.txt  potato.txt
$
```

I think this is the exact problem - that we are invalidating the directory cache from the root

```
2019/10/07 17:09:25 DEBUG : /: Rename: oldName="New Folder", newName="New Name", newDir=/
2019/10/07 17:09:25 DEBUG : New Folder: Updating dir with New Name  
2019/10/07 17:09:25 DEBUG : : invalidating directory cache  <<<<<< problem
2019/10/07 17:09:25 DEBUG : New Folder: forgetting directory cache
```

I've had a go at fixing this here - can you have a go?
