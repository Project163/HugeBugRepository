Title

Inconsistent `null` value handling in Html::renderTagAttributes()

Description
In general, value handling for `data` attributes in BaseHtml::renderTagAttributes() is consistent with non-`data` attributes. For example, these both would result in the same HTML being returned:

```
php
Html::renderTagAttributes([
    'data-foo' => true,
    'data-bar' => false,
    'data-hello' => 'world',
... [Log Snipped] ...
]);
// => data-foo data-hello="world" data-a='{"b":"c"}'
```

The only value that’s *not* handled consistently between those two syntaxes is `null`. Non-`data` attributes set to `null` will be omitted completely, per this condition:

[URL]

However that `$value !== null` condition is not included for `data` array attribute values:

[URL]

As such, these two calls result in different things:

```
php
Html::renderTagAttributes([
    'data-baz' => null,
]);
// => (empty)
... [Log Snipped] ...
]);
// => data-baz=""
```

### What steps will reproduce the problem?

1. Call BaseHtml::renderTagAttributes(), passing a `data` attribute set to an array, with a nested `null` value.

### What is the expected result?

The attribute should be omitted from the rendered HTML.

### What do you get instead?

The attribute is included, set to an empty string.
