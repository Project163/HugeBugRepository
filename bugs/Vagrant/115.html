Title

File provisioner slightly broken in 1.9.8

Description
Please note that the Vagrant issue tracker is reserved for bug reports and
enhancements. For general usage questions, please use the Vagrant mailing list:
[URL] Thank you!

### Vagrant version
1.9.8

### Host operating system
Windows 10

### Guest operating system
Centos 7.3

### Vagrantfile
```ruby
      machine.vm.provision "file", source: "keys/public", destination: "~/.ssh/authorized_keys"
 ```

### Expected behavior
File provisioner should copy the file from source on host to ~/.ssh/ where ~ is /home/vagrant.
This worked fine in 1.9.7.

### Actual behavior
The files get copied into /home/vagrant/~/.ssh where ~ is a directory.

### Steps to reproduce
1. "vagrant up" with the line above

### References
I see in the changelog and git history that the file provisioner was changed in 1.9.8 to remove expansion of pathnames, which why I assume this issue is occuring. Not sure if the git change is a regression or a bug fix and expansion is never supposed to work.
