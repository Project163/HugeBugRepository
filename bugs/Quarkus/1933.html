Title

Quarkus 3.1 rest client uses wrong Messagewriter

Description
### Describe the bug

We use [URL] for sending cloud events with quarkus via a rest client. This worked fine for us until quarkus 3.1.
Using quarkus 3.1 a different Message writer is used than using quarkus 3.0.x.

Unfortunately it fails with this exception:

```
java.lang.IllegalArgumentException: mediaType, language, encoding all null
        at jakarta.ws.rs.core.Variant. (Variant.java:111)
        at jakarta.ws.rs.client.Entity. (Entity.java:189)
        at jakarta.ws.rs.client.Entity.entity(Entity.java:64)
        at org.jboss.resteasy.reactive.client.impl.RestClientRequestContext.setEntity(RestClientRequestContext.java:276)
... [Log Snipped] ...
        at org.apache.maven.surefire.booter.ForkedBooter.run(ForkedBooter.java:507)
        at org.apache.maven.surefire.booter.ForkedBooter.main(ForkedBooter.java:495)
```

With quarkus 3.1 io.cloudevents.http.restful.ws.impl.RestfulWSClientMessageWriter which fails.
With quarkus 3.0 io.cloudevents.http.restful.ws.impl.RestfulWSMessageWriter which works.

You can find them here [URL] We are using version 2.5.0 (The jakarta version is automatically created based on them)

Why is the other writer used in quarkus 3.1? Can this be changed somehow?

### Expected behavior

Either using the old Messagewriter or no exception.
