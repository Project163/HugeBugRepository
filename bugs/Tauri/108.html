Title

Sidecar binaries not cleaned up when using `prevent_exit` and `AppHandle::exit`

Description
### **Describe the bug**

Children processes are not cleaned up when using `Event::ExitRequested`'s `api.prevent_exit()`, and invoking `AppHandle::exit(0)`. 

### **To Reproduce**
Steps to reproduce the behavior:
1. With a main.rs that looks like this and also launches sidecar binaries:
```
rust
tauri::Builder::default()
    .system_tray(sys_tray)
    .on_system_tray_event(|app, event| {
      match event {
... [Log Snipped] ...
          }
    });
```
2. Run the tauri app.
3. Execute the "quit" system tray item.
4. See in the task administrator that the sidecar programs are still running.

### **Expected behavior**
That the sidecar programs are shutdown when the `api.exit(0);` is executed

### **Platform and Versions (required):**
```
Operating System - Windows, version 10.0.18363 X64
Webview2 -  

Node.js environment
  Node.js - 14.17.3
... [Log Snipped] ...
  framework - Vue.js (Vue CLI)
  bundler - Webpack
```
