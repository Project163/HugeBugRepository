Title

Changing baseHref in Angular along with the Upgrade Module to work with AngularJS router causes infinite redirect

Description

## Current behavior
If using the Angular router and the AngularJS router together with the Upgrade Module you can define routes that each router will handle and the other router will, since the route is not defined, go to its sink state and not populate the router-outlet or ng-view respectively. This works great except for if you want to host your app anywhere but root. As soon as you define a baseHref things will go haywire and you get in a (seemingly) infinite redirect between the two frameworks. _(For more information on the project set-up you can visit Victor Savkin's [Link: tutorial])_.


## Expected behavior
You should be able to define a baseHref and have the two routers still play nice with each other just like they do when hosted at root.


## Minimal reproduction of the problem with instructions
 

Detailed steps along with some things I've tried to fix the problem are on [Link: StackOverflow] but to summarize:

* Clone the [Link: repo] _(bare bones Angular-CLI project demonstrating the issue. I would have used plunker but SystemJS appears to rely on the ``` ``` tag which makes it so I can't demonstrate the problem)_
 * ```npm install```
 * ```ng serve```
 * Navigate to [Link]
 * View it working normally by clicking back and forth on any of the links.
 * Change the .angular-cli.json file like so adding a baseHref-
```
"defaults": {
"styleExt": "css",
"component": {
},
"build": {
  "baseHref": "/"
}
```
to
```
"defaults": {
"styleExt": "css",
"component": {
},
"build": {
  "baseHref": "/sub/"
}
```
 * See it break when clicking on any of the two AngularJS links (navigate from Angular to an AngularJS page)

- Thanks for the pull request! The logic on this is pretty sound but there is a problem with the commit as is. If pulled in as is you will still get the infinite redirect.

Until the url.href is set (like it is on ```url.href = next;```) ```url.protocol``` and ```url.host``` will not be set properly (":" and "" respectively). The logic for setting the baseHref most likely needs to be put in the ```$locationChangeStart``` **AFTER** the ```url.href = next;```.
