   PDFBOX-2936  : avoid orphan /CF dictionaries found in US govt "I-" files
- Here's what's happening: 
PreflightParser.initialParse() first calls the super method and then searches for objects that haven't been parsed. In this case, it is "6813 0 obj". That is a weird one: it identical to "6883 0 obj". "6883 0 obj" is not decrypted because it is part of the encryption dictionary "6884 0 obj". However "6813 0 obj" is not referenced anywhere. My change prevents such a dictionary to be decrypted. Your files are still not PDF/A, but you'll get a less annoying output.
