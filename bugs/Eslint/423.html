Title

Should no-extra-semi trigger for es6 class methods?

Description
###### Disclaimers:
1. I've only just started my ES6 journey (so this could be my misinterpretation of `class` semantics)
2. I'm using the [Link: babel-eslint] parser, if that matters (although the same behaviour seems to occur with the default parser)
###### Issue:

Given the class:

```
/*eslint semi: [2, "always"], no-extra-semi: 2*/

class Foo {
  constructor() {
    ...
... [Log Snipped] ...
  }         // <- note: no semicolon after closing brace
}
```

... no warnings are raised.  Should they be?

It would seem that semicolons are allowed, but optional, for ES6 class methods.

If so, I would have expected that either:
1. the `semi` rule would complain about the missing semicolons on the `constructor()` and `baz()` methods; **or**
2. the `no-extra-semi` rule would complain about the explicit semicolon after the `bar()` method?
Discussion
- Here's the relevant portion of the [Link: spec]:

[Image: screenshot 2015-06-19 09 52 21]

So semicolons are allowed, but [Link: per ESTree], they get dropped from the AST. I agree ESLint should catch that somehow, but I'm not sure as to the best way to address it. I'm happy to file an issue with ESTree if that's the best option, though it's probably more of a concern for the concrete syntax tree. Should we do something ourselves with the tokens instead?
- `MethodDefinition` seems to not have semicolon.
Semicolon seems to make an empty `ClassElement`. 
It resembles that a semicolon makes an `EmptyStatement`.

So I think it's better that the `no-extra-semi` rule warns the semicolon after the `bar()`.
