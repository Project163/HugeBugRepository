Title

Regression with expression templates and bitfields.

Description
## Description
The program below fails to compile (but did with version 1.9.6). The first `REQUIRE` compiles just fine, while the second does not:
```
c++
#include "catch.hpp"
void test() {
    struct Y { 
        uint32_t v : 1;
... [Log Snipped] ...
    REQUIRE(0 == y.v);
}
```

The problem is the following operator (passing bitfields by reference is not possible):
```c++
template 
template 
auto ExprLhs ::operator == ( RhsT&& rhs ) -> BinaryExpr  const {
    return BinaryExpr ( compareEqual( m_lhs, rhs ), m_lhs, "==", rhs ); 
}
```

Replacing it with the following version fixes the issue:
```c++
template 
template 
auto ExprLhs ::operator == ( RhsT const & rhs ) -> BinaryExpr  const {
    return BinaryExpr ( compareEqual( m_lhs, rhs ), m_lhs, "==", rhs );
}
````

I have not looked deeper into the code. Is there a reason to not explicitely use a const reference here?

### Extra information
* Catch version: v2.0.0-develop.4 and v1.10
* Compiler+version: clang/gcc

- I've just pushed a change so that it takes the RHS by const reference.

When I was rewriting it (from the original Catch 1.x version) I was trying to be const/ non-const agnostic (to avoid having to `const_cast` at the bottom). My reasoning was that it's easy to write a comparison operator overload and forget to make it const. The person writing the test may not even have any control over that. And it would be a difference in behaviour from doing the comparison without the expression decomposition - which I was trying to avoid.
Anyway, I ended up having to make the LHS a const ref anyway, and this issue has shown that my attempt to hold out on the RHS was misguided. So I'm letting go on this one.

The universal references where never about perfect forwarding - no values are being stored as we're only ever consulting the values while they are still on the stack.
- I think const references are the way to go. For "non-standard" comparison operators the user should put an extra pair of parenthesis around the comparison. Just my 2 cents.
