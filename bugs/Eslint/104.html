Title

Rule `no-warning-comments` duplicates errors

Description
Is it normal that `no-warning-comments` throws two identical errors now when comment is between lines of code?

``` js
a;
// TODO zzz 
b;

// warning  Unexpected todo comment       no-warning-comments
// warning  Unexpected todo comment       no-warning-comments
```
Discussion
- No, that's a bug. Most likely in the core where comments are processed. I wonder if Esprima is attaching comments to more than one node, in which case, we'd need to track which comments have already been seen so we don't fire another event.
