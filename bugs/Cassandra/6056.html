Discussion
- I don't think what we are trying to accomplish here is possible with current ant version. Right now, the ant JUnit task we are using provides two different attributes: 
 
	 test -> it has a required field called name, and which represents the FQDN of the test class. It has an optional methods parameter that can be used to define a list of methods to be run. We are using this attribute in the  testsome target . Name field does not support wildcards, and that is the reason the testsome target fails as described in the ticket. 
	 batchtest -> it receives a series of filters that are used to determine which test classes will be run, and doesn't accept any concept of methods. We are using this attribute in the  test target , you'll see that if you follow the macros definitions. Those filters support wildcards, and that is the reason the test target works as described in the ticket. 
 

 Full documentation of these two attributes can be found  here . 

 Now, as I understand this ticket, we would need to be able to filter by two different dimensions on the batchtest approach (the goal is to perform several test), class name AND methods. As we have just seen, this is not supported at this point as batchtest only supports class names. 

 Hence, in my opinion, the correct path forward would be: 
 
	  Create an enhancement report  for Ant. This should mention the need to modify the  batchtest logic  in order to support filter by method names. 
	 Work with Ant team members to have this implemented and released. 
	 Update the version Cassandra is using to have support for this. 
 

 The alternative of extending the  JUnitTask class  in our own project to add support to that seems hardly maintainable on the long run, and I would definitely discourage it.
