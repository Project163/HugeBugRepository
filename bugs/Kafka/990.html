Title

Broker fails to parse Null Metadata in OffsetCommit requests

Description
librdkafka sends a Null Metadata string (size -1) in its OffsetCommitRequests when there is no metadata, this unfortunately leads to an exception on the broker that expects a non-null string.

Discussion
- This is a regression caused by changing `KafkaApis` to use the Java protocol classes. Marking as a blocker since it breaks existing clients.
- This could happen for basically any string in the protocol. The java protocol implementation assumes that string was not nullable, while the old Scala messages allowed all strings to be nullable. This came up in   broker crash on receipt of produce request with empty client ID" class="issue-link" data-issue-key="KAFKA-3088"> KAFKA-3088   where we added NULLABLE_STRING and a default for the client id.  

 If this is considered a regression, we should consider holistically how we want to handle the remaining strings that are not nullable.
