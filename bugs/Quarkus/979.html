Title

Quarkus AWS S3AsyncClient doesn't apply default connectionMaxIdleTime set by AWS

Description
**Describe the bug**
[Link: There was a bug in AWS SDK2.0+ S3AsyncClient]that caused Netty 'stale' connections to be picked up and reaped by `IdleConnectionReaper` when multiple concurrent async calls were performed. SDK picked up 3 threads that were to be killed by the reaper one by one and it caused retry policy to fail (3 unsuccessful attempts) and fire with  

`software.amazon.awssdk.core.exception.SdkClientException: Unable to execute HTTP request: Server failed to send complete response: java.util.concurrent.CompletionException: software.amazon.awssdk.core.exception.SdkClientException: Unable to execute HTTP request: Server failed to send complete response`

The solution AWS team introduced was to decrease `connectionMaxIdleTime` to 5 sec, so AWS always peaked up fresh connections.



**Expected behavior**
Default AWS SDK parameters apply by default for AWS SDK clients

**Actual behavior**
Quarkus overrides default parameters for AWS SDK clients that causes AWS S3AsyncClient to fail again despite the fact that bug was fixed.

```
io.quarkus.amazon.common.runtime.NettyHttpClientConfig

    @ConfigItem(defaultValue = "60S")
    public Duration connectionMaxIdleTime;

```
