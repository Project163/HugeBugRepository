Title

[YSQL] ERROR: Wrong key entry type kNullHigh for bool column

Description
Jira Link: [Link: DB-11047]
### Description

Commit   introduces DecodeBoolColumn

```
cpp
  if (entry_type == kTrue) {
    if (kMatchedId) {
      row->SetDatum(index, 1);
    }
... [Log Snipped] ...
    return STATUS_FORMAT(Corruption, "Wrong key entry type $0 for bool column", entry_type);
  }
```

Notice there is no case for `kNullHigh`, so that case causes the error to be thrown:

```
ERROR:  Wrong key entry type kNullHigh for bool column
```

This is an issue with decoding a bool value stored in DocDB, particularly bools that are stored as kNullHigh.  The choice of kNullLow or kNullHigh depends on the schema: `NULLS LAST` uses kNullHigh.

Following is a survey of cases where the error is hit.  Run on master commit  , almalinux 8, fastdebug, gcc11.

```
sql
DROP TABLE IF EXISTS bools;
CREATE TABLE bools (b bool);
INSERT INTO bools VALUES (null);
CREATE INDEX NONCONCURRENTLY asc_nulls_last ON bools (b ASC NULLS LAST); -- = (b ASC)
... [Log Snipped] ...
/*+IndexOnlyScan(bools asc_nulls_last)*/ SELECT FROM bools;
/*+IndexOnlyScan(bools asc_nulls_last)*/ SELECT count(*) FROM bools;
```

YCQL does not appear to have the issue.  It is not surprising since the file holding the function is named `pg_key_decoder.cc`.

```
ycqlsh:k> CREATE TABLE bools (b boolean, i int PRIMARY KEY) WITH transactions = {'enabled': true};
ycqlsh:k> CREATE INDEX ON bools (i, b) WITH transactions = {'enabled': true};
ycqlsh:k> INSERT INTO bools (b, i) VALUES (null, 1);
ycqlsh:k> SELECT * FROM bools WHERE i = 1 ORDER BY b;

... [Log Snipped] ...
 Index Only Scan using k.bools_i_b_idx on k.bools
   Key Conditions: (i = 1)
```
