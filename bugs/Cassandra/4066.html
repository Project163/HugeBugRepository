Title

Drop column in results in corrupted table or tables state (reversible)

Discussion
- I'll fix this, but for info, this happens only when a 3.x version reads an older sstable, so a simple workaround to this is to avoid removing columns until you've run  upgradesstables  on the newly upgraded nodes. This is also likely why later attempts to alter worked properly.
- Attaching trivial patch below. The code was checking for dropped columns but was mistakenly using the full cell name rather than just the column name. I'm attaching only the 3.0 branch as it merges cleanly and given the fix, running tests on 3.3 and trunk is just a waste of electricity.
