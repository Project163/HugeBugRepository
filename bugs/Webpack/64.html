Title

Webpack 2.1.0-beta.7 doesn't rename imported symbols which appear before their import declaration

Description
In the following example, the call to imported `foo()` doesn't get renamed within `notExportedAsync()`. 

Given this module file:

```
export function foo() {
    return;
}
```

And this entry file:

```
import { foo } from './module';
// will transform to: 
// /* harmony import */ var __WEBPACK_IMPORTED_MODULE_2__module__ = __webpack_require__(50);

export async function exportedAsync() {
... [Log Snipped] ...
    foo(); // rename OK
}
```

This is the output:

```
/// ... Lots of Babel and Webpack code here
/// ....
/***/ function(module, exports, __webpack_require__) {

    /* harmony import */ var __WEBPACK_IMPORTED_MODULE_0_babel_runtime_regenerator__ = __webpack_require__(52);
... [Log Snipped] ...

/***/ },
```

webpack.config.js:

```
module.exports = {
    entry: './index',
    output: {
        path: 'build',
        filename: 'bundle.js'
... [Log Snipped] ...
    }
};
```
Discussion
- I cannot reproduce your issue... see testcase in b4a1b98.
- Found the problem - 
For some reason, Babel's compilation puts `import { foo } from './module';` after the declaration of `notExportedAsync`

Here is the output of Babel, before Webpack, notice `import { foo }` in the middle.
Webpack won't rename symbols occuring before their import.
Is it a proper behavior?

```
import _regeneratorRuntime from 'babel-runtime/regenerator';
import _asyncToGenerator from 'babel-runtime/helpers/asyncToGenerator';
// will rename foo() to __WEBPACK_IMPORTED_MODULE_2__module__["a"].bind()()

var notExportedAsync = function () {
... [Log Snipped] ...
    foo(); // rename OK
}
```
