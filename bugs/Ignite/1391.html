Discussion
- There are several issues in GridNearAtomicUpdateFuture: 
 
	 there is a race between onNodeLeft and onResult, it is possible that remap for failed keys and remap for GridNearAtomicUpdateResponse.remapKeys run concurrently, this can break internal invariants 
	 when do retry for 'invokeAll' operations results of previous successful updates are lost ('opRes' is reset in 'remap') 
	 if execute atomic put when tx lock is held (flag 'topLocked=true') it still can wait for topology future if does remap for GridNearAtomicUpdateResponse.remapKeys 
	 before trying to remap GridNearAtomicUpdateResponse.remapKeys need to wait for next topology version to avoid unnecessary retries
- moved all GridNearAtomicUpdateFuture state into separate class GridNearAtomicUpdateFuture.UpdateState 
	 added more tests for retry 
	 executed atomic-put, atomic-put-get benchmarks, no difference with master
- Alexey, please review (branch ignite-1124, patch is also attached).
- Changes look good to me.
