Title

Wrong number of fonts leads to OOM-Exception

Description
We got the following error report from Pinohans@JDArmy through security@
In FontBox of Apache PDFBox, a carefully crafted PDF 
file can trigger an OutOfMemory-Exception while loading the file. This 
issue affects Apache PDFBox version 1.8 to 3.0.0-alpha2. 

         Product: Apache PDFBox 

         Version: 1.8-3.0.0-alpha2

Discussion
- 1.8.x is not affected as it doesn't support TTF-collections.
- Commit 1895356 from lehmi@apache.org in branch 'pdfbox/branches/2.0' 
[  [URL] ] 

   PDFBOX-5333  : check number of fonts for invalid values
- Commit 1895357 from lehmi@apache.org in branch 'pdfbox/trunk' 
[  [URL] ] 

   PDFBOX-5333  : check number of fonts for invalid values
- The vulnerability can't be triggered by simply crafting a malicious pdf. PDFBox doesn't use the affected class to read any data from a pdf directly. It is used only when collecting information for the font cache using the local installed fonts. Saying that, one has to install a malicious font to the local file system and once PDFBox tries to create the font cache it will stumble upon that ttf-collection and immediately shutdown with an exception. There is no simple attack vector and even if there is a manually installed malicious ttf collection in place PDFBox will crash immediately.
