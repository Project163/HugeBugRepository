Title

Abort option for triggers incorrectly exits in a multi-threaded context

Description
I use `trigger.abort` to stop Vagrant from doing any further work with my machine once it's been started. The machine in question is a virtual image of a network router, so not a real server and there is nothing Vagrant can help with. (If there is a better way to achieve my goal I will also be happy to learn about it).
My solution works well when I spin up one single machine. But I get an error when I try to start two machines at once (or simply `vagrant up`).

### Vagrant version
```
$ vagrant --version
Vagrant 2.2.4
```

### Host operating system
Ubuntu 18.04
Probably more important than the host OS is the provider which is libvirt. I am not sure whether the root cause of the bug is Vagrant itself or the provider. I didn't try with another provider. 
```
$ virsh version 
Compiled against library: libvirt 4.6.0
Using library: libvirt 4.6.0
Using API: QEMU 4.6.0
Running hypervisor: QEMU 2.12.0
```

### Guest operating system
CentOS based

### Vagrantfile
My Vagrantfile includes the following Action based trigger:
```ruby
   config.trigger.after :"VagrantPlugins::ProviderLibvirt::Action::StartDomain", type: :action do |trigger|
     trigger.only_on = /pfe$/
     trigger.abort = true
   end
```

When I run `vagrant up vmx01pfe` all is good:
```
$ VAGRANT_EXPERIMENTAL="typed_triggers" vagrant up vmx01pfe
==> vagrant: You have requested to enabled the experimental flag with the following features:
==> vagrant:
==> vagrant: Features:  typed_triggers
==> vagrant:
... [Log Snipped] ...
==> vargant: Running trigger...
==> vargant: Vagrant has been configured to abort. Terminating now...
```

Return code is 1. 
All good here.
