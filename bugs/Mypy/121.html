Title

Crash in check_overlapping_op_methods() when other method is decorated

Description
Example:

```
python
from typing import *

def deco(f: Any) -> Any:
    return f
... [Log Snipped] ...
    def __gt__(self, other: C) -> bool:
        return True
```

This produces an internal error with a traceback ending in:

```
File "/Users/guido/src/mypy/mypy/checker.py", line 449, in visit_func_def
    self.check_func_item(defn, name=defn.name())
  File "/Users/guido/src/mypy/mypy/checker.py", line 505, in check_func_item
    self.check_func_def(defn, typ, name)
  File "/Users/guido/src/mypy/mypy/checker.py", line 545, in check_func_def
... [Log Snipped] ...
  File "/Users/guido/src/mypy/mypy/checker.py", line 716, in check_overlapping_op_methods
    assert False, 'Forward operator method type is not CallableType'
```
Discussion
- Removing the assert or adding `if isinstance(forward_type, AnyType): return` to the beginning of the function prevents the exception -- but is that the right fix?

Also, looks like this crash was previously prevented by the checks I removed for #1101.
- A somewhat clearer example:

```
python
from typing import *

def deco(f: Any) -> Any:
    return f
... [Log Snipped] ...
    def __radd__(self, other: C) -> C:
        return C()
```

This clarifies that the problem occurs when we're analyzing `__radd__`; we end up lookup up the forward operator `__add__` but because of the decorator its type is Any -- the analyzer can't even tell that it's a method. I'm going to fix this as I suggested -- inserting a check for Any and an early return at the top of check_overlapping_op_methods().
- The approach seems reasonable to me.
