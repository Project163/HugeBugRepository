Title

[bug] cargo tauri build -b deb --no-sign errors out with `A public key has been found, but no private key`

Description
### Describe the bug

If I want to create bundles without signing, a --no-sign option is provided. But if I run 
`cargo --locked --frozen auditable tauri build -b deb --no-sign`

I get the following misleading message:
```
Warn --no-sign flag detected: Signing will be skipped.
...some build output, and at the end the build errors out with:
Error A public key has been found, but no private key. Make sure to set `TAURI_SIGNING_PRIVATE_KEY` environment variable.`
```
Even though I've requested to skip signing explicitly 

I'm using this in github actions to skip signing when building for AUR.

### Reproduction

Add a tauri signing public key to tauri.conf.json
Run cargo tauri build -b deb --no-sign

### Expected behavior

tauri cli does not error out with signing key missing when `--no-sign` is requested.
