Title

`$localize` is not found after `ng add` with cli v15.0.0-next.4 and ng v15.0.0-next.5

Description
### Command

add

### Is this a regression?

- [X] Yes, this behavior used to work in the previous version

### The previous version in which this bug was not present was

14.2.5

### Description

Angular v15.0.0-next.5 contains the fix from @alan-agius4 to properly add the `@angular/localize` polyfill in a CLI app now that the `polyfills.ts` file is gone. [URL]

The polyfill is added when running `ng add`, but it looks like using `$localize` still doesn't work.

```
Error: src/app/app.component.ts:9:11 - error TS2304: Cannot find name '$localize'.

9   title = $localize`i18n-next`;
```

### Minimal Reproduction

```
npx @angular/cli@15.0.0-next.4 new i18n-next --defaults
cd i18n-next
npm i
ng add @angular/localize@15.0.0-next.5 --skip-confirmation
```

then update `app.component.ts` with:
```ts
title = $localize`i18n-next`;
```

and run:
```
ng extract-i18n --output-path src/locale/
```

The same repro using the stable release of the CLI and fwk works out of the box.


### Exception or Error

```text
Error: src/app/app.component.ts:9:11 - error TS2304: Cannot find name '$localize'.

9   title = $localize`i18n-next`;
```

Discussion
- The problem here is that while we are adding `@angular/localize/init` to the polyfills this is not included as part of the TypeScript compilation which caused the global `$localize` type to not be added.

Therefore we'd need to add `"@angular/localize/init"` as a `type` in the TypeScript configurations. 

I am going to transfer this to the framework as this needs to be addressed by the `ng-add` schematic.
