Title

ConfigSlurper does not process property files with nested properties correctly

Description
I created the following Groovy test:
  
  import  java.io.IOException;

 public   class  PropertyParsingTest  extends  GroovyTestCase {
     public  void test()  throws  IOException{
        ConfigSlurper configSlurper =  new  ConfigSlurper()
        Properties props =  new  Properties()
        props.load(PropertyParsingTest. class. getResourceAsStream( "system.properties" ))
        ConfigObject newConfig = configSlurper.parse(props)
        props = newConfig.toProperties()

        assertEquals( " false " , props.get( "catalog.prov" ))
        assertEquals( "sa" , props.get( "catalog.prov.db.user" ))
    }
}
 
   
	 I created system.properties file and put it to into classpath:
  
 catalog.prov =  false 
catalog.prov.db.user = sa
 
   
 

 I got the following exception:

Discussion
- Graeme, I couldn't think of a universal solution for non-nested properties so have implemented a poor man's solution. It will handle the case above (which I regard as an edge case) but probably then fails if you attempted to merge etc. which I regard as an even rarer thing to want to do if you are trying to handle non-nested property lists. Never-the-less I am not 100% happy in that I didn't try to test out what happens in such cases and perhaps the error handling will be less than ideal.
- Let me know if you are happy with the proposed fix and I will merge into 1.5.6 - code freeze is a few days away.
