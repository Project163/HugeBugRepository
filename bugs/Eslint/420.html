Title

object-shorthand should have an exception for named functions [$15 awarded]

Description
In general, I want to enforce `object-shorthand` rule in all my code.

However, I also care about proper function names (`.name` property) and would like to have a [configurable] exception for cases when function name is explicitly set and is different from property name like in following case:

```
javascript
Object.create(proto, {
    toString: {
        writable: true,
        configurable: true,
... [Log Snipped] ...
    }
});
```

- I feel like we are talking in circles.

My point is that we should never warn when a property has a named function expression, as the shorthand version would not behave the same way. It doesn't matter if the name is the same as the property or not, this rule shouldn't warn for it.

If you want something that cares about function expression name being the same or different than the property, then that would be a different rule.
