Title

Error for importing ModuleWithProviders into @Component.imports could be improved

Description
### Which @angular/* package(s) are the source of the bug?

compiler

### Is this a regression?

No

### Description

Using `RouterModule.forRoot([...])` in standalone's component imports results in errors that are not immediately actionable. This is a pretty common scenario since people trying out "standalone" will try to move router's configuration _somewhere_ and many will try moving the `RouterModule.forRoot([...])` into `@Component.imports`., ex.:

```
typescript
@Component({
  selector: 'app-root',
  template: `
   ....
... [Log Snipped] ...
export class AppRoot {
}
```

Trying to do the above will result in the 2 following errors:

```
Error: src/main.ts:25:12 - error NG1010: 'imports' must be an array of components, directives, pipes, or NgModules
  Value is of type '[(not statically analyzable)]'.

25   imports: [RouterModule.forRoot([])],
              ~~~~~~~~~~~~~~~~~~~~~~~~~~
... [Log Snipped] ...
25   imports: [RouterModule.forRoot([])],
               ~~~~~~~~~~~~~~~~~~~~~~~~
``` 

Things that might be confusing to the users:
* `(not statically analyzable)` might be cryptic and not-actionable
* the second error actually gets us a bit more info since it indicates that `ModuleWithProviders` don't "fit" into the `@Component.imports` "slot"

Not sure if we can improve things on the compiler side, especially for the first error.

```true
v14
```
