Title

[YSQL] Possible incorrect classification as a single row modification

Description
Jira Link: [Link: DB-548]
### Description

The ModifyTableIsSingleRowWrite function  
[URL]
may mistake a multi-row modify table statement for a single row.
The criteria that subplan under the ModifyTable node is a Result node is insufficient. The Result node may be used as a wrapper around a larger subplan to evaluate a one-time condition, and either execute or skip the subplan depending on the result.
Example:
```
yugabyte=# explain insert into test select i, 0, 0 from generate_series(1, 100) i where (((0.14198202)::MONEY)>=((0.14222479)::MONEY));
                                      QUERY PLAN                                      
--------------------------------------------------------------------------------------
 Insert on test  (cost=0.01..10.01 rows=1000 width=12)
   ->  Result  (cost=0.01..10.01 rows=1000 width=12)
         One-Time Filter: ((0.14198202)::money >= (0.14222479)::money)
         ->  Function Scan on generate_series i  (cost=0.01..10.01 rows=1000 width=4)
(4 rows)
```
Also function has poorly, even dangerously written comments, implying the limitation are temporary and may be relaxed in future. They may encourage developers to implement unsafe algorithms violating ACID properties.
