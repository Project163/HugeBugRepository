Title

Apps using `typedRoutes` and no dynamic routes leads to no type errors on href of Link components

Description
### Verify canary release

- [X] I verified that the issue exists in the latest Next.js canary release


### Which area(s) of Next.js are affected? (leave empty if unsure)

App directory (appDir: true), TypeScript

### Link to the code that reproduces this issue

[URL]

### To Reproduce

1. Install packages

   ```bash
   npm ci
   ```

1. Attempt to run a build to see the expected type error

   ```bash
   npm run build
   ```

   The type error:

   ```
./src/app/page.tsx:14:19
   Type error: "/foo/bar" is not an existing route. If it is intentional, please type it explicitly with `as Route`.

     12 |            
     13 |             {/* No defined page file, type error */}
... [Log Snipped] ...
     16 |            
     17 |             {/* Has a defined page file (/[slug]/page.tsx), no type error */}
```

   This type error is _expected_ as `/foo/bar` does not have an applicable page file.

1. Rename `/[slug]` to `/slug` to make it into a static path

   ```bash
   mv src/app/\[slug\] src/app/slug
   ```

1. Rerun the build command

   ```bash
   npm run build
   ```

   No error will occur this time, even though the links to both `/foo/bar` and `/baz` should both produce errors. This is likely because `DynamicRoutes` is typed as a string when there are no dynamic paths:

   ```ts
   type DynamicRoutes  = string;
   ```

   This means that any string put into the `href` of the `Link` component will be valid.

### Describe the Bug

When an app using the `typedRoutes` config has no dynamic paths in the app, any value put into `href` prop of the `Link` component becomes valid, leading to no type errors.
