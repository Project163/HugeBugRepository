Title

[YSQL] PG crash observed when object locking and auto analyze are both enabled

Description
Scenario

When a series of back to back ANALYZE are run by the auto analyze service, postgres backends all over the cluster which attempt to rebuild the relcache init file after this DDL may crash. The crashes stop once the series of DDL stop and the crash is timing dependent. **The issue only happens when object locking is enabled**

On master, the issue is alleviated through some internal retries. **On 2025.2, the crash is visible to the user as failed conn, hence marking as a blocker**.

Discussion
- Saw this in one of the stress case rerun as well: New gflags added were

- enable_object_locking_for_table_locks
- ysql_yb_ddl_transaction_block_enabled

Run link in JIRA
- The issue seems to be that during the initial relcache build (YbLoadRelations), we accept invalidation messages which delete the relcache entry for some (critical) catalog tables like oid 2662 `pg_class_oid_index`. This can happen because an ANALYZE running in the background can update reltuples counts for such catalog tables and invalidate those tuples in the catalog/relcache. Such inval msgs are applied any time a lock is applied, including those on catalog tables like pg class taken during relcache build.

PG seems to consider this possibility at [URL] but some of our code modifications do not.
