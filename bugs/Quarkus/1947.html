Title

Kubernetes + Smallrye Health Extensions: Knative deployment fails due to presence of startupProbe

Description
### Describe the bug

The Smallrye health extension adds a startupProbe to the generated target/kubernetes/knative.yml when I set my deployment-target to knative.  The Knative admission controller however does not allow the startupProbe element, resulting in a failed deployment.   

### Expected behavior

I expect the knative.yml to not contain the unsupported startupProbe element.

### Actual behavior

_No response_

### How to Reproduce?

Steps to reproduce:

1. quarkus create app knative-bug -x kubernetes -x smallrye-health
2. mvn package -Dquarkus.kubernetes.deployment-target=knative
3. verify that a startupProbe is present in the generated target/knative.yml
4. deploy to Knative, and observe the following error:

```
[ERROR] Caused by: io.fabric8.kubernetes.client.KubernetesClientException: Failure executing: POST at: [URL] Message: admission webhook "validation.webhook.serving.knative.dev" denied the request: validation failed: must not set the field(s): spec.template.spec.containers[0].startupProbe. Received status: Status(apiVersion=v1, code=400, details=null, kind=Status, message=admission webhook "validation.webhook.serving.knative.dev" denied the request: validation failed: must not set the field(s): spec.template.spec.containers[0].startupProbe, metadata=ListMeta(_continue=null, remainingItemCount=null, resourceVersion=null, selfLink=null, additionalProperties={}), reason=BadRequest, status=Failure, additionalProperties={}).
```
