Title

Middleware rewrite doesn't work with i18n

Description
### What version of Next.js are you using?

12.0.2

### What version of Node.js are you using?

14.17.6

### What browser are you using?

Chrome

### What operating system are you using?

macOS

### How are you deploying your application?

next start

### Describe the Bug

Next 12 Middleware rewrite doesn't handle locale correctly with [Link: i18n routing] enabled. For example, if we rewrite `/test` to `/fr/test` using middleware, it will still show `/test` with the default locale because the locale info is lost during rewrite.

So you can't do this:
```ts
// in middleware
req.nextUrl.locale = detectedLocale;
return NextResponse.rewrite(req.nextUrl);
```

or equivalently this:
```ts
// in middleware
req.nextUrl.pathname = `/${detectedLocale}${req.nextUrl.pathname}`
return NextResponse.rewrite(req.nextUrl);
```

### Expected Behavior

The locale info should be parsed when rewriting from middleware.
