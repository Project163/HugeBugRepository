Discussion
- Some testcases in XplainStatisticsTest did not take into account that the order in which testcases could be run may differ. Specifically, phoneME runs testcases in the opposite order of other jvms we are running tests on. 

 XplainStatisticsTest now ran ok on phoneME and jvm1.6.

- Those changes look fine to me. Thanks for tracking this down, Ole!
- DERBY-4188  _1.diff.txt committed to trunk as revision 823066.
- Performing clean-up in a finally block may hide the root cause in case of a test failure. In this particular case, if enableXplainStyle() fails before xpltest.sysxplain_resultsets has been created, the finally clause will fail with "table not found" and we won't see the original exception. I think it would be better to drop the table outside the finally clause, even if it means that subsequent test cases may fail, since then at least the root cause is reported. Alternatively, and perhaps better, we could call JDBC.dropSchema(dmd, "XPLTEST") from tearDown().
