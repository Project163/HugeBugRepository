Title

quarkus.log.console.enable disable file log handlers

Description
## Describe the bug
with the following application.properties
```
quarkus.package.type=uber-jar
quarkus.log.level=INFO
quarkus.log.console.enable=false
quarkus.log.console.level=INFO

... [Log Snipped] ...

quarkus.log.category."".handlers=CONSOLE_MIRROR
```
when running the uber jar (it's working file with quarkus:dev) 
 the file quarkus.log is created but is empty.

This was working prior quarkus 1.13

## To Reproduce

[URL]

Steps to reproduce the behavior:
1.  mvn install
2. java -jar target/code-with-quarkus-1.0.0-SNAPSHOT-runner.jar
 -> application does not log to quarkus.log
3. java -Dquarkus.log.console.enable=true -jar target/code-with-quarkus-1.0.0-SNAPSHOT-runner.jar
 -> application log to quarkus.log
Discussion
- This works:
```
#...
quarkus.log.file.enable=true
quarkus.log.file.path=quarkus.log
```
If you really want a named handler you need to use a proper category, like `org.acme` in your case:
```
#...
quarkus.log.handler.file."CONSOLE_MIRROR".enable=true
quarkus.log.handler.file."CONSOLE_MIRROR".path=quarkus.log

quarkus.log.category."org.acme".handlers=CONSOLE_MIRROR
```

[URL] does not mention `""` to be a valid category.
So I'm inclined to close this. WDYT @dmlloyd?
- In my understanding it was the way to declare the root category. Also It was working before quarkus 1.13.4 ( I upgraded directly from 1.12) so I assume something has changed recently.

My use case is that I need multiple log files attached to the root category with different format.
