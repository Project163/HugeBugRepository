Title

[YSQL] "Duplicate table" error caused by relfilenode OID collision

Description
Jira Link: [Link: DB-15818]
### Description

Encountered the "Duplicate table" error while working on [URL]

The reason for this error is a relfilenode oid collusion when there is a table rewrite operation.
There was a fix in the past that avoids relfilenode collusion by checking that there is no other pg_class oid collusion when assigning a new relfilenode id.
However, That's not enough and we might allocate an already allocated relfilenode to a new relation in case the relation has been rewritten (thus relfilenode id != pg_class oid). Thus, the assumption that relfilenode and pg_class oids are the same in YB is not correct.

The semantics of separating logical vs physical oids should be the same between postgres and YB. relfilenode represents the identifier to the physical storage. In pg, relfilenode is the actual file on disk while in YB, relfilenode is the pointer to the DocDB table (our physical storage).
So I think we still need the equivalent of `DoesRelFileExist`  in YB where we check for the uniqueness of DocDB table UUID.

Example to reproduce the issue:
```
CREATE DATABASE db1;
\c db1
CREATE TABLE base_t(k int, c1 INT, c2 INT);  
CREATE INDEX base_t_c1_idx ON base_t(c1);
CREATE INDEX base_t_c2_idx ON base_t(c2);
... [Log Snipped] ...
CREATE INDEX base_t_faulty_c2_idx ON base_t_faulty(c2);
ERROR:  Duplicate table
```
