Title

Kakfa extension logs too much

Description
### Describe the bug

Starting a Quarkus app which uses reactive-messaging with kafka logs the following by default:

```
2021-09-15 15:04:06,927 INFO  [io.sma.rea.mes.kafka] (Quarkus Main Thread) SRMSG18248: Key serializer omitted, using String as default
2021-09-15 15:04:06,927 INFO  [io.sma.rea.mes.kafka] (Quarkus Main Thread) SRMSG18237: Setting client.id for Kafka producer to kafka-producer-warehouse
2021-09-15 15:04:06,941 INFO  [org.apa.kaf.cli.pro.ProducerConfig] (Quarkus Main Thread) ProducerConfig values: 
	acks = 1
	batch.size = 16384
... [Log Snipped] ...
2021-09-15 15:16:34,594 INFO  [org.apa.kaf.com.met.Metrics] (smallrye-kafka-producer-thread-1) Closing reporter org.apache.kafka.common.metrics.JmxReporter
2021-09-15 15:16:34,594 INFO  [org.apa.kaf.com.met.Metrics] (smallrye-kafka-producer-thread-1) Metrics reporters closed
```

I'm pretty sure most of this is garbage. Can we remove those logs?

- Is this your area @cescoffier or perhaps @ozangunalp ?
- We were discussing about suppressing some of those standard logs. 
As a start you can change the level of those loggers 
```
quarkus.log.category."org.apache.kafka.clients".level=WARN
quarkus.log.category."org.apache.kafka.common.utils".level=WARN
quarkus.log.category."org.apache.kafka.common.metrics".level=WARN
```

I'm not sure we want to set the level to WARN, they may be some additional interesting messages. 
However, some of them are useless to regular users, and I'm +1 to hide them.  We can start with setting the log level to WARN and see if we get feedback. 

The two first messages are on our side, so we can just change the level.
