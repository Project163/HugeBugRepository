Title

Count for issues found vs issues that can be fixed is wacky

Description
Running `psalm --show-info=false` on CakePHP [Link: 4.x] generates the following result.

```
------------------------------
No errors found!
------------------------------
34 other issues found.
------------------------------
... [Log Snipped] ...
to see what it can fix.
------------------------------
```

So it claims to be able to fix 2 more issues than it has found :slightly_smiling_face:.

Running `psalm --alter --issues=MissingParamType --dry-run` as suggested results in output:

```
/path/to/cake-apps/cakephp/src/Core/ObjectRegistry.php:
--- /path/to/cakephp/src/Core/ObjectRegistry.php
+++ /path/to/cakephp/src/Core/ObjectRegistry.php
@@ -328,8 +328,10 @@
      * be attached into the event manager
... [Log Snipped] ...
No errors found!
------------------------------
```

I would not expect any change to be done here. `@param object $object` should not be modified since `@psalm-param TObject $object` already exists.

Also what about the other 30+ errors it claimed to have found / can fix?
Discussion
- I understand now that `psalm --alter --issues=MissingParamType --dry-run` only does one change since that's the only issue pertaining to `MissingParamType`.

So the suggested alter command should either list all the fixable issues in `--issues` option or if it's meant to be just an example then the wording should be improved and a link to the [Link: docs] should be provided where user can find list of all fixable issues.
- It's supposed to show all fixable issue types: [URL]
