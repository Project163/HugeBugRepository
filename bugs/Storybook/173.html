Title

[Bug]: `yarn storybook:ui` not running with Node 23 due to code patterns in `code/.storybook/main.ts`

Description
### Describe the bug

It seems that Node 23.9 / 23.10 fail to resolve two things in the main file.

It cannot resolve `../frameworks/react-vite...`, which can be replaced with `@storybook/react-vite/node`.

It also doesn't know what to do with `__dirname` which would need rewriting with `path.dirname(fileURLToPath(import.meta.url))`.

I'm fixing something else right now so no PR yet, anyone wanting to fix this can take it up.

### 🐞 **Bug Summary**
On Node.js **23.9 / 23.10**, Storybook fails to:
1. **Resolve `../frameworks/react-vite/...`**
   - ✅ Fix: Use `@storybook/react-vite/node` instead.
   - This is likely due to stricter ESM resolution in newer Node versions.

2. **Handle `__dirname`**
   - Node 23+ doesn't support `__dirname` in ESM (ECMAScript modules).
   - ✅ Fix: Replace with:
     ```js
     import { fileURLToPath } from 'url';
     import { dirname } from 'path';

     const __filename = fileURLToPath(import.meta.url);
     const __dirname = dirname(__filename);
     ```

---

### ⚠️ **Reproduction Steps (Reconfirmed)**
```bash
nvm use 23
yarn task compile
cd code
yarn storybook:ui
```

Fails due to module resolution + `__dirname`.

---

### 🧰 **Environment**
- **OS**: Linux (Arch, kernel 6.13)
- **Node**: 23.9 / 23.10
- **Yarn**: 4.6.0
- **Storybook**: In a monorepo (exact version unknown)

---

### ✅ **Fix Plan**
1. Replace all paths like:
   ```js
   import something from '../frameworks/react-vite/...';
   ```
   with:
   ```js
   import something from '@storybook/react-vite/node';
   ```

2. Replace any use of `__dirname` or `__filename` with:
   ```js
   import { fileURLToPath } from 'url';
   import { dirname } from 'path';

   const __filename = fileURLToPath(import.meta.url);
   const __dirname = dirname(__filename);
   ```

---

### 💬 Additional Notes
- This issue stems from **Node 23’s stricter ESM rules**, which is why it wasn’t happening on older Node versions.
- You might want to add a `.cjs` fallback or define `"type": "module"` smartly in sub-packages if you’re mixing CJS and ESM.
