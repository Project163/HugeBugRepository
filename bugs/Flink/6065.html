Discussion
- The direct reason for this problem is currently on stopping the StreamTask, the mailbox would be first preClose to forbid adding new mails, then it would drain all the pending mails. However, in this case for the AsyncWaitOperator to produce the last piece of the async task result, it seems to use a recursive way to output the pending completed records: namely for each mail it outputs one record, if there are new records, it would submit more mails, which conflict with the action of preClose before.  

 Perhaps after we finish reverting the process of stop-with-savepoint to first endInput and emit all the completed elements, and then taking a savepoint and terminate, the issue would be solved?
