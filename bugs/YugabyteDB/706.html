Title

[DocDB] race condition on min_pinned_op_index_, which can cause later operations with lower index evicted from LogCache before being flushed to disk

Description
Jira Link: [Link: DB-3355]
### Description

Slack thread: [URL]

There's the race on `min_pinned_op_index_` between `LogCallback` and `PrepareAppendOperations`

Considering the following sequence of log cache operations:
```
insert(1.1)
insert(1.2)
flush(1.1) -> min_pinned_op_index_ = 2
insert(2.1) -> min_pinned_op_index_ = 1
flush(1.2) -> min_pinned_op_index_ = 3
```
2.1 can be evicted before being flushed, which is not expected.
Discussion
- Fix:
if we update min_pinned_op_index_ in PrepareAppendOperations to a lower value, increment num_batches_overwrite_min_pinned_op_index_. When calling LogCallback, update min_pinned_op_index_ only when num_batches_overwrite_min_pinned_op_index_ == 0.
