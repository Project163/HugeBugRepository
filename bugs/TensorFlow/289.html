**Describe the current behavior**
`Dataset.shuffle()` returns results in the same order across invocations and across runs.

**Describe the expected behavior**
Previously, `Dataset.shuffle()` would return randomized results.

Provide a reproducible test case that is the bare minimum necessary to generate the problem.

(TF 2.0)
```python
import tensorflow as tf
ds = tf.data.Dataset.from_tensor_slices(list(range(10)))
print([x.numpy() for x in ds])
for i in range(10):
    print([x.numpy() for x in ds.shuffle(10)])

Discussion
- @jsimsa This does look problematic. I recall some changes, but maybe those went further than we wanted?
- This is working as intended. In TF 2.0, the shuffling order is determined by a resource (created for each `shuffle` transformation) whose initial state is derived from the graph-level random seed.

To retain the TF 1.X behavior, one can do:

```
ds = tf.data.Dataset.from_tensor_slices(list(range(10)))
print([x.numpy() for x in ds])
ds = ds.shuffle(10)
for i in range(10):
  print([x.numpy() for x in ds])
```

This will reuse the state that is used to determine the shuffle order across epochs (resulting in reshuffling between epochs).

Or, you can change set the seed used for creating the resource that controls the shuffle order (or use `tf.random.set_seed()`):

```
ds = tf.data.Dataset.from_tensor_slices(list(range(10)))
print([x.numpy() for x in ds])
for i in range(10):
  print([x.numpy() for x in ds.shuffle(10, seed=i)])
```
- @jsimsa, thanks for the quick reply!  Is it expected that random seed is kept the same across process invocations though?
- I was wrong. This was not working as intended. I have tracked down the issue and have a pending fix for this, that will be cherry picked into the 2.0 release. After the fix, your original program works the same between TF 1.X and TF 2.0. Thank you for reporting the issue.
