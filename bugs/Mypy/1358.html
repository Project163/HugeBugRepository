Title

Ignore doesn't work when two errors share a line

Description
```
python
from typing import Any

from array_api_compat import get_namespace
import numpy as np
... [Log Snipped] ...
        retval[target_index] = source_values
    return xp.reshape(retval, s)
```
Produces an error without a line number for a line on which the error should be ignored!
Discussion
- Simplified reproducer:
```python
from typing import Any
import numpy.typing as npt

m: npt.NDArray[Any]
index: tuple[int, ...]
m[*index, :]
```
which outputs
```none
main.py: error: Argument 2 to   has incompatible type "slice[Any, Any, Any]"; expected "ndarray[Any, dtype[integer[Any]]] | ndarray[Any, dtype[bool]]"  [arg-type]
main.py:6: error: Argument 1 to   has incompatible type "*tuple[int, ...]"; expected "ndarray[Any, dtype[integer[Any]]] | ndarray[Any, dtype[bool]]"  [arg-type]
```
- Reproducer without numpy:
```python
class Foo:
    def __getitem__(self, key: tuple[str, ...]) -> None: ...

m: Foo
index: tuple[int, ...]
m[*index, :]
```
outputs
```none
main.py: error: Argument 2 to   has incompatible type "slice[Any, Any, Any]"; expected "str"  [arg-type]
main.py:6: error: Argument 1 to   has incompatible type "*tuple[int, ...]"; expected "str"  [arg-type]
```

- Because slice expressions don't contain information in the raw ast before Python 3.9, fixing this while mypy still supports 3.8 is a bit complicated. Fortunately, mypy will be dropping support for 3.8 in the near future. Once that happens, I have a patch ready.

In the meantime, `slice(None)` can be used in place of `:` as a workaround.
