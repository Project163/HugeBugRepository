Title

Init context creates multiple instances of global variable

Description
I've run into a nasty issue (k6 V0.23.1) which can demonstrated by using 3 js files. The main test file (test.js) refers to two other files: engine.js and common.js. engine.js also refers to common.js.

The problem in brief is that common.js has a global variable, but there are actually two instances of it: One created and accessible from test.js and one created and accessible from engine.js. I have added these 3 code files (and a support file to create UUIDs) that are as simple as possible for demonstration purposes.

The code of common.js is

```
import { uuidV4 } from "./uuid-v4.js";

var globalId;

export function initMetric(metricName) {
... [Log Snipped] ...
    console.log("globalId: " + globalId);
}
```
Now, the globalId is not unique. It's one if listMetrics is called from test.js and another if called from engine.js. Actual output:

INFO[0000] globalId: edd33b60-c51e-4e6a-bef3-20654b09d469
INFO[0000] globalId: 489d0e75-5bde-4a07-9d84-b96186c14df3
