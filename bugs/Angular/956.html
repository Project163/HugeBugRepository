Description

If this is your first time contributing to Angular, you can find some general instructions in [CONTRIBUTING.md][1] and also instructions related to angular.io (or aio for short) specifically in [aio/README.md][2].

Basically, the problem we have here is that we assumed `window.sessionStorage` will always be available. But when cookies are disabled, trying to even access `window.sessionStorage` throws an error.

A possible fix could be this:
Change aio's [ScrollService][3] to check whether `window.sessionStorage` is accessible and if not use a no-op stub. In code, this could look something like this (off the top of my head):

```
ts
class ScrollService {
  private storage: Storage;

  constructor(...) {
... [Log Snipped] ...
  ...
}
``` 

Then, inside `ScrollService`, replace all occurrences of `window.sessionStorage` with `this.storage`.
Finally, we need some tests to ensure this works as expected and there will be no regressions. (I can help with that, when the time comes.)
