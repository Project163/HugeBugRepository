Discussion
- @sheenaqotj  please assign to someone on C-core team to investigate. The test is also flaky on linux, so this shouldn't be hard to debug.

Manual repro on linux:
`bazel --bazelrc=tools/remote_build/manual.bazelrc test --config=opt //test/core/end2end:h2_http_proxy_nosec_test@disappearing_server@poller=epoll1 --runs_per_test=250`
- Currently, test cases under this issue has top flake rates of 5%, 5.26%, 5.56%, 10.53%, 16.67% on master. Escalate to P1.

Statistically, any PR on master has at least 36.63% of chance failing due to this flake.
- I was finally able to give this time. I believe I know what is happening here.

This test makes sure that in-flight requests are completed before the server shuts down.
1) Client sends a request.
2) Before the request is completed, the server starts shutting down.
3) The request is completed.
4) The server shuts down.

After this,
5) The server is recreated.
6) Client sends a second request.
7) Before the request is completed, the server starts shutting down.
8) The request is completed.
9) The server shuts down.

In the failure mode, what happens is, before the client detects the server shutdown, it starts the second request which fails because the server has already shutdown. 

This problem worsens when we are using proxies in the middle because it adds to the timing problem.
- This issue would also not occur if the C client correctly handled GOAWAY frames. If the client refused to start new requests on connections where a GOAWAY has been received, we would not have this issue.
