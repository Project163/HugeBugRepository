Title

Black crashes when multiple `# fmt: skip` are added in a multi-part if-clause.

Description
**Describe the bug**

Black crashes on the following valid python code:

```
python
class ClassWithALongName:
    Constant1 = 1
    Constant2 = 2
    Constant3 = 3
... [Log Snipped] ...
        return True
    return False
```

 

**To Reproduce**

Just run black on the given code.

 

The resulting error is:

```
error: cannot format temp.py: Cannot parse for target version Python 3.9: 15:5:     ): # fmt: skip

Oh no! 💥 💔 💥
1 file failed to reformat.
```

 

**Environment**

 

- Black's version: `main`
- OS and Python version: Ubuntu 24.04 LTS, Python3.9 (tested on others on playground)

**Additional context**

- Crash is also observed when the second skip is on the previous line (L15)
- Found it while looking into #4730. Don't have a solution **yet**.
Discussion
- I've identified the root cause: when the second `# fmt: skip` is processed, its `prev_sibling` (the node that should be ignored) includes the `STANDALONE_COMMENT` generated by the first `# fmt: skip`. Since `STANDALONE_COMMENT` nodes do not include trailing newlines (these are added at a later stage), the formatter produces the following output:

```
python
class ClassWithALongName:
    Constant1 = 1
    Constant2 = 2
    Constant3 = 3
... [Log Snipped] ...
        return True
    return False
```

A simple fix  would be to traverse the ignored nodes and insert trailing newlines for any STANDALONE_COMMENT nodes encountered:

```
diff
diff --git a/src/black/comments.py b/src/black/comments.py
index 8c88668..893a10b 100644
--- a/src/black/comments.py
+++ b/src/black/comments.py
... [Log Snipped] ...
             prefix = first.prefix
             if comment.value in FMT_OFF:
```

I'll look for a better approach. If anyone has suggestions or ideas, I'd be glad to hear them.
