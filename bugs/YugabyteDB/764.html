Title

[DocDB] Tablet-splitting - Inserts fail after splitting a tablet

Description
Jira Link: [Link: DB-3737]
### Description

1. Create an RF1 (I created 3 masters and 1 TS but it shouldn't matter). Also, set the value of `cleanup_split_tablets_interval_sec` gflag to 1, to speed up deletions of parent
2. Create a YCQL table with 1 tablet
3. Insert 10k rows
4. Issue the yb-admin split command to manually split the tablet into 2 tablets
5. Sleep for 5 secs
6. Insert a row in the table, it times out

To repro it with an existing unit-test, check `YbAdminRestoreDuringSplit.RestoreBeforeParentHidden`. Just comment out the `ASSERT_OK(cluster_->SetFlagOnTServers("TEST_skip_deleting_split_tablets", "true"));`
line. You can also comment out parts of the test that performs a restore subsequently although it does not matter, it fails much before that.

TEST_F(YbAdminRestoreDuringSplit, RestoreBeforeParentHidden) {

  SetRf1Flags();
