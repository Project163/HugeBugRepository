Title

Docstrings should not dipslay as magic strings in Python 3.8

Description
# Summary

In Python 3.8, function docstrings are being displayed a magic strings. This is incorret.

The correct behavior is exhibited in Python 3.6 which supresses displaying function docstrings using magic.

## Steps to reproduce

Run the following **in Python 3.8**:

```py
import streamlit as st

def f():
    """This is a docstring."""
    pass

f()
```

# Behavior

## Actual behavior

You will see "This is a docstring." displayed in the app.

[Image: image]

## Expected behavior

We should see no ouput, because the first string is a docstring.

**Note:** Streamlit performs the correct behavior in Python 3.6.

Discussion
- Bump - wondering if there was a resolution on how to deal with this. Though it really wouldn't make sense to use docstrings for functions that are displaying to screen.
- @tvst why was this closed with no reason given?
- Just in case someone stumbles across this problem like I did - the solution is to turn off magic as described in the [Link: docs]. 
Add
`[runner]
magicEnabled = false`
to your config. [Link: Config docs]

This issue was likely closed, since this behavior seems to be intended. See issue #533 .
