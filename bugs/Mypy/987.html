Title

Final variable is mutable when using structural subtyping

Description
**Bug Report**

Under structural subtyping with a variable narrowed to `Final`, it's possible to modify the var contents

**To Reproduce**
```
# poc.py
from dataclasses import dataclass
from typing import Protocol, Final

@dataclass
... [Log Snipped] ...

print(f(FinalY(17)))
```



**Expected Behavior**

Class with a variable `Final[T]` should not be a structural subtype of a protocol with variable `T`

**Your Environment**

- Mypy version used: 0.910
- Python version used: 3.9.6


_This bug was inspired by @erictraut's [Link: example of how to deal with other kind of issue]_
Discussion
- @JelleZijlstra This is unrelated to [URL]

Here is a minified example of the issue:
```
py
from typing import Protocol, Final

class MutY(Protocol):
    y: int
... [Log Snipped] ...
y: MutY = Y()
y.y = 1
```
[Link: playground]

An error is correctly shown when you attempt to subtype the protocol directly:
```
py
from typing import Protocol, Final


class MutY(Protocol):
... [Log Snipped] ...
y: MutY = Y()
y.y = 1
```
