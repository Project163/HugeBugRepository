Title

ACL fails when evaluating domain object as property of another domain object

Description
In this example my models are: Project, ProjectRole - ProjectRole has a ManyToOne Unidirectional relationship back to Project.

I'm rendering the controller from my view in a few places:
- When I render from a view that passes in a project instance straight from the $em; no problem.
- However, when I render from a view that passes in $project_role.project the ACL does not work
Discussion
- Can you check if this is linked to proxy classes or not.

When retrieving objects through Doctrine, if you didn't load & hydrate them explicitly, then you will be working with a proxy class. Check the class of `$project_role.project`, if it implements the Doctrine Proxy interface, then the identity of your object is not resolved correctly.

There is not good automated fix for this right now.

And if this is indeed the issue then it's the same as #2056, #2035 and #2048
- That indeed looks like related to #2056 & co.
This bug should really be fixed for 2.1 (maybe tag it as a 2.1 blocker...) as there are already many issues on GH about this.

Besides, now that Doctrine Common has a `ClassUtils`, the patch should be easier than what I previously did (and as a bonus, Doctrine proxies don't load the objects when we only retrieve an identifier now :)).
