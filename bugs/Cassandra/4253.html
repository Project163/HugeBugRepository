Title

Removing an element from map corrupts commitlog

Description
2.2.6 has no this bug. 
I've tried 3.0 alpha 1, 3.0 beta 1, 3.0 beta 2, 3.0.0, 3.0.6, 3.5, datastax-ddc 3.5.0 (from repo), and trunk (3.6) - all of them have this bug.  
I've found that the error is thrown since  , which is included in 3.0 beta 1 (but  not  in the alpha 1). 
Cassandra 3.0 alpha 1 does not throw the error, but forgets about the changes after shutting down. 

 Only after rm ./data/commitlog/* , Cassandra starts fine. 
By the way, map<int, boolean> works fine. 

 Steps to reproduce: 
  
 $ ant build
$ ./bin/cassandra
$ ./bin/cqlsh
 
  
  
  CREATE  KEYSPACE bugs
     WITH   replication  = { 'class' :  'SimpleStrategy' ,  'replication_factor' :  '1' }
     AND  durable_writes =  true ;

 CREATE   TABLE  bugs.bug1 (
    id  int ,
     m    map < int ,  tinyint   or   smallint >,  --  key  can be  any   type 
      PRIMARY   KEY  (id)
);

 INSERT   INTO  bugs.bug1 (id,  m )  VALUES  (1, {0: 4, 4: 3});

 UPDATE  bugs.bug1  SET   m [0]= NULL   WHERE  id=1;
 --  and / or   UPDATE  bugs.bug1  SET   m [1]= NULL   WHERE  id=1;
 
 SELECT  *  FROM  bugs.bug1;
 
  
  
  id | m
----+--------
  1 | {4: 3}

(1 rows)
 
  
  
 $ ./bin/nodetool stopdaemon
$ ./bin/cassandra
Discussion
- Cell.validate()  was wrongly trying to validate the value for tombstone cells. It was almost never a problem as tombstone cells uses an empty ByteBuffer as value which almost all types accepts (due to legacy), but  smallint  and  tinyint  being new types, they don't. 

 Patch is rather trivial and comes with some unit test for that  Cell.validate()  method (patch against 3.0 but merge cleanly to trunk and there is clearly no difference between the 2 here so didn't bother running CI twice):
