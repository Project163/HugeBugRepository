Title

Docker compose dev services fails on Docker v29

Description
### Describe the bug

When trying to run anything through the docker compose dev services when a docker daemon of at least v29 is installed, the dev service will fail with:

```
2025-11-26 11:49:50,516 ERROR [io.qua.dep.dev.IsolatedDevModeMain] (main) Failed to start quarkus: java.lang.RuntimeException: io.quarkus.builder.BuildException: Build failure: Build failed due to errors
	[error]: Build step io.quarkus.devservices.deployment.compose.ComposeDevServicesProcessor#config threw an exception: java.lang.NullPointerException: Cannot invoke "java.util.Map.isEmpty()" because the return value of "com.github.dockerjava.api.model.Network.getContainers()" is null
```

This still worked perfectly fine on Docker v28.5.2, and this only starts happening once you upgrade to v29.

### Expected behavior

The compose dev service should not crash on docker v29

### Actual behavior

The compose dev service crashes on docker v29

### How to Reproduce?

1. Install a docker daemon version of v29.0.0 or newer
2. Clone my reproducer: [URL]
3. Run `./gradlew test` or `./gradlew quarkusDev`

### Output of `uname -a` or `ver`

Tested on Ubuntu 24.04 and 25.10

### Output of `java -version`

21.0.9

### Quarkus version or git rev

3.29.4

### Build tool (ie. output of `mvnw --version` or `gradlew --version`)

Gradle 9.1.0

### Additional information

I'm aware of the issues that Quarkus 3.29.2 had around testcontainers and docker 29, this is very explicitly on Quarkus 3.29.4 where that previous issue is already fixed, so this is a separate issue from earlier reports of testcontainer failures.
