Discussion
- Why did we need to include the log4j JUL jar?  We already had jul-to-slf4j-2.0.7.jar to route JUL to slf4j, which then routes to log4j2. 

 There shouldn't have been any changes required to have Lucene's logs end up in solr.log because we already had JUL handling.
- With the log4j jul jar and the sysprop telling log4j to use it, lucene classes get added to the logging->level page.  Without them, those classes aren't in the level page.  I wonder if that means there's a bug in jul-to-slf4j.
