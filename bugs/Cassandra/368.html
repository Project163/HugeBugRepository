Discussion
- There is still plenty of window for this to happen, but this should narrow it down some.
- i don't think the window between when the bootstrapping machine chooses a machine to ask for a token, and when it actually does so (sub ms under any scenario i can think of) is large enough to add the extra check in getBalancedToken.  either way the main danger is that some node has already chosen the same token but we haven't heard about it yet over gossip. 

 it would be worth checking though in getBootstrapSource that if sorted node zero has a bootstrap target already (i.e.,  every  node already has one), then we should fail the bootstrap (and tell the user to specify an initialtoken manually, or wait for one of the current bootstraps to finish).
