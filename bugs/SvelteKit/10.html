Title

kit: page store does not update when navigating to the same page with a query parameter

Description
**Describe the bug**
When navigating to the same page with a query parameter (e.g. from `/` to `/?lang=jp`) the page store from `$app/stores` does not update. Navigating either by ` ` tag or by `goto()` has the same result.

**To Reproduce**
```bash
npm init svelte@next
# js-only and css
npm install
npm run dev
```
Replace `index.svelte` with the following:
```
svelte
 
	import { page } from '$app/stores';
	import { goto } from '$app/navigation';
 
... [Log Snipped] ...

 Anchor Tag 
```
Click either the button or the anchor tag to see a lack of update. Refresh the page to see the actual update.

**Expected behavior**
That the page store is updated without refreshing the page. e.g. Hello World to change to こんにちは.

**Information about your SvelteKit Installation:**
```
System:
    OS: Windows 10 10.0.19042
    CPU: (16) x64 AMD Ryzen 7 3700X 8-Core Processor
    Memory: 18.32 GB / 31.95 GB
  Binaries:
... [Log Snipped] ...
    @sveltejs/kit: next => 1.0.0-next.49
    svelte: ^3.29.0 => 3.35.0
```

**Severity**
You could use `rel=external` to force the page load, but that's janky and not necessarily appropriate for all use cases.
Discussion
- I think the problem is at [URL] and that we also need to be checking whether the query changed. I'm not sure why we're not using the `changed.*` values that we're computed above.
- Oh, there _is_ no `changed.path`. But adding ` || changed.query` to that `if` does seem to fix this in my brief manual tests, and it doesn't break any of our other automated tests.
- I was looking to add a new test for this, and I'm not sure why the tests in [URL] aren't already catching this.
- they're not testing client-side navigation, only full reloads
