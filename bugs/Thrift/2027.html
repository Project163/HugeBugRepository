Title

Scary and spammy "error processing request: EOF" logs from TSimpleServer

Description
After upgraded our code to 0.13.0, we noticed a lot of the logs in stderr: 

  
 
2019/10/22 22:04:52 error processing request: EOF
 
  

 I think they are generated by this line  [URL] which means EOF is an error returned by processRequests function. 

 In that function we actually treat some EOF errors as non-errors ( example ), so I think it's just that we missed some cases and didn't treat all harmless EOF errors as non-errors.
Discussion
- Also can someone provide more context as of why do we treat EOF errors as normal there?
- > Also can someone provide more context as of why do we treat EOF errors as normal there? 

 I imagine it's because there is nothing the user can do with it.  Technically, we could "return p.AcceptLoop()"  here  but what would the user do with it? After an EOF, there is nothing more to be read from the connection.
- Actually after  [URL] we still see a lot of EOF errors in the log, so this is not resolved yet.
- If the EOFs are harmless, I#d propose to contiunue as follows: 

 1) reopen the ticket 

 2) someone (you?) puts together a PR which removes them from being logged and comments the "why" at the relevant code lines 

 3) send the PR 

 Sounds like a plan?
