Title

function arguments should not be optimized away

Description
Function arguments should not be optimized away, as this comprimizes the function's length property.

 What steps will reproduce the problem? 

// ==ClosureCompiler==
// @compilation_level SIMPLE_OPTIMIZATIONS
// @output_file_name default.js
// ==/ClosureCompiler==
function foo (bar, baz) {
  return bar;
}
alert (foo.length);
function foo (bar, baz) {
  return bar;
}
alert (foo.length);

--------------------------------------

What is the expected output?

function foo(a,b){return a}alert(foo.length);

--------------------------------------

What do you see instead?

function foo(a){return a}alert(foo.length);

--------------------------------------

 What version of the product are you using? On what operating system? 

I'm using the product from the web page [URL]

I'm using Firefox 3.6.10 on Ubuntu 10.0.4

 Please provide any additional information below. 

The function's length property is essential to many techniques, such as currying functions.
Discussion
- This kind of reflection is generally not supported by the compiler as evident by its restrictions imposed on eval:  

[URL]

In the general case, referring to length on anything other than named function expression is not safe:

function f(a,b,c) {return f.length};
console.info( f() );
var g = f;
f = function(a) {};
console.info( g() );

For a named function expression the could replace the length with a constant even in simple mode (although it doesn't currently):

var f = function me(a,b,c){ return me.length() };

could then be transformed to (after unused variable removal):

var f = function() {return 3};
