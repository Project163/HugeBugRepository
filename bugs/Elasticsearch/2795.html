Title

Missing `bind_password` or `secure_bind_password` should cause node to fail

Description
When using an LDAP or Active Directory realm, one can set `bind_dn` and the relevant password so that operations against LDAP ( user search, group search etc.) are performed by this service account and not by the authenticated user. 
When one sets `bind_dn` but does not set `bind_password` or `secure_bind_password` , there is no way that the realm configuration will be functional since simple bind operations are not permitted without a password and the underlying LDAP library we use understandably throws an error.

We should fail to start the node, so that our behavior is similar to what we do for other realm misconfigurations.

All the relevant settings are defined in the `PoolingSessionFactorySettings` class. In the [Link: constructor of the `PoolingSessionFactory`] we read the settings value. We can decide to throw if `bindDn` is not null both both `LEGACY_BIND_PASSWORD` and `SECURE_BIND_PASSWORD` are null

Note: When dynamic realm configuration is in place, we can revisit the validation and which configuration fails the node, but this aims to make the behavior uniform across our realms.
