The problem is related to PgSQL bytea data type and I think we should fix it.
As far as I see, we can deal with the problem by introducing the additional boolean property `encodeSession` to `yii\web\DbSession` and encode/decode the payload when the property is set to true.
- It is one possible solution. Two observations here:
- We had this problem in Yii 1 and we changed the `data` column to `TEXT` type. That didn't work in Yii 2.
- Maybe you could check the database type and, if it is PostgreSQL, you would apply encode/decode. But it would be interesting to check which databases have that problem.

A `encodeSession`is probably a good solution, anyway. Just make a friendly explanation in the documentation.
- In this case i'd prefer configuration over convention.

I don't like the idea of autodetecting because it creates an unobvious behavior, breaks the encapsulation of a DB driver (`yii\web\DbSession` must be DBMS-agnostic and use only abstract interfaces) and breaks the BC.
