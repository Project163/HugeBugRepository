Title

Crash on bad raise (or something like that)

Description
### Steps to reproduce
In a file called `pylint_test.py` put
```
class BlargException(Exception):
    pass


def blarg():
... [Log Snipped] ...
    except BlargException:
        raise
```
Then run `pylint pylint_test.py`, and it blows up with a big stack trace.

I don't know exactly what triggers it, but every element there is apparently needed in some way.

For example, changing the `5` to something else (including `None`) still crashes, but a bare `return` with no return value does not.

For another example, changing the bare `raise` to `raise 5` does not crash (and raises the appropriate `raising-bad-type` pylint error).

### Current behavior
```
$ pylint pylint_test.py

```

### Expected behavior
Normal pylint output
