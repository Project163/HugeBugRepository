Title

SpawnNewInstance should not pass --command (-e) argument

Description
When alacritty is run with --command (-e) option, SpawnNewInstance is also passed this argument.

My specific use case was running "alacritty -e ranger", and I expected SpawnNewInstance to give me a terminal for the directory I am currently parsing. Instead, it launched a new alacritty instance with ranger running.
When I use ranger without invoking alacritty's --command option, it works as expected.

I don't know if there's some other use case benefiting from the current behavior.
