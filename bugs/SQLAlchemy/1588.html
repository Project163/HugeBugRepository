Title

[Bug] select() of a enum[] column with NULL entries in the array fails

Description
### Discussed in [URL]

 

 Originally posted by **ari-s** September  5, 2025 
When select()-ing a column / table with enum[] where an entry of the array is `NULL` sqlalchemy fails, from my understanding in the parsing of the return value. 
selecting a simple/non-array enum column with Null entries works though.
This is with a postgres-DB, unsure about other DBs
I'm posting this here because the issue-tracker tells me to, but it very much looks to me like a bug.

MWE (well, almost working, you need a postgres-server and a database in it)
This example uses introspection, but it fails in the same way with manually writing the objects.

```
python 
from sqlalchemy import text, Enum, Table, MetaData, select
from sqlalchemy.dialects.postgresql import ARRAY
from sqlalchemy.engine import create_engine

... [Log Snipped] ...

print(data)
```
 

patch:

```
diff
diff --git a/lib/sqlalchemy/dialects/postgresql/array.py b/lib/sqlalchemy/dialects/postgresql/array.py
index 96f6dc21a..7155921f5 100644
--- a/lib/sqlalchemy/dialects/postgresql/array.py
+++ b/lib/sqlalchemy/dialects/postgresql/array.py
... [Log Snipped] ...
```
