Title

aio: fix links to source when path contains symlinks

Description
When paths contain symlinks (e.g. `packages/upgrade/static/src/...` --> `packages/upgrade/src/static/...`), the links to source generated on the API docs use the "unnormalized" path, and lead to 404 on GitHub (which doesn't know about the symlinks). E.g. [UpgrradeModule][1].

The links are generated based on `doc.fileInfo.projectRelativePath` ([here][2]), which in turn comes from the dgeni-packages (either [here][3] or [there][4], I assume).

This could be solved by using [fs.realpath()][5] to get to the actual file path (without symlinks), but I am not sure if updating the existing `FileInfo` properties is appropriate or a new property needs to be added.

cc @petebacondarwin

Discussion
- So if this is only for API docs then it is the responsibility of `typescript` dgeni-package, since we do not use `readFilesProcessor` for acquiring TypeScript files - the TS compiler does that for us.

Except for generating links to stuff on github, I think that the OS ensures that the symlinks provide us with the correct content when we ask for it. It is a shame that github is not clever enough to do rewrites for us to match the the OS.

I guess the safest thing (to prevent unexpected BCs) would be to add an extra property to the `FileInfo` class (something like `realFilePath` or similar) which we can use for the github links.
