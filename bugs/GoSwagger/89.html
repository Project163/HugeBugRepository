Title

Responses should support a description

Description
## Problem statement

The `Responses:` of a `swagger:route` should have support to add a description (which is required by the Swagger specification).

Having a comment on the response type adds a description in the `definitions` but not on the `responses`.

## Swagger specification

See [URL]

## Steps to reproduce

1. Declare a `swagger:route` with `Responses:`
2. No description can be set (just a named response)
3. The `description` property is missing on the `responses` object in the generated JSON
Discussion
- I was looking at adding this (which would fit right here: [URL] but I changed something that made my responses outputs looks like:

```
          "200": {
            "$ref": "#/responses/pet"
```

and I believe they were previously outputting the schema as a reference - which I mocked up below: 

```
          "200": {
            "schema": {

            }
          },
```

Whatever the change was, description is no longer required by the parser at [URL] .  In fact, when including a description, I get a warning that the field is ignored.
- I also wanted to point out that the reference is url encoded, so spaces turn into `%20`.  I was thinking about splitting the value portion of the line based on the first space, so any text after the first space would become the description.

I am not sure what I changed in my comment or build command that stopped outputting schema, but I don't think I understand the problem well enough to code a solution.
