Title

vagrant up hangs mounting folders - OSX Host, Win7 Guest, ssh from cygwin installed on guest

Description
Starting from a modern.ie Win7/IE10 box, installed and configured cygwin sshd, created a base box, but vagrant up stalls:

```
DEBUG ssh: stdout: Windows PowerShell 
Copyright (C) 2009 Microsoft Corporation. All rights reserved.

DEBUG ssh: Sending SSH keep-alive...
... [Log Snipped] ...
DEBUG ssh: Sending SSH keep-alive...
DEBUG ssh: Sending SSH keep-alive...
```

In the actual VM, the network share shows as properly connected.

It does _not_ hang if I don't put this in the Vagrantfile:

```
config.vm.guest = :windows
```

But it does pop this error:

```

- Same here.

I started with the MSEdgeOnWin10 Vagrant Box availabe from [URL] This box comes with the OpenSSH server from [URL] So it's possible to start this box with the following settings:

```
ruby
Vagrant.configure(2) do |config|
  config.vm.box = "Windows10"
  config.vm.guest = :windows
  config.vm.synced_folder ".", "/vagrant", disabled: true
... [Log Snipped] ...
  end
end
```

Here the guest type "windows" is combined with communicator type "ssh". If the Vbox shared folder mounting is disabled then the box starts flawlessly and `vagrant ssh` can be used to access the OpenSSH server / Cygwin shell within Windows.

Enabling Vagrants synced folder support brings up this SSH keep-alive issue. Here the culprit is in [Link: `plugins/guests/windows/cap/mount_shared_folder.rb`] where a PowerShell script is executed despite of communicator "ssh".

So in `mount_shared_folder()` the winrm-related stuff could be embedded in an conditional block which checks the communicator first, e.g.

```
ruby
def self.mount_shared_folder(machine, name, guestpath, vm_provider_unc_base)
  if machine.config.vm.communicator == :winrm
    name = name.gsub(/[\/\/]/,'_').sub(/^_/, '')
    path = File.expand_path("../../scripts/mount_volume.ps1", __FILE__)
... [Log Snipped] ...
    end
  end
```

In the else block the ssh-related stuff (running in the Cygwin shell) could be implemented similar to the PowerShell script [Link: `plugins/synced_folders/smb/scripts/mount_share.ps1`]:
- Mapping the VBox synced folder to a new Windows drive via `NET USE \* \\\\vboxsvr\\{#guestpath} {#ssh password} /USER:{#ssh user} /PERSISTENT:YES`
- Extracting the letter of the mapped drive from the output
- Creating a symlink via `cmd /c mklink /d {#guestpath} {# mapped drive}`

Doing this manually after via `vagrant ssh`:

```

==> default: password for you. If you're prompted for a password, please enter

IEUser@ 's password:
... [Log Snipped] ...
