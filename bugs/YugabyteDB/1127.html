Title

[YSQL] Wrong query result with JSONB column and index

Description
Jira Link: [Link: DB-10335]
### Description

My coworker (JB) discovered this Yugabyte YSQL bug (yugabyte-2.20.1.3for linux-x86_64) and was able to come out the minimal test case (shown below) to demonstrate it:

"The IndexScan hint is not really part of the bug itself, but is needed for the test case to get the optimizer to use the index without the partial index filter in the original scenario.  The JSONB column is required to cause the bug.  Normal columns in the index/query do not seem to trigger the issue" - JB

*****  test case  starts  ******
```
sql
drop table IF EXISTS t1;
create table t1 (
c1 bigint,
c2 jsonb,
... [Log Snipped] ...
(c2->>'c4')) hash
);
```
Table rows:
```sql
select * from t1;
 c1 |         c2         
----+--------------------
  2 | {"c3": 2, "c4": 2}
  1 | {"c3": 1, "c4": 1}
(2 rows)

```
Fails by returning rows:
```
sql
/*+IndexScan(t1 t1_idx)*/
--explain
select * from t1
where (c2->>'c3') = '4';
... [Log Snipped] ...
  1 | {"c3": 1, "c4": 1}
(2 rows)
```
Works correctly:

```
sql
/*+IndexScan(t1 t1_idx)*/
--explain
select * from t1
where (c2->>'c3') = '4'
... [Log Snipped] ...
----+----
(0 rows)
```
**** test case ends******
