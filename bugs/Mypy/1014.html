Title

Mypy uses pip for --install-types but does not list pip in requirements

Description
**Bug Report**

 

On Linux distributions packages such as mypy may be built using PEP517 methods by now. Packagers use a project's list of requirements to figure out what is required during build, test and runtime.
The same is true for minimal venvs in which only the specific set of packages are installed that are required to run a specific thing (e.g. mypy).
Mypy requires pip for `mypy --install-types` but does not list pip in its requirements. This leads to virtual environments that can not plainly list mypy as dependency and run `mypy --install-types`. The same is the case for users of given Linux distributions, that install mypy via their package manager (and do not install pip directly or via some other transitive dependency).

**To Reproduce**

1. On Arch Linux install mypy, but not pip (e.g. on a fresh system): `pacman -S mypy`
2. In a project that e.g. uses `aiofiles`, run `mypy --install-types -p my_project`

The same behavior can be gotten by creating a minimal project using e.g. pdm and adding only packages that do not require pip themselves.
When adding mypy there and doing a `pdm run mypy --install-types -p my_project` the same issue as above occurs.

**Expected Behavior**

 

Pip is a requirement of mypy and therefore already available when running `mypy --install-types`.

**Actual Behavior**

 

```
mypy --install-types -p repod
repod/repo/management/outputpackage.py:7: error: Library stubs not installed for "aiofiles" (or incompatible with Python 3.10)  [import]

```
