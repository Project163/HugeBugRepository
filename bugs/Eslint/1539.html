Title

Bug: [new config system] globs are ignoring dot files

Description
### Environment

Node version: v16.14.0
npm version: v8.3.1
Local ESLint version: v8.23.0 (Currently used)
Global ESLint version: Not found
Operating System: win32 10.0.19044

### What parser are you using?

Default (Espree)

### What did you do?

```js
// eslint.config.js

module.exports = [];
```

```js
// .foo.js
```

```
npx eslint *.js -f tap
```

### What did you expect to happen?

Per the [Link: RFC], this should include ` .foo.js`?


In that case, I would expect this output:

```
TAP version 13
1..2
ok 1 - D:\tmp\tmp\.foo.js
ok 2 - D:\tmp\tmp\eslint.config.js
```

### What actually happened?

The `.foo.js` file was not linted:

```
TAP version 13
1..1
ok 1 - D:\tmp\tmp\eslint.config.js
```

Discussion
- Confirmed, this is a bug. We should be picking up dot files by default now.
- Because this example has a glob without quotes, that means the shell is expanding it and is therefore not including dot files. I don't think there's anything we can do about that.

However, I also see that quoting the glob pattern does not pick up dot files. That is a bug per the RFC:

```
npx eslint "*.js" -f tap
```

This may end up being a case where we should mirror the shell expansion to avoid confusion?
- ... [Middle Discussions Snipped for Brevity] ...
- In the 2022-09-08 TSC meeting, we discussed this and came to the conclusion that users likely expect glob patterns to exclude dot files by default because that's how eslintrc and shell expansions behave. We're intentionally deviating from the RFC so that glob patterns ignore dot files.

---

Speaking for myself now, if differences arise between eslintrc, flat config, and shells, I think it makes sense to match eslintrc unless there's a case to be made that that shell expansions set a better precedent for that particular scenario going forward.
- Now that we have rewritten the search functionality, we are actually finding dot files by default. As it is now, it will end up being more difficult to mimic the eslintrc functionality than it will be to ensure the originally intended functionality works. Given that, I think the best path forward now is to include dot files in the glob patterns by default.
