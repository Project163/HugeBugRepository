Title

Panic on range query with unlimited upper when using scorch.

Description
A panic will be occurred cause `index out of range` when doing range query with unlimited upper by using **scorch**.

There are some logic issue in `RangeIterator` method of `index/scorch/segment/zap/Dictionary` struct.  

[URL]

When a range query with unlimited upper invoked, the `end` parameter of this method will be an  empty string. Then the `endBytes` variable will becomes a byte slice without any element. 

```go
	// need to increment the end position to be inclusive
	endBytes := []byte(end)
	if endBytes[len(endBytes)-1] < 0xff {
		endBytes[len(endBytes)-1]++
	} else {
		endBytes = append(endBytes, 0xff)
	}
```

The above code will trying to **access element from empty slice**, so that an `index out of range` panic will be occurred.

This issue found by my colleague @heidawei .
We will submit a merge request soon to fix this problem.
Discussion
- And for fst.Iterator(start, end)，if we want to include max, we need set end is nil, not []byte(nil), so in this case, we need set endBytes = nil to replace the []byte(end) when end is empty string
