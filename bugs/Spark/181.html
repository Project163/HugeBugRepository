Title

Hive Dependencies being checked by MIMA

Description
It looks like code in companion objects is being invoked by the MIMA checker, as it uses Scala reflection to check all of the interfaces. As a result it's starting a Spark context and eventually out of memory errors. As a temporary fix all classes that contain "hive" or "Hive" are excluded from the check.
Discussion
- We could change the object to contain a lazy val instead of being a TestHiveContext itself.  That should fix the issues.
- I think this is fixed now that MIMA loads classes passing false to "initialize".
