Title

Speed regression since 19.10b0 on large collection

Description
I'm seeing a nasty speed regression on a 1500-line file containing a long list of objects: 

```
$ black --version
black, version 19.10b0
$ time black data-infra-common/qschema/registry/data_infra.py 
All done! ✨ 🍰 ✨
1 file left unchanged.
... [Log Snipped] ...
user    0m58.048s
sys     0m0.168s
```
Discussion
- Profiling shows a lot of time spent in the append_leaves function (https://github.com/psf/black/blob/master/src/black/__init__.py#L4583). The assertion on line 4597 looks like it could cause quadratic behavior, so maybe we should remove it. Removing that assertion speeds it back up to `real	0m18.696s`, which is better but still 10x worse than 19.10b0.
- I spent a bit more time on this today and I think it's mostly around the `append_leaves()` calls in the new string formatting code, since these basically end up copying over the whole line. I'm trying to optimize this by manipulating the line directly instead of using `append_leaves()`, but haven't been able to get it to work yet.
- #1592 helped enough that I was able to run master on our codebase in a somewhat reasonable time, so I no longer consider this a release blocker (#1583). I think there's still more opportunities for improvement around append_leaves() though, so leaving this open.
