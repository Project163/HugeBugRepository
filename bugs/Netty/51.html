Title

Performance regression in ByteBuf vs ChannelBuffer

Description
I saw a performance regression between my netty4 based redis client and my netty3 based redis client. Tracking it down, it appears to be in the implementation of SlicedByteBuf vs SlicedChannelBuffer.

For my benchmark test (decoding redis replies) I see that Netty4 is 1.5x slower than Netty3.

Tested with Alpha5 and Alpha6-SNAPSHOT from master.
