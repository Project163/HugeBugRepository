Title

Build: check-commit length check is off by 1 for single line commits

Description
**What did you do? Please include the actual source code causing the issue.**

``` sh
git commit -m 'Fix: (fixes #9012)'
npm run check-commit
```

**What did you expect to happen?**
`First line of commit message must not exceed 72 characters`

**What actually happened? Please include the actual, raw output from ESLint.**
no error

The commit message above is 73 characters long, so it should have failed the test.

For #3706 @platinumazure added the check in [URL] using `slice`. However, when there's no newline, `indexOf` returns `-1`, so `slice` returns a commit message without the ending ")" (of "(fixes #9012)".
