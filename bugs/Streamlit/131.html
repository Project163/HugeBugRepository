Title

st.expander cuts off sliders

Description
# Summary

Expander in sidebar cuts off sliders and potentially other stuff

# Steps to reproduce
Run the following code
```
import streamlit as st

sidebar_expander = st.sidebar.beta_expander("Bad sliders underneath!")
with sidebar_expander:
    st.slider("Bad layout slider 1", 0, 100, value=0)
    st.slider("Bad layout slider 2", 0, 100, value=(0,100))

st.sidebar.slider("Good layout slider")
```
## Expected behavior:

Sliders appear nicely under the expander

## Actual behavior:

Sliders ends are cut off under the expander (see picture)

[Image: image]


## Is this a regression?

No

# Debug info

- Streamlit version:  0.69.1
- Python version: 3.8.2
- Using PipEnv
- OS version: Windows 10
- Browser version: Firefox and Chrome, recent versions

# Additional information

May also happen in containers outside of sidebar? Have not checked it though..
Discussion
- A temporary workaround is to add columns, like

```
import streamlit as st

sidebar_expander = st.sidebar.beta_expander("Slim sliders underneath!")
with sidebar_expander:
   _, slider_col, _ = st.beta_columns([0.02, 0.96, 0.02])
... [Log Snipped] ...

st.sidebar.slider("Standard layout slider")
```
- Note; this is also broken outside of sliders, too -- see [URL]
- Hm, from staring at the images for 5 minutes, it feels as though sliders (and also button highlights in #2437 ) are actually exceeding the bounds of the div; it's been okay in the past since there's nothing on that side anyways, but now Expanders bound the excess, so it's a lot more noticeable.

[Image: image]

Two possible approaches:
1. Force sliders (and button outlines, etc) to stay within the parent container by eg adding some more margin to those elements
2. Allow elements to bleed outside expanders

Approach 2 is less work, if there indeed exists a CSS property that allows for it. Let's start looking there.
