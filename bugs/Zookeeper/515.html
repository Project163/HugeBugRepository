Title

investigate differences in client last zxid handling btw c and java clients

Description
In   ZOOKEEPER-1412   it was identified that the c and java clients handle updating the last zxid seen a bit differently.   ZOOKEEPER-1412   fixed a bug associated with this, however there are still some differences that should be investigated.
Discussion
- Modify c-client to match Java behavior. Only update lastZxid when receiving request response (ignore zxid from ping and watch notification)
- Here is my current understanding on how this part works. 

 The client receives 3 types of responses: ping, watch notification and request response.  

 Ping: we should ignore its zxid 

 Watch notification: when watch is triggered, it will be remove from the list of active watchers, so last zxid delivered as part of notification shouldn't affect how watches are being triggered on reconnect 

 request response: we should always update last zxid when receive this type of packet.
