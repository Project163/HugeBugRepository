Title

`polymorphic: true, null: false` should set `NOT NULL` in the db schema on both _type & _id columns, not just the _id column

Description
### Steps to reproduce
  1. generate a migration with a non-nullable polymorphic relation, e.g., `t.references :author, polymorphic: true,  null: false`
  2. inspect the database schema and notice that the _id column (e.g., `author_id`) is not nullable while the _type column (e.g. `author_type`) of the polymorphic relation is still nullable

### Expected behavior
  * the _type column should also be set to `NOT NULL` in the database when `polymorphic: true, null: false` is set on a relation in a migration, since both columns are needed to identify the relationship, and without which, the polymorphic relationship could be left in an inconsistent state (with an id, but not a type)

### Actual behavior
  * only the _id column of the polymorphic relationship is set to `NOT NULL`, while the _type column has no such constraint

### System configuration
**Rails version**: 5.1.1
**Ruby version**: 2.4.1
