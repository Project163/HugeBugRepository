Title

[YSQL][randgen] Bitmap Scan plan causes "unexpected postmaster exit" fatal error

Description
Jira Link: [Link: DB-10992]
### Description

Problem
---
* The postmaster process disappears immediately when the query is executed, and the client executing the query freezes until its server process is killed or it gets cleaned up after restarting the cluster. No client can make connection until the postmaster is restarted.
```
YB test# /*+ Set(enable_seqscan OFF) Set(enable_hashagg OFF) */ SELECT col_int_nokey AS field1, pk AS field2 FROM CC AS table1 WHERE ( ( ( table1.col_varchar_key LIKE 'c%' AND table1.col_varchar_key NOT IN ('v') ) OR table1.col_varchar_key LIKE 'c%' ) OR table1.col_varchar_key IS NULL );
FATAL:  Connection terminated unexpectedly due to unknown session 386
server closed the connection unexpectedly
	This probably means the server terminated abnormally
	before or while processing the request.
The connection to the server was lost. Attempting reset: Succeeded.
psql (15.6 (Homebrew), server 11.2-YB- -b0)
YB test#
```
* An error is reported in the postgres-xxx.log: `FATAL:  terminating connection due to unexpected postmaster exit`
* Reproducible on a recent master (42add04f18).


The plan:
```
QUERY PLAN
-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
 YB Bitmap Table Scan on cc table1
   Storage Filter: ((((col_varchar_key)::text ~~ 'c%'::text) AND ((col_varchar_key)::text <> 'v'::text)) OR ((col_varchar_key)::text ~~ 'c%'::text) OR (col_varchar_key IS NULL))
   ->  BitmapOr
... [Log Snipped] ...
               Index Cond: (col_varchar_key IS NULL)
(11 rows)
```
