Title

should defaultp use the fully qualified name for highp?

Description
I have a small container class Rectangle based on either glm::vec2 or glm::ivec2, but when the precision stuff was introduced and I attempted to use defaultp :

```
template  
class Rectangle
{
public:
    Rectangle() {}
... [Log Snipped] ...
    typedef Rectangle  Rectangle;
}
```

But was unable to because defaultp is defined as such:

```
#define defaultp    highp
```

It works if the definition is changed to the following:

```
#define defaultp    ::glm::precision::highp
```

Is this sort of reusability desirable? If so, then updating the definition would be helpful, I think.
Discussion
- This bug is fixed in GLM 0.9.5 branch.

defaultp is now an enum alias of highp.
