Title

Zalgo text causes Netty to throw an exception

Description
If I paste some [Link: zalgo text] into a form input and submit the form, Netty throws an exception and the page is completely broken. The zalgo text appears in the address bar.

[Image: screen shot 2014-03-11 at 10 12 52]

[Image: screen-shot-2014-03-11-at-10 13 28]
Discussion
- This error may be because the HTTP URL is larger than 4096 bytes and not specifically because of the Zalgo text in the URL. If you capture the request, how long is the URL?

The error is thrown by Netty (see [URL] If you look at [Link: this thread] you can see that there's a command line setting you can use to increase the max size from 4096, e.g. `-Dhttp.netty.maxInitialLineLength=8192`. Does setting that work for you?
- I think the problem is exactly as you described it, but I had hoped this sort of thing could be guarded against instead of changing an arbitrarily long number. Granted, I doubt I’m really going to face this in the wild since I don’t think my users will be trying to sabotage their own accounts by submitting Zalgo text, but it’s nice to be rigorous.

Is there a way to sanitise input like this? Should this thing be at the application level, or the framework level? I’m not sure, but I think it’s worth discussing.
