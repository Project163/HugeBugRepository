Title

Spamming the ascii bell character freezes alacritty when a bell command is set

Description
Using the following configuration file:

```toml
[bell]
command = { program = "true" }
```

Executing the following command completely freezes alacritty until 8 seconds have passed on my system:

```sh
for i in $(seq 1000); do printf '\a'; done
```

The following command will freeze it indefinitely, such that alacritty has to be forcibly killed:

```sh
while true; do printf '\a'; done
```

While these seem like constructed examples, this is particularly annoying when accidentally outputting binary data to the terminal. E.g. executing

```sh
cat $(which alacritty)
```

will take over a minute for alacritty to finally respond again on my system.

I think, the best way to fix this would be to somehow throttle bell command spawning, e. g. by a cooldown.

I’m using Alacritty 0.15.1 within Arch Linux under Wayland (sway).
