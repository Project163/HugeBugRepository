Title

Alias incorrectly refers to data stream

Description
**Elasticsearch version** (`bin/elasticsearch --version`): 7.10.0

**Description of the problem including expected versus actual behavior**:

User somehow managed to create an alias referring to the backing indices of a data stream:

`GET _data_stream` shows the data stream:
```
{
  "data_streams" : [
    {
      "name" : "endpoint-performance-stream-v3",
      "timestamp_field" : {
... [Log Snipped] ...
  ]
}
```
`GET _alias/endpoint-performance-stream` shows the alias referring to backing indices on the data stream:
```
{
  ".ds-endpoint-performance-stream-v3-000001" : {
    "aliases" : {
      "endpoint-performance-stream" : { }
    }
... [Log Snipped] ...
  }
}
```

Attempts to index through the alias resulted in the following error:

```
elasticsearch.exceptions.RequestError: RequestError(400, 'illegal_argument_exception', 'no write index is defined for alias [endpoint-performance-stream]. The write index may be explicitly disabled using is_write_index=false or the alias points to multiple indices without one being designated as a write index')
```

Originally reported by @jesse-sant
Discussion
- Pinging @elastic/es-core-features (Team:Core/Features)
- Just to add one additional detail, I was able to send docs just fine using the alias up until the data stream did its first rollover and added the second backing index.  As soon as that happened, I ran into the error in the description.
- So it is possible to create an alias pointing to a data stream and bypassing the validation that was added to avoid this:

```
PUT _index_template/template_1
{
    "data_stream": {},
    "index_patterns": [
        "endpoint-performance-stream-*"
... [Log Snipped] ...

GET _alias/endpoint-performance-stream
```

The get aliases api returns:

```
{
    ".ds-endpoint-performance-stream-v3-2021.01.20-000001": {
        "aliases": {
            "endpoint-performance-stream": {}
        }
    }
}
```

Note that it is not possible to create an alias via api to a backing index:

```
POST /_aliases
{
  "actions" : [
    { "add" : { "index" : ".ds-endpoint-performance-stream-v3-2021.01.20-000001", "alias" : "my-alias" } }
  ]
}
```

Returns:

```
{
    "error": {
        "root_cause": [
            {
                "type": "illegal_argument_exception",
... [Log Snipped] ...
    "status": 400
}
```

Which is correct and what is intended.

So we need to make sure that this validation also occurs when an alias gets associated with a backing index at index time creation through a composable index template. This should fail in the same as the update aliases api.

Also we probably want to deny templates that create aliases and data streams. These templates should should be rejected by the put template api.
