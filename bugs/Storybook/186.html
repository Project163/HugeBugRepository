Title

[Bug]: Svelte - Auto-docs includes all inherited HTMLAttributes when using utility types on svelte/elements

Description
### Describe the bug

When creating a Svelte component with Storybook in a Vite environment, the automatic documentation generation for props behaves inconsistently depending on how types from `svelte/elements` are extended.

Specifically, when using a TypeScript utility types like `Omit<>` to extend the attributes, Storybook's documentation includes the entire list of inherited attributes, flooding the props table. This does not happen when the interfaces from `svelte/elements` are extended/type-intersected "as is".

 

### Reproduction link

[URL]

### Reproduction steps

1. Go to the link above.
2. Open `ExtendsModifiesProps` component story in the preview.
3. Notice that all the inherited HTML attributes are displayed in the generated args table.
4. In contrast, view the `ExtendsProps` component story in the preview.
5. Notice that the inherited HTML attributes are properly ignored.

### Expected behavior

The generated documentation should only display the component's own, explicitly defined props (e.g., `label`), regardless of whether `Omit<>` or other utility types are used. The long list of inherited HTML attributes should be omitted from the primary controls table to keep the component's API clear and usable.
