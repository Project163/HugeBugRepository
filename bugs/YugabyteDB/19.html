Title

RedisKeyValue app reports wrong values if node dies and timeout is low

Description
To reproduce, change the `jedisSocketTimeout` in `AppConfig.java` to `2000` (`2` seconds), rebuild with `mvn clean install -DskipTests`. Then start the app and stop one node while it's running.
Then the app will report `ConnectionException` errors as expected, but in addition, it will also report wrong values (not expected): 
```
2018-05-08 11:46:59,409 [FATAL|com.yugabyte.sample.common.SimpleLoadGenerator|SimpleLoadGenerator$Key] Value mismatch for key: 7549, expected: val:7549, got: val:9771
2018-05-08 11:46:59,410 [FATAL|com.yugabyte.sample.common.SimpleLoadGenerator|SimpleLoadGenerator$Key] Value mismatch for key: 8480, expected: val:8480, got: val:15434
2018-05-08 11:46:59,411 [FATAL|com.yugabyte.sample.common.SimpleLoadGenerator|SimpleLoadGenerator$Key] Value mismatch for key: 1126, expected: val:1126, got: val:762
```
This appears to be an app issue as the mismatch errors will go away if restarting the app. Also checking the values from `redis-cli` yields the correct results.
