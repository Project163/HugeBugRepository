Title

sqlite "rename table" is wrong

Description
**Describe the bug**
During the batch operation to drop a non-null constraints, the final step is to rename the temporary table to the real table name. However, when the table is in a schema, alembic generates DDL of the form `ALTER TABLE scehma._alembic_tmp_table RENAME TO schema.table`. However, the [Link: sqlite ALTER TABLE syntax] does not expect or allow a schema name on the target table name.

**Expected behavior**
The `ALTER TABLE` statement should respect the sqlite grammar and be of the form `ALTER TABLE scehma._alembic_tmp_table RENAME TO table`

**To Reproduce**

```
py
import sqlite3
from alembic.migration import MigrationContext
from alembic.operations import Operations
from sqlalchemy import MetaData
... [Log Snipped] ...
with op.batch_alter_table("the_table", schema=SCHEMA) as batch_op:
    batch_op.alter_column('int_col', existing_type=Integer, nullable=True)
```

**Error**

```
$ python bug.py

2022-07-12 10:55:14,607 INFO sqlalchemy.engine.Engine [raw sql] ()
2022-07-12 10:55:14,608 INFO sqlalchemy.engine.Engine

[SQL: ALTER TABLE sn._alembic_tmp_the_table RENAME TO sn.the_table]
```
