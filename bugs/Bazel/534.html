Title

new_http_archive incorrectly reports a symlink pointing to a file outside of the zip archive

Description
When using new_http_archive to fetch a zip archive containing a symlink, bazel incorrectly reports that the symlink points outside of the directory.

Minimal working example can be found here:
[URL]
[URL]

the bazel-tests repo tries to fetch a very simple archive.zip file from the archive repository. This repository has a README.md at the top level, and a symlink at doc/README that points to README.md. It also a simple hello-world.cpp. The specific error I get is:

ERROR: no such package '@archive//': Error extracting /private/var/tmp/_bazel_luke.peterson/ /external/archive/master.zip to /private/var/tmp/_bazel_luke.peterson/ /external/archive: Zip entries cannot refer to files outside of their directory: master.zip has a symlink to ../README.md.
INFO: Elapsed time: 1.921s

I ran into this issue when trying to get bazel to build flatbuffers, which has a symlink at docs/source/CONTRIBUTING.md that points to ../../CONTRIBUTING.md. At first I thought it was because this was an invalid symlink but even after fixing the invalid symlink that the problem still persists:

[URL]
Discussion
- Yeah, [URL] disallows all up-level references.  This is a bit harsh, we could allow symlinks that don't travel up past the root dir.
- Just hit this bug as well because of test fixture (replicating `/proc`). 

If you are pulling from github you can quickly work around this by switching from grabbing a zip to grabbing a tarball:
```diff
- url = "[URL]
- type = "zip",
+ url = "[URL]
+ type = "tar.gz",
```
