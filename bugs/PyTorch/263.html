Title

Segmentation fault when using TorchDispatchMode.__enter__() with tensor string representation

Description
### 🐛 Describe the bug

A segmentation fault occurs when attempting to convert a PyTorch tensor to a string (via `str()`, `repr()`, or f-string formatting) while `torch._dynamo.explain()` is being used and a custom `TorchDispatchMode` is active. The crash happens during the tensor's string representation, specifically in `torch/_tensor_str.py:722` within the `_str()` function, when `_disable_current_modes` is called in `torch/utils/_python_dispatch.py:366`.

## Steps to Reproduce

### Minimal Reproducible Example

Create a file `reproduce_bug.py` with the following content (19 lines):

```
python
import torch
from torch.utils._python_dispatch import TorchDispatchMode

... [Log Snipped] ...
x = torch.randn(2, 3)
torch._dynamo.explain(fn)(x)
```

## Expected Behavior

The code should execute without crashing. The `torch._dynamo.explain()` should handle the graph break caused by tensor string representation gracefully, and the `LoggingMode` dispatch should not interfere with tensor string formatting.

## Actual Behavior

The program crashes with a segmentation fault. **The crash occurs with all tensor string representation methods:**
- `str(tensor)` - Crashes
- `repr(tensor)` - Crashes
- `f"Text: {tensor}"` - Crashes (f-string formatting)

All three go through the same code path and crash at the same location:

```
python

from torch.utils._python_dispatch import TorchDispatchMode
```
