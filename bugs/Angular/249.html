Title

DatePipe tranform adds extra unicode characters in Edge

Description

**Current behavior**
If the`DatePipe` is used programatically to transform a date, a unicode character (_\u200E_)) gets added to delimit/escape `/`

**Expected/desired behavior**
These extra characters should not be added

**Reproduction of the problem**
If you try the following plnk in MS Edge you can see the issue. Works fine on all the other browsers:
[URL]

**What is the expected behavior?**
No extra unicode characters should be added or the extra unicode characters should be replaced with empty characters as demonstrated in the plnk.

**What is the motivation / use case for changing the behavior?**
It's a bug

- I dig that Edge handles the bidi control characters in its Intl and locale APIs. IMO it fits with the spirit of the API. That said, for cross-environment consistency in Angular it should probably be stripped from the results.  I can cook up a PR to tackle that.

/cc @bterlson for his take.
- This doesn't seem to be a bug based on the documentation which states (mostly correctly), "In javascript, only the components specified will be respected (not the ordering, punctuations, ...) and details of the formatting will be dependent on the locale." Pedantically, not even the components you specify must be supported by the Internationalization APIs (eg. imagine a constrained hardware device that maybe only has a few date formats available). Regardless, it is never a good idea to be sensitive to the exact byte-for-byte contents of strings returned from the Intl APIs because there is no guarantee it will be the same across runtimes and platforms (or even from day-to-day as the underlying locale data gets updated).
