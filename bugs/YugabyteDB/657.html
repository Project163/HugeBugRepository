Title

PSQL bundled in YugaByte docker image intermittently fails on select.

Description
Steps to reproduce:
- Use instruction from [URL] docker tab, but instead of yum install use `/home/yugabyte/bin/psql`
- Then try multiple times following command, it will fail intermittently:
```
docker exec -it yb-tserver-n3 /home/yugabyte/bin/psql --host yb-tserver-n3 --port 5433 -c "SELECT * FROM sample.stock_market;"
```
Discussion
- Reproduced with bundled PSQL 10.3:

- With PSQL 9.6.8 there is a different intermittent failure:
```
21:36 $ docker exec -it yb-tserver-n3 /home/yugabyte/bin/psql --host yb-tserver-n3 --port 5433 -c "SELECT * FROM sample.stock_market;"
Database 'root' does not exist

sh: relocation error: /home/yugabyte/bin/../lib/linuxbrew/libc.so.6: symbol _dl_find_dso_for_object, version GLIBC_PRIVATE not defined in file ld-linux-x86-64.so.2 with link time reference
```
- ... [Middle Discussions Snipped for Brevity] ...
- Found a way to set libraries only for binary we want to run and avoid doing it for child processes:
```
#!/usr/bin/env bash
${BASH_SOURCE%/*}/../lib/ld.so --library-path ${BASH_SOURCE%/*}/../lib/system:${BASH_SOURCE%/*}/../lib/yb:${BASH_SOURCE%/*}/../lib/yb-thirdparty:${BASH_SOURCE%/*}/../lib/linuxbrew ${BASH_SOURCE%/*}/../lib/unwrapped/psql "$@"
```
If we use `ld.so` linker with `--library-path` option to run the binary - this will affect only this binary, but not its child processes (as happens when using `LD_LIBRARY_PATH` env var)

Also, we can use [URL] ELF program interpreter and avoid wrapper scripts at all, but we will have to put all libs in one directory without nested dirs. Or another option is to have simple interpreter based on rtldi which allows multiple libs directories.

Probably using rtldi and put all libs in one directory is the best option - it eliminates wrapper scripts and we can check for lib names conflicts during packaging the release, if there is more than one lib with the same name - most probably we have an issue with the build.

But the first step could be to just update wrapper scripts to use `ld.so --library-path` instead of `LD_LIBRARY_PATH`
- Fixed by seting rpath correctly during post install step for all binaries and custom build libraries.
