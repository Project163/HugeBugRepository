Title

`cpoptions` resets on lua files

Description
### Problem

when the user opens a lua file for the first time, cpoptions resets to default values. from my tests, other filetypes are not affected.

when i discovered this, at first i thought i was doing something wrong and the cpoptions just resets itself for some reason while opening any file for the first time, because i tested the behaviour on the `init.lua` file in my config directory.

but then i grepped the files from `:scriptnames` and found some lines in `/usr/share/nvim/runtime/ftplugin/lua.vim`.

lines 25-26:
```vim
let s:cpo_save = &cpo
set cpo&vim
```

lines 61-67:
```vim
" The rest of the file needs to be :sourced only once per Vim session
if exists("s:loaded_lua") || &cp
  let &cpo = s:cpo_save
  unlet s:cpo_save
  finish
endif
let s:loaded_lua = 1
```

i don't know vimscript, but if i understood correctly, the script saves previous cpo values into `s:cpo_save` variable and resets cpo to vim defaults. after that, because `cp` is set to false (i saw on the website in vim_diff section) and `s:loaded_lua` variable is non existent (created only after the block), the if block does not execute and cpo values are not restored. but after the first loaded file, the variable is created and the block is correctly executed.

### Steps to reproduce

create any lua file 1
`touch sample1.lua`

create any lua file 2
`touch sample2.lua`

create any not lua file 1
`touch sample1.txt`

create any not lua file 2
`touch sample2.txt`

launch nvim with clean config
`nvim --clean`

check default cpoptions (`aABceFs_`)
`:set cpo?`

make any cpo change
`:set cpo-=_`

check the change (`aABceFs`)
`:set cpo?`

open first not lua file
`:e sample1.txt`

verify that the cpoptions changes are still here
`:set cpo?`

open first lua file
`:e sample1.lua`

for some reason, cpoptions changed to default values
`:set cpo?`

open second not lua file
`:e sample2.txt`

change to default values is still here
`:set cpo?`

make custom changes once again
`:set cpo-=_`

check the changes
`:set c
