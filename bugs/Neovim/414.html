Discussion
- This problem doesn't exist in v0.5.1, so this is a regression.
- The problem seems to happen if the inserted character occupies a different number of bytes than the following multibyte character. For example, if the line contains one 2-byte character, then inserting a 1-byte character or a 3-byte character before it will cause an error, but inserting a 2-byte character before it will not.

I don't yet have much experience with the C code, so lmk if this is an easy fix for you, but I see you're taking a (well-deserved) break so I can look into fixing this over the next few days.
- @rish987 you could try changing it from `(char_u)` to `(ptrdiff_t)`. Or perhaps nothing, I think `PTR + long` should be considered well-defined anyways.
