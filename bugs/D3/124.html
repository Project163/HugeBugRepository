Title

Using d3 in node pollutes the global namespace

Description
Testcase in nodeJS:

```
require('d3');
console.log('Is D3 Global:', !!global.d3);
```

Just requiring in d3 should not put itself on the global object.
Discussion
- This happened with the change in #1921.  It does seem bad to clobber any existing `d3` global in all environments.  The proposal in #1921 was specifically relating to the use of AMD; a `d3` global makes loading plugins easier.

We could set `this.d3 = d3` for non-Node environments only (AMD and browser).  I’m guessing no-one relies on this behaviour in Node.js, but I’m not sure.
- Fix staged in #2075 for 3.4.13.
