Title

multiple package paths can hide files in the root package

Description
FileSystemUtils does not consider the package with empty name when deciding if a directory can have files coming from a parent [Link: package] (called when planting the [Link: link forest]). This causes the following bug. Execute from the root of a Bazel workspace:

```
echo "sh_binary(name = 'root', srcs = ['a/root.sh'])" >> BUILD
mkdir -p a
touch a/root.sh
chmod +x a/root.sh
mkdir -p ../other-bazel/a/b
... [Log Snipped] ...
bazel build //:root --package_path='%workspace%:../other-bazel'
# succeeds
```

One solution might be banning the package_path flag in Bazel. Getting rid of this special-casing logic might be tricky because of Google-internal issues.
Discussion
- The good solution would be to fix FileSystemUtils.
