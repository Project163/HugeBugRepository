Title

experimental-string-processing causing INTERNAL ERROR: Black produced code that is not equivalent to the source

Description
**Describe the bug**
Feeding Black a file containing a string split over several lines can cause an internal error when using experimental-string-processing

**To Reproduce**

1. Take this file 
    File 

   ```py
   (
       "my very long string"
       " that should get formatted"
       " if I'm careful to make sure"
       " it goes over 88 characters which"
       " it has now"
   )
   ```
    
2. Run _Black_ on it with these arguments `--experimental-string-processing`
3. See error

 
 Log 

```
diff
--- src
+++ dst
@@ -4,10 +4,46 @@
       value=
... [Log Snipped] ...
   type_ignores=
 )  # /Module
```
 

**Expected behaviour** Black formats the string into two lines as follows:
```py
(
    "my very long string that should get formatted if I'm careful to make sure it "
    "goes over 88 characters which it has now"
)
```

**Environment (please complete the following information):**

- Version: 20.8b2.dev50+g7f75fe3
- OS and Python version: Linux/Python 3.9.0

**Does this bug also happen on master?** Yes
Discussion
- @ichard26 Thanks for tagging me on this.

The problem was that black was trying to remove the surrounding parens, which changes the AST in this case. This issue should be fixed by #1888.
- @Starwort Note that the expected behavior should actually be that the string is left unchanged in this example, since black respects manual/user string splits when it is possible to do so without violating the line length limit.
- @bbugyi200 out of interest, what is a 'pointless string' in this context? When I first read your commit name I kinda thought you were mocking my example string but then after reading more into it it's clear that that's a proper term - could you explain it to me?
- @Starwort No problem. I'm stealing that nomenclature from [Link: pylint]'s "basic" checker's `pointless-string-statement` check. You can find a description of this check in [Link: pylint's documentation]. Taken directly from that documentation:


To be clear, regardless of whether the string is "pointless" or not, it should _not_ cause black to crash, so this was a valid issue. Thank you for reporting it.
