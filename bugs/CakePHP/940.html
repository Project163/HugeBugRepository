Title

Dynamic plugin loading in (Console)IntegrationTestCase

Description
This is a (multiple allowed):

* [x] bug
* [ ] enhancement
* [ ] feature-discussion (RFC)

* CakePHP Version: 3.6.6

### What you did
Updated plugin loading in Application::bootstrap for plugins that where still using Plugin::load() to $this->addPlugin() (plugins missing Plugin.php)

### What happened
I got some ConsoleIntegrationTestCase(s) for commands and these are all throwing MissingPluginException since the upgrade to 3.6.6 for these types of plugins.

Example stacktrace:
```
1) App\Test\TestCase\Command\IndexCommandTest::testHelp
Cake\Core\Exception\MissingPluginException: Plugin Migrations could not be found.

xx/vendor/cakephp/cakephp/src/Core/PluginCollection.php:125
xx/vendor/cakephp/cakephp/src/Http/BaseApplication.php:137
... [Log Snipped] ...
xx/vendor/cakephp/cakephp/src/TestSuite/ConsoleIntegrationTestCase.php:95
xx/tests/TestCase/Command/IndexCommandTest.php:36
```

A part of my command testcase:

```
php
namespace App\Test\TestCase\Command;

use Cake\Console\Command;
use Cake\ElasticSearch\Index;
... [Log Snipped] ...
    }
...
```

I dont have many controller integrations at the moment but i believe the same issue is also happening over there. 

The problem is that ```Configure::read('plugins')``` returns null, after a quick check but i can't seem to trace down where this is reset because ```PluginCollection::loadConfig()``` is executed correctly and populates the configure array.
Discussion
- Returning the path from already loaded plugins seems to fix the issue as shown in 

[URL]

Not sure this is the correct way to fix this but i feel like this line should be there anyway, could open a PR if you want :-)

**edit**: never mind still happening when running on multiple integration cases (was testing on a single one)
- Ok, found the the issue: Its related to [Link: TestCase::tearDown] that calls Configure::clear()

As Plugin::getCollection() returns a static instance of PluginCollection that uses Configure::read('plugins') to check loaded plugins. As this value is unset and therefore never rebuilt exceptions are thrown when these type of plugins want to be loaded.
- Thank you for digging up why this is happening. I think I have a solution now.
- Closing as there is a pull request now.
