Title

Axis function throws error when switching between linear and logarithmic scales

Description
The `.call(axis)` throws an error when switching between logarithmic and linear scales and the linear domain crossed/contained 0 (the log domain is always adjusted before calling the axis function).
The axis function seems to try to call `scale(0)` for the tick label and fails, because it wants to translate to `(0,Infinity)`.

I copied one of the public code samples provided on the axes documentation page and adjusted it to demonstrate:
[URL] (click 'change' button on top right side to see the error)
Discussion
- Although an "error" is logged in the console along with a stack trace, note that the axis still works as expected.  It's not an exception that is thrown and prevents the rest of the code from executing normally; think of it more as a warning.

Your example doesn't reset the positions of the ` ` elements after switching the scales, so you might have incorrectly attributed this to the error message in the console.

Still, it would be nice to avoid setting an invalid transform.  We can replicate the existing behaviour (and that of switching between ordinal and quantitative scales) by only setting a transform if the scale returns a finite number.  Admittedly, this might look a bit strange because some exiting ticks would fade out in-place, while others would move to their positions in the new scale while fading out, but that is what the current behaviour is anyway.
- Fix staged in #2075 for 3.4.13.
