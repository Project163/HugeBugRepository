Title

Client Headers in response panic

Description
## Problem statement
When a response has a header like `Location` with a type `string` and format `uri`, and the value is provided it will trigger a panic on the client.
The latest template will still call `strfmt.Parse` and the type is always a pointer when `UnmarshalText` is used (https://github.com/go-openapi/strfmt/blob/master/format.go#L311).
As a result when the generated client code attempts to assert the type, it is now being asserted as a value and not a pointer. The type assertion is now causing the generated client to panic.

Currently generated code
```
func (o *AddResourceCreated) readResponse(response runtime.ClientResponse, consumer runtime.Consumer, formats strfmt.Registry) error {

	// hydrates response header Location
	hdrLocation := response.GetHeader("Location")

... [Log Snipped] ...
	return nil
}
```

Previously generated code
```
func (o *AddResourceCreated) readResponse(response runtime.ClientResponse, consumer runtime.Consumer, formats strfmt.Registry) error {

	// response header Location

	location, err := formats.Parse("uri", response.GetHeader("Location"))
... [Log Snipped] ...
	return nil
}
```
