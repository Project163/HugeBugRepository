Title

StrBuilder does not implement clone()

Description
As reported by FindBugs. 

 Does StrBuilder need to be Cloneable?
Discussion
- Neither StringBuffer, StringBuilder or String itself is cloneable, so we're not doing this because it's needed.
- As we don't have the public clone(), this is only of value to subclasses. The state of this class is currently in 4 attributes. Two are protected, two are private. Both of the private attributes have public get/set methods. 

 So no reason for subclasses to need a clone.
