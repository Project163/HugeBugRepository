Title

select cast('false' as boolean) returns true

Description

    
Discussion

    
- The reason is that all non-empty strings are converted to  true  when casting to boolean. This behavior isn't intuitive, but it is consistent with Hive. I'm not sure whether we want to change this.  

 PostgreSQL only allows string literals  'true'  and  'false'  to be casted to boolean (case insensitive), casting any other strings to boolean results in error.

- We need to document this behavior change in our release note. The new behavior is that casting a string to a boolean will return true for 't' 'true' 'y' 'yes' '1',  false for 'f' 'false' 'n' 'no' '0' and null for others. The matching of those literals are case in-sensitive.
