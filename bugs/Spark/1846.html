Title

Inconsistent handling of dates in PySparks Row object

Description
Consider the following Python code: 

  
 import datetime

rdd = sc.parallelize([[0, datetime.date(2014, 11, 11)], [1, datetime.date(2015,6,4)]])
df = rdd.toDF(schema=['rid', 'date'])
row = df.first()
 
  

 Accessing the  date  column via  __getitem__  returns a  datetime.datetime  instance 

  
 >>>row[1]
datetime.datetime(2014, 11, 11, 0, 0)
 
  

 while access via  getattr  returns a  datetime.date  instance: 

  
 >>>row.date
datetime.date(2014, 11, 11)
 
  

 The problem seems to be that that Java deserializes the  datetime.date  objects to  datetime.datetime . This is taken care of  here  when using  getattr , but is overlooked when directly accessing the tuple by index. 

 Is there an easy way to fix this?
Discussion
