Title

Junction Aliases Are Too Long

Description
## Issue Description

When using entities with long names and many-to-many relations, it can be that junction aliases get quite long.
This results in the driver truncating the junction aliases in our case (Postgres has a limitation of 63 characters).
Sometimes, it happens that two **different aliases get truncated to the same alias**.
Thus, the query fails.

Scenario: We have the entities `Device`, `Deployment`, `DeviceDeploymentAttempt`, `Label` (amongst others) with relations between them. In that case, a simple `EntityManager` `findOne` leads to junction aliases like `DeviceDeploymentAttempt_deployment_deployment_DeviceDeploymentAttempt_deployment_deployment_labels` and `DeviceDeploymentAttempt_deployment_deployment_DeviceDeploymentAttempt_deployment_deployment_devices`. Both are truncated to `DeviceDeploymentAttempt_deployment_deployment_DeviceDeploymentA` which is bad.

### Expected Behavior

The junction aliases should be unique und thus the query shouldn't fail.


### Actual Behavior

The junction aliases are truncated in the driver and the query fails with the following error:

```
QueryFailedError: table name "DeviceDeploymentAttempt_deployment_deployment_DeviceDeploymentA" specified more than once
```


### Steps to Reproduce

1. Create entities with long names or many nested levels.
2. Query them with `EntityManager` (no special options needed).
