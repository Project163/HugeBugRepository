Title

Capture whether quotes have been used in template expressions

Description
The following example fails when used with Closure compiler, as we don't record whether the user has used quotes or not in the expression in the template:

```
@Component({
  template: `  `
})
class MyComp {}
```

A workaround is to put the object into the TypeScript code, e.g.
```
@Component({
  template: `  `
})
class MyComp {
  aObject(x: any) { return {'a': x}; }
}
```

- This bug seems to be even worse:

1. for actions, we seem to always strip quotes: We are just creating an `o.literalMap` which defaults to using no quotes for property names (see [Link: here])
2. for property bindings, we generate calls to `pureObjectDef`, which takes an array of property names (see [Link: here]). As we captured the property names during compilation, they won't get renamed.
- Idea for the solution in `pureObjectDef`: Change it to receive an object literal, where we only use the keys. This way, closure compiler can also minify the property names. We already do this in other places in the view engine too...
