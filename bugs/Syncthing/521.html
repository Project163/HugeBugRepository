Title

Race on folder restart

Description
The following unrelated test failure due to a nil-deref recently happened:

```
[TestIssue4357] [Test Output]
2018/06/01 13:31:01.338709 model.go:2630: INFO: Adding folder "default" (default)
2018/06/01 13:31:01.338709 set.go:73: INFO: No stored folder metadata for "default": recalculating
2018/06/01 13:31:01.339691 model.go:198: INFO: Ready to synchronize "default" (default) (sendreceive)
2018/06/01 13:31:01.341635 model.go:394: INFO: Paused folder "default" (default)
... [Log Snipped] ...
created by github.com/syncthing/syncthing/lib/model.(*folder).startWatch
	C:/BuildAgent/work/src/github.com/syncthing/syncthing/lib/model/folder.go:327 +0x17e
```

This happened on a folder restart, when the model already removed the ignore patterns but the folder loop was still running. This is possible due to `select` choosing a random option, not necessarily the canceled context. This could also lead to parallel pulling and scanning, if a folder is restarted during pulling, because the pull operation can keep running (processing deletes) after the folder was stopped.

I'll propose a mechanism to wait for the folder to "clean up" in the model shortly.
