Discussion
- I noticed the problem goes away when I comment out `counter-parent` compoment in `app.component.html` template.
How I understand this problem happens due to `nextId` global scope in `spy.directive.ts`. In fact both `spy-parent` and `counter` components increment the same variable `nextId`.
- But I find this situation _confusing for a reader_. Becuase there's a smth like unexpected coupling between examples that look independent at first sight.
I think this should be fixed somehow.
- More importantly, you get complitely different results in the actual example vs the gif when detroying the components.
The gif shows:

```
Spy #5 onDestroy
Spy #4 onDestroy
Spy #3 onDestroy
Spy #2 onDestroy
Spy #1 onDestroy
```

...while in the actual example you get:

```
Spy #7 onDestroy
Spy #8 onDestroy
Spy #9 onDestroy
Spy #10 onDestroy
Spy #11 onDestroy
```

I.e. it uses a different ID to log `onDestroy` than it used to log `onInit` for the same element instance.

And even if we fix that, the order of destruction seems to be different now: The elements are destroyed in the same order as they were created, so the correct output would be:

```
Spy #1 onDestroy
Spy #2 onDestroy
Spy #3 onDestroy
Spy #4 onDestroy
Spy #5 onDestroy
```
