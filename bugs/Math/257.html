Title

Seeding a default RNG

Description
In "RandomDataImpl": 
  
  private  RandomGenerator getRan() {
     if  (rand ==  null ) {
        rand =  new  JDKRandomGenerator();
        rand.setSeed( System .currentTimeMillis());
    }
     return  rand;
}
 
  
 The conditional branch is used by "sample()" in "AbstractContinuousDistribution". 

 When several "...Distribution" objects are instantiated in a short time interval, they are seeded with the same value.
Discussion
- I see your point, but at the same time it might be difficult to deal with correctly. One work-around is to use the serialVersionUID field together with System.currentTimeMillis(), but I am not sure if that is a good idea nor how well it can be implemented.
- No, my point was that the seeding should just be removed: When several distribution objects are instantiated, we usually don't want the samples to be the same...
- ... [Middle Discussions Snipped for Brevity] ...
- I thought about changing the default seeding in AbstractWell and agree that would be a good idea.  I still like to supply the seed explicitly and document it in RandomDataImpl, though, so users of that class know exactly what they are getting by default.  There is a little wrinkle here, too that keeping the seeding expressed and documented in RandomDataImpl makes easier to keep track of.  If we ever implement hashcode in RandomDataImpl (or the Well generators), things could get messed up if it does not separate generator instances the way the system identity haschcode does.
