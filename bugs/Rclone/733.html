Title

rclone serve restic does not close unix sockets cleanly

Description

#### What is the problem you are having with rclone?

`rclone serve restic` does not close unix sockets cleanly, so that subsequent executions of `rclone serve restic` fail, unless the socket is removed from the filesystem beforehand.

- os/arch: amd64
- go/version: go1.19.4
- go/linking: static
- go/tags: none

#### Which OS you are using and how many bits (e.g. Windows 7, 64 bit)

debian 11.6 (64 bit)

#### Which cloud storage system are you using? (e.g. Google Drive)

Jottacloud

#### The command you were trying to run (e.g. `rclone copy /tmp remote:tmp`)
```

restic snapshots --verbose -o rclone.args="serve restic --stdio --addr 'unix:///tmp/rclone_test.sock' --b2-hard-delete -vv"
echo "-------"
restic snapshots --verbose -o rclone.args="serve restic --stdio --addr 'unix:///tmp/rclone_test.sock' --b2-hard-delete -vv"
echo "-------"
rm /tmp/rclone_test.sock
restic snapshots --verbose -o rclone.args="serve restic --stdio --addr 'unix:///tmp/rclone_test.sock' --b2-hard-delete -vv
```

#6647 seems to apply here as well, which is why I am using the --stdio option.
