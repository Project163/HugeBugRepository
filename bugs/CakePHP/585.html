Title

Unit-test: Wrong restart sequence command

Description
on-TearDown() phrase, CakeFixtureManager call unload() then Postgres->truncate() to do reset the sequence of called models.

The problem occurs when CakeFixture try to reset sequence number of sub-Model. (redundant `.""`)

Error: SQLSTATE[42601]: Syntax error: 7 ERROR: zero-length delimited identifier at or near """" LINE 1: ALTER SEQUENCE "xxx_id_seq"."" RESTART WITH 1 ^

Expected: ALTER SEQUENCE "xxx_id_seq" RESTART WITH 1
Discussion
- How can someone reproduce this issue? What does your fixture look like?
- I think Postgre's sequence handler isn't working well with custom-sequence name in Models.

To reproduce: Write unittest of function in Model that call to another Model. Ex: `testCrossCall()`

```
php
class Thread extends AppModel {
    public $sequence = 'thread_id_seq';
    $hasAny = array('Entry');

... [Log Snipped] ...
    public $sequence = 'entry_id_seq';
}
```

PHP Warning: `Notice: Undefined offset: 1 in /lib/Cake/Model/Datasource/Database/Postgres.php on line 355`

``` php
list($schema, $sequence) = explode('.', $sequence);
```

`$sequence` may not contain `'.'` in case:

Postgres.php:275

``` php
if (isset($model->sequence)) {
    $this->_sequenceMap[$table][$model->primaryKey] = $model->sequence;
}
```
- ... [Middle Discussions Snipped for Brevity] ...
- First. Names of the schema (e.g., `public`) depends on how DB-admin want to set. Hard writing schema names in all models is not a good practice.

Second. This (sequence names without schemas) works well in my CakePHP applications (usually `$Model->getLastInsertID()`), except the Unit-test. (failed at `$Postgres->truncate()`).
- I understand that postgres dba's are often more creative with how they design dbs, but do your sequences have no schema?

CakePHP is a conventions based framework so some degree of pre-wired values should be expected. It doesn't seem unreasonable to think that sequences would be in schemas.
