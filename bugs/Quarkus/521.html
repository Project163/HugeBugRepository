Title

Panache adding @XmlTransient to fields breaks Jackson serialization in @QuarkusTest

Description
**Describe the bug**
Say I'm using Panache for easier persistence handling and Jackson for serialization. Notably, I use Jackson for serialization _both_ on the server side (inside the application) and on the client side (inside a `@QuarkusTest`, which uses RestAssured, which integrates with Jackson). And even more notably, the client side (which, again, is a unit test) uses the same bytecode-enhanced version of the entity class.

Then, I found that entity fields are not serialized in the test properly. A lot of fields (actually all of them except the `id`) are not serialized at all.

I was able to trace this down to [URL] which adds the JAXB `@XmlTransient` annotation to all fields. This causes Jackson (when the `jackson-module-jaxb-annotations` dependency is present) to ignore the property completely.

Note that I'm saying "property"; it doesn't ignore just the field, as the comment in `PanacheEntityEnhancer` suggests. Jackson is smart enough to understand that the field and the getter are the same thing (property), and if one of them is "ignorable", the entire property is ignored.

**Expected behavior**
Jackson serialization of Panache entities in `@QuarkusTest` works.

**Actual behavior**
Jackson serialization of Panache entities in `@QuarkusTest` doesn't work.


**To Reproduce**
Steps to reproduce the behavior:
1. `git clone [URL]
2. `mvn clean test`

See also the commit history. I was able to find a workaround, but it's nothing more than that, a workaround.
