Title

UseAsDataSource() - filtering by date in OData query results in mapping exception

Description
Given you have an entity like

 
public class Order
{
   ... 
   public void DateTIme? OrderDate{get;set;
   ...
}
 

and you have a web api controller returning an IQueryable  (where orderdto has the very same members as order) using UseAsDataSource

 
public IQueryable  Get(){
     return _context.Orders.UseAsDataSource().For ();
}
 

when you then filter by OrderDate like so:

 
api/Orders?$filter=OrderDate gt DateTime'2012-02-01T00:00:00'"
 

You get the following Exception:

```
Additional information: GenericArguments[0], 'System.Nullable`1[System.Boolean]', on     'System.Nullable`1[T]' violates the constraint of type parameter 'T'.
```

thrown in ExpressionMapper

 
static void UpdateToNonNullableExpression(Expression right, out Expression newRight)
Discussion
- I debugged this.

The resulting expression is:

 
.Call System.Linq.Queryable.Where(
    .Call System.Linq.Queryable.OrderBy(
        .Constant (AutoMapperSamples.EF.Dtos.OrderDto[]),
        '(.Lambda #Lambda1 )),
    '(.Lambda #Lambda2 ))
.Lambda #Lambda1 (AutoMapperSamples.EF.Dtos.OrderDto $o) {
    $o.Price
}
.Lambda #Lambda2 (AutoMapperSamples.EF.Dtos.OrderDto $$it)
{
    $$it.OrderDate > (System.Nullable`1[System.DateTime]).Constant (System.Web.Http.OData.Query.Expressions.LinqParameterContainer+TypedLinqParameterContainer`1[System.DateTime]).TypedProperty ==
    .Constant (True)
}
 

Because of the "TypedLinqParameterContainer", AutoMapper sees that both parameters are nullable and therefore calls

 
private static void UpdateToNonNullableExpression(Expression right, out Expression newRight){
    
                if (right is ConstantExpression)
                    newRight = Expression.Constant((right as ConstantExpression).Value,
                        typeof(Nullable<>).MakeGenericType(right.Type));
}
 

... and here it tries to replace the ConstantExpression.
But as right.Type is of type "Nullable ", it cannot create a generic type as it would result in
Nullable > which is not supported.

I fixed it, reproduced it with a test (ODataQueryTests.CanFilter_OrderDateGT()) 
and added a checkin in PR #997
