Title

Don't ignore exceptions thrown during JPA rollback

Description
I noticed this bit of code [Link: in the JPA implementation] where we're catching a `Throwable` and ignoring it. See the `catch (Throwable e) {}` below:

```scala
} catch (Throwable t) {
  if (tx != null) {
    try { tx.rollback(); } catch (Throwable e) {}
  }
  throw t;
} ...
```

1. We should try and avoid catching `Throwable` - maybe catch `NonFatal` instead?
2. Since we've got two exceptions at this point but we can only throw one, we should update `catch (Throwable e) {}` to log the value of `e` before we `throw t`.
Discussion
- I'll be happy to take this one.
Regarding the exception's type being caught and according to [Link: the doc]), one option is to:
1. Check isActive() before calling rollback
2. Catch `PersistenceException` only

Then we can log thenested  exception as @richdougherty proposed.
