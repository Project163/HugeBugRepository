Title

xbean-naming should support referenceable

Description
Sometimes people want to bind a Referenceable into jndi that isn't actually the object they want to get back out but just a Reference factory for such objects.  I'm not sure if we should support this only with a flag but we should support it somehow.  Initial implementation will just support Referenceable all the time.
Discussion
- implemented in rev 776407. 

 Need to updated fix versions, for 3.6-SNAPSHOT.
- We need more configuration around this feature.  For instance tranql "DataSource" claims to implement Referenceable but doesn't supply a reference when you ask. 

 Some possible choices: 
 
	 ignore Referenceable 
	 only bind Reference if its non-null and when you dereference you get an object not equal to the original value (this is actually the motivation for this feature) 
	 only bind Reference if its non-null and can successfully dereference to some object 
	 always bind Reference and object if its null. 
 

 For now I'm committing the 2nd choice in rev 776890
