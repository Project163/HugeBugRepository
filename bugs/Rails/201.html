Title

`SUM` is no longer casting to Integer with our custom MySQL adapter

Description
In #39039 and then followup PRs the types on calculation got changed.                                                                                        
                                                                                                                                                             
We have a custom adapter at GitHub and the client for that adapter follows the MySQL spec - that `SUM` on integers should return a `BigDecimal`. See [URL] for more information on that. 
                                                                                                                                                                                                                      
We have been unable to reproduce this outside of our application and at the moment our adapter and client are private so we can't share a reproduction script that actually breaks. The one provided here passes, but we've added notes about the behavior in GitHub.                                                     
                                                                                                                                                             
In our case the `BigDecimal` for `sum` calls was converted into `Integer` and now remains a `BigDecimal`. We have found that we can "fix" this by calling `yield` when we're using `sum` in `type_cast_calculated_value`, however that breaks other enum tests and we're not sure of next steps.

It also feels odd that the `type_cast_calculated_value` method only yields in the case of max and min, but the code makes it look like it always yields. With our bug it seems like there are more cases we should yield to ensure we deserialize.
