Title

[YSQL] Regression in performance of queries returning large columns

Description
Jira Link: [Link: DB-5446]
### Description

Memory tracking introduced by commit ` ` causes a significant slow down in queries on large (5KB+) columns that are stored by reference, not value. 

## Setup
Tested on a release build on dev server with RF=1. 

## SQL
```sql
CREATE TABLE tab_5000 (a INT PRIMARY KEY, len INT, j jsonb);
INSERT INTO tab_5000 (a, len, j)
    SELECT i, 5000,
        CAST('{"k": "' || REPEAT('a', 5000) || '"}' AS jsonb)
    FROM generate_series(1, 5000) AS t(i);
CREATE INDEX ON tab_5000(a ASC);
```

## Query
```sql
SELECT j FROM tab_5000 WHERE a < 1000;
```

This query returns 1000 rows of 5KB JSON. 

## Results
Timings were measured as a median across 10 runs. 
| | Time |
| --- | --- |
| Master | 103.2 ms |
| `UpdateCur` disabled | 66.2 ms | 
| `UpdateCur` and `UpdateMax` disabled | 48.5 ms |
| `YbPgMem{Add,Sub}Consumption` disabled | 45.6 ms |
