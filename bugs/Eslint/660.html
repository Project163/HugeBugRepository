Title

Auto-fix incorrectly applies fixes if both eqeqeq and space-infix-ops specified

Description
ESLint version: v1.8.0

If there is a case for auto-fix where eqeqeq and space-infix-ops are both applicable, it adds the space in the wrong location. Without space-infix-ops, the third equal is added correctly. Without eqeqeq, the space is added correctly. At the least I think it shouldn't break the existing JS.

Config: 

```
{
    "rules": {
        "eqeqeq": 2,
        "space-infix-ops": 2
    }
}
```

Input: 

```
'use strict';
var x = 4;
if (x ==4) {
    x++;
}
```

Expected Output:

```
'use strict';
var x = 4;
if (x === 4) {
    x++;
}
```

Actual Output:

```
'use strict';
var x = 4;
if (x == =4) {
    x++;
}
```
Discussion
- Sorry about that, we will look into it.
- @nzakas The best way to fix this issue and also to be always safe when fixes our applied we need to change [Link: `if (fix.range[1] <= lastFixPos) {`] to `if (fix.range[1] < lastFixPos) {`.

Thoughts?
