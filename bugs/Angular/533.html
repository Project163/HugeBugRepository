## Current behavior
Any `id` set on downgraded component is [Link: overwritten by the downgrade function].

For example when declaring:
```
  
```
The compiled output will be: 
```
  
```


## Expected behavior
The user should be able to use the `id` of its choice, which will not be overwritten. Upgrade ids could be renamed as `ng2-upgrade-id="27_0"`. 

## Minimal reproduction of the problem with instructions
 
Declare a ng2 component in a ng1 module:
```
angular.module('myNg1module')
   .directive('myComponent', downgradeComponent({component: MyComponent}))
```
then use the component with an HTML id:
```
  
```

## What is the motivation / use case for changing the behavior?
Ability for the user to keep on using its existing ids, even on downgraded components.

Otherwise migration could require more significant rewriting of an existing app (to match another discriminator than the `id` in existing JS or CSS code).
