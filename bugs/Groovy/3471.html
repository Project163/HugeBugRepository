Discussion
- I originally marked methods with @Generated but the requirements for coverage/Jacoco are different to the methods we currently mark as synthetic, so instead I have created a new @Internal annotation. 

 These methods are no longer synthetic normally but are instead marked @Internal. There was a condition where we didn't add @Internal due to an NPE that would occur in that scenario - I believe that would normally only occur when creating AST fragments which we do for some of our unit tests. But since I am unsure what some AST transformations might do, I left that condition in and for that case I leave the methods as synthetic. 

 there is some code when using the metaclass mixin capability which used to skip synthetic methods. It now skips also @Internal methods. We'll need to see whether we need to make that condition more specific.
- HEADSUP: I am likely to reopen this issue and defer for one more minor version. The current fix added @Internal and removed synthetic all in one go. This forces other libraries/tools which sneak into the more private areas of the language like Spock and possibly others to have to upgrade immediately. Instead I plan to keep the @Internal annotation as per the current solution but leave the methods as synthetic for at least one more version. This gives us times to get all the libraries/tools updated. I am also testing a few other libraries. I'll also write an email to the dev mailing list summarising this once I finish more testing.
- Resolving just for 3.0 for now. We can add a 2.5.x fix version if/when we backport to 2_5_X.
