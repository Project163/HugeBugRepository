Title

Postgres update of polymorphic object generates invalid SQL with synchronize_session='fetch'

Description
originally at #8332.    after looking at what we currently support, this is a bug.

### Describe the bug

When updating an object with `polymorphic_identity` and using `synchronize_session="fetch"`, SQLAlchemy's PostgreSQL dialect generates invalid SQL. Specifically, it tries to fetch columns from the base table without including it in a `FROM` clause.

We're migrating an app from 1.3 to 1.4 and have hit this in a number of places. Most cases can be replaced with the `evaluate` method, so it hasn't been a blocker.

### To Reproduce

```
python
from sqlalchemy.orm import as_declarative, relationship, Session
from sqlalchemy.engine import create_engine
from sqlalchemy.sql.schema import Column, ForeignKey
from sqlalchemy.sql.sqltypes import Integer, String
... [Log Snipped] ...

session.query(Thing).filter(Thing.thing_name == "baz").update(dict(thing_name="quix"), synchronize_session="fetch")
```
