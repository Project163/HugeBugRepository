Title

OpenAPI annotation @APIResponse without content makes Quarkus crash

Description
The following code prevents Quarkus to start and generates an java.lang.NullPointerException exception (see stacktrace below). 
 
This code was tested on macOS Mojave and OpenJDK Runtime Environment 18.9 (build 11+28) with Quarkus 0.12.0.  NOTE!  This did work with Quarkus 0.11.0. 
```
java
@Path("/")
public class GreetingEndpoint {
  @GET
  @APIResponses(value = {@APIResponse(responseCode = "204", //
... [Log Snipped] ...
  }
}
```
```
Failed to start quarkus: java.lang.RuntimeException: org.jboss.builder.BuildException: Build failure: Build failed due to errors
	[error]: Build step io.quarkus.smallrye.openapi.deployment.SmallRyeOpenApiProcessor#registerOpenApiSchemaClassesForReflection threw an exception: java.lang.NullPointerException
	at io.quarkus.runner.RuntimeRunner.run(RuntimeRunner.java:134)
	at io.quarkus.dev.DevModeMain.doStart(DevModeMain.java:105)
	at io.quarkus.dev.DevModeMain.main(DevModeMain.java:66)
... [Log Snipped] ...
	at java.base/java.lang.Thread.run(Thread.java:834)
	at org.jboss.threads.JBossThread.run(JBossThread.java:479)
```

Adding a content value to the annotation such as this:
```java
@APIResponses(value = {@APIResponse(responseCode = "204", //
      description = "A response with no content", content = @Content(mediaType = "application/json",
          schema = @Schema(implementation = String.class)))})
```
makes the code work but shouldn't be mandatory AFAIK.

The issue seems to be in smallrye-openapi-module:
```
SmallRyeOpenApiProcessor#registerReflectionForApiResponseSchemaSerialization 
``` 
which expects that a content attribute exist 
```AnnotationInstance[] contents = apiResponseAnnotationInstance.value(OPENAPI_RESPONSE_CONTENT).asNestedArray(); //<- this causes the NPE```
