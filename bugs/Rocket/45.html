Title

Unable to write documentation for similar ending routes

Description
Hello, I'm trying to write some documentation for my project and noticed, that I'm unable to write documentation for routes that have a similar ending. For example: `/user/add` and `/survey/add`. Both routes are in different modules.

- Rocket version: Master branch
- Rust version: rustc 1.46.0-nightly (346aec9b0 2020-07-11)
- Os: Linux Mint 20 Cinnamon Edition (beta)

Here is a small working example of my code:
```
rust
#![feature(proc_macro_hygiene, decl_macro)]

#[macro_use] extern crate rocket;
use tokio::runtime;
... [Log Snipped] ...
        .launch()).unwrap();
}
```

Everything works fine until I start to add some documentation like this:
```
rust
    ...

    /// Route to add a survey.
    #[get("/survey/add")]
... [Log Snipped] ...

    ...
```

I'm able to document the first route but after the second one I get the following error message from the compiler:
```
rust
error[E0428]: the name `rocket_uri_macro_add9134641248968336068` is defined multiple times
  --> src/main.rs:16:5
   |
8  |     #[get("/survey/add")]
... [Log Snipped] ...
   = note: `rocket_uri_macro_add9134641248968336068` must be defined only once in the macro namespace of this module
   = note: this error originates in an attribute macro (in Nightly builds, run with -Z macro-backtrace for more info)
```

This only happens if the routes end similarly. It should be possible to document routes of this type.
Discussion
- This is a limitation introduced by #964, when we removed the usage of the `decl_macro` feature. In particular, each route generates a corresponding macro in the crate's global namespace. Since the names must be unique, they are disambiguated by hashing the `file_name`, `line`, and `column` of the function - this should provide a unique hash, and usually does...

until you add documentation with `///`. It looks like this causes rust-lang/rust#43081, and one of the effects of that bug is that both routes appear to be at line 1, column 0 of the file and hash the same.

Some workarounds that you can use today:

* Put the routes in different *files*. `file_name` is also part of the hash and it appears to be unaffected by the `rustc` bug.
* Use `#[doc = ""]` instead of the `///` syntax sugar, which also seems to avoid the bug. This is very ugly, even for a workaround.
* Name the routes differently, e.g. `add_survey` and `add_user`. The name of the route is part of the macro name, so this will make them unambiguous.

One really awkward workaround rocket might be able to do is to hash more, such as the function *contents*. Another awkward workaround in rocket would be to randomly generate the disambiguator instead of deriving it from the input.
- is there no way to include the namespaces / module in the hash?
