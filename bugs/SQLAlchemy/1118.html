Title

Mypy plugin crashes when using instances as relationship.collection_class

Description
**Describe the bug**
When using an instance as `relationship.collection_class` the mypy plugin crashes. It works for types as `list`, `set`, `dict`. However, not using [Link: custom collection implementations] like those in `sqlalchemy.orm.collections` or `sqlalchemy.ext.orderinglist`.

**Expected behavior**
I'm little unsure here, it could use the type of the instance or perhaps check for the `__emulates__` attribute mentioned in the custom collection docs?

from sqlalchemy.orm import registry, relationship
from sqlalchemy.ext.orderinglist import OrderingList

Discussion
- **Mike Bayer** has proposed a fix for this issue in the **master** branch:

**Accommodate for callable fns for collection_class** [URL]
- @zzzeek It seems that my initial report here is incorrect/incomplete. The `relationship.collection_class` should be a class or callable, not an instance of that class. I mixed that up while creating a minimal reproduction sample. 

However, it seems that mypy  does not pick up the annotation that it should be a [Link: `Type`]. I'm not sure if that is an error in de stubs or that the plugin's functionality for the `relationship` ignores the stub typing.

The fix for this issue is that it should either take a type (which is functioning correctly in the 1.4.6 release) or a callable. See [URL] for reference:

```py
parent = relationship("A", collection_class=lambda: OrderingList("ordering")) # not exposed in __all__
parent = relationship("A", collection_class=ordering_list("position")) # equivalent, exposed in __all__
```
