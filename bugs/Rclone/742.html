Title

mount: Folder is still uploaded if renamed and deleted before --vfs-write-back time expired.

Description
#### The associated forum post URL from `[URL]
[URL]


#### What is the problem you are having with rclone?
If I mount a cloud storage with --vfs-cache-mode=writes or full, rclone does not seem to handle folder renames and deletions properly. Steps to reproduce:

Mount cloud to /mnt/tmp:
`
rclone -vv mount --cache-dir=/tmp/rclone_vfscache/ --vfs-cache-mode=writes --vfs-cache-max-age=2m --vfs-write-back=60s --vfs-cache-max-size 1M pCloud: /mnt/tmp
`

The following steps must be done within the vfs-write-back time (which can of course be set to something longer than 60 s).
Create folder old in /mnt/tmp:
`
mkdir old
`

Create file in old:
`
touch old/file
`

rename old to new:
`
mv old new
`

delete new:
`
rm -rf new
`

Result:
* At first, everything looks OK both in /mnt/tmp and cloud WebGUI. Nothing is present.
* But after the vfs-write-back time has expired, new/file is uploaded to the cloud and visible in the WebGUI.
* After the dir-cache-time (I guess) has expired, it is also visible in /mnt/tmp

If the folder is deleted AFTER the vfs-write-back-time has expired, everything works as expected.
