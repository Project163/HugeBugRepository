Title

error with weme 6.1. in test timestampArith.java

Description
test lang/timestampArith fails with j9_foundation 1.1.: 

 (from the .tmp  
Test timestamp arithmetic starting. 
Unexpected result from 'values( {fn TIMESTAMPADD( SQL_TSI_FRAC_SECOND, -1000, 
{d '2005-05-11'})})'.  Expected 2005-05-10 23:59:59.999999 got 2005-05-11 23:59:59.999999. 
Unexpected result from 'values( {fn TIMESTAMPADD( SQL_TSI_FRAC_SECOND, -1000,{d '2005-05-11'}
 )})'.  Expected 2005-05-10 23:59:59.999999 got 2005-05-11 23:59:59.999999. 

 This is likely a jvm problem. So I'll not mark this as a regression.
Discussion
- This is indeed a jvm problem. Referred to vendor.
- The problem is in the calculation of GregorianCalendar(<someint>, -1). Sometimes (some conditions: no getTimeInMillis or getTime calls before the add), that results in an incorrect Day (in the repro I managed to make, DAY_OF_MONTH is wrong in the toString() method after the add call).
- This is fixed in version weme 6.1.1. So, that is the version of j9 one needs to run derbyall. With revision 499506 (  [URL] I removed the canon file I had checked in earlier (with revision 497678).
