Title

Scheduler - JobDefinition programmatic API does not work if quarkus-quartz and DB type store is used

Description
### Describe the bug

Because there is no way to serialize the task instance.

I think that we should:

1. Add a `setTask()` variant that accepts `Class > consumerClass` instead (and the same for `setAsyncTask()` of course),
2. Fail the registration if `JobDefinition#setTask(Consumer )` is called and `quarkus-quartz` and DB type store is used,
3. Either make it clear that `Scheduler.unscheduleJob()`, `Scheduler.getScheduledJob()` and `Scheduler.getScheduledJobs()` will not reflect the jobs registered programmatically after the app restart or try to fix this part as well.

### Workaround 

Delete the job manually with `org.quartz.Scheduler.deleteJob(JobKey)` and `new JobKey("THE_JOB_IDENTITY", "io.quarkus.scheduler.Scheduler")` and reschedule it.

### Expected behavior

The `JobDefinition` programmatic API works if `quarkus-quartz` and DB type store is used.
