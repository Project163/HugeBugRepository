Title

False positive "not-callable" for "multiprocessing.current_process"

Description
Hello.

### Steps to reproduce
Lint the following code:
```python
import multiprocessing
multiprocessing.current_process()
```

### Current behavior
This reports an issue: `E:  2, 0: multiprocessing.current_process is not callable (not-callable)`

### Expected behavior
No issue reported.

### pylint --version output
```
pylint 1.7.4,
astroid 1.5.3
Python 3.6.3 (default, Oct  4 2017, 02:55:45)
[GCC 5.4.0 20160609]
```

### Notes
Curiously, `threading.current_thread()` works fine.
Discussion
- This happens because we are inferring `current_process` as a staticmethod, coming from here: [URL] We should check why the inference engine can't infer accessors such as this one as being callable. Th brain_multiprocessing plugin is here [URL] which just instantiates `BaseContext` and adds its members to the global namespace.
Basically when the issue gets fixed, the following should not emit `Uninferable` as it does now, but rather the `current_process` function:

```
from astroid import extract_node
n = extract_node('''
from multiprocessing.context import BaseContext
c = BaseContext()
c.current_process
''')
i = next(n.infer())
print(i)
```
- I think there may be an easy workaround for this issue using `@staticmethod` in the multiprocessing brain and then opening up a separate issue in astroid for explicitly calling staticmethod

---

Here's what I found about `staticmethod`: In Python, a function wrapped with staticmethod isn't inferable unless it's defined in a class namespace (and called after the namespace is fully created).

Here's a Python code example of when staticmethod is / is not `Callable`:
```
python
def hi():
    pass
staticmethod_instance_hi = staticmethod(hi)
staticmethod_instance_hi # Not Callable here
... [Log Snipped] ...
func = Foo.hi_staticmethod
func() # Callable
```

Astroid only infers `staticmethod`s correctly using the `@staticmethod` syntax (using this decorator it correctly infers the attribute as a function instead of a bound or unbound method.

When explicitly calling staticmethod on a function in a class namespace (as in multiprocessing's case), astroid is either inferring the value as an instance of staticmethod (which is valid when not defined inside a class definition) or `Uninferable` (not sure why)
- After learning about python descriptors I'm thinking this is related to astroid not understanding them (PyCQA/astroid#118)

Until I get to that, I think I'll make an exception for `not-callable` messages for instances of staticmethod in pylint
- @brycepg Sounds like a good plan to me.
