Title

Test execution swallows IOException

Description
When running //src/test/shell/bazel:bazel_toolchain_test with remote caching, the test fails with an error message that the log file was not created. What's happening is that there's actually an IOException thrown, which is swallowed by the TestStrategy. Complete stack trace:

```
com.google.devtools.build.lib.actions.DigestOfDirectoryException: Input is a directory: src/test/shell/bazel/testdata/bazel_toolchain_test_data
	at com.google.devtools.build.lib.exec.SingleBuildFileCache$1.load(SingleBuildFileCache.java:84)
	at com.google.devtools.build.lib.exec.SingleBuildFileCache$1.load(SingleBuildFileCache.java:66)
	at com.google.common.cache.LocalCache$LoadingValueReference.loadFuture(LocalCache.java:3716)
	at com.google.common.cache.LocalCache$Segment.loadSync(LocalCache.java:2424)
... [Log Snipped] ...
	at java.util.concurrent.ThreadPoolExecutor$Worker.run(ThreadPoolExecutor.java:617)
	at java.lang.Thread.run(Thread.java:745)
```
Discussion
- The reason is a filegroup in src/test/shell/testdata that names a subdirectory.
- The simple fix is to update the BUILD file not to do that, which is easily possible.
- ... [Middle Discussions Snipped for Brevity] ...
- Thanks for confirming that, it's useful to know that there is no easier way.

By staring some more at the set of passing vs. failing tests and what dependencies they have in common, I was able to track it down to the same root cause as in your case, a filegroup that includes a directory; I'll fix the BUILD file not to do that.

For anyone else who runs into this, with Bazel 0.5.2, the symptoms in my case looked like this (I substituted `...target...` and `...environment vars...` to protect the innocent):

- That's been fixed a while ago. When we find such a directory we do readdir() on it.
