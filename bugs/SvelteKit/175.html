Title

Using fetch from PageEvent results in the wrong content being cached in certain circumstances

Description
### Describe the bug

When fetching from f.ex a graphql endpoint, most of the time the URL is the same but the body (query) is different. This causes the fetch provided by the PageLoad event to use the wrong cached data during hydration.

Discussion
- Hashing the body or using some other ID is probably what we need to do. Omitting POST request from the hydration behavior would be disastrous for anyone using GraphQL etc which do POST requests all the time.
Update: From looking at the code, we are already hashing the body, so now I'm wondering why this even happens. Update 2: It happens because we only support reading from the body when it's passed as the `init` argument to `fetch`, not when the body is passed to the `Request` object and that is then passed to the fetch function.
