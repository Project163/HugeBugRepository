Title

ER_DUP_FIELDNAME with simple find on 0.2.10

Description
**Issue type:**

[x] bug report

**Database system/driver:**

[x] `mysql 5.7.24`

**TypeORM version:**

[x] `0.2.10`

**Steps to reproduce or a small repository showing the problem:**

Given the following two entities:
```
ts
@Entity({ name: "payrolls" })
export class Payroll {
    @PrimaryGeneratedColumn()
    public id: number;
... [Log Snipped] ...
    public payroll: Payroll;
}
```

And the following find:

```ts
dbConn.getRepository(PayrollPayslip).findOne(id, { relations: ["payroll"] });
```

I now receive `ER_DUP_FIELDNAME` after upgrading to 0.2.10

Discussion
- Okay, its a bug.

Why it creates different queries? Because we added `limit 1` to `findOne` to prevent additional stuff loading. Currently, in query builder "special distinct-based query" is used in the case if either limit or offset is defined. In this case we don't need this special query, but this is too complex to resolve right now, and we already have a different relation load mechanizm in 0.3.0.

But the actual bug is in query we had even in 0.2.9. It shouldn't select columns from two tables with same names. I have fixed that.
- Published it under `@rc`, its a breaking bug, but its not super urgent since issue reproduces only when using custom join column names. `npm i typeorm@0.2.12-rc.1`
- ... [Middle Discussions Snipped for Brevity] ...
- @Zclhlmgqzc as I answered in a separate issue you must select primary keys because ORM rely on them to make proper mapping of your relations.
- Hi! Not sure I should open a new issue just for this, but it looks like this change introduced a bug in our application. I just reverted this single commit (and kept using the current `master`), and the bug disappeared.

We have a deep nested relation that we fetch using `relations` in the FindOptions of `findOne`. It suddenly became `undefined`, with [Link: this] commit. Getting back to a single underscore solved the problem: back to normal/expected behavior.

I'd like to investigate and propose an additional fix. But I just wanted to let you know @pleerock as you might have an instant idea 🙄.

Anyway, will keep you posted. thanks!
