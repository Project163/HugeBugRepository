Title

hasMany with a custom primary key and a custom foreignkey not fetched properly in Oracle

Description
Created by **Paolo Bergantino**, 11th Jun 2010. _(originally [Link: Lighthouse ticket #812])_:

---

What I did:

```
php
class Area extends AppModel {
    var $name = 'Area';
    var $useTable = 'OR_AREA';
    var $primaryKey = 'A_ID';
... [Log Snipped] ...
    );
}
```

With this schema:

```
CREATE TABLE ORDB_ADMIN.OR_AREA
(
  A_ID            NUMBER(8),
  NAME            VARCHAR2(255 BYTE)            NOT NULL,
  FK_F_ID         NUMBER(8),
... [Log Snipped] ...
  BLDG           VARCHAR2(90 BYTE)              NOT NULL
)
```

I then tried:

``` php
$this->Building->find('all', array('recursive' => 2));
```

What I expected:
- An array of all buildings and their associated Areas, if any.

What I got:
- An array of all buildings and empty associated Areas, regardless of whether there are any records linked. No query in the log shown even attempting to get information from OR_AREA.

Some extra information:

I posted a question in Stackoverflow with all the details (most of them are here)
[URL] 

There's a ticket that looks to describe what is happening but it seems to already be closed and is pretty old and vague
[URL]

I can't change the columns names to adhere to CakePHP conventions, but I created a few dummy tables and they seem to come closer to working with the proper names but were still not 100% right. Although it actually attempted to query OR_AREA I got a few invalid key errors inside the driver file.
Discussion
- 14th Jun 2010, **Paolo Bergantino** said:

---

Finally found out why it is happening - case sensitivity! Although the column names in my Oracle tabled are defined ALL CAPS, CakePHP is bringing them over as lowercase and if I set my keys to be 'b_id' instead of 'B_ID' and so on everything seems to work.

I am not sure this is a bug, but it sure would be nice to mention that in the Book somewhere.
- Should we close as the convention is to use lowercase field names?
- I don't think being unconventional is an appropriate justification for not working.

That said, the oracle driver only exists in (of relevance) 1.3 so there's not really a reason to fix this now (which is a bit of a pity, there's probably just a `strtolower`-too-far somewhere in the [Link: driver's source].
- Maybe for a dusty and 2 year old ticket it is.
Anyway, closing then for the above reasons.
