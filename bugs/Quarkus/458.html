Title

Custom serializer in ObjectMapperCustomizer is loaded randomly

Description
**Describe the bug**
A custom serializer registered in Jackson's ObjectMapper through ObjectMapperCustomizer is loaded randomly. Sometimes it works, sometimes it doesn't after a restart or during tests.

**Expected behavior**
Data should always be serialized the same way. The ZonedDateTime field in the below example should always look like this : 2020-02-10T10:39:22Z

**Actual behavior**
The ZonedDateTime field is sometimes serialized like this after a restart : 
2020-02-10T11:41:21.854544+01:00

**To Reproduce**
Steps to reproduce the behavior:
1. I created a sample app which reproduces the issue : [URL]
2. run the app : mvn compile quarkus:dev
3. get request on the following endpoint : [URL]
4. Restart app and reproduce step 3 until date format has changed 

**Environment (please complete the following information):**
 - Output of `uname -a` or `ver`: Darwin 19.2.0 Darwin Kernel Version 19.2.0: Sat Nov  9 03:47:04 PST 2019; root:xnu-6153.61.1~20/RELEASE_X86_64 x86_64
 - Output of `java -version`: 
openjdk version "11.0.2" 2019-01-15
OpenJDK Runtime Environment 18.9 (build 11.0.2+9)
OpenJDK 64-Bit Server VM 18.9 (build 11.0.2+9, mixed mode)
 - Quarkus version or git rev: 1.3.0.Alpha1 (issue is also there in 1.2.0.Final)

**Additional context :**
ObjectMapperCustomizer can be found here : [Link: DateFormatConfig]
Discussion
- Thank you for reporting this! 

I was able to reproduce this one. I'll take a look at it soon
- A super quick look reveals that Quarkus itself doesn't appear to be doing anything wrong, the customizer is always called on application restart so this will require some digging most likely
- This turns out to be a problem with the order that the customizers are applied. Basically Quarkus applies it's own customizer that registers the JSR310 and it sometimes overrides the user provided one.

I'm going to fix this today by introducing a priority to the `ObjectMapperCustomizer` interface and make the default Quarkus customizers have the lowest priority.
- #7142 takes care of the issue
