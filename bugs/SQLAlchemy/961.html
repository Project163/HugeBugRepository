Title

the transaction nesting model is broken

Description
we'd like to get rid of the transaction nesting model as we see in #4644.  however, the nesting is still there for now and going back to many versions, it doesn't actually make sense.   the Transaction object does not point to the previous Transaction object, and the management of the "reset agent" which we unfortunately still need for some two-phase types of situations is all over the place.

basic demo of nesting not even making sense:
```
from sqlalchemy import create_engine


pg_url = "postgresql://scott:tiger@localhost/test"

... [Log Snipped] ...

assert not t2.is_active   # fails - t2 was just forgotten
```

see if we can revise the nesting model and localize how reset agent gets set up, then again it may not be worth it as 2.0 has a simpler model.
