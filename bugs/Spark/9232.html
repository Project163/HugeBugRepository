Discussion
- This is a classloader issue with the serialization of an UDF pulling classes from the client's class context that it doesn't necessarily need, and then resulting in ClassNotFoundException on the server. 
org.apache.spark.SparkException: org/apache/spark/sql/connect/client/SparkResult 
It's not specifically related to the tests in that suite, but can happen anyplace with UDFs.
- Hmmm, this was supposed to be fixed by stubbing. The underlying issue is that for lambda deserialization we need to be able to load its capturing class. When that class contains any reference to a class we don't have on the classpath (and one we definitely don't want), it will fail with a CNFE.
