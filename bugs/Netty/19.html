Title

CookieEncoder and CookieDateFormat set Expires with invalid 2-digit year

Description
[URL]

   HTTP applications have historically allowed three different formats
   for the representation of date/time stamps:

```
  Sun, 06 Nov 1994 08:49:37 GMT  ; RFC 822, updated by RFC 1123
  Sunday, 06-Nov-94 08:49:37 GMT ; RFC 850, obsoleted by RFC 1036
  Sun Nov  6 08:49:37 1994       ; ANSI C's asctime() format
```

   The first format is preferred as an Internet standard and represents
   a fixed-length subset of that defined by RFC 1123

Chrome interprets two digit years as in the past

[URL]

This means that any cookies sent with an expires by Netty, some browsers consider them already dead, Chrome being one of them. This is biting me in Play because play uses Netty.

Culprit: 

[URL]

A Y2K bug in this day and age?
Discussion
- There is another bug as well.

CookieEncoder does not include a space after the semicolon when encoding cookies. If this is added, then the cookie expires is properly processed by chrome

```
     private static void addUnquoted(StringBuilder sb, String name, String val) {
         sb.append(name);
         sb.append((char) HttpCodecUtil.EQUALS);
         sb.append(val);
         sb.append((char) HttpCodecUtil.SEMICOLON);
         sb.append((char) HttpCodecUtil.SP);
     }
```

The space is required by the cookie standard.
