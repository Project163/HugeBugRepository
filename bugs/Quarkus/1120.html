Title

Injected Bean Validator has different behavior than the static default Hibernate one

Description
## Describe the bug
The specific difference in behavior I found is around validating containers (list, maps, optionals...) without adding `@Valid` to them. See the reproducer or the code below.

### Expected behavior
The injected bean validator has the same behavior and supports the same features as the Hibernate default one, in this case, elements in containers are validated without having to explicitly add `@Valid` to them.

### Actual behavior
The injected bean validator behaves differently that the Hibernate default one, in this case it doesn't find any violations on containers unless `@Valid` is explicitly added to them.

## To Reproduce
[Link: container-validation-test.zip] is a maven project that shows the issue, but the only dependency is `quarkus-hibernate-validator` and the whole Java code is this:

```
java
@QuarkusMain
public class App implements QuarkusApplication {

    @Inject
... [Log Snipped] ...

}
```
