Title

Javascript API monitor functions don't work

Description
### **Describe the bug**
In the window API, the [Link: `currentMonitor()`, `primaryMonitor()` and `availableMonitors()` functions] don't work. They call an incorrect command from the JS side which causes an error.

### **To Reproduce**
Steps to reproduce the behavior:
1. In a project with the JS API enabled, use any of the above functions.
2. See an error in the Javascript console:

### **Additional context**
These three functions are standalone functions and call a top-level Tauri command, which is expected to be a variant of [Link: the `Cmd` enum]. But these commands are actually [Link: in the `WindowManagerCmd` enum] and should be invoked with a window label. 

So I think a fix would be to move all three of these functions into the `WebviewWindow` class and call them with the current window label as a window command. Unless the `availableMonitors()` and `primaryMonitor()` functions should be standalone commands, in which case the Rust side will need to be updated to accept these as a top-level command.
