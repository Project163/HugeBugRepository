Title

FilterAllocationDecider handles exclude._tier filters not correctly

Description
**Elasticsearch version**: master

**Plugins installed**: []

**JVM version (java -version)**: 14.0.1

**OS version (uname -a if on a Unix-like system)**: Mac OS 10.13.6

**Description of the problem including expected versus actual behavior**:

When we setup a cluster with only one node, and set the node as `data_hot` and `master`:

```
node.roles: [ data_hot, master ]
```
then we set cluster level shard allocation filter: `"cluster.routing.allocation.exclude._tier": "data_cold"`, 
finally, new index'shards canot be allocated because:

```
{
    "index":"z",
    "shard":1,
    "primary":true,
    "current_state":"unassigned",
... [Log Snipped] ...
    ]
}
```

**Steps to reproduce**:

1. setup a cluster with only one node:

```
node.roles: [ data_hot, master ]
```
2. PUT _cluster/settings

```
{
  "transient": {
    "cluster.routing.allocation.exclude._tier": "data_cold"
  }
}
```

3. Create a new index with setting `index.routing.allocation.include._tier_preference:"data_hot"`
4. GET _cluster/allocation/explain
