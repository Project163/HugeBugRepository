Title

AsyncIndexUpdate unable to cope with missing checkpoint ref

Description
The async index uses a checkpoint reference stored under the  :async  hidden node as a base for running the index diff. 
It might happen that this reference is stale (pointing to checkpoints that no longer exist) so the async indexer logs a warning that it will reindex everything and will start its work. 
The trouble is with the #mergeWithConcurrencyCheck which does not cope well with this scenario. Even if the ref checkpoint is null, it will throw a concurrent update exception which will be logged as a misleading debug log  Concurrent update detected in the async index update . 

 Overall the code looks stuck in an endless reindexing loop. 

  
 *WARN* [pool-9-thread-1] org.apache.jackrabbit.oak.plugins.index.AsyncIndexUpdate Failed to retrieve previously indexed checkpoint 569d8847-ebb6-4832-a55f-2b0b1a32ae71; re-running the initial async index update
*DEBUG* [pool-9-thread-1] org.apache.jackrabbit.oak.plugins.index.AsyncIndexUpdate Concurrent update detected in the async index update
Discussion
- fixed in trunk with rev 1609081, merged to 1.0 with rev 1609083.
- A manual workaround would be to use the oak-console and delete the 'async' property under the root path in the ':async' node: _/:async  
{ async = 'uuid' }
 _. 
This node is hidden on the JCR layer, so that's why you need to use the oak-console.
