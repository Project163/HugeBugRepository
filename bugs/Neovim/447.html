Title

:cd causes the path of open files in sym-linked directories to change to their target path instead

Description
### Neovim version (nvim -v)

NVIM v0.5.0

### Vim (not Nvim) behaves the same?

Yes.  Vim 8.2

### Operating system/version

macOS 11.6

### Terminal name/version

Terminal with zsh

### $TERM environment variable

xterm-256color

### Installation

homebrew

### How to reproduce the issue

* Create a temporary directory
* Create a sub directory named `source`
* Create a file inside `source` named `foo.txt`
* Execute `ln -s ./source ./dest` from the temporary directory
* `nvim -u NONE`
* `:e [PATH_TO_DEST]/foo.txt`
* `:echo expand('%')`
* Note that this displays the `dest` directory
* `:cd`
* `echo expand('%')`
* Note that this now displays the `source` directory

### Expected behavior

When editing a file inside a sym-linked directory, it would be really helpful if neovim continued to use the linked path instead of the source path at all times, instead of suddenly changing to the source path during seemingly unrelated commands.  Alternatively, it would be good to document what the actual intended behaviour is around editing files inside sym linked directories.

### Actual behavior

Neovim changes the path for open sym-linked files to the source path after executing certain commands like `cd`
