Title

[DocDB] Change ScopedLeaderSharedLock long lock error message

Description
Jira Link: [Link: DB-4415]
### Description

The ScopedLeaderSharedLock is acquired by yb-master RPCs and prevents a new leader from reloading the sys catalog until it is complete (i.e. it is a read lock on the `state_lock_` of the catalog manager). If this lock is held for a long time (> 1 second by default), the following error message is printed:
```
scoped_leader_shared_lock.cc:165] Long lock of catalog manager (../../src/yb/master/master_heartbeat_service.cc:51, TSHeartbeat): 1.646s
```

This is misleading people into thinking there is a deadlock, when in reality the RPC just took longer than our threshold (e.g. because of CPU overload, slow disks, or even underlying lock contention). It should be renamed to something like `RPC took a long time`.
