Title

Helm does not wait for Statefulset to be ready after upgrade

Description
Helm does not wait for Statefulset to be ready after upgrade to 3.6.3 from 3.3.1. I have tried using versions:
* 3.7.0 (does not work),
* 3.6.3 (does not work),
* 3.5.4 (works!),
* 3.3.1 (works!).

It seems that this behavior was introduced with: [URL]

Helm 3.7.0 behavior - unexpected:

```
helm upgrade --install --reset-values XXX chart --version X.Y.Z --wait --timeout 900s --create-namespace --namespace dummy --values /tmp/helmfile351904154/XXX-values-6fd57cf55 ... --history-max 10 --debug
helm:whTHc> history.go:56: [debug] getting history for release XXX
helm:whTHc> upgrade.go:139: [debug] preparing upgrade for XXX
helm:whTHc> upgrade.go:488: [debug] resetting values to the chart's original version
helm:whTHc> upgrade.go:147: [debug] performing update for XXX
... [Log Snipped] ...
NAME: XXX
...
```

Helm 3.5.4 behavior - expected:
```
exec: helm upgrade --install --reset-values XXX chart --version X.Y.Z --wait --timeout 900s --create-namespace --namespace dummy --values /tmp/helmfile549477625/XXX-values-68c7579fb5 ... --history-max 10 --debug
helm:whTHc> history.go:56: [debug] getting history for release XXX
helm:whTHc> upgrade.go:123: [debug] preparing upgrade for XXX
helm:whTHc> upgrade.go:437: [debug] resetting values to the chart's original version
helm:whTHc> upgrade.go:131: [debug] performing update for XXX
... [Log Snipped] ...
helm:whTHc> Release "XXX" has been upgraded. Happy Helming!
NAME: XXX
```

It's weird because I have similar releases of this chart where `--wait` works as expected. I do not know if it is relevant but release XXX was converted from Helm 2 release using 2to3 plugin a while ago.
