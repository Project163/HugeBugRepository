Title

property with setter misidentified as Method

Description
I recently upgrade to pylint-1.5.5

``` sh
pylint --version
pylint 1.5.5, 
astroid 1.4.5
Python 2.7.6 (default, Jun 22 2015, 17:58:13) 
[GCC 4.8.2]
```

And now my code is generating a lot of false-positive no-member errors, one class of which can be summarized by the following code:

```
py
# foo.py
class X(object):
    def __init__(self, foo=None):
        self._foo = foo
... [Log Snipped] ...
if __name__ == '__main__':
    print X([]).foo.append
```

pylint generates the following error:

```
$ pylint -E foo.py                                                                                               
************* Module foo
E: 12,10: Method 'foo' has no 'append' member (no-member)
```

The error goes away if I remove the `foo.setter` method, which is not used in the code above.  So for some reason when `.setter` is defined for an `@property`, pylint thinks the property is a method.

- I looked into it for a while:

When hitting `@property`, astroid infers that this node is not a BoundMethod, but when hitting `foo.setter`, it says that `foo` is a `BoundMethod` now.

If the setter uses a different name, there is no collision.

In `astroid.bases._is_property`, `meth.decoratornames()` returns an empty list because, even if `meth.decorators.nodes` is not empty (`[ ]`), `decoratornames` catches an `InferenceError`.

I hope this helps to narrow it down.
