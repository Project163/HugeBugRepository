Title

jetty IdleTimeout bugs with Http2SolrClient, cause sprious timeouts on intranode requests

Description
There is evidence in some recent jenkins failures that we may have some manor of bug in our http2 client/server code that can cause intra-node query requests to stall / timeout non-reproducibly. 

 In at least one known case, forcing the jetty & SolrClients used in the test to use http1.1, seems to prevent these test failures.
Discussion
- Here's the backstory which lead me to this hypothosis... 

 I've been investigating jenkins failures in TestDistributedStatsComponentCardinality – which don't reproduce reliably – that manifest as request timeout during intranode communication. 

 (Side note: the failures manifest as response vs control comparisons assertion failures, due to some weird oddity in the way intranode timeouts get propogated back to the original client – evidently as "successful" responsess w/status=200)
