- The problem comes from the fact that the Kotlin compiler jar contains its own version of `com.google.common.base.Strings`.
- @stuartwdouglas I know what needs to be done to solve this, but I need your blessing or an alternative idea.

Basically what happens in this case is that the Kotlin compiler jar has its own very stripped down version of `com.google.common.base.Strings`, so when Jib tries to access this class (in the `AugmentationClassLoader`), instead of the class it being loaded from the Guava jar, it gets loadedfrom the Kotlin jar. 
So my idea is that we introduce a mechanism to configure the classloader in a way that moves elements to the bottom of `List  elements`. For this case to work we would ensure that the Kotlin jar is configured like that.
WDYT?
