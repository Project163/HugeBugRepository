Title

Standardize idioms for error context in c10::Error in c10/util/Exception.h

Description
A common situation when reporting errors is that we don't know enough about the context at the point we are reporting the error. For example, in the new op registration API we have:

```
#define DEF_PRELUDE "def(\"", schema.operator_name(), "\"): "
Library& Library::_def(c10::FunctionSchema&& schema, c10::OperatorName* out_name) & {
  TORCH_CHECK(kind_ == DEF || kind_ == FRAGMENT,
    DEF_PRELUDE,
    "Cannot define an operator inside of a ", kind_, " block.  "
    "All def()s should be placed in the (unique) TORCH_LIBRARY block for their namespace.  ",
    ERROR_CONTEXT
  );
```

However, the description of what the shape of the def operation was is misleading, because `_def` may be called from the implementation of `def(schema, impl)` (and so the error message would misreport that it's from a `def(schema)` call). These things may seem minor, but there are more major situations where lack of context can seriously impede understanding of an error message (e.g., a BLAS failure in some low level helper function, which should we report as having occurred when someone did a matrix multiply call.)

Today, `c10::Error` supports a limited form of error context in the form of its `AppendMessage` method, which can be used append an arbitrary string at the end of the existing c10 exception string. This is used in very few places. The purpose of this issue is to propose a more general formatting and API convention for adding context, with the intent of using it more broadly in the codebase.

----

Typical message format today:

```
Traceback (most recent call last):
  File " ", line 1, in  
RuntimeError: The size of tensor a (3) must match the size of tensor b (2) at non-singleton dimension 1
```

Suggested updated format with context:

```
Traceback (most recent call last):
  File " ", line 1, in  
RuntimeError: The size of tensor a (3) must match the size of tensor b (2) at non-singleton dimension 1
  In operator "add.Tensor"
```

Discussion
- Some possible refinements on C++ API: an attractive alternate API for context addition is an RAII structure, which appends the context onto the exception in its destructor. We would have to maintain a thread local tracking the "current exception", ensure that it is maintained correctly. This has performance cost (unlike exception handling frames, which are free if no exception is raised).

Conclusion: continue with explicit exception try-catch frames for now.
