Title

PostgreSQL index reflection erroneously includes columns that are part of the INCLUDE clause

Description
Since PostgreSQL 11 the `INCLUDE` postfix was implemented for covering indexes. Currently it's not implemented within SQLAlchemy and I use `Index.argument_for('postgresql', 'include', None)` with special hook `@compiles(CreateIndex, 'postgresql')` to modify creation of such indexes. It works but when I use alembic it's auto generation algorithm sees the difference between metadata and real structure, in particular - indexed columns. Therefore it tries to create new index with all keys and included columns.

Refs: #4458
