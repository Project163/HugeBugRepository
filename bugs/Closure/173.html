Title

try ... catch is sometimes optimized away when it shouldn't be

Description
What steps will reproduce the problem? 
This program does nothing and raises no error (provided that 'a' isn't 
defined, so accessing it raises a ReferenceError)

try { while(a); } catch(_){}

After compilation, we get:
for (;a;);

which throws an error which is not caught.

 What version of the product are you using? On what operating system? 
r15

 Please provide any additional information below. 

Found using the next version of fuzz-test :)
Discussion
- Ha. Inside Google, we've forced all variables to be explicitly declared for a few 
years, so we haven't looked at plain ReferenceErrors for a long time. (in the stand-
alone jar, you'll get a compiler error with --warning_level=VERBOSE).

I'm not really sure how we want to handle cases like this. We could mark every extern 
variable access as HAS_SIDE_EFFECTS, but that's not much fun.

Thoughts?
- Seems reasonable. I guess people who would want to benefit from the side effect + dead 
code elimination passes would need to make sure they declare all their variables.
