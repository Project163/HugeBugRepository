Title

rules:quotes.js too strict - doesn't allow for quotes within quotes

Description
I use single quote strings when I have double quotes inside of them to avoid having to unnecessarily escape quotes, thus keeping file size and complexity down.  Others might do vice versa (double quotes with single quotes inside).

Could a pass be issued if it detects a quote character of the opposite kind within the string?

var foo = 'I am single quoted.'; // fail
var foo = '"I am single quoted, but have double quotes inside."'; // pass

- @brandonpayton 
We discussed options as objects before, and decided against it. While it might be slightly easier to ready, it's just not necessary. Also, from your example above, it's not clear if the rule is enabled or disabled, and if it's set as a error or warning. I think we should stick to the existing way of setting options, i.e. array of values.
Quote rule already have an option, that can be set to either "double" or "single", I think you have a choice, of either adding another option, like this:
`"quote": [2, "double", true]`
or having 4 options, like this:
`"quote": [2, "double-outer"]`
- I'd opt more for a string than a boolean, since a boolean doesn't tell you
what's going on:

"quote": [ 2, "double", "something-descriptive" ]
