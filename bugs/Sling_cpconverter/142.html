Title

Converter doesn't reset the aclManager after first pass and rejects too much after resets

Description
The converter doesn't reset the acl manager after the first pass. That makes it so that the service users are collected and put into the all feature. Furthermore, if it resets, it is loosing the acls that have matching service users but that come too later in the contenpackage.
Discussion
- angela  - I merged this already but I still would like to have your review. I think it is doing the right thing but it maybe it needs more improvement (which we might need a new issue for). Basically, the idea is to keep a global list of the service users encountered to allow for acls in a feature that didn't bring the service users. That has the downside that it will miss service users created by repoinit (especially if they are coming from the seed). That would have been the case before as well so I don't think it is making things worse but I guess I might be missing something.
- karlpauls , the problem with service users coming from the seed or from other repo-init statements is that it's not possible to determine their path (in contrast to content packages). the path is used to determine if a given access control entry points to some user home.... but i agree that with the fix we essentially keep 2 sets of global service-user information: one 'globalServiceUsers' for this defined in all packages and a second one for the ids of all those service users  plus  the ids of those defined in repo-init and seed, for which we don't know the path. for the sake of clarity and maintainability i would suggest that we try to merge those 2 sets. i will create a separate improvement request for that.
