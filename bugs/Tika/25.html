Title

XML files with (unsatisfied) SYSTEM entities can not be extracted

Description
When trying to extract an XPI file (Firefox extenstion, which probably is not a best candidate for extract) I got the below exception. 
It was caused by SYSTEM entities refering the chrome:// protocol. 
However, obviously any XML file that contains SYSTEM entities which can not be accessed at the time of extraction will not be extracted properly.

Discussion
- Minimal test case for the issue. 

 xmlTest.xml: when blah.xml is present at time of extracting (with any content, eg "blah"), everything works OK, otherwise not. 

 xmlTest2.xml: always fails because chrome protocol is not defined. However there exist xml files using this protocol, eg in Firefox plugins.
- We probably should prevent Tika and the parsers it invokes from trying to access any external entities when parsing XML (or any other file formats for that matter). The only input for content extraction should be the input stream and input metadata passed to the parse() method.
- ... [Middle Discussions Snipped for Brevity] ...
- +1 to not resolving external references. 

 If this appears to be a sought after feature we need to think carefully about including it and definitely not by default, IMHO.
- Fixed in revision 734861. 

 I implemented an OfflineContentHandler decorator class that makes the XML parser silently replace all external entities with nothing. This decorator is now used in all places where Tika uses an XML parser on input documents. 

 I also enable the secure processing feature  [1]  that's designed to prevent XML bombs from breaking the system.
