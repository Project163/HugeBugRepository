Title

new_http_archive doesn't work Go Appengine SDK

Description
I'm trying to pull Go Appengine SDK into my repository. Bazel has hard time unzipping the archive.

I run it on MacOS 10.11.4. In order to reproduce create an empty directory with two files:
WORKSPACE:

BUILD.app:

and run:
`bazel build @goappsdk//:sdk`

It downloads file but then fails with:

Droping `strip_prefix` attribute from new_http_archive doesn't help
Discussion
- Reproduced, I'd guess that the zip file has demos/ twice and Bazel's unzip code isn't handling that properly.  As a workaround for now, you can download and manually extract the .zip, then replace new_http_archive() with:

```
new_local_repository(
    name = "goappsdk",
    path = "/path/to/your/download/go_appengine",
    build_file = "BUILD.app",
)
```
- Okay, nope, the go appengine zip just lists demos/ as being of type "regular file" (not directory). "Fixing" bazel to assume paths ending in / are dirs, regardless of type...
