Title

Potential issues in Netty 3.8's Spdy implementation?

Description
Hi!

We upgraded to Netty 3.8 and suddenly started getting "SpdyProtocolException: client sent extra data beyond headers" on some of the messages we were sending (note the only change was the update).

It looks like it's related to the change in buffer size from 8k to 4k (https://github.com/wgallagher/netty/commit/ ). This decrease causes an odd condition where the decompressor doesn't fully decompress the message because it runs out of room in the buffer, but it won't clear the buffer because it doesn't have a full header.

When we adjust the size back up the exception goes away.
Discussion
- @wgallagher @jpinner could you check ?
- @MWhiteley I think you're right -- from reading the code it appears that header names/values that are larger than 4k cannot be decoded. Thanks for reporting!

@wgallagher do you want to take a look? We could either go back to using a dynamic buffer, or use a static buffer with a capacity of maxHeaderSize, or try to decode into a composite cumulation buffer if the decode buffer isn't writable. Thoughts?
