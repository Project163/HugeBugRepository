Title

Metaclass operators not respected by TypeVar bounds

Description
Using `mypy 0.590`, running `mypy` on the following code:

(EDIT: See [URL] for a smaller test case)

```
python
import ctypes
from typing import Type, TypeVar

S = TypeVar("S", bound=ctypes.Structure)
... [Log Snipped] ...
def g(x: Type[S]) -> ctypes.Array[S]:
    return (x * 0)()
```

fails with

```
test.py:9: error: Unsupported operand types for * ("Type[S]" and "int")
test.py:9: error: "int" not callable
```

But AFAICT, `g` should be perfectly valid -- because it has a bound of `ctypes.Structure` (which supports multiplication with integers), it should also support multiplication with integers.
Discussion
- But does the ctypes.Structure type support multiplication with integers?

Also, it doesn't look like the ctypes stubs has a `__mul__` implementation for Structure.
- There is `__mul__` and `__rmul__` on a metaclass. This may be a real bug in mypy, operators are special cased (probably old code) instead of re-using `checkmember`, therefore corner cases (like access via bound via metaclass) is not treated correctly unlike the latter one. This needs some refactoring I think. I left a TODO in code while previously fixing a similar corner case, it looks like we need to implement that TODO.
