Discussion
- Ok, if I understood correctly here, the issue is that [URL] does not warn about a string being passed to the first arg even though the third arg is false. In the other example, the error is correctly emitted

This is due to the fact that the error is emitted in the Assertion module of Psalm. It's the module that handle `truths` from structure like `if`, `assert`, `ternaries` etc...

The example just returns the result so it's not affected by all that.

Unfortunately, I can't think of an existing place where Psalm just emits issue based on validity of arguments for a function call except in TypeProviders.

I think this could be handled in both `FunctionParamProviderInterface` or `FunctionReturnTypeProviderInterface` but the latter is more frequently used and we could also use it to refine the return type to false or true in some cases.

If anyone want to take this, there is an example of an issue being emitted in `ArrayReduceReturnTypeProvider`, the concept would be the same
