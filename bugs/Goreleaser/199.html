Title

Release fails on first tag using github-native release notes

Description
### What happened?

I created a new Go package and GoReleaser fails to create the release notes until there's at least two tags with some commits between them:
```
GoReleaser latest installed successfully
/opt/hostedtoolcache/goreleaser-action/1.13.1/x64/goreleaser release --rm-dist
  • starting release...
  • loading config file                              file=.goreleaser.yml
  • loading environment variables
... [Log Snipped] ...
  ⨯ release failed after 0s                  error=POST [URL] 400 Invalid previous_tag parameter []
Error: The process '/opt/hostedtoolcache/goreleaser-action/1.13.1/x64/goreleaser' failed with exit code 1
```

### How can we reproduce this?

I have the following `.goreleaser.yml` file:
```
---
builds:
  - skip: true
release:
  prerelease: auto
changelog:
  use: github-native
```
So it's using the GitHub native release notes.

### goreleaser version

```bash
1.13.1
```

### Additional context

Workaround was to create a single commit, (I created an empty commit), then a new tag and pushed that. The release notes then create correctly.
