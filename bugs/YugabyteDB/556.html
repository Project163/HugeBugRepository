Title

[YSQL] unique constraint violation error happened in PL/pgSQL block causes "FATAL: RollbackAndReleaseCurrentSubTransaction: unexpected state STARTED" error with background process crash

Description
Split off of #2397.
Here's @robertsami 's simple test case and his comment:
```
➜  bin/ysqlsh
ysqlsh (11.2-YB- -b0)
Type "help" for help.

yugabyte=# create table t1(k int primary key, v text);
... [Log Snipped] ...
	before or while processing the request.
The connection to the server was lost. Attempting reset: Succeeded.
```
Discussion
- The problem is that YBUpdateActiveSubTransaction, which propagates the subtransaction id to the YB side flushes the pending buffered operations, and when one of the operations throws an exception, it long-jumps to the PG_CATCH block in exec_stmt_block for PL/pgSQL exception handling without doing rest of the transaction state transition stuff.

A potential fix is to flush or reset at the beginning of high-level transaction control functions instead of lower level ones such as Push/PopTransaction. i.e.: flush in ReleaseCurrentSubTransaction, reset in RollbackAndReleaseCurrentSubTransaction. We need to flush at the beginning of BeginInternalSubTransaction, too, so the statements before entering the blocks are executed in the correct subtransaction context.

exec_stmt_block wraps the exec_stmts call with a PG_TRY block when it has the EXCEPTION clause:
```
...
 if (block->exceptions)
 {
    BeginInternalSubTransaction();
    PG_TRY();
... [Log Snipped] ...
    rc = exec_stmts(estate, block->body);
  }
```
- Two more scenarios that lead to unexpected transaction state, in these cases, an assertion failure of not being in a valid transaction detected when yb::pggate::PgSession::HandleResponse tries to get the unique constraint name.
