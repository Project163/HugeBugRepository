Title

figure out why "secondary" uses eval() and if not a good reason, change it

Description
I dont really know why secondary uses eval.  it should be string name of table, possibly schema qualified, looked up in metadata.  i can't think of a valid Python expression one would need there instead where they would not use lambda.

See #10563.
Discussion
- It's to support [Link: late evaluation of relationship arguments]. Basically if the value of "secondary" is known only at runtime, after evaluation of some condition. I guess it is to support more flexibility of database operations. The documentation heavily states that this is a potential vulnerability though.
- I didn't say it shouldn't be accepted as a string, just that the string itself does not need to be python-evaluated
- **Mike Bayer** has proposed a fix for this issue in the **main** branch:

**lookup "secondary" directly, dont use eval()** [URL]
