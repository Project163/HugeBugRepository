Title

[xerces-c] produces strange files in installed/x64-linux/lib

Description
**Host Environment**
- OS: CentOS 7
- Compiler: g++ (GCC) 8.2.1 20180905 (Red Hat 8.2.1-3)

**To Reproduce**
`./vcpkg install xerces-c`

**Failure logs** 
```
$ ls -l installed/x64-linux/lib/
-rw-r--r--. 1 user user 12969802 Jul 31 15:16 libxerces-c-3.2.a
lrwxrwxrwx. 1 user user       17 Jul 31 15:16 libxerces-c.so -> libxerces-c-3.2.a
drwxrwxr-x. 2 user user       24 Jul 31 15:16 pkgconfig

$ ls -l installed/x64-linux/lib/pkgconfig/
-rw-r--r--. 1 user user 483 Jul 31 15:16 xerces-c.pc
```

Also, `config-*-err.log` files contain strange entry:
```
CMake Warning at /home/user/vcpkg/scripts/buildsystems/vcpkg.cmake:107 (message):
  There are no libraries installed for the Vcpkg triplet x64-linux.
```
Discussion
- In _source\cmake\XercesDll.cmake_:23 :
```
set(BUILD_SHARED_LIBS ON CACHE BOOL "Build shared libraries")
```

Forced to set a dynamic library caused this issue.
- What is the proper way to fix it -- should I patch it so it sets this variable only if `VCPKG_LIBRARY_LINKAGE` is not static? (assuming this variable is visible at that point)
