Title

Wrong count query results / Containment state of clean query copies only reset partially

Description
This is a (multiple allowed):

* [x] bug
* [ ] enhancement
* [ ] feature-discussion (RFC)

* CakePHP Version: 3.4.8

---

So there's two problems here

1. `\Cake\ORM\Query::cleanCopy()` partially resets containments
2. Count queries can return wrong results

I stumbled over this via **[URL]

### The cause of the problems

Count queries are using clean query copies, and the docblock of `\Cake\ORM\Query::cleanCopy()` claims that the method would reset the containment state, but before **#10657**, [Link: **there would be no changes to the containments at all**].

The changes introduced with **#10657** will "reset" the containments that have been set in the `beforeFind` event, as [Link: **the cloned eager loader where these containments have been applied**], will be overwritten with [Link: **a new eager loader cloned from the original query**], which holds the containments that have been set on the query directly.

### Expected behavior

Given the description of `cleanCopy()`, one would expect that all containments are being removed. However, since clean copies are being used for counting, removing containments can cause wrong results, as containments might apply joins that can have an effect on the included rows, ie one would expect the containments to be kept.

Here's two tests to illustrate the behavior changes:

```
php
public function testCleanCopyContain()
{
	$table = TableRegistry::get('Articles');
	$table->hasMany('Comments');
... [Log Snipped] ...
	$this->assertEquals(3, $count);
}
```
