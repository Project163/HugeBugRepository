Title

Rare registry configurations may cause NUnit to fail

Description
Having recently upgraded my NUnit version on one of my old machines I got

```
NUnit-Console version 2.6.4.14350
Copyright (C) 2002-2012 Charlie Poole.
Copyright (C) 2002-2004 James W. Newkirk, Michael C. Two, Alexei A. Vorontsov.
Copyright (C) 2000-2002 Philip Craig.
All Rights Reserved.
... [Log Snipped] ...
   at NUnit.ConsoleRunner.ConsoleUi.Execute(ConsoleOptions options)
   at NUnit.ConsoleRunner.Runner.Main(String[] args)
```

Looking through the code and then at the registry, I found that I still had the .net 4 Beta 2 Windows Update Opt-in Key `HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\NET Framework Setup\NDP\v4B2WU` (see [URL]

While this particular case may affect about one other person who forgot to delete this key, it suggests that there may in future be other legitimate instances where keys beginning v may not be followed by a version number; and such keys should be skipped (possibly with a warning logged).
Discussion
- I copied this issue from nunit/nunit-console, where it was originally filed by @SteveGilham.
- We should fix this in 3.0 and also go through the code that accesses the registry and identify any other points where we are making assumptions about the registry content. That entire area of code should be written more defensively.
- I had the same issue in version 3.6.0 when using teamcity.
