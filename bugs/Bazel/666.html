Title

Bazel 0.22 prints repository rule modified arguments on every run

Description
### Description of the problem / feature request:

After [URL] which changed the log level from info to debug, the repository rule results are printed on every build command, even when they have not changed. For workspaces with many repository rules, this adds a lot of log spam to the day-to-day build logs.

### Bugs: what's the simplest, easiest way to reproduce this bug? Please provide a minimal example if possible.

Build a target in a workspace with a few repository rules on bazel 0.22. Observe the following output:

```
shell
λ bazel run //host/Applications/ImagingSandbox --config=asan
INFO: Invocation ID: 89861536-76f3-4f2d-b6b8-911ad430de41
DEBUG: Rule 'io_bazel_rules_go' modified arguments {"shallow_since": "1543610332 -0500"}
DEBUG: Rule 'com_github_bazelbuild_buildtools' modified arguments {"sha256": " "}
... [Log Snipped] ...
INFO: 0 processes.
INFO: Build completed successfully, 1 total action
```

### What operating system are you running Bazel on?

macOS 10.14.3

### What's the output of `bazel info release`?

release 0.22.0
Discussion
- Note that `debug` is a lower log level than `info`, i.e., whenever `debug` messages are printed, `info` messages are printed as well.


That I cannot reproduce (see example below). Debug information from the repository rules is only printed if it is advisable to change the definition of the repository rule (either directly in the `WORKSPACE` file, or by using a resolved file); will change the message to make this more obvious. In your example, bazel points out the following.

- A file is downloaded without a checksum being specified. Downloading files without verifying integrity can be a security issue; providing a hash also improves caching.

- A `git_repository` is used for a specific commit, but no reference date is given. Specifying a reference date allows users of the same `WORKSPACE` file to clone in a shallow way.

And here the example that I believe shows that the debug messages do not occur on a clean `WORKSPACE` file.

```
$ cat WORKSPACE
load("@bazel_tools//tools/build_defs/repo:http.bzl", "http_archive")

http_archive(
  name =  "ext",
... [Log Snipped] ...
(09:05:04) INFO: Build completed successfully, 1 total action
$
```
