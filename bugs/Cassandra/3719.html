Title

Repeated slices on RowSearchers are incorrect

Description
In  AbstractThreadUnsafePartition , repeated  slice()  calls on a  RowSearcher  can produce incorrect results.  This is caused by only performing a binary search over a sublist (based on  nextIdx ), but not taking  nextIdx  into account when using the search result index. 

 I made a quick fix in  this commit  on one of my branches, but the full fix also needs to cover  ReverseRowSearcher  and include a test to reproduce the issue.
Discussion
- It turns out that this is only really reproducible through mixed-version tests, because an  AbstractThreadUnsafeParitition.SliceableIterator  has to be used with a NamesFilter, and that seems to only occur when processing legacy responses (although I could be missing something).  In any case, my dtests for   CASSANDRA-9704   do cover this with  multi_in_compact_non_composite_test . 

 I verified that the behavior for  ReverseRowSearcher  is correct, so only  ForwardRowSearcher  was affected.
