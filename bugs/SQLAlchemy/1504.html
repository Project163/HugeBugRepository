Title

Add preserve_rowcount execution_option to momeize the rowcount in all cases

Description
### Describe the bug

Tring to migrate from psycopg2 to psycopg3 some queries.

Found that inserts do not return rowcount, even if the cursor correctly populates it.
Also while debugging this I've noticed that insertmanyvalues is not used in psycopg3, while is should (I think)

### Optional link from [URL] which documents the behavior that is expected

_No response_

### SQLAlchemy Version in Use

2.0.23 - any 2.0.x should be affected

### DBAPI (i.e. the database driver)

psycopg2 2.9.9; psycopg 3.1.17

### Database Vendor and Major Version

postgresql - any

### Python Version

python 3.10

### Operating system

any

### To Reproduce

```
python
import psycopg
import psycopg2
import sqlalchemy as sa

... [Log Snipped] ...
using_sqlalchemy_conn("psycopg2", echo=False)
using_sqlalchemy_conn("psycopg", echo=False)
```

Discussion
- INSERT statements that dont use RETURNING do not need to use insertmanyvalues.  an exception is made for psycopg2 because it has extremely slow executemany() performance that is unique to that driver.
- Ok that makes sense.

It's quite strange, adding returning makes the rowcount work in pg3. This looks like something strange is going on on pg3 for some reason.
```
py
import psycopg
import psycopg2
import sqlalchemy as sa

... [Log Snipped] ...
using_sqlalchemy_returning("psycopg2", echo=False)
using_sqlalchemy_returning("psycopg", echo=False)
```
prints the correct
```
sqlalchemy returning
psycopg2 insert values 3
psycopg2 insert select 6
psycopg2 insert values exec many 2
psycopg insert values 3
psycopg insert select 6
psycopg insert values exec many 2
```

will try to find what's causing this, but it seems not to be sqlalchemy. Will close if not
