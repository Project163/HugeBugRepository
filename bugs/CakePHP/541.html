Title

Use $validator->add() in validation always enforce view form input to has required attribute.

Description
I have validation of uniqueness of contacts:

``` php
$validator->add('value', 'unique', [
    'rule' => 'emailUniqe',
    'provider' => 'table'
]);
$validator->allowEmpty('value', function($context) {
    return $context['providers']['entity']->isNew();
});
```

By default `$validator->add()` enforce 'value' field to be not empty. But in my app logic I allow this value to be empty: if entity is new, then I skip to save this entity. If entity exists in database, then 'value' cannot be empty. In #3767 was added conditional emptiness validation to be closure.
But If I create form input in view:

``` php
echo $this->Form->input('value');
```

then html input 'value' has attribute `required="required"`. I can disable this value by using Form input attribute ['required' => false], but I think it should be disabled be default in this case.
Discussion
- What if you use `allowEmpty('value', 'create')` instead?
- I don't think there will be a simple way to make inputs execute the conditional methods to accurately determine whether or not a field is required. I think our options are always yes or always no.
