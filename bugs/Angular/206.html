Title

bug(Router) (Dart only) Router stops receiving updates after first error

Description
Branching from #7349 .

In Dart, subscribing to Router changes happens via the `ObservableWrapper` class, which [Link: always passes `cancelOnError: true`] when subscribing to the underlying `Stream` object. This has the effect that, after the first error (e.g. incorrect URL entered by the user), future updates are lost.

I am not familiar with the reasons behind unconditionally setting `cancelOnError: true`, but if that was not a hard requirement, perhaps just removing it or allowing setting it via an explicit argument would solve this issue.

- Having been educated in the ways of Rx and Observables I now understand that they should indeed close the observable stream when an error occurs.

Instead, I propose that we change the API to expose an Observable stream that contains a sequence of Router change events, which can have a status of either success:

```
{ status: 'success', next: ..., previous: ... }
```

or failure

```
{ status: 'fail', next: ..., previous: ... }
```
