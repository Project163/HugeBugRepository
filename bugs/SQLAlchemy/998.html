Title

`StatementError.__str__` can fail due to a lazy import

Description
**Describe the bug**

Sometimes exceptions propagate during the final GC cleanup, when the interpreter exits. At that point, you can't really import new modules, so you'd get some obscure behavior if you do try to. One example I've found is [URL]

This results in `sqlalchemy.exc.ProgrammingError:  `, which is pretty obscure.

**Expected behavior**

At the very least, the exception message should be reasonable (in this particular case, it should be `Cannot operate on a closed database`).

Then, I'm not quite sure if that particular code should result in the errors. Not sure what's closed the database in the first place, everything is in a context manager? What's more, it's not always happening (see "NOTE:" comments).
