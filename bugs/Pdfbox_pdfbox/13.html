 I just realized that there is another case which is not dealt with with my patch. 

 If the unbalanced parentheses issue happens on the last line in the object block, then the character to test for should be a '>" as well as a '/' 
But we don't have a test case for this,   (nextThreeBytes [1]  == 0x2f  ||  nextThreeBytes [1]  == 0x3e )))  // Look for a slash / or a > 

 Examples of possible issues: 

 /CreationDate (1/8/2003 12:18:53 )  
>>  
or  
/CreationDate  ((1/8/2003 12:18:53 )  
>>  

 It would mean adding the following change to the patch. 

 	             nextThreeBytes [1]  == 0x0a &&  // Look for a new line 
+	             (nextThreeBytes [2]  == 0x2f   ||  nextThreeBytes [1]  == 0x3e )) || // Look for a slash / or  a > 
+	                                           // Add a second case without a new line 
+	            (nextThreeBytes [0]  == 0x0d &&  // Look for a carriage return 
+	             (nextThreeBytes [1]  == 0x2f  ||  nextThreeBytes [1]  == 0x3e )))  // Look for a slash / or a >
