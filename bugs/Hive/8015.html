Title

Map partition key columns when pushing TNK op through select

Description
The following TPC-DS query fails at runtime when the table  store_sales  is an external JDBC table. 

  
 
 SELECT  ranking
 FROM 
    ( SELECT   rank ()  OVER  ( PARTITION   BY  ss_store_sk
         ORDER   BY   sum (ss_net_profit))  AS  ranking
      FROM  store_sales
      GROUP   BY  ss_store_sk) tmp1
 WHERE  ranking <= 5

Discussion
- The problem can be reproduced by running   external_jdbc_table_perf2.q      with  TestMiniLlapLocalCliDriver  

  
 
mvn test -Dtest=TestMiniLlapLocalCliDriver -Dqfile=external_jdbc_table_perf2.q -Dtest.output.overwrite
- The problem seems to be related with the TopN key optimization since disabling it ( set hive.optimize.topnkey=false ) makes the problem disappear.
- Wrong plan is generated after pushing TopNKey operator through Select operator. 
  
 
                TableScan
                  alias: store_sales
                  properties:
                    hive.sql.query SELECT  "ss_store_sk" , SUM( "ss_net_profit" ) AS  "$f1" 
FROM  "STORE_SALES" 
GROUP BY  "ss_store_sk" 
                    hive.sql.query.fieldNames ss_store_sk,$f1
                    hive.sql.query.fieldTypes  int ,decimal(17,2)
                    hive.sql.query.split  false

 Map-reduce partition columns contains an invalid column reference. It should reference columns by their names if the parent is TableScan like in the  keys  property.
