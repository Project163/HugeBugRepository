Title

Returning empty query expressions for association conditions generates invalid SQL

Description
I'm note quite sure whether this is a bug, as this usage seems neither documented nor tested (at least I couldn't find any explicit tests). I've seen it on Stackoverflow here

**[URL]

and noticed that returning the expression object like

```
php
$TableA->hasOne('TableB', [
    'className' => 'TableB',
    'foreignKey' => 'table_a_id',
    'conditions' => function ($e, $query) {
... [Log Snipped] ...
    }
]);
```

will result in an error as it will generate invalid SQL, specifically it will compile an empty set of parentheses into the `WHERE` clause, something like

``` sql
... WHERE (() AND x = y)
```

When adding conditions to the expression object it works fine, so I guess this just needs an empty check somewhere.
