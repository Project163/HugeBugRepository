Title

Thresholds over Trend metrics fail as the `med` sink's value remains zero

Description
### Brief summary

As reported by a user on the [Link: OSS support forum], there seems to be an issue with Thresholds applying to the median value of Trend metrics. Both core and custom metrics are affected.

Setting a threshold on a Trend metric's value, such as `http_req_duration`, will always fail, regardless of the expression used.

### k6 version

### OS

Docker + Linux

### Docker version and image (if applicable)

loadimpact/k6:latest

### Steps to reproduce the problem

Here is an example script demonstrating the issue. It depends on having [Link: Lhotse] running locally to simulate the desired performance of a target HTTP server. 

```
javascript
import { check } from "k6";
import http from "k6/http";
import { Trend } from "k6/metrics";

... [Log Snipped] ...
  customTrend.add(90);
}
```

In this example, both thresholds on the `http_req_duration`, and `custom_trend` will fail, although the performance of the target HTTP server, and the values fed into the Trend should lead them to pass.

### Expected behaviour

We would expect thresholds to pass.

### Actual behaviour

```
checks.........................: 100.00% ✓ 1                    ✗ 0  
   ✗ custom_trend...................: avg=80       min=70       med=80       max=90       p(90)=90       p(95)=90      
     data_received..................: 156 B   5.  B/s
     data_sent......................: 97 B    3.233102973992046 B/s
     http_req_blocked...............: avg=271.89µs min=271.89µs med=271.89µs max=271.89µs p(90)=271.89µs p(95)=271.89µs
... [Log Snipped] ...
     vus............................: 4       min=4                  max=4
     vus_max........................: 4       min=4                  max=4
```

Although the displayed median values are consistent with a threshold that should be passing, we observe the opposite.
Discussion
- I have traced back the issue to the [Link: `Thresholds.Run` method]. As I debug through the execution of this script's execution, the `ts.sinked["med"]` value remains `0`.
- I think this might be happening because we are not calling the `TrendSink`'s `Calc()` method, which is the thing that actually calculates and updates the value of `Med`: [URL]

Or at least I don't see where we are calling it in `Thresholds.Run()`, while it internally is called by both the percentile and the format methods:
[URL]
[URL]

And if there is a threshold on `med` for a `Trend` metric without a percentile threshold on the same metric to call `Calc()` eventually, the value of `Med` will never actually be calculated: [URL]

I might be missing something, but I think this is at least part of the problem. An easy workaround would be to just use `p(50)` instead of `med`, since they are basically the same thing, but this feels like a major bug :disappointed: Potentially enough for releasing v0.41.1 :thinking:
- ... [Middle Discussions Snipped for Brevity] ...
- This bug seems to have been introduced in k6 v0.37.0, probably due to the [Link: threshold refactoring there]. 

And, for anyone that has hit it, the workaround is to just replace `med` with `p(50)` in your threshold definitions. They are the same thing, after all, `med` is just there for convenience.
- Heads up, I've started working on a fix for this 👋🏻
