Title

stop referring to batches as atomic

Description
We still refer to logged batches as atomic, we should remove those references.
Discussion
- It would be more useful if you could point at where those references are. Also feel free to offer some suggestion of what you think we should use instead.
- There's a few references here:  [URL]

 Instead of: 

  By default, all operations in the batch are performed atomically. See the notes on UNLOGGED for more details.  

 how about: 

  By default, all operations in the batch are performed as LOGGED, to ensure all mutations eventually complete. See the notes on UNLOGGED for more details.  

 Replace: 
  By default, Cassandra uses a batch log to ensure all operations in a batch are applied atomically.   
 With: 
  By default, Cassandra uses a batch log to ensure all operations eventually complete.   

 Replace: 
  There is a performance penalty for batch atomicity when a batch spans multiple partitions. If you do not want to incur this penalty, you can tell Cassandra to skip the batchlog with the UNLOGGED option. If the UNLOGGED option is used, operations are only atomic within a single partition.  

 With: 
  There is a performance penalty for batch logging when a batch spans multiple partitions. If you do not want to incur this penalty, you can tell Cassandra to skip the batchlog with the UNLOGGED option.
- Alright, I committed some minor variations of what's above. Closing, thanks.
