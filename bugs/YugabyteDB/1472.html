Title

[YSQL] False negative catcache hits with minimal preload + negative caching

Description
Jira Link: [Link: DB-19288]
### Description

After a catcache is preloaded, we set `yb_cc_is_fully_loaded=true` for that cache. Whenever a lookup gets a miss on a cache with `yb_cc_is_fully_loaded=true`, we treat it like a negative entry (when negative caching is enabled). 

When `ysql_minimal_catalog_caches_preload` is enabled, we preload catcaches with only the rows corresponding to system entities.

However, even with `ysql_minimal_catalog_caches_preload`, we still set `yb_cc_is_fully_loaded=true`, meaning that the cache is now partially filled with only system entries, and we assume that all the remaining rows do not exist.

This leads to the system thinking that user objects do not exist. Example repro:

Start a cluster with `ysql_minimal_catalog_caches_preload=true`

Start connection 1:
```
CREATE TYPE user_color AS ENUM ('red', 'green', 'blue');
CREATE TABLE user_enum_table (c user_color);
```

Start connection 2:
```
SET yb_neg_catcache_ids='23,24';
INSERT INTO user_enum_table VALUES ('red');
```
The `INSERT` fails with `ERROR:  invalid input value for enum user_color: "red"`.
