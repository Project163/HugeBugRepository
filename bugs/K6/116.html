Title

async setup does not create the data object

Description
### Brief summary

When using the async version of setup() the return value of the function call does not create the data object that should be passed in to the default function.

If you change back to a non-async setup call then the data object is set correctly.

### k6 version

0.44

### OS

Mac OS 13.1

### Docker version and image (if applicable)

_No response_

### Steps to reproduce the problem

export async function setup() {
    return {data: "Arbitrary value here"}
}

export default function (data) {
    console.log(data)
}

### Expected behaviour

The data object is created and the console log would display an object { data: "Arbitrary value here" }

### Actual behaviour

The console log will display an empty object.

- Hi, thanks for opening this issue.

Unfortunately, async `setup()` is not supported yet. So this is not really a bug, but a feature request.

I can see how it would be useful, though in the meantime, you can resolve Promises with `.then()`, so you don't have to define `setup()` as async.
- It kind of is a bug though, since we kind of support `async` in both `setup()` and the default / scenario `exec` function - we don't throw an error and we wait for the event loop to clear :thinking: Try this:
```
js
import { setTimeout } from 'k6/experimental/timers'

export async function setup() {
    console.log('setup()')
... [Log Snipped] ...
    return new Promise(resolve => setTimeout(resolve, 2000, null))
}
```

We just don't "unpack" the result if we get it in a promise, but adding this to [Link: `js/runner.go`] seems to do the trick:
```
diff
diff --git a/js/runner.go b/js/runner.go
index 056bba774..4507c4ccd 100644
--- a/js/runner.go
+++ b/js/runner.go
... [Log Snipped] ...
 		return fmt.Errorf("error marshaling setup() data to JSON: %w", err)
 	}
```
- It also is a very old bug as this has been the case from when we have promises and event loop so almost a year since [Link: v0.37.0]. 

After all `async` means:
1. this will return a promise
2. you can use `await` inside the body

Here only number `1` is true and have been possible since we have Promises. The event loop just added ways for there to be stuff working on the result *off* the event loop. And now the `async`/`await` keywords support give us more ergonimic way to do this. 

To expand on @imiric workaround - I expect that you care about the result and it comes from an asynchronous call - let's say `http.asyncRequest`. In that case you will need to return an object and set a property of it in the `.then` so something like.
```
javascript 
import http from "k6/http"

export function setup() {
  let result = {}
... [Log Snipped] ...
  console.log(data.data)
}
```


As you can see you can even use `async` function within ;)
- Thanks @mstoykov interestingly I had tried using the .then() with a non async setup already and received no result as I was passing back the resulting data string directly, encapsulating it in an object as you suggested worked perfectly.
