- Hi @gfrench17,

thanks again for the very valueable bug report. :smiley:

**TL;DR: If you install mitmproxy from master, the issue should be fixed.**

 The issue you were seeing was a result of (a) OpenSSL's not-so-wonderful APIs and (b) a friendly CDN (CloudFlare) which now apparently rejects all connections without TLS Server Name Indication.
Due to OpenSSL's limited API, we can't detect that a connection hasn't sent an SNI request until it's too late for upstream certificate sniffing, so we have to establish a server connection without SNI beforehand and use that cert by default. However, CloudFront raises an SSL alert for connections without SNI, which kind of breaks our OpenSSL workaround. To cope for this, we now temporarily suppress the first failure and hope for a SNI from the client. If that doesn't happen, we raise the original error again.

Cheers,
Max
