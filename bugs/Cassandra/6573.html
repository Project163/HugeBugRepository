 When the node get restarted, 

 1. it first got gracefully shutdown, it will broadcast the GOSSIP_SHUTDOWN message to the rest of the cluster. 

 2. When it get back up, it will try to update it's generation and gossip with other nodes.

Discussion
- Assuming we have a very large delay in network  

 That is quite a delay!  But this does all make sense to me and adding a generation check sounds like the correct solution.
- in 5.0 we changed the logic to no longer mutate using local versions and instead the node shutting down sends its full state and the peers use that. 

 the previous logic had issues due to version values not being relative to the node that went down, which lead to the cluster not converging properly...  

 in 5.0 if sees this message after the node started up again, then we would override with the down state... but eventually should fix itself... we def could do a check here to be extra safe.
