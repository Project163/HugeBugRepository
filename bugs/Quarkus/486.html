Title

JDBC resources leaked when using `PanacheQuery .stream()`

Description
### Describe the bug
I have a method like this one:

```java
public Set  getThingsCalled(String name)
   return MyEntity. find("name", name).stream()
      .map(entity -> entity.toDomainObject())
      .collect(Collectors.toSet());
}
```

When executed, the following warning is printed in the logs:

```
2020-02-28 17:14:37,005 WARN  [io.agr.pool] (pool-5-thread-5) Datasource ' ': Closing open connection prior to commit
2020-02-28 17:14:37,005 WARN  [io.agr.pool] (pool-5-thread-5) Datasource ' ': JDBC resources leaked: 1 ResultSet(s) and 1 Statement(s)
```

If I change the method code to look like this:

```java
public Set  getThingsCalled(String name)
   List  entities = MyEntity. find("name", name).list();
   return entities.stream() 
      .map(entity -> entity.toDomainObject())
      .collect(Collectors.toSet());
}
```

then there is no warning in the logs.

Judging from the above, **it seams to me that the implementation of `stream()` method of `PanacheQuery ` does not handle DB resources properly**. According to [URL] the issue started to appear after `1.0.0.CR1`

### Environment
 - Java version:  1.8.0_172
 - Quarkus version: 1.2.1.Final
 - Build tool: Maven 3.6.2 

### Additional context
Not sure how relevant it is but the actual code runs on separate thread inside user managed transaction. The way the method is called looks more or less like this:

```
java
@Inject protected TransactionManager tm;
...
executor().execute(() -> {
   try {
... [Log Snipped] ...
   }

```

I wouldn't be surprised if the thread and transaction management contribute to the issue.
That said, I still believe there is a bug since `list()` method works fine (or so it seams) while `stream()` does not in the very same context.
