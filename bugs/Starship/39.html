Title

`$HOME/.Rprofile` should be ignored

Description
#### Current Behavior
When there's `.Rprofile` under `$HOME`, `starship` detects it and shows the section for R-lang in prompt..

#### Expected Behavior
`$HOME/.Rprofile` is the user-wide profile and should be ignored.


See [URL]

#### Possible Solution
- When seeing `.Rprofile`, ignore it if it's in `$HOME`.
- Alternatively, treat `$HOME` differently for all languages.

- Hi @lebensterben, while not idea you should be able to work around this issue by adding the following to your starship config file 

```toml 
[rlang] 
detect_files = [] 
```
- That would disable the module in project folders with `.R`/`.Rmd`/etc. files though, right?

I came here because I was looking for a solution to this, and was wondering if the `when` config option for custom modules could maybe be supported for other modules as well?
E.g. `when = ''' test "$HOME" != "$PWD" '''`

But then again, if _any of_ `when`, `detect_files` and `detect_folders` are sufficient to trigger the module, then that's likely not sufficient either :/
- @jemus42 Adding [Link: negative matching] works for me
```toml
[rlang]

```
