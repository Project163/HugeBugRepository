Title

IdentitiesOnly=yes ssh argument not passed by ansible provisioner

Description
Version: 1.7.1

This argument is passed in `vagrant ssh` but not `vagrant provision`. Causing issues with provisioning when the host have 5+ ssh keys.

Edit: I only observed in the ansible provisioning. Not sure about others.
Discussion
- Can you please share you Vagrantfile and the debug output in a gist?
- I'm having some trouble scrubbing all the info from the debug output. However I don't think it's really needed. However, here's the command that vagrant used to start ansible during `ansible provision`:

```
PYTHONUNBUFFERED=1 ANSIBLE_FORCE_COLOR=true ANSIBLE_HOST_KEY_CHECKING=false ANSIBLE_SSH_ARGS='-o UserKnownHostsFile=/dev/null -o ControlMaster=auto -o ControlPersist=60s' ansible-playbook --private-key=/path/to/project/.vagrant/machines/default/virtualbox/private_key --user=vagrant --connection=ssh --limit='default' --inventory-file=/path/to/project/.vagrant/provisioners/ansible/inventory --sudo provisioning/setup.yml
```

Note that `-o IdentitiesOnly=yes` is missing from it.

If you connect with vagrant ssh, you'll see this line (with IdentitiesOnly=yes):

```
INFO ssh: Invoking SSH: ["vagrant@ ", "-p", "2222", "-o", "Compression=yes", "-o", "DSAAuthentication=yes", "-o", "LogLevel=FATAL", "-o", "StrictHostKeyChecking=no", "-o", "UserKnownHostsFile=/dev/null", "-o", "IdentitiesOnly=yes", "-i", "/path/to/project/.vagrant/machines/default/virtualbox/private_key"]
```

If you're not familiar with `IdentitiesOnly`, this is the documentation on it:

The implication without `IdentitiesOnly=yes` is that if the user has more than something like 5 ssh keys, it will offer them all in some order (I'm not sure how it is ordered) to the server. After 5 keys, the connection will fail with too many authentication failures. 

So the simple workaround is adding `IdentitiesOnly=yes` to the raw_ssh_args for ansible in the Vagrantfile, but it would be nice to have vagrant do this itself, as it already does this for vagrant ssh. I'm not familiar enough with Vagrant's code base to pinpoint where the best location is to add this. I've found [Link: this], but I'm not sure if that's the correct location to add this argument.
