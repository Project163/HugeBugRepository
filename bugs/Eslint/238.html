Title

func-names incorrectly errors on get/set/shorthand methods.

Description
### Abstract

`func-names` rule errors for valid getter/setter and es6 shorthand functions
### Details

Given the following JS:

``` js
exports = {
  get foo() {
     return 1;
   }
 };
```

This produces the following Esprima syntax tree (trimmed for brevity & relevancy):

```
json
 "properties": [{
    "type": "Property",
    "key": {
        "type": "Identifier",
... [Log Snipped] ...
    "shorthand": false
}]
```

Given the following ES6 JS:

``` js
exports = {
    foo() {
        return 1;
    }
};
```

This produces the following Esprima syntax tree (trimmed for brevity & relevancy):

```
json
"properties": [{
    "type": "Property",
    "key": {
        "type": "Identifier",
... [Log Snipped] ...
    "shorthand": false
}]
```

func-names looks for `FunctionExpression` tokens, and attempts to ensure the expression has a name. However, in the case of a getter/setter/shorthand it doesn't (the name is the property name). This means func-names errors on this code snippet with `error  Missing function expression name`.
### Solution

`func-names` needs to check the `kind` flag. If it is `'get'`, `'set'` or `'init'` then func-names should not attempt to validate the name.
