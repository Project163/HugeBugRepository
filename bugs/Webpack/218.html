Title

Webpack incorrectly removes parentheses around complex constructor expression

Description
# Bug report

Webpack is generating output that drops parentheses around a constructor expression when it shouldn't be. SWC/esbuild transform complex constructor expressions one way, and Babel does it another way. Webpack 5 currently only correctly handles the form that Babel produces.

More details are described in the reproduction repo linked below.

**What is the current behavior?**

Given the following input:

```javascript
const a = new (require('url').URL)('file:' + __filename).href
const b = new (require('url')).URL('file:' + __filename).href
console.log(a, b);
```

webpack produces the following

```javascript
var __filename = "/index.js";
const a = new (__webpack_require__(/*! url */ "url").URL)('file:' + __filename).href
const b = new __webpack_require__(/*! url */ "url").URL('file:' + __filename).href
console.log(a, b);
```

This code is _not_ equivalent to the source input. Running the above will produce a runtime error


**If the current behavior is a bug, please provide the steps to reproduce.**

[URL]

I've provided several scripts to help demonstrate the issue:

```console
$ yarn build-webpack
$ yarn build-babel
$ yarn build-esbuild
$ yarn build-swc
```

Additionally, a JS loader can be enabled in `webpack.config.js` by uncommenting the loader config and swapping
`(babel|esbuild|swc)-loader` to see their effect on webpack output.

 
 
 
 
 
 

**What is the expected behavior?**

The generated code for `b` should should have parentheses around its `__webpack_require` expression.
