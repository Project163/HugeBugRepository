Title

`ecs@mappings` template breaks dynamic mapping of intermediate object fields

Description
### Elasticsearch Version

  (8.12-SNAPSHOT)

### Installed Plugins

_No response_

### Java Version

_bundled_

### OS Version

Linux

### Problem Description

The `ecs@mappings` component template's dynamic templates unintentionally match dynamically mapped object fields, attempting to map them as non-object field types, breaking ingestion of that object's child properties.

For example, the dynamic template [Link: `ecs_usage_scaled_float`] will match the "usage" object when dynamically mapping `a.usage.b: 123`.

### Steps to Reproduce

```
PUT /_index_template/xyz
{
  "index_patterns": ["xyz"],
  "composed_of": ["ecs@mappings"],
  "template": {
... [Log Snipped] ...
  "a.usage.b": 123
}
```

```
{
  "error": {
    "root_cause": [
      {
        "type": "illegal_argument_exception",
... [Log Snipped] ...
  "status": 400
}
```

(Also that error message is completely unhelpful.)

Discussion
- P.S. this is not a hypothetical issue, it affects dynamic mapping of the metric field `system.process.cgroup.memory.mem.usage.bytes` when using that component template.
- Pinging @elastic/es-data-management (Team:Data Management)
- #102795 proposes to fix this issue with changing the [Link: `*.usage` dynamic template] as follows:
```
{
          "ecs_usage_scaled_float": {
            "mapping": {
              "type": "scaled_float",
              "scaling_factor": 1000
... [Log Snipped] ...
          }
        }
```
While this fixes the reported issue, it still leaves room for other failures, for example when ingesting a document that contains:
```
        {
          "chair.usage": "sitting"
        }
```

Therefore, #102807 may be preferable as it would allow to do:
```
{
          "ecs_usage_scaled_float": {
            "mapping": {
              "type": "scaled_float",
              "scaling_factor": 1000
... [Log Snipped] ...
          }
        }
```
- Pinging @elastic/es-search (Team:Search)
