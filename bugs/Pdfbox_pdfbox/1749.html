Title

Long rendering time

Description
Attached pdf file takes too long (more then 9 secs) to render in PDFDebugger (this is a simplified version of a real life pdf that I can not publish for privacy reasons, it takes 57 seconds to render and it contains 56 images and some text). 

 I have tried with the options provided in  [URL] but performance is the same
Discussion
- The page contains 11 300dpi JPEG images, it is similar to the files in   PDFBOX-1350   and   PDFBOX-2035  .
- Some thoughts after profiling... Most time is spent in 
 
	 graphics.drawImage - this we can't change, or the quality would go down 
	 ImageReader.read - can't change 
	 DCTFilter.fromBGRtoRGB - maybe write on the source raster instead of making a copy? Won't make it faster but will lessen the memory footprint. 
	 ScratchFileBuffer.read - it is called with small chunks in SampledImageReader.from8bit, the bytes for 1 pixel, thus usually only 3 bytes at a time. This was done in   PDFBOX-2301   [  [URL] ] to lessen the memory footprint. Reverting that change makes it about 20% faster but increases the memory footprint, obviously. Maybe make a compromise by reading one row at a time.
- ... [Middle Discussions Snipped for Brevity] ...
- I tried with the snapshot. It takes 7,97 secs now in my computer. 

 Rendering time for the real life pdf decreased from 57 secs to 48 secs.
- I'll do the memory optimization in DCTFilter.java after the release because I want to have more time for feedback.  
 I tested different -Xmx options. Without the change (keep using  raster.createCompatibleWritableRaster() ) it works with -Xmx140m but not 130. With the change (cast existing raster) it needs -Xmx160m to render the file. Very weird... so I'll leave that one untouched.
