Title

Webpack 3 bug when using ModuleConcatenationPlugin

Description
**Do you want to request a *feature* or report a *bug*?**

I found a bug I found in Webpack 3 when using `ModuleConcatenationPlugin`.

**What is the current behavior?**

Webpack is producing `__webpack_require__(null)`.

**If the current behavior is a bug, please provide the steps to reproduce.**

An example of the issue is here in this repository I made reproducing the problem:
[URL]

Install and re-build run as usual:
```bash
npm install
npm run build
```

Relevant files producing the error are `entry.js` and `vars.js`.

**What is the expected behavior?**

Webpack should produce `__webpack_require__(0)` (for the example).

**Please mention other relevant information such as the browser version, Node.js version, webpack version and Operating System.**

I'm using Webpack 3.5.5 and Node.js v8.4.0 under macOS.

The bug comes from this line: [URL] where `dep.module.id` is `null`.

I fixed it by setting the `module.id` (if there isn't one already) by inserting the following code to [URL]
```javascript
if (dep.originModule.id === null) {
	dep.originModule.id = dep.originModule.index;
}
```

Now, I'm sure that's probably not the best approach and I'd love to see this fixed as it's something that is a showstopper for me.

The issue reported in [URL] is probably related.
