Title

negative number can be used as key for map

Description
e:\temp\demo.groovy: 1: unexpected token: : @ line 1, column 28. 
   m = [1:"a", 2:"B", 0:"c", -2:"d"] ; 
                              ^1 Errors 
for my groovy file: 

 m = [1:"a", 2:"B", 0:"c", -2:"d"] ; 
println m;
Discussion
- There's no reason why we shouldn't put negative numbers as keys for a Map!
- Why negative number can't be the key of a map, I think it's a basic feature for map. I really can't accept this decision. Is it difficult to implement this feature?
- ... [Middle Discussions Snipped for Brevity] ...
- This is not a bug in the implementation; it is a feature of the design. 
Even though '-2' seems like a simple numeric literal, it is not; it is an expression. 
Items before label-colon must be simple identifiers or literals. 
If you mean to have a complex expression, use parentheses. 

 To address the problem of user surprise, I've put a diagnostic in the 
parser which will guide users around this issue. 

 I thought about making a special case for  [-1:foo] . 
But that just moves the surprises around on a slippery slope. 
(What about foo(!x: y), what about  
{println -2}
 .) 
It's better to diganose the problem in the parser, and 
require the user to be a little more explicit.
- This is a reasonable user error with an unreasonable parser diagnostic.
