Discussion
- Okay, apparently the CLI Option `--stderr` doesn't work on Windows, as the build still fails for them. At least in combination with `.phpt` type tests...
- Maybe for better understanding / reference:

The failing test uses print to output the content of the recorded trace from the file. This writes to the same output stream as PHPUnit's other outputs and, apparently, on GH Actions that causes a problem.

My fix was to simply have PHPUnit write the regular output to `stderr`. That works flawlessly on my box as well as on the linux based matrix builds. Apparently, for the Windows builds the `--stderr` switch doesn't have the same effect.
- I'm confused ;)

Looking at the Code that runs PHPT's, `stdErr` redirection is enabled. So my change shouldn't have had any effect?

I tried to use `--CAPTURE_STDIO--` for the test, but realized that PHPUnit's PHPT implementation doesn't support it.

I'm still convinced, based on how I understand the diff output for the failing test, the root cause is the mix of outputs. But maybe I'm totally off here ;)
- As of   we're now skipping this test on Windows.
