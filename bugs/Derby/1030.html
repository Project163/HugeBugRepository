Discussion
- The problem only happens when upgrading from
- I didn't fully debug this, but I theorize that what happens, is that the test framework attempts to create an EmbeddedSimpleDataSource, but instead of finding this with the 10.0 derby.jar, it finds the 10.3 version and uses that. Hence, the db is really created with 10.3 and the test fails. 

 I did a manual simple test, and created a   database (with one very simple table) using jdk15, then used JSR169 to upgrade to 10.3 with soft upgrade, then went back at it with jdk15 and that was fine. Then I used the simple 10.0 database with very simple table and did a hard upgrade to 10.3 with JSR169 and that was fine too. 

 I don't think we should automate that test, it was just to make sure upgrade from 10.0 works also for JSR169.
