Title

[YSQL] Incorrect results from the full PK scan when parallel mode is forced

Description
Jira Link: [Link: DB-12405]
### Description

Repro:
```
co=# \d part
                          Table "public.part"
    Column     |         Type          | Collation | Nullable | Default 
---------------+-----------------------+-----------+----------+---------
 p_partkey     | integer               |           | not null | 
... [Log Snipped] ...
 182436
(1 row)
```
The reason is that upon the first invocation PgDmlRead::Exec removes primary key binds and puts ybctid into the request instead.
After request is done, the ybctid is gone, too, and subsequent execs with new bounds make full scans of the respective ranges instead.
