Title

HevcConfig.parse misreads reserved bit

Description
### ExoPlayer Version

2.18.0

### Devices that reproduce the issue

N/A

### Devices that do not reproduce the issue

N/A

### Reproducible in the demo app?

Not tested

### Reproduction steps

Attempt to play an MP4 or MKV file with an HEVC stream having bit 6 set to 1 in the first byte of a NAL array in an `HEVCDecoderConfigurationRecord`.

### Expected result

HevcConfig.parse() should read the low 6 bits of the first byte to correctly determine the NAL type for each array.

### Actual result

Instead, it reads the low _7_ bits, incorrectly including the reserved bit. This is currently meant to always be 0, but could be given some kind of meaning in a future revision. This is very minor, but I happened to notice it while investigating another issue in the area, and figured I'd bring it up.

See [URL]

```
int nalUnitType = data.readUnsignedByte() & 0x7F; // completeness (1), nal_unit_type (7)
```
should instead be:
```
int nalUnitType = data.readUnsignedByte() & 0x3F; // completeness (1), reserved (1), nal_unit_type (6)
```
