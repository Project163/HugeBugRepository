Title

BUG: RequestHandler behaves inconsistently with debug on vs. off with .json extension

Description
I have an API that has RequestHandler component loaded in the ApiController::initialize() method
$this->loadComponent('RequestHandler');
I am passing a .json extension to a controller action paged() that uses the PaginatorComponent to return results
When debug is ON, everything works as expected - that is, it displays my data in a json format in an unstyled layout. But when debug is turned off, with no other changes, Cake (Router) throws an exception - the action cannot be found. 

Additionally, the styled layout is shown. 

2014-11-05 19:34:57 Error: [Cake\Controller\Exception\MissingActionException] Action ApiController::paged.json() could not be found, or is not accessible.
Exception Attributes: array (
  'controller' => 'ApiController',
  'action' => 'paged.json',
  'prefix' => '',
  'plugin' => 'Api',
)

(Both the cache and tmp files are purged before each request)

So the .json is correctly stripped to create a correct action/method name (or request param if one trails it) when debug is on, but not when it's off. 

It appears to be a bug. 

This is Cake 3.0.0-beta2 on PHP 5.5.10, fyi

- ... [Middle Discussions Snipped for Brevity] ...
- DebugKit using extensions should only enable the json extension for routes connected in the plugin prefix. However, it looks like applying an extension in one scope will make it apply to other scopes as the RouteCollection maintains a list of all the extensions that could possibly be handled.  This is primarily to afford backwards compatibility for `Router::parseExtensions()`. I think separating the default/global extensions and extensions used in each scope might be a good solution to this issue.
