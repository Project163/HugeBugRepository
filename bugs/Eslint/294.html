Title

Using built-in tag via JSX literal incorrectly counts as variable usage

Description
Minimal reproducing scenario:

``` jsx
var div = 1;
React.render( );
```

I would expect this to warn on unused `div` variable, but it does not.

React is in the process of removing the tag whitelist in JSX - it's slated to land in React 0.13 (facebook/react#2746).

The current rule is that JSX tags beginning with a lowercase character will transform to a string, and others will transform to a variable. I guess it's an open question whether this can be considered a part of the "JSX spec", or a react-specific implementation details

This logic to special-case tags that start with a lowercase character already exists in the no-undef rule, so the suggested fix is just to port this over to no-unused-vars.
Discussion
- Seems like this special case is specific to react. Maybe we should remove this special case logic from `no-undef` or at least make it an opt-in option.
- It's tricky to say, the only other JSX compilers I could find were [URL] and [URL]

Their examples all show using lowercase strings, and from reading their implementations they appear to follow React's rules about strings vs variables.
