Title

copyTextureToTexture(): Wrong processing of mipmaps

Description
##### Description of the problem

There is something seriously wrong with the dataTexture and copyTextureToTexture functions. 
I was struggling for many days with this issue until I was convinced that this is a three.js bug.

When I upload an image to texture1 and then copy that texture to a datatexture texture2, I cannot use the minFilter and magFilters for mipmaps at all (LinearMipmapLinearFilter and LinearFilter correspondingly) for the destination datatexture, as the texture will not be rendered, so the only option is to enjoy wild aliasing artifacts when applied to a moving plane or other object.

In order to make sure that this is a three.js bug, I added the WEBGL equivalent functions on an example WEBGL code and I was able to use mipmaps and filtering on the destination data texture with no problems at all.
