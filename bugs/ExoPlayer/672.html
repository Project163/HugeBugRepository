Title

CastPlayer.getDuration() returns -1000 for live streams

Description
### [REQUIRED] Issue description
`CastPlayer.getDuration()` always seems to return `-1000` when casting a live stream. This duration eventually becomes  the `TimeBar`'s duration, which causes the scrubber to disappear, leaving you unable to timeshift the live stream.

I have tried setting the `StreamType` to `MediaInfo.STREAM_TYPE_LIVE`, but it didn't help.

A possible workaround seems to be:
```
kotlin
override fun getDuration(): Long {
    val remoteMediaClient = remoteMediaClient ?: return super.getDuration()
    val seekableDuration = remoteMediaClient.approximateLiveSeekableRangeEnd - remoteMediaClient.approximateLiveSeekableRangeStart

... [Log Snipped] ...
    }
}
```

However, this doesn't solve the `TimeBar` issue, since its duration is based on the `Timeline`'s duration.

### [REQUIRED] Reproduction steps
1. Cast a live stream
2. Call `CastPlayer.getDuration()`
3. The result of the above above function call is `-1000`

One thing that is not working correctly however is timeshift. Even with the workaround applied, timeshift was not working correctly (the time was moving too fast and seeking would not seek to the correct position). I had to override the following methods to make timeshift work properly for live streams:

```
kotlin
override fun seekTo(windowIndex: Int, positionMs: Long) {
    val approximateLiveSeekableRangeStart = remoteMediaClient?.approximateLiveSeekableRangeStart
            ?: 0
    super.seekTo(windowIndex, positionMs + approximateLiveSeekableRangeStart)

    }
}
```
