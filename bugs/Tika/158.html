Title

Tika hangs on corrupt zip files

Description
We ran into an issue recently where Tika's AutoDetectParser hung on a corrupt zip file. 
(CPU load constantly at 100%, and the call to AutoDetectParser's parse never returned). 

 I traced it to a bug in Commons Compress 1.0 :  [URL] which has been fixed in their latest trunk. 

 When I try Tika on the same zipfile with a locally built commons-compress-1.1-SNAPSHOT.jar (from SVN r925271) everything works correctly and Tika just throws a TikaException. 

 Would it be possible to upgrade to the latest Commons Compress trunk ? 

 Thanks.
Discussion
- IMHO it would be a better idea to campaign for a compress 1.1 release. 

 The trunk contains fixes to issues   COMPRESS-73  ,   COMPRESS-87   and   COMPRESS-89   which are relevant to Aperture. We've been using a snapshot version since last August. 

 There is a thread on commons-dev, Let's call for some "Release early, release often"
- Agreed, I'll keep an eye on dev@commons to see if I can help push out the release.
- In revision 987074 I upgraded Tika to use Commons Compress 1.1. That should solve this problem.
