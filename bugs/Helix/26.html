Title

`apply_workspace_edit` panic on Windows due to inconsistent letter case in file path

Description
HI! Performing a code action on Windows would panic:
```
thread 'main' panicked at 'assertion failed: `(left == right)`
  left: `Url { scheme: "file", cannot_be_a_base: false, username: "", password: None, host: None, port: None, path: "/C:/path/to/project/src/main.rs", query: None, fragment: None }`,
 right: `Url { scheme: "file", cannot_be_a_base: false, username: "", password: None, host: None, port: None, path: "/c:/path/to/project/src/main.rs", query: None, fragment: None }`', helix-term\src\commands.rs:2486:21
stack backtrace:
   0: std::panicking::begin_panic_handler
... [Log Snipped] ...
   5: helix_term::commands::apply_workspace_edit
...
```

Notice the upper case ```C:``` and lower case ```c:``` cause this.
Even though NTFS can be configured as case-sensitive, and [Link: Windows CreateFile API provides a flag to enable posix behavior, eg, case-sensitive file path], I don't think they are widely used. Most people on windows seem to just stick with the default case-insensitive file system, and developers tend to do the same. So do we just convert that paths to all lower case on Windows before checking them or do we provide an entry in configuration, or do we detect what file system helix is working in and check accordingly?
