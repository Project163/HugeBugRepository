Title

Serviceworkers `prerendered` paths incorrect with `trailingSlash: 'always'`

Description
### Describe the bug

When having set `trailingSlash` to `'always'`, the paths for page-endpoints (`__data.json`) and endpoints like `sitemap.xml` in the `prerendered` variable of the `$service-worker` module are normalized to have a trailing slash.

Discussion
- That change was part of #4699, whose intent was to fix bugs like #4294. Reverting that specific change (which removes the special treatment of filenames with `.` in them) would undo the fix for #4294.

In the PR description of #4699, @Rich-Harris wrote that the `trailingSlash` option would now apply only to pages, and not be applied to endpoints. So I think this is just a bug that was missed when #4699 was written. Thanks for the reproduction; that'll be useful in solving it.
- Yea, i thought something like that was the reason for this change.

The Problem is, in prerendering, we don't know if it is an endpoint or not.

I guess, the only thing we could do, is strip the trailingSlash of again, if the last part has a `.` here: [URL]
