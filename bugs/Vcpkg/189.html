Title

[opusfile] Build error with opusurl on Windows

Description
**Host Environment**

- OS: Windows 11
- Compiler: MSVC v143, cl version 19.34.31937
- vcpkg-tool version: 2023-01-24- 
- vcpkg-scripts version: 36fb23307 2023-02-10 (3 hours ago)

**To Reproduce**

Steps to reproduce the behavior:

`./vcpkg install opusfile[opusurl]`

**Failure logs**

Console output:

```
Computing installation plan...
The following packages will be built and installed:
    opusfile[core,opusurl]:x64-windows -> 0.12#2
Detecting compiler hash for triplet x64-windows...
Installing 1/1 opusfile:x64-windows...
... [Log Snipped] ...

Please use the prefilled template from D:\git\vcpkg\installed\vcpkg\issue_body.md when reporting your issue.
```

Log file: [Link: install-x64-windows-dbg-out.log]

**Additional context**

Build works on Linux (`x64-linux`) and macOS (`x64-osx` and `arm64-osx`). Only Windows triplets (`x64-windows`, `x64-windows-static`, and `x86-windows`) seems affected.

This issue was noticed in #29511 but was already present before this PR.
Discussion
- Reproducible with x64-mingw-dynamic (linux host).
- AFAICS there is no public definition backing `typedef struct x509_lookup_st X509_LOOKUP;` from `openssl/types.h`.
`wincerts.c` was added in 2013, and no significant updates have been done since this time:
[URL]
Probably this code already broke with openssl 1.1: 
[URL]

IMO feature `opusfile[opusurl]` should be marked unsupported on windows. This is the state of upstream with regard to maintained version of openssl.
- Confirmed, reproduced on windows(x64-windows, x64-windows-static, x86-windows).
