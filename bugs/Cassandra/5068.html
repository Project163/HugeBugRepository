Title

Revert 4.0 GC alg back to CMS

Description
CASSANDRA-9608   accidentally swapped the default GC algorithm from CMS to G1. Until further community consensus is achieved about swapping the default alg, we should switch back to CMS. 

 As reported by  rustyrazorblade  on the  dev@ ML
Discussion
- Using the  previous, 3.11 settings  as a guide, reverting the java8 settings was simple. However, java11 was not as trivial. A naive reenabling of java8's GC settings yielded: 

  
 Unrecognized VM option 'UseParNewGC'                                                                                                                                                                               
Error: Could not create the Java Virtual Machine.
Error: A fatal exception has occurred. Program will exit.
 
  

  UseParNewGC  was deprecated in java 9 and  removed in java 10 . Once that flag is removed, cassandra can start and run properly. However, this is this log statement upon process start: 

  
 OpenJDK 64-Bit Server VM warning: Option UseConcMarkSweepGC was deprecated in version 9.0 and will likely be removed in a future release.                                                                          
 
  

 For those who haven't been playing along with every gyration of the JDK, the  CMS collector is deprecated . However, CMS  might not be removed , but might not be supported directly by the OpenJDK project. 

 Either way, it appears that simply removing  UseParNewGC  form the java 11 config gets us back to on-par with the java 8 config.
