Title

Weird problem when using interface + class for JAX-RS Resources + Auth

Description
### Describe the bug

When using interfaces with JAX-RS annotations plus classes without those annotations + `@RolesRequired`, there seems to be a weird problem.

Logs:
```
CDI: programmatic lookup problem detected
-----------------------------------------
At least one bean matched the required type and qualifiers but was marked as unused and removed during build

Stack frame: io.quarkus.resteasy.reactive.server.runtime.security.EagerSecurityHandler.handle(EagerSecurityHandler.java:62)
... [Log Snipped] ...
	at io.quarkus.vertx.http.runtime.security.HttpSecurityRecorder$2$2$1.onItem(HttpSecurityRecorder.java:137)
	at io.quarkus.vertx.http.runtime.security.HttpSecurityRecorder$2$2$1.onItem(HttpSecurityRecorder.java:127)
```
This problem can be kinda solved by adding this bean to the unremovable beans list by config. 
But, by doing so, any JAX-RS custom exception mappers for Forbidden and Unauthorized seem to stop working.

### Expected behavior

Requests with correct Auth return 200.
Requests with invalid Auth return 401, using custom JAX-RS exception mapper.
Requests without necessary roles return 403, using custom JAX-RS exception mapper.

### Actual behavior

All requests return 500.

After adding the bean to the unremovable list,

Requests with correct Auth return 200.
Requests with invalid Auth return 401, using default response.
Requests without necessary roles return 403, using default response.
