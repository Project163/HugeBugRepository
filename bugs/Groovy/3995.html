		println( 'set  boolean  to  null ' )

	}

Discussion
- The changement of the behaviour came with the version 2.5.13. With groovy 2.5.12 no exception. 

 By comparing the java bytecode compiled by groovyc then decompiled we can see a difference in the code generated to affect a value to the boolean field ;  

 
	  with Groovy 2.5.12 :
  
 
     Object  object =  null ;
    ScriptBytecodeAdapter.setGroovyObjectProperty( Boolean .valueOf(DefaultTypeTransformation.booleanUnbox(object)), _f_closure1.class, (GroovyObject) this ,  "b" );
 
   
	  with Groovy 2.5.13 :
  
 
     Object  object =  null ;
    ScriptBytecodeAdapter.setGroovyObjectProperty(object, _f_closure1.class, (GroovyObject) this ,  "b" );
- This was the direct result of changes for   GROOVY-7701  :  [URL]

 Prior to visiting the variable "b" in "b = null", there was a type lookup and groovy cast.  "b" must be visited first to know its type confidently.  Within a closure, "b" could resolve to anything. 

 Now that the call  ScriptBytecodeAdapter.setGroovyObjectProperty(null, _f_closure1.class, (GroovyObject)this, "b")  is written for the closure, DefaultTypeTransformation.booleanUnbox may need to be added within setGroovyObjectProperty.
