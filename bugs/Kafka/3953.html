- Hi  lianetm , 
  The expectation is that the new consumer does not send a HB request if there's a previous one in-flight  
   
However, when membershipManager().state() is MemberState.LEAVING, the result of canSendRequest() will be ignored. 
 
	  [URL]
 

 The memberState will transite to LEAVING state after process UnsubscribeEvent application event.  
 
	  process(final UnsubscribeEvent event)  
	  membershipManager().leaveGroup()  
	  transitionToSendingLeaveGroup(false)
- That is a trade off. 

 If we don’t allow to have two heartbeat request, we may lose leave request when previous non-leave request is in-flight. 

 If we allow to have two heartbeat request, we may send leave group with empty member before getting member id from previous request. 

 That is why we need KIP-1082, allowing we send leave group with pre-defined member id even if previous request is not completed.
