Title

Namespace mismatch in samples that use SimpleStockQuoteService

Description
According to the WSDL generated by Axis2, SimpleStockQuoteService uses two namespaces (i.e. wsdl:types contains two xs:schema elements):  [URL] and  [URL] Responses from SimpleStockQuoteService use these two namespaces as expected. Unfortunately SimpleStockQuoteService is a POJO service and for this type of services, Axis2 doesn't check the namespaces used in request messages. 

 There are multiple samples that send messages to SimpleStockQuoteService that don't conform to the WSDL. E.g. sample 158 sends the following SOAP request:  

 <soapenv:Envelope xmlns:soapenv="[URL]  
  <soapenv:Body>  
    <ns0:getQuote xmlns:ns0="[URL]  
      <ns1:request xmlns:ns1="[URL]  
        <ns2:symbol xmlns:ns2="[URL]  
      </ns1:request>  
    </ns0:getQuote>  
  </soapenv:Body>  
</soapenv:Envelope>  

 This message doesn't conform to the WSDL of SimpleStockQuoteService because the "symbol" element is expected to be in the  [URL] namespace, not in  [URL]

 Even the code of the test client (see the StockQuoteHandler class) uses the wrong namespaces, as shown in the following piece of code: 

     /**

	 </m:GetQuote> 
	 @param symbol the stock symbol 
	 @return OMElement for SOAP body 
     */ 
    public static OMElement createStandardQuoteRequest(String symbol, int itrCount)
