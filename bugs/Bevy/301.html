Title

Bloom not restricted to cameras with BloomSettings?

Description
## Bevy version

- latest main
- bevy 0.9
- PR #6677 as of 1/27


## What you did

I want bloom to be applied only to a subset of my scene, so I added a separate camera with `BloomSettings`.

```
rust
use bevy::{
    core_pipeline::{bloom::BloomSettings, clear_color::ClearColorConfig},
    prelude::*,
    render::view::RenderLayers,
... [Log Snipped] ...
    ));
}
```

## What went wrong

`BloomSettings` is only on the camera that renders the hexagon, so I expected only the hexagon to get bloom.

Instead, both shapes get bloom.

[Image: image]

## Additional information

It's not clear if this is user error, a known limitation, or a bug.
Discussion
- Reminder to myself to investigate this.
- Afaik the fix for this is to give each camera their own set of textures and then compositing them together after everything.

Ideally there'd be some system that would detect for each post processing effect if it's being run on all the views that are going to be composited together or not so you could run post processing after compositing if all views used a post-fx to avoid running the same post processing passes multiple times (which can be very expensive). However, his gets complicated very quickly due to certain effects having to run before others, and requires a better post-processing stack for creating and managing shaders.

This can also get quite expensive in terms of the VRAM and bandwidth cost of compositing all the different sets of textures together.
