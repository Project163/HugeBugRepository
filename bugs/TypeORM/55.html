Title

Serious issue on index creation for relation joined column (referencedColumn - propertyPath)

Description
Hi I have a serious issue regarding indices and relations and I would appreciate some assistance.

I have a normal one to many relation between 2 entities. 
Table B contains column AId that references table A.Id (primary key)
This is normal, but then I created an index on column AId.

The RelationJoinColumnBuilder created the relation and set the referencedColumn of AId to be A.Id
Then this referencedColumn participates on the propertyPath building (ColumnMetadata.buildPropertyPath) which concatenates the property names for the column and it's referencedColumn (this seems a bit weird). This results in a path Id.AId which is wrong.

Since the IndexMetadata tries to build the index by finding the columns on the table based on the propertyPath, this fails.

I am not sure how referencedColumn and propertyPath are used in the ORM. I believe that the error is on ColumnMetadata.buildPropertyPath, referenced column should not participate in the path. 
But again I am not sure.

I would need some assistance on that, it is rather serious and it is a blocker for me.

Thank you

- its a bit hard to explain but I'll try.

We need to build column property path because of two reasons:
* embeddeds, for example "post.counters.likes"
* referenced in relations columns, for example "post.category.id"

When we create a relation it defines a new column (lets say categoryId) and marks it as virtual.
Virtual means this column exist in the database but does not exist in entity defined by user.
This column has propertyPath equal to "category.id".

But when we create a relation and a column called exactly the same as relation suppose to create a column (we create a categoryId column inside our entity) orm does not create any extra column, thus does not mark anything as virtual. And such column propertyPath is just like any other column's property paths are - its equal to simply "categoryId".
