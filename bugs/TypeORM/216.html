**Steps to reproduce or a small repository showing the problem:**

```
ts
@Entity()
export class ChangeSet {
  @PrimaryColumn('uuid')
  public id: string;
... [Log Snipped] ...
  public forUserId: string;
}
```

In the above scenario, duplicate definitions created for the relation ID columns with _different names_ and duplicate FK constraints are generated with the _same names_. See the following migration output as an example:

```
ALTER TABLE "change_sets" ADD "forArtifactId" uuid
ALTER TABLE "change_sets" ADD "forUserId" uuid
ALTER TABLE "change_sets" ADD "initializerForartifactid" character varying NOT NULL
ALTER TABLE "change_sets" ADD "initializerForuserid" character varying NOT NULL
ALTER TABLE "change_sets" ADD "finalizerForartifactid" character varying NOT NULL
... [Log Snipped] ...
ALTER TABLE "change_sets" ADD CONSTRAINT "FK_f0e1be463c54638152058446def" FOREIGN KEY ("forArtifactId") REFERENCES "artifacts"("id")
ALTER TABLE "change_sets" ADD CONSTRAINT "FK_7c584ae18dac9a1d4fa42c2ab03" FOREIGN KEY ("forUserId") REFERENCES "users"("id")
```

I was able to partially work around the first issue of duplicate column definitions by tweaking the naming strategy, but currently the FK constraint name generation does not take into account the possibility of embedded parent prefixes.
