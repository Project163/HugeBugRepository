Title

3.0: __x function's `context` option is "lost"

Description
I'm not exactly sure, which package should be fixed, if it's the \Aura\Intl\Translator or the __x function.

The problem is, that when you pass a `$context` variable to the __x function it passes it on to the selected translator:

``` php
return I18n::translator()->translate($singular, ['_context' => $context] + $arguments);
```

However, when \Aura\Intl\Translator is used, the `_context` option is never checked in its `translate` method, which results in a translation not found, since the key in the translations lookup table looks like `[Context]\x04[Key]` and it tries to find `[Key]` instead.
Discussion
- Can you show your translation file, and the configuration you used for your I18n? Are you using any special formatter for messages?
- I've tried it on the skeleton app of cakephp 3.0-beta3 with the most simple example. My translation file looks like this:

```
code
#: Template/Pages/home.ctp:2
msgid "It should work"
msgstr "Tai turetu veikti"

... [Log Snipped] ...
msgid "This should not work"
msgstr "Tai neturetu veikti"
```

Running

``` php
echo __( 'It should work' );
```

will get translated as it should and output `Tai turetu veikti`, while running

``` php
echo __x( 'New Context', 'This should not work' );
```

will output an untranslated string `This should not work`
