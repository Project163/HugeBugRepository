Title

_cat/nodes API sorts number based on string instead of number value

Description
**Elasticsearch version** (`bin/elasticsearch --version`):
Elasticsearch 6.8.3

**OS version** (`uname -a` if on a Unix-like system):
CentOS 7.X

**Description of the problem including expected versus actual behavior**:
_cat/nodes API sort uses string sort on number values, should sort number columns by number value instead of string value.

**Steps to reproduce**:

Using:
`GET _cat/nodes?v\&h=name,disk.used_percent\&s=disk.used_percent:desc`

example result:
```
node1 80.18
node6 79.83
node3 78.78
node8 78.44
node5 69.78
node2 6.22
node4 5.57
node7 36.18
```
Discussion
- Pinging @elastic/es-core-features (:Core/Features/CAT APIs)
- Confirming this issue persists in 8.3.3

```diff
# GET _cat/nodes?v&s=disk.used_percent:desc&h=disk.used_percent

disk.used_percent
            97.78
-             9.89
-             8.11
            76.95
```
- The same issues is present for _cat/nodes :

```
# GET _cat/nodes?v&s=load_5m:desc&h=load_5m
load_5m
7.13
5.67
4.13
31.42          <== Should be the first
3.66
```
- For the issue on _cat/nodes, CPU loads are converted by String.format() in class RestNodesAction:
```java
table.addCell(
    hasLoadAverage == false || osStats.getCpu().getLoadAverage()[1] == -1
        ? null
        : String.format(Locale.ROOT, "%.2f", osStats.getCpu().getLoadAverage()[1])
);
```
Since format `%.2f` does not add leading 0, later when RestTable is sorted, String order is used.
A fix can be to use format `%06.2f` but result would be unesthetic :
```
load_5m
031.42
007.13
005.67
004.13
003.66
```
