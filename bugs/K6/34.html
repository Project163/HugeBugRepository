Title

Stop sending data to the Load Impact cloud when the test gets aborted

Description
Something like this should be avoided:
[Image: 07_09_2019__09_45_33]

Once the cloud test gets aborted by limit, k6 should stop sending data to the cloud. The load test itself probably shouldn't be aborted though, since it could have thresholds, an end-of-test summary and other outputs configured as well. On the other hand, manually aborting the test from the web app should probably also abort the local execution...

Maybe this would be a good opportunity to refactor the current [Link: `Collector` interface] to be both more suitable and more flexible, since it has been clear that it has some issues and is a poor fit for a lot of the outputs. There's both a lot of duplicated code between the outputs, and a lot of its methods like `SetRunStatus()` aren't implemented by the all outputs, since they don't need them. That, and the fact that currently the cloud output can't abort the test, makes it clear that we should rethink the `Collector` interface.

Edit: created a separate issue about refactoring of the `Collector` interface, since after some reflection, that issue turned out to be way bigger than this single instance: [URL]
