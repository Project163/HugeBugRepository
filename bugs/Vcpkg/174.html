Title

[zstr] zstr.hpp can't include strict_fstream.hpp due to being installed inside include/zstr

Description
**Host Environment**
- OS: Windows 10
- Compiler: Clang 11

**To Reproduce**
Steps to reproduce the behavior:
1. `[...]/vcpkg$ ./vcpkg install zstr`
2. Create these files:
- CMakeLists.txt:
```cmake
add_executable(foo src/foo.cpp)

find_package(ZLIB REQUIRED)
find_path(ZSTR_INCLUDE_DIRS "zstr/strict_fstream.hpp")

target_link_libraries(foo PRIVATE ZLIB::ZLIB)
target_include_directories(foo PRIVATE ${ZSTR_INCLUDE_DIRS})
```
- src/foo.cpp:
```cpp
#include  

int main()
    {return 0;}
```
3. `[...]/build$ cmake .. -DCMAKE_TOOLCHAIN_FILE:FILEPATH=[...]/vcpkg/scripts/buildsystems/vcpkg.cmake`
4. `[...]/build$ cmake --build .`

**Failure logs** 
```
In file included from [...]/src/foo.cpp:1:
[...]/vcpkg/installed/x64-windows-static/include\zstr/zstr.hpp:15:10: error: 'strict_fstream.hpp' file not found with   include; use "quotes" instead
#include  
          ^
```
Discussion
- It appears zstr expects to be installed directly in `include/`, not `include/zstr/`. There's two fixes that could be made:

#### 1. Install directly into `include/`
Change this line:
[URL]
to:
```cmake
     DESTINATION ${CURRENT_PACKAGES_DIR}/include)
```
This is the simplest fix, although segmentation is lost. This may be an issue especially with `strict_fstream.hpp`.

#### 2. Patch includes to point inside `include/zstr/`
Prepend all of zstr's internal includes with `zstr/`. This keeps segmentation, but is more complicated. Plus, the contributing guidelines state to avoid patching whenever possible.
- I think the following is the wrong approach:


because you will get the directory were "zstr/strict_fstream.hpp" is. But you seem to need the directory where "strict_fstream.hpp" is. How about the following:

```cmake
find_path(ZSTR_INCLUDE_DIRS "zstr.hpp" PATH_SUFFIXES "zstr")
```
(Note: the public header, not the implementation detail.)

Then you can also use

```c
#include  
```
