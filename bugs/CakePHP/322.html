Title

3.0 - The offset value is not calculated correctly when paginating.

Description
Originally in #3158.

Because it is calculated using `Query::page()` and it relies on `limit` being already calculated; and because `PaginatorComponent::getDefaults()` always returns `page` before `limit` in the array, it will be wrong most of the time.

We can change that order, but I don't think that's a fix because the public methods are still there: `Query::page()`, `Query::offset()`, `Query::limit()` and `Query::applyOptions()`.

Maybe we need to make some functions protected and the ones that are exposed follow a specific order so that it is always built the same way. Maybe the default `limit=25` has to go away.
Discussion
- If you have more than 25 rows you will see the problem here.

Try something simple like this for example:

```
$options = [
    'order' => ['id' => 'asc'],
    'limit' => 5
];
$data = $this->Paginator->paginate($this->Categories, $options);
```

You'll end up with 5 elements in page 1 and 5 elements in page 2 as expected because of `limit`.

But page 2 will start at element 26, not 6 as expected.

This is OK for page 1: `LIMIT 5 OFFSET 0`

```
SELECT Categories.id AS `Categories__id` FROM categories AS Categories ORDER BY Categories.id asc LIMIT 5 OFFSET 0
```

This is _NOT OK_ for page 2 : `LIMIT 5 OFFSET 25` where it should be `LIMIT 5 OFFSET 5`

```
SELECT Categories.id AS `Categories__id` FROM categories AS Categories ORDER BY Categories.id asc LIMIT 5 OFFSET 25
```
- Why would changing the order the methods are called in not fix the issue?  Another option is to recalcuate the page when limit() is called.
