Title

matching of given expression, for -m and -k option, is done in a fuzzy way and produces unexpected results.

# Problem
## Functional

The options -m and -k produce strange results. Here are some examples, used with attachment file 'x.py':
- **py.test -k something x.py** --> Matches on the fixture 'something' as well, while it should only match on the function name 'test_something'
- **py.test -k __doc__ x.py** --> Matches both tests, since the keywords contain magic attributes (not only __doc__, but also others like __dict__, __subclasshook__, etc.). Since it is a substring match with the -k option, you can actually do things like 'py.test -k __ x.py' or 'py.test -k sub x.py' to match everything.
- **py.test -m test_something x.py** --> Matches the function name 'test_something', while it should only match on markers. Also happens when providing a classname, like 'TestClass' with the attached file.
- **py.test -m __dict__ x.py** --> Same thing that happens with -k option, described above. It matches on every test, since all of the keywords always contain the magic attributes __dict__, __doc__, etc.
## Technical

The matching functions in _pytest/mark.py, called _matchmark_ and _matchkeyword_, both pass the _eval()_ function a local mapping, based on all of the keywords in the current item.
This means that there is no difference in the way -m and -k match, apart from the fact that -m is a complete string match (BoolDict) and -k is a substring match (SubstringDict).

There is no seperation of the markers and the keywords in the item, since everything is put in the NodeKeywords instance of the item.
