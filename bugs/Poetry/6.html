Title

exclude option fails on paths with capital letters

Description

- **Link of a [Link: Gist] with the contents of your pyproject.toml file**: [URL]
## Issue
There seems to be an issue with the exclude section in the pyproject.toml files with paths containing capital letters.
The issue can be reproduced with the example .toml file and a directory setup as follows:

```
poetry_example
-- __init__.py
-- Foo
------ Bar.py
------ lowercasebar.py
-- bar
------ foo.py
------ Capitalfoo.py
```

`poetry build -vv` yields:
```
Building poetry_example (0.1.0)
 - Building sdist
 - Adding: poetry_example\__init__.py.py
 - Adding: poetry_example\bar\Capitalfoo.py
 - Adding: poetry_example\Foo\Bar.py
... [Log Snipped] ...
 - Adding: [...]\poetry_example-0.1.0\poetry_example\Foo\lowercasebar.py
 - Built poetry_example-0.1.0-py3-none-any.whl
```
in which only one (bar/foo.py) of the four files specified to be excluded actually gets excluded.

The same issues also seems to affect exclusions through the vcs.
Discussion
- So the issue obviously is that Path.glob() returns case-insensitive files on a case-sensitive fs (such as Windows).
Hence we need to fix the paths back to their original case (and make sure this doesn't happen again anywhere else in the build process).
- This is fixed in the latest `0.12.11` release (commit 27d6fcf).
