Title

need to clean up the "annotations can't be interpreted" case

Description
### Discussed in [URL]

We need to set up ``__allow_unmapped__`` as a first class way to have declarative types that are incorrect to be ignored, for 1.4 compatibility.

right now it fails for this case:

```
py
from __future__ import annotations

from sqlalchemy import create_engine
from sqlalchemy import ForeignKey
... [Log Snipped] ...
s.add(A(bs=[B()]))
s.commit()
```

because:

```
When initializing mapper Mapper[A(a)], expression "relationship('list[B]')" seems to be using a generic class as the argument to relationship(); please state the generic argument using an annotation, e.g. "bs: Mapped[list['B']] = relationship()"
```

what it should do is completely not use that annotation that was detected as "wrong".

also the error message raised for the non-evaluable annotation is very confusing and im not sure what I has in mind when I wrote that.   so let's make something less ambiguous.
