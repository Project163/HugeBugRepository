Title

Implicit bootdelegation causes hang on android

Description
When felix is embedded inside an android app and a bundle triggers a classload which in turn hits our implicit bootdelegation then we run into an endless loop and hang. The workaround for now is to set "felix.bootdelegation.implicit=false".
Discussion
- Our implicit bootdelegation detection assumes that if we walk a classloader.getClass.getClassloader() chain we will ultimately arrive at the bootclassloader which is represented by null. Apparently this is not true on android but at one point we get the same classloader for the next as the one we already have (i.e., we run into an endless loop). I commited a fix which makes sure we stop if we hit null or the same classloader again which seems to fix the issue.
