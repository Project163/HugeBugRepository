Title

Bug: Collada uvs from channels a,b,c are imported into Assimp channels 0,1,2.

Description
**Describe the bug**
Collada: Now that we properly import uv channel numbers used by textures (merged today), it becomes apparent that second half of problem is importing data into correct uv channels. We properly find out that mesh contains data in channels a, b and c (example). But then   changes a,b,c to 0,1,2 and we store data into wrong uv channels.

**To Reproduce**
Steps to reproduce the behavior:
1. Import and render .dae with texture mapped mesh that uses uv channel 1.
2. See that render is wrong, material wants data from channel 1 but data are stored in channel 0.

**Expected behavior**
Collada files should be imported with original uv channel numbers in both meshes and materials.

**Additional context**
