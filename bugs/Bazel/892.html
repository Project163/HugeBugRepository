Title

Bazel doesn't cleanup partial input downloads for remote_download_minimal

Description
### Description of the problem / feature request:

The build without the bytes feature downloads remotely located output files locally only if needed to execute an action locally. This is done as follows:
1. It downloads the file at the exact output path where the actual action would have generated it hence making it transparent to the local action where the previous action was executed. 
2. It [Link: marks the permissions] of the local file to 0755.
3. On completion of the action, the input files are [Link: removed from the local disk] to make the local action cache in sync with the local output base.

However, since Bazel executes actions in parallel if any other build action fails this cancels all other concurrent actions using the thread executor service (I assume). This can happen at multiple points:
  
1. During/Before (1) above. This leads to an incomplete download. On the next run bazel sees that the digest of the output does not match the remotely expected digest and hence reruns the action. This is okay.
  
2. After (1) above. Since the file is completely downloaded and the digest does not take permissions into account, Bazel assumes the file is completely downloaded and attempts to execute the action using the file as an input. **However, this is not okay.** Some actions like `ExecutableSymlink` expect the file to be executable before the action is executed on it and can fail.
