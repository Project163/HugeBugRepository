Title

Wayland: alacritty ignores activated configure option, and instead relies on keyboard focus

Description
Alacritty seems to decide if it should draw the focused cursor or the unfocused one, depending on if it has keyboard focus, instead of relying on the `activated` configure option.

Additionally it starts assuming it *has* keyboard focus, making it impossible to open an alacritty window, without focus (at least visually).

It'd be nice if it would support the configure option, or at least start assuming it has no focus.

### System

OS: Linux
Version: alacritty 0.4.0
Linux: Wayland (kiwmi)
