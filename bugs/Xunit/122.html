Title

Tuples with more than 8 values are not properly serialized

Description
We have a project with some ~2000 tests running xUnit 3.0.0. The update to 3.0.1 causes the test process to crash on Ubuntu ARM64:

```
default
VSTest version 18.0.0-preview-25380-108 (arm64)

Starting test execution, please wait...
A total of 1 test files matched the specified pattern.
... [Log Snipped] ...
[xUnit.net 00:01:00.68] Catastrophic failure: Test process crashed with exit code 1.
No test is available in /home/runner/work/CSnakes/CSnakes/src/CSnakes.Runtime.Tests/bin/Debug/net9.0/CSnakes.Runtime.Tests.dll. Make sure that test discoverer & executors are registered and platform & framework version settings are appropriate and try again.
```

CI Run: [URL]

Related: [URL]

We found the crash was related to a test with `[MemberData(nameof(SubTestCases)]` and changing it to `[MemberData(nameof(SubTestCases), DisableDiscoveryEnumeration = true)]` fixed the issue

Change to enable tests: [URL]
Discussion
- The issue appears to be related to [Link: us adding tuple serialization support] in 3.0.1, and the 17-member tuple value in `Tuple17ConverterTests` not being serializable.
- For those who might be curious what's happening here, it turns out that `(int, int, int, int, int, int, int, int, int)` isn't `ValueTuple ` as you might expect. `ValueTuple` stops at 8 generic arguments. The compiler, therefore, is creating a tuple of type `ValueTuple >`, using the last generic type to continue on with additional tuples. This is how we ended up with "parameter count mismatch", since the type we were creating was `ValueTuple``8` but we had 9 ints as our argument list.

Strictly speaking, a tuple with 17 items wasn't necessary to trigger this (9 was enough), though I did write tests for 3, 10, and 17, just to ensure that we continued to dive down all the way into the tuple depths, since a 17 member tuple is actually a tuple which contains 7 values + a tuple which contains 7 values + a tuple which contains 3 values. 😄
- Fix available in v3 `3.1.0-pre.17` [URL]
