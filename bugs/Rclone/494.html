- Sorry about the late reply. I somehow missed your message two months ago. Anyway...

I would like to be able to run `rclone mount` like this

`rclone mount ... --rc ... --attr-timeout=-1 --dir-cache-time=-1 --poll-interval=0 ...`

i.e., with "infinite" caching and no polling because I know exactly when the remote changes. It's always the result of a (scripted) invocation of `rclone move` and said script knows what parts of the directory tree change as a result of the move and thus what parameters to pass to `rclone rc vfs/refresh` to update the cache.

I think it makes sense that disk space usage is tied to the directory cache and that if `rclone rc vfs/refresh` updates the directory cache, then disk space usage is updated as well. I don't see why you would ever want the two to potentially diverge. (And there are indeed flags enough already!)

BTW, it would simplify scripting a bit if you could run `rclone rc vfs/refresh dir=/` instead of `rclone rc vfs/refresh` to refresh the root directory, but I digress... :-)
