Title

The new PSR7 middleware doesn't work in combination with session login and setting up a cookie

Description
- [x] bug
- [ ] enhancement
- [ ] feature-discussion (RFC)
- CakePHP Version: 3.3.0
- Platform and Target: Apache 2.4.12, PHP 5.6.11, MySQL 5.6.25
### What you did

Converted my application to the new PSR7 middleware stack by replacing my webroot/index.php, config/bootstrap.php and added src/Application.php (also bin/cake.php for the vendor autoload) Everything was taken from cakephp/app 3.3.0 and then I fine tunned the new bootstrap with my own settings, plugins, whatever.

Also worth mentioning is that I store my sessions in mysql (using the schema/sessions.sql code)

Anyway, everything seemed to work except for the login. I'm using Cookies for a "remember me" feature and when submitting the form it wouldn't log me in at all, it would just redirect me back to the login page like a refresh, no error message, nothing.

What actually happened was that a new CAKEPHP id was generated that was not logged in and the old one was actually updated and logged in, however my browser used the new regenerated id. With a Chrome addon called EditThisCookie, when editing my CAKEPHP session id with the old one that was before i was actually logged in (because it contained the Auth session key that the new session id didn't)

I don't know how to explain this better but it looks like if you're trying to setup a cookie after successfully logging in, cake will regenerate a new session id and use that instead of using the one that it had which was updated with the Auth key holding my user info.
