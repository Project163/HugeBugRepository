Title

Rule too-few-public-methods should NOT ignore parent class methods

Description
Originally reported by: **Anonymous**

---

This is the opposite case to issues #248 and #364 where we do want to ignore parent class methods, and the fix for those issues appears to be the cause for this one. The following code reports a too-few-public-methods warning for class B although it clearly has more than one public method:

```
#!python

class A(object):
    def a(self):
        return self
... [Log Snipped] ...
    def c(self):
        return self
```

This causes subclasses to incorrectly report warnings. The two rules should use different ways to count the number of methods they are checking.
