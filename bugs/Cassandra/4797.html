Title

Correctly timed kill -9 can put incremental repair sessions in an illegal state

 This prevents a scenario where sessions can revert to an earlier state on startup. Here, as part of the finalize propose sequence, we flush the repairs table after setting the local state to FINALIZE_PROMISED, but before responding to the coordinator. If we fail after, we'll be in a state we can get to FINALIZED to. If we fail before the sync, we won't have responded to the coordinator, so the session will end up failing anyway.
