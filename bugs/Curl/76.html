Title

crash in multi_socket when closing connection doing many parallel transfers

Description
### I did this

@kunalekawde posted this on [Link: the curl-library mailing list on May 11 2019].

There seems to be a problem if several concurrents transfers are done as streams over a single connection and that connection is closed. In `multi_socket` where it iterates over the transfers done on the same connection, it can end up dereferencing a NULL pointer:

~~~
1. multi_socket() -> does multi_runsingle() where disconnect is detected
and tries to reconnect.
2. singlesocket() does sh_delentr().
3. Curl_llist_remove() does:

  e->ptr  = NULL;
  e->prev = NULL;
  e->next = NULL;
4.  During the next iteration, as prev is set to NULL, it finds data NULL

Please correct if my analysis is wrong.
I tried with following fix:
      /* the socket can be shared by many transfers, iterate */
      for(e = list->head; e; e = e->next) {
        data = (struct Curl_easy *)e->ptr;
        // crash fix - temp
        if (!data)
          continue;
~~~

The discussion on the list stopped. There's currently no proposed proper fix and we don't have a reliable way to reproduce.

The scenario is mostly:
1. client initiates multiple streams to server
2. server after some successful responses send GOAWAY(0) for connection and still sends HEADER & DATA before client acknowledges FIN. 
3. I think client is updating socket/list by setting some pointer to NULL and since its part of later execution, it also reads from socket and tries to access the list.
