Title

Index sorting causes illegal_state_exception

Description
**Elasticsearch version** (`bin/elasticsearch --version`): 7.12

**Plugins installed**: [analysis-stempel]

**JVM version** (`java -version`): built-in version

**OS version** (`uname -a` if on a Unix-like system): `Linux hostname 3.10.0-1127.18.2.el7.x86_64 #1 SMP Sun Jul 26 15:27:06 UTC 2020 x86_64 x86_64 x86_64 GNU/Linux`

**Description of the problem including expected versus actual behavior**:
Expected index sorting to speed up AND conjunctions and not to raise illegal_state_exception.

**Steps to reproduce**:

Used index structure:
```
json
{
  "index_name": {
    "mappings": {
      "dynamic": "false",
... [Log Snipped] ...
  }
}
```

Search query:
```
json
{
  "_source": false,
  "size": 24,
  "query": {
... [Log Snipped] ...
  }
}
```

And then the raised exception:
```
json
{
  "error": {
    "root_cause": [
      {
... [Log Snipped] ...
  "status": 500
}
```

- Index contains about 100M documents and weighs about 10GiB
- Peaks to 12.000 search requests per minute

This was an experiment to improve search query performance and I assumed that [Link: index sorting] would speed up AND conjuctions given that my query is fairly simple. However, I've had mixed results. Some queries ran faster and others started raising illegal_state_exception exceptions. I've tried changing number_of_shards, sorting criteria but the problem persisted. It got worse when I tried putting everything into 1 shard and would raise an exception on every 2nd request.
