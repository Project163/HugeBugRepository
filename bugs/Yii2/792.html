Title

W3C Validation Errors on ActifeField radioList

Description
I've added to the latest basic template with yii 2.0.12 to the LoginForm model a simple required attribute:
```
...
    public $gender;
...
    [['username', 'password', 'gender'], 'required'],
```
and a radioList imput field to the login form (I've removed the fieldsConfig option from ActiveForm):
```
...
     'login-form',
        'layout' => 'horizontal',
    ]); ?>
...
     field($model, 'gender')->label('Gender')->radioList([1 => 'male', 2 => 'female']) ?>
...
```
This simple input generates two HTML validation error using W3C validation:
```
Error: Element div is missing one or more of the following attributes: aria-expanded, aria-valuemax, aria-valuemin, aria-valuenow, role.
From line 44, column 56; to line 44, column 103
  value="">  ↩ Gender
```
Note that the second error comes up only if the `label` method is explicitly using.

I would expect, that simple forms and fields generates HTML without validation errors.

Note also, that there are also 2 warning,associated with the navigation and the form:
```
Warning: The navigation role is unnecessary for element nav.

Discussion

    
- This issue is mainly related to yii2-bootstrap.

1. To solve the `aria-required="true"` problem, the method `\yii2\bootstrap\ActiveField::radioList()` could add the` role="radiogroup"` attribute. I can submit a PR if that's ok:
```php
    public function radioList($items, $options = [])
    {
        if ($this->model->isAttributeRequired($this->attribute) && !isset($options['role'])) {
            $options['role'] = 'radiogroup';
        }  
        ...
    }
```
2. Your call to `->label('Gender')` must be after the `->radioList()`. That way the field will know that a radiolist don't need a HTML "for" attribute. (maybe it needs to be recommended on Docs, or refactor` \yii2\widgets\ActiveField::label()` to work independent of the call order);

3. The `nav` and the `form` issues are already solved on yii2-bootstrap repo;
