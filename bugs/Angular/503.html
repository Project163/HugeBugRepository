Title

Relative path would be better in source element/attribute

Description
**I'm submitting a ...**  (check one with "x")
```
[ ] bug report => search github for a similar issue or PR before submitting
[x] feature request
[ ] support request => Please do not submit support request here, instead see [URL]
```

**Current behavior**

When ng-i18n extract strings it adds source element that contains the source code and line where the strings was extracted. This is very good.

However the extracted source code file is absolute.

` "> D:/Source/Angular/Escape/src/app/app.component.ts:2 Sample 
`

Would be better to have relative to the project root

` "> src/app/app.component.ts:2 Sample 
`

This would make it easier to move the project into different location. It might also be the different developers or localization enginerrs have different local directory structures.

**Expected behavior**

Use relative path.

` "> src/app/app.component.ts:2 Sample 
`

In addition it would be better to store source into an attribute instead of source element inside the string playload.

` " source="src/app/app.component.ts:2">Sample 
`

**Minimal reproduction of the problem with instructions**

Extract any template

**What is the motivation / use case for changing the behavior?**

Make localization easier.

**Please tell us about your environment:**

Windows 10, VS code 1.12.1

* **Angular version:** 4.0.X

* **Browser:** all
