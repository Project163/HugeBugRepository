Title

[YSQL] Explain Analyze Forces Distributed Transaction

Description
Jira Link: [Link: DB-8384]
### Description

Consider an RF-3 cluster with nodes spread across multiple regions, and with preferred leaders in us-west. Create a table with the following schema:
```
CREATE TABLE orders_int(
    id serial PRIMARY KEY,
    total decimal(12, 2),
    products VARCHAR(255)
);
... [Log Snipped] ...
Indexes:
    "orders_int_pkey" PRIMARY KEY, lsm (id HASH)
```

Insert a few rows into the table in a single, stable connection, note down the timings:
```
  yugabyte@yugabyte=# INSERT INTO orders_int2 (total, products) VALUES (1.0, 'test');
INSERT 0 1
Time: 77.826 ms
  yugabyte@yugabyte=# INSERT INTO orders_int2 (total, products) VALUES (1.0, 'test');
INSERT 0 1
... [Log Snipped] ...
INSERT 0 1
Time: 71.869 ms
```

Repeat the same experiment with `EXPLAIN ANALYZE INSERT ...`:
```
  yugabyte@yugabyte=# EXPLAIN ANALYZE INSERT INTO orders_int2 (total, products) VALUES (1.0, 'test');
 
Time: 133.137 ms

  yugabyte@yugabyte=# EXPLAIN ANALYZE INSERT INTO orders_int2 (total, products) VALUES (1.0, 'test');
... [Log Snipped] ...
 
Time: 118.401 ms
```

We notice the following with respect to `EXPLAIN ANALYZE INSERT ...`:
1. The average latency is higher by an amount that is approx 1 round trip between us-west (preferred leader) and the closest region to it (us-central in the above example)
2. There is higher variance in the latency numbers.

**Symptom**:
In multi-region clusters, `EXPLAIN ANALZE INSERT ...`  are 1 round-trip time slower than vanilla `INSERTS`.

**Cause**
EXPLAIN statements are treated as utility commands/statements, while vanilla INSERTs are treated as PORTAL_MULTI queries. We have checks to perform the single-row insert optimization in case of the latter:
