Title

Static compilation fails with multiple bounds generics

Description
Consider the following interfaces: 

  
  public   interface  H1 {
   String  getFoo();
}
 
  

  
  public   interface  H2 {
   String  getBar();
}
 
  

 and the following Groovy class: 
  
 @CompileStatic
 class  HGroovy {
	 public  <T  extends  H1 & H2> void doSomething(T obj) {
		obj.foo
		obj.bar
	}
}
 
  

 Compilation fails: 
  
 HGroovy.groovy: 9: [Static type checking] - No such property: bar for class: T
 @ line 9, column 3.
                obj.bar
Discussion
- Please also note that if I remove the visibility modifier ("public") from  doSomething() , compilation also fails with: 
  
 HGroovy.groovy: 8: unexpected token: < @ line 8, column 2.
        <T extends H1 & H2> void doSomething(T obj) {
 
  

 Is this another problem or the expected behaviour?
- It's not a problem with static compilation, but a known limitation of the Groovy parser. 
It's something we might be able with the ongoing rewrite of the parser for a future version of Groovy.
- I can verify the issue of the static compiler thinking T is a normal class is present on master
- Yes, I'm convinced there are two problems here. The first one is the static compilation error, as reported in the original report, the second one is a limitation of the parser (regarding the second compiler error if "public" is missing described in my previous comment).
