Title

Environment variables from secrets are not exported on OCP 3.11

Description
**Describe the bug**
Exporting secrets as environment variables as described by [Link: Deploying to OpenShift guide] does not work on OCP 3.11.

The same feature works correctly on OCP 4.x.

**Expected behavior**
Secrets should be present in environment variables specified by the property name.

**Actual behavior**
Environment variables are not available in deployment pods on OCP 3.11.

**To Reproduce**
Steps to reproduce the behavior:
1. Checkout [URL]  
2. `oc login` to OCP 3.11
3. `cd quarkus/getting-started/`
4. `oc apply -f src/main/resources/secret.yaml`
5. `mvn clean package`
6. check the deployment pod's env vars - the environment variables are not exported in environment variables as defined by the application's `application.properties` file, e. g. `DB_DATABASE=postgresql`

**Configuration**
```
properties
quarkus.openshift.expose=true
quarkus.kubernetes-client.trust-certs=true
quarkus.s2i.base-jvm-image=registry.access.redhat.com/openjdk/openjdk-11-rhel7

... [Log Snipped] ...
quarkus.openshift.env-vars.DB_PASSWORD.secret=postgresql
quarkus.openshift.env-vars.DB_PASSWORD.value=password
```

- @iocanel Alright, I believe I found out what's the problem. As you said, Quarkus does not know about where it is going to be deployed. The `env` section from generated `kubernetes.yaml` is as follows:

```
- env:
        - name: "KUBERNETES_NAMESPACE"
          valueFrom:
            fieldRef:
              fieldPath: "metadata.namespace"
... [Log Snipped] ...
              name: "postgresql"
              optional: false
```
`secretKeyRef` does not have `optional` field on OCP 3.11 as far as I can see - and if the `optional` field is present, the secret does not get imported to any environment variable whatsoever.

If the `optional` fields are removed, the secrets are exported properly.
