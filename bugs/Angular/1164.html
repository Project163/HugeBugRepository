Title

ViewRef.onDestroy broken in Angular 9, but works if Ivy disabled.

Description
# 🐞 bug report

### Affected Package
    "@angular/core": "~9.0.5",

### Is this a regression?
Yes, this worked in Angular 8.  It also works in Angular 9 if you turn off Ivy.

### Description
Registering a callback with ViewRef.onDestroy will result in the following error when the component is destroyed:

ERROR TypeError: tCleanup[i].call is not a function

## 🔬 Minimal Reproduction
I cannot seem to update the packages in stackblitz.com, so here is a short snippet:

```
import { NgModule, Component, ChangeDetectorRef, ViewRef } from '@angular/core';
import { BrowserModule } from '@angular/platform-browser';

/** AppComponent */
@Component({
... [Log Snipped] ...
})
export class AppModule { }
```

## 🔥 Exception or Error
  
ERROR TypeError: tCleanup[i].call is not a function
  

## 🌍  Your Environment

**Angular Version:**
  
9.0.5

While I can definitively see the difference in the behaviour with the ivy enabled, there are 2 quick observations:
* casting `ChangeDetectorRef` to `ViewRef` is really using private APIs and those can change in major release without an warning;
* I'm not sure why one would use a specific pattern like this when it is possible to have a `OnDestroy` hook:

```typescript
@Component({ selector: 'app-dummy', template: ` Hello World ` })
export class DummyComponent implements OnDestroy {  

  ngOnDestroy() {
    console.log('Good bye!');
  }
}
```

Would you mind sharing _why_ you've decided to use the particular pattern of casting to `ViewRef` and subscribing to the destroy callback in this particular way?
- I would never use that pattern in a real app.  It was just to replicate the bug.  The real code is here:

```
import { ChangeDetectorRef, FactoryProvider, SkipSelf, ViewRef } from '@angular/core';
import { ControlContainer, FormGroupDirective, NgForm } from '@angular/forms';

export const controlContainerFactoryProvider: FactoryProvider =  {
  provide: ControlContainer,
... [Log Snipped] ...
  return 'onDestroy' in cdr; // <== "instanceof ViewRef" doesn't work
}
```

Our forms are way too big in our app, so we spread the FormControls out into child components.  As everyone knows, reactive forms does not like this.  You have to inject ControlContainer in the child and do some other goofy stuff to make it work.  I am trying to remove this repetitive boilerplate code out of our app with the code above.
- As @pkozlowski-opensource points out, `onDestroy` here is technically a private API. However, the fact that it doesn't work is a bug. 

It looks like when we refactored how we stored cleanup functions, we updated `storeCleanupWithContext` but not `storeCleanupFn` (the latter is used to make `ViewRef.onDestroy` work properly). To fix this, we will need to update `storeCleanupFn` so that the context is stored in `LView` and the cleanup function itself is stored in `TView`. That way, the logic in `removeListeners` will actually extract and call a cleanup function as expected and not an index (which throws an error when you try to call it like a function).
