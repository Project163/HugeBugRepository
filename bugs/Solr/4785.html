- Hi, Richardo! Thanks for rising an issue. 

 In short: 

 Unfortunately it is unable to workaround the problem due to its nature. This is caused because the results of the shard backup requests are not included to the task object that is used for async tracking. 

 Details: 

 Async backup requests work the following way. When a request hits the Solr it checks if there is an  async  parameter provided. If it is, the action will be queued and response will be immediately returned without waiting until backup will be completed. Then queued action will be processed and its result will be placed to the distributed map within the Zookeeper (you can check these maps using Solr Admin web interface). In case of collection backup, a request will be also sent to each of the shards to make backup of the index files (each shard will backup it's own index files). These requests will be also sent as async and will be handled in a similar way. Action will be submitted to executor service and immediate response will be returned without waiting until the shard backup process will be completed. After submitted action will be processed the results would be stored in local tracking map in a form of  org.apache.solr.handler.admin.CoreAdminHandler.TaskObject :
