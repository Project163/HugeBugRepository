Title

Correctly handle and document how TypeAliasyType (pep685) work in SQLAlchemy

Description
As the title says, currently what there is not consistent and was organically developed without a clear api.

The main idea here is to thread type alias type as new type, since this is what python seems to suggest (eq of tho identical TypeAliasType is false)

This means that to use of them inside `Mapping` they need to be explicitly added to the type map. SQLAlchemy will not use the value the type alias refers to when checking the type.

This breaks what was added in #11305 but that's the only consistent way of doing it
