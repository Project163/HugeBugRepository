Title

Syncthing GUI can inundate Syncthing with pending requests

Description
Hi,

As mentioned in #867, I'm seeing issues where GUI starts sending polls to Syncthing before the previous polls have completed. This snowballs, resulting in the Syncthing having to process lots of duplicate requests. Everything does recover, but it takes a fair while.

Now, Syncthing is running on a low-power device here - an ODROID-C1 - but the GUI could still play more nicely.

I've yet to find a nice way of capturing a single screenshot which contains all the information I want to convey. So, I'll describe what happens for now:
1. Load the GUI. A bunch of requests go out, and typically 'connections' or 'report' can take up to a minute to respond.
2. In the meantime, the GUI has requested the 'model' resource for all folders, and all connections for all devices on all models. This adds up to quite a lot of pending connections!
3. 'system', 'connections', and 'errors' then start stacking up - I can get quite a few simultaneous sets of these 3 before the original holdup clears.

Suggestions:
- Don't schedule one poll before the previous poll has finished. 
- Consider limiting the total number of pending requests.

Thanks!
