Title

[bug] NSIS auto updater passive mode

Description
### Describe the bug

The current NSIS updater requires user interaction to install the update., even with the passive option in the configuration. 
`"windows": {
        "installMode": "passive"
      }`

### Reproduction

- make nsis build
- make update
- open app and get update notification
- install update
- update not passive

### Expected behavior

update is passive with a progress bar like the msi updater

Discussion
- Ok, I did some testing. adding the silent argument for the nsis installer manually in the config makes it install silently
```json
"installerArgs": ["/S"]
```
Maybe the updater isn't adding the silent arg correctly, I didn't check.
However, now that it silently installs, the app does not launch automatically after the update, the user must manually open the app again
This can be fixed by using the callback function `.onInstSuccess`, and check if is silent mode, and exec the app
add this to `installer.nsi`:
```
Function .onInstSuccess
  IfSilent silent done
  silent: 
    Exec '"$INSTDIR\${MAINBINARYNAME}.exe"'
  done:
FunctionEnd
```
- `passive` mode is not supported by `NSIS` you need to use `quiet` mode instead, I will be updating the docs and add running the app after it has been updated.
