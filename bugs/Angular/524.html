Title

@import in multi-line css comment is wrongly interpreted

Description
## I'm submitting a ...
[x] Bug report

## Current behavior
`@import` statements in multi-line comments in CSS are incorrectly interpreted, generating a network request.

## Expected behavior
Comment, and the `@import` statement inside it, should be ignored.

## Minimal reproduction of the problem with instructions
  
/* 
This import statement should be ignored: @import "foo.scss"; 
*/
  

## What is the motivation / use case for changing the behavior?
Obviously, the import statement inside a comment should be ignored.

## Please tell us about your environment

  
Angular version: 4.2.5
 

Browser:
- [x] Chrome (desktop) version 59
Discussion
- The problem may be in the following line:

    var /** @type {?} */ modifiedCssText = cssText.replace(CSS_COMMENT_REGEXP, '').replace(CSS_IMPORT_REGEXP, function () {

where `CSS_COMMENT_REGEXP` is

    var CSS_COMMENT_REGEXP = /\/\*.+?\*\//g;

which fails to pick up multi-line comments. It should be

    var CSS_COMMENT_REGEXP = /\/\*[^]+?\*\//g;
