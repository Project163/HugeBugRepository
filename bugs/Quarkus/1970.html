Title

Native image building fails when using podman

Description
### Describe the bug

Trying to build a simple quarkus native app with `podman` fails, while the build succeeds when using `docker`.

### Expected behavior

Build should succeed.

### Actual behavior

Build fails with:

```
[8/8] Creating image...       [**]                                                                       (0.0s @ 4.74GB)

	at jdk.internal.vm.ci/jdk.vm.ci.common.JVMCIError.shouldNotReachHere(JVMCIError.java:52)
	at org.graalvm.nativeimage.pointsto/com.oracle.graal.pointsto.reports.ReportUtils.reportImpl(ReportUtils.java:159)
	at org.graalvm.nativeimage.pointsto/com.oracle.graal.pointsto.reports.ReportUtils.report(ReportUtils.java:140)
... [Log Snipped] ...
[ERROR] For more information about the errors and possible solutions, please read the following articles:
```

### How to Reproduce?

```
quarkus create app
cd code-with-quarkus
./mvnw -Pnative clean package -Dquarkus.native.container-runtime=podman
```

Discussion
- This was probably introduced by [URL]

What essentially happens is that [Link: when the `container-runtime` is explicitly set the rootless detection code is not invoked] which results in `--userns=keep-id` not being passed to `podman`.
- To work around this, one can pass `-Dquarkus.native.container-runtime=podman-rootless` to the build
