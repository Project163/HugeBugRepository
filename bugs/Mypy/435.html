Title

Modules are sometimes type checked in the wrong order

Description
The build manager sometimes schedules type checking of modules in the wrong order (if module a imports b, a is type checked before b). This may result in bogus type checking results.

Sorry, no simple test case available yet, but you can reproduce it with the mypy implementation (for example, typefixture is type checked before nodes).

This needs to be fixed soon (for the common case where there are no circular imports).

Circular imports need not be solved now; #90 will be of help in that case. More generally, we may require explicit type annotations for code that uses circular imports.
