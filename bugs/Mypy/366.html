Title

Class level __getattr__ causes error: __getattr__ is not valid at the module level outside a stub file

Description
After updating to mypy 0.530, I am getting an error on a `__getattr__()` method defined on a class:

```
$ mypy --version
mypy 0.530
$ python3 --version
Python 3.6.3
[~/cretonne/lib/cretonne/meta]
... [Log Snipped] ...
$ mypy cdsl/formats.py
cdsl/formats.py:143: error: __getattr__ is not valid at the module level outside a stub file
```

I don't have any module level `__getattr__()` functions.

This didn't reproduce with a smaller test case, but you can check out the [Link: Cretonne repo] to reproduce.
Discussion
- Confirmed on master, I am stepping through now. I appears the issue only occurs in the second pass of the checker (the class is added to the scope stack in the first pass, but not in the second).
- It appears that when we defer functions to the second pass, we [Link: try to put the class context information]. However, the function `node` is not removed on L261, so the class is not resolved, and that returns `None`. This later causes issues when we try to append the class context, but cannot, so the `__getattr__` method appears to be in the file context (this occurs in `check_second_pass`). The `__getattr__` checking for module levels if the first thing that relied on the size of the scope being 1 (module level), so it exposed this issue.
