Discussion
- That `@apiNote` is referring to calling `execute(LauncherDiscoveryRequest)` after having called `discover(LauncherDiscoveryRequest)` with the same request. Executing the same test plan twice is currently not supported since test engines are bound to have some state (like Jupiter does in your case) that is not cleared. However, we should fail with a proper failure message when the same `TestPlan` is executed again and we should document that this is not supported.
- I've submitted #2380 to address this issue.
- ... [Middle Discussions Snipped for Brevity] ...
- Hm. My reasoning might be wrong but I'm wondering if this dependency does prevent generic de/serialization of a test plan?

Why do I think this is important? Imagine you want to split starting/reporting tests from running tests in two different processes (e.g. over the network or through inter-process communication). I think this was one of the scenarios we had in mind when we decided to make TestIdentifiers immutable. This is not such a fancy scenario, in fact, I was recently contacted about building an external test runner to trigger and observe tests running somewhere else (in this case a Spring boot app).
- `TestPlan` is not serializable and IIRC never was. If you want to execute tests elsewhere your best bet is to collect all leaf unique ids and discover a new test plan.
