Discussion
- I'm able to reproduce this locally (outside of docker, running the rails app on port 3000)

```
~/src/forem$ curl -X POST -H "Content-Type: application/json" -H "api-key: $API_KEY"  -d '{"listing":{"title":"Title","body_markdown":"Body","category":"cfp"}}'   [URL] at /api/listings
==============================

undefined method `delete' for nil:NilClass

... [Log Snipped] ...
   44       params.require(:listing).permit(ALLOWED_PARAMS)
   45     end
```

I used nearly the exact curl example from the api docs (I added $API_KEY in place of API_KEY so the shell would expand the header value, and changed the target from [URL] to [URL] This looks like it rules out the docker setup (and points to either a bug in forem's api for this use case, or a drift in the api requirements and the documentation). 

Putting a breakpoint in that location (in the listings toolkit helper, just before the tags assignment where the error occurs) shows params has a key "listings", and that "listings" is nil.

```ruby
[10] pry(# )> params
=> # nil, "locale"=>nil, "format"=>"json", "controller"=>"api/v0/listings", "action"=>"create"} permitted: false>
```

 Checking caller indicates the listings controller's listing_params calls the toolkits listing_params:

```
 "/home/djuber/src/forem/app/controllers/concerns/listings_toolkit.rb:40:in `listing_params'",
 "/home/djuber/src/forem/app/controllers/api/v0/listings_controller.rb:100:in `listing_params'",
 "/home/djuber/src/forem/app/
...[Text Truncated]...
s_toolkit.rb:8:in `create'",
```

Checking the [Link: api controller's method] - it looks like this is related to a renaming (a while back) of the Listings model from the ClassifiedListings model, the code has a comment about an existing public api using "classified_listings" as the top level key for the json body, and assigns from there to listings (which is what the rest of the app uses). I understand the reasoning there - you don't want your internal refactoring/simplification to break a published api endpoint (someone might have written automation on top of it).

I think a reasonable fix for this would be to use a conditional assignment to accept either?

```ruby
        params["listing"] ||= params["classified_listing"]
```

That would set "listing" only if it were blank.

The alternate fix would be to change the api docs to reflect the legacy name, but that feels like it entrenches a requirement based on names that existed several years ago.
