Title

Multiple assignment from Iterator skips every other element

Description
If you try to assign multiple variables from an iterator Groovy will skip every other value. 

 Example: 
  
  final  list = [1,2,3]
 final  iter = list.iterator()

 final  def (a,b,c) = list
 final  def (d,e,f) = iter

 assert   "$a $b $c"  ==  "$d $e $f" 
 
  

 Result: 
  
 Assertion failed: 

assert "$a $b $c" == "$d $e $f"
         |  |  |  |    |  |  |
         1  2  3  |    1  3  null
                  false
 
  

 The expected behavior is either that the assertion succeeds, or the assignment to (d,e,f) fails outright. 

 If this is fixed it would also be nice if any Iterable could be used on the RHS.
Discussion
- Just a note at this stage. Changing the problematic assignment to: 
  
  final  def (d,e,f) = iter.toList()
 
  
 works around the problem. 

 What the shorthand is currently equivalent to:  
  
  final  def (d,e,f) = [iter[0], iter[1], iter[2]]
 
  
 But with  iter  advancing (one item being consumed) with each access. 

 What we would need to do (or do the toList() automatically as shown above): 
  
  final  def (d,e,f) = [iter[0], iter[0], iter[0]]
 
  

 Regarding support for  Iterable . You can just go  iterable.iterator()  (albeit with the current behavior as per this issue) or we'd need to support the  getAt(Integer)  method for  Iterables .
- If it's feasible it'd be nice if it effectively did: 

  
  final  d = iter? iter.next() :  null , e = iter? iter.next() :  null , f = iter? iter.next() :  null 
 
  

 Then if the  Iterator  is something that's expensive to materialize as a  List , or if you just want to use the unconsumed elements later you still can.
