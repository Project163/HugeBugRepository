- Found the culprit. This is a funny one.

The failing test creates a params file and then asserts that the option parser recognizes that the flag is a path to a params file, parses the params file, and substitutes the args vector with the flags from the file.

This is the buggy line:
[URL]

The parser processes the file character-by-character, in order to handle multiline flag values, e.g. `--foo=line1\nline2`. Problem is, Windows has CRLF line endings, so we terminate the arg parsing on the CR, and treat the LF as a standalone flag value, and push it into the args vector. So instead of ["--baz", "oops", "--bar", 17], we end up with ["--baz", "", "oops", "", "--bar", "", 17]
