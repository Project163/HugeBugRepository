Title

Enabling queryCache on a database that is also the storage for Cache causes a loop

Description
I notice a loop when enabling `queryCache` on a database that is also the storage for the `cache` component. This might be related to #5106.

It seems that the `DbCache` his `setValue` and `addValue` function just write the info to the default `db` component,  that in the end causes a loop since the query to save the cache value will also trigger a new insert for the `queryCache`.

I've took a quick look in `DbCache` but there seems no way to block a new insertion in the DbCache from generating a new cache entry.

This patch encloses those updates in a `noCache()` call, and if I'm right, that should solve this. Am I correct? Did I miss anything?

```
patch
diff --git a/framework/caching/DbCache.php b/framework/caching/DbCache.php
index 8c1fcbb..55819e1 100644
--- a/framework/caching/DbCache.php
+++ b/framework/caching/DbCache.php

     }
```

Discussion
- What does this solution?
- It makes sure that an insert due to a cache update doesn't update the queryCache for that insert-query.
- Why is this not integrated? Currently working around it, by extending DBCache and encapsulating overwritten  setValue()  content in:
```
php
protected function setValue($key, $value, $duration)
{
	if ($this->db->enableQueryCache) {
		// temporarily disable and re-enable query caching

	}
}
```
Most other methods of DBCache use  $this->db->enableQueryCache  as this, I guess for the exact same reason.
