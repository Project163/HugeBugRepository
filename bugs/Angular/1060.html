Title

[IVY] Can't create component instance in a feature module constructor

Description
# 🐞 bug report

### Affected Package

@angular/core, maybe @angular/compiler...

### Is this a regression?

Worked in 8 and below

### Description

A module throws when trying to create a new component instance in the constructor.

```
ts
@NgModule({
  declarations: [
    FeatComponent,
  ],
... [Log Snipped] ...
  }
}
```

Note that both a self declared component and a parent component will fail.

The fix in #35580 solve a portion of the issue but not all of it. (Iv'e tried to [Link: explain it here] with no luck)

The problem starts [Link: here] with the root module of the app is created along with an `NgModuleRef` for it:

```ts
    this._r3Injector = createInjector(
        ngModuleType, _parent,
        [
          {provide: viewEngine_NgModuleRef, useValue: this},
          {provide: viewEngine_ComponentFactoryResolver, useValue: this.componentFactoryResolver}
        ],
        stringify(ngModuleType)) as R3Injector;
```

`ngModuleType` is the app's root module class and in this call it will go and instantiate all child modules...  (`FeatModule`).

The child module will try to create a component instance (`FeatModule.constructor`) which will
at some point require the `_r3Injector`. However, it is still not there because the original function call (`createInjector`) did not still finish (the one called from the app module root).

This definitely worked in v8.

Discussion
- Debugged it a bit and it seems like the problem is that we are trying to use `_r3Injector` _while it is being created_ here: [URL]

We should investigate it / see what we can do about it, given that it used to work in Angular 8. As the very minimum we should throw a descriptive error message if we decide _not_ to support this case.

@shlomiassaf out of curiosity - what is the functional use-case for creating a component instance in a module constructor? Sounds like pretty early in the application / module lifecycle. Not dismissing the use-case, just trying to understand it better.
- @pkozlowski-opensource I have a grid library which is template based.

I allow users to provide a component with templates for the grid (cells, headers, etc..). They provide it in a static function (think `forRoot`) so they are not hassled with provider configuration.

I take this component and instantiate it which immediately  registers all template references in the libraries template registry.

I can always force them to include that component in a template somewhere, since that component does nothing but register templates, which has no immediate UI effect but that's not user friendly.

I agree that such operation should not be done in the constructor. `OnInit` is the perfect place for this. But there is no `OnInit` event in modules, not one that i'm aware of anyway.

If you would to add that lifecycle event to modules this will not be an issue as it is already the recommended approach to handle angular stuff, in the `OnInit` event and not in the constructor. 

---

EDIT: Thinking more into this, now that this issue is here and if it's hard to fix maybe `OnInit` for module is a good solution... It looks (to me) as the perfect logical solution.
