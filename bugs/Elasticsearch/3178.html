Title

Failure to get snapshot information when there's a repository with incorrect credentials

Description
### Elasticsearch Version

8.18.1

### Installed Plugins

_No response_

### Java Version

_bundled_

### OS Version

cloud

### Problem Description

When there's a snapshot repo with incorrect credentials it can block loading the list of snapshots. 

### Steps to Reproduce

- add keystore values for client access/secret keys (invalid ones for example)
- update repo to use the client with the invalid credentials
- reload secure settings (ie: POST _nodes/reload_secure_settings)
- `GET  /_snapshot/*/*` - should 500 error

- This behaviour is by design and I'm not really seeing what else we could do in this case given all the other constraints on this API's behaviour. In particular, it offers a sorted and paginated view of the snapshots in all the requested repositories, plus summary statistics, so if even one of them isn't available there's no way we can know what's missing and the results will be (possibly-dangerouly) incorrect.
