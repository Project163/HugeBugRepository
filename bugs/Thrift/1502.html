Title

generated code would cause ClassCastException

Description
Looking at the thrift generated code for cassandra, i'm seeing 

  msg = (org.apache.thrift.TBase)new org.apache.thrift.TApplicationException(org.apache.thrift.TApplicationException.INTERNAL_ERROR, e.getMessage()); 

 as seen here 

  [URL]

 i don't see how TApplicationException can be cast to TBase, and so i'd expect a ClassCastException there.
Discussion
- The base class for Thrift exceptions is TExceptions, not TBase, as specified by   THRIFT-1761  .  

 Speaking about that subject, there is also some kind of a pending discussion in  THRIFT-2935 , where I personally disagree with, mainly because of the inconcistency this would cause, but I'm not that much of a Java user to fully understand all the implications that may exist. Feel free to contribute to that discussion if you have something to add.
- Yes, but the code generator mistakenly casts to TBase which is incorrect as specified in   THRIFT-2988  . That is the issue that would be great to have remedied. 

 Extract from AsyncMethodCallback onError(Exception e): 

  
  if  (e  instanceof  MyCustomException) {
    result.myCustomException = (MyCustomException) e;
    result.setMyCustomExceptionIsSet( true );
    msg = result;
}
 else  
{
    msgType = org.apache.thrift.protocol.TMessageType.EXCEPTION;
     // The line below will cause a  class   cast  exception,  this  line was generated by the thrift library
     msg = (org.apache.thrift.TBase) new  org.apache.thrift.TApplicationException(org.apache.thrift.TApplicationException.INTERNAL_ERROR, e.getMessage());
}

- Turns out   THRIFT-3112   does not reveal similar  ClassCastException  issues if you use the generated client code correctly, but the correct usage is odd and inconsistent with the async server code.
- The cast was removed in 0.10.0.
