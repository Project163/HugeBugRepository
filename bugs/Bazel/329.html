Title

sandbox should create regular empty files rather than symlinking to /dev/null

Description
`Runfiles` may have an `EmptyFileSupplier` instance that can add empty files to the runfiles tree. `build-runfiles` creates regular empty files for paths added by the supplier. The sandbox code, however, creates symlinks to `/dev/null` for such paths. This means the empty files in the sandbox dereference to character devices not genuine files. For two reasons, I believe the sandbox code should create regular empty files, too:
1. It's an inconsistency between standalone and sandbox mode.
2. The only (public) use for `EmptyFilesSupplier` is adding `__init__.py` to make Python packages. (C)Python 2 is okay with `__init__.py` being a character device, but Python 3 is not. Moreover, other Python implementations and tools that do not exactly replicate CPython's arcane import behavior are generally confused by `__init__.py` being a character device.
