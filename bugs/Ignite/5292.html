- As I can see the mentioned  sessionEnd  is deprecated because Ignite introduced the  CacheStoreSessionListener  interface which is supposed to manage connections and transactions for custom  CacheStore  (see   IGNITE-891   ). 

 But  CacheJdbcPojoStore  and  CacheJdbcBlobStore   are part of the public API and remain unchanged - they still manage the connections themselves. 

 Therefore, I consider the proposed solution to be a good one. 

 For example, if we set up multiple  CacheJdbcPojoStore  stores and disable write-behind, the  sessionEnd  method will be called for those stores. 
And I don't see a fundamental difference in this case in the behavior of external storage management (write/read-through only vs write-behind). 

 The test  testDefragmentationStatus   fails because of   IGNITE-17761   and does not relates to the proposed changes.
