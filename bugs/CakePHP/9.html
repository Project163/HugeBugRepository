Title

nocache in views that extend another one

Description
Created by **mixer2**, 14th Apr 2013. _(originally [Link: Lighthouse ticket #3756])_:

---
#### What I did

I created a layout (same with elements and other views) and extended it with another one that contains nocache parts. 
#### What happened

nocache doesn't work, in view files, that extend another view. It does work fine in the parent view, if that is toplevel and doesn't extend another one.    
#### What I expected to happen

nocache should work, like in views, that don't extend other views.
Discussion

---

Could you give a short example of what isn't working?
- 15th Apr 2013, **mixer2** said:

---

The nocached part get's cached.
In _parseFile() the CacheHelper searches for the nocache tags in the $file and the $cache. But for views that extend another one the $cache varibale is empty. So it does find the PHP code which should be inserted to the cache, but not the correct tags in the cache, that should be replaced ($outputResult is empty). And that is empty because in the main view class the result of _evaluate() is passed to the afterRenderFile callback. And that result is empty for extending views, because it contains everything that is outputted, while the view is included. But extending views don't output anything, they just set content for view blocks, which will later be outputted by the extended view. For that view the CacheHelper does find the nocache tag in the output, but it doesn't find the matching php part to replace it, because it really isn't in that view file, but in the one that extended it.

I tried to make a simple demo for the bug and found a even more strange behavior. It's like described if the extended view doesn't contain a nocache tag. If it does contain a nocache tag the content of that view get's cached and a non cached version get's injected into the extending view. This may be completely different content than the content that is in the extending view.
To make it more easy to reproduce i added a demo as attachment. Just copy in a fresh cake installation and get sure that Configure::write('Cache.check', true), Configure::write('Cache.disable', false), Configure::write('debug', 0) and the tmp is writable.
- Another time to vote against nocache tags. I'd like to see that esi-like tags make its appearance in 3.0. Closing as in my view it is impossible to fix a feature that is broken by design.
