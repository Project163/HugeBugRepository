Title

rdfcat produces invalid decimals N3

Description
According to the N3 grammar, decimals must have at least one digit to the left of the decimal point. 
Rdfcat ignores this when abbreviating datatyped xsd:decimal literals. 
This causes reasoners like CWM and (older versions of) EYE to throw syntax errors. 

  [URL]
decimal ::=	 [-+] ? [0-9]  (\. [0-9]  )? 

 Test case: 

 rdfcat -ttl test.ttl -out N3 > result.n3 

 test.ttl: 
@prefix xsd: < [URL]
@prefix :	<#>. 
:s   ".3"^^xsd:decimal. 

 result.n3 
@prefix :        < file:///home/axgze/tmp/decimal/test.ttl# > . 
@prefix xsd:     < [URL] . 

 :s           .3 .
Discussion
- Thank you for the report. 

 Jena will follow Turtle here - N3 as a writer name is a convenience as people confuse N3 and Turtle.  The current working draft for Turtle is wrong but the intention seems to be be to allow .3.  I'll check with the WG.
- The regex for Turtle (last call publication) is 

  [+-] ?  [0-9] * '.'  [0-9] + 

 so no leading digit is required.
