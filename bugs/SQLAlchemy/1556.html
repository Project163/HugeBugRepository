Title

KeyError when removing an event listener that had been added to two scoped sessions

Description
### Describe the bug

Hey there 👋 

There seems to be a bug in `lib/sqlalchemy/event/registry.py::_removed_from_collection` or the way `owner_ref` and `listen_ref` get built that causes a `KeyError` exception to be raised when a same event listener gets added and then removed from two different scoped sessions.

With the debugger I've seen that in both the `event.remove` calls we end up with the same `listen_ref` and `owner_ref` variables in  `_removed_from_collection`. In the first pass we're able to successfully do `listener_to_key.pop(listen_ref)`, but in the second we get the error as that dictionary is empty.

I don't know if it's intended to have the same `listen_ref` and `owner_ref`, but if so we could fix this by doing:
```
diff
diff --git a/lib/sqlalchemy/event/registry.py b/lib/sqlalchemy/event/registry.py
index 773620f8b..76ef1bd37 100644
--- a/lib/sqlalchemy/event/registry.py
+++ b/lib/sqlalchemy/event/registry.py
... [Log Snipped] ...
+    if listener_to_key := _collection_to_key[owner_ref]:
         listener_to_key.pop(listen_ref)
```

I can in case open a PR for it, I would need some guidance though on where to add the tests for it.
