Title

Local Package Identifiers not currently supported in Gitea

Description
### Description

When running Gitea as a private PyPi package registry there may be packages that do not match the canonical public version and instead use a [Link: local version identifier] as outlined in PEP-0440.  An example of this could be an internally forked version of `certify` [URL] that includes custom CAs specific to that organization.

When attempting to use these packages with Gitea it will return a 400 Bad Request with "invalid name or version"

### Gitea Version

1.17.3
