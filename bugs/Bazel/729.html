Title

"--package_path" is broken in Bazel@HEAD

Description
Bazel supports finding packages in multiple paths. 
[URL] 
This is currently broken at HEAD.

Note that this is a different issue as b/132327507 which is already fixed by  

Culprit:  

To reproduce with [URL]

```
$ bazel-  build //... --package_path ../buildfiles
Starting local Bazel server and connecting to it...
INFO: Reading 'startup' options from c:\users\pcloudy\.bazelrc: --output_user_root=C:/src/tmp
INFO: Options provided by the client:
  Inherited 'common' options: --isatty=1 --terminal_columns=320
... [Log Snipped] ...
        at com.google.devtools.build.skyframe.AbstractParallelEvaluator$Evaluate.run(AbstractParallelEvaluator.java:450)
FAILED: Build did NOT complete successfully (2 packages loaded)
```
Discussion
- Although I tested on Windows, this is also broken on Linux.
- This isn't a bug with --package_path. The issue is that there's no WORKSPACE file under the package_path you specified. You'll see the same crash happen if you remove the WORKSPACE file from the root of your workspace and run bazel with no --package_path argument there. That being said, we should certainly not crash in this situation, even though we're going to error out momentarily because there's no WORKSPACE file.
- ... [Middle Discussions Snipped for Brevity] ...
- No matter this is a bug or not, it is definitely an incompatible change, because the above example works with Bazel built before 9c5b310
- I wouldn't describe it as an incompatible change: it's just a bug. Fixing it with my pending internal change will revert to the previous behavior except with multiple package paths, and I don't think behavior in that case was ever specified.
