Title

Rest client does not support other primitive response types when filter like OIDC client filter is used after optimization of primitive checks

Description
### Describe the bug

[URL] causes problems when our reactive REST client is also `@OidcClientFilter`  as return type `boolean` is not supported for `text/plain` anymore.

### Expected behavior

`boolean` is valid `text/plain` response type as is when `@OidcClientFilter` is not used

### Actual behavior

An exception is thrown `jakarta.ws.rs.ProcessingException: Response could not be mapped to type boolean for response with media type text/plain;charset=UTF-8`

### How to Reproduce?

Steps to reproduce the behavior:

1. `git@github.com:quarkus-qe/quarkus-test-suite.git`
2. `cd quarkus-test-suite`
3. `mvn clean verify -f security/keycloak-oidc-client-reactive-extended/ -Dit.test=OidcRestClientIT#testAutoAcquireToken`
