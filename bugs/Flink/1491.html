Discussion
- I have looked into this issue. It only occurred when applying a renaming project and the expected type is a POJO. 

 The reason is that the `ProjectRemoveRule.INSTANCE` rule removes identity project so that the renaming project doesn't exist at last. Not sure how to fix this. We can't remove  `ProjectRemoveRule.INSTANCE`  rule.
- You are right. This issue is not trivial. Actually we need a `ProjectRemoveRule` that pushes the field names in the input node, such that the field names are not getting lost.  fhueske  and I already discussed about having an easier architecture with conversion mappers at the beginning and end, and only operators handling row types in the middle. Maybe it is time for that now. We could then have a additional rule that merges two conversion mappers if nothing is in between.
