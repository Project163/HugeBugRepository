Title

RouterLinkActive causes `Maximum call stack size` error when wrapped in `ng-template`

Description

**Current behavior**
In my application, I'm loading users from a server. Those users are then shown in a searchable navigation list so you can select one and view the details. Something like this.

```html
 
       
             {{ user.name }} 
       
 
```

That `ng-template` is then used in the `search-list` to render each individual user and works perfectly.

Off course I also want to visually show what user is selected by using the `routerLinkActive` attribute. 

```html
 {{ user.name }} 
```

And here is where it fails. If you navigated to `users/2` for instance and you refresh the page, this means that the route of user `2` should be set to active after the data comes back from the server. And this is very important! If the data is static and thus not delayed, it works. But if the data comes in later, it will result in the following error.

```
ERROR RangeError: Maximum call stack size exceeded
    at isViewDebugError (core.es5.js:8629)
    at callWithDebugContext (core.es5.js:13020)
    at Object.debugCheckAndUpdateView [as checkAndUpdateView] (core.es5.js:12553)
    at ViewRef_.detectChanges (core.es5.js:10122)
... [Log Snipped] ...
    at callViewAction (core.es5.js:12340)
    at execEmbeddedViewsAction (core.es5.js:12312)
```

This also only seems to happen if you wrap it inside a `ng-template`, otherwise it works fine if you just render it in a list.

**Expected behavior**
The `routerLinkActive` property should work in a ` ` as well and mark the link as active even if the data is coming in delayed. It worked in Angular 2.x so it seems a regression bug.
