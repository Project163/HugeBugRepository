Title

Add compiler error for DISTINCT ON that doesn't match initial ORDER BY expressions

Description
For example:

```
rust
table! {
    entries (id) {
        id -> Int4,
        name -> Text,
... [Log Snipped] ...
    .distinct_on(name)
    .load(&conn)
```

This compiles fine, but inevitably causes "SELECT DISTINCT ON expressions must match initial ORDER BY expressions" when executed.

The correct version, of course, is:

```rust
entries
    .order_by((name, date.desc()))
    .distinct_on(name)
    .load(&conn)
```

According to [Link: the PostgreSQL docs] `DISTINCT ON` is valid with no ordering, or with a matching prefix. I don't know enough about Rust to have any idea how feasible it is to encode that in the types, but it would be a neat sanity check!
