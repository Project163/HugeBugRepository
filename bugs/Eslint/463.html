Title

False positive in `one-var` for successive `for-in` and `for-of` loops

Description
Minimal repro case:

``` sh
# Command line:
eslint --no-eslintrc --rule '{"one-var":[2,{"uninitialized": "always"}]}' file.js
```

``` js
// file.js
for (var i in foo) {}
for (var j in foo) {}
```

Output:

```
tmp.js
  2:6  error  Combine this with the previous 'var' statement with uninitialized variables  one-var

✖ 1 problem (1 error, 0 warnings)
```

Same problem with with `let` and `const`, and with `for-of` loops (both with `--env es6`).

``` js
// file.js
for (let i of foo) {}
for (let j of foo) {}
```

As for `let`/`const`, the semantics are different, so it should never trigger the warning, but it probably shouldn't for `var`, either.
Discussion
- In the case of `var`, the preferred style would be to declare both variables at the top of the scope instead of inside the loop. For `let`, however, that looks correct since the loop would create a new scope. I'd say that part is a bug with how the rule determines scopes.
