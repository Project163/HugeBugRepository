Title

Black changes f-string into string even though there is a substitution in it.

Description
**Describe the bug**:
Black changes f-string into string even though there is a substitution in it.

**To Reproduce**:
1. Put this into a file:
```py
temp_msg = (
    f"{f'{humanize_number(pos)}.':  >\n"
)
```
2. Run _Black_ on it with no arguments:
3. See error
```
error: cannot format test.py: INTERNAL ERROR: Black produced code that is not equivalent to the source.  Please report a bug on [URL] This diff might be helpful: C:\Users\Jakub\AppData\Local\Temp\blk_08urbts5.log
```
Contents of the log file:
```
diff
--- src
+++ dst
@@ -85,60 +85,11 @@
                     )  # /Constant
... [Log Snipped] ...
                 -1,  # int
               format_spec=
```

**Expected behavior**:
I would expect _Black_ to not touch that f-string.

**Environment:**
- Version: master (commit  , with `--experimental-string-processing` flag)
- OS and Python version: Windows/Python 3.8.3

**Does this bug also happen on master?**
It *only* happens on master, it doesn't happen on current release as there's no string reformatting in it yet. Online formatter doesn't error, but it does produce this output which is obviously not equivalent to the original:
```py
temp_msg = (
    f"{f'{humanize_number(pos)}.':  >\n"
)
```
