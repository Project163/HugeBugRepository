Title

Ensure that empty SAI column indexes do not fail on validation after full-SSTable streaming

Description
I actually discovered this in some exploratory testing for  CASSANDRA-19007 ... 

  
 @Test
public void testRepairWithEmptyColumnIndex() throws IOException
{
   try (Cluster cluster = init(Cluster.build(2).withConfig(config -> config.with(GOSSIP).with(NETWORK)).start()))
   {
       cluster.schemaChange(withKeyspace("CREATE TABLE %s.t (k int PRIMARY KEY, a int, b int)"));
       cluster.schemaChange(withKeyspace("CREATE INDEX ON %s.t(a) USING 'sai'"));
       cluster.schemaChange(withKeyspace("CREATE INDEX ON %s.t(b) USING 'sai'"));

       // insert a split row
       cluster.get(1).executeInternal(withKeyspace("INSERT INTO %s.t(k, a) VALUES (0, 1)"));
       cluster.get(2).executeInternal(withKeyspace("INSERT INTO %s.t(k, b) VALUES (0, 2)"));
       cluster.get(1).flush(KEYSPACE);
       cluster.get(2).flush(KEYSPACE);
       cluster.get(1).nodetoolResult("repair", KEYSPACE).asserts().success(); // fails w/ no data for the "a" index on node 2!
   }
}

Discussion
- The fix should be fairly simple, essentially making sure we don't assume the column index components are present during validation when the index completion marker is present.  
 Good catch. How can validation distinguish between components that are absent because of a lack of indexable data and wrongly lost components? Maybe we should start writing empty components?
- adelapena  The first thing that occurred to me is that we could simply write a boolean to the index completion marker indicating whether the index is empty or not. If it's empty, we don't need to check any components. If it's non-empty, we know the exact set of components we need to check. WDYT?
