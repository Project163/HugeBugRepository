Title

[YSQL] Memory leaks occur in PgGate module when exceptions are raised

Description
This bug happens intermittently when updating table with indexes.

When Postgres raises exception, I saw the leak intermittently due to PgGate data handlers are not released at that time. In the current design, YugaByte allocates PgGate objects when it enters an execution node and free them when exiting.  This design does not work well when there's nested node.  In this case, it happens when updating tables with secondary indexes.

- Most execution nodes in Postgres have nested node.
- When nested node has exception such as duplicate-requests, Postgres did a long jump.
- YugaByte objects in the outer node would not be freed, and as a result we have memory leaks.
