Title

/dev/shm not writable

Description
### Description of the problem / feature request / question:

I want to use python multiprocessing module in a python test (python3.5), but it fails with OSError: [Error 30] Read-only file system. I think the following is the problem.

when I run bazel test with --sandbox_tmpfs_path=/dev/shm/, I expect os.listdir("/dev/shm/") to return [] and os.mkdir("/dev/shm/test") to succeed (if I understand the --sandbox_tmpfs_path option correctly, it mounts a fresh writable filesystem at given path). however, what I got from os.listdir("/dev/shm/") is the same list of files I got when I run that in a python interpreter without bazel/sandboxing, and os.mkdir("/dev/shm/test") fails with OSError: [Error 30] Read-only file system: "/dev/shm/test".

it seems that --sandbox_tmpfs_path is handling /dev/shm in a special way (maybe because it is already mounted? --sandbox_tmpfs_path /dev/shm seems to have no effect.). --sandbox_tmpfs_path /some/other/path seems to work as expected (i.e. os.listdir("/some/other/path") returns [] and os.mkdir("/some/other/path/test") succeeds).

### Environment info
* Operating System:
Ubuntu 14.04

* Bazel version (output of `bazel info release`):
release 0.4.0
