An type error occurs when building Teleport using the

Description
### Version
3.0.4

### Reproduction link
[Link]

### Steps to reproduce
1. install dependencies.
2. run build script.

### What is expected?
Building Success.

### What is actually happening?
typescript throws the following error.

```
semantic error TS2345: Argument of type '{ new (): { $props: VNodeProps & TeleportProps; }; __isTeleport: true; }' is not assignable to parameter of type 'string | ComponentOptions  | WritableComputedOptions >, MethodOptions, any, any, any> | ... 9 more ... | ClassComponent'.
  Type '{ new (): { $props: VNodeProps & TeleportProps; }; __isTeleport: true; }' is not assignable to type 'ComponentPublicInstanceConstructor  | WritableComputedOptions >, MethodOptions>'.
    Types of property '__isTeleport' are incompatible.
      Type 'true' is not assignable to type 'never'.
```

---
It looks like the incompatibility between the [Link: createBlock] and Teleport types is the cause of the.
Discussion
- `createBlock()` accepts the following types as its first argument:

```
ts
export type VNodeTypes =
  | string
  | VNode
  | Component
... [Log Snipped] ...
  | typeof TeleportImpl
  | typeof SuspenseImpl
```

Those `*Impl` types ares used internally only though. Externally, these implementations are cast to soemthing different - `typeof Teleport != TeleportImpl`.

First instinct is that we should use `Teleport` and `Suspense` here as well, instead of their internal `*Impl` counterparts.

This isn't a problem when not using `script setup` as the created render function never runs through the typescript compiler in these cases. In other words: a normal component creates the same render function, and at runtime it works - but only with `script setup` this is actually catched by the TS compiler.
- Workaround:

```
vue

  Teleport as teleport_,
  TeleportProps,
```
