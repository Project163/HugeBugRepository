Title

[GraalVM for JDK 24+] org.jboss.threads.JDKSpecific$ThreadAccess needs --add-opens java.base/java.lang=ALL-UNNAMED

Description
### Describe the bug

All GraalVM native integration tests are failing due to this issue. With JDK 24+ or better we see failures in native integration tests that look like this:

```
Caused by: java.lang.IllegalAccessError: module java.base does not open java.lang to unnamed module @79827e71; to use the thread-local-reset capability on Java 24 or later, use this JVM option: --add-opens java.base/java.lang=ALL-UNNAMED
	at org.jboss.threads.JDKSpecific$ThreadAccess. (JDKSpecific.java:32)
	at java.base/jdk.internal.misc.Unsafe.ensureClassInitialized0(Native Method)
	at java.base/jdk.internal.misc.Unsafe.ensureClassInitialized(Unsafe.java:1169)
	at org.graalvm.nativeimage.builder/com.oracle.svm.hosted.classinitialization.ClassInitializationSupport.ensureClassInitialized(ClassInitializationSupport.java:208)
... [Log Snipped] ...
	at java.base/java.util.concurrent.ForkJoinWorkerThread.run(ForkJoinWorkerThread.java:187)
Internal exception: com.oracle.svm.core.util.UserError$UserException: Class initialization of org.jboss.threads.JDKSpecific$ThreadAccess failed. Use the option
```

See for example here:
GraalVM for JDK 25: [URL]
Mandrel for JDK 24: [URL]

### Expected behavior

Native IT tests with GraalVM for JDK 24+ pass.

### Actual behavior

All native IT tests fail.
