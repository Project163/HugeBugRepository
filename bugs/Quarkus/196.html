Title

Incorrectly registered metrics inherited from superclasses

Description
```
@Timed
public class A  {
  public void a() {}
}

public class B extends A {
  public void b() {}
}
```

This setup should create 5 metrics
- `A.A` (for the constructor of A)
- `A.a`
- `B.B` (for the constructor of B)
- `B.b` 
- `B.a`

However, 
- instead of `B.B` we get `A.B`
- instead of `B.b` we get `A.b`
- `B.a` we don't get at all

The problem is basically that when registering metrics for subclasses, we use a `ClassInfo` of the subclass, which however does not by itself include information about the inherited annotations, so SmallRye is unable find the annotation on the desired class, and resorts to looking into the superclass, but when the annotation is found in the superclass, the name of the superclass is used to determine the name of the metric. 
Another part of the problem is that `SmallRyeMetricsProcessor` calls `registerMetrics` for each method of an annotated class, but doesn't take into account methods inherited from superclasses.

We basically need to find a way in the `JandexBeanInfoAdapter` to construct a `io.smallrye.metrics.elementdesc.RawBeanInfo` that contains inherited annotations, and adjust the logic in `SmallRyeMetricsProcessor.registerMetricsFromAnnotatedMethods` to call `registerMetrics` for inherited methods.
