Title

[asyncpg] rowcount not returned for SELECT statements

Description
### Describe the use case

`cursor.rowcount` always returns -1 for SELECT statements.

### Databases / Backends / Drivers targeted

asyncpg

### Example Use

```
result = await connection.execute(text("SELECT * FROM test"))
print(result.rowcount)
```

### Additional context

_No response_
Discussion
- I would be -1 on this (no pun intended) if this only works on asyncpg.    ~~DBAPI rowcount is only supposed to be for DML statements~~ we generally discourage the use of "rowcount" for plain SELECT statements as there is very little driver support for this and it also has major performance implications as it implies the database needs to retrieve the entire result set, and maybe even sending it to the client.

If this is relevant to a CTE INSERT, then it should work for all the PostgreSQL drivers and we'd need all-pg-backend tests which exercise this.  the bug would be that no test is exercising this right now.
