Title

d3.geom.voronoi fails with N=2

Description
"""
I've been playing around with the voronoi implementation and found 
that it has a bug (well at least IMHO). The problem arises the case 
when the number of sites is two _and_ you want to clip the cells. 
Context, the documentation at [URL] 
states that when you want clipped cells, you have to post process the 
results using polygon.clip. However, when you pass only two sites to 
the voronoi function, the return value will basically be two lines 
(instead of closed polygons). Using polygon.clip on a line has 
undefined results. This whole behavior is demonstrated here: 
[URL] (Tried to make a 
bl.ocks.org out of it but that didn't work for me). 
I do understand that clipping is not a default action in the voronoi 
implementation for performance reasons. However, clipping should work 
for all results of a voronoi tessalation. A possible solution would be 
to add an extra vertex to all polygons, resulting from a call to 
voronoi, which have only two vertices. I'm not sure if adding one 
vertex is enough though as this might result into missing corners in 
due to the clip in some cases. 
"""

One of the problems with your code is that you've inverted the meaning of polygon.clip: it's bounds.clip(polygon), meaning that the argument to the clip method is the polygon that you want to clip, and the object performing the clipping represents the bounding polygon. So, something like this:

``` js
var rect = d3.geom.polygon([[0, 0], [0, height], [width, height], [width, 0]]);
var clippedPolygon = rect.clip(polygon);
```

Clipping will also fail if you use a closing coordinate for d3.geom.polygon (i.e., an extra [0, 0] at the end), which should probably be documented or fixed.
