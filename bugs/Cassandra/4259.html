Title

When forcibly exiting due to OOM, we should produce a heap dump

Description
CASSANDRA-7507   introduced earlier termination on encountering an OOM, due to lack of certainty about system state. However a side effect is that we never produce heap dumps on OOM. We should ideally try to produce one forcibly before exiting.
Discussion
- I guess the simplest way would be to add the  -XX:+HeapDumpOnOutOfMemoryError   command line argument to our startup scripts.

 Sorry, I initially misunderstood the problem. 

 The patch use  jmap  to generate a heap dump when the  JVMStabilityInspector  detects an OOMError.  
One issue is to retrieve the process ID to be able to execute the  jmap  call. The Java API will only provide a reliable way for retrieving the process ID in Java 9. The current method used by the patch will work on the Oracle JVM but might not work on all the JVMs. If the process ID cannot be retrieved no dump will be generated.
