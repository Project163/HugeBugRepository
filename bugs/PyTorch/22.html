Title

Attempt to use jited `torch.isnan` hit internal assert

Description
## 🐛 Bug

Running JITed `lambda x: x.isnan()` crashes on SkyLake CPU but passes on Haswell if input type is `torch.float16`:

## To Reproduce

Steps to reproduce the behavior:

1. Download build artifacts from recent CI build, for example [URL]
1. Run following code
```
#!/usr/bin/env python3
import torch

torch._C._jit_override_can_fuse_on_cpu(True)
torch._C._debug_set_fusion_group_inlining(False)
... [Log Snipped] ...
f = torch.jit.trace(lambda x: x.isnan(), (inp,))
y = f(inp)
```
which is a trimmed down version of 
[URL]

And it will crash as follows:
```

  - GCC 7.5
  - C++ Version: 201402
  - Intel(R) Math Kernel Library Version 2020.0.2 Product Build 20200624 for Intel(R) 64 architecture applications
  - Intel(R) MKL-DNN v2.1.2 (Git Hash  )
... [Log Snipped] ...
python: /tmp/llvm/lib/CodeGen/SelectionDAG/LegalizeVectorTypes.cpp:2032: bool llvm::DAGTypeLegalizer::SplitVectorOperand(llvm::SDNode*, unsigned int): Assertion `Res.getValueType() == N->getValueType(0) && N->getNumValues() == 1 && "Invalid operand expansion"' failed.
Aborted (core dumped)
```

It should pass
