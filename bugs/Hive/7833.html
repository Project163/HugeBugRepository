Title

UNION query with regular expressions for column name does not work

Description
STEPS TO REPRODUCE:  

 1. Create a table: 

  
 CREATE TABLE t (a1 INT, a2 INT);
INSERT INTO TABLE t VALUES (1,1),(1,2),(2,1),(2,2); 
  

 2. SET hive.support.quoted.identifiers to "none": 

  
 SET hive.support.quoted.identifiers=none; 
  

 3. Run the query: 

  
 SELECT `(a1)?+.+` FROM t
UNION
SELECT `(a2)?+.+` FROM t;

Discussion
- ROOT-CAUSE  

 Current issue is the regression of Apache  HIVE-15938  :  position alias in order by fails for union queries  

 Reverting of  HIVE-15938  from Hive fixes the issue. Place that introduces the bug is method  processSetColsNode()  from class  ParseUtils : 

  
 
   /**
     * Replaces a spurious TOK_SETCOLREF added by parser with column names referring to the query
     * in e.g. a union. This is to maintain the expectations that some code, like order by position
     * alias, might have about not having ALLCOLREF. If it cannot find the columns with confidence
     * it will just replace SETCOLREF with ALLCOLREF. Most of the cases where that happens are
     * easy to work around in the query (e.g. by adding column aliases in the union).
     * @param setCols TOK_SETCOLREF ASTNode.
     * @param searcher AST searcher to reuse.
     */
     private   static  void processSetColsNode(ASTNode setCols, ASTSearcher searcher) {
      searcher.reset();
 
  

 which as added in scope of  HIVE-15938 .
- SOLUTION  

 Add verification 

  
 
 if  (SemanticAnalyzer.isRegex(colAlias, conf)) {
  LOG.debug( "Skip creating child column reference because of regexp used as alias: "  + colAlias);
   return   false ;
}
 
  

 and skip adding child column reference if column alias is regex in  ParseUtils . 

  EFFECTS  

 1. Parsing of  UNION  queries 
2. Parsing of  ORDER BY  with column id
