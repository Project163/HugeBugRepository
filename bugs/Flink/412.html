Title

Deadlock in SuccessAfterNetworkBuffersFailureITCase

Description
I ran into the issue in a Travis run for a PR:  [URL]

 I can reproduce this locally by running SuccessAfterNetworkBuffersFailureITCase multiple times:

Discussion
- I'm debugging this. The result so far is that some backwards termination events (from sync task to heads) get lost. The sync task sends out all tasks and clear itself. I'm currently trying to figure out where the events get lost...
- GitHub user uce opened a pull request: 

      [URL]

       FLINK-2134   Close Netty channel via CloseRequest msg 

     The failing `SuccessAfterNetworkBuffersFailureITCase` discovered a race between sending backwards events (e.g. from sync task to iteration head task) and closing the TCP channel. The close overtook outstanding backwards task events. This change guarnatees that it is in order by sending a explicit close msg. 

     (I've also tried other approaches, but this struck me as the simplest solution.)
