Title

Inconsistent behaviour between dev and build in parallel routing.

Description
### Link to the code that reproduces this issue

[URL]

### To Reproduce

1. Clone the mentioned project
2. `npm install`
3. `npm run dev` (for development)
4. `npm run build` followed by `npm run start` (for production server)

The [Link: src/app/routing/parallel-routing/@slot1/layout.tsx] should be visible for the `@slot1`. In dev mode, this works as expected, but in build mode, the layout seems to be missing.

- So currently the parallel routes have a lot of bugs and there are still a lot of issues pending for the Next.js team to focus on, I went ahead and resolved this issue using `router.push()` and `router.refresh()` methods.

I know they will be solved soon, but releasing such big features without proper testing seems less professional. Considering I discovered this bug while toying with Next.js.

Anyhow, I'll keep this issue open until someone from the team presents a resolution!
- Hi there - thanks for the report. 

Slots do not support layout files -- that shouldn't be working in dev, so we'll take a look! Parallel routes are meant to be used within a shared layout.

Our [Link: Parallel Routes docs] clarify this a bit more. The supported file types for a slot are `error`, `loading`, `page`, and `default`.
