Title

Verifier.addDefaultParameters erases metadata if run more than once

Description
When processing sources with closure with parameter defaults,  Verifier  is wiping out the node metadata that contains the initial value expression.  At the end of  addDefaultParameters(DefaultArgsAction action, MethodNode method) , there is a for loop: 

  
 
         for  (Parameter parameter : parameters) {
             // GRECLIPSE add
              if  (!parameter.hasInitialExpression())  continue ;
             // GRECLIPSE end
              // remove  default  expression and store it as node metadata
             parameter.putNodeMetaData(Verifier.INITIAL_EXPRESSION, parameter.getInitialExpression());
            parameter.setInitialExpression( null );
        }
 
  

 This loop currently moves the initial expression to node metadata.  However, when this method runs a second time, it takes null from  getInitialExpression  and puts that as the new metadata value, even if the node already has been processed. 

 Adding a check  hasInitialExpression  solves this issue, making  addDefaultParameters  idempotent.  This also prevent adding the metadata value in the first place for a parameter that never had a default value expression.
Discussion

 From there, I'm not sure if it would be unset within an AST transform, but it was unset when visiting the AST in eclipse for purposes of semantic highlighting of the source.
- It wouldn't normally be called from AST transforms. It would appear possible with joint compilation and static compilation together. I have already added the code change but didn't have a test. I think the idempotent code is safer anyway, so I'll close.
