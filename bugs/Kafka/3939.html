Discussion
- The first issue, "Unexpected state transition from ERROR to PENDING_SHUTDOWN"  [1] , was caused by a racing between streams.close() and shutdownHelper() thread  [3] . 

 After GlobalThread dead, the shutdownHelper() thread is triggered asynchronously.  [2]  [3]  
The state of KafkaStream changes in this order: RUNNING -> PENDING_ERROR -> ERROR 

 However, the test called stream.close() in parallel  [4] , which conduct a non-atomic check-and-set flow as shown below:  [5]  
 
	 state.hasCompletedShutdown() (Passed if state is in PENDING_ERROR) 
	 state.isShuttingDown() (Passed if state is in ERROR) 
	 setState(State.PENDING_SHUTDOWN)  
 

 The third step will throw an error since state transition "ERROR to PENDING_SHUTDOWN" is illegal. 
This racing issue can be simulated by the attached patch.   0001-reproduce-unexpected-state-transition.patch

- The second issue, "Condition not met within timeout 15000"  [1] , occured when the KafkaStreams stayed in "PENDING_ERROR" for too short time . In my local PC, it only stay for 7 ms before transite to ERROR. 

 This can be reproduced by adding a little delay before checking "PENDING_ERROR" in the test:  patch   0002-reproduce-waiting-timeout-for-PENDING_ERROR.patch
