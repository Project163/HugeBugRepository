Title

Multiple scheduled methods overrides they configuration

Description
### Describe the bug

If you define multiple methods annotated as `@Scheduled` they override configurations. 

First:
```
java
@ApplicationScoped
class StaticScheduler {

	@Scheduled(cron = "0 1 * * * ?")
... [Log Snipped] ...

}
```
second:
```
java
@ApplicationScoped
class ScheduledNonStatic {

	@Scheduled(cron = "1 * * * * ?")
... [Log Snipped] ...

}
```

effective configuration visible in dev-ui:

[Image: Image]

And `scheduledStatic` is called with the same trigger as `scheduledNonStatic`. Original configuration is ignored.

### Expected behavior

Configurations should not be overridden. Methods should work with they own triggers.

### Actual behavior

The last loaded method definition overrides all other definitions.

Discussion
- It's a problem with static `@Scheduled` methods which are probably only rarely used because we did not have a similar report yet. In any case, the [URL] should fix the problem.
- In the meantime, reverting to a non-static scheduled methods works around the bug in older versions.
