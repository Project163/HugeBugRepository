Title

Fails to create mock of inner class hierarchy with type variable from outer class

Description
Reported on the mailing-list [Link: here] by Thang

This bug exists in Mockito 2.1.0 and does not exists in 1.10.19. The issue seems related to how ByteBuddy gather type variables.

Here's how to I reproduced the issue : 

```
java
public abstract class AbstractOuter  {
    public abstract class AbstractInnerParent {
        public abstract InputT input();
        public abstract void output(OutputT output);
... [Log Snipped] ...
    public abstract class AbstractInnerParentChild extends AbstractInnerParent { }
}
```

``` java
@Test
public void should_not_fail_creating_mock_of_inner_class_with_type_variable_of_outer() {
    mock(AbstractOuter.AbstractInnerParentChild.class,
         withSettings().outerInstance(AbstractOuter.class));
}
```

This code produces the following stacktraces, VM is irrelevant here.

```

Mockito can only non-private & non-final classes.
If you're not sure why you're getting this error, please report to the mailing list.

```

Discussion
- Its a bug in Byte Buddy, it does not capture the scope of the variables correctly.
- I see what is happening here. Byte Buddy is asked to subclass an inner type what is not normally legal. A subclass must always be declared in the scope of its outer type. As Byte Buddy applies the Java rules for type variable resolution, such a variable cannot be found and the exception is thrown.

I need to detect such subclassing and rather apply the erasure as the variable does not technically exist for the mock class.
