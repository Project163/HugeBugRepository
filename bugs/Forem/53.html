Title

File is deleted after executing test suite

Description
**Describe the bug**
The following file is deleted while going through the test suite:
`spec/support/fixtures/approvals/liquid_tweet_tag_spec.received.html`

**To Reproduce**
`rspec spec/liquid_tags/tweet_tag_spec.rb:24`
(It "renders properly ...)

**Expected behavior**
The file should not be deleted

not applicable

Chromium 76 installed to handle Selenium tests, on Ubuntu 19.04
Discussion
- Very interesting, confirmed that I can replicate this.
- If we look at the files in ``spec/support/fixtures/approvals/``, all of them are ``.approved`` except for this one which has both an ``.approved`` and a ``.received`` file.

[Image: fixtures]

According to the [Link: github page for approvals]:

```
If the contents of the received file is to your liking, you can approve the file by renaming it.

mv my_spec.received.txt my_spec.approved.txt
```

This probably means that at some point ``spec/support/fixtures/approvals/liquid_tweet_tag_spec.received.html`` was approved, renamed, but was not removed from git history.

If we look at [Link: the source code for Approvals.verify], it creates a ``.received`` file from an object, looks for an ``.approved`` file, check if they match, and then deletes the ``.received`` if the match is successful, so this seems to be the expected behaviour. 

The correct thing to do here would be to actually **delete this file and commit the changes**.
