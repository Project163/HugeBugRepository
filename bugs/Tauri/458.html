Title

[bug] Tauri V2: CSP issues on external window URLs

Description
### Describe the bug

Hi! I'm using Tauri v2 and have a window with an external URL. This worked fine with injecting scripts and calling to rust when I was previously on v1, but I recently switched to v2. Now, I get content security policy errors like the following when using any window.__TAURI__ API; for example:
```
Refused to connect to '[URL] because it violates the document's Content Security Policy.
```

I'm sorry if I'm overlooking something. Thank you!

### Reproduction

- Create a new Tauri v2 project
- Add the following code to `main.rs`:
```
rust
// Prevents additional console window on Windows in release, DO NOT REMOVE!!
#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]

#[tauri::command]
... [Log Snipped] ...
        .expect("error while running tauri application");
}
```
- In the console, you should see `Refused to connect to '[URL] because it violates the document's Content Security Policy.`

### Expected behavior

The Tauri APIs should ideally work regardless of the site's content security policy, but I understand that's likely not an option. This setup worked in Tauri v1, so something is different. From what I can tell, Tauri used `window.ipc.postMessage` but now uses these custom protocols on Windows and MacOS; I assume it's not as easy as overriding `ipc_custom_protocol` to false, but doing that along with overriding the check in `ipc-protocol.js` seems to work in most situations.
