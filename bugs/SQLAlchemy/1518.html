Title

Incorrect serialization/deserialization of the `over` clause

Description
### Describe the bug

When serializing and deserializing a statement containing the `over` clause with `None` or `0` in range using `sqlalchemy.ext.serializer`, the resulting query contains a different range. Concrete ranges like `(1, 2)` seem to work fine.

The issue can be reproduced in both v2 and v1.4, the latter having a seemingly undefined parameters in the result.

While the serializer extension in considered legacy, we are (unfortunately) still using it in our RPC scenario with untrusted user inputs. Any tips on how to patch `over` on the user side or any alternatives to `sqlalchemy.ext.serializer` are much appreciated)

### To Reproduce

```python
import sqlalchemy as sa
from sqlalchemy.ext.serializer import dumps as sa_dumps, loads as sa_loads


stmt = sa.func.SUM().over(range_=(None, 0))
dumped_query = sa_dumps(stmt)
loaded_query = sa_loads(dumped_query)
```

### Error

Expected result (the same as for the original statement):
```
'sum() OVER (RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)'
```

Actual result for `SQLAlchemy-2.0.30`:
```
'sum() OVER (RANGE BETWEEN CURRENT ROW AND 1 FOLLOWING)'
``` 

Actual result for `SQLAlchemy-1.4.52`:
```
'sum() OVER (RANGE BETWEEN   FOLLOWING AND   FOLLOWING)'
``` 
with exact numbers varying per run.
