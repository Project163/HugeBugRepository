Title

Cardinality Agg wrongly accepts sub aggregation

Description
On the REST API you can construct a request for a cardinality aggregation which has a sub-aggregation.  This should not be allowed since the Cardinality aggregation is a metrics aggregation.

```
js
POST test/doc/1
{
  "l":1
}
... [Log Snipped] ...
  }
}
```

This returns 

```
{
   "took": 5,
   "timed_out": false,
   "_shards": {
      "total": 5,
... [Log Snipped] ...
   }
}
```

It should instead throw an error response back.
