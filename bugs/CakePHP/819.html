Title

CookieComponent writes bad cookie since 3.3.5

Description

- CakePHP Version: 3.3.5
- Platform and Target: NGINX, Mysql PHP-FPM.
### ISSUE

In my Application I use the CakeDC/Users plugin which provides the RememberMeComponent.
This component writes a bad cookie on login since cakephp 3.3.5. When I debug CakeDC\Users\Auth\RememberMeAuthenticate the cookie which is read is empty.

When I downgrade to cakephp 3.3.4 and do a login, the rememberme works fine, then I update to 3.3.5 and it successfully logs me in with the cookie written by 3.3.4.
Discussion
- What is wrong about the cookie? Are your cookies encrypted?
- Yeah they get aes encrypted with the app salt. I did not configure anything related to cookies, I have a basic app using cakedc users. 
I think the cookie encryption is default behavior. 
I checked the diff from 3.3.4 to 3.3.5 and there are some cookie related changes so I hope the bug is not on my end.

I also checked the Cookie Components config and they both have the app salt as key.
When I try to read a Cookie in 3.3.5 it is an empty string but Cookie->check() returns true.
I figured since in 3.3.5 I can read the remember_me cookie written by cakephp 3.3.4, the problem lies in Cookie->write in 3.3.5
