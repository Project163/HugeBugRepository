Title

child_process.execSync() in cluster mode crashes pm2 logs

Description
I'm on OSX 10.10.3 and using io.js v2.3.1 and pm2@0.14.2

Reproduce:
`pm2 --no-daemon start test.json`

The config file `test.json`:

```
json
{
  "apps" : [{
    "name"               : "test",
    "script"             : "tmp/test.js",
... [Log Snipped] ...
  }]
}
```

The app `tmp/test.js`:

``` js
'use strict'
setInterval(function () {
    console.log('run `echo`')
    require('child_process').execSync('echo')
}, 200)
```

The output:

```
➜  paidui git:(master) ✗ pm2 --no-daemon start test.json
pm2 launched in no-daemon mode (you can add DEBUG="*" env variable to get more messages)
2015-06-26 11:42:07: [PM2][WORKER] Started with refreshing interval: 30000
2015-06-26 11:42:07: [[[[ PM2/God daemon launched ]]]]
2015-06-26 11:42:07: BUS system [READY] on port /Users/xiaody/.pm2/pub.sock
... [Log Snipped] ...
    at Socket.ondata (_stream_readable.js:521:20)
➜  paidui git:(master) ✗
```
Discussion
- The `process.stdout.write` in `io.js` only accept `String` argument.
Currently it's an object like `{type: 'Buffer', data: []}`. @jshkurti
- See [URL]
execSync() write some `Buffer` data but after being passed between processes, the data is no longer a Buffer (`Buffer.isBuffer() --> false`) (see also [URL]
And finally the io.js socket refuse to write it [URL]
- `npm i -g Unitech/PM2#development` does this fix it ? :)
- It does actually, I just tested.
Thanks for reporting this :)
