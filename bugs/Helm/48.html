Title

Fix output when --verify flag used

Description
Output of `helm version`: 3.1.0

Here's some example output...
```
$ helm pull --verify --keyring foo.pgp demo-repo/foo
Verification: &{  sha256:  foo-0.1.0.tgz}
```

Don't think this is what we expect to see.
Discussion
- Doing more digging I found that the UI output pattern was explicitly put in this way. It looks like it was via the commit  . Later commits around this just updated it or added tests to show it.

Because this is a UI change it would be considered breaking to change this. We might need to put this off to Helm v4. Unless this was an unintended bug that's lasted a long time. Paging @technosophos 

Prior to this change more useful information, such as who signed, was provided.
- Doing more research... Here's how it works when things fail...

The case where the sha's do not match
```
$ helm pull --verify --keyring foo.pgp demo-repo/foo
Error: sha256 sum does not match for foo-0.1.0.tgz: "sha256: " != "sha256: "
```

When the key is not in the keychain used for verification...
```
$ helm pull --verify --keyring foo2.pgp demo-repo/foo
Error: openpgp: signature made by unknown entity
```

And, when the signature is from some known and the hash listed matches the file but the sig is for something else...
```
$ helm pull --verify --keyring foo.pgp demo-repo/foo
Error: openpgp: invalid signature: hash tag doesn't match
```

The issue is with the information when the verification passes.
- This was most definitely a bug that I introduced.
