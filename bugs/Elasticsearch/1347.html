Title

Plugin Installation No Longer Checks for Already Installed Plugin

Description
When installing a plugin in ES 1.7, there is a check to verify that the plugin doesn't already exist, and the plugin installation aborts if it does: 

```
bin/plugin install elasticsearch/license/latest
-> Installing elasticsearch/license/latest...
Trying [URL]
Downloading ..............................DONE
Installed elasticsearch/license/latest into /path/to/elasticsearch-1.7.0/plugins/license
... [Log Snipped] ...
-> Installing elasticsearch/license/latest...
Failed to install elasticsearch/license/latest, reason: plugin directory /path/to/elasticsearch-1.7.0/plugins/license already exists. To update the plugin, uninstall it first using --remove elasticsearch/license/latest command
```

In 2.0, this check no longer appears to take place, and the plugin installation appears to be attempted and fails: 

```
bin/plugin install license
-> Installing license...
Trying [URL] ...
Downloading ......DONE
Verifying [URL] checksums if available ...
... [Log Snipped] ...
jar1: /path/to/elasticsearch-2.0.0-rc1/plugins/license/license-2.0.0-rc1.jar
jar2: /var/folders/1r/t56v_5710ygd6klpsbsrmbsr0000gn/T/ /license/license-2.0.0-rc1.jar
```
Discussion
- Its actually not really trying to install the plugin again, its just that the jar hell check happens before the "already installed check". Thanks @skearns64
- The issue is unique to this license plugin: it hits this problem because it uses the deprecated `isolated=false`. This kind of thing is not really surprising, its why we deprecated it...
