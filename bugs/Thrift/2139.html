- So the problem, as I understood it, is that 

 1. You do not have go namespaces explicitly defined in the thrift files, so the go namespaces are inferred from the file names 
2. We added a logic to dedup multiple includes from the same namespace, that logic likely incorrectly assumed that the two different thrift files without go namespaces are from the same go namespace and dedup'd the second one. The logic likely didn't get the inferred namespace from filename correctly.
- So while we can fix 2, 1 is a much easier immediate fix for you (by adding explicit go namespaces to the thrift files).
