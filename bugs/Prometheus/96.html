Title

promtool rule test flaky (not deterministic) when eval_times are far apart

Description
# promtool is flaky when eval_times are far apart in a rule test

## What did you do?

Ran `promtool test rules bug.testall.flaky.yaml` and got different results:
```
$ promtool-2.20.0 test rules bug.testall.flaky.yaml 
Unit Testing:  bug.testall.flaky.yaml
  FAILED:
    expr: "some_metric", time: 1h,
        exp:"{__name__=\"some_metric\"} 0E+00"
... [Log Snipped] ...
Unit Testing:  bug.testall.flaky.yaml
  SUCCESS
```
I used a script tun run promtool many times in succession to observe the flakiness.

The test has a single `promql_expr_test` against a trivial metric, but the `eval_time` of the two ` `s are many `evaluation_interval`s apart. See the full file below.

## What did you expect to see?

It appears that under some circumstances, the test tool drops old data (see the failure above).

I expect the test tool not to drop any old data under any circumstances and, in this case, the test should consistently succeed.

* versions that exhibit the correct behaviour: `2.15.2`, `2.16.0`
* versions that exhibit the bug: `2.17.0`, ..., `2.20.0`

## What did you see instead? Under which circumstances?

I was unable to pinpoint to a particular reason for a failed vs successful run.

If you are getting consistent results, try running the tool 100 times and/or tweaking the later `eval_time`.
The value posted below (`30000h`) worked reasonably fine to trigger the flakiness on my system.

## Workaround

In my case the easiest workaround was to place the tests with different `eval_time` into separate files (see `bug.test1.ok.yaml` and `bug.test2.ok.yaml` in the attached archive).

Note that making these a separate ` ` in a single file didn't help.
