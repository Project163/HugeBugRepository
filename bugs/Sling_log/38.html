Discussion
- the corresponding logger misconfiguration that caused this was: 
  
 <jcr:root xmlns:sling= "http: //sling.apache.org/jcr/sling/1.0" 
 	xmlns:jcr= "http: //www.jcp.org/jcr/1.0"  jcr:primaryType= "sling:OsgiConfig" 
 	org.apache.sling.commons.log.file= "logs/my-granite-project.log" 
	org.apache.sling.commons.log.level= "debug" 
	org.apache.sling.commons.log.names= "[demo.demo]" 
	org.apache.sling.commons.log.pattern= "\{0,date,yyyy-MM-dd HH:mm:ss.SSS} {4} [{3}] {5}"  />
- One thing to note that logging would still work and all log message with level INFO+ would be directed to stdout.log. So no loss of imp log message here.  

 Would update the configuration logic to handle such cases if possible and ignore malformed message formats
- Fixed with  [URL] In case of any error in pattern a default pattern would be used
