Title

SSL connection silent drop on unknown certificate

Description
**Description:**

Syncthing silently drops a connection when it does not know the peer certificate. 

**How to reproduce:**
1. Run one clear (no config) instance of syncthing to have it generate its certificate. You may then stop it.
2. Run one other clear (no config) instance of syncthing with full debug log (STTRACE=all). Do not configure the peer connection.
3. Using the cert.pem and key.pem from the first syncthing, try a connection using openssl towards the other:

```
cd ~/.config/syncthing/
openssl s_client -connect [remote_ip_goes_here]:22000 -state \ 
  -cert cert.pem -key key.pem 
```

Openssl will report:

```
(...)
SSL3 alert read:warning:close notify
closed
SSL3 alert write:warning:close notify
```

signalling that the remote end closed the SSL connection. No log entry justifying the connection termination is observed on the targeted syncthing instance. 

**Expected result:**

A log entry in the debug log signalling the termination should be output. Any SSL termination should be logged.

**Rationale:**

Syncthing is presented as a reference implementation of the protocol. As such the debug log should be very verbose; more verbose than if it were implemented for application users.

I don't know enough about TLS for an informed opinion but, going out on a limb, I imagine TLS has provisions for reporting failed client certificate authentication.

It's a bit of a separate issue, but if you are going to touch the code near this event, it may be a good opportunity to improve the behaviour.
- It may have - if so it doesn't seem like that functionality is exposed in the Go implementation of TLS. We could send back a packet with an error message. At some point I think a CLOSE message of some kind should be implemented anyway to be able to say "I'm going to close the connection now for the following reason: ..." and that could be used. (#122)
