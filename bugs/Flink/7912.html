Title

Avoid delete ForSt's directory when there happened to be an existing one

Description
Currently, ForSt State backend will create the working directory, if there exists one with same name the directory will be cleared. The name contains jobid, vertexid, task_index, parallelism and attempt. In JM failover scenario, this would be a collision as the attempt number restart from 0, resulting in checkpoint broken. 

   

 We should remove the clear existing directory logic.
