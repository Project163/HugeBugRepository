Title

Artifact filter misbehaves when plugin run on Windows

Description
Consider a configuration like 
  
  <configuration> 
   <filters> 
     <filter> 
       <artifact> foo:bar </artifact> 
       <includes> 
         <include> **/a.properties </include> 
       </includes> 
       <excludes> 
         <exclude> org/apache/* </exclude> 
       </excludes> 
     </filter> 
   </filters> 
 </configuration> 
 
  

 When the plugin gets executed on Windows, this will erroneously exclude the path "a.properties" (though included by "**/a.properties") and "org/apache/maven/a.properties" (though not excluded by "org/apache/*"). 

 This is due to misuse of util methods that expect the platform-specific file separator to be used for the paths but the plugin uses the unaltered strings from its configuration. This discrepancy prevents proper directory splitting, leading to the described mismatches.
