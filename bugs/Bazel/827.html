Title

Description

bug: fatal error when start bazel with --output_user_root=/data/tmp/

Discussion
- Good point about Bazel trying to make a directory that already exists. We should look at this.

But if you want to share a cache between users, you probably want to use `--disk_cache` instead. We don't support using `--output_user_root` to share data between users. Does that help?
- @susinmotion I thought "--output_user_root" option is created with goal to share build objects with other users. See [URL] section "--output_user_root". Am I getting it wrong?
- ... [Middle Discussions Snipped for Brevity] ...
- OK, so this was an intentional change but unfortunately it's from cl/69071385 (not available in Git, back from 2014). The change description provides no rationale for the change other than "be paranoid with directory creation", and we have an integration test to verify that the user root cannot actually be shared among users.

I understand why this may be desirable when the output root goes, by default, into a temporary directory that may be shared across users. And it does, e.g. as in #11100.

So... I think the answer here is to change the documentation to say that this is not supported instead of trying to fix this.
- That rings a bell. Before open-sourcing Bazel, we went through a security review, and the reviewer may have pointed out the risk in sharing the output directory locally.
