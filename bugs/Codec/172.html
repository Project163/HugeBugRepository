Title

org.apache.commons.codec.language.bm.Rule.parsePhonemeExpr(String) adds duplicate empty phoneme when input ends with |

Description
Component: org.apache.commons.codec.language.bm.Rule 

 Method: private static PhonemeExpr parsePhonemeExpr(String ph) 

   
   Problem 

 When the input string is  (()|)  

 The method  parsePhonemeExpr(String)  first strips the parentheses, producing:  body = "()|”  
Then it executes  body.split(" [|] ")  
Due to Java's default behavior, the trailing empty string (after the  | ) is discarded, resulting in   ["()"]   
To compensate for this, the following logic is used: 
if (body.startsWith("|") || body.endsWith("|")) 

{     phs.add(new Phoneme("", Languages.ANY_LANGUAGE)); }

 However, the  "()"  entry already results in a  Phoneme("")  when parsed. 
As a result, the list ends up containing two empty phonemes, which seems unintended. 
   Expected Result 

 Only one empty phoneme should be added for (()|). 

   
   Actual Result 

   

 Two empty phonemes are returned: 
 
	 One from parsing "()" 
 

 
	 One manually added due to .endsWith("|")

- Hi  ggregory , 

 I investigated the call chain of the "parsePhonemeExpr" method and found that it is invoked by "parseRules", which in turn is called during the construction of Rule. Therefore, I focused on whether creating a Rule instance behaves correctly when encountering a specific phoneme expression. 

 To test this, I created a rule file at: src/test/resources/org/apache/commons/codec/language/bm/gen_rules_english.txt 
With the following content: "s" "" "" "(()|)" 
This rule is picked up during Rule initialization. The phoneme expression "(()|)" is parsed via "parsePhonemeExpr", which is expected to return a PhonemeList containing exactly one phoneme (an empty one). However, the method currently returns two phonemes, incorrectly treating the trailing "|" as a separate empty phoneme. 

 To verify this behavior, I wrote a JUnit 5 test with proper camel case naming conventions: 
  
 
 package  org.apache.commons.codec.language.bm;
 import  java.util.List;
 import  org.junit.jupiter.api.Test;
 import   static  org.junit.jupiter.api.Assertions.assertEquals;
 public   class  RuleParsePhonemeExprTest {
    @Test
     public  void TestRule() {
        List<Rule> rules = Rule.getInstance(NameType.GENERIC, RuleType.RULES,  "english" );
        Rule rule = rules.stream()
                .filter(r -> r.getPattern().equals( "s" ))
                .findFirst()
                .orElseThrow(() ->  new  AssertionError( "Rule not found" ));
        Rule.PhonemeExpr expr = rule.getPhoneme();
        assertEquals(1, expr.size());  // Expected 1, but got 2
     }
}  
  

 In this test, expr.size() should return 1, but it actually returns 2, confirming the bug in "parsePhonemeExpr".
