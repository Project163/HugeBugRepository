Title

groovyc doesn't check that inherited abstract methods are implemented

Description
groovyc will successfully compile a class that doesn't implement all of  it's abstract inherited methods. For example 

 public interface Iface { 
    String getName(); 
} 

 class Impl implements Iface { 
} 

 These will both compile fine, but then this test case will fail throwing a groovy.lang.MissingMethodException 

 class ImplTest extends GroovyTestCase { 
  void testBasic()  
{ 
    Iface i = new Impl()
    assert i.getName() != null
  }
 }
Discussion
- we should check that we overload all abstract methods in the base class as well
- The enclosed file is a patch containing the changes to have Groovy correctly generate 
errors when compiling a non-abstract class that does not implement all of the  
methods required by its declaration. This correctly finds both cases where a method from an abstract superclass is unimplemented, and cases where methods from an interface are unimplemented. 

 Both the example from this bug report, and the modified "Bar.groovy" from the src/tests directory can serve as simple tests for this. (I'm not sure how to wrap them as tests; I haven't learned much maven yet, and I'm not sure how to add a test that requires the compiler to fail.) 

 I will attach some more interesting tests tommorow.
- This (really final this time) patch checks for unimplemented abstract 
methods, both inherited from superclasses, and declared in implemented interfaces. It includes a set of unit tests.
