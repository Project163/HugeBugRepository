Title

Memory Leak in gRPC Python Server

Description
We have run into a consistent leak in a python gRPC server we wrote and have determined it must be happening somewhere in gRPC. I've included a simple script to reproduce the problem quite quickly in python. Note sure how to track down the leak or if it's on the python side or in the C core. We have tried replacing the worker queue with a different one (not concurrent.futures thread pool) and that didn't help. We also switched to a different simple python RPC  service ([Link: speedy]) and that completely fixes the problem. 

I've attached a zip of requirements.txt (just futures, grpc and proto), compiled proto and client / server setup. The server can run with a simple client sending requests in a loop and the server will leak. The bigger the request size the faster it leaks. The server will print out the memory for you (or you can watch it increase in top). Here is how you run the server: 

```
python leaky/server.py --port 3000 --pool_size 100 --run_client_here 1
```

You can also run the client and server separately: 

```
python leaky/server.py --port 3000 --pool_size 100 
```

```
python leaky/client.py
```

[Link: leaky.zip]

- I did some investigation using [Link: this client] and [Link: this server].  The leak in the server is related to the size of the request (i.e. reading) and does is not affected by the size of the response (i.e. not writing).

In the following, the x axis is the number of identical requests made from the client to the server, and the y axis is the server's memory usage in MB. When the response size is small but the request size is large, the memory leak is clearly visible:

When that is reversed so that the responses are large but the requests are small, the memory leak doesn't occur.
[Image: large_response]

Valgrind gives me the same stack trace that @zeiler posted above.  I've scoured the source but I can't find anywhere that fails to free memory nor any obvious circular references.  However, my understanding of the source is still sketchy.
