Title

[Bug]: "Maximum call stack size exceeded" error when using Cally date picker

Description
### Describe the bug

When the [Link: Cally] date picker is used in Storybook, a "maximum call stack size" error occurs. This error does not occur outside of Storybook.

### Reproduction link

[URL]

### Reproduction steps

1. Check out the repro and run `npm i`. 
2. Run `npm run storybok`. This command runs React + Vite + Storybook.
3. In a browser, open [URL]
4. Open browser dev tools and open the console tab.
5. Click a date.
6. Note that the follwoing error appears in console: "VM1030 cally.js:19 Uncaught RangeError: Maximum call stack size exceeded".
7. Press an arrow key.
8. Note that the highlighted date does not move.

This repro uses Storybook React, but I've also seen the issue when using Storybook Angular.

### Viewing expected behavior

1. Run `npm run dev`. This command runs a React + Vite app.
2. Open the local dev site in a browser.
3. Open browser dev tools and open the console tab.
4. Click a date.
5. Note that no errors appear in console.
6. Press an arrow key.
7. Note that the highlighted date moves in the direction of the arrow key that was pressed.

### Additional context

The "maximum call stack size" error appears when Cally [Link: attempts to focus] to focus the button for currently selected date. This logic runs when the month is focused.

If focus events bubbled, then I could see why this error would occur. The button's focus event would bubble up to the month, which would trigger another button focus, which would trigger another month focus, which would trigger another button focus, etc.

My understanding is that [Link: focus events don't bubble], so I'm confused as to why this loop would occur. Is it possible that something in Storybook is causing focus events to bubble?

Thank you!!
Discussion
- I found the root cause of the issue,but I’m not sure whether it’s something Storybook needs to fix or if it’s intended behavior.

Storybook globally overrides `HTMLElement.prototype.focus`, changing it from a normal function property into a `getter` accessor property (in `code/core/src/test/preview.ts`).

```
ts
Object.defineProperties(HTMLElement.prototype, {  
  focus: {  
    configurable: true,  
    set: (newFocus: () => void) => {  
... [Log Snipped] ...
  },  
});
```

When a focus event is triggered (via mouse click, keyboard arrow keys, etc.),
an internal function in the **Cally** library accesses this modified `focus` property, which then triggers its own infinite recursion bug.

If I add a log in the getter:

```ts
get: () => {  
  console.log("Event triggering");  
  return currentFocus;  
},
```

When a focus event is triggered, it results in:

```
log
9454 Event triggering              chunk-JMF622MS.js?v=e59c3cb5:17153
Uncaught RangeError: Maximum call stack size exceeded  chunk-JMF622MS.js?v=e59c3cb5:17152
    at HTMLButtonElement.get [as focus] (chunk-JMF622MS.js?v=e59c3cb5:17152:23)
    at HTMLButtonElement.r (cally.js?v=cccb3b49:926:54)
... [Log Snipped] ...
    at HTMLButtonElement.r (cally.js?v=cccb3b49:926:56)
...
```

I was able to work around this (though I haven’t done further tests yet):
When an element’s `.focus` method is accessed for the first time, I “mark” it using a `Set`. Then, with `setTimeout(..., 0)`, I defer the “unmark” operation until after the current synchronous execution finishes. After doing this, Cally’s behavior appears to work fine.
