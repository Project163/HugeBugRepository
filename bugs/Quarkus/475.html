Discussion
- /cc @stuartwdouglas looks like a class loading issue?
- So the issue here is the use of CompletableFuture.runAsync. This uses the fork join pool which does not provide any way to set the context class loader, so if you attempt to load a service it will use the wrong CL.

I am still trying to figure out a way to resolve this, but I can't really see any except for nasty hacks that may stop working in future versions of Java.

You can work around this by calling Thread.currentThread().setContextClassLoader(DoKubernetesRequestOnStartService.class.getClassLoader()); at the start of the async task.
- Thanks for the super fast feedback and workaround. I also found that creating a new Thread (instead of calling CompleteableFuture.runAsync) works as well. Still, I wonder why the same code works with quarkus 1.2 then. Shouldn't it not work their as well?
- It was not an isolated class loader, so even though the TCCL was wrong the effects of a wrong TCCL were not as bad. 

I have an idea for how to fix the TCCL, I am just testing it now.
