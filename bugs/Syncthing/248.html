Title

pull order: newest first doesn't seem to work

Description
Just added a new share to back up a set of photos from an android device.  Android is 0.11.18 via syncthing-silk, puller is Linux 0.11.19 via ubuntu ppa.

Set the folder pull order to "newest first", but observed the files getting pulled in filename order (DSC_nnnn.jpg), which is essentially oldest first.  Wondered if the sort order was accidentally reversed, so tried "oldest first", this is pulling in the same order as previously.  Either they're the same, or just ignored?
Discussion
- Newest first is based on file modification times. Are those correct on the source, or perhaps all set to the time the photos were imported?
- The file times are as taken; this is the original phone with images being
backed up for the first time. They're being set accordingly on the receiver
too.

I'll try and set up some more controlled tests. I wonder if the synthetic
mtime code is somehow involved?
