Title

Traits cannot modify their internal variables

Description
trait Level {
     int  maxLevel
     int  currentLevel = 0
    
    void foo() {
         if ( currentLevel < maxLevel ) {
            currentLevel += 1
        }
    }
}

 class  Leveller  implements  Level {
    Leveller() {
        maxLevel = 3
    }
}

def v =  new  Leveller()
v.foo()
v.foo()
v.foo()
v.foo()
 assert  v.currentLevel == 3
 
  

 fails with  

  
 Assertion failed: 

 assert  v.currentLevel == 3
       | |            |
       | 0             false 
       Leveller@1f757867
 
  

 But if you change the trait to: 

  
 trait Level {
     int  maxLevel
     int  currentLevel = 0
    
    void foo() {
         if ( Level__currentLevel < maxLevel ) {
            Level__currentLevel += 1
        }
    }
}
 
  

 It works... 

 I'm guessing this is a bug, as the given example ( [URL] of: 

  
 trait Counter {
     private   int  count = 0                   
     int  count() { ++count }                 
}
 class  Foo  implements  Counter {}             
def f =  new  Foo()
 assert  f.count() == 1  
 
  

 doesn't work if you add: 

  
  assert  f.count() == 2
 
  

 to the bottom
Discussion
- This bug highlights a more general problem with: +=, ++, – and other variants. In this code, replace: 

  
 currentLevel += 1
 
  

 with 

  
 currentLevel = currentLevel + 1
 
  

 and it will work. The reason is how the code is internally transformed into helper method calls.
- Ahhh, I see what you mean...otherwise it just returns an incremented (or post incremented) copy of the original number (without updating the original)
- Fixed this one by supporting the "plus equals" and other assignment operators, yet  ++x  and  y--  are not supported (see  GROOVY-6689 ).
