Title

Rule reference to target can't supply helpful error

Description
If a novice user uses rules_typescript, but didn't install the typescript dependency via npm, then they get this error:

```
ERROR: C:/users/alexeagle/projects/try_bazel/BUILD.bazel:3:1: every rule of type ts_library implicitly depends upon the target '@npm//typescript:typescript__typings', but this target could not be found because of: no such package '@npm//typescript': BUILD file not found on package path
ERROR: Analysis of target '//:root' failed; build aborted: no such package '@npm//typescript': BUILD file not found on package path
```

Bazel knows that the ts_library rule has an attribute that refers to `@npm//typescript:typescript__typings`. It could print the docstring from that attribute, or allow the ts_library rule some other way to help the user fix the error.
Another way to fix this would be for rules_nodejs to be able to intercept all `no such package: @npm//...`  messages and say "you need to npm install this package"
