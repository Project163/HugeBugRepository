Title

Support scopes on @Bean methods in spring-di

Description
From spring Javadoc (https://github.com/spring-projects/spring-framework/blob/master/spring-context/src/main/java/org/springframework/context/annotation/Bean.java#L82):


But the current implementation of SpringDiProcessor doesn't conform to this:

1. `@Dependent` scope is added to all beans produced by `@Bean` methods in `@Configuration` classes, so following #2178 in Quarkus 0.14.0+ it generates an error:

```
@Configuration
public class MyConfig {

	@Bean
	@Singleton // Causes "multiple scope type annotations" error
... [Log Snipped] ...
	}
}
```

Actual behavior:
```
Caused by: javax.enterprise.inject.spi.DefinitionException: Producer method org.acme.quickstart.MyConfig$SomeBean myBean() declares multiple scope type annotations: javax.inject.Singleton, javax.enterprise.context.Dependent
	at io.quarkus.arc.processor.Beans.multipleScopesFound(Beans.java:281)
	at io.quarkus.arc.processor.Beans.createProducerMethod(Beans.java:175)
	at io.quarkus.arc.processor.BeanDeployment.findBeans(BeanDeployment.java:696)
	at io.quarkus.arc.processor.BeanDeployment. (BeanDeployment.java:142)
	at io.quarkus.arc.processor.BeanProcessor.process(BeanProcessor.java:153)
	at io.quarkus.arc.deployment.ArcAnnotationProcessor.build(ArcAnnotationProcessor.java:282)
```
Expected behavior: the default scope should be singleton (not dependent), and it should also be allowed to make it explicit with `@javax.inject.Singleton` without causing "multiple scope type annotations" error.

2. Using `@org.springframework.context.annotation.Scope` causes a NPE: 

```
@Bean
@Scope("singleton") // NPE
public SomeBean myBean() {
	return new SomeBean();
}
```
