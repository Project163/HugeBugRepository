Title

Mongo id duplication

Description
### Describe the bug

With a native application deployed in several pods, inserting a document in mongo can fail with this kind of error :
```
com.mongodb.MongoWriteException: Write operation error on server localhost:30003. Write error: WriteError{code=11000, message='E11000 duplicate key error collection: compiiu.events index: _id_ dup key: { _id: ObjectId(' ') }', details={}}.
```
The ObjectId is set by the mongo driver. It is composed of several parts, see [Link: doc] :
- A 4-byte timestamp, representing the ObjectId's creation, measured in seconds since the Unix epoch.
- A 5-byte random value generated once per process. This random value is unique to the machine and process.
- A 3-byte incrementing counter, initialized to a random value.

In jar deployment, no problem, the unicity of the different parts is managed by the SecureRandom class.
In native mode, it appears that SecureRandom is replaced at build time. So each pod share the same SecureRandom

With such a replacement, the second part in ObjectId is the same across all application instances.
```
java
static {
        try {
            SecureRandom secureRandom = new SecureRandom();
            RANDOM_VALUE1 = secureRandom.nextInt( );
... [Log Snipped] ...
        }
    }
```
    
The third part is also impacted :
```java
private static final AtomicInteger NEXT_COUNTER = new AtomicInteger(new SecureRandom().nextInt());
```

As SecureRandom is used in several ObjectId parts, conflicts are not the majority but can occur and occur during our bench tests.



### Expected behavior

ObjectId generated by the mongo driver is intended to be unique

### Actual behavior

ObjectId duplications occcur at low rate but occur
