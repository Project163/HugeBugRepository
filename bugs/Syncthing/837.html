Title

Rename with different case triggers delete on android

Description
Today I noticed a file unexpectedly disappearing from a shared directory on my mac. This seems to happen when I rename a file using different casing. Steps to reproduce the issue:

- in a shared folder, using my terminal: `touch FOO.txt`
- `mv FOO.txt foo.txt`
- foo.txt is gone from my mac.

Here's the relevant activity log:

```
Samsung Galaxy S10e Bas | deleted | file | Bas | foo.txt | 2021-03-03 18:57:18
MacBook Bas | deleted | file | Bas | FOO.txt | 2021-03-03 18:57:02
MacBook Bas | modified | file | Bas | foo.txt | 2021-03-03 18:57:02
MacBook Bas | modified | file | Bas | FOO.txt | 2021-03-03 18:56:42
```

It is as if my phone sees the rename as a delete of the original file, then echoes that delete back to its peers.

I'm using Syncthing 1.6.1-1 on mac OS Catalina (10.15.6) and Syncthing v1.13.0 on my Samsung Galaxy S10e.
Discussion

As far as I remember mac is sort of hybrid when it comes to case-sensitivity, but basically case-insensitive, so this is likely relevant. I'll close the ticket - feel free to reopen if you can reproduce with an up-to-date Syncthing.
