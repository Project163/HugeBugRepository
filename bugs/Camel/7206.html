Title

Incorrect Exchange status when using camel-rest

Description
Consider the following integration yaml file and also an Event Listener: 
  
 
- from:
    uri:  " rest :get:/demo" 
    steps:
      - removeHeaders:
          pattern:  "Camel*" 
      - to:
          uri: https: //httpbin.org/status/500
           parameters:
            bridgeEndpoint:  true 
            httpMethod: GET  
  
  
 
 package  com.lsergio.poc;

 import  org.apache.camel.spi.CamelEvent;
 import  org.apache.camel.support.EventNotifierSupport;
 import  org.slf4j.Logger;
 import  org.slf4j.LoggerFactory;
 import  org.apache.camel.*;

 public   class  MyEventListener  extends  EventNotifierSupport {

     protected  Logger log = LoggerFactory.getLogger(getClass());

     public  void notify(CamelEvent event)  throws  Exception {
       if  (event.getSource()  instanceof  Exchange) {
          Exchange ex = (Exchange)event.getSource();
          log.info( "Event class: "  + event.getClass());
          log.info( "Event: "  + event.getType().name() +  " - Failed:"  + ex.isFailed() +  " Id: "  + ex.getExchangeId() +  " - Exception: "  + ex.getException());
          log.info( "--------------------------" );
      }
    }
}
 
  
 The integration intentionally fails by calling an endpoint that always returns status 5xx. 

 After running this code with  
  
 
jbang -Dcamel.jbang.version=4.13.0 camel@apache/camel run integration.yaml MyEventListener.java

Discussion
- Zulip thread about this issue:  [URL]
- Some info I found after debugging: 

 The request is handled by the  VertxPlatformHttpConsumer  

 I noticed that when I added a breakpoint  at this block: 
  
 
            vertx.executeBlocking(() -> processExchange(exchange),  false ).onComplete(processExchangeResult -> {
                 if  (processExchangeResult.succeeded()) {
                    writeResponse(ctx, exchange, getEndpoint().getHeaderFilterStrategy(), muteExceptions)
                            .onComplete(writeResponseResult -> {
                                 if  (writeResponseResult.succeeded()) {
                                    handleExchangeComplete(exchange);
                                }  else  {
                                    handleFailure(exchange, ctx, writeResponseResult.cause());
                                }
                            });
                }  else  {
                    handleFailure(exchange, ctx, processExchangeResult.cause());
                }
            });
 
  
 sometimes the exchange had the failure info, sometimes it didn't. And it usually did when I added a breakpoint to the http component and executed the code step by step. 
So I guess this might be related to some async processing.
- Okay so I have found the problem that its in platform-http-vertx that clears the caused exception which it should not have done - the other http components like jetty does not do that
