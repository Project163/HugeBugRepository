Title

Freetype symlink incorrect in 2.0 GCC

Description
Not sure if this applies to other downloads, but the freetype.framework is not set up correctly in the SFML 2.0 GCC - universal 32+64 bits (OS X 10.5+) download. Our Mac App was rejected upon submission because of a "malformed framework":

```
Malformed Framework - The framework bundle (Shibashiba.app/Contents/Frameworks/freetype.framework) must contain a symbolic link 'freetype' -> 'Versions/Current/freetype'. Refer to the Anatomy of Framework Bundles for more information.
```

If you look in the folder using Finder, the links look correct, but if you compare it to _sndfile.framework_, it is different. For example:

```
sndfile.framework
    sndfile -> Versions/Current/sndfile
    Versions
        A
            sndfile
        Current -> A
```

versus

```
freetype.framework
    freetype -> Versions/A/freetype
    Versions
        A
            freetype
        Current -> A
```

You can see above that freetype points **DIRECTLY** to the "A" version of freetype, whereas in the correct "Anatomy", it should point to _Current_, which in turn points to the current version. I believe that the freetype symlink needs to be changed. It works fine since the framework can be found, but Apple considers this a malformed setup.
