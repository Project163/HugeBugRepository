Title

Invalid size while trying to read a Timestamp

Description
### Rust Version

1.89.0

### Diesel Version

2.3.1

### Diesel Features

mysql chrono

### Database Version

MariaDB 11.8.3

### Operating System Version

Debian trixie

### What happened?

Creating a struct representing a table row fails with:
```
thread 'main' panicked at src/main.rs:24:53:
called `Result::unwrap()` on an `Err` value: DeserializationError(DeserializeFieldError { field_name: Some("date"), error: "Received a buffer with an invalid size while trying to read a Timestamp value: Expected at least 48 bytes but got 40" })
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace
```

### What did you expect to happen?

Correct deserialization

Discussion
- Thanks for reporting this issue. I can reproduce it but I did not have the time to find a fix yet. The fix was introduced in [URL] to fix a potential out of bounds read and it seems like that it did in fact catch that.

Now as pointed out in the [Link: release blog] we are currently looking for someone to take care of the mysql backend, due to capacity reasons. I will also try to have a look at this but I cannot promise that this happens soonish.
- So I had another short look at this and it seems like the [Link: bindings generated from `libmariadbclient`] do miss the `time_zone_displacement` field compared to the [Link: `MysqlTime` type used by diesel]. This explains the size difference.

I would consider that as upstream bug, as debian marks that package compatible to libmysqlclient (which [Link: has this field], while it's not a perfect replacement. This is for obvious reason not ABI compatible. I would prefer if you could raise that issue in the upstream issue tracker.
