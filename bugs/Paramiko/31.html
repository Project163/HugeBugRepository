Title

SFTPClient does not keep a reference to the Client

Description
SFTPClient does not keep (properly) a reference to the parent, so when it falls out of scope and gets closed, the sftp object becomes unusable.

```
python
... [Log Snipped] ...
[u'xxx']
```
Discussion
- It's because you must return the client variable, if you don't return it the garbage collect it immediatly when the scope change.
- Yeah, I know why that happens. My point is that that's completely unexpected in a idiomatic Python environment.

SFTPClient should keep a reference to Client so that it doesn't get garbage collected while it's in use.
- Is this ticket still relevant? The example provided seems to work with e58df62 and #44 was closed by it. Any reason this was was just referenced?
- This situation is a bit complicated. There was an intentional mechanism which closed the Transport when the SFTPClient was garbage collected, called a "ResourceManager". It was added to prevent connection leaks. The "Add back-reference" commit was not a good idea, it just defeated the "ResourceManager". So I removed both, in #952. That also fixes this, but leaves the possibility of Transport leaking and never closing the connection (if you don't explicitly close it).

So yes I think this issue can be closed. (I don't see any particularly new references, unless these old commits being cherry-picked or rebased onto new branches is doing it.)
