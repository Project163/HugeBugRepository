Title

C++ action conflicts when using new Python version transition semantics

Description
When `--incompatible_allow_python_version_transitions` is enabled, it is possible to see action conflicts like the following:

```
python
# pkg/BUILD

cc_binary(
    name = "cc",
... [Log Snipped] ...
    python_version = "PY3",
)
```

```
sh
bazel build --nobuild :cc :py3 --incompatible_remove_old_python_version_api --incompatible_allow_python_version_transitions

ERROR: file 'pkg/_objs/cc/cc.pic.o' is generated by these conflicting actions:
Label: //pkg:cc
... [Log Snipped] ...
INFO: 0 processes.
FAILED: Build did NOT complete successfully (15 packages loaded, 202 targets configured)
```

This was supposed to be fixed in  , but it turns out more work is needed to ensure that we don't produce separate configurations for when `--python_version` is set to the default value explicitly, versus when it is set ot the default value by, well, default. We have a fix in mind and hopefully should have it in place for Bazel 0.25, when we intend to flip the flag.
Discussion
- I have a prototype fix and just need to polish it and add some javadoc / tests.
