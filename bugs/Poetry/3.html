Title

poetry install does not install extras in a DirectoryDependency that is also a poetry project

Description
- **OS version and name**:  Windows 10 Pro, version 1803, build 17134.112 
- **Poetry version**: 0.11.2
- **Link of a [Link: Gist] with the contents of your pyproject.toml file**: [Link: pyproject.toml]  

## Issue
 
If you look at my gist above, my project's pyproject.toml specifies a local path dependency that also contains its own (poetry) pyproject.toml. Non-optional dependencies and dev-dependencies in this secondary pyproject.toml get installed just fine, but dependencies specified in its extras (which *have* to be optional or else poetry complains about it) that are explicitly requested by the first project don't get installed at all.

I did some debugging and digging into poetry's source and found that DirectoryDependency._package.extras is always an empty dict. Inserting `self._package.extras = package.extras` in the block below gets rid of this issue, but I'm not sure if this is the correct approach.
