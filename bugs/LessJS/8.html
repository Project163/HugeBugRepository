Title

File separator in Rhino build 1.3.0

Description
Be nice to windows users. Replace '/' by environment['file.separator'] when splitting system file paths please. Then even imports should work properly.
Thx
Discussion
- If you use '/' as the path seperator it works on windows.. so changing to use the environment seperator seems like a pretty low priority..
- If you do something like
 var sheetName = name.slice(0, name.lastIndexOf('/') + 1) + sheet.href 
you obviously need to use environment['file.separator'] instead of '/' if  name  is a file system path on windows.

I reported the issue to give other users of less.js rhino build the chance to fix their importing problem. As many blocking bugs as there are, I did not assume this issue will be fixed at all.

- your solution (replaced '\' by '\\') worked in my example. environment['file.separator'] uses the os-specific file seperator provided by the jvm (so also unix style file path). this should be more elegant, no? anyway, thank you for taking the time to fix this bug.
- I didn't spot the bug because although on windows I was in cygwin and was writing everything with unix paths.. and it all worked. If I had changed it to environment file seperator it would stop working. I'm willing to bet that considering it didn't use to work with windows seperators that it would break a few peoples setups if I stopped supporting unix paths on windows.. hence the reason to split on both, not just the system environment..
