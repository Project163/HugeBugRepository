Title

IGNITE.NODE_METRICS view fails with "Cannot parse "TIME" constant" > 24h

Description
This is because we are using TIME type for several additive measurements: 

  SqlSystemViewNodeMetrics.class: 
                        valueTimeFromMillis(metrics.getTotalJobsExecutionTime()), 
                        valueTimeFromMillis(metrics.getTotalBusyTime()), 
                        valueTimeFromMillis(metrics.getTotalIdleTime()),  

 which will be hundreds of hours on long-running cluster, but  TIME  type is limited to 24 hours and will fail to be converted otherwise, as in: 

  0: jdbc:ignite:thin://localhost> SELECT CAST('40:52:26.548' AS TIME); 
Error: Failed to parse query. Невозможно преобразование строки "40:52:26.548" в тип "TIME" 
Cannot parse "TIME" constant "40:52:26.548"; SQL statement: 
SELECT CAST('40:52:26.548' AS TIME)  [22007-197]  (state=42000,code=1001)
Discussion
- pkouznet , We need to change data type of all such columns to LONG, as this is not TIME, but rather duration. And duration cannot be expressed in terms of TIME data type.
- vozerov  Changes seem to be trivial. Should we also create human readable versions of that columns?  
  
 UPTIME_MS      1267392877
UPTIME         '352d:3h:12s:877ms'
