Title

HEAD request for managed resource returns 500 Server Error

Description
HEAD  requests for managed stopwords/synonyms fail with 500 Server Error. This is true for both stopword lists/synonym maps and their child resources. 

  
 
$ curl -sI  "[URL] | head -n 1
HTTP/1.1 500 Server Error

$ curl -sI  "[URL] | head -n 1
HTTP/1.1 500 Server Error
 
  

 A request for a non-existent word in a list/map does return the correct 404 response. 

  
 
$ curl -sI  "[URL] | head -n 1
HTTP/1.1 404 Not Found
Discussion
- Here's a comparison between 8.11.1 and 8.11.2 with the same requests executed as  GET  and  HEAD . The  HEAD  requests for non-existent words used to return the wrong response code, now those for existing words do. One would suspect that   SOLR-15116   has something to do with it.
