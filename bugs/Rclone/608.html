Title

ncdu mode dies and fails when it doesn't have permission to access a remote subdirectory

Description
#### What is the problem you are having with rclone?

when `rclone ncdu` can't access a subpath of a given remote, it fails and quits and provides no way to skip/ignore the directory in question, thus making it completely useless on the whole remote.

For example, suppose I have a shell where I log in as 'me', and where 'user2' has unique acess to her own subdirectory.

The filesystem looks like this:
```
$ ssh me@sftphost  ls -l
total 240
drwx------   10 19463  user2  10 Feb  3 10:08 user2
drwx------   3 19463  me   9 Feb 27 03:30 dir1
drwx------   3 19463  me   9 Feb 27 13:33 dir2
drwx------   3 19463  me   9 Feb 27 04:35 dir3
```

(sftphost is an sftp remote where i connect as user 'me')
```
$ rclone ncdu sftphost:
2020/02/27 18:25:57 Failed to ncdu with 4 errors: last error was: ncdu directory listing: ncdu listing failed: error listing "user2": sftp: "Permission denied" (SSH_FX_PERMISSION_DENIED)
$
```

#### What is your rclone version (output from `rclone version`)

```
rclone v1.49.1
- os/arch: linux/amd64
- go version: go1.12.9
```

#### Which OS you are using and how many bits (eg Windows 7, 64 bit)

Ubuntu LTS

####  Which cloud storage system are you using? (eg Google Drive)

SFTP
