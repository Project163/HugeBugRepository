Title

ReferenceEditor may not enforce referential integrity

Description
VersionHistory.removeVersion() allows to remove a version of a checked in node still referencing that version. This results in a dangling base version. 

 This is caused by a more general issue in the ReferenceEditor, which does not enforce referential integrity in some cases.
Discussion
- Added a test to trunk:  [URL]

 The test succeeds unless the call to vMgr.checkout() is commented out. I looks like the ReferenceEditor does not add a reference entry for the jcr:baseVersion reference on checkin().
- Turns out this is actually a more general issue with the ReferenceEditor. Updated the title of this issue accordingly. 

 Added more tests to trunk:  [URL]

 As can be seen from the test, the ReferenceEditor fails to enforce referential integrity when a referenceable node is removed together with a reference pointing to it and there are other existing references still pointing to the referenceable node.
