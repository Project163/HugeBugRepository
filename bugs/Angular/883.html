Title

Regression Ivy with ComponentFactory

Description
# 🐞 bug report

Tbh: I didn't search if this was already known (no idea how I would have found it 😅)

### Affected Package
The issue is caused by package @angular/core

### Is this a regression?

This works without Ivy enabled.

### Description

I was trying out Angular Ivy in our codebase. One of the last 'problems' that is really blocking seems to be [Link: 'ngx-toastr'].

They dynamically add the [Link: toastr component] on runtime in the DOM.

[Link: Link to code that is responsible for this]

When switching to Ivy this code doesn't work anymore:

```
ERROR DOMException: Failed to execute 'createElement' on 'Document': The tag name provided ('') is not a valid name. at DefaultDomRenderer2.createElement
```

After some debugging I found out that it's because the code that's responsible for retrieving the selector of a component in Ivy doesn't work: [Link: Link]

In case of the toast component (see link above) it's ['', 'toast-component', '']. As a result the tag name becomes ''. And that explains the error above.

I cloned ngx-toastr, changed the component name from `[toast-component]` to `toast-component` (removed the brackets). And everything seems to be working. This of course changes the result from a div with as attribute 'toast-component' to a custom component with as selector 'toast-component'.

TL;DR: Dynamically generating components on runtime with Ivy doesn't work when using attribute notation.

## 🔬 Minimal Reproduction

Use ngx-toastr with Ivy enabled.
If more time, I'll create a stackblitz.
