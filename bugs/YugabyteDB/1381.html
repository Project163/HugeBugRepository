Title

[YSQL][Transactional DDL] Intermittent "Column for deletion not found" during transactional DDL + table-level locks workload

Description
Jira Link: [Link: DB-16871]
### Description

Version:  -b143
Logs: Added in Jira comments
 
We observed the following issue once while running a transactional DDL and table-level locks workload that executes parallel DDLs (one per database) alongside concurrent DMLs (inserts, updates, deletes).

Keyspace name is **_postgres_3_**
```
Query: ALTER TABLE postgres_3_tb_3149971_7607583 DROP COLUMN col_postgres_3_tb_3149971_7607583_6593260_8473610

ERROR: Column for deletion not found 
```

Just 3–4 seconds before the above error, the following was encountered on the same table (although the index was on a different column):

```
2025-05-24 04:16:19,007 
Query : CREATE INDEX NONCONCURRENTLY postgres_3_index_postgres_3_tb_3149971_7607583_2626343_3055080 ON postgres_3_tb_3149971_7607583 (k, v1)

ERROR: Invalid column number 37 
```

In the transaction where we saw ERROR: Column for deletion not found, the following queries were executed

Keyspace name is postgres_3

```
begin;

2025-05-24 04:16:23,341 

QUERY:
... [Log Snipped] ...

ERROR: Column for deletion not found
```
