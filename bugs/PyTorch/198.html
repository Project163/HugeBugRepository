Title

`torch.randint` raises a `RuntimeError` if `dtype=torch.uint64` and `high >= 2**63`

Description
### 🐛 Describe the bug

I was trying to get a `torch.randint` distribution over all of `uint64` and ran into this interesting error.

`torch.randint` "returns a tensor filled with random integers generated uniformly between low (inclusive) and high (exclusive).", and `uint64` is [0, 2**64) so `high` would need to be `2**64`, but

```
python

Traceback (most recent call last):
  File " ", line 1, in  
... [Log Snipped] ...
```

I had expected that `torch.randint(2**64, (1,), dtype=torch.uint64)` might not work which is why I tried it, but I was surprised to find that it failed all the way down to `torch.randint(2**63, (1,), dtype=torch.uint64)`!

I also retried everything explicitly including the `low` parameter, e.g. `torch.randint(0, 2**64, (1,), dtype=torch.uint64)`, and the results were identical.

Discussion
- This feels as a duplicate of an issue filed a long time ago. As upper bound is exclusive and 64-bit dtype is used to pass this upper bound it's non-trivial to fix it. But if your point that it should throw ValueError rather than RuntimeError (for say torch.int32 dtype), please do not hesitate to propose a PR
- @malfet : The issue is broader than that. 

I expected to find that it didn't work when `high=2**64`, because that can't be represented in 64 bits, and there's not a great fix I can imagine for it.

I did _not_ expect to find that it fails for all `high` in [2**63, 2**64]!. All but one of those 10 quintillion numbers can be represented in 64 bits. Another way to see it is that half of all the possible values for `high` plus one will cause this error, so it's "barely most of the time".

----

My feeling is that some `uint64` gets converted to `int64` at some point, and that's where this happens, and that might be able to be fixed without fixing the single difficult case `2**64`.
- I'm a noob, but I think there's something to do with data types. I suggest trying `int64` rather than `unit64` If that didn't work then try working with `int128`
- @dhruv-dhiman122: There is no `torch.int128`! 😬 

(And to use a much larger data type wouldn't be a good solution.)
