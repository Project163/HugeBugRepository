Title

Allow runtime fields to be added to mappings with "enabled":false

Description
Mappings which have [Link: enabled set to false] at their root currently don't allow runtime fields to be added. This limitation makes sense to forbid adding regular field types as it would otherwise make the index inconsistent, as documents that were indexed while enabled:false would not be parsed and therefore not be correctly analyzed w.r.t. the mapping. For runtime fields, this limitation is unnecessary (as no inconsistencies can arise), and prevents a use case of making fields searchable that the user previously explicitly opted out of having analyzed / searchable. The specific use case I have in mind is using runtime fields on a searchable snapshot mounted from a source-only repository (which means that the index is read-only, has an empty mapping, and has enabled:false at its root). Allowing runtime fields to be defined on this index will allow this index to provide queryability like a regular index, even though the repository will only store the _source.
