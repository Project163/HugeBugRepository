Title

Author Field Name Inconsistency in Gitea Swift Package Registry

Description
### Description

I am using a local Gitea server to host a Swift Package registry. I successfully uploaded a binary Swift package to the registry, but when attempting to fetch the package, the operation fails with the following error:

error: failed fetching controller.Redacted version 25.4100.267 release information from [URL] keyNotFound(CodingKeys(stringValue: "name", intValue: nil), Swift.DecodingError.Context(codingPath: [CodingKeys(stringValue: "metadata", intValue: nil), CodingKeys(stringValue: "author", intValue: nil)], debugDescription: "No value associated with key CodingKeys(stringValue: \"name\", intValue: nil) (\"name\").", underlyingError: nil))

Issue Details

- The error message indicates that the `"author"` field is missing the `"name"` subfield.
- When I upload metadata containing `"author.name"`, it is not reflected in the server’s response.
- If I provide `"author.givenName"` in the format specified by  [Link: schema.org] , it appears in the server response, but the Swift Package Manager (SPM) does not recognize it.
- By editing SPM’s source code to use `"givenName"` instead of `"name"`, everything works as expected.

Root Cause
There is a mismatch between the JSON schema references in different documentation sources:
- The Gitea [Link: documentation] follows a schema that uses `"givenName"`, `"familyName"`, and `"additionalName"` fields for the author.
- In contrast, the Swift Package Registry [Link: documentation] specifies a simpler schema with just the `"name"` field for the author.

Expected Behavior
Gitea’s Swift Package Registry implementation should conform to the schema expected by Swift Package Manager, specifically providing an `"author.name"` field in the package metadata. Gitea [Link: documentation] should also be updated.

1. Host a Swift Package Registry using Gitea.
2. Upload a binary Swift package with metadata including `"author.name"`.
