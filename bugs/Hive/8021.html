Title

AIOBE in conv UDF if input is empty

Description
Repro 
  
 
create table test (a string);
insert into test values ("");
select conv(a,16,10) from test; 
  
 Exception trace: 
  
 
Caused by: java.lang.ArrayIndexOutOfBoundsException: 0
 at org.apache.hadoop.hive.ql.udf.UDFConv.evaluate(UDFConv.java:160)
Discussion
- What do we return when input is not a number? Do we throw? If that'ts the case maybe we should throw as well.
- zabetak  We return 0 for invalid input. I can return the same for empty input as well.
- nareshpr  After having a second look in the PR I kind of change my mind. The CONV function is mostly known from MySQL and I think the implementation so far tends to stay as close to the MySQL version as possible. 

 I did a quick test in MySQL (version 8.0) and it returns the following results: 

  
 mysql> SELECT CONV('',10,2);
+---------------+
| CONV('',10,2) |
+---------------+
| NULL          |
+---------------+
mysql> SELECT CONV('4?:+',10,2);
+-------------------+
| CONV('4?:+',10,2) |
+-------------------+
| 100               |
+-------------------+
mysql> SELECT CONV('1?:+0',10,2);
+--------------------+
| CONV('1?:+0',10,2) |
+--------------------+
| 1                  |
+--------------------+
mysql> SELECT CONV('*10?:+2',10,2);
+----------------------+
| CONV('*10?:+2',10,2) |
+----------------------+
| 0                    |
+----------------------+
1 row in set, 1 warning (0.00 sec)

Warning (Code 1292): Truncated incorrect DECIMAL value: '*10?:+2'
 
  
 So for empty string it returns NULL and for invalid literals it tries to kind of parse the literal till it finds an illegal character. 

 Based on the above I would suggest to return NULL for empty string as you had it initially. Sorry for the back and forth.
- Thanks for the analysis  zabetak  

 I updated PR to return null for empty input.
