Title

`mypy --help` output wraps long URLs, breaking automatic parsing/linking in rich terminals

Description
**Bug Report**

 

This is admittedly a _very_ stupid, trivial thing, but it is an annoyance.

Many terminal applications augment the shell output they display with rich features, including automatic conversion of printed URLs to active hyperlinks.

In an 80-column terminal, because at least one of the URLs displayed by `mypy --help` is too long to fit in an 80-column terminal, it gets split across two lines in the help output.

Compounding the issue is that the URL is displayed in an indented context, so both lines of output have spaces inserted before them. On the second line, these spaces fall in the middle of the URL fragment, fouling the terminal's automatic linking by chopping off the end of the URL.

**To Reproduce**

1. Run a graphical terminal (such as `gnome-terminal` or macOS `Terminal.app`) which automatically links URLs in the output.
2. Resize the window to 80 characters wide (standard graybeard width).
3. Run `mypy --help` from any recent version (tested in `1.0.1` and `1.17.1`)
4. Find whatever URL is included in the "None and Optional handling" section
5. Either:
    1. Hover over it with the pointer, to determine how much of it is linked
    2. Click/right-click on it, to open the URL in a web browser

**Expected Behavior**

The entire URL is output as a continuous, unbroken string. This is then automatically converted into a link to the referenced page.

**Actual Behavior**

The output is formatted similar to these examples:

```
console
$ /usr/bin/mypy --version
mypy 1.17.1 (compiled: no)

$ /usr/bin/mypy --help
... [Log Snipped] ...
  and-the-none-type
# -- 8 

- Mypy version used: 1.0.1, 1.17.1
- Mypy command-line flags: `--help`
- Python version used: 3.9, 3.13

- @sterliakov Hm, displaying URLs in `--help` isn't too common, so I'm having trouble coming up with other examples of that.

For tools that display URLs in man pages, fixed-wrapping text files, etc., they typically just ensure the whole URL gets printed as a contiguous string, even if it's required to exceed their normal line length. (It'll get wrapped by the terminal, if it's longer than that width.)

A wrapped URL will still be recognized as such, if it's otherwise unbroken.

IOW, in an 80-column-wide terminal, this will be parsed as a complete url:

```console
#  
$ echo "[URL]
[URL]
-none-type
```
Both of these will get cut off at the newline:

```console
#  
$ echo "[URL]
[URL]
-none-type
$ echo "[URL]  -none-type"
[URL]
  -none-type
```

As long as the _terminal_ (not the program) is doing the wrapping, it's OK.
- Looks like the issue is that argparse's default formatter uses `textwrap.fill()` to format the output, and `textwrap.fill()` will break URLs by default:
