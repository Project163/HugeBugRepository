Title

camelcase dings on function and property names in library interface

Description
Using, for instance, Uglify, I end up with code like this

``` javascript
compressedAst.figure_out_scope();
compressedAst.compute_char_frequency();
```

which gives errors

```
  77:18  error  Identifier 'figure_out_scope' is not in camel case        camelcase
  78:18  error  Identifier 'compute_char_frequency' is not in camel case  camelcase
```

Also, this

``` javascript
stream = uglify.OutputStream( {source_map: sourceMap} );
```

```
68:37  error  Identifier 'source_map' is not in camel case              camelcase
```

I pretty much have no recourse here other than turning it off.  Should it be hitting me on these at all?
Discussion
- Yes, I think most people would keep a consistent style between variable and member names, so would want the `camelcase` rule to warn them about these.

**edit:** Oh I see, you're interfacing with a library that does not use camel-case names. Interesting...
- The problem is that there's no way for us to know what is an object that you define vs. an object being used from a library. There is literally no discriminating information in that regard. 

I think the real answer is to be able to programmatically turn off rules in section of code. That's what #320 is about. 

I'm open to other suggestions as well - at the moment I can't see a change to this rule that would make this easier.
