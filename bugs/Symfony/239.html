Title

[Console][Table] Invalid "UTF-8" string caused by text warping

Description
### Symfony version(s) affected

6.4

### Description

When using the Console [Link: table helper], the following exception is sometimes thrown : `Invalid "UTF-8" string.`. I've found the cause to be the following line, which may split an UTF-8 character badly when the cell text is wrapped on multiple line. 

[URL]

`applyCurrentStyle` will indeed receive an Invalid "UTF-8" string because of the result of `substr`: 

 run();
```

Run : 
```
php test.php debug
```

Result should be : 
```
In ByteString.php line 444:
                           
  Invalid "UTF-8" string.  
                           

debug
```

### Possible Solution

Replacing `substr` with `mb_substr` on [Link: this line] will solve the issue. However it might be prudent to check if `mb_substr`  should be used elsewhere.

Discussion
- Just replacing `substr` with `mb_substr` would break things entirely (even for cases where the current logic is lucky enough to avoid breaking UTF-8 codepoints). `mb_substr` expects an offset computed in codepoints, not in bytes, so the computation of the offset needs to be changed as well
- The problem is still present.  Someone needs to take the time to write a patch and (presumably) a unit test.
- I can confirm the "How to reproduce" code from the initial post still produce the issue with Symfony Console 7.2.5
