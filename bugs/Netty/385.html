Title

VoidPromise notification works against contract

Description
Hi folks,

after talking to @trustin and @normanmaurer looks like there is something wrong (either docs or code).

The docs of void promise say:

```
 * Be aware that the returned {@link ChannelPromise} will not support most operations and should only be used
 * if you want to save an object allocation for every write operation. You will not be able to detect if the
 * operation  was complete, only if it failed as the implementation will call
 * {@link ChannelPipeline#fireExceptionCaught(Throwable)} in this case.
```

Turns out, the pipeline will remain silent if something goes wrong during the write phase. For example, in my case there were some refCnt issues which never did show up in the pipeline. When I used a correct promise, it got notified with the error. Looking into the implementation of the proper parts as @trustin pointed out, the code looks like (AbstractChannelHandlerContext): 

```
private static void notifyOutboundHandlerException(Throwable cause, ChannelPromise promise) {
    // only try to fail the promise if its not a VoidChannelPromise, as
    // the VoidChannelPromise would also fire the cause through the pipeline
    if (promise instanceof VoidChannelPromise) {
        return;
... [Log Snipped] ...
    }
}
```

So I guess the change need to be that if its a void promise, we are either logging this thing to WARN and fix the docs or redirect it into the pipeline?

 if (!promise.tryFailure(cause) && !(promise instanceof VoidChannelPromise)) {
