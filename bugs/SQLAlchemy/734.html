Title

pool_pre_ping does not properly detect the disconnect when the database user is dropped

Description
**Migrated issue, originally created by Mike Shantz ([Link: @meshantz])**

sqlalchemy version: 1.2.2
database: oracle (cx_Oracle 6.1, oracle client 12.1)

Dropping the user of an open connection results in an exception being raised, instead of a graceful attempt to reconnect. (Note that my actual use case also provides a creator callback to create_engine, which is able to recover from this condition on the new connection).

As demonstrated below, the attempt to close the cursor in the finally clause, when the connection has entered this error state, results in a second uncaught exception.

