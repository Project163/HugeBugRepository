Title

Streaming does not guarantee cache invalidation

Description
Looking at the code, we attempt to invalidate the row cache for any rows we receive via streaming, however we invalidate them immediately, before the new data is available. So, if it is requested (which is likely if it is "hot") in the interval, it will be re-cached and not invalidated.
Discussion
- I thought of iterating over all the received  SSTableReader  keys on  StreamReceiveTask.OnCompletionRunnable  and invalidate the keys before adding them to  ColumnFamilyStore . Is this a valid approach or do you think there is a more efficient way of doing this,  benedict ? Do we want to perform the cache invalidation and addition of sstables to  ColumnFamilyStore  atomically, or is it acceptable to invalidate just before adding?
- We need to invalidate  after  adding sstables to CFS, or a read request can still cache stale data before the add is finished.
