Title

Channel MessageBridge concurrency issues

Description
I've noticed that when using LocalChannels and sending several objects at a time, there would be execptions thrown by the `LocalEventGroup::run()` method. 

Specifically `ArrayIndexOutOfBoundsException`.

The offending method is 

```
java
DefaultChannelHandlerContext.MessageBridge {
    void fill() {
            if (msgBuf.isEmpty()) {
                return;
... [Log Snipped] ...
        }
}
```

The relevant method calls are

``` java
    public Object[] toArray() {
        return copyElements(new Object[size()]);
    }
```

```
java
private   T[] copyElements(T[] a) {
        if (head   tail) {
... [Log Snipped] ...
        return a;
    }
```

The specific problem is that the `ArrayDeque` is getting modified between the two calls, as in my case, `a.length=3` and `this.size()=4` in the second method. Since they are different sizes... BLAMMO.

What I think might be the issue is something akin to a concurrent modification. Since it's a `ArrayDeque` that is being used, it doesn't throw a `concurrent modification exception`, it just  throws an `exception` when it gets to that point.

I haven't thought exactly how to solve this (maybe some tricks from Brian Goetz will fit the bill). This took a while to track down, and involved connecting/sending messages/disconnecting very, very quickly on local channels.

To figure out exactly what was going on, I modified `LocalEventLoop` to catch `Exception` in it's run method instead of just `InterruptedException`.

```
java
        for (;;) {
            Runnable task;
            try {
                task = takeTask();
... [Log Snipped] ...
            }
        }
```

As filling the Bridge is used everywhere, I'd imagine this affects everything else. I first noticed it when I started losing messages in my LocalChannel UnitTests.
