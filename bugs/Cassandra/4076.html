Title

Legacy SSTables for KEYS indexes can't be read in 3.0+

Description
Trying to read an SSTable for a KEYS index created in 2.1 throws a deserialization error when being read following an upgrade to 3.0. This occurs whether the read comes via the query path or by running  nodetool upgradesstables .
Discussion
- The legacy tables are dense and non-compound but  CassandraIndex::indexCfsMetadata  wasn't creating the metadata as such, leading to an exception in  OldFormatSeserializer  when reading tables in the old format. KEYS indexes created on 3.0+ (for COMPACT STORAGE tables) are not affected.  This branch  includes a fix to create the index metadata correctly and again, KEYS indexes created with 3.0+ use  CurrentFormatDeserializer  and so work as expected. I'm working on an upgrade dtest and will update with details shortly.  

 The patch is valid for 3.0 -> trunk and merges cleanly, so I've only linked a single branch.
