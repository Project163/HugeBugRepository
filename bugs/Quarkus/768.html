Title

JAX-RS Providers in RESTEasy are not initialized unless a @Path is present in the Application

Description
**Describe the bug**
A RESTEasy deployment is only produced if something with a `@Path` is found:

[URL]

This works fine for most cases. There is one case where this doesn't work:

If we have a Quarkus app, using a simple `ClientBuilder.newClient()`, annotated Providers are not automatically registered with the client, because the RESTEasy deployment was not initialized:

[URL]

Which causes the Providers to not being registed with the client.

If we add a simple endpoint or even a dummy rest client interface with `@Path`, it works!

**Expected behavior**
Consistent behaviour of Providers with `ClientBuilder.newClient()` independent of other classes in the application.

**Actual behavior**
Providers are only registered if a `@Path` class exists in the application.

**Environment (please complete the following information):**
- Quarkus version or git rev: 1.7.0.Final

**Additional context**
Providers can still be registered manually in the `ClientBuilder` to workaround this issue. Also RESTEasy is clear regarding Providers registration and the Client: [URL]
Discussion
- To fix this issue, I'm wondering if we should always start the RESTEasy Deployment anyway. Or maybe we just need to start it if we find user defined Providers.
- Wouldn't be better a configuration to force it to start?

- An additional update:

The `ResteasyDeployment.start();` performs the registration of the `ResteasyProviderFactory` which is used to add the required `Providers`. The `ResteasyProviderFactory` may also be initialized directly via `ResteasyProviderFactory.setInstance`.

If we do it for clients, independently if there is an app it works. It an app is deployed, it will override the instance and also works.
