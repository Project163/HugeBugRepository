Title

Savepoint resume is not retried

Description
When during resuming from a savepoint, restoreState fails for a task node, job is retried but without retrying resume from savepoint state. This leads to the job being restarted with empty state.
Discussion
- Test case to reproduce this behaviour.
- GitHub user uce opened a pull request: 

      [URL]

       FLINK-3390    [runtime, tests]  Reset Execution state on ExecutionVertex reset 

     Resuming from a savepoint sets the initial state of the execution graph. If the restore operation fails on the task managers, the job will be retried with new executions, which  don't  have their initial state set. 

     This PR changes the `ExecutionVertex#resetForNewExecution()` behaviour to reset the state of the `Execution` as well.
