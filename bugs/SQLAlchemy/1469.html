Title

support postgresql host forms that have a colon in them but are not multihost format

Description
### Describe the bug

We use the [Link: Cloud SQL Proxy] to mount a connection on the local socket `/cloudsql/my-gcp-project:us-central1:mydbisnstance`. Per the docs, we specify the socket using the host parameter. However, it looks like point release 2.0.18 (I suspect in  ) added a new feature for multiple hosts which breaks the existing connection string.

From semantic versioning, I would expect that 2.0.17 -> 2.0.18 to not break existing parsing.

Thank you for your time and consideration.

### To Reproduce

```python
# This code works in 2.0.17 and fails in 2.0.18
sqlalchemy.create_engine("postgresql://username@password/mydb?host=/cloudsql/my-gcp-project:us-central1:mydbisnstance")
```
