Title

gogo command exports org.osgi.service.log

Description
The command bundle uses the org.osgi.service.log package to get the LogService in order to implement the `log` command.  I think it would be better to optionally import (and/or dynamically import) the package instead.
Discussion
- tjwatson  how would you feel about adding the log commands directly to the log service impls? It's almost trivial code and there's no upstream dependency on gogo.
- That could be fine except we have the log service impl in the Equinox framework.  IIRC it is not so nice to provide the nice `@Descriptor` information about the command and params without binding to the runtime package `org.apache.felix.service.command`
- ... [Middle Discussions Snipped for Brevity] ...
- rotty3000  I second that. 
The basic gogo commands should be tied to the core only. They are fundamental and I would always want to have them and therefore they should not force on me any additional ways to work with other services.
- rinswind  I agree that moving the log command to the impl is the best approach.  We can consider doing that in another issue.  But for now I just made the dependency on the log service package a dynamic import.
