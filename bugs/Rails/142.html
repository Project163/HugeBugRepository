Title

setting nil for serialized fields with a defined type will make it return as changed? when unmodified in 4.2

Description
This concerns columns that use `serialize` with a class (eg `serialize :categories, Array`) that are set to `nil` and might be a regression of sorts?

In 4.2.0 I'm seeing that a field set to nil like this seems to be considered to be changed, even when it has not been touched while in 4.1.8 the same actions would result in the field not being considered changed.

```
ruby
class Post < ActiveRecord::Base
  serialize :categories, Array
end

... [Log Snipped] ...
post2.categories # == [] in 4.2.0 and 4.1.8
post2.categories_changed? # == true in 4.2.0, false in 4.1.8
```

The upgrade guide mentions something about nil serialised values being stored as NULL instead of being serialised before storage (http://edgeguides.rubyonrails.org/upgrading_ruby_on_rails.html#serialized-attributes), sounds like this could be related?
