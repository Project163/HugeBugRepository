Title

WebSockets V00 handshake broken

Description
[URL] modifies `HttpClientCoded#isContentAlwaysEmpty` to return `true` if the `statusCode == 101` which breaks the WebSocket V00 handshake [1]. The V00 handshake includes a payload in the request which is echoed back in the response. It could be argued that V00 is now irrelevant and folks should use the finalized RFC variant [2], but either way this feature is now broken. We have a few options:

1. Remove support for V00
2. Special case this somehow when V00 is used, and continue to support V00's handshake with a payload
3. Revert this fix
4. Update the `HttpClientCoded#isContentAlwaysEmpty` to check against `HttpStatusClass#INFORMATIONAL`.

Based upon the HTTP/1.x RFC [3] we shouldn't do 3, and we should actually also do 4.

Option 1 and 2 are debatable. It would be nice to do 2 because the V00 handshake is prohibited by the HTTP/1.x RFC.
