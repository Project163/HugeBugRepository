Title

replace doesn't clean up system.peers if you have a new IP

Description
When you use replace_token (or replace_node or replace_address) if the new node has a different IP, the old node will still be in system.peers
Discussion
- Existing nodes will already have the correct peers state due to the token conflict(s) from the replacer, but the replacer will still have the dead node in its own peers table.  The simplest thing to do is finish replacing by removing the replace_address from the table, since either it will be our own (which should not appear there) or it will be the old node.  Trivial patch to do so.
