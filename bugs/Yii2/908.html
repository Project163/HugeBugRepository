Title

filterHeaders() should consider user IP

Description
### What steps will reproduce the problem?

Let's suppose following architecture:
~~~
 Client   --->  Load Balancer  --->  Yii2 App
                        
~~~

_Load Balancer_ is configured to replace `X-Forwarded-For` with reliable value (as advised in [URL] and _Yii2 App_ is configured to trust headers from * *.

Example scenario:
 1. _Client_ connects via HTTP**S**
 2. Load balancer replaces *X-Forwarded-For* with user real IP ( ) and appends own IP ( ). It also sets *X-Forwarded-Proto*, so final headers look like:
    ~~~
    REMOTE_ADDR:  
    X-Forwarded-For:  , 
    X-Forwarded-Proto: https
    ~~~

### What is the expected result?

Headers should be trusted and `getIsSecureConnection()` should return `true`.

### What do you get instead?

Headers are not trusted, because [Link: filterHeaders] uses `getRemoteIP` instead of `getUserIP`.
