Title

Derive `Eq` on `ContentType`

Description
**Existing Functionality**

`ContentType` currently derives `PartialEq` but not `Eq`. This is problematic to deal with when many `ContentType`s have to be ingested and used in some way. For example:

```
rs
if ContentType::Binary == content_type {
    "bin"
} else if ContentType::HTML == content_type {
    "html"
... [Log Snipped] ...
    "json"
} // etc
```

What would be nicer is to be able to match:
```rs
match content_type {
    ContentType::Binary => "bin",
    ContentType::HTML => "html",
    ContentType::Plain => "txt",
    ContentType::JSON => "json",
}
```

**Suggested Changes**

Deriving `Eq` would allow using `ContentType`s  in a `match` expression.

**Alternatives Considered**

A method such as `ContentType::to_extension` would also work for the example outlined here.

**Additional Context**

[Link: `Eq` requires the equality comparison to be an equivalence relation.] Since `PartialEq` is derived rather than implemented manually, `ContentType` should satisfy these requirements.
Discussion
- I think `Eq` is not derived on `ContentType` because it is not derived on the inner `MediaType`, for which the rationale is [Link: here].

I think the current implementation is incorrect--`PartialEq` should be used when there are could be values for which `a != a`, but that's not possible with the [Link: implementation of `PartialEq`]. I think the same code would fulfill the `Eq` contract fully.

Also, it looks like the [Link: Hash implementation] does not match the documentation and is affected by all parameters.
