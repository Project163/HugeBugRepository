Title

[2.5.8] ViewClasses are not honored on exception

Description
Summary:
ViewClasses are not honored on thrown exception when RequestHandler is on select controllers instead of in the AppController.  CakePHP seems to expect RequestHandler to be in AppController and it doesn't support custom viewClasses when RequestHandler is selectively added to only some controllers.

Scenario:
1) Setup at least one controller (PiesController)
2) Setup RequestHandler on PiesController, but not in the AppController
3) Add a custom viewClass for "json" to the RequestHandler setup in PiesController
4) Trigger an exception in the PiesController with the "json" extension

What was expected:
The custom json viewClass to be used for serialization

What occurred:
The default/built-in viewClass for json serialization was used

Workaround:
Create CustomRequestHandlerComponent that extends the default RequestHandlerComponent, with the protected viewClass set with your custom viewClasses.  Copy "CakeErrorController" into your project and change "RequestHandler" to "CustomRequestHandler".
Discussion
- What kind of exception? And more importantly, thrown when?
- Any type of exception.  Just add a controller action/function that only contains "throw new CakeException('test')".
- Well, that's not going to work =).

When an exception is thrown, it doesn't matter what controller is in use - the [Link: CakeErrorController] class is used to render the error, which [Link: extends the AppController].

Given that, it's expected that config that is local to an individual controller takes no effect, whereas config in the `AppController` does. 

If you want the requestHandler component to be configured on a per-controller basis, you can do that (sort of) but it needs to be with code that is executed when the `CakeErrorController` is instanciated.

Closing as that's expected behavior and not likely to change.
