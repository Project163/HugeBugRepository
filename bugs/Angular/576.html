Title

updateOn: 'blur' is firing an ngModelChange, regardless of the ngModel value changing

Description

## Current behavior
I'm using the new ngModelOptions updateOn to reduce the ngModelChange event firing from every key press to when the user blurs. However, the ngModelChange is now firing regardless of whether the ngModel has changed or not.

So the user can tab into the input, make no changes, tab out and the ngModelChange event is fired.


## Expected behavior
The ngModelChange should only fire when the ngModel actually changes. As in, user tabs/selects the input makes one or several change(s) then tabs outs, should result in a single ngModelChange event.

` `

## What is the motivation / use case for changing the behavior?
Firing the ngModelChange on blur regardless of whether the model changed or not results in false positives.
