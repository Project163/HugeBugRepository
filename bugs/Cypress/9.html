Title

Cypress doesn't correctly handle the -s option

Description
Cypress seems to be looking inside it's own app for the spec to test..

```
$ ls cypress/integration/end-to-end/setup.js 
cypress/integration/end-to-end/setup.js

$ cypress run -s _does_not_exit_/end-to-end/setup.js 
Can't find test spec: /Users/shauvik/src/mn/projects/fullstory/cypress/integration/_does_not_exit_/end-to-end/setup.js
... [Log Snipped] ...
  at trim_prefix (/Applications/Cypress.app/Contents/Resources/app/node_modules/express/lib/router/index.js:302:13)
  at /
```
Discussion
- It would be great if cypress also supported specifying a directory of specs like:

`cypress run --spec spec_dir`
OR 
`cypress run --spec spec_dir/*.js`

where `spec_dir` is in `cypress/integration`..  Not sure if this was already in the plan.
- Just found that `cypress ci` doesn't support the `--spec/-s` option. It would be great if it were to support that too.
- Fixed in [Link: `0.15.3`].
- Open a new issue for passing a dir to `--spec` since that is a new feature, and we'll track it better that way.

As for passing `--spec` to `cypress ci` that's going to be a no go. I understand why you want to do it since you're essentially using `cypress ci` as an alternate to `cypress run` due to not being able to log in from the command line.

At the moment there's not much difference between `cypress ci` and `cypress run` but soon they will be two very different things. One will spin up real browser instances, record the screen, take screenshots, do analysis, and make the build results available to you, which will take up build hours. The other will simply run the tests locally and will not record any permanent results.

This platform will be rolling out fairly soon and if we just added the ability to log in from the command line then my guess is you'd use `cypress run`.
