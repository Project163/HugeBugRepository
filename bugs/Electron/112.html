- This is likely a side-effect of X11 -> Wayland migration. Currently Electron uses `_NET_WM_STATE_SKIP_TASKBAR` to tell the WM to hide an app from the taskbar.

### GNOME

According to [Link: wayland-bites] the equivalent to `_NET_WM_STATE_SKIP_TASKBAR` on GNOME is with `Window.is_skip_taskbar`, but that "Since GNOME 41, WaylandClient, Workspace, WorkspaceManager, IdleMonitor and Window Meta APIs are available only to GNOME Extensions or in the unsafe mode."

The same page says that "WaylandClient.{hide_from|show_in}_window_list" might also be an approach, but that "WaylandClient controls only subprocess surfaces".

### KWin

On the KWin side, the `KWin::Toplevel::skipTaskbar` is the API to use but "[the] KWin Scripting API is available only to dedicated registered scripts."


... in short, there doesn't seem to be an easy way to do this anymore in a Wayland world, and the tradeoffs involved (e.g. running in unsafe mode) are IMO not worth the cost.

I'd be happy to be proven wrong if someone knows of a better workaround, but if the above is correct IMO we should update the documentation to say that `skipTaskbar` is not supported on Wayland
- Has anyone requested at the Wayland issue tracker that an API be provided? It seems like that should have been the first port of call.
