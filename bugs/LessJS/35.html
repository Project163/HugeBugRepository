Title

Named arguments mixins matching is not consistent with mixin arguments resolver

Description
I was trying to learn how named arguments work and found it a bit odd. The issue is about a case when named argument conflicts with unnamed argument. This is a "nice to have" kind of issue, not the "big important one".

Conflict happens when the named parameter and unnamed parameter potentially reference the same mixin parameter. For example, the parameter `@a` in following call _may_ take either `11` or `a` value:

```
.mixin(@a:defA, @b:defB, @c:defC) {
  three: @a, @b, @c;
}

.mixin(@a:defA, @b:defB, @c:defC, @d:defD) {
... [Log Snipped] ...
  .mixin(@a:a, 21, 22, 23);
}
```

It seems like mixins matching and mixins arguments resolver are using two different algorithms:
- Arguments resolver: unnamed argument supply value for the variable at its absolute position. If named parameter references the same argument as some unnamed one, the first one wins. 
- Mixins matching: looks for exact match between expected number of parameters and declared number of parameters. It acts as if it would be impossible to reference the same parameter by both named and unnamed arguments.

For example, both mixin call in the above snippet will match second mixin definition, the one with four arguments. However, the last and first parameters in both cases reference the same argument `@a` - first one will win. The argument `@d` will remain undefined:

```
#named-conflict {
  four: 11, 12, 13, defD;
  four: a, 12, 13, defD;
}
```

I think that mixin matcher and argument resolver should use the same approach. Both approaches are fine and so would be "this is incorrect mixin call anyway - throw error" approach. 

It seems to me that the language should either (whatever is easier to implement):
- throw an error
- match three parameters version with the result:
  
  ```
  #named-conflict {
    three: 11, 12, 13;
    three: a, 12, 13;
  }
  ```
- resolve arguments in a non-conflicting way:
  
  ```
  #named-conflict {
    four: a, 11, 12, 13;
  }
  ```
