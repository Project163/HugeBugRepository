Title

asyncpg connections not returned to pool if task is cancelled

Description
**Describe the bug**
Using postgresql+asyncpg, I noticed a web app eventually runs out of connections and crashes. It turns out asyncpg connections are not returned to the pool when a task is cancelled.


**To Reproduce**
Provide your [Link: Minimal, Complete, and Verifiable] example
here.

```
pyimport logging
import asyncio

from asyncio import current_task

... [Log Snipped] ...

asyncio.run(main())
```

**Error**
Provide the complete text of any errors received **including the complete

Correct behaviour from `get_and_return`
```
DEBUG:sqlalchemy.pool.impl.AsyncAdaptedQueuePool:Created new connection  >
INFO:sqlalchemy.engine.Engine:select version()
INFO:sqlalchemy.engine.Engine:[raw sql] ()
INFO:sqlalchemy.engine.Engine:select current_schema()
INFO:sqlalchemy.engine.Engine:[raw sql] ()
... [Log Snipped] ...
DEBUG:sqlalchemy.pool.impl.AsyncAdaptedQueuePool:Connection  > rollback-on-return
INFO:root:Pool size: 20  Connections in pool: 1 Current Overflow: -19 Current Checked out connections: 0
```

Incorrect behaviour from `get_and_cancel`
```
DEBUG:sqlalchemy.pool.impl.AsyncAdaptedQueuePool:Connection  > checked out from pool
INFO:sqlalchemy.engine.Engine:BEGIN (implicit)
INFO:sqlalchemy.engine.Engine:SELECT 1
INFO:sqlalchemy.engine.Engine:[cached since 0.0375s ago] ()
INFO:sqlalchemy.engine.Engine:ROLLBACK
...
INFO:root:Pool size: 20  Connections in pool: 1 Current Overflow: -18 Current Checked out connections: 1
```

As you can see, the ROLLBACK triggers, but the connection is not returned to the pool and 1 connection remains checked out. After running the full loop of 20 tries, 20 connections are checked out and not doing anything.

**Versions.**
 - OS: Windows 10, also tested in Alpine container
 - Python: 3.9.2
 - SQLAlchemy: 1.4.18
 - Database: Postgres 11
 - DBAPI: asyncpg 0.21.0

```
python
from sqlalchemy.pool import NullPool

```

that pool class is literally just connect() / close().   so I don't know what options we have here if the task is completely cancelled and GC does not seem to be closing out connections.

The asyncpg connections here are no longer referenced in any way that SQLAlchemy has access to, and they should be garbage collected.  Some initial attempts to trace out exactly what happens in this test case seem to indicate there's no point at which SQLAlchemy could intercept these connections to .close() them, we have a garbage collection hook on them and even that is not getting called.

I have a feeling you could make this program with asyncpg directly pretty easily and im not sure why asyncpg doesn't close out connections that should be garbage collected.     their docs give no guidance: [URL]
