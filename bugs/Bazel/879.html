Title

Downstream projects broken by toolchain change

Description
Culprit:  

Looks like this defines `target_compatible_with` in native rule definitions, which breaks starlark rules which themselves define `target_compatible_with`.

Example failure: [URL]

```
ERROR: Traceback (most recent call last):
--
  | File "/var/lib/buildkite-agent/.cache/bazel/_bazel_buildkite-agent/ /external/bazel_toolchains/rules/rbe_repo.bzl", line 621, column 34, in  
  | _rbe_autoconfig = repository_rule(
  | Error in repository_rule: There is already a built-in attribute 'target_compatible_with' which cannot be overridden
```
Discussion
- @gregestren @katre @philsc @AustinSchuh
- Looks like `target_compatible_with` is declared differently than `exec_compatible_with`:

- `target_compatible_with` is declared in [Link: `BaseRuleClasses.commonCoreAndStarlarkAttributes`], which means it is picked up by all rules, native, starlark, and repository
- `exec_compatible_with` is declared twice separately:
   - [Link: `BaseRuleClasses.RuleBase`], which is the ancestor of all native non-repository rules
   - [Link: `StarlarkRuleClassFunctions.baseRule`], which is the ancestor of all Starlark non-repository rules.

So a simple fix is to make `target_compatible_with` like `exec_compatible_with`.

I'll send out a PR shortly to address this.
