Title

Child order not updated on source after move

Description
The hidden child order property on the source parent of a move operation is not updated when the moved node was orderable under the source parent. 

 The issue does not seem serious, because AbstractTree.getChildNames() is quite lenient and will add children not present in :childOrder at the end of the returned Iterable.
Discussion
- Test to reproduce the issue and proposed changes in PR  [URL]
- The pull request also fixes another issue in MutableTree.moveTo(). The call to the underlying NodeBuilder.moveTo() may returns false. In this case, the MutableTree must not change state, but it currently does. It incorrectly changes its parent to the move target already before NodeBuilder.moveTo(). I added a test that exercises this scenario.
