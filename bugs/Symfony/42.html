Title

[Translator] Does not track changes to files without clearing the cache in dev env

Description
- I work for a developer environment
- I add a file to translations folder, such as validators.ru.yml
- I reload page
- The file dev/translations/catalogue.ru.php sees no change
- I remove cahce
- I reload page
- Translations is OK
- If I change the value of translation and reload page, then I will see changes.

I think the behavior of the system in point 4 incorrect

Regards,
Dmitry
Discussion
- As far as I know this is just not done for performance reasons, because rescanning all dirs for new translation files on every request would be quite expensive. Perhaps someone else has a better explanation though.
- It's not that expensive if you only scan the translation dirs.

I think it's just that no-one has implemented it yet.

- This would be partially fixed by #391 which is still planned for 2.1 as I understand.
The problem is that the cache is compiled with existing resources and since the translation component can always find a fallback, it won't look for something new. Listing translation directories as resources to watch for changes in the cache instead of listing files. Then only when adding a new translation directory would this problem appear.
