Title

Timeout incorrectly reported instead of actual failing assertion when using isEqualTo with SEPARATE_THREAD

Description
In some cases, JUnit reports an exceeded timeout although it is not exceeded. This seems to happen when using `SEPARATE_THREAD` and `isEqualTo`.

## Steps to reproduce

code to reproduce: [URL]

run `./gradlew test`

### Actual result:

The project contains two unit tests. Both (deliberatly) have failing assertions, but no timeout should occur.

For the first test (which uses `isEqualTo`), JUnit reports:

```
ExampleTest > test_reports_timeout_incorrectly() FAILED
    java.util.concurrent.TimeoutException: test_reports_timeout_incorrectly() timed out after 10 seconds
        at org.junit.jupiter.engine.extension.TimeoutExceptionFactory.create(TimeoutExceptionFactory.java:29)
        at org.junit.jupiter.engine.extension.SeparateThreadTimeoutInvocation.proceed(SeparateThreadTimeoutInvocation.java:43)
        at org.junit.jupiter.engine.extension.TimeoutExtension.intercept(TimeoutExtension.java:156)
…
```

The tests run within 2 seconds, so reporting an exceeded timeout seems like a bug.


### Expected:

```
ExampleTest > test_reports_timeout_incorrectly() FAILED
    org.opentest4j.AssertionFailedError: 
    expected: 21
     but was: 42
        at java.base@17.0.3/jdk.internal.reflect.NativeConstructorAccessorImpl.newInstance0(Native Method)
... [Log Snipped] ...
        at java.base@17.0.3/java.lang.reflect.Constructor.newInstanceWithCaller(Constructor.java:499)
        at app//ExampleTest.test_reports_timeout_incorrectly(ExampleTest.java:8)
```

You get this expected output when removing `systemProperty "junit.jupiter.execution.timeout.default", "10"` or `systemProperty "junit.jupiter.execution.timeout.thread.mode.default", "SEPARATE_THREAD"` from `build.gradle`.

Note that the test using `contains` (and no `isEqualTo`) runs just fine in any case.

I just skimmed through the code and would guess that `SeparateThreadTimeoutInvocation` should check whether `failure.cause` is an `ExecutionTimeoutException` [Link: here].
