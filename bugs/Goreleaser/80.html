Title

Gitlab Releases broken

Description
**Describe the bug**

Gitlab releases are broken for gitlab.com:

```
 • github/gitlab/gitea releases
         • token type                type=gitlab
         • creating or updating release repo= tag=v1.12.0-rc1
         • projectID                 name=5174485 owner= projectID=5174485
   ⨯ release failed after 4.14s error=github/gitlab/gitea releases: failed to publish artifacts: GET [URL] 404 {message: 404 Not Found}
```

The release is not there, as it is expected, because goreleaser should create it.

**To Reproduce**

Steps to reproduce the behavior:

```yaml
project_name: vaultbot
release:
  gitlab:
    owner: ""
    name: "{{.Env.CI_PROJECT_ID}}"
```

**Expected behavior**

A new Gitlab release is created successfully.

**Environment (please complete the following information):**

- OS: mac
- OS version: Darwin C02Z1054LVDQ 20.5.0 Darwin Kernel Version 20.5.0: Sat May  8 05:10:33 PDT 2021; root:xnu-7195.121.3~9/RELEASE_X86_64 x86_64
- GoReleaser Version: 0.173.1
- GitLab version: gitlab.com

When performing the same request against the URL we can see that the Gitlab API returns `404`:

```
❯ curl --header "PRIVATE-TOKEN: $GITLAB_COM_TOKEN"  [URL]
{"message":"404 Not Found"}
```

It looks like the code expects a `403` for non-existent releases: [URL]

Maybe there was an API change here, not sure. I can create a PR and add the `404` to the condition as well.
