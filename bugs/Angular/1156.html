Title

routerLinkActive + OnPush + lazy routes = strange behavior

## Current behavior
When using the `routerLinkActive` directive inside a component that is using `ChangeDetectionStrategy.OnPush` and lazy loaded module routes the `routerLinkActive` directive does not update after clicking a link to a lazy loaded route that has not already been loaded.

Also the `OnPush` nav component does not set `routerLinkActive` correctly when the default route loads, the non-`OnPush` nav component works fine.


## Expected behavior
The `routerLinkActive` directive updates the element correctly when navigating to a lazy loaded route for the first time.


## Minimal reproduction of the problem with instructions
My reproduction - [URL]

Live - [URL]

This is a very simple app. There are two lazy routes and two eager routes. There are two navs, one with `OnPush` and one without it.

`npm i && npm start`

## What is the motivation / use case for changing the behavior?
I would prefer to be able to set all my components to `OnPush` for change detection but it doesn't look like this is going to work correctly with the combination I described above.

The problem here is, `[class.active]="rla.isActive"` is your component's own binding, not `routerLinkActive`'s, so even `rla.isActive` is updated successfully, the `class.active` of your component won't be updated (in `OnPush`).

---

You can instead make a feature request like:

**`RouterLinkActive` should perform change detection whenever status of `isActive` changes.**

 Likely too tricky for an attribute directive to control `ChangeDetector` in background. 

Or

**`RouterLinkActive` should expose an Observable version of `isActive` (on status change) so that component can use `async` pipe on it (without change detection on each tick).**
