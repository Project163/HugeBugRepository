Title

Build fails when using the Quartz extension and @Scheduled(..., skipExecutionIf = Scheduled.ApplicationNotRunning.class)

Description
### Describe the bug

When using the Quarkus Quartz extension (https://quarkus.io/guides/quartz) with `@Scheduled(..., skipExecutionIf = Scheduled.ApplicationNotRunning.class)` the build fails with the following exception:

```
2023-11-30 09:57:44,529 ERROR [io.qua.dep.dev.IsolatedDevModeMain] (vert.x-worker-thread-1) Failed to start quarkus [Error Occurred After Shutdown]: java.lang.RuntimeException: io.quarkus.builder.BuildException: Build failure: Build failed due to errors
	[error]: Build step io.quarkus.arc.deployment.ArcProcessor#generateResources threw an exception: jakarta.enterprise.inject.spi.DeploymentException: java.lang.IllegalStateException: There must be exactly one bean that matches the skip predicate: "io.quarkus.scheduler.Scheduled$ApplicationNotRunning" on: @Scheduled(every = "10s",identity = "task-job",skipExecutionIf = io.quarkus.scheduler.Scheduled$ApplicationNotRunning)
	at io.quarkus.arc.processor.BeanDeployment.processErrors(BeanDeployment.java:1447)
	at io.quarkus.arc.processor.BeanProcessor.processValidationErrors(BeanProcessor.java:178)
	at io.quarkus.arc.deployment.ArcProcessor.generateResources(ArcProcessor.java:501)
... [Log Snipped] ...
	at java.base/java.lang.Thread.run(Thread.java:840)
	at org.jboss.threads.JBossThread.run(JBossThread.java:501)
```

The same error has occurred before, but without Quartz: [URL]

When a clone of the bean `io.quarkus.scheduler.Scheduled.ApplicationNotRunning` is declared (lets say `MyApplicationNotRunning`) in the application and then used in `@Scheduled(..., skipExecutionIf = MyApplicationNotRunning.class)`, it works.

### Expected behavior

The build should succeed without an error message and behave as expected: [URL] 

### Actual behavior

An exception occurred during the build
