Title

HttpPostRequestEncoder applies URL-encoding to name and filename values in Content-Disposition fields of multipart attributes. Not all 3rd party web apps can handle this correctly.

Description
HttpPostRequestEncoder applies URL-encoding to name and filename values in Content-Disposition fields of multipart attributes. Not all 3rd party web apps can handle this correctly.

E.g.: A file upload with a filename of `"hello world.txt"` is sent as `"hello+world.txt"`. (Or `"hello%20world.txt"`, if the other encoder mode is used.)

I'm not sure who is following the standards, probably netty. The issue is, that it does not work as expected with some existing SaaS applications, as they are not URL-decoding the values. So in this case, the uploaded file would be stored with the filename `"hello+world.txt"`.

As far as I can see: Firefox does not URL-encode these fields.

Would it be considerable to provide a third `HttpPostRequestEncoder.EncoderMode`, like "PLAIN" or "NONE", which would just not alter the provided values in `HttpPostRequestEncoder.encodeAttribute()`? Like this:

```
java
private String encodeAttribute(String s, Charset charset)
            throws ErrorDataEncoderException {
        if (s == null) {
            return "";
... [Log Snipped] ...
        }
    }
```
