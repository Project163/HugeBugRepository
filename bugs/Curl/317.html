Title

CURL does not follow getaddrinfo sorting policy

Description
### I did this

On Linux one can define IPv6 or IPv4 preference by editing `/etc/gai.conf` and CURL will apply the defined policy.

```
label ::1/128       0    
label ::/0          1
label 2002::/16     2
label ::/96         3
label ::ffff:0:0/96 4
... [Log Snipped] ...
precedence ::/96          20
precedence ::ffff:0:0/96  100
```

Result:

```
root@debian:~# curl my.ip.fi
87.138.*.*
```

On FreeBSD we can likewise set the policy:

```
root@freebsd:~ # service ip6addrctl status
Prefix                          Prec Label      Use
::1/128                           50     0        0
::/0                              40     1        7
::ffff: /96                100     4        0
... [Log Snipped] ...
fec0::/10                          1    11        0
3ffe::/16                          1    12        0
```

Result:

```
root@freebsd:~ # curl my.ip.fi
*:*:*:*:be24:11ff:fe60:a3df
```

So on FreeBSD CURL seems to prefer IPv6 unconditionally.

### I expected the following

CURL should prefer IPv4 if the address sorting policy is configured that way.

Discussion
- BTW: policy selection does fundamentally work in FreeBSD. If I use FreeBSD's own `fetch` tool:

```
root@freebsd:~ # fetch -q -o - [URL]
87.138.*.*
```
- curl uses `getaddrinfo` to resolve hostnames and walks through the list in the order the addresses are returned. I believe that is the correct method. If this is the wrong order, I believe your getaddrinfo implementation might be doing it wrong.
- ... [Middle Discussions Snipped for Brevity] ...
- If we go for this, we need it to treat it with the resolve source in mind. Following the order returned should then only apply to sources like `getaddrinfo()`, but not to DoH where the order in which the A/AAAA queries are answered is not relevant.

Don't know about cares, but I am sure @bagder has a better idea.
- c-ares has its own getaddrinfo function that sorts the addresses as per RFC 3484 but it does not respect `/etc/gai.conf` from what I can tell.
