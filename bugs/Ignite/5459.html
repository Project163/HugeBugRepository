Title

Incorrect backward connection check with loopback address.

Description
We may skip backward connection check of a previous node if it has the same loopback address as the current node. 

 Consider: 
 
	 Neither  IgniteConfiguration#setLocalHost()  or  TcpDiscoverySpi#setLocalAddress()  is set. Or the localhost parameter is  "   ". 
	 Nodes start on different hosts. All the available host addresses are resolved. 
	 Among the other addresses, all nodes get the loopback address " :47500" (47500 is the default tcp discovery port). 
	 Cluster starts and works. 
	 Some node N (A) decides that the connection to node N+1 (B) is lost and tries to connect to node N+2 (C) and sends  TcpDiscoveryHandshakeRequest . 
	 Before C accepts incoming A's connection, it decides to check B and pings it with  ServerImpl#checkConnection(List<InetSocketAddress> addrs, int timeout)  
	 Around here, the network is restored, and A can now connect to B anew. 
	 "  :47500 " is last in  List<InetSocketAddress>  addrs by  IgniteUtils#inetAddressesComparator(boolean sameHost) . But the connect attempts in  checkConnection(...)  are parallel. "  :47500 " answers first. 
	 C sees it can connect to "  :47500 " and chooses it as the alive address of B. Other pings to rest of B's addresses are ignored. 
	 But "  :47500 " is one of C's addresses. C realizes it pinged itself and marks that B is not reachable:
  
 
          // If local node was able to connect to previous, confirm that it's alive.
          ok = liveAddr !=  null  && (!liveAddr.getAddress().isLoopbackAddress() || !locNode.socketAddresses().contains(liveAddr));
 
   
	 C accepts connection from A and answers with  TcpDiscoveryHandshakeResponse#previousNodeAlive() == false  
	 B is ok now, but A connects to C and B is kicked from the ring. 
 

 The problem is that C pings itself with B's address "  :47500 "
