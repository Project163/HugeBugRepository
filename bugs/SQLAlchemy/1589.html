Title

async DBAPI wrappers do not seem to do any handle_exception for the connect attempt itself failing

Description
### Discussed in [URL]

asyncpg, asyncmy, aiomysql, psycopg3, aioodbc, aiosqlite.   all of these do a connect outside of a try/except that would call _handle_exception(), and further, _handle_exception() is local to AsyncAdapt_dbapi_connection which we dont have an instance of without a connection.

This requires a significant refactor of each of the AsyncAdapt_*_dbapi classes and also requires a connection-free version of _handle_exception() is made available, and all the async DBAPIs need their existing _handle_exception() handlers be ported to the new version that does not require a connection present (likely a classmethod AsyncAdapt_dbapi_connection.handle_error_noconneciton).
Discussion
- Hello, can I work on this issue?
- @ShivamHP this is a fairly complex issue as it refactors a significant amount of code and also needs to establish new architectural patterns that will be re-used across many modules.    I haven't worked out how it will be organized.   It will require a lot of fast iteration and changes as it goes and we're on fairly short timeframes for the 2.1 series.     This is to say this is overall not a good first issue for someone to work on, I would never stop anyone from writing code they want to write but you'd need to be ready for a lot of critique and possible rejection for this one.
- adding some context, all the async dialects we have right now other than asyncpg raise exception objects that are from the sync version of the DBAPI, so _handle_exception() thing is only critical for asyncpg.
- **Mike Bayer** has proposed a fix for this issue in the **main** branch:
