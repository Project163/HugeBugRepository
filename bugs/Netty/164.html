Title

Does ctx.read() work correctly?

Description
I don't be able to make this feature works correcly.

I've got a simple pipeline with a single handler "MyHandler" which reads bytes from the inboundbuffer and writes them into a queue. This queue is read by another thread.
When this queue is full, it does'nt block, so my IO thread can return and exit MyHandler.inboundBufferUpdated() method. 

The way autoread=false works (or what I understood), I should not have new inboundBufferUpdated() call as long as ctx.read() is not called.
However, inboundBufferUpdated() method is called as long as IO thread has bytes to read from channel socket. When socket becomes "empty", read is suspended, but
if socket contains bytes, there's no option to stop the "stream".

Here is my analysis (and so possible issue):
In AbstractNioByteChannel.NioByteUnsafe::read() method, if pipeline.fireInboundBufferUpdated() is called from "case2" (when inbound buffer has reached its max capacity) there's no way to exit loop even if autoread=false

Yes,

In **"AbstractNioByteChannel.NioByteUnsafe::read()"** method, we have a loop for(;;) from which we cannot exit as long as socket is not empty.
We first read from socket and then enter a switch:

**case 0**: all data has been read from socket -> exit loop and call **inboundBufferUpdated()**. After **inboundBufferUpdated()** call -> exit read() method, so _"autoread=false"_ mode works correctly in this case.

**case 1**: not all data has been read, buffer has been expanded, so we loop again to read more data. ok

**case 2**: not all data has been read, buffer is full, comment is _"Let the inbound handler drain the buffer and continue reading"_. 
But, in this case, **fireInboundBufferUpdated()** is always called, even if it was already called since last ctx.read() call (in _"autoread=false"_ mode)
After what, we are still in loop, if socket contains enough data to fill inboundBuffer, case 2 is reached again and **fireInboundBufferUpdated()** is called again, and so on
