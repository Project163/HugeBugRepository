Title

DbTarget + flushInterval + exportInterval results in "memory exhausted" errors

Description
Hi!

I'm developing queue worker and I need flushing logs to db at the time when log entry generated, not at the time of app exit.
But when I put "exportInterval=1" to the config - the app dies with memory exhausted error in Target::filterMessages function.
If I do "file_put_contents('file.txt', print_r($messages,1));" in the function start I see array of thousands of identical "opening DB connection" messages:

```
[0] => Array
  ....
    [1] => Array
        (
            [0] => Opening DB connection: mysql:host=localhost;dbname=db
... [Log Snipped] ...

        )
```

Part of my not working config:

```
'log' => [
            'flushInterval' => 1,
            'targets' => [
                [
                    'class' => 'yii\log\DbTarget',
... [Log Snipped] ...
            ],
        ],
```

I've tried the same config for console and web app, with same issue.

Can you please tell me if I'm doing something wrong here?
Discussion
- Do not set `flushInterval` to be 1 because DB operations will log their own messages. So each time you flush message to DB target, more log messages will be generated.
- So what is the recommended way to do realtime (or with lag no more than 5-10 seconds) logging to db in my case?
flushInterval=10 does not help the situation, the app still can't startup properly.
