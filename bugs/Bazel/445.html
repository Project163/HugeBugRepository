Title

worker protocol seems to drop empty lines in argument file

Description
### Description of the problem / feature request / question:
When using workers with an argument file, it seems empty lines are dropped. So, if you expect empty arguments and you are writing one argument per line, you get different behavior if you run in worker vs non-worker mode.

### If possible, provide a minimal example to reproduce the problem:
In the scala rules we have support for thrift using twitter scrooge. We have a worker implementation of this here: 

[URL]

we set up our args file here:
[URL]

note we have 1 arg per line, and some may be empty strings, meaning the argument is optional.

When we run without worker we get, for instance, this argument file:
```
bazel-out/darwin_x86_64-fastbuild/bin/zoolander-thrift/src/main/thrift/com/stripe/thrift/api/libapi_srcjar.srcjar
bazel-out/darwin_x86_64-fastbuild/bin/zoolander-thrift/src/main/thrift/com/stripe/thrift/api/libpay_server_api_thrift_lib.jar


external/com_stripe_pay_server_api_thrift/jar/pay-server-api-thrift-0.0.1-SNAPSHOT.jar
```
when we run with worker, the created args looks like:
```
bazel-out/darwin_x86_64-fastbuild/bin/zoolander-thrift/src/main/thrift/com/stripe/thrift/api/libapi_srcjar.srcjar
bazel-out/darwin_x86_64-fastbuild/bin/zoolander-thrift/src/main/thrift/com/stripe/thrift/api/libpay_server_api_thrift_lib.jar
external/com_stripe_pay_server_api_thrift/jar/pay-server-api-thrift-0.0.1-SNAPSHOT.jar
```
note we have lost the empty lines. I *believe* bazel is in control of this, but maybe we have done something wrong.

we can work around by ensuring each line is non-empty:
[URL]
