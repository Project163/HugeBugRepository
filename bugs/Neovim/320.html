Discussion
- The semantics of `WinScrolled` is "whenever the viewport changes". A buffer entering a window is a viewport change. This is so that plugins such as [Link: nvim-treesitter-context] or maybe even treesitter highlighting can update visual content only for the current viewport. However it could be changed, because plugins could alternatively listen to both `WinScrolled` and `BufWinEnter`.

I can't reproduce the segfault with either test case, but I see why it happens. I'm not sure what would be the correct behavior for this case. Should it be disallowed? Or can freeing the window be deferred until the end of the iteration? What do `w_closing` and `b_locked` do?

Edit: meanwhile [URL] should prevent that from happening, but I worry that I haven't handled all repercussions of closing a window down the line.
- The abnormal termination is due to my use of the ASAN build. It may not end abnormally for a normal build. In any case, invalid memory accesses should not occur.

Invalid memory accesses will not occur, so I think 0224d36 is fine. However, I have found other similar problems. There may be others.
