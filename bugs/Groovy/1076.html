Title

'this' reference in closure of a closure not correctly resolved when using @Category annotation

Description
'this" in two imbricated closures not resolved to method parameter. 

 The following test case fails : 
  
 @Category(Guy)
 class  Filtering {
	List process() {
		 this .messages.findAll{it.name !=  this .getName()}
	}
}

 interface  Guy {
	 String  getName()
	List getMessages()
}

 class  MyGuyver  implements  Guy {
	List messages
	 String  name
}

def onetest =  new  MyGuyver(
		name:  'coucou' ,
		messages : [[ 'name' : 'coucou' ], [ 'name' : 'test' ], [ 'name' : 'salut' ]])

Guy.mixin 	Filtering

 assert  onetest.process() == onetest.messages.findAll{it.name != onetest.getName()}
Discussion
- Using ' this ' inside a closure is potentially confusing - even though you would expect it to be transformed away in this case before being applied. 

 The workaround (which is also perhaps clearer) is to avoid this inside the closure altogether: 
  
 @Category(Guy)
 class  Filtering {
    List process() {
        def myName =  this .name
         this .messages.findAll{it.name != myName}
    }
}
 
  
 Not saying that we don't need to have a well-defined semantics here - just pointing out alternatives. 
You may already have found a similar workaround by now but searches may lead others here.
- The "this" outside the closure should be the same as the "this" inside the closure. That was a decision we made long ago. I think that the transform simply does not handle ClosureExpression correctly.
- fixed
