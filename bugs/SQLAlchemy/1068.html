Title

Regression with joinedload() on 1.4

Description
**Describe the bug**

I am unable to call `.joinedload()` and `.count()` at the same time with SQLAlchemy 1.4. It affects Flask-SQLAlchemy, as `.paginate()` is broken (https://github.com/pallets/flask-sqlalchemy/issues/910)

**To Reproduce**
```
py
from sqlalchemy import (
    Column,
    ForeignKey,
    Integer,
... [Log Snipped] ...
query = session.query(User).options(joinedload(User.parent))
query.count()
```

**Error**

```
Traceback (most recent call last):

    query.count()
  File "/venv/lib/python3.7/site-packages/sqlalchemy/orm/query.py", line 3009, in count
    return self._from_self(col).scalar()
... [Log Snipped] ...

```

**Versions.**

- SQLAlchemy 1.4
Discussion
- I would see if Flask can remove this meaningless joinedload() as it is not necessary here.
- OK this is extremely specific to just the query.count() method.    Usually, options that make no sense raise an error, including on 1.3, such as:

    s.query(A.id).options(joinedload(A.bs)).all()

I'll adjust query.count() to behave as closely to the old way as possible as this is all frozen in time stuff.
- ... [Middle Discussions Snipped for Brevity] ...
- What I'm doing is:

```python
query = session.query(User).options(joinedload(User.parent))

count = query.count()
items = query.items()
```

or, with flask-sqlalchemy:

```python
def my_endpoint():
  query = query.options(joinedload(User.parent))
  res = query.paginate(page=0, per_page=30)
  schema = schemas.UserListSchema()
  return schema.dump({'data': res.items, 'meta': res})
```

(I can provide full working examples if necessary)


What is the "best" way to achieve this?
- you would have two separate queries:

```python
count = session.query(func.count()).select_from(User).scalar()

items = sesion.query(User).options(joinedload(User.parent)).all()

```

the idea is that this does not rely on implicit guessing and you also get a much more efficient query for the COUNT part, as the ORM's .count() method has to run everything in an inefficient subquery.
