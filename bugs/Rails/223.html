Title

Time attribute changes from Time to ActiveRecord::Type::Time::Value

Description
### Steps to Reproduce

Pseudo code here. Executable test case below.

```
ruby
model = Model.last
# =>  
model.time_attribute.class
# => Time
... [Log Snipped] ...
model.time_attribute.class
# => ActiveRecord::Type::Time::Value
```

### Actual behavior
`model.time_attribute.class` changes from `Time` to `ActiveRecord::Type::Time::Value` after calling `model.save`. 

This is a problem if the code later tries to do arithmetic with the time attribute.

### Expected behavior
`model.time_attribute.class` is still `Time` after saving the record.

### System configuration
**Rails version**: 6.0.2.rc1 (using `config.load_defaults 5.2`)
**Ruby version**: 2.6.3

### Executable Test Case
```
ruby
# frozen_string_literal: true

require "bundler/inline"

... [Log Snipped] ...

end
```

### My Theory 

* `Time.change` will [Link: implicitly convert] `ActiveRecord::Type::Time::Value -> Time` because it always creates a new `Time` instance, whether the receiver of the `change` call is actually a `Time` or not. `ActiveRecord::Type::Time::Value` is [Link: a wrapper] around `Time`.

* The optimisation introduced in [URL] has created a code path that does not "unpack" 
`ActiveRecord::Type::Time::Value` to become a `Time` again.
