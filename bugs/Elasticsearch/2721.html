Title

Index Template API: Invalid alias JSON can result in unrelated filters

Description
**Elasticsearch version** (`bin/elasticsearch --version`): 7.8.1
**Description of the problem including expected versus actual behavior**: When creating an index template with an alias, that is not properly resembling a filter but contains the `filter` term, weird and wrong filters are created instead of just throwing an exception.

**Steps to reproduce**:

```
DELETE _template/mytemplate

DELETE myindex

# this one works but should have thrown an exception...
... [Log Snipped] ...
# this one shows a crippled filter...
GET myindex
```

The response of the last call is 

```
{
  "myindex" : {
    "aliases" : {
      "filtered-data" : {
        "filter" : {
... [Log Snipped] ...
  }
}
```

This is a completely different filter, than the one that was initially specified. I think the put index template API should thrown an exception because of invalid JSON to prevent this problem before new indices with broken aliases get created.
Discussion
- Pinging @elastic/es-core-features (:Core/Features/Indices APIs)
- This has been fixed with composable index templates (they get no filter at all, rather than an invalid filter), however, I think the Alias validation should throw an error on the unknown field `bool` so that it's apparent to the user what's happening.
- Pinging @elastic/es-storage-engine (Team:StorageEngine)
