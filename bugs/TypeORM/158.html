**Steps to reproduce or a small repository showing the problem:**

1. Create the following schema with previous migrations (no problems there):

```
ts
export enum UserLoginMethod {
    DeviceId = "device_id",
    Facebook = "facebook",
    Bot = "bot"
... [Log Snipped] ...

}
```

2. Create a new entity:

```
ts
@Entity()
export class UserDeviceId {

    @OneToOne(type => User, { primary: true })
... [Log Snipped] ...
    deviceId: string;
}
```

3. Try to generate a new migration:

```
typeorm migration:generate -n UserDeviceId
```

**Expected result:**

A new migration is created, with a new table that uses a composite foreign key as a primary column.

Discussion
- Updated from 0.2.22 to 0.2.24, bug still persists.
- So, it seems that it's failing here:

[URL]

While trying to create an up migration for a new enum. But it's not a new enum! It should use the same enum that was created before.

I digged the code that checks if enum exists already, and found this:

[URL]

Apparently, table name is included in the generated enum name - so, although it's the same enum type on both columns, TypeORM tries to create a new type for each table that uses this enum.

If I understood all that correctly (and it's very possible that I didn't), that seems like a very strange design choice and defeats the whole purpose of user-defined data types.
- Found a workaround!

In the code that decides how an enum should be named, there is mention that I could specify the enum name explicitly:

[URL]

So, I put it into my user entity (just in case, although the name stayed the same):

```
ts
@Entity()
// We have to create a composite index for it to be a target of a foregn key
@Index("user_login_method", ["id", "loginMethod"], { unique: true })
export class User {
... [Log Snipped] ...
    })
    loginMethod: UserLoginMethod;
```

And then into my new table, too:

```
ts
@Entity()
export class UserDeviceId {

    @Column({
... [Log Snipped] ...
    deviceId: string;
}
```

And now it uses the same type name for both.
- You can use `enumName` property for this case.

```ts
@Column({
    type: "enum",
    enumName: "loginMethodEnum",
    enum: UserLoginMethod
})
loginMethod: UserLoginMethod;
```
