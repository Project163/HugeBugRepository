- Another workaround seems to be coding up the bind and unbind methods manually, and specifying them in the @Reference annotation.  If this is done, the split verifier workaround is not required.
- Just so I'm sure I understand, the problem occurs with bind/unbind methods generated by the maven-scr-plugin but not with methods you write in java yourself?  So the problem is with the generated bytecode?

- I've now fixed this by looking at the version of the class file: 
if it's java7 or above use ClassWriter.COMPUTE_MAXS  | ClassWriter.COMPUTE_FRAMES 
otherwise 0 is used.
