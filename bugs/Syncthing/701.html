Title

"fatal error: runtime: out of memory" during database migration on QNAP NAS

Description
### "fatal error: runtime: out of memory" after upgrade syncthing from version 1.3.2 to 1.4.0 on a QNAP NAS TS-419 II 

### Version Information

Syncthing Version: syncthing v1.4.0 "Fermium Flea" (go1.13.8 linux-arm)
OS Version: QNAP firmware version 4.3.3.1161 Build 20200109
Browser Version: not applicable
NAS Model:      TS-419P II

 - what happened,
Syncthing service crashed after updating from v1.3.2 to v1.4.0. The log shows the problem happened after "Migrating database to schema version 9..." entry and the crash report describes a "fatal error: runtime: out of memory".  
see attached files: [Link: sync.log]
[Link: panic-20200318-175040.reported.log]

 - what you expected to happen instead, and
Indeed the system is an old QNAP NAS with only 512MB of RAM but it have never had problem with previous version updates. The problem persisted even after stopping all services to free up memory before performing the update.

Discussion
- Main answer: The database migration on upgrade just requires too much memory for your system. There might be workarounds, but that's better suited for [URL]

"Internal" Implementation stuff: Looking at the migration, we do not `Checkpoint` the transaction, meaning it will only be committed when reaching 128MiB instead of the 1MiB in usual operations. That looks like an oversight, I doubt the fewer commits will speed the whole thing up by much, or does it? ( @calmh )
- I doubt that as well, we should checkpoint here and there in the transition. Good 1.4.1 material.
