Title

class-scoped fixture caching is broken if there are module-level test functions

Description
Originally reported by: **Ivan Kalinin (BitBucket: [Link: PuPSSMaN], GitHub: [Link: PuPSSMaN])**

---

Basically, class-scoped fixture is initialized once for a test module if it contains test classes as well as test functions.

Test-case:

```
#!python

import pytest

... [Log Snipped] ...
    def test_c(self, a):
        assert a == 3
```

This test case fails for me for python-pytest v 2.3.4-8 on Ubuntu 12.04 with Python 2.7.3-0ubuntu2.

If runned with -v -s, it comes obvious that fixture is only initialized once for the test_a.

This one passes (just to demonstrate the principle behind the test):

```
#!python

import pytest

... [Log Snipped] ...
    def test_c(self, a):
        assert a == 2
```
