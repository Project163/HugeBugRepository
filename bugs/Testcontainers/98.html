Title

[Bug]: Using the default user for Clickhouse will result in "Authentication Failed"

Description
### Module

Clickhouse

### Testcontainers version

1.20.4

### Using the latest Testcontainers version?

Yes

### Host OS

Linux

### Host Arch

x86

### Docker version

```shell
Does not matter
```

### What happened?

Because of this recent change in ClickHouse, the default testcontainer setup for Clickhouse won't work, because the `default` user is used:
[URL]

You will see the test fail with an error like this:
` Authentication failed: password is incorrect, or there is no user with such name.`
[URL]

### Relevant log output

```
shell

If you use ClickHouse Cloud, the password can be reset at [URL]
on the settings page for the corresponding service.

	at java.base@21.0.5/java.lang.Thread.run(Thread.java:1583)
```

### Additional Information

We set up the testcontainer like this
```
companion object {
        private val CLICKHOUSE_IMAGE_NAME: DockerImageName = DockerImageName.parse("clickhouse/clickhouse-server")

        @Container
        var clickHouseContainer = ClickHouseContainer(CLICKHOUSE_IMAGE_NAME)
... [Log Snipped] ...
        }
    }
```
Discussion
- I think the fastest way to fix this, would be to add the new environment variable `CLICKHOUSE_SKIP_USER_SETUP`.

```java
    @Override
    protected void configure() {
        withEnv("CLICKHOUSE_DB", this.databaseName);
        withEnv("CLICKHOUSE_USER", this.username);
        withEnv("CLICKHOUSE_PASSWORD", this.password);
+       withEnv("CLICKHOUSE_SKIP_USER_SETUP", "1");
    } 
```
- I'm having this issue as well, but I'm dealing with it by setting up a clickhouse account and password

like this

```
java
        @Container
	@ServiceConnection
	static ClickHouseContainer clickhouse = new ClickHouseContainer(DockerImageNames.clickhouse())
                .withUsername("root")
... [Log Snipped] ...
		registry.add("spring.datasource.password", clickhouse::getPassword);
	}
```
- @alexkops @eddumelendez I think we should fix this problem in a way like MySQLContainer or PostgreSQLContainer, rather than using some means to block it
