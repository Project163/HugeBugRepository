Issue:
I work on a private project, so I will not disclose any info about it, but...
I have an umbrella helm-chart in the packaged format (tgz file), where I get the following stacktrace:

```
helm3 inspect CHARTNAME
panic: runtime error: invalid memory address or nil pointer dereference
[signal SIGSEGV: segmentation violation code=0x1 addr=0x98 pc= ]

goroutine 1 [running]:
... [Log Snipped] ...
main.main()
	/home/circleci/helm.sh/helm/cmd/helm/helm.go:74 +0x1e2
```

I also have a newer version, where I do not get a stacktrace...
So I started to look into the code, and what is the difference here...
The code shows at [URL] at line 126 that the requirements.lock file is parsed, and we get a nil pointer. This file shows that there are a few initializations of c.Metadata, like this
```

if c.Metadata == nil {
				c.Metadata = new(chart.Metadata)
}
```

But this is not done in every place.
I have checked, and
- The tgz package of the faulty file has the requirements.lock file earlier in the package than the Charts.yaml and others
- The tgz package of the correct file has the Charts.yaml first
