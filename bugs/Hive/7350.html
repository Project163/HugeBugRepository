Title

TRUNCATE TABLE fails due MySQL limitations on limit value

Description
HMS currently has some APIs that accepts an integer limit value. Prior to the change in   HIVE-21734  , HMS was silently converting this int to short and thus we havent seen this issue. But semantically, its incorrect to do so quietly.

Discussion
- In case of truncate table, the code specified Integer.MAX_VALUE for the limit, but its real intention is to get all the partitions for the table. In this case, using  -1  instead of MAX_VALUE is to be used as it returns all the partitions. Prior behavior was to convert this value to short, which would have secretly used  -1 //nolimit  under the covers as well. But I think this is more appropriate semantically.
- +1 overall
