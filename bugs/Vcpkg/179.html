Title

[qpid-proton] `find_package` is broken

Description
**Describe the bug**
`find_package(qpid-proton REQUIRED CONFIG)` does not work since there is no file `qpid-protonConfig.cmake`. `find_package(Proton REQUIRED CONFIG)` and `find_package(ProtonCpp REQUIRED CONFIG)` do not work either out of the box. Setting `Proton_DIR` and  `ProtonCpp_DIR` so that their config files are found helps, but then there is another failure because `_IMPORT_PREFIX` is not set in the `Config` files and the `IMPORTED_LOCATION_DEBUG` does not point to the debug libraries. Hence, it would seem that the original config files are not what `vcpkg_cmake_config_fixup` expect them to be.

Another unrelated problem is a warning that `BUILD_PYTHON` and `BUILD_RUBY` are CMake variables that are not used. I mention it cause I'll submit a pull request that will solve the main issue, and I will also take the opportunity to remove this warning.

**Environment**
- OS: Experienced on both Windows and Linux (Ubuntu 20.04)
- CMake version: 3.22.2

**To Reproduce**
Steps to reproduce the behavior:
1. Adds the port `qpid-proton` to `vcpkg.json`
2. Try to add `find_package(qpid-proton REQUIRED CONFIG)`, `find_package(Proton REQUIRED CONFIG)` or `find_package(ProtonCpp REQUIRED CONFIG)` to your CMake file
3. Run `cmake -B debug -G Ninja -S .` and see the warning _and then_ the error.
4. Set  `Proton_DIR` and  `ProtonCpp_DIR` so that the config files are found
5. Run `cmake -B debug -G Ninja -S .` and see the other error.

**Expected behavior**
`find_package(qpid-proton REQUIRED CONFIG)` should work and there should be no warning
