Title

Indexed access to star import is miscompiled in webpack 2

Description
This is very easy to reproduce with coffeescript 1.11's import/export syntax support, as while the syntax will just be emitted as is, actual use of the module record will be subjected to [Link: coffeescript's es3-compatible output], which will convert `a.default` into `a['default']`.

In real code terms:

``` coffee
store.default.dispatch(unfollowUser(@user_id))
```

is translated to:

``` js
store["default"].dispatch(unfollowUser(this.user_id));
```

which webpack compiles to:

``` js
__WEBPACK_IMPORTED_MODULE_3_store__.dispatch(__webpack_require__.i(__WEBPACK_IMPORTED_MODULE_4_actions_user_unfollow__["b" /* default */])(this.user_id))
```

that errors out at runtime with:

```
TypeError: __WEBPACK_IMPORTED_MODULE_3_store__.dispatch is not a function. (In '__WEBPACK_IMPORTED_MODULE_3_store__.dispatch(__webpack_require__.i(__WEBPACK_IMPORTED_MODULE_4_actions_user_unfollow__["b" /* default */])(this.user_id))', '__WEBPACK_IMPORTED_MODULE_3_store__.dispatch' is undefined)
```

due to the missing `["a" /* default */]`. The same happens with any indexed symbol access, but is impossible to avoid with `.default` access in coffeescript, other than by making a separate `import theDefault from 'module'`.
