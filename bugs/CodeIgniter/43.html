Title

ReDoS (Regular Expression Denial of Service) / Code Injection Risk

Description
The second parameter `$separator` in function `increment_string` in file `system/helpers/string_helper.php` is not properly escaped for use in regular expressions. 

Nevertheless the parameter is injected directly into PHP's `preg_match` function on line 256.
`preg_match('/(.+)'.$separator.'([0-9]+)$/', $str, $match);`

This can cause a Denial of Service (ReDoS) and makes it possible to inject code into the regular expression. When the developer used this `increment_string` with a dynamic (user customizable) string and this string is not properly escaped, code injection is possible and a potentially ReDoS can be caused.

I would recommend to use PHP's `preg_quote` function to mitigate this vulnerability. 
Line 256 in file `system/helpers/string_helper.php` should be:
`preg_match('/(.+)' . preg_quote($separator) . '([0-9]+)$/', $str, $match);`

Also without the use of `preg_quote` it's not possible to call this `increment_string` function with one of the following delimiters `. \ + * ? [ ^ ] $ ( ) { } = !   | : -`

---

This vulnerability seem to exists since CodeIgniter versions 2.1.0 and higher and also applies to stable releases 2.2.0 and 3.0.0.
