Title

Multiple source matches for a destination property

Description
I've added a Github reproduction: [URL]

The problem:
What happens is that since version 10.1.1 several mappings started reporting `mapping exceptions` in my unittests. Where in the previous version they didn't. And shouldn't.

Investigating:
In this case automapper reports a `mapping exception` because of an arbitrary value it gets from running an instance **method**. That is: A method named `GetXYZ` which it isn't supposed to execute during mapping. It's not supposed to be executed by the mapper because it's not tied to a property being mapped. It's just a regular instance method.

Seeing this I got curious. I posited that it might have something to do with the **method's name starting with `Get`**. Which might cause Automapper to mistakenly assume that the method is a property. 

Turns out that was the case.

Work-around:
After I changed the method name to `GenerateXYZ` the exception was remedied. 

Community notes:
If you updated and are encountering new mapping exceptions: verify whether Automapper is calling any methods whose names start with `Get` and consider renaming those methods until a patch is issued. 
This is obviously not feasible in many environments, in which case it would be better to postpone updating until a patch is issued.
Discussion
- We have method mapping since forever, but I think your point is that when both a property and a method match, it seems the method is preferred. You can disable method mapping with `ShouldMapMethod`.
- Try the [Link: MyGet] build.
