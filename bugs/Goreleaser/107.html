Title

.TagSubject and .TagContents are using the underlying commit subject/contents instead of the ones from the annotated tag

Description
### What happened?

`.TagSubject` and `.TagContents` in Release output are using the underlying commit subject/contents instead of the ones from the annotated tag.

[Link: Here is a test repo] where you can see this bug in action in the release notes generated, with the release for either of tags:
- [Link: v0.3.0] or
- [Link: v0.3.1-rc0]

Both have annotated subject and message body, that I have also verified using git as confirmed by these commands:

```
$ git tag -l --format='%(contents)' v0.3.1-rc0
Lot of exciting features in this release.

- Mix of both small and large changes in the same release.
- Improves performance by 5x compared to previous release.
- And more smaller changes to the codebase to improve readability.
```

```
$ git tag -l --format='%(contents:subject)' v0.3.1-rc0
Lot of exciting features in this release.
```

```
$ git tag -l --format='%(contents)' v0.3.0
Thirs release.

Excited to get a third release going for this test package, getting more
impactful changes out there!

That's all folks!
```

```
$ git tag -l --format='%(contents:subject)' v0.3.0
Thirs release.
```

My [Link: `.goreleaser.yml`] contains these sections to include both `.TagSubject` and `.TagContents` in the release notes header for demonstration:

```
release:
  header: |
    ## {{ .TagSubject }}
    {{ .TagContents }}
```

Also, I am using the `goreleaser/goreleaser-action@v2` github action in my workflow to cut releases. The [Link: config] is available here if it makes any difference.

### How can we reproduce this?

1. Create an annotated tag with both a tag subject and a message body.
2. Add the following to the `goreleaser.yml`
3. Invoke `goreleaser` to cut a new release.

```
release:
  header: |
    ## {{ .TagSubject }}
    {{ .TagContents }}
```
