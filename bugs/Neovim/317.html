Title

abort() by 'resize -1' with 'cmdheight=0 redrawdebug=invalid'

Description
### Describe the bug

`resize -1` leads to abort() if options `cmdheight=0 redrawdebug=invalid` are set.

### Steps to reproduce

nvim --clean
set cmdheight=0 redrawdebug=invalid
resize -1

### Expected behavior

resize works

### Actual behavior

nvim is terminated by abort(3).

abort() is called at line 427 in ui_compositor.c.
[URL]

### Neovim version (nvim -v)

NVIM v0.9.0-dev-877+g228684d2f-dirty

### Vim (not Nvim) behaves the same?

no

### Operating system/version

Ubuntu-22.04, macOS (Mojave etc.)

### Terminal name/version

gnometerminal, Apple's Termial.app

### $TERM environment variable

xterm-256color

### Installation

build from source
Discussion
- Here is the back trace from the core (macOS Mojave).
[Link: bt.txt]
- The problem is in `update_screen`, it invalidates all `msg_grid` rows that are used for displaying a message, when the screen is scrolled down back [URL]  
But then, if redraw type is `UPD_NOT_VALID`, `msg_grid` rows from 0 to `p_ch` are used for compositing in [URL]  
So, any command that shows a scrolled message, and causes a `UPD_NOT_VALID` redraw should trigger the same bug. For example, `:split | echo "\n"` command with `redrawdebug=invalid` set also triggers the bug.  
Here's the fix I came up with:  
```
diff
diff --git a/src/nvim/drawscreen.c b/src/nvim/drawscreen.c
index 73dd584fb..608b7806d 100644
--- a/src/nvim/drawscreen.c
+++ b/src/nvim/drawscreen.c
... [Log Snipped] ...
     }
     msg_grid.throttled = false;
```
