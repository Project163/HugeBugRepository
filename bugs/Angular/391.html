Title

Expose name in package.json of subpackages

Description

```
[ ] bug report => search github for a similar issue or PR before submitting
[x] feature request
[ ] support request => Please do not submit support request here, instead see [URL]
```

**Current behavior**
No name in `@angular/platform-browser/animations` package.json

**Expected behavior**
name equals `@angular/platform-browser/animations`

**What is the motivation / use case for changing the behavior?**
Possibility to bundle typings using `typings` 


* **Angular version:** 4.0.0-rc.1

* **Language:** TypeScript 2.2.1

* **Node (for AoT issues):** `node --version` =   7.6.0
Discussion
- we don't know how to expose these secondary entry points in the main package.json. there is no standard or precedence for this as far as I know.

We do want to bundle the d.ts files though. `tsc` currently doesn't support this option. Are you saying that `typings` can do that? Does it produce d.ts files with ES modules (exports) or with ambient modules?
- @IgorMinar `typings` can bundle multiple d.ts files into one, so it can be shared for typechecking without need to install base module
For example result of bundle of `@angular/animations` module `typings bundle -out animations.d.ts`
