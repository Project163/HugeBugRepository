Title

Native runtime error due to HibernateBasicProxy

Description
## Describe the bug
Hello,
When using a small hierarchy of JPA entities (abstract parent and concrete child plus discriminator), Hibernate generates a proxy entity that does not seem to be kept by the quarkus-hibernate-orm extension during native compilation.

### Expected behavior
The entity should be loaded from database when in native mode. This is the observed behavior with the uber-jar packaging.

### Actual behavior
When trying to retrieve an entity, the following error occurs:
```
Caused by: java.lang.InstantiationException: Type `org.example.quarkus.AbstractEntity$HibernateBasicProxy$SwF3dMZa` can not be instantiated reflectively as it does not have a no-parameter constructor or the no-parameter constructor has not been added explicitly to the native image.
at java.lang.Class.newInstance(DynamicHub.java:912)
at org.hibernate.bytecode.internal.bytebuddy.BasicProxyFactoryImpl.getProxy(BasicProxyFactoryImpl.java:57)
```

## To Reproduce
Please find attached a reproducer:
[Link: quarkus-hibernateproxy-reproducer.zip]

Steps to reproduce the behavior:
1. Build the native executable
```
mvn clean package -Pnative
```
2. Start the external standalone H2 database
```
java -cp ./h2/h2-1.4.199.jar org.h2.tools.Server -ifNotExists &
```
3. Start the quarkus native executable 
```
./target/quarkus-hibernateproxy-reproducer-0.0.1-SNAPSHOT-runner
```
4. Access the GET /entities endpoint
```
curl localhost:8080/entities
```

This is the application.properties of the above reproducer. Real world usage is Oracle database (btw, many thanks for this new feature).
