Title

refresh of expired columns does not trigger autoflush

Description
Here's roughly what I have.

A column property:
```python
Parent.has_child = column_property(
    exists().where(Child.parent_id == Parent.id)
)
```

Some code which creates a child:
```python
session.add(Child(parent_id=parent.id, ...))
# session.flush()
session.expire(parent, ['has_child'])
```

Some code which checks whether the parent has a child:
```python
if parent.has_child:
    ...
```

These latter two snippets run one after the other in the same session. The session is using standard settings with auto-flush on and auto-commit off.

The problem is that the last snippet observes `parent.has_child == False`, unless the `session.flush()` line from the snippet before is uncommented. I would expect that accessing `has_child` after it has been expired would cause a query to be issued to the database, and this query would cause the session to be flushed so that the child would be visible to the query. However, this does not happen, and somehow the column property still sees no child.

Even more strangely, this only seems to happen if `parent.has_child` was *not* accessed before the child was added.
Discussion
- the query doesn't autoflush when it is re-populating the immediate column attributes of an object, as this operation typically means whatever values might be present on those attributes is to be overwritten, rather than persisted (this is the populate_existing() case which is not quite the same as the "expired" case but same codepath).
