Title

script.painless.regex.enabled: true still applies regex.limit-factor

Description
### Elasticsearch Version

7.10.0+

### Installed Plugins

_No response_

### Java Version

Not relevant

### OS Version

Not relevant

### Problem Description

`script.painless.regex.enabled`: `true` should ignore the `limit-factor` but it is being applied.

Tracing the code, the static constants are being set correctly, in `Compiler.compile`.  `CompilerSettings.asMap()` is also returning `0` for the `regex_limit_factor` if `enabled` is `true`.


### Steps to Reproduce
```
PUT test/_doc/1
{
  "abc": "abcdef.abcdef.abcdef.1122.xxddee.%%%%.___"
}

... [Log Snipped] ...
  }
}
```
```
"error": {
        "root_cause": [
            {
                "type": "circuit_breaking_exception",
                "reason": "[scripting] Regular expression considered too many characters, pattern: [.*abc.*def.*hij.*], limit factor: [85], char limit: [3485], count: [3486], wrapped: [abcdef.abcdef.abcdef.1122.xxddee.%%%%.___], this limit can be changed by changed by the [script.painless.regex.limit-factor] setting",
... [Log Snipped] ...
            }
        ],
```
