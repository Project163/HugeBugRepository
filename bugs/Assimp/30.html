Title

Memory leak in gltf2 importer

Description
There seems to be a memory leak when importing some gltf2 objects:

```
=================================================================
==2509==ERROR: LeakSanitizer: detected memory leaks

Direct leak of 7136 byte(s) in 1 object(s) allocated from:
    #0   in operator new[Link] (/nt/_out/dbg/bin/ModelExtractor_binary+ )
... [Log Snipped] ...

SUMMARY: AddressSanitizer: 7136 byte(s) leaked in 1 allocation(s).
```

Here is the relevant C++ code for the importer:

```cpp
Assimp::Importer importer;
importer.SetPropertyInteger(AI_CONFIG_PP_RVC_FLAGS, aiComponent_LIGHTS | aiComponent_CAMERAS);
const aiScene *scene = importer.ReadFile(filePath, aiProcess_RemoveComponent | aiProcess_GenSmoothNormals | aiProcess_ImproveCacheLocality | aiProcess_LimitBoneWeights | aiProcess_RemoveRedundantMaterials | aiProcess_GenUVCoords | aiProcess_FindDegenerates | aiProcess_FindInvalidData | aiProcess_Triangulate | aiProcess_OptimizeMeshes | aiProcess_JoinIdenticalVertices);
```

Other details:

- OS: Xubuntu 19.04
- Compiler: Clang 8.0.0
- Branch: Master (built from source on approx. 15 Sep - can't remember exactly)
- The GLB file was exported from Blender 2.80.

I've attached the GLB file that generates the leak.

[Link: 3.glb.tar.gz]
Discussion
- Saw the same behaviour on glTF2-Exporter. When the central database for glFT2-object called asset will be created all the entities like Cameras, buffers and meshes are stored in a lazydict as a reference.
The name of the mesh will be used as the key for the storage in this dict ( an unordered map is in use for that ). And this key seems to be the reason for the leakage. 

I investigated this yesterday but I was not able to get an idea why there is a leak.
- I think the problem is with these lines (https://github.com/assimp/assimp/blob/master/code/glTF2/glTF2Importer.cpp#L447):

```cpp
aim->mColors[c] = new aiColor4D[attr.color[c]->count];
attr.color[c]->ExtractData(aim->mColors[c]);
```

From what I can see, the `ExtractData` method already creates a new array and copies the colors into it. This overwrites the new array created on the previous line, which is thus never deleted in the `aiMesh` destructor. I therefore think the first of these two lines can be removed - it doesn't seem to be necessary.
- This seems to be right for the importer, thanks for he hint. In the exporter a string leaks.
