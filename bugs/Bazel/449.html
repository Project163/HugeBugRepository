Title

Built-in `pkg_tar` produces a warning for internal code

Description
According to the documentation the [Link: pkg_tar] rule expects a list for the `files` parameter. So, the following would be a correct usage (to generate an empty archive).

```
load("@bazel_tools//tools/build_defs/pkg:pkg.bzl", "pkg_tar")

pkg_tar(name="foo", files=[])
```
And while `bazel build :foo` correctly generates the archive, it also complains with the following warning.

```
WARNING: /usr/home/aehlig/.cache/bazel/_bazel_aehlig/ /external/bazel_tools/tools/build_defs/pkg/pkg.bzl:196:9: pkg_tar: renaming non-dict `files` attribute to `srcs`
```

I'm not sure if the documentation of the `files` parameter is incorrect or the built-in skylark code, but it definitely is a confusing user experience.
