Title

Dictionary changed size during iteration during lambda generation

Description
### Describe the bug

Thank you for reading this, and thank you for sqlalchemy.

While tracking this issue [URL] we received an exception in the lambda generation code

This appears to be a thread safety issue as the logs the user provided (attached) show multiple threads around the same area of the code 

One of the side effects is that it appears the bindparams get confused with other queries that happen to be running at the same time

### To Reproduce

Reproduction is currently not possible on demand. As [URL] progresses we may end up with a small reproducer

- well the error is clear, and part of what lambda stmt does is that it does hold a single copy of a "statement" around.  There are then some "memoized" attributes on objects like Select that are evaluated just once, such as during string compilation, so those together make this condition plausible.

We would observe, if you can confirm, that the error occurs only once and very early in the application's runtime; once the Select object has all of its memoized elements initialized, there should be no further modifications to dict.

Also, as we see in my POC below, at least on my end this error does not seem to occur in Python 3.10, but does occur in Python 3.8 and 3.9.  So this would suggest an upgrade to Python 3.10 would resolve immediately.

Proposal is to apply list() to this particular clone method, which as an implementation detail would appear to cause the iteration to proceed atomically even though the items() method that returns an iterable ItemsView is still returned.
