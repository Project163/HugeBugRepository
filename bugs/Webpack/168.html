Title

`exports.nodeType`: Self-reference dependency has unused export name

Description
# Bug report

Importing a library built by webpack 4 (amd) into webpack 5 project results in

```
Self-reference dependency has unused export name
```

Adding log to the error shows that it is caused by

```
CommonJsSelfReferenceDependency {
  weak: false,
  optional: false,
  loc: SourceLocation {
    start: Position { line: 6, column: 4686 },
... [Log Snipped] ...
  call: false
}
```
 
 
 
 

**What is the current behavior?**

Build fails with error.

**If the current behavior is a bug, please provide the steps to reproduce.**

Seeing how `export.nodeType` seems to be rather common approach I hope that reproduction code is not needed. I can provide the code we have privately.

So far it looks like it is one of the buffer related files from lodash that is bundled and minified by webpack 4. Then it is imported into webpack 5 project (the same code builds fine with webpack 4).

The build only fails in production mode, development mode works fine.

 
 
 
 
 
 

**What is the expected behavior?**

No error as `exports.nodeType` is used to check for exports variable, it is not intended to be defined by the module.

 
 

**Other relevant information:**
webpack version:  5.1.0
Node.js version: 12.13.1
Operating System: Win10
