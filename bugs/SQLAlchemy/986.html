Discussion
- Hi SQLAlchemy team,

I have looked into the above issue and have the below question

_Using the following [Link: link] as reference:_ Is it reasonable and clearer to change the error message to "'Myclass' instance is not a mapped object in the database"? Since it would have to be an instance of a object or a descriptor for the database in the first place.

**My understanding of the issue from debugging the code**
After debugging the code i found that the error is raised by the following [Link: line] specifically where instance_state(instance). 

instance_state() uses the operator.attrgetter method to see if the object in question has the attribute "_sa_instance_state". If the object doesn't have the attribute an the error is raised. In this particular issue it was raised for the reasons @zzzeek stated.

Ramon
- hey there -

there's an existing exception that does the messaging automatically.   In a case like this we simply need to raise sqlalchemy.orm.exc.UnmappedInstanceError(instance), taking into account we want to use util.raise_() so that the "cause" can be linked, and the messaging is already there.
- **RamonWill** has proposed a fix for this issue in the **master** branch:

**Raise UnmappedInstanceError if the attribute of a database object is an unmapped object.** [URL]
