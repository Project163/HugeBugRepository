Title

Snap and parallel builds

Description
First up - GoReleaser is awesome and thanks for all the hard work thats gone into it. Happy to fix this one up as a PR if you agree with the change.

**Describe the bug**

When using Snap builds I see the following error intermittently. 

```
FileExistsError: [Errno 17] File exists: '/root/.cache/snapcraft/download'
```

Tracking down the code in snap it's a call in python which checks if a folder exists then, if it doesn't exist, attempts to create it. 

"/snap/snapcraft/current/lib/python3.6/site-packages/xdg/BaseDirectory.py", line 81

[Image: image]

In my example I'm building for an number of different architectures inside a docker container. I *think* the following code in GoReleaser

[URL]

is kicking off multiple instances of snapcraft, in my case 2, and this is causing a concurrency bug in the snapcraft python where two instances enter the check, both see the folder doesn't exist, then the first instance creates it and the second instance fails attempting to create it as it's already been done. Unlucky right? 😢

So I wasn't sure if this could be the case and I wanted proof - the way I proved it was to remove one of the `goarch` so I build just `arm64` instead of `386 & arm64` and problem was gone and fixed consistently 🎉

I think to resolve the issue the builds for snapcraft should be called serially rather than in parallel. If you can point me how to do this happy to submit a PR.

**To Reproduce**

Machine spec is going to influence things here, locally on i9 with lots of ram it happens every time. In GitHub actions CI I get anywhere between 1/2~1/10. 

Pull down this repo here [URL] with branch `lg/reenablesnap` you can see an example of the failure here [URL]

Run `IS_CI=true BUILD_NUMBER=1 make devcontainer-release` (this requires docker and nothing else). Run a few times and see the issue occur. 

**Expected behavior**

Snaps to be built.

- Thanks for the bug report, will take a closer look soon.

For now, as a workaround, you can run goreleaser with `--parallelism=1` (which will affect everything, not just snap).
- Thanks, I found another workaround which might help others too. If you pre-create the folders needed then there is no race condition in `snapcraft` as it doesn't handle the creation. 

Before calling `gorelaser` run 

```
mkdir -p $HOME/.cache/snapcraft/download
mkdir -p $HOME/.cache/snapcraft/stage-packages
```
Works my end and I get to keep parallel builds.
