Title

$USER expansion to invalid path for tempname()

Description
### Neovim version (nvim -v)

v0.8.0-dev+555-gd07a39c54

### Vim (not Nvim) behaves the same?

No

### Operating system/version

Fedora 35

### Terminal name/version

Kitty

### $TERM environment variable

xterm-256color

### Installation

appimage

### How to reproduce the issue

_Prelim_

- I understand that this example is explicitly using `--badname`, but the user on my Linux system is handled by a Windows domain controller for work and there is nothing I can do about it being a "bad name".
- I understand that it is _far_ easier to work with when _not_ using a plugin like `fugitive`, however there are enough things going on that I was not able to easily reproduce this myself without following the path that led me to the issue in the first place.

---

_Repro_

Setup first:
```
sh
sudo useradd --badname -m foo\\bar
sudo su - foo\\bar
mkdir tmp-project && cd tmp-project
git init
... [Log Snipped] ...
end
' > /tmp/init.lua
```

Once setup completed (same `$PWD` as above):
```sh
nvim --noplugin -u /tmp/init.lua
```

Then when inside `nvim`:
```
:G
```

to pull up the staging area. Hit `cc` to commit the previously staged changes.

### Expected behavior

The usual `fugitive.vim` "edit commit message" buffer pops up such that I can edit a commit message, then `:wq` the buffer and so on.

### Actual behavior

```
sh: /tmp/nvim.foobar/3Q33mx/1.sh: No such file or directory                                                                                                                                                                         
error: There was a problem with the editor 'sh /tmp/nvim.foo\bar/3Q33mx/1.sh'.
Please supply the message using either -m or -F option.
```
