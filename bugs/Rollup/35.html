Title

Function calls with side effects are removed (when they shouldn't be)

Description
Here is a reduced test case:

[URL]

As you can see, it completely removes the calls to `set`

In my real application, I am using an object to store configuration, and then I am using function calls to populate the object.

const foo = {};

It's curious that the resulting core preserves the _definition_ of `set` as it's never used in the output. Removing the `console.log` also results in the definition of `set` being removed.

Replacing the `set` arrow-function _expression_ with a function _declaration_ like so, `set` is [Link: completely removed from the output].

```
js
const foo = {};

function set( key, value ) {
  foo[key] = value;
... [Log Snipped] ...

console.log(foo);
```

I suspect that Rollup preserves the definition of the arrow function above, as it believes that the _definition itself_ somehow _modifies_ `foo`; while the calls to `set` don't. I've no idea why every reference to `set` is removed in the second example.
