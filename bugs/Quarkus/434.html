Title

Native build fails with "quarkus-logging-gelf" extension (Unsupported method sun.nio.ch.DatagramDispatcher.read0)

Description
**Describe the bug**
Adding the extension "quarkus-logging-gelf" makes the native build fail with " Unsupported method sun.nio.ch.DatagramDispatcher.read0(FileDescriptor, long, int) is reachable: Native method."

**Expected behavior**
Native build should be successful using "quarkus-logging-gelf" extension.

**Actual behavior**
Native build fails if "quarkus-logging-gelf" extension is added to pom.xml.


**To Reproduce**
Steps to reproduce the behavior:
1. Goto [URL]
2. Select "Core / Logging GELF" in addition to default extensions
3. Download and extract archive to disk
4. Execute `./mvnw clean package -Pnative`
5. Fails with "Unsupported method sun.nio.ch.DatagramDispatcher.read0(FileDescriptor, long, int) is reachable: Native method"

**Environment (please complete the following information):**
 - Output of `uname -a` or `ver`: Linux xxxx 4.15.0-74-generic #84-Ubuntu SMP Thu Dec 19 08:06:28 UTC 2019 x86_64 x86_64 x86_64 GNU/Linux
 - Output of `java -version`: OpenJDK Runtime Environment (build 1.8.0_232-20191008104205.buildslave.jdk8u-src-tar--b07)
 - GraalVM version (if different from Java): penJDK 64-Bit GraalVM CE 19.2.1 (build 25.232-b07-jvmci-19.2-b03, mixed mode)
 - Quarkus version: 1.1.1.Final

Discussion
- Looks like enabling JNI fixes the issue, I'm on it.
- You can work around the issue by setting `quarkus.native.enable-jni` to true at the bottom of the generated pom.xml. It should look like:
```xml
       
         native 
         true 
       
```
