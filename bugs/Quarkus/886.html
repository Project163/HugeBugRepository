Title

Throwing AuthenticationFailedException from IdentityProvider.authenticate stalls connection.

Description
**Describe the bug**
The documentation of `IdentityProvider.authenticate` is a little bit unclear on how one should throw `AuthenticationFailedException` or return the same exception wrapped in an `Uni`. I got it wrong and noticed that throwing `AuthenticationFailedException` stalls the client connection without any warning in the logs. Other exceptions (e.g. `RuntimeException`) are properly logged as an error and immediately return a 500 error to the client. This took me a while to figure out...

**Expected behavior**
Throwing `AuthenticationFailedException` from `IdentityProvider.authenticate` should either do the same as returning it wrapped in an `Uni`, or be handled as an application error (just like any other exception) resulting in a 500 error response.

**Actual behavior**
Throwing `AuthenticationFailedException` from `IdentityProvider.authenticate` does not produce an error log entry, does not trigger a 500 error response, and instead stalls the client connection until it times out.

**To Reproduce**

Implement a custom `IdentityProvider` that throws `AuthenticationFailedException`, add one of the auth annotations to a jax-rs resource, then request that resource with credentials.

```
java
@ApplicationScoped
public class BasicIdentityProvider implements IdentityProvider  {
	@Override
	public Class  getRequestType() {
... [Log Snipped] ...

// curl [URL]  # This will block until timeout
```

**Configuration**
```properties
quarkus.http.auth.basic=true
```
**Environment (please complete the following information):**
 - Output of `java -version`: 14.0.2+12-Ubuntu-120.04
 - Quarkus version or git rev: 1.10.1.Final
