Title

[bug] Tauri window theme is not propagated to webview (`prefers-color-scheme`)

Description
### Describe the bug

No matter which [Link: theme] I set in the Tauri config file, the WebView always answers CSS media query `prefers-color-scheme` with OS color theme. According to the [Link: doc], it should only be the behavior is the `theme` field is `None`.

There is [Link: a similar issue] in Electron, and they managed to [Link: fix it] by "propagate preferred color scheme to the renderer".

### Reproduction

1. Set Windows color mode in Personalization to "Dark".
2. In tauri.conf.json, set `windows[0].theme` to "Light".
3. In Rust `main()`, call main window's `theme()` to make sure it is `tauri::Theme::Light`.
4. In CSS, have different style for of both `@media (prefers-color-scheme: light)` and `@media (prefers-color-scheme: dark)`.
5. Observe that the section in `@media (prefers-color-scheme: dark)` is used.

### Expected behavior

If `theme()` returns `Light`, styles in `@media (prefers-color-scheme: light)` should be used.

Discussion
- I did some research and found the root cause. Tauri uses wry to handle WebView stuff, and wry calls APIs exposed by [Link: webview2-com]. The original interface of the WebView core, [Link: `ICoreWebView2`], does not support profile or preferred color scheme. This functionality is later added to the 13th updated interface, [Link: `ICoreWebView2_13`]. And to use it, one just [Link: `cast`] the `ICoreWebView2` instance to `ICoreWebView2_13`, and update the profile.

I did a local test, by adding the following line to wry
```
diff --git a/src/webview/webview2/mod.rs b/src/webview/webview2/mod.rs
index da3fb62..e247795 100644
--- a/src/webview/webview2/mod.rs
+++ b/src/webview/webview2/mod.rs
@@ -203,6 +203,8 @@ impl InnerWebView {
... [Log Snipped] ...
     if !attributes.transparent {
       if let Some(background_color) = attributes.background_color {
```

and now my Tauri app will unconditionally use Light color scheme regardless of my Windows color settings.

It seems Tauri currently only sets [Link: `theme`] in tao, and never passes the theme config to wry.
