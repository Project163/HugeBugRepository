Title

Driver retries in cluster mode always fail if event logging is enabled

Description
yarn-cluster mode will retry to run the driver in certain failure modes. If even logging is enabled, this will most probably fail, because: 

  
 Exception in thread "Driver" java.io.IOException: Log directory hdfs://vanzin-krb-1.vpc.cloudera.com:8020/user/spark/applicationHistory/application_1417554558066_0003 already exists!
        at org.apache.spark.util.FileLogger.createLogDir(FileLogger.scala:129)
        at org.apache.spark.util.FileLogger.start(FileLogger.scala:115)
        at org.apache.spark.scheduler.EventLoggingListener.start(EventLoggingListener.scala:74)
        at org.apache.spark.SparkContext.<init>(SparkContext.scala:353)
 
  

 The even log path should be "more unique". Or perhaps retries of the same app should clean up the old logs first.
Discussion
- We have an configuration item "spark.eventLog.overwrite", is it enough to solve this issue?
- It doesn't sound right to force the user to enable another setting just to get basic functionality working. The way it is, the default settings make Yarn retries useless.
