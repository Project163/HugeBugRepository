Title

Batched rollover requests hoard heap space

Description
A master node OOMed because a large number of rollover requests (`586` to be precise) were batched into one cluster state update task. When we process all the batched rollover requests, we add a `RolloverResult` for every request to a [Link: list]. The issue is that every `RolloverResult` contains a field for the resulting cluster state, meaning we're holding on to all of those intermediate cluster state objects until the whole batch is finished. From the looks of it, we don't actually need the intermediate cluster states, so we should be able to refactor this to avoid keeping references to the intermediate ones and only return the final one.

This specific occurrence was seen on `v8.17.2`, but it probably goes back to when rollover became batched.
