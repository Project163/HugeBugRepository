Title

Description

 public   class  MinimalTest {

		 String  queryString =  "SELECT ?a WHERE { <%s> <http: //ex.com> <[URL] }" ;
 		Query q = QueryFactory.create(queryString);
		 String  serialized = q.serialize();
		 System .out.println(serialized);
	}
}

- Ho  michaelcochez  - thanks for the report. 

 There are two issues here - the illgeal relative  <%s>  isn't causing a WARN message ( <x:%s>  does). It should emit: 

  Bad IRI: <...%s> Code: 30/ILLEGAL_PERCENT_ENCODING in PATH: The host component a percent occurred without two following hexadecimal digits.  

 While strictly bad syntax,i.e. error, the SPARQL parser isn't strict on URIs because the real world has bad URIs in published data. It only emits WARN and continues. 

 In a URI  %  should followed by 2 hex digits. 

 Regardless,  PrefixMappingImpl.qnameFor  should be defensive and not return an out of bounds index.
