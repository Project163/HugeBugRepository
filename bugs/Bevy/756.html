## What you did

Using `bevy_trenchbroom` to load BSP files into Bevy. Specifically, the lightmaps are from `bevy_trenchbroom::bsp::lighting::types::AnimatedLighting`.

- [ ] _TODO_: Investigate exactly how the lightmaps end up in `bevy_pbr`.

## What went wrong

I get a panic in `bevy_pbr` seemingly at random, with the following message:

```ignore
thread 'Compute Task Pool (6)' (442851) panicked at /home/eira/Github/bevy/crates/bevy_pbr/src/lightmap/mod.rs:421:37:
attempt to shift left with overflow
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace
Encountered a panic in system `bevy_pbr::lightmap::extract_lightmaps`!
```

It does not seem to be related to which map I try to load, as the same map may sometimes cause the crash and sometimes not. I originally thought it was due to [URL] causing Bevy to load the same map multiple times (and therefore creating too many copies of the lightmap), but even after applying [URL] locally (which fixes the issue) the crash in the lightmap allocation appears to still happen. It also appears to occasionally happen when loading the first map, which could rule out the possibility of the old map not being fully deloaded before the next is loaded. 

The path shows a local checkout of Bevy due to applying #20449. Otherwise the branch is identical to the `release-0.17.2` branch, specifically commit  .
