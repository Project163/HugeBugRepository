Title

Moving analog stick very slowly does not trigger sf::Event::JoystickMoved

Description
When I move the analog stick very slowly, sf::Event::JoystickMoved event does not trigger. However it's fine if I move it fast.

I tried this with Dualshock 4 controller and Logitech F310 which has two modes, X (XInput) and D (Dualshock?), I tried both of them and it's same on those too.

I tried this with @binary1248 's new DirectInput patch (https://github.com/SFML/SFML/pull/1326) and without it. Same problem exists.

One player also tried the same and approves.

On the other hand, Windows Control Panel -> Set up USB Game controllers -> Properties does not have the same issue, maybe it's polling the current value instead of working with events.

I already implemented XInput for my game. If I use an XInput emulator for these gamepads, Game's XInput library works fine. 

I am incredibly busy these days so I can't provide a code snippet but it's just the most basic pollEvent loop.

Windows 10
Dualshock 4
Logitech F310
g++ (x86_64-posix-seh-rev1, Built by MinGW-W64 project) 7.2.0
Discussion
- This is most likely not directly a bug, but the joystick threshold instead. Check out [Link: `sf::Window::setJoystickThreshold()`].

It will basically remove tiny movement, but should most likely work in a different way (i.e. only allowing the axes to center properly).
