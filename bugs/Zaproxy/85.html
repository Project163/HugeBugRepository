Title

Active scanner request count mismatch

Description
From OWASP ZAP User Group: [URL]

---

Steps to reproduce the issue:
1. Run ZAP with "Active scanner rules (beta)" add-on (v19) installed (easier to reproduce the issue);
2. Change the "Default Policy" to disable all scanners except "Heartbleed OpenSSL Vulnerability", "Source Code Disclosure - /WEB-INF folder" and "Cross-Domain Misconfiguration";
3. Start the active scan against a target;
4. Once finished see the number of requests sent by each scanner (using the GUI, "Scan Progress" dialogue, or the ZAP API, [URL] and note that the count does not correspond to the messages sent by each scanner. For example, in the attached screen capture, the scanners "Source Code Disclosure - /WEB-INF folder" and "Cross-Domain Misconfiguration" have 0 messages while "Heartbleed OpenSSL Vulnerability" has 9, but from the messages sent:

```
[URL]
[URL]
[URL]
[URL]
[URL]
... [Log Snipped] ...
[URL]
[URL]
```

the scanner "Source Code Disclosure - /WEB-INF folder" sent 7 and "Cross-Domain Misconfiguration" sent 2.

Remarks;
Messages sent during the analysis step, before any active scanner has been run, will be counted as sent by the first scanner run.

ZAP Versions:
Version >= 2.4.3.
