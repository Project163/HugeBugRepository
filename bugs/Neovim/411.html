Title

Highlight groups not properly cleared ("Too many highlight and syntax groups")

Description
### Neovim version (nvim -v)

NA commit 73b35ef10f955 (git describe: v0.5.0-1213-g73b35ef10)

### Vim (not Nvim) behaves the same?

no, vim 8.2.3582

### Operating system/version

Arch Linux

### Terminal name/version

kitty 0.23.1

### $TERM environment variable

tmux-256color

### Installation

Arch User Repository (neovim-git)

### How to reproduce the issue

The error is pretty generic, see the below explanation. It can be easily reproduced using the following `.vimrc` if one provokes many changes that update highlighting groups.

```
vimrc
" This line should not be removed as it ensures that various options are
" properly set to work with the Vim-related packages.
runtime! archlinux.vim
" Move around code blocks in e.g. Julia
... [Log Snipped] ...
Plug 'mhinz/vim-signify'  " VCS sign indicators
call plug#end()
```

### Expected behavior

No errors regardless of how long I keep my vim session open.

### Actual behavior

After a while errors similar to this one `E849: Too many highlight and syntax groups` pop up and all new highlighting in vim stops working. This can be further confirmed by looking at the highlighting groups (`:hi`) which contain thousands of the following lines:
```
           xxx cleared
           xxx cleared
           xxx cleared
           xxx cleared
           xxx cleared
```

The problem seems to be that syntax groups (here induced by vim-signify but any plugin that frequently updates highlighting groups breaks nvim) are not properly cleared and nvim eventually runs into the limit specified at [Link: nvim/syntax.c]. This does not happend with nvim-v0.4.3 thus I assume it is a bug in nvim rather than the various plugins that update highlighting groups.
