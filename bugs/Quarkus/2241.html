Title

Upgrading to 3.13.x+ causes parameterised tests using record argument to fail with LinkageError 'loader constraint violation'

Description
### Describe the bug

JUnit5 parameterised tests having a Java record as argument type for the test method fail when upgrading to Quarkus 3.13.0 or higher.
The issue is caused by some class loading issue when the Java record has a property of a type not provided by Java like a Vavr `Option`. Just using String or Integer property type does not cause the test to fail.

I think this is somehow related to the change made for issue #15892 .

What is the point of cloning a Java record anyway? The object is already immutable.
Can the `NewSerializingDeepClone` introduced to fix #15892 (I think) just **not** clone Java records?
