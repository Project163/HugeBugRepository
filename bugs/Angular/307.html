Title

Code generated for '?.' does work with strict null checking.

Description
**I'm submitting a ...**  (check one with "x")
```
[x] bug report => search github for a similar issue or PR before submitting
[ ] feature request
[ ] support request => Please do not submit support request here, instead see [URL]
```

**Current behavior**
 

The code generated to conditional property defeats TypeScript type narrowing and generates an error 'Object could be null'.

**Expected behavior**
 

The code generated should correctly narrow the type.

**Minimal reproduction of the problem with instructions**
 

In a new project (`ng init`) change `app.component.ts` to:

```
ts
import { Component } from '@angular/core';

export interface Issue {
  getInfo(): string;
... [Log Snipped] ...
  element: MyElement;
}
```

and `app.compoennt.html` to:

```html
 
  {{element.issue?.getInfo() || ''}}
 
```

invoke `ngc` in the app directory and you will see the error.

**What is the motivation / use case for changing the behavior?**
 

Correct typing of `?.` usage.
