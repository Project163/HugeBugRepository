Title

SIGSEGV on exit on cygwin

Description
### I did this

It's hard to get a MWE. I'll discribe what I've done:
* I'm the maintainer of cygwin target of rust, and recently I've managed to compile `cargo` targeting MSYS2 (a variant of cygwin), linking libcurl 8.13.0 and openssl 3.5.0 (dynamically).
* `cargo` fail silently with SIGSEGV on an anoymous thread exits. Backtrace:
```
#0    in ?? ()
#1    in pthread_testcancel () at /d/S/B/src/msys2-runtime/winsup/cygwin/thread.cc:399
#2  pthread_rwlock_wrlock (rwlock= ) at /d/S/B/src/msys2-runtime/winsup/cygwin/thread.cc:4352
#3    in _sigfe () at sigfe.s:35
#4    in CRYPTO_THREAD_write_lock () from /usr/bin/msys-crypto-3.dll
... [Log Snipped] ...
#14   in pthread_wrapper (arg= ) at /d/S/B/src/msys2-runtime/winsup/cygwin/create_posix_thread.cc:79
#15 pthread_wrapper (arg= ) at /d/S/B/src/msys2-runtime/winsup/cygwin/create_posix_thread.cc:39
```
* It turns out that a thread exits and libcurl is detached. It calls OPENSSL_thread_stop and crashes.
* So I looked into the source code and the comment says that it is for statically linked openssl, so I removed this call and compiled again. Now `cargo` works fine.

### I expected the following

Well, as it's very hard to construct a MWE, I'm asking experts for help. Could someone explain that whether it is necessary to call `OPENSSL_thread_stop` if openssl is dynamically linked?

Or, could someone help me to get the clue that, why libcurl is detached when `cargo` is running?

### curl/libcurl version

curl 8.13.0

### operating system

MSYS2

The function is effectively idempotent and it's supposed to be safe to call it multiple times. If OpenSSL is its own DLL (like in this case) then it calls the function beforehand and if it's a static library then it doesn't. The function should be called at least once per thread to prevent a memory leak. We make a call regardless and I think that was because we don't know if OpenSSL is part of the current module (like whether OpenSSL is its own DLL or part of some other DLL like libcurl or a DLL that contains static libcurl and static openssl).
- So, I assume that it's OK to not call this method in my case?
