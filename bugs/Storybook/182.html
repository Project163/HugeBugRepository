Title

Screen reader announces incorrect state as selected on non-selected tab controls in windows.

Description

**Test Environment:**
OS: Windows 11

Discussion
- This is a known accessibility issue in Storybook 8.x: the core tab components (like those used for Controls, Actions, Interactions, etc.) do not set the required `aria-selected` attribute on tab elements. As a result, screen readers—especially Narrator on Windows/Edge—may announce all tabs as "selected" or fail to announce the correct state, matching what you’re seeing. This gap is confirmed in multiple issues and is tracked for future improvement, but is not yet fixed in 8.x ([Link: issue #32235], [Link: issue #23640], [Link: issue #26674]).

As a workaround, you can patch your local Storybook tab components to add `aria-selected={active}` to each tab button, following [Link: WAI-ARIA Authoring Practices]. For example, in your tab rendering code:

```jsx
 
```

This will ensure screen readers announce the correct selected state. Storybook is actively working on accessibility improvements for future releases (9.x+), so keep an eye on updates if you want a built-in fix.

If you’re using custom tab components in your stories, make sure they also follow this pattern. If the issue only appears in your own components and not in the default Storybook UI, please provide a minimal reproduction so we can help further.
