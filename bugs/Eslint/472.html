Title

root: true not behaving correctly for config

Description
Version: `master`
Parser: `Default`

Command to run: `npm test` on master

Scenario: I have `eslint` folder and also have an `.eslintrc` file alongside it. when I run the `npm test` command on `eslint` folder it also grabs the `.eslintrc` file from outside eslint folder. Important to note that our `.eslintrc` file has `root:true` so that means it should not grab the file from outside.

Output:

```
sh
$ DEBUG=eslint:* npm test

... [Log Snipped] ...
    at Config.getConfig (c:\Users\gs025879\Documents\webstrom\eslint\lib\config.js:364:22)
Validating JSON Files
```
Discussion
- Looks like a bug, we should add some debug logging so it's easier to tell when `root: true` was found and when it was not.
- I think why its happening is before we can say that we are going to ignore a particular config file, we have to load the config. In my case during the load of that it blows up because I dont have `eslint-config-ideal` installed.
I think the way to fix this is as soon as you find a config file with `root:true`, then we should exit the loop. As of now we keep reading and loading configs. Since the theme of this functionality is that we will stop looking for configs as soon we see `root:true`.
With that being said, do we still need the check for `pathIsInside`?

Would this change makes sense @nzakas and @IanVS . If yes, then I will implement this change as I already have the fix figured out.
