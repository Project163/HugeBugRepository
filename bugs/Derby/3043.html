Title

Discussion
- The attached patch   d6703-1a.diff      makes the following changes: 

  MergeNode.addColumn() : 
 
	 Use a different bind method for binding the ColumnReference. That method will raise an exception instead of silently returning null if the column is not in the from list. 
	 Remove the handling of tableName being null (which is where the NPE happened). No longer needed since a no such column error will already have been raised in the cases where tableName previously could be null. 
 

  MergeStatementTest : 
 
	 Add test case. There already was a test for invalid columns in the ON clause, but it didn't expose the problem because it used a qualified name. The new test case uses an unqualified name. 
 

  FromList.bindColumnReference() : 
 
	 Mention the possibility of returning null in the javadoc. 
 

  ColumnReference.bindExpression() : 
 
	 Make return type more specific (ValueNode -> ColumnReference) to prevent the need for a cast in MergeNode.addColumn(). 
 

 All regression tests ran cleanly with the patch.
