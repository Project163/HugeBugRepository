Title

[YSQL] Check failed: 'g_palloc_fn' Must be non NULL

Description
Jira Link: [Link: DB-2430]
When an error that returns a YB Status occurs in the (metrics) webserver process, we use `HandleYBStatus` to report it.
But `HandleYBStatus` will use `YBCPalloc` internally when copying over the error string.
But we do not call `YBCInit` for the webserver (only for the connection backends) so `g_palloc_fn` (the implementation of `YBCPalloc`) is not set.
As a result, instead of reporting the correct error, the server will fatal due to the `CHECK` above.

We should be able to replicate this by introducing a bad status in any function wrapped with `HandleYBStatus` in `yb_pg_metrics.c`.
To fix, we can probably make sure we initialize g_palloc_fn in the webserver too, otherwise we can handle the statuses (i.e. error reporting) differently there.
