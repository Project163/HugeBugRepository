Title

Labeled a SideEffectCapStep cause problems.

Description
gremlin> g.V().hasLabel( "person" ).aggregate( "x" ).by( "age" ).cap( "x" ).as( "y" , "z" ).select( "x" , "y" , "z" )
==>[x:[29, 27, 32, 35], y:[[29, 27, 32, 35], [29, 27, 32, 35]], z:[[29, 27, 32, 35], [29, 27, 32, 35]]]  // BAD
 gremlin> g.V().hasLabel( "person" ).aggregate( "x" ).by( "age" ).cap( "x" ).filter{ true }.as( "y" , "z" ).select( "x" , "y" , "z" )
==>[x:[29, 27, 32, 35], y:[29, 27, 32, 35], z:[29, 27, 32, 35]]  // GOOD 
 
  

 This only seems to be an issue with  AggregateStep  

  
 gremlin> g.V().hasLabel( "person" ).groupCount( "a" ).cap( "a" ).as( "b" , "c" ).select( "a" , "b" , "c" )
==>[a:[v[1]:1, v[2]:1, v[4]:1, v[6]:1], b:[v[1]:1, v[2]:1, v[4]:1, v[6]:1], c:[v[1]:1, v[2]:1, v[4]:1, v[6]:1]]
gremlin> g.V().hasLabel( "person" ).aggregate( "a" ).cap( "a" ).as( "b" , "c" ).select( "a" , "b" , "c" )
==>[a:[v[1], v[2], v[4], v[6]], b:[[v[1], v[2], v[4], v[6]], [v[1], v[2], v[4], v[6]]], c:[[v[1], v[2], v[4], v[6]], [v[1], v[2], v[4], v[6]]]]

- Okay, it has to do with  select(Pop) , where  select(...)  is  select(Pop.all,...)  

  
 gremlin> g.V().hasLabel( "person" ).aggregate( "x" ).by( "age" ).cap( 'x' ).as( "y" ).select(first, "y" )
==>{29=1, 27=1, 32=1, 35=1}
gremlin> g.V().hasLabel( "person" ).aggregate( "x" ).by( "age" ).cap( 'x' ).as( "y" ).select(last, "y" )
==>{29=1, 27=1, 32=1, 35=1}
gremlin> g.V().hasLabel( "person" ).aggregate( "x" ).by( "age" ).cap( 'x' ).as( "y" ).select(all, "y" )
==>[[29, 27, 32, 35], [29, 27, 32, 35]]
gremlin>
- The problem was in  BulkSet.equals()  which caused the labeled path to duplicate itself as equality wasn't properly defined. Added test cases to  BulkSetTest  and added the exposing traversal to  AggregateTest . This is why  group() ,  groupCount() , etc. were not effected by this problem as they don't use  BulkSet  like   aggregate()  and  store()  do.
