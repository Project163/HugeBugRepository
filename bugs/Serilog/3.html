Title

JsonFormatter issues

Description
When using the _JsonFormatter_ on _RollingFileSink_ the first message is not written and it creates an invalid json, each _LogEvent_ is not separated by a comma.

```
C#
long DefaultFileSizeLimitBytes = 1L * 1024 * 1024 * 1024;
int DefaultRetainedFileCountLimit = 31;

var jsonSink = new RollingFileSink(@"log-{Date}.json", new JsonFormatter(), DefaultFileSizeLimitBytes, DefaultRetainedFileCountLimit);
... [Log Snipped] ...

Console.ReadKey();
```

Generates the following json

``` Javascript
{"Timestamp":"2014-04-07T09:10:26.3089245+02:00","Level":"Information","MessageTemplate":"2nd message"}{"Timestamp":"2014-04-07T09:10:26.3119247+02:00","Level":"Information","MessageTemplate":"3rd message"}
```
Discussion
- Wow - great catch! Thanks for getting in touch.

The problem is with the `RollingFileSink` itself - the first message won't be written regardless of formatter etc.

We'll get a patched build out ASAP.

- Alright - investigated this further, the issue only appears when the rolling log file name doesn't include a path; e.g. `foo-{Date}.txt` exhibits the bug, while `c:\logs\foo-{Date}.txt` does not.

The fix is on its way through CI and should be out as package version 1.2.40.
