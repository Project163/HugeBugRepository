Title

`diesel migrations redo` doesn't respect `run_in_transaction` migration metadata

Description
## Setup

### Versions

- **Rust:** rustc 1.67.0 
- **Diesel:** 2.0.3
- **Database:** sqlite 3.40.1
- **Operating System** Arch Linux

### Feature Flags

- **diesel:** "sqlite", "time"
- **diesel_cli:** "sqlite"

## Problem Description

The `diesel migrations redo` command doesn't respect the `run_in_transaction` migration metadata, while `run` and `revert` separately do.

This seems to be because it is [Link: hard-coded] to use a transaction for anything except mysql, specifically for the redo command.

### What are you trying to accomplish?

A migration that needs to handle transactions itself

Specifically temporarily turn off an [Link: sqlite specific pragma] as dictated [Link: here], which cannot be done inside a transaction.

### What is the expected output?

```
Rolling back migration  
Running migration  
```

### What is the actual output?

```
Rolling back migration  
Failed to run   with: cannot start a transaction within a transaction
```

### Are you seeing any additional errors?


### Steps to reproduce

 

- `diesel migration generate example`
- Add the following

```toml
# example/metadata.toml
run_in_transaction = false
```

```sql
-- example/up.sql
BEGIN TRANSACTION;
COMMIT TRANSACTION;
```

```sql
-- example/down.sql
BEGIN TRANSACTION;
COMMIT TRANSACTION;
```

- Run `diesel migration run` and see it works as expected
- Run `diesel migration revert` and see it works as expected
- Run `diesel migration redo` and see it fail
