Title

Crash in `nvim_open_win` when autocmd deletes a buffer on `Buf*` events

Description
### Neovim version (nvim -v)

v0.6.0-dev+207-g684550ff3

### Vim (not Nvim) behaves the same?

N/A maybe, unless it can be done without the API

### Operating system/version

Ubuntu 20.04 & Fedora 34

### Terminal name/version

tmux 3.0a & tmux 3.1c

### $TERM environment variable

tmux-256color

### Installation

Source

### How to reproduce the issue

Run the following Lua:

```
lua
vim.cmd "autocmd BufLeave * ++once bwipeout!"  -- :quit also works
local buf = vim.api.nvim_create_buf(true, true)
vim.api.nvim_open_win(buf, true, {
  relative = 'win',
... [Log Snipped] ...
  noautocmd = false,
})
```

The important parts are `nvim_open_win` with `noautocmd = false`, and an `:autocmd` deleting curbuf on events usually suppressed by `noautocmd = true`.

Note that at the point the autocmd runs, curbuf is not the buffer passed to `nvim_open_win` (it's still the previous buffer).
When we delete curbuf, our new float is closed immediately, even though that wasn't the buffer we passed to `nvim_open_win`.

I _think_ this behaviour is consistent with how Vim generally handles opening new buffers in new windows: create the new window (still viewing the same buffer), then change the viewed buffer of the new window. (`:new`, `:split`, etc. does this)

So I guess checking `win_valid` again after `win_set_buf` is maybe the way to fix this:

```
diff
diff --git a/src/nvim/api/vim.c b/src/nvim/api/vim.c
index 2536249de..b2eed6949 100644
--- a/src/nvim/api/vim.c
+++ b/src/nvim/api/vim.c
... [Log Snipped] ...
   if (fconfig.style == kWinStyleMinimal) {
     win_set_minimal_style(wp);
```

Fixes the crash and gives the emsg as expected.

### Expected behavior

No crash. Give the "Window was closed immediately" emsg instead.

### Actual behavior

Crash.
