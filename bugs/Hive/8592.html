having merge join shouldn't have branch with more than one GBY operator. 
A possible solution is to disable SMB join conversion in such cases: 
 [URL]
- A possible solution is to disable SMB join conversion in such cases:  
 This seems a reasonable option.  So both sides of the join will need to be examined for the presence of 2 or more GROUP-BY operators.  The traversal would check until it hits a TableScan operator.  If such a pattern is encountered, we would not generate the SMB join. It wasn't clear what role does the Partitioned Table Function (PTF) have to play in this.  If the sufficient condition for the problem is the presence of 2 GROUP-BYs on either side of a join, I suppose the query could be simplified further.

I think the summary of this jira is misleading. As per my analysis the issue is caused by 
 
	 The operator tree in a reducer has a merge join operator and any of the join branches has more than one GBY:
  
 
RS-...-GBY-...-GBY-...-MERGEJOIN-...
               RS-...-/
 
   
	 the data have unique values in GBY key(s) processed by that branch or at least the last 3 records in the record stream. 
 

 The presence of PTF operator is irrelevant in this issue. It can be anything. Please see another example:
