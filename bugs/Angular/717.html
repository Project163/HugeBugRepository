The Webpack guide is outdated, but still available through direct links and search results. Since we're promoting use of the CLI, we should add a deprecation warning to the top of the guide or remove it.
Discussion
- *Please* do not remove this guide.

Instead, please add a warning to the top that setting up Webpack manually is not normally recommended, though it is possible. Then, to support those of us who need to do it anyway, update the guide to explain how to manually set up Webpack with Angular 6.

I am one of many developers working on projects that are incompatible with the current version of the Angular CLI. (My latest problem is the CLI is now incompatible with multiple NPM packages—but that's just the most recent in a series of problems I've had using the CLI.) For us, updating this Webpack guide will solve two problems:

In the short run, it will enable us to use Angular 6 right away—without having to first wait for the CLI to fix its incompatibilities.

In the long run, it will increase our confidence that we will be able to use Angular long term (and therefore increase our willingness to both use Angular in new projects and recommend it to others), by providing some insurance protection in case future incompatibilities arise with the CLI.

One of the things I love about Angular is the way it balances being highly opinionated, while stopping short of being dictatorial. For example, Angular strongly recommends using TypeScript. However, if a specific developer wants to ignore that and write plain JavaScript—that isn't recommended, but it *is* allowed. Updating this guide would continue that excellent tradition by recommending the CLI, but also allow using plain Webpack if needed. (The Angular CLI itself has never struck this balance well, and has acted dictatorially multiple times, especially by [Link: repeatedly blocking users from configuring Webpack themselves] ([Link: 1], [Link: 2], [Link: 3], [Link: 4], [Link: 5])—a problem this guide would provide a permanent alternate solution for.)
- I kinda disagree with @dschnelldavis for a reason.

Angular CLI v6 introduces a concept of builders, which will allow developers to plug their own build system. This way, developers can change Webpack config that they need.

The thing is this API isn't stable yet, but it's coming!
