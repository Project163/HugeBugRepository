Title

Guarded mixin needs default mixin

Description
The following code fails to build with a `Variable @bg is undefined` error:

```
.radius (@r) when not (@r = 8px) {
    border-radius: @r;
}
div.a {
    .radius(8px);
... [Log Snipped] ...
    background: @bg;
}
```

This only happens when the guard blocks the mixin from executing. If you remove the guard completely, or change `.radius(8px)` to `.radius(4px)`, compilation succeeds. But if the guard is triggered, `@bg` never gets defined.
Discussion
- As a workaround, it seems like scoping the `@bg` variable (ie moving it inside of the `div.b` block) allows the less file to compile. This obviously isn't an ideal solution, but at least it allows me to keep working on my project. :)
- in trunk you get a different error - the mixin is not found. At the moment you need to add a default case to the guarded mixin.

Add this below your mixin

```
.radius (@r) {
}
```

and the error should go away.

in dotless we only error if we don't find any mixin, not if we find a mixin and the guard fails, that might be an approach we should change less.js too...
