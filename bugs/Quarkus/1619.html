Title

MP Config `Converter` fails in native build

Description
### Describe the bug

Apparently, there's some compatibility issue with using MP config `Converter` and `@WithConverter` with native mode. If there is a property declared in a `@ConfigMapping`-annotated class that uses a value converter, the application compiles cleanly, but fails at bootstrap with `NoSuchMethodError`. See minimal [Link: reproducer] and stacktrace below:

```
java.lang.NoSuchMethodError: com.example.Config$BConverter. ()
	at io.smallrye.config.ConfigMappingContext.lambda$getConverterInstance$7(ConfigMappingContext.java:194)
	at java.util.Map.computeIfAbsent(Map.java:1054)
	at io.smallrye.config.ConfigMappingContext.getConverterInstance(ConfigMappingContext.java:178)
	at io.smallrye.config.ConfigMappingContext.getConverter(ConfigMappingContext.java:104)
... [Log Snipped] ...
	at io.quarkus.runtime.Quarkus.run(Quarkus.java:120)
	at io.quarkus.runner.GeneratedMain.main(Unknown Source)
```

### Expected behavior

Configuration values are picked up correctly with `@WithConverter` and work nicely in a native image. 

### Actual behavior

Native image builds, but fails at bootstrap.

### How to Reproduce?

How to reproduce:

1. Generate a new app, use of any extension in particular doesn't seem to matter.
2. Create a configuration mapping class.
3. Have at least 1 field resolved using `@WithConverter`.
4. Inject the config class.
5. Compile with GraalVM and start.
