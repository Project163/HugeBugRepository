Title

AudioOutput.play() panics on Ogg Vorbis files if `vorbis` feature is not opted in

Description
- Bevy 0.2.1 and  , no custom feature enabled
- Rust 1.46.0
- Mageia 8 x86_64

With the following startup system, I get an unrecoverable panic when calling `AudioOutput.play()` with an Ogg Vorbis file:
```rust
fn setup(asset_server: Res , audio_output: Res ) {
    let music = asset_server
        .load("WindlessSlopes.ogg")
        .unwrap(); // No load error.
    audio_output.play(music); // Panic.
}
```

Enabling the `vorbis` feature in `Cargo.toml` solves it, but I think that users should be given the opportunity to handle a load or play error before panicking.

Discussion
- Loading happens asynchronously in a non-blocking manner.  We can't provide / handle load errors at the point where load is called because the load hasn't happened yet.

`audio_output.play()` is also asynchronous. It will play the audio as soon as it has loaded.

```rust
// this just kicks off the load process
let music = asset_server
    .load("WindlessSlopes.ogg");
   // .unwrap() ----> The latest Bevy no longer unwraps here

// doesn't immediately panic. it panics (in a separate thread without crashing) in the latest Bevy
audio_output.play(music);
```

That being said, we should provide a way for users to respond to asset load errors. This should probably happen by adding downcastable errors to an event queue.
