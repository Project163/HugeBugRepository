**Steps to reproduce or a small repository showing the problem:**
```
ts
export type UserRole = 'user' | 'admin';
export const userRoles = {
  USER: 'user' as UserRole,
  ADMIN: 'admin' as UserRole,
... [Log Snipped] ...
})
role: UserRole;
```
On each compilation related constraint is removed and recreated so existing data is overwritten with default value (in this case switching all `admin` roles to `user`). I tried also using native `enum` or setting an static array `['user', 'admin']` as Column enum option, both with same result.

Discussion
- I am having this exact same issue.

First I received a warning that ALTER TABLE isn't possible unless the enum'ed column was either nullable or had a default value. If I added nullable, then on server refresh (with synchronise on) the entire column was made NULL, and if I added a default value, the entire column became that default value.

Are there any updates on this?
- I am experiencing the same issue when declaring the ` type: 'simple-enum',`
- Typeorm overwrites my enums with the Postgres driver as well.
- I am having the same issue with Postgres 13. As far as I have tested, this issue is present in typeorm v0.2.32 and has been present since 0.2.21. To reproduce:
1. Create an entity with an enum member. Do not give the enum member a default value, and make it non nullable.
2. Create (do not generate) a migration. In the migration, create a table for the entity and populate it with rows for which the value of the enum is not identical.
3. Run the migration and start the server.
4. The server should crash when typeorm tries to destroy your table. This is because it tries to set an entire column to null, but since null values are not allowed and there is no default, the server crashes and you get a handy stacktrace.


Edit: I found a hacky fix. If you append "_enum" to the name of your enum (in the database), typeorm won't take a wrecking ball to your data. I'm not sure, but I think typeorm is converting the camel-case name of your enum in the code to a snake-case name and appending "_enum," then creating a new type with this name (identical to the existing enum) and trying to set this as the type of the column in your table. 


For example; I had an "image" table with an "image_category" enum. In the code, this enum was called "ImageCategory." I found that typeorm crashed when trying to run the query `ALTER TABLE "image" ADD "category" "image_category_enum" NOT NULL`. It had created a type named by converting "ImageCategory" to snake case and appending "_enum." I was able to fix this issue by reverting the migration and renaming the enum (in the db) to "image_category_enum."
