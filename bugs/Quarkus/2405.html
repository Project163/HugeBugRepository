Title

Beanparam without fields is not supported

Description
### Describe the bug

If I use a class as a `@BeanParam`, which has no fields annotated as jax-rs parameters (e.g. QueryParam), I get an exception on start. see below.

```
@Path("/hello")
public class GreetingResource {

    @GET
    @Produces(MediaType.TEXT_PLAIN)
... [Log Snipped] ...
    }
}
```

### Expected behavior

The exception itself states 
`No annotations found on fields at 'org.acme.GreetingResource$Params'. Annotations like `@QueryParam` should be used in fields, not in methods.`

However, the jakarta rest spec states (Appendix A):
[URL]
[Image: Image]

So this is behaviour which (unintentionally?) differs from the spec

No matter what decision is taken here, the log message itself is confusing. The second sentence does not seem to have any relevance to the first sentence?

I actually don't see what the problem is here, the error message seems reasonable to me
- Probably the issue is that in this case, there are no methods, so we're not really detecting the error properly, and so the error message is confusing. In this case, the error should be "Parameter container with no parameter are not supported: you should add fields annotated with @Rest* or @*Param (for example @RestPath)" or something like that.
