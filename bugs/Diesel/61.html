I had a short look at the exact failure: The relevant assert is here: 

[URL]

It is supposed to verify that the underlying buffer is initialised on rust side with zeroed memory for at least the buffer side. Given that the capacity of the buffer matches what's expected but the size not, it seems like it still misses a branch somewhere. This initialisation was added as additional safety layer as we don't know how may bytes libmariadb initialises. By setting the buffer to all zero in the beginning at least we don't expose uninitialised memory if something goes wrong again of their side. 

So a potential fix would need to track down where this initialisation is missing. As "workaround" you might be able to just compile diesel in release mode to disable the assert. Obviously that just skips the check that might point to an actual problem
