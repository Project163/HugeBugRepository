Title

Zap waiting for Spider endlessly when it crashed.

Description
I have an example reposity that has ZAP waiting for the Spider to end at 96% done. The spider never ends because apparently it crashes. Hitting CTRL-C displays an exception. In this case it is a HSQLDB problem:
`org.hsqldb.HsqlException: Data cache size limit is reached: 10000`

The issue is that ZAP doesn't detect this and just waits for the spider forever instead of failling or displaying an error.

Reproduction steps:

```
git clone [URL]
cd Flockademic
git checkout 1e6dbaf6 
mkdir wrk
docker run -ti --rm -v $PWD:/zap/wrk owasp/zap2docker-live zap-baseline.py -d -t [URL] 
```
It will start the spider and it quickly will get stuck at 96% . Interrupt with CTRL-c to see the exception. Here it is :

```

11514 [ZAP-SpiderInitThread-0] INFO org.zaproxy.zap.spider.Spider  - Spider initializing...

27228 [ZAP-SpiderThreadPool-0-thread-1] FATAL hsqldb.db..ENGINE  - /home/zap/.ZAP_D/session/untitled1.data getFromFile failed 37817
... [Log Snipped] ...
        at java.util.concurrent.ThreadPoolExecutor$Worker.run(ThreadPoolExecutor.java:624)
```

Increasing the cache size allow the run to complete, but the underlying issue is still there.

```
docker run -ti --rm -v $PWD:/zap/wrk/:rw owasp/zap2docker-live sh -c 'sed -i "s/SET FILES CACHE SIZE 10000/SET FILES CACHE SIZE 100000/" db/zapdb.script && zap-baseline.py -d -t [URL] '
```
