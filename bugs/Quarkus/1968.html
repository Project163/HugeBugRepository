Title

Rest client running GET requests instead of POST after redirect

Description
### Describe the bug

I am using a Rest client to run POST requests on an endpoint that redirects to another POST endpoint.

[Link: Quarkus v3 introduced a way to register a custom redirect handler] that works fine.
The problem is that the request done after the redirect is GET and not the origin request type (POST in my case). So all my calls end with HTTP 405 "Method not allowed".


### Expected behavior

The expected behavior is to run a POST request after the redirect.

- POST /token
- HTTP 307 - /token/2
- **POST** /token/2
- HTTP 200


This is what cURL and Postman do:

```sh
curl --location '[URL] \
    --header 'Content-Type: application/json' \
    --data '{"value": "test"}' \
    -v
```

```
2023-07-10 11:33:42,831 INFO  [io.qua.htt.access-log] (vert.x-eventloop-thread-1)   - - 10/Jul/2023:11:33:42 +0200 "POST /token HTTP/1.1" 307 -
2023-07-10 11:33:42,847 INFO  [io.qua.htt.access-log] (vert.x-eventloop-thread-1)   - - 10/Jul/2023:11:33:42 +0200 "POST /token/2 HTTP/1.1" 200 70
```


### Actual behavior

The actual behavior is buggy, it runs a GET request instead of POST.

- POST /token
- HTTP 307 - /token/2
- **GET** /token/2
- HTTP 405

```
2023-07-10 11:32:27,476 INFO  [io.qua.htt.access-log] (vert.x-eventloop-thread-1)   - - 10/Jul/2023:11:32:27 +0200 "POST /token HTTP/1.1" 307 -
2023-07-10 11:32:27,487 INFO  [io.qua.htt.access-log] (vert.x-eventloop-thread-0)   - - 10/Jul/2023:11:32:27 +0200 "GET /token/2 HTTP/1.1" 405 -
[...]
org.jboss.resteasy.reactive.ClientWebApplicationException: Received: 'Method Not Allowed, status code 405' when invoking: Rest Client method: 'com.github.jdussouillez.client.TokenServiceApiClient#getToken'
[...]
```


### How to Reproduce?

Repo : [URL]

- Run the server
- Run the client, when it starts it makes a request on the server and fails

The important code is here: [URL]
The "/token" endpoint just redirects to "/token/2" which is also a POST request.
