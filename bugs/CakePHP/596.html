Title

TreeBehavior getPath ordering is broken in 2.5.7

Description
Recent change to treeBehavior completely breaks getPath tree ordering in CakePHP 2.5.7.

CakePHP manual states:
"The ‘path’ when referring to hierarchal data is how you get from where you are to the top.".

This used to work with default ordering being the left -field.

Currently there are actually two 'order' keys in getPath function:
'order' => array($Model->escapeField($left) => 'asc'),
'order' => false,
Discussion
- Can you please clarify the problem. What code gives what result?

Is the problem not covered by [Link: the getPath testcase]?
- Previously getPath created the following query:

```
SELECT `TreeModel`.`id`, `TreeModel`.`lft`, `TreeModel`.`rght` FROM `my_database`.`tree` AS `TreeModel` WHERE 1 = 1 AND `TreeModel`.`lft`  = 4395 ORDER BY `TreeModel`.`lft` asc
```

With CakePHP 2.5.7 the query is the same but without ordering:

```
SELECT `TreeModel`.`id`, `TreeModel`.`lft`, `TreeModel`.`rght` FROM `my_database`.`tree` AS `TreeModel` WHERE 1 = 1 AND `TreeModel`.`lft`  = 4395
```

When using getPath like this:

```
$this->TreeModel->getPath(2280, array('id', 'parent_id', 'lft', 'name'));
```

I used to get the results, correctly in order by the lft field:

```
array(
    (int) 0 => array(
        'Bunit' => array(
            'id' => '2720',
            'parent_id' => null,
... [Log Snipped] ...
    )
);
```

With CakePHP 2.5.7 I get this instead:

```
array(
    (int) 0 => array(
        'Bunit' => array(
            'id' => '2279',
            'parent_id' => '2720',
... [Log Snipped] ...
    )
);
```

The problem with getPath test case might be that the data is created with $this->Tree->initialize(2, 2); which creates a data that is already in correct order by the id field.

I'm not that familiar with NumberTree model or other models used by the test case, so I cannot fix the test case right away.
- I can take a look as I probably broke this.
