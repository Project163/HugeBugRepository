Title

Streamlit multiselect default options not working when using sequence of custom classes with __str__ method

Description
### Checklist

- [Link: X] I have searched the [existing issues] for similar issues.

### Summary

When using custom class as a choice option and also giving all the options as default values, we do not get the proper default values selected. The comparison of the default options and the option choices fails, since the class attributes are all the same but the underlying object attributes aren't.

### Reproducible Code Example

```
Python
import dataclasses
import streamlit as st

@dataclasses.dataclass
... [Log Snipped] ...
        )
print([choice.name for choice in choices])
```


### Steps To Reproduce

1. Copy this code example in jupyter notebook with streamlit installed
2. Run the code example.

### Expected Behavior

It should print ["option 1", "option 2"]

### Current Behavior

It prints ["option 1", "option 1"]

- Hi @frederiksteiner,

I'm not sure if this is something that we could reasonably fix on the Streamlit side of things as we're offloading the responsibility of deciding what index of a collection an element is in to Python's builtin `list.index()` method. While writing a more specialized implementation here would be possible, I'm not sure it would be worth the additional implementation+maintenance effort to support what I think is a relatively rare use-case.

The standard way of getting this to work would be to provide a custom `__eq__` method in your class implementation that considers two `Choice`s equal if they have the same name (or by some other more complex criteria for the real class this is being done for):

```python3
def __eq__(self, other) -> bool:
    return self.name == other.name
```

Let me know if this solution works for you!
