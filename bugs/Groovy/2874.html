Title

Explicit type hints are not respected

Description
@groovy.transform.CompileStatic
 class  Example {
   static  void main( String [] args) {
    Collections.< String >emptyList().get(0).toUpperCase()
  }
}
 
  

 That fails to compile because it doesn't respect the <String> hint.
Discussion
- For this to work, we need to keep track of the explicit type information.  MethodCallExpression  has  genericsTypes , but it seems to be unused. The AST doesn't have the  String  hint, so probably this information is just lost during parsing. In any case,  genericsTypes  in  MethodCallExpression  isn't used, so we need to solve two problems actually
