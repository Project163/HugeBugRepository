Discussion
- It appears this issue was introduced in **ESLint v9.39.0**, specifically affecting the `@typescript-eslint/unified-signatures` rule.
For now, the temporary fix is to **revert ESLint to v9.38.0**, where this problem does not occur.

You can do so with:

```bash
npm install eslint@9.38.0 --save-dev
```

Or, if you want to enforce the version across your workspace, you can use **package manager overrides**:

**For pnpm:**

```json
"pnpm": {
  "overrides": {
    "eslint": "9.38.0"
  }
}
```

**For npm (v8.3.0 or newer):**

```json
"overrides": {
  "eslint": "9.38.0"
}
```

- The `@typescript-eslint/unified-signatures` rule has a visitor function with multiple parameters:

[URL]

[URL]

After [URL] Linter is passing one more argument (`node.parent`) to visitor functions, and that caused the breakage in this rule.

I think that passing more arguments doesn't constitute a breaking change in the API, and that this problem should be fixed in the rule code.
- I can reproduce the problem with the repro from [URL]
- My 2c: The fact that this has broken a rule suggests otherwise. You have changed the constraints of the API which has broken that contract and caused a breakage in a downstream consumer. 

A constraint of the visitors for the past **_decade_** has been visitors always pass one argument. Which allowed you to do things such as the rule has done - passing a reused function which had an optional second parameter unused by the visitor usecase.
