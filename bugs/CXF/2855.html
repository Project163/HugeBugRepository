- This is very interesting issue, apparently related to changes in Swagger 2.  
So what is happing, and you see that as well,  /cxf/bpc-core/swagger.json and /cxf/bpc-monitor/swagger.json return the same results.  

 However, you should see 2 tags in the resulting json, something like: 
  
  "tags" : [
     {  "name" :  "bpc-core"  }, 
     {  "name" :  "bpc-monitor"  }
]
 
  

 So basically you always have all your APIs in same specification. Very luckily, the heavy use of statics in Swagger may cause this  weird behaviour. I will try to investigate if something could be done in CXF to workaround that. 
Thank you.
- Ok, the issue has been fully understood now. The cause is Swagger's overuse of Java statics.  
Essentially, the problem reveals itself like this:  Swagger2Feature -> BeanConfig -> ScannerFactory.setScanner(this) . Every time new JAX-RS APIs with Swagger2Feature is initialized, the scanner is reset to the its BeanConfig instance. 
Not sure we can workaround that on CXF side, but patch to Swagger may help,  sergey_beryozkin  what do you think? 
Thanks.
