Title

Rows not serializeable between restarts on SQLALchemy>=2

Description
### Describe the bug

Since the switch from `LegacyRow` to `Row` in 2.0.0, deserialization is no longer possible between sessions (it IS possible if you don't restart the kernel).

### Optional link from [URL] which documents the behavior that is expected

_No response_

### SQLAlchemy Version in Use

1.4.42 and 2.0.4

### DBAPI (i.e. the database driver)

pg8000

### Database Vendor and Major Version

PostgreSQL 12

### Python Version

3.11.2

### Operating system

Ubuntu 20.04.5 LTS (Focal Fossa)

### To Reproduce

```
python
# mre.py

import os.path
import sqlalchemy
... [Log Snipped] ...
        pickle.dump(data, f)
    print(f"Serialized {type(data)=} using {sqlalchemy.__version__=}.")
```

### Error

```
Traceback (most recent call last):
  File "/home/dev/mre/mre.py", line 16, in  
    data = pickle.load(f)
           ^^^^^^^^^^^^^^
  File "/home/dev/mre/.venv/lib/python3.11/site-packages/sqlalchemy/util/langhelpers.py", line 1636, in __new__
    raise TypeError(
TypeError: Can't replace canonical symbol for unpickled with new int value  
``` 

### Additional context

The exact dialect + driver don't seem to matter as far as I can tell (I've tested more variants). The issue seems to be `Row` vs `LegacyRow`.

This does NOT appear if you do not allow the python process to exit before deserialization.

Exact steps that I used for the MRE:
```
bash
pip install pg8000
docker run -p 5002:5432 -d rsundqvist/sakila-preload:postgres

rm -f data.pkl && pip install 'sqlalchemy==1.4.46' --quiet && python mre.py && python mre.py
... [Log Snipped] ...
#

```

Maybe I missed something and this isn't permitted anymore?
