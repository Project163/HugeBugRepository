Title

[Inductor] F.lp_pool{1,2,3}d fail with OverflowError when norm_type=float('inf')

Description
### 🐛 Describe the bug

When using `torch.compile` (Inductor backend) with `F.lp_pool1d`, `F.lp_pool2d`, or `F.lp_pool3d` setting `norm_type=float('inf')`, the code crashes with an `OverflowError` during the lowering phase.

It appears that Inductor attempts to compute the mathematical formula literally (computing `pow(x, inf)`) instead of decomposing it into the equivalent `max_pool(abs(x))` operation. This results in an overflow when handling the infinite exponent.

This behavior is inconsistent with Eager mode, which handles `norm_type=inf` correctly.
