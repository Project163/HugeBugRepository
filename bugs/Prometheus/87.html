Title

Report a coding issue that uses reference to loop iterator variable

Description
**What did you do?**

Run a static analyzer DeepGo, which reports a finding on the related code.

**What did you see instead? Under which circumstances?**

At [URL]
[URL]

Within the loop `for i, r := range g.Rules`, variable `r` is shared by all the loop iterations, as described in the Go specification (https://golang.org/ref/spec).
All instances of `&r` and its field addresses such as `&r.Record` within the loop may refer to the last rule updated by the loop. 
```
		for i, r := range g.Rules {
			for _, node := range r.Validate() {
```
Within `r.Validate()`, the return value `nodes` includes multiple instances of the same `&r.Record`:
[URL]

Next, all the nodes returned by `r.Validate()` are appended into the `errs` slice, which escapes the loop:
[URL]

As a consequence, `errs` may hold multiple instances of the same rule's fields.

For example, supposed `g.Rules = [r1, r2]`,  code
```
for i, r := range g.Rules {
			for _, node := range r.Validate() {
				...
				errs = append(errs, &Error{
					Group:    g.Name,
... [Log Snipped] ...
			}
		}
```
produces
```
errs = [
  &Error{..., Err: WrappedError{ ..., node:  &r2.Record} },
  &Error{..., Err: WrappedError{ ..., node:  &r2.Record} },
]
```
That is, it contains two instances of `&r2.Record`, while the correct result should be:
```
errs = [
  &Error{..., Err: WrappedError{ ..., node:  &r1.Record} },
  &Error{..., Err: WrappedError{ ..., node:  &r2.Record} },
]
```

**What did you expect to see?**

A fix is to avoid reusing the shared variable item:
```
		for i, r := range g.Rules {
			for _, node := range g.Rules[i].Validate() {
				...
```

**Found by #deepgo.**
