Title

getPrefixLength return -1 if unix file contains colon

Description
A simple 

  
  int  prefixLength = FilenameUtils.getPrefixLength( "/:foo/bar" );
 
  

 return  -1 , but  0  was expected. The path is absolutely valid for unix systems.
Discussion
- However, in both cases I think the expected length should be 1, not 0, as the prefix will be "/", not "" (these are absolute pathnames)
- Looks like FilenameUtils#getPrefixLength is finding the colon character in the second position, and then it gets the previous character (around line 660 and 666 r1727892) and checks the following: 

  
 ch0 =  Character .toUpperCase(ch0);
 if  (ch0 >=  'A'  && ch0 <=  'Z' ) {
     if  (len == 2 || isSeparator(filename.charAt(2)) ==  false ) {
         return  2;
    }
     return  3;
}
 return  NOT_FOUND;
 
  

 The ch0 >= 'A' && ch0 <= 'Z' is evaluated to false, since ch0 is '/'. 

 Maybe this issue could be fixed by updating the Javadoc to state that one of the valid prefixes is a case insensitive character, from a to z, followed by a colon?
