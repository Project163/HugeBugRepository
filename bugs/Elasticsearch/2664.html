Title

AssertionError: Found shard snapshot waiting to be assigned...

Description
In a recent `master` ( ) I saw a snapshot stress test trip the `Found shard snapshot waiting to be assigned` exception. The problematic shard was `[index-1][1]` and the assertion tripped at the cluster state transition which finalised a snapshot with a future clone queued up. The previous state of this shard was like this:

    snapshot:
    {
      "index": {
        "index_name": "index-1",
        "index_uuid": "kigpd8yeTZm5R6PHbZKpww"
      },
      "shard": 1,
      "state": "FAILED",
      "generation": "CcvNa4iURmCdg0YDvwIM9w",
      "node": "PgoVP627RAqZnA5y4ZQeDQ",
      "reason": "node shutdown"
    },

    clone:
    {
      "index": {
        "name": "index-1",
        "id": "3cG2OCEuSB2MINCVHFxI4g"
      },
      "shard": 1,
      "state": "QUEUED",
      "generation": null,
      "node": null
    }

The finalisation removed the first entry, leaving the dangling `QUEUED` clone. FWIW the shard was in yellow health at the time, although as a clone we should be able to proceed even if it were red.

Full test output in case it helps: [Link: testoutput-1630475019.tar.gz]
