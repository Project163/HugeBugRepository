Title

Angular 2.0 alpha 34 error loading router.dev.js

Description
Hello,

I was just changing my app from alpha 33 to alpha 34 and when I tried to load it, it wouldn't work and produced the following error message:

```
Error: System.get(...).retrieveGlobal is not a function
    Error loading [URL]
    at [URL]
    at u (http://localhost:63057/dependencies/systemjs-0.18/system.js:4:19870)
    at a (http://localhost:63057/dependencies/systemjs-0.18/system.js:4:18435)
... [Log Snipped] ...
    at [URL]
    at Zone.run (https://code.angularjs.org/2.0.0-alpha.34/angular2.dev.js:136:17)
```

Which the message indicates that it stems from the following line of code:

``` javascript
return System.get("@@global-helpers").retrieveGlobal(__module.id, false);
```

I perused through the rest of the files and I see that retrieveGlobal, along with prepareGlobal, are defined in the angular2.sfx.dev.js file, which I have never used. Correct me if I'm wrong but that file is meant for people writting code in ES5 spec and I'm writing ES6 code.

Has anyone stumbled upon this yet or am I the only one with this problem?

Best regards,
André
Discussion
- This one is "interesting" - what is going on here is that SystemJS builder is auto-detecting [URL] as a file with "global module" system. This happens since [URL] is "empty" - that is - it contains only TS interface definitions so after transpilation to JS it is effectively empty.

I guess this started to be a problem after TS or SystemJS version update, since the "empty" file was there from like 2.0.0-alpha.32 ( ).

@hitmanmcc as a work-arround you can add "global" plugin to your SystemJS config.
