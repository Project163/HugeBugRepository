Title

Cross-compiled gRPC is missing binaries for the target

Description
This is a follow-up issue to the PR [URL] that introduced the problem. I could just send a PR that reverts it but that reintroduces the problem again that led to that PR. I sadly don't know the intention of their PR as we have been cross-compiling gRPC successfully since at least 1.32.

### What version of gRPC and what language are you using?

1.39

### What operating system (Linux, Windows,...) and version?

Linux and macOS

### What runtime / compiler are you using (e.g. python version or version of gcc)

Various; this issue is independent of that.

### What did you do?

We are building gRPC through cross-compilation for e.g. Apple M1 or Linux aarch64 and providing the output as conda packages that are intended to be used on these architectures. There you will need a native version of `grpc_cpp_plugin` to natively build packages that depend on gRPC.

### What did you expect to see?

`$PREFIX/bin/grpc_cpp_plugin` should be built and installed into the target prefix.

### What did you see instead?

The above-mentioned plugin was neither built nor installed. This makes sense if the build of gRPC would only be used in a cross-compiling environment but the output of the mentioned build here will be used for cross-compiling as well as compiling natively on the target system later.

### Anything else we should know about your project / environment?

We will revert the PR [URL] in conda-forge for now for the 1.39 builds to get the users of the cross-compiled package back to a working state.
