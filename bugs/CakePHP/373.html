Title

TextHelper's autoLink() failing on link containing email address

Description
The following link:
  [URL]
is not auto-linked properly TextHelper's autoLink().
The call to autoLinkUrls() does work, but the resulting HTML is then broken apart by the subsequent call to autoLinkEmails(), since toEmail=DellOnlineSales@Dell.com is interpreted as an email address.
Discussion
- Yeah, you should probably not call autolink() then, as it can't handle nested replacement patterns. I don't think there is an elegant way to solve this as linking emails first will cause the URL to not link. Perhaps there's a solution though.
- Thanks Mark. Unfortunately I can't disable autolink() that easily, it is used to enhance the thousands of notes and comments our users already put in our system. Ironically, github has no problem dealing with this link, as seen above :)
The following code in TextHelper finds the emails to autolink:

``` php
        $atom = '[\p{L}0-9!#$%&\'*+\/=?^_`{|}~-]';
        $text = preg_replace_callback(
            '/(' . $atom . '+(?:\.' . $atom . '+)*@[\p{L}0-9-]+(?:\.[\p{L}0-9-]+)+)/ui',
            array(&$this, '_insertPlaceholder'),
            $text
        );
```

My gut feeling would be to put an extra delimeter in front of $atom, so that no email is found in an URL. A combination of \w, \W, \s or \S inside the first '/(' comes to mind, or maybe not allow any '&' or '?' right in front of an email, to deal with URLs like the one above. I haven't found anything that would quite work for now -- I'd assume one could put an email address in between parentheses too for example.
