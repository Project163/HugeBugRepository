- @UAHector, people, I found out what the issue is

`NextResponse.redirect` uses `307` HTTP status code, that preserves the `POST` request method that you have in your api route. Thus when you redirect from your api route to a page the nextjs server gets a `POST` request for the page and not a `GET` request, and does not know what to do with it. Heres their rationale why they did so:

[URL]

The article above advises for our use case to use the `303` status code, but does not specify how, and in fact i could not find anywhere in the docs how to do it, but after looking through the source code i found out that you can supply a second argument to `NextResponse.redirect` to specify status code. I did it and the issue resolved itself.

Try and edit your route code as follows and see if the fixes your issue:

```
typescript
import { NextResponse } from "next/server";

export async function POST(request: Request) {
  try {
... [Log Snipped] ...
  }
}
```

As for the error itself, its name is very unintuitive, but basically because you are running a Nextjs server, when it redirects a `POST` request to your page the server sees that the request is not `GET` and thinks that you do not want the page to be served, but insted some internal processing to happen and that the request is some internal nextjs workings, referred to as actions. It looks for the internal id of the action that all internal requests have, but does not find any (because it is not internal request, it is your simple redirect) and anounces the freakout concerning that to you in an error message. When you fix the redirect to do a `GET` request the issue disappers as now nextjs server will just serve the page you requested.

Also when **somebody from nextjs dev team reads this** - add how to use a custom status code in `NextResponse.redirect` to the docs guys, am also pretty sure the second parameter can be an object with a lot of cool keys to customize the redirect, thanks in advace!
