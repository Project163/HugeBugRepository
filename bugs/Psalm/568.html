Title

error when templating key-of from another templated param, InvalidDocblock affecting expected templated param count

Description
# issue
* psalm seems to have less of an issue when defining DATA as a simple `array`, but this leads `key-of` to resolve to `array-key`, which then causes issues with `@return ID` on a method that returns `string`.
* `InvalidDocblock` seems to mess with the expected templated param count, I'm wondering if this would be mitigated by resolving "invalid" template to `as mixed` to suppress `TooManyTemplateParams` ?
* `MismatchingDocblockReturnType` is raised seemingly directly as a result of `key-of ` failing to parse.

as always, there's always the possibility that I'm grossly misusing psalm :P

Discussion
- `@template K as key-of ` shouldn't be defined at the class level - I've updated the example above to reflect proper usage, but there are still some bugs evident.
- *edited to update the error list & commit ref
- the idea with this was so that psalm wouldn't have to make a round trip to verify that `@template ID as key-of ` was present on `@template T as array `, with the implicit linkage between `@return ID` in `Foo::IdProperty()`, `@return ID_VAL` on  `Foo::ObtainRepoId()` with the method body passing `Foo::IdProperty()` to `Foo::__get()` implicitly hinting that `ID_VAL` is the specific `value-of ` corresponding to `ID as key-of `. While the updated example is cleaner (i.e. DRY), it *feels* a little looser?
