Title

mini-css-extract-plugin hmr broken after #24573

Description
### What version of Next.js are you using?

10.2.3

### What version of Node.js are you using?

14.16.1

### What browser are you using?

All

### What operating system are you using?

macOs

### How are you deploying your application?

next dev

### Describe the Bug

[Link: Style9] is a css-in-js compiler that generates css at build time. To do so, its [Link: Next.js integration], makes use of the `mini-css-extract` plugin bundled with Next (`require('next/dist/build/webpack/plugins/mini-css-extract-plugin')`).

It works fine when creating a production build, but since the release of `v10.2.1` (and more specifically #24573), running `next dev` throws the following error:
```
./pages/index.22C1ZZc.css:4:0
Module not found:
  Can't resolve '[...]/node_modules/next/dist/compiled/mini-css-extract-plugin/hmr/hotModuleReplacement.js'
null
```

A simple reproduction repository using Style9 can be found here: [Link: TxHawks/style9-latest-next-repro]
The 1st commit is a working example using Next `v10.0.9`
The 2nd commit breaks after an upgrade to latest Next (`v10.2.3`)
The 3rd commit remains broken after upgrading next-transpile-modules to its latest version (`v7.2.0`)

### Expected Behavior

Optimally, i hope for this to be fixed inside Next's implementation, so that it works like it did before.

Alternatively, any suggestions as to how to fix it on Style9's side would also be greatly appreciated.

### To Reproduce

A simple reproduction repository using Style9 can be found here: [Link: TxHawks/style9-latest-next-repro]

The 1st commit is a working example using Next `v10.0.9`
The 2nd commit breaks after an upgrade to latest Next (`v10.2.3`)
The 3rd commit remains broken after upgrading next-transpile-modules to its latest version (`v7.2.0`)

To reproduce, simply clone the repository and run `next dev`.

To see a working example with a previous version of Next, checkout the first commit ( ), reinstall dependencies, and run `next dev`.
