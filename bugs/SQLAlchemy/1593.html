Title

cloned traverse of AnnotatedFromClause incomplete

Description
### Discussed in [URL]

narrowed down version of the problem

```
py
from typing import Any

from sqlalchemy import bindparam
from sqlalchemy import BindParameter
... [Log Snipped] ...

print(stmt.compile(compile_kwargs={"literal_binds": True}))
```

when we create the AnnotatedCTE, the params relies on cloned traverse which is not applied to the original CTE.  This original CTE is consulted later for its `.c` collection, producing columns that point to the non-traversed version of the select:

```
python test3.py 
/home/classic/dev/sqlalchemy/test3.py:35: SAWarning: Bound parameter 'ids' rendering literal NULL in a SQL expression; comparisons to NULL should not use operators outside of 'is' or 'is not' (this warning may be suppressed after 10 occurrences)
  print(stmt.compile(compile_kwargs={"literal_binds": True}))
WITH cte AS 
(SELECT "user".id AS id, "user".name AS name 
... [Log Snipped] ...
 SELECT cte.id, cte.name 
FROM cte
```

The exact case above works if we propagate the copy internals, but remains to be seen if a. this doesnt break other things (answer: it does :( ) and b. doesn't hit a performance trap somewhere (I think it's unlikely):

```
diff
diff --git a/lib/sqlalchemy/sql/selectable.py b/lib/sqlalchemy/sql/selectable.py
index 60f062ec9..004755ab5 100644
--- a/lib/sqlalchemy/sql/selectable.py
+++ b/lib/sqlalchemy/sql/selectable.py
... [Log Snipped] ...
         if kw.get("ind_cols_on_fromclause", False):
             ee = self._Annotated__element  # type: ignore
```

```
$ python test3.py 
WITH cte AS 
(SELECT "user".id AS id, "user".name AS name 
FROM "user" 
WHERE "user".id = 17)
 SELECT cte.id, cte.name 
FROM cte

```

it breaks tests in the usual areas, deep inside of polymorphic inheritance.   so need to see if this is possible to fix without breaking those very old cases
