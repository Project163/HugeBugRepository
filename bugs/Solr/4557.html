Title

HealthCheckHandler shouldn't be an implicit SolrCore level handler and should be configurable

Description
While trying to use the HealthCheckHandler I noticed that: 
 
	 CoreContainer has some logic to read config from  solr.xml , however, this is never used, and the handler is constructed explicitly inside  InfoHandler . This means you can't plugin a different implementation. 
	 Also noticed that it was added as an implicit plugin to the  SolrCore . which means one could access the handler like  /<collection-or-core>/admin/health , however, this will never work, since it uses a parameterless constructor, which leaves the handler in an invalid state  [1] . I honestly don't know why it's being added to the  SolrCore , this is supposed to be a node level handler, and for SolrCore one could use the  PingRequestHandler
