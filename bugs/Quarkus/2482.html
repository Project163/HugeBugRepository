Title

MethodTooLargeException is thrown in compilation when the project has large number of rest clients (even unused)

Description
### Describe the bug

If there are too many rest client in quarkus project, compiling fails with following exception.

```
[ERROR] Failed to execute goal io.quarkus.platform:quarkus-maven-plugin:3.20.2:build (default) on project methodtoolarge: Failed to build quarkus application: io.quarkus.builder.BuildException: Build failure: Build failed due to errors
[ERROR]         [error]: Build step io.quarkus.rest.client.reactive.deployment.RestClientReactiveProcessor#registerProvidersFromAnnotations threw an exception: org.objectweb.asm.MethodTooLargeException: Method too large: io/quarkus/rest/client/reactive/runtime/AnnotationRegisteredProvidersImplementation.  ()V
[ERROR]         at org.objectweb.asm.MethodWriter.computeMethodInfoSize(MethodWriter.java:2088)
[ERROR]         at org.objectweb.asm.ClassWriter.toByteArray(ClassWriter.java:506)
[ERROR]         at io.quarkus.gizmo.ClassCreator.writeTo(ClassCreator.java:246)
... [Log Snipped] ...
[ERROR]         at org.jboss.threads.JBossThread.run(JBossThread.java:499)
[ERROR] -> [Help 1]
```

The error also occurs if these rest clients are unused and come from maven (transitive) dependencies. Here is a (silly) example repository to reproduce the issue 

[URL]

Just checkout the repo and try to compile it. Though the example repository contains only silly example, this issue already occured to one or two of our teams as they are heavily using shared libraries containing rest clients. Disregarding the unfortunate design, failing quarkus build because of large number of unused (rest client) classes is not quite ideal.

The problem is clearly caused by combination of dynamically building the constructor of AnnotationRegisteredProvidersImplementation and having many rest clients and providers.
