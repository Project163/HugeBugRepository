Title

Consider using user-select: none instead of preventDefault on drag mousedown.

Description
Previous title: 

When dragging elements in d3 using d3.behavior.drag(), the dragEnd event isn't triggered when the mouse is released outside of the window or an iframe. 

This causes "sticking" behavior if the mouse is dragged out of a window or iframe, the mouse button is released, and the mouse returns to the window, as d3 was never notified of the dragEnd event. This can be easily seen in this preexisting example, by dragging an element outside of the frame and letting go of the mouse button: [URL]

However, outside of d3, $(window).mouseup _is_ normally triggered on a mouseup event that happens outside of the window. We can normally use this to end a drag. For example, in this jsFiddle, we can drag the blue box outside the iframe, release the mouse, and when we return the box is not "stuck" to the mouse: [URL] [Edit: create bl.ocks example of this as well: [URL]

This would be doable in d3, except that the dragEnd event swallows mouseup, and so the mouseup event does not bubble up to window.

It seems to me that d3 should listen to mouseup events on window and call dragEnd if there is a drag in progress.
