Title

TUI: 'termguicolors' provokes gnome-terminal-server memory leak

Description
When using neovim 0.2.1 in combination with gnome-terminal switching between tabs (and possibly other window related operations) results in the memory of gnome-terminal-server increasing quite rapidly. I ran into this when at some point the total memory used was around 2 GB, when normally gnome-terminal-server hardly goes above 100 MB.

I did some manual testing with other terminals (e.g. tilix and roxterm) and they seem to suffer from the same problem. I haven't tested non libvte terminals though. Seeing how the nvim process itself is not increasing in memory usage I think neovim is spitting something out these terminals don't like.

Neovim 0.2.0 does not suffer from the mentioned problem.

- `nvim --version`: v0.2.1
- Vim (version: ) behaves differently?
- Operating system/version: Arch Linux, kernel 4.9 LTS
- Terminal name/version: gnome-terminal 3.26.2 VTE version 0.50.2
- `$TERM`: xterm-256color

### Requirements To Reproduce

* Python 3
* gnome-terminal
* [URL] installed

### Steps to reproduce

1. `curl -s [URL] -o /tmp/reproduce.vim`
2. `curl -s [URL] -o /tmp/reproduce.py`
3. Run `env NVIM_LISTEN_ADDRESS= :9999 nvim -u /tmp/reproduce.vim` in one gnome-terminal instance
4. Run `python /tmp/reproduce.py` (requires python 3) in another instance
5. Wait until the Python script completes

### Actual behaviour

Memory of gnome-terminal-server (but weirdly enough not nvim itself) increases over time.

On 0.2.0 the script output is:

```
Memory start: 89.63671875 MB
Memory increase: 0.0 MB
```

On 0.2.1:

```
Memory start: 90.5625 MB
Memory increase: 45.60546875 MB
```

### Expected behaviour

Memory does not increase drastically.
