Title

async preValidation with custom validator does not trigger error handler

### Description

Errors thrown from a custom validator while using an async `preValidation` hook are not caught by the error handler. Instead the error is unhandled and propagated to the Node runtime which kills the app. Removing the hook all together or using a synchronous approach (with `done()`) resolves the issue.

### Expected Behavior

Error handler should be called (we should see a `setErrorHandler  ` logged), the client is given a response, and the instance continues running. Instead the handler is not called, the connection socket hangs up, and the instance crashes.
Discussion
- The validator should return an `{ error }` instead of throwing it:

```
function (data) {
      try {
        const result = schema.validateSync(data, yupOptions)
        return { value: result }
      } catch (e) {
        return { error: e }
      }
    }
```
