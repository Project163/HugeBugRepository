Title

Syntax used for PostgreSQL check constraints will be deprecated in PostgreSQL 12

Description
### Summary

Reflection of check constraints against PostgreSQL databases queries the `pg_constraint.consrc` column.  This has been deprecated in PostgreSQL 12, so constraint reflection will fail against that version.

### Details

Check constraint reflection takes place in the following code function:

[URL]

However, this query will fail in PostgreSQL 12, when the `consrc` column of the table is deprecated:

[URL]

### Potential fix

The recommended way to fix this is to use the `pg_get_constraintdef` function instead.  The PostGIS project hit this issue and their solution may be helpful: [URL]

### Is this a bug?

I think this counts as a bug. I encountered the issue when models generated by sqlacodegen had different constraints to those displayed in PGAdmin4's SQL view.  However, I can't provide a script to demonstrate this because I don't know how the results from `pg_get_constraintdef` and `pg_constraint.consrc` came to be different in the first place!

This will be a bug when run with PostgreSQL 12.  A potential way to test it is to add check constraints to a PostgreSQL 12 table and then try to reflect them.

### SQLAlchemy version

Issue noticed against version 1.2.12 (but applies to [Link: latest commit at time of writing])
