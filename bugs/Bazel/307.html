Title

maven_rules.bzl: classifier doesn't seem to be handled correctly

Description
With the current `tools/build_defs/repo/maven_rules.bzl` I would expect, that something like this just works:

WORKSPACE (copied original maven_rules.bzl version locally):

```
load("//tools:maven_rules.bzl", "maven_jar",
     "maven_dependency_plugin")

maven_dependency_plugin()

... [Log Snipped] ...
    sha1 = " ",
)
```

BUILD:

```
java_library(
  name = "jetty-server",
  exports = ["@jetty_server//jar"],
)

... [Log Snipped] ...
  exports = ["@jetty_server_javadoc//jar"],
)
```

And running this command:

```
  $ bazel build ...
```

Should produce this result:

```
$ ls -R $(bazel info output_base)/external/jetty_server*
/home/davido/.cache/bazel/_bazel_davido/ /external/jetty_server:
jar  WORKSPACE

/home/davido/.cache/bazel/_bazel_davido/ /external/jetty_server/jar:
... [Log Snipped] ...
/home/davido/.cache/bazel/_bazel_davido/ /external/jetty_server_sources/jar:
BUILD  jetty-server-9.3.11.v20160721-sources.jar
```

- I wasn't aware that there are native and skylark java rules.

I got it working now when I properly loaded the skylark rules:

    load("@bazel_tools//tools/build_defs/repo:maven_rules.bzl", "maven_jar")
- The native rules seem to be working but have the packaging, classifier, version order mixed up.
The following code snippet works

    native.maven_jar(
        name = "com_salesforce_servicelibs_reactor_grpc",
        artifact = "com.salesforce.servicelibs:reactor-grpc:jar:jdk8:0.8.2",
        repository = "[URL]
    )

Artifact should thus be of the form: `groupId:artifactId[:packaging][:classifier]:version`
