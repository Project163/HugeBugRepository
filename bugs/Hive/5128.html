Title

LLAP TaskExecutorService race can lead to some fragments being permanently lost

Description
A fragment can be evicted before it's submission completed. A race can cause a situation As a result, we end up trying to unregister the fragment for stateChangeNotifications before it has been registered - leading to an exception, which skips the actual fragment kill.
Discussion
- Patch makes a few changes. Some unrelated to the core issue. 
For the core issue, the registration for state change notifications has moved into the main lock. 

 Additional changes. 
 
	 Avoid excessive debug logging in the ZK registry. 
	 Handle a potential leak in the AM 
	 Switch around the maybeRegisterForStateChangeNotifications to work correctly with the return value (was inverted)
