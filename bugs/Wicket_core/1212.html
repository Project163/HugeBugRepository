Title

StringLengthValidator does not validate, but cuts off input

Description
I have a change-password-page with a PasswordField with a StringValidator.lengthBetween( 3, 20 ). 

 I ran into an error where I could paste a long password (>20 chars), and Wicket not throwing errors, but cutting the password to length 20. 

 Wicket version: 7.0 
Chrome: 45 

 The maxlength is rendered as attribute on the element. 

 <input id="password" type="password" name="password" value="" maxlength="20" minlength="3">
Discussion
- How do you manage to send the longer value to the server? 
I guess you paste something longer than 20 chars but the browser accepts only the first 20 chars in the text field and thus sends just them. 
Please verify with DevTools/Firebug.
- If you change the form method to GET and then paste something like "[URL] then you'll see that the error is there.
- ... [Middle Discussions Snipped for Brevity] ...
- I was going to add protected method that the application developer could override and suppress this behavior, but I see I'll have to the same for 'minlength'... 
I see no reason to make it so configurable/complex - the application developer could just override #onComponentTag().  
Just use the constructors, e.g. 'new StringValidator(min, max)', instead of the static factory methods. 

 Changing StringValidator to not write these attributes is a rather big behavior change that may break applications in production. We can do it for Wicket 8.x if you think this is the better default.
