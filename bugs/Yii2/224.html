- Here comes the pull request.

Although rearranging the order of applying Twig options obviously fixes this bug, it rather seems like a quickfix because there are no tests to ensure that Twig will always behave as we expect it.

Maybe we should write more tests before applying this fix or even discard this issue and open a new issue for tests refactoring? 

I would like to test every kind of Twig option (extensions, functions, lexer options...) in isolation and within a configuration that contains every option. Although this might seem like an overhead of testing a third-party library, I still think it makes sense to ensure that our wrapper class has no chance of breaking any Twig internals.
