Title

STC: problem with a getAt call in double nested collect call

Description
The following code works well dynamically, properly type checks, but fails static compilation: 
  
 @groovy.transform.CompileStatic test() {
    def versionRanges = [[ '1.7' , 11]]
    versionRanges.collect { versionRange -> versionRange[1].collect { versionRange[0] } }.flatten()
}

test()
 
  
  
 Exception thrown

BUG! exception in phase 'class generation' in source unit 'ConsoleScript23' At line 3 column 45
On receiver: versionRange with message: getAt and arguments: 1
This method should not have been called. Please try to create a simple example reproducing this error and filea bug report at [URL]
 
  

 Although it's reported on the first  versionRange [1]  , it's actually seems related to the second call ( versionRange [0]  ). If you remove that second call, all is fine.
Discussion
- My initial algorithm looked like so: 
  
 def versionRanges = [
    [ '1.7' , 11],
    [ '1.8' , 9],
    [ '2.0' , 8],
    [ '2.1' , 9],
    [ '2.2' , 2],
    [ '2.3' , 2]
]

versionRanges.collect { versionRange -> (0..versionRange[1]).collect {  "${versionRange[0]}.${it}"  } }.flatten()
 
  

 The idea was to generate all the versions of Groovy 1.7 onward for referencing them on the Groovy website.
