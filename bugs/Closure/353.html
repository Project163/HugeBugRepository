Title

Bad optimization resulting in a=a=something

Description
What steps will reproduce the problem? 

Below is a test function:

function test(p0, p1) {
  var i, foo, bar, ndx;

  foo = Math.max(1, p1 - 8);
  bar = Math.min(p0, foo + 16);
  foo = Math.max(1, bar - 16);

  for(i = foo, ndx = []; i <= bar; i++) {
    ndx.push(i);
  }

  return ndx;
}

We compile it with SIMPLE_OPTIMIZATIONS:

java -jar /path/to/compiler.jar --compilation_level SIMPLE_OPTIMIZATIONS --js test.js --js_output_file test.min.js

 What is the expected output? What do you see instead? 

Output:

function test(d,e){var a,b,c;a=Math.max(1,e-8);b=Math.min(d,a+16);a=a=Math.max(1,b-16);for(c=[];a<=b;a++)c.push(a);return c};

Unexpected code: "a=a=..."

 What version of the product are you using? On what operating system? 

Version: 20100917 (revision 440)
Built on: 2010/09/17 17:55
Windows 7 Pro / 64-bit

 Please provide any additional information below. 

My guess: Closure Compiler moved the "i = foo" out of the for loop but failed to notice that the same temporary variable is used for both 'foo' and 'i'. So it did the assignment twice. Hence the "a=a=...".
Discussion
- [UPDATE] This problem *does not* occur with the latest stable version (revision 706), at least with this test function. So it may have been already fixed.
- Fixed in a prior release.
