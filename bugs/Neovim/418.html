Title

C++ indenting does not respect cinoptions 'N' flag with inline namespaces

Description
### Neovim version (nvim -v)

v0.6.0-dev+4c4353c32-dirty

### Vim (not Nvim) behaves the same?

yes, vim 8.2

### Operating system/version

macOS, Linux 5.x

### Terminal name/version

Alacritty, Windows Terminal (WSL) 1.11.3471.0, Linux console

### $TERM environment variable

xterm-256color, linux

### Installation

built from source

### How to reproduce the issue

(Note: I don't recall the full set of commands/options to enable syntax highlighting/filetype plugins, so insert those into this list of steps as appropriate.)
```
nvim --clean
:set ft=cpp
:set cindent
:set cinoptions=N-s
```

Now insert `namespace X {` and press enter--the cursor will correctly be positioned at the very beginning of the next line and not after an indent. This is the expected behavior.

However, if you insert `inline namespace X {` and press enter, the cursor will be placed on the next line indented like any other block (exact amount depends on your shift width and whatnot, but some indent should be present).


### Expected behavior

Following the steps above, the new line after the opening `{` of the inline namespace should not be indented. Essentially, the output should look like this after pressing the enter key:

### Actual behavior

The namespace is indented, contrary to the settings specified in `cinoptions`. The actual result looks like this (note that in this screenshot the trailing whitespace is highlighted in red and indicated with a +, and I indent with two spaces):
