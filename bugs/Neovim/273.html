Title

when using shada, Neovim slow to exit and makes a large amount of irrelevant IO calls before exiting

Description
### Neovim version (nvim -v)

0.9.0

### Vim (not Nvim) behaves the same?

no VIM - Vi IMproved 8.1 (2018 May 18, compiled Sep 19 2022 04:59:57)

### Operating system/version

Ubuntu 20.04

### Terminal name/version

alacritty 0.9.0

### $TERM environment variable

alacritty

### Installation

ppa:neovim-ppa/unstable

### How to reproduce the issue

Vim sometimes slow to close when there are other instances or recent instances that have opened files that are mounted through `sshfs`, even though I am not currently opening any files on `sshfs`.

1. mount some slow devices, e.g. using `sshfs` for remote servers that are physically locate thousands of kilometers away so that they have bad ping
2. open some files with nvim on the slow device
3. open a new instance of nvim, without opening any files, and try to close it quickly.

Please note: since this problem has to do with shada, I could not use `nvim --clean` (which disabled shada).

### Expected behavior

The Neovim that was opened in the last step should close quickly since I haven't opened any files with it so it should not be making any reads and writes. I don't really see any reason why it should touch the other files in the `shada` since I haven't opened any files in my current session.
