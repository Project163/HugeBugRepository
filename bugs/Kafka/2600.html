Title

ProducerBatch.split takes up too many resources if the bigBatch is huge

Description
ProducerBatch.split takes up too many resources  and might cause outOfMemory error if the bigBatch is huge. About how I found this issue is in  [URL]

 Following is the code which takes a lot of resources. 

  
 
  for  (Record record : recordBatch) {
             assert  thunkIter.hasNext();
            Thunk thunk = thunkIter.next();
             if  (batch ==  null )
                batch = createBatchOffAccumulatorForRecord(record, splitBatchSize);

             // A newly created batch can always host the first message.
              if  (!batch.tryAppendForSplit(record.timestamp(), record.key(), record.value(), record.headers(), thunk)) {
                batches.add(batch);
                batch = createBatchOffAccumulatorForRecord(record, splitBatchSize);
                batch.tryAppendForSplit(record.timestamp(), record.key(), record.value(), record.headers(), thunk);
            }
 
  

 Refer to RecordAccumulator#tryAppend, we can call closeForRecordAppends() after a batch is full. 

  
 
     private  RecordAppendResult tryAppend( long  timestamp,  byte [] key,  byte [] value, Header[] headers,
                                         Callback callback, Deque<ProducerBatch> deque,  long  nowMs) {
        ProducerBatch last = deque.peekLast();
         if  (last !=  null ) {
            FutureRecordMetadata  future  = last.tryAppend(timestamp, key, value, headers, callback, nowMs);
             if  ( future  ==  null )
                last.closeForRecordAppends();
             else 
                 return   new  RecordAppendResult( future , deque.size() > 1 || last.isFull(),  false ,  false );
        }
         return   null ;
    }
