Discussion
- I've ran into the exact same problem earlier. Running the ng build command with --verbose showed a lot of warnings and errors on the TerserPlugin part of the build. 

Eventually I stumbled upon this issue: [Link: Issue 13939]
This comment in specific was what I needed to get it fixed: [Link: Comment]

By default the memory limit in Node. js is 512 mb, to solve this issue you need to increase the memory limit use command —- max-old-space-size . 

I've added the following line to my package.json
`"ng-high-memory": "node --max_old_space_size=1024 ./node_modules/@angular/cli/bin/ng",`

From the comment on [Link: Issue 13939] :
- That is not solution, that is hack :D. If someone can answer if this is a bug inside angular?
- ... [Middle Discussions Snipped for Brevity] ...
- Another small update. When you set the `optimization` to true, but you set the `buildOptimizer` to false, the bundling and localize works and you do get a minified bundle with the terser plugin (because that still spits out a great amount of warnings), with the proper localization. So it seems like the issue is in the build optimizer. Personally I don't know what the difference is between the two settings, apart from that the buildOptimizer uses the `@angular-devkit/build-optimizer` package. Reverting to version 0.900.0 of this package doesn't help.
- This line in your output:

```
I18N_0 = "The actual string that's inside the i18n tag";
```

Is after the compile-time translation has occurred, which removes the `$localize` call and just leaves the translated (or not in this case) text.
