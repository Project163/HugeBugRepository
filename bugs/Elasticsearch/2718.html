Title

CCS requests to disconnected cluster all wait for a connection timeout

Description
**Description of the problem including expected versus actual behavior**:

Today when sending a request to a remote cluster we first ensure that the remote is connected:

[URL]

If we don't have an open connection then this code attempts to open one. If the remote cluster is partitioned away then this attempt will time out (after 30s I believe) at which point the response handler receives the failure. If we attempt to send multiple requests to the remote cluster in sequence then these timeouts stack up, potentially resulting in many minutes of delay for the overall request.

This behaviour is ok for CCR, but a 30s delay in a cross-cluster search seems less acceptable, especially if the remotes are configured with `skip_unavailable: true`. I think it would often be preferable to fail search requests to disconnected clusters immediately instead.

**Steps to reproduce**:

 1. Establish a remote-cluster connection between two clusters (optionally with `skip_unavailable: true`)
 2. Introduce a black-hole-style network partition between the clusters
 3. Perform a cross-cluster search and observe that each search takes 30s to fail.
