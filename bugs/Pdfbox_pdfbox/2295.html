Title

PDFBOX-3531 has re-appeared when trying to use  "sun.java2d.cmm.kcms.KcmsServiceProvider" in JAVA 1.8_222

Description
PDFBOX-3531   has re-appeared when trying to use  "sun.java2d.cmm.kcms.KcmsServiceProvider" in JAVA 1.8_222 
	 It looks like lcms is loading even though we have specified sun.java2d.cmm to use Kcms. 
	 Not sure if the unofficial flag doesn't work anymore
Discussion
- Suggested fix is check if KCMS really exists as done in PDFRenderer.java 

 /pdfbox/src/main/java/org/apache/pdfbox/pdmodel/graphics/color/PDICCBased.java 

   
  
 
     private   static   boolean  IS_KCMS;
     static 
    {
            String  cmmProperty =  System .getProperty( "sun.java2d.cmm" );
           IS_KCMS =  false ; 
            if (!isMinJdk8() ||
             "sun.java2d.cmm.kcms.KcmsServiceProvider" .equals(cmmProperty))
           {
                try 
               {
                       Class .forName( "sun.java2d.cmm.kcms.KcmsServiceProvider" );
                      IS_KCMS =  true ;
               }
                catch (ClassNotFoundException e)
               {
                       // KCMS not available
                }
         }
   }
- OK, I got it, in PDICCBased.java not just check wether KCMS is set, but also check whether KCMS exists. Makes sense.
