Title

WireGuard: doesn't create `.mitmproxy` folder if it doesn't exist yet

Description
#### Problem Description

Using `mitmdump --mode wireguard` on a fresh system doesn't work.

```
[17:36:42.295] WireGuard server failed to listen on *:51820 with [Errno 2] No such file or directory: '/home/alex/.mitmproxy/wireguard.conf'
```

I think if more parts of mitmproxy start using `confdir`, we need to ensure it exists in a central place and not in `certs.py` (or whatever creates it right now).

#### Steps to reproduce the behavior:

Docker masks this issue because the entry point uses `mkdir`. But if you run the image directly it repros. Also repros on my Ubuntu by simply deleting `.mitmproxy` (or I renamed it to `._mitmproxy` for a quick test).

1. `docker run --rm -it mitmproxy/mitmproxy:9.0.1 bash`
2. `mitmdump --mode wireguard`

```
[16:38:27.663] WireGuard server failed to listen on *:51820 with [Errno 2] No such file or directory: '/root/.mitmproxy/wireguard.conf'
```

Running `mitmdump` once, closing it, and then running `mitmdump --mode wireguard` works.
