Title

`no-remote` and `no-remote-cache` are affecting the disk cache

Description
### Description of the problem / feature request:

When an action is tagged with `no-remote` or `no-remote-cache`, it's not properly using the disk cache. Only with `no-cache` should it exclude the disk cache as well.

### Bugs: what's the simplest, easiest way to reproduce this bug? Please provide a minimal example if possible.

```shell
bazel build --disk_cache=/tmp/disk_cache -- //some/cacheable:target
bazel clean
bazel build --disk_cache=/tmp/disk_cache --modify_execution_info='.*=+no-remote-cache' -- //some/cacheable:target
```

The second build won't check the disk cache.

### What operating system are you running Bazel on?

macOS 11.4

### What's the output of `bazel info release`?

4.1.0, but is still broken at HEAD.
Discussion
- For the given repro, the second build missed the cache because the `actionKey` is changed - adding `no-remote-cache` [Link: changes]  field `do_not_cache` of `Action` message from `false` to `true`. I am not sure what's the expected behavior here.

However, we do expect the second build hit the disk cache if the first build has the same flag `--modify_execution_info='.*=+no-remote-cache'`. The culprit is that we doesn't upload the AC to disk cache due to the [Link: check in the upload code] checked `do_not_cache` field is `true` which is obviously wrong in this case.
- Seems to me that `do_not_cache` shouldn't be part of the `actionKey`.
