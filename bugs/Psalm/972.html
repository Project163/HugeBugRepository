Title

Template params, string callable functions, and namespaces

Description
I'm attempting to use `@template` with `callable` like this:

```
php
/**
 * @template T
 * @param callable(): (T|Throwable) $get_resource
 * @param callable(T): Result $action
... [Log Snipped] ...
    };
}
```

In use, I expect that if the `$get_resource`'s `T` does not match `$action`s `T` then a type error will be raised.

**If no `namespace` is used**, then an `InvalidArgument` is [Link: correctly raised]:

```
/**
 * @param OtherThing $thing
 * @return Result
 */
function execute( $thing ) {
... [Log Snipped] ...
    'execute'
);
```

The error as I expect:

```
ERROR: InvalidArgument - 30:1 - Type OtherThing should be a subtype of Thing
```

### The Problem

If a `namespace` is used, [Link: the error disappears].

I would expect the same error:

```
ERROR: InvalidArgument - 32:1 - Type Hello\OtherThing should be a subtype of Hello\Thing
```

But there is no error.
Discussion
- In your second example, you refer to the function as `Hello\execute` **from within** `Hello` namespace - so you're actually calling `Hello\Hello\execute` which does not exist: [URL]

When this is fixed, Psalm correctly reports the issue: [URL]
- Actually string callables need to be fully qualified (I was wrong above): [Link: works], [Link: fails].

**So the bug on Psalm's part is that it qualifies string callables, but it should not.**
