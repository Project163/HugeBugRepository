Title

'future' & 'experimental' keys are set to required in type `NextConfig` whereas they're supposed to be optional

Description
### What version of Next.js are you using?

10.2.3

### What version of Node.js are you using?

12.16.3

### What browser are you using?

Chrome

### What operating system are you using?

macOS

### How are you deploying your application?

Vercel

### Describe the Bug

I'm using [URL] to get type checking on `next.config.js`. The type `NextConfig` does not have 'future' & 'experimental' key as optional, so I had to set them to `{}` even when I don't want to use 'future' & 'experimental'

But `next build` shows a warning `Experimental features are not covered by semver, and may cause unexpected or broken application behavior. Use them at your own risk.` because the condition in [Link: config.ts] does a simple check which always turns to true as it compares `{}` to `defaultConfig.experimental`

This is causing unnecessary startle when seeing the console during a build 😅

### Expected Behavior

type `NextConfig` should have 'future' & 'experimental' as optional. So we can skip having 'future' & 'experimental' in `next.config.js` when it's not needed.

### To Reproduce

Add the following to `next.config.js` in a typescript project and run `next build`

```
// @ts-check

/**
 * @type {import('next/dist/next-server/server/config').NextConfig}
 **/
... [Log Snipped] ...

module.exports = nextConfig
```
