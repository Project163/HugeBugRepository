Title

Routing: Spread segments can match in the middle of another segment

Description
**Describe the bug**
Routes with `[...spread]` segments can match in the middle of another segment, without needing a `/` to match. In my repro linked below, I have a `src/routes/foo/[...rest]/index.svelte` route. This matches `/foo/one/two` as expected, with `rest` having the value `'one/two'`. But it *also* matches `/food/one/two`, with `rest` getting assigned the value `'d/one/two'`. I believe that the latter match is a bug.

The other buggy route match in my repro is the route `src/routes/[dynamic]-bar/[...rest].svelte`. This correctly matches `one-bar/two/three`, with `dynamic` being assigned `'one'` and `rest` being assigned `'two/three'`. But it *also* matches `one-bard/two/three`, with `dynamic` being assigned `'one'` and `rest` being assigned `'d/two/three'`. The latter match is, IMHO, a bug.

**Logs**
Server-side console logs produced by `pnpm run dev` and loading the four routes in my repro:
```
js
{
  host: 'localhost:3000',
  path: '/foo/one/two',
  query: URLSearchParams {},
... [Log Snipped] ...
  params: { dynamic: 'one', rest: 'd/two/three' }
}
```

Browser console logs contain exactly the same info.

**To Reproduce**
Clone [URL] run `pnpm i` then `pnpm run dev`, then open [URL] and follow the links to see the issue.

**Expected behavior**
The `/food/one/two` and `/one-bard/two/three` routes should have not matched; instead of matching, they should have returned a 404.
