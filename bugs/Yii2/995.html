Current behavior is like that on purpose and there's a test for it in `ViewTest.php`:

```
php
// The timestamp setting won't be redefined because global AssetManager is used
$view = new View();
$view->registerJsFile('/assetSources/js/jquery.js', [
    'appendTimestamp' => true,
... [Log Snipped] ...
$html = $view->render('@yiiunit/data/views/layout.php', ['content' => 'content']);
$this->assertNotRegExp($pattern, $html);
```

Similar for CSS.

The reasoning was that while script itself changes, dependencies are likely static and to be cached. That's why options of individual script / CSS aren't propagated and instead use either config of the asset bundle itself or asset manager config.

Thank you for contributing but won't merge the pull request:

1. The behavior is correct one for some valid cases.
2. It is configurable.
3. It's covered by tests so changing it is a backwards compatibility break for the functionality developers may rely on.
