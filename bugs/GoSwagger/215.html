Title

Missing required validation for property referencing string

Description
## Problem statement

The generated server code does not enforce a property to be required when it references a definition of type string. However, Swagger UI correctly shows the property to be required.

## Swagger specification

bug.yaml:
```
yaml
---
swagger: "2.0"
info:
  version: 0.1.0
... [Log Snipped] ...
  my_string_ref:
    type: string
```

## Steps to reproduce

```console
swagger generate server -f bug.yaml
```

In `models/my_object.go` can be seen that the validation methods require `required_string` and `required_referenced_object` but not `required_referenced_string`.

```
go
// MyObject my object
//
// swagger:model my_object
type MyObject struct {
... [Log Snipped] ...
	return nil
}
```

The validation on `MyStringRef` is a noop:

```go
// Validate validates this my string ref
func (m MyStringRef) Validate(formats strfmt.Registry) error {
	return nil
}
```

`MyObjectRef` does not even have a `Validate` method.

## Environment
swagger version: v0.25.0
go version: 1.14.3
OS: macOS 10.14.6
Discussion
- There is a bug in the following part:
```
go
func (m *MyObject) validateRequiredReferencedString(formats strfmt.Registry) error {

	if err := m.RequiredReferencedString.Validate(formats); err != nil {
		if ve, ok := err.(*errors.Validation); ok {
... [Log Snipped] ...
	return nil
}
```
which should include a call to "Required". The rest of the generated code behaves as expected.
