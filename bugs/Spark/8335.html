Title

Fix ColumnVectorUtils.populate to handle CalendarIntervalType correctly

Description
`ColumnVectorUtils.populate()` does not handle CalendarInterval type correctly -  [URL] . The CalendarInterval type is in the format of (months: int, days: int, microseconds: long) ( [URL] ). However, the function above misses `days` field, and sets `microseconds` field in wrong position. 

   

 `ColumnVectorUtils.populate()` is used by Parquet ( [URL] ) and ORC ( [URL] )vectorized reader to read partition column. So technically Spark can potentially produce wrong result if reading table with CalendarInterval partition column. However I also notice Spark explicitly disallows writing data with CalendarInterval type ( [URL] ), so it might not be a big deal for users. But it's worth to fix anyway. 

   

 Caveat: I found the bug when reading through the related code path, and I don't have experience in production for partition column with CalendarInterval type. I think it should be an obvious fix unless anyone more experienced could find some historical context. The code was introduced a long time ago where I couldn't find any more info why it was implemented as it is ( [URL] )
