Title

@import (inline) "file.css" puts the inlined css at the top of the output

Description
Take the following less file, call it `everything.less`:

```
@import "bootstrap/less/bootstrap.less";
@import (inline) "perfect-scrollbar/src/perfect-scrollbar.css";
@import "my-app.less"
```

Compile it with `lessc everything.less everything.css`.

Look at the generated `everything.css`.

I would expect it to contain bootstrap's CSS, followed by the contents of `perfect-scrollbar.css`, followed by my app's CSS.

Instead I see perfect-scrollbar's CSS, followed by bootstrap's CSS, followed by my app's CSS.

This can break stuff when the order of the CSS rules matters (which doesn't seem to be the case with the specific example of bootstrap + perfect-scrollbar.css, but is the reason why I had to rename `my-app.css` to `my-app.less` as a workaround).
Discussion
- yep, would seem a valid bug. I think its because normal css imports get floated to the top and it seems to be doing that even though it is inline.
- This was fixed by the merged pull request.
