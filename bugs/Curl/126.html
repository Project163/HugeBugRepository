Discussion
- I should add that this is the CI-Fuzz job that crashes and the link shows it crashed for an unrelated PR. Reproducing the exact same crash is probably a little cumbersome.
- Is there some other signaling that the nghttp2 session has already been closed? I notice that most of the other checks in the method check the stream_id as well.
- I spent some time looking at this, but didn't find a codepath that leads to this state.

So instead I reconsidered where I had added the connclose() call:

curl signals that data is available to the nghttp2 protocol library by calling nghttp2_session_mem_recv(). Instead of checking at http_done, instead we can check whether the server has requested a connection be closed after the mem_recv() call, since that's the only place where the state changes.

So I reviewed all the mem_recv() calls. It turns out that there were 3 codepaths, all similar, but also different.
I consolidated them to use the existing h2_process_pending_input() method.
