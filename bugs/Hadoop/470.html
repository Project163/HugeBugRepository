Title

When copying a file out of HDFS, modifying it, and uploading it back into HDFS, the put fails due to a CRC mismatch

Description
Performing an hdfs -get on a file, modifying the file, and using hdfs -put to place the file back into HDFS results in a checksum error.  It seems that the problem is a .crc file being generated locally from the -get command even though the -crc option was NOT specified.
Discussion
- It is due to the change in the default behavior. FsShell for some reason now creates CRC files (.<filename>.crc) in the local file system by default. Unaware of existence of the .filename.crc, users can modify files stored in the local file system and make the CRC invalid. The default behavior needs to be reverted back to ingnoreCrc.
- Actually ignoreCRC is for disabling checksum verification. CRC copying needs to be disabled by default when -crc is not specified.
