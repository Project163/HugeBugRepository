Title

_schema always cleared out for DataSource classes that have listSources

Description
I have written a custom data source that doesn't have schema information (it is a file based data source).  So I specified the _schema in each of the models that use the data source.  The data source extends the DataSource class in Cake/Model/Datasource/DataSource and I've overridden the listSources function to return null (as the book says [URL]

When I run a test for my model, it fails because _schema is empty.  Going through Cake's code, I found that setSource is always being called in the test because it switches to a test datasource (which I've setup).  Since my DataSource has the method listSources, it always sets _schema to null.

There needs to be a way to prevent it from setting _schema to null.  I want to extend the DataSource class so I have to implement listSources (since it implements it).  Maybe the setSource function should check to see if the result is null and if it is, it shouldn't set _schema to null?

For now, I've worked around this by overridding the schema() method and hardcoded the schema inside of that method.
Discussion
- I think only emptying the _schema if the source list was truthy makes sense.
