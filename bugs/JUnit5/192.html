Title

Cannot provide multidimensional array as argument with `@MethodSource`

Description
## Overview

I am attempting to pass two-dimensional arrays of primitives to a parameterized test. The one-dimensional array works as expected, but JUnit complains on the second with "Error resolving parameter at index 0". This is on JUnit Jupiter 5.1.0.

[Link: According to Sormuras], on `5.4.0-SNAPSHOT`, the error message reads: `org.junit.jupiter.api.extension.ParameterResolutionException: Error converting parameter at index 0: No implicit conversion to convert object of type [I to type [[I` 

see the snippet below

## Steps to reproduce

```
java
// This is ok
static Stream  arrayStream1(){
    return Stream.of( new int[] {1}, new int[] {2});
}
... [Log Snipped] ...
    assertTrue(true);
}
```

## Context

 - Used versions (Jupiter/Vintage/Platform): JUnit 5.1.0
 - Build Tool/IDE: Eclipse 4.9.0

- FWIW, my _fix_ on the feature branch does in fact support the failing use case described in this issue.

However, it also brings to light some oddities with regard to support for Object and primitive arrays.

1. If you have a factory method that returns `Stream `, that will **NOT** allow you to have a `@ParameterizedTest` method that accepts a single `Object[]` argument.
   - Rather, if the lengths of the arrays are at least 2, that would require a `@ParameterizedTest` method with a signature of `test(Object, Object)`, `test(String, int)`, or similar.
2. If you have a factory method that returns `Stream `, that **WILL** allow you to have a `@ParameterizedTest` method that accepts a single `int[]` argument.
   - And that was the case before my _fix_.
- @junit-team/junit-lambda, this is one of the points we need to decide on: what is actually "expected" here with regard to the previous points I made.
