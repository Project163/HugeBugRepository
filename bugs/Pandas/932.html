Title

API/BUG: SparseSeries.shape ignores fill_value

Description
`SparseSeries.shape` seems to return incorrect result ignoring shapes filled by `fill_value`.

```
s = pd.SparseSeries([0, 0, 1, 0], fill_value=0)
s
#0    0
#1    0
#2    1
... [Log Snipped] ...
s._data.shape
# (4,)
```
Discussion
- This refers to the shape of the sparse values, not the shape of the series itself. 

```
In [19]: s._data.blocks[0].sp_values
Out[19]: array([1])

In [20]: s._data.blocks[0].sp_values.shape
Out[20]: (1,)
```
- I see. This is a spec and not be fixed?

May be a option to fix docstring to say `underlying` means sparse values.

```
help(pd.SparseSeries.shape)
# return a tuple of the shape of the underlying data
```
- I don't remember where exactly this is used and whether its just user-facing. If its user facing only, then it _should_ be consistent and return the shape of a densified frame, and we should have a `sparse_shape` or something. I am not sure what this really should do. If you want to experiment and report back would be gr8.
