Title

doctest-modules with NUMBER option ignores zero decimal precision

# Description
This was found in [URL]  Using NUMBER option causes zero-precision numbers to pass when the numbers are off by 1 by not by 2.  Also using NUMBER option in a module causes this behavior to leak out into other docstring tests that do not use NUMBER.  Not using NUMBER correctly fails the tests.

Thanks to @adeak who identified the off by 1 but not by 2 aspect of this.


Using commands `pytest --doctest-modules test_1.py` and `pytest --doctest-modules test_2.py`.

Discussion
- This also occurs if the numbers aren't inside a list, e.g.

```py
def number():
    """
    Passes.

    Examples
    --------
    0.
    """
- I've found that it uses `approx` under the hood [Link: here] which means that it can be off by one in this case.  The description of `NUMBER` makes it sound like it should be more like a string comparison that ignores the extra precision.
