Title

ZAP should ensure response in base message before passing them to scanners

Description
The base message in scanners might not contain a response (getBaseMsg().getResponseHeader().isEmpty() returns true), which will lead to FPs.

ZAP should ensure that the messages have a response before passing them to scanners. If not it should send a new request and use that as base message.

Noticed in pull request [URL] by @thc202 (see [URL]

If the issue is fixed it would be recommandable to ensure that all active scanners won't do the same check (i.e. [URL]
Discussion
- Do you have any examples where this happens?
- The messages with empty responses are the "temporary" messages created for the Sites tree. An example that would lead to FP is the scanner TestUserAgent since it was comparing the responses using the base message, although there are other scanners [Link: 1] [2] that are sending the original request to obtain the response (which shouldn't as that might modify the original request).
The passive scanner ignores the temporary messages, maybe it should happen the same with active scanner? The user would have to explicitly access those pages to have them scanned though.
