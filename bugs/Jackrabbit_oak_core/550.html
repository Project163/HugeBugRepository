Discussion
- It would appear that there are some versioning related concerns if we use 'nt:unstructured' so what other options are there?
- as suggested earlier in other issues i would suggest to define a specific node type for such repository internal content that might the also be used for hidden content and so forth... something like 

  
 rep:Unstructured
  - * (UNDEFINED) IGNORE
  - * (UNDEFINED) multiple IGNORE
  + * (nt:base) IGNORE (or maybe ABORT would be even better)
 
  

 i will create an improvement issue to discuss the creation of that node type. in the mean time you may fix the issue by using nt:unstructured. hope that works for you and doesn't block you from fixing this issue.
- Fixed in revision 1544280 with  nt:unstructured . We use the same type also for  /jcr:system/rep:namespaces . 

 I don't see any particular reason to worry about versioning behavior here.
