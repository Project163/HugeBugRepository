Title

Expiry strategy improvement request for DefaultDnsCache

Description
### Expected behavior
Hostname configured with both IPv4 and IPv6 dns records. Netty dns resolver is configured to prefer IPv4 addresses, so I should always get IPv4 address.

### Actual behavior
but after several minutes run, it can only return ipv6 record.

### Steps to reproduce
Create a NettyDns resolver with DefaultDnsCache, and keep it running for several minutes. You can see finally only ipv6 record can be got.


### Minimal yet complete reproducer code (or URL to code)
the url have the issue is "mirrors.servercentral.com"

### Netty version
4.1.15.Final

Discussion
- The root cause for this issue if the expire strategy of the DefaultDnsCache. The DefaultDnsCache controls the expiry per record, and remove the record from the list if the record is expired. In this case, the ipv4 record ttl is 60, while the ipv6 record ttl is 21599. 

So, ipv4 record will surely be expired before ipv6 record. And ipv6 record is still recorded in DefaulDnsCache, so query the DefaultDnsCache can still get the record for the URL with the ipv6 record.  

But as mentioned above, we are expecting the ipv4 record.

I am not sure what is the strategy used by InetAddress, but the Java resolver does always prefer ipv4 address every resolving.
