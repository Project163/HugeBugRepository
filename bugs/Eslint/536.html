Title

`object-shorthand` and `quote-props` have incompatibilities

Description
``` bash
$> eslint -v
v1.2.1
```

My `.eslintrc`:

```
json
{
  "ecmaFeatures": {
    "objectLiteralShorthandProperties": true
  },
... [Log Snipped] ...
  }
}
```

The code:

``` javascript
var x = true;
({
  x,
  'needs-quote': true
});
```

Running `eslint` gives the following output:

``` bash
index.js
  2:2  error  Inconsistently quoted property `needs-quote` found  quote-props
```

Changing the code to:

``` javascript
var x = true;
({
  'x': x,
  'needs-quote': true
});
```

Will instead give the error:

``` bash
index.js
  3:3  error  Expected property shorthand  object-shorthand
```

So there's a Catch-22 between these two rules. I could of course rename the `x` variable to something else, but I would prefer to be able to use the object property shorthand syntax even when I have `"consistent"` or `"consistent-as-needed"` for the `quote-props` rule.

What do you think? I could probably solve this myself and submit a PR but the question is what's actually the best solution for this? Or maybe you're of the opinion that this is by design and the rules should really be incompatible when using this combination of options?
Discussion
- I think you need to drop `object-shorthand` and use `"consistent-as-needed"` option for `quote-props`.
- Thank you for the report.

I think this is a bug of `quote-props`.
This rule should ignore computed/shorthand properties.

``` js
/* eslint-env es6 */
/* eslint quote-props: [2, "always"] */
var x;
var obj = ({
    [x]: 0,
    x
});
```
