Title

Rules: `semi-spacing` and `block-spacing` conflict on one-liner functions

Description
With the following rules, there is no way to have a function in one line without a conflict between the 2.

```
js
// eslint v1.3.1
/*eslint "semi-spacing":2*/
/*eslint "block-spacing":[2, "never"]*/
var fnArr = [
... [Log Snipped] ...
  }
]
```

Is there a way to have both rule and a function declaration in one line ?
Discussion
- Hmm, we need to figure out how to clean that up. I'm not sure how at the moment.
- I just saw a similar issue with `space-in-parens`
where 
`for(let i = 0; i < results.length;) {` is invalid because of `semi-spacing` and
`for(let i = 0; i < results.length; ) {` is invalid because of `space-in-parens`
The only valid case is 

``` js
for(let i = 0; i < results.length; 
) {
```
- So, should `semi-spacing` be skipped if the next token is a closing paren (`)`, `}`, `]`)?
- That might be the solution. We'd have to update the docs to reflect that as well.
