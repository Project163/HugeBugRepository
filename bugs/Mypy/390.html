Title

False negative in incremental mode

Description
We don't yet fully understood this, but @msullivan and I observed the following:

- the code was of the form `assert x.y.z ==  `
- the expected error was of the form `Item "None" of "Optional[Y]" has no attribute "z"`
- the type of `x.y` was inferred from a method `f() -> Optional[Y]`
- previously, `f` (defined in a different file) did not have an annotation
- the file with the error was not modified

Apparently the cache for the file with the error was considered up-to-date, and not dependent on the file where `f` was defined. It's possible that interface hash calculation is at fault.
Discussion
- I've produced a small reduced test case, but haven't started debugging the failure yet:
```
[case testIncrementalStrictOptionalInheritance]
# flags: --strict-optional
import a
[file a.py]
import b
... [Log Snipped] ...
[out2]
tmp/a.py:3: error: Unsupported operand types for + ("int" and "Optional[int]")
```
Instead of the error, we produce no message.
If `a` uses `Baz` directly, if `Bar` is defined in `a`, or if the original version of `get` is annotated---either with `int` or with `Any`---then we pass the test.
- It appears that b's interface hash is not updated when `Bar`'s base class changes.
- ... [Middle Discussions Snipped for Brevity] ...
- Here is a very related test case that also fails:
```
[case testIncrementalLotsOfInheritance]
import a
[file a.py]
from b import B
from d import D
... [Log Snipped] ...
[out2]
tmp/a.py:5: error: Argument 1 to "take" has incompatible type "B"; expected "D"
```

The problem in both of these cases is that we fail to detect the indirect dependencies that `a` has on `c` (which we *do* correctly do if `get` is annotated in the first test). We shouldn't need `b`'s interface hash to change if the indirect dependencies are properly calculated.

In the first test case, we fail to detect the indirect dependencies because the `CallableType`s assigned to unannotated methods lack a `definition` field, so `TypeIndirectionVisitor` can't find that it is defined in `C`.

To get the second test case right, `a` needs to indirectly depend on every class in `Baz`'s mro, so that it can detect mro changes. Doing this also fixes the unannotated method failure.
- (I think this is important, so I set priority to high.)
