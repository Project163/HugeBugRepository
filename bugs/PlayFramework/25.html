Title

Play routes compiler incompatible with globally defined sbt-idea plugin

Description
The play routes compiler now has a dependency on commons-io 2.4.  If a sbt-idea is defined as a global plugin, this causes the routes compiler to fail with:

```
java.lang.NoSuchMethodError: org.apache.commons.io.FileUtils.writeStringToFile(Ljava/io/File;Ljava/lang/String;Ljava/nio/charset/Charset;)V
    at play.router.RoutesCompiler$$anonfun$compile$1.apply(RoutesCompiler.scala:315)
    at play.router.RoutesCompiler$$anonfun$compile$1.apply(RoutesCompiler.scala:314)
        ...
```

The reason for this is that it seems that sbt creates a classloader that contains just the globally defined plugins, and then for the project build, it creates another classloader, which also includes the globally defined plugins, _and_ has the first classloader (with just the global plugins) as its parent.  Since sbt-idea depends on commons-io 2.0.1, that means commons-io 2.0.1 is in the parent classloader.  When the projects sbt project classloader is loaded, the 2.4 version of commons-io is never used, and thus the routes compiler, which uses methods from 2.4, fails.

I'm not sure if this is a regression in sbt or not, but it does seem like the wrong parent classloader is being used here.  Here's a dump of the classloaders (with not so relevant bits snipped).

First, here's the project classloader (this is from running `consoleProject` in sbt):

```

```

Discussion
- Work around is to add the following to `~/.sbt/0.13/plugins/build.sbt`:

```
libraryDependencies += "commons-io" % "commons-io" % "2.4"
```
