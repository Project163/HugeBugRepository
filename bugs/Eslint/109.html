Title

eqeqeq smart mode only allows `null` checks not `undefined` ones

Description
As the title says

`return Math.pow(10, precision == null ? 2 : precision);`

logs no errors but

`return Math.pow(10, precision == undefined ? 2 : precision);`

does. Is this intentional or a bug? Happy to make PR to fix this, I imagine it's trivial.

If it's intentional please close...and explain so I can make a PR to update the docs :)
Discussion
- Don't compare against `undefined`, since it's an identifier, so at worst it may be reassigned (in ES3) or shadowed and at best it requires a walk of the scope chain. `== void 0` would be acceptable, but why not just use `== null`?
- @briandipalma This is intentional. As @michaelficarra, it's usually not a good idea to compare against `undefined`, which is why people use `== null` to cover both cases. I'll leave this open as a documentation bug.
- Alright, makes sense. I should have a PR tomorrow for the doc.
- Nice to see it's now doced. I was afk so couldn't, thanks :)
