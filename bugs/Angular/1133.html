Title

ModuleWithProviders broken in v10.0.0-next.8

Description
# 🐞 bug report

### Affected Package
The issue is caused by package @angular/compiler-cli

### Is this a regression?

 
  Yes, the previous version in which this bug was not present was: 10.0.0-next.6 (maybe 10.0.0-next.7, skipped this one)

### Description

`ngcc` fails to compile the `NgModule.forRoot()` of my library.

Seems to be introduced by #36948 ([Link: commit])

## 🔬 Minimal Reproduction
1. `git clone [URL]
2. `cd angular-async-local-storage`
3. `git checkout ng10`
4. `npm ci`
5. `npm run build`
6. `npm run unit`

You can also see the error in this [Link: CI test].

Source code [Link: is here] (it's a very simple NgModule with a classic `forRoot()`).

## 🔥 Exception or Error
  
The identity given by StorageModule referenced in "static forRoot(config) {

                ngModule: StorageModule_1,
                providers: [...],
            };

Discussion
- I think that this is actually more likely due to the changes in TypeScript 3.9, which can now wrap ES2015 classes in an IIFE, which is what is happening to this class:

```
ts
let StorageModule = /** @class */ (() => {
    var StorageModule_1;
    let StorageModule = StorageModule_1 = class StorageModule {
        /**
... [Log Snipped] ...
    return StorageModule;
})();
```
- I will dig into why we are not matching `StorageModule_1` to the correct class declaration.
- Indeed it is a bug in the Es2105ReflectionHost changes to deal with IIFE wrapped classes.

The `StorageModule_1` identifier is declared as a `var` and so this is not picked up as the “alias declaration” of the “inner declaration”.

I’ll put together a fix tomorrow.
- Basically, when given the alias `StorageModule_1` the host is finding the inner class "expression" instead of the outer class "declaration".
