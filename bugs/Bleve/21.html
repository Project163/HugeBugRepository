Title

incorrect order of token filters in italian analyzer

Description
Reported on mailing list:

[URL]

The order of the token filters matches descriptions on the web, but does not appear to match their behavior in practice.  We should add a test case to reproduce this, then fix the order to ensure both inputs produce the same output.

Also, we should review the other analyzers using the elision filter for the same potential problem.

Elasticsearch output:

```
$ curl -s -XGET 'localhost:9200/_analyze?analyzer=italian' -d "nell'anfora" | jq .
{
  "tokens": [
    {
      "position": 1,
... [Log Snipped] ...
  ]
}
```
Discussion
- It turns out the order in which we have the filters is the same as Lucene.  However, in Lucene the Elision filter is using a CharArraySet with the "ignore case" property set to true.  In our implementation we are doing a case sensitive comparison.
- So, there are 2 options, we can enhance our TokenMap to support case-insensitive comparison.  This might be more useful in other places long term.  But, here it seems like its unnecessary and just a more expensive way of doing the same thing.

I checked, all 4 languages using the Elision filter use the ignoreCase option.  So, I think it makes sense to simply ensure that the lower_case filter is performed first.  Starting this change now.
