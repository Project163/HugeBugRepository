Title

Helm fetch untar needs conflict management

Description
Fetching and extracting charts to the local system does not currently warn the user when the chart name conflicts with an existing file or directory. Instead it has ambiguous behavior depending on the conflict.

Two ambiguous conflicts:

1. File exists in `$PWD` with same name

   Download fails with error message
   ```
   $ echo test > velero
   $ helm fetch stable/velero --untar
   Error: open velero/Chart.yaml: not a directory
   $ cat velero 
   test
   ``` 

2. Directory exists in `$PWD` with same name

   Download succeeds but gets merged into existing directory

   ```
   $ mkdir velero
   $ echo test > velero/test.txt
   $ helm fetch stable/velero --untar
   $ ls velero/
   Chart.yaml	OWNERS		README.md	ci		crds		templates	test.txt	values.yaml
   $ cat velero/test.txt 
   test
   ```

Output of `helm version`:

```
$ helm version --client
Client: &version.Version{SemVer:"v2.11.0", GitCommit:" ", GitTreeState:"clean"}
```

Output of `kubectl version`:

```
$ kubectl version --client
Client Version: version.Info{Major:"1", Minor:"14", GitVersion:"v1.14.8", GitCommit:" ", GitTreeState:"clean", BuildDate:"2019-10-15T12:11:03Z", GoVersion:"go1.12.10", Compiler:"gc", Platform:"darwin/amd64"}
```

Cloud Provider/Platform (AKS, GKE, Minikube etc.): 

AWS
Discussion
- I think we should stop the command immediately and show the error that a file or directory with that name already exists and that we cannot proceed further
- The same issue occurs even with helm v3

`version.BuildInfo{Version:"v3.0.1", GitCommit:" ", GitTreeState:"clean", GoVersion:"go1.13.4"}`

We can mark this as both v2 and v3 issue. 

I also see this as a bad UX as the error that shows up is not clear as to what's the problem when there's already a file in that name. 

And the latter - existing directory with same name, it's problematic as it's possible that user might not be aware that there's already a directory in that name and it's all getting merged. One such example is when let's say I'm trying out multiple versions of the same chart using untar 

```
$ helm fetch stable/redis --untar
$ ls redis
Chart.yaml              ci                      values-production.yaml  values.yaml
README.md               templates               values.schema.json
$ cat redis/Chart.yaml
```
