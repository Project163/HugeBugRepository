Title

Struggling to Pass Authentication Header that contains space (for API ZAP scan)

Description
Hi There,
I am trying to pass Authorization header as described here:
[URL]

However, my header must contain space i.e.`Bearer TOKEN_VALUE`
I noticed it seems that space is treated as end of value and my application receives only `Bearer ` 

```
./zap-api-scan.py  \
        -z "-config replacer.full_list(0).description=auth1 \
        -config replacer.full_list(0).enabled=true \
        -config replacer.full_list(0).matchtype=REQ_HEADER \
        -config replacer.full_list(0).matchstr=Authorization \
... [Log Snipped] ...
        -t [URL] \
        -f openapi -d
```
I think I need to escape space somehow so it is taken into account as value. I tried to use sinle quotes (') but it didn't work.
` -config replacer.full_list(0).replacement='Bearer $ACCESS_TOKEN'" \` resulted in exactly same behavior..
Discussion
- Right, escaping the space (or quote the `-config` value) would be the way to go but the script is not taking that into account (yet).
- Hi, I fixed it with the following workaround:

1. Generate token
```
ACCESS_TOKEN=YOUR_TOKEN_HERE
```
2. Store it in a props file (auth.prop) - 
```
BEARER_AUTH="Bearer "$ACCESS_TOKEN
echo $BEARER_AUTH

echo "----> Building prop file:"
echo  "replacer.full_list(0).description=auth1" >> auth.prop
... [Log Snipped] ...
echo  "replacer.full_list(0).regex=false" >> auth.prop
echo  "replacer.full_list(0).replacement=$BEARER_AUTH" >> auth.prop
```
3. call Zap
```
/zap-api-scan.py -z \"-configfile ./auth.prop"
```
