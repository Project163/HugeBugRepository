Title

RestClient reactive hangs forever when url is invalid

Description
### Describe the bug

When using the rest client with an invalid url example `http//localhost:8080` note the missing colon. Something makes the calls never return, and timeout values are also ignored. Using `@URL` from hibernate validator is a good way to catch it, but still I believe it should not hang.

In the reproducer I am using quartz scheduler as well. IN that case the app fully hangs and becomes totally unresponsive, it needs to be killed -9.

### Expected behavior

The invalid url should throw a runtime exception of something instead of making the app hang

### Actual behavior

The full application hangs and is not stoppable without killing it

### How to Reproduce?

Reproduder: [URL]

Steps to reproduce:
1. mvn quarkus:dev
2. app will hang you need to kill it.

To make it work;
1. in the application.properties change `http//localhost:8080` to `[URL]
2. mvn quarkus:dev
