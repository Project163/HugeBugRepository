Discussion
- if the constructor is internal, those tests are ignored. If it's public, it runs.
- There is a bug here, but it's not what you think it is.

The fix (for you) is simple: xUnit.net does not support test data attributes with internal constructors. Change the constructor to public, and the problem will go away. The test data class itself can remain internal.

The bug in xUnit.net is that it should be reporting an error for this test case because it violates the rule, but it does not; instead, it does not discover the test.

The secondary bug (which caused most of your confusion here, I think) is that the Resharper runner _**should never have discovered the test in the first place**_. Therefore, you should open an issue against the Resharper runner (at [URL] for this additional bug.
- The fix for this is to return a single (failing) test case which indicates the missing constructor. This may actually fix the Resharper issue, so you may not need to log an extra issue.
