Title

A SessionException is thrown (instead of a JMSException) when an error occurs during a commit.

Description
If the broker throws a session level exception, during or just before the client invokes a commit on a transaction, the JMS client throws a SessionException instead of a JMSException. 
This is due to the AMQSession_0_10.java not handing the SessionException. 

 (Please note this issue is only present in the 0-10 code path).
Discussion
- An easy way to reproduce the issue is to send x number of messages to Queue A in a transacted session, where the qpid.max_count for Queue A is x-1. This will cause the broker to throw an exception when a commit is issued for that transaction. 

 Another way to reproduce that issue is to start a two node cluster and kill the broker the client is connected just before a commit is issued.
- Attaching a reproducer created by Siddhesh Poyarekar.  

 To run the reproducer, 
1. Start a two node cluster 
2. run TxFailover and kill the broker (on port 5672) when the program prompts you to. 

 You can observe that the JMS client throws a SessionException instead of a JMSException
