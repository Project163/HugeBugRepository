Title

@CompileStatic(SKIP) throws an error

Description
If you annotate a class with @CompileStatic, then use @CompileStatic(SKIP) on a method, then calling that method throws an error. However, annotating each method separately with @CompileStatic works. 

 Example: 
  
  import  groovy.transform.CompileStatic
 import   static  groovy.transform.TypeCheckingMode.SKIP

@CompileStatic
 class  A {
    @CompileStatic(SKIP)
    void m() {}
}

 new  A().m()

Discussion
- Guillaume recommends I join the discussion on this issue, as I'm interested in whether @CompileStatic is sufficient for building Groovy-based Android projects – looking at the issue in detail, I don't think @CompileStatic(SKIP) is relevant to Android - where the goal is to avoid any dynamic recompilation - of course, "I am but an egg"
- Resolved by always generating the call site array. A better solution would be to check if the class is fully statically compiled. If we go that far, an even better solution would be to remove some of the MOP methods which are generated too and will never be used by the static version of a Groovy class.
- Perhaps worth creating a dedicated issue for a better fix?
- @Guillaume, sure, feel free to create one
