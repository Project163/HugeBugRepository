Title

conan package registry and header only packages

Description
### Description

Header only conan packages can generate an empty `conaninfo.txt`, due to

```py
def package_id(self):
    self.info.clear()
```

`gitea` is currently ignoring such files, which appears to be due to [URL] which breaks the `conan` client when trying to consume such packages:

```
tuplet/2.1.1: ERROR: Exception while getting package:  
tuplet/2.1.1: ERROR: Exception:   Corrupted tuplet/2.1.1:  in 'external' remote: no conaninfo.txt
ERROR: Corrupted tuplet/2.1.1:  in 'external' remote: no conaninfo.txt
```

Removing the above block in `conan.go` allows the empty `conaninfo.txt` to be stored in the registry, and the `conan` client works successfully.

Whether there are any other side effects of removing the check I couldn't say... seems OK so far though.
