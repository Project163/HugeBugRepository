Title

documentation for Keycloak authorization is insufficient

Description
**Describe the bug**
I've spent some time investigating usage of the `quarkus-keycloak-authorization` extension in the OpenShift context and found a few insufficiencies in the documentation. Specifically:

- [ ] 1. In OpenShift, the `/health` endpoint (and possibly also `/metrics`) must always be accessible. However, if I use `quarkus-keycloak-authorization`, it takes over the entire URL space, OpenShift can't reach the health endpoint and the application is never ready. (Yes, I always include health checks. If I omitted them, this wouldn't be a problem, but that's always a bad idea.) This behavior is probably correct from Keycloak perspective, but it took me a long time to figure out how to make my application work.

    I first tried to configure the Keycloak realm to let anyone and everyone access `/health/*`. But I wasn't able to figure out the correct Keycloak configuration. I'm certainly no Keycloak expert, for sure. Then, I spent some time in the debugger and in the end, I have found some undocumented configuration options that let me disable authz for the `/health` endpoint:

    ```properties
    quarkus.keycloak.policy-enforcer.enable=true
    quarkus.keycloak.policy-enforcer.paths.health.path=/health/*
    quarkus.keycloak.policy-enforcer.paths.health.enforcement-mode=DISABLED
    ```

    There should be a reference for all these additional options (unless they are not documented because the config shape is experimental and will change in the future, in which case I'd suggest something needs to be stabilized at least for the health check usecase). I'd also say there should be an example -- ideally with this exact usecase.

- [ ] 2. The documentation also says (https://quarkus.io/guides/security-keycloak-authorization#mapping-protected-resources) that `quarkus.keycloak.policy-enforcer.lazy-load-paths` defaults to `false`, which wrong. It clearly defaults to `true`: [URL] That documentation section should be rewritten.
