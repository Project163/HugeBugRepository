Title

Validation with "valueAs" and "setValueAs" behavior is different from documented

Description
**Describe the bug**
As stated in the doc:
[Image: image]
Using `validate` alongside with `setValueAs`, the value passed into the `validate` function turns out to be already processed with the `setValueAs` configuration as opposed to the doc which says the process happens after validation.

**To Reproduce**
Steps to reproduce the behavior:

1. Register an input with custom  `validate` and `setValueAs`
2. Fill in some input
3. See the value passed in the `validate` callback as processed from `setValueAs`

**Codesandbox link (Required)**
[URL]

**Expected behavior**
The value passed into the `validate` callback should be the raw version of it before being processed with `valueAs` or `setValueAs`

**Desktop (please complete the following information):**
- OS: macOS Catalina
- Browser: Chrome
- Version  87.0.4280.141

**Additional context**
As I looked through a code at this specific line
[URL]
I found that `fieldValue` is gotten as **processed** right of the bat before the real validation step starts.
