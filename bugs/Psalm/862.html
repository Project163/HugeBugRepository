Title

Return type with multiple inherited interfaces leading to type confusion

Description
When having multiple levels of "inheritance" Psalm seems to incorrectly apply the type hints - this is [Link: a simple example]:

```
php
interface NumberInterface
{
    public function getStatus(): string;
}
... [Log Snipped] ...
    }
}
```

Psalm gives the following error in this case:

    ERROR: LessSpecificImplementedReturnType - 18:34 - The inherited return type 'string(assigned)|string(external)|string(fragmented)|string(free)|string(locked)|string(parent)|string(ported)' for NumberInternalInterface::getStatus is more specific than the implemented return type for NumberInternal::getstatus 'string'

If you move the `@psalm-return` to the `NumberInterface` instead of the `NumberInternalInterface`, the error still stays the same, so the problem seems to be that there are multiple levels of inheritance.

When only one interface in the example is used, it works without an error, as seen [Link: in this example]:

```
php
interface NumberInternalInterface
{
    /**
     * @psalm-return "free"|"assigned"|"locked"|"ported"|"parent"|"fragmented"|"external"
... [Log Snipped] ...
    }
}
```

This reports no issues, as expected.
Discussion
- Slightly simpler-to-parse example:

```
php
class A {}
class AChild extends A {}

interface IParent {
... [Log Snipped] ...
    }
}
```
- The return type of Concrete in your example is probably wrong though, should be:

```php
class Concrete implements IChild {
    public function get(): A {
        return new AChild;
    }
}
```

Otherwise psalm will probably complain about it not being the advertised AChild as specified in IChild when this bug is fixed :-)
