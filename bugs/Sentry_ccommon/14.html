Title

Rename sentry property to provide the list of sentry servers

Description
Starting with Sentry 2.0, we start to support HA and thus the need to provide a comma separated list of sentry servers in the configuration. It is better to use a new property name for this. (Note: This breaks the compatibility with older 1.x Sentry releases)
Discussion
- I think that we should still understand old property if the new one isn't set and the old one is. Something like 

  
      if  (newProperty.isAvailable()) { use it }
     else  { use old one }
- For the fact that we are releasing a new major version of Sentry, I think it is safe for us to break the compatibility in that aspect and make the code simpler by simply referring only to the new property. Any thoughts?
- I think it is safer to support old configs - this is the principle of least surprise - not breaking something that worked before.
