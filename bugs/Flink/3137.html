- The root cause of this unstable case is an unexpected debug log involved. This case sets the log level to  DEBUG  for checking the truncating log. However it sets the global log level. There might be a debug log "Responding with error: ..." in  PartitionRequestServerHandler  if a  PartitionNotFound  occurred. This would fail the error checking due to there is a word "error" in this log. 
I propose to shrink the log level setting to  BucketingSink . I believe it's more reliable than skip checking the  PartitionNotFound .
