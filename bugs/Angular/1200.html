Title

Using an Angular Decorator like @Output with a string literal class member causes a build error

Description
# 🐞 bug report

### Affected Package
 
  The issue is caused by package @angular/compiler-cli@10.0.6


### Is this a regression?

 
  Yes, the previous version in which this bug was not present was: @angular/compiler-cli@10.0.5


### Description

I think this is related to the feature added in PR [URL]

I had some code like this before:

```
@Output() 'did-finish-load' = new EventEmitter();
```

(`did-finish-load` is the name of an [Link: Electron API] I was using, I was just trying to keep the same naming scheme).

It looks like before, output names like `'did-finish-load'` were just ignored completely.
In the newer Angular version, it causes a mysterious build error.

Discussion
- Thanks for reporting, definitely broken since #38226. When compiling that `ɵsetClassMetadata` call there's no special handling of the quoted name, which ends up being emitted as (invalid) identifier.
- Btw, the workaround is quite simple once you know it exists; you can remove the `@Output()` decorator from the declaration and declare it in the `@Component` decorator instead:

```ts
@Component({ outputs: ['did-finish-load'] })
```

Doing so removes the faulty code from the `ɵsetClassMetadata` call.
