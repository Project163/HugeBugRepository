Title

streamlit.experimental_memo causes errors with mypy

Description
### Summary

mypy complains about @experimental_memo 

### Steps to reproduce

Code snippet (test.py):

```
import streamlit as st

@st.experimental_memo
def foo(value: int) -> None:
  st.write(value * 2)

foo("bar")
```

Discussion
- Thanks for reporting this @clo-vis.

It looks like this was caused by a combination of a bug in mypy (https://github.com/python/mypy/issues/7781) as well as some refactoring that was done to wrap the `st.experimental_memo` API in a class.

This one might be a bit tricky for us to resolve in the near future since `st.experimental_memo` and `st.experimental_singleton` were wrapped in classes so that we could add support for the `st.experimental_{memo,singleton}.clear()` APIs, and it'd now be a worse crime to break those APIs to fix this issue with `mypy`. The `mypy` bug also seems to have existed for the past few years 😕
