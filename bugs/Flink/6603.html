Title

FIx non-multi insert statement fall into multi insert logic in Hive dialect

Description
In  FLINK-27387 , we support multi insert statment in Hive dialect,  but the check for  multi insert statment  is not strict which will result non-multi insert statement fall into such logic. 

 For example,  

   
  
 
with cte as (select t.a as a,t.a as b,t.a as c from t where t.b is  null ) select * from cte  
  
   

 . The AST for it is  [TOK_CTE, TOK_FROM, TOK_INSERT] , then it  

 will be mistaken as multi-insert statement 

   
  
 
 private   boolean  isMultiDestQuery(HiveParserASTNode astNode) {
     // Hive's multi dest insert will always be [FROM, INSERT+]
      // so,  if  it's children count is more than 2, it should be a multi-dest query
      return  astNode.getChildCount() > 2;
}
Discussion
- To fix it, we need a more strict check.
