Title

Cookie component: inconsistent dot notation write/read/delete

Description
[URL]

The docs for write() are potentially misleading / unclear.  It uses dot notation to write and read  "array" values, but this is not "true" array dot notation as used elsewhere in Cake (e.g. Hash).

I say this because of this behavior:

```
$this->Cookie->write('User',
    array('name' => 'Larry', 'role' => 'Lead')
);
echo $this->Cookie->read('User.name'); //'Larry'

... [Log Snipped] ...
$this->Cookie->delete('User.name'); 
echo $this->Cookie->read('User.name'); //'Larry'  !!!
```

This is because the component will create 1 distinct cookie for each of the following calls:

```
$this->Cookie->write('User',
    array('name' => 'Larry', 'role' => 'Lead')
); // creates a cookie named "User"

$this->Cookie->write('User.name', 'coco'); //creates a *second* cookie named "User.name" instead of modifying previous cookie array value
```
Discussion
- Yeah cookies are a bit inconsistent. It gets even stranger when you have deeply nested structures, and access the data in different ways. One issue with lumping all the data into a single cookie value is the increased risk of exceeding the 4k limit on each cookie, especially when encrypted cookies are used.

While I think the fix to this is fairly straightforward I have concerns about breaking userland applications which jam excessive amounts of data into cookies.
- Setting to 2.5.0 as if we change the behavior it would be best to do it at a minor release level so we can more clearly communicate the changes made.
- Moved back to 2.4.3 as I think the solution I came up with will not impact existing cookie data in a negative way.
