Title

restic serve with jottacloud: Leaking TCP Connections

Description
#### What is the problem you are having with rclone?
Rclone is leaking TCP connections. (More than 1000 open connections so it's running into the file descriptor limit)

#### What is your rclone version (output from `rclone version`)
rclone v1.43.1
- os/arch: freebsd/amd64
- go version: go1.11

####  Which cloud storage system are you using? (eg Google Drive)
Jottacloud

#### The command you were trying to run (eg `rclone copy /tmp remote:tmp`)
rclone serve restic

I haven't managed to reproduce this intentionally and it has only happened on 2 occasions so far but I'm still trying to do so. I already rechecked the Jottacloud backend but all connections opened there should get closed so I doubt it's related to this backend. Will update this if I manage to reproduce it.
Discussion
- If you can get it to do it again `kill -QUIT` the rclone process - that will generate a backtrace of all goroutines which is usually enough to work out what is happening.
- Just wanted to pitch in and say I've seen this as well. I backup 878648 files which is 253.7 GiB using restic->rclone (rclone is the one giving the errors). The backup runs fine (restic backup ...), however the prune job will kick out file descriptor limit errors and eventually hang the entire job (this happends everytime I run prune).

For now I just set the ulimit to something high, however not very ideal.
