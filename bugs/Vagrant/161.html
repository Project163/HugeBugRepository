Title

NFS BSD automatic /etc/exports file incorrect

Description
I've been having trouble with NFS permissions errors so I tested NFS exports with a Linux laptop that I've got and noticed that the Vagrant entry wasn't properly evaluating `maproot` there either. 

Careful reading of the manpage [URL] revealed that the options need to be before the host.

Note that there's another bug - the options are not completely overriden: the docs [URL] say:

The automatic one below doesn't do that - also, I realize that my leading dashes are my user error.

It's important that these options be entirely replaced because `maproot` and `mapall` are mutually exclusive.

### Vagrant version
`Vagrant 2.2.3`

### Host operating system
macOS High Sierra 10.13.6

### Guest operating system
`config.vm.box = "hashicorp/precise32"` - i.e., Ubuntu 14.04

### Vagrantfile
```
ruby
VAGRANTFILE_API_VERSION = "2"

Vagrant.configure(VAGRANTFILE_API_VERSION) do |config|
  # All Vagrant configuration is done here. The most common configuration
... [Log Snipped] ...

config.vm.provision "shell", path: "scripts/vagrant/init_environment_minimal.sh"
```

Full version is probably at [URL]

### Debug output
N/A

### Expected behavior
The `/etc/exports` should abide by the rules for the file on BSD [URL]
`The secondcomponent of a line specifies how the file system is to be exported to the host set. The option flags ... third component of a line specifies the host set to which the line  applies.` Proper entry would look something like this:
`"/Users/bencreasy/code/open-source/taskwarrior-group/inthe.am" -maproot=root  `


### Actual behavior
Meanwhile, the automatically added `/etc/exports` looks like this:

```
# VAGRANT-BEGIN: 503 7db477f2-fac6-45b7-b605-c178588f9db7
"/Users/bencreasy/code/open-source/taskwarrior-group/inthe.am"   --maproot=0:0 --mapall=1000:1000 -mapall=503:20
# VAGRANT-END: 503 7db477f2-fac6-45b7-b605-c178588f9db7
```
