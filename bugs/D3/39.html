Title

Same-type interpolateTransform is sometimes undesirable.

Description
Hmm, this had an undesirable effect (“swooping”) on [URL] since it switched to using interpolateString rather than interpolateTransform. I’ve created a forked version [URL] that preserves the use of interpolateTransform, but the only way to preserve the old behavior is to tack on a no-op transform ("scale(1)") at the end to force the transforms to be dissimilar. I don't like that at all!

- By the way, this no longer seems to occur in Firefox 14. It still occurs in IE9 and IE10 Consumer Preview, though, so it would be good to have some way to work around it. I'm not sure whether the munging behaviour is a bug, although it seems like it [Link: might be].
- Another possibility (also from #344) is to provide some kind of regex-based canonicalisation for transform strings. This gets around the rotate(a x y) problem that we had when using the SVG API directly.

We could say:

``` js
.attrTween("transform", d3.tween("translate(100 100)",
    d3.interpolateTransformPiecewise));
```

Where:

``` js
d3.interpolateTransformPiecewise = function(a, b) {
  return d3.interpolateString(d3_interpolateTransformCanonical(a), b);
};
```

Now that we have d3.tween, we no longer have to worry about breaking other attributes since this interpolator is entirely optional. Hurrah!

I'm assuming the user will supply a canonical end value but I guess it could also be canonicalised for good measure.
