Title

Table schema not getting refreshed for some Command methods

Description
(Follow-up issue for [URL]

`yii\db\Schema::refreshTableSchema()` is called after most schema-altering methods in `yii\db\Command` are called, but not the following ones:

- `createTable()`
- `addForeignKey()`
- `dropForeignKey()`
- `addCommentOnColumn()`
- `dropCommentFromColumn()`

Each of these do have an effect on what gets memoized by `getTableSchema()`, so they should be clearing the schema cache.

### What steps will reproduce the problem?

1. call `yii\db\Schema::getTableSchema()` for a table that doesn’t exist
2. create the the table
3. call `yii\db\Schema::getTableSchema()` again for the same table name 

### What is the expected result?

a `yii\db\TableSchema` object is returned

### What do you get instead?

`null` is returned, because it was cached as `null` in step 1, and that cache was not cleared in step 2.

### Additional info

Similar steps to reproduce for the other functions listed above.
