Title

Fix null pointer exception when the interpreter repository's url protocol is http

Description
Correct the phenomenon that there couldn't access when the url protocol of repository is http. 

 If the repository's url protocol is http, it tries to access the repository through LightweightHttpWagon. 

 Inside the LightweightHttpWagon, the authenticator is referenced. 

 At this time, the authenticator is null referenced, resulting in a null pointer exception. 

 Set the LightweightHttpWagonAuthenticator in the part that creates LightweightHttpWagon to solve the problem.
Discussion
- Any reason to use http ?  morningmemo  I think user should use https instead
- It is a policy that it does not support the repository using http protocol, or if it is not there, I think that when using a repository that uses http protocol, it should be processed by validation instead of null pointer exception. 
I fixed pull request so that null pointer exception does not occur when using http protocol repository. If you want to do something that doesn't support the http protocol repository, you'll need to look for other methods such as validation and change the logic to generate other httpWagons based on the http and https protocols.
