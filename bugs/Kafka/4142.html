Title

AbstractFetcherThread should verify the current leader epoch in the fetch request matches the leader epoch in the fetch state

Description
This is to follow up on  [URL]

 It's possible that a fetch response (for an old leader epoch) returns divergingEndOffsets. In this case, we will take the divergingEndOffsets in the fetch response and truncates the local log based on that. This could cause a committed record to be removed from the follow's log, potentially leading to data loss. 

 We can fix this issue by ignoring the fetch response if the leader epoch in the fetch request doesn't match the leader epoch in the current fetch state.
