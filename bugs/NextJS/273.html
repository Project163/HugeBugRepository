### Link to the code that reproduces this issue

[URL]

### To Reproduce

1. Run `npm run dev`
2. Wait for `.next/types/link.d.ts` to be generated

### Describe the Bug

Route groups are hidden from the actual route hierarchy, but are included in the auto-generated `Route` type.

In my example, routes are defined like this:

1. `/page.tsx` -> `/`
1. `/foo/page.tsx` -> `/foo`
1. `/(group)/bar/page.tsx` -> `/bar`

But I got type error when using `next/link`:

```
tsx
// works fine
 To Foo 

// throws error
... [Log Snipped] ...
// does not throw
 To Bar 
```

You can also confirm that the `/(group)/bar` type is generated by looking at `.next/types/link.d.ts`.

```ts
type Route  = 
  | `/${Suffix}`
  | `/(group)/bar${Suffix}`
  | `/foo${Suffix}`  | `/${Suffix}`
  | `/(group)/bar${Suffix}`
  | `/foo${Suffix}`
```


### Expected Behavior

I think route groups should be ignored by route type generations.
