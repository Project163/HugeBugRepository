Title

Stable sort is not stable

Description
The WebGLRenderer function that sorts objects by depth is still not stable. There are two problems:
- Not all renderable objects are assigned an id (which is used to resolve ties in the sorting). See [Link: here]
- Object id's are generated per scene graph node, but if a mesh has a MeshFaceMaterial, it will consist of multiple renderable objects, which will then all get the same id. This is especially bad since those objects have all the same position. See [Link: here]

[Link: Here] is a simple patch that solves the issue (patch was generated against three.js r54). The idea is to resolve ties by comparing the old index in the list of renderables instead of the object id.

This patch solved flickering of transparent objects for us, where each object had multiple materials.

This may be related to #2568 and #2668. @rmx
