Title

[webpack 2] `watch` & System.import compile with new chunk name

Description
I've search high and low; I don't think anyone has reported this yet.

I'm building an application using dynamic code splitting with `System.import`, as detailed [Link: here]. I've got a build that spits out an entry point (`app.js`) and two chunks (`0.js` & `1.js`). However, when running with `--watch`, if I make a change in one of the dependencies of `0` or `1`, `webpack` rebuilds the chunk with a new name, ouputting a new `3.js` chunk instead of updating the already-built chunks.

Because the main `app.js` chunk hasn't changed, it continues to load the already-emitted chunk `0.js` or `1.js` chunk (depending on the page), so the changes don't actually show up in the loaded scripts.

Here's my `webpack.config.js`:

```
js
module.exports = {
    entry: {
        'app': './app.js'
    },
... [Log Snipped] ...
    plugins: []
};
```

- Update: This is reproducible using the examples. Run this in `examples/code-splitting-harmony`:

``` bash
node ../../bin/webpack.js --display-reasons --display-chunks --display-modules --display-origins --output-public-path "js/" --output-pathinfo --watch  ./example.js js/output.js
```

And modify either of the files in `node_modules/c` and you'll see new chunks emitted as `4.js` and `5.js`. I first modified `b.js` and saw the same chunk emitted, but modifying `c/1.js` emited the `4.js` and `5.js` chunks without emitting `output.js` again to point to the new chunks.
