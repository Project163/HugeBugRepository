- @opinali I'm starting to think the original code was correct.  maxSize is the size at which we have to grow (defaults to 0.5 \* capacity). If we add a bunch of entries and then delete them, the number of AVAILABLE slots could eventually become 0 since they have been marked as REMOVED. In this case, we rehash with the current capacity to clear out the REMOVED nodes and make them AVAILABLE again.  We shouldn't need to grow in this case.

I suspect that the problem you're running into is related to the choice of capacity.  This choice is important for reducing collisions in open addressing and to this point I've just been ensuring that it's odd.  Using prime numbers for capacity, however, is the typical approach and I think we should migrate to this before making any other changes.

Sound reasonable?
