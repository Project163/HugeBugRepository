Title

Resteasy + Hibernate Validator : @Produces on super interface is not taken into account, JSON is default

Description
### Describe the bug

I have a `ResourceInterface` and a `ResourceImplementation`.

The `ResourceInterface` defines everything related to JAX-RS and OpenAPI.x

It looks like this

```
// ...
@Produces("application/xml")
@Consumes("application/xml")
public interface ResourceInterface {
    //...
    @POST
    Output method(@Valid Input input);
    //....
```

The `ResourceImplementation` looks like this

```
@ApplicationScoped
public class ResourceImplementation implements ResourceInterface {
    //...
    public Output method(Input input) {
        //....
    }
}
```

When I get a validation exception, it gets outputted as JSON, even though I specified XML on the class as described by the JAX-RS specification.

The guilty piece of code is the following, that only checks on the invoked method and class but not the super.

This comes from `JaxrsEndPointValidationInterceptor`

```
@AroundInvoke
    @Override
    public Object validateMethodInvocation(InvocationContext ctx) throws Exception {
        try {
            return super.validateMethodInvocation(ctx);
... [Log Snipped] ...
        return Arrays.asList(producedMediaTypes);
    }
```

### Expected behavior

Return validation error as XML

### Actual behavior

Returns validation error as JSON

PS : Of course, a workaround is possible. The annotation should be put on the implementating class' method. It doesn't work when put on the interface's class method.

### How to Reproduce?

Create the classes as described above and produce a validation error.
It will get outputed as JSON and not XML.
