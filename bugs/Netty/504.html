Title

Netty 4.1.0.CR1: DNS resolver accepts invalid FQDN with label length > 63 octet

Description
According to [URL] (section 2.3.1), the length of a label in domain name should be 63 octets or less. However, Netty DNS resolver accepts invalid domain name with label greater than 63, and actually send out DNS query with the invalid name. 

So the final outcome of such query depends on the underlying resolver. During my tests, I sometimes see FormErr returned. In other cases, Netty resolver actually got unexpected exception, and caused the request to timeout. See the following stack trace:

```
[WARN] (dns-response-handler-0) io.netty.resolver.dns.DnsNameResolver: [id:  , /0:0:0:0:0:0:0:0:50879] Unexpected exception: 
io.netty.handler.codec.CorruptedFrameException: name has an out-of-range pointer
    at io.netty.handler.codec.dns.DefaultDnsRecordDecoder.decodeName(DefaultDnsRecordDecoder.java:116) ~[netty-all-4.1.jar:4.1.0.CR1]
    at io.netty.handler.codec.dns.DefaultDnsRecordDecoder.decodeQuestion(DefaultDnsRecordDecoder.java:37) ~[netty-all-4.1.jar:4.1.0.CR1]
    at io.netty.handler.codec.dns.DatagramDnsResponseDecoder.decodeQuestions(DatagramDnsResponseDecoder.java:102) ~[netty-all-4.1.jar:4.1.0.CR1]
... [Log Snipped] ...
    at io.netty.util.concurrent.SingleThreadEventExecutor$5.run(SingleThreadEventExecutor.java:742) [netty-all-4.1.jar:4.1.0.CR1]
    at java.lang.Thread.run(Thread.java:745) [?:1.8.0_74]
```

I think the resolver should reject such invalid domain name in the first place, and should not send out any DNS query.
