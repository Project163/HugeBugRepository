Title

find_package(Vorbis REQUIRED) fail quietly

Description
## Subject of the issue

find_package(Vorbis REQUIRED) fail quietly, and make fail configuration later in the process

CMake is case-sensitive however VORBIS is used instead of Vorbis in FindVorbis.cmake file which cause it to not see the Vorbis_FIND_REQUIRED which should make the configuration failed on `find_package(Vorbis REQUIRED)` and not later when using variables

Possible fixes
- Change FindVorbis.cmake to FindVORBIS.cmake and use `find_package(VORBIS REQUIRED)` instead
- Use `Vorbis*` variables instead of `VORBIS*` ones in FindVorbis (requires to fix cmake using old variables)

## Your environment

OS:Ubuntu 18.04
SFML: master( )
Compiler: Not relevant

## Steps to reproduce

Have libvorbis installed without libvorbis-dev

## Expected behavior

```
CMake Error at /usr/share/cmake-3.13/Modules/FindPackageHandleStandardArgs.cmake:137 (message):
  Could NOT find Vorbis (missing: VORBIS_INCLUDE_DIR VORBIS_LIBRARY
  VORBISFILE_LIBRARY)
```

## Actual behavior

```
CMake Error at cmake/Macros.cmake:333 (message):
  Missing item in
  VORBISENC_LIBRARY-NOTFOUND;VORBISFILE_LIBRARY-NOTFOUND;VORBIS_LIBRARY-NOTFOUND;/usr/lib/x86_64-linux-gnu/libogg.so
```
Discussion
- Looking at [Link: FindVorbis.cmake], the uppercase CMake package `VORBIS` is searched, and variables referring to it also use upper case:

    find_package_handle_standard_args(VORBIS DEFAULT_MSG VORBIS_LIBRARIES VORBIS_INCLUDE_DIR OGG_INCLUDE_DIR)
    set(VORBIS_INCLUDE_DIRS ${OGG_INCLUDE_DIR} ${VORBIS_INCLUDE_DIR})

The Vorbis package is found at [Link: this line in the Audio config]:

    sfml_find_package(Vorbis INCLUDE "VORBIS_INCLUDE_DIRS" LINK "VORBIS_LIBRARIES")

But here we use the uppercase variables as exported in `FindVorbis.cmake`. If we changed the line to `sfml_find_package(VORBIS...`, then the filename `FindVorbis.cmake` would not match anymore.

Where exactly is the conflict?
- The conflict is between `sfml_find_package(Vorbis REQUIRED)` and `find_package_handle_standard_args(VORBIS ...`
Because `find_package_handle_standard_args` will search in `VORBIS_FIND_REQUIRED` instead of `Vorbis_FIND_REQUIRED` variable set by `find_package(${target} REQUIRED)` in `sfml_find_package` where target is `Vorbis`

It's also a bad practice to have variable that are not in the format  _* however due to the difference in case none of the variable create in FindVorbis match with Vorbis package name as it is not fully in uppercase
