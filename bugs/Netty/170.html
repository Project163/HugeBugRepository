Title

AioSocketChannel may process corrupt data on read

Description
I've tested the HexDumpProxy example to use the new Aio. At the bottom is the diff of my modifications ( basically change references of Nio to Aio). 

It works when running on Windows 7. However in Linux, Ubuntu 12 64bit and RedHat 5.8 both Oracle JDK7, there's some issue. I've tested with netty-4.0.0.CR2 and netty-4.0.0.CR3.

The easiest way I've been able to reproduce the issue is to use the HexDumpProxy to tunnel an ssh connection. 

For example I'll run the proxy on the remote Linux box (ommitting the classpath arguments):

java io.netty.example.proxy.HexDumpProxy 7000 localhost 22

Then locally I'll run:

ssh -p 7000 remotelinuxhost

The ssh command errors out saying:
Disconnecting: Protocol error: expected packet type 33, got 31

On the server, the hexdump proxy logs the steps of the ssh handshake. The ssh client and server respond to each other about 4 times before the connection dies.

However when running the proxy on Windows 7 ( set to proxy to the same linux remote host), it's able to proxy the ssh session fine with no hickups.

This issue is not unique with ssh. When proxying ldap for example the connection seems to freeze. 
However it seems to work fine in some cases with http. If I use netcat "GET /" and proxy to google.com, it seems to reply back with the html fine.
