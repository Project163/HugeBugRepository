Title

[Bug]: NFPM does not respect binary subdirectories

Description
### What happened?

In goreleaser 0.170.0+, if your binary is in a subdirectory, that subdirectory is trimmed out when the binary is added to the package.

here is some debug output from a 0.169.0 release:

```
      • adding binary to package  arch=amd64 dst=/apps/testapp/bin/testbin package=testapp_latest.deb src=/build/dist/testbin_linux_amd64/testbin
      • adding binary to package  arch=amd64 dst=/apps/testapp/bin/nesteddir/nestedbin package=testapp_latest.deb src=/build/dist/nestedbin_linux_amd64/nesteddir/nestedbin
```

and here is some debug output from a 0.170.0 release:

```
      • adding binary to package  arch=amd64 dst=/apps/testapp/bin/testbin package=testapp_latest.deb src=/build/dist/testbin_linux_amd64/testbin
      • adding binary to package  arch=amd64 dst=/apps/testapp/bin/nestedbin package=testapp_latest.deb src=/build/dist/nestedbin_linux_amd64/nesteddir/nestedbin
```

I believe c49c7712 is the offending commit. It seems the commit a0dd4559, which was to fix #2311, fixed the archive part of the bug, but left the nfpm part of the bug there.

### How can we reproduce this?

In `builds`, specify a binary in a subdirectory (e.g. `binary: some/dir/mybinary`).

Then, create a deb with `nfpms`.

`some/dir` will be left out of the deb, and `mybinary` will exist directly in the `bindir` specified in `nfpms`.

### goreleaser version

```bash
The subdir is omitted in 0.170.0+. 0.169.0 works as I would expect.
```
