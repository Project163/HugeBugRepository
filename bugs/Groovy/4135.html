Title

Java 8 Type Param Annotation Not Generated in Byte Code

Description
Groovy 3.0.4 is based on Java Minimum Version 1.8. So it should support Byte Code Level compatible with Java 8. And It should generate Annotations on Type Param in its Byte Code. 

 ```
 

 class Names  
{
 @NotEmpty
... [Log Snipped] ...

 
```
Discussion
- We are aware of incomplete work in our JSR 308/JEP 104 implementation, see   GROOVY-8225   but thanks for the reminder. We'll have to find time to increase its priority.
- Hello, as this is a bug in 3.0.4 why the correction was made in 4.0.0 ? 

 Is there a way to backport this correction to groovy 3.x version please ?
- To support type annotations involved numerous changes to the public API including things as fundamental as ClassNode and how we handled representing primitive types throughout the codebase, e.g. one of the related commits: 
 [URL]

 It wouldn't be safe to backport all of that in a 3.0.x point release. 

   

 What is your use case? There might be a small number of cases which could be made to work with the previous design.
- I wanted to use javax.validation on container like List<@NotBlank String> to ensure that the items in the list are not blank. 

 Moreover i have a some groovy/grails legacy code and grails seems to not be compatible with groovy 4. 

 Then i think here to only report the type parameter annotation from source to bytecode. I'm aware that the 'only' may need a lot of work...
