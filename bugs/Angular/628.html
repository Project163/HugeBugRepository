[FormBuilder#control] - Change the signature method

## Current behavior
Currently the signature of [Link: **`FormBuilder#control`**] is:

`control(formState: Object, validator?: ValidatorFn|ValidatorFn[]|null, asyncValidator?: AsyncValidatorFn|AsyncValidatorFn[]|null): FormControl`

So, if you have the following line:

~~this.formBuilder.control('angular');~~
```
this.formBuilder.control(null);
```

or

```
this.formBuilder.control(undefined);
```

... with `strict` option enabled in `tsconfig.json`, it doesn't compile. See the error:


In fact, I don't see a good reason to use `Object` instead of `any` as in [Link: **`FormControl#constructor`**].

Thinking more about it... it seems like a bug, since the `FormBuilder#control` acts like an wrapper for `FormControl#constructor`, so shouldn't it have exact the same signature of it?

## Expected behavior
I'd expect my app to compile well with `strict` option enabled.

1. formState is declared of type **O**bject. (so we can assing value to it, but invoke only the methods defined in the Object interface )
1. If it were declared of type **o**bject (the type used to describe non-primitive types), then passing a string(primitive value in TypeScript) would have resulted in the error mentioned above
