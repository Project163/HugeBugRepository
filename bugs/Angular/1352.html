Title

[TS3.8] Useful error message for ES private field

Description
# 🚀 feature request

### Relevant Package

compiler

### Description

TypeScript 3.8 adds support for `#privateField` in classes. Of course, Angular's component classes can have its own private fields but they are not accessible from its template. 
I don't think that is a problem. It is the same behavior as TypeScript's original private field: `private foo`.

My proposal is that Angular should emit an error when templates try to access to ES private field **with a similar message**. 

For the TS private field, Angular emits TS2341 error.

```
@Component({
  selector: 'app-root',
  template: `
   {{ title }} app is running! 
   {{ privateTitle }} 
... [Log Snipped] ...

error TS2341: Property 'privateTitle' is private and only accessible within class 'AppComponent'.
```

I understand the current implementation for TS3.8 compatibility is still in progress. So the following is not a bug report, but just a log.
For the below code, Angular emits TS2551 error. 

```
@Component({
  selector: 'app-root',
  template: `
   {{ title }} app is running! 
   {{ privateTitle }} 
... [Log Snipped] ...

error TS2551: Property 'privateTitle' does not exist on type 'AppComponent'. Did you mean '#privateTitle'?
```

When the template try to access to `#privateField`, the compiler emits a template parse error;

```
ERROR in Template parse errors:
Parser Error: Unexpected token # at column 2 in [{{ #privateTitle }}] in /Users/laco/Works/angular-ts38-sandbox/src/app/app.component.ts@6:8 ("
  template: `
   {{ title }} app is running! 
   [ERROR ->]{{ #privateTitle }} 
  `,
})
"): /Users/laco/Works/angular-ts38-sandbox/src/app/app.component.ts@6:8
```

### Describe the solution you'd like

- Solution 1. Add new error code and message for ES private field
- Solution 2. Use the same error code to TS private field
