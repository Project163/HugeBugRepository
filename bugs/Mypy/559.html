Title

testpep561.py fails locally when run from a venv

Description
There's one test that always fails for me when I run pytest locally. Other people also see this, and it is apparently due to the nesting of virtual environments. In particular, I run pytest in a venv, and then the test creates a _nested_ virtual environment. It's been speculated that it would pass if I created my own virtual environment using `virtualenv` rather than `venv`. (The testpep561.py file uses `virtualenv`, and it has a comment explaining why -- it needs to create a Python 2 virtual environment.)

If this can't be fixed, maybe the offending tests can detect that they're being run inside of a `venv` and then be skipped? Note that Travis-CI and AppVeyor are unaffected.
Discussion
- Could you give a snippet of output? Also I presume you mean that it would work if `venv` was used instead of `virtualenv`?
- I don't know for sure what combination would work. I chatted a bit with @msullivan and he seems to think that `venv` doesn't nest properly but `virtualenv` does. I haven't tested this theory yet.
