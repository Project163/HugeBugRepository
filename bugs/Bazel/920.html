Title

NullPointerException when overriding copts and linkopts to None in transition

Description

The core issue, I believe, is there are different kinds of data typing in Bazel. When you set a value to `None`, you're setting it to a type in the Starlark language. Transitions ultimately set that to pure Java types. For example, `copt` is [Link: ultimately] a Java `List `.

I think the specific code doing this translation is at [URL] So this may be a matter of examining the option's type, and if it's a list type, change it to `[]` instead of `null`?

An alternative approach could be to ban setting values to `None`, so examples like the above simply report "This is not a valid assignment`.  With that approach, maybe the same  would trigger an error message instead of trying to change the conversion. 

But for non-list types, setting to `None` makes more sense. So maybe the first approach is more consistent.

Is that enough to work with?
