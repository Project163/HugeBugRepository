Title

NotificationBroadcastReceiver not receiving notifications; ViewPager

Description
### Issue description
TL;DR Activity with a ViewPager, with ten-ish Fragments, most, but not all of them, each having an ExoPlayer, the later fragments will not have their notification play buttons work, while the first/earlier ones will.  Notification buttons always break after there's a gap in the ViewPager display hierarchy, of a fragment without an ExoPlayer in it.

Long Version:  I have an activity, which uses a ViewPager, which instantiates (via the ViewPager adapter) fragments, ten-ish.  Many fragment has an SimpleExoPlayer in it, but a few fragments do not (they just have an ImageView).  Each player gets set to a PlayerNotificationManager.  Each PlayerNotificationManager has a class implementer of MediaDescriptionAdapter set to it.

Depending on the layout/orientation, a fragment may get instantiated early, and held in memory, or instantiated real time, as the user swipes back/forth.

For the first fragment, showing a SimpleExoPlayer, and having a notification, the notification Play/Back buttons work fine (com.google.android.exoplayer.play).  The NotificationBroadcastReceiver, inside of the PlayerNotificationManager, has its onReceive(Context, Intent) called, when the buttons on the notification are pressed.

If swiping to the right once, you would have a non-SimpleExoPlayer fragment.  Swiping once more to the right, you would have a fragment with another SimpleExoPlayer, and a notification shows for it.  However, when pressing the buttons on the notification, nothing happens.  The broadcast receiver's onReceive method is not called.

If I restart the app, and go to a later page/fragment, the notification buttons may or may not work.  If I manually slide back and forth some, eventually, I can get some page's/fragment's notification buttons to work, even if they were not working previously in the same app run.

If I change the adapter to only instantiate one of the later fragments, in the view pager, it'll work fine.

- I think the problem is around having two instances of PlayerNotificationManager registering a broadcast receiver. You should try using a single PlayerNotificationManager only.

I'd also suggest to have only a single player instance for all fragments in the ViewPager. 

That's a similar arrangement like for a RecyclerView. If you are using more than one instance of the player, you need to make sure that a given device has enough codec instances. This is not trivial because there's no reliable API to check the number of available codec instances.

If you choose to use more than a single ExoPlayer instance I'd still use only one instance of the PlayerNotificationManager and then use playerNotificationManager.setPlayer(player) with the player instance which is currently playing and for which you want to have a notification displayed.

But to make things easy, I'd go with one single player instance and one single PlayerNotificationManager instance and reuse these in the fragments. This also saves you from the problem to make sure that you've never two notifications displayed which may happen when you have two player instance/two notification manager at once.

- I think you're assuming components are more tightly coupled than they are, and making assumptions about how notifications should work that don't necessarily apply to other use cases. ExoPlayer as a library knows nothing about your ViewPager/Adapter. There's no real requirement that the player is bound to any view in the view hierarchy for a notification to be shown by `PlayerNotificationManager`, and even if there were, in many cases it wouldn't make sense to link the notification's visibility to the visibility of a corresponding view. Conversely, one of the primary uses of a playback notification would explicitly be to still allow control of the player when it's _not_ visible elsewhere in the UI.

It's your application code's responsibility to define the behavior you want and link things together. It should be reasonably easy for you to work out which views are visible in your app's UI, even within a ViewPager (I found a bunch of related StackOverflow questions and blog posts with a quick search). You do of course need to write some code to do this, and put some logic in place to achieve whatever behavior's you want, but that's kind of necessary given different apps will want different behaviors.
