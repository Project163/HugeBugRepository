Title

`no-extra-parens` conflicts with `wrap-regex`

Description
Having both `no-extra-parens` and `wrap-regex` turned on means that in the case of a regular expression you will always get a warning.

If `wrap-regex` is turned on can `no-extra-parens` ignore regular expressions much like it already ignores IIFEs?
Discussion
- Yup. Can you provide an example where you're seeing this?
- Kind of a trivial example.

``` js
if ( !(/text|password|email|search/).test( input.type ) ) {
  input.setAttribute( "type", "text" );
}
```

Would yield "Gratuitous parentheses around expression"
Switching it to

``` js
if ( !/text|password|email|search/.test( input.type ) ) {
  input.setAttribute( "type", "text" );
}
```

Would yield "Wrap the regexp literal in parens to disambiguate the slash"

I would like to have both of these rules on, basically IIFEs and RegExp would be the exceptions to `no-extra-parens`
