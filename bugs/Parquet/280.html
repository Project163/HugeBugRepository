Discussion
- yumwang , 

  UserDefinedPredicate.keep(T)  shall handle  null  values because the parquet-mr library do invokes it with a  null . This is the only way the filtering API can check if a  null  value fulfills the UDP. 
It did not occur before the ColumnIndex feature because the statistics and the dictionary filters invokes  keep(T)  only in some special scenarios (e.g.  if all the values are  null  in the column chunk ). 
So the problem is at the client side. Please, update your code so that  keep(T)  checks for  null  value and returns accordingly. 

 It is another issue that the described behavior is not properly documented. I'll create a JIRA about it. 

 Closing this issue as not a bug.
- We discussed this on   SPARK-28371  . 

 Previously, Parquet did not fail if a UserDefinedPredicate did not handle null values, so I think that it is a regression that Parquet will cause previously working code to fail. I think that it is correct for Parquet to call a UDP the way that it is, but that Parquet should catch exceptions thrown by the predicate and should process the row group where there error was thrown. That way, Parquet can keep the optimization for columns that are all null, but it doesn't break existing code.
