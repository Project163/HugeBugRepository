Title

3.1, Prefix routing with the 'Route' class

Description
**TL;DR**
Using a prefix route, without fallback routes and the `Route` class as the default route class, causes the passed controller param to be directly mapped to both `Controller::$name` and thus `Controller::$modelClass`.

**What's going on?**
I had an issue with the Crud plugin and lost my pagination. Turns out it was trying to match on the `Controller::$modelClass`, which was `packages` rather than `Packages`.

Chasing this all the way through it was being taken directly from the url. To fix it I changed my default route class to `InflectedRoute` and it was fine after that.

**Example application** 
[URL]

**Reproduction**
`example.com/examples` gives `Controller::$name === 'Examples'`
`example.com/foo/examples` gives `Controller::$name === 'examples'`

You can change the capitalization of the `Controller::$name` just by changing the url and refreshing.
Discussion
- I'll take a look and see if I can reproduce.
- This is expected behavior. The default Route class does not apply any inflection. It's intended to be simple. The reason your unprefixed routes are inflecting is that your `/` scope uses `DashedRoute` when connecting the default routes.

Closing as the base Route class is working as it should and not being fancy :smile:
