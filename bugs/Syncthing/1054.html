Title

Syncthing 2.0.0 fails to open database when path includes `#`

Description
UPD: **Unsolved** issue with 2.0.0 version and **--home=**"/setupdir" attributes

**Solved** as **symlink** to /home/user/.config/syncthing

### What happened?

newly updated syncthing 2.0.0-1 is not running with previous version of DB:

syncthing --no-restart --no-browser --home="/home/user/syncthing"
2025-08-13 09:02:06 INF syncthing v2.0.0 "Hafnium Hornet" (go1.24.6 linux-amd64) syncthing@archlinux 2025-08-13 02:38:16 UTC [noupgrade] (log.pkg=main)
2025-08-13 09:02:06 ERR Error opening database (error="openbase (PRAGMA journal_mode = WAL): unable to open database file: is a directory" log.pkg=main)

I checked it at Linux (log is here) and at Windows.

### Syncthing version

2.0.0-1

### Platform & operating system

Linux x64

### Browser version

_No response_

### Relevant log output

```shell
syncthing --no-restart --no-browser --home="/home/user/syncthing"
2025-08-13 09:02:06 INF syncthing v2.0.0 "Hafnium Hornet" (go1.24.6 linux-amd64) syncthing@archlinux 2025-08-13 02:38:16 UTC [noupgrade] (log.pkg=main)
2025-08-13 09:02:06 ERR Error opening database (error="openbase (PRAGMA journal_mode = WAL): unable to open database file: is a directory" log.pkg=main)
```
Discussion
- What does this mean exactly - what did you try to do?
- Is docker involved? That looks like a messed up mount point
- Linux updated with new Syncthing 2.0.0 version

I have dir with syncthing setup and running it with attributes:
syncthing --no-restart --no-browser --home="/home/user/syncthing"

Dir is another (I've typed it to simplify it): **/home/a/#SYNC/J/J@V/V#Settings/syncthing**

I've created **symlink** at 
**/home/a/.config/syncthing**
to
**/home/a/#SYNC/J/J@V/V#Settings/syncthing**

And **Syncthing is running now!**
**Partically solved**!

So I have partically the trouble at **2.0.0** version with my full settings path and attributes:
--home=/home/a/#SYNC/J/J@V/V#Settings/syncthing
- That explains it, sqlite has an issue with paths that include `#` because it becomes a URL internally. We probably need some escaping...
