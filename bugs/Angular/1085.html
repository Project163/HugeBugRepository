Title

NG6002/NG6003: Ivy with yarn workspaces and hoisting (repro)

Description
# 🐞 bug report

### Affected Package
 The issue is probably caused by package @angular/compiler

### Is this a regression?

Not sure. Did not use Ivy before.

### Description

There is an error when compiling with Ivy when using yarn workspaces and the angular libraries are hoisted to the root `node_modules` in a particular way by yarn.

I have attached a repro.

## 🔬 Minimal Reproduction

Repro at: [URL]

Run 
```bash
yarn
yarn repro
```
^ Fails

Note that if you delete the `library` directory from under `packages`, the compilation will finish just fine.

```
rm -rf packages/library
yarn && yarn repro
```
^ Works

Alternatively, adding `enableIvy: false` to tsconfig.json also works.

Edit: In an actual project you will probably need to add all of your angular related dependencies to `nohoist` as well, which is a bit of a logistical problem. Adding `@angular/*` to nohoist in my project resulted in errors such as:

```

ERROR in The target entry-point "angular2-text-mask" has missing dependencies:
 - @angular/core
 - @angular/forms
 - @angular/platform-browser
```

Adding `angular2-text-mask` to nohoist too fixes it, but there are a lot of other dependencies and it will be tedious to manually add everything.
- It seems that in "target" mode ngcc is not correctly looking up the tree to find the hoisted packages.

A workaround is to run ngcc on the root folder directly before building the projects:

* `yarn ngcc -t @ngx-loading-bar/http-client -l debug --create-ivy-entry-points`
* `yarn workspace angular-app start`
