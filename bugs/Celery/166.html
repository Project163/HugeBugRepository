# Brief Summary
The setting [Link: task_create_missing_queues] gives ability to autocreate queues and exchanges. Celery 5.5 adds ability to use quorum queues in RabbitMQ. But I haven't found any ability to autocreate missing queues with `'x-queue-type': 'quorum'`. I can only set [Link: task_default_queue_type] which affects only default queue.
To my mind, it would be important to have this ability, as classic mirrored queues are [Link: removed in RabbitMQ 4.0+].

## Proposed Behavior
Add a setting `task_create_missing_queue_type` which declares queue type when creating missing queues (classic/quorum). Or, alternatively add `task_create_missing_queue_arguments` setting in order to edit arguments for autocreated queues in a much extandable manner.
Discussion
- @Nusnus can you verify if this issue is legit?
- @auvipy I’ve verified the issue in Celery 5.5 and RabbitMQ 3.13.x:

`task_create_missing_queues = True` correctly auto-creates queues when they are missing.
However, the queue type defaults to `"classic"`, and there is no way to pass `x-queue-type: quorum` to these auto-created queues.
The existing setting `task_default_queue_type = 'quorum'` only applies to the default queue, not to any dynamically created queues.

Tested with:
- Celery: 5.5.x
- Kombu: 5.x
- RabbitMQ: 3.13.x
- Broker: `pyamqp://guest:guest@localhost//`

Expected:
```python
task_create_missing_queue_type = 'quorum'
```
