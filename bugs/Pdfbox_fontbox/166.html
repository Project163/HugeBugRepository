Discussion
- heap usage while building font cache captured using VisualVM
- This isn't a font cache issue. It's been a problem ever since we started scanning the local system for fonts in 2.0. It's become worse now that we can load TTC files, as those tend to be especially large. 

 The problem is that FontBox's parsers are greedy with memory, especially the CFF parser. This is basically because most of the parsing is done up-front rather than "on demand" and large amounts of data are copied into auxiliary data structures, as well as an in-memory cache of the entire file. So there can be very high heap usage when parsing large fonts from disk.
