Title

[YSQL] Wrong offset when preparing fast path update

Description
### Description

Reproducer:
```
yugabyte=# create table orders2 (order_row_id uuid,  total_executed_qty numeric, order_status_cd character varying(1), primary key (order_row_id));
CREATE TABLE
yugabyte=# update orders2 set TOTAL_EXECUTED_QTY=TOTAL_EXECUTED_QTY+1, ORDER_STATUS_CD='B'  where order_row_id='5a5c3d42-638a-465a-8f49-8541ebb35e6c';
ERROR:  invalid memory alloc request size  
```

The fast path update plan looks like this:
```
yugabyte=# explain verbose update orders2 set TOTAL_EXECUTED_QTY=TOTAL_EXECUTED_QTY+1, ORDER_STATUS_CD='B'  where order_row_id='5a5c3d42-638a-465a-8f49-8541ebb35e6c';
                                         QUERY PLAN                                         
--------------------------------------------------------------------------------------------
 Update on public.orders2  (cost=0.00..4.12 rows=1 width=88)
   ->  Result  (cost=0.00..4.12 rows=1 width=88)
         Output: '5a5c3d42-638a-465a-8f49-8541ebb35e6c'::uuid, 0, 'B'::character varying(1)
(3 rows)
```
The 0 value in the Result's output is a placeholder for the expression we pushdown. The data type for the placeholder is int4, this type is used by Result to construct the tuple. However, when we construct the update request, we use tuple descriptor from the target table which is numeric type in our example above, so the third attribute is looked for at incorrect offset.
