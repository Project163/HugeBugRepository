Title

Connect converter validation does not accept class aliases

Description
Connect allows users to specify aliases instead of full classes when configuring plugins. For example, the following configuration is valid: 
  
 {
        "connector.class": "FileStreamSource",
        "topic": "anything",
        "key.converter": "JsonConverter"
} 
  
 In <= 3.7.1 this will pass validation and function correctly. 

 In 3.8.0-rc1 this will instead fail with this error message:

Discussion
- The difference seems to be caused by the difference between these two calls: 

  [URL] which passes the class alias into Class.forName, and 

  [URL] which uses the alias to first load the class, and then calls Class.forName with the full name of the class. 

 These diverged a long time ago in   KAFKA-8550   and the same bug resurfaced when we added more validation surrounding the converter classes.
