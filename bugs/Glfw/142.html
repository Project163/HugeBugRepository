Title

Monitor callback never fired

Description
The monitor callback set with glfwSetMonitorCallback() is never fired on my system.

I have a nVidia GTX970 with 353.06 drivers on Win 7 x64.

I'm using the latest stable version of glfw, 3.2.

```
3.2.0 Win32 WGL EGL MinGW DLL
NVIDIA Corporation
GeForce GTX 970/PCIe/SSE2
4.5.0 NVIDIA 353.06
```

Running the test program events.c, I tried to enable/disable a second monitor from the nVidia control panel, the monitor is attached/removed as expected to/from the OS but no event is fired in the events test program.

I also tried to physically connect/disconnect the monitor from the graphic card, still the same.

I also tried to manually call glfwGetMonitors() from my own code (by pressing a function key) after I attached/detached the second monitor, but the list of reported monitors is not updated and it's the one detected at the moment the program was launched.

I have to exit the program and relaunch it to make glfwGetMonitors() aware of the changed configuration.

Also I tried in a simple API program with a single window, to see what messages were sent to the window.
In winproc I'm testing for WM_DEVICECHANGE and WM_DISPLAYCHANGE

I get a WM_DEVICECHANGE when I connect/disconnect a USB joystick
I get a WM_DISPLAYCHANGE when I add/remove a monitor in the nVidia control panel, but no WM_DEVICECHANGE

In my case, to make all work I had to change windowProc() in win32_windows.c adding WM_DISPLAYCHANGE to the second switch(), the one associated to the MAIN window (not the helper one).

```
switch (uMsg)
    {
    ...
    }

... [Log Snipped] ...
       etc
       ...
```

This way the callback work for bot attacth and detach and the monitor list has been refreshed when I call glfwGetMonitors()

I would like to add a suggestion.

If I understood correctly looking at the source glfwGetMonitors() returns the cached configuration retrieved at the initialization of the library or updated when a change monitor event is fired.

Would be possible to add a flag to glfwGetMonitors() (or to add a new separated function if you prefer it) to ask for an update of the current configuration ? In short, to call _glfwPlatformGetMonitors() again.

This way, since this "change" event looks tricky, we would have at least a backup to manually update the configuration when required, for example just before entering a configuration page in our program or similar "hot" spots. 

I believe it would be a useful fallback to have.
