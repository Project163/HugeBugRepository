Discussion
- turns out i was running trunk client against   brokers. currently rebuilding trunk locally to try all trunk everything.
- I found the bug. The problem is that in a particular call to `RecordAccumulator.append`, we do two calls to `ProducerBatch.tryAppend`, with a gap in the middle where the lock is released. 

 So it is possible that the first `ProducerBatch.tryAppend` closes the the `MemoryRecordsBuilder` for appends because the incoming record is too large for the batch. But then before we can allocate a new batch, another append comes along with a smaller size and which fits in the current batch. In this case the second append will see this exception.
