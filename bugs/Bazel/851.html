Title

dummy_link for Windows runfiles can causes rare build failures

Description
### Description of the problem / feature request:

In rare instances we have seen the following error in builds.

```
build-runfiles error: CreateSymbolicLinkW failed: (error: 183): Cannot create a file when that file already exists.
```

Further investigation found a `dummy_link` file was under a host config tool under `$EXECUTION_ROOT/bazel-out/host/...`. Our builds use dynamic scheduling and `--windows_enable_symlink`, although both of these seem irrelevant to cause the problem. 

Until we remove `dummy_link` all builds on our CI failed with the CreateSymbolicLinkW error. 

Since we use `--windows_enable_symlink`, we guarantee our Windows host is up to date and running with Developer Mode enabled. It should be possible then to avoid the creation of `dummy_link` for determining if symlinking is supported.
