Title

[DocDB] Incorrect update of last_caughtup_physicaltime metric when tablet is applying operation

Description
Jira Link: [Link: DB-14702]
### Description

XClusterTestWaitForReplicationDrain.TestConsumerPollFailureMetric in TSAN fails intermittently, about 2 out of every 10 times, due to a tablet being incorrectly marked as drained.
Here is the error message:
```
../../src/yb/integration-tests/xcluster/xcluster-test.cc:2977
Failed
Bad status: Illegal state (yb/integration-tests/xcluster/xcluster_test_base.cc:810): Mismatched number of non-drained streams. Expected 9, got 8

```
Root cause:
Currently, source consider target is caught up when GetChanges responds with 0 records.
```
void CDCServiceImpl::UpdateTabletXClusterMetrics(
  ...
  if (records_size  last_caughtup_physicaltime->set_value(GetCurrentTimeMicros());
```
However, In scenarios where the majority replicated op ID has advanced but the last committed op ID has not, GetChanges responds with 0 records. However, this does not indicate that the target is fully caught up, as more records remain to be read.
