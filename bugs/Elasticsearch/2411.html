Title

S3Service Leaks S3ClientSettings on Repository Close

Description
There is a small memory leak in `org.elasticsearch.repositories.s3.S3Service`'s handling of `S3ClientSettings`.
If you use a repository definition that includes any setting override in the `Settings` in `RepositoryMetadata` like e.g. `endpoint` then the cached settings instance will never be removed from `org.elasticsearch.repositories.s3.S3Service#derivedClientSettings` when closing the repository even though it's not used by any client any longer.

A reproducer test for the issue would be:

```
java
    public void testCachedClientsAreReleased() {
        final S3Service s3Service = new S3Service();
        final Settings settings = Settings.builder().put("endpoint", "[URL]
        final RepositoryMetadata metadata = new RepositoryMetadata("first", "s3", settings);
... [Log Snipped] ...
        assertNotSame(clientSettings, clientSettingsReloaded);
    }
```

The last line currently fails, because even though no client remains that uses the `clientSettings` instance the cache still finds cached settings for the given metadata.


This is practically a non-issue and has been around ever since at least 6.8.x without any one noticing. We should still fix the logic in `S3Service` to properly clean up the settings cache at some point.
