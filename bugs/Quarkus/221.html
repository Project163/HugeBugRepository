Title

RESTEasy does not return the ErrorMessage when JSON is expected from the client

Description
How to reproduce:
from a new project with resteasy-jsonb in

```
@Path("/api")
@Consumes(MediaType.APPLICATION_JSON)
@Produces(MediaType.APPLICATION_JSON)
public class TodoResource {
    //@GET
... [Log Snipped] ...
    }
}
```

Note the commented `@GET`.

It leads to the following cryptic error

```
2019-09-03 10:17:16,577 ERROR [io.und.req.io] (executor-thread-3) Exception handling request b79b6cef-aa9b-4cde-ad23-a6ffab0a61ac-6 to /api/: org.jboss.resteasy.spi.UnhandledException: org.jboss.resteasy.core.NoMessageBodyWriterFoundFailure: Could not find MessageBodyWriter for response object of type: io.quarkus.resteasy.runtime.NotFoundExceptionMapper$ErrorMes
sage of media type: application/json
        at org.jboss.resteasy.core.SynchronousDispatcher.writeException(SynchronousDispatcher.java:221)
        at org.jboss.resteasy.core.SynchronousDispatcher.lambda$invoke$4(SynchronousDispatcher.java:249)
        at org.jboss.resteasy.core.SynchronousDispatcher.lambda$preprocess$0(SynchronousDispatcher.java:153)
... [Log Snipped] ...
        at org.jboss.resteasy.core.SynchronousDispatcher.writeException(SynchronousDispatcher.java:217)
        ... 52 more
```

So the error fails to serialize and thus hides the underlying error.

Proposal:
- make sure `NotFoundExceptionMapper$ErrorMessage` has a JSON mapper
- make the RESTEasy error report better upstream
