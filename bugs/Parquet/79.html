Title

ParquetThrift should throw when unrecognized columns are passed to the column projection API

Description
It appears that giving wrong / unrecognized column names to the projection API doesn't fail fast or even report that the columns were unrecognized at all. 

 We should also log at start up what columns are being projected, this is useful info to have in the logs.
Discussion
- skrishnan  points out that passing a wrong column name actually causes all columns to be dropped, which is bad news
