Title

EQL: Allow event in sequences without tiebreakers

Description
Based on the discussion in #64671, the following [Link: inconsistency] has been identified:

When a tiebreaker is missing, we do not validate its existence for event queries however for sequences, we do (and throw a somewhat obscure exception otherwise).
We should align the two - currently a missing tiebreaker occurs after those that specify it. That is null/missing is considered greater than a specified value so that those that do take priority.
We can apply the same for sequences so events with missing tiebreakers instead of throwing an exception will be considered last and incorporated accordingly into the sequence:

`event[2020-11-06T11:22:33.4444][1]` occurs before `event[2020-11-06T11:22:33.4444][null]`

Considering the behavior of event queries, the same ordering characteristics should apply to sequences.
That is:

1. allow a specified tiebreaker with null value. This means no validation of said field, it might be completely missing.
2. if it's missing, null are considered greater than specified values in order to pick those over those that lack this information. This is consistent with event queries.
