Title

Gradle build fails if there is no src/main/resources/META-INF/resources/

Description
**Describe the bug**
While looking into reverting #2214 so that I could rebase #1986, I noticed that the Gradle build fails if there is no `src/main/resources/META-INF/resources/`. 

**Expected behavior**
Gradle build should work even if there are no `src/main/resources/META-INF/resources`.

**Actual behavior**
Gradle build fails, as shown below.

**To Reproduce**
This can easily be seen in the Quickstart, like this:

```
git clone [URL]
cd quarkus-quickstarts/getting-started
rm src/main/resources/META-INF/resources/index.html
./gradlew clean build --stacktrace

... [Log Snipped] ...
        at io.quarkus.creator.phase.augment.AugmentPhase.provideOutcome(AugmentPhase.java:235)
        ... 86 more
```

Curiously this does not seem to affect Maven builds; `./mvnw clean package
` in  `quarkus-quickstarts/getting-started` works even if you `rm src/main/resources/META-INF/resources/index.html`.


**Environment (please complete the following information):**
 - Output of `uname -a` or `ver`: Linux toby 5.1.6-300.fc30.x86_64 #1 SMP Fri May 31 17:43:23 UTC 2019 x86_64 x86_64 x86_64 GNU/Linux
 - Output of `java -version`: 
```
openjdk version "11.0.3" 2019-04-16
OpenJDK Runtime Environment 18.9 (build 11.0.3+7)
OpenJDK 64-Bit Server VM 18.9 (build 11.0.3+7, mixed mode, sharing)
```

 - GraalVM version (if different from Java): N/A

Discussion
- To unblock #1986 I've proposed a revert of #2214 in #2783 simply by adding a `src/main/resources/META-INF/resources/index.html` (which makes `devtools/gradle-it` build again). Of course that does not fix the problem this bug raises, but works around it. 

The underlying problem should eventually still be fixed, so that Gradle build still work even if one does not have src/main/resources/META-INF/resources. And when that is fixed, it would be nice to have test coverage for it, adding a case for this to #1986 after it's finally merged? ;-)
