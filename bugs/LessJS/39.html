Title

Class stacking - bug or feature?

Description
I'm not sure if the following is a bug or a feature. I couldn't find a less.js group / forum to discuss this, so here it goes.

I used to be able to do something like this:

```
less
.item {
    color: white;
    &.blue { background-color: blue; }
}
... [Log Snipped] ...
    .item.blue;
}
```

...Which resulted in:

```
less
.item {
  color: white;
}
.item.blue {
... [Log Snipped] ...
  background-color: blue;
}
```

At more recent versions this behavior changed and now compiling the file results in a syntax error.

``` text
$ lessc tmp.less
NameError: .item.blue is undefined in /home/www/tmp.less:7:1
6       .item;
7       .item.blue;
8 }
```

Versions:

``` text
$ lessc --version
lessc 1.3.0 (LESS Compiler) [JavaScript]
$ node --version
v0.8.9
$ npm --version
1.1.61
```

Thanks!
Discussion
- This did come up in a different issue report and we assumed (or worked out?) it was a bug...

But I can't guarantee that's right.

At least its not documented behaviour.
- Not sure if it helps somebody, but something very similar with "indirect" appender still works in 1.3.1:

```
#namespace {
  .borders {
    border-style: dotted;
  }
}
.chips {
  #namespace .borders;
}
```

I found it in mixins.less test case.
- It's a bug. I'm close to a fix.
