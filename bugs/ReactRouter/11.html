Title

path params with '+' in them being replaced with a space, breaks path

Description
I traced it down to utils/Path, 

Path.decode
Path.js:41 function (path) {
        return decodeURI(path.replace(/+/g, ' '));
      }

HistoryLocation.js puts the url in the history object with the + sign intact. 

in 

function notifyChange(type) {
  var change = {
    path: getWindowPath(),
    type: type
  };

this calls Path.decode which mangles my url that has a slug in it. 

examples: 

Path.encode(path)
"/places/second-bar-+-kitchen-201-congress-ave-austin-tx"

Path.decode(window.location.pathname)
"/places/second-bar- -kitchen-201-congress-ave-austin-tx"

I end up making an XHR request for this path, and it inserts %20, which is not correct. 

I'm using server rendering, and when I load this same page server side, express keeps the + sign in the url param, so it works.
Discussion
- Is there something that would break if we did this in historylocation.js?

function getWindowPath() {
  return window.location.pathname + window.location.search;
}

?

i feel like the url pushed into the history object shoudl be the same as what's made available in state after router run
