Title

Handling of SIGPIPE

Description
The simple example from the front page of click:

```
import click

@click.command()
@click.option('--count', default=1, help='Number of greetings.')
@click.option('--name', prompt='Your name',
... [Log Snipped] ...
if __name__ == '__main__':
    hello()
```

when piped to a command that closes the pipe prematurely, produces an ugly python stack trace:

```
$ python ./test-click.py --name ob --count 1000 | head -1
Hello ob!
Traceback (most recent call last):
  File "./test-click.py", line 13, in  
    hello()
... [Log Snipped] ...
    return io.TextIOWrapper.write(self, x)
IOError: [Errno 32] Broken pipe
```

Python maps the handling of SIGPIPE to an exception that I believe click.echo is not catching.
It seems it should silently exit in this particular case.
