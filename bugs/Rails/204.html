Title

Association statement cache cause wrong query after table name changed

Description
When accessing an association, a partial query is cached for the relation. After the association's table name changed, the previous cached query is used instead of generating new SQL from the new table.

The project which i'm working on require changing the table name before each request to apply the appropriate database view for the models.

### Steps to reproduce
 
```
ruby
# frozen_string_literal: true

require "bundler/inline"

... [Log Snipped] ...
  end
end
```

### Expected behavior
 
After Comment's table name changed to `visible_comments`.
`Post.first.comments` generate the query:
```sql
SELECT "visible_comments".* FROM "visible_comments" WHERE "visible_comments"."post_id" = 1  [["post_id", 1]]
```


### Actual behavior
 
After Comment's table name changed to `visible_comments`.
`Post.first.comments` generate the query:
```sql
SELECT "comments".* FROM "comments" WHERE "comments"."post_id" = 1  [["post_id", 1]]
````

### System configuration
**Rails version**: 5.1.7

**Ruby version**: 2.4.4
