Title

Ability to rollback a closure-style transactions

Description
Closure-style transaction shortcut is much readable in easy to use, then full code. But closure-style does not allow an easy rollback. The only whay is to `throw` and `catch` custom exception. In that way it will be a mess of that two styles:

```
php
try {
    \Yii::$app->db->transaction(function () {
        if (something was wrong) {
            throw new MyRollbackException();
... [Log Snipped] ...
    // rolled back
}
```

It whould be very nice to have ability to make rollback more easy. For example, it can be something like this:

``` php
\Yii::$app->db->transaction(function () {
    if (something was wrong) {
        throw new \yii\db\RollbackException();
    }
});
```

But the problem is what to do with return value in case of rollback.
May be

``` php
$result = \Yii::$app->db->transaction(function () {
    throw new RollbackException(42);
});
// $result === 42
```

or one more closure, which will be called in case of `RollbackException` and which return value will be used in that case:

```
php
// another method to keep BC
$result = \Yii::$app->db->transaction2(
    function () {
        throw new RollbackException();
... [Log Snipped] ...
);
// $result === 42
```
Discussion
- How about passing the transaction object as an argument to the closure?

```
    $result = \Yii::$app->db->transaction(function ($db, $transaction) {
       $transaction->rollback();
    return 42;
    });
```

Note that you can already access the transaction object directly via $db->getTransaction().
- @SamMousa, transaction object already can be accessed with `$db->transaction`, but there is only one and the same Transaction object. Any way it will be either commited or rollback'ed inside `transaction()` method. So, using `commit()` or `rollback()` in such manner will broke nested transactions.
