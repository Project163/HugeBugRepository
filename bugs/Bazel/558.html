Title

Bazel performance regression since 0.9

Description
### Description of the problem / feature request:

0.10 doubled the build time for 100% remote cache hit builds

### Bugs: what's the simplest, easiest way to reproduce this bug? Please provide a minimal example if possible.

Populate a cache with results of a build under 0.9 and 0.10.x, observe the 100% hit rate builds compared between the two.

I happen to have a large number of C++ targets, and I am beginning to suspect more post-action activity (header inclusion rule) as the source of this. I am attempting to bisect the problem out.

### What operating system are you running Bazel on?

Ubuntu 14.04

### What's the output of `bazel info release`?

0.9, 0.10.1, 0.11
