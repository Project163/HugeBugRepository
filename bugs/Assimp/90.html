Title

Bug: obj-parsing fails if a comment is at the end of a line of a definition with variable number of elements to read.

Description
**Describe the bug**
The parser fails and stops parsing if a comment is at the end of a line defining an element with a variable number of possible elements following the token. For example, when defining a vertex like `v 0.0576127 0.0488792 0.2423 # End point line 1`, the function `getNumComponentsInDataDefinition` in `ObjFileParser.cpp` does not take the `#` comment token into account and continues parsing the line and incorrectly determines that there are 4 components.
Furthermore, the function `getFace` in `ObjFileParser.cpp` also does not stop parsing the current line when it comes across a `#` comment token.
Last but not least, the function `SkipLine` in `ParsingUtils.h` also doesn't skip the rest of the line if there is a `#` comment token.

**To Reproduce**
Steps to reproduce the behaviour:
1. Compile the latest master of assimp
2. Download and build the following sample code or try loading the included linien.obj file with a current version of assimp: 
[Link: AssimpObjCommentBug.zip]
3. Assimp will fail with the exception `DeadlyImportError("OBJ: Invalid face index.")`

**Expected behaviour**
The mentioned functions should stop parsing/skip a line once it reaches the comment character `#` and continue with the next line.

**Platform (please complete the following information):**
 - OS: Windows 10 Pro x64 - 22H2
 - Compiler: MSVC 17.12.1 latest
 - assimp-version: master (commit 6fad13c8)
