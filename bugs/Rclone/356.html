Title

Slow list / download for Azure Blob Storage

Description
#### What is the problem you are having with rclone?

I have container on Azure Blob Storage with 30M files. Listing these files (and downloading them) is slow and limited to around 100/second. With simple ruby script I'm able to reach 1000/second for listing. It also affects download speed which is capped to around 100/second.

ruby

Discussion
- Not to mention rclone uses thousands of transactions (practically one per file?) while ruby script is using few according to metrics dashboard (one per page).
- Consider using `--checksum` or `--size-only` so rclone doesn't have to read the modification time from the metadata - this will reduce the number of transactions greatly.

How are the files arranged - are they in directories or are they all in one directory?

You could also use `--fast-list` but that will use **a lot** of memory perhaps 1k per object.


Yes the azure blob backend has a minimum time between transactions of 10ms hence the 100/second.

This is probably a mistake.  We implemented a pacer for s3 recently which in the happy case of things working properly doesn't delay.  This should probably be applied to all the enterprise class backends eg azure/googlecloudstorage/swift

This isn't user twiddleable at the moment alas.
