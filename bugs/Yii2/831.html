Title

Unexpected unixtime returned from DateValidator::parseDateValueIntl()

Description
### What steps will reproduce the problem?
Configure the validator with a timestampAttribute and a format without time and run it.
### What is the expected result?
The expected result will be a unixtime related to the 00:00:00 hours of my current timezone.
So if I enter a value like '2017-06-15', I am setting this date in my current timezone and if I'm currenty in GMT + 2 (Europe/Berlin) I am expecting a unixtime pointing to '2017-06-14 22:00:00' UTC.
### What do you get instead?
A unixtime pointing to the '2017-06-15 00:00:00' hours UTC. When i parse the unixtime backwars to my current timezone to show or compare the value the received datetime is '2017-06-15 02:00:00' instead of '2017-06-15 00:00:00'

### Additional info

| Q                | A
| ---------------- | ---
| Yii version      | 2.0.12
| PHP version      | 7.0.18
| Operating system | Ubuntu 16.04
Discussion
- The problem is on the $hasTimeInfo variable inside the parseDateValueIntl() method. I think the method should not consider if time is provided or not in the format string to set the timezone for parsing the value.
- Additionally, I would add a feature to the parser to receive the unixtime of the end of the day rather than the one of the beginning of the day when no time is provided in the format string.
- **This is not a bug, this is a feature.** This has already been discussed several times. See the following issues:
* #10737
* #14795
