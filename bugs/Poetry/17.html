## Issue
 

Building wheel packages with Poetry produces different version naming/wheel packages than `bdist_wheel` which is preventing other packages from finding it in our private index.

For example, our library package has a version set to:
```
name = "arroyo-settings"
version = "0+untagged.35.g68290c5"
```
When building it with Poetry it produces a wheel:
```
Building arroyo-settings (0+untagged.35.g68290c5)
 - Building wheel
 - Built arroyo_settings-0_untagged.35.g68290c5-py3-none-any.whl
```
When building with `setup.py bdist_wheel`:
```
arroyo_settings-0+untagged.35.g68290c5-py3-none-any.whl
```

Using the Poetry built wheel, trying to `poetry add arroyo-settings` in our second project, I get the following: [URL]
Discussion
- Ah the version in the metadata wasn't transformed `0+untagged.35.g68290c5` (with the `+`) - which is probably causing the mismatch.
- I see this issue as well when using poetry and devpi server - except the devpi server rejects the upload:

```sh
poetry publish --repository kristofferb_dev

Publishing my-package (0.1.3-dev0+some_branch) to kristofferb_dev
 - Uploading my-package-0.1.3.dev0+some.branch.tar.gz 100%
                                                                                                                                                                                       
[HTTPError]                                                                                                                                                             
400 Client Error: filename 'my-package-0.1.3.dev0_some.branch-py3-none-any.whl' does not contain version '0.1.3.dev0+some.branch' for url: [URL] devpi package index>/kristofferb/dev/ 
```
