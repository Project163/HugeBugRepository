Title

Deprecation notices point to @angular/* which is parsed as a separate JSDoc tag

Description
We use the TSLint `deprecation` rule [URL]
which parses the JSDoc tags to give a message.

In HTTP we have marked things with
`/** @deprecated use @angular/common/http instead */`

which is equivalent to
```
/**
 * @deprecated use
 * @angular/common/http instead
 */
```
so the deprecation text doesn't appear in the lint warning.
Discussion
- I looked a bit into this, the only way I found to make the deprecation message visible is to change the message to 
```
 * @deprecated use @angular/common/http instead
```

In the IDE it will show like such;
[Image: image]

While in the console when running tslint it will show like; 
```sh
RequestMethod is deprecated: use &#commat;angular/common/http instead
```

This is due to [URL] as it's printing the `text` directly,

I am not sure if this is acceptable or not. I did a PR for this. [URL]

Feel free to close it you think it's not enough
- I think we should change it to just avoid the @ sign, it would be just as
readable (possibly more readable) to point to some documentation about the
http -> common/http migration, or link to [URL]
