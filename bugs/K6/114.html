Title

The docker-compose can't build the grafana image

Description
It's not possible to build the grafana image.

Steps to reproduce:
1) `git clone '[URL]
2) `cd k6`
3) `git submodule update --init`
4) `docker-compose up -d influxdb grafana`

Grafana image won't be built
Output:
```
Building grafana
Step 1/6 : FROM grafana/grafana
 ---> 1bfead9ff707
Step 2/6 : RUN apt-get update && apt-get -y install curl
 ---> Running in 3e89ad9d7a9c
Reading package lists...
E: List directory /var/lib/apt/lists/partial is missing. - Acquire (13: Permission denied)
ERROR: Service 'grafana' failed to build: The command '/bin/sh -c apt-get update && apt-get -y install curl' returned a non-zero code: 100
```

Hint: The build will pass when we change the `Dockerfile.grafana` to use basic grafana/grafana image < v5.1.0
[URL]
e.g. `FROM grafana/grafana:5.0.4`

It looks like there were major changes in grafana docker image v5.1.0 which prevents the build process to finish.
Discussion
- Hi @piotrkedzia,

Another way to keep the image version the same, is to do the following:

Under the FROM grafana/grafana line, before the RUN apt-get line in the Dockerfile.grafana, add the following: ```USER root```

I think in the latest images for grafana, they are using a new grafana user which breaks this build. Do NOT switch back to ```USER grafana``` later on in the Dockerfile, it will not work and break the linking between grafana and indexdb.

Entire Dockerfile below:
```
Dockerfile
FROM grafana/grafana
USER root
RUN apt-get update && apt-get -y install curl

... [Log Snipped] ...

CMD ["/run.sh"]
```

***NOTE***: There _may_ be security implications with this change, I really don't know. Use at your own risk. 😈
