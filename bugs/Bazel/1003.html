Title

Crash using --experimental_sandbox_async_tree_delete_idle_threads="auto"

Description

### Feature requests: what underlying problem are you trying to solve with this feature?

Using --experimental_sandbox_async_tree_delete_idle_threads="auto"

I'll have to create a simple use-case to show the problem, but the stacktrace may be enough as the code shows that casting between two types cannot be done.

Discussion
- I'm guessing you first ran with `--experimental_sandbox_async_tree_delete_idle_threads=0` (or not set) and then in the same Bazel instance changed the flag. `SandboxModule.java:610` uses the flag setting rather than the type of `this.treeDeleter` to decide whether to set threads, but it's strange that there's a wrong kind of `TreeDeleter`, that should have been handled during `setup`. The direct fix would be to check `treeDeleter instanceof AsynchronousTreeDeleter` before casting, but that would leave the unfortunate fact that changing the option didn't seem to change the deleter here. This can happen if you interrupt the build after changing the option before the start of the execution phase - then `afterCommand` can get called without `registerSpawnStrategies()` having been called (through `BuildTool.buildTargets()`).  But if `registerSpawnStrategies()` has not been called, we also know there's nothing to clean up, so we can safely ignore this case and only set #threads if we have an `AsynchronousTreeDeleter`.
