Title

No MQTT connection possible because clientId is too long

Description
The used FuseSource MQTT library only supports (outdated) MQTT version 3.1. According to MQTT v3.1 protocol ( [URL] a clientId must be <= 23 characters, otherwise the connection must be rejected by the server. However, in MqttIO ( [URL] the clientId is always appended with a random UUID which itself is longer than 23 characters. This implies that establishing a connection this way should never work. 

 FYI: If you don't encounter this error when testing it may be because some servers do not correctly implement the standard and accept connections with a clientId longer than 23 characters (e.g. HiveMQ) or crash and/or don't respond to such connection requests at all.
