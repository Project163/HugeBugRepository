Title

Background thread exception not caught by test, and test runner crashes and locking up

Description
I was writing some tests of multithreaded code and I came across an issue when a background thread was throwing an exception, that the exception was not caught by the test, but in fact this also causes the whole test runner to fail. And when running the test through the xunit.v3.runner.console CLI tool, it locks up the command line. To isolate the cause, I created this simple test class and helper to show the problem. 
```
C#
public class BackgroundThreadTestHelper
{
   private int entryCount;
   private int exitCount;
... [Log Snipped] ...
   }
}
```

The test TestBackgroundThreadBad is designed to fail, as there is an exception thrown on a background thread, but the expcetion should be caught, and the test failed like any other test, but instead, the result is as follows, when run with the command line tool:
```
xUnit.net v3 Console Runner v3.2.0+9e422989c1 [net48/AnyCPU] (64-bit .NET Framework 4.8.9221.0)
  Discovering: UnitTests
  Discovered:  UnitTests
  Starting:    UnitTests
    UnitTests.BackgroundThreadTest.TestBackgroundThreadBad [OUTPUT] pretending to do work...
... [Log Snipped] ...
        --- End of stack trace from previous location ---
           at System.Threading.ExecutionContext.RunInternal(ExecutionContext executionContext, ContextCallback callback, Object state)
```
This was run with the command:
xunit.v3.runner.console.exe ...\UnitTests.dll -class "UnitTests.BackgroundThreadTest" -nUnit TestResultTestNunit.xml -showLiveOutput
The result is that it locks up, requiring me to manually terminate the test runner, and nothing is reported to the output file. When running with other tests, it terminates any test running, and tests already run are not reported to the output file either.
