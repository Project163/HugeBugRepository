Title

changing a repos path to a new (fresh) folder deletes all files on remote repo

Description
May be I did not understand syncthing, but in my testing environment I had two repos (r1, r2) in sync. At one (r1) of them I changed the path to the repo to a not existing one, expecting that syncthing will create the folder (done.) and sync all the files from the other repo (r2) to my new fresh folder. But syncthing did it the other way round. All the files on the other repo (r2) were deleted (pull: delete).

Why did this happen? I do not think this is the expected / wanted behavior. How does syncthing decide if a file has to be deleted on r2 instead of synced to r1? How could I change the directory of a repo on a machine and do an "initial sync" without having to take care of deleting all files on other repos?
