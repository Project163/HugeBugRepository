Title

bind-level processors can only be applied to DB-specific type when subclassing, otherwise use typedecorator

Description
Hi guys,

Starting on 1.3.0 (also tested on 1.3.1), SQLAlchemy ORM suddenly stopped casting fields defined with ARRAY of Enum values. This works fine on 1.2.18, but as soon as I update to the next version it breaks, leading to a situation where I can't add an instance to a session by setting this kind of field to a list of enum values.

I'm not sure if this is a bug or if the library was changed in a way that this behavior is intended, but is anybody else aware of this?

Please let me know if you want me to provide more details, or a test case perhaps for regression testing - I just wanted to be sure if this is really a bug and not an expected change in behavior first.

Cheers,
Diogo
