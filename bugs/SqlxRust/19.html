Title

InnerPool not dropped when a Pool is created and discarded in quick succession

Description
### Bug Description
The maintenance tasks [Link: spawned] by the InnerPool prevent it from being dropped when a pool is created and dropped in quick succession. If an application uses code that creates and "quickly" discards a pool without manually closing the pool, connections in the pool will be leaked.

I think that the following are probably related to this:

- #1824
- #1862

And these _may_ be related:

- #2294
- #2249
- #1928

### Minimal Reproduction

```
rust
use sqlx::{
    postgres::{PgConnectOptions, PgPoolOptions},
    query, Connection, PgConnection, query_scalar,
};
... [Log Snipped] ...
    println!("{count} connections left open"); // prints 10 connections left open
}
```

```toml
[dependencies]
sqlx = { version = "0.6", features = ["runtime-tokio-rustls", "postgres"] }
tokio = { version = "1", features = ["full"] }
futures = "0.3"
```

### Info
* SQLx version: 0.62
* SQLx features enabled: "runtime-tokio-rustls", "postgres"
* Database server and version: postgres 14.7
* Operating system: macos
* `rustc --version`: 1.67.1
Discussion
- In fact the problem is much simpler. There's nothing to notify the maintenance task that the last handle to the pool has been dropped because you're not calling `.close()`. We recommend doing that anyway, but we should also check on-drop of `Pool` if it's the last handle and if so call `.close()`.
- Even so, without calling `.close().await` you will still have connections hanging around for as long as the TCP keepalive timeout on the server, because dropping `Pool` can't perform a graceful termination as that requires each connection sending a `Terminate` message to the server. I'd recommend being sure to call `.close().await` either way.
- I think that either having Pool perform the check on drop or updating the documentation to recommend manually closing the pool would work. 

Right now, the wording of the documentation makes the manual close call seem optional or at least doesn't give the impression that omitting it would leave the pool's connections open.
- Yeah, it shouldn't leak connections for sure but it's important to be aware that they may not be closed immediately.
