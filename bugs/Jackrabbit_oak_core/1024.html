Title

DocumentNodeStore does not detect hierarchy conflict

Description
The DocumentNodeStore does not detect a hierarchy conflict when a node is added and its parent is concurrently removed.
Discussion
- Added a test (currently ignored) in  [URL]
- The root cause for this issue is the snapshot isolation (SI) implemented by DocumentNodeStore. SI does not guarantee serializability of schedules. The write skew anomaly occurs because adding a node in Oak usually does not modify the parent. A conflict goes undetected if the parent is concurrently removed.
