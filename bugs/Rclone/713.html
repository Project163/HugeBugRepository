Title

s3: --s3-no-head causing: panic: reflect: Elem of invalid type s3.PutObjectInput

Description
Hello,

We are using rclone to transfer files between S3 buckets (disaster recovery plan).
Using **1.59.0** we get a strange error. This error is reproducible. Using version 1.58.1 of rclone everything worked fine. 
If it matters we are using the bitnami/rclone docker image.

This is the command we use:
```shell
rclone --config /tmp/rclones.conf \
    copy s3-source:/bucket-source s3-target:/bucket-target \
    -P --stats 10s --stats-log-level NOTICE --max-backlog 20000 --checkers=96 --transfers=32 \
    --buffer-size 4Mi --checksum --tpslimit 150 --s3-no-head --s3-no-head-object --fast-list
```
In case it matters we copy files from DigitalOcean Spaces (FRA1) to ScaleWay Object Storage (PAR). The source bucket has about 1.1 mio objects (target about the same).

This is the error message we see:
```
panic: reflect: Elem of invalid type s3.PutObjectInput

goroutine 258 [running]:
reflect.(*rtype).Elem(0x0?)
	/usr/local/go-1.18.4/src/reflect/type.go:965 +0x134
... [Log Snipped] ...
created by github.com/rclone/rclone/fs/sync.(*syncCopyMove).startTransfers
	/bitnami/blacksmith-sandox/rclone-1.59.0/src/github.com/rclone/rclone/fs/sync/sync.go:443 +0x45
```

I assume the error is printend after fast-list has finished its work because it took about 17 minutes to get there and there were no`checking` or `transfering` output.

If more information is needed I can try to provide that.
