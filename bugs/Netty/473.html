Title

HttpClientUpgradeHandler.setUpgradeHeaders() append a wrong 'upgrade'.

Description
See [Link: here].

It has to be `HttpHeaderValues.UPGRADE` instead. Most servers should be OK with `HttpHeaderNames.UPGRADE` because they do case-insensitive comparisons, but some (e.g. Jetty) requires it to be `Upgrade` (no lowercase u).
Discussion
- Seems like we should use `HttpHeaderValues` here. The specification calls out the lowercase variant [1]. Should we change `HttpHeaderValues.UPGRADE` to lowercase, and should/are we using case insensitive compare when evaluating this header value?

[1] [URL]
- We are using case-insensitive comparison, which is fine in my opinion. (more tolerating)

Jetty uses case-sensitive comparison and expects `Upgrade`, which seems incorrect. (They just do `.contains()` on a `List ` IIRC.)

So, we could:
- Use `HttpHeaderValues.UPGRADE` instead,
- Change it from `Upgrade` to `upgrade`, and
- Ping the Jetty folks about this so they fix this or they have a chance to disagree.
