Title

Self-deadlock when inserting row with identity column in soft-upgraded database

Description
Create a database called "wombat" with Derby  . 

 Then, in the same directory, execute the following code using the   release candidate: 

  
         Connection c = DriverManager.getConnection( "jdbc:derby:wombat" );
        c.setAutoCommit( false );
        Statement s = c.createStatement();
        s.execute( "create table t(i  int  generated always as identity)" );
        s.execute( "insert into t values ( default )" );
        c.rollback();
 
  

 The INSERT statement will fail with a self-deadlock:

Discussion
- Linking to derby-6554. Seems to be failing in the self-deadlock detection code introduced to fix that issue.
- Attaching derby-6692-01-aa-handleSelfDeadlock.diff. This patch fixes the bug. 

 This situation is exactly the self-deadlock scenario addressed by the machinery which derby-6554 introduced. In 10.10, a lock-timeout exception is thrown in this case. That exception is caught by InsertResultSet, which then escalates the identity-bumping into the parent transaction. The fix is to make InsertResultSet check for self-deadlock as well as lock-timeout.
