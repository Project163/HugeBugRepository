Title

Concurrent Snapshot Delete and Snapshot Repository Removal can Lead to Master Nodes Looping

Description
When executing a snapshot delete we do not check if the repository we are deleting from actually still exists when attempting to put the delete in the cluster state. 
In older versions pre-7.8 where we found this, this would lead to a snapshot delete operation that would apply to a repository that is gone from the cluster state. In versions newer than 7.8 that make use of [URL] this may lead to an infinite loop on the master because the consistent state update will never find the metadata expected by the repository instance in the cluster state.

Working on a fix.
