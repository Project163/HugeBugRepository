Title

Flake8 ignore particular errors per file

Description
In GitLab by @adamchainz on Aug 23, 2016, 06:55

Since 3.0 we can ignore particular errors per line with `# noqa: A123`,  it would be nice if this was extended to the syntax for per file ignore (`# flake8: noqa`) to allow ignoring only particular errors per file e.g. `# flake8: noqa: A123` would ignore all `A123` errors for that file.

This would be particularly useful for removing `# noqa` noise in `__init__` files which have lots of imports just to export them, e.g. Django has in its file `django/db/models/__init__.py`:

```
from django.core.exceptions import ObjectDoesNotExist  # NOQA
from django.db.models import signals  # NOQA
from django.db.models.aggregates import *  # NOQA
from django.db.models.deletion import (  # NOQA
    CASCADE, DO_NOTHING, PROTECT, SET, SET_DEFAULT, SET_NULL, ProtectedError,
... [Log Snipped] ...
)
...
```
Discussion
- In GitLab by @sigmavirus24 on Aug 23, 2016, 07:07

If they're exporting them, why not add them to `__all__`, e.g.,

```py
__all__ = (
    'ObjectDoesNotExist',
    'signals',
    'CASCADE',
    'DO_NOTHING',
    # etc.
)
```

Then they can remove the `# noqa` comments for things they're importing but not using. As for the `import *`s this won't help.

We're planning a different feature that looks a little more like what flake8-putty allows you to do (having a config file with ignore codes per-file). That makes it easier to see at a glance which files are doing making up their own style-guides.
