`array_filter` on unknown value wrongly assumed to return falsey value.

### Summary of a problem or a feature request

Discussion
- If the argument is not an array or union exclusively of array types, the return type of `array_filter` is considered to be `false`. See [URL]

[URL]

[URL]

`ArrayFilterFunctionReturnTypeReturnTypeExtension` calls `TypeUtils::getArrays()`, this function will return an empty array on a mixed type or union with one or more non-array types (see `TypeUtils::map()`).

This causes the type extension to return `false` instead of returning `array|false`.

`TypeUtils::map()` shouldn't return an empty array if there is a non-array type, but just return all array types or a general array type on `mixed`. Than if there is union with a non-array type or in case of `mixed`, `false` should be added as possible return type.

_Before making the change, we need to check if modifying `TypeUtils::map()` doesn't break other rules._
- There should just be a special handling of mixed in this extension,
changing TypeUtils behaviour would break many other things.
