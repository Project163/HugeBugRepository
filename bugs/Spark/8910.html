Title

[YARN] OMP_NUM_THREADS not set to number of executor cores by default

Description
Run this PySpark script with `spark.executor.cores=1` 
  
 
 import  os
 from  pyspark.sql  import  SparkSession
 from  pyspark.sql.functions  import  udf

spark = SparkSession.builder.getOrCreate()

var_name =  'OMP_NUM_THREADS' 

 def  get_env_var():
   return  os.getenv(var_name)

udf_get_env_var = udf(get_env_var)
spark. range (1).toDF( " id " ).withColumn(f "env_{var_name}" , udf_get_env_var()).show(truncate=  False  )
 
  
 Output with release `3.3.2`: 
  
 +---+-----------------------+
|id |env_OMP_NUM_THREADS    |
+---+-----------------------+
|0  |null                   |
+---+-----------------------+
 
  
 Output with release `3.3.0`: 
  
 +---+-----------------------+
|id |env_OMP_NUM_THREADS    |
+---+-----------------------+
|0  |1                      |
+---+-----------------------+
Discussion
- Looks like a regression from   SPARK-41188   where it removed the code that sets the default OMP_NUM_THREADS from PythonRunner. 

 Its PR assumes the code can be moved to SparkContext, unfortunately `SparkContext#executorEnvs` is only used by StandaloneSchedulerBackend for Spark's standalone cluster manager, thus the PR broke YARN as shown in the test case above, probably Mesos as well but I don't have a way to test.
