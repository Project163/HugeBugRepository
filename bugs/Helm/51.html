Title

helm v3 packaging charts differently on windows and linux (breaks artifactory)

Description
I'm trying to package a helm chart and deploy it to a private helm repo on artifactory 6.18.0.

This works fine if I package the chart on linux, but fails if the chart is packaged on windows.

It also works fine with charts packaged on windows with a v2 helm client, so it appears to be an issue introduced in helm v3.

I can also see that the resultant tgz files are different by listing their contents with tar (note the backslashes):

Good (linux or windows v2):
```
$ tar -tvf tds-proxy-1.0.0.tgz
-rwxr-xr-x 0/0             129 2020-03-09 11:47 tds-proxy/Chart.yaml
-rwxr-xr-x 0/0             195 2020-03-09 11:47 tds-proxy/values.yaml
-rwxr-xr-x 0/0            1033 2020-03-09 11:47 tds-proxy/templates/deployment.yaml
-rwxr-xr-x 0/0             547 2020-03-09 11:47 tds-proxy/templates/service.yaml
-rwxr-xr-x 0/0             364 2020-03-09 11:47 tds-proxy/.helmignore
```

Bad (helm v3 on windows):
```
$ tar -tvf tds-proxy-1.0.0.tgz
-rw-r--r-- 0/0             129 2020-03-09 11:57 tds-proxy\\Chart.yaml
-rw-r--r-- 0/0             195 2020-03-09 11:57 tds-proxy\\values.yaml
-rw-r--r-- 0/0            1033 2020-03-09 11:57 tds-proxy\\templates\\deployment.yaml
-rw-r--r-- 0/0             547 2020-03-09 11:57 tds-proxy\\templates\\service.yaml
-rw-r--r-- 0/0             364 2020-03-09 11:57 tds-proxy\\.helmignore
```

This has been [Link: raised as an issue with artifactory], but I feel it's up to helm to package consistently irrespective of where helm package is run. This looks like a bug in the helm v3 windows client.
