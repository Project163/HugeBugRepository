Title

Race condition in MessageToMessageEncoder if ch.write(..) is called from channelWritabilityChanged

Description
Hi,

I triggered a race condition by calling ctx.channel().write(...) from channelWritabilityChanged.

One can argue if it's a bug or expected behavior, but since I think it is very hard to track down for new netty users it should be fixed or the user should be warned in documentation of channelWritabilityChanged.

Assuming your handler calls write in "channelWritabilityChanged" e.g. like:

```
        @Override
        public void channelWritabilityChanged(ChannelHandlerContext ctx) throws Exception {
            if (ctx.channel().isWritable()) 
               ctx.channel().write(anotherChunk);
        }
```

and then write something to the channel

```
channel.write(someChunk);
```

you end up triggering a race condition in MessageToMessageEncoder breaking HTTP chunked transfer.

This could produce this output:

a - size(someChunk)
a - CRLF
a - someChunk
b - size(anotherChunk)
b - CRLF
b - anotherChunk
b - CRLF
**a - CRLF**

instead of 

a - size(someChunk)
a - CRLF
a - someChunk
**a - CRLF**
b - size(anotherChunk)
b - CRLF
b - anotherChunk
b - CRLF

Browser won't parse that and terminate the http connection.

This is because MessageToMessageEncoder triggers multiple writes for each HTTP chunk (chunk size, CRLF, chunk content, CRLF). channelWritabilityChanged seems to get fired between these writes:

```
for (int i = 0; i   ctx.channel().write(anotherChunk));
        }
```

So in my opinion, enqueuing channelWritabilityChanged in the eventloop could fix it inside netty.
