Title

CqlStorage loading compact table adds an extraneous field to the pig schema

Description
CREATE TABLE t (
  key text,
  field1  int ,
  field2  int 
  PRIMARY KEY (key, field1)
) WITH COMPACT STORAGE;

INSERT INTO t (key,field1,field2) VALUES ( 'key1' ,1,2);
INSERT INTO t (key,field1,field2) VALUES ( 'key2' ,1,2);
INSERT INTO t (key,field1,field2) VALUES ( 'key3' ,1,2);
 
  

  
 grunt> t = LOAD  'cql: //ks/t'  USING CqlStorage();
 grunt> describe t;                                 
t: {key: chararray,field1:  int ,field2:  int ,value:  int }
dump t;
(key1,1,2,)
(key3,1,2,)
(key2,1,2,)
Discussion
- This is caused by an additional ColumnDef being added in the CfDef used to construct the Pig schema. Where a value_alias is specified for the compact value column, CqlStorage.getKeysMeta adds a ColumnDef for it. The additional one is then added in AbstractCassandaStorage.getColumnMeta, so I've added an additional boolean arg to indicate whether the the value_alias has already been processed. I've also refactored ACS.getColumnMeta a bit to (hopefully) make the logic clearer.
