Title

No elegant way to free non-in/outbound buffers held by a handler

Description
If a handler has other buffers than its inbound (or outbound) buffer, they should be freed by the handler in the two places: `channelDeregistered()` and `handlerRemoved()`.  Previously, it was done in `freeInbound/OutboundBuffer()` until we removed them.

This is a pain because:
- an outbound handler has to implement `ChannelStateHandler` just because of this, and
- The code that frees the buffer has to be duplicated in the two places.

However, I don't think it's a good idea to resurrect `freeInbound/OutboundBuffer()` either because what a user really wants is a place to put the common hook for releasing its resources.
Discussion
- Current idea is to call `handlerRemoved()` for all handlers when a channel is deregistered, which means the pipeline of the closed channel will become empty (i.e. only head handler?)
- I agree with the above idea.
- Makes sense. I think this is even what the user may expect anyway. I think we should just make it clear in the javadocs.
