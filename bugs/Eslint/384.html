Title

Feature request: sharable config as a scoped package

Description
For example, when I (`@shinnn`) publish a sharable config `eslint-config-myconfig` as a [Link: scoped package], npm will place it on `node_modules/@shinnn/eslint-config-myconfig` after installing.

So, if I want to use the config via `extends` option, I should write `.eslintrc` like below:

``` json
{
  "extends": "./node_modules/@shinnn/eslint-config-myconfig/index.js"
}
```

I'd like to use a scoped sharable config more simply, just like:

``` json
{
  "extends": "@shinnn/myconfig"
}
```
Discussion
- Yeah, this is a bug, we should have had this working.
- Any reason why we can't have an arbitrary package name for shared configurations? My first thought when I looked at this issue was, hmm...if I just did a require on @shinn/myconfig and the scoped package name was @shinn/myconfig rather than @shinn/eslint-config-myconfig, this wouldn't require any manipulation of the package name used in the extends.

I think the fix for this could either be, manipulate the package name to add eslint-config- to the package name or drop the requirement to prefix configurations with eslint-config- 

To not be a breaking change, for non-scoped packages, we could first check for eslint-config-  and if not present fall back to the non-prefixed package.
