Title

Setting Host headers causes: TypeError: hostHeader.startsWith is not a function

Description
Since version 2.1.0, setting `Host` header causes `fetch` call to fail. This is a minimal example

    const fetch = require('node-fetch');
    (async () => {
        const resp = await fetch('[URL] { headers: { 'Host': 'example.com' } });
        console.log(resp);
    })();

that throws following exception:

    (node:5895) UnhandledPromiseRejectionWarning: TypeError: hostHeader.startsWith is not a function
        at calculateServerName (_http_agent.js:240:20)
        at Agent.addRequest (_http_agent.js:155:26)
        at new ClientRequest (_http_client.js:257:16)
        at request (https.js:245:10)
        at /home/user/tmp/node-fetch-host-header/node_modules/node-fetch/lib/index.js:1355:15
        at new Promise ( )
        at fetch (/home/user/tmp/node-fetch-host-header/node_modules/node-fetch/lib/index.js:1342:9)

    (node:5895) UnhandledPromiseRejectionWarning: Unhandled promise rejection. This error originated either by throwing inside of an async function without a catch block, or by rejecting a promise which was not handled with .catch(). (rejection id: 3)
    (node:5895) [DEP0018] DeprecationWarning: Unhandled promise rejections are deprecated. In the future, promise rejections that are not handled will terminate the Node.js process with a non-zero exit code.
