Title

Confusing wording for location of no-fallthrough

Description
Here's the code I'm linting:

```
function f() {
    switch (0) {
        case 1:
            console.log(2)
            break
... [Log Snipped] ...
    }
}
```

And here's my package.json:

```
{
    "scripts": {
        "lint": "eslint src"
    },
    "devDependencies": {
... [Log Snipped] ...
    }
}
```

I get the following output:

```
/home/andy/git/ESLINT/src/foo.js
  6:3  warning  Expected a "break" statement before "case"  no-fallthrough

✖ 1 problem (0 errors, 1 warning)
```

There is a `break` before the `case` on line **6**. The missing break is before line **8**.

This could be fixed by changing the message to someting like `Expected a "break" statement at the end of this "case"`.
Discussion
- Should we fix the message or error line reported?
- I also felt odd the message while #4251.
I think changing the location is fine, because it's near to actual problem's location.

```
  8:9  warning  Expected a "break" statement before "case"  no-fallthrough
```
