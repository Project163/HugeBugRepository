Title

Runtime fields and _source disabled

Description
### Elasticsearch Version

8.2

### Installed Plugins

_No response_

### Java Version

_bundled_

### OS Version

Ubuntu 20.04.4 LTS

### Problem Description

Currently when using runtime fields it is not possible to search using `fields` when the index has `_source` disabled.

It will fail with `Unable to retrieve the requested [fields] since _source is disabled in the mappings for index [example-disabled]` even if `_source` isn't being used in a runtime field. Steps below.

Ideally this would fail only if the runtime field referenced `_source` fields.

Usecase is that certain logging platforms configure Elasticsearch indices with `_source` disabled (even though this is not recommended) and `store: true` for fields. Having more flexibility in using runtime fields in this instance would make migrations easier.

### Steps to Reproduce

Create indices with `_source` enabled or disabled.

```
PUT example-enabled
{
  "mappings": {
    "_source": {
      "enabled": true
... [Log Snipped] ...
PUT example-enabled/_doc/1
{}
```

Search over both indices:

```
GET example-*/_search
{
  "fields": [
    "age"
  ]
}
```

Response

```
{
  "took" : 459,
  "timed_out" : false,
  "_shards" : {
    "total" : 2,
... [Log Snipped] ...
  }
}
```
