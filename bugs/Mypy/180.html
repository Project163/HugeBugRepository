Title

Crash with bad encoding

Description
When processing a large number of files, if a single file has a bad encoding, mypy crashes instead of flagging an error and continuing:

```
9.796:LOG:  Parsing Lib/test/bad_coding.py (test.bad_coding)
Traceback (most recent call last):
  File "/usr/local/bin/mypy", line 6, in  
    main(__file__)
  File "/usr/local/lib/python3.2/site-packages/mypy/main.py", line 54, in main
... [Log Snipped] ...

Lib/test/bad_coding.py: error: Internal error -- please report a bug at [URL]
```
Discussion
- I'm going to start looking into this. I'm in the sprint room and am `margaret_` on the IRC `#python-mypy` channel.
- From my understanding, just catching the `LookupError` and raising a `CompileError` should fix this since the `BuildManager` object will collect those instead of crashing. Should I check for the `LookupError` separately or group it in here with the [Link: except `UnicodeDecodeError`]? I think it makes sense to have the same "can't decode file" mypy message.
- ... [Middle Discussions Snipped for Brevity] ...
- Actually, I'm not sure raising a `UnicodeDecodeError` here is correct, since files could be using a different valid encoding. Raising a `UnicodeDecodeError` [Link: requires specifying] the exact position of the invalid character anyway, which doesn't make sense if it couldn't even read the file at all. 

Should I go back to catching the `LookupError` together with the `UnicodeDecodeError`?

Edit: Talked to Greg again. Going to define a general `DecodeError` in `errors.py` and use that.
- I recommend not over thinking it and just doing the first thing that works.
