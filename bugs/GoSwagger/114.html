Title

x-nullable for array values doesn't have any effect Playground

Description
## Problem statement

If an array/slice value is `nil` and the aim is to exclude it from the encoded JSON there doesn't seem to be a way to define that. Is this intended behaviour or should `x-nullable` for a property containing an array or `nil` also result in an `omitempty` annotation within the model spec? If it is intentional, is there any other way to exclude null array values from the encoded response?

In previous version null arrays were excluded but to allow `nil` and empty arrays to be distinguished, improvements got introduced in #707.

In the example given below, the `books` array of a store object is always included in the JSON.

## Swagger specification
```
yaml
swagger: "2.0"
info:
Swagger Playground
... [Log Snipped] ...
    required:
      - message
```

## Steps to reproduce

```go
api.StoreGetStoresHandler = store.GetStoresHandlerFunc(func(params store.GetStoresParams) middleware.Responder {
  res := []*models.Store{&models.Store{
    ID:    1,
    Name:  "My Book Store",
  }} // note the Books attribute is not set
  return store.NewGetStoresOK().WithPayload(res)
})
```

## Expected Result
```json
[{
  "id":1,
  "name":"My Book Store"
}]
```

## Actual Result
```json
[{
  "id":1,
  "name":"My Book Store",
  "books":null
}]
```
Discussion
- Probably, we can add something like 'x-omitempty'?
