### Expected Behavior

The profile entity is being updated when posting data like 

```
php
[
    'id' => 'fafde4e3-25b1-4869-94b6-1b8530e663cf',
    'profile' => [
        'firstname' => 'ADMIN',
... [Log Snipped] ...
    'email' => 'new@email.com',
]
```
### Actual Behavior

The Profile entity not being updated.Its fields are mark as dirty but 'profile' is not dirty in the user entity

```
object(App\Model\Entity\User) {

        'id' => 'f6ae698f-3ce1-400f-b218-eda119718e73',
        'email' => 'new@email.com',
        'profile' => object(App\Model\Entity\Profile) {
... [Log Snipped] ...
        '[repository]' => 'Users'
}
```

As you can see, `profile` is not added in as `dirty` in the `User` entity  after patching and therefore is not saved.

The previous patch did not solved this case, and I didn't found any existing test that covers this scenario.
