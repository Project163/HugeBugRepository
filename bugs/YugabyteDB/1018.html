Title

[DocDB] 2.18.1.x Query error: Schema packing not found' in setup containing a colocated schema with YSQL packed rows enabled

Description
Jira Link: [Link: DB-7371]
### Description

**Note:**

- Currently I am exploring the reproducibility and The build from where we are seeing the issue
- This is seen with the automation- TestYSQLTSPCMVAndBR

**Steps:**

1. Create two Universes (U1 & U2) with splitting enabled, with RPC(algo=1) and PC.
           Perform below ops on U1
```
MASTER_FLAGS["ysql_enable_packed_row"] = "true"
            MASTER_FLAGS["ysql_enable_packed_row_for_colocated_table"] = "true"
            TSERVER_FLAGS["ysql_enable_packed_row"] = "true"
            TSERVER_FLAGS["ysql_enable_packed_row_for_colocated_table"] = "true"
```

  2. Create colocation database with some colocated and some colocated opt out tables
      and non colocated database with some tables (HASH and RANGE Shard Tables)
  3. Create Unique, Secondary and Partial indexes for some tables.
  4. Create Materialized Views for some tables
  5. Load some data and validate data in tables and indexes and refresh Materialized Views
     and validate data
  6. Create 2 more tables(1 HASH and 1 RANGE) and Materialized Views and indexes and
     load data using COPY FROM cmd(50K rows/ table) to both tables
  7. Collect data points and take backup(B1)
  8. Do some DDLs and DMLS(Add a column, update a column name and Insert, delete and updates)
     and validate data and tablets
  9. Take backup(b2)
  10. Drop database and restore B1 and validate data and tablets
  11. Restore B2 into that U2
  12. Validate data and tablets at both universes
        
**Issue**:
On executing a `select * on one of the non_colocated_db` tables in the source universe, this error is returned.  this error does not go away-
  ```
  non_colocated_db=# select count(*) from non_colocated_employees;
  ERROR:  Schema packing not found: 7, available_versions: [9, 0]
  ```

Discussion
- This error messages indicates there's a schema version used by a row in a rocksdb table that's not present in the old schema packings for the table. When using the packed columns feature this makes the row unreadable. It's the backup/restore mechanism's job to save all required schema packings with the other backup files and restore them correctly as part of the restore flow.

In this case it looks like either the backup code did not save the required schema packings correctly or they were removed from the original database while they were still required. Since the source DB of the backups is dropped in this test I can't be sure what happened. My process was extracting the files from the saved backup and using the tool `sst_dump` with the tablet metadata. In the tablet backed up tablet ` `, sst files 49 and 50 are missing schema packings.
- From the logs a snapshot and a compaction were interleaved for the tablet missing some schema packings[0]. It's possible the snapshot creation flow saved sst files from before the compaction and saved a copy of tablet metadata from after the compaction. If the rows with older schema packings were GC'd by the compaction, the schema packings may have been GC'd from the tablet metadata causing the error.
