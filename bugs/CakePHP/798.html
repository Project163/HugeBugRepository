Title

Table::save() should return false if transaction gets rolled back in afterSave() callback

Description
Currently if for e.g. you are saving a record in `afterSave()` callback and the operation fails the transaction would be rolled back but the primary `save()` would still return an entity instead of `false`.

@lorenzo is aware of the problem so I won't go into details :)
Discussion
- Isn't `afterSave` now implemented with events. As a result, there could be many listeners responding to `afterSave`. As far as I'm aware, there is no way for a listener to signal that the event is a failure. You can only signal the stopping of propagation.

I would recommend an exception be thrown that is caught by the `Table::save()` when it broadcasts the afterSave. That would be easier and more stable than trying to handle a response true/false from multiple listeners. 

Developers would have to throw this exception from afterSave to signal a failure.
- So the point that I was making was this section of code in the EventManager

```
foreach ($listeners as $listener) {
            if ($event->isStopped()) {
                break;
            }
            $result = $this->_callListener($listener['callable'], $event);

            }
        }
```

It makes it difficult to signal failure. If a listener returns false it stops propagation, but will not set the $event->result to false. The developer would have to maybe set $event->result = false and also return false.

I've been using exceptions in my listeners and this has worked better, but it's not directly supported by the EventManager

We could add some specific exceptions like `EventStopException` and `EventAbortException` that would be caught by EventManager and handled better.

As far as `save()` is concerned when it broadcasts `afterSave` it's responsibilities are done. That is the purpose of that event.
