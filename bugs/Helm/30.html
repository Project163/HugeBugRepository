Title

Helm v3 packaging apiVersion v1 Charts packages in apiVersion v2 format

Description
Output of `helm version`:


Output of `kubectl version`:



Cloud Provider/Platform (AKS, GKE, Minikube etc.): Bare-metal K8s deployment

This would be a duplicate of #6887, but that's been closed as an intended feature affecting downstream users of the dependency system.

The bug *here* is that the Chart's apiVersion is still `v1` after packaging, but it no longer works with tools that support Chart apiVersion v1, such as Helm v2.

Along auto-merging of requirements.yaml into Chart.yaml by `helm package`, the Chart apiVersion should have been auto-updated to `v2` so that Helm v2 would have given a hard failure to install with meaningful output.

My preference would have been to continue including requirements.yaml when packaging an apiVersion v1 Chart.

The problem this introduces for Helm v2 is that aliases in requirements.yaml are no longer visible, so installations that use the same chart multiple times via aliases fails and logs something less-directly useful like
Discussion
- I also noticed that such packages also fail `helm lint`:
```
PS> helm lint ..\service-0.18.1-autobuild.3266+master.g34455f13.tgz -v 9
==> Linting ..\service-0.18.1-autobuild.3266+master.g34455f13.tgz
[INFO] Chart.yaml: icon is recommended
[ERROR] Chart.yaml: dependencies are not valid in the Chart file with apiVersion 'v1'. They are valid in apiVersion 'v2'

Error: 1 chart(s) linted, 1 chart(s) failed
```

I was trying to work around this by manually adding the files with `tar` and `gzip`, but it appears that Helm adds some [Link: magic to the gzip `FEXTRA` field], and without that, it cannot find `Chart.yaml` in Helm v2 or Helm v3.

I haven't yet found in the codebase where that magic is consumed though.
- The fix for the Helm v2 compatibility break should be as-simple as adding the code from the `default:` case in `func LoadFiles` to the end of the cases for `requirements.lock` and `requirements.yaml`.

It'd be *nicer* (and fix the `helm lint` test) if the `Chart.lock` and `dependencies` field of `Chart.yaml` were not written out in the APIVersion1 case.
