Title

Global Channel ID map can leak

Description
If a user creates a new channel and then deregisters it before closing it, the ID of the channel will never be reclaimed from the global ID map, because there's no way for Netty to know when the underlying JDK channel is really closed.

I can think of the two ways to fix this issue.
- Remove `Channel.id()`. A user gets the ID via `hashCode()` instead because it's not collision-free anymore.  Keep the ID internally and continue including it as a part of the string representation of a Channel.  Because there is very low chance of ID collision already, it will still be useful to find a specific Channel from a log file.
- Add `AbstractChannel.removeId()` so that a user can remove the ID from the global ID map manually.

I prefer the first solution in spite of the backward compatibility problem.  If a user was using Channel IDs as a key or a value of a map or a collection, he or she will have to use the Channel references instead.

The second solution is error-prone at best and thus it just isn't worth it in my opinion.
