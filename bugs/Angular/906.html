# 🐞 bug report

### Affected Package
 
  Ivy


### Is this a regression?

 
 

Yes, works in non-ivy.

### Description

May be related to [URL] however, supposedly that was fixed in `9.0.0-next.1`, so I'm reporting it here again in case it is a different problem. 

Here's what I've discovered:
1. This problem only appears when an `ng-packagr` library is used.
2. This problem goes away if `--prod --aot` is used (however then you will run into [URL]
3. Doesn't happen if `enableIvy` is set to `false`.

**EDIT**: All of the above is not really relevant, as apparently `angular-test` is actually installed into `node_modules` and processed by ngcc 🤦‍♂
- So, the bug is with _ngcc_, where the `ItemsComponent`'s metadata has a declaration node of `class ItemsComponent {}` (the inner class declaration), whereas the component's scope (i.e. its registration in `ComponentsModule`) is registered under `let ItemsComponent = class ItemsComponent {}` (the outer class declaration). Therefore, the scope of the component can't be determined which results in the `directives: [i1.NgForOf]` to be missing from the compiled code.
