Title

query.update check, warning in 0.9 execption in 1.0, incorrect for pypy

Description
**Migrated issue, originally created by Michael Bayer ([Link: @zzzeek])**

```
from sqlalchemy import *
from sqlalchemy.orm import *
from sqlalchemy.ext.declarative import declarative_base

Base = declarative_base()
... [Log Snipped] ...

s.query(A).update({"data": "foo"})
```

run w/ pypy:

```
#!

Traceback (most recent call last):
  File "app_main.py", line 75, in run_toplevel
... [Log Snipped] ...
    (methname, )
InvalidRequestError: Can't call Query.update() or Query.delete() when join(), outerjoin(), select_from(), or from_self() has been called
```

because we are testing `() is ()`, bzzt
Discussion
- **Michael Bayer ([Link: @zzzeek]) wrote:**

- Fixed regression from 0.9.10 prior to release due to :ticket:`3349`
where the check for query state on :meth:`.Query.update` or
:meth:`.Query.delete` compared the empty tuple to itself using ``is``,
which fails on Pypy to produce ``True`` in this case; this would
erronously emit a warning in 0.9 and raise an exception in 1.0.
fixes #3405
