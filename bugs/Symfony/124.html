Title

[config] Error occurs when the key attribute is removed from the child node and only a key named 'value' is left there

Description
When the key attribute is removed from a child node of a prototyped array node, if there is only one key named 'value' left in the child node, the child node will be degenerated from an array into a string.
When processing the config tree, an 'Symfony\Component\Config\Definition\Exception\InvalidTypeException' is thrown.

The root cause of this issue is: 
before the degeneration, the prototype of the child node is ArrayNode and the child node matches its prototype. After the degeneration, the child node has become a ScalarNode, but its prototype is still ArrayNode.
I have created PR #14082 for this issue, but didn't receive any feedback yet.

The following example may reproduce this issue:

```
php
 buildTree();
$result = $processor->process($tree, $configs);
```

```
yml
# attribute-as-key-left-value-only.yml
app:
    parameters:
        - name: server_name
... [Log Snipped] ...
        - name: password
          value: password
```

Assume the original data parsed from YAML is as follows:

```
php
array(
    'parameters' => array(
        array(
            'name' => 'name1', 
... [Log Snipped] ...
    )
)
```

If the 'parameters' node is defined as a prototyped array and its key attribute is 'name', then the data will be changed to:

```
php
array(
    'parameters' => array(
        'name1' => array(
            'value' => 'value1'
... [Log Snipped] ...
    )
)
```

Now, because there is only one key named 'value' left in its child nodes, which is a special name as per the specification, the data is supposed to be further simplified to:

``` php
array(
    'parameters' => array(
        'name1' => 'value1', 
        'name2' => 'value2'
    )
)
```

But, if you try the example code I provided, an `Symfony\Component\Config\Definition\Exception\InvalidTypeException` is thrown.

I have addressed the root cause of this issue:
1) The original prototype of node 'parameters' is an array node, which matches the type of its child nodes:

```
php
array(
    'parameters' => array(
        array( // child node is array, prototype is array too
            'name' => 'name1', 
... [Log Snipped] ...
    )
)
```

2) After the data structure is simplified, the type of its child nodes is changed to scalar, but the prototype is still an array node:

``` php
array(
    'parameters' => array(
        'name' => 'value1', // child node is scalar, but prototype is array
        ...
    )
)
```
