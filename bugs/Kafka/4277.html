Title

OOM when loading large uncompacted __consumer_offsets partitions with transactional workload

Description
When loading a large poorly compacted __consumer_offsets partition with a transactional workload (alternating transaction offset commits and commit markers), we create and discard lots of TimelineHashMaps. These accumulate in the SnapshotRegistry's rollback mechanism. Overall, memory usage is linear in the size of the partition. 

 We can commit the snapshot every N offsets in  CoordinatorLoaderImpl , to allow the memory to be reclaimed.
