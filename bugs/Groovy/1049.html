Title

Compiler incorrectly generating bridge methods

Description
In the code below: 

 public class GroovyBean { 
  @Lazy volatile String foo = 
{ ['some','items','in','the','lists'] }
 () 
} 

 The compiler generates get$foo and set$foo methods. Both of these are marked as bridge methods which is incorrect because they are not actually bridge methods at all.
Discussion
- It's some fault of groovy and some fault of Java probably. 

 Groovy's fault is that it is creating the get$field / set$field methods and setting their modifiers as the field's modifiers without considering the fact that some modifiers make sense for fields but not for methods - like volatile, transient. 

 Java's fault is that it is using the "same" modifier bits to indicate volatile fields/bridge methods( ) and transient fields/varargs methods( ). So, even though, what groovy is doing is marking a method as "volatile" (and not marking it as "bridge"), Java takes it as "bridge" because same bits are used for both and a method as volatile does not make sense to Java. 

 So, a volatile field's getter/setter show up as bridge methods and a transient field's getter/setter show up as varargs methods as shown in the code below: 

  
  import  java.lang.reflect.*

 public   class  GroovyBean {
	@Lazy  volatile   String  foo =  "anything" 
    @Lazy  transient   String  bar =  "anything" 
}

def fooMethod = GroovyBean. class. getMethod( 'get$foo' )
def barMethod = GroovyBean. class. getMethod( 'get$bar' )

 // both checks below respond  true  as same bits are used
  assert  fooMethod.isBridge()
 assert  Modifier.isVolatile(fooMethod.modifiers)

 // both checks below respond  true  as same bits are used
  assert  barMethod.isVarArgs()
 assert  Modifier.isTransient(barMethod.modifiers)
 
  

 I guess Verifier#visitProperty() needs a change in that when it creates getters/setters, before relaying the field modifiers to the getter/setter modifiers, it should clear out the bits for transient/volatile as methods cannot be transient/volatile. 

 Any issues seen with that?
- Just to add that it is not an issue with @Lazy but a general groovy issue, as observed in the regular groovy code below: 
  
  import  java.lang.reflect.*

 public   class  GroovyBean {
     volatile   String  foo =  "anything" 
     transient   String  bar =  "anything" 
}

def fooMethod = GroovyBean. class. getMethod( 'getFoo' )
def barMethod = GroovyBean. class. getMethod( 'getBar' )

 assert  fooMethod.isBridge()
 assert  Modifier.isVolatile(fooMethod.modifiers)

 assert  barMethod.isVarArgs()
