Title

Any base class should not match None

Description
Consider this (oversimplified) code:
```python
from typing import Any

dynamic: Any

class C(dynamic): ...

y: None = C()
```
It passes mypy without errors, but it arguably should not, because `None` is a _non-subclassable_ singleton.

In reality, this causes the following problem: descriptors need to distinguish between access on classes and access on instances, in the former case the instance is `None`. Mypy works well with this pattern that allows to correctly type various ORM patterns. However, if a class has `Any` fallback, then the class and instance access are confused causing weird bugs.
