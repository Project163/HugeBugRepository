Title

[YSQL] In some rare cases YSQL attempts to fetch dropped column from DocDB

Description
Jira Link: [Link: DB-11731]
### Description

BNL + IndexScan with CBO returns the following error: 

`ERROR: cache lookup failed for type 0` after dropping a column on a table.
`

kind/bug

Discussion
- The case reported is quite complex, there is easier repro:
```
yugabyte=# create table t1(k1 int, k2 int, v0 int, v1 int, v2 int, primary key ((k1, k2) hash));
CREATE TABLE
yugabyte=# alter table t1 drop column v0;
ALTER TABLE
yugabyte=# create index on t1(k1, k2, v1); 
... [Log Snipped] ...
        before or while processing the request.
The connection to the server was lost. Attempting reset: Succeeded.
```
It is a code bug, where v1 column is supposed to be added to the fetch list, and column number in the index is used instead of the column number in the table, coincidentally the table has a dropped column in that position. In debug builds it triggers an assertion failure, in release it proceeds and fails because deleted columns have InvalidOid as the type Oid. Without deleted column it may have small performance impact, as column is unnecessarily fetched.
