### Describe the Bug

Using a middleware that performs a path rewrite like the following

`middleware.ts`:

```
ts
// eslint-disable-next-line @next/next/no-server-import-in-page
import { NextRequest, NextResponse } from 'next/server'

// RegExp for public files
... [Log Snipped] ...
  return NextResponse.rewrite(url)
}
```

Will cause an error (404) and reload the page on the `Link` component for `/` urls when used with `shallow`

Example

```
tsx
const Example = () => (
<>
   Home  {/* this will fail to resolve and reload the page */}
   Home  {/* this will fail to resolve and reload the page */}
... [Log Snipped] ...
 
)
```

The same error happens with `router.push`.

A different error happens also for `router.push`, when used like so:

```ts
  const onClick = useCallback(() => {
    push('/[device]', '/', { shallow: true })
  }, [push])
```
```
Error: The provided `as` value (/) is incompatible with the `href` value (/[device]). Read more: [URL]
```

The error exists (as far as I can tell) since next `12.1.1`. It works correct in `12.1.0`.

### Expected Behavior

It should not fail with a `404` and reload the page but just route correctly.

Discussion
- I ran into the same issue on non-root paths as well. I think it affects any route where the middleware rewrite is adding dynamic params to the URL.

I think this is due to this change which was [Link: released in v12.1.1]: [URL] 

Before that PR, the middleware would be called to rewrite the `href` route, but after the PR it must resolve directly to the destination route.

The workaround I found is to:
- Use the rewritten destination route as the `href` (`/[device/` in your example)
- Include the dynamic params as query parameters in the `href`
