Title

NameError resolving forward ref when non-builtin type is mapped on base class in different module

Description
### Describe the bug

Given a base class that defines a column with a forward ref type defined in one module, and a subclass defined in another module, resolution of the base class forward ref annotation occurs with the subclass module globals. This is an issue if the mapped type on the base class isn't a builtin, or if the annotation name is defined in the subclass module with a different type to the name in the base class module.

### To Reproduce

Given project layout:

- `app/lib/orm.py`
- `app/lib/domain.py`
- `app/main.py`

```
python
# app/lib/orm.py

"""Application ORM configuration."""
from __future__ import annotations
... [Log Snipped] ...
    def __tablename__(cls) -> str:
        return cls.__name__.lower()
```

```
python
# app/lib/domain.py
from sqlalchemy.orm import Mapped

from lib.orm import Base
... [Log Snipped] ...
class Author(Base):
    name: Mapped[str]
```

```python
# app/main.py
from lib.domain import Author
```
