Title

Angular 9 during language build causes "No translation found for " " (" {$ICU} ").

Description
# 🐞 bug report

### Affected Package
With Ivy disabled the language build succeeds


### Is this a regression?
Yes, this error started appearing after our upgrade from 8.2 to 9.1.1.  Disabling Ivy is our current workaround.


### Description
The issue only appears to affect translations that make use of the ICU select format. After further testing it seems that ivy doesn't like it when a value is passed to a component via Input().

- So I think we have found the source[sic] of the problem. Traditionally we have had to keep whitespace inside ICU expressions when generating message ids. But it seems that we should be normalizing out the `\r` characters from line-endings. At least it appears that the old ViewEngine message extraction is doing so.
- By the way, if you were to use `XLIFF 2` or `XMB` formats for your translation files then this is already fixed. Note that the "decimal" ids are the same in both cases. The `XLIFF 1.2` format is using a legacy message id digest that we want to retire.
