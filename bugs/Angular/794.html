Title

ivy: ngcc does not append the inputs that has same name with selector

Description
# 🐞 bug report

### Affected Package
@angular/compiler
@angular/router

### Is this a regression?
No

### Description
Ngcc does not append the inputs which suit with the directive selector. 

## 🔬 Minimal Reproduction
[URL]


## Current behavior 
Ngcc generates directive def like so
```
typescript
RouterLink.ngDirectiveDef = ɵngcc0.ɵdefineDirective({
    ...
    inputs: {
      // Expected routerLink input
... [Log Snipped] ...
    }
});
```

## Expected behavior
```
typescript
RouterLink.ngDirectiveDef = ɵngcc0.ɵdefineDirective({
    ...
    inputs: {
        routerLink: 'routerLink',
... [Log Snipped] ...
    }
});
```
Discussion
- I would add that this applies to all accessor decorators like:

**router-link.ts**
```
@Input()
set routerLink(commands: any[]|string) {
  ...
}

... [Log Snipped] ...
  ...
}
```

Since they become in generated js both:  CallExpression members and decorators

```
// members
Object.defineProperty(RouterLinkWithHref.prototype, "routerLink", {
    set: function (commands) {...},
    enumerable: true,
    configurable: true
... [Log Snipped] ...
  __metadata("design:paramtypes", [Boolean])
], RouterLinkWithHref.prototype, "preserveQueryParams", null);
```
Esm2015ReflectionHost loops over those members, removes each key from `decoratorsMap` and tries to retrieve class member.
[URL]

But it can't since it's not class member but rather CallExpression

[URL]

@petebacondarwin Please take a look. I think you know more)
- A quick check seems to show that it is fine for ES2015 files but is a problem with ES5 files.

And as @alexzuza suggests the problem is that in ES2015 the `setter`  property looks like


```
ts
set routerLink(commands) {
    if (commands != null) {
        this.commands = Array.isArray(commands) ? commands : [commands];
    }
... [Log Snipped] ...
    }
}
```

whereas in ES5 it is a call to `defineProperty` which we are not reading as a "member" of the class.

```
ts
Object.defineProperty(RouterLink.prototype, "routerLink", {
  set: function (commands) {
      if (commands != null) {
          this.commands = Array.isArray(commands) ? commands : [commands];
... [Log Snipped] ...
  configurable: true
});
```


We need to teach the `Esm5ReflectionHost` how to read these members of a decorated class.
