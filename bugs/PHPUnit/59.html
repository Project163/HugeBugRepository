Title

XSD schema in 5.x does not validate

Description
I'm not particular good at XSD schemas so I cannot really judge if this serious thing or not. But when I run the 5.x version of `phpunit.xsd` through a validator I get an error stating.

```
Not valid.
Error - Line 14, 38: org.xml.sax.SAXParseException;
lineNumber: 14;
columnNumber: 38;
cos-nonambig: whitelist and whitelist (or elements from their substitution group)
              violate "Unique Particle Attribution". During validation against 
              this schema, ambiguity would be created for those two particles.
```
Discussion
- I am not particularly good at XSDs either, but `xmllint` has no problem:

```
$ xmllint --schema phpunit.xsd --noout phpunit.xml
phpunit.xml validates
```
- Sax seems to be a lot stricter with XSD handling than libXML2. While having a choice of two times the same child element doesn't make any logical sense of course it shouldn't actually be a problem when verifying a document as either choice would lead to the same result.

While the PR by @kubawerlos fixes the duplication, the xs:choice could also be removed as it's superfluous with only one sequence to choose from.
