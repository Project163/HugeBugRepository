Title

Nillable field, in a json payload, was sent as "@nil":"true" instead of an empty string

Description
Moving from CXF version 2.2.7 to 2.7.13 a nillable field, in a jax-rs client with json format, wil be sent with the annotation "@nil":"true" instead of an empty string (as configured). 

 The request with the version 2.7.13 
  
 ---------------------------
ID: 1
Address: [URL]
Http-Method: POST
Content-Type: application/json
Headers: {Accept=[application/json], Content-Type=[application/json]}
Payload: {"nillableField":{"@nil":"true"}}
--------------------------------------
 
  

 The request with the version 2.7.7 
  
 ---------------------------
ID: 1
Address: [URL]
Http-Method: POST
Content-Type: application/json
Headers: {Accept=[application/json], Content-Type=[application/json]}
Payload: {"nillableField":""}
--------------------------------------
 
  

  The client configuration

- Test case that reproduce the problem. 

 In pom.xml switch the parameter cxf.version in order to change the used library 
  
  <properties> 
      <!-- cxf.version> 2.7.7 </cxf.version -->  
     <cxf.version> 2.7.13 </cxf.version> 
     <project.build.sourceEncoding> UTF-8 </project.build.sourceEncoding> 
     <maven.compiler.source> 1.7 </maven.compiler.source> 
     <maven.compiler.target> 1.7 </maven.compiler.target> 
 </properties>
- Thanks for a test. Debugginghas confirmed that XMLStreamWriter.writeAttribute(String name, String value) is called without the XSI prefix and namespace. So it is is not a bug
