Title

@ConsumeEvent can return `Uni ` if parameter is `T` but throws error for `Message `

Description
### Describe the bug

The [Link: "Using the event bus" documentation] has examples of methods annotated with `@ConsumesEvent` returning `void`, `R`, and  `Uni `:

```
java
@ConsumeEvent("greeting")
public String consume(String name) {
    return name.toUpperCase();
}
... [Log Snipped] ...
    return Uni.createFrom().item(() -> name.toUpperCase()).emitOn(executor);
}
````

Based on the examples I'd expect the same to work for `Message `, but attempting to consume an event from `EventBus.send` or `EventBus.request` results in a `NoSuchMethodError`. 

This occurs with both Kotlin and Java.

### Expected behavior

A method annotated with `@ConsumesEvent` can return either `void` or `Uni ` regardless of whether the parameter is `T` or `Message `.

### Actual behavior

If the method parameter is `Message `, the Vertx event bus only works if the return type is `void`.
