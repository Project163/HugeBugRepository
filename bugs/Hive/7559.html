Title

Disable export/import of views and materialized views

Description
According to  [URL] import and export can be done by using the 
  
 
export table ...
 import  table ... 
 
  
 commands. The document doesn't mention views or materialized views at all, and in fact we don't support commands like 
  
 
export view ...
 import  view ...
export materialized view ...
 import  materialized view ... 
 
  
 they can not be parsed at all. The word table is often used though in a broader sense, when it means all table like entities, including views and materialized views. For example the various Table classes may represent any of these as well. 

 If I try to export a view with the export table ... command, it goes fine. A _metadata file will be created, but no data directory, which is what we'd expect. If I try to import it back, an exception is thrown due to the lack of the data dir:

- I agree that in the context of import/export statements, we might not require supporting view/MV. however the code paths for replication and export/import is common in lot of places since they do similar things during bootstrap.  
For replication including view + MV would be required and work well since we would copy the state of MV based on valid Txn List. Currently replication performs view replication as it is ( Assuming the view definition is only restricted to data in the same db ) and disables MV's.  We will try to prevent MV export/import and only enable it via replication.
