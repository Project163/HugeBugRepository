Title

Literal[negative int]

Description
Python 3.7.4
typing_extensions 3.7.4
mypy git tip ( 0.750+dev. ):

mypy returns false positives for negative integer literals.
errors inlined for convenience:
```
python
from typing_extensions import Literal


a: Literal[-2] = -2  # error: Incompatible types in assignment (expression has type "int", variable has type "Literal[-2]")
... [Log Snipped] ...
d: Literal[1] = 1
e: Literal[2] = 2
```
Discussion
- Apparently nobody thought of negative integer literals! This clearly looks like a bug. Either negative literals should be rejected in literal types or they should work as expected.

cc @Michael0x2a
- By coincidence, I also ran into this the other day -- the problem is expressions like `-1` are actually `(1).__neg__()` and so we end up using the return type of just `__neg__()`, which is just int.

The easiest fix is probably to special-case the `__neg__` method for ints using a plugin. E.g. intercept `Instance` objects and copy over the `last_known_value` field to the return type or something.

(If somebody wants to try taking this, feel free. Otherwise, I'll probably work on this later next week.)
