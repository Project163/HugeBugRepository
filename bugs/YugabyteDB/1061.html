Title

[YSQL] alter user fails in per-database catalog version mode when publication for all tables exist

Description
Jira Link: [Link: DB-8937]
### Description

1. create a cluster and convert it into per-database catalog version mode

```
yugabyte=# select * from pg_yb_catalog_version;
 db_oid | current_version | last_breaking_version
--------+-----------------+-----------------------
      1 |               1 |                     1
  13242 |               1 |                     1
... [Log Snipped] ...
  13246 |               1 |                     1
(5 rows)
```
The above query output indicates that the cluster is running in per-database
catalog version mode.

2. Create a publication for all tables
```
yugabyte=# CREATE PUBLICATION testpub_foralltables FOR ALL TABLES;
CREATE PUBLICATION

```
3. The following DDL statement fails
```
yugabyte=# ALTER USER yugabyte SUPERUSER;
ERROR:  cannot update table "pg_yb_catalog_version" because it does not have a replica identity and publishes updates
HINT:  To enable updating the table, set REPLICA IDENTITY using ALTER TABLE.
CONTEXT:  SQL function "yb_increment_all_db_catalog_versions" statement 1

```

In per-database catalog version mode, we internally call call `yb_increment_all_db_catalog_versions` to update pg_yb_catalog_version table. In global-database catalog version mode, we directly issue an update on pg_yb_catalog_version table which by-passes `CheckCmdReplicaIdentity`. We should also by-pass
`CheckCmdReplicaIdentity` to mimic update of pg_yb_catalog_version under the global catalog version mode.
