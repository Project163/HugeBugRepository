Title

FormHelper multiple checkbox bug with special chars

Description
Created by **[Link: euromark]**, 14th Sep 2013. _(originally [Link: Lighthouse ticket #4064])_:

---
#### What I did

```
$options = array(
    'type' => 'select',
    'multiple' => 'checkbox',
    'options' => array('A+' => 'A+', 'A++' => 'A++')
);
$this->Form->input('energy_class', $options);
```
#### What happened

"ProductEnergyClassA" twice as ID:

```
...
 
     
     A+ 
 
... [Log Snipped] ...
 
...
```
#### What I expected to happen

DOM IDs are not allowed to be used twice. This creates weirdness when clicking the labels.
My initial thought was to convert special chars into their numeric equivalent.
Discussion
- 13th Sep 2013, **[Link: Mark Story]** said:

---

What would the numeric equivalent of + be?
- 14th Sep 2013, **[Link: euromark]** said:

---

According to `ord('+')` this would be 43. 
I personally find it dangerous to use the value to form a unique ID. But using the ord() numbers for non-allowed characters could make the current system work.

It would still not be 100% correct in all cases. One would need to "remember" all used ids and compare them to add an additional suffix in case of more collisions. But that is an edge case of some sort.

Sidenote: The current approach using Inflector::slug() also filters out numbers and other valid chars, which is bad IMO, as it also increases the changes for collisions. I think this method (whose primary use case is slugs for urls) should not be used to create unique DOM IDs. We need an own method for this.
By knowing if the FormHelper should output html4 or html5, we can also simplify a great deal - in html5 everything except spaces is valid for the last part of an ID.
