Title

GEORADIUS returns the same key twice on Redis 3.1.999

Description
# The bug

A `GEORADIUS` query returns the same key twice. Since `GEORADIUS` [Link: is defined as]:

I assume that having a duplicate in the set is an erroneous behaviour. 
# Steps to reproduce on `redis-cli`

```
 :6379[1]> GEOADD users -47.271613776683807 -54.534504198047678 user_000000
(integer) 1
 :6379[1]> GEOADD users -47.271613776683807 -54.534504198047678 user_000000
(integer) 0
 :6379[1]> GEORADIUS users 0 0 50000 km WITHCOORD
... [Log Snipped] ...
   2) 1) "-47.271613776683807"
      2) "-54.534504198047678"
```
# Notes
## Adding the key multiple times

Adding the same key more than twice seems to add the key only twice:

```
 :6379[2]> GEOADD users -47.271613776683807 -54.534504198047678 user_000000
(integer) 1
 :6379[2]> GEOADD users -47.271613776683807 -54.534504198047678 user_000000
(integer) 0
 :6379[2]> GEOADD users -47.271613776683807 -54.534504198047678 user_000000
... [Log Snipped] ...
   2) 1) "-47.271613776683807"
      2) "-54.534504198047678"
```
## Other coordinates

The bug was not reproduced with other coordinates, e.g.:

```
 :6379[2]> GEOADD users 10 10 'x'
(integer) 1
 :6379[2]> GEORADIUS users 10 10 500 km WITHCOORD
1) 1) "x"
   2) 1) "10.000002086162567"
... [Log Snipped] ...
   2) 1) "10.000002086162567"
      2) "10.00000092823273"
```

Discussion
- Thanks for reporting, actually you can use a single `GEOADD` command and yet the item will be reported twice. It is a bug with the GEORADIUS implementation and not with the underlying sorted set data structure. I'll fix this tomorrow hopefully.
- In this specific case the problem is due to the fact that the neighbors squares calculated for north_west and south_west are the same, due probably to the huge radius used. It's a corner case which should be pretty easy to fix AFAIK.
- Fixed, thanks for reporting.
