Title

IS NOT NULL condition for relative properties not working as expected

Description
It seems that a query like 
  
 SELECT * FROM [nt:base] WHERE [a/b] IS NULL
 
  
 should return paths where there exists a child  a  without a property  b  (this works as expected) 
But, it should also return paths where there is not child  a  in the first place. 

  tmueller , does this sound a reasonable expectation?
Discussion
- Attaching   OAK-6838.patch      with tests and potential fix (this doesn't break any tests in oak-core or oak-jcr... haven't tested all modules)
- Sounds reasonable, but possibly it's a compatibility problem (with Jackrabbit 2.x, but also with older versions of Oak). So if you fix this, I suggest to add a feature flag (system property) so people can re-enable it if needed, until they can fix their application.
