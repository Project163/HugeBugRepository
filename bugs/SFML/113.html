Title

NvOptimusEnablement not exported for /SUBSYSTEM:CONSOLE

Description
When /SUBSYSTEM:CONSOLE is specified the exported symbols NvOptimusEnablement and AmdPowerXpressRequestHighPerformance in MainWin32.cpp aren't brought into the executable. I think this is because WinMain isn't referenced and so the entire .obj is ignored. Here's [Link: a related article].
Discussion
- Current temp fix is to use declare them in your own code and then use /FORCE:MULTIPLE to allow multiple declarations.
- It's a linker/optimization thing. Don't think there's anything we can do about this and in the end you'd just have to ensure to include the export on your own (as you do now).

On the flip side, you don't really have to link to **sfml-main** anyway; it's just a convenience thing. Just add your own little wrapper `WinMain()` calling `main()`. In the end it's just a trivial call if you don't care about parameters.

    #ifdef WIN32
    #include  
    int WINAPI wWinMain(HINSTANCE, HINSTANCE, PWSTR, int) {
        return main(0, NULL);
    }
    #endif
- ... [Middle Discussions Snipped for Brevity] ...
- Only when you're shipping, but I have spent 99% of the time testing my game with a console. Also be aware that games do ship with console sometimes, especially during Early Access / Beta. 

I suppose the least we could do is warn people that the symbols aren't exported in /SUBSYSTEM:CONSOLE mode. The best approach would be to make SFML responsible for exporting those symbols, but unfortunately it looks like it has to be in the main executable.

Another approach could be to just offer that code as a #define that the user can call in their application code. SFML_FORCE_HIGH_PERFORMANCE_GRAPHICS() or something, and then drop it in the tutorial/docs.

In any case, I think this issue will help future gamedevs, so it's good to get it all out there.
