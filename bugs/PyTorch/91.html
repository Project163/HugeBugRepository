Title

Crash with `numpy >=1.23.4` and `torch 1.13.0` due to `DLpack` interaction

Description
### 🐛 Describe the bug

We use PyTorch in our ML framework [Link: Thinc], and we started noticing CI failures on both Windows and Linux after `torch 1.13.0` was released late last week. After isolating the delinquent test case, we were able to reproduce the crash locally with the following minimum reproducible example:

```python
import torch

x = torch.zeros(10)
data_np = x.detach().cpu().numpy()
rev = torch.utils.dlpack.from_dlpack(data_np)
x.data = rev
```

Discussion
- The `array_dlpack_deleter` provided by numpy does not acquire the GIL before calling into python APIs, hence the error.
Note that it does work fine with numpy 1.21.6 for me locally.

I opened an issue on the numpy side to see what they think: [URL]
