Title

[bug] tauri-cli incorrectly parses application arguments

Description
### Describe the bug

Running `cargo tauri dev -- -- --myoption` causes tauri to pass `--no-default-features` to my application. That means `cargo build` doesn't get that flag, and it means my application crashes because `clap` isn't expecting the `--no-default-features` flag in my application.

This seems to be due to this code: [URL]

After that line the rest of the function splits up `args` into `args` and `run_args` by looking for `--`.  Since `--no-default-features` is `push`ed onto `args` beforehand, it will incorrectly end up in `run_args`.

Likely the code that pushes `--no-default-features` should either use an insert to put the flag at the beginning of `args`, or the push needs to occur _after_ `run_args` has been split off.
