To reproduce
1. Click the blue button to open the plunker in a separate window
2. Click on the _Regex Test_ link
3. Note the values for a and b are populated, and the values for 0, 1, 2 are empty
4. Refresh the window using CMD-R(Mac) or CTRL-R(Windows)
5. Note the values for a and b are empty, and the values for 0, 1, and 2 are populated
Discussion
- This is due to the Regex having no mapping to function parameters. JS doesn't support named groups as far as I can tell, so we probably need a mapping structure between group index and parameter name, which might even obviate the need for the serializer function.

This could look like this:

   {
    name : 'Test',
    regex: '^test/(.+)/(.+)$',
    regex_group_names: ['a', 'b'],
    serializer: (params) => {
      return new GeneratedUrl(`test/${params.a}/${params.b}`, {});
    },

Then we should be able to always only populate a and b in the router params.

For more complex regex, and when no group names are given, we could still pass the match indexes to the component, if there is an advantageous case for that somehow - maybe in the case of dynamic number of groups?
