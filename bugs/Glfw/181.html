Title

segfault during startup in sway/wayland

Description
GLFW @ `3.2.1` crashes for me under sway (0.15.0) and libwayland (`wayland-git` in arch linux (`1.14.90.2028.5d201df-1`).

This segfault happens during startup and is _probably_ due to some not yet initialized structs.
I could fix this when I added a simple check for `surface == NULL` in `keyboardHandleEnter` (src/wl_init.c).
But I don't know if this is the preferred way to fix this properly, I have no prior experience in GLFW (except for using it, thanks for the awesome library btw!)

Discussion
- This looks like a bug in your compositor, the `wl_keyboard::enter` event doesn’t have any `allow-null="true"` attribute on its surface event.  I recommend you to report this bug to Sway instead.
- Could it not also be a race?

GLFW seems to:

Create window A,
Destroy window A
Create window B

What the wl_keyboard.enter() might be is the enter for window A, which libwayland-client can no longer resolve, thus hitting NULL.

- Actually, if I add a `wl_display_cancel_read` at the end of the `_glfwPlatformDestroyWindow` function, it fixes the problem.
That's however not a nice solution as it affects other windows as well, right?
- This was indeed a GLFW bug, #wayland was very helpful in understanding the intrinsic race condition caused by this testcase, which wasn’t in any way specific to Sway.
