Title

Load vcpkg toolchain file causes msmpi cmake error

Description
In my downstream CMakeLists

```
cmake_minimum_required(VERSION 3.10)

project(Example)

set(PROJECT_SRCS ${PROJECT_SOURCE_DIR}/mycpp.cpp) 
... [Log Snipped] ...

target_link_libraries(${PROJECT_NAME} MPI::MPI_CXX)
```

If I CMake it without including any vcpkg toolchain file, `cmake -A x64 ..` everything works. However, in my actual project I need to add the toolchain file but when I add it with `cmake -A x64 -C ..\initcmake ..` where initcmake is `set(CMAKE_TOOLCHAIN_FILE $ENV{VCPKG_ROOT}/scripts/buildsystems/vcpkg.cmake CACHE STRING "")` it starts breaking. I get the error

```
-- Could NOT find MPI_C (missing: MPI_C_COMPILER) (found version "2.0")
-- Could NOT find MPI_CXX (missing: MPI_CXX_COMPILER) (found version "2.0")
```

if I run  `cmake -A x64 -C ..\initcmake ..` more than once.

When I investigate more thoroughly, I notice that if the tool chain file is not loaded

variable `MPI_msmpi_LIBRARY` is `C:/Program Files (x86)/Microsoft SDKs/MPI/Lib/x64/msmpi.lib`
variable `MPI_CXX_HEADER_DIR` is `C:/Program Files (x86)/Microsoft SDKs/MPI/Include`

when the toolchain file is loaded

variable `MPI_msmpi_LIBRARY` is `C:/dev/vcpkg/installed/x64-windows/debug/lib/msmpi.lib`
variable `MPI_CXX_HEADER_DIR` is `C:/dev/vcpkg/installed/x64-windows/include`

When I investigate the portfile of msmpi I noticed that vcpkg is building msmpi from source itself. Why is it necessary? Why is it not like the cuda port where it just simply verify whether the installation was successful since msmpi is installed through manually double clicking `msmpisdk-8.1.msi` and `MSMpiSetup-8.1.exe`?

EDIT: This might be also related to the update on FindMPI.cmake in 3.10 as shown in [URL]
