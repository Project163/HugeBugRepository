Title

Postgres::describe doesn't handle uuid null columns correctly

Description
I have a postgres table that has a uuid column.  I have a model for this table and a fixture that uses the model to import the table structure.  During the test, it calls Postgres::describe to determine how to generate the table in the test datasource.  At this point, it creates varchar(36) with a default of an empty string.  But the default for a uuid column is null.  So my tests are failing because the code is expecting it to be a null instead of an empty string.

I fixed it by adding an "is_null($c->default)" check together with the "$fields[$c->name]['default'] === 'NULL'" check.
