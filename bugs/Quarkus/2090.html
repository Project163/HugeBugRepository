Title

quarkus-cache: "keyGenerator" destroyed, even if it is annotated with "Singleton"

Description
### Describe the bug

The key generator seems to be destroyed, even if it is marked as `Singleton`.
This seems a bit confusing, because I thought, that the key generator is only instantiated once - as the annotation `Singleton` says.

A simple CacheKeyGenerator instance:
```
java
@Singleton // We only want a single instance here
public class RequestContextKeyGenerator implements CacheKeyGenerator
{
  public RequestContextKeyGenerator()
... [Log Snipped] ...
  }
}
```

CacheKeyGenerator used in a demo method:
```java
@CacheResult(cacheName = "sourceRoots", keyGenerator = RequestContextKeyGenerator.class)
protected Path calculateSourceRoot(@NonNull Path pPath)
{
  // do some calculations here
}
```

Let's say I call the `calculateSourceRoot` method 5 times; the key generator gets instantiated 5 times too.

### Expected behavior

I think it is not necessary to destroy the bean after key creation - the key generator bean should be reused, especially if it is marked as `Singleton`.

### Actual behavior

The key generator gets destroyed after every cache-method invocation.
It seems, that `keyGenerator.destroy(keyGen);` in io.quarkus.cache.runtime.CacheInterceptor#generateKey() should not be invoked, if the bean is a `Singleton` instance.
Then the generator would be reused properly.
