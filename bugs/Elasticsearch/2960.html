- This one returns the row with empno `10024` which has a salary change of `[]`. That shouldn't be included, but it sure is! The filter that failed is `where not(salary_change > 1)` - because that employee doesn't have a salary change at all the `salary_change` field would load as `null`, so it's comparison to `> 1` should also be `null`, and `not(null)` resolves to `null`. And tuples which return `null` from the expression in `where ` are supposed to be filtered.

So! What's up. My guess is that we somehow ended up with a segment that *just*contains empno `10024` and there's a bug in the query. Let's see if I can reproduce that.
