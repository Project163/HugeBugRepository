Title

nvim crashes by nvim_buf_set_lines() when undolevels = -1

Description
### Problem

Nvim crashes when the number of lines gets larger than the window height -- but this is possibly due to a plugin. ~~The root cause might be on somewhere `extmark`; I will try to modify the title and the reproduce step if I can find why the crash happens.~~

I find that this happens when we call `nvim_buf_set_lines` for a buffer with `undolevels = -1`.

With git bisect I figured out that 008154954 (#24824) is the first bad commit. /cc @bfredl

Stacktraces tell that `u_force_get_undo_header` via `extmark_splice_impl` is where it aborts.

### Steps to reproduce

`$ nvim -u minimal.lua` where minimal.lua:

```
local buf = vim.api.nvim_create_buf(false, true)
vim.api.nvim_buf_set_option(buf, 'undolevels', -1)
vim.api.nvim_buf_set_lines(buf, 0, 1, false, { })
```
