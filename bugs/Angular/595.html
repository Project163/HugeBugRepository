Title

Browser back button broken when navigating from ng1 to ng2 and ng2 has a route redirect

Description
[ ] Regression (a behavior that used to work and stopped working in a new release)
[X] Bug report   
[ ] Feature request
[ ] Documentation issue or request
[ ] Support request => Please do not submit support request here, instead see [URL]
  

## Current behavior
We have an application that has both angular 1 and angular 2 components. The angular 1 has a link to an item in angular 2+ which is then redirectedto another route within the same angular 2 app.
This causes an extra entry in the browser history and the user cannot use the browser back button to go back in the application as the user is redirected back again


## Expected behavior
Only one entry is added to the browser history and the browser back button works as expected


## Minimal reproduction of the problem with instructions
See [URL] You can clone the repo and use @angular/cli to run it and follow the steps in the [Link: README.md]

## What is the motivation / use case for changing the behavior?
As we migrate our application from ng1 to ng2 and add more granular separation of components we need to add some redirection to land on hte default page which should be managed by the routing config in the angular 2 router. This causes unexpected behaviors in the browser with the browser history
