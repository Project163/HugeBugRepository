Title

Cake 3.x: Memory Leak in Email Sending

Description
In Cake3, When using SMTP in a simple email loop, there appears to be a memory leak, at least when using attachments (or large message bodies)

Each email which is sent increases the memory foot-print, even though they should be individual emails and there shouldn't be anything building anywhere. Eventually, after around 100 emails, the PHP memory limit is reached and is shut down.

Keeping the code as simple as possible, I am able to reproduce this issue with this block of code:

```
$attachments = ['/tmp/attachment.png'];
 foreach($recipients as $recipient) {                             
                                $email = new Email('smtp');
                                $email->from($from)
                                        ->sender($sender)
... [Log Snipped] ...
                                        ->send($body);
                        }
```

The memory error is in the following:
PHP Fatal error:  Allowed memory size of 134217728 bytes exhausted (tried to allocate 1107147 bytes) in /home/www/app/vendor/cakephp/cakephp/src/Network/Socket.php on line 280

Which is the line (in the write() function)

```
$rv = fwrite($this->connection, substr($data, $written));
```

I have narrowed down the problem as best as I am able to - for example, it is definitely in the sending part which is causing the issue (removing the ->send() call works fine). It's not an issue with the $data being passed to the write function, as that is consistent with each iteration, so there's got to be something else somewhere building up.

Watching the process with a process monitor shows that with each email sent, the memory increases and is never released (including the full size of the attachment, so with larger attachments, the issue happens faster). With no attachment, the issue doesn't arise (but that could just be because the emails are then much smaller).
