Title

`--files-from` does not list the files with leading/trailing whitespace in its name

Discussion
- I see what you mean.

Currently files-from
- accepts comments
- removes whitespace from start and end of line

I think I'd probably prefer to make `--files-from` not do either of those things and just read newline delimited files.  That was always the intention and that makes it play well with `rclone lsf`.

That would be a backwards incompatible change though

If you want to use wildcards then you can use "--include-from".
- I think the change is necessary and it would be consistent with the way `--files-from` functions, which is it reads the filenames separated by newline on the condition that each line contains exactly the filename (with whitespaces, or special characters).


This is my current solution with this type of problem with rules like:
```
*filenames.abc*
?filenames.abc?
# etc. 
```
The process of copy/move or anything with the file quickly become a nightmare if there are multiple corrupted files in the source with slightly different names (I know I am a monkey and I only have similar intellectual friends/colleagues).
- OK, I agree..

Here is my proposal which I [Link: posted in the forum]

Currently `--files-from` parses the input files in the same way that `--include-from` does, namely it
- ignores comments starting with `#` and `;`
- strips whitespace from start and end of strings

This makes `--files-from` less useful that it might be and was never the original intention.

I propose to make the backwards incompatible change so that `--files-from` reads every line from the file ignoring comment characters and not stripping whitespace.

This will restore the expected behaviour that `rclone lsf` is good input to `--files-from` when files have leading spaces, `;` or `#`.

The expected impact of this is minimal I think as most `--files-from` lists are auto generated.
- The `--files-from-raw` flag has been merged to master now which means it will be in [Link: the latest beta] in 15-30 mins and released in v1.52
