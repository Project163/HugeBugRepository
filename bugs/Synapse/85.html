- It seems this issue is taking more time than expected since this is related to axis2. Till I fix this issue properly, you can use the following workaround to get rid of this issue (this is not the proper fix, and I will fix this ASAP).  

 Use the parameter named useOriginalwsdl to print the specified WSDL with changing the endpoints as appropriate. You can set this parameter in your proxy definition for example as; 

 <proxy ...> 
...... 
<publishWSDL uri="...."/> 
<parameter name="useOriginalwsdl">true</parameter> 
</proxy>
- There was a conceptual change in the axis2 WSDLToServiceBuilder and hence we had to change the proxy service building code to cater that.  

 Anyway the proxy services either has to specify the transports on which it is exposed correctly or else provide the necessary parameters for the transports (fr example email address for the mail transport). 

 Otherwise WSDL2 generation will through an exception even though the WSDL11 generation will work and produce a error prone WSDL without address locations for those WSDL ports.
- Issue is fixed in the SVN trunk.
