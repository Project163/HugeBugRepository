Title

Augment KStream.print() to allow users pass in extra parameters in the printed string

Description
Today  KStream.print  use the hard-coded result string as: 

  
  "["  +  this .streamName +  "]: "  + keyToPrint +  " , "  + valueToPrint
 
  

 And some users are asking to augment this so that they can customize the output string as  KStream.print(KeyValueMapper<K, V, String>)  : 

  
  "["  +  this .streamName +  "]: "  + mapper.apply(keyToPrint, valueToPrint)

Duplicating KIP-160:  [URL]
Discussion
- I'd like to tackle this, but beforehand I have a question.  
I see that your mentioned line of code is part of  KeyValuePrinter , and now I am unsure whether this was just an example. 
If my understanding is correct, what was suggested with  KStream.print(KeyValueMapper<K, V, String>)  is meant to be an extension of  KStream  in order to let the user decide how the output of the K,V shall look like. However, this rises my concerns as we wouldn't allow to set a  streamName  with this function definition. 
Therefore, my approach would be to extend KStream with  void print(final Serde<K> keySerde, final Serde<V> valSerde, final String streamName, final KeyValueMapper<K,V,String> mapper) . 
Furthermore, as  KStreamImpl.print  creates an instance of  KeyValuePrinter , this class would have to be changed too accordingly. Or is that meant be left open to the user?
