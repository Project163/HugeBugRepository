Title

panic when importing modules from cdnjs

Description
From [URL]

This script causes a panic:
```js
import faker from "cdnjs.com/libraries/Faker";

export default function () {
}
```
Discussion
- relevant upstream issue `[URL]

The problem is that cdnjs tells us there is version 5.X.X but that version has no files defined for it and when we try to get the first one we panic (the array of files is empty).
Given the current issue there are 2 fixes:
1. when we can't find the file (the place where it breaks) because there are no files for the latest version - just abort ...
2. order versions and get the latest oldest version.

`1.` will be super simple, `2.` will take some work and will be hard to test. Given that I have been for dropping cdnjs (and github to some extend) magical links since 2 years ago when I *fixed* them for archives .... I am more inclined for `1.` and a big warning that people should just use real URLs.
- I also vote for 1. - this is an error, we should treat it as such, we should just not panic when it happens.

Also, I vote we should deprecate the cdnjs magic loading... In k6 v0.33.0, we should emit a warning somewhat like this:
```
Importing libraries from cdnjs.com without a scheme is deprecated, instead of "cdnjs.com/libraries/moment.js/2.18.1" import it like "[URL]
```

And then we should drop support the next version or the one after that.
- We had a side-channel discussion about this and the decision was that we won't deprecate any of the "magic" loaders quite yet. The reasons for that are:
- All of the hard work for supporting them has already been done and is mostly stable
- We'd have to support .tar bundles with such scripts for quite a while yet anyway
- The functionality (or something like it) might actually be more useful in the future, potentially in conjunction with xk6 extensions
