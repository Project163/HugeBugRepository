Title

Incorrect 'key_as_string' response in date_histogram when using 'epoch_millis' and 'time_zone'

Description
When doing a `date_histogram` aggregation with `"format":"epoch_millis"`, the aggregation response key shows the correct value as UTC time stamp, but the `key_as_string` does not reflect that key if a `time_zone` other than UTC is used. Reproduced on 2.3 and master:

```
PUT /foo

PUT /foo/_mapping/bar
{
  "properties":{
... [Log Snipped] ...
  }
}
```

The aggregation in the response:

```
"aggregations": {
    "ts": {
      "buckets": [
        {
          "key_as_string": "1462060800000",
... [Log Snipped] ...
    }
  }
```

The key correctly represents the date `2016-05-01T00:00:00.000+01:00`, the expectation would for `epoch_millis` format that the `key_as_string` is the same value.
Same problem happens for `epoch_second` format. With other formats like `date_optional_time` or custom formats `key_as_string` changes correctly according to the keys value.
