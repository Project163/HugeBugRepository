Title

Problem with form validator for numeric and integer type

Description
I discover 2 issues in form framework for the validator for numeric and integer fields. In my form, i have 1 field with interger  type and another with  numeric type.

When I bind the value 'Abc'  for the  numeric field, I had an exception : in the transform() method : 

[2011-10-12 15:41:13] request.CRITICAL: Symfony\Component\Form\Exception\UnexpectedTypeException: Expected argument of type "numeric", "boolean" given (uncaught exception) at C:\wamp\www\menu\vendor\symfony\src\Symfony\Component\Form\Extension\Core\DataTransformer\NumberToLocalizedStringTransformer.php line 73 [] []

So I can't perform the isValid() Method.

When I bind the value 'Abc' for the integer field, I don't had an exception, but the string is converted  to 0. So when I perform the isValid() method, the form is valid.
Discussion
- There are two issues here:
1. When the PHP intl extension is not installed Symfony's stub implementation is used instead, and its `StubNumberFormatter::getErrorCode()` always returns U_ZERO_ERROR. Since this is not a failure code, an exception will not be raised and the false value returned by `StubNumberFormatter::parse()` for invalid arguments will be used as the transformed value. Obviously, this boolean is not a valid number, so when it is checked elsewhere, the UnexpectedTypeException will be raised.
2. The integer-string transformer is indiscriminately casting anything it is given to an integer, rather than letting the number formatter handle type casting. This results in invalid values becoming valid integers and therefore not triggering any exceptions.

I am working on patches for these issues.
