Title

[YCQL] Application stuck in BoundStatement execution if a variable was not bound

Description
The Application is stuck with the Java reproducer:
```
session.execute("CREATE TABLE productkey (key text," +
                    "                         key_type text," +
                    "                         tenant text," +
                    "                         PRIMARY KEY (key)) " +
                    "WITH TRANSACTIONS = {'enabled' : true};");
... [Log Snipped] ...
    Row row  = rs.one();
    LOG.info("ROW: " + row);
```
It hangs. And failed with the timeout later:
```
org.junit.runners.model.TestTimedOutException: test timed out after 180 seconds
	at app//org.yb.cql.TestBindVariable.test1(TestBindVariable.java:2397)
```
Discussion
- The log - it looks like endless retry-loop:
```
ts2|pid31142|:18313|[URL] E0123 23:47:16.267711 31360 process_context.cc:180] SQL Error: Invalid Arguments. Invalid bind variable kind -2
ts2|pid31142|:18313|[URL] BEGIN TRANSACTION insert into productkey (key, tenant) values (:key, :timestamp); insert into productkey (key, key_type, tenant) values (:key, :keyType, :tenant); END TRANSACTION;
ts2|pid31142|:18313|[URL]                          ^^^^
ts2|pid31142|:18313|[URL] I0123 23:47:16.267829 31455 replica_state.cc:1268] T   P   [term 2 FOLLOWER]: SetLeaderNoOpCommittedUnlocked(1)
2020-01-23 23:47:16,267 (cluster1-nio-worker-4) [INFO - com.datastax.driver.core.RequestHandler$SpeculativeExecution.onSet(RequestHandler.java:618)] Query BEGIN TRANSACTION insert into productkey (key, tenant) values (:key, :timestamp); insert into productkey (key, key_type, tenant) values (:key, :keyType, :tenant); END TRANSACTION; is not prepared on / :9042, preparing before retrying executing. Seeing this message a few times is fine, but seeing it a lot may be source of performance problems
... [Log Snipped] ...
ts2|pid31142|:18313|[URL] BEGIN TRANSACTION insert into productkey (key, tenant) values (:key, :timestamp); insert into productkey (key, key_type, tenant) values (:key, :keyType, :tenant); END TRANSACTION;
ts2|pid31142|:18313|[URL]                          ^^^^
```
- It happens when the TS returns retry-able CQL return code to the driver, so the driver repeat the request again and again. To fix this - TS must return another (non retry-able) CQL error code.
