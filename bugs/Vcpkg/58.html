Title

Can't find ZeroMQ from CMake project

Description
Hi,

I installed ZeroMQ using "vcpkg install zeromq:x64-windows" command. But when I try to use ZeroMQ in my project, I got the following CMake error:

```
CMake Error at C:/vcpkg/installed/x64-windows/share/zeromq/ZeroMQConfig.cmake:48 (get_target_property):
  get_target_property() called with non-existent target "libzmq-static".
Call Stack (most recent call first):
  C:/vcpkg/scripts/buildsystems/vcpkg.cmake:222 (_find_package)
  CMakeLists.txt:48 (find_package)
```

It seems ZeroMQConfig.cmake wants to find both static and dynamic versions of ZeroMQ. This is wrong behavior because "zeromq:x64-windows" was supposed to be a dynamic library.
Discussion
- I have a similar issue.  CMake can no longer find `libzmq.dll` using `find_library`.  It worked a few months ago.  It also seems that since then the verbosity of the build was reduced so I can no longer see which files vcpkg actually installs.  I reproduced my problem in a test repo and set up a test build on AppVeyor.

- Thanks for reporting this issue! It should be fixed in the latest master.

The issue was with the upstream zeromq cmake config files -- they are not set up to correctly handle installation of only one of the targets. I've added a vcpkg-local patch that accounts for this.
- @hmenke The CMakelists.txt provided by zeromq appears to create "boost-style" lib files on windows now (`libzmq-mt-4_2_3.lib`) so they unfortunately won't be locatable with `find_library(X NAMES libzmq-static)` like you have in [1]. However, I've fixed `find_package()` so you can use that (just run `vcpkg install zeromq` to get the full details).
