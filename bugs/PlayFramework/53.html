Title

Request headers are dropped when compressed `Content-Encoding` is used

Description
## Most of request headers are dropped when `Content-Encoding` header with values `gzip` or `deflate` is sent with the HTTP request.

### Play Version: 2.6.6

### API: Scala

### Operating System: any

### JDK (Oracle 1.8.0_144)

### Library Dependencies: no

### Expected Behavior
Regardless of `Content-Encoding`, the unrelated headers like `Authorization` or custom headers should be preserved. Particularly, when sending a request like:

```bash
curl -X POST [URL] \
-H 'Content-Encoding: gzip' \
-H 'Authorization: Bearer 123' \
-H 'X-Custom-Header: 123' -vvv
```
Then `X-Custom-Header` and `Authorization` should be available in the `play.api.mvc.RequestHeader.headers` collection.

### Actual Behavior
However, the actually available headers in the `play.api.mvc.RequestHeader.headers` collection are the following: 
`List((Transfer-Encoding,chunked), (Content-Type,none/none), (Content-Encoding,gzip))`. 
As you can see, `X-Custom-Header` and `Authorization` headers are missing.

### Reproducible Test Case

The project (a basic Play app) helping to illustrate this issue can be found at
[URL] Just run it in the dev mode via sbt, and execute the specified curl command to see the result.
Discussion
- I've just tested the same project with Netty as a backend, and then this issue is not reproducible. It seems this problem comes either from Akka Http, or from its integration with Play.
- Verified in an integration test. Headers are present at the first level of Akka parsing, but are missing by the time Play receives Akka's request object. I'll debug a bit more to find when/why the headers disappear. This will probably require a patch to Akka HTTP.
- I've submitted a fix for this: #7930.
- The fix for this will be in 2.6.7 and is in the latest 2.6.x [Link: nightly snapshot], version [Link: 2.6.7-2017-10-18-e1366be-SNAPSHOT].
