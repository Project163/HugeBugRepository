Title

[Bug]: `docker_manifest` stage can't reference unpublished images from `dockers` stage

Description
### What happened?

Adding `skip_push: true` to docker steps causes the subsequent manifest step to fail:

```
• docker images
      • building docker image     image=quay.io/authzed/spicedb:v1.1.1-devel-amd64
      • building docker image     image=quay.io/authzed/spicedb:v1.1.1-devel-arm64
      • pipe skipped              error=docker.skip_push is set
   • publishing
... [Log Snipped] ...
         • creating docker manifest  images=[quay.io/authzed/spicedb:v1.1.1-devel-amd64 quay.io/authzed/spicedb:v1.1.1-devel-arm64] manifest=quay.io/authzed/spicedb:v1.1.1-devel
   ⨯ release failed after 10.69s error=docker manifests: failed to publish artifacts: failed to create quay.io/authzed/spicedb:v1.1.1-devel: exit status 1: no such manifest: quay.io/authzed/spicedb:v1.1.1-devel-amd64
```

### How can we reproduce this?

This is the config we have currently for publishing multi-arch images:

```
yaml
dockers:
  - image_templates:
      - &amd_image "quay.io/authzed/spicedb:v{{ .Version }}-amd64"
    dockerfile: &dockerfile "Dockerfile.release"
... [Log Snipped] ...
      - *amd_image
      - *arm_image
```

This works well, but it publishes three tagged images (for example):

- `quay.io/authzed/spicedb:v1.1.1-amd64`
- `quay.io/authzed/spicedb:v1.1.1-arm64`
- `quay.io/authzed/spicedb:v1.1.1`

This technically doesn't cause any problems, but it would be much nicer to only push the final multiarch image (`quay.io/authzed/spicedb:v1.1.1`). OCI image clients will either pick the right arch automatically or provide options for a user to pick the underlying image, so the extra tags are unneeded. Adding `skip_push: true` causes the error above.
