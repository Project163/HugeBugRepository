Title

Maven proxy usage is broken with Quarkus 3.0.2.Final

Description
### Describe the bug

Hi folks,

Unfortunately, with Quarkus 3 the proxy usage is not working anymore, at least in case proxy authentication (e.g. basic auth) is required. I've created a reproducer which should help to analyze the issue.

_No response_

### Actual behavior

_No response_

### How to Reproduce?


1) Clone [URL] (Quarkus default app generated with ``Quarkus cli``)
2) You might need to update ``tinyproxy.conf`` to access the proxy within your local network. Currently ``Allow  /8`` is configured
3) Start ``tinyproxy`` via ``docker compose up -d``
4) Execute ``./mvnw clean test -s settings.xml``

Build should fail with the following error: 407 Proxy Authentication Required 
```
[ERROR] Plugin org.apache.maven.plugins:maven-failsafe-plugin:3.0.0-M7 or one of its dependencies could not be resolved: Failed to read artifact descriptor for org.apache.maven.plugins:maven-failsafe-plugin:jar:3.0.0-M7: Could not transfer artifact org.apache.maven.plugins:maven-failsafe-plugin:pom:3.0.0-M7 fro
m/to central (https://repo.maven.apache.org/maven2): proxy authentication failed for [URL] status: 407 Proxy Authentication Required -> [Help 1]
[ERROR]
```

There is an additional commit with Quarkus 2.16.7.Final, where everything works like a charm:

- It would appear that the proxy information is being specified into the proxy selector correctly, including authentication information. The only thing that immediately springs to mind is that perhaps directly using the `SettingsDecrypterImpl` to obtain the proxy credentials is somehow a problem (like, it's decrypting the password incorrectly perhaps?) - maybe we should be querying the bean container for a `SettingsDescrypter` instead, and using that to produce the request and process the result?
