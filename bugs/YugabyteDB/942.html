Title

[DocDB] Deadlock in Snapshots + Tablet Splitting

Description
Jira Link: [Link: DB-6048]
### Description

Consider the following sequence of events:
1. Thread t1 begins splitting tablet on master. It acquires an exclusive lock on `tablet_map_` structure and creates in-memory child tablet but before upserting to sys catalog there's a context switch to thread t2
2. Thread t2 begins taking a snapshot. The snapshot operation is replicated on the master. During the apply phase it sends out snapshot rpcs to tablets as part of which, it tries to look up their tablet info by acquiring a shared lock on the same `tablet_map_` structure. Since t1 has an exclusive lock it gets blocked and waits. 
3. Now there is a context switch to thread t1. Thread t1 begins writing to the sys catalog but it cannot replicate (or apply) it since there's an apply of snapshot operation ongoing. It is thus blocked and cannot progress.

Both the threads are blocked waiting for each other and there is no progress. Eventually, the sys catalog write times out and this splitting fails. 

Just snapshots and tablet splitting in the system are enough to repro this. It's not just PITR but Backup/Restore also that could be affected by it although the probability of PITR suffering from this is more since we take periodic snapshots in PITR.
