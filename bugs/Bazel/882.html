Title

grpc protobuf compilations do not pass through PATH even if --client_env=PATH

Description
### Description of the problem / feature request:

I am building Bazel on Windows at my company from scratch on a build server that does not have the MSVC runtime installed. Instead, we provide the path to the MSVC runtime dll directories in PATH. Bazel generally handles this pretty well (including other invocations of protoc.exe) but I found one action that doesn't. Using procmon I found the subprocess that doesn't receive PATH:

"C:\dev\cayman_bazel\build\temp\bazel_yDk0ywS3\out\execroot\io_bazel\bazel-out\host\bin\external\com_google_protobuf\protoc.exe" --plugin=protoc-gen-PLUGIN=bazel-out/host/bin/third_party/grpc/cpp_plugin.exe --PLUGIN_out=bazel-out/x64_windows-opt/bin --proto_path=. --proto_path=. --proto_path=bazel-out/x64_windows-opt/bin/external/com_google_protobuf/_virtual_imports/descriptor_proto --proto_path=bazel-out/x64_windows-opt/bin src/main/protobuf/command_server.proto

This appears to come from [URL]

### Feature requests: what underlying problem are you trying to solve with this feature?

I am trying to build Bazel from scratch without the MSVC runtime installed but with those dlls present in PATH and --client_env=PATH provided

1. Make a copy of the MSVC 14 runtime dlls in a temp directory.
2. Either uninstall the MSVC 14 runtime or rename C:\windows\system32\vcruntime140.dll to C:\windows\system32\vcruntime140.dll.backup.
3. Build Bazel from scratch with VS2015/VS2017/VS2019 using the instructions [URL]
