Discussion
- I know that adding a new architecture can take time, but it would be helpful if you stopped publishing the `universal-darwin` version of the compiled gem until you've added Arm support. With MacOS dropping 32-bit support in 10.15 and the advent of Arm Macs, Apple now uses "universal" to mean x86_64 and arm64. When I use bundler to install this gem with a lock file that has `arm64-darwin` as a platform on my Arm Mac, it sees "universal" and uses the current definition to download your "universal" build. Unfortunately, this doesn't work, but allowing it to install and build from source does.
- Is there anything that I can do to help this issue towards resolution?  This issue is quite important for us, at least, as it makes installation of our code (which depends on `grpc`) an annoyingly fiddly task on an arm64 Mac, as the user has to install `grpc` manually from source, and then install our gem on top -- which is a pretty bad UX.

The interim fix -- pending support for adding arm64 into the build, which I totally understand is probably not trivial -- could potentially be as simple as replacing the `universal` label with `x86_64` on the Darwin arch spec.  Forcing the (probably very few, by now) PPC users to build `grpc` from source is a reasonable trade-off, IMO, in order to allow arm64 users to also build from source, as compared to the current situation where `grpc` fails with a fairly inscrutable error message at runtime for arm64 users.

If a PR for the above would be accepted, please let me know and I'll whip something up ASAP.
