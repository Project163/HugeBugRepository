Title

Mixins called with !important keyword don't pass it on to nested mixins

Description
According to the LESS language reference, the !important keyword "marks all properties brought by the mixin as !important".

However, if some of those properties are brought in by nested / sub mixins, the !important keyword is not added to those properties.

I've tested this on both 1.3.3 and 1.4.0 beta, and the output is identical... so it's not something that has been addressed in the new beta version.

Given this input:

```
css
.mixinBorder() {
    border: 1px solid red;
}

... [Log Snipped] ...
    .mixinBorderAndText() !important;
}
```

and running lessc from the command line with "lessc input.less", I get the following output:

``` css
div.blueNoBorder {
  color: blue;
}
div.blueNoBorder.withGoldAndRed {
  border: 1px solid red;
  color: gold;
}
```

I'd expect the !important keyword to be passed down to nested mixins to provide this:

``` css
div.blueNoBorder {
  color: blue;
}
div.blueNoBorder.withGoldAndRed {
  border: 1px solid red !important;
  color: gold !important;
}
```

It makes no difference whether I remove the brackets in the mixin calls or not.

Am I reading too much into the wording of the language reference and expecting too much, or is this a bug?

Thanks!

Dan
