Title

LDAP DN is not case sensitive, resulting in user login failure

Description
In some user scenarios, uppercase and lowercase logins to LDAP fail. 

 Root Cause： 

 When all users are obtained from ldapUserService in the code, the attribute names in the recorded dn contain uppercase letters, but the DN attribute names passed in by customers when they log in to ldap are lowercase, resulting in inconsistent capitalization and login failure. Customers here CN =xxx,DU=xxx,DC=xxx, but ldap here is cn=xxx,du=xxx,dc=xxx 

 A point where later maintenance can be optimized:  

 When troubleshooting LDAP problems, there are often strange problems that the user names cannot be matched. It is very laborious to troubleshoot. You need to add this information to the log instead of printing it all the time. You can consider printing it after polling for a number of times, and printing it when it is loaded for the first time. and so on
Discussion
- Design： 

 Since the components of the dn obtained in the org.springframework.security.ldap.userdetails.LdapUserDetailsMapper#mapUserFromContext method are all lowercase, it cannot be matched with the dn of the native LDAP user called by Kylin through the API, and the spring framework natively obtains It is the case of the key to obtain the dn through the system, and the default is lowercase 

     

 Therefore, in the KylinPropertySourceConfiguration.java code, the configuration prefixed with kylin.system.property. in the kylin.properties file is added to the system configuration, so that the spring framework can read the configuration
