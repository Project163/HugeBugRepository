Title

Failed Serialization of Scripted Geo fields

Description
### Elasticsearch Version

8.7

### Installed Plugins

_No response_

### Java Version

_bundled_

### OS Version

N/A

### Problem Description

In a multi-node cluster with multiple shards it is not possible to use scripted geo fields.
It fails with:
```
        "reason": {
          "type": "illegal_argument_exception",
          "reason": "can not write type [class org.elasticsearch.common.geo.GeoBoundingBox]"
        }
```

### Steps to Reproduce

In a multi node cluster, create an index with more than 1 shard:
```
PUT /test-geo/
{
  "settings": { "number_of_shards": 2},
  "mappings": { "properties": { "geo_shape" : { "type": "geo_shape" }}}
}
```
Index a few shapes to it so that both shards are populated:
```
POST /test-geo/_doc/
{
  "geo_shape": "POLYGON((24.04725 59.942,24.04825 59.94125,24.04875 59.94125,24.04875 59.94175,24.048 59.9425,24.0475 59.94275,24.0465 59.94225,24.046 59.94225,24.04575 59.9425,24.04525 59.94225,24.04725 59.942))"
}
```

Then search with:
```
GET /test-geo/_search
{
  "script_fields": {
    "bbox": {
      "script": { "source": "doc['geo_shape'].getBoundingBox()" }
    }
  }
}
```

The non-local shard will fail.

- The core problem is that the painless scripting was provided the function `getBoundingBox()` in [URL] which provided support for rendering the BoundingBox as a map of maps, but this only works for the final result in JSON. The inter-node communication appears to use a different serialization, and `GeoBoundingBox` is not supported. There appear to be several ways to support this, so I'll investigate the best option.
