Title

Wrong media type of response

Description
Resource class 
public Response getMediaType()  
{
		MediaType media = MediaType.APPLICATION_ATOM_XML_TYPE;
		Response response = Response.ok().type(media).build();
		return response;
	}

 get media type from response on client side is  null. 
Spec 3.8 Determining the MediaType of Responses 
1. If the method returns an instance of Response whose metadata includes the response media type 
(Mspecified) then set Mselected = Mspecified, finish.
Discussion
- Hi Neal, 

 I think this test is invalid. It does not make sense to return a media type if a response entity is absent.  
I'm afraid it needs to be challenged, sorry about it   

 Sergey
- Please watch a "Section 3.7.8 should be clarified" thread on the 370 list
- ... [Middle Discussions Snipped for Brevity] ...
- The problem with some  of TCK tests is that they basically mechanically test some of spec sentences and by doing so they enforce the runtime to do the bad HTTP, i.e, send a Content-Type which is supposed to describe the body content which is not there at all. So on the wire you'd see: 

 Content-Type: foo/bar 
Content-Length: 0 

 <no content here> 

 This is a bad practice. The fact that it is enforced via TCK makes me unhappy at all
- Having said all of the above I've decided to get it done by default but also let people optionally block sending Content-Type with empty bodies by setting a property.
