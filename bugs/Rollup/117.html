Title

Code splitting with default exports produces broken CJS output

Description
- Rollup Version: 1.3.0
- Operating System (or Browser): Mac OS Mojave
- Node Version: 10.14.0

### How Do We Reproduce?

Code splitting any modules with default exports will produce broken CJS output, even for very simple modules. I noticed the issue when reading [Link: this blog post] by @lukastaegert.

Say we have two files:

```js
// foo.js
export default 'hello'
```

```js
// main.js
export { default as foo } from './foo'
```

When these files are bundled with code splitting we get:

```js
// foo.js
module.exports = 'hello'
```

```js
// main.js
var foo = require('./foo.js')
exports.foo = foo.default
```

But `foo.default` is undefined!

The blog post I mentioned earlier has a [Link: REPL] which illustrates this issue. Just look at the CJS output and you'll see the export statements in `main.js` are broken.

### Expected Behavior

```js
// main.js
var foo = require('./foo.js');
exports.foo = foo;
```

### Actual Behavior

```js
// main.js
var foo = require('./foo.js');
exports.foo = foo.default;
```
