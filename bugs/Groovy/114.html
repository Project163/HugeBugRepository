Title

Infinite loop for n = []; println n[-1];

Description
n = [] 
println n [-1]  

 causes a (seamingly) infinite loop
Discussion
- The culprit here is this piece of code in DefaultRubyMethods. 
This algorythm goes into an endless loop when size = 0 (empty array) and i < 0. 

     protected static int normaliseIndex(int i, int size) { 
        while (i < 0)  
{
            i += size;
        }
         return i; 
    } 

 In other cases, it also leads to unintuitive results, such as  

 n [-15]  == n [5]   
if n is a list (or array) of 10 elements 

 Groovy lists are sparse. I.e., if n has one element, n [2]  == null, and can be assigned. What should be a behavior for negative indices then? Ruby behaves like this: 

 irb(main):001:0> n = [] 
=> [] 
irb(main):002:0> n [-1]  
=> nil 
irb(main):003:0> n [-1]  = 2 
IndexError: index -1 out of array 
        from (irb):3:in `[]=' 
        from (irb):3 

 And also: 

 irb(main):005:0> n = (1..5).to_a 
=>  [1, 2, 3, 4, 5]  
irb(main):006:0> n [-15]  
=> nil 
irb(main):007:0> n [-15]  = 2 
IndexError: index -15 out of array 
        from (irb):7:in `[]=' 
        from (irb):7 

 I guess it should be same in Groovy.  
Not sure how to fix this. Maybe like this: 

     protected static int normaliseIndex(int i, int size) { 
        if (i < 0) { 
            if (-i > size)  
{
                throw new IndexOutOfBoundsException("SUITABLE MESSAGE");
            }
  else  
{
                return (i + size)
            }
         } else  
{
            return i;
        }
     } 

 Clients of this method should then catch this exception and return null if they are doing a read access, or just pass the exception up the stack, if it is an assignment.
- FIX   GROOVY-426  : If your negative index is out of bounds, you will now get an exception instead of a strange wrapping behavior or an infinite loop.
