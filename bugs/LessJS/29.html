Title

allow trailing semi-Colon after nested rules

Description
Coming form the haskell world, I've adopted the leading punctuation list style:

``` css
body
  { margin: 5px
  ; padding: 5px
  ; font-face: serif
  ; }
```

The advantage of this is that its much easier to spot syntax errors and such.

in SCSS I could do the same for nested rules:

```
body 
  { margin: 5px
  ; h1 { ... }
  ; h2 { ... }
  ; } 
```

But in LESS, the semi-colons after nested rules break the syntax.  I'd be interested in working on a patch if the community would adopt it.  Would they?
Discussion
- There is probably not much demand for this - but it should treat anything from the end of the value to the semi-colon as whitespace and not care that there is a new line. If it doesn't then less might fail on some working css.
- and we/I would certainly consider any pull request you do.
