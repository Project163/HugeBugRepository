Title

[Bug]: SB10 - A11y addon loses state when navigating to docs page

Description
### Describe the bug

Not sure if it's intended but doesn't seem like it,

When defining a specific type of report (passes, violations, etc) and whether highlights are enabled, navigating between stories keeps that preference saved.. until you navigate to a docs page. Then it's lost:
[Image: Image]

This seems like a flow break on a user perspective

### Reproduction link

MealDrop, any story

### Reproduction steps

1. Access MealDrop or any other Storybook
2. Turn on a11y highlights
3. Visit a docs page
4. Go back to the story
5. See the issue
Discussion
- Hi, I'm interested in contributing to fix this problem.

After analyzing the codebase, I found the root cause: the A11y addon uses mixed state management - some states (like `results`) use `useAddonState` for persistence, while user preferences (`tab`, `highlighted`, `selectedItems`) use `useState` which gets reset when the component remounts during view mode transitions.

I've identified three potential solutions:
1. Migrate key states to `useAddonState` for persistence (minimal changes, recommended)
2. Use localStorage for cross-session persistence 
3. Listen for view mode changes to save/restore state

I believe Solution 1 has the smallest impact and lowest risk. I'm preparing a PR with this fix and would appreciate your guidance and feedback!
