Title

helm lint not finding subchart imported values when templates in main chart

Description
While working on some complex helm charts I isolated a weird lint issue. I worked on isolating what triggered it and wrote a sample reproducer:

[Link: helm-lint-issue-reproducer.zip]

The following setup:

* `libchart` is a library chart defining a template and a value copied.value
* `subchart` depends on `libchart` and uses the template with `{{ template name . }}`
* `mainchart` is kind of an umbrella chart that depends on `subchart`, but defines a YAML file too

Linting on the mainchart after dependency builds are done breaks with the following error:

```
[ERROR] templates/: template: mainchart/charts/subchart/charts/libchart/templates/_object.yaml:5:19: executing "object.template" at  : nil pointer evaluating interface {}.value
```

If you remove the templates folder from the mainchart, lint starts working again.

Output of `helm version`:

```
version.BuildInfo{Version:"v3.5.4", GitCommit:" ", GitTreeState:"clean", GoVersion:"go1.15.11"}
```

This issue is independent of the version of kubectl or the cloud provider chosen: it is pure helm lint.
