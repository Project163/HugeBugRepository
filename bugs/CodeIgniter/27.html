Title

Nested verbatim tags don't minify correctly

Description
Some tags, ` `, ` ` or ` ` should not have their contents minified. We try not to, but in the case where they are nested the content after the closing child tag gets minified anyway.

This is because the regex that matches these verbatim tags just looks for the first closing tag after the opening tag.
### The html I'm minifying:

```
 
     
     Nesting is hard 
     
     This whitespace... 
... [Log Snipped] ...
     ...should be preserved 
 
```

Since ` ` is a verbatim tag, I expect none of that html to be modified
### What I get:

```
 
     
     Nesting is hard  This whitespace...  Should be preserved  
```

Note that whitespace and comments after the closing child ` ` tag are removed.
### Thoughts:

I wonder if CI should really be attempting to do HTML minification in the first place. Conventional wisdom (supported by issues such as this) seems to be that trying to match HTML tags with regex is a bad idea and I doubt a full HTML parser is within the scope of CI.

If transfer size is really an issue, presumably the first step would be to turn on gzip. Once gzip is on, does removing white-space and comments really make a meaningful size difference?

I don't mean this as a criticism of the decision to include minification in CI in the first place, but to propose that the cleanest solution to this bug may be to simply drop this feature.
