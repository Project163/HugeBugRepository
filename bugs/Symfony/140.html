Title

[DependencyInjection] ArrayNodeDefinition::canBeEnabled() doesn't make the configuration disabled by default

Description
| Q                | A
| ---------------- | -----
| Bug report?      | yes
| Feature request? | no
| BC Break report? | no
| RFC?             | no
| Symfony version  | 2.7


Consider the following configuration:

```php
$builder = new TreeBuilder();
$root = $builder->root('acme_foo');
$root->canBeEnabled();
```

**Expected behaviour**

If the section wasn't provided in configuration, it will be disabled.

**Actual Behaviour**

The section is enabled unless it was explicitly disabled. 

**Supporting information**

It only seems to be an issue for root nodes. Any child nodes work as expected (i.e. `$root->children()->arrayNode('foo')->canBeEnabled()`).

The docblock for `canBeEnabled()` says that the section should be disabled by default (which is also what I expected):

```
php
    /**
     * Adds an "enabled" boolean to enable the current section.
     *
     * By default, the section is disabled. If any configuration is specified then
... [Log Snipped] ...
     * enableableArrayNode: false                  # The config is disabled
     */
```
