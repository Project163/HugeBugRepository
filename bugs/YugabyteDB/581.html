Title

[YSQL] Prepared LIMIT statements with NULL parameters wrongly send down a 0 limit to DocDB

Description
Jira Link: [Link: DB-2657]
### Description

Consider the following set of queries:

```
create table test(h int, r int, primary key(h hash, r asc));
prepare myplan as SELECT * FROM test LIMIT $1;
explain execute myplan(null);
execute myplan(null);
execute myplan(null);
... [Log Snipped] ...
explain execute myplan(null);
execute myplan(null);
```
Note that the first explain gives an output of just a sequential scan as such as it is not using a generic plan:
```
                       QUERY PLAN                        
---------------------------------------------------------
 Seq Scan on test  (cost=0.00..100.00 rows=1000 width=8)
(1 row)
```
After five executions of `myplan`, the planner defaults to using a generic plan with a limit node as such
```
                          QUERY PLAN                           
---------------------------------------------------------------
 Limit  (cost=0.00..10.00 rows=100 width=8)
   ->  Seq Scan on test  (cost=0.00..100.00 rows=1000 width=8)
(2 rows)
```
At this point the final execute statement has a NULL limit. However, this is not a scenario that is taken into account as [Link: this] line still sets `yb_exec_params.limit_use_default` to `false`, allowing the invalid limit of 0 to be pushed down to DocDB and cause an invalid access to `table_iter_` [Link: here].
