- I came across the same issue with [Link: eslint-plugin-jsonc]. I could work around the issue with a [Link: runtime plugin]. 
The initial problem:

```
javascript
// Prior (non flat config) -----------------------------------
module.exports = {
  extends: ["plugin:jsonc/recommended-with-jsonc"],
  parser: "@babel/eslint-parser",
... [Log Snipped] ...
  rules: {...}
}];
```
The initial idea to bypass the `parser`[Link: as object] failed because of this issue:
```js
  languageOptions: {
     parser: await import('jsonc-eslint-parser') // <- Error must be string. Object not implemented yet
  }
```
To work aroud this, I defined a runtime plugin of the same name `'jsonc'` and made the `parser` available under the `'parsers'` prop: `[Plugin_Name].parsers.[Parser_Name]`. No need to change `languageOptions.parser` to an object any more:
```
js
import {default as jsonc, parseForESLint, configs} from "eslint-plugin-jsonc";

const parsers = {
  'jsonc-eslint-parser': {
... [Log Snipped] ...
  rules: {...}
}];
```
Not sure if this is a valid approach, but it seems to work so far.
- Great that you found a workaround! We discussed the [Link: `meta` cache key proposal] in the [Link: 2023-02-09 TSC meeting], and all were in favor, so there will be a built-in solution to this once that's implemented.
