Title

Description

Discussion
- I think its impossible for what you've described to happen. You can use the /db/file endpoint to query the version of the file, which can explain if its being modified in one or more places.

If this was a bug, it should happen to every single file.

I think what can potentially happen is that modification timestamp of the file gets adjusted by some piece of software you have on the side which is not modifying the file content, but the metadata, which is still a valid reason for a conflict.
- Also, -verbose -audit options could show something, but I think you are probably syncing something you shouldn't (a running/active database for example) hence why it happens.
