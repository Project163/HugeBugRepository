Title

execute( ) behaves subtly differently from execute( .next_value())

Description
**Describe the bug**
`session.execute(seq_obj.next_value())` performs schema translation mapping, whereas `session.execute(seq_obj)` does not.  Leading to confusing and inconsistent behaviour

**Expected behavior**
Based on the docs which state:


It seems reasonable to call `session.execute(seq_obj)`.  This superficially works, but follows a very different code-path than calling `session.execute(seq_obj.next_value())`.  This can lead to subtle and hard-to-find bugs.

For example, `execute(seq_obj.next_value())` performs schema translation mapping, whereas the other form does not.

**To Reproduce**
Given the following script:

```
py
import sqlalchemy
import sqlalchemy.orm
import logging 

... [Log Snipped] ...
if __name__ == '__main__':
    main()
```

Expected output:
```
VERSION: X.Y.ZZ

INFO:sqlalchemy.engine.base.Engine:{}
INFO:sqlalchemy.engine.base.Engine:SELECT nextval('"YYYYYY".foo') AS next_value_1
INFO:sqlalchemy.engine.base.Engine:{}
```
