Title

Provisioner fails to run when declaring ruby constant variable as frozen `gsub!': can't modify frozen String (RuntimeError)

Description
### Vagrant version
Vagrant 1.9.5

### Host operating system
Ubuntu 16.04

### Guest operating system
'hashicorp/precise64'

### Vagrantfile
```
ruby
TEST_CONSTANT_VARIABLE =   default: Running provisioner: shell...
==> default: Forcing shutdown of VM...
==> default: Destroying VM and associated drives...
/opt/vagrant/embedded/gems/gems/vagrant-1.9.5/plugins/provisioners/shell/provisioner.rb:268:in `gsub!': can't modify frozen String (RuntimeError)
        from /opt/vagrant/embedded/gems/gems/vagrant-1.9.5/plugins/provisioners/shell/provisioner.rb:268:in `with_script_file'
... [Log Snipped] ...
        from /opt/vagrant/embedded/gems/gems/vagrant-1.9.5/lib/vagrant/action/runner.rb:66:in `block in run'
        from /opt/vagrant/embedded/gems/gems/vagrant-1.9.5/lib/vagrant/util/busy.rb:19:in `busy'
```

### Expected behavior
I am new to ruby and I am using rubocop to do static analysis/formatting on code. One of the recommended changes is to 
```
Freeze mutable objects assigned to constants.
TEST_CONSTANT_VARIABLE = <<-TEST_CONSTANT_VARIABLE
```
by appending **.freeze**. I provide a multi line string containing provisioner instructions. I expect to be able to create the VM without any issue. Removing the .freeze in the VagrantFile above resolves the issue

### Actual behavior
VM fails to be brought up. It seems that vagrant is trying to modify the provisioner string.

### Steps to reproduce
1. vagrant up with the above provided VagrantFile
