Title

Session methods used before they are initialized

Description
### What steps will reproduce the problem?
After this bugix:
[Link: Bug #15523]

When I use:

```
$config = [
    'components' => [
        'cache' => [
            'class' => yii\mongodb\Cache::className(),
        ],
... [Log Snipped] ...
    ]
];
```

But I've noticed that any other session has this problem too

### What is the expected result?
Sessions are initialized and just work.

### What do you get instead?
It seems that the new methods `freeze()` and `unfreeze()` are triggering `readSession()` before `init()` is called resulting in reading `$this->cache->get($this->calculateKey($id));` when `$this->cache` is just a string at that moment since it was not initialized in `init()` as `$this->cache = Instance::ensure($this->cache, 'yii\caching\CacheInterface');`

Discussion
- OK. Now the session is unfreezed regardless if it was fronzen. That's not correct.
- I've updated config to be nothing about session. Just defaults and it works.

Then I've added this and it still works:
```
        'session' => [
            'class' => yii\web\CacheSession::className()
        ],
```
Then I've added this and it breaks:
```
        'session' => [
            'class' => yii\web\CacheSession::className(),
            'useCookies' => true
        ],
```

Exactly same this even if I use other session:
```
        'session' => [
            'class' => yii\mongodb\Session::className(),
            'db' => 'mongodb',
            'sessionCollection' => 'session',
            // 'useCookies' => true // this breaks it
        ],
```

So it seems that `useCookies` is causing this. I've cleared the cookies and it breaks, I've opened in private mode and it breaks too.
- ... [Middle Discussions Snipped for Brevity] ...
- Maybe this freeze/unfreeze feature should be disabled during `__constructor()`? What is the point of doing this if session was not initialized yet?

Or configure these getters after `init()`.
- Configuration after `init()` contradicts how Yii configures objects overall so I think a check in freeze/unfreeze about if session was ever frozen should be performed before unfreeze.
