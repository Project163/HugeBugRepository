Title

The _ids key is ignored by patchEntity for hasMany association

Description
This is a (multiple allowed):

* [x] bug
* [ ] enhancement
* [ ] feature-discussion (RFC)

* CakePHP Version: 3.5.17

### What you did

Following the book examples:

```php
$Articles = \Cake\ORM\TableRegistry::get('Articles');
$Comments = \Cake\ORM\TableRegistry::get('Comments');
$Articles->hasMany('Comments');
$article = $Articles->newEntity(['comments' => ['_ids' => [1,2]]]);
$Articles->patchEntity($article, ['comments' => ['_ids' => [1,2]]]);
```
Comments 1 and 2 exist in the database. I'm doing this to simulate reading the article with the comments from the database and then patching it.

### What happened

```
=> Cake\ORM\Entity {#390
     +"comments": [
       Cake\ORM\Entity {#356
         +0: 1,
         +1: 2,
... [Log Snipped] ...
     +"[repository]": "Articles",
   }
```

### What you expected to happen

I expected it to replace the comments field with the new data. Calling patchEntity with _ids works as long as the comments field is empty but in my test it doesn't work because the article had comments already loaded.
Discussion
- If I understand correctly the article you are updating with `patchEntity()` already has comment entities loaded and you want to replace those with the records defined in `comments._ids`?
- Yes, that was what I expected. In the controller I usually read an entity from the database with all the associations needed for the view then use patchEntity to update the entity with form data.

This is how I do it:

- Read entity and associations for the view.
- Is POST:
  - Patch entity.
  - Save.
  - If OK then redirect.
- Read additional data for dropdowns, etc.

I could do this instead:

- Read entity.
- Is POST:
  - Patch entity.
  - Save.
  - If OK then redirect.
- Read associations (loadInto).
- Read additional data for dropdowns, etc.

But when saving fails, the data of the associated enties edited by the user would be lost when reading associations. Think of an article form that lets you edit the status of comments.
