Title

STC misses type error when involving a variable with a char a declared type

Description
I have the following program 

  
 
 class  Test {
   public   static  void main( String [] args) {
     char  f = ( Integer )  null ;
  }
}
 
  

   Actual behaviour 

 groovyc compiles this program 

   Expected behaviour. 

 groovyc should have rejected this program with an error of the form:  

  
 
error: incompatible types:  Integer  cannot be converted to  char
Discussion
- Groovy supports numeric conversion to and from  char .  Here is an example:  [URL]

 As a consequence,  null  may be encountered.  Maybe a type-checking extension could be more stringent. 

 Direct assignment of  null  produces a type-checking error:  char c = null  

 Array assignment also produces a type-checking error:  char[] c = new Character [0]   (see   GROOVY-11371  )
- I'll have to dig up the spec on this as I'm seeing mixed results. 
  
 
@TypeChecked test( char  ch) {
   Character   c = ch 
  BigInteger b = ch 
   Integer     i = ch
   Number      n = ch
  ch = c
  ch = b
  ch = i
  ch = n
}
- ... [Middle Discussions Snipped for Brevity] ...
- I think STC is missing  char  in the loss of precision checking: 
  
 
@TypeChecked test() {
   byte  b = 0
  println(b)
  b = ( char )1000
  println(b)  // prints  "-24" 
   println(b.class)
}
test()
 
  

 It does not allow cast from number to  Character , which the runtime does support: 
  
 
@TypeChecked test() {
  print(( Character ) 2)
}
test()

And there is no warning about the possibility of  null :
{code:groovy}
@TypeChecked test( Byte  bb) {
   byte  b = bb
}
test()
 
  

  blackdrag   paulk  Any thoughts on changing one or more of these in STC?

 It seems most in keeping with the current separation between char and numbers to prevent number to char assignment rather than open up char as another number type in STC.
