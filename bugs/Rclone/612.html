Title

1.53.2+ fails to upload file to Wasabi S3 - works with 1.47.0

Description
#### What is the problem you are having with rclone?
File fails to copy using 1.53.2+ but works with 1.47.0

We have a script that takes application backups and uploads them to Wasabi S3.  This has been working for at least a year. Most installs are using rclone 1.47.0 and these all work.   Some recent installs installed 1.53.2 & 1.53.3 (via your script) and these fail to upload stating lack of permission to create a bucket. Replacing the rclone binary with 1.47.0 makes these instances work as expected. 

Please note the bucket already exists - so permissions to create it seem irrelevant, especially as swapping the rclone binary to version 1.47.0 makes it work and swapping to version 1.53.2+ makes it fail.

Does the user have permission to create buckets? Rclone tries to create the bucket as a shorthand for see if the bucket exists, create it if it doesn't. It relies on the error codes returned from the API which I guess may be different for wasabi.

You can almost certainly work around this with 

      --s3-no-check-bucket     If set, don't attempt to check the bucket exists or create it

However I'd like to get to the bottom of this!

I note that wasabi is returning the wrong error code here if I try to `mkdir` an existing bucket.
