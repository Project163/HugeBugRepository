We thank you for your feedback! Appreciate it. 

One thing I want to mention is that in our recommended deployment mode (whether it be for [Link: local dev testing] or production style [Link: multi-node deployments]), the only two server side processes of interest are yb-master & yb-tserver. The functionality of yb-cqlserver is essentially bundled into the yb-tserver itself, and the yb-cqlserver does not need to be run separately and is no longer heavily tested.

Each node's TServer process itself listens to a Cassandra & Redis compatible protocol natively and implements the YCQL & YEDIS compiler/execution engines in a embedded manner. [Link: There is no need to separately run the yb-cqlserver process.] For an architectural overview of yb-tserver process and its sub-components, see [here].

For example, you can start a yb-tserver and specify gflags for which port you want to listen to the YCQL & YEDIS protocols on:
```
./yb-tserver --tserver_master_addrs $IP:7100 --fs_data_dirs $DATA_DIRS --cql_proxy_bind_address $IP:9042 --redis_proxy_bind_address $IP:6379 >& /mnt/disk1/yb-data/tserver.out &
```
Having said that, we'll look into this error, and report back. [CC'ing @amitanandaiyer for this input.]
