Title

HttpObjectDecoder#isContentAlwaysEmpty does not handle upgrade responses correctly

Description
I ran into the following when testing Undertow HTTP2 interop via upgrade. This method contains the following:

```
// Correctly handle return codes of 1xx.
        //
        // See:
        //     - [URL] Section 4.4
        //     - [URL]
... [Log Snipped] ...
            return !(code == 101 && !res.headers().contains(HttpHeaderNames.SEC_WEBSOCKET_ACCEPT));
        }
```

This assumes that every response that does not have SEC_WEBSOCKET_ACCEPT is a Hixie 76 response, which is obviously incorrect for HTTP2 upgrade requests. A better approach would be to check directly for Hixie 76 headers. The only way I could get h2c to work correctly was to add a fake sec-websocket-accept header to my upgrade request.
Discussion
- @stuartwdouglas could you link me to the code you used for testing?
- [URL]
This is based on the http2 client example in the netty repo

If you remove the sec-websocket-accept header the test fails. I think a more correct approach to detect Hixie 76 would be to check for the presence of Sec-WebSocket-Key1 and Sec-WebSocket-Key2 headers.
