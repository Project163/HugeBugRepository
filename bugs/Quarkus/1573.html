Title

Change Content type in prematch filter does not change content type when matching (reactive!)

Description
### Describe the bug

When you post message with a non existing content-type (application/example) and in the prematch you change it 
to "application/json" i expect the matching rule should use the new content-type when matching. 

Instead i get the following message: 

```
posh
ERROR: Exception occured, message= The content-type header value did not match the value in @Consumes
javax.ws.rs.NotSupportedException: The content-type header value did not match the value in @Consumes
	at org.jboss.resteasy.reactive.server.handlers.ClassRoutingHandler.handle(ClassRoutingHandler.java:118)
	at org.jboss.resteasy.reactive.server.handlers.ClassRoutingHandler.handle(ClassRoutingHandler.java:27)
... [Log Snipped] ...
	at org.jboss.resteasy.reactive.server.vertx.ResteasyReactiveVertxHandler.handle(ResteasyReactiveVertxHandler.java:17)
	at org.jboss.resteasy.reactive.server.vertx.ResteasyReactiveVertxHandler.handle(ResteasyReactiveVertxHandler.java:7)
```

Below the simple pre match rule

```
java
 @ServerRequestFilter(preMatching = true)
  public void preMatchingFilter(ContainerRequestContext requestContext) {
  
    
... [Log Snipped] ...

  }
```



I am using the following libs:
```
 
			 io.quarkus 
			 quarkus-amazon-lambda-rest 
		 		

... [Log Snipped] ...
			 url-connection-client 
		 
```


### Expected behavior

Matching will use the new content-type set in the pre match filter

### Actual behavior

Matching will use the old content-type

### How to Reproduce?

1. Implement a simple rest service:

```java
 @Path("/example")
@Consumes(MediaType.APPLICATION_JSON)
  @POST
  public Uni  example(byte[] bytes)  {    

....
}
```

2. Create pre match filter which changes the content-type to application/json
3. Post a message with a content-type application/example
