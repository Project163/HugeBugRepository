Title

Shell.runCommand can deadlock

Description
Ran into a deadlock in Shell.runCommand.  Stacktrace details to follow.
Discussion
- Saw this while running the TestNodeManagerResync.testKillContainersOnResync unit test, although the nature of the deadlock looks like it could happen in other scenarios as well.

 It looks like we need to either be a little more persistent in trying to join with the errThread before entering the finally block where we lock and try to close the input stream, or we need to rethink the locking scheme that was added in   HADOOP-10146  .
- Attaching a quick patch that should solve the problem for the common case where the thread is only interrupted once.  Basic idea is to remember if we successfully joined with the errThread, and if we didn't we try to do so again before attempting to close the input stream.
