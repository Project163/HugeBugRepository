Title

ActiveRecord::afterFind() critical bug

Description
For example we have model `Post`:

```
php
class Post extends ActiveRecord
{
    public function getTags()
    {
... [Log Snipped] ...
    }
}
```

By making query like:

```
$model = Post::find()->with('tags')->where(['id' => $id])->one();
```

I assume that in `afterFind()` i can check is some relation populated or not. In Yii 1 it works very well. But unfortunately code like `$this->isRelationPopulated('tags'))` always return false even if relation is populated! Seems as critical bug.

Note that if you do something like:

```
$model = Post::find()->with('tags')->where(['id' => $id])->one();
VarDumper::dump($model->isRelaionPopulated('tags')); // return true!
```

So this bug affects only `afterFind()`.
Discussion
- yeah, afaik we call afterFind() before populating relations.
- Should be fixed anyway. Because in Yii 1 this works well. Also using `isRelationPopulated()` inside `afterFind()` needed for creating behaviors and very often used. Currently this bug seems for me as biggest Yii 2 active record drawback in compare with Yii 1 active record.
- @cebe I maked some investigations, seems can be easily fixed.
- sure, has to be fixed but it is a bit tricky.
