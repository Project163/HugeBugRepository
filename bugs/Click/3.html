Title

CliRunner.invoke returns "wrong" error code when using sys.exit

Description
`CliRunner.invoke` returns the "wrong" error code when the target function uses `sys.exit(error_string)`. Instead of a numerical code (as expected), `Result.error_code` contains the string message of the `SystemExit` exception raised by `sys.exit`. The reason is that `SystemExit.code` (which is [Link: used by `CliRunner.invoke`]) also contains that string:

```
In [1]: import sys

In [2]: try:
   ...:     sys.exit('error')
   ...: except SystemExit as e:
   ...:     print e.code
   ...:     
error
```

The [Link: documentation of `sys.exit`] says that

However, the actual exit code seems to be set somewhere else (and only if the `SystemExit` exception is not caught, obviously).

In my opinion, `CliRunner` should try to report the exit code that is reported to the OS. Hence, if `SystemExit.code` is not an integer, `Result.exit_code` should be 1.

I'd be happy to provide a corresponding PR if that helps.
Discussion
- It seems that `Result.output` also doesn't contain the error message in that case: Compare the output of 

```
import sys
import click
from click.testing import CliRunner

@click.command()
... [Log Snipped] ...
result = runner.invoke(main, [])
print 'Output: %r' % result.output
```

with that of 

```
import sys
import click
from click.testing import CliRunner

@click.command()
... [Log Snipped] ...
result = runner.invoke(main, [])
print 'Output: %r' % result.output
```

In my opinion, `Result.output` should be the same in both cases, since both cases yield the same console output when not run via `CliRunner`.
- `sys.exit("...")` is IMO not a thing people ought to do, but I'd agree that `CliRunner`'s isolation layer is too thin there. I'd be happy to merge a PR.
