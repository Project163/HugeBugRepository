Title

Request replaying fails when proxy is bound to local interface

Description
When the proxy is bound to the local interface, replayed requests fail.

Example that works:

1. Start mitmproxy with no arguments. Proxy will listen on port 8080 of all interfaces.
    ```
    $ netstat -na | grep 8080
    tcp          0      0  *.8080                 *.*                    LISTEN
    ```
2. Make a request through the proxy. Example: `http_proxy="[URL] curl -v [URL] A response is received.
3. Modify or just resend the request in mitmproxy (key `r`). A new response is received, and everything works correctly.

Example that fails:

1. Start mitmproxy binding only to the local interface: `mitmproxy --listen-host  `
   ```
    $ netstat -na | grep 8080
    tcp          0      0   .8080         *.*                    LISTEN
    ```
2. Make a request through the proxy, as before. A response is received.
3. Modify or just resend the request in mitmproxy (key `r`). **Now the request fails after a while (some timeout?) with an error**. At least one of the errors is `Error connecting to "www.example.org": [Errno -5] no address associated with name`.

Version tested:

```
$ mitmproxy --version
Mitmproxy: 3.0.0dev0967 (5067438e) 
Python:    3.6.0
OpenSSL:   LibreSSL 2.5.3
Platform:  OpenBSD-6.1-amd64-64bit
```
