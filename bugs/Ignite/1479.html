Discussion
- This issue was fixed as part of changes done for   IGNITE-264  , now IgniteAtomicLongChangingTopologySelfTest pass.
- Added in the  AtomicLongChangingTopologySelfTest. one more test case which creates/closes IgniteAtomicLong from client node, this test sometimes hangs on atomic long closing.
- Found reason for hang: GridDhtColocatedLockFuture erroneously tried to remap while it was executed inside system tx which locked topology. Fixed, merged in master (commit 3036c8d).
- at IgniteAtomicLongChangingTopologySelfTest.testFailoverWithClient() 
increase timeout: 
long stop = System.currentTimeMillis() + 30_000; 

 130_000 caused thread hang on in my case.
