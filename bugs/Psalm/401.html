Title

Variadic argument in definition assumed to be array

Description
The following code:
```php
function variadic_arguments( $foo, ...$bars ) {}

variadic_arguments($baz, $qux);
```
Produces the following error:
```
MixedArgument - 5:26 - Argument 2 of variadic_arguments cannot be mixed, expecting array 
```
[URL]

There is no implication that second argument should be `array ` here.

I suspect it might be confusing `...` when _calling_ a function (which does expect arguments supplied as array) with its use when _defining_ a function (which means a variable amount of standalone arguments of the type).
Discussion
- If you clear up the undefined vars errors this error also goes away: [URL]
- In my actual code there is still this error if the input is valid, but its type cannot be determined.

This specific message just seems to be misleading in nature. It doesn't say "you need to figure out which type argument is" it says "argument should be **numeric array**", which is not true.

- The problem is that if second argument `$qux` is of unknown type then error message claims it should be `array `, which is wrong. It just pulls this array type out of thin air, probably because it's confused by variadic function definition?

As long as you don't have error "upstream" it doesn't matter. The problem is that if you _do_ have problem it causes error message to be incorrect and confusing.
