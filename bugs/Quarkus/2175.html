Title

@CacheResult with method returning Uni makes cache exceed its maximum size

Description
### Describe the bug

When a method retuning a `Uni` is annotated with `@CacheResult` the result of the `Uni` is cached as expected, but the cache grows infinitely even when a maximum size is set.

### Expected behavior

When the cache reaches the specified maximum size, the number of elements in the cache should stop growing, or at least not grow infinitely.

### Actual behavior

No elements are evicted and the cache grows infinitely

### How to Reproduce?

In [Link: GreetingResource] there are two endpoints ("/hello/fast" and "/hello/delayed"). The "delayed" endpoint gets its data from a method returning a `Uni ` where the response is delayed, and the method is annotated with `@CacheResult`. The "fast" endpoint gets it data from method returning a `Uni` with an item without any delay.

```
java
@Path("/hello")
public class GreetingResource {

  @GET
... [Log Snipped] ...
  }
}
```
The cache maximum size is defined as `quarkus.cache.caffeine.maximum-size = 10`

In the [Link: GreetingResourceTest] the endpoints are invoked 20 times and then wait for the size of the cache to become 10.

```
java
@QuarkusTest
class GreetingResourceTest {

  @Inject
... [Log Snipped] ...
  }
}
```
However, the size remains at 20 even after waiting for 5 seconds
