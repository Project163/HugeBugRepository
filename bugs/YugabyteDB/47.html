Title

deletes of specific range key incorrectly deleting all rows for that partition key

Description
This was an issue reported by [URL] here [URL]

Consider the following example with a compound primary key consisting of 3 columns -- one partition column and two clustering column. [Note: Simpler compound primary keys, with say just two columns do not have this bug.]

```
CREATE KEYSPACE IF NOT EXISTS k;
USE k;

DROP TABLE T;
CREATE TABLE T (k text, t1 int, t2 int, v text, PRIMARY KEY (k, t1, t2));
... [Log Snipped] ...
INSERT INTO T (k, t1, t2, v) VALUES ('key2', 2, 1, 'v');
INSERT INTO T (k, t1, t2, v) VALUES ('key2', 2, 2, 'v');
```

Now,
```
DELETE FROM T WHERE k = 'key1' and t1=1;
```
should only delete 2 of the above rows. But all 4 of the rows for 'key1' seem to be getting deleted.

```
cqlsh:k> SELECT * FROM T;

 k    | t1 | t2 | v
------+----+----+---
 key2 |  1 |  1 | v
 key2 |  1 |  2 | v
 key2 |  2 |  1 | v
 key2 |  2 |  2 | v
```
Discussion
- Note: Simpler test cases with just one partition & one clustering column in the compound primary key do not seem to have this bug.

For example, this works just fine:

```
cqlsh:k> CREATE KEYSPACE IF NOT EXISTS k;
cqlsh:k> USE k;
cqlsh:k>
cqlsh:k> DROP TABLE T;
cqlsh:k> CREATE TABLE T (k text, t1 int, v text, PRIMARY KEY (k, t1));
... [Log Snipped] ...

(3 rows)
```
