Title

need an 88718-style workaround for table names

Description
from [URL] , given a model:

```
from sqlalchemy.ext.declarative import declarative_base
from sqlalchemy import MetaData
from sqlalchemy.schema import Column, ForeignKey
from sqlalchemy.types import CHAR, VARCHAR

... [Log Snipped] ...
	name = Column(VARCHAR(255), unique=True)
	table1_id = Column(CHAR(36), ForeignKey("Table1.id"))
```

user reports that with mysql 8 on osx the FK spec comes back as:
```

For conn_fk_by_sig:
(None, 'Table2', ('table1_id',), None, 'table1', ('id',), None, None, 'not deferrable')

For metadata_fks_by_sig:
(None, 'Table2', ('table1_id',), None, 'Table1', ('id',), None, None, 'not deferrable')
```

since we haven't tested against OSX or a lower case platform we need to either look into that or start turning off the 88718 fix for greater than 8.0.3, or just turn it off entirely and warn for 8.0.1-> 8.0.3
