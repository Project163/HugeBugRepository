Title

esrecurse uses unmonkeypatched estraverse

Description
There is a bug when getting `sourceCode` from code containing JSX, and then passing it back into `eslint.verify()`.  The problem seems to be that esrecurse uses a version of estraverse that we have not monkeypatched to include JSX keys.  Because of this, esrecurse visits all properties of the node (https://github.com/estools/esrecurse/blob/master/esrecurse.js#L73). Normally, this isn't a problem when simply linting text, as the esrecurse (called from escope) happens early on in `eslint.verify()` ([Link: here]), before `parent` properties are added to the AST ([Link: from the enter event]).  But, after linting is performed and the `sourceCode` is obtained, the AST will now contain the `parent` properties, which causes a stack overflow when passed to `escope.analyze()`.

To solve this, @mysticatea has suggested monkeypatching estraverse similarly to [URL]  I have no real experience with monkeypatching, so I have no idea how we could/should go about this.  But, it's important to solve if we want to allow autoconfig to work on JSX code, because it uses sourceCode extensively (for performance reasons).
