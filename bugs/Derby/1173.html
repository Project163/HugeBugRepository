Title

getTables() call with 10.3 causes java.sql.SQLException: The parameter position '8' is out of range. The number of parameters for this prepared statement is '7'.

Description
The DatabaseMetaData.getTables() call below causes this error with 10.3.  10.2 is fine.

 public class GetTables { 

     public static void main(String[] args) throws Exception {

	ResultSet tableRS = conn.getMetaData().getTables(null, 
							 null, null, new String[] 
{"TABLE", "GLOBAL TEMPORARY", "LOCAL TEMPORARY", "ALIAS", "SYNONYM"}
 ); 

 	tableRS.close(); 
	conn.close(); 
    }

Discussion
- If this issue requires changing the metadata statements,   DERBY-1107   will also need to be fixed to allow metadata statements to be updated with maintenance releases. 

 Kathey
- The workaround for this issue is to only pass table types returned by getTableTypes: 
Table Types: 
        SYNONYM 
        SYSTEM TABLE 
        TABLE 
        VIEW 

 or just pass null to the types argument to get all the types. 

 The javadoc for getTables actually says: 
types - a list of table types, which must be from the list of table types returned from getTableTypes(),to include; null returns all types.  So, I suppose it could be argued that this is incorrect usage, but I think it should still work since it did before.

- I'm not sure a warning is worth it. The table types must be from getTableTypes() is a new comment in JDK 6 (and hence JDBC4). JDBC 3 users will not be expecting such a warning to be issued. Also maybe such a change (to add a warning) should be under a new issue?
- Here is a patch for   DERBY-3000   and   DERBY-1790  .   The new behavior is that the table types are no longer just determined by the first letter but expect a match to the table types in getTableTypes() 

 One possible concern about the patch is that applications that have used the workaround of passing a table type starting with 'A' to  get Synonyms  will need to be changed.
