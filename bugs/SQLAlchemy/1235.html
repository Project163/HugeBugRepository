Title

The on_duplicate_key_update method for MySQL renders with fixed columns names

Description
### Describe the bug

When calling the `visit_on_duplicate_key_update` method, the compiled output will replace all the `insert_stmt.inserted` aliases to the one matching the `column.name`, even if the alias points to another object.
 
The issue could be considered a split-off from #5173, at [URL] where it sets `"VALUES(" + self.preparer.quote(column.name) + ")"`.

I think the best way is to use `obj.name` instead of `column.name`.

Btw, the issue can be reproduced on both `1.3.24` and `1.4.26`.


### To Reproduce

```
python
from datetime import datetime
from sqlalchemy import Column, Integer, String, Boolean, DateTime, func
from sqlalchemy.ext.declarative import declarative_base

... [Log Snipped] ...
    'updated = IF(VALUES(updated) > debug_tbl.updated, VALUES(updated), debug_tbl.updated)'
)
```


### Error

AssertionError

### Versions

- OS: Windows
- Python: 3.8.8
- SQLAlchemy: 1.3.24
- Database: MySQL 5.7.33
- DBAPI (eg: psycopg, cx_oracle, mysqlclient): pymysql 0.9.3
