Title

[2.5.0] AbstractFileObject is backwards-incompatible

Description
This is a show-stopper issue. 

 This commit: 

  [URL]

 Made the abstract (mandatory) method `doGetInputStream()` into a protected method that calls `doGetInputStream(int bufferSize)` which throws an exception. 

 All current implementations implement only `doGetInputStream()` (because that was the API in `2.4.1`) which is actually not called anywhere in the class -  only `doGetInputStream(int bufferSize)` is. This means that  ALL  VFS plugins break on `2.5.0`.
Discussion
- boris-petrov , 

 May you provide a test case please? 

 Doc:  [URL] does not flag this as binary incompatible.
- ggregory  - well, just change in "commons-vfs2/src/main/java/org/apache/commons/vfs2/provider/ram/RamFileObject.java" line 94 which says: 

  
 protected InputStream doGetInputStream(final int bufferSize) throws Exception {
 
  

 To: 

  
 protected InputStream doGetInputStream() throws Exception {
 
  

 (as a 3rd party provider would have because it doesn't know of the method with the argument) 
and then run "mvn test -Dtest=RamProviderTestCase" - you'll see the tests fail. Which is normal as VFS 2.5.0 never calls the method without the argument. 

 P.S. The change is not binary-incompatible (because the method exists in the base type and is overridable) but is a breaking one because this method is no longer called by anything.
