Title

setError problems, possible related to #140

Description
**Describe the bug**
I've found that setError when used as part of an submission handler causes unexpected behaviour. In many instances, the component rerenders then the entire error is deleted, in other (less consistent) cases you are unable to set a message. The former problem appears to affect versions `3.8.10` onwards and works correctly in `3.8.9`. Additionally, the error is only cleared when the first parameter of `setError` matches exactly the name of the input field.

This is linked to issue #140 and I've slightly adjusted the CodeSandbox example in that issue thread (https://codesandbox.io/s/react-hook-form-basic-n53gm) to create a reproduction of the problem, as below.

**To Reproduce**
Steps to reproduce the behavior:
1. Load the following sandbox: [URL]
2. Note that on submission, no error is displayed
3. Change the dependency version of `react-hook-form` from `3.8.10` to `3.8.9`
4. On submission, an error is displayed

From the same issue thread (#140), you can use the other Sandbox example to see that a message cannot be set for the error:

[URL]

**Expected behavior**
A rerender does not cause the error to be cleared and a message can be set when using `setError` on submit.
