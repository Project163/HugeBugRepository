Title

INTEGER function cannot be abbreviated

Description
The reference manual ( [URL] states that the INTEGER function can be abbreviated by INT, but Derby   does not accept that. 

 Example: 

   VALUES INTEGER(1.5); 
  -> OK 

   VALUES INT(1.5); 
  -> ERROR 42X80: VALUES clause must contain at least one element.
Discussion
- I ran into this problem when I was writing grant/revoke testcases this morning, so I fixed it.    
The derbyall suite is still running, I will post the patch when it ran successful. 

 I noticed that lang/cast.out has a testcase for this but the expected result is wrong in the master. 

 values CHAR(INT(67890)); 
ERROR 42X01: Syntax error: Encountered "INT" at line 2, column 13.

 Ran derbyall suite and no new regression is introduced by this patch.  Appreciate it if someone can review this.  Thanks!
