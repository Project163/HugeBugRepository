Title

Yii2 butchers SQLSTATE error in \yii\db\Exception

Description
### What steps will reproduce the problem?
```
PHP
// Execute under MySQL.
try
{
	\Yii::$app->getDb()->createCommand('SELECT * FROM does_not_exist')->execute();
... [Log Snipped] ...
	die;
}
```

### What is the expected result?
When executed under MySQL:
42S02

### What do you get instead?
42

### Additional info
SQLSTATE value is NOT an integer! It can contain letter characters! This fact is correctly handled by PHP (PDOException::getCode() returns a string):

[URL]

[URL]

But for some reason Yii2 decided it would be a good idea to just convert this string code with letters to integer completely butchering its value in the process (in yii2\db\Schema.php):
```PHP
    public function convertException(\Exception $e, $rawSql)
    {
        // ...
        return new $exceptionClass($message, $errorInfo, (int)$e->getCode(), $e);
    }
```
This needs to be fixed ASAP.


| Q                | A
| ---------------- | ---
| Yii version      | 2.0.32
| PHP version      | 7.4.3
| Operating system |Windows 10
Discussion
- You can get the error code from `$e->errorInfo[1]`

```php
try {
  \Yii::$app->getDb()->createCommand('SELECT * FROM does_not_exist')->execute();
} catch(\yii\db\Exception $e) {
  var_dump($e->errorInfo[1]);
  die;
}
```
- That does NOT give you any right or reason to render perfectly good SQLSTATE value into a broken and useless integer in the `\yii\db\Exception::getCode()`.
- ... [Middle Discussions Snipped for Brevity] ...
- It still occurs when Connection errors are thrown such as HYT00 which is being cast as 0.

It is mainly visible whenever you have timeout or internet issues between your Yii2 app and your database.

The culprit seems to be this line which still cast the error code as an int: [URL]
