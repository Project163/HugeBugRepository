Title

Different extended stats with apparently same query

Description
I tested this both from Kibana and using the HTTP API of elasticsearch to check that is a problem of elasticsearch instead of Kibana:

This request:

```
curl -XPOST " :9200/my_index_*/_search?pretty" -d '{
    "aggs" : {
        "grades_stats" : { "extended_stats" : { "field" : "my_field" } }
    }
}'
```

Returns this

```
"aggregations" : {
    "grades_stats" : {
      "count" : 24526,
      "min" : 0.0,
      "max" : 5545.0,
... [Log Snipped] ...
    }
  }
```

With a wrong **std_deviation_bounds**. Only 24526 documents from index my_index_docs_with_my_field have the field my_field so it should does not matter that I just use my_index_\* instead of my_index_docs_with_my_field. In fact, the next request, specifying the index my_index_docs_with_my_field returns the same count of documents, 24526 and the same variance and std_deviation but with different std_deviation_bounds. These std_deviation_bounds make sense because are equal to avg+/-2*std_deviation while the first request seems wrong.

The second request:

```
curl -XPOST " :9200/my_index_docs_with_my_field/_search?pretty" -d '{
    "aggs" : {
        "grades_stats" : { "extended_stats" : { "field" : "my_field" } }
    }
}'
```

returns

```
"aggregations" : {
    "grades_stats" : {
      "count" : 24526,
      "min" : 0.0,
      "max" : 5545.0,
... [Log Snipped] ...
    }
  }
```

Is this behaviour normal? If so, why the first std_deviation_bounds is not equal to avg+/-2*std_deviation?
Discussion
- This is a bug indeed. When some requested indices do not have mappings for the requested field, a parameter that is used to compute this bounds (sigma) is not propagated correctly.
