- I think that the commons-csv should not be opinionated concerning the question if an empty header makes sense or not. It should parse it (if the structure is legit csv) and leave this decision to the user. 

   

 It's a common pattern to have an empty header for the first column containing the row number/index. E.g. see official examples such as  [URL]
- After a second look at this issue, I think there should probably be a way to configure a CSVFormat such that this example at least doesn't throw an exception. 

 But, if you have two columns with the same name, or two column names missing, that would cause undefined results for  CSVRecord.get(String) , which is bad IMO, and  CSVRecord.get(int)  would still be OK. 

 Perhaps throwing an exception could be changed from the current fail-fast to delegating it to  CSVRecord.get(String) . I don't think we want to allow for undefined results. 

 ATM, I do not think we should add an option to make fail-fast vs. not vs.  CSVRecord.get(String)  throws vs.  CSVRecord.get(String)  doesn't throw.
