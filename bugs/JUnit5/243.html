Title

junit-platform-commons 1.7.0 does not contain MANIFEST.MF as first JAR entry

Description
While the JAR file specification doesn't mention this, the `java.util.jar.JarInputStream` implementation assumes that `META-INF/MANIFEST.MF` is the first or second entry in a jar file.

Also the [Link: Java Archive Tool Documentation] mentions:


Commit 5631ebc (#2217) introduced reproducible builds. Part of this is `java-repackage-jars` plugin, which sorts jar entries alphabetically. For junit-platform-commons, this results in the following first entries:


Evidently, this causes issues with any tools implemented using `JarInputStream`.

## Steps to reproduce

- download [Link: junit-platform-commons-1.7.0.jar]
- `unzip -l junit-platform-commons-1.7.0.jar` (or list the file contents in another way)

Note: my real scenario involved [Link: code in an Apache Sling module]

## Desired outcome

It would be nice if `MANIFEST.MF` could be sorted to the top of the list for reproducible builds.
