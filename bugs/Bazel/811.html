Title

Disable //src/tools/singlejar:combiners_test due to incompatible_auto_configure_host_platform

Description
Currently, `//src/tools/singlejar:combiners_test` fails to build when `--incompatible_auto_configure_host_platform` is enabled (which is #7081).

Example:
```
$ bazel test --incompatible_auto_configure_host_platform //src/tools/singlejar:combiners_test 
DEBUG: /usr/local/google/home/jcater/.cache/bazel/_bazel_jcater/ /external/bazel_toolchains/rules/rbe_repo/checked_in.bzl:103:9: rbe_ubuntu1804_java11 not using checked in configs as detect_java_home was set to True 
DEBUG: /usr/local/google/home/jcater/.cache/bazel/_bazel_jcater/ /external/bazel_toolchains/rules/rbe_repo/checked_in.bzl:103:9: rbe_ubuntu1604_java8 not using checked in configs as detect_java_home was set to True 
ERROR: While resolving toolchains for target //src/tools/singlejar:combiners_test: no matching toolchains found for types @bazel_tools//tools/cpp:toolchain_type
WARNING: errors encountered while analyzing target '//src/tools/singlejar:combiners_test': it will not be built
... [Log Snipped] ...
FAILED: Build did NOT complete successfully
FAILED: Build did NOT complete successfully
```

The fix for this is to change the target [Link: `//:default_host_platform`] to inherit from `@local_config_platform//:host` instead of from `@bazel_tools//platforms:host_platform`.

However, that currently fails because in Bazel 0.28.1, `@local_config_platform//:host` was missing public visibility. This was added in  , which is included in Bazel 0.29.0.

Therefore, I propose to disable this test in BazelCI until after Bazel 0.29.0 is released, and then re-enable it and fix the platform definition.
