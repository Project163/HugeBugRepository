Title

bug: `catch (symbol)` changed

Description
While using Rollup's sources as a test case for `uglify-es` I stumbled across a Rollup `catch` symbol replacement bug. I was unable to make a simple standalone test case, but if you apply the following patch to Rollup's source tree itself then the bug can easily be reproduced with `npm test`:
```
patch
--- a/rollup.config.js
+++ b/rollup.config.js
@@ -24,7 +24,7 @@ export default {
                buble({
... [Log Snipped] ...
                fs.mkdirSync( dir );
        }
```
```
$ npm test
...
Error compiling dist/rollup.js:
---
89 : function mkdirpath ( path$$1 ) {
... [Log Snipped] ...
                     ^
Unexpected token (93:15)
```
The `catch` symbol should never be replaced as it is essentially a scoped variable declaration in the `catch` block.

Note: a yet to be released fix for `acorn` may have to be applied prior to running `npm test` due to an ES6 bug: [URL]
