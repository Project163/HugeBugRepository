Title

[YSQL] Query processing incorrect if schema ordering does not match PK ordering

Description
There is a bug in processing WHERE clause in cases where ordering of columns in CREATE TABLE does not match PK order:
```
=> CREATE TABLE test (id1 BIGINT, date DATE, id2 BIGINT, id3 INT, value JSONB, PRIMARY KEY(id1 HASH, id3 ASC, date ASC, id2 DESC));
CREATE TABLE
=> INSERT INTO test (id1, date, id2, id3, value) VALUES (' ', '20190101', '0', '1', '"val"');
INSERT 0 1
=> SELECT * FROM test;
... [Log Snipped] ...
-----+------+-----+-----+-------
(0 rows)
```

This happens because we push down WHERE condition on `id3` with column ID `3` (instead of `1`).
Discussion
- This has been fixed.
