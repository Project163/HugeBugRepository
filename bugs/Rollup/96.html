Title

Incorrect function name mangling while tree shaking dependencies

Description
Rollup does some incorrect mangling for function names while tree shaking. We have seen this behavior for quite a while, so not sure what exact version this was introduced.

I believe this might be a trivial bug to fix for the owners if you know the code base. Otherwise, if you don't have time to prioritize this, let me know and I will dig in.

[Link: Repro]

## Code example: 
This example is a boiled down version of the use of babel helpers (latests babel 7).

main.js
```js
import _inherits from "./inherits";
export function test() {
    var Foo = {};
   _inherits({}, Foo);
}
```

inherits.js
```js
import setPrototypeOf from "./setPrototypeOf";

export default function _inherits(subClass, superClass) {
  if (superClass) setPrototypeOf(subClass, superClass);
}
```

setPrototypeOf.js

```
js
export default function _setPrototypeOf(o, p) {
  _setPrototypeOf = Object.setPrototypeOf || function _setPrototypeOf(o, p) {
    o.__proto__ = p;
    return o;

  return _setPrototypeOf(o, p);
}
```

Output:

```
js
Object.defineProperty(exports, '__esModule', { value: true });

function _setPrototypeOf(o, p) {
  _setPrototypeOf = Object.setPrototypeOf || function _setPrototypeOf(o, p) {

exports.test = test;
```

As you can see the `setPrototypeOf` call is named incorrectly.
Discussion
- Do add a bit more detail, I think the issue is because of the dynamic binding used in the `_setPrototypeOf` exported function.
- Seems to be a very old issue around the interplay of assigning names to default exports that have ids themselves and are reassigned. Would probably need to check how a "real" ES6 loader handles this. The issue is very specific to the use of default exports. You can avoid it effectively by using named exports.
