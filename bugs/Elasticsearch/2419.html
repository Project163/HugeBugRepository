Title

Composite Aggregation have missing buckets on paginated results with "size" and "after"

Description
**Elasticsearch version**:
7.7.1

**Description of the problem including expected versus actual behavior**:
Composite aggregation will produce fewer buckets when used with limited "size" and pagination with "after"

**Steps to reproduce**:

 1. Create this index:
```
PUT test-activities
{
  "mappings" : {
      "properties" : {
        "activityTime" : {
... [Log Snipped] ...
    }
}
```
 2. Add test data to the index
```
POST _bulk
{"index":{"_index":"test-activities"}}
{"subscriberID":37640,"activityTime":"2020-06-03T00:53:10"}
{"index":{"_index":"test-activities"}}
{"subscriberID":90640,"activityTime":"2020-06-03T00:55:10"}
... [Log Snipped] ...
{"index":{"_index":"test-activities"}}
{"subscriberID":31640,"activityTime":"2020-06-03T01:54:10"}
```

 3. Use below search request which contains a composite aggregation with size 10, **produce six buckets**.
```
POST test-activities/_search
{
  "aggs": {
    "rollup":{
      "composite": {
... [Log Snipped] ...
  "track_total_hits": false
}
```

Here are 6 buckets created for above request:

```
{
  "took" : 4,
  "timed_out" : false,
  "_shards" : {
    "total" : 1,
... [Log Snipped] ...
  }
}
```

4. Run above search request with limited composite aggregation size:3
```
POST test-activities/_search
{
  "aggs": {

      "composite": {
... [Log Snipped] ...

}
```

Here are first 3 buckets and after key returned as below:

```
POST test-activities/_search

  "aggs": {
    "rollup":{
      "composite": {
... [Log Snipped] ...
  "track_total_hits": false
}
```
