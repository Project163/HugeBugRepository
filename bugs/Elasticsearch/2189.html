Title

Default javatime string formatter in date_histo differs from joda

Description
It looks like the new javatime default formatter for `date_histogram` (and maybe elsewhere?) appends the timezone verbatim to the string.  This differs from how joda did it, which was to append the offset.

Example:

```
js
PUT my_index/_doc/1?refresh
{
  "date": "2015-10-01T00:30:00Z"
}
... [Log Snipped] ...
  }
}
```

In 6.5, the default formatter for `key_as_string` returned `-06:00` as the timezone component:

```
js
{
 ...
  "aggregations" : {
    "by_day" : {
... [Log Snipped] ...
  }
}
```

But on master, it now returns `America/Edmonton`
```
js
{
 ...
  "aggregations" : {
    "by_day" : {
... [Log Snipped] ...
  }
}
```
