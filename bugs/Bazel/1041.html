Title

Platform-based flags + label flags + bzlmod

Description
### Description of the bug:


The syntax required to specify a label flag in an external repository as one of platform-based flags depends on whether one uses bzlmod to manage dependencies or not. Furthermore, the syntax in the presence of bzlmod is very unintuitive!

In the WORKSPACE world, the natural syntax (simply copy-pasted from CLI invocations) worked fine:

```
flags = [
    "--@upstream//:label_flag=@upstream//:alt",
],
```

With bzlmod enabled, this produces an error:

```
ERROR: no such package '@@upstream//': The repository '@@upstream' could not be resolved: Repository '@@upstream' is not defined
```

Instead, one has to write:

```
flags = [
    "--@@upstream~//:label_flag=@@upstream~//:alt",
],
```

Besides looking a bit weird, I worry that this depends on some private implementation details of bzlmod.

Is there a nicer syntax, or some function I could pass `@upstream//:alt` to in order to obtain the correct string? (Some BUILD file equivalent of `str(Label(...))`, I suppose?)
