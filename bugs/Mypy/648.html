Title

Several same Forward References in TypedDict wrongly detected as Recusive Type

Description
MNWE:
```
from mypy_extensions import TypedDict
from typing import Any, List

class Foo(TypedDict):
    bar: 'Bar'
... [Log Snipped] ...

Bar = List[Any]
```

Result: 
```
$ mypy --python-version 3.6 mypy_test.py 
mypy_test.py:4: error: Recursive types not fully supported yet, nested types replaced with "Any"
```
(Python 3.6, mypy 0.570 & 0.580)

The TypedDict Foo has two fields, both being of type Bar which is defined later and a forward reference is used to mention it (obviously not needed in this MWNE but needed in real life). This is incorrectly detected as a Recursive type by mypy which then produce a rather confusing error message.

The error appears using both syntaxes for TypedDict (the class-like syntax used here, or the TypedDict() syntax commented out).

The error disappears without the forward reference (moving the definition of Bar up and removing the quotes in Foo). The error stays if Bar is moved up and the quote stay in Foo ("forward" reference backward?)

The error only appears if there are two (or more) fields of type Bar inside Foo. If either bar or baz is removed, the error disappears.

The error disappears if Bar is a simpler type, eg int or Any. It seems to depend on a more complex type.
Discussion
- Good catch! I think there is a flaw in recursive type detection logic. Currently it fires if a type was encountered twice while processing a given node. The problem is that resolving subscripted forward type aliases results in the same type (even by identity). So it looks like we need a more sophisticated logic, or maybe a simpler solution would be to just copy the type every time we resolve a subscripted alias, this will be consistent with how we process simple (unsubscripted) aliases, that create a new instance for each encounter.

I am actually surprised this obvious corner case was not noticed before.
- Same problem (I guess), but even less intuitive:
```
from mypy_extensions import TypedDict
from typing import Any, List

Bar = List[Any]

... [Log Snipped] ...

Toto = int
```
This causes an incorrect Recursive Types detection.
Removing any of the fields in Foo makes the Recursive Type detection disappear. Moving Toto up also does that.

So it needs both a type being used more than once, and a forward reference, but not necessarily on the same type. And the duplicated type need to be complex enough (`Bar = int` is OK).
