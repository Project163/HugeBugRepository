Title

ConfigInstaller is not deleting files in the etc directory

Description
The ConfigInstaller takes the pid from the ConfigurationEvent and tries to get the configuration from ConfigAdmin. This will not return the config because the config has been deleted. See  [URL]

 The ConfigurationEvent must provide the felix.fileinstall property, so that the ConfigInstaller can use that to delete the corresponding file in etc.
Discussion
- FELIX-5686   fixed a NPE that was happening due to this issue, but did not fix the issue of files not being deleted.
- The dictionary is not available anymore when the event is sent.  This means we'll have to keep an additional map to cache the link between pid -> file so that we can delete the file when the pid is deleted.
