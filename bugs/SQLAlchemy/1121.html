Title

try to get rid of str(self) in proxy label mechanics once and for all

Description
**Describe the bug**
I've [Link: recently hit a a breaking test] in an open source library we maintain. 

The issue involves the use of`sqlalchemy.ext.compiler.compile` decorator.

We currently have two definitions of a function, one for a "default" dialect, and one specifically for postgresql (see [Link: here] for context):

```
python
@compiles(last)
def compile(element, compiler, **kwargs):
    """
    By default, `last` is not defined.
... [Log Snipped] ...
    """
    return f"last_agg({compiler.process(element.clauses)})"
```

Up to 1.4, this worked well enough - but since 1.4 it seems like having both definitions doesn't work: the sqlalchemy runtime seems to somehow pick up the "wrong" one (the default one rather than the postgresql one) when running our unit-tests.

If I simply remove the default one altogether, everything works fine. In `1.3.x`, this wasn't an issue however - I was able to have both definitions and have the sqlalchemy runtime use the right one everytime.

Is this intended behavior? any tips would be helpful, otherwise seems to me like a bug.

**Expected behavior**
Having multiple definitions for a function element `compiles()` block for different dialects should work as it did before `1.4` release.

**To Reproduce**

Please see [Link: here] for unit-test which used to work and now fails. the actual code which is relevant is linked to above, for completeness here it is again:

```
py
class last(FunctionElement):
    """
    Define a SQLAlchemy function that maps to a postgres function to select the last non-null value in window.
    """
... [Log Snipped] ...
    """
    return f"last_agg({compiler.process(element.clauses)})"
```

**Error**

See above, there is no explicit error message, rather the wrong specification is picked up by the runtime which doesnt match the active dialect when using `compiles()` on a `FunctionElement` class multiple times for different dialects.
