Title

Highlighted hints use old data for their actions

Description
Currently the following logic is used to open hints with the mouse/vi mode:

```rust
                let hint = ctx.display().vi_highlighted_hint.take();
                if let Some(hint) = &hint {
                    ctx.trigger_hint(hint);
                }
                ctx.display().vi_highlighted_hint = hint;
```

```rust
        let hint = self.ctx.display().highlighted_hint.take();
        if let Some(hint) = hint.as_ref().filter(|_| button == MouseButton::Left) {
            self.ctx.trigger_hint(hint);
        }
        self.ctx.display().highlighted_hint = hint;
```

Both of these take the current highlighted hint and pass it directly to `trigger_hint`. However `trigger_hint` uses the following logic to convert the hint to its text equivalent:

```rust
        let hint_bounds = hint.bounds();
        let text = match hint.hyperlink() {
            Some(hyperlink) => hyperlink.uri().to_owned(),
            None => self.terminal.bounds_to_string(*hint_bounds.start(), *hint_bounds.end()),
        };
```

This is problematic since the highlighted hint has not been checked for validity since the last frame, which means the underlying terminal content could have changed since the user requested its opening.

To avoid accidentally opening arbitrary text, Alacritty should either invalidate the highlighted hints before passing them to the `trigger_hint` function or recreate the hints.

If the hints are recreated, we might also be able to remove the ugly `take()` -> `assign` stuff.
