Title

Fix issue where ORDER BY in SQL subqueries does not take effect

Description
When executing SQL queries that contain an ORDER BY clause inside a subquery, the ordering is not respected in the final query results. This behavior is inconsistent with standard SQL semantics and may cause incorrect result ordering or unexpected query outputs.
Discussion
- Root Cause  
Due to a Calcite version upgrade, a feature was introduced that removes ORDER BY clauses inside subqueries. 
This feature is enabled by default, causing the subquery ORDER BY to be ignored during RelNode parsing. 

  Dev Design  
A new system-level configuration is introduced: 
 kylin.query.calcite.remove-sort-in-subquery  
The default value is false, which means Kylin will keep the ORDER BY clause in subqueries instead of removing it.
