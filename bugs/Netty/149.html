Title

EventExecutorGroups and Channel Initialization

Description
Found in 4.0.0.CR1:

I configure a ChannelPipeline with several handlers, the last of which can take a variable amount of time to execute. With that in mind I have the final handler run in its own EventExecutorGroup.

I had expected that the earlier handlers in the pipeline would execute regardless of whether the EventExecutor pinned for the final handler in the channel was currently busy or not, but find that if the EventExecutor pinned for the final handler is busy, then the ChannelInitializer is delayed in its execution, and the entire channel waits for the EventExecutor to become available before it is initialized.

This is because when the channel is initialized, it will execute the addLast using the configured EventExecutor if there is one:

DefaultChannelPipeline.addLast():181 

```
java
executeOnEventLoop(newCtx, new Runnable() {
    @Override
    public void run() {
        synchronized (DefaultChannelPipeline.this) {
... [Log Snipped] ...
    }
});
```

In my case, I am using Netty with the Http Codec support, so my pipeline consists of:
1. A handler which listens for channelRegistered, placing the channel in a ChannelGroup
2. The normal HttpResponseDecoder/Encoder codec netty ChannelHandlers
3. My custom handler which can sometimes take some time to execute.

I had expected that regardless of whether the entire pool of available Executors in my DefaultEventExecutorGroup were currently consumed, incoming Http Requests would be placed in the ChannelGroup and requests would decoded and queued on my final handler.

This is important, because amongst other things, if I want to close the server I want to send a 503 to all currently connected clients, so I want connection and request parsing to be independent of processing.
