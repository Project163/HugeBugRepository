Title

FileDependency is prone to fail in certain situations

Description
### Minimal example:

config.php:

``` php
'components' => [
    'cache' => [
        'class' => 'yii\caching\FileCache',
    ],
    'volatileCache' => 'yii\caching\ArrayCache',
    ...
],
```

controller.php:

```
php
// insert appropriate namespace and use statements here
class TestController extends \yii\console\Controller
{
    private $_parsedContent;
... [Log Snipped] ...
    }
}
```
### Problem Analysis

Interestingly enough the above example does work when using the `FileCache` component in favor of the `ArrayCache` component. Since I could not trace any direct call on `clearstatcache`, I assume that the stat cache is implicitly cleared by PHP after either of the calls to `file_put_contents`, `chmod` and `touch` inside `FileCache::setValue`.

Probably the easiest way to fix this bug is to explicitly call `clearstatcache` inside `FileDependency::generateDependencyData`, i.e. modify it as follows:

```
php
protected function generateDependencyData($cache)
{
    if ($this->fileName === null) {
        throw new InvalidConfigException('FileDependency::fileName must be set');
... [Log Snipped] ...
    return @filemtime(Yii::getAlias($this->fileName));
}
```
### Additional info

Yii: 2.0.9
PHP: 7.0.8-0ubuntu0.16.04.2 (cli)
