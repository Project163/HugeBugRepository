Title

-Dpidfile.path=NUL no longer works on Windows

Description
This was broken in #7244
```
scala
scala> val pid = new java.io.File("NUL")
pid: java.io.File = NUL

scala> new java.io.FileOutputStream(pid).write(42)
... [Log Snipped] ...
  at java.nio.file.Files.newOutputStream(Unknown Source)
  ... 42 elided
```

Workaround is to use `-Dpidfile.path="/dev/null"` even on Windows because [Link: Play has a special case for it]
Discussion
- Hi @dwickern, thanks for the report. Would you mind checking if there are any `OpenOption`s that we can pass to `newOutputStream` that might solve the problem. E.g. perhaps `Files.newOutputStream(pid.toPath, APPEND)` would work for the special `NUL` file, rather than the default of `CREATE, TRUNCATE_EXISTING, WRITE`.
- Indeed, it works using `APPEND`. It also works with `CREATE+WRITE` but fails if `TRUNCATE_EXISTING` is included.
- ... [Middle Discussions Snipped for Brevity] ...
- @dwickern well I just think that it's better to use `-Dpidfile.path=/dev/null` on both systems, because you don't need seperate vm configurations then ;)
I think why it worked is, because the old way would go trough a windows api where NUL meant something like `/dev/null`.
- There is a fix for this now: #7673.
