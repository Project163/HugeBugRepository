Title

[PR offer] Always call onCompletion in ConcatenatingMediaSource.moveMediaSource

Description
### Issue description
In `moveMediaSource` method in `ConcatenatingMediaSource` class, [Link: at this line], when there's actually no source to move (current and new index are the same), the `onCompletion` action is **not** invoked:

```java
if (currentIndex == newIndex) {
    return;
}
```

That is somehow a different behavior than e.g. `removeMediaSourceRange`, where completion callback is invoked right away when there's nothing to remove.

Also, that forces callers to always check for this special scenario, basically requiring a wrapper around this specific operation.

Would you consider a PR changing `moveMediaSource` behavior, so that it always calls completion callback?

We understand this can be considered a breaking change in API, as client code in its own logic may rely on this *missing invocation*. Maybe you could make the new behavior as an opt-in, like an additional method signature on `ConcatenatingMediaSource`, e.g. `moveMediaSource(int currentIndex, int newIndex, @Nullable Runnable actionOnCompletion, bool alwaysComplete)`.

Thanks for your attention
