Title

auto_correlate fails if all froms are existing in a superquery

Description
**Migrated issue, originally created by Luke Cyca ([Link: @lukecyca])**

    from sqlalchemy.ext.declarative import declarative_base
    from sqlalchemy import *
    from sqlalchemy.orm import *
    Base = declarative_base()
    
    
    class Document(Base):
        __tablename__ = 'documents'
    
        id = Column(Integer, primary_key=True)
    
        @classmethod
        def __declare_last__(cls):
    
            cls.result_type = column_property(
                select([Link: distinct(Result.type)]))
                .where(Result.document_id == cls.__table__.c.id)
            )
    
    
    class Result(Base):
        __tablename__ = 'results'
    
        id = Column(Integer, primary_key=True)
        type = Column(Unicode)
        document_id = Column(Integer, ForeignKey(Document.id))
        document = relationship(Document)
    
    
    session = Session()
    
    # This works
    print session.query(Document)
    
    # This does not
    print session.query(Document).join(Result)

I would like both of these queries to work. I would expect the latter to emit the following query:

    SELECT
        documents.id AS documents_id, 
        (
            SELECT DISTINCT results.type
            WHERE results.document_id = documents.id
        ) AS anon_1 
    FROM documents
    JOIN results ON documents.id = results.document_id

I've tried using various forms of select().correlate() and select().correclate_except() but I don't think there is any way to make both of the above queries work.

I've verified this behaviour in the latest 0.8 snapshot as well as the 0.8.0b2 release.

- **Luke Cyca ([Link: @lukecyca]) wrote:**

You're right: I hit this issue while trying to optimize a query which joins these two tables together. Previously, I just correlated to `cls.__table__` (as you suggested) which works, but results in a slow loop when I EXPLAIN ANALYZE the joined query in Postgres. I made it fast by correlating to ''both'' tables, but then it breaks when the Result class isn't joined to the superquery.

Removing [Link: this if block] is what I had in mind for fixing this issue, but I'm not surprised that it's there for a good reason. Another solution would be to support `Select.correlate('*')` which would correlate to every table that's available in the superquery but not fail when they all end up correlated.

Do you have any other suggestions? Can I optimize the specific query with some combination of query options? Am I misusing `column_property()`?
