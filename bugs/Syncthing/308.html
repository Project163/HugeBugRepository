Title

Performance regression in memory use

Description
My Syncthing used to require around 100-150 MB, sometimes peaking up close to 200 MB. Current master branch idles at around 650 MB, peaks at 1.2 GB. Something odd has happened, either due to the 1.6 GC or due to something else we've done. Merits investigation.

[Image: image]

Step one would be to recompile with 1.5 and see if that makes a difference. If not, it's bisection time.

- Looks like index data kept alive during scanning and index reception...

- Would it make sense to have many more small buffers potentially capped at //max? Or some other annotation to use a separate buffer pool for one of the attributes?
