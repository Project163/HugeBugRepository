Title

Is CanLoad supposed to be called evertime the route is accessed?

Description
**I'm submitting a ...**  (check one with "x")
```
[x] bug report => search github for a similar issue or PR before submitting
[ ] feature request
[ ] support request => Please do not submit support request here, instead see [URL]
```

**Current behavior**

Everytime a route with a `CanLoad` guard is accessed, the guard is executed, even after it was already loaded once.

**Expected behavior**

I would expect for the route to be loaded once the `CanLoad` guard returns `true` and then, once loaded, the guard not be called again. I thought it was the role of `CanActivate` to do this kind of checks everytime…
Note that I make the assumption that "loaded" means loaded in memory, as in lazy-loading or stuffs like this, maybe I'm wrong :)

**What is the motivation / use case for changing the behavior?**

Currently I am making a call to the backend in the `CanLoad` guard, and I want to avoid that :)
