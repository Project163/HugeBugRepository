Title

3.x: missing Alias.field syntax for updateAll()

Description
In 2.x it was pretty common, to use the same syntax as for find() etc:

``` php
// Example from the cookbook 
// [URL]
$this->Baker->updateAll(
    array('Baker.approved' => true),
    array('Baker.created   $thisYear)
);
```

In 3.x this breaks, though.

``` php
$this->Users->updateAll(array('Users.password' => $newPwd), array(...));
```

The resulting query is (for Users with users table):

``` sql
 UPDATE users SET `Users`.`password` = '...' WHERE ...
```

Is this intended or accidental? I bet many will trip over this when upgrading 2.x applications, as I did.
Also, when joins are involved, this might be very crucial also in 3.x to alias properly.
Discussion
- You cannot do updateAll with joins in 3.x, so that is not a concern. I'd rather not just trim off aliases as queries could end up doing the wrong thing.
- Not trimming aliases sounds like the right solution to me
- People will have to rewrite their queries then. Sounds fine to me.
