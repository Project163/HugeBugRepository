Title

status module pipestatus segment and fill don't play well together on bash

Description
## Bug Report

#### Current Behavior
When a pipeline is executed with pipestatus segement of status enabled and the fill module is used, the fill character is only printed one time instead of enough times to fill.

#### Expected Behavior
fill works with status and pipestatus to fill the line

- My findings on linux/fish (prompt has $fill in front of $status):
- each pipe element reduces the available space for $fill with a **fixed 27 chars**
- base length if the one for when there is 1 or no pipe (`--pipestatus=""` or `--pipestatus="0"`)
- when there are 2 pipes (`--pipestatus="0 0"`) the fill decreases by 54 (2*27)
- when there are 3 pipes (`--pipestatus="0 0 0"`) the fill decreases by 81 (3*27)
- when there are 4 pipes (`--pipestatus="0 0 0 0"`) the fill decreases by 108 (4*27)
