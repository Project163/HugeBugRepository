Title

Incorrect schema validation for `externals`?

Description
**I'm submitting a bug report**

**Webpack version:**
`webpack@2.1.0-beta.27`

**Example:**
Taken from [Link: here]:

```
{
    output: { libraryTarget: "commonjs" },
    externals: [
        {
            a: false, // a is not external
... [Log Snipped] ...
    ]
}
```

**Current behavior:**
```
Invalid configuration object. Webpack has been initialised using a configuration object that does not match the API schema.
 - configuration.externals[0]['a'] should be one of these:
   string | object
 - configuration.externals[0]['b'] should be one of these:
   string | object
... [Log Snipped] ...
   string | object {  : string | object } | function | RegExp | [(recursive)]
   Specify dependencies that shouldn't be resolved by webpack, but should become dependencies of the resulting bundle. The kind of the dependency depends on `output.libraryTarget`.
```

**Expected/desired behavior:**
If this hasn't changed, this should not throw.
Discussion
- You are using the old documentation for the beta. Please see [URL] for the new documentation of the `externals`.
- Yeah, the example is from the old docs, but I'm not sure from reading the new docs, if this format is still valid or not. (I'd guess it worked for beta.25.)
- `false` and `true` are still supported, so it looks like it is an omission from the schema: [URL]

Unless it's intended for them to not be supported anymore. I might be wrong, but it looks like `false` just does nothing (delegates to the normal factory), while `true` uses the key name itself as the module name.
- They are missing in the schema. Do you want to send a PR?
