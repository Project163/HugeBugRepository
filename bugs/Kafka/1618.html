Title

Fix AdminClient request timeout handling bug resulting in continual BrokerNotAvailableExceptions

Description
The AdminClient does not properly clear calls from the callsInFlight structure.  Later, in an effort to clear the lingering call objects, it closes the connection they are associated with.  This disrupts new incoming calls, which then get  java.util.concurrent.ExecutionException: org.apache.kafka.common.errors.BrokerNotAvailableException .

       KAFKA-5658  . Fix AdminClient request timeout handling bug resulting in continual BrokerNotAvailableExceptions 

     The AdminClient does not properly clear calls from the callsInFlight structure. Later, in an effort to clear the lingering call objects, it closes the connection they are associated with. This disrupts new incoming calls, which then get BrokerNotAvailableException. 

     This patch fixes this bug by properly removing completed calls from the callsInFlight structure.  It also adds the Call#aborted flag, which ensures that we only abort a connection once-- even if there is a similar bug in the future which causes old Call objects to linger.  This patch also fixes a case where AdminClient#describeConfigs was making an extra RPC that had no useful effect.
