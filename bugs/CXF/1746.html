Title

CXF-rt-frontend-simple - incorrect "location" attribute with "wsdl:import" tag

Description
I'm using CXF 2.6.2 implementation with OpenEJB embedded 4.5.0 for functional testing in my project. 
When using interface for WebService and implementation of this interface but without "name" and "targetNamespace" attribute in @WebServic, OpenEJB server publish wsdl with "wsdl:import" that has incorrect "location" attribute. 

 CXF implementation with Jboss 7 behave correctly. 

 Example. 

 1. Interface 
  
 @WebService(name =  "WSTest " , targetNamespace =  "http: //test.com/wstest" )
  public   interface  WSTest {
  //...
 }
 
  

 2. Implementation 
  
 @Stateless
@WebService
 public   class  WSTestImpl  implements  WSTest {
  //...
 }
 
  

 3. Published wsdl by OpenEJB under  [URL] :  
  
 <wsdl:definitions xmlns:ns1= "http: //test.com/wstest"  xmlns:ns4= "[URL] xmlns:soap= "[URL] xmlns:wsdl= "[URL] xmlns:xsd= "[URL] name= "WSTestImplService"  targetNamespace= "[URL]
 <wsdl: import  location= "http: // :8983/test/WSTestImpl?wsdl?wsdl=TestWS.wsdl"  namespace= "[URL]
 
  

 The "?wsdl" keyword is repeated 2 times: 
<wsdl:import location="[URL] color="red">?wsdl =TestWS.wsdl" 

 OpenEJB or CXF doesn't set any properties of the endpoint WS (like PUBLISHED_ENDPOINT_URL) and this cause that WSDLGetUtils.updateDoc method take the whole address of wsdl ( [URL] and append to it another "?wsdl" keyword causing this bug. 

 I've made quick, not elegant, fix to WSDLGetUtils.java version 2.6.2 (but problem exists also with newest 2.7.3). Simply cutting the end of base location if it has "?wsdl" substring. 

  
              // FIX base adres can be like [URL]
              // remove wsdl parameter
              int  indexOfParam = base.indexOf( "?" );
             if  (indexOfParam != -1){
                base = base.substring(0, indexOfParam);
            }
 
  

 Probably more elegant solution is needed. 

 Attached source of the whole class WSDLGetUtils.java version 2.6.2
