Title

[docdb] Investigate yb-admin change_master_config REMOVE_SERVER + ADD_SERVER failure

Description
Jira Link: [Link: DB-1581]
Had a situation today where we had to fix a broken master raft quorum. Removing the broken master worked just fine, but adding it back afterwards failed, with some remote bootstrap messaging about not being able to find `tablet-meta` files for sys catalog (000....000). 

Checking the file system however, there was no data (as expected after REMOVE). We had to restart the master with an empty `--master_addresses=""` to force it to go in shell mode and then the `ADD_SERVER` worked just fine.

cc @hectorgcr @rahuldesirazu
Discussion
- We should be able to test this in a local `yb-ctl` setup, where we:
- bring up RF3 `yb-ctl --rf 3 create`
- remove a master with `./build/latest/bin/yb-admin -master_addresses  :7100, :7100, :7100 change_master_config REMOVE_SERVER   7100`
- add that master back with `./build/latest/bin/yb-admin -master_addresses  :7100, :7100, :7100 change_master_config ADD_SERVER   7100`

- The issue seems to be that the REMOVE SERVER deletes the underlying directories (tablet-meta, data) on that master node and when the ADD SERVER comes in, the directories are not recreated. I will look into how those directories were created in the restart case that Bogdan mentioned above and see how we could make it happen on the add.
- It looks like the history of changes to the code for going into shell mode is:

1/ Going into shell mode deleted only certain tablet data and group membership data initially.

2/ With this change - [URL] -
we overcorrected by deleting all dirs under yb-data, including logs, rocksdb and instance metadata

3/ [URL] then walked back some steps and preserved the google logs directory

I will work on a fix and a possible unit test to capture this issue. We need to retain some of the root level dirs so that the server can bootstrap once again and also preserve instance metadata so that the uuid that is used by the server in memory is preserved across restarts.
