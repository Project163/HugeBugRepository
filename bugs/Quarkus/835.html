Title

ClassNotFoundException on primitive arguments with quarkus-test-security

Description
**Describe the bug**
If I include quarkus-test-security, a ClassNotFoundException is raised if there are test methods with arguments of primitive data types (for instance on a `@ParametrizedTest`). No need to actually use the `@TestSecurity` annotation.

**Expected behavior**
No exception is raised.

**Actual behavior**
```
java.lang.reflect.InvocationTargetException
	...
	at io.quarkus.test.junit.QuarkusTestExtension.beforeEach(QuarkusTestExtension.java:363)
	at org.junit.jupiter.engine.descriptor.TestMethodTestDescriptor.lambda$invokeBeforeEachCallbacks$1(TestMethodTestDescriptor.java:161)
	at org.junit.jupiter.engine.descriptor.TestMethodTestDescriptor.lambda$invokeBeforeMethodsOrCallbacksUntilExceptionOccurs$5(TestMethodTestDescriptor.java:197)
... [Log Snipped] ...
	at io.quarkus.test.security.QuarkusSecurityTestExtension.lambda$beforeEach$0(QuarkusSecurityTestExtension.java:32)
	... 111 more
```

**To Reproduce**
Steps to reproduce the behavior:
1. Add quarkus-test-security dependency
    ```
     
       io.quarkus 
       quarkus-test-security 
       test 
     
    ```
2. Create a ParametrizedTest with arguments of primitive data types:
    ```
    @QuarkusTest
    class QuarkusSecurityBugTest {
    
        @ParameterizedTest
        @ValueSource(ints = 1)
        public void replayTest(int number) {
        }
    }
    ```

**Environment (please complete the following information):**
 - Quarkus version: 1.8.1.Final
