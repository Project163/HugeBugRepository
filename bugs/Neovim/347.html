Title

Tree-sitter highlighting no longer takes query range/specificity into account

Description
### Problem

Before [URL] queries where a more specific capture appeared earlier than a less specific capture later on used to have a higher precedence, but now that is no longer the case, which is a pretty breaking change really, since I've taken into account specificity of a capture plenty of times when writing queries (especially highlights) for nvim-treesitter. Highlights in certain circumstances will appear off now as a result. I understand this wasn't really documented/obvious, but it was a convenient feature to use.

### Steps to reproduce

config:

```
lua
vim.api.nvim_create_autocmd("FileType", {
	pattern = { "c" },
	callback = function(args)
		vim.treesitter.start()
... [Log Snipped] ...
vim.cmd("highlight! @variable.parameter gui=bold guifg=#ff0000 guibg=NONE")
vim.cmd("highlight! @operator gui=bold guifg=#00ff00 guibg=NONE")
```

```sh
nvim --clean -u minimal.lua test.c
```

write `void foo(int *bar)`

Notice that `*` is highlighted the same as `a` because the `@variable.parameter` capture captures the whole `pointer_declarator` node, but the earlier `@operator` capture for `*` ideally would have a higher priority than this

### Expected behavior

I'd expect `*` to be highlighted with `@operator`, not `@variable.parameter`, a possible solution could be to account for the size of the node when applying captures.

It'd also be fine to just not consider specificity anymore, that's totally fine but some queries need to be reworked then (e.g. some of C's highlights) and this should be documented to avoid further confusion
