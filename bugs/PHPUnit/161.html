Title

--migrate-configuration can only migrate phpunit.xml or phpunit.xml.dist

Description
| Q                   | A
| --------------------| ---------------
| PHPUnit version     | 9.3.9
| PHP version         | 7.4.10
| Installation Method | Composer

#### Summary

I use several different phpunit configuration files. Some use a code coverage setup that needs to be migrated to version 9.3. The migration command does NOT migrate the given file.

#### Current behavior

I would assume that `vendor\bin\phpunit -c phpunit_php-code-coverage.xml --migrate-configuration` creates a backup of the given configuration file `phpunit_php-code-coverage.xml` and migrates this file.
But the existing default file `phpunit.xml` will be backed up and migrated.

If there is no `phpunit.xml` the `phpunit.xml.dist` will be migrated.
If neither of the default files exists, an error is written to the console:
`No configuration file found in D:\phpunitmig`

#### How to reproduce

Have two or more configuration files, e.g. `phpunit.xml` and `phpunit_php-code-coverage.xml`.
Execute `vendor\bin\phpunit -c phpunit_php-code-coverage.xml --migrate-configuration`.

Outputs:
`Created backup:         D:\phpunitmig\phpunit.xml.bak`
`Migrated configuration: D:\phpunitmig\phpunit.xml`

#### Expected behavior

A migration of the given file and an output of:
`Created backup:         D:\phpunitmig\phpunit_php-code-coverage.xml.bak`
`Migrated configuration: D:\phpunitmig\phpunit_php-code-coverage.xml`
