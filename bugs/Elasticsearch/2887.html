Title

`EnterpriseSearchRestIT` failure

Description
### Context
With [URL] enterprise search adds the `behavioral_analytics-events-final_pipeline` lazily only when the data stream is created. This contradicts a validation that is about to be added within [URL] which does not allow to install an index template if it refers to a non-existing `default_pipeline` or `final_pipeline`.

As agreed with @jimczi, we will disable `EnterpriseSearchRestIT` for now, so that it doesn't block [URL] and figure out how to handle that later on.

One optional solution we discussed is changing [Link: `behavioral_analytics-events-final_pipeline`] to contain:
```
{
  "processors": [
    {
      "pipeline" : {
        "name": "lazily-added",
... [Log Snipped] ...
  ]
}
```
and install the `lazily-added` upon the proper trigger (data stream creation or other).

Note that while this will prevent dependency-related errors, it may still imply there is an undesirable race condition between the installation of the ingest pipeline and the referring index template.
