Title

Omitting a forward slash from http domain produces Bad HTTP request line

Description
#### Problem Description
Running a GET request for "[URL] will produce the following output:
` :43784: clientconnect
  :43784: request
  -> HTTP protocol error in client request: Bad HTTP request line: b'GET [URL] HTTP/1.1'
 :43784: clientdisconnect`

The request status, headers and body are as follows for the client:
`400
 
b' \n             \n                 400 Bad Request \n             \n             \n             400 Bad Request \n             HttpSyntaxException("Bad HTTP request line: b'GET [URL] HTTP/1.1'") \n             \n         `

Running a GET request for "[URL] will not produce this error. Nor will "[URL]
Curl runs the problematic URL fine as it appends the missing trailing slash before running the request which can be seen by printing flow.request.url.

#### Steps to reproduce the behavior:
1. Start mitmproxy using "mitmdump -s proxy_server.py --set block_global=false"
2. Run a GET request with mitm proxy as the request proxy for "[URL]

#### System Information
Mitmproxy: 5.3.0
Python:    3.7.9
OpenSSL:   OpenSSL 1.1.1h  22 Sep 2020
Platform:  Linux-4.14.203-156.332.amzn2.x86_64-x86_64-with-glibc2.2.5
