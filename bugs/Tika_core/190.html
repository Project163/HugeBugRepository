Title

PDF Text extraction without permission

Description
In   TIKA-1442   text extraction from files like 717226.pdf that don't have text extraction permission works. The permissions in PDF files are only enforced by the application (i.e. PDFBox), i.e. the text information isn't stored separately in encrypted form.  

 PDFBox ExtractText command line does throw an exception. 
So I wonder why TIKA is able to extract text. Either TIKA or the PDFBox call used bypasses the permission checking.
Discussion
- I would consider this a feature rather than a bug! 

 Generally though, if you give Tika a valid password, or the default password works, then Tika will extract the text. If you can't give the right password, then Tika won't extract the text. In this case, it seems that the default password works, so Tika uses it 

 You need to use a PasswordProvider -  [URL] - to supply non-standard passwords for protected / encrypted documents
- If I understand correctly, this is a separate issue from encryption.  In PDFBox's ExtractText, there are these lines of code: 

  
                AccessPermission ap = document.getCurrentAccessPermission();
                if( ! ap.canExtractContent() )
                {
                    throw new IOException( "You do not have permission to extract text" );
                }
 
  

 Again, if I understand correctly,  tilman 's point is that applications have a responsibility to respect the document's desired access irrespective of encryption.
