Title

Crash using forward-referencing type alias parameterised by dependent type variables

Description
**Crash Report & To Reproduce**

See [Link: mypy Playground].

This is a much less obscure example than #19185, and came about while trying to find workarounds for that snippet. I'm not sure if it's related.

```
python
from typing import Generic, TypeVar, TypeAlias

T1 = TypeVar("T1")
T2 = TypeVar("T2", default=T1)
... [Log Snipped] ...

class MyClass(Generic["T1", "T2"]): ...
```

**Traceback**

```
Deferral trace:
    __main__:6
    __main__:6
    __main__:6
    __main__:-1
... [Log Snipped] ...
main.py: error: INTERNAL ERROR: maximum semantic analysis iteration count reached
Found 1 error in 1 file (errors prevented further checking)
```

- Python version used: 3.9, 3.12
Discussion
- I think defaulting one type variable to another one is what causes the problem. If I try `default=int` everything works.
cc @JelleZijlstra @cdce8p who worked on defaults a while ago.
- Not completely. Yes, it's one of the few areas where the Mypy implementation of PEP 696 is still incomplete. However, basic examples should work. This looks like an error in the deferral logic. Just moving `Alias` after `MyClass` does resolve it.

```
py
from typing import Generic, TypeVar, TypeAlias

T1 = TypeVar("T1")
T2 = TypeVar("T2", default=T1)
... [Log Snipped] ...

Alias: TypeAlias = "MyClass[T1, T2]"
```
