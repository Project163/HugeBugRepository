Title

valid-jsdoc rule doesn't work on @param {String} options.X-My-Header custom header

Description
**What version of ESLint are you using?**
v2.2.0

**What parser (default, Babel-ESLint, etc.) are you using?**
default

**Please show your full configuration:**

Full config is at [URL] but here's the relevant bit.

``` js
        'valid-jsdoc': [1, {
          'requireReturn': false,
          'requireParamDescription': false,
          'requireReturnDescription': false
        }],
```

 I also tested and confirmed that I get the same issue with just `'valid-jsdoc': 1`.

**What did you do? Please include the actual source code causing the issue.**

This is one example of my (working) JSDoc that's failing ESLint:

`* @param {Number} [options.X-WDC-PL-OPT-OUT=0] set to 1 to opt-out of allowing Watson to use this request to improve it's services`

You can see it in context at [URL]

I also tried writing it as

`* @param {Number} [options['X-WDC-PL-OPT-OUT']=0] set to 1 to opt-out of allowing Watson to use this request to improve it's services`

That passes ESLint but causes JSDoc to explode. (I filed a bug about that at [URL] - but I still think the first behavior is an ESLint bug: a rule named "valid-jsdoc" really shouldn't enforce invalid JSDoc.)

**What did you expect to happen?**

I expect my working JSDoc to pass the valid-jsdoc rule, or for there to at least be some format that works for both ESLint and JSDoc

**What actually happened? Please include the actual, raw output from ESLint.**

That line gives me 

`26:1  warning  Missing JSDoc parameter type for 'Number'  valid-jsdoc`

Here's the full output:

```
~/watson-speech (master) $ npm run lint

... [Log Snipped] ...

✖ 10 problems (0 errors, 10 warnings)
```

Discussion
- ESLint uses Doctrine as a parser for jsdoc, so I think you might've filed an issue in the wrong repository (jsdoc). I think the rule is complaining because you are trying to describe properties of an object, where your function accepts only one object. I'm actually not sure how this is supposed to work. @gyandeeps any ideas about the right way to do jsdoc comments for object properties of an argument?
- I think he needs to define `options` using `@type` first and then simply say `{OptionsObject} [options]`.
