Title

globs miss hidden files

Description
### Description of the problem / feature request:
Globs of filegroups miss hidden (`.foo.bar`) files.
I see this since I have an attribute in a rule that accepts certain file types (using `allow_files`), and when that attribute depends on the filegroup I get `in deps attribute of printer rule //attributes:some_target: '//attributes:sources' does not produce any printer deps files (expected .scala)`.  (In the above example the glob is for `*.scala` and there is a `.foo.scala` file).
Important to add that when the glob is on the attribute then it evaluates correctly (sees `.foo.scala`). When the glob is on the filegroup but the file is not hidden (`foo.scala`) it also works and finally when the filegroup has an explicit file (`srcs = [".foo.scala"]`) and the rule depends on the filegroup it also works. 

The only case that doesn't work is attribute that depends on a filegroup that uses a glob that should evaluate to a single hidden file but does not.

Discussion
- we have a workaround for #7516 so we won't need this. Still probably worth fixing as is unclear and surprising.
- This looks like a bug in the glob function, and it's not related to filegroup.
Examples, after `touch .foo.scala`:

```
print(glob(["*.scala"]))
# no match

print(glob([".*.scala"]))
# matches .foo.scala

print(glob(["*"]))
# matches .foo.scala
```

The [Link: documentation] says that hidden files are matched by the `*` wildcard.
