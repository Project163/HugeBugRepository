Title

`argsort()`/`msort()`/`sort()` can use the 0D tensor of a `complex` type value against error message

Description
### 🐛 Describe the bug

[Link: sort()] cannot use the tensor of `complex` type values according to the error message as shown below:

```
python
import torch

my_tensor = torch.tensor([7.+5.j])

... [Log Snipped] ...

torch.sort(input=my_tensor) # Error
```


But `sort()` can use the 0D tensor of a `complex` type value against the error message as shown below:

```
python
import torch

my_tensor = torch.tensor(7.+5.j)

... [Log Snipped] ...
# values=tensor(7.+5.j),
# indices=tensor(0))
```

### Versions

```python
import torch

torch.__version__ # 2.3.0+cu121
```

cc @malfet
Discussion
- Thank you for reporting the issue. We will accept the patch that errors out or documentation update that mentions this behavior: sort is a trivial operation for tensors with less than 2 elements, so it can return self for any dtype.
But sorting does not make sense for complex tensors with more than one element as there are no unambiguous comparison operation for complex numbers
