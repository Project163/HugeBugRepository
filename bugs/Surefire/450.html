- Sorry, I have to push that one back one version, as I didn't have time to dig into your patch, yet.
- For the impatient, simply unpack the tests as workaround: 

   pom.xml   
  <plugin> 
	  <!-- due to [URL] -->  
	  <!-- we have to unpack the tests -->  
	 <groupId> org.apache.maven.plugins </groupId> 
	 <artifactId> maven-dependency-plugin </artifactId> 
	 <version> 2.10 </version> 
	 <executions> 
		 <execution> 
			 <id> unpack-tests </id> 
			 <goals> 
				 <goal> unpack-dependencies </goal> 
			 </goals> 
			 <configuration> 
				 <includeArtifactIds> tests-jar </includeArtifactIds> 
				 <includes> **/IT*.class,**/*IT.class,**/*ITCase.class </includes> 
				 <outputDirectory> ${project.build.testOutputDirectory} </outputDirectory> 
			 </configuration> 
		 </execution> 
	 </executions> 
 </plugin>

- I'm testing in 2.22.2, and this issue still exists.  

 I am using <dependenciesToScan> and failsafe. The tests run normally, then verify incorrect fails with "No tests to run!".  

 If I create directory target/test-classes then verify works as expected. Seems when dependenciesToScan was originally implemented, failsafe support was not completed. 

 I had a look at Tibor's commit, seems he did some refactoring and added an IT, but never fixed the reported issue. Strange. 

 So it seems the fix is still the same, make failsafe consistent with surefire so that dependenciesToCheck is considered when determining if tests are "found".
