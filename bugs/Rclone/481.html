Title

drive: Service account with wrong credentials doesn't return errror when listing root

Description
```
rclone size hbg: --drive-service-account-file=/opt/sa/1.json
Total objects: 0
Total size: 0 Bytes (0 Bytes)

```
```
rclone size hbg:
Total objects: 20001
Total size: 20.623 TBytes (22675191555624 Bytes)
```
```
rclone lsd hbg: --drive-service-account-file=/opt/sa/1.json
echo $?
0
```
```
rclone lsd hbg:
-1 2019-11-07 00:12:05        -1 hbg
echo $?
0
```
Discussion
- Just to clarify, this issue is about the exit code. I believe a non-zero exit code needs to be returned when the auth with the specific service account fails.
- Further to the above:

This can be extraordinarily dangerous. EDIT: Missing error code/odd behavior only occurs when you try to sync/copy/lsd/etc from the root of a remote e.g. `source:`. When copying from any subfolder you will get the correct error ( error message plus exit code = 3).
****************
`rclone size/lsd/etc` does not show an error. Which is inconvenient.

But if you run `rclone sync` with a service file that exists but does not have sharing/permission on the source Shared Drive then it deletes all the files in the destination.

`rclone sync source: destination:`  <= works perfectly.

`rclone sync source: destination: --drive-service-account-file=1.json` <= works perfectly when 1.json exists and source and destination both have shared files with the email for 1.json.

`rclone sync source: destination: --drive-service-account-file=2.json` <= DELETES all the files in destination when 2.json exists and has permissions in destination but does not have permissions in source.

Tested with current rclone win/linux/mac and observed the same behavior.
