Title

Ivy regression: TypeError: el.setAttribute is not a function

Description
# 🐞 bug report

### Is this a regression?
Yes, it worked well on Angular 8, and still works well on Angular 9 when disabling Ivy.

### Description
In a routed component, when applying a specific directive (`kendoGridSelectAllCheckbox`) on `ng-template`, an error is thrown: `TypeError: el.setAttribute is not a function`.
Again, this occurs only in a _routed_ component: if the same template is used directly in the AppComponent (or any other component that explicitly belongs to the root component tree), the issue is gone.

## 🔬 Minimal Reproduction
An extremely simplified reproduction is in [Link: this GitHub repository].
1. Clone that repository
2. Run `yarn`
3. Run `ng s` and navigate to `/list` route

### Actual behavior
The above error is thrown and nothing rendered.

### Expected behavior
No errors. Since the grid isn't fed with data, the string `No records available.` should be rendered.
You can see this expected behavior just by disabling Ivy.

I can confirm that this is a bug and the crux of it that if we've got a directive with a host binding writing to an attribute _and_ we put this directive on ` ` (and probably ` `!) it will throw.

In VE such errors would be silently ignored since since host bindings were part of the usage template so VE _knew_ if it makes sense at all to have a binding on ` ` / ` `.

We could "fix" it ivy by ignoring host bindings on  ` ` / ` ` but one could also argue that this is invalid directive usage - here `[kendoGridSelectAllCheckbox]` expects to be put on a regular element (since it wants to set attributes) but it is used on ` `. I don't know enough abut Kendo impl but the example given puts the mentioned directive on an ` ` element: [URL]
