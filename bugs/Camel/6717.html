Title

rest-dsl - Using code first and setting consumes/produces on rest configuration should be used for api-doc

Description
When using rest-dsl code-first and have api-doc exposed then the generate doc does not include produces/consumes on the API operations if its configured globally in the rest configuration.
Discussion
- This should be fixed in camel-openapi-java
- Sample yaml routes 
  
 
- restConfiguration:
    apiContextPath: api-doc
    bindingMode: json
-  rest :
    id:  rest -ff6d
    path: abc
    consumes: application/json
    produces: application/json
    get:
      - id: get-aec7
        path:  "{id}" 
        to: direct:dummy
- route:
    id: dummy
    from:
      id: from-64ca
      uri: direct
      parameters:
        name: dummy
      steps:
        - log:
            id: log-1875
            message: ${body}
 
  

 Gives rest api without consumes/produces 

  
 
{

{

 }

 "abc"

- This api is very basic and has no in / out type that would then use the consumes/produces. 
You could argue that the default response, should be "200" instead of "default {}" 

               "application/json": { 
                "schema":  
{
                  "type": "string"
                }
               }
- You need to set inputType and outputType for the api to have such details.
