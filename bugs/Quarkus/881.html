Title

Mongodb panache entities with enums persist vs query

Description
**Describe the bug**
When creating a document in mongo with an entity that has an Enum, the persit will use the enum.name() to persit the String. When querying the same field with the same enum, the value used in query is enum.toString(). This causes problems if we have an enum with values:
```
public enum Status {
        ALIVE("He's Alive!"),
        DEATH("Poor guy");
        
        private final String value;
... [Log Snipped] ...
        }
    }
```

The persisted field will be "ALIVE" but the query will try to use "He's Alive!"

**Expected behavior**
Both methods should behave the same way, either using the enum name() or enum toString()

There is a test RepositoryPersonTest that shows the behaviour
