Title

Null values for `v-text` directive not handled in SSR

Description
### Version
2.4.2

### Reproduction link
[Link]

[URL]
[URL]

### Steps to reproduce
Try to render `  ` where `x` is is `null` or `undefined`

### What is expected?
It may be gracefully handled just like `v-html` directive (see notes below) or client side version of `v-text`.

### What is actually happening?
Throwing an internal `TypeError`:

```bash
Cannot read property 'replace' of undefined
```

```js
function escape (s) {
  return s.replace(/[<>"&]/g, escapeChar)
}
```

---
Seems the simple fix would be defining a default value for `s` parameter in [Link: util.js] (or better do a `string` type check on value)

Related to nuxt/nuxt.js#1638

**Some Notes**

`v-html` behaviour also differs in SSR and client. SSR renders `v-html:  null ` while it changes into `  ` on client side. Seems ` ` is being optimized into `' ' + (_vm.foo)`. So we can change it into `(_vm.foo|| '')` to handle this inconsistency during SSR render.
