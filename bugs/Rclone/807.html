Title

rclone serve s3: invalid error response when using wrong password

Description
**rclone serve s3** can't handle invalid credentials very well:

1. Open a terminal and run `rclone server s3` (in my case, I use a container):
    ```bash
    $ podman run --rm --env=RCLONE_ADDR=:8080 --env=RCLONE_AUTH_KEY=admin,admin --publish=8080:8080 --volume=/tmp/data:/data docker.io/rclone/rclone:1.66 serve s3 /data
    ```
2. Open a 2nd terminal and run a simple request with rclone as a client (the password is wrong on purpose):
    ```bash
    $ RCLONE_S3_ENDPOINT=[URL] RCLONE_S3_ACCESS_KEY_ID=admin RCLONE_S3_SECRET_ACCESS_KEY=admin2 ./rclone lsf -vv s3:
    ```
    `/home/tony/.config/rclone/rclone.conf`:
    ```
    [s3]
    type = s3
    provider = Other
    env_auth = true
    ```
4. Result: I can see many HTTP 403 responses with Wireshark and rclone seems to ignore all of them and doesn't do much for roughly a minute until it finally exists with an error:
    ```
bash
	2024/04/09 22:07:58 DEBUG : Setting default for s3-access-key-id="admin" from environment variable RCLONE_S3_ACCESS_KEY_ID
	2024/04/09 22:07:58 DEBUG : Setting default for s3-secret-access-key="admin2" from environment variable RCLONE_S3_SECRET_ACCESS_KEY
	2024/04/09 22:07:58 DEBUG : Setting default for s3-endpoint="[URL] from environment variable RCLONE_S3_ENDPOINT
	2024/04/09 22:07:58 DEBUG : rclone: Version "v1.66.0" starting with parameters ["./rclone" "lsf" "-vv" "s3:"]
... [Log Snipped] ...

	caused by: expected element type   but have
```
