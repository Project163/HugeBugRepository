Title

--no-cache returns a different result than cached

Description
This sounds exactly like #1051.

Unfortunately, I can't reproduce it easily in simple codebases.

We are getting 4 errors on our code base if we use `--no-cache` and none if we omit the option.

If it helps the offending issues were:

* TraitMethodSignatureMismatch
* InvalidDocblock x 3

Version: Psalm 3.9.3@
Discussion
- What sort of errors were the invalid docblocks?
- All of them were `Badly-formatted @param in docblock for  `

Exs:

```
php
/**
 * Function: something 
 * Purpose:  Blah blah blah
 *           Blah Blah blah.
... [Log Snipped] ...
 * @return string
 */
```

```
php
/**
 * Blah Blah Blah. Blah
 * example 1 => 1k, 2333 => 2.3k, 999999 => 999.9k.
 *
... [Log Snipped] ...
 * @return string
 */
```

```
php
/**
 * Blah blah blah
 *
 * Type:     modifier 
... [Log Snipped] ...
 * @return string
 */
```

It looks like part of the problem is that we are suppressing MissingParamType, thus the docblocks are actually invalid according to [URL]

For reference, we do have theses InvalidDocblock's baseline.

It's unclear why these methods only showup when `--no-cache` is provided while setting the baseline.

* Psalm 3.9.3
* MissingParamType in psalm.xml as info
* All InvalidDocblock's in baseline

Steps to reproduce:

* Set `Tests/psalm-load.php`
```php
if (!defined('CODE_DIR')) {
   $codeDir = self::getCodeDir();
   define('CODE_DIR', $codeDir);
}
```

* Set the conf to:

```
xml
 
 
 
```
* Notice: `psalm-load.php` is our autoloader and under the ignored `Tests` directory
* Run `psalm` twice (to ensure reading from cache)
* Notice psalm complains like:

```php
ERROR: UndefinedConstant - SomeFile.php:65:14 - Const CODE_DIR is not defined (see [URL]
      return \CODE_DIR . '/tmp';
```
* Running `psalm --no-cache` the psalm complaint disappears
- @muglug thanks! I tested this out. This fixed the original issue: the UndefinedConstant / InvalidDocblocks are no longer an issue.

Note: `psalm --no-cache` is returning 457 issues vs while `psalm` is returning 418 issues.

I will leave it for now since I was testing an unreleased version. If the issue persists I'll try and get you more info next release.
