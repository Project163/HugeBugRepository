Title

"*" does not add to jumplist if cursor line does not change

Description
- `nvim --version`:      NVIM v0.4.0-529-gfb555c689 Build type: RelWithDebInfo
 - Vim (version: 8.1-1119) behaves differently? Yes.
 - Operating system:     Ubuntu 16.04.6 LTS
 - Terminal emulator:    rxvt-unicode v9.22
 - Terminal multiplexer: tmux 2.9
 - `$TERM`:              tmux-256color
 - Shell:                zsh 5.7.1-dev-0 (x86_64-pc-linux-gnu)

### Steps to reproduce using `nvim -u NORC`

Consider this shell command:

    $ printf 'hello world' | nvim -Nu NONE +'norm! fr' -

### Actual behaviour

If I press `*` while the cursor is on the `r` of `hello world`, the cursor jumps to the start of the word `world`.

Now, if I press `C-o` to jump back to where I was (the `r` in `world`), it raises the error `E37`:

    E37: No write since last change (add ! to override)

[Image: gif]

Neovim tries to jump to a location in another file, and it didn't add the original position to the jumplist.

Had there been two occurrences of the word `world`:

    $ printf 'hello world\nhello world' | nvim -Nu NONE +'norm! fr' -

Then the position would have been added.

In Vim, it doesn't matter whether the current word is present once or multiple times in the buffer. The current position is always added to the jumplist before a `*` motion.

[Image: gif]

I rely on this behavior in a plugin similar to [Link: vim-slash] to restore the position of the cursor after a `*` search (I just want the search register to be populated and all the occurrences to be highlighted).
In Vim it works consistently; in Neovim, it works only when the word under the cursor is present more than once in the current buffer.

### Expected behaviour

Before `*` jumps, I expected the current position to be added to the jumplist, like in Vim, regardless of the number of occurrences of the word under the cursor.
