Title

[zlib:x64-linux, ffmpeg[zlib]:x64-linux] zlib debug library not found by FindZLIB

Description
**Is your feature request related to a problem? Please describe.**

On vcpkg under x64-linux, cmake will always set ``ZLIB_LIBRARY_DEBUG`` to ``ZLIB_LIBRARY_DEBUG-NOTFOUND``. When requesting a ``CMAKE_BUILD_TYPE=DEBUG``, instead, ``ZLIB_LIBRARY_RELEASE`` is set to the debug library. This is a problem for some ports that consume zlib especially if they rely on ZLIB_LIBRARY_DEBUG and ZLIB_LIBRARY_RELEASE to point to the correct locations, such as for instance the ffmpeg port; see [Link: here].

More precisely, due to this bug, ffmpeg[zlib] compiles, but projects in debug mode cannot be linked to it. Here's a full test script:

```
$ find /home/***/vcpkg/installed/x64-linux/ -name 'libz*.a'
/home/***/vcpkg/installed/x64-linux/lib/libz.a
/home/***/vcpkg/installed/x64-linux/debug/lib/libz.a
$ cat CMakeLists.txt
cmake_minimum_required(VERSION 3.12)
... [Log Snipped] ...
make[1]: Leaving directory '/home/***/zlib_test'
make: *** [Makefile:84: all] Error 2
```

**Proposed solution**

FindZLIB could grow a vcpkg wrapper to ensure somehow that the correct variables are set. Currently it expects the debug library to have a "d" suffix. This works fine for windows (where the libraries are called ``zlib.lib`` & ``zlibd.lib``), but not for linux. See [URL]

Another solution is to name the debug library on linux ``libzd.a`` on vcpkg so upstream FindZLIB finds it properly (as it looks for "zd"). This risks breaking other ports, and it breaks with the practice of not renaming upstream libraries (as per the developer guidelines).

A third (ugly, IMO) solution is to leave zlib behaviour on linux as it is, but instead patch consumers (such as FFmpeg) not to use ZLIB_LIBRARY_DEBUG on linux, and instead to use ZLIB_LIBRARY_RELEASE under all circumstances for linux.

There might be other solutions too, but either way, it would be nice to have this fixed.
Discussion
- The solution always is to use the target or _LIBRARIES variables set via SelectLibraryConfigurations. Everything else is probably always wrong.
- Thanks @Neumann-A for sharing your insight. I can confirm that using ZLIB_LIBRARIES works indeed, and fixes the problem. I'll submit a patch for ffmpeg.
