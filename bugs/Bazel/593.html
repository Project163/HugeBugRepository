Title

Deadlock in BuildEventServiceTransport.java

Description
### Description of the problem / feature request:

Bazel can deadlock while writing to the BES. The issue is that sendBuildEvent() is reentrant, which in turn can cause multiple lock orderings. One such ordering pair is PrintStream causing a BuildEvent to be sent, and a BuildEvent being sent causing a file digest to be computed, causing a PrintStream to be called if it is slow.

- I think we have enough information to know what's happening. 

T1 | T2 
--- | ---
sends a build event (lock1) | Writes stderr (lock2) ...
Writes a "Slow Read:" warning to stderr (lock2) | ... and realizes that the stderr buffer is full, thus flushes and sends a build event (lock1).

We can fix this particular case, but I need some more thinking on how to ensure that some other case doesn't trigger a deadlock too.
- So in 59f9159 I have removed the lock on `BuildEventServiceTransport.sendBuildEvent`, because it wasn't necessary anymore. That hasn't fix the bug though, because the bug had already been fixed as a side effect of ce9aafc as we moved the serialization of the build event protos from the `sendBuildEvent` method to the uploader thread.
