Title

pool_size=0 means empty pool instead of unlimited pool as documentation says

Description
### Describe the bug

According to [URL] setting `pool_size` size 0 means that the pool is unlimited. I expected that `max_overflow` is ignored in such a case and the pool size will increase when necessary and never decrease. Hence, it will always be equal to the peak demand for connections.

However, the following code hangs on the query which suggests `pool_size=0` means empty pool.

### To Reproduce

```
python
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker
from sqlalchemy.pool import QueuePool

... [Log Snipped] ...

session.execute("SELECT 1")
```


### Error

The code hangs.

### Versions

- OS: Ubuntu
- Python: 3.10
- SQLAlchemy: 1.4.41
- Database: PostgreSQL 13
- DBAPI: psycopg2


### Additional context

As connections are created lazily, unlimited pool size can be emulated by setting `pool_size` to a huge number. Maybe it's just a documentation issue.
