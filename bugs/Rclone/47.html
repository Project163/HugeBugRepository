Title

Copying large >10GB file from ACD fails

Description
Hello,

I have successfully synced content from Amazon Cloud Drive to Google Drive. Except for one large file which failed to copy. The file is ~11GB in size. Google Drive has sufficient storage available. This is what I'm getting:

```
rclone copy -v acd:/Videos/Raw/footage.m2ts drive:/Videos/Raw/              
.
2015/11/08 19:52:25 footage.m2ts: Failed to open: HTTP code 400: "400 Bad Request", reponse body:  
  InvalidArgument  Only one auth mechanism allowed; only the X-Amz-Algorithm query parameter, Signature query string parameter or the Authorization header should be specified  Authorization 
...
 
2015/11/08 19:52:25 Attempt 1/3 failed with 1 errors
```

Before I successfully syncronized/copied around 300 GB of data without problem. It only failed on this file, which is also the only file that large (others are < 4GB).

I then tried copying the file from ACD to local instead, but got the same error. Downloading it via Amazon Cloud Drive Web gui works without problem.

rclone v1.24 (linux 64bit) used.

Cheers
Alex
Discussion
- The error message is an S3 error message.  Presumably ACD is based on S3, but I don't think it should be exposing S3 error messages, which makes me wonder whether this is an ACD problem.

I'm pretty sure the web gui uses a different API to the one used by rclone since it can, for example, delete files permanently which the published API can't.

Tomorrow I'll try a 10 GB file myself and see what happens.

Any thoughts @klauspost  ?
