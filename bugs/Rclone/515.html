Title

azureblob mounts container to subfolder instead of root folder with SAS URL [regression]

Description
#### What is the problem you are having with rclone?
The Microsoft Azure Blob Storage backend now mounts containers to subfolders of a local mount folder instead of directly in the root folder. This is a regression from rclone v1.48.

*rclone v1.48 behavior:*
```
$ rclone mount mycontainer: myfolder/ &
$ ls myfolder
myfile1  myfile2 
```

*rclone v1.51 behavior:*
```
$ rclone mount mycontainer: myfolder/ &
$ ls myfolder
mycontainer
$ ls myfolder/mycontainer
myfile1  myfile2
```

*cat rclone.conf:*
```
[mycontainer]
type = azureblob
sas_url = [URL]
```

#### What is your rclone version (output from `rclone version`)
```
rclone v1.51.0
- os/arch: linux/amd64
- go version: go1.13.7
```

#### Which OS you are using and how many bits (eg Windows 7, 64 bit)
Ubuntu 16.04 64 bit


####  Which cloud storage system are you using? (eg Google Drive)
Microsoft Azure Blob Storage


#### The command you were trying to run (eg `rclone copy /tmp remote:tmp`)
`rclone mount my-container: myfolder/`


#### A log from the command with the `-vv` flag (eg output from `rclone -vv copy /tmp remote:tmp`)

N/A

The new behavior is also the same as the b2 backend with the equivalently limited container.

So I think I'd like to remove this feature, especially since this feature was added in v1.49.1 and it hasn't been reported until now 7 months later.
