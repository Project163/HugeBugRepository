Title

XLIFF 2.0 file created by the extract tool misses equiv="ICU"

Description
**I'm submitting a ...**  
```
[x] bug report => search github for a similar issue or PR before submitting
[ ] feature request
[ ] support request => Please do not submit support request here, instead see [URL]
```

**Current behavior**

I have following element in a template

` Sample: {ski, plural, one {I have {{ski}} ski.} other {I have {{ski}} skis.} } `

Then I run the extract tool to create XLIFF 2.0 file I will get

```
     ">
       
         D:/Localization/Angular/Bugs/Icu/src/app/app.component.ts:2 
       
       
         Sample:   
       
     
```
Note! ph element does not have equiv="ICU" attribute.

I translate the XLIFF

` Esimerkki   `

Compile it I will get error that equiv is misisng.

If I manually add equiv="ICU" like this

` Esimerkki   `

Then it works. 

**Expected behavior**

The original source element extracted  b the extractor should contain the equiv="ICU" attribute. This is how it works with XBM and XLIFF 1.2.

**Minimal reproduction of the problem with instructions**

Create template as above, extract XLIFF 2.0, localize it by keeping the XML structure in target element the same as in source element.

**What is the motivation / use case for changing the behavior?**

Make localization easier.
