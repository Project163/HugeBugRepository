## Problem statement

I just got bitten by this. If you have a field name that ends in something like "_windows", then the file produced will end with "_windows.go", and will only be included in the build if you are on that OS. Likewise for other fields that happen to match a possible GOARCH or GOOS value (see [URL]

I could imagine several ways to handle this:
- Stop using underscores in file names, since it's not recommended anyway
- Warn or err when a path component would overlap with GOARCH/GOOS
- Rather than warn or err, use some replacement
Discussion
- How about adding the windows word as a custom initialism (with CLI option)?
It should render as _WINDOWS and this is likely to pass the build. Just a thought, I haven't tested this.
- we can add this to the mangle name function. We rewrite numbers and operators already, we can make sure we don't override os names
