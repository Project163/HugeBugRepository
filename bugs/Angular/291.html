Title

enableDebugTools clobbers ng and removes ng.probe

Description
**I'm submitting a ...**  (check one with "x")

```
[x] bug report => search github for a similar issue or PR before submitting
[ ] feature request
[ ] support request => Please do not submit support request here, instead see [URL]
```

**Current behavior** 
If I enable Angular's built-in debug tools `enableDebugTools`, like this:

```
javascript
import { enableProdMode, ComponentRef } from '@angular/core';
import { enableDebugTools } from '@angular/platform-browser';
import { platformBrowserDynamic } from '@angular/platform-browser-dynamic';
import { AppModule } from './app.module';
... [Log Snipped] ...
    enableDebugTools(ref);
});
```

Then `ng.probe` is no longer available for debugging because `ng` is overwritten with the `AngularTools` class. This results in an error if I try to use Augury, see: [URL]

**Expected behavior**
I would expect `enableDebugTools` to _extend_ `ng` with additional methods, e.g. `ng.profiler`, rather than clobbering it. This would allow me to continue to use `ng.probe` and extensions like Augury when Angular's debug tools are enabled.

[URL]

**What is the motivation / use case for changing the behavior?**
Allows developers to continue using Augury when `enableDebugTools` is in use.
