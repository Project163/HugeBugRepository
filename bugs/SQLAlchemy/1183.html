Title

`FlushError` after unexpected cache hit after `bulk_save_objects`

Description
**Describe the bug**
When I use `bulk_save_objects` it caches the `INSERT` query without `RETURNING`.
If after that I use `session.add` and` session.flush` it fetches that cache request but expects a request with `RETURNING` so we get` FlushError`.


**To Reproduce**

```
py
from sqlalchemy.ext.declarative import declarative_base
from sqlalchemy import create_engine
from sqlalchemy import Column, Integer, String
from sqlalchemy.orm import Session
... [Log Snipped] ...
# 2021-07-21 11:30:13,351 INFO sqlalchemy.engine.Engine [cached since 0.009323s ago] ({'name': 'C'}, {'name': 'D'})
# 2021-07-21 11:30:13,354 INFO sqlalchemy.engine.Engine ROLLBACK
```

**Error**
```
Traceback (most recent call last):
  File ".../bug.py", line 26, in  
    session.flush()
  File ".../venv/lib/python3.9/site-packages/sqlalchemy/orm/session.py", line 3298, in flush
    self._flush(objects)
... [Log Snipped] ...
    raise exc.FlushError(
sqlalchemy.orm.exc.FlushError: Instance  > has a NULL identity key.  If this is an auto-generated value, check that the database table allows generation of new primary key values, and that the mapped Column object is configured to expect these generated values.  Ensure also that this flush() is not occurring at an inappropriate time, such as within a load() event.
```

**Versions.**
 - OS: Ubuntu, MacOS
 - Python: 3.9
 - SQLAlchemy: 1.4.21
 - Database: PostgreSQL
 - DBAPI: psycopg2
