Title

split property definitions aren't carrying final modifier to getters

Description
Split property definitions were created as an alternative to the full long-hand way to express a property. They allow modifiers (final and synchronized), and annotations to be applied to either the backing field or the accessors. 
  
  
 
 import  groovy.transform.PackageScope

 class  MyTask {
    @Deprecated private final  Integer  f1 = 0
    final  Integer  f1

    protected synchronized  Integer  f2 = 0
    synchronized  Integer  f2

    public  Integer  f3 = 0
    @Deprecated  Integer  f3
}

println MyTask
 
  
 Currently, everything is carried across except for the final on the  f1  accessor methods.
Discussion
- I don't follow why this situation or the 11633 indicates that the access method(s) should be final.  Synchronized makes sense.  But what does the method being unable to be overridden have to do with read-only?
- Read-only and being able to be overridden are definitely separate things so split definitions supports that. You can declare read-only by putting "final" on the field. You can put "final" on the property to indicate you want non-overridden methods. It's only the split definition case that I think needs changing. And I think split definition usage is rare, so low priority.
