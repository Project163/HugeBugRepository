Title

Marking dictionary objects as required is ignored in generated code

Description
## Problem statement

If a property is defined as a pure map (without any other fixed fields), making it "required" does not work in generated code.

## Swagger specification

Consider this object:

```
"properties": {
    "currencies": {
      "type": "object",
      "additionalProperties": {
        "$ref": "#/definitions/amount"
... [Log Snipped] ...
},
"required": ["currency"]
```

This produces (correctly) a go representation of `map[string]Currency`. It seems however that the `required` directive is ignored, requests that do not include `currencies` are accepted and defaulted to an empty map.

I want them to be rejected as per the json-spec.
Discussion
- You have set the property `minProperties` to 1 or more. The required just checks if something is null or not
- @Marclev78 You have `"currencies"` in one place and `"currency"` in the other.  Is that intentional?
