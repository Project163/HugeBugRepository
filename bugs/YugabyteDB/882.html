Title

[YSQL] Reads in SERIALIZABLE isolation are not following Wait-on-Conflict concurrency control even when enable_wait_queues=true

Description
Jira Link: [Link: DB-5218]
### Description

```
CREATE TABLE test (k INT PRIMARY KEY, v INT);
INSERT INTO test VALUES (1, 1);
```

Start 2 transactions T1, T2 in SERIALIZABLE isolation level.
```
T1: UPDATE test SET v=2 WHERE k=1;
T2: SELECT * FROM test WHERE k=1;
```

After the SELECT in T2, either T1 or T2 will be aborted because the SELECT is following Fail-on-Conflict concurrency control policy which results in "failure" of either transaction based on the randomly assigned priority. But the expectation is that T2 should instead wait for T1 to commit and then make progress.
