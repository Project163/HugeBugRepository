Title

VC++ compiler failed to compile UTF-8 files without BOM

Description
I tried to compile qt5.8 and failed, in `build-x64-windows-rel-out.log`, I found this error:


You can manually check this file, and there's a Unicode character in the 491th line. I googled a lot, and it's said that `cl.exe` would interpret source files using the same encoding as system, unless the file has BOM. Windows simplified-Chinese version use GBK encoding, so `cl.exe` misinterpreted that Unicode character as something containing newline.

According to [Link: MSDN], you can specify command line option `-source-charset:utf-8` to force `cl.exe` to understand UTF-8.

Firstly, I tried to modified `portfile.cmake` to add option `QMAKE_CXXFLAGS+="-source-charset:utf-8"` when configuring qt. But that brought another problem: if I do so, the generated Makefile would miss `-I D:\Dev\vcpkg\installed\x64-windows\include`, so source files that include other packages's staff like `zlib.h` would fail to compile. It's weird, I can't figure out the reason.

Then, I turned to modify `vcpkg\buildtrees\qt5\src\qt-5.8.0\qtbase\mkspecs\common\msvc-desktop.conf` to add option `QMAKE_CFLAGS+="-source-charset:utf-8"`. It did solve this problem, though it's kind of a dirty trick. Can anyone find a neater solution?

PS: I believe that #1037 and #1024 are actually the same as this issue, since the openners are both Chinese (you can check their profiles).
