Discussion
- Pinging @elastic/es-analytical-engine (Team:Analytics)
- I managed to reproduce this problem, it's just due to extra parentheses in the query, eg.

```
row a = 1 | where a < 2 )
```

We should return a ParsingException and a better error message, but the query is invalid anyway
- Additionally, `FROM test | eval x = [1, 2, 3]]`

Since the parser/lexer `errorListener` does not get to see all unchecked exceptions. The parser should probably catch more than just `StackOverflowError`, to cover such cases.
- Invalid stack popping is not properly handled by ANTLR, despite the issue being reported years ago [URL] . There is also a [Link: PR for it] but it didn't get merged suggesting the problem is a bit more complicated.
Catching the exception seems the best way forward atm.
