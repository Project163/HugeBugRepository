Float multiplication of numpy.ndarray in lambda is incorrectly analysed

Discussion
- The root of the problem is that mypy incorrectly infers the type of multiplying `Point` by a float. Here's a shorter example:

```py
from typing import Any

C: Any
class D(C):
    pass

reveal_type(0.5 * D())   # float, but should be Any
```

As a workaround, you can try installing stubs for numpy (https://github.com/numpy/numpy-stubs).
- It looks like #8019 didn't actually fix this issue, at least Jukka's simple example above still fails. It accidentally passes in tests (see `testOpWithInheritedFromAny`) because in builtins fixtures `float` doesn't have `__add__()`. I am going to mark it `xfail` in [URL] (since I need that `__add__()` that actually present in real builtins stubs, for my tests).
