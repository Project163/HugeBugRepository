Title

2.0 env es6: imperfect detection of calling super

Description
Correct callings of `super()` in a constructor are not correctly detected.  
Affects rules:
- `constructor-super`
- `no-this-before-super``

**What version are you using?**

```
$ eslint --version
v2.0.0
```

**What did you do?**

I created a class, extending from another class. Within the constructor, called `super()` and accessed properties via `this`. So far no problems.  
When creating new blocks (for example, using a `for ... of` loop) within the constructor, the previously correctly detected call of `super()` is somehow rendered obsolete, triggering the rules mentioned above.

`test.js`:

```
JavaScript
/* eslint-env es6 */
/* eslint constructor-super: 2 */
/* eslint no-this-before-super: 2 */
class A {
... [Log Snipped] ...
  }
}
```

**What happened?**

Running `eslint test.js` outputs the following:

```
test.js
  19:3  error  Lacked a call of 'super()' in some code paths  constructor-super
  26:7  error  'this' is not allowed before 'super()'         no-this-before-super
  28:5  error  'this' is not allowed before 'super()'         no-this-before-super

✖ 3 problems (3 errors, 0 warnings)
```

**What did you expect to happen?**

The calls of `super()` in class B's and class C's constructors should be detected correctly and the three errors concerning class C's constructor method should not have been yielded.

**Further observations**

When removing the access to `this` within the `for ... of` loop's block and after it, the false triggering of the `no-this-before-super` error yields vanish, the `constructor-super` rule still yields an error.
