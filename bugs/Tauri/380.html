Title

[bug] Updater fails when using an NSIS installer requiring administrator access

Description
### Describe the bug

When I try to have my Tauri application update itself to a new version, it fails when the new version is bundled with an NSIS installer that has installMode `both`. 

What happens is that the update is started, it waits a bit (I'm imagining it's downloading the installer), and eventually quits the old version without launching the new one. No installer for the update shows. When the application is started again, it's still the old version and no update was installed.

When I run the old version of my application with `tauri dev` and I attempt to update from there, I get an error:

```
thread 'tokio-runtime-worker' panicked at 'installer failed to start: Os { code: 740, kind: Uncategorized, message: "The requested operation requires elevation." }', C:\Users\Raph.cargo\git\checkouts\tauri- \076e1a8\core\tauri\src\updater\core.rs:722:10
```

The issue gets resolved when I run my application as administrator, before trying to update.

### Reproduction

1. Set up a Tauri app and update your tauri.conf.json:
  a. Enable the updater functionality
  b. Set the version to 1.0.0
  c. Set the install mode for the NSIS installer to `both` or `perMachine` (Both require elevation)
2. Build a first version 
3. Build a second version with a higher version number (1.1.0)
4. Make the second version available as an update
5. Run the first version and attempt to update to the second version.

Notice how step 5 fails unless you run the first version as administrator.

### Expected behavior

When an outdated version of the application is run without elevation, I would expect the user to be given a UAC prompt when the NSIS installer for the update is run, should it require elevation.
