Title

Installing CakePHP pear package via composer and including `vendor/autoload.php` causes test files to be loaded

Description
It would appear that when installing cakephp's pear package via composer, a [Link: class map] is generated which includes all of the files from CakePHP's test directory.

While [Link: it's possible to mitigate composer wanting to be the primary autoloader] so that app files that exist are loaded in preference to files in the class map - classes that are ordinarily optional become mandatory to create if the autoloader is included.
### Steps to reproduce:

```
composer --keep-vcs -sdev create-project friendsofcake/app-template ProjectName
cd ProjectName
echo '  app/Model/Foo.php
echo '$foo = ClassRegistry::init("Foo");' >> app/Config/bootstrap.php
echo '$foo->User;' >> app/Config/bootstrap.php
app/Console/cake
```
### Result:

```
www-data @ dev [ /tmp ]
-> composer --keep-vcs -sdev create-project friendsofcake/app-template ProjectName
Installing friendsofcake/app-template (dev-master  )
  - Installing friendsofcake/app-template (dev-master master)
    Cloning master
... [Log Snipped] ...
www-data @ dev [ /tmp/ProjectName ] (master *%=)
->
```

The request for the User class, which ordinarily is considered optional, results in attempting to load the file `vendor/pear-pear.cakephp.org/CakePHP/Cake/Test/Case/Model/models.php` as the class `User` [Link: appears in composer's classmap].
Discussion
- I guess one solution would be to exclude the core test suite from the pear packages?
- Composer has [Link: an option to influence the classmap] though I don't know if it's possible to influence that with the pear install (?).

Unless there's a simple way to have the test files and exclude them - I'm :+1: on removing the Test files from the pear package (we'd still need the test _suite_ to run app/plugin tests).
