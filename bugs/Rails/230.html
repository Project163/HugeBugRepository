Title

Querying for associated ActiveRecord objects inside `find_by` condition fails when the association uses a non-standard foreign key in Rails 6.1

Description
This issue is closely related to #40809, and I am borrowing heavily from that issue here

### Steps to reproduce 

`has_one` and `belongs_to` association using a foreign/primary key other than the default for the model no longer works inside of a `find_by` query.
 
Given these two models:
 
```
class Post < ActiveRecord::Base
  has_many :comments, foreign_key: "post_slug", primary_key: "slug"
end
 
class Comment < ActiveRecord::Base
  belongs_to :post, foreign_key: "post_slug", primary_key: "slug"
end
```
 
### Expected behavior
 
In Rails 6.0, given the two models configured above, `Comment.find_by(post: post)` acted as the equivalent of `Comment.find_by(post_slug: post.slug)`.
 ### Actual behavior
 
In Rails 6.1, given the same models configured above, `Comment.find_by(post: post)` seems to act as the equivalent of `Comment.find_by(post_slug: post.id)`.

### System configuration
 
**Rails version**: 6.1.1 (edge)
 
**Ruby version**: 2.7.1
