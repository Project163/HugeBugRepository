Title

mapjoin: memory leak for same key with very large number of values

Description

    
Discussion

    
- The mem leak turns out to be caused by the MRU cache manager in JDBM. Currently Hive caches 25000 rows in JDBM through MapJoin by default. I changed it to 1 and it seems works fine. I'll looking into MRU.
- This patch added solves the Out-of-memory exception thrown by MapJoinOperator. The changes include: 
1) make the persistent hashtable HTree non-transactional. (this is not the cause of out-of-memory error, but it may improve performance) 
2) commit the RecordManager for every 100 record insertion. (this is the main cause of OOM issue).
