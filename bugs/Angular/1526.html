- Fixed stackblitz: [URL]

This is a confirmed bug. What is going on here is that the styling algorithm doesn't seem to account for non-string and empty string values. Those unchecked values are propagated to the other parts of the framework and throw exceptions in other parts (DOM etc.).

While this might look like a corner cases, I can understand how people might want to use ternary expressions to have conditional classes (and evaluate to an empty string / null / undefined if a given class  should not be applied).

We should fix it, although I'm not sure what is the best approach here: throw for "invalid" values or just ignore them.
- @undsoft  I think that any null or falsy value shouldn't affect the other class declaration. We can still show warning like "class declaration shouldn't contain any null or falsy values".. After showing this warning we should ignore falsy values and continue to apply other class declaration
