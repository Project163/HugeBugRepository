Title

Regression - Gizmos panicking given bad output from `GlobalTransform::to_scale_rotation_translation`

Description
## Bevy version

v0.13.0

## What you did

Draw some big spheres.

## What went wrong

The application now crashes when moving the camera near a large sphere. Previously, the gizmo would simply fail to render. Fixing the issue, the gizmo still fails to render, so the crash is not actually protecting against some avoidable behavior.

## Additional information

I'm hitting a 
```
thread 'main' panicked at bevy_math-0.13.0/src/primitives/dim3.rs:40:9:
assertion failed: value.is_normalized()
```

When trying to update `big_space` to 0.13. This happens when drawing the very large sphere gizmos. It turns out the issue is the rotation produced by `GlobalTransform::to_scale_rotation_translation()` is invalid, and is then panicking when the gizmo  creates an unchecked direction.

Minimal repro:

```
rs
fn main() {
    App::new()
        .add_plugins(DefaultPlugins)
        .add_systems(Update, |mut gizmos: Gizmos| {
... [Log Snipped] ...
        .run()
}
```

Uncommenting the `normalize` will prevent the crash. Note that in my case, the bad `Quat` is being produced by `GlobalTransform::to_scale_rotation_translation`.
Discussion
- Can we just normalize the `Quat` inside of the `sphere` call? Or should we just silently accept garbage data and add a debug assertion that it's normalized?
- I'd probably normalize in the `sphere` call. Debug gizmos are likely to get garbage data and should handle that gracefully. I don't think we need to add any more assertions, that already exists.
