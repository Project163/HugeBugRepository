Title

--backup-dir doesn't work for single file copy/move

Description
#### What is the problem you are having with rclone?

`rclone.1` [Link: says] `--backup-dir` works for "sync, copy or move", but in fact it only works for `sync`. From the code it seems this option is only implemented for `sync`, and if that is the case the doc should be refined.

#### What is your rclone version (output from `rclone version`)

```
rclone v1.47.0-074-g81fad0f0-beta
- os/arch: linux/amd64
- go version: go1.12.5
```

#### Which OS you are using and how many bits (eg Windows 7, 64 bit)

`Debian GNU/Linux 10 (buster), x86_64`

####  Which cloud storage system are you using? (eg Google Drive)

#### The command you were trying to run (eg `rclone copy /tmp remote:tmp`)

`rclone -vv move myfile remote:afolder --backup-dir remote:backupdir`

Discussion
- I'm under the impression that `--backup-dir` should work for move and copy and it did appear to in my tests below using the local backend.  I tried a test with onedrive with identical results.

Which backend did you use for your tests?

- I was using OneDrive, but I think I found the problem. In [Link: cmd/copy], rclone runs a sync if src is a directory and runs a CopyFile operation if it is a single file. Your commands are doing this on directories so `--backup-dir` works. Also, if `rclone sync` is used instead of `rclone copy` or `rclone move`, sync is always used so `--backup-dir` works even for a single file.
