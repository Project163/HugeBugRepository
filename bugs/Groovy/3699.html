Title

Groovy completely ignores @GrabResolver annotation

Description
Steps to reproduce inside docker. Repository added using GrabResolver is completely ignored during resolution and fetching. 

   

 Manually putting repository location into ~/.groovy/grapeConfig.xml solves the problem and make the custom repository work properly. Tested on Groovy 2.5.x and Groovy 3.x, both have the same issue. This example comes from docker container  groovy:3.0.0-rc-3-jre8

- We can take a look. It depends how rich the Ivy api is as to what will be possible. Workaround in the meantime would be to set your classpath up to ensure your own custom grapeConfig.xml was always at the start of the classpath.
- @GrabResolver  resolvers are added by  groovy.grape.Grape#addResolver  which delegates to  groovy.grape.GrapeIvy#addResolver . At the moment, extra resolvers end up at the end of the chain. You could use  chainResolver.getResolvers().add(0, resolver)  instead of  add(resolver) .
