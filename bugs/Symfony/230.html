Title

`RedisTrait` loses database with multiple persistent connections

Description
### Symfony version(s) affected

6.*

### Description

Due to a [Link: bug in phpredis], the persistent redis connections are not keeping their desired selected database.

Specifically connections that are supposed to be on dbindex `0` end up on other databases. This is because the RedisTrait only calls `select` for a truthy dbindex: [URL]

I'm wondering if you would consider calling `select` every time, not just for a truthy dbindex in case the connection is persistent?

I know this would be a workaround for a Symfony-external bug, but it's a small fix.

### How to reproduce

Have two persistent cache connections on different DBs, e.g.:

```
yml
services:
  _defaults:
    autowire: true
    autoconfigure: true
... [Log Snipped] ...
        persistent: 1
        persistent_id: 'db1'
```

### Possible Solution

Change the dbindex check:

```diff
- || ($params['dbindex'] && !$redis->select($params['dbindex']))
+ || (($params['dbindex'] || $connect === 'pconnect') && !$redis->select($params['dbindex']))
```
