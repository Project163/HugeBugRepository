Title

Source map URLs shouldn't be prefixed with a local path

Description
**Do you want to request a *feature* or report a *bug*?**

Bug.

**What is the current behavior?**

Some libraries (i.e. nearly all created via [Link: Scala.JS]) have URLs in their source maps. However when being used with webpack, webpack is prepending a `./` to all the URLs results in trillions of warnings like this:

```
[info] Cannot find source file '[URL] Error: Can't resolve './[URL] in '/home/golly/projects/misc/target/scala-2.12/scalajs-bundler/main'
[info]  @ ./fastopt-launcher.js 1:0-91
[info] 
[info] WARNING in ./demo-fastopt.js
[info] Cannot find source file '[URL] Error: Can't resolve './[URL] in '/home/golly/projects/misc/target/scala-2.12/scalajs-bundler/main'
... [Log Snipped] ...
[info] Cannot find source file '[URL] Error: Can't resolve './[URL] in '/home/golly/projects/misc/target/scala-2.12/scalajs-bundler/main'
[info]  @ ./fastopt-launcher.js 1:0-91
```

And resulting in a final source map that no longer works for those libraries.

**If the current behavior is a bug, please provide the steps to reproduce.**

Setup any dummy project with [Link: Scala.JS] and [Link: scalajs-bundler] which runs everything through webpack.

**What is the expected behavior?**

Source map links that can be identified as absolute URLs should be used as is, without modification.

I believe the fix would be a very simple test like this before prepending:
[URL]

**Please mention other relevant information such as the browser version, Node.js version, webpack version and Operating System.**

Using webpack 2.2.1, Node.JS 7.7.3.
