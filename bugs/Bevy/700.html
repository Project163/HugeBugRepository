Title

RayMeshHit.triangle_index contains the first vertex index instead of the triangle index

Description
**Bevy Version: 0.15**

**Issue Summary**  
`RayMeshHit.triangle_index` currently stores the index of the first vertex of the hit triangle rather than the triangle’s actual index. This makes it impossible to determine the other two vertices when the mesh uses indexed geometry (especially when vertices are shared among multiple triangles or aren’t strictly grouped in triples). As a result, getting UVs or texture colors for the exact hit point is blocked.
This prevents use-cases like texture painting and texture based decals from working.

**Background**  
This problem was previously identified in the [Link: `bevy_mod_raycast` crate] and an unmerged PR [Ref: #117] proposed a fix. The same issue appears to apply in the core Bevy code where the relevant code assigns `Some(a)` for the triangle index instead of using the iteration (triangle) index:

```
rust
for triangle in indices.chunks_exact(3) {
    let [a, b, c] = [
        triangle[0].try_into().ok()?,
        triangle[1].try_into().ok()?,
... [Log Snipped] ...
    // ...
}
```

Switching to:

```
rust
for (i, triangle) in indices.chunks_exact(3).enumerate() {
    let [a, b, c] = [
        triangle[0].try_into().ok()?,
        triangle[1].try_into().ok()?,
... [Log Snipped] ...
    // ...
}
```

would correctly store the triangle’s index instead of the first vertex index, resolving the issue.

**Request**  
Please let me know if there’s any oversight or if I should open a PR to address this.
Discussion
- Fixing the issue as proposed above would require the user to get the vertex indices like this:

```
rust
fn get_indices(mesh: &Mesh, hit: &RayMeshHit) -> Result  {
    let i = hit
        .triangle_index
        .ok_or_eyre("Intersection Index not found")?;
... [Log Snipped] ...
    ))
}
```
This works (tested it with a patch) but isn't very ergonomic. As an alternative the triangle_index field of RayMeshHit struct could be changed from
```rust
pub triangle_index: Option 
```
to
```rust
 pub triangle_indices: Option ,
```
- Meanwhile I created a PR which fixes the issue with "variant 1" so that the interface does not change. I realized that for "variant 2" the field should be called vertex_indices because it's not a triangle index anymore so I went for the simplest solution which unblocks me.
