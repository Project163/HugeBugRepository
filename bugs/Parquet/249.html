Discussion
- adding a call to duplicate() fixes it. 

 Apparently Spark isn't calling that, if you use its parquet reader to create a DataFrame the same thing happens, values are skipped.  Its a Parquet bug, since GenericRecord.get()'s contract does not indicate that two different instances can return the same ByteBuffer instance.   Parquet should call return a duplicate() if it is re-using underlying data between records.
