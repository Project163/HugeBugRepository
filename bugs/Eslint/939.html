Title

Docs: Error in Pull Requests guide?

Description
These sections in PR guide:
- [Link: Rebase on to upstream]
- [Link: Rebasing]

Gives me this error:

```
$ git fetch upstream
fatal: 'upstream' does not appear to be a git repository
fatal: Could not read from remote repository.

Please make sure you have the correct access rights
and the repository exists.
```
Discussion
- Looks like we are missing a step with `git remote add upstream git@github.com:eslint/eslint.git`
- That's part of the development environment guide, which is referenced at the top of the page. [URL]

I was trying not to duplicate information.
- ... [Middle Discussions Snipped for Brevity] ...
- @mysticatea Most users, especially users who do not have contributor access to ESLint, have to fork the repository on GitHub first and then clone their fork onto their local machine. Thus, they have to use `git remote add` to add the ESLint remote repository and do not clone the ESLint repository directly.

From what I've seen, it's a fairly common convention to use `origin` as the name of your clone remote, and `upstream` as the name of the remote for the original source code that was used as the base for the GitHub fork.
- Here's what I currently have after doing `git remote add upstream git@github.com:eslint/eslint.git`:

```
$ git remote -v
eslint    [URL] (fetch)
eslint    [URL] (push)
origin    [URL] (fetch)
origin    [URL] (push)
upstream    git@github.com:eslint/eslint.git (fetch)
upstream    git@github.com:eslint/eslint.git (push)
```

Not sure whether the `eslint` remotes were already there prior to adding the upstream tho.

EDIT: I used Git Desktop to do the initial clone to local, not sure if that makes any difference?
