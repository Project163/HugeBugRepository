Title

pkg_rpm fails when using --incompatible_py3_is_default

Description
### Description of the problem / feature request:

`pkg_rpm` rules fail when the `--incompatible_py3_is_default` flag is used. This is the error output:
```
$ bazel build --incompatible_py3_is_default rpm:fake-package
INFO: Analysed target //rpm:fake-package (0 packages loaded, 0 targets configured).
INFO: Found 1 target...
ERROR: /Users/athompson/code/bazel-test-workspace/rpm/BUILD:3:1: MakeRpm rpm/fake-package-x86_64.rpm failed (Exit 1) make_rpm failed: error executing command bazel-out/host/bin/external/bazel_tools/tools/build_defs/pkg/make_rpm '--name=fake-package' '--arch=x86_64' '--spec_file=bazel-out/k8-py3-fastbuild/bin/rpm/fake-package.spec' ... (remaining 1 argument(s) skipped)

... [Log Snipped] ...
INFO: 0 processes.
FAILED: Build did NOT complete successfully
```
This appears to be failing because the `make_rpm.py` binary is only Python2-compatible, but it is being executed with a Python3 interpreter. I suspect this is because its corresponding `py_binary` rule [Link: here] does not set the `python_version` attribute to `"PY2"`.

### Steps to reproduce

1. `git clone [URL]
2. `cd bazel-pkg-rpm-py3-default/`
3. `bazel build --incompatible_py3_is_default rpm:fake-package`

### What operating system are you running Bazel on?

`CentOS Linux release 7.5.1804`

### What's the output of `bazel info release`?

`release 0.24.0- (@non-git)`

### If `bazel info release` returns "development version" or "(@non-git)", tell us how you built Bazel.

Installed from `vbatts-bazel` COPR repository.
