Title

python3.7 - Pylint crashes with astroid.exceptions.DuplicateBasesError when using Generic types

Description
With python3.7, the pylint crashes on following minified example:
```
python
from typing import Generic, TypeVar

IN = TypeVar('IN', contravariant=True)
OUT = TypeVar('OUT', covariant=True)
... [Log Snipped] ...

print(Example.__mro__)
```

```
python
import astroid

node = astroid.extract_node("""
# context
... [Log Snipped] ...
metaclass = node.declared_metaclass()
metaclass.mro() # DuplicateBasesError here
```

Specifically, the error occurs because the astroid detects duplicate bases of `type`.

astroid detects duplicate bases of `type` because it's inferring the the `bases` of the metaclass to be `type` and `type` and not the `MetaA` and `MetaB`, but only when constructed through the declared_metaclass call.

---

This appears to be a bug in `Call` inference inside the metaclass keyword because the following change does not trigger the issue (The ta base properly infers to `MetaA`):

```python
ta = type(A)
class C(metaclass=type('', (ta, type(B)), {})):
    pass
```
- @brycepg [URL] already seems to fix this bug, you can check the solution proposed by this PR.
