Title

PumpStreamHandler hangs if process is terminated by timeout and it has not generated stdout / stderr output

Description
Hi, 
I've found an issue with DefaultExecutor hanging while waiting for PumpStreamHandler to close all subprocess streams if child process was terminated by watchdog (e.g. on timeout). 

 I've created a test case for the issue demonstrating working behaviour & issue. 

 Test requires commons-io 1.4, Junit 4.x and commons-exec 1.1 to compile
Discussion
- Unit test + 2 scripts demonstrating the issue.
- I am also encountering PumpStreamHandler hanging, though my external processes have exited with a zero exit value. Then PumpStreamHandler locks upon join of the outputThread in the stop() method: 
   from stop method   
  if  (outputThread !=  null ) {         
   try  {
    outputThread.join();
    outputThread =  null ;
  }  catch  (InterruptedException e) {
     // ignore
   }
}
 
  
 As near as I can tell (from debug sessions), the outputThread is locked on read from the inputStream that is the output of the Process. Though in my scenario I have read all the expected output from the Process.
- ... [Middle Discussions Snipped for Brevity] ...
- The joy of multi-platform support - the problem under Ubuntu 

 
	 the process is indeed killed by the watchdog 
	 the StreamPumper is blocked reading from the child process streams and never returns 
	 therefore the the worker threads are not terminated (since the are still in InputStream.read()) 
	 the Thread.join will never succeed
