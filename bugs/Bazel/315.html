Title

Windows: Poor performance when executing java rules that depend on many .jar (related: #2218)

Description
Please provide the following information. The more we know about your system and use case, the more easily and likely we can help.

### Description of the problem / feature request / question:

On Windows, executing external command from a bash script is much slower than on Linux.
Also on Windows, the default is to use RUNFILE_MANIFEST files.

These two things together make executing java rules much slower than necessary, because of the following code in java_stub_template.txt:

```
  function rlocation() {
    if [[ "$1" = /* ]]; then
      echo $1
    else
      echo $(grep "^$1 " $RUNFILES_MANIFEST_FILE | awk '{ print $2 }')
    fi
  }
```

For each invocation of "rlocation", which happen for each CLASSPATH entry, there are 3 (or 4 maybe?) processes executed: bash, grep and awk. It would be much better to do this in memory and avoid calling external processes.

### If possible, provide a minimal example to reproduce the problem:

I can't really share my project because it is big, but it is easy to reproduce with many java rules than all depend on many jar files. On my HP Z840 with 48 Cores, running bazel with such build files makes the machine totally unresponsive (even the mouse pointer is janky), even though there is plenty of memory available.
