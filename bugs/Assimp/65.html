Title

Compiled V5.0.1 reports errors not in previous version.

Description
I downloaded and ran the Windows installer assimp 3.3.1 from assimp.org and everything worked nicely. However, that version does not export gltf2 (there are some related discussions here about -fgltf2 not working). So I downloaded the source and compiled using VS 2019. I followed the instructions on the ReadMe.md page:

    Open a command prompt
    mkdir build
    cd build
    cmake ..
    cmake --build .

However, the compiled V 5.0.1 reports many errors that the older version does not. For examples,

Discussion
- Attached are the files used in the test.  Really appreciate it if anybody can check if their compiled 5.0.1 version can export these two files to gltf.
[Link: samples.zip]
- The `Tile_10_L21.mtl` file is not a 3D format. Assimp should not load it at all.
It's a sidecar file that is used by an OBJ file, and as there's no OBJ file, it's useless.

If a previous version of Assimp did anything with it, then that was a bug.
- The DAE is rather strange.
It references a file `Tile_10_L19_0.jpg` (not present), but specifies it as being zero pixels in size which is not permitted.

The reason for the failure to export is because the glTF2Exporter is trying to export using a scene called "defaultScene", but the original DAE already uses that name.
- We ran a batch test on a number of file formats and these were flagged with errors.  Some of the sample files are probably not very well-formed.  Your explanations make sense.  Thanks.
