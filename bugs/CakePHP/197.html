Title

Possible Bug: Content Length header is not exact

Description
It’s a well known fact that CakePHP serves the assets inside `themed` through PHP. But looks like the `Content Length` is set before the file is rendered as PHP. We ran into a problem where the contents of js file were being trimmed on browser. Refer the screenshot below.

This is what cakephp returns for ` ` at the bottom of our js file.
[Image: returned]

This is what it should be
[Image: actual]

On examination we found that it was because of the content length header possibly set on [Link: AssetDispatcher.php#153]. The content length of a file is not same after it is evaluated as PHP. The actual header length of our JS file should be `45,245` (size after evalutating PHP) instead of `45,217` (size before evaluating PHP) that CakePHP returns. Thus trimming the last `28` characters `ceedcontentlengthcakephp.org`.

This is the header added by CakePHP
[Image: response_header]

This is what it actually should
[Image: real_content_length]

Looks like there is something wrong with the offset added in `_setContentLength` at [Link: CakeResponse.php#505].
