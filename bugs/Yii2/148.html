### Here's what happens:
1. There's no `hu` translation.
2. `MessageSource::translate` returns source language string as a fallback. In our case it's English.
3. `I18N::format` tries formatting English string using Hungarian rules.
4. Old ICU versions (tried with 4.2.1, 4.6.1) fail when there's nothing defined in a language data for a keyword used in plurals pattern. In our case it's `one` (not sure if it's data bug or there are no plurals in Hungarian).
5. Newer ICU versions since 49.1.2 (or maybe  ) ignore any keywords with missing data in plural rules. That's why it was kinda OK for me.

### What's wrong

Currently we are falling back to English message and then formatting it using non-English locale. It leads to not replaced parameters on ICU version lower than 49.1.2 (or probably  ) and to using wrong plural rules otherwise.

Generally we should not format message for one language using another language rules.
