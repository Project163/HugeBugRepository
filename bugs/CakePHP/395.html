Title

3.0 - Validation rules for date/time/datetime fail

Description
Create a table with date, time, or datetime field. Add a validation rule on it. It will fail because the entity marshals it into a DateTime object and the validation rules expect a string.

Marshalling sort of checks for validity already, if its not a valid string format that DateTime can parse it throws an exception and the marshaller returns the string back instead of a `DateTime` object

I'm not sure if a sane solution would be to add an early return to the core validation rules if `$check` is a `DateTime` object because the validation rules seem to be more of checking if a **_string**_ is in a **_specific**_ format.
Discussion
- I would say just return true for DateTime objects in Validation::datetime, the object is already a valid date and it can be formatted back to any pattern
- Closing as #3058 has been merged.
