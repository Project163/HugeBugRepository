Title

HttpClient: string input allows injection attack

Description
[URL]

This "feature" allows maliciously-crafted requests to attach arbitrary files to any HTTP request based on user input. There is currently no support for escaping strings beginning with "@". Escaping functionality could be added, but the feature is non-obvious, so most developers would be unlikely to know that escaping is necessary. Better would be to remove this feature completely, as the alternative form using file handles isn't much more complicated:

```
$response = $http->post('[URL] [
    'file' => fopen('/my/file', 'r'),
]);
```
Discussion
- Dumping un-sanitized user data into HTTP adapters is asking for trouble. Similar [Link: features are offered by ext/curl] which is why it was implemented the way it was.
- It's a bad idea in cURL as well, which is why it is now deprecated:

[URL]

 As of PHP 5.5.0, the @ prefix is deprecated and files can be sent using CURLFile. The @ prefix can be disabled for safe passing of values beginning with @ by setting the CURLOPT_SAFE_UPLOAD option to TRUE. 

In vanilla PHP, I would use http_build_query to handle sanitation. My assumption, before I started investigating more closely, was that Cake would handle sanitation in the same way.

If you want to use the '@' syntax, there needs to be a way for me to make user-inputted strings safe. I don't see a mechanism allowing for any sort of sanitation.
