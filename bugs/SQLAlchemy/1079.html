Title

Issue using func.current_date() in relationship primaryjoin

Description
**Describe the bug**
 
When using `func.current_date()` in a `relationship` `primaryjoin`, accessing that field after loading the object from the database emits an incorrect query that doesn't properly translate `func.current_date()`.

This issue doesn't occur with `sqlalchemy 1.3.23` and so this seems to be a regression.

**Expected behavior**
 
`func.current_date()` is properly translated (to `CURRENT_DATE` in this case specifically) and the relationship field can be accessed.

**To Reproduce**

```
py
from sqlalchemy import Column, Integer, ForeignKey, Date, MetaData, create_engine
from sqlalchemy.ext.declarative import declarative_base
from sqlalchemy.orm import relationship, scoped_session, sessionmaker, selectinload

... [Log Snipped] ...
print(Session.query(B).options(selectinload(B.a_s)).get(1).a_s)  # works
print(Session.query(B).get(1).a_s)  # doesn't work
```
