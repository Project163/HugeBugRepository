Title

Internal error - AttributeError: 'AssignmentStmt' object has no attribute 'expr'

Description
Mypy fails on on this example:

```
import itertools

def chunk(iterable, chunk_size):
    key = lambda (i, elem): i  # type: ignore
```

(note that type: ignore doens't help)

Stacktrace:

```
Traceback (most recent call last):
  File "/Library/Frameworks/Python.framework/Versions/3.5/bin/mypy", line 6, in  
    main(__file__)
  File "/Library/Frameworks/Python.framework/Versions/3.5/lib/python3.5/site-packages/mypy/main.py", line 53, in main
    type_check_only(sources, bin_dir, options)
... [Log Snipped] ...
    return ret.expr
AttributeError: 'AssignmentStmt' object has no attribute 'expr'
```
Discussion
- So this seems a bug in parsing lambda args. Note that `lambda (x, y): ...` is not the same as `lambda x, y: ...` -- the former is a tuple argument of length 2.
- I think the issue here is that
- the `FuncExpr` code is assuming that the body of a lambda is always one statement, a return statement:

```
    def expr(self) -> Node:
        """Return the expression (the body) of the lambda."""
        ret = cast(ReturnStmt, self.body.body[0])
        return ret.expr
```
- The way we handled #934, in PR #929, made that not true when we have a Python 2 tuple-parameter to desugar -- the body can start instead with an AssignmentStmt. See in particular here: [URL]

Probably the immediate fix is to complicate `FuncExpr.expr` to handle this case -- maybe just change `body[0]` to `body[-1]`? That'll still feel a little awkward and potentially fragile. But it's probably OK in practice because we're not likely to add more desugaring like #929 -- we believe we're done parsing all syntax.
- I independently discovered the fix of using body[-1]. I think it's okay if we add a test. I'll commit this soon.
