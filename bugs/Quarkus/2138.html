Title

Solve POM formatting issues when creating project/adding extension/removing extension

Description
I create one unified issue to solve these problems globally as they are highly intertwined.

Original issues: [URL] [URL]

# Problem to solve

## POM format when creating project

Our initial POM file created by the project generator is poorly formatted.

I'm not sure how to solve this problem, if it's a matter of updating codestarts or if we need adjustments to [URL] . 

Note that we can't really count on all codestarts to have consistent formatting.

Ideally, I would like our generated POM to:

- be indented with 4 spaces as it's the convention used by the Quarkus project - that should probably be handled by the library
- insert a blank line between major sections  (` `, ` `...) - this was requested by a user and it makes a lot of sense given we do exactly that when we create a POM file manually - if not easy to add to the library, a regexp to replace `^    <[^/]` and add a new line should do the trick

## Adding extensions

Currently, when adding an extension, the whole POM is rewritten, comments are lost... At some point it also reordered the properties and the dependencies. Not sure if it's still the case but we don't want that either.

When adding an extension, no other changes than the added dependency should be made to the POM file.

Also, ideally, we should add the extension before the first test scoped dependency.

## Removing extensions

Currently, when removing an extension, the whole POM is rewritten, comments are lost...

Removing an extension shouldn't make any change to the POM file.

# Implementation ideas

## Creating project

All this should either be handled in [URL] or by postprocessing the output to beautify it.

## Adding/Removing extensions

Either this is implemented in [URL] but we need to make sure it doesn't apply any unwanted change to the POM.
Not sure how realistic that is.
