Title

Elasticsearch is fsyncing on transport threads

Description
It is currently possible for a cluster state listener to execute a transport fsync.

1. Currently in `TransportShardBulkAction` it is possible that a shard operations will trigger a mapping update. 
2. When this happens Elasticsearch [Link: registers] a `ClusterStateObserver.Listener` to continue when the mapping is complete. 
3. This listener will eventually attempt to [Link: reschedule] the write operation. 
4. If the write thread pool cannot accept this operation, the `onRejection` callback will fail outstanding operations and [Link: complete] the request (probably trying to notify of the operations that were able to be completed).
5. Completing a `TransportShardBulkAction` will attempt to fsync or refresh as [Link: necessary] after initiating replication.
