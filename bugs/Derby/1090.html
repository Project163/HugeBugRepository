Title

calling getByteLength on org.apache.derby.impl.jdbc.StoreStreamClob makes BinaryStream, fetched before this call, unusable

Description
StoreStreamClob.getByteLength first resets the internal stream and then reads the entire stream. Due to this any read on Stream obtained by StoreStreamClob.getRawByteStream returns -1. 

 StoreStreamClob is a read only InternalClob, so probably keeping the length in a variable will be good idea.
Discussion

 I consider separating the error reporting changes into a separate patch. 
I have added a position-aware stream on top of the stream from store (OverflowInputStream), which can reposition itself on request and also tell its current position.

 Note that a positioned stream is only created on top of Resetable-streams.
