Title

Filenames with extended characters not ignored correctly on macOS

Description
### What happened?

With `.stignore` content:

```
bäd
bad
```
The file `bad` is ignored by `bäd` is not.

I also found a workaround. If you use .stignore` content:

```
ba*d
```
it matches and ignores both files. Possibly `ba?d` would also match, but I have tested it.

I believe this is because the NFD-encoded paths (on macOS) are being matched against NFC-encoded ignore patterns.

The solution is to convert to NFC-encoding before matching.

I have confirmed the bug and a proposed fix by modifying the existing unit test.

Note that some non-ASCII characters work, I presume those that have identical NFC and NFD form.

PR forthcoming.
