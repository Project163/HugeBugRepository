Title

ClientCookieDecoder doesn't support some valid RFC6265 expires fields

Description
`ClientCookieDecoder` currently uses `HttpHeaderDateFormat` underneath, which has a fallback strategy and tries the following patterns:
* `E, dd MMM yyyy HH:mm:ss z`
* `EEEE, d-MMM-y HH:mm:ss z`
* `EEE, MMM d HH:mm:ss yyyy`

The former is more or less RFC1123 (it accepts full days of week, while RFC1123 requires 3 letters), I don't know where the 2 others come from.
RFC1123 is [Link: the spec for headers such as `Expires` or `Date`].

The problem is that RFC6265 defines [Link: its own spec] (shaking head) that supports RFC1123 format.

While most people stick to RFC1123, some don't.
For example, Github uses a thing of beauty such as `Sun, 27 Nov 2016 19:37:15 -0000` (`-0000` instead of `GMT` (banging head on desk).
Basically, the spirit is that:
* the day of week is ignored (completely redundant/useless)
* the timezone is ignored as RFC6265 enforces UTC
* delimiters can be many things, so it's not problem to write something like `27-Nov-2016`

Working on a fix.
