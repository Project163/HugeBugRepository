Title

Custom signature template in `binary_signs` leads to release upload failure

Description
### What happened?

I'm trying to get cosign working via goreleaser. Mostly it's been straightforward (and pretty neat actually).

I'm not sure if this is a problem that I've caused or a problem with GoReleaser.

When creating the release, the signing process is called, showing the expected `signature` name being passed in:

```
signing cmd=./ci-only.sh artifact=chinmina-bridge signature=dist/release_linux_amd64_v1/chinmina-bridge_linux_amd64.cosign.bundle
```
[Link: ref]

After the signing process completes, it indicates the addition of the signature artifact:

```
added new artifact name=chinmina-bridge_ type=Signature path=dist/release_linux_amd64_v1/chinmina-bridge_linux_amd64.cosign.bundle
```
[Link: ref]

Note the `name=chinmina-bridge_` there.

When the release uploads occur, there are two signatures (one per arch), but they both have the same `name`, resulting in errors.

- Actually, I think I might understand this.

The template is `'${artifact}_{{ .Os }}_{{ .Arch }}.cosign.bundle'`

Before signing, the `Signature` template is applied:

[URL]

[URL]

So the template is executed with the Artifact in its context.

Afterwards, the `Signature` template is re-executed:

[URL]

This time the Artifact is not in the template context. I think this template application is failing due to the missing references, leading to the truncated name.
