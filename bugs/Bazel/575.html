Title

build-runfiles does not use environment variables set with --action_env

Description
### Description of the problem / feature request:
We have to set LD_LIBRARY_PATH in our environment for bazel to work since it will not find GLIBCXX otherwize.
We would like to use --experimental_strict_action_env together with --action_env to make sure we have control of the environment and possibility to use the remote cache in the best way.

When  --experimental_strict_action_env is set the command build-runfiles fails because GLIBCXX is not found even if LD_LIBRARY_PATH is set with --action_env

Output from command
 exec env - \
    PATH=/bin:/usr/bin \
  _bin/build-runfiles

build-runfiles failed: error executing command

- @burkpojken : FYI, a workaround for the glibcxx problem is to install OpenJDK 8 and export `JAVA_HOME` to point at it, e.g.:

```
export JAVA_HOME=/usr/lib/jvm/java-8-openjdk-amd64/
```

Re: build-runfiles: do you see this with `bazel run` by any chance? It seems that in that case Bazel won't use the normal action execution machinery to run "build-runfiles", see:

- Hi! 
From bazel 0.13 and above it is not possible to make build-runfiles use neither the LD_LIBRARY_PATH from the environment or from --action_env=LD_LIBRARY_PATH=/app/vbuild/RHEL6-x86_64/gcc/5.2.0/lib

We cannot use the later versions of bazel now in our environment :(

Preferable for us the environment variables for LD_LIBRARY_PATH and PATH should be used in all actions if --experimental_strict_action_env is not set.
