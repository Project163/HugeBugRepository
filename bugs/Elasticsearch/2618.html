Title

Preview Datafeed API - Better Handling of Empty body + ID

Description
**Elasticsearch version**: 7.13.0-SNAPSHOT

**Description of the problem including expected versus actual behavior**:

Currently, the .NET client library prefers using POST for any endpoints which support it. In some cases, endpoints accept an empty request body where all elements are optional.

When using the new preview datafeed endpoint which supports POST the client makes the following request:

```
POST /_ml/datafeeds/f1b2010b-datafeed/_preview
{}
```

When the datafeed ID is supplied in the URL path, and the user has not set optional properties explicitly, the response body is an empty object.

Currently, this causes the server to parse the body and return an error:

```
"error" : {
    "root_cause" : [
      {
        "type" : "illegal_argument_exception",
        "reason" :
... [Log Snipped] ...
       org.elasticsearch.xpack.security.rest.SecurityRestFilter.lambda$handleRequest$1(SecurityRestFilter.java:90)\r\n
...
```

After discussing with @benwtrent I am raising this issue to review better handling of an empty request for an existing datafeed ID. It would be nice if an empty body is accepted when a datafeed ID is present.

**Steps to reproduce**:

 1. Send a POST request to `/_ml/datafeeds/f1b2010b-datafeed/_preview` (where f1b2010b-datafeed is the ID for a valid existing Datafeed.
 2. Include an empty object in the body.
