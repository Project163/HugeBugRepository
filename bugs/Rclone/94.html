Title

Upload failed, file removed, but retry continuing

Description
When filing an issue, please include the following information if
possible as well as a description of the problem.  Make sure you are
using the [Link: latest version of rclone].

I am syncing a directory with many large video files, 25 altogether.  After 13 files completed successfully 1 file of 6.6 Gb size reached 100% and then started over from 0% again.  I removed the file from the directory completely but the retry is carrying on merrily on its way!  Does rclone cache the whole file before uploading?  It is too large to be in memory, besides there are 3 other files running too.

I have experienced failed upload before, and solved it by using the Amazon desktop app for Windows.  So, I am doing that in this case.  I don't want to interrupt the rclone process because other files are in an advanced stage of upload, but I want it to stop the retry of the failed file and move on to another file.  Is there a command modification that will tell rclone not to retry failed uploads?

Thanks.
Discussion
- A 2nd file reached 100% and then started over from 0% again.  I killed the process and started it fresh.
- I suspect this is the same problem as #601 which unfortunately is an Amazon problem which I can't fix :-(

If you supply a log with `-v` I can confirm.

No rclone doesn't cache the file.  On unix you can delete an open file and the processes which have it open will carry on just fine.  Windows prevents you from deleting open files at all.

Checkout the `--retries` flag and also the `--low-level-retries` flag.
