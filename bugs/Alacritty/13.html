Title

[Ranger] Bright colors do not get transferred correctly to bg color

Description
[Image: ranger]

Urxvt top, alacritty bottom.

When using ranger with alacritty I noticed that the colors do not match with the ones I get with urxvt. It seems like ranger uses the current color of the file type to draw the background. However in alacritty it doesn't seem to take into account that the bold text changed the color and instead uses the non bright color to draw the bg strip.
Discussion
- There's a config option to draw bold text with bright colors. Please make sure you've got that enabled and that your bright colors are configured differently than normal colors.
- If you mean `draw_bold_text_with_bright_colors: true` then I have that activated, yes.

As you can see in the screenshot, the bold text has a different color than the bg color with alacritty.
Here is my color settings:
```
# Colors (Tomorrow Night Bright)
colors:
  # Default colors
  primary:
    background: ' '
... [Log Snipped] ...
    cyan:    ' '
    white:   ' '
```
- Oh, sorry. I misunderstood. Sounds like a bug.
- @jwilm It seems like the problem is the "invert" color terminal code:
```
echo -e "\e[32mNormal \e[7mInverted\e[27m \e[1mBold \e[7mInverted Bold\e[27m"
```

Paste that into your terminal and you will see that the inverted bold is not correctly handled. I did take a look at where the bright color computation happens and I think that it happens too late in the pipeline to be able to handle this.

Because as it is now, the fg and bg colors are split of long before the bright check happens. So it is impossible to know if the bg color should be bright or not.
