Discussion
- From my analysis, it looks like a timing issue. 

 Occasionally in this test, by the time code flow reaches the line 
 try (OutboundMessageQueue.WithLock lock = queue.lockOrCallback(0, () -> {}))  

 lock acquired on the queue prior to it has not been released. Therefore, lock has a null value resulting in the  NullPointerException . 
When I added  Uninterruptibles.awaitUninterruptibly(lockUntil)  before the line of code mentioned above, test ran for a long time without failing.  

 Another option to fix this test, perhaps is to add a callback and check for the content of the queue in the callback.
