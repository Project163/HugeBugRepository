Title

Calcite engine. Wrong casting to interval

Description
There are a couple of bugs when casting numeric to interval, for example, literal to interval casted correctly: 
  
 assertEquals(Duration.ofDays(1), eval("CAST(1 AS INTERVAL DAYS)"));
 
  
 But explicetely casted literal give a wrong result: 
  
 assertEquals(Duration.ofDays(1), eval("CAST(1::INT AS INTERVAL DAYS)"));
 
  
 expected:<PT24H> but was:<PT16M40S> 

 Another problem, floating point values can be casted correctly: 
  
 assertEquals(Duration.ofHours(36), eval("CAST(1.5 AS INTERVAL DAYS) FROM t")); 
  
 But the same values pushed from downstream are rounded to integer: 
  
 assertEquals(Duration.ofHours(36), eval("CAST(f AS INTERVAL DAYS) FROM (VALUES(1.5)) AS t(f)"));
 
  
 expected:<PT36H> but was:<PT48H>
