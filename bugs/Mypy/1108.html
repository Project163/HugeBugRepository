Title

Issue with importing from relative imports (Name already defined)

Description
Repro setup:

```
➜  mypy git:(master) ✗ tree relative_root some_other_root
relative_root 
├── __init__.py
└── inner.py
some_other_root
... [Log Snipped] ...
➜  mypy git:(master) ✗ cat some_other_root/some_module.py
from relative_root import Inner
```

And the error:

```
➜  mypy git:(master) ✗ mypy --use-python-path -m some_other_root.some_module
some_other_root/some_module.py:1: note: In module imported here:
relative_root/__init__.py:1: error: Name 'Inner' already defined
```
Discussion
- Thanks for reporting this! Did you have `PYTHONPATH` or `MYPYPATH` defined?
- Hey Jukka, 
Thanks for the quick reply, really excited about the project!

```
➜  mypy git:(master) ✗ echo $PYTHONPATH

➜  mypy git:(master) ✗ echo $MYPYPATH
```

So, no. BTW: Python3.4 (tried on mac an linux).
- I've got a simpler repro: put the same two files in `relative_root`, but instead of having a separate package, just run `mypy -c 'from relative_root import Inner'`.

It almost feels as if the import (`from relative_root import Inner`) tries to store Inner in the wrong namespace (the globals of `relative_root` instead of `__main__`). Variants where I write `from relative_root import inner` (note lower case 'i') or `import relative_root` don't exhibit the problem.
