Title

Yii2 suppresses error if it has occured during Response::prepare()

Description
Steps to reproduce:
1. In the model code define function toArray() and type something like zzz; in this method
2. return this model as is in one of controller actions (without call to toArray())
3. Application calls Response::send()
4. Response::send() will call Response::prepare()
5. Inside of prepare() exception will occur (because of that zzz; in item 1)
6. This exception will be caught by ErrorHandler
7. ErrorHandler::renderException() will call $response->send()
8. Nothing happens because $response->send() has been called already in item 3 and send() has this if:
   
   ```
   if ($this->isSent) {
       return;
   } else {
       $this->isSent = true;
   }
   ```

So the error occured during the send() execution will not be sent.
Discussion
- // Line 95 at ErrorHandler.php
$response = Yii::$app->getResponse();
$response->getHeaders()->removeAll();
$response->clear(); // fixes the issue
- The fix you're suggesting above has a couple of concerns:
- `Response::EVENT_BEFORE_SEND` will get triggered twice. Can anyone comment on whether or not this is ok?
- What happens if an exception is thrown inside of `Response::prepare()` again when `ErrorHandler::renderException()` invokes `$response->send()`? This looks like it could potentially cause an infinite loop using the solution above?

If the _first_ bullet point above isn't an issue, then `$response->clear()` near the beginning of `ErrorHandler::renderException` could be a good solution, but in that case I'd recommend putting the `$response->send()` invoked by `renderException()` inside a try block to prevent the infinite loop.

I could prepare a pull request for this, but would like to get some feedback on my suggested approach first since Exceptions can be a bit tricky and I'm also new to Yii core functions.
- Digging a bit deeper it looks like bullet point 2 from above is not really a concern since `Application.php` already looks out for exceptions thrown while already in the error handler. So if someone can advise me on point 1 I can go ahead with preparing a pull request.
