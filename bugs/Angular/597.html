Title

Doc examples e2e flakes cause frequent CI failures for aio_e2e2 job

Description
## Current behavior
Frequently occurring flake in the "aio" travis job:
```
1) Api pages should show classes that implement an interface
  - Failed: stale element reference: element is not attached to the page document
    (Session info: chrome=62.0.3202.0)
    (Driver info: chromedriver=2.33.506092 ( ),platform=Linux 4.11.6-041106-generic x86_64)
```


## Expected behavior
no flakes :)
Discussion
- @petebacondarwin and @gkalpak already started looking into this issue a few days ago, but it is still occurring. Pete, George, can you please post the most recent status update here?

@vicb - fyi since you are the caretaker that sees this one quite often.
- AFAICT, there are currently 3 flakes that come up:

1. `expected 0 to be greater than 0`
    They occur in [these specs][1] and are related to the fact that we always [scroll to the top][2] after a short delay once a new doc is rendered. (So, it is a race condition.)

2. `stale element reference: element is not attached to the page document`
    I've seen this occur in tests that [use the `getLink()` helper][3]. It might be related to the fact that the links can appear in two places, either in the topbar (if the window is wide enough) or in the sidenav. This changes dynamically depending on the window's width.

3. `javascript error: document unloaded while waiting for result`
    This happens mostly in the [API pages specs][4] (in any of them), but I've seen it in other specs too (with much lower frequency though). I have no idea what might be causing this.

##
Other things we (don't) know:

- We don't know exactly what triggered the flakes. Changes that happened around the same time the flakes started to appear and may have affected e2e tests (but without being clear how or why):
    - Upgrade to Chrome 62 (in 820bb7bd8).
    - Fix another flake related to Google Analytics (in 441e01c56).
- There is a PR that might address (or at least considerably reduce) the first two flakes: #20117
- I don't think we have been able to reproduce the 3rd one locally (I haven't).
- As pointed out by @petebacondarwin, it seems as if protractor is not properly waiting for Angular. Could be an issue with (a) Protractor, (b) ChromeDriver, (c) Zones, (d) the Testability service, (e) all of the above. 
- There is an ongoing investigation :smiley:

Considering this is a major pain point for all PRs atm, @petebacondarwin has suggested (and I agree) that we should move the e2e tests into a selarate optional job, while we investigate.
