Title

[Next14] Phase in next config is set to `PHASE_DEVELOPMENT_SERVER` when running `next build`

Description
### Link to the code that reproduces this issue

[URL]

### To Reproduce

1. Run the build script in the linked reproduction sandbox
2. Observe the logged output for the phase values

### Current vs. Expected behavior

**Current behavior**
Starting with next.js v14, it seems that the next config is loaded twice when running `next build`:

- The first time, the `phase` value is set to `PHASE_PRODUCTION_BUILD` and the invocation is triggered by [URL]
- The second time, the `phase` value is set to `PHASE_DEVELOPMENT_SERVER` and the invocation is triggered by `getStartServerInfo` in [URL] It seems that `getStartServerInfo` always uses `PHASE_DEVELOPMENT_SERVER`, no matter the context: [URL]

**Expected behavior**
`getStartServerInfo` should be called with a value of `PHASE_PRODUCTION_BUILD` when run in a `next build` context.

In my case, I used the `phase` value to skip the execution of some logic only in the buildphase which is now no longer possible.
I worked around this issue by using a custom env var when launching the build`BUILD_PHASE=true next build` and then checking for the value of this env var in my `next.config.js`. 

I wonder if this change is intended behaviour or a bug. In my opinion, the `phase` argument loses most of its usefulness if it's set this way.
