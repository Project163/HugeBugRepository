Title

ArgumentError: wrong number of arguments (given 3, expected 2)

Description
The below mentioned two posts are better off lying in the issues section rather than in the forem.dev website.

- [Link: Heroku and Dokku logs]
- [Link: Fedora Core OS logs]

---

In this [Link: post], I manually checked the difference between 3 types of Forem installations and produced their logs.
- Fresh installation of Forem with the current repo ([Link: logs]) => Build failing
- Fresh installation of Forem using the old repo, where the ruby version of 2.7.2 ([Link: logs]) => Build Passed and Working
- 2.7.2 Ruby-based Forem upgrading to the latest Repo ([Link: logs]) => Build Passed and Working
Discussion
- I think this might have to do with the way ruby3 treats keyword arguments - [Link: the code in question] looks like this 

```ruby

  INDEX = [:user_optional_fields, [:label, :user_id], unique: true].freeze
  def up
    drop_table :user_optional_fields

    remove_index(*INDEX) if index_exists?(*INDEX)
  end
```

The remove index you're seeing the error raised on may be the issue - the last item in the array, {unique: true} is being seen as a positional argument rather than a keyword hash - this was [Link: a change] in ruby3's argument passing rules.

This wouldn't happen in an environment where you had already run this migration on ruby 2, then upgraded to ruby 3, but might happen on a clean deploy or if you dropped and recreated the db, then migrated.

Smallest reproduction (raises the same error in development): 

```
bundle exec rails db:drop
RAILS_ENV=development bundle exec rails db:create
RAILS_ENV=development bundle exec rails db:migrate
```
