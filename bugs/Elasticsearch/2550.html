Title

Elastic Watcher API regression bug (optional parameters are no longer optional when indices_options is specified)

Description
**Elasticsearch version**: 7.10.1

**Plugins installed**: []

**JVM version** (`java -version`):
openjdk version "15.0.1" 2020-10-20
OpenJDK Runtime Environment AdoptOpenJDK (build 15.0.1+9)
OpenJDK 64-Bit Server VM AdoptOpenJDK (build 15.0.1+9, mixed mode, sharing)

**OS version** (`uname -a` if on a Unix-like system):
Linux 39b5309d4c57 4.15.0-132-generic #136-Ubuntu SMP Tue Jan 12 14:58:42 UTC 2021 x86_64 x86_64 x86_64 GNU/Linux

Note: This was using the [Link: Elasticsearch Docker v7.10.1 image]

**Description of the problem including expected versus actual behavior**:

#### Expected 
When creating a watcher using the Elastic watcher API and using the `indices_options` section, I should not have to include all the following optional paramaters:
* allow_no_indices
* expand_wildcards
* ignore_unavailable

The docs say each of the above is optional: 
[URL]

#### Actual
However, if `indices_options` is specified, then all of the above parameters become required. 

This was not the case in a previous version of Elasticsearch we were using (v7.6.2). 

Attempting to create a watcher with a payload that does not contain those parameters leads to errors: 
```
{
  "error" : {
    "root_cause" : [
      {
        "type" : "parse_exception",
... [Log Snipped] ...
  "status" : 400
}
```

Looking at the code, this section looks like the cause: 
[URL]
