Title

[bug] Error while creating updater tar.gz

Description
### Describe the bug

I'm bundling an app for distribution that includes some macOS Frameworks. These Frameworks have symlinks inside them, which is pretty common. The bundle process fails with this error:

```
Error: failed to bundle project

Caused by:
    0: Failed to tar.gz update directory
    1: Failed to tar.gz update directory
    2: `Is a directory (os error 21)`
    3: Is a directory (os error 21)
```

Digging into the code for the bundler, [Link: this section] that creates the tar.gz file is expecting each path to be a directory or a file. This fails to process the Frameworks because they have symlinks that point to directories – it's taking the `else` branch when the path is not actually a file.

Here's a PR that seems to fix the issue: [URL]

### Reproduction

In `tauri.conf.json`, under `macOS.frameworks`, specify a framework that include symlinks. Any old framework on the system will work.

Here's [Link: a minimal example repo] where I'm pointing to a framework inside Google Chrome.app

### Expected behavior

It should build and create the .tar.gz file for the updater.
