Title

Bug: no-multiple-empty-lines ignores failures when there is a single empty line at EOF

Description
I introduced a bug in #4208 

Now when there is a single empty line at the end of the file, no errors are reported.

This should be invalid but it is not:

``` js
var a=5;\n\n\n\nvar b = 3;\n
```
Discussion
- I'm not clear on what you're reporting. I thought the point of the earlier change was so that this code wouldn't flagged? Now it seems like you're reporting the reverse is true? Can you explain?
- The code before the two issues always removed the last empty line. If there were multiple empty lines at the end, it would fail to report that in some cases (depending on max value and the number of empty lines).

Now it only removes the last line when there is exactly one empty line, to avoid reporting when max is 0 (or any value in fact, since it won't report for max > 0).
- What do you mean by "removed" the last line? Are you talking about auto-fixing behavior?
- No, I'm sorry. I am talking about [Link: this line]. I mean excluding it from the checks. Returning is wrong because it prevents other errors from being reported (as the multiple linebreaks in the example above), since this rule is checking the whole file on program exit.

The difference with the original is the condition under which the exclusion happens (only when there is exactly one empty line at the end).
