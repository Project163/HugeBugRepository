Title

Multithread copy not setting modtime correctly on Windows

Description
**What is the problem you are having with rclone?**
download loop.

**What is your rclone version (output from rclone version)**
rclone v1.51.0
- os/arch: windows/amd64
- go version: go1.13.7

**Which OS you are using and how many bits (eg Windows 7, 64 bit)**
Windows 10, x64

**Which cloud storage system are you using? (eg Google Drive)**
Google Suite

**The command you were trying to run (eg rclone copy /tmp remote:tmp)**
"rclone.exe" sync "remote:/folder/" "f:\folder" --bwlimit 250M --config "rclone.conf" -v

**A log from the command with the -vv flag (eg output from rclone -vv copy /tmp remote:tmp)**
Multi-thread Copied (replaced existing)

hello,
i got a problem today with synching a remote (google suite) to a local drive.
i was running an old rclone version, don't remember the version.
`"rclone.exe" sync "remote:/folder/" "f:\folder" --bwlimit 250M --config "rclone.conf" -v`
my local drive was empty, it was a complete restore.
it took 24h, job was still running  and then i started to see messages "Multi-thread Copied (replaced existing)".
previously, the job was at 99%, and sudently it go back to 88%.
i checked size of all files in the cloud and my local drives, size was the same.
but some files was always downloaded again each time i start the job again, and it should not.
i tried the last version of rclone but it was the same.
then, i realize that it was all videos files.
i understand, with the "Multi-thread Copied (replaced existing)" message that it was relative to reassembling files so i add --multi-thread-streams=0
now it's ok
