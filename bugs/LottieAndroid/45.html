Title

Calling Paint.setAlpha() generates several ColorSpace$Named[] allocations

Description
**Link to fork with a repro in the issue-repro module**
[URL]

**Describe the bug**
Calling an Enum `values()` method clones the values of the enum, allocating memory. If this is executed in a loop, we can see a significant amount of allocations in a short period of time. Calling Paint.setAlpha() generates a ColorSpace which calls Named.values() where Named is an Enum. This was modified in Android 30.

**Steps To Reproduce**
Steps to reproduce the behavior:

1. Start the issue-repro app
2. Go to Profiler
3. Select the Memory profiler
4. Start Java/Kotlin allocation recording
5. After a few seconds you will see a huge amount of ColorSpace$Named[] allocations.
