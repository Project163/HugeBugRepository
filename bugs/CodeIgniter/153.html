Title

Bug in dbforge->modify_column() for PostgreSQL and default value for a column

Description
Maybe linked with #5542

**CI Version used: 3.1.10
Postgres v.10.4**


**Prerequisite:**  table 'users' a column 'activated': 
**Here is the migration script to create this table :** 
        $this->dbforge->add_field('id');
        $this->dbforge->add_field([
            'privileges' => [
                'type' => 'INTEGER'
            ],
            'email' => [
                'type' => 'VARCHAR',
                'constraint' => 255
            ],
            'name' => [
                'type' => 'VARCHAR',
                'constraint' => 255
            ],
            'token' => [
                'type' => 'VARCHAR',
                'constraint' => 20
            ],
            'tokenValidity' => [
                'type' => 'INTEGER'
            ],
            'activated' => [
                'type' => 'BOOLEAN'
            ]
        ]); 
        $this->dbforge->create_table('users');


**An other migration to set a default value to the column activated:** 

$fields = array(
                    'activated' => array(
                        'type' => 'BOOLEAN',
                        'default' => FALSE
                    )
            );
$this->dbforge->modify_column('users', $fields);

**When executing this migration, it seams that the transcoding to SQL write twice SQL word:  `DEFAULT`. Please see the following error:** 

Error Number:
        ERROR:  syntax error at or near "FALSE"
LINE 1: ... "users" ALTER COLUMN "activated" SET DEFAULT  DEFAULT FALSE
                                                                  ^
        ALTER TABLE "users" ALTER COLUMN "activated" SET DEFAULT  DEFAULT FALSE
        Filename: C:/wamp/www/portfolio/system/database/DB_driver.php
        Line Number: 691
Discussion
- Please verify if the commit linked above fixes the issue.
