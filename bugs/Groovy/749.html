Title

GroovyConsole does not execute GroovyTestCase subclasses as command line invocation does

Description
The class 
  
  class  TestIt  extends  GroovyTestCase {
    void testTrue ( ) {
        assertEquals ( 1 , 1 )
    }
}
 
  
 when executed from the command line: 
  
 |> ./testing.groovy
.
Time: 0.148

OK (1 test)
 
  
 but when executed in GroovyConsole: 
  
 Exception thrown: groovy.lang.MissingMethodException: No signature of method: TestIt.main() is applicable  for  argument types: ([Ljava.lang. String ;) values: {[]}

groovy.lang.MissingMethodException: No signature of method: TestIt.main() is applicable  for  argument types: ([Ljava.lang. String ;) values: {[]}
	at TestIt.invokeMethod(Script0)
 
  
 I think GroovyConsole should execute the same as command line invocation does.
Discussion
- The issue isn't the Console, the problem is that GroovyShell.evaluate(scriptText, scriptName) doesn't treat the code the same as the groovyshell run varients. 

 Also, I think the severity is overstated.
- I probably agree it isn't a major bug but isn't it a worthwhile enhancement request?
