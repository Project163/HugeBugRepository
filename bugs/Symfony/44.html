Title

[Service Container] Inlining property-injected service definitions generates invalid XML

Description
Hello,

Defining a private service then injecting it only once will cause its definition to be dumped 'inline' when generating a cached service definitions XML file (which is expected in the dev environment). However, when this service is injected using property injection, the following error occurs:

```
 [InvalidArgumentException]

 [ERROR 1871] Element '{[URL]
 This element is not expected. (in [...] /app/cache/dev/appDevDebugProjectContainer.xml [...] )
```

The cached services definitions XML files contains the following chunk, which is indeed invalid:

```
   
     
      [...]
     
   
```

You can reproduce the issue by adding the following snippet in a services definitions XML file:

```
 
     
     
         
     
 
```

Temporary workaround: Make that service definition public so it does not get inlined.

When it comes to a permanent fix, I am not sure about whether the xsd should accept inlined definitions of property-injected services (see: [URL] for a somewhat related issue) or if property-injected services should just skip inlining.

All the best,
## 

mirsal
