Discussion
- The RenameAction was modified to use java.nio so it can better report rename failures and their cause. This won't fix the issue. That will require an enhancement to the RollingFileAppender to write to the filePattern directly instead of renaming files.
- Commit   in logging-log4j2's branch refs/heads/master from  ralph.goers@dslextreme.com  
[  [URL] ] 

   LOG4J2-1032   - Make DefaultRolloverStrategy more efficent when renaming files. Add nomax option to the fileIndex attribute.
- The fix for this is now in master. It consists of 2 parts: 
1. Only the files that exist will attempt to be renamed. Previously it looked for all files from min to max. 
2. fileIndex="nomax" can now be specified. This will simply increment the counter for each new archive so no renames occur at all. 

 Please verify and close if it works for you.
