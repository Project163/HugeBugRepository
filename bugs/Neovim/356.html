Title

`vim.deprecate()` can be significantly slower than deprecated function

Description
### Problem

Adding `vim.deprecate()` to a deprecated function can lead to its relatively significant performance decrease. In particular, this is noticeable after #28440.

### Steps to reproduce

1. Create the following 'init.lua':
    ```
lua
    _G.bench_tbl_islist = function()
      local durations, arg = {}, { 'a' }
      for _ = 1, 5 do
        local start_time = vim.loop.hrtime()
... [Log Snipped] ...
      return durations
    end
```
2. `nvim --clean -u init.lua`
3. `:=bench_tbl_islist()`. It gives me the following results:
    -  On current Nightly (`NVIM v0.10.0-dev-2976+g208852126`) it is something like `{ 3.72243, 0.918169, 0.968143, 0.763256, 0.783424 }`.
    - On 0.9.5: `{ 0.002955, 0.000361, 0.000281, 0.000251, 0.00019 }`.

The main slowdown seems to be due to [Link: usage of `vim.version()`], which in turn seems to be due to [Link: usage of `vim.fn.api_info()`].

### Expected behavior

Deprecating (except hard deprecating) should not significantly impact performance of a deprecated function.

### Neovim version (nvim -v)

NVIM v0.10.0-dev-2976+g208852126

### Vim (not Nvim) behaves the same?

No (doesn't have this functionality)

EndeavourOS Linux x86_64 (6.8.7-arch1-1)
