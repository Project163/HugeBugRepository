Title

Question on MP3 Playback.

Description
MP3Extractor.java has a logic to check for 4 consecutive MP3 frames to sniff the content and detect it as MP3. This is also done in synchronize API.  Is there any specific reason for this?
Discussion
- The logic is intended to (approximately) match the behavior of the platform extractor (see [Link: MP3Extractor.cpp]). I think the search is intended to avoid false positives -- it is very unlikely that frames would be found at the correct offsets in random data. Do you think it should work in a different way?
- Well, we have a requirement of playing a file that has 3 MP3 frames. So, it fails because of this check. In my opinion, a check for one or two frames is sufficient.
