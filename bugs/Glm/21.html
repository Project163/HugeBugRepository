Title

glm- \glm\gtc\quaternion.inl(678): error C2784: 'glm::detail::tvec4 glm::atan2(const glm::detail::tvec4 &,const glm::detail::tvec4 &)' : could not deduce template argument for 'const glm::detail::tvec4 &' from 'float'

Description
Not sure this issue has been reported yet but when I specify the **GLM_FORCE_RADIANS** macro, this error appears:

```
1>...\glm- \glm\gtc\quaternion.inl(678): error C2784: 'glm::detail::tvec4  glm::atan2(const glm::detail::tvec4  &,const glm::detail::tvec4  &)' : could not deduce template argument for 'const glm::detail::tvec4  &' from 'float'
1>          ...\glm- \glm\gtx\compatibility.hpp(83) : see declaration of 'glm::atan2'
1>          ...\glm- \glm\gtc\quaternion.inl(654) : see reference to function template instantiation 'T glm::pitch (const glm::detail::tquat  &)' being compiled
1>          with
1>          [
1>              T=float,
1>              P=0
1>          ]

```
Discussion
- After further investigation, I can confirm that this error only occurs if I include the **glm/gtx.hpp** header file. If I don't include the **gtx.hpp** header but instead only include the individual headers then I do not get this error.

So I changed this:

``` c++
#define GLM_FORCE_RADIANS
#include  
#include  
```

to this:

``` c++
#define GLM_FORCE_RADIANS
#include  
//#include  
#include  
#include  
#include  
#include  
```

I was able to reproduce this error in the **glm/test/gtx/gtx_quaternion.cpp** test case by including the **ext.hpp** header instead of the separate header files.
- This bug is now fixed in GLM 0.9.5 branch for next release.
