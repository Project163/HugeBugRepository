Title

Unexpectedly encountered partial type

Description
**Bug Report**

With updating from mypy `1.6.1` -> `1.7.1` I get an assertion error: "AssertionError: Unexpectedly encountered partial type". This happens in the released version `1.7.1` as well as on the current git main branch.

**To Reproduce**

```
python
from typing import Any

from pymongo import MongoClient
from pymongo.errors import ConnectionFailure
... [Log Snipped] ...
    if client:
        client.close()
```

**Expected Behavior**

Mypy should not raise an assertion.

**Actual Behavior**

This is the output from current mypy version from git:

```
mypy --show-traceback my_project 
my_project/worker.py:45: error: INTERNAL ERROR -- Please try using mypy master on GitHub:
[URL]
Please report a bug at [URL]
version: 1.8.0+dev. 
... [Log Snipped] ...
AssertionError: Unexpectedly encountered partial type
my_project/worker.py:45: : note: use --pdb to drop into pdb
```

**Your Environment**

- Mypy version used: 1.7.1
- Mypy command-line flags: none
- Mypy configuration options from `mypy.ini` (and other config files):

```
toml
[tool.mypy]
python_version = "3.11"
plugins = "pydantic.mypy"
follow_imports = "silent"
... [Log Snipped] ...
module = "xxx.*"
ignore_missing_imports = true
``` 

- Python version used: 3.11.6
Discussion
- This issue lasted for two years, and the reproducer is surprisingly trivial:

```
python
from typing import Generic, TypeVar

T = TypeVar("T")

... [Log Snipped] ...
    if client := Foo():
        db = client
```

still crashes on master (no mypy config/flags/plugins needed), but does not crash with `--local-partial-types`

This works differently (but is also incorrect):

```python
def init_worker() -> None:
    global client, db
    client = Foo()
    if client:
        db = client  # E: Statement is unreachable  [unreachable]
```
- I can confirm this solves my issue and with the next release I can finally upgrade from 1.6.1. Thanks @sterliakov for fixing this and thanks @ilevkivskyi for review and merge. 🙏
