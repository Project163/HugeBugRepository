Title

Bugs in man script

Description
### Problem

Hi there!

I've found that man.lua author assumed that man pages sections:
1) can be only number: [URL]
2) can be only single character: [URL]

Both assumptions are wrong: there are so many variations:

```
ShellSession
$  ls /usr/share/man/man* -1d
/usr/share/man/man0p/
/usr/share/man/man1/
/usr/share/man/man1p/
... [Log Snipped] ...
/usr/share/man/man8/
/usr/share/man/mann/
```

There is not only "most common" ` p` sections (which already fails at both this places), but there is also "n" section (still single char, but not a number), and `  ` sections

And if "n" section is "abused" by only tcl/tk-related manpages,
the "worded" ones is part of "default" `man-pages` package.
and " p" ones is even part of "more standard" `man-pages-posix` package.

So, both assumptions are wrong.



Although, on my system it is enough to fix only `1)` to make man in neovim work as expected, I think `2)` should be fixed a well.

Althouth(2), if fix for `1)` is pretty simple (just remove `tonumber()` around `args[1]`) and I can send PR with it in any moment, I'm not sure if changing `man?/` to `man[^/]+/` would be acceptable fix for `2)` :man_shrugging: 

If yes, I can make PR with both fixes ASAP (maybe, after pause about 4-6 hours after posting this ticket)

### Steps to reproduce

`nvim --clean`
`:Man 1p man`
or
`:Man 3type uint8_t`

### Expected behavior

It should open manpage, but not show error that there is no such man page
