Discussion
- According to the error log the issue is reproduced when shared memory clients are used for communication SPI instead of TCP ones. 

 This error is not reproduced on TCP communication clients. Will investigated shared memory communication clients.
- The issue more often happens on Mac OS. Need try to reproduce on Apple's machine: 
 [URL]
- Unable to reproduce 'Client already created' assertion. However determined using the failing logs that it happened under tough memory conditions.  

 Set tough memory conditions and could reproduce another NPE exceptions that reported by  TcpDiscoveryMultiThreadedTest.testMultiThreadedClientsRestart()  test. 
 [URL]

 Fixed NPE: 
 
	 in GridDhtPartitionsExchangeFuture caused by race; 
	 in TcpCommunicationSpi caused by the fact that the SPI has not been fully started at the moment when a local node id was required. 
 

 Keep try to reproduce 'Client already created' assertion after that.
- 'Client already created' assertion and other errors happened because of insufficient memory during the test. The main reason that caused this is that client nodes were stopped with 'cancel' flag set to  false . This led to a resource/memory leak because right after such stop a new client was started. 

 So the test was fixed. Plus a couple of races and NPE was fixed as well (see above).
