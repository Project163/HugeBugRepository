Title

[CDCSDK] Tablet getting deleted even after being hidden

Description
Jira Link: [Link: DB-11517]

We have a corner situation where we observed that if a tablet split and the process behind hiding the tablet gets coupled with master restarts, the tablet ends up being deleted because of a race condition. The flow is described as follows:

1. TabletManager thread tried to CleanupSplitTablets and calls `DeleteNotServingTablet` but master is not available, so it keeps retrying.
2. There is a Master restart and it loads the `sys_catalog`. The TabletLoader doesn't load the said tablet as hidden because the tablet was not hidden in the first step.
3. The master after restart immediately gets `DeleteNotServingTablet` request from TServer from CleanupSplitTablets. There are **TWO** calls incidently just one after another.
4. First call correctly hides the tablet in `DeleteTabletListAndSendRequests` but after hiding it there is a delay in adding it to `retained_by_xcluster_` or `retained_by_cdcsdk_`
5. Meanwhile the second call in `DeleteTabletListAndSendRequests` finds the tablet hidden but doesn't find the tablet in `retained_by_xcluster_` or `retained_by_cdcsdk_` . It assumes that it should be deleted and deletes it.
6. In case of CDC, we have data loss as we expect the parent to be polled but our metadata misses this tablet.

Discussion
- Main issue here is with point 4:

This can be reproed by adding a delay in DeleteTabletListAndSendRequests before we add to the retained_by_* maps
