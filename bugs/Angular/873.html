Discussion
- This might be the same issue that I get when setting `enableIvy: true` in my project, but I find the description here pretty vague.

`tsconfig.json`:
```
{
  "compilerOptions": {
     // ...
    "paths": {"config": ["src/config.dev.ts"]}
  },
  "angularCompilerOptions": { "enableIvy": true }
}
```

When building, this with Angular 8.1.0, I'm getting an`ERROR in ENOTDIR: not a directory, scandir '{...}/client/src/config.dev.ts'`, which makes me think there's an assumption that the path mappings always map to a directory. Setting an exception breakpoint allowed me to get the stack trace:
```
Error
    at handleErrorFromBinding (fs.js:126:5)
    at Object.readdirSync (fs.js:795:3)
    at NodeJSFileSystem.readdir (node_modules/@angular/compiler-cli/src/ngtsc/file_system/src/node_js_file_system.js:37:74)
    at EntryPointFinder.walkDirectoryForEntryPoints (node_modules/@angular/compiler-cli/ngcc/src/packages/entry_point_finder.js:85:18)
... [Log Snipped] ...
    at NgccProcessor.processModule (node_modules/@ngtools/webpack/src/ngcc_processor.js:54:16)
    at node_modules/@ngtools/webpack/src/compiler_host.js:317:36
```

Maybe the `EntryPointFinder` should check if the path mappings do in fact map to a directory or not.
