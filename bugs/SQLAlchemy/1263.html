Title

TextualSelect.add_cte() drops the CTE when compiled

Description
### Describe the bug

When using the `.add_cte()` method on a `TextualSelect` instance, the CTE does not seem to be taken into account when the statement is compiled.

In the example code below, the expected output would be:
```
WITH baz AS (
    SELECT id FROM foo
)
SELECT bar.id, bar.attr FROM bar WHERE bar.foo_id IN (SELECT id FROM baz)
```
Yet the actual output is `SELECT bar.id, bar.attr FROM bar WHERE bar.foo_id IN (SELECT id FROM baz)`, without the CTE, whether compiling the statement with a specific dialect or the default "StrCompiler".

Reading the documentation again and in particular this note:

Had me think the `TextAsFrom` is maybe still not behaving exaclty like "full blown" SELECT statement but more like a FROM clause as its old name suggested. From there I managed to find a work around (see code below). But I wonder if this is really working as intended?
