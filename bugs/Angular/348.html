Title

Router: canActivateChild can't find guard provided in own module

Description

**Current behavior**

 

When trying to use a children guard (canActivateChild) in the same module where the guard is provided, the guard fails to be injected.

`Error: No provider for ChildGuard!`

If we provide the guard in a parent module, it works.
If we provide the a canActivate guard in the same module where it is used, it works.

**Expected behavior**

 

The guard should be injected and work like the canActivate guard.

**Minimal reproduction of the problem with instructions**

 

Demo can be found here: ~~[URL] [URL]
1. Click on "Go to route with child guard" button.
2. See error in console: Error: No provider for ChildGuard!

What happens:
- when click on the button, router navigates to /admin
- AdminModule provides ChildGuard service
- Default route in AdminModule (empty) uses ChildGuard `canActivateChild: [ChildGuard]`

**What is the motivation / use case for changing the behavior?**

 

I have to protect all the child routes using a guard that is only known by that module, loaded by lazy-mode.
