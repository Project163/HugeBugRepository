Title

WebGL2 fallback: A possible typo in a function name `gerDrawingBufferSize`

Description
### Description

Recently I found that one of the TSL textures fails when WebGL2 fallback is used: [Link: Water drops]. It works fine with WebGPU. The error message is:

```
Uncaught TypeError: this.backend.gerDrawingBufferSize is not a function
```

#### The good news:

I was able to track it down to the function `copyFramebufferToTexture`, which calls `this.backend.gerDrawingBufferSize().y`. Note that the called function starts with `ger`. It might be a typo and the correct name could be `getDrawingBufferSize` with `get` instead of `ger`.

[URL]


#### The bad news:

This TSL texture worked fine when it used r168. For the time being I am not able to identify what part of my code is causing the execution to go via `gerDrawingBufferSize`. Also, I am unable to make a minimal reproduction demo that illustrates the issue, I tried, but the minimal demo works fine. 

In any case, if `ger` is a typo, it should be fixed, even if it is not clear when it is executed by "Water drops".


### Reproduction steps

1. Use WebGL2 fall-back
2. Open the texture here: [Link]
3. Look in the console for error messages
