Title

Global ignore doesn't work at end of file

Description
Commit   broke global ignores for pylint violations at the end of the file. With pylint 1.7.5, the violation is ignored as expected. The patch contains a logic bug. In the case below, ``is_message_enabled`` is called with ``line = 3``, but ``max_line_number == 2``. 

### Steps to reproduce
```
$ cat > example.py << EOF
l = [
    None
        ]
EOF
... [Log Snipped] ...
-----------------------------------
Your code has been rated at 0.00/10
```

### pylint --version output
```
pylint 2.0.0.dev2
astroid 2.0.0.dev4
Python 3.7.0rc1 (default, Jun 12 2018, 12:42:02) 
[GCC 8.1.1 20180502 (Red Hat 8.1.1-1)]
```
Discussion
- Notes:

* ~~`astroid` node `.tolineno` and `.fromlineno` counts starting from zero~~
* tokenizer `TokenInfo` class line `start` attribute counts starting from 1 (excluding the encoding token)
* pylint reports line number starting from 1
* astroid tolineno and fromlineno count starting from 1, but tolineno isn't always accurate

~This causes some fun off by one errors all over the place when using `add_message` with tokenizer checkers, and makes add_message think the line is past the end of the file and auto enabling the message for some ast corner case~

~I think the best solution is to add by one in the case of astroid `line=node.tolineno`/fromlineno so users get the correct line number, keep tokenizer line report values the same, and then consider one based indexing in `add_message` so that the last line isn't ignored + document~
