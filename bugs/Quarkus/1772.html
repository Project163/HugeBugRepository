Title

`Redis host not configured` exception when using certain extensions with devservices disabled (using custom TestResources)

Description
### Describe the bug

After [URL] I receive `Redis host not configured` exception 
In one old project we are using relatively large set of extensions and custom TestResources with devservices disabled.

I was able to trim down the set of extensions that trigger the trouble ++ one needs to specify `quarkus.devservices.enabled=false`.

```
xml
     
       io.quarkus 
       quarkus-redis-client 
     
... [Log Snipped] ...
       quarkus-smallrye-reactive-messaging-kafka 
     
```


### Expected behavior

Tests pass

### Actual behavior

`io.quarkus.runtime.configuration.ConfigurationException: Redis host not configured - you must either configure 'quarkus.redis.hosts` or 'quarkus.redis.host-provider-name' and have a bean providing the hosts programmatically.`

### How to Reproduce?

 - get [URL] (see commit [URL]
 - run `mvn clean verify -Dquarkus.platform.group-id=io.quarkus -Dquarkus.platform.version=999-SNAPSHOT -Dquarkus.devservices.enabled=false`

Discussion
- I think there are two problems in this:
1/ There is no default value for `quarkus.redis.host` as @afalhambra mentioned this should be removed:  to be double-checked by @cescoffier 
2/ The smallrye-kafka extension creates a redis client (unused if not necessary) but that triggers the creation of a redis client by config. In the fix the smallrye-kafka extension needs to create the redis client only when it is necessary by config.
- having a default value to `quarkus.redis.host` is problematic, as we need to check if the user was expecting it (no value because my redis is running on the default port) to know if we need to start a dev service.
