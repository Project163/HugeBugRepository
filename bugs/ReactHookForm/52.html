Title

Dynamically added radio group throws exception on the second validation attempt

Description
**Describe the bug**
My form has a radio group. I hit submit and the validation works fine. If I remove the radio group from the form or it changes because I load a new set of options based on some condition, when I try to submit and validate again there is an uncaught exception and validation fails.

Example here: [URL]

**To Reproduce**
Steps to reproduce the behavior:
1. Go to [URL]
2. Open dev tools
3. Press Submit button and you will see "required" validation error message
4. Change the dropdown to "No topic"
5. Press submit
6. You will not see any errors since the form is valid
7. Change the dropdown back to "Show topic"
8. Press submit and you will get an exception when it tries to validate 

**Codesandbox link**
[URL]

**Expected behavior**
The same "required" validation error should appear and there is no exception 

**Desktop (please complete the following information):**
 - OS: iOS mac pro
 - Browser chrome
 - Version 78.0.3904.108

**Additional context**
I have done some initial investigation and part of the problem is in `useForm.ts line 117`:

```
const validateFieldCurry = useCallback(
    validateField.bind(
      null,
      fieldsRef.current,
      nativeValidation,
... [Log Snipped] ...
    [],
  );
```
This is a memoized callback hence the value for `fieldsRef.current` supplied to `validateField` will never update when `fieldsRef.current` has changed.
