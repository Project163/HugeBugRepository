Title

json + verbose non tty fails TypeError: expected a character buffer object

Description
# json + verbose - tty
## TypeError: expected a character buffer object

There seems to be something dodgy with the json + verbose switches when combining them and piping or redirecting output.
## Tested on
- Mac OS X 10.8.2 
- Python 2.7.2 
## Debug output:

```
$ http GET [URL] -j -v --debug | cat
HTTPie 0.3.0
HTTPie data: /Users/insperion/.httpie
Requests 0.14.2
Pygments 1.5
... [Log Snipped] ...
    buf.write(chunk)
TypeError: expected a character buffer object
```
## Without debug:

```
$ http GET [URL] -j -v| cat

http: error: TypeError: expected a character buffer object
GET / HTTP/1.1
Host: api.github.com
Accept-Encoding: gzip, deflate, compress
Accept: application/json
User-Agent: HTTPie/0.3.0

```
## Redirecting is the same:

```
$ http GET [URL] -j -v > tt.out

http: error: TypeError: expected a character buffer object
$ cat tt.out
GET / HTTP/1.1
... [Log Snipped] ...
Accept: application/json
User-Agent: HTTPie/0.3.0
```
## Normal tty output

Output not being piped or redirected works as expected.

```
$ http GET [URL] -j -v
GET / HTTP/1.1
Accept: application/json
Accept-Encoding: gzip, deflate, compress
Host: api.github.com
... [Log Snipped] ...
    "user_url": "/users/{user}"
}
```

This also doesn't happen with explicitly setting the Accept header
