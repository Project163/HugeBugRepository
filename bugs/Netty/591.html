Title

@Sharable CombinedChannelDuplexHandler usage problems

Description
Netty version: 4.1.8.Final

@Sharable CombinedChannelDuplexHandler implementation shares ChannelHandlerContext among different connections. Problem could be reproduced with [Link: this code] _(compile and run with netty-all-4.1.8.Final.jar in classpath)_. Output will differ from time to time.

For example I get:
 
io.netty.channel.CombinedChannelDuplexHandler$1@3e234509: [1-1]
io.netty.channel.CombinedChannelDuplexHandler$1@3e328346: [1-2]
io.netty.channel.CombinedChannelDuplexHandler$1@3e328346: [2-1][2-2][2-3]
io.netty.channel.CombinedChannelDuplexHandler$1@3e328346: [2-4]
io.netty.channel.CombinedChannelDuplexHandler$1@3e328346: [1-3][1-4]
 
but expect that `[1-*]` strings will be handled by the first handler (`3e234509`).
Discussion
- @errandir `CombinedChannelDuplexHandler` implementation can't be `@Sharable` as it contains state. Let me ensure we throw an exception if someone tries to make a sub-class of `CombinedChannelDuplexHandler ` `@Sharable`.

Thanks for reporting
- @normanmaurer There is real lack of such exception and even `CombinedChannelDuplexHandler` comment.
