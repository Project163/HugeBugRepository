Title

URL StandardParameterParser not working correctly with QueryString

Description
If a URL GET parameter is parsed by the  StandardParameterParser which actually splits on '&' and '=' , the result is not correct if the parameter value includes a '=" as value. 
With SAML this is quite often the case as SAML requests are BASE64 encoded.

Digging into the problem it turned out that the Querystring is read several times either in or in HttpMessage The problem is generated by 

[URL]
[URL]

...getURI().getQuery();

which should be 

...getURI().getRawQuery());

Example SAML Request with an Encoded "=" at the end:

[URL]

Querystring decoded looks like:
SAMLRequest=fZHbTsJAEEB/ZbPvbRcM2kwoptCYNCohQIzhbW1X2aR7cWeK6Ne7gBjjA49zPWcyY/RQ9rS1S/XeKyS2N51FQF/wPlhwEjWClUYhUAOr8vEBhqkAHxy5xnWclYgqkHZ25iz2RoWVCjvdqNq2al/wIWd1VfD59Ob+2i2JYojYxyqStBTrYjBKRJ4M8rXIYTQCcbXhbBHcTrcqzCO44JvnumKVMo6tFpw9qYARF0dTwSdjlHDcGM7m8rK5PPvyyZbIQ5Y1bzrBk3Tif8ApStMN08YZyMWx40Xb7Guv21tXTMfZLzUKeDho1tXCdbr5ZGXXuY9ZUJKiOoVecXbngpF02euQ0W3yemwFfzgSSVmKJ2b/EKfM369NvgE=

The parser(splitting parameters at '=') would generate an incorrect value of SAMLRequest missing the last '='. Besides being incorrect the base64 decoding will fail due to missing padding.
