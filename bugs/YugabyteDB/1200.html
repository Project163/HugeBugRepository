Title

[YSQL] Missing writes in batched execution with a concurrent DDL

Description
Jira Link: [Link: DB-12746]
### Description

### Issue

Commit fa8a1382c0df solves the missing writes issue in batched execution but for transaction conflicts with DMLs. When there is a concurrent DDL that causes schema mismatch error, the retry code path is different. Let's handle this code path as well.

### Example

Session 1: bunch of UPDATE t SET v = 2 WHERE k = ...
Session 2: ALTER TABLE t ALTER COLUMN v SET NOT NULL

An intermediate update in session 1 is retried due to a schema mismatch error and only that update is in effect.

In the absence of table locks, the schema version changes and causes a schema mismatch error. Currently, we retry schema mismatch errors when possible. We also incorrectly retry in batched execution case. We should avoid doing that.
