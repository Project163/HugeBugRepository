Title

ngc codegen quotes properties, which breaks closure compiler

Description
Say I configure my routes with

```
export const routes: Routes = [
  {path: 'search', redirectTo: '/'}, {path: '', component: SearchVideos},
  {path: 'upload', component: UploadVideos}
];
```

ngc produces an ngfactory.ts containing:

```
get _ROUTES_40():any[] {
      if ((this.__ROUTES_40 == (null as any))) { (this.__ROUTES_40 = [[
        {
          'path': 'search',
          'redirectTo': '/'
... [Log Snipped] ...
    return this.__ROUTES_40;
  }
```

note that `redirectTo` got quoted as `'redirectTo'`

When closure compiler renames the `redirectTo` property to some short name, it won't rename the one in the ngfactory.ts because it's quoted.
Discussion
- We should do whatever the user wrote is put into the generated code.
I.e. if the user used `{path:...}` we should use `path`, if the user used `{'path': ...}` we should use `'path'`.
- I did update the metadata collector to preserve quotes: [URL]

But @tbosch thought more about places in the expression parser that would need to change to match the semantics. Instead we'll just stop quoting properties in codegen map literals.
