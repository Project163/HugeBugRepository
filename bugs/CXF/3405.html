Can't tell CXF to use a custom certstore for SSL certificate check

Description
In my cxf.xml, I declared a custom certstore because my server's certificate is not considered valid by the JDK: 
  
 
<beans xmlns= "http: //www.springframework.org/schema/beans"  xmlns:xsi= "[URL] xmlns:sec= "[URL]

- Hi, 

 In your scenario you use https to retrieve the wsdl, so you  need read this  , more specifically, this part 
  
 
If your service endpoint uses an SSL WSDL location (i.e.,  "https: //xxx?wsdl" ), you can configure the http conduit to pick up the SSL configuration by using a hardcoded http conduit name of  "{[URL]
 
  

 so the <http:conduit name="...."> should be like 

  
 
 <http:conduit name= "{http: //cxf.apache.org/}TransportURIResolver.http-conduit" > 
 
  

 Cheers 
Freeman

- Hi  ffang ,  michelsaumon , 

 I investigated this issue as I remember running into it before. The wiki is actually incorrect (I have since updated it). The correct conduit name is: 
  
 
<http:conduit name= "{http: //cxf.apache.org}TransportURIResolver.http-conduit" > 
 
  
 Note there is no "/" at the end of the namespace as in the previous example. I've added a test-case to CXF to check that it works OK.
