Title

Form validation throws deprecation messages if no rules are set

Description
This is a (multiple allowed):

* [x] bug
* [ ] enhancement
* [ ] feature-discussion (RFC)

* CakePHP Version: 3.6.1

### What you did
I have a modelless form which now contains the new 3.6.x `validationDefault` function (replaced the old protected `_buildValidator` function)
```
public function validationDefault(Validator $validator) {
    return $validator;
}
```

### What happened
[Image: image]

It raised a deprecation message because of this line right here -> [URL]

Cake actually calls a deprecated function itself because I didn't explicitly set any validation rules. The form itself is very simple, it doesn't need any validation rules.

Even if I delete the function `validationDefault` from my modelless form it still raises the same deprecation message

### What you expected to happen
not raise any deprecation message 😅 

cc @jeremyharris - [URL]
Discussion
- This is a tricky one. The call to deprecated method `validator()` was added in #11857 in an attempt to ensure backward compatibility. Though the usage example of overriding `validator()` to add validation is kinda wrong itself. As per the docs the developer was supposed to use the `_buildValidator()` hook to configure the validator.
- Only emitting the deprecation warning when the subclass implements the `validator()` hook might let us work around this issue.
- Pull request open now.
