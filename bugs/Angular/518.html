Title

elements do not render to the DOM following a `ng-container`

Description
## I'm submitting a...
 
  
[ ] Regression (a behavior that used to work and stopped working in a new release)
[x] Bug report   
[ ] Feature request
[ ] Documentation issue or request
[ ] Support request => Please do not submit support request here, instead see [URL]
  

## Current behavior
 
elements following an ng-container element within a component with an attribute selector do not render to the DOM

## Expected behavior
 
all elements in the component template should render to the dom

## Minimal reproduction of the problem with instructions
 


    @Component({
      selector: '[table-body-component]',
      template: `
         
           
             {{datum.row1}} 
           
           
             {{datum.row2}} 
           
         
         
           missing row 
         
      `,
      styles: ['table, tr, td, th {border: 1px solid black} table {border-collapse: collapse}']
     })
     export class TableBodyComponent {
        @Input('table-body-component')
        datum;
      }


[URL]

In the aforementioned plunker, the tr element with content of 'missing row' does not get rendered in the template for TableBodyComponent.  If you were to not wrap any of the content in a ng-content element, all of the rows would show appropriately.

## What is the motivation / use case for changing the behavior?
 

I have a use case where there is some complicated logic for tr elements that use varying colspan and rowspan which I want to keep separated into it's own component to keep the code clean and readable and also necessitates the use of ng-container elements to handle the complexity of logic.  

In my use case there actually end up being multiple tbody elements in the table that are repeated using the NgForOf directive.  For this use case to work, I need to use an attribute selector for the component representing the contents of the tbody so that the parent element of the tr elements is the tbody.
