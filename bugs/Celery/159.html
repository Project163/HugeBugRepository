Title

_maybe_close_db_fd in Django fixups does not correctly handle all exceptions

Description
# Details

Inside [Link: `_maybe_close_fd`], Celery attempts to catch exceptions relating to closing the file descriptor. Currently it catches [Link: `django.db.utils.InterfaceError`].

However, when using `psycopg` or `psycopg2`, the exception thrown is _not_ `django.db.utils.InterfaceError`, it is `psycopg2.InterfaceError` or a `psycopg.OperationalError`:

```
python
In [1]: import django.db
In [2]: connection = django.db.connections.all()[0]
In [3]: connection.connection 
Out[3]:  >
... [Log Snipped] ...
... 
psycopg.OperationalError: the connection is closed
```

Psycopg2 throws this from [Link: this macro], called from [Link: this C function] when `.fileno()` is accessed.

This means that if you have a connection that is already _closed_, [Link: on_worker_process_init] will throw an exception whilst attempting to close the connection:

```
Signal handler  >> raised: InterfaceError('connection already closed')
```
