Title

--doctest-modules runs __main__ files

Description
- [x] a detailed description of the bug or suggestion
- [ ] output of `pip list` from the virtual environment you are using
- [x] pytest and operating system versions: pytest 5.4.1, MacOS
- [ ] minimal example if possible

As per this [Link: SO question], pytest will run `__main__.py` files when passed `--doctest-modules`, even though it avoids them when collecting tests without that flag.

Is that intentional?
Discussion
- pytest normally avoids `__main__.py` files not because of any specific `__main__.py` handling, but simply because the name `__main__.py` doesn't match the `test_*.py` or `*_test.py` patterns pytest looks for.

That said, `__main__.py` files are typically not considered modules, and even `multiprocessing` doesn't expect `__main__.py` files to have an `if __name__ == '__main__'` guard. Importing `__main__.py` is questionable behavior. Plus, `--doctest-modules` already avoids `setup.py`, which is a very similar case.
