Title

[FATAL] Potential race-condition between compactions and snapshots ends up deleting newly compacted file

Description
Found a FATAL file in one of our nightly CI/CD:
```
Log file created at: 2019/02/24 03:09:26
Running on machine: yb-itest-gsched-41cd20bbd3-20190224-024500-n6
Log line format: [IWEF]mmdd hh:mm:ss.uuuuuu threadid file:line] msg
F0224 03:09:26.893852 17162 tablet.cc:784] T   P  : Failed to write a batch with 1 operations into RocksDB: IO error (yb/rocksdb/util/env_posix.cc:191): /mnt/d0/yb-data/tserver/data/rocksdb/table- /tablet- /000021.sst: No such file or directory
```

Seems like the RemoteBootstrap process ends up checkpointing RocksDB, which ends up conflicting with a concurrent compaction.

Starting the RB process:
```
1204 I0224 03:09:22.540403 17113 remote_bootstrap_service.cc:161] Beginning new remote bootstrap session on tablet   from peer   at  :43188: session id =  - -493.942s
```

```
I0224 03:09:22.547974 17126 compaction_job.cc:909] T  : [default] [JOB 3] Generated table #21: 1677 keys, 102458 bytes
```
