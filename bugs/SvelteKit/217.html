Title

fetch inside a server hook throws error instead of forwarding request to proxied API

Description
### Describe the bug

I have an app served behind a reverse proxy. Any call to `/api` gets forwarded to the API server, the others are forwarded to sveltekit.

Given an relative API endpoint `/api/endpoint`:

- Calling `event.fetch` inside a `load` or action handler works fine
- Calling `event.fetch` directly inside the `hooks.server.ts` gives a 404 error without making an HTTP request (I DON'T have any route on `/api/endpoint/+server.ts`, as it should be forwarded to the API server by the proxy) 

When calling `event.fetch` inside a `load` function I can see by logging `event.url.href` that the request to the same endpoint pass through `hooks.server.ts` just fine.

I think the issue is caused by fetch that shorts internal requests to their handler as said in the ([Link: docs]):


It seems to do that only if `fetch` is called inside `hooks.server.ts`, should be the same behaviour regardless of where `fetch` is called?

As a solution maybe sveltekit should short-hand requests to an handler only if the route exists?

- domain.com/api - Proxied API server
