Title

Silent integer overflow when querying SQLite DB as Any DB

Description
### Bug Description
When opening a SQLite DB as an `Any` DB, integers returned from queries are decoded as 32bit integers since SQLite calls everything an `INTEGER`, but stores it with up to 64bit width. This leads to silent overflows/invalid decoding.

### Minimal Reproduction
[Link: I've implemented a minimal reproduction here.] The relevant part:

```
rust
let db = AnyPool::connect("sqlite::memory:").await?;
let mut connection = db.acquire().await?;

// 4294967297 = 2^32
... [Log Snipped] ...

assert_eq!(number, 4294967296);
```

This panics with:

```
assertion `left == right` failed
  left: 0
 right: 4294967296
```

### Info
* SQLx version: `0.7.4`
* SQLx features enabled: `"runtime-tokio", "any", "sqlite"`
* Database server and version: SQLite (`libsqlite3-sys v0.27.0`)
* Operating system: NixOS/Linux
* `rustc --version`: `rustc 1.76.0 (07dca489a 2024-02-04)`

### Workarounds

For anyone looking for a workaround: just cast the integer to `TEXT` in SQL and then parse it on the rust side. I'm currently doing this in one of my weekend hack projects: [URL]
