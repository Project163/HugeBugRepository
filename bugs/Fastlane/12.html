Title

Supply and Screengrab can create inconsistent locale directory names in Android metadata

Description
🔑
### New Issue Checklist

- [x] Updated fastlane to the latest version
- [Link: x] I have read the [Contribution Guidelines]

### Issue Description

I've noticed a discrepancy between the locale directory names that are created after running `fastlane supply init` and those that are created after running `fastlane screengrab`. This only occurs with languages that have no country code in the locale name. For example, here are the resulting directory names for each tool for an app with a Google Play listing that supports Arabic, English (GB), German (DE) and Slovak:

| Language | Supply Directory Name | Screengrab Directory Name |
| - | - | - |
| Arabic  | ar | ar- |
| English (GB)  | en-GB | en-GB |
| German (DE)  | de-DE | de-DE |
| Slovak  | sk | sk- |

As you can see, the Screengrab directory names for the locales that don't contain a country code still have the dash ("-") appended to the end. This causes problems when updating existing screenshots since the original metadata that Supply created will be contained within the directory without the "-" at the end (e.g. **"ar"**), and any newly generated screenshots will be automatically placed in the directory with the "-" at the end (e.g. **"ar-"**). This inconsistency can be manually resolved, but that's not ideal if screenshots are updated with an automated job.

It looks like this can be fixed by checking the country code string in the `localeToDirName()` in `screengrab/screengrab-lib/src/main/java/tools.fastlane.screengrab/FileWritingScreenshotCallback.java:107`. I'm happy to submit a PR for this fix, but I first wanted to make sure this wasn't intentional behavior, and of course I'd like the feedback of those who are more familiar with the project on whether or not I've diagnosed this issue properly.
