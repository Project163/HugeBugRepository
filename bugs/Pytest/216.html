Title

Parametrized test fails with fixture named "request"

Description
Originally reported by: **Veeti Paananen (BitBucket: [Link: veeti], GitHub: [Link: veeti])**
- Bitbucket: [URL]

---

```
python
import pytest

@pytest.fixture
def request():
... [Log Snipped] ...
    # test stuff
    assert True
```

Fails with:

```
    def get_direct_param_fixture_func(request):
E       AttributeError: 'int' object has no attribute 'param'
```
Discussion
- There should be a `RuntimeError` or something similar in this case, explaining that the `request` fixture cannot be overridden.
- are there other restricted names?
- i think "request" is the only real restriction as it serves a purpose for interactions between test or fixture functions and the pytest core.  Treating "request" as an illegal name for fixture functions is possible but then again, it's probably used here and there and some might "decorate" the internal request fixture to provide more attributes.  Maybe we could generate a warning and then outlaw it with pytest-3.0 or so.
- We should try to do this in time for 4.0
