Title

Timer in GWT backend stacks up events

Description
I believe the Timer is incorrect at the moment.
What will reproduce the issue is setting the FPS very high, causing an increasing framedrop.

The scheduleRepeating basically is a setInterval, and it seems that can stack up according to:
[URL]
Some confirmation on this would be nice.
There is also a fix written for setInterval there, I'm not sure it works.
Either way there's some documentation here as well:
[URL]

requestFrame seems the new way to go, and if WebGL is supported, that should probably work as well. There's also ways to have it fallback to setInterval.

Is there a specific reason a setInterval is used?

In GWTApplication:

I

```
new Timer() {
        @Override
        public void run () {
            try {
                mainLoop();
... [Log Snipped] ...
        }
    }.scheduleRepeating((int)((1f / config.fps) * 1000)); //setInterval
```
Discussion
- I'll write a patch that uses AnimationScheduler
- For reference the proper way to do it without requestAnimFrame is with a self referencing and starting timeout. This way one frame may take twice as long but never longer. With setInterval if a frame cannot start on time, it is rescheduled, not discarded and goes on a pile afaik.
