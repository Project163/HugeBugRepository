Title

Inconsistent router cache behavior

Description
### Link to the code that reproduces this issue

[URL]

### To Reproduce

1. `npm run dev`
2. Open `[URL] 
3. Click "Go to page /b" link on Page A
4. Click "Go to page /a" link on Page B
5. Wait for more than 30 seconds
6. Click "Go to page /b" link on Page A
7. Click "Go to page /a" link on Page B
8. Click "Go to page /b" link on Page A

### Current vs. Expected behavior

### Current behavior

Page component corresponding to `/b` is executed on server when the 8th step navigation.

And as shown in the following video, once this situation occurs, all subsequent `/a` and `/b` transitions result in an RSC request.

[URL]

It seems that router cache for `/b` keeps "stale" after rerender of the 6th step.

### Expected behavior

Fresh router cache for `/b` (which is cached with the 6th step navigation) should be used when the 8th step. And the `/b` component should not executed in the 8th step.

- [X] I verified that the issue exists in the latest Next.js canary release

- There seems to be an issue when the `prefetch` of the ` ` component is not set.

To be precise, the problem seems to be when the state of `PrefetchKind` is `auto`. The logic in the prefetch reducer that updates the `lastUsedTime` and `prefetchTime` by setting the value of `state.prefetchCache` throughout the code is only in the prefetch reducer. However, when in `auto` mode, the conditional does not reach the prefetch action in the Link component.

Therefore, from 30 seconds to 5 minutes after the first update within the navigate action, i.e. the navigate reducer, which is triggered on the click event of the ` ` component, the `getPrefetchEntryCacheStatus()` value is evaluated to `PrefetchCacheEntryStatus.stale`, and it is continuously refetched, and only after 5 minutes does it become `PrefetchCacheEntryStatus.exipired` and a new `state.prefetchCache` is assigned.

This is a wrong action and I think we need some logic to update the `prefetchTime` once the cache with the `PrefetchCacheEntryStatus.stale` value is used.

Of course, this can be solved with ` `, but that's not possible in a development environment, and I'm actually having [Link: this difficulty] because of the stale refetch method.
 
If I'm having trouble because I'm using Next.js in a way it wasn't intended, I'd like some solid guidelines.
