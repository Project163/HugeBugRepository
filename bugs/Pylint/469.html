Title

missing comma in pylintrc "enable" section does not cause a parsing failure

Description
### Steps to reproduce
1. create a `pylintrc` file with an `enable` argument like:

```
enable=
  trailing-whitespace,
  missing-final-newline,
  eval-used,
  exec-used,
... [Log Snipped] ...
  reimported,
  parse-error
```

2. run `pylint`

### Current behavior

`pylint` runs a full report, but the checks below the line without the trailing comma are not checked.


### Expected behavior

`pylint` throws an error while parsing `pylintrc`.


### pylint --version output

Encountered this issue in py27 and py35:


Discussion
- I've been testing how pylint handles enabling unknown checks:
- in `pylintrc`: silently ignored
- passed via a CLI argument `--enable foo`: silently ignored
- in source comment `# pylint: enable=foo`: E0012: bad-option-value

Shouldn't all of the above result in an error?
