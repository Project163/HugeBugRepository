Title

Make bootstrap retry

Description
We ran into a situation where we had rpc_timeout set to 1 second, and the node needing to compute the token took over a second (1.6 seconds). The bootstrapping node hangs forever without getting a token because the expiring map removes it before the reply comes back.
Discussion
- I have a patch for this I'll be adding within the next day. I make ExpiringMap support custom timeouts per object, and make bootstrap getToken retry, while exponentially increasing the timeout until retries is met.
- I think the retry logic is a distraction here. If it doesn't work the first time because of anything other than "we didn't wait long enough" (i.e. it errored out) it's not likely to magically unbreak for the second. 

 Suggest just giving it a long retry to begin with.
