Title

[bug] Rust deserialization of raw ipc fails

Description
### Describe the bug

`tauri::ipc::InvokeBody::deserialize` fails on raw ipc response. 
When receiving raw data  the function fails with: `Error("expected ident", line: 1, column: 2)`.

The function uses  `InvokeBody::Raw(v) => serde_json::from_slice(&v)` to get Rust type from raw bytes. 
 From `serde_json` [Link: documentation] `serde_json::from_slice()` is used to deserialize raw bytes of **JSON text**. 

Hence the deserialization error is that `serde_json::from_slice()` expects a json string starting with a double quote which is not what we give it.

### Reproduction

This happens when trying to parse input from the plugin `fs:read_file`. 
Recent  [Link: PR#1251] make use of raw IPC streaming for read/write file.  

Hence getting response from `fs:read_file` now returns an `InvokeBody::Raw` which is not properly deserialize with `InvokeBody::deserialize(self)`.

### Expected behavior

`tauri::ipc::InvokeBody::deserialize` should not panic on raw data. 

I have no clear idea on how to produce a robust function that can produce generic types from raw bytes.
