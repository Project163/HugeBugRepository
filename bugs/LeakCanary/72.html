Title

Plumber: InputMethodManager.mCurRootView fix doesn't work on child windows

Description
Leaktrace:

```
┬───
│ GC Root: System class
│
├─ android.view.inputmethod.InputMethodManager class
│    Leaking: NO (InputMethodManager↓ is not leaking and a class is never leaking)
... [Log Snipped] ...
│    ↓ ContextWrapper.mBase
╰→ com.squareup.ui.main.MainActivity instance
```
Discussion
- Investigation showed that this can happen when the IMM held root view belongs to a child window of the window of the destroyed activity. For example, when opening a dialog that contains an EditText, the root view of the window of that dialog will be held by the IMM, and our fixing code did not anticipate this.
- Fix looks something like this:

```
kotlin
          val rootView = mCurRootViewField[inputMethodManager] as View?
          val isDestroyedActivity = rootView != null &&
            activity.window != null &&
            activity.window.decorView === rootView
... [Log Snipped] ...
            mCurRootViewField[inputMethodManager] = null
          }
```

with

```
kotlin
  private val Context.activityOrNull: Activity?
    get() {
      var context = this
      while (true) {
... [Log Snipped] ...
      }
    }
```
