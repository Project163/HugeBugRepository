Title

[Console] Command executed even when it is ambigous

Description
When I launch 'php app/console doctrine:', it executes the doctrine:ensure-production-settings command. But when I type 'php app/console doctrine' or 'php app/console doctrine:s', suggestions are properly displayed.

I thought it was because it's ending with an ':', but I don't have the issue for other namespaces where I have multiple commands (eg. 'router:' works fine).

Do you know why it happens?
Discussion
- It looks like it considers it unambiguous when there is only 1 command in the namespace, even if there is subnamespaces. This looks like a bug
- I've took a look at the code but I don't understand why suggestions are handled by namespaces? It looks over-complicated to me.

When a command is not found, wouldn't be possible to just count the command names 'starting with' what is typed, considering ':' as a regular character?

For example I have a 'faker:populate' command, when I type 'faker:', the command is executed, but when I type 'faker', I have an error message with only one suggestion, it looks weird.
- @bamarni they are handling by namespace, because it allows the feature of shortened commands to be more useful (as soon as it is not ambiguous, it can be used).
for instance, in my project, I can run `doctrine:migration:migrate` with `d:mi:m` (or anything including more chars for each part), making it shorter as there is no autocompletion
- oh I didn't know about this feature :)
