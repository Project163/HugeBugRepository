Title

Do not flush on truncate if "durable_writes" is false.

Description
CASSANDRA-7511   changed truncate so it will always flush to fix commit log issues.  If durable_writes is false, then there will not be able data in the commit log for the table, so we can safely just drop the memtables and not flush.
Discussion
- Patches for 2.0 and 2.1 to put back the "just throw the memtables away" code if durable writes is false and auto snapshot is false.
- I'd rather we did not reintroduce the 'renew memtable' method, as it is inherently dangerous. If we are to do so, it should have clear danger warnings around it, OR it should explicitly clear the CL of any records it contains.
- committed with an assert in 2.0 that renewMemtable is only called with durable_writes false
- Patch to be applied to trunk to fix the tests that weren't updated on merge for   CASSANDRA-6968
