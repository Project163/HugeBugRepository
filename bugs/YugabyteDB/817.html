Title

[DocDB] log-dump should be able to print out decoded UUIDs

Description
Jira Link: [Link: DB-4259]
### Description

We currently cannot print out decoded UUIDs (txn-id) and hybrid times for operations in log-dump

`./build/latest/bin/log-dump {path/to/walfile} --print_entries=pb`

produces output like:
```
29.3884@ 	REPLICATE UPDATE_TRANSACTION_OP
	id { term: 29 index: 3884 } hybrid_time:   op_type: UPDATE_TRANSACTION_OP committed_op_id { term: 29 index: 3884 } monotonic_counter: 0 transaction_state { transaction_id: "1\366*\022\215\221@\361\205m\315\317\322\306Vg" status: APPLYING tablets: "abcdefghij..." commit_hybrid_time:   sealed: false aborted { } }
```
Discussion
- `log-dump -print_entries=pb  ` will print entries in protobuf text format
- @ttyusupov nice -- i think it would be nice to still decode UUIDs and hybrid times then
- As @ttyusupov said, when using the option `--print_entries=pb`, the WAL entry is being printed using the `DebugString()` of `google::protobuf::Message` class. Which prints the object without decoding the fields of type `bytes` and the `transaction_id ` is of type `bytes` and hence it is printed this way.
In this case, maybe we cannot use the `DebugString()` of protobuf and instead have our own implementation for it which should traverse recursively all the fields/subfields in the `LogEntryPB ` object. The problem with that solution is that it will be coupled with the current structure of `LogEntryPB` message and any change on the message definition might cause the new function to break. I am not sure if this is the best way to move forward or you propose something else?
cc @rthallamko3
- So what @rthallamko3 and I concluded is that if we want to print the UUIDs in human readable format even in the case of choosing   `--print_entries=pb` we need to traverse ourselves the fields of the `entry` object and decode the UUIDs which takes us back to almost doing the same thing as with the option `--print_entries=decoded` (with the slight difference that maybe one field is not printed in the decoded option).
@robertsami : So my question is, why do we have these two different printing options? Maybe there is some context in the past that might be useful to know.
Thanks for your feedback.
