Title

Checks in setup() and teardown() are reported partially

Description
General background
===
I own a service which was designed for optimal write operations. Read operations are trickier, especially if there were many write operations since the last read operation. I try to test such a scenario using k6, as follows:
1. `POST` 100 commands using 10 vus and 100 iterations, check the response status for each (group `POST requests`)
2. `GET` once *after all `POST`s are done (group `GET request`)

Issue description
===
To accomplish the second part, I'm making the request in the `teardown` function and check the response status.

Expected result
===
1. Result set should be compiled of two groups:
1.1. `POST requests`: 100 checks
1.2. `GET requests`: 1 check
2. Total amount should be 101 checks

Actual results
===
1. Result set contains only the first group, 100 checks
2. Total amount is 101 checks (correct)

```
js
import { group, check } from "k6";

export function setup() {
    group("setup-code", () => {

```

```
   █ default-code
```
