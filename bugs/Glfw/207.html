Title

CMake build script doesn't check for XInput2

Description
For 3.3 on a Debian Buster machine without `libxi-dev` installed I'm seeing cmake succeed:

```
genpfault@machine:~/glfw/build$ cmake ../
-- The C compiler identification is GNU 8.3.0
-- Check for working C compiler: /usr/bin/cc
-- Check for working C compiler: /usr/bin/cc -- works
-- Detecting C compiler ABI info
... [Log Snipped] ...
-- Generating done
-- Build files have been written to: /home/genpfault/glfw/build
```

...but the subsequent build fails:

```
genpfault@machine:~/glfw/build$ make
Scanning dependencies of target glfw
[  1%] Building C object src/CMakeFiles/glfw.dir/context.c.o
In file included from /home/genpfault/glfw/src/internal.h:187,
                 from /home/genpfault/glfw/src/context.c:28:
... [Log Snipped] ...
make[2]: *** [src/CMakeFiles/glfw.dir/build.make:63: src/CMakeFiles/glfw.dir/context.c.o] Error 1
make[1]: *** [CMakeFiles/Makefile2:123: src/CMakeFiles/glfw.dir/all] Error 2
```

**Expected behavior**: The CMake build scripting should error out if it can't find XInput2 instead of letting the build fail.
Discussion
- Maybe check `X11_Xinput_FOUND` inside the [Link: `if (_GLFW_X11)` block] & tack on `X11_Xinput_INCLUDE_PATH` to `glfw_INCLUDE_DIRS` at the end?  Or maybe it's the `Xi` variants, not super clear from [Link: CMake's FindX11 doc].

Though oddly enough the `Xinput` variant has disappeared from the [Link: current (3.14.3 as of this writing) FindX11 doc].
