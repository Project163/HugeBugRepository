Discussion
- I did some digging with `lsof` but didn't find anything conclusive.
Java occurred the most time (~1000) but even the most FD-intensive process had only about 380 open, while the system max limit (`sysctl kern.maxfilesperproc`) is over 10K.
Rebooting the machine to see if it helps. :/
- We had a [Link: similar report on Mac Os X], but not for a test but for regular build target;

Using Bazel 0.4.4 the build of release.war fails with "Too many open files in system" on Mac OS 10.12.3.
Increasing kern.maxfiles from default 12288 to 16384 fixes this issue:

```
  $ sudo sysctl -w kern.maxfiles=16384
```
