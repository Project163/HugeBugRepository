Title

Dead Code Elimination doesn't understand null values

Description
Consider this block of code:

```
javascript
if (__ambidexRefluxDefinitionsPath) {
  var reflux = Reflux.instantiate(
    require(__ambidexRefluxDefinitionsPath)
  );
... [Log Snipped] ...
  );
}
```

If I use the DefinePlugin to declare `__ambidexRefluxDefinitionsPath` to be a string that points to a module location, the module loads as expected.  If I declare `__ambidexRefluxDefinitionsPath` to be `undefined`, webpack tries to import the whole world (treating the `require()` as an expression).  If I do `__ambidexRefluxDefinitionsPath: (variable) || false`, Dead Code Elimination kicks in and makes sure this block is ignored.

Can Dead Code Elimination be smart enough to know that falsy values (`""`, `undefined`, `false`) should cause the `if` block to be skipped?
Discussion
- If the expression of the `if`-block can be statically resolved, the block will be removed.

``` javascript
if (false) {
    // will be removed
}
```

```
javascript
var expr = false;

...

... [Log Snipped] ...
    // can't be resolved without running the code
}
```

When you use the `DefinePlugin`, it will replace all occurrences of `someVar` with the given expression.

``` javascript
new DefinePlugin({
    DEBUG: false
});
```

With that config this code

``` javascript
if (DEBUG) { ... }
```

becomes

``` javascript
if ((false)) { ... }
```

and thus will be removed.
- Right, but my point is that if, after DefinePlugin, you end up with this:

``` javascript
if ("") {
  require("");
}
```

it should be removed (it's falsy; hence, it can never run), but isn't.

I just looked at the options being passed into DefinePlugin, and they look like this:

``` json
{ 
  "__ambidexSettings":                      "...",
  "__ambidexRoutesPath":                    "\"/Users/bresimpson/Projects/tardis/routes.jsx\"",
  "__ambidexRefluxDefinitionsPath":         undefined,
  "__ambidexCallActionsForRouterStatePath": undefined 
}
```

which is generated by this:

``` javascript
{
  "__ambidexSettings":                        settings,
  "__ambidexRoutesPath":                      self._get("routesPath"),
  "__ambidexRefluxDefinitionsPath":           self._get("refluxDefinitionsPath"),
  "__ambidexCallActionsForRouterStatePath":   self._get("callActionsForRouterStatePath"),
}
```

After [Link: re-reading the DefinePlugin docs], I can see that it's trying to `JSON.stringify(undefined)`.  I'm guessing that when it doesn't get a string back, from that function, it drop the whole key,value pair.

That's all well-and-good, but it shouldn't happen silently.  If DefinePlugin gets something it doesn't know how to parse, it should throw a warning:

```
"Cannot stringify `"__ambidexRefluxDefinitionsPath":  undefined`; so it's been ignored."
```
- Also, it doesn't seem to be DCE-ing nulls:

``` json
{
    "__ambidexSettings": "…",
    "__ambidexRoutesPath": "\"/Users/bresimpson/Projects/tardis/routes.jsx\"",
    "__ambidexRefluxDefinitionsPath": "null",
    "__ambidexCallActionsForRouterStatePath": "null"
}
```
