Title

Fix edge cases for NULL typval_T Lists

Description
See vim/vim#768, later there will probably be more issues. Current list of known issues:
- [x] `map(v:_null_list, 'v:val')` returns 0. It should return v:_null_list. (#7447)
- [x] `filter(v:_null_list, 'v:val')` returns 0. It should return v:_null_list. (#7447)
- [x] `add(v:_null_list, 1)` returns 1, it should fail. Though with locked list it returns 1 as well, so probably it should fail and return 1. (#7695, #7708)
- [x] `extend(v:_null_list, [])` returns 0, it should fail. Again locked list returns 0 and fails. (#5119)
- [x] `setreg('x', v:_null_list)` crashes. Already reported. (#5835)
- [x] `setline(1, v:_null_list)` crashes. `append()` is fine. (#7708)
- [x] `v:_null_list == v:_null_list` returns 0. NULL list is not equal to itself! `is` operator works as expected. (#5119)
- [x] Same for `v:_null_list == []`: returns 0, should return 1. (Considered to be not a bug.)
- [x] `islocked('v:_null_list')` does not crash. Though it does not return 1. I am not sure whether this needs to be fixed because e.g. `islocked('v:throwpoint')` is also zero (as it is VAR_FIXED and not VAR_LOCKED).
- [x] `v:_null_list + any_other_list` is `E15: Invalid expression`, as well as `any_other_list + v:_null_list`. Since `list + list` produces a new list it should work like `[] + any_other_list`. (#5119)
- [x] `count([v:_null_list], v:_null_list)` returns 0 in place of 1. Guess same problem as with `==`. (#5119)
- [x] `extend([1], v:_null_list)` returns 0 in place of returning `[1]`. (#5119)
- [x] `inputlist(v:_null_list)` treats this as non-list. (#7708)
- [x] `writefile(v:_null_list, "/tmp/test.fname")` returns 0, but does not actually do anything, with empty list it creates empty file (and returns 0). (#7708)
- [x] `remove(v:_null_list, 0)` returns 0 in place of E684. (#7708)
- [x] `setqflist(v:_null_list)` returns -1 (and I guess, does nothing with quickfix list), same for `setloclist(1, v:_null_list)`. For empty list it returns 0. (#7708)
