Title

[xCluster] Missing pgschema_name during SetupUniverseReplication

Description
Jira Link: [Link: DB-6425]
When setting up replication for old tables created in versions prior to 2.13, we don't have the `pgschema_name` field. This can cause errors such as:
```
E0330 17:21:46.609167 26045 catalog_manager_ent.cc:4966] Found error while validating table schema for table  : Not found (yb/master/catalog_manager_ent.cc:4800): Could not find matching table for yugabyte.my_table
```

There is code that is supposed to check if this field is missing, and then go and fetch those values, but that doesn't seem to be working.
From my initial testing, this seems to be another issue with protobuf `has_` checks again. See `SchemaToPB` where we always run `pb->set_pgschema_name(schema.SchemaName());` , which would lead to our various `has_pgschema_name` to return true

[DB-6425]: [URL]
Discussion
- would be nice to also see if we can add more logging to make these errors clearer as to why the schema mismatch failed (ie print the schemas)
