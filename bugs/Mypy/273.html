Title

mypy does not recognize that result of type() is callable

Description
mypy does not recognize that the result of e.g. `type(1)` is callable. This leads to the following code to fail type checking, even though it is correct:

```
import argparse

parser =  argparse.ArgumentParser()

# No error from this
... [Log Snipped] ...

print(parser.parse_args()) # Both produce identical results (argument is read as an integer)
```
Discussion
- Here is a simple repro:
```python
from typing  import Type, Callable

x: Callable[..., int]
y: Type[int]

y = x # error: Incompatible types in assignment (expression has type Callable[..., int], variable has type Type[int])
x = y # error: Incompatible types in assignment (expression has type Type[int], variable has type Callable[..., int])
```
(Note, ``type(1)`` is inferred as ``Type[int]``)
I think this should be quite easy to fix by simply adding a corresponding case in ``subtypes.py``
- Alternatively, we could make ``type`` return callable type generated by ``type_object_type``.
- Changes to subtyping don't fully fix this. There is another problem:

```
python
from typing import Callable, TypeVar
T = TypeVar('T')
def f(x: Callable[..., T], y: T = None) -> None: return None
class A: pass
... [Log Snipped] ...
y: A
f(x, y)  # OK
```
(with strict-optional `None` is substituted with ` `)

I'd like to tackle this.

edit:
Another repro

```python
from typing import Callable, Type
def f(x: Callable[..., T]) -> T: return x()
class A: pass
x: Type[A]
f(x)  # E: Argument 1 to "f" has incompatible type Type[A]; expected Callable[..., None]
```

Both examples pass with `Type[Any]`.
