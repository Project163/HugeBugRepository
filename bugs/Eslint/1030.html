- Thanks for the report. This is probably caused by [URL] or maybe [URL]
- For what it's worth, I think your syntax is invalid based on the [Link: current version of the rest/spread spec]; trailing commas aren't allowed after rest properties, since no property could actually be added after it. (See [URL] for more info.)

``` js
class Foo {
  constructor ({
    bar,
    ...baz, // <-- trailing comma is not allowed here according to rest/spread spec
  }) {}
}
```

Does the problem go away if you remove that comma?
- ... [Middle Discussions Snipped for Brevity] ...
- I understand that you're using babel, but a trailing comma after a rest property is not valid syntax even according to the [Link: current proposal spec], because there is nothing that could follow a rest property.

The same thing applies with the already-standardized rest elements:

``` js
const [
  foo,
  ...bar, // <-- This is a syntax error in ES6
] = baz;
```

In order to be more compliant with the spec, babel's parser [Link: temporarily reported this as a syntax error], but it was [Link: later reverted] due to breakage.

The fix in this case is to simply remove the comma, so that it becomes valid syntax according to the Stage 3 proposal.
- Oh, I see! This I did not know!

So Babel is being more liberal than the standards in what it accepts. Interesting.
