Title

layout's nested blocks cannot be replaced sometimes

Description
Nested blocks cannot be replaced when their parent block has already been replaced by a layout.  In my example, base.pug's `content` block is totally wiped out but replaced by a new `content` block in layout.pug.  However, when page.pug tries to put markup in the `content` block, it is ignored.

## base.pug
```pug
block body
    block content
```

## layout.pug
```pug
extends ./base.pug
block body
  script(src="jquery.js")
  block content
    // blank page
```

## page.pug
```pug
extends ./layout.pug
block content
  h1 Main page content!
```

## Expected page.html
```html
  
 Main page content! 
```

## Actual page.html
```html
  
 
```

```bash
# Dependencies:
    "pug": "^2.0.0-beta11",
    "pug-cli": "^1.0.0-alpha6"
# Command:
node_modules/.bin/pug -P page.pug
```

When layout.pug's `content` block is renamed to `content2`, and page.pug replaces `content2` instead of `content`, it works.  This suggests that the `content` block introduced by layout.pug is not properly shadowing the `content` block declared in base.pug.
