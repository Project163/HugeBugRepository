Title

env doesnt work when passed to cli object as array of strings

Description
I am using version `0.7.3`
I am trying to call the cli interface with all the options correctly.

``` .js
               options:{
                    env:["node"],  // doesnt work
                    global:["test"]  // works
                }
```

All the options work but `env` doesn't work.

I think the reason is beacuse

```
.js
function createEnvironmentConfig(envs, reset) {

    var envConfig = {
        globals: {},
... [Log Snipped] ...
    return envConfig;
}
```

If you look at my comments in code above:
1. During the filter process it returns the correct value "node"
2. On this step the input parameter name is intialized to 0 and so `environments[0]` is `undefined`. I think this `forEach` staement is running on the Object.keys and not on the filtered values. confused?

I think i am passing in the `env` array correctly because the option says it has to be `[string]` that means array of strings.
Discussion
- Can you clarify what you mean by calling the cli interface with 

```
               options:{
                    env:["node"],  // doesnt work
                    global:["test"]  // works
                }
```

?

Because that looks more like an .eslintrc. And eslintrc works with objects, as shown in [URL]

```
{
    "env": {
        "browser": true,
        "node": true
    },
... [Log Snipped] ...
    }
}
```

So, the reason you are seeing this behavior is because eslint is trying to read the array as an object - it thinks you want to set an environment with the name of the array's index, since it looks like an object of this form:

```
{
    "0": "node"
}
```

Maybe we should check that it's an object explicitly and throw an error if it's not.
- The options file explictly says that `env` is of type `[string]`, which means array of strings.

``` .js
options:{
    env:["node"],  // doesnt work
    global:["test"]  // works
}

require("eslint").cli.execute(options);
```

This works for everything else except the `env`.

I agree that it works woith `objects` but you cannot pass them through `cli` because it throws error for unrecognized variable (mainly because of the format)
- Ah! So you're referring to the command line options object that's passed through.

You're absolutely right, there's a problem with the way it's being interpreted now. The createEnvironmentConfig doesn't accurately reproduce this block that it replaced in [URL] (among other things):

```
js
     // Add cli-supplied environments
     if (this.env) {
         if (!userConfig.env) {
             userConfig.env = {};
... [Log Snipped] ...
         });
     }
```

The fix would be to either have a new method for the command-line configs, which will be an array `["browser", "node"]` instead of an object `{"browser": true, "node": true}`, or to transform the array to the object before passing it in.
- Seems like it would be a much less intrusive change to just transform the envs array immediately, just like we're doing with the globals. Working on this.
