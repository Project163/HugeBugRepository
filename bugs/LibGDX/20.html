Title

Intersector#intersectRayBoundsFast incorrect

Description
Haven't tested it numerically, but Pax Britannica relies on this functionality to do intersectin testing in it's main menu. The last change broke the main menu. I reverted the BoundingBox version to the old code and left the Vector based version as is in the last HEAD. 

We need to have both return the same result eventually :)
Discussion
- I think I found the problem. The only mathematical changes I made, was checking for division by zero:

```
final float divX = ray.direction.x == 0f ? 0f : 1 / ray.direction.x;
```

In my (3d) tests the check for division by zero never happened. But Pax Britannica is a 2d game (on the XY plane I assume), meaning that direction.x and direction.y will always be zero (and direction.z always -1 I assume).

Not guarding for division by zero or changing the lines to:

```
final float divX = ray.direction.x == 0f ? Float.MAX_VALUE : 1f / ray.direction.x;
final float divY = ray.direction.y == 0f ? Float.MAX_VALUE : 1f / ray.direction.y;
final float divZ = ray.direction.z == 0f ? Float.MAX_VALUE : 1f / ray.direction.z;
```

seems to solve the issue. Note that I choose to use MAX_VALUE here, but POSITIVE_INFINITY works as well (and might have your preference or to remove the check at all). Would you mind to verify these findings?

BTW: Using ray-aabb intersection for a 2d hittest is proven to be a great way to find bugs, but might be an overkill in most other scenarios ;)
