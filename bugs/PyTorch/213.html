Title

Crash in jagged tensor stack/cat along dimension 0

Description
### 🐛 Describe the bug

```python
import torch as th
x = th.nested.nested_tensor([th.ones(3, 2, 3), th.ones(4, 2, 3)], layout=th.jagged)
th.cat([x, x])
```
fails with
```
Traceback (most recent call last):
  File " ", line 1, in  
  File "/Users/monroe/.pyenv/versions/pyenv-311/lib/python3.11/site-packages/torch/nested/_internal/nested_tensor.py", line 367, in __torch_function__
    return func(*args, **kwargs)
           ^^^^^^^^^^^^^^^^^^^^^
... [Log Snipped] ...
    raise ValueError(
ValueError: NestedTensor cat_default(tensors: any, dim: any): expected at least 2 arguments and at most 2 arguments, but got: 1 arguments
```

Variations that produce identical errors:
* Passing an explicit `dim=0`
* Calling `th.vstack` instead of `th.cat`
* Calling `th.stack` instead of `th.cat` (except the traceback has `stack_default` in place of `cat_default`)

Things that do work:
* Passing any other `dim` argument besides 0 and the jagged dimension, including other dimensions before the jagged one. (A different, clearly intentional, error occurs when concatenating on the jagged dimension, including when using `th.hstack` on these inputs.)
* Calling `th.dstack`

Discussion
- I guess `cat` or `stack` are not supported for NJT on dimension 0 because it would require merging batches by concatenating and re-indexing the offsets and reconciling metadata (e.g., contiguous invariants, ragged_idx) across inputs. Handling mismatched ragged structures and validating cross-batch constraints is nontrivial, and I am not sure whether the current jagged path has implemented it or not. BTW, dimension 1 is the ragged dimension (symbol as `j1` when you print the shape), so `vstack` is also not supported in your case. For more information, you can check this out here: [URL]

But the error message shows another problem. The schema could theoretically accept only one input for `cat` and `stack` since `dim` is optional. I would like to raise a pr to fix it.
