Title

[RDB] Updated blob still deleted even if deletion interval lower

Description
If an existing blob is uploaded again, the timestamp of the existing entry is updated in the meta table. Subsequently if a call to delete (RDBBlobStore#countDeleteChunks) is made with  maxLastModifiedTime  parameter of less than the updated time above, the entry in the meta table is not touched but the data table entry is wiped out.  

 Refer  [URL]
Discussion
- A simple test and a possible fix is attached. All tests pass with the fix. 
 julian.reschke@gmx.de  Can you please review the patch. 
The above is a strong possibility during the concurrent run of blob gc and async index update as there is a likelihood that an older lucene blob gets recreated which is marked for GC. Since, it would have been updated it should not be deleted.
- The patch looks good to me. I think the bug in the original code was that the comparison was wrong: 

  
 // correct:
// delete only if the last modified is older than x
metaStatement.append(" and LASTMOD <= ?");

// wrong:
// delete only if there is NO entry where the last modified of the meta is older than x
dataStatement.append(" and not exists(select * from " + this.tnMeta + " m where ID = m.ID and m.LASTMOD <= ?)");

// correct would also be:
// delete if there is NO entry where the last modified of the meta is YOUNGER than x
dataStatement.append(" and not exists(select * from " + this.tnMeta + " m where ID = m.ID and m.LASTMOD > ?)");
 
  

 But the patch is also fine. The logic is a bit different: delete if there is no meta record. This is correct if the meta record is removed before the data record. Please note it would not be correct if the data record is removed before the meta record. But that's not the case: 

  
 count += prepMeta.executeUpdate();
prepData.execute();
 
  

 I guess it would be good to add comments in the code, to avoid adding bugs later on.
