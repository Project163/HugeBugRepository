Title

IAsyncLifetime fixtures are potentially initialised more than once

Description
If a test class includes more than one IAsyncLifetime implementing class fixtures, all existing class fixtures will have their `InitializeAsync()` calls re-invoked, and on test clean-up the number of calls to `InitializeAsync()` won't match the number of calls to `DisposeAsync()`.

For example, if a class includes three class fixtures `AlphaFixture`, `BetaFixture`, and `GammaFixture`. `AlphaFixture` will be invoked 3 times, `BetaFixture` twice, and `GammaFixture` once.

Collection fixtures are also affected.

Here is a test reproducing the bug: 

```
cs
using System;
using System.Threading.Tasks;
using Xunit;

... [Log Snipped] ...
    }
}
```

A workaround for this issue is to create a composite test fixture that initialises each fixture only once. Another workaround would be to ignore repeated calls to `InitializeAsync()` in the fixture.

A second potential bug is that async test fixtures are initialised serially and not in parallel, reducing the benefit of supporting async fixtures.

I would expect following test to only take 2 seconds to execute but due to the combination of both bugs takes 5 seconds.

```
cs
using System;
using System.Threading.Tasks;
using Xunit;

... [Log Snipped] ...
    }
}
```
