Title

Deprecated bundles cause compiler warnings

Description
## Bevy version

0.15.1

## What you did

Mark a bundle as deprecated in favor of required components.

```rust
#[deprecated(note = "all uses can be safely removed, uses required components")]
struct SomeBundle {
    // ...
}
```

## What went wrong

The derived implementation of `Bundle` and `DynamicBundle` cause compiler warnings about using a deprecated struct. IMO, `#[allow(deprecated)]` should be included in the derived implementations to silence these warnings.
Discussion
- Can you post a minimal reproduction? Are you using nesting deprecated bundles, or is this just the straightforward case?
- If the following is the contents of lib.rs, then `cargo check` emits a warning.
```rust
use bevy::prelude::*;

#[derive(Resource)]
#[deprecated]
pub struct Empty {}

```
- The proc macro needs to generate an allow for deprecated (and an expect for the allow).
- I've opened a PR for this. Can you clarify what expect is needed? I added the allow and there are no clippy warnings.
