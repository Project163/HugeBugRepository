Title

Using `text(...)` for `Select.with_for_update(of=...)` argument broken since 1.3.2

Description
**Describe the bug**
Using a `text(...)` value for the `of` argument in a `Select.with_for_update()` call results in a broken query since version 1.3.2; the value isn't included in the `FOR UPDATE OF` part at all.

**Expected behavior**
A valid query to be generated, including the supplied value in the `FOR UPDATE OF` part.

**To Reproduce**

```
py
#!/usr/bin/env python
# -*- coding: utf-8 -*-
import sqlalchemy.sql
from sqlalchemy import *
... [Log Snipped] ...
s.query(User.id).with_for_update(of=User).all()  # Succeeds
s.query(User.id).with_for_update(of=sqlalchemy.sql.text('_user_')).all()  # Fails
```

**Error**

```
Traceback (most recent call last):
  File "./reproduce.py", line 29, in  
    s.query(User.id).with_for_update(of=sqlalchemy.sql.text('_user_')).all()  # Fails
  File "/home/me/venv/lib/python3.9/site-packages/sqlalchemy/orm/query.py", line 3161, in all
    return list(self)
... [Log Snipped] ...
sqlalchemy.exc.ProgrammingError: (psycopg2.errors.SyntaxError) syntax error at end of input
LINE 2: FROM _user_ FOR UPDATE OF
```

**Versions.**
 - OS: Ubuntu 18.04.5
 - Python: 3.9.0 (also reproduced on 3.6.x)
 - SQLAlchemy: 1.3.2, 1.3.20
 - Database: PostgreSQL 9.6
 - DBAPI: psycopg2 2.8.6

**Additional context**
This worked in SQLAlchemy 1.1.x, 1.2.x, 1.3.0 and 1.3.1.  It got broken in 1.3.2 (also tested 1.3.5, 1.3.10 and 1.3.20, broken in all of them).
