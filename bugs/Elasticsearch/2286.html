Title

high level rest client count request fails with 400 Bad Request

Description
**Describe the feature**:

 

**Elasticsearch version** (`bin/elasticsearch --version`): 6.7.0

**Plugins installed**: []

**JVM version** (`java -version`): official 6.7.0 docker

**OS version** (`uname -a` if on a Unix-like system): linux

**Description of the problem including expected versus actual behavior**:
when executing count request from high level rest client and using "terminate_after", requests fails with this error:
{
        "type": "parsing_exception",
        "reason": "request does not support [terminate_after]",
        "line": 2,
        "col": 2
      }


this is because terminate_after is sent in the request body and not as request param

was able to reproduce with kibana by running this:

PUT /test
POST /test/_count
{
 "terminate_after":1 
}

however this works:

POST /test/_count?terminate_after=1

**Steps to reproduce**:

can reproduce with this code:

`
CountRequest countRequest = new CountRequest(index);
        countRequest.terminateAfter(1);
        CountResponse countResponse = highLevelClient.count(countRequest, RequestOptions.DEFAULT);
`
