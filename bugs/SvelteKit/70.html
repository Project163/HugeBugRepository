Title

adapter-static build with `trailingSlash: "alway"` option fails.

Description
### Describe the bug

build command try to access a file with trailing slash. (ex. `/favicon.png` -> `/favicon.png/`)

### Reproduction

- create app  using create-svelte, 'SvelteKit demo app'.
```
npm init svelte@next my-app  # Choose default options
cd my-app
```
- Add adapter-static
```
npm add -D @sveltejs/adapter-static@next
npm rm -D @sveltejs/adapter-auto
npm install
```
- Adjust `svelte.config.js` to use adapter-static, and `trailingSlash: 'always'` option.
```
diff
--- a/svelte.config.js
+++ b/svelte.config.js
@@ -1,9 +1,10 @@
-import adapter from '@sveltejs/adapter-auto';
... [Log Snipped] ...
                // Override http methods in the Todo forms
                methodOverride: {
```
- run build
```
npm run build
```

### Additional Information

Discussion
- `@sveltejs/kit: next => 1.0.0-next.322` also seems to have broken the output file structure `static-adapter` builds.

```
src/routes/[param]/index.svelte
src/routes/[param]/file.json.js
src/routes/[param]/index.json.js
```

Generates the following output files in the build folder:
```
[param]/file.json
[param].html
[param].json
```

This broke all paths using a route parameter for a github pages deployment I had set up.
