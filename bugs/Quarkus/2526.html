Title

[Graal master] spring-data-jpa native integration test fails at runtime with MissingReflectionRegistrationError

Description
### Describe the bug

When running the `spring-data-jpa` native integration test with a GraalVM build from the master branch it fails the `BookResourceIT>BookResourceTest.testEnsureFieldPageableIsSerialized` test. It appears the root cause is a missing reflection config:

```
2025-12-04 14:06:36,847 fedora /home/sgehwolf/Documents/openjdk/quarkus/quarkus-source/integration-tests/spring-data-jpa/target/quarkus-integration-test-spring-data-jpa-999-SNAPSHOT-runner[56166] ERROR [io.qua.ver.htt.run.QuarkusErrorHandler] (executor-thread-1) HTTP Request to /book/paged?size=2&page=1 failed, error id: b60c695a-be21-4b00-9876-15b65c341d0b-1: org.graalvm.nativeimage.MissingReflectionRegistrationError: Cannot reflectively invoke method 'public default boolean org.springframework.data.util.Streamable.isEmpty()'. To allow this operation, add the following to the 'reflection' section of 'reachability-metadata.json' and rebuild the native image:

    {
      "type": "org.springframework.data.util.Streamable",
      "methods": [
... [Log Snipped] ...
	at org.graalvm.nativeimage.builder/com.oracle.svm.core.thread.PlatformThreads.threadStartRoutine(PlatformThreads.java:829)
	at org.graalvm.nativeimage.builder/com.oracle.svm.core.thread.PlatformThreads.threadStartRoutine(PlatformThreads.java:805)
```

Note, this class is already registered for reflective access when `--future-defaults=all` or the like is specified.

### Expected behavior

Native integration test passes.

### Actual behavior

Native integration test fails.
