Title

Alerts Summary reports on filtered alerts. Difference between 2.15.0 & 2.16.0

Description
### Describe the bug:

We are using 2 API's in order to extract Alerts from ZAP via zap clientapi in JAVA

- org.zaproxy.clientapi.gen.Alert#alertsSummary
- org.zaproxy.clientapi.gen.Alert#alerts

We're also setting alert filters using the following API:

- org.zaproxy.clientapi.gen.AlertFilter#addAlertFilter

Up till ZAP v. 2.15.0 the alerts filtered ( with 'newlevel' set as FALSE_POSITIVE ) were filtered from output of 'alertsSummary' & 'alerts' API's. 

With ZAP v.2.16.0 the alerts are counted under summary under initial risk i.e. 'High'
Funnily enough they are not present on the reports.

### Steps to reproduce the behavior:

1. Apply Alert filter to modify Confidence to 'False Positive'
2. Start Active Scan with of an App where a **High** Alert will be generated. 
3. Call the **org.zaproxy.clientapi.gen.Alert#alertsSummary** API
4. The API provides a response with _{"alertsSummary":{"High":1,"Low":0,"Medium":0,"Informational":0}}_

### Expected behavior:

The API provides a response with _{"alertsSummary":{"High":0,"Low":0,"Medium":0,"Informational":0}}_

### Software versions:

{"version":"2.16.0"}
