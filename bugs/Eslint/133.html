Title

.eslintrc globals no longer used with 0.7.1 -- works fine with 0.6.2

Description
I have a configuration file like this -- we're just using the `no-undef` rule:

```
{
  "env": {
    "browser": true
  },

... [Log Snipped] ...
  }
}
```

This works fine with 0.6.2 but with 0.7.1, none of the globals in the configuration file are parsed. The directory structure is like:

`root/some/directory/lot_of_js`

With `root/.eslintrc` and we run `eslint some/directory/lots_of_js` from root.
Discussion
- I was about to fill the same issue. It happens for Drupal as well with that configuration: [URL] 

Issue in the drupal issue tracker: [Ref: #2299269].
- I found the problem. It's a minor mistake in the recent massive overhaul of configuration hierarchy and merging logic; relevant commit [URL] but see also [URL] Hopeful fix and further explanation forthcoming.
- The problem appears to be the change made starting on line 170 of lib/config.js, which I corrected in the above PR. The line assigning this.globals was changed to default to an array outside of the reduce; however that isn't the behavior of the original code which performed a reduce operation on the original globals or an array, resulting in an object in either case.
