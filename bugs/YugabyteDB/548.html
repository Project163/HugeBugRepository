Title

[YSQL] Webserver appears to die unremarked, leading to loss of metrics being reported

Discussion
- I think I identified the problem. If postmaster catches a child that was ordered to terminate via signal 9, either from the application  or pg_terminate_backend(), it will kill all dependent children for that postmaster process:
```
2021-08-20 17:14:38.409 UTC [89] LOG:  all server processes terminated; reinitializing
```
The webserver is only started in _PG_init() which I think gets called only when yb-tserver does the initial fork() and exec() of the postgres backend. In PostmasterStateMachine() though in src/postgres/src/backend/postmaster/postmaster.c - it does not restart the webserver for metrics, et al.
- So this only happens when a child dies (most likely candidate is OOM killer) and not pg_terminate_backend().
- So a signal like SIGKILL on the postgres backend for a session on a tserver will also reproduce this behavior without waiting a long time to cause the death by OOM killer.
- Turns out that setting bgw_restart_time to value of 1 allows webserver to restart.
