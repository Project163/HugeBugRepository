Title

Incorrect XSD resolution when the file name is the same in different folders

Description
The attached gradle project contains a WSDL file which imports a XSD and it, in turn, imports another two XSD files with the same name but located in different directories. It triggers incorrect resolution of the XSD files. The structure is the following: 
  
 1) MyWebservice.wsdl
   1.1) imports schema/MyWebservice.xsd -> schema/MyWebservice.xsd
        1.1.1) imports ../../../common/common.xsd -> ../../common/common.xsd
        1.1.2) imports ../../common/common.xsd -> ../common/common.xsd
                ) imports ../../common/common.xsd -> ../../common/common.xsd
 
  
 The resulting imports are: 
  
 1) [URL] (OK)
   1.1) [URL] (OK)
        1.1.1) [URL] (KO)
        1.1.2) [URL] (OK)
                ) [URL] (KO)
 
  
     
The URL   [URL] in 1.1.1 returns invalid content. The content is the file in 1.1.2 (not 1.1.1) and besides the contained import is not rewritten in its location. 
  
   Steps To reproduce: 

 
	 Download attached maven project.
  
 
unzip wsdl-test.zip
cd wsdl-test/
mvn clean  package 
mvn jetty:run
 
   
	 Go to the wsdl   [URL] and follow imports until   [URL] and check the received output is incorrect. 
	 You can also execute the client while the jetty is running with:
  
 
mvn exec:java
Discussion
- After looking into it, this  three lines  are adding the location that appears in the file and later  the other schema is not added because it is already present in the map . In those lines the key is only added if not present (so it's optional), but in the reproducer it is the other way around, first the optional key is added and then the real one is not because the previous is already present. The issue   CXF-6717   introduced those lines in this  commit  and my feeling is that it was just added to cover the "urn" catalog type. But: 
 
	 Right now the "urn" URI schema is not valid anymore after   CXF-8167   (I don't see any way to make it valid). 
	 The example in   CXF-6717   works using a generated key ( _import1.xsd ) even after removing the three lines. I need to manually add "urn" to the valid schemas at code level to test it. 
 

 I'm going to send a PR with  this branch .  All tests pass for me (included the one added for this issue). There is another option to solve this, adding the optional keys at the end (for example storing them in another map, and only adding them at the end if not present). But I think that removing the lines is enough. Please comment in the PR if any change is wanted.
