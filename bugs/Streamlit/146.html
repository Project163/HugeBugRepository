Title

The option --server.fileWatcherType does not work from the command line

Description
# Summary

The option --server.fileWatcherType does not work from the command line but works when specified in the toml config file.

# Steps to reproduce

What are the steps we should take to reproduce the bug:

Run streamlit as follows:
`streamlit run hello.py  --server.fileWatcherType=none --logger.level debug`
Looking at the log, you will notice a line like:
Watcher created for /path/to/hello.py

However, if I set this variable in the toml file to none, it works as expected.

## Expected behavior:

A watcher should not be created when set to none and thus the above line should not be present in the log.

## Actual behavior:

The fileWatcherType still defaults to 'auto' and an EventBasedFileWatcher is created.

## Is this a regression?

Not sure

# Debug info

- Streamlit version: (get it with `0.65, 0.69`)
- Python version: (get it with `3.6`)
- Using Pip
- OS version: tested on both MacOS 10.15.7 (Python 3.6.4) and Ubuntu 18.04 (Python 3.6.9)
- Browser version: N/A

- OK, I have repro'd this bug and it's a real one.   I think the problem is that the word "None" isn't getting translated into the None object.
- I also have encountered this problem and it prevents my app from starting. Tried the following 4 combinations:
 * `streamlit run --server.fileWatcherType=none my_app.py`
 * `streamlit run --server.fileWatcherType=poll my_app.py`
 * `STREAMLIT_SERVER_FILE_WATCHER_TYPE=none streamlit run my_app.py`
 * `STREAMLIT_SERVER_FILE_WATCHER_TYPE=poll streamlit run my_app.py`

From this traceback it is evident that [Link: config.get_option()] invoked by [Link: file_watcher.get_default_file_watcher_class()] returns value that does not take into account options passed by command line and options passed by environment variables.

The result is that [Link: file_watcher.get_default_file_watcher_class()] always returns [Link: EventBasedFileWatcher].

My first guess would be to see whether `LocalSourcesWatcher` is created before or after the options passed by command line and environment variables are reflected in [Link: config._config_options], which is [Link: indirectly accessed by] `config.get_option()`.
