Title

Transfer fail from S3 to Google Storage - Corrupted on transfer: md5sums differ

Description
Just checking out the rclone application for the first time today to mirror some AWS S3 bucket to Google Cloud Storage and came across issues with larger files not transferring over with the following error - Corrupted on transfer: md5sums differ

I tried on a couple of source S3 buckets today and had the same issue - small files seemed to transfer OK but larger files kept giving this md5sums differ error.

Is there a configuration option I missed or a new issue?

Discussion
- Something strange is going on...  ` -56` isn't even a valid MD5SUM.  That was reported by the source which was AWS.

This looks like it describes the problem
- [URL]

So I would guess that you uploaded the file using a multipart uploader into S3.  rclone is expecting that it was uploaded in a single part and so has an MD5SUM for an Etag.

I could blank the md5sum if I detect one with a `-` in, which would cause that check to be skipped which is probably what you want.

What do you think?
- For our source files in this case, we use mysqldump locally, gzip the file and use the aws cli tools as follows to upload to S3 in a bash script. That sounds exactly what is happening...
