### To Reproduce

Upgraded from 13.0.0 to 13.2.1 (i.e. latest). Migrated `pages/api/route1` to the new `appDir` methodology. Moved it to `app/api/route1/route.ts`. 

`app/api/route1/route.ts`: 
```
export default async function GET(req: Request) {
    const { searchParams } = new URL(req.url);
    const { data, error } = await fetch(process.env.BASE_URL + '/route1' + searchParams)
    return new Response(JSON.stringify({
        data: data ? data : [],
        error: error ?? ""
    }), { status: 200 })
}
```

From within a client component, calling:
```
fetch('/api/route1?query=Query', {method: 'GET'})
```
Returns an error:
```
body: ReadableStream {locked: true}

ok: false

... [Log Snipped] ...

url: "[URL]
```

### Describe the Bug

The bug is returning a 405 Method not allowed when the route is defined for a `GET` and explicitly set the method to `GET`. 

### Expected Behavior

The route should be called from within the originating fetch call.

- You should be exporting it as a named handler (`export async function GET`), but you're exporting it as a default instead (`export default async function GET`).
