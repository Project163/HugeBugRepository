Title

[YSQL][postgres_fdw] ERROR: System column with id -1 is not supported yet

Description
Jira Link: [Link: DB-13874]
### Description

Not sure if this is an expected limitation or not.
Setup:
```
CREATE EXTENSION postgres_fdw;

CREATE SERVER testserver1 FOREIGN DATA WRAPPER postgres_fdw;
DO $d$
    BEGIN
... [Log Snipped] ...
) SERVER loopback OPTIONS (schema_name 'S 1', table_name 'T 1', use_remote_estimate 'true');
ALTER FOREIGN TABLE ft2 DROP COLUMN cx;
```
Running:
```
yugabyte=# SELECT t1.ctid, t1, t2, t1.c1 FROM ft1 t1 JOIN ft2 t2 ON (t1.c1 = t2.c1) ORDER BY t1.c3, t1.c1 OFFSET 100 LIMIT 10;
ERROR:  System column with id -1 is not supported yet
```

[DB-13874]: [URL]
Discussion
- Same with `SELECT * FROM ft1 t1 WHERE t1.ctid = '(0,2)';`:
```
ERROR:  System column with id -1 is not supported yet
CONTEXT:  remote SQL command: SELECT "C 1", c2, c3, c4, c5, c6, c7, c8 FROM "S 1"."T 1" WHERE ((ctid = '(0,2)'::tid))
```
- This is expected since YB doesn'T support ctid yet, will have to change tests not to use ctid.
- Some test queries do not have "ctid" yet still use it:

`src/postgres/contrib/postgres_fdw/expected/yb_pg_postgres_fdw.out`
```
EXPLAIN (verbose, costs off)
UPDATE ft2 SET c2 = c2 + 300, c3 = c3 || '_update3' WHERE c1 % 10 = 3;              -- can be pushed down
ERROR:  System column "ctid" is not supported yet
CONTEXT:  remote SQL command: EXPLAIN SELECT "C 1", c2, c3, c4, c5, c6, c7, c8, ctid FROM "S 1"."T 1" WHERE ((("C 1" % 10) = 3)) FOR UPDATE
-- YB: port further queries when CTID is supported (see #11419)
```

Note the error message changed in
- This is reproducible when any foreign table that is queried has been created with the `use_remote_estimate 'true'` option.
postgres_fdw sends queries of the form `EXPLAIN SELECT ctid FROM  ` to the foreign server to fetch row estimates for various scans while planning the query.
