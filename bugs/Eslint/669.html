Title

allowBlockStart option in lines-around-comment doesn't support if blocks

Description
Code like this:

```
if (cond) {
  // a comment at the beginning
}
```

with:

`/*eslint lines-around-comment: [2, { "beforeLineComment": true, "allowBlockStart": true }]*/`

shouldn't throw an error as it doesn't on function blocks
Discussion
- This is a good question. This rule was written for ES5, and in ES5 `if` is not a block. I'm not sure we should update it for ES6. @eslint/eslint-team
- @ilyavolodin `if`s create block statements and are already supported by this rule, see [Link: test case].

It seems to fail when there is only a comment in the body.
- ... [Middle Discussions Snipped for Brevity] ...
- Thanks for looking at this! I didn't notice this was limited to comment-only if blocks, I just got the error and thought it was general
- @alberto no. Comments are not considered part of the AST. We hack it so our traversal includes comments, but the comment is not technically a child of the block.
