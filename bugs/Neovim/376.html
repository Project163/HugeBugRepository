Title

Auto-complete sometimes halts the program completely without any way to exit if you type too fast after opening the auto-complete menu.

Description
### Neovim Version

0.5.0

### Operating system/version:

Arch-linux 5.10.45-1-lts

### Terminal name/version:

st

### TERM environment variable

xterm

### Installation

Pacman

### Steps to reproduce

Add the following to your config, enable spellcheck, set g:autocompleteion to v:true and g:autocomplete_type to "buffer"

```
function! OpenCompletion()
    if pumvisible() && (g:autocompletion == v:true)
        if g:autocomplete_type == "buffer"
            call feedkeys("\ \ ", "i")
        endif
... [Log Snipped] ...

autocmd InsertCharPre * noautocmd call OpenCompletion()
```

Then open neovim and type text very fast. It can be any text but it must be frequently space-separated. You can type some gibberish but it must be space separated every couple of keys for fastest bug reproduction

### 

- [ ] Please check the box if it's possible to reproduce the bug with `nvim --clean` as well

### Vim

_No response_

### Expected behavior

Such configuration should enable as-you-type auto-completion, closing and reopening auto-complete menu every time a character is pressed.

### Actual behavior

And it actually does that exact thing, but if you type too fast, it halts in an infinite loop. This works not only with my configuration but also with some existing as-you-type auto-complete plugins. There is no way to exit the program, no way to stop the infinite loop, you can only kill it from a different terminal.
Discussion
- I found the actual place where it halts -- in the file edit.c in function ins_compl_get_exp it checks if it has found all the matches by checking if the latest match position matches the first ever found match position. But if you type too fast, the first ever found match disappears and is never found again, so it just keeps going through the buffer over and over, never stopping, because that first match is the only thing that can stop it, and it does not exist anymore. I may have fixed it, but I`m not sure -- I have not fully tested the solution yet, but it does not halt anymore in my custom installation [URL]
