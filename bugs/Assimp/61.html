Title

Something keeps writing "dna.txt"

Description
Something in assimp keeps writing a file named "dna.txt". I *think* it's the Blender importer.

It should not be doing this. Will investigate.

Example: [Link: dna.txt]
Discussion
- Ok, so; dna.txt is created only in assimp debug builds, when ASSIMP_BUILD_DEBUG is defined; via:

[URL]

Then:

[URL]

Etc.

I don't know what to do about it, if anything, because:

- It's only in debug builds; that seems reasonable, but also...
- I don't want it to be generated, but also...
- I assume other people *do* want it.
- Any precompiler-based solution on the library side would have to involve setting build flags when building assimp, but I don't know enough about cmake or the build system here to implement that.
- Any precompiler-based solution that can be done on the *application* build level [Link: isn't really feasible]. 
- Any runtime code-based solution would involve picking a default, and applications wishing to change that would have to call some Blender-specific function, which feels awkward -- unless assimp has a sort of global options concept? I suppose it could be an importer property? 
- An env var based approach is fine with me but given that I just hacked in #3834, I'm a little wary to continue that pattern. Ya know, slippery slope and all.

Or, I could just deal with the file being always written, and do nothing here. 

Or it could be the case that nobody cares about this file any more and so it can be disabled by default or always.

---

Any thoughts? I guess the fundamental open questions are:

1. Is this file still needed at all?
2. If so, is it better to have it be enabled by default, or disabled by default?
3. Where is the most convenient place to stick the option (so that it is as transparent as possible to application developers)?
- `DumpToFile();` looks like a code path you’d selectively enable during very specific debugging, but you’d never push that call into the official repo. Should be `#if 0` and whoever needs it, must enable it.
