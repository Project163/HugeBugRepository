Title

Custom type breaks when column type is decimal on MariaDB

Description
### Bug Report

 

|    Q        |   A
|------------ | ------
| Version     | 3.7.1

#### Summary

When using a custom DBAL type which maps to a `DECIMAL` type in MariaDB the schema comparison always thinks it is incorrect. I did a bisect which identifies   as being the problematic commit.

#### Current behaviour

Schema tool generates an `ALTER TABLE` statement to change the column type to `NUMERIC` which is mapped to `DECIMAL` by MariaDB.

#### How to reproduce

1. `git clone [URL]
2. `composer install`
3. Amend `$dsn` inside `test.php`
4. `php -f test.php`
5. Run queries 
6. `php -f test.php` - observe alter table query
7. `composer require doctrine/dbal 3.6.*`
8. `php -f test.php` - observe no query generated

#### Expected behaviour

Schema tool should work as it did in 3.6.7 and not detect any differences.

- The issue is caused when checking commented column types where the column declaration used is a synonym of the MySQL/MariaDb internal column type names. The simplest approach to fixing this is to restrict the type checking of commented columns to json only which is the only case this test should be necessary.

Changing the column declaration to the internal type as per your patch also works but there is nothing to stop a custom type hard wiring NUMERIC into the type declaration and triggering the issue.
