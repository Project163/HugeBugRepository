Title

Transport handshake starts before TLS handshake completes

Description
When opening a connection to a remote node we establish a collection of TCP channels and once they're all open we send an `internal:tcp/handshake` to the remote node with a 30-second timeout. However today we don't wait for the TLS handshake to complete before considering a channel to be open. This means if the TLS handshake fails (e.g. it times out after 10s) then we report the `internal:tcp/handshake` as failing due to the channel closing, rather than reporting a more useful error about the TLS handshake failure. We should wait for the TLS handshake to complete before considering each channel to be open.
