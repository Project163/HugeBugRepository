Title

Repository configuration file permissions too wide

Description
Output of `helm version`: `version.BuildInfo{Version:"v3.10.1", GitCommit:" ", GitTreeState:"clean", GoVersion:"go1.18.7"}`

Output of `kubectl version`:
```console
Client Version: version.Info{Major:"1", Minor:"23", GitVersion:"v1.23.13", GitCommit:" ", GitTreeState:"clean", BuildDate:"2022-10-12T10:57:16Z", GoVersion:"go1.17.13", Compiler:"gc", Platform:"linux/amd64"}
Server Version: version.Info{Major:"1", Minor:"23", GitVersion:"v1.23.13", GitCommit:" ", GitTreeState:"clean", BuildDate:"2022-10-12T10:50:48Z", GoVersion:"go1.17.13", Compiler:"gc", Platform:"linux/amd64"}
```

Cloud Provider/Platform (AKS, GKE, Minikube etc.): `kubeadm`

I just noticed that Helm creates `~/.config/helm/repositories.yaml` with POSIX file permissions `0644`, which is probably not appropriate considering that it can contain credentials. Even if Helm derives the file permissions from the umask, world-readability is probably always too wide. Can we change the default permissions?
