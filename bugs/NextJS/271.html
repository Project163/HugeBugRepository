### To Reproduce

create a site that returns 200,000 dynamically generated pages

```
javascript
// pages/[id].js
export const getStaticPaths = async () => {
  paths = [...(new Array(200000))].map((_i, x) => ({ params: { id: x }}))
  return {
... [Log Snipped] ...
  };
};
```

`next build` will take a long time ~`1h 20m`, and eventually stop responding.



### Describe the Bug

During the build process, a Next app builds an array of paths for all of its pages, a [Link: function called `detectConflictingPaths`] iterates over those paths and checks for conflicts that would result in duplicate paths. If any conflicts are detected, it throws an error `Conflicting paths returned from getStaticPaths, paths must be unique per page` and exits the process.

During the build process, the CLI progress indicator reports "Collecting page data ..."

This function gets exponentially slower as the paths array increases:

- 100 paths `0.002461s`
- 200 paths `0.006019s`
- 400 paths `0.020899s`
- 800 paths `0.062096s`
- 1600 paths `0.224554s`
- 3200 paths `0.874216s`
- 6400 paths `3.370s`
- 12800 paths `14.280s` 💥 at this size, the CLI progress indicator stopped working
- 25600 paths `60.795s`
- 51200 paths `4m 01.98s`
- 102,400 paths  `14m 10.272`
- 204,800 paths `1.6h`




### Expected Behavior

`detectConflictingPaths` should not take more than a second to run.
