Title

Google cloud storage modification time update doesn't work anymore on v1.49.0

Description
#### What is the problem you are having with rclone?
I updated to the latest version, using the google-cloud-storage backend. It now doesn't have permissions anymore to update modification times on the remote:

`googleapi: Error 403: Insufficient Permission, insufficientPermissions`

#### What is your rclone version (output from `rclone version`)
```
rclone v1.49.0
- os/arch: darwin/amd64
- go version: go1.12.9
```

#### Which OS you are using and how many bits (eg Windows 7, 64 bit)
Mac OS 10.14.6, 64 bits. 

####  Which cloud storage system are you using? (eg Google Drive)
Google Cloud Storage

#### The command you were trying to run (eg `rclone copy /tmp remote:tmp`)
`/usr/local/bin/rclone sync /tmp/backupmount  google-cloud-storage:backup-prive-laptop --fast-list --create-empty-src-dirs --config /Users/wmuizelaar/.config/rclone/rclone.conf --exclude-from /etc/rsyncd.exclude -l --delete-excluded --delete-during --transfers 100 --checkers 50 --buffer-size=256M --retries=1 -v --stats-one-line`

#### A log from the command with the `-vv` flag (eg output from `rclone -vv copy /tmp remote:tmp`)
An excerpt is:
```
2019/08/28 16:16:31 ERROR : usr/local/Homebrew/.git/FETCH_HEAD: Failed to set modification time: googleapi: Error 403: Insufficient Permission, insufficientPermissions
```
No further details are added unfortunately.

#### Remark
Could it be related to tightening the oauth-scopes as done in [URL] ?
Discussion
- Yes that is the cause.  According to my tests the `full_control` scope is needed to issue the metadata PATCH command.

So going down from "[URL] to "[URL] has meant that we can't run PATCH on objects to set new metadata.

I removed this in the oauth review because Google said


Unfortunately I failed to check updating the mod time.

There is a work-around for this - do the oauth again with v1.48 (use `rclone config` and edit the remote). The config file and generated token will work fine with v1.49.  However the oauth with v1.48 will give nasty errors.
