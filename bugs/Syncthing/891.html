Title

API: /rest/system/connections has misleading "total" entries

Description
Popped up [Link: on the forum].

The `total` element has these invalid entries:
```
"paused" : false,
"connected" : false,
"clientVersion" : "",
"type" : "",
"address" : ""
```

The first two could be used for a logical conjunction of all remote devices' states, but the latter three are useless.

Easiest fix would be to dump the fields by using `protocol.Statistics` instead of `ConnectionInfo` for the response type.
Discussion
- It's also questionable that we return empty strings and bogus datetimes for disconnected devices to begin with. A more JSON-y approach here would be to either not return them at all or as nulls. Changing that now will probably break everyone who uses this, though.
