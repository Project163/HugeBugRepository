Title

QuarkusComponentTest fails with ambiguous dependencies if bean is injected with parameterized qualifier multiple times

Description
`QuarkusComponentTest` fails with ambiguous dependencies if bean is injected with parameterized qualifier multiple times

### Describe the bug

We have a project which connects to RabbitMQ using the SmallRye Reactive Messaging extension. One class injects two emitters on different channels.

When trying to test the class using `@QuarkusComponentTest`, the test fails to start due to ambiguous dependencies. Arc seems to produce both synthetic beans but cannot distinguish between them anymore (which is possible when running Quarkus itself).

I created a minimal reproducer using a custom qualifier.

### Expected behavior

The test class starts and runs the actual tests.

### Actual behavior

The test discovery fails with an error:

```
Caused by: jakarta.enterprise.inject.spi.DeploymentException: Found 2 deployment problems: 
[1] Ambiguous dependencies for type `com.example.TestBeanClass` and qualifiers [`@TestQualifier("foo")`]
	- injection target: `com.example.TestAppScopeClass#testBeanClass`
	- declared on CLASS bean [types=[`com.example.TestAppScopeClass`, `java.lang.Object`], qualifiers=[`@Any`, `@Default`], target=`com.example.TestAppScopeClass`]
	- available beans:
... [Log Snipped] ...
		- SYNTHETIC bean [types=[`com.example.TestBeanClass`, `java.lang.Object`], qualifiers=[`@Any`, `@TestQualifier("foo")`], target=n/a]
		- SYNTHETIC bean [types=[`com.example.TestBeanClass`, `java.lang.Object`], qualifiers=[`@Any`, `@TestQualifier("bar")`], target=n/a]
```

Discussion
- @b-strange Thanks for the report. It's a bug. We need to treat qualifiers with non-binding members specially.
- @b-strange [URL] should fix the problem. 

However. keep in mind that a single Mock bean will be used for all duplicit injection points, i.e. `TestAppScopeClass#testBeanClass` and `TestAppScopeClass#testBeanClass2` in your reproducer. If you need to create different mocks, then you'll need to use the [Link: mock configurator API] or a custom producer method.

Also note that the `TestBeanProducer` from your reproducer is completely ignored, as it's not a [Link: component under the test]; moreover it declares `@jakarta.ws.rs.Produces` instead of `jakarta.enterprise.inject.Produces`.
