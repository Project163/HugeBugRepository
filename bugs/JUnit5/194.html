Title

Exception thrown by a static @RegisterExtension field is swallowed

Description
## Steps to reproduce

Running this test case

```
java
package org.example;

import org.junit.jupiter.api.Test;
import org.junit.jupiter.api.extension.Extension;
... [Log Snipped] ...
	}
}
```

should report: 

```
java.lang.Error: boom
	at org.example.ExplosiveTests$1. (ExplosiveTestClass.java:31)
	at org.example.ExplosiveTests. (ExplosiveTestClass.java:28)
```

instead of:

```
java.lang.NoClassDefFoundError: Could not initialize class org.example.ExplosiveTests
```

## Context

 - Used versions (Jupiter/Vintage/Platform): JUnit Jupiter 5.2.0
 - Build Tool/IDE: Intellij Idea 2018.2

## Related Issues

- #602
Discussion
- FYI: I authored `ExplosiveTests` (based on input from @mbaechler on [Link: Gitter]) and verified the behavior against the status quo on `master`.
- Tentatively slated for 5.4 M1 for _team discussion_.
- Please note that the described (undesirable) behavior only exists if the field is `static`!

If the `@RegisterExtension` field is non-static, JUnit properly propagates the `java.lang.Error: boom` exception.
- The reason for the latter is that `ReflectionUtils.newInstance(...)` does _not_ swallow the exception; whereas, `ReflectionUtils.readFieldValue(...)` silently swallows the exception and returns `Optional.empty()`.
