- Troubleshooting a bit further...

I even went back to the version I used when I wrote that article and played with the `rest-fights` app & I see the same error.

I've put together some smaller yamls that can be imported via `oc apply -f` which only contain the `rest-fights` service showing the issue. I'm deploying on [Link: Red Hat Developer Sandbox], as described in the blog post.

[Link: rest-fights-java17.zip]

If you unzip this there is a single folder `rest-fights-java17`. Inside are 2 yaml files: `rest-fights-quarkus-2.7.3-java17.yml` and `rest-fights-quarkus-2.8.2-java17.yml`.
- `rest-fights-quarkus-2.7.3-java17.yml` is for Quarkus `2.7.3`, which is the version I used when I created [Link: the blog post], so I know this worked!
- `rest-fights-quarkus-2.8.2-java17.yml` is for Quarkus `2.8.2`, the most recent version of the app. They both suffer from this problem.

Before deploying either you first need to [Link: create the managed services as described in the blog post].


Then before deploying the app (via `oc apply -f`) you need to update a few values in the respective yaml file:
- In the `rest-fights-config` ConfigMap (1st element in the yaml document) you need to update the values:
    - `kafka.bootstrap.servers`: Update ` ` with the bootstrap server of your Kafka managed service
    - `mp.messaging.connector.smallrye-kafka.apicurio.registry.url`: Update ` ` with the core registry API URL of your service registry service
