Title

hmac imported from cwd

Description
### Current behavior

If you use the `-j` option, a module named `hmac` from the current working directory may be imported:

```
$ echo 'raise RuntimeError("BAD PYLINT!")' > hmac.py
$ touch test.py
$ pylint -j2 test.py
No config file found, using default configuration
Traceback (most recent call last):
... [Log Snipped] ...
    raise RuntimeError("BAD PYLINT!")
RuntimeError: BAD PYLINT!
```
### Expected behavior

pylint should not let any modules be imported from cwd (unless it was asked to do so).
### pylint --version output

```
No config file found, using default configuration
pylint 1.5.6,
astroid 1.4.6
Python 3.5.2rc1 (default, Jun 13 2016, 09:33:26)
[GCC 5.4.0 20160609]
```
Discussion
- This is not a problem of pylint. It is triggered in -j mode, because the standard library module `multiprocessing` imports hmac itself, which in turn, will point to the local file, instead of the stdlib's module. You can also test this with `python -c "import hmac"` and you will get the same result. I can only suggest you to rename it to something that does not shadow a stdlib's module or run pylint on the parent directory instead.
- When you use `-c`, the Python interpreter adds cwd to `sys.path`. This is not the case when you run a Python script. So no, you can't blame the interpreter.

I want to run pylint against untrusted code, so this is not an option for me.

Actually, chdir'ing to a trusted directory doesn't help:

```
$ cd / && pylint -j2 /home/jwilk/badpylint/test.py
No config file found, using default configuration
Traceback (most recent call last):
  File "/usr/local/bin/pylint", line 11, in  
    sys.exit(run_pylint())
... [Log Snipped] ...
    raise RuntimeError("BAD PYLINT!")
RuntimeError: BAD PYLINT!
```
