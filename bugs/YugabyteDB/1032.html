Title

[DocDB] Select rows count inconsistency after bulk load

Description
Jira Link: [Link: DB-8159]
### Description

We can have inconsistency in selecting rows count in debug build in the following scenario:
```
./bin/yb-ctl start
./bin/ysqlsh -c "CREATE DATABASE db WITH colocation = true;"
./bin/ysqlsh -d db -f ~/code/tpch-dbgen/yugabyte_colocated.ddl

./bin/ysqlsh -d db -c "select count(*) from lineitem;"
... [Log Snipped] ...

./bin/ysqlsh -d db -c "select count(*) from lineitem;"
```

`select count(*)` sometimes returns less rows after restart. We were only able to reproduce this in debug build and this is reproducible on master branch (commit  ). 

Content of `yugabyte_colocated.ddl` is just creating some tables and using `\copy` command to load data into these tables from files.

I’ve did some investigation and was able to reduce the dataset reproducing scenario, so load only takes ~15 minutes instead of original ~3 hours. Also I confirmed that missing rows are present in WAL files even after restart, but they absent in RocksDB SST files even before restart.

Looks like the issue is related to replay of applying of intents/distributed transactions during local tablet bootstrap.
