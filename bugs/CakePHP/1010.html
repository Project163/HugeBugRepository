Title

belongsTo association with strategy=select

Description
This is a (multiple allowed):

* [ ] bug
* [x] enhancement
* [ ] feature-discussion (RFC)

* CakePHP Version: 3.8.

### What you did
In table: defined belongsTo association with strategy=select
In controller: feetched results without assoc foreign key in select expression:
`$this->Table->find()->select(['id', 'name'])->contain(['Assoc'])->first();`

### What happened
I got results from primary table, but property with assoc entity is null.

### What you expected to happen
`RuntimeException` is thrown with message `'Could not find primary key value for source entity'`.

It works only when I specify assoc foreign key in select expression or skip select:
`$this->Table->find()->select(['id', 'name', 'assoc_id'])->contain(['Assoc'])->first();`
`$this->Table->find()->contain(['Assoc'])->first();`
Discussion
- This is expected. You need to either explicitly select the foreign key field too or enable auto fields for the query using `Query::enableAutoFields()`.
- `Query::enableAutoFields()` on main query enabled all fields, not only 'assoc_id'.
enableAutoFields in query builder on contain does not help:

```
$this->Table->find()->select(['id', 'name'])
	->contain(['Assoc'=>function (Query $query) { 
		return $query->enableAutoFields(); 
	}])
	->first();
```
- ... [Middle Discussions Snipped for Brevity] ...
- Not in PDO, but when we are collecting foreign key values to prepare the conditions for the association query. Having no foreign key values is a valid state as all selected rows could have nulls in the foreign key.

I agree that validating during query building is not a tractable solution. Validating in result generation is also difficult because of billable associations. I will explore how adding foreign keys would work. This wouldn't prevent fields being restricted after the contain() call unfortunately, but could help mitigate how frequently this comes up.
- But foreign key is not null. It is not present in primary records if it was not specified in select clause.
So checking using array_key_exists after fetching primary rows should help here.
