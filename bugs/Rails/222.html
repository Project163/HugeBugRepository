Title

activestorage blob isn't created with ArgumentError when initialized by nested attributes

Description
### Steps to reproduce
 

First, create has_many association between `:shops` and `:members` with nested attributes and activestorage declaration.

```
ruby
class CreateShops   success
... [Log Snipped] ...
)
# => ArgumentError (wrong number of arguments (given 1, expected 0; required keywords: io, filename))
```

I guess the cause is with nested attributes it converts arguments to indifferent access hash.

[URL]

While, building methods of ActiveStorage::Blob expect keyword arguments.

[URL]

### Expected behavior
 

Create, associate, upload blob successfully using nested attributes.

### Actual behavior
 

Fail with the following error.
`ArgumentError (wrong number of arguments (given 1, expected 0; required keywords: io, filename))`

### System configuration
**Rails version**:
6.0.0
**Ruby version**:
2.5.1p57

I'm not sure the best way to fix this issue, but please check this behavior once.
Discussion
- Also getting this issue, not sure how to properly do nested model attachments
- @metheglin were you able to resolve this?
- @heaven Sorry, I just stuck on this issue at checking the behavior of activestorage. Not in actual code. You may be able to resolve this issue by avoiding nested attributes like below.

```ruby
shop = Shop.new(name: :shop)
shop.members.build(name: :test1, image: {io: StringIO.new('test1'), filename: :test1})
shop.members.build(name: :test2, image: {io: StringIO.new('test2'), filename: :test2})
shop.save!
```
- I made a PR #39908 to fix this

Meanwhile, another workaround to continue using _nested attributes_ is passing `ActiveStorage::Blob.build_after_unfurling(...)` or `ActiveStorage::Blob.build_after_upload(...)` instead of `Hash`:
```
diff
Shop.create!(
  name: :shop,
  members_attributes: [
-    {name: :test1, image: {io: StringIO.new('test1'), filename: :test1}},
... [Log Snipped] ...
  ]
)
```
