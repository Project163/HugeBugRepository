Title

Config provider parsing is broken

Description
The  regex  used by the  ConfigTransformer  class to parse config provider syntax (see  KIP-279 ) is broken and fails when multiple path-less configs are specified. For example:  "${provider:configOne} ${provider:configTwo}"  would be parsed incorrectly as a reference with a path of  "configOne} ${provider" .

    The regex used to parse config provider syntax can fail to accurately parse provided configurations when multiple path-less configs are requested (e.g., `${provider:pathOne} ${provider:pathTwo}`). This change fixes that parsing and adds a unit test to prevent regression.
