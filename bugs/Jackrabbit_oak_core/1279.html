Title

UserProvider.getFolderPath may throw StringIndexOutOfBoundsException

Description
the 'intermediate' path passed to the createUser or createGroup is empty string (instead of null) or evaluates to empty string when being converted from absolute path, UserProvider.getFolderPath throws StringIndexOutOfBoundsException. This should obviously be avoided; proposed fix: treat empty relative path the same as  null  and fall back to the implementation defined content structure.
Discussion
- I think while falling back, we should also log a message (warn???) so that app developer at least knows what to look for when authorizable node doesn't get created where she intended to.
- alternatively we can also throw a  ConstraintViolationException  or  IllegalArgumentException ; i just felt that it would be nicer to not throw. but i don't have a strong preference here.
- I too don't have a strong preference one way or the other... but, I'd tend slightly towards  IllegalArgumentException .
- fixed at r1695450. 
an intermediate path resolving to the configured user/group root (either by passing in empty string or the corresponding absolute is path) is treated like  null . 
note, that while writing some tests i additionally found a bug in  NodeUtil.addOrCreateTree  that would result in a path containing a parent or current path element; fixed as well and added a dedicated  NodeUtil  test class.
