The actual conditions for triggering this bug are: move a derived class where the base class has some inheritable properties and the `PropertyNotSetInConstructor` check is enabled.

If I understand correctly, in order to run the `PropertyNotSetInConstructor` check we are generating some fake constructor calls here: [URL] and then we check the generated code instead of the original.

Well, we are also **refactoring** the generated code instead of the original. The `airliftClassLikeReference` method is trying to move a reference that is not present in the original code, it's only present in the fake constructors generated for the purpose of the `PropertyNotSetInConstructor` check. `startFilePos` / `endFilePos` are nulls because the code doesn't exist in the original file.

Obvious (tested) workaround: disable the `PropertyNotSetInConstructor` check, for example add the following to `psalm.xml`:
