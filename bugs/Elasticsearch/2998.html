Title

Elasticsearch does not refresh AWS Web Identity Token file when changed on disk

Description
### Elasticsearch Version

8.x

### Installed Plugins

_No response_

### Java Version

_bundled_

### OS Version

Kubernetes 

### Problem Description

**Observed**
We have ECK users reporting that S3 repository setups that rely on AWS IAM roles for service accounts (IRSA) stop working after a while and only a restart of the affected Pods restores functionality. 

[URL]

The users are following this documentation on the ECK side [URL] which configures a `CustomWebIdentityTokenCredentialsProvider` based on information from the two environment variables `AWS_WEB_IDENTITY_TOKEN_FILE` (and `AWS_ROLE_ARN`) 

My hunch is that Elasticsearch is not watching the file pointed to by `AWS_WEB_IDENTITY_TOKEN_FILE` and does not [Link: refresh] the credentials when the token changes on disk after the configured expiration time. This would be consistent with the users reporting that a restart of the Pods solves the problem. 


**Expected** 
I think it would be reasonable to expect that Elasticsearch reloads the credentials when the token changes on disk without user intervention.

[URL]

with a short ` expirationSeconds: 300` or something along those lines. 
Then wait for token refresh. (Disclaimer: I have not tried it yet myself just relaying user reports here)

- ES indeed doesn't watch for changes in the token file, but nevertheless the changes in the web Identity token file should be automatically picked up when a role session expires (the default duration is an hour). When the session expires, `STSAssumeRoleWithWebIdentitySessionCredentialsProvider` should [Link: re-read] the file and use the new token for establishing a new session.

I wonder if there's some duration mismatch, so when the old token expires, but the AWS SDK still consider the session from valid and only invalidates it after a restart.

In the meantime, I also looked at `S3Service` and we don't refresh the credentials when the S3 repository is reloaded with new settings. We should do that so at least users don't need to restart the pod.

I will look further at the issue, because I assumed that the token update workflow should work transparently with the AWS SDK.
