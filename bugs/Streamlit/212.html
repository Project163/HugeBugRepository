Title

"ValueError: Value out of range" when uploading large files (~>= 4.5GB) with `st.file_uploader`

### Summary

Uploading a large file with `st.file_uploader` can reliably lead to a:

```
ValueError: Value out of range  

File "/Library/Frameworks/Python.framework/Versions/3.9/lib/python3.9/site-packages/streamlit/runtime/scriptrunner/script_runner.py", line 565, in _run_script
    exec(code, module.__dict__)
File "/Users/skekre/Downloads/streamlit-misc/file-uploader-size.py", line 3, in  
... [Log Snipped] ...
File "/Library/Frameworks/Python.framework/Versions/3.9/lib/python3.9/site-packages/streamlit/elements/file_uploader.py", line 108, in serialize
    file_info.size = f.size
```

where "large" in my case was approximately close to or greater than 4.5GB. I'm not sure whether the specific size after which this error is thrown is machine dependant. @serdar-bayramov who first [Link: reported] this on the Streamlit forum encountered the error for files >= 2GB.

### Reproducible Code Example

```Python
import streamlit as st

f = st.file_uploader("Upload a file")

if f is not None:
    st.write(f.name)
    st.write(f.size)
```


### Steps To Reproduce

1. Create a `.streamlit/config.toml` file to set the upload limit to 4.5 GB:

    ```toml
    [server]
    maxUploadSize = 4500
    ```
2. Create a 4.4 GB file:
    ```sh
    truncate -s 4280m example.file
    ```
3. Run the above app and upload `example.file` to the file uploader widget

### Expected Behavior

As the uploaded 4.4 GB file is under the 4.5 GB limit set in `.streamlit/config.toml`, one would expect:
1. to see the upload successfully complete
2. the file uploader widget to be visible after the upload
3. see the output of the filename and filesize displayed

- Brief update on this issue:
- the error was caused by setting the file size on the proto field [Link: UploadedFileInfo.size] during serialization. The field's type is `uint32` which matches the error happening at ~4GB (2^32 bytes) when the size exceeds the max size for uint32 fields.
- the field does not seem to be used since Streamlit version `>=1.27` anymore in the production code path.

We *could* change the proto field to `uint64` as a precaution in case the field will be used again in the future, which should be compatible with the existing type according to [Link: the docs]. Or maybe we are going to remove it. No matter the next steps though, this issue does not seem to occur anymore since version `1.27`.
