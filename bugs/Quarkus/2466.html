Title

Compose Dev Services do not work on Windows

Description
### Describe the bug

Compose Dev Services do not work on Windows, execution ends with 
```
Caused by: io.smallrye.common.process.AbnormalExitException: Process exited abnormally (pid 6280) with exit code 125 with error output:
unknown shorthand flag: 'd' in -d
See 'docker --help'.
...
```

CC @ozangunalp 

The **root cause** is that docker-compose plugin is not found and thus docker execution fails. 

Me and @michalvavrik did several experiments on these environments:
 * Windows 10 with Docker Desktop
 * Windows Server with Docker CLI and Compose installed using Chocolatey
 
Our conclusion is that **some environment variables need to be propagated**.

For Michal (Windows Server with Docker CLI and Compose installed using Chocolatey) it was PROGRAMDATA to detect plugins in `C:\ProgramData\Docker\cli-plugins` as Chocolatey puts stuff there - [URL]

In my case (Windows 10 with Docker Desktop) it was PROGRAMFILES property so that docker-compose was detected.

I did changes in [URL]
The initial approach was `env.putAll(System.getenv());` to see that it makes difference and after that trying env properties one by one.
The one needed in my case was `env.put("PROGRAMFILES", System.getenv("PROGRAMFILES"));`

The right property is obviously end system dependent, there are also other env properties which may have influence on other systems - e.g. PROGRAMFILES(X86), COMMONPROGRAMFILES, COMMONPROGRAMFILES(X86).

To me it almost feels like `System.getenv()` should be reflected in the command execution.

Workaround in case you know the needed property: `quarkus.compose.devservices.env-variables.PROGRAMFILES=C:\\Program Files`
(Please note `\\` in the path)

Compose Dev Services work well on Windows
