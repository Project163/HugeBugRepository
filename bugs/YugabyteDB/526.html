Discussion
- The scenario was copying out one of the tables from the sample apps to a file, `/tmp/data`, then trying to copy that file back:
`copy cassandrasecondaryindex(k, v) from ‘/tmp/data’ with maxbatchsize=5;`
- Faced another occurrence of this issue.
There are a lot of
```
W0518 11:48:21.665313 23680 table.cc:347] Error getting table locations: Not found (yb/master/catalog_manager.cc:528): The object ' .cassandrauniquesecondaryindex'
does not exist, retrying.
...
W0518 11:50:01.718245 23680 table.cc:347] Error getting table locations: Not found (yb/master/catalog_manager.cc:528): The object ' .cassandrauniquesecondaryindex'
does not exist, retrying.
E0518 11:50:05.538031 23680 table.cc:360] OpenTable timed out
```

It tries to get table locations in a loop until timeout. During that time other threads looking for table locations are stuck on a mutex. Then one thread times out and another thread repeats the same thing…

So, it is not actually a deadlock, but still, blocking threads waiting for table locations.

An old table with this name has been deleted and a new one with the same created, but split was disabled for new one until backfill completed and once split was enabled - it tries to fetch table locations for the old table because old table ID is cached somewhere.

FetchPartitions should just return that table was deleted without retries in that case.
