Title

Unexpected NotNullViolation with Sqlite and custom ToSql implementation

Description
### Discussed in [URL]

 

 Originally posted by **PhotonQuantum** November 21, 2022 
I have a custom rust type like this
```rust
#[derive(Debug, FromSqlRow, AsExpression)]
#[diesel(sql_type = Text)]
struct CustomWrapper(String);
```

... and its `ToSql` implementation

```rust
impl ToSql  for CustomWrapper {
    fn to_sql (&'b self, out: &mut Output ) -> serialize::Result {
        // Change this to `out.set_value(&self.0);` works.
        out.set_value(self.0.to_string());
        Ok(serialize::IsNull::No)
    }
}
```

I expect it to work on a `TEXT NOT NULL` field. However, when inserting it into the table, I got `DatabaseError(NotNullViolation, "NOT NULL constraint failed: kvs.v")`. And if I feed set_value a borrowed str, it works as intended.

I read the doc and the implementation of [Link: `SqliteBindValue`] but still don't know what went wrong. Could you please help me with this?

The minimal reproduce repo is at [URL]
Discussion
- This seems to be a bug in our bind logic. We handle owned and borrowed values in a different manner to avoid additional allocations whenever possible. The relevant code section is here:
[URL]

The problem there is the `if` statement, which checks if the string is empty or not. For an empty string we just use a null pointer as argument to `sqlite3_bind_text`. Seems like I missed the relevant part of the sqlite documentation:


To fix this we need to remove the special handling of empty strings there. I think it might be fine to just unconditionally execute the other branch, but I've not checked that yet. The same fix needs to be applied to the `InternalSqliteBindValue::Binary` branch a few lines above: [URL]

Also we likely want a test for this, as our CI executes most of the sqlite tests with asan enabled. This might catch additional issues here.

I'm happy to accept a PR for this, if someone want's to touch the corresponding unsafe code. I myself will likely not be able to work on a fix till next week or so.
