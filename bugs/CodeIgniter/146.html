Title

Field data returns one-less fields after query with limit

Description
I'm extending the `query()` from core oci8 driver and I've found bug on `$result->field_data()` (`$result` is an `oci8_result` returned from `parent::query()` method).
The `field_data()` is returning one less fields on subsequent queries after doing select query with `limit()`.

Here's the scenario where it failed:
```
// query with limit
$db->limit(5)->get('TABLE'); // field_data() returns full fields here

// subsequent query
$db->get('TABLE'); // field_data() returns one-less fields
```

Here's how I extends the query() and found the bug:
```
public function query($sql, $binds = FALSE, $return_object = NULL)
{
	$result = parent::query($sql, $binds, $return_object);
        // ............
        $field_data = $result->field_data();
       // dump field_data to check the fields, second query will return one-less fields
       var_dump($field_data); 
}
```
After I trace oci8 driver files, I found that `$this->limit_used` is not reset to `FALSE` after select query is reset. Why it matters? When `$this->limit_used` is `TRUE`,  number of fields that being returned by `field_data()` will be subtracted by 1.

So my fix / workaround is by adding/overriding `_reset_select()` method on `oci8_driver`
```
protected function _reset_select ()
{
        parent::_reset_select();
        $this->limit_used = false;
}
```

Note that this problem occurs only with `oci8` driver.
I hope it's already fixed in future release. 
Thanks.
