Title

[bug] Using glob syntax in tauri.conf "resources" causes error during build: "error running light.exe"

Description
### Describe the bug

Specify glob syntax in `tauri.conf.json`:

```json
"resources": ["./assets/**/*"],
```

This will work during dev, and in fact the assets will be properly bundled into both `/target/debug/` and `/target/release/`.

However, it results in this error after running `npm run tauri build`:

```
Error running CLI: failed to bundle project: error running light.exe: error running light.exe: ``
```

Notes:
- It seems there must be a subfolder inside the `/assets` folder for the error to occur
- If the glob syntax is omitted via `"resources": ["./assets"]`, then it seems that assets inside the subfolder are not re-copied during debug

### Reproduction

**Minimal reproduction in git repo:**
1. `git clone [URL]
2. `npm install`
3. `npm run tauri build`
4. Error occurs

```
Error running CLI: failed to bundle project: error running light.exe: error running light.exe: ``
```

**Repro from scratch:**
1. Create an asset in a nested subfolder, e.g. `/assets/subfolder/resource.txt`
2. Add these resources to `tauri.conf.json` using glob syntax: `"resources": ["./assets/**/*"]`
3. `npm run tauri build`
4. Error occurs

```
Error running CLI: failed to bundle project: error running light.exe: error running light.exe: ``
```

### Expected behavior

Installer should be correctly bundled when using glob syntax for `resources`.
