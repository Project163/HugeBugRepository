Title

quarkus-extension-processor race conditions when modules are built in parallel

Description
When the Quarkus source tree is built with `mvn -T 1C` or with [Link: mvnd] (which internally uses `-T 1C`), the build intermittently fails either in `quarkus-extension-processor` code or in `io.quarkus.docs.generation.AllConfigGenerator`. This is because quarkus-extension-processor reads and writes files in ` /target/asciidoc/generated/config` without any locks or synchronization. When the extension modules are built in parallel, the individual AnnotationProcessor instances overwite eachother's changes. 

Synchronization would be tricky, because the individual AnnotationProcessor instances run in isolated class loaders, so we'd have to synchronize globally on something loaded by the Bootstrap class loader. Locking files would probably lead to a performance bottleneck.

Looking into the details of the data written and read, it seems to be possible to split the files in such a way that each piece is written just once. The ordering of reads after writes should be guaranteed by the module dependency ordering. 

A PR follows.
