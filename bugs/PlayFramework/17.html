Title

Routes parsing breaks with nested parameterized types

Description
This compiles happily in a routes file:

```
GET /my/url @controllers.MyController.something(value: Option[String])
```

However, the parser breaks if you do something like this:

```
GET /my/url @controllers.MyController.something(value: Option[Option[String]])
```

You get an error: 

```
Compilation error[`)' expected but `]' found]
```

I don't believe this has anything to do with missing binders - rather that the parser seems to choke with parameterized parameterized types.
Discussion
- Should be fairly simple to fix, just need to make the routes compiler handle nested square brackets.
- Just ran into this in a java play app trying to map an optional string list:

GET /tags  @controllers.Application.tags(tag: play.libs.F.Option[java.util.List[String]])
- Fixed by #2843, thanks @OlivierBlanvillain
