Title

go-swagger generate server: minItems (maxItems) on array fails during validation. Example version: 0.1.0 paths: ... [Log Snipped] ... type: string

Description
## Problem statement
When using _minItems_ on a array the validation always fails. This should also be true for _maxItems_.

## Problem solution
I could verify that there is a error in the generated code.
Use the swagger spec below to generate a server model:
In _restapi/operations/assets/register_asset_parameters.go_ the generated code (in func BindRequest) looks something like this
```
golang
 1: var body []*models.AssetProperties
 2: if err := route.Consumer.Consume(r.Body, &body); err != nil {
 3:     // .......
 4: } else {
... [Log Snipped] ...
15:	}
16:}
```
**Problem**: ` o.assetProperties` in _Line 5:_ is always a empty slice at this point in time.    

The line  `assetPropertiesSize := int64(len(o.AssetProperties))` must change to `assetPropertiesSize := int64(len(body))`. 

I could narrow the source of the error down to this position [URL] .

I think someone with more experience in templates than me can fix this fairly easy.

## Swagger specification
```
swagger: "2.0"
info:
Name of Asset
```

## Steps to reproduce
```
go-swagger generate server (... with given swagger spec)
```
Then see _restapi/operations/assets/register_asset_parameterts.go_
