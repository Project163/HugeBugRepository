Title

[freeimage] Usage problem. Typedef redefinition in MacOS

Description
**Describe the bug**
There is a problem using FreeImage in MacOS, due to conflicting typedefs with Objetive-C header "objc/objc.h" . It fails both for x86_64 and arm64, just with a different type (see logs below)

**Environment**
- OS: MacOS Ventura 13
- Compiler: Xcode 15. Apple clang 15

**To Reproduce**
Steps to reproduce the behavior:
1. ./vcpkg install freeimage
2. Just include objc/objc.h and FreeImage.h headers in a C++ HelloWorld project.

**Expected behavior**
Build should succeed.

**Failure logs**
x86_64:
```
/Users/ /build_x86/vcpkg_installed/x64-osx-mega/include/FreeImage.h:158:17: error: typedef redefinition with different types ('int32_t' (aka 'int') vs 'signed char')
typedef int32_t BOOL;
                ^
/Applications/Xcode.app/Contents/Developer/Platforms/MacOSX.platform/Developer/SDKs/MacOSX14.0.sdk/usr/include/objc/objc.h:81:25: note: previous definition is here
    typedef signed char BOOL; 
                        ^
```
arm64:
```
/Users/ /build_arm64/vcpkg_installed/arm64-osx-mega/include/FreeImage.h:158:17: error: typedef redefinition with different types ('int32_t' (aka 'int') vs 'bool')
typedef int32_t BOOL;
                ^
/Applications/Xcode.app/Contents/Developer/Platforms/MacOSX.platform/Developer/SDKs/MacOSX14.0.sdk/usr/include/objc/objc.h:78:18: note: previous definition is here
    typedef bool BOOL;
                 ^
```
