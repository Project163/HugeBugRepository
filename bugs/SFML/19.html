Title

sf::Window::Create and rendering are buggy on Mac OS X

Description
The first time a window is created there is no rendering issue but when `Create` is called again (with any parameters) the window is unable to render its graphics content correctly. Then if `Create` is called again everything works fine.

Apparently, this issue appears only on Mac OS X (Leopard and Snow Leopard are concerned but not Lion). I didn't test this on Leopard but I suspect that the problem is also present. I tested also on Ubuntu 11.04 in a virtual box without encountering any trouble, however, I haven't tested it on Windows – I guess the problem would have been found by now as there are many SFML/Windows users.

Here's a minimal code that reproduces the error :

```
#include  

int main (int argc, const char * argv[])
{
    // Create the main window
... [Log Snipped] ...
    return EXIT_SUCCESS;
}
```

Strangely enough, the following code works fine :

```
#include  

int main (int argc, const char * argv[])
{
    // Create the main window
... [Log Snipped] ...
    return EXIT_SUCCESS;
}
```

The only difference between the two code is the use of dynamically allocated memory for the window in the second version instead of classic memory management in the first one.

What is very disturbing is that both code should have exactly the same effect because of `sf::Window` (thus `sf::RenderWIndow`) internal behavior. `Create` method calls `Close` first and then do it's dedicated work (it creats a new OS-specific window object allocated dynamically) and `delete` + `new` call `Close` (in `sf::Window` dtor) and then `Create` (in `sf::Window` ctor) – it really should do the same work!
