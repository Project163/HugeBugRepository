Title

1.5.0.CR1 ClassCastException in multi-module maven project

Description
**Describe the bug**
1.5.0.CR1 introduces a new regression that was not present in 1.4.2.Final.

An invalid ClassCastException occurs within code that was generated by the quarkus-infinispan client during the execution of unit tests.

**Expected behavior**
The Generated code functions without error.

**Actual behavior**
This exception is raised during unit testing:

```
[ERROR] persist_GivenIdentifierWithId_UsesExistingId  Time elapsed: 0.019 s  <<< ERROR!

My hunch is that the annotation processor being used by Infinispan is causing issues for the Quarkus tests.
One reason why I think this is a happening is because if I remove the dependency in Quarkus that brings in the Infinispan annotation processor (`org.infinispan.protostream:protostream-processor`) and simple replace it with with the `protostream` dependnecy, the application gets passed the exception (although it obviously doesn't work because there is no marshaller generated).
- This is due to [URL]

Basically for safety we added in some additional checks for directory elements in the QuarkusClassLoader. Because of the way this project is laid out with parents and children next to each other the discovery generated paths with '../' in them, that interfere with the directory escape protection code.
