Title

Nested order is broken after PIG-3591 in some cases

Description
The following script fail after   PIG-3591  . 
  
 a = load  '1.txt'  using PigStorage( ',' ) as (a0:chararray, a1:chararray);
b = load  '2.txt'  as (b0:chararray);
c = cogroup b by b0, a by a0;
d = foreach c {
    a_sorted = order a by a1 desc;
    generate group, a_sorted, b;
}
dump d;
 
  
 1.txt 
a,0 
a,2 
a,1 

 2.txt 
a 

 Expected: 
  
 (a,{(a,1),(a,2),(a,0)},{(a)})
 
  
 Actual: 
  
 (a,{(a,2),(a,1),(a,0),(a)},{})
Discussion
- The reason is PigSecondaryKeyComparator doesn't sort on index, but POPackage assumes iterator is sorted by index after   PIG-3591  . Before that, if there are multiple inputs, POPackage will create multiple bag and accumulate individually. Now once POPackage sees an index of the last input, it stop accumulating and create a PeekedBag immediately. However, the iterator may have records of other inputs not processed.
- Few questions: 
  1) This is not an issue with Tez right? 
  2)  If we are removing null checks in tuple, won't output be incorrect if cogroup is on multiple keys and they contain null? Most likely there are no test cases covering that scenario. I realized that with self joins for   PIG-4627   and had to add/modify tests to use studentnulltab10k.
