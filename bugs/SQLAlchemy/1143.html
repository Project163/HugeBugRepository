Title

1.4.11 Got Future attached to a different loop when using asyncio.gather()

Description
**Describe the bug**
Hi everyone!

We are using `asyncio.gather()` to run a few tasks that use the same AsyncEngine. It worked fine in 1.4.10, however, it works neither in 1.4.11 nor 1.4.12.

We are getting `Got Future   attached to a different loop` if there is more than one future passed into the `asyncio.gather`.

**Expected behavior**
 

All futures should be processed without errors.

**To Reproduce**

```
py
import asyncio

from sqlalchemy import text
from sqlalchemy.ext.asyncio import create_async_engine
... [Log Snipped] ...
if __name__ == '__main__':
    asyncio.run(main())
```

**Error**

```
Traceback (most recent call last):
  File "/home/fns/workspace/work/example/main.py", line 30, in  
    asyncio.run(main())
  File "/home/fns/.pyenv/versions/3.9.1/lib/python3.9/asyncio/runners.py", line 44, in run
    return loop.run_until_complete(main)
... [Log Snipped] ...
    await fut
RuntimeError: Task   cb=[gather. ._done_callback() at /home/fns/.pyenv/versions/3.9.1/lib/python3.9/asyncio/tasks.py:761]> got Future   attached to a different loop
```

**Versions.**
 - OS: Linux Mint 19.3 / Ubuntu 18.04
 - Python: 3.9.1
 - SQLAlchemy: 1.4.11, 1.4.12
 - Database: PostgreSQL
 - DBAPI: asyncpg

**Additional context**
 
We have figured out that we need to execute any query with engine before using it in the tasks, like this:

```
py
import asyncio

from sqlalchemy import text
from sqlalchemy.ext.asyncio import create_async_engine
... [Log Snipped] ...
if __name__ == '__main__':
    asyncio.run(main())
```

However, we do not understand why.
