Title

Repository redefinition using skylark rules are ok but should error out.

Description
Update by @laszlocsomor: Damien no longer works on Bazel, but this bug is still not fixed with Bazel 0.21.

---

With latest bazel (0.6.1):

Recreation of the repo:
```
bash
$ cat >test.bzl  local_repo/BUILD
```

This creates an error as expected:
```
bash
$ bazel clean --expunge
INFO: Starting clean (this may take a while). Consider using --expunge_async if the clean takes more than several minutes.
$ bazel fetch //...
..............
... [Log Snipped] ...
ERROR: error loading package 'external': Package 'external' contains errors
Building: no action running
```

Now let's use a skylark repository:

```bash
$ cat >WORKSPACE <<'EOF'
local_repository(name = 'local_repo', path = 'local_repo')
load('//:test.bzl', 'my_repo')
my_repo(name = 'local_repo')
EOF
```

Bazel accept it no issue:
```bash
$ bazel clean --expunge
INFO: Starting clean (this may take a while). Consider using --expunge_async if the clean takes more than several minutes.
$ bazel fetch //...
...
$ bazel query //external:local_repo --output=label_kind
my_repo rule //external:local_repo
```
Discussion
- Note that I found the bug while looking at external repo code:

[URL] is throwing the error but Skylark repositories call directly [Link: createAndAddRepositoryRule] which does not have that check.
- The fix (https://github.com/bazelbuild/bazel/commit/ ) was apparently rolled back (https://github.com/bazelbuild/bazel/commit/ ) so I've reopened the bug.
- I confirmed that the bug is still present in Bazel 0.21.0 -- it was never fixed.
- And the bug is also present on Linux.
