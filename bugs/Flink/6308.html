Title

FileSystem.delete is not implemented consistently

Description
The BlobServer cleanup does not work for the Presto S3 filesystem in case of failure due to some bug in the recursive delete implementation. The  false  return value is not processed which leads to an error case being "swallowed", i.e. recursive cleanups do not work in this case (see  PrestoS3FileSystem:496 )
Discussion
- This seems to be deep down in the Presto code, with limited options for any overrides. Can you please outline how do you want to tackle this?
- We should implement the recursive deletion in  FileSystem  and only rely on  FileSystem.deleteFile(path)  (which is a replacement for  FileSystem.delete(path, false) ),  FileSystem.exists(path) , and  FileSystem.listStatuses(path) . We can remove redundant code in  LocalFileSystem  as well due to that. 

  LocalFileSystem  and  HadoopFileSystem  are the only implementations that don't delegate to another  FileSystem  implementation internally.
- Further discussion happened in the PR. No need to backport this change because we don't do retries in older versions of Flink.
