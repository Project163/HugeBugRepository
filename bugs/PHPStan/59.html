Title

`is_iterable` argument typing strange behavior

Description
### Summary of a problem or a feature request

After `is_array` returned `false`, if `is_iterable` is called then the type should be `Traversable`, but it seems that `IterableType` is set without considering previous call on `is_array`.

```
initial type : mixed
$ if (is_array) : return
type : mixed, but not array
$ if (is_iterable) : then
   type : mixed and iterable, but not array 
        => Traversable and array, but not array
        => Traversable
```
### Code snippet that reproduces the problem

[URL]

```
php
class HelloWorld
{
	public function toArray($value): array
	{
... [Log Snipped] ...
	}
}
```

### Expected output

No errors should be reported, but the following error occurs : 
```
Parameter #1 $it of function iterator_to_array expects Traversable, iterable given.
```
Discussion
- Hi,
yes, you described the issue well, it's because PHPStan sees the types like this:

```
php
class HelloWorld
{
	public function toArray($value): array
	{
... [Log Snipped] ...
	}
}
```

That's because a feature called "complement types" that would do exactly what you described, isn't yet implemented.

You have  two ways of fixing this: Either change the second `if` to `$value instanceof Traversable` (https://phpstan.org/r/ ) or add a typehint to the method (https://phpstan.org/r/ ):


```php
public function toArray(iterable $value): array
```

If you're at least on level 5, you can them simplify the method body like this:

```
php
class HelloWorld
{

	public function toArray(iterable $value): array
... [Log Snipped] ...
	}
}
```

Because PHPStan checks that nothing else actually get passed to the method (even when the type is just in phpDoc) 😊
- or if you want to preserve mixed parameter
```
php
class HelloWorld
{
    public function toArray($value): array
    {
... [Log Snipped] ...
    }
}
```
