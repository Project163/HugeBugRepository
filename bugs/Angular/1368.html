Title

`providedIn: null` has the same effect as `providedIn: 'root'`

Description
# 🐞 bug report

### Affected Package
 
  The issue is caused by package @angular/core.

### Is this a regression?

 
  No, I don't think so.


### Description

  Creating a service/token with `providedIn: null` makes it still be able to be injected. Actually, not sure if this is by design, though.

#### Steps to reproduce
- Create a service/token with `providedIn: null`, e.g.
```
typescript
import { InjectionToken } from '@angular/core';

export interface MyService {
  getValue(): any;
... [Log Snipped] ...
  }
});
```

- Inject the service to a component, e.g.
```typescript
export class HelloComponent  {
  @Input() name: string = 'Glenn';

  constructor(@Inject(MY_SERVICE_TOKEN) private myService: MyService) {
    console.log(`myService value: ${myService.getValue()}`);
  }
}
```

- Observe whether it throws.

#### Actual
- The "providedIn: null" service is still able to be injected.

#### Expected
- The "providedIn: null" service should not be able to be injected and Angular should throw.
