Title

Response::sendContentAsFile() broken in Yii 2.0.3

Description
This commit (https://github.com/yiisoft/yii2/commit/ ) changed the first line of yii\web\Response::prepare() from:

``` php
if ($this->stream !== null || $this->data === null) {
```

to:

``` php
if ($this->stream !== null) {
```

and now, sendContentAsFile() responses (which have `$this->content` but not `$this->data`) are no longer passing the condition. As a result, they proceed down the function, hitting this condition:

``` php
} elseif ($this->format === self::FORMAT_RAW) {
    $this->content = $this->data;
} ...
```

overwriting `$this->content` (which sendContentAsFile() had set to the file’s contents) to `null`, resulting in a response that has no body.

Given a version number MAJOR.MINOR.PATCH, increment the:
1. MAJOR version when you make incompatible API changes,
2. MINOR version when you add functionality in a backwards-compatible manner, and,
3. PATCH version when you make backwards-compatible bug fixes.

When new features added by following SemVer you should raise MINOR version. That means that we should have: 2.1.0, 2.2.0, 2.3.0 already. Patch versions used only for patches. Usually it work next way: master and develop branches. You merge develop with master only when you plan raise MINOR version. Patches very useful for force major situations like that to make new fw version available ASAP. If short Yii use PATCH section for MINOR purposes.
