Title

Winding order in equirectangular projection.

Description
I’ve found an angle in the equirectangular projection using world-110m.json that seems to exhibit a winding order bug:

[Link: [Image: screen shot 2013-06-08 at 8 50 10 am]]

This is using the world-110m.json from gist 4090846 (actually slightly out of date, but I tried updating it and the behavior was identical), which is derived from Natural Earth 1:110M with no simplification.

Interestingly, the problem fixes itself when you apply a clipExtent to the viewport.
Discussion
- I’ve isolated it to this polygon in Russia:

```
json
{
  "type": "Feature",
  "id": 643,
  "properties": {},
... [Log Snipped] ...
  }
}
```
- Seems to be d3_geo_clipAreaRing returning a negative visible area (-5.011506098654028) for this `segment` input:

```
json
[
  [-3. , -0. ],
  [-3. , +0. ],
  [-3. , +0. ],
... [Log Snipped] ...
  [-3. , -0. ]
]
```

I converted these back to degrees and ran it through d3.geo.area:

```
js
d3.geo.area({
  type: "Polygon",
  coordinates: [[
    [-180.00000000000000, -0. ],
... [Log Snipped] ...
  ]]
})
```

Which a more reasonable positive result: 0. . So my first inclination is to say this is a problem with the approximate ring area algorithm used during clipping.
- Fix staged in #1285.  I extracted the point-in-polygon algorithm from the clip-polygon branch and optimised it a bit.  It’s a tiny bit slower than before, but it’s accurate.  I also optimised d3.geo.resample, which means there is roughly zero net performance change here. ;)
