Title

`--json` with empty body doesn't set Content-Type

Description
I'd expect `--json` to explicitly set the Content-Type header, even when no request items are present.
Instead, I'm seeing:

```
POST /api/message/in/14/ HTTP/1.1
Accept: application/json
Accept-Encoding: gzip, deflate, compress
Content-Length: 0
Host: ca.dev
User-Agent: HTTPie/0.5.0-alpha
```

which the server is defaulting to `text/plain`.

 It's not immediately clear from RFC2616 if Content-Type should be present without a body, but there's at least 1 similar spec (for SIP: in [Link: RFC3261 sec 20.15]) that provides the rationale:

Which I think is valid here as well; an empty file can still be a valid document of a given type.

So, I'd suggest that `--json` (and `--form`) always provide an over-the-wire Content-Type header in the request.
