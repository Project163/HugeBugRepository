Title

Dropbox: rclone repeatedly uploads the same file even though the file has the same content as the old file but a different modification time

Description
#### What is the problem you are having with rclone?
rclone repeatedly uploads the same file even though the file has the same content (same checksum) as the old file but a different modification time.

##### How to reproduce
1. Create a text file with one character in it.
2. Wait until files are synchronised.
3. Wait for a period of time larger than `--max-window`.
4. Modify the file modification time without modifying the content.
5. Sync using rclone.
6. Sync again to see it being re-uploaded.
Note that the modification time shown on the Dropbox web interface will not change after synchronisation using rclone.

#### What is your rclone version
Problem is reproducible on both rclone stable v1.40 and rclone beta.
```
rclone v1.40-045-g0358e9e7
- os/arch: windows/amd64
- go version: go1.10
```

#### Which OS you are using and how many bits
Windows 7 SP1, 64 bit

####  Which cloud storage system are you using?
Dropbox

Discussion
- Thanks for tracking that down and the nice reproduction.  I can verify that.

Dropbox can't set modification times on files without uploading them again.  Unfortunately dropbox has a bug where if you upload the same file with the same contents but a different modification time, it doesn't update the modification time.

To work around this, rclone should delete the existing file first - that is what v1.39 did anyway.

However in the process of fixing #2134 -   it stopped deleting the file before  upload and caused this issue.
