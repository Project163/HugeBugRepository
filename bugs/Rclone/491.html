Title

rclone mount failing at boot on new FreeBSD 12.1-RELEASE

Description
#### What is the problem you are having with rclone?
I just updated my system to FreeBSD 12.1-RELEASE. Along with this release comes some improvements to fusefs, outlined here: [URL]
Another notable change is the kernel module loaded is now fusefs.ko instead of fuse.ko

Here is the problem: 
At boot I mount a gdrive using @reboot in my crontab with the following command:
@reboot rclone mount -vvv --allow-other --allow-non-empty --log-file /var/log/rclone.log --fast-list --vfs-read-chunk-size-limit off --timeout 1h --daemon --daemon-timeout 0 cachedrive: /mnt/gcache

Something goes wrong and it doesn't mount correctly, an error is attached below.
All I have to do is rerun the command from my terminal and everything mounts correctly. No other changes were made, just a simple running of the command again.

- Hi. You also can fix it by port patch.
Just add to /usr/ports/net/rclone/Makefile:
```
post-patch:
        @${REINPLACE_CMD} -e 's|panic("opBmap")|goto unrecognized|' ${WRKSRC}/vendor/bazil.org/fuse/fuse.go
```
before line  `.include  `

Complete Makefile looks like this:
```
# $FreeBSD: head/net/rclone/Makefile 518968 2019-12-03 21:50:58Z woodsb02 $

PORTNAME=       rclone
DISTVERSIONPREFIX=      v
DISTVERSION=    1.50.2
... [Log Snipped] ...

.include  
```
I've tested mount with two remotes (yandex disk and s3 like), works fine last few hours.
