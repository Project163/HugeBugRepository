Title

org.codehaus.groovy.runtime.metaclass.MetaClassRegistryImpl#registerMethods should not call System.exit

Description
After an unexpected exit from our app, I saw that org.codehaus.groovy.runtime.metaclass.MetaClassRegistryImpl#registerMethods has an System.exit routine. 

 We are using groovy from within our Java application. It actually killed our app due to a configuration issue. 

 The groovy engine should throw an exception not System.exit. 

 I suggest to review all System.exit calls and replace them with throwing an exception.
Discussion
- The title should be : org.codehaus.groovy.runtime.metaclass.MetaClassRegistryImpl#registerMethods should NOT call System.exit
- Also it called System.exit(0) indicating that it is a clean exit which it is not.  

 My suggestion to anyone integrating this groovy library to install their own security manager and override the checkExit method.
- Corrected the issue title as noted in the comment.
- One more place from where System.exit() should be replaced by an exception is org.codehaus.groovy.reflection.GeneratedMetaMethod.Proxy#createProxy(). 

 Anyone sees any issue with replacement of these 2 instances by throwing an exception?
