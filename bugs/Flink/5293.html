Title

CREATE TABLE LIKE cannot reference tables in HiveCatalog

Description
create a table like with a hive catalog table 

  CREATE TABLE  temp_order 
 WITH  ( 
  'properties.group.id'  =  'test1'  ,   'properties.bootstrap.servers'  =  'kafka.address' ) 
 LIKE  hive.ods.flink_order 

 It has a error, log is : 

   

 Exception in thread "main" org.apache.flink.table.api.ValidationException: Unable to create a source for reading table 'default_catalog.default_database.test_taos_customer_agent_cinema'. 

 Table options are: 

 'connector'='upsert-kafka' 
'is_generic'='true' 
'key.format'='json' 
'properties.bootstrap.servers'='kafka.address' 
'properties.group.id'='test1' 
'topic'='topic1' 
'value.format'='json' 
... 
Caused by: org.apache.flink.table.api.ValidationException: Unsupported options found for connector 'upsert-kafka'. 

 Unsupported options: 

 is_generic 

   

 the ’is_generic‘ option is  added by hive catalog,  but  `kafka` connector  does not support this  option.
Discussion
- I have a solution: 

  CREATE TABLE  temp_order 
 WITH  ( 
  'connector' = 'upsert-kafka'  ,   'key.format' = 'json'  ,   'topic' = 'topic1'  ,   'value.format' = 'json'  ,   'properties.group.id'  =  'test1'  ,   'properties.bootstrap.servers'  =  'kafka.address' ) 
 LIKE  hive.ods.flink_order 
( 
    EXCLUDING OPTIONS 
) 

   

 It's not perfect, you  must to  overwrite  all options
- I'd prefer to deprecate the  "is_generic"  flag, and follow flink's convention to use  "connector"  to distinguish hive and non-hive tables. I guess it'll make the logic simpler and avoid more issues in the future. 

 If we do that, we need to keep backward compatibility in mind – tables created by an older HiveCatalog should continue to be usable after this change.
