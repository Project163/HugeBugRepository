Title

Surprising memory consumption when extracting images

Description
ExtractImages seems to fail to release memory resources on some files in both PDFBox 1.8.5 and trunk.   

 On this file 4MB file  [URL] if extracting every image on every page (and there are many, many duplicate images), there is an OOM with -Xmx1g.  If there is no Xmx and there is > 2.5g available, ExtractImages will work. 

 With some experimentation, the triggers seem to be JPEG images that have masks.  I'm not sure, though, whether the issue is with PDFBox or Java. 

 Commandlines: 
1.8.5: 
java -Xmx1g -cp pdfbox-app-1.8.5.jar org.apache.pdfbox.ExtractImages 239665.pdf 

 2.0_SNAPSHOT: 
java -Xmx1g -cp pdfbox-app-2.0.0-SNAPSHOT.jar org.apache.pdfbox.tools.ExtractImages -addkey 239665.pdf

Discussion
- I can confirm the described OOM on windows 7 64bit but NOT on linux fedora 20. I've checked both for pdfbox 1.8.5.
- While working on this it should be considered to switch to the ByteArrayOutputStream provided by Commons IO which doesn't need to constantly copy arrays when growing. That makes it faster  and it has a lower peak memory consumption  (that is only true if you can use the writeTo(OutputStream) method and don't need the toByteArray()).
