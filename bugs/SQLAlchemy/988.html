Title

Give more details in LookupError message

Description
`LookupError` raised in `Enum` methods has the following message:
```'LookupError: "%s" is not among the defined enum values' % elem```

For easier debugging I think it would be helpful to include the enum name and possible values in the error message.

I'm happy to implement it if it sounds plausible.
Discussion
- note that enums don't need to have names unless they are Postgresql specific, however adding the name to the message if one is available should be fine.   

As far as possible values, this is also a good idea, but for it to be robust it would need to be implemented so as not to create an error message that is too long - assume some people have enums with 500 names in them and/or names that are hundreds of characters long.         There is a class that is used for this task within the realm of bound parameter sets at [URL] this is more complicated than what's needed here, a new helper function _repr_tuple_names() can be added to util/langhelpers.py that will list out the string entries of a given tuple using ellipses for more than four values, as well as use ellipses for very long names:

```
'foo', 'bar','bat',  ... 'hoho'
'foo', 'bar', 'someverylongnametha...', .., 'hoho'

```
