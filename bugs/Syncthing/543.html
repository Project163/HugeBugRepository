Title

Symlinks marked as removed on windows

Description
symlinks created on a Linux machine are being removed by a Windows machine. Syncthing used to warn it cannot sync it, but for a while now this is no longer true.

The links are within the repository, so are supported (or at least used to be). Even if I forget to run as admin in the Windows machine, I do not want it to delete files! In any case I tested with admin as well.

I would be happy run a special debug mode or provide whatever other info is needed,
thanks

- I know what's the problem here: With fine grained local flags instead of just one boolean the condition used when detecting deleted files isn't sufficient anymore:  
[URL]
In this concrete example on windows: Symlink is marked as unsupported on pull. Then on scan `IsIgnored` is false, so the deletion check is performed, which is positive (there is no symlink) -> file info is wrongly marked as deleted.
