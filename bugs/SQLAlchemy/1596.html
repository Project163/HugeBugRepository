Title

fix SQL form for batch mode with explicit server function

Description
for #13014 we need to fix what's essentially a bug in 2.0 as well, which is given this:

```
py
import uuid

from sqlalchemy.orm import DeclarativeBase
from sqlalchemy.orm import Mapped, Session
... [Log Snipped] ...
    sess.add_all([MyClass(data=f"i {i}") for i in range(50)])
    sess.commit()
```

we render this:

```
INSERT INTO my_table (data, id) SELECT p0::VARCHAR, p1::INTEGER FROM (VALUES (%(data__0)s, nextval('foo_id_seq'), 0), (%(data__1)s, nextval('foo_id_seq'), 1), (%(data__2)s, nextval('foo_id_seq'), 2), (%(data__3)s, nextval('foo_id_seq'), 3), (%(data__ ... 1953 characters truncated ... 9)) AS imp_sen(p0, p1, sen_counter) ORDER BY sen_counter RETURNING my_table.id, my_table.id AS id__1

```

which is wrong, it should be this:

```
INSERT INTO my_table (data, id) SELECT p0::VARCHAR, nextval('foo_id_seq')::INTEGER FROM (VALUES (%(data__0)s, 0), (%(data__1)s, 1), (%(data__2)s, 2), (%(data__3)s, 3), (%(data__ ... 1953 characters truncated ... 9)) AS imp_sen(p0, p1, sen_counter) ORDER BY sen_counter RETURNING my_table.id, my_table.id AS id__1

```

VALUES is ordered and delivers the rows to the SELECT in that order, that's where the server default function has to be called.  we can't rely on the individual tuples inside of VALUES running their embedded functions in that order (even though there's no practical reason they wouldn't).

this proposed form matches what I mentioned at [URL] and what Tom Lane referred to at [URL] .

this can likely be contained within visit_insert() in the `if use_insertmanyvalues:` block, but we have to modify the statement as well as the InsertManyValues structure we pass from that point onwards and it's pretty gnarly.

after this, we can then do #13014 which will add support for server side functions like `uuidv7()` to work.

- claude:

Yes, in the second statement (the direct one), the order in which nextval() is executed will match the order of the VALUES tuples as sorted by ORDER BY num.
INSERT INTO mytable (id, a, b)
SELECT nextval("mytable_id_seq"), p1, p2 FROM (VALUES (10, 11, 1), (12, 13, 2)) AS sel(p1, p2, num) 
ORDER BY num
RETURNING mytable.id
In this case:
The VALUES are sorted by num (so order is: (10, 11, 1) first, then (12, 13, 2))
The SELECT processes rows in that sorted order
nextval() is called for each row in that order
First nextval() call → row with p1=10, p2=11
Second nextval() call → row with p1=12, p2=13
