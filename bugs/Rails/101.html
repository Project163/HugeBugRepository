Title

[Regression 4.0 => 4.1] Changed a way to serialize empty hash

Description
After this patch:
[URL]

We have a problems migrating our app to 4.1 because:

``` ruby
sites_path(a: {}) # => "/sites?" in 4.0
                # "/sites?a=" in 4.1
```

It causes  `params[:a]` return an empty string instead of `nil`. That is kind of significant behaviour change.

Not sure this is right to serialize empty hash as an empty string.

`jQuery` for example have a different opinion on this:

``` js
jQuery.param({})  // => ""
jQuery.param({a: {}}) // => ""
jQuery.param({a: {b: {}}}) // => ""
```

I think we should implement the empty hash serialization in the same way:
1. It is backward compatible
2. It will be consistent with implementation in other frameworks.
Discussion
- Not sure how to handle this. If we change this on 4.1.1 people who is relying on this new behavior will have regressions.
- I think 99% of production code still runs 4.0 so far and we will cause more problems to people who have not upgraded yet than people who have already upgraded.

Rails was released 3 weeks ago. It means that people were leaving with an issue fixed by  326e652 for 5+ years and it was completely unusable before.

And it sound even better to fix issue now than live with not the best solution forever.

So I am pretty sure it is better to fix it now than wait until huge production app maintainers (like me) will blame us all.
- Yes. :+1:
