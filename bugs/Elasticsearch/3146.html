Title

Nested synthetic source fails to load vectors correctly

Description
### Elasticsearch Version

8.17

### Installed Plugins

### Problem Description

When using synthetic mode with nested fields, children fields may remain unloaded. This occurs when the fields present in the children docs are not uniform (e.g. when a child is missing a particular field).

```
DELETE synthetic_test

# simple minimal mapping
```

This indicates:

```
    @Override
    public int advance(int target) throws IOException {
      assert docID() < target;
      return disi.advance(target);
    }
```

Which tells me that when we are advancing to gather the children doc vectors, we aren't handling missing values.

Seems like we ask for child doc `1`, that value isn't there so advance goes doc `4`, but the next child doc to load is value `2`, so we call advance again, but on a previously skipped doc.

I am not sure if fixing the this iteration issue would actually fix the bug. But it would prevent this assertion from being tripped.
