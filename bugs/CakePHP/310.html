Title

3.0 - ORM failing count() after all(), PaginatorComponent

Description
I just tested CakePHP3.0 and I encountered a problem with the ORM that seems to crash when doing an all() followed by a count(); 

```
    $query = TableRegistry::get('Posts')->find('all', [
        'fields'   => ['Posts.id', 'Posts.name'],
        'contain'=> ['Users'],
        'limit'     => 10
    ]);
    debug($query->all()); // object(Cake\ORM\ResultSet)
    debug($query->count()); // SQLSTATE[42000]: Syntax error or access violation: 1066 Not unique table/alias: 'Users'
```

Calling the two methods in the reverse order works

```
    $query = TableRegistry::get('Posts')->find('all', [
        'fields'   => ['Posts.id', 'Posts.name'],
        'contain'=> ['Users'],
        'limit'     => 10
    ]);
    debug($query->count()); // (int)
    debug($query->all()); // object(Cake\ORM\ResultSet)
```

This problem also affect the paginatorComponent (since it calls the same methods in the same order) 
## The problem

Calling all() seems to affect the query and the next calls.
## The solution

Call count() before find() in the PaginatorComponent
AND/OR
Fix the all() method
