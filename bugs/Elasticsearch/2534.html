I just checked 7.9 and that was OK so this was a new problem added in 7.10, probably as a result of the refactoring of mappers and field types  e.g.  

The code that fails is [Link: this line] where we try retrieve an `AnnotatedText` object from one of possibly several values (e.g. when a doc has an array of values).  Each time the TokenStreamComponents is called with a new java.io.Reader we assume we are moving on to the next array item in the same document/field.

What looks to be happening is `wrapComponents` is now only being called once which therefore doesn't reset the `readerNum` counter between documents. When the Reader for the second document's text is presented we increment that counter with the false assumption that we are trying to read the second array value of the first document.

I have [Link: a PR] that fixes this by re-initializing the readerNum counter whenever the setAnnotations method is called.
