Title

Router should not export Type Interface

Description
We currently get two docs exported for Type Interface: one for core, and one for router. This is confusing -- and I think unnecessary duplication? Can we make Router depend on the Type exported from core?
Discussion
- The router does depend on `Type` from core, but because it exposes a class with member of type `Type`, it must also re-export `Type` or TypeScript is unhappy.

@mprobst @alexeagle any ideas?
- I think that is WAI in TypeScript, if you don't re-export, downstream clients cannot understand your type signatures. You could re-export or relax the field to be of type `any`.

is the field private by chance? Because if so, then it'd be a valid feature request for TS to support this use case (not being required to re-export private fields).
