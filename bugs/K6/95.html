Title

rps=0 value causes a GoError

Description
### Brief summary

Setting the above parameter in the options object causes a GoError to be thrown during the run. Tested this on both local runs and k6 Cloud, the behaviour is the same.

### k6 version

k6 v0.38.3

### OS

macOS 12.4

### Docker version and image (if applicable)

_No response_

### Steps to reproduce the problem

setting an option `rps` in the options object to a value of 0

`export let options = {
    rps: 0,
    "stages": [
        {
            "duration": "5s",
            "target": 15
        },
        {
            "duration": "2m",
            "target": 15
        },
        {
            "duration": "5s",
            "target": 0
        }`
        
causes the following exeption:

`ERRO[0042] GoError: rate: Wait(n=1) exceeds limiter's burst 0
Run    [at go.k6.io/k6/js/modules/k6/http.(*RootModule).NewModuleInstance.func2 (native)
        at file:///Users/nobody/Documents/GitHub/Demo-scripts/SimpleDemo.js:34:12(5)
        at native
 executor=ramping-vus scenario=default  instance_id=1 lz="amazon:ie:dublin" source=stacktrace test_run_id=1429887
` 

### Expected behaviour

It would be expected either a validation/config error to be thrown out or that the `rps` limit is disabled/unlimited.

### Actual behaviour

the test runs successfully, but it throws out the errors constantly in the console:

`ERRO[0042] GoError: rate: Wait(n=1) exceeds limiter's burst 0
Run    [at go.k6.io/k6/js/modules/k6/http.(*RootModule).NewModuleInstance.func2 (native)
        at file:///Users/nobody/Documents/GitHub/Demo-scripts/SimpleDemo.js:34:12(5)
        at native
 executor=ramping-vus scenario=default  instance_id=1 lz="amazon:ie:dublin" source=stacktrace test_run_id=1429887
`
