Title

prefer-template autofixer should not convert a string to a template if it contains an octal escape sequence

Description
**Tell us about your environment**

* **ESLint Version:** 4.18.1
* **Node Version:** 9.6.1
* **npm Version:** 5.6.0

**What parser (default, Babel-ESLint, etc.) are you using?**

**Please show your full configuration:**

 
 Configuration 

 
```yml
rules:
  prefer-template: error
parserOptions:
  ecmaVersion: 6
```

 

**What did you do? Please include the actual source code causing the issue, as well as the command that you used to run ESLint.**

 
```js
'\033' + foo
```

 
```bash
eslint theFile.js --fix
```

**What did you expect to happen?**

I expected no autofix to happen, because the string `'\033'` contains an octal escape sequence, which is a syntax error when it appears in a template literal.

**What actually happened? Please include the actual, raw output from ESLint.**

The problem was automatically fixed, resulting in a syntax error.

```
1:2  error  Parsing error: Octal literal in strict mode
```

(Note: the error message is a bit misleading; this is a parsing error because the resulting string is a template literal, not because it's in strict mode.)

- @MuraliNunna Thanks for looking into this! You're correct that ESLint just catches parser errors and reports them as linting errors. However, I think there are a few issues with the test code that you're using, which are preventing it from being a good demonstration of this issue.

* The test code is running in strict mode, due to the `"use strict"` directive at the top. However, using octal escape sequences is a syntax error in strict mode, regardless of whether it's in a template literal, so the `prefer-template` rule never runs in that case.
* The test code is concatenating two string literals (`"\033"` and `"postfix"`). However, the `prefer-template` rule only reports an error when concatenating a string literal with something other than a string literal (e.g. a variable).

Have you tried using the example code and configuration that were provided in the original issue? I think if the source file only contains `'\033' + foo` (with nothing else), and only the `prefer-template` rule is enabled, it will be easier to trigger this bug.
