Title

Byte array responses break if quarkus-amazon-lambda-http is used

Description
### Describe the bug

When adding the quarkus-amazon-lambda-http extension to the starter project using only quarkus-rest, Quarkus fails to return a simple byte array containing all 255 bytes from 0x00 to 0xff if it does not recognize the mime type in `@Produces`

Observing this bug does not require deploying to AWS and can be observed locally in dev mode.

### Expected behavior

Viewing the response with xxd hex viewer yields the same response as when not using the quarkus-amazon-lambda-http extension

```
00000000: 0001 0203 0405 0607 0809 0a0b 0c0d 0e0f  ................
00000010: 1011 1213 1415 1617 1819 1a1b 1c1d 1e1f  ................
00000020: 2021 2223 2425 2627 2829 2a2b 2c2d 2e2f   !"#$%&'()*+,-./
00000030: 3031 3233 3435 3637 3839 3a3b 3c3d 3e3f  0123456789:; ?
00000040: 4041 4243 4445 4647 4849 4a4b 4c4d 4e4f  @ABCDEFGHIJKLMNO
... [Log Snipped] ...
000000e0: e0e1 e2e3 e4e5 e6e7 e8e9 eaeb eced eeef  ................
000000f0: f0f1 f2f3 f4f5 f6f7 f8f9 fafb fcfd feff  ................
```

### Actual behavior

All the bytes with leading 1 bit are broken:
