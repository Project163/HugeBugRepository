Title

[YSQL] PG15 Online Upgrade fails with tablegroups, indexes, and permissions

Description
Jira Link: [Link: DB-14004]
### Description

```
sql
CREATE USER user_3;
GRANT CREATE ON SCHEMA public TO user_3;

CREATE TABLEGROUP test_grant;
... [Log Snipped] ...
CREATE TABLE e(i text) TABLEGROUP test_grant;
CREATE INDEX ON e(i);
```

and then upgrading results in the pg_restore output:
```
pg_restore: connecting to database for restore
pg_restore: dropping DATABASE PROPERTIES yugabyte
pg_restore: dropping DATABASE yugabyte
pg_restore: creating DATABASE "yugabyte"
pg_restore: connecting to new database "yugabyte"
... [Log Snipped] ...
pg_restore: error: could not execute query: ERROR:  tablegroup with OID 16384 does not exist
Command was: CREATE INDEX "e_i_idx" ON "public"."e" USING "lsm" ("i" ASC);
```

Discussion
- After fixing one or more basic bugs here, I'm running into a permission issue I believe is caused by upstream PG commit  , combined with us not properly setting the tablegroup's ACL. The following is during mixed mode, after the catalog upgrade is complete:
```
[PG11]
yugabyte=# SELECT tg.oid, tg.grpname AS tg_owner, r.rolname, tg.grpacl FROM pg_yb_tablegroup tg, pg_roles r WHERE tg.grpowner = r.oid;
  oid  |  tg_owner  | rolname  |                 grpacl
-------+------------+----------+-----------------------------------------
 16384 | test_grant | yugabyte | {yugabyte=C/yugabyte,user_3=C/yugabyte}
... [Log Snipped] ...
 16384 | test_grant | yugabyte |
(1 row)
```

I think the right thing to do here is just to correctly populate the tablegroup's ACL during the upgrade.
