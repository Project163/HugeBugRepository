Title

Bug: Inconsistent behavior for `ignores: ["/"]`

Description
### Environment

Node version: v22.5.1
npm version: v10.8.2
Local ESLint version: v9.7.0 (Currently used)
Global ESLint version: Not found
Operating System: linux 6.9.9-zen1-1-zen

### What parser are you using?

Default (Espree)

### What did you do?

 
 Configuration 

```
export default [
  { ignores: ["/"] },
  { rules: { "no-console": "error" } },
];
```
 

```js
// file.js
console.log();
```

```js
// subdir/file.js
console.log();
```

### What did you expect to happen?

Either both or none of the two files are ignored.

### What actually happened?

Only `file.js` is ignored.

### Additional comments

[URL]

`isDirectoryIgnored` does not check whether `directoryPath` is an empty string before splitting.

- For input `""`, it checks `"/"`
- For input `"foo"`, it checks `"foo/"`
- For input `"foo/bar"`, it checks `"foo/"` and `"foo/bar/"`
Discussion
- Thanks for the issue! I can also reproduce this.


Paths in `ignores` should be relative, so `/` should have no effect, and thus none of the two files should be ignored.




Indeed, this is likely the culprit. I'm working on the fix.
