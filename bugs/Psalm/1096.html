Title

Array extended by += thinks that values are mixed

Description
psalm version: 3.8.5
php version: 7.4.7
issue type:  bug

The following code reproduces the issue:

```
 , array{a: PsalmIssue\TestInstance, b: PsalmIssue\TestInstance, c: PsalmIssue\TestInstance, d: PsalmIssue\TestInstance|mixed, e: PsalmIssue\TestInstance|mixed} provided
    new Expector($a);
```

```
ERROR: InvalidArgument - src/psalm-issue.php:44:15 - Argument 1 of PsalmIssue\expectoir expects iterable , array{a: PsalmIssue\TestInstance, b: PsalmIssue\TestInstance, c: PsalmIssue\TestInstance, d: PsalmIssue\TestInstance|mixed, e: PsalmIssue\TestInstance|mixed} provided
    expectoir($a);
```

To my surprise the closure and arrow functions do not throw the same error. Maybe psalm does not read those annotations above closures?

Anyway, even though the array `$a` in the example contains only instances of `TestInstance` class, psalm reports detected type `TestInstance|mixed`. If I remove the call to `array_map`, the values under keys `d` and `e` no longer are detected as `|mixed` and no error is triggered, which is the expected behaviour even if the array_map statement is present.
