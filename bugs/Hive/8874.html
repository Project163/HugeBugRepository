Title

CI fails intermittently cause some runs exceed ephemeral storage limits

Description
The CI fails intermittently cause some runs/splits exceed the 20Gi limit on ephemeral local storage that was set recently (  HIVE-28954  ) and the respective pods are being evicted. 
 
	  [URL]
	  [URL]
	  [URL]
 

  
 Unable to create live FilePath for hive-precommit-master-2603-3bz8w-bkgst-7wgqt; hive-precommit-master-2603-3bz8w-bkgst-7wgqt was marked offline: Pod failed (Reason: Evicted, Message: Pod ephemeral local storage usage exceeds the total limit of containers 20Gi. )
Discussion
- Having a limit (as indicated in   HIVE-28954  ) is useful to protect against  runs that consume unreasonably large storage space but we probably have to revisit the upper bound given the number of failed runs recently.
- I gathered some disk usage statistics from  PR-5946  that is currently running and where split-12 failed due to the storage limit using the following script: 

  
 
node=hive-precommit-pr-5946-2-nlm1g-nckm6-tp8xd; while  true;  do  date; kubectl exec  $node  -c hdb -- du /home/jenkins/agent/workspace/hive-precommit_PR-5946 -h --max-depth=1; kubectl exec  $node  -c hdb -- du / -h --max-depth=1; sleep 30s;  done  > pr5946-du.log
 
  

 As it can be seen from    pr5946-du.log      just before the failure the hdb container was consuming in total 24G of space: 

  
 1.5G	/home/jenkins/agent/workspace/hive-precommit_PR-5946/packaging
3.8G	/home/jenkins/agent/workspace/hive-precommit_PR-5946/.m2
7.3G	/home/jenkins/agent/workspace/hive-precommit_PR-5946/itests
15G	/home/jenkins/agent/workspace/hive-precommit_PR-5946
15G	/home
4.4G	/usr
4.1G	/work
24G	/
 
  

 I am pretty sure that what lies under the hive-precommit_PR-5946 directory (i.e., 15G) definitely accounts for ephemeral storage. I am less sure if  /work and /usr account for ephemeral storage but based on the current observations we definitely have to bump up the request/limit fields. 

 For the rest, it would be useful to understand what in itests folders amounts to 7GB (if its normal or regression) but we can do this after we stabilize CI.
- Closing the jira as the fix seems to have merged.
- I noticed branch-4.1 also has this issue, i will cherry-pick this change into branch-4.1.
