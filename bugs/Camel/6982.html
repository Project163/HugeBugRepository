Title

camel-kafka - KafkaIdempotentRepository misses continuous updates from its topic after startup

Description
With   CAMEL-20218   and   CAMEL-20373   the initialization of the  KafkaIdempotentRepository  has been changed and seems to work fine. 

 One purpose of a  KafkaIdempotentRepository  is to synchronize an idempotence state over multiple processes (running in parallel on potentially different machines). So a key feature of a  KafkaIdempotentRepository  is the continuous update of the local in-memory cache with add/remove events from the idempotent repository's topic  after initialization . With Commit     this capability got lost. 

 I absolutely hope this happened unintentionally and will be fixed soon. 

  Side Note  
I was surprised to see, that consuming from the idempotent repository's topic worked without providing a consumer group even though we have Kafka's access control activated, restricting describe/read access of this topic to dedicated consumer groups only.
Discussion
- Ah okay so the new code will populate the cache to be up-to-date on startup, and then afterwards it does not sync over changes from other nodes that may use the same topic. 

 In that case, maybe there should be an option to turn on|off whether to sync continuesly or only on startup
- Yeah the groupId should be supported and we should set it on the kafka configuration if configured.
