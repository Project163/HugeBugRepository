Title

Node runs out of memory running our builds

Description
I've seen it crash on JS bundle tasks and `build/pure-packages.dart`. @hterkelsen reports it crashing on JS sourcemaps.

Workaround: `node --max-old-space-size=2000 ./node_modules/.bin/gulp {TASK}`

(2000 is 2GB)
- [ ] fix the underlying issue
- [ ] remove the heap config workaround from `scripts/publish/npm_publish.sh`
Discussion
- i merged this one yesterday to try mitigate the JS/source map end without getting too invasive, and it seemed to help somewhat, but might need a bit more work. [URL]

See also [URL] as we're likely to be re-orging this
- I was _so_ happy that we can run this bundling in parallel :-) But yeh, if it gives trouble to our build infrastructure we can easily re-shape it to do things sequentially. Provided that we are sure that this is the root cause, of course.
- ... [Middle Discussions Snipped for Brevity] ...
- @pkozlowski-opensource is looking into this. I don't think that we'll be able to reduce the memory usage easily without impacting the total build time, so let's increase the heap size by default when calling `gulp build.js` (or more specifically the bundle task that causes the OOM).

This will require spawning a new process from within the gulp process but that should be a big deal. We just need to make sure that it's done a cross-platform compatible way.
- Why not allocate more memory to the entire gulp process, rather than start a sub-process? Is it to avoid parts of the build outside of bundling that start to rely on more available heap?

One solution is to use npm run-scripts in the `package.json` so the memory settings are saved with the gulp command to run, eg

```
"scripts": {
  "build": "node --max-old-space-size=2048 ./node_modules/.bin/gulp build.js"
}
```

(I'm trying this now because I have the same issue on Circle, which already uses `npm run build` rather than shell scripts as the build step)
