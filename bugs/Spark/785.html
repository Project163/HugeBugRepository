- matei  any thoughts on this issue?
- I'm not completely sure that this is because hashCode provides a partial ordering, because I believe TimSort is supposed to work on partial orderings as well. I believe the problem is an integer over flow when we subtract key1.hashCode - key2.hashCode. Can you try replacing the line that returns h1 - h2 in keyComparator with returning Integer.compare(h1, h2)? This will properly deal with overflow. 

 Returning h1 - h2 is definitely wrong: for example suppose that h1 = Int.MaxValue and h2 = Int.MinValue, then h1 - h2 = -1. 

 Please add a unit test for this case as well.
