Title

Sending EMPTYBUFFER via NIO-UDP results in spaming the socket

Description
Sending and EMPTYBUFFER on an NIO-UDP socket keeps sending the data because of this:

(netty 4alpha2)
NioDatagramChannel::203
final int writtenBytes = javaChannel().send(nioData, packet.remoteAddress());

The problem is that "writtenBytes" will always be 0, because we wrote zero bytes (on purpose), thus crashing wireshark I had listening on the interface that I was sending the packet out of.

I think the "doWriteMessages" method should also check the size of the ByteBuffer sent to the socket. 
202:: final boolean emptyBuffer = nioData.isEmpty();
207:: if (writtenBytes <= 0 && !emptyBuffer) {
...
}

Thoughts?

To work around this, I sent a single byte instead of EMPTYBUFFER.
