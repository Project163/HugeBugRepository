Title

Debug MailPanel cannot be extend in other mail api library

Description
[Image: screen shot 2014-03-25 at 2 21 19 am]

here's my scenario

I am creating a SendGrid api wrapper. I extend the BaseMessage and BaseMailer to my sendgrid extensions. everything works fine except the MailPanel. Sendgrid doesn't fully use SwiftMailer. it can send email using an SendGrid API only which I don't have a method called `getSwiftMessage()` I think it should be rename to `getMessage()` and subclass will override the it. 

and it throwing me error 

Unknown method: bryglen\sendgrid\Message::getSwiftMessage()

adding `getSwiftMessage()` in SendGrid is not good. so I think the method must be renamed
Discussion
- i dont think we should change anything here. Current mail panel designed to use yii2 official mail extension and it is not supposed to be for everything.
There was a disscusion also that in such issues you can create your own panels if needed.
- why would you need to create own panel? here I want to subclass BaseMessage and BaseMailer, so it means everytime there is Mailer Api Library such as SendGrid I need to create another panel called SendGridPanel? I don't think its right. there is an interface called `MessageInterface` I don't see an issue why it would be a roadblock and the possible solution is to rename `getSwiftMessage()` to `getMessage()` so subclass can override it to whatever mail library they use.

- As far as I understand: array is used to compose a grid, which allows sorting. Single string representation will not suffice. But this can be used as an alternative in case message is not from Swift.

for error message


for success message
