### Steps to reproduce using `nvim -u NORC`

```vim
nvim -u NORC --cmd "lua vim.schedule(function() vim.cmd('vsplit | q') end)" +q
nvim -u NORC --cmd "lua vim.schedule(function() vim.cmd('vsplit | q') end) vim.cmd('q')" also works
```

### Actual behaviour
Neovim coredumps somewhere in libuv.
### Expected behaviour
Neovim quits normally.

There isn't usually a reason to be calling `:q` right after startup but in my case I'm using the `vsplit | q` to force certain plugins to load early and I'm using `+q` to benchmark my config startup with hyperfine. (As an aside, is there a way to quit w/o finishing scheduled commands first? I don't care too much about how long the commands take, but I am interested in the time it takes to schedule them)
