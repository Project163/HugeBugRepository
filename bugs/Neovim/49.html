Essentially: we trust terminfo, and xterm-256color on macOS is outdated. You can fix the issue by updating your terminfo.

@DarkDefender at `:help nvim-features-changed` I see that one of the changes from the TUI refactor was that we don't "fill in" missing terminfo entries from our builtin terminfos. I think we should do that, what do you think?
- @justinmk I didn't remove that (just FYI).

I feel that it would be nice if we didn't have to patch terminfo stuff to work around issues. But as with most things with the TUI, it seems like we could make things work more smoothly if we patched these things. (So it just works™)

However, it would also be nice if OSX updated their terminfo database instead. As it seems like most, if not all, these outdated terminfo problems mainly happens on mac. But that will not happen in a while so...
- ... [Middle Discussions Snipped for Brevity] ...
- The "macOS has a bad terminfo, you should update it" argument seems fair, but if this breaks everyone on macOS who isn't using iTerm, then a guide explaining how to fix this would be helpful. Especially as it's a regression from the previous release. Maybe something for the FAQ?

Copying the `terminfo` from @DarkDefender (in [URL] does fix the problem for me:

```bash
curl -sL -O [URL]
unzip xterm-256color.zip; rm xterm-256color.zip
cp ~/.terminfo/78/xterm-256color ~/.terminfo/78/xterm-256color.bak
mv xterm-256color ~/.terminfo/78/xterm-256color
```

**_EDIT:_** You can also just do `alias nvim="TERM=tmux-256color nvim"`
- @gibfahn This is definitely a  regression, it'll be fixed.
