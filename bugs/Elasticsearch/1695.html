Title

ES 5.0.X synonyms bug with multi-match/cross_fields

Description
**Elasticsearch version**: 5.0.0/5.0.1   
Hi, I updated our ES from 2.4 to 5.0.X, and encountered this synonyms bug.
the solar format like following doesn't work anymore with dis_max/multi-match/cross_fields
              "synonym": {
                    "type": "synonym",
                    "synonyms": [
                        "1st,first",
                        "2nd,second"
                    ]
                },
for more info, "=>" works, but not exactly what we want
              "synonym": {
                    "type": "synonym",
                    "synonyms": [
                        "1st=>first",
                        "2nd=>second"
                    ]
                },

**Steps to reproduce**:
I am able to simplify our case and reproduce with clean ES 5.0.1 (by docker/elasticsearch image)

1) create index and insert 2 sample records
```
curl -XPUT localhost:9200/test -d '
{
    "settings": {
        "analysis": {
            "filter": {
... [Log Snipped] ...
curl -XPUT localhost:9200/test/product/1 -d ' { "name" : "first shoe", "desc": "desc" } '
curl -XPUT localhost:9200/test/product/2 -d ' { "name" : "1st shoes", "desc": "desc"  } '
```

2) search with single term works as expected
```
curl 'localhost:9200/test/_search?q=name:1st'
```

3) multimatch doesn't return result, this is to search '1st' in all fields as cross_fields.
```
curl localhost:9200/test/_search -d '
{ "query" : {
  "bool" : {
    "must" : [
      { "dis_max" : {
... [Log Snipped] ...
} }
'
```

4) if I replace synonym in setting to be "1st=>first", and recreate whole index, then the dis_max/multi_match works.
