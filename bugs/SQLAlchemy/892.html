Title

Accessing an association proxy in an after_flush context duplicates the last linked object

Description
Hello,

When writing some after_flush code we noticed a strange behavior, where the last linked child object is duplicated in the parent object's association proxy. This association proxy is a many to many.

Here's a little script to reproduce

```
python
import sqlalchemy as sa
from sqlalchemy.ext.declarative import declarative_base
from sqlalchemy.ext.associationproxy import association_proxy

... [Log Snipped] ...
session.add(dutch_class)
session.commit()
```

When running this script, the result is 

```
❱ python test.py
[ >]
[1]
[ >,  >,  >]
[1, 2, 2]
```

As you can see, after the first commit, the list only has the teacher for the french class, while after the second commit, the list has one teacher for the french class, and a duplicated teacher for the dutch class (same database id, different internal python id).

Doing a `session.refresh(target)` within the after flush is a current workaround.

Versions this was reproduced on:
- 1.2.0b3
- current master branch ( )

Python version is 3.6.7

To allow Mr. Bayer's fun on Link's awakening, I will investigate further and see if I can propose a fix at a later date ;)
