Title

fix(docs-infra): entry-points are incorrectly labelled as packages

Description
On API docs pages for Angular packages (e.g. [URL] we show all primary and secondary entry-points. Following a link to one of the secondary entry-points (e.g. [URL] navigates the docs page for the secondary entry-point, where it is incorrectly (and misleadingly) labelled as `PACKAGE` and not as an entry-point.

(NOTE: This currently only affects secondary entry-points, because the primary entry-point has the same name as the npm package, so they are on the same API docs page.)

##
We should implement a new `ENTRY-POINT` label and add support for correctly differentiating between entry-points and packages.

To avoid regressions, we should also check against invalid package names, like `@angular/common/http`.

## New docType
One is to create a new docType say, `secondary-entry-point` and then change all the `package` docs that are actually secondary entry-points to have this. Then we would need to check through the dgeni config for places where `packages` are mentioned and then accommodate this new type. A quick search of the code base brings back this list of places to consider:

```
aio/tools/transforms/angular-api-package/index.js
  52,89:           return EXPORT_DOC_TYPES.concat(['decorator', 'directive', 'ngmodule', 'pipe', 'package']);
  197,24:             docTypes: ['package'],

aio/tools/transforms/angular-api-package/processors/computeApiBreadCrumbs.js
... [Log Snipped] ...
aio/tools/transforms/angular.io-package/processors/createOverviewDump.js
  17,29:         if (doc.docType === 'package') {
```

Plus a new template would be needed for this new docType that will display the entry-point correctly.

## Discriminate within the package docType

The package/entry-point docs have a property: `doc.isPrimaryPackage`, which could be used to discriminate between packages and secondary entry-points.

The fix would involve changing this line: [URL]

to something like

```
  {% if doc.isPrimaryPackage %} package {% else %} {$ entry-point $} {% endif %}
```

And then tweaking the AIO styles to display the label correctly.
