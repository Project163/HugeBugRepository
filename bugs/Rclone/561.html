Discussion
- This is rclone trying to create the bucket if it doesn't exist. 

This is quite a similar problem to #4297 which was fixed by  

This fix would work here too, but because you've used `--no-traverse` and `--no-check-existing` by the time rclone comes to do the upload it doesn't know if the bucket exists or not because it hasn't listed it or anything within it.

So I guess options are

- ignore the 403 forbidden message when we come to create the bucket. The could potentially mask other errors though
- don't try to create the bucket - maybe make a `--s3-assume-bucket-exists` flag or something like that

Thoughts?

Any other idea?
- Thanks @ncw for the answer.


I have tried with and without the `--no-traverse` and `--no-check-existing` options, but it would not work either (due to the very restrictive bucket policy).

The `--s3-assume-bucket-exists` would be the best option, according to me.


Maybe a more global switch like `--bare-requests` would also be appropriate (only for `copy`) ? 

This would just send the PUT requests (which is what `aws s3api cp` does). I think it would be more convenient than having to set `--no-traverse`, `--no-check-existing` and `--s3-assume-bucket-exists`.
