Title

.pipe operators on EventEmitter leaks subscriptions

Description
## I'm submitting a...
  [X] Bug report  

## Current behavior
`EventEmitter` overrides `Subject.subscribe` to add `isAsync` support but doesn't take all `Subject.subscribe` param types into account. In this case `FilterSubscriber` (and probably other `Subscriber` types) filters correctly but does not cleanup on unsubscribe.

## Expected behavior
Methods available on `EventEmitter` should function and not leak.

## Minimal reproduction of the problem with instructions
```
it('should have no observers after .pipe(op).subscribe().unsubscribe()', () => {
  const ee = new EventEmitter();
  ee.pipe(filter(() => true)).subscribe().unsubscribe();
  expect(ee.observers.length).toBe(0);
});
```

## What is the motivation / use case for changing the behavior?
While I don't think this is a standard (or supported?) use case of `EventEmitter`, there are definitely [Link: some use cases] out there. Or people could potentially be listening to outputs within their own components etc. Either way, if the standard `Subject` methods are available they should probably function correctly and not leak.

Changing `EventEmitter` to not extend `Subject` would be another solution which I know has been mentioned before.
