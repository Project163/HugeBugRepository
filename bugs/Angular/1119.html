Title

[i18n] Different ICU and NgPlural behaviour when using sourceLocale

Description
# 🐞 bug report

### Description

I found out that using a custom `sourceLocale` configuration ("es" in my case), the result from this code is unexpected:

```
 
  {{ case }}
  ICU: {case, plural, zero {zero} one {one} other {other}}

  NgPlural:
... [Log Snipped] ...
   
 
```

### Expected:

0 ICU: other NgPlural: other
1 ICU: one NgPlural: one
2 ICU: other NgPlural: other

### Received:

0 ICU: other NgPlural: other
1 ICU: **other** NgPlural: one
2 ICU: other NgPlural: other


## 🔬 Minimal Reproduction

I haven't been able to reproduce it in Stackblitz, it doesn't recognize `sourceLocale` 
 configuration in `angular.json` [URL]

Using CLI:
ng new project
Enable `localize` and set `sourceLocale` to "es" in angular.json
Copy the above code and run the project

Discussion
- Here's the problem:

[Image: Screenshot 2020-05-02 at 21 22 34]

It appears that Ivy passes a string form of the number through to the pluralization function, whereas ngPlural passes through the number form.
- We actually strip out the conversion from string to number in the generated plural CLDR functions: [URL]

This is to keep the size of the locale data files to a minimum, I believe.

So I think the best fix is to ensure that we only pass a number to these generated functions, by fixing it here: [URL]
