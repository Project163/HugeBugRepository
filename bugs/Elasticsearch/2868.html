Title

Indexing a large (>32k) keyword field without indexing and docvalues (_source only) throws mapping error

Description
### Elasticsearch Version

8.6.0

### Installed Plugins

_No response_

### Java Version

_bundled_

### OS Version

Ubuntu 22.04

### Problem Description

Indexing a large (larger than the Lucene 32k field limit) keyword field with `index: false` and `doc_values: false` produces HTTP 400 error during bulk operation, but I assume this is the case when indexing a single document.

We know this field can get big, really big and we would like to store it only, no indexing, aggregation, nothing, just store them in the `_source`. 
Last year we migrated our app to v8.1.x, worked without issues, but now going up to a more recent version breaks one of our integration tests. It also works with earlier Elasticsearch 7 versions.

It seems that there is an ordering issue in this method:
[URL]

The check for large field value happens before checking whether we need to index it to Lucene or not.

Related issue and PR:
[URL]
[URL]

### Steps to Reproduce

* Create an index with the following mapping:

```
{
  "document" : {
    "mappings" : {
      "properties" : {
        "result" : {
... [Log Snipped] ...
  }
}
```


* Index the following document:

```
{
  "result": "really_long_field_value" // really long larger than Lucene 32k limit
}
```
