Title

RESTEasy Reactive fails to handle collections of parameterized types as parameter

Description
### Describe the bug

We try to switch from RESTEasy Classic to RESTEasy Reactive and checked the differences in the [Link: migration guide].

The problem is now, that (with RESTEasy Reactive) we get an exception during the startup, because we have methods defined, which uses a List/Set of parameterized types, like in the following example:

```
@GET
@Path("/wrapperList")
public String wrapperList(@QueryParam("wrapperList") final List > wrapperList) {
    // ...
}
```

For the `WrapperClass` we defined a `ParameterConverter`, which worked fine with RESTEasy Classic and also when we provide a single parameter to a method (not a collection) in RESTEasy Reactive.

Example (dummy implementation):

```
public class WrapperClassParamConverter implements ParamConverter > {

    private final Class  rawType;
    private final Type genericType;

... [Log Snipped] ...

}
```


The exception (complete stacktrace can be found in "Actual behavior"):

```
Caused by: java.lang.IllegalArgumentException: Unable to support parameter converter with type: 'org.acme.WrapperClass '
        at org.jboss.resteasy.reactive.server.core.startup.RuntimeResourceDeployment.smartInitParameterConverter(RuntimeResourceDeployment.java:544)
        at org.jboss.resteasy.reactive.server.core.startup.RuntimeResourceDeployment.buildResourceMethod(RuntimeResourceDeployment.java:366)
        at org.jboss.resteasy.reactive.server.core.startup.RuntimeDeploymentManager.deploy(RuntimeDeploymentManager.java:136)
        at io.quarkus.resteasy.reactive.server.runtime.ResteasyReactiveRecorder.createDeployment(ResteasyReactiveRecorder.java:135)
... [Log Snipped] ...
        at io.quarkus.runner.ApplicationImpl. (Unknown Source)
...
```


The code worked fine with RESTEasy Classic, but fails with RESTEasy Reactive. Because of this and as there is no hint in the migration guide, I declare it as a bug.
