- Came across a reference to this while scanning for getFileBlockLocations() use. 

 HDFS shouldn't be throwing this.  getFileBlockLocations(Path, offset, len)  is nominally the same as  getFileBlockLocations(getFileStatus(Path), offset, len) ; the latter will return an empty array on a directory. Looks like the HDFS behaviour has been there for years, and people can argue that it's the correct behaviour: but its the only subclass of the base FileSystem implementation, and it doesn't fail on a directory. Maybe it can be fixed, at the very least the behaviour needs to be specified explicitly.
