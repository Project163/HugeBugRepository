Title

[Freetype] Removal of Harfbuzz causes Ubuntu build failure on linking of project using Freetype.

Description
**Describe the bug**
While Freetype itself builds fine, linkage into an actual project causes a build failure. Specifically, it is looking for harfbuzz-related objects, which naturally cannot be found as of #9888 .

**Environment**
- OS: Linux (Ubuntu 18.04)
- Compiler: vcpkg dependencies - g++8, linking project - Clang 8.0.1

**To Reproduce**
Steps to reproduce the behavior:
1. Set up a Ubuntu instance that does not have, or depend on, Harfbuzz as a core OS library (so no GNOME, for example).
1. Install Freetype (./vcpkg install freetype).
2. Link to Freetype in an application.
3. Observe the issue when performing a build of said application.

**Expected behavior**
The build should be succeeding without Harfbuzz, assumedly, based on the aforementioned PR.

**Failure logs** 
Relevant AzDO logs: [URL]

**Additional context**
Please note that Windows is completely unaffected.

Since this happened on an AzDO machine and based on further testing, it came to light that installing freetype via vcpkg like this may cause it to rely on the local copy of harfbuzz that comes with Ubuntu as of 16.04 LTS, which is probably not the intended behaviour. This also suggests that Freetype still has a dependency on harfbuzz somewhere.

Please also note that I am certain it is the Harfbuzz changes due to the fact NovelRT is built daily on the master branch, and the last succeeding build for it was before #9888 was merged. It was fine before this.
