Title

v3.0.1 - Cache Fallback Broken

Description
In [Link: this commit] the code that was used to setup the connection to the cache server (Redis and Memcache[d]) was moved from a sub-method of the `is_supported` method to the construct method. This is causing issues when the primary cache adapter is not supported.

So let's run through the problem from the start. Let's assume the PHP memcache(d) modules are disabled and this is the CI cache driver setup:

```
$this->load->driver('cache', ['adapter' => 'memcached', 'backup' => 'file']);
```

If memcache(d) is not available, we'll get a debug message telling us so, and the system will fallback to the backup file-based adapter. [Link: The logic for this can be found here.]

However, when the primary adapter class, memcached, is loaded the construct method is run and because of [Link: these conditions] we end up with the RuntimeException thrown, which halts the script and kills the site.

I only use the memcached and file adapters, but I assume this is happening in any cache adapter that throws an exception in the construct. We can't throw exceptions in the adapter construct methods if we need them to fail gracefully (so the back-up adapter can be used).
