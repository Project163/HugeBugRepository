Discussion
- It seems you've specified `[['aa']]` as your dependencies instead of `['aa']`. So Angular look for a provider registered with the token `['aa']` instead of `'aa'`.

See [URL]
- @wszgrcy thanks for the report!

The problem here is that the Angular compiler (which compiles `@Injectable`) and the runtime injector (which handles `{provide: X, useFactory: factoryFn, deps: [...]}` don't use the same structure for `deps`.

The runtime injector will accept `deps: [new Optional(), 'aa']` - anything in this array that isn't an injection flag like `Optional` is considered to be the token to inject.

The compiler, on the other hand, expects all elements to be injection flags, so in your example this would need to be specified as `[new Optional(), new Inject('aa')]`.

I think the compiler is clearly in the wrong here - `[new Optional(), 'aa']` should be legal. We should follow the same logic as the runtime.

If you're interested in taking on this bug yourself, the logic in question is here: [URL] It should be relatively readable, but let me know if you have any questions and I'd be happy to explain anything confusing there.
