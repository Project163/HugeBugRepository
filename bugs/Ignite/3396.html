Discussion
- Main reason of this behavior: transaction hangs when some error occurs during processing of  GridNearLockRequest . In  testPessimisticTxPutAllMultinode  after rebalancing minor topology version changed, partition for primary key changes state to  RENTING . When we try to update data in this partition exception is thrown, but response with error is not sending to transaction initiating node. 

 Another simple reproducer for this case:

            .setCacheConfiguration(

                    .setCacheMode(CacheMode.PARTITIONED)

            .setEventStorageSpi(

                         if  (evt.type() == EVT_CACHE_ENTRY_CREATED && getTestIgniteInstanceIndex(igniteInstanceName) == 1)
