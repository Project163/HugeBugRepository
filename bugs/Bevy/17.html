Title

Shared query iteration progress between stages?

Description
## Bevy version

  (latest main right now)

## Operating system & version

Arch Linux, Kernel 5.11.2-zen1-1-zen

## What you did

```
rust
use bevy::prelude::*;

struct Component;

... [Log Snipped] ...
    println!("entities: {}", query.iter().len());
}
```

## What you expected to happen

Even after pressing the return key, it should print out "entities: 3".

## What actually happened

After each press of the return key, the number decreased by one (eg. "entities: 2", ...)

## Additional information

Moving the counting system into the same stage as the modifying system seems to resolve the issue.

Since we're not iterating through all entities, could a possible cause be that the query iteration progress is shared between queries of different stages?

This is the minimal reproducing code I could construct. The original code worked fine on 0.4, but while trying to upgrade to `main` this came up.

An alternative repro is the following, without the `break`:
```
rust
use bevy::prelude::*;

struct ComponentA;
struct ComponentB;
... [Log Snipped] ...
    println!("entities: {}", query.iter().len());
}
```
Discussion
- it seems it only fails in a `SystemStage::single`
if instead of 
```rust
        .add_stage_after(CoreStage::Update, "CustomStage", SystemStage::single(count_entities.system()))
```
the stage is added as a `SystemStage::parallel()` with a single system, it works
```rust
        .add_stage_after(CoreStage::Update, "CustomStage", SystemStage::parallel())
        .add_system_to_stage("CustomStage", count_entities.system())
```
