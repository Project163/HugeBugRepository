### Summary

When using `st.session_state` to pre-set the value of a widget, the widget will sometimes appear to have a blank/0 value that does not match the value returned by the DeltaGenerator function call, and this behavior depends on the user switching from a different Streamlit "page" which did or did not finish running to completion.

```
Python

```

did some testing/logging of this too, I believe the behavior you describe is correct. 
When the user clicks on a page-change link, the frontend sends the re-run request to the backend and immediately clears its WidgetStateManager of inactive widgets (e.g. all of them, because the page is changing). However, the backend does not clear out old widget states until the active script_runner hits a "script finished" point. When this doesn't happen (because the user changed pages mid-run and fast-reruns are enabled), the old widget states are not removed.

There are two "root" issues going on:

### Issue 1: value-retention for widgets with user keys depends on previous script-runner finishing while active. 
This one is pretty easy to fix; but requires a choice.



### Issue 2: The desynchronization of WidgetStateManager (frontend) and SessionState (backend) when a page change occurs.
This is easy if you go with option B and commit to clearing ALL backend widget state every time a page changes. Nothing needs to get changed on the frontend because it's _already_ clearing it's widget state as soon as the page changes.

If you go with option A, then this is a lot tricker. Either, as you said above, the backend needs to send all the widget states it knows about to the front-end at the start of a re-run, OR the frontend WidgetStateManager needs to keep track of which widgets have a user_key, and purposefully avoid clearing those widgets' state when a page change is requested.
