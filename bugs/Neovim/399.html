Title

Regression: `:lua vim.api.nvim_set_keymap('', '', '', '')` crashes with `LuaJIT ASSERT lj_api.c:921: lua_next: stack slot -2 is not a table`

Description
### Neovim version (nvim -v)

NVIM v0.6.0-dev+424-gc61a3865e. Note that this doesn't happen on stable.

### Vim (not Nvim) behaves the same?

N/A, this is a Lua-specific issue

### Operating system/version

Tested on newly-initialized Ubuntu 20.04 (from Docker), MacOS using home-manager on the unstable channel, and NixOS unstable.

### Terminal name/version

Kitty 0.23.1

### $TERM environment variable

xterm-kitty (but also occurs on xterm-256color)

### Installation

This happens both from nightly (nixpkgs) and when built from repo in a blank environment.

### How to reproduce the issue

Run `nvim`, then type `:lua vim.api.nvim_set_keymap('', '', '', '')`.

### Expected behavior

Not to crash.

### Actual behavior

On a release build, this segfaults; on a debug build, it fails with a LuaJIT error: 
```
LuaJIT ASSERT lj_api.c:921: lua_next: stack slot -2 is not a table
Aborted (core dumped)
```
Discussion
- Seems to also happen to some other api functions called with invalid arguments. For example, `nvim_open_win('', '', '')` also crashes.
- Bisected to [URL]
- I think I know the cause of the error - in the old working code, the code called `nlua_pop_Dictionary`, which checked the type of the current stack top using `nlua_check_type`. However, in the new code, `nlua_pop_keydict` does not validate the type of the top of the stack before trying to pop it, causing errors. I will most likely PR soon.
