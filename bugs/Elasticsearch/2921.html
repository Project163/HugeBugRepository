It's important that the parent of the geopoint field is also an array. Note e.g. that this works as expected (tested on 7.17):

```
PUT test/_doc/1
{
  "results": {
      "value": [

                }
```

Also, other field types (e.g. numeric types) work nested in an outer array as in:
```
PUT test/_doc/1
{
  "results": [{
       "foo" : [1,2]
    } ]
}
```

I am confused by the last part of your comment, "Note e.g. that this works as expected (tested on 7.17)". Can you add some clarification. Does this mean that the observed behavior of fields not returning geopoint values is expected and will not be fixed? - No, your reproduction has an array of objects under the root "results" field, while in the example I posted (that works as expected) the root "results" field is a plain single-valued object. We already have a test case for that, so I was surprised that you ran into a problem.
Your repro also doesn't work on 7.17, so its a bug we already had there, not a regression.
