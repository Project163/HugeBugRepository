Title

New consumer topic metadata events should set requireMetadata flag

Description
In the new asyn consumer, application events that require topic metadata should overwrite the requireSubscriptionMetadata func defined in the CompletableApplicationEvent class (returning false by default). This ensures that api calls that trigger those events receive metadata errors that may be discovered in the network layer. 

 We should ensure that AbstractTopicMetadataEvent sets this to true, so that topic metadata calls like partitionsFor are aware of metadata errors. 

   

 This should allow to enable the SaslClientsWithInvalidCredentialsTest that are not currently running for the new consumer (and fail with attempting to enable them)
