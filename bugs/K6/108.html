Title

Iterations count in InfluxDB is lower than what k6 reports

Description
When using k6 with InfluxDB output, we noticed the iterations count in InfluxDB is ~1% lower than the iterations count in the k6 console output.  I'm trying to understand whether this is a bug in k6's InfluxDB reporting or if I'm misunderstanding how to read the metrics in InfluxDB.

While our real test saw a ~1% discrepancy, we were able to reproduce a much larger discrepancy with a script that ran very fast:
```javascript
export let options = {
    iterations: 10424
};

export default function() {}
```

We tested it this way, using a new database name (k67 in this case) each time:
```sh
k6 run noop.js --out influxdb=[URL]
```

As expected, the k6 output showed 10424 iterations and no errors:
```
noformat
          /\      |‾‾|  /‾‾/  /‾/
     /\  /  \     |  |_/  /  / /
    /  \/    \    |      |  /  ‾‾\
   /          \   |  |‾\  \ | (_) |
... [Log Snipped] ...
    vus..................: 1     min=1 max=1
    vus_max..............: 1     min=1 max=1
```

However InfluxDB unexpectedly reported a much lower iteration count:
```
noformat
Using database k67
name: iterations
... [Log Snipped] ...
---- ---------
0    494
```

I tried adding a short sleep to the script (`sleep(.001);`), and the problem went away.

Are the iterations in InfluxDB intended to match the number of iterations that actually ran?  I am curious if two iterations start at the same time, if k6 reports them to InfluxDB with the same timestamp, which means InfluxDB collapses them into a single data point:
[URL]

Should k6 track when multiple iterations have the same timestamp, and in that case report a `value` higher than 1 to InfluxDB?
