Title

Using a scoped package name break UMD module generation

Description
I want to generate a UMD module where the name is a scoped package, e.g. `@something/modulename`. Doing so triggers an error a build time because the generated code is invalid:

```
factory((global.@something/modulename = {}) ... etc.
```

Would it be possible to detect this kind of situation an instead generate something like:

```
factory((global['@something/modulename'] = {}) ... etc.
```

This is a killer for me because we scope all of our internal modules.
Discussion
- Huh, I just replied to [URL] suggesting that using an invalid identifier as a `moduleName` should cause an error to be thrown instead of generating bad code. But you're saying you actually want to create a property of `window` called `@something/modulename` rather than e.g. `window.something.modulename`?
- i believe babel umd-plugin strips the `@` and `/` characters so we have something like `@most/create` which becomes `global.mostCreate`
- I created a PR #1144 which allows arbitrary `moduleName` including `module-with-dashes`, yet still processes dot-notation `foo.bar.baz`.
