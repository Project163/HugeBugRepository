Title

MS SQL restart not recognized

Description
**Describe the bug**
The mssql-pyodbc dialect fails to recognize a restart of the MS SQL server. (It doesn't expect the current (?) error-code `"01000"`.)

**Expected behavior**
The result of a restart should be understood as an `is_disconnect`-error, e.g. to trigger a reconnect.

**To Reproduce**
I can reproduce the problem with a local MS SQL Express installation, but what got me searching was a remote MS SQL server.

The example below stops after a successful query to await an input from the user after the DB-restart. After that the next query fails.

```
py
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker

MY_DATABASE_NAME = 'your_db_name'
... [Log Snipped] ...
input('restart done?')
session.execute('SELECT 1')  # this triggers an exception if the DB was restarted
```

Discussion
- hey there -

there are two issues here.    one is that we aren't catching 01000, will add that right now but unfortunately no release is planned for a few weeks, so instead of using a patch you can use the [Link: documented event hook]:

```
@event.listens_for(Engine, "handle_error")
def handle_exception(context):
    if isinstance(context.original_exception, pyodbc.Error):
        for code in (
            '01000', ):

            if code in str(context.original_exception):
                context.is_disconnect = True


```

second issue, your test is expecting pool_pre_ping to resume a transaction that was in progress when the database was stopped.  this behavior is not possible as documented at [URL] so your test would need to be connecting on a new transaction in order for pre-ping to take effect.  existing transactions will definitely raise an error when the DB is stopped and additional SQL is emitted on those transactions.
- 01000 seems to be an error-on-connect, not during a connection, that would seem to conflict with the apparent raise during pyodbc cursor.execute() .
