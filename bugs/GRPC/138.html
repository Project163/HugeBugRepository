Title

Python multiprocessing example doesn't achieve true parallelism

Description
### What version of gRPC and what language are you using?

gRPC version: 1.74.0
Language: Python

### What operating system (Linux, Windows,...) and version?

macOS Darwin 24.6.0 (Darwin Kernel Version 24.6.0, ARM64)

### What runtime / compiler are you using (e.g. python version or version of gcc)

Python 3.13.5

###  What did you do?

1. Ran the official gRPC Python multiprocessing example from
examples/python/multiprocessing/
2. Modified the server.py to log PIDs when processes start and when handling requests
3. Created a test that tracks which processes actually handle requests

Here's the test that demonstrates the issue followed by the modified `server.py` file with additional logging:
```
py

Test for multiprocessing example. Save under
grpc/examples/python/multiprocessing/test/test_multiprocessing_so_reuseport.py
"""

The test can be executed from the `grpc` repo top-level directory by running
```
python3 examples/python/multiprocessing/test/test_multiprocessing_so_reuseport.py
```

The test shows that despite spawning multiple processes (8 on an 8-core machine),
only one process handles all ~10,000 requests.

### What did you expect to see?

Based on the `README.md` statement:
I expected:

1. The load to be balanced across all spawned processes
2. Each process to handle a roughly equal share of requests
3. True parallel processing utilizing multiple CPU cores

### What did you see instead?

- 8 server processes are spawned (on an 8-core system)
- Only 1 process handles ALL ~10,000 requests
- The other 7 processes sit idle
- No load balancing occurs despite using SO_REUSEPORT
