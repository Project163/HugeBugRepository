Title

FilesystemIterator current return value is incorrect in CallMap

Description
### FilesystemIterator current reflection is incorrect

The mapping for FilesystemIterator is incorrect
the return value for the current function is mixed, NOT string
what this returns is controlled by the second parameter to the constructor, and the DEFAULT is an SplFileInfo instance

(default flags are FilesystemIterator::KEY_AS_PATHNAME | FilesystemIterator::CURRENT_AS_FILEINFO | FilesystemIterator::SKIP_DOTS)

Changing

[URL]

'FilesystemIterator::current' => ['string'],

to 

'FilesystemIterator::current' => ['mixed'],

would be enough - although really

'FilesystemIterator::current' => ['string|SplFileInfo'],

if that syntax works - would be the most accurate
Discussion
- I've made it `mixed` for now - making it `string|SplFileInfo` (which is valid syntax) would penalise code that rightly assumed the output could only be one of `string` or `SplFileInfo`. But I'll also think of a better workaround for this.
