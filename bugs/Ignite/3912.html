Title

Primary response error info can be lost due to unwrapping a key

Description
It can happen when we use SQL DDL to create a table or some dummy values for QueryEntity.keyType. Without using Cache API (only SQL), key and value should not be deserialized/unwrapped. 

 If primary update error happens onPrimaryError call may try to unwrap keys, get ClassNotFoundException and hide the original error.
