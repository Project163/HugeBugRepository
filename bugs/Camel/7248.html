Title

OpenTelemetry: Unclosed Span Scope with Parallel Multicast

Description
I'm encountering a tracing issue with the  camel-opentelemetry2  component, specifically when using a  multicast  EIP with  parallelProcessing . 
 Problem:  The root  Span  for my SQS-triggered route is failing to close. I believe this is because the  Scope  associated with this span is not being properly closed and detached from the thread after the  multicast  with  parallelProcessing  completes. 
 Observed Behavior:  
 
	  Leaked Trace Context:  Due to the unclosed scope, subsequent, unrelated spans (in this case SQS reads ) are incorrectly attached to the trace of the completed route. 
	  Cycle Repetition:  This behavior persists until a new message is consumed from the SQS queue, which starts a new trace. However, this new trace then suffers from the same issue. 
 

  Key Finding:  The tracing behaves as expected (the root span's scope is closed correctly) if  parallelProcessing  is removed from the  multicast . 

 This suggests an issue with how the OpenTelemetry tracer handles the thread context lifecycle during asynchronous, parallel processing. I've attached screenshots illustrating the difference.
