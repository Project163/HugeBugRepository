Title

Continuous Testing not using updated log level

Description
## Describe the bug
Quarkus 2.0.0.Final Continous Testing not applying an updated log level changed in application.properties

### Expected behavior
Log level does not change. When app started with default (INFO), and then quarkus.log.level is updated to a higher log level (like TRACE or DEBUG), the logs should include the appropriate logging statements.

### Actual behavior
Logging continues to log at INFO log level.


## To Reproduce

1. Clone the [Link: reproducer git repo].
2. `mvn quarkus:dev`
3. Press 'r' to run tests
4. Press 'o' to enable output
5. Press 'r' to run tests again. Should see:
```
FATAL [org.acm.LoggingResource] ***** JBossLogManagerLogger: FATAL *****
ERROR [org.acm.LoggingResource] ***** JBossLogManagerLogger: ERROR *****
WARN  [org.acm.LoggingResource] ***** JBossLogManagerLogger: WARN *****
INFO  [org.acm.LoggingResource] ***** JBossLogManagerLogger: INFO *****
INFO  [io.quarkus] greeting stopped in 0.009s
```
6. In application.properties, update quarkus.log.level to TRACE.
7. Test will automatically run, and display above text reflecting the log level is still INFO.
Discussion
- This is kind of by design, you have two applications present (the dev mode one and the test one) and only one can configure logging. Any %test logging config is ignored, and dev mode logging settings are used instead. 

In Quarkus upstream pressing 's' would restart the app and apply the logging changes. But I can't really see a good solution for this.
