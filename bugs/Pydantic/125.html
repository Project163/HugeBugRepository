# Bug

Output of `python -c "import pydantic.utils; print(pydantic.utils.version_info())"`:
```
             pydantic version: 1.9.0a2
            pydantic compiled: True
                 install path: /Users/paul/.cache/pre-commit/repo8u79aah5/py_env-python3.9/lib/python3.9/site-packages/pydantic

                     platform: macOS-10.16-x86_64-i386-64bit
     optional deps. installed: ['typing-extensions']
```
 

 

 

I'm testing out the new `pyproject.toml` config support in alpha. I tried to set the config in my `pyproject.toml` exactly like in the docs: [URL] . However, this doesn't seem to work with `mypy` `0.930`, when I run it I get the folllowing traceback:
```
Error constructing plugin instance of PydanticPlugin

Traceback (most recent call last):
  File "/Users/paul/.cache/pre-commit/repo8u79aah5/py_env-python3.9/bin/mypy", line 8, in  
    sys.exit(console_entry())
... [Log Snipped] ...
    s = __fp.read().decode()
AttributeError: 'str' object has no attribute 'decode'
```

The issue is here: [URL]

Newer `mypy` versions (`>=0.920`) use `tomli` for parsing, and `tomli`'s version of `load` expects the file handle in binary mode explaining the error.
