Title

Apache-cxf wsdlvalidator returns error in mime:part

Description
Apache-cxf wsdlvalidator returns 

 "WSDLValidator Error: cvc-complex-type.2.4.a: Invalid content was found starting with element 'mime:part'. One of ' 
{part}
 ' is expected." , 

 if I try to validate wsdl document with such structure: 

 <mime:multipartRelated> 
   <mime:part> 
       <soap:body parts="header parameters" use="literal"/> 
   </mime:part> 
   <mime:part> 
       <mime:content part="attachment" type="application/octetstream"/> 
   </mime:part> 
</mime:multipartRelated> 

 wsdl document example from:  [URL] (I also tried other examples) 

 If I change "mime:part" to "part", validator returns error: 

 WSDLValidator Error : javax.wsdl.WSDLException: WSDLException (at /wsdl:definitions/wsdl:binding/wsdl:operation [1] /wsdl:input/mime:multipartRelated/part): faultCode=INVALID_WSDL: Encountered unexpected element ' 
{[URL]
 part'.
Discussion
- I think this is a result of validating a mime-binding wsdl using the incorrect mime binding xsd schema at  [URL]

 This official mime-binding xsd at is broken and contradicts what is described in the wsdl 1.1 note and also differs from the xsd fragment included in that note, which was correctly defined. 

 This problem is mentioned in the following Attachment Profile Version 1.0 
 [URL]

 I'm not sure if there is a simple workaround out of the box and if not, what would be the simplest workaround (maybe using a catalog to fetch the corrected xsd schema?).
- Some trivial solution: Old schema file  \apache-cxf-3.0.1-src\core\src\main\resources\schemas\wsdl\mime-binding.xsd must be replaced  by new correct schema, which is located on  [URL]
- sorry for the delay in replying. 
i though this auto redirection using xml-catalog should usually take place so that the 0824 schema is used, I have to look at an example to see what is happening.
- You are right. 
we should just replace the invalid mime-binding schema with the correct 2004-08-24 one. 
I noticed that wsdl.xsd in core is also from 2004-08-24.xsd. 
regards, aki
