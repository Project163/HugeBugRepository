Title

Website URL 404 bug

Description
☑️Still present after disabling extensions.

**Describe the bug**

When following the link to my personal site in my Dev portfolio 'www.fayesipiano.co.uk', user is redirected to '[URL] which displays a 404

**To Reproduce**

Chrome browser, www.fayesipiano.co.uk in the website URL section of the header. Hit save, click on the link in the dashboard. Unexpected redirect to 404 occurs.

My portfolio opens in a new page

- Thanks for this bug report! At a glance, I think the issue is because we're rendering the link as a relative link.

As you mentioned feel free to update it to the full URL for now on your profile since that is currently working.
- @Zhao-Andy I think the issue is we're not validating (in the [URL] page) the website url is a url (we accept any string and render links that were paths without a scheme/host as local links). 

The suggested text is "[URL] but nothing prevents users from accidentally adding any string there (and this is automatically used to create a link, with no "fixup" to make it an external url). We can probably catch this by validating the url provided is a url and not just a string.

Just to rephrase my proposal "when a user enters a non-url string in their profile, reject input and require that it be a valid url" (this will prevent the local links based off of dev.to when we build the links).
- Hi Faye,

I pushed out a change today that did two things:

- users are required to give a full url (including http:// or [URL] when adding a website url to their profile, this prevents future confusion. The input field has hinting for this (prior to submitting the profile update) and the backend does additional checks, both will give a response indicating the url is not well formed.

- existing website urls that were relative (like yours) have been moved to include an https:// prefix (fixing the links for existing users). Website urls that were not fixable by just adding a prefix (for example if someone had added an email address in the url field) were cleared.

I confirmed your profile in dev links back to your site (and your site links to your dev.to profile). I had added an invalid website url to my own profile as well and verified that updated to be valid. 

One cosmetic change (which seems like it would be a separate issue) is that the full url is both present in the link target and the link text shown on the user profile page, I could see an argument that you only want to show "www.fayesipiano.co.uk" while still linking to [URL] - right now the link looks different than it did (but works correctly, this is in line with your work-around in the comment).

[Image: updated-link]

I'm marking this issue resolved for now - but if the link presentation excluding the https part were something  you felt strongly about, feel free to open a second issue or reopen this one.
