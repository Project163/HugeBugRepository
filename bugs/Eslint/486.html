Title

`no-throw-literal` does not catch concatenated exception messages

Description
Using eslint `master`, and the following code:

```
throw 'a' + 'b'
```

and the following rule:

```
"no-throw-literal": 2
```

I expect an error, but get none.
Discussion
- This is reproducible in online demo.
- [Link: This commit] appears to be what precipitated this issue report.

The problem with trying to catch something like this would be testing for the following:

``` js
var err = new Error("error");
throw 'Now I am throwing an ' + err;
```

The above throws an actual Error, and should be considered valid.  Whereas:

``` js
var err = 'literal';
throw 'Now I am throwing an ' + err;
```

ends up throwing a literal and ideally would be flagged.  However, I don't see a good way to handle this via static analysis.  Anyone else is welcome to try, but I have to back out I'm afraid.
- ... [Middle Discussions Snipped for Brevity] ...
- Hm, looks like you're right.  I get:

``` js
throw 'Now I am throwing an ' + err;
                              ^
Now I am throwing an Error: error
```

Which at first glance looked like an error but isn't, the error was recast to a string.

So, maybe one solution would be to catch any `throw` with a `BinaryExpression` argument, since it will not result in a real error?
- Yes, I guess this rule should catch below:
- `ArrayExpression` (an array)
- `FunctionExpression` (a function)
- `ArrowFunctionExpression` (a function)
- `ClassExpression` (a function)
- `TemplateElement` (a string)
- `UnaryExpression` (converted implicitly to boolean, number, string, or undefined)
- `BinaryExpression` (converted implicitly to boolean, number, or string)
- `UpdateExpression` (converted implicitly to number)

And should catch partially below:
- `SequenceExpression` - checks the last element of `expressions` recursively.
- `LogicalExpression` - checks both `left` and `right` recursively.
- `ConditionalExpression` - checks both `alternate` and `consequent` recursively.

However, this probably be the overspec :)
