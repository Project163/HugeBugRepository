Title

TypedDict is recognized only when imported directly

Description
* Are you reporting a bug, or opening a feature request?

This is a bug.

* Please insert below the code you are checking with mypy,
  or a mock-up repro if the source is private. We would appreciate
  if you try to simplify your case to a minimal repro.

The code to reproduce this bug should have one module nested in one or two directories and the main module in the root. Something like this will do:

* `/typed_dict_test.py`
* `/foo`
    * `/foo/__init__.py`
    * `/foo/bar`
        * `/foo/bar/__init__.py`
        * `/foo/bar/kitty.py`

The `kitty.py` module defines a single `TypedDict` object:

```
#!/usr/bin/env python3

from typing_extensions import TypedDict

BadKitty = TypedDict(
... [Log Snipped] ...
    },
)
```

This is used in the `typed_dict_test.py` file in the root:

```
#!/usr/bin/env python3

import foo.bar.kitty
from foo import bar
from foo.bar import kitty
... [Log Snipped] ...
print(kitty.BadKitty(foo="abc", bar="def"))
print(BadKitty(foo="abc", bar="def"))
```

* What is the actual behavior/output?

When this code is executed by Python, it works as expected:

```
C:\test>python typed_dict_test.py
{'foo': 'abc', 'bar': 'def'}
{'foo': 'abc', 'bar': 'def'}
{'foo': 'abc', 'bar': 'def'}
{'foo': 'abc', 'bar': 'def'}
```

However, `mypy` does not like all instances of `BadKitty`, which import this class indirectly. Only the last instance, which is imported as a top-level name, makes `mypy` happy:

```
C:\test>mypy typed_dict_test.py

          ^

... [Log Snipped] ...
typed_dict_test.py:10:7: error: Unexpected keyword argument "bar" for "BadKitty"  [call-arg]
    print(kitty.BadKitty(foo="abc", bar="def"))
```
