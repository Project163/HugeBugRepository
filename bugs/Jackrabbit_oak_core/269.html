Title

Recursive wrapping of ModifiedNodeState

Discussion
- I added an initial workaround in revision 1468828. The root cause of this seems to be the various NodeBuilder.setNode() calls using previously acquired ModifiedNodeState instances. In those cases it might be a good idea to unwrap such an instance instead of using it as-is as the new base state of the affected builder.
- As of revisions 1469250 and 1469264 the MemoryNodeBuilder class now automatically unwraps all ModifiedNodeState instances passed to reset() and setNode() methods. This should prevent such stacked cases from coming up regardless of how the builder is used.
