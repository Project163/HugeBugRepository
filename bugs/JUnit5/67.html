Title

Cannot select default method by fully qualified method name

Description
Given the code:

``` java
interface ATest {
   @Test
    default void testSmthCommon() {}
}

class BTest implements ATest {}
```

I expect that passing `BTest#testSmthCommon` as the _fully qualified method name_ would discover test method in `BTest` class. 

Instead, the JUnit Platform discovers method in the interface and then the `JupiterTestEngine` fails to run it.

I believe the problem is due to the use of `method.getDeclaringClass()` in `DiscoverySelectors#selectJavaMethod(String)`.

This was noticed in the latest `SNAPSHOT` version.

- Tentatively assigned to @bechte in conjunction with his work on #489.
- This issue makes the difference of `JavaMethodSelector` and `JavaMethodSource` very obvious. A selector references to the _Thing Under Test_ (also requiring the explicit `Class` to run the tests with), while the source points to the place _where_ the code is defined. Therefore, for the selector we have to extract the class from the fully qualified name and cannot use the `getDeclaringClass()`. For the source, we really want to use `getDeclaringClass()` for its purpose.

I changed this accordingly in both classes (selector and source), see commit 318f097. This will be merged with #489 as it is part of the overall rework on this topic.
