Title

PlainActionFuture#assertCompleteAllowed false positives on concurrent resolve

Description
### Elasticsearch Version

8.14

### Installed Plugins

_No response_

### Java Version

_bundled_

### OS Version

macos

### Problem Description

PlainActionFuture detects dangerous usage patterns where threads from the same pool are simultaneously resolving and waiting on the future. This is to prevent tests that deadlock and is only switched on when assertions are enabled.

This deadlock detection can falsely fire when threads from the same pool are simultaneously resolving a future.

The sequence of events is as follows:

1. T1 calls `PlainActionFuture.Sync.complete` with a value or exception, it successfully performs `compareAndSet(RUNNING, COMPLETING)` and proceeds to set the value/exception.
2. T2 calls `PlainActionFuture.Sync.complete` with a value or exception, if fails to perform `compareAndSet(RUNNING, COMPLETING)` while state is `COMPLETING`. It calls `awaitShared` to wait for T1 to finish.
3. T3 from the same pool as T2 attempts to complete the future, it throws in `assertCompleteAllowed` because there is a thread from the same pool (T2) waiting on the result.

This is a false-positive because T2 will definitely complete.

Note that T1 can be the same as T3 if completing the future in a loop or the thread gets recycled.
