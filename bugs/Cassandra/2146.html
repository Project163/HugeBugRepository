Title

forceTablePrimaryRange fails with nullpointer exception

Description
Running JMX operation forceTableRepairRange fails with nullpointer exception. 
Three node cluster with one keyspace and one large columnfamily. 

 Works when running nodetool -pr but not over JMX.

Discussion
- UPDATE 
====== 
The jmx operation is successfully invoked on node 1 according to system.log (AntiEntropySession started) but the other two nodes generates nullpointer exception.
- Unclear to me how you can generate a null snapshot message.  Can you test with 1.2 git branch?  May be fixed by   CASSANDRA-5424  . 

 In the meantime you can also pass isSequential=false to avoid creating snapshots.
- forceTablePrimaryRange's second boolean parameter is for sequential repair using snapshot(you can do this with nodetool repair -snapshot too), and when it's on, looks like it fails as described. 

 We somehow omitted registering Snapshot message's serializer in 1.2 branch. Trivial patch attached.
