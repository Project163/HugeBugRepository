Title

Container Port is 0 in Manifests generated by Kubernetes Extension

Description
When generating Kubernetes Manifest with `./mvnw package` the resulting containerPort in the Pod Spec is always 0. As a side effect the Service is generated with port and targetPort set to 0 too.

**Expected behavior**

The Pod containerPort should be the same as `quarkus.http.port`, and consequently port and targetPort in service Spec.

**Actual behavior**

The Pod Template Spec generated is:
```
yaml
      spec:
        containers:
        - env:
          - name: "KUBERNETES_NAMESPACE"
... [Log Snipped] ...
            name: "http"
            protocol: "TCP"
```

And the Service Spec is:

```yaml
  spec:
    ports:
    - name: "http"
      port: 0
      targetPort: 0
```

**To Reproduce**
Steps to reproduce the behavior:
1. Go to [URL]
2. Add Kubernetes Extension
3. Click Generate Application
4. Unzip the Application and go to the code-with-quarkus folder
5. Run `./mvnw package`
6. Open target/kubernetes/kubernetes.yml to see the generated manifests

**Configuration**
```properties
# Configuration file
# key = value
```

- This boils down to the fields of `io.quarkus.vertx.http.runtime.HttpConfiguration` not being populated with the default (or even the changed for that matter) values in `VertxHttpProcessor#kubernetes` during build time.

We can work around this problem easily for this instance for `1.1.1`, but the problem seems general.

@dmlloyd any idea why this is happening? It looks like the runtime config values aren't properly populated when used in build steps. 
Just for testing purposes I changed `HttpConfiguration` locally to be a `BUILD_TIME` config instead of `RUN_TIME` and the values **were** showing up properly in `VertxHttpProcessor#kubernetes`. Switching it back to `RUN_TIME` and the values go away...
- Run time configuration values are not available during build time under any circumstances.


Yep, this doesn't make sense to do.  It's an error.  If we want to derive a build time property, then we should have a separate HTTP port build time property which represents the default port, have the run time HTTP port default to that, and have the kubernetes port also default to that, or something similar.

Build steps can only reference build time values.  Run time code can access build or run time values.  Run time config property default value expressions can reference build time or run time values.
