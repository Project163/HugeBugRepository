Title

"no-undef" rule and "browser" environment acting strange with regard to identifier case

Description
**What version are you using?**

``` bash
$ eslint -v
v1.3.1
```

**What did you do?**

``` bash
$ echo "var Document = {};" | eslint -f json --stdin --no-eslintrc --env "browser" --rule '{"no-undef": 2}'; echo $?
```

**What happened?**

``` json
[{"filePath":" ","messages":[{"ruleId":"no-undef","severity":2,"message":"\"Document\" is read only.","line":1,"column":5,"nodeType":"Identifier","source":"var Document = {};"}],"errorCount":1,"warningCount":0}]
1
```

**What did you expect to happen?**

``` json
[{"filePath":" ","messages":[],"errorCount":0,"warningCount":0}]
0
```
## 

Oddly enough, if one adds the "commonjs" environment to the command invocation, the expected output is shown.  I have no idea why adding the "commonjs" environment makes this go away from the CLI, but my actual use-case is invoking ESLint with an hierarchical inherited `.eslintrc` configuration via webpack, and the file where this issue came up is configured to lint with both the "browser" and the "commonjs" environments, and I still receive the error there.

I think it's safe to ignore this CLI w/o `.eslintrc` vs webpack w/ `.eslintrc` oddity and just fix the case-sensitivity issue with "browser" environment/globals/the no-undef rule.
Discussion
- Okay, I think now I am entirely wrong about this being an issue with `no-undef` and "browser".  I realize now that `Document` is indeed a browser environment "global" that should not be redefined (distinct from `document`/`window.document`).

I think instead, this is an issue with the "commonjs" environment, and perhaps an issue with how environments are configured/applied when using the hierarchical inherited `.eslintrc` configuration.

I think that the expected behavior when adding the "commonjs" environment from the CLI w/o `.eslintrc` is correct, but via webpack w/ `.eslintrc` is not.  Adding a `/* eslint-env commonjs */` to the top of the file with issues makes the webpack case happy.

It's seems simply like the `{"env": {"browser": true, "commonjs": true}}` override for the file isn't picking up the CommonJS environment.
