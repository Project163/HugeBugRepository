Title

Introducer feature keeps sharing encrypted folder with device where it's unencrypted

Description
### What happened?

I have 3 devices: A, B - linux, C - android. All have syncthing v1.30.0.

First there was folder shared from A(send only) to C(receive only), no encryption. Then B appeared, A shared folder with B(receive only encrypted) encrypted. 

A(encrypted) -> B
A(unencrypted) -> C

B and C have A as an introducer with auto-accept.

After that B and C started trying to share folder to each other, but unsuccessfully because B had this folder encrypted, and C plain. Futhermore due to this these devices were going disconnected to each other.
Error message:
“remote expects to exchange plain data, but is configured to be encrypted (0 remain)”
When I tried to unsync this folder between B C on both devices, that was of no use because that "ignore" or manual unsharing didn't help from them trying to sync automatically as if this folder was not ignored.

So the only option I had was to remove introducer and auto-accept on both devices.

First I made a topic on the forum, just for reference: [URL]

I see 2 approaches on my mind to fix this. 
First is just to ignore automatically sharing folders if they are not both in same encryption state. Both unencrypted or both encrypted with same password is good, otherwise don’t share. And probably give a one-time notification if not shared. 
Second is simpler: if folder is shared as encrypted, just don’t count it as eligible to introducing it to others never mind what. Only manually set up sharing.

### Syncthing version

v1.30.0
