Title

Modifying config during first scan corrupts folder state

Description
I have seen this problem several times but have not been able to reproduce until now.

How to reproduce:

1. Add a new folder, preferably with a lot of files (so that it takes some time to scan it).
2. While the folder is being scanned for the first time, modify some of its configuration. I changed `Max Conflicts` from `10` to `0`.
3. The folder state is incorrect.

[Image: image]

Below is the same folder, which was just left to scan, with no config changes in between. The state is correct here.

[Image: image]

Rescanning does nothing. The only way to fix the problem seems to be wiping out the database.
