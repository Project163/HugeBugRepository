Title

`*_path` and `*_url` helpers ignores `only_path` option

Description
## The Problem

In Rails 4.2, the `*_url(...)` and `*_path(...)` helpers ignore the `only_path` option.

~~In Rails 4.2/master, when using a `*_url(...)` helper with the `only_path: true` option in a mailer, it will generate the following error:~~

```
ActionView::Template::Error:
    Missing host to link to! Please provide the :host parameter, set default_url_options[:host], or set :only_path to true
```

~~As you can see, the error message itself suggests that using the `only_path` option would make the error go away. I also confirmed that on Rails 4.1 it does not generate this error when using `only_path: true`.~~
## Fix

(**Updated based on discussions**)
1. `*_url` helpers should continue to support the `only_path: true | false` option without deprecation
2. `*_path` helpers should continue to support the `only_path: true | false` option with a deprecation warning that (`*_path(..., only_path: false)` would not work on Rails 5, use `*_url` instead)
3. `*_url(...., only_path: true)` should not require the `host` option to be set (globally or as an argument)
4. test the above
## Background

As @fxn mentioned in his [Link: comment], sometimes there are legitimate cases that you might _really_ want to generate a path in a mailer.

I'm all :+1: deprecating and eventually removing `*_path` helpers from mailers to protect uses from the 90% cases where they actually want a URL, but we should also have a explicit-but-not-super-difficult way for the cases where you _really_ want to generate a path for whatever reason.

`*_url(..., only_path: true)` seems fine to me for that purpose, if you explicitly say "no, I want a path", we can assume you know what you are doing. (Once we fixed this we can probably mention it in the deprecation warning? Something like "If you really want a path, use ..._url with `only_path: true`")

1. The error should be updated to remove the reference to `only_path`, because that doesn't work anymore.

Likewise, `*_path` with `only_path` should also raise. I _know_ for a fact that these are being used today so having them just suddenly behave differently would break apps out there. In fact, something like this should probably go through a deprecation cycle first? Not knowing about this until your app tries to render an infrequently-visited page and blow up doesn't seem too great... (@tenderlove wdyt?)
3. We are back to square one on the `_path` deprecation...

On the third point, while I agree that "by default we should generate full URLs", and I'd be okay with "making it hard to generate paths so people don't shoot themselves in the foot", we should probably still provide an escape valve for those "I _really_ want a path scenarios". I agree with @fxn that making it impossible to generate a path seems too strong.
