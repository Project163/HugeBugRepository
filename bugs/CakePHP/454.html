Description
Sorry for the long title. I noticed a bug with 3.0.0-dev and it's still in 3.0.0-alpha1. I have an Articles table initialized with the Translate behavior:

```
public function initialize(array $config) {
    $this->addBehavior('Translate', ['fields' => ['body']]);
}
```

I then attempt to add a new article while setting the locale, so that the data sent goes to where it should (my i18n table):

```
$this->Articles->locale('en_us');
$article = $this->Articles->newEntity($this->request->data);
if ($this->request->is('post')) {
    $this->Articles->save($article)
}
```

This yields "SQLSTATE[23000]: Integrity constraint violation: 1052 Column 'id' in where clause is ambiguous".

I think from a logic perspective I'd expect to be able to set the locale there since it's a valid public property of the Table. I tracked it down to the Table::_processSave() line 1122:

```
$primary = $entity->extract((array)($this->primaryKey()));
if ($primary && $entity->isNew() === null) {
    $entity->isNew(!$this->exists($primary));
}
```

That passes a raw primary key sans the table name to $this->exists(), which is where the error is thrown. As a fix I made it 

```
$primary = $entity->extract((array)($this->alias() . '.' . $this->primaryKey()));
if ($primary && $entity->isNew() === null) {
    $entity->isNew(!$this->exists($primary));
}
```

You'd want to check if something exists with `Table`.`id` instead of just `id`. That makes everything work for me. This error might not be specific to the Translate behavior but that's where it showed up for me.
