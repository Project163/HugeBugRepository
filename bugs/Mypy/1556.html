Title

[possibly-undefined] False-positive with nested try block and finally

Description
**Bug Report**
Small false-positive I noticed after #14114.
Seems to be a scoping issue with `finally`.

/CC: @ilinum 

**To Reproduce**

```
python
try:
    try:
        msg = some_func()
    except Exception:
... [Log Snipped] ...
print(msg)  #  

- Mypy version used: `mypy 1.0.0+dev.  (compiled: no)`
- Mypy command-line flags: `--enable-error-code possibly-undefined`
- Python version used: 3.11
Discussion
- If `some_func` raises an exception, the second `print` will never be executed because the exception will be re-raised at the end of the `finally` block. So I think that means no error should be generated for the final line of the code sample.
- Yep, good find! This only occurs with nested statements because we have to do a ~hack~ clever trick with [Link: disable_branch_skip]. 

We can probably do something smarter here and only report errors in `finally` blocks when we're in `disable_branch_skip` mode.

I don't really have time to work on this right now, so happy for someone else to pick it up. Otherwise, I could probably start in February.
