Title

Call synstack() may crash nvim

Description
### Neovim version (nvim -v)

0.7.0

### Vim (not Nvim) behaves the same?

no

### Operating system/version

ArchLinux

### Terminal name/version

Alacritty

### $TERM environment variable

alacritty

### Installation

build from repo

### How to reproduce the issue

1. Install nvim-treesitter under `opt`;
2. Git clone nvim repo and change the current working directory to the root of repo;
3. Run `nvim -u crash.lua +75 src/nvim/edit.c +'norm $'` with below script;
4. Neovim will crash.

`cat crash.lua`
```
lua
local cmd = vim.cmd
local api = vim.api

local scratchBuf = api.nvim_create_buf(true, false)
... [Log Snipped] ...

createAndCloseFloatWinLoop()
```

### Expected behavior

Neovim doesn't crash.

### Actual behavior

Crash.
Discussion
- ASAN log:
```
=================================================================
==1423527==ERROR: AddressSanitizer: heap-use-after-free on address   at pc   bp   sp  
READ of size 8 at   thread T0
    #0   in restore_chartab **/src/nvim/syntax.c:811:16
    #1   in syn_current_attr **/src/nvim/syntax.c:2025:3
... [Log Snipped] ...

```
- Simpler Vim script to reproduce with `nvim -u NONE -S`:
```vim
autocmd WinEnter * call synstack(line("."), col("."))
autocmd WinEnter * call synID(line('.'), col('.') - 1, 1)
call setline(1, 'aaaaa')
normal! $
new
close
```
Crash is reproducible ~in Nvim v0.4.0 and above~ in Nvim v0.3.4 and above with ASAN. I haven't tested older versions.
- Oh, I first though this was a regression. I just built Vim with ASAN and found out that this heap-use-after-free also exists in Vim.
