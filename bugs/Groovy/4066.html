Title

@CompileStatic not recognising Literal list when LHS is a concrete list type

Description
Compiling this code: 
  
 @CompileStatic
 class  X {
    ArrayList list = [1,2,3]
}
 
  
 or this: 
  
 @CompileStatic
def method() {
    ArrayList list = [1,2,3]
}
 
  
 gives: 
  
 [Static type checking] - No matching constructor found: java.util.ArrayList <E extends java.lang.Object -> java.lang.Object><init>(int, int, int)
Discussion
- The compiler tries to apply tuple constructor transformation. Should this case work the same as this? 
  
 
ArrayList list = [1,2,3]  as  ArrayList
 
  

 What about a more complex type that also implements  List , like  groovy.lang.Range  or  groovy.lang.Tuple  or  org.spockframework.lang.Wildcard ?
- Runtime uses the list as a constructor argument when no constructor is found for the tuple of the list elements.  STC/SC does not implement this fallback.  I think  StaticTypeCheckingVisitor#addListAssignmentConstructorErrors  is where the extra check needs to be added.  After that, not sure if classgen needs something as well.
