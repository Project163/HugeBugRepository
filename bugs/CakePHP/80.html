Title

3.0 - Accessing related tables from within table class

Description
When trying to access related table objects, and run custom finders or other custom methods on them from within a certain table class, in the context of a plugin, it fails, if the relation if configured in accordance with the docs.

[URL]

``` php

$this->belongsTo('Authors', [         
'className' => 'Publishing.Authors', 
'foreignKey' => 'authorid',         
'propertyName' => 'person'     
]); 
```

debug of the relation `$this->Related` gives this output:

```
object(Cake\ORM\Association\BelongsTo) {
    [protected] _name => 'Related'
    [protected] _className => 'Plugin.Related'

```

and when trying to call anything on it it throws a fatal error in `TableRegistry.php` on line 160

but this is what actually works:

``` php
$this->belongsTo('Plugin.Related', [ 
        'className' => 'Related', 
        'foreignKey' => 'my_id']); 

```

```
object(Cake\ORM\Association\BelongsTo) {
    [protected] _name => Plugin.Related'
    [protected] _className => 'Related'
```
Discussion
- Interesting, the className option should work, I can take a look at this as the docs are how the code _should_ work.

All plugin tables will need to have the plugin prefix on them, there are no implicit plugin prefixes in 3.0.
