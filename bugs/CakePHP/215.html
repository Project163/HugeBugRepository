Title

saving records with hasOne relationship throws no error

Description
If you create a model with a hasOne relationship to a table based on conditions (i.e. 'conditions'=>['primary'=>1]), if a record already exists and primary is set to 1 and you try to create another before setting primary to 0 on the existing record it simply fails without an error. This is the correct behaviour but was very difficult to debug as there was only a BEGIN and ROLLBACK query being show in the logs and nothing in between.
An error message giving an indication to where the error is would be useful.

conflict with the hasone permission.  This will fail but produce no error
on the save function.
