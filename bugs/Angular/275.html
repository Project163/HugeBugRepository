Title

i18n: extracted xliff file is not valid, ctype attribute is wrong

Description
**I'm submitting a ...**

```
[x] bug report => search github for a similar issue or PR before submitting

```

**Current behavior** 
The extracted xliff file is not valid. If you have a translation text in your html file like that:

```
 
My Text has a 
line break.
 
```

It creates in your xliff file the following trans-unit tag:

```
 
  
  My Text has a 
  line break.
  
 
```

**Expected output according to xliff spec 1.2 should be**

```
 
  
  My Text has a 
  line break.
  
 
```

I think there should be a mapping for all predefined ctype: [URL]

something like that:

```
let ctype;
switch(ph.tag) {
  case 'br':
    ctype = 'lb';
    break;
... [Log Snipped] ...
    ctype = 'x-' + ph.tag;
}
```

is needed instead of ph.ctype around that lines here:
