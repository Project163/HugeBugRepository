Title

Partitioning discovery logic HadoopFsRelation should use a higher setting of parallelism

Description
At  [URL] we launch a spark job to do parallel file listing in order to discover partitions. However, we do not set the number of partitions at here, which means that we are using the default parallelism of the cluster. It is better to set the number of partitions explicitly to generate smaller tasks, which help load balancing.
Discussion
- I couldn't find the best solution for this issue though, it seems at least we'd better to limit #parallelism for this file listing before the v2.0 release 
because users might get surprised at generating many tasks in case of large defaultParallellism. 
I know we can control this by defaultParallelism though, this seems to be not suitable for that because it is a global option. 
One of solutions is to set (paths.size / parallelPartitionDiscoveryThreshold + 1) at the number.
