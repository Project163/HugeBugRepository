Title

PostgreSQL: JSONB subscription syntax missing parentheses for JSONB-returning functions

Description
### Discussed in [URL]

 

 Originally posted by **noirbee** August  1, 2025 
Following [URL] and [URL] , upgrading to sqlalchemy 2.0.42 now triggers syntax errors on PostgreSQL's side when using JSONB-returning functions, e.g. `jsonb_array_elements()`.

This is due to a quirk in PostgreSQL's own syntax, where the `["key"]`-style JSONB subscription cannot be used as readily as the `->` / `->>` one.

A good example is worth a thousand words:

```
postgres=# SELECT jsonb_array_elements('[{"key": "value1"}, {"key": "value2"}]'::jsonb) -> 'key';  -- good old "->" syntax, no parentheses needed
 ?column? 
----------
 "value1"
 "value2"
... [Log Snipped] ...
 "value2"
(2 rows)
```

Since  , sqlalchemy now uses the `['key']` syntax everywhere; in most cases (i.e. JSONB column subscription) this pauses no problem, but when using functions with an explicit `type_=JSONB` it now always generates statement using the new syntax, which may fail. 

```
python
# sqla_postgresql_jsonb_subscript.py
from sqlalchemy import __version__, func
from sqlalchemy.dialects import postgresql
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column
... [Log Snipped] ...
):
    print(statement.compile(dialect=postgresql.dialect()))
```
In SQLAlchemy 2.0.41:
```shell
% ./venv/bin/python sqla_postgresql_jsonb_subscript.py
sqlalchemy 2.0.41
hello.data -> %(data_1)s
jsonb_array_elements(hello.data -> %(data_1)s)
jsonb_array_elements((hello.data -> %(data_1)s)) -> %(jsonb_array_elements_1)s
```
In SQLAlchemy 2.0.42:
```shell
% ./venv/bin/python sqla_postgresql_jsonb_subscript.py
sqlalchemy 2.0.42
hello.data[%(data_1)s]
jsonb_array_elements(hello.data[%(data_1)s])
jsonb_array_elements(hello.data[%(data_1)s])[%(jsonb_array_elements_1)s]
```
