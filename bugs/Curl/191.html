Title

Timeout can result in segv in Curl_multiuse_state with nss

Description
### I did this
Using the attached modified curl example program a segv is regularly seen in Curl_multiuse_state when a timeout is forced. This is with NSS (version 3.68.1 RTM). With curl debug assertions enabled the following error is instead emitted:
multi.c:3486: Curl_multiuse_state: Assertion `conn->bundle' failed.

[Link: curl-nss-crash.c.txt]

The callstack of the assertion failure / crash is:
```
#4    in Curl_multiuse_state (data= , bundlestate=-1) at multi.c:3486
#5    in HandshakeCallback (sock= , arg= ) at vtls/nss.c:893
#6    in ssl_FinishHandshake () from /lib64/libssl3.so
#7    in tls13_FinishHandshake () from /lib64/libssl3.so
#8    in tls13_SendClientSecondRound () from /lib64/libssl3.so
... [Log Snipped] ...
#25   in curl_multi_perform (multi= , running_handles= ) at multi.c:2559

```

and appears to be due to this change: [URL] which reads any pending close notify alert prior to closing a connection. If there is an issue in how we are calling curl or curl_multi please let us know!

### I expected the following
It not to crash.
