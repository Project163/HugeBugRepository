Title

The explanation about .eslintignore seems wrong

Description
Looking at [URL]

Here is the wrong (or at least confusing) text:

This is not the behavior I see, especially the `current working directory` part. It seems to me eslint tries to find a .eslintignore file in the parent directories as well.

Another issue is how it matches entries that do not start with '/'. Say we have the following structure:

```
/.eslintrc
/.eslintignore
/src/
/src/extensions/
/src/extensions/hello.js
/extensions/
/extensions/hello.js
```

And .eslintignore contains:

```
extensions
```

Then running eslint would ignore both `/src/extensions/hello.js` and `/extensions/hello.js`. And we get the same behavior whether we run eslint from the project's root directory or a subdirectory (eg `src`):

```
0:0  warning  File ignored because of a matching ignore pattern. Use --no-ignore to override
```

If we use `/extensions` instead of `extensions` in `.eslintignore`, then it works as I intend: it only ignores the top level `extensions` directory.

So at the very least this behavior should be described in the documentation. But best would be to change this behavior, and request a `**/` prefix to match subdirectories as well.
