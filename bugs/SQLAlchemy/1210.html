Title

result can be iterated and populate the wrong identity map

Description
### Discussed in [URL]

since the async session prebuffers rows, the linked examples show different behavior for async vs. sync.  however, the sync example produces invalid state: foo thinks its persistent in the session when it's actually not.  this is a bug.  the session is closed so there is no way to fetch the result here and this must raise.

```
py
from sqlalchemy import create_engine, select, text, Integer, Column
from sqlalchemy.orm import declarative_base, sessionmaker

Base = declarative_base()
... [Log Snipped] ...

go_sync()
```

it can raise minimalistically like this, but having it be more cleanly enforced at the result level would be better:

```
diff
diff --git a/lib/sqlalchemy/orm/identity.py b/lib/sqlalchemy/orm/identity.py
index 7eec4fd8d8..4911135f6c 100644
--- a/lib/sqlalchemy/orm/identity.py
+++ b/lib/sqlalchemy/orm/identity.py
... [Log Snipped] ...
         self._new = {}
         self._deleted = {}
```
Discussion
- then again if the result is prebuffered, it sohuld just work, and since asyncio is doing that, maybe that should pass.  if its prebuffered lists of ints and not ORM objects there's not a problem.

the main thing is that loading.py should not be allowed to attach to the wrong identity map, that's the most critical part here that produces the invalid state.
- e.g. this should pass:

```
py
def go_sync():
    with engine.begin() as conn:
        Base.metadata.drop_all(conn)
        Base.metadata.create_all(conn)
... [Log Snipped] ...
    from sqlalchemy import inspect
    assert inspect(foo).detached
```
- **Mike Bayer** has proposed a fix for this issue in the **master** branch:

**disallow adding to identity map that's been discarded** [URL]
