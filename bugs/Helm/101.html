Title

Could not delete default keys from subcharts if subchart is defined in dependencies

Description
Hi,

looking at docs [URL] I'm able to remove keys from default values located in subcharts:

values.yaml:
```
yaml
# demo/values.yaml:
global:
  hash:
    key1: null
... [Log Snipped] ...
  key5: 5
  key6: 6
```

Output:

```
jkr@joe-nb demo % helm template .
---
# Source: demo/charts/subchart/templates/values.yaml
global:
  hash:
... [Log Snipped] ...
  key5: 5
  key6: 6
```

But If I add:

```yaml
dependencies:
  - name: subchart
    version: 0.1.0
```

to the main Chart.yaml the behavior changes:

```
jkr@joe-nb demo % helm template .
---
# Source: demo/charts/subchart/templates/values.yaml
global:
  hash:
... [Log Snipped] ...
  key5: 5
  key6: 6
```

The merge of values is still working while removing key isn't working.
This bug exists on helm2 w/ requirements.yaml, too. Just for notice.

Output of `helm version`:

```
jkr@joe-nb demo % helm version  
version.BuildInfo{Version:"v3.4.0", GitCommit:" ", GitTreeState:"dirty", GoVersion:"go1.15.3"}
```

Demo: [Link: chart.tar.gz] (wrong file extension, its an uncompressed tar)
Discussion
- The attachment you provided is not a gzipped tarball, FYI. Just a tar file.

```

gzip: stdin: not in gzip format
tar: Child returned status 1
tar: Error is not recoverable: exiting now
```

`tar xf chart.tar.gz` works fine.

I can reproduce this behaviour via the values file.

```
/tmp/test-9027/demo ><> helm template .
---
# Source: demo/charts/subchart/templates/values.yaml
global:
  hash:
... [Log Snipped] ...
  key5: 5
  key6: 6
```

However, this can be worked around by setting a value via `--set` to `null`.

```
/tmp/test-9027/demo ><> helm template . --set subchart.hash.key1=null,subchart.hash.key2=null
---
# Source: demo/charts/subchart/templates/values.yaml
global:
  hash:
... [Log Snipped] ...
  key5: 5
  key6: 6
```

This to me seems like something to do with the YAML parser where a null value is not received or parsed, whereas the `--set` parser can pick up these null values and propagate them down the tree as needed.
- Thanks for the info about the attachment, I add a note.

If you are removing

```
dependencies:
  - name: subchart
    version: 0.1.0
```

from Chart.yaml everything works as expected. 

I don't know if the YAML parser is wrong here but it seems like there is a different code path if dependencies are defined.
