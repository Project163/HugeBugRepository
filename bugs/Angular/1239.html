Title

HttpClient#put with `observe: events` and generic as return type doesn't take in `reportProgress: true`

## Current behavior
 

Consider this:
```
ts
this.http.put ('endpoint', {}, {
  reportProgress: true,
  observe: 'events',
});
... [Log Snipped] ...
  reportProgress: true,
});
```

Basically, the top `HttpClient#put` call doesn't compile in TS from a non-matching override function definition. Bottom does.

According to: [URL]

There's no way to specify `reportProgress: true` when you're using a generic type to specify the return type for `HttpClient#put` and the configuration `observe: 'events'` to exist. Compare this to:

[URL]

Where there is the definition for it if you're not returning a generic type as a part of `HttpEvent`.


## Expected behavior
 

Supposedly you add `reportProgress?: boolean` into the override definition? Can definitely make a quick PR if this is the case.


## Minimal reproduction of the problem with instructions
 

[URL] shows the TS compile error.

## What is the motivation / use case for changing the behavior?
 

Well, type correctness? I don't think that type of PUT request wasn't supported. I assume like every other methods, they are small wrappers to create an `HttpRequest` for `HttpClient#request`, which handles `reportProgress` and `observe: events` the same for any types of requests.

## Environment

Considering the code is still in `master`, I'm assuming all versions of Angular to this date and all versions of TypeScript.
