- @allevato I'm not able to replicate this issue.
I ran it on macOS 10.14.2 with latest command line tool installed, Python 3.7.
And it was a successful build. 
Btw there was just one warning which seems like an easy bug to fix.

And I followed [Link: the building guide].
- I ran into similar issues, even after following `BUILDING.md`. In my case, I was using Command Line Tools for Xcode instead of a full Xcode installation. I found that `make` was successful but `bazel build :all` didn't work.

The issues were resolved once I installed Xcode, used `xcode-select` to switch to that installation, and ran `bazel clean --expunge`.
- Sorry for the very late delay on this; I got pulled onto other work.

I've found the problem—the `cares` BUILD file only recognizes the `darwin` CPU value, but Bazel also allows `darwin_x86_64` (and that is what the Apple build rules recommend). Until that gets cleaned up, I'm sending a PR to add the alternate CPU value. After doing that, the repository builds properly.
