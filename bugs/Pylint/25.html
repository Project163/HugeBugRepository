Title

regression when using flymake

Description
Originally reported by: **Aurélien Campéas (BitBucket: [Link: auc], GitHub: @auc?)**

---

emacs + flymake-mode + pylint is a powerful combo

However recent pylint releases have broken some of the sweetness.

The epylint thing only works with this change::

```
#!python

@@ -76,7 +77,8 @@

     # Start pylint
... [Log Snipped] ...
     cmd = [sys.executable, lintPath] + options + ['--msg-template',
             '{path}:{line}: [{symbol}, {obj}] {msg}', '-r', 'n', childPath]
```

Then, within emacs, several issues:
- coloring is now wrong (everything looks like an error, e.g. in red)
- some errors are "No module named uicfg_flymake.py" ...
- the minibuffer/message content is weird-looking, e.g.
  
  pylint: [[1;31mundefined-variable[0m, ] [1;31mUndefined variable 'StringField'[0m [6 times]

Discussion
- _Original comment by_ **Joel Cooper (BitBucket: [Link: joel_cooper])**:

---

Also, the --msg-template doesn't include an argument that ensures that warnings from lint have the correct "W".  This causes the subsequent regex to fail and all warnings appear highlighted as errors.

This can be fixed by making the --msg-template include the msg_id.  For example: '{path}:{line}: [{msg_id} {symbol}, {obj}] {msg}'.
- This was apparently fixed by f8fdbc3f. If there are still issues with flymake + epylint, please create a new issue per each existing problem.
