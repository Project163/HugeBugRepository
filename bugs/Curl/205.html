Title

sftp blocking and infinite loop problem

Description
### Discussed in [URL]

 

 Originally posted by **jiexuelc** March 24, 2022 
## Program running environment
The curl(7.66.0) is built with libssh (0.9.6) to support sftp protocol.

## Q1: curl get stuck when network disconnected
I see that in SSH_SFTP_INIT state, the ssh session working mode is set to blocking mode. If the network is suddenly disconnected during sftp transmission, curl will be stuck, even if curl is configured with a timeout. 
Is the sftp transport designed to work only in blocking mode? Is there a way to change the working mode to non-blocking in sftp transfer?

## Q2: curl infinitely tries to create directory
When configuring CURLOPT_FTP_CREATE_MISSING_DIRS option for curl, the directory will be created automatically if it does not exist. However, if the server is disconnected frequently, it may lead to infinite creation of directories. The reason is that when libssh fails to write data to the server, the error code is set to SSH_FX_FAILURE. 
Is it possible to remove this error code in the error judgment condition? Or can we add a limit on the number of failures?

- Everything in libcurl is (or should be) non-nonblocking.

Note that you're using a fairly old libcurl version, but I'm not sure the libssh backend has been changed a lot since then.


If  there's something blocking while SFTP'ing. It's a bug. Either in libssh or in curl itself.
