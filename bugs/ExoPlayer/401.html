Title

ChunkSampleStream cannot handle empty chunks

Description
It assumes a source has at least one sample. If it doesn't and reports EOS immediately, this happens:

```
java.lang.ArrayIndexOutOfBoundsException: length=5; index=-1
       at java.util.ArrayList.get(ArrayList.java:439)
       at com.google.android.exoplayer2.source.chunk.ChunkSampleStream.maybeNotifyPrimaryTrackFormatChanged(ChunkSampleStream.java:582)
       at com.google.android.exoplayer2.source.chunk.ChunkSampleStream.maybeNotifyPrimaryTrackFormatChanged(ChunkSampleStream.java:577)
       at com.google.android.exoplayer2.source.chunk.ChunkSampleStream.readData(ChunkSampleStream.java:358)
... [Log Snipped] ...
       at android.os.Looper.loop(Looper.java:164)
       at android.os.HandlerThread.run(HandlerThread.java:65)
```

There are also some related edge cases to do with empty chunks:

* Should we report their formats to `downstreamFormatChanged` (probably yes, but we don't currently do this in all cases).
* Should we do this even if it's the very last chunk (probably yes).
* Should `discardBuffer` discard empty chunks immediately before the current position (probably no, since it breaks reporting their formats).
