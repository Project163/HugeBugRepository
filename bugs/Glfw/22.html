Title

cmake Warning on OS X 10.9.5 leads to make error

Description
#### Assumptions
- Using OS X 10.9.5
- Using a fresh clone of master branch from git repository
- see: [Link: _Environmental Details_] section for more detail.
#### Steps to reproduce:
- Step One: run cmake
  
  ``` shell
  $ cmake .
  ```
  - _Step One's observed output(some omitted for brevity):_
  
  ```
shell
  ...
  -- Building GLFW only for the native architecture
  CMake Warning (dev) at examples/CMakeLists.txt:31 (add_executable):
    Policy CMP0037 is not set: Target names should not be reserved and should
... [Log Snipped] ...
  This warning is for project developers.  Use -Wno-dev to suppress it.
  ...
```
- Step Two: run make
  `shell
  $ make
  `
  - _Step Two's observed output(some omitted for brevity):_
  
  ``` shell
  ...
  [ 35%] Built target Simple
  examples/CMakeFiles/Split View.dir/build.make:76: *** missing separator.  Stop.
  make[1]: *** [examples/CMakeFiles/Split View.dir/all] Error 2
  make: *** [all] Error 2
  ```
####   Environmental Details:

```
shell
$ cmake -version
cmake version 3.0.2

CMake suite maintained and supported by Kitware (kitware.com/cmake).
... [Log Snipped] ...
$ git --version
git version 2.0.1
```
#### My Workaround:

After reading:

```
shell
$ cmake --help-policy CMP0037
CMP0037
-------

... [Log Snipped] ...
3.0.2 warns when the policy is not set and uses OLD behavior.  Use
the cmake_policy command to set it to OLD or NEW explicitly.
```

I implemented a fix in [Link: one of my fork's branches] that allowed `$ make` to complete successfully.
