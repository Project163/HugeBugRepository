Title

[Question] Continuous setError will Behave Incorrectly

Description
**Describe the bug**
I'm currently using v3.10 and planning to upgrade.
However, I've noticed some stranger behavior when using the latest release (v3.18).
I'm making a select component using React Material Text Field which is a custom component (https://material-ui.com/components/text-fields/).
I do manual validation on the select component when the `onChange` occurred.
It seems that calling `setError(name)` continuously will "toggle" the error. Please refer to the reproduce step.

**To Reproduce**
Steps to reproduce the behavior:
1. Go to [URL] This is a simple demo that will do validation on the select component each time `onChange` occurred. The select component will be displayed in red color if the selected item is invalid. The invalid item is 'Strawberry', 'Vanilla' and 'Chocolate' is valid.
2. The initial selected item should be `Strawberry`, and the select component is red-colored.
3. Click on the select component and choose 'Chocolate'. The select component error indicator is gone.
4. Click on the select component and choose 'Vanilla'. The select component is now red-colored again.
5. Click on the select component and choose 'Vanilla' again, the component error indicator is gone.
6. Now try to use v3.10 and repeat the process. The bug won't happened.

**Expected behavior**
Valid item shouldn't treated as error.
