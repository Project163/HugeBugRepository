Title

ES2015's object literal shorthand properties breaks `key-spacing`

Description
It appears that passing shorthand property to object literal breaks `key-spacing` rule:

``` javascript
const xyz = 123;
const test = {
    aaaa: 123,
    bbbb: 1123,
    xyz
};
```

with these errors

``` javascript
error  Missing space before value for key "aaaa"  key-spacing
error  Missing space before value for key "bbbb"  key-spacing
```

ESLint version: v1.3.1
`.eslintrc` file: [URL]

I'm not confident this can squarely be called a bug because it's ambiguous how this should be treated, and the current behavior could be seen as consistent with the rule description ("Groups of properties separated by blank lines are considered distinct and can have different alignment than other groups.")
