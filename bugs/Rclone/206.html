Title

Bandwidth limiter toggle fails in conjunction with schedules

Description
When using a schedule like `--bwlimit "08:00,768 13:00,512 23:00,off"`, signaling `USR2` to rclone yields unexpected results. Initially, disabling the bwlimit works fine, but if a later schedule overrides the `tokenBucket`, sending the signal seems to activate the `tokenBucket` that was disabled with the first signal. 

I believe this is the case due to the variable swap in `account_unix.go` as well as the ticker in `startTokenTicker()` not considering whether the bwlimit is currently disabled or enabled. If it's disabled, it should probably not set `tokenBucket` to the scheduled bwlimit, but instead `prevTokenBucket`, s.t. the scheduled bwlimit only becomes active when toggled again. However, unfortunately I currently don't have the time to verify this, but I hope this helps fixing the issue.
