Title

2.1.0-beta.22 - build hangs when non-web `target` specified.

Description
**I'm submitting a bug report**

**Webpack version:**
2.1.0-beta.22

**Please tell us about your environment:**
OSX 10.10.5

**Current behavior:**
When `target` is specified as any of `node`, `async-node`, `node-webkit` or `electron` the build never finishes it hangs at:

`75% advanced module optimization`

This arose while attempting to build for `electron`

**Expected/desired behavior:**
This same config file worked without issues in `1.13.1`, I never even noticed this `advanced module optimization` step before updating to 2.1.0-beta.22

Below is my webpack config:

```
const autoprefixer = require('autoprefixer');
const path = require('path');
const webpack = require('webpack');

module.exports = {
... [Log Snipped] ...
    target: 'electron'
};
```

And here is the output:

```
[10:26:36] $ npm run build:webp[ack 
NODE_ENV=production webpack --config webpack.config.js --progress

 75% advanced module optimization
^C                               

[11:11:44] $
```

Until that `75% advanced module optimization` I see regular progress.

 Is there anything in my `webpack.config.js` which is going to cause issues when building for the `electron` target? 

I have tried removing the `plugins`, `postcss`, `resolve` and `resolveLoader` to get this config to be as simple as possible, but I've seen no change in behaviour.

Apologies if this is considered a support request, it seemed to me likely to be an issue with the `2.1.0-beta.22` build.

Thanks in advance.

- A couple of additional items of note:

- This issue only occurs when using the `require.ensure([], (require) => cb(null, require('something')));` syntax. Using the generic `require()` seems to work fine.
