Title

HttpClient5 - RequestEntityProxy#isRepeatable incorrectly returns false before entity is consumed

Description
The behavior of  RequestEntityProxy#isRepeatable  changed in  this commit , where the method now returns  false  unless  writeTo()  has already been called. 

 This appears to be a regression. Previously, an entity was considered repeatable as long as it hadn't been consumed yet and the original entity itself was repeatable. The new logic incorrectly assumes that an entity is only repeatable  after  it's been consumed, which defeats the purpose of determining retry eligibility  before  transmission.
