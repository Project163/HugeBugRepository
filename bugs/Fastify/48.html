Title

A change in Fastify hook types broke our hooks

Description
## 💬  A change in Fastify hook types broke our hooks

When upgrading Fastify we encountered strange problems with our `preHandler`-hooks. Narrowing down, the problem was introduced when upgrading from 3.18.0 to 3.18.1, and more specifically it was this change: [URL]

Given a custom hook
```ts
// A hook that does nothing, just to demonstrate the issue with the types
const myHook: preHandlerAsyncHookHandler ,
  RawReplyDefaultExpression ,
  {}
```

and using it like this
```
ts
interface TestRoute extends RouteGenericInterface {
  readonly Reply: { ok: boolean };
}

... [Log Snipped] ...
  return Promise.resolve();
};
```

we get this error
```
src/testRoutes.ts:27:20 - error TS2769: No overload matches this call.
  The last overload gave the following error.
    Argument of type '"preHandler"' is not assignable to parameter of type '"onClose"'.

27   instance.addHook("preHandler", myHook);
... [Log Snipped] ...
        ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
    The last overload is declared here.
```

I set up a minimal project demonstrating just this issue: [URL]

Just run `yarn && yarn build` to see the error. 

What are we doing wrong?

## Your Environment

- *node version*: 14.15.4
- *fastify version*: 3.18.1 and onwards
- *os*: Mac, but issue seems to be platform independent
