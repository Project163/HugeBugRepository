Title

rails g devise admin/some_model doesn't work properly

Description
When running the devise generator against a model in a sub-directory e.g. admin, it does most things right, but it misses out adding the necessary code to the model. 

It adds code to routes.rb correctly, and it gets the table name in the migration right, but I have to manually edit the model.
Discussion
- I actually found what is causing this:

[URL]

Is using only the last class name. We should use the complete name. The problem is that if we use that, the generator will stop working on engines.

Thoughts ?
- Thanks for taking a look at this issue.

If it gets the naming right just fine for routes and migrations then how does it handle routes and migrations in engines?

I guess one way, though an inelegant way, would be simply to add a command line parameter to let the generator know it's being used in the context of an engine.

Which is used more frequently, adding Devise to a model in a namespace, e.g. an admin namespace, or adding Devise to a model in an engine? Make the most frequent use the default and then the other one would require a command line parameter.
- @JohnSmall 

I probably introduced this bug while fixing another one (https://github.com/plataformatec/devise/pull/1823). Probably this changes make the generators inside modules to break. 

But I don't think that we should introduce a bug just to fix another one. We should figure out a way to fix both. Maybe a check if we're inside an engine, and execute the proper code (without the `.last` on [URL] ) when needed. 

The generator idea that you gave may be a solution, but I think we may try adding it without this (I have a feeling that not many people will check the documentation and them they may come here and say that it doesn't work).
