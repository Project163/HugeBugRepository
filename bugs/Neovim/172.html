Title

echo getchar() == "\ " return 0 when I press

Description
I found an issue with neovim and gvim, but I am not sure if this is  correct. I test it in neovim-master and gvim8.0.

in both neovim and gvim, `:echo getchar() == "\ "` return 0 when I press ` `,  but `:echo getchar() == "\ "` return 1 when I press ` `.

BTW I have test ` `, ` `, ` `, ` `, both works well.
Discussion
- While this is strange, it is documented: `getchar()` returns either a number (which needs to be passed to `nr2char()` then) or a string, do read documentation: this is right in the second paragraph.

And do not use `==` for string comparison, use `is#`: it is case-sensitive always (`==` depends on `&ignorecase` option) and does not compare true with zero (`"\ " == 0` yields 1).
- @ZyX-I I have test `:echo getchar() is# "\ "` then press ` `, still return 0.
- @wsdjeg This is not what you should do specifically for ` `: being a single byte it will return a number. What normally is done with `getchar()` is *first* converting `getchar()` output to a string *if* its output is number and only then doing anything with it at all: e.g. just always use wrapper

 ```VimL
function Getchar(...)
    let ret = call('getchar', a:000)
    return (type(ret) == type(0) ? nr2char(ret) : ret)
endfunction
```

This way you do not need to bother which of the keys are represented with what type of the output.
