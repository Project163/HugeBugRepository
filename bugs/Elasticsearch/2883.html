Title

Prewarm Tasks for Cold Snapshots are not actively interrupted and lead to running out of disk space

Description
We seem to have no check for a closed directory during the actual downloading part of a pre-fetch in `org.elasticsearch.xpack.searchablesnapshots.store.input.CachedBlobContainerIndexInput#prefetchPart`.

This appears to cause running out of disk space if large shards and reallocations come together with prefetch tasks for shards that are not recovering any longer pilling up in the background, still doing work.

I think we can/should fix this by adding a check for a closing store like we have in e.g. standard snapshot recovery via something like `org.elasticsearch.repositories.blobstore.FileRestoreContext#ensureNotClosing`.
