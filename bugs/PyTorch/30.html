Title

Comparing tensor subclass instance with `None` causes segmentation fault

Description
Repro:

```python
# LoggingTensor from test_python_dispatch.py
x = LoggingTensor(torch.tensor([3.0, 4.0], requires_grad=True))
self.assertEqual(x, None)
```
 


cc @ezyang @gchanan @zou3519 @bdhirsh @jbschlosser @albanD
Discussion
- `self.assertEqual` calls `tolist` on `LoggingTensor` which leads to the segfault.


 

 Reproducer 

```
python
import torch
import logging
import torch
from torch.utils._pytree import tree_map
... [Log Snipped] ...
print(t.numpy())
print(t.tolist())
```

Output
```
LoggingTensor(tensor([1.]))
[2.]
Segmentation fault (core dumped)
```

 


Also note calling `numpy()` produces array with incorrect value.
- The reason for this is that we are trying to access storage (via `load_scalar` [URL] in a function (`tolist`) that doesn't go through the dispatcher.  

We should probably just error out if the tensor subclass doesn't overload `tolist`. Just realized that `to_list` is also problematic for conjugated tensors (https://github.com/pytorch/pytorch/issues/66024).
