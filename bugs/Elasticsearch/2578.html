Title

[ML] effective_max_model_memory_limit may be too low in autoscaling environment

Description
One of the outputs from the `_ml/info` API is `effective_max_model_memory_limit`.  This value is intended to be a hint for the UI about the highest sensible `model_memory_limit` to suggest taking into account both hard limits configured in `xpack.ml.max_model_memory_limit` and the size of available ML nodes, the idea being to stop users from creating jobs that can never be opened in the cluster.

The logic used to calculate `effective_max_model_memory_limit` does not take into account the value of the recently added `xpack.ml.max_ml_node_size` setting.  This leads to two possible problems:

1. In a cluster with no ML nodes currently but autoscaling enabled we do not consider all available information so do not return a value for `effective_max_model_memory_limit` when we could.
2. In a cluster with small ML nodes and autoscaling enabled we base `effective_max_model_memory_limit` on the size of these small nodes rather than the size that autoscaling could scale those nodes up to if necessary.

Problem 2 is likely to manifest in the case where a user has some small ML jobs, then decides to create one that would ideally have a large `model_memory_limit`.  The UI will guide them to set a `model_memory_limit` that is suboptimally small on the assumption that new ML nodes added to the cluster will be the same size as the current ones.
