Title

`bevy_winit` feature pulls in too many crates

Description
## Bevy version and features

```
toml
bevy = { version = "0.17.2", default-features = false, features = [
	"std",
	"async_executor",
	"bevy_window",
... [Log Snipped] ...
	"wayland",
] }
```

## What you did

I'm planning to write a custom renderer, with bevy only handling runtime, windowing, input. So I wanted to strip out any crates that had to do with higher level rendering. So I configured my features as above.

## What went wrong

Despite this several crates (bevy_input_focus, bevy_camera, bevy_mesh) I don't want still got compiled in.

## Additional information

This series of deps seems to be the main issue:
```
$ cargo tree -i bevy_mesh
bevy_mesh v0.17.2
└── bevy_camera v0.17.2
    └── bevy_picking v0.17.2
        └── bevy_input_focus v0.17.2
            └── bevy_winit v0.17.2
                └── bevy_internal v0.17.2
                    └── bevy v0.17.2
```
Asking for windows should not result in a bunch of picking and 3d stuff to come along with it.
Discussion
- The `bevy_winit` -> `bevy_input_focus` link is the key problem here.

I also think we can probably make the `bevy_camera` -> `bevy_mesh` dependency optional at least.
- @atlv24 I know you worked on some parts of that dep chain so I assume you might have some opinions on how to fix it.
- bevy_camera needs bevy_mesh because it does visibility (i want to split out a bev_visibility someday but its low priority)
bevy_picking needs bevy_camera because it needs to know how to casts rays from the view (can't really be fixed afaik)
i am unfamiliar with bevy_input_focus, i think its a new crate.

anyhow, the intentions of all the crate work ive been doing have been to make it possible to use those bevy_mesh and bevy_camera etc crates with custom renderers. They do not include any rendering related code. Even bevy_shader and bevy_light are usable without a renderer. I strongly recommend looking at what the crates are before deciding not to use them, because they'll probably save you time. If you find something lacking in those crates i'd love to know.
