Title

Analyzed wildcard always uses OR operator on split terms

Description
Query string queries ignore the default operator on terms split from an analyzed prefix query.

```
sh
curl -XGET 'localhost:9200/test/doc/_search?pretty=true' -d '{
  "query": {
    "query_string": {
      "query": "apples-oranges*",
... [Log Snipped] ...
  }
}'
```

The above will search for apples OR oranges, even though the default operator is set to AND.

This gist will reproduce the bug, showing that the above query will match a document with just "apples" or just "oranges":
[URL]
Discussion
- The problem can be seen in [Link: line 533 of MapperQueryParser.java] which creates a boolean query out of the analyzed terms using a hardcoded `BooleanClause.Occur.SHOULD`.  The occur should be changed to MUST when the default_operator is AND.
- A workaround for this issue is to use `"minimum_should_match": "100%"`
- ... [Middle Discussions Snipped for Brevity] ...
- I think that stacked tokens (tokens in the same position) should be OR'ed, while tokens in different positions should be AND'ed.
- In fact the wildcard should only apply to the term (or terms) in the last position.
