Description
On master branch and RoR 4.1.19, I have the following Order:

``` ruby
ActiveAdmin.register Order do
  filter :payment_type
  # irrelevant code redacted ...  
end
```

The Order model: 

```
ruby
# +-----------------------------------------+---------------+------+-----+---------+----------------+
# | Field                                   | Type          | Null | Key | Default | Extra          |
# +-----------------------------------------+---------------+------+-----+---------+----------------+
# | id                                      | int(11)       | NO   | PRI | NULL    | auto_increment |
... [Log Snipped] ...
  # irrelevant code redacted ...  
end
```

When visiting the Orders page, the following error is raised:

```
undefined method `payment_type_code_eq_eq_eq_eq_eq' for Ransack::Search >:Ransack::Search
```

If visited a subsequent time, the "_eq" is appended even more!

```
undefined method `payment_type_code_eq_eq_eq_eq_eq_eq_eq_eq_eq_eq' for Ransack::Search >:Ransack::Search
```

The following monkey patch resolves:

```
ruby
module ActiveAdmin
  module Inputs
    module Filters
      class SelectInput < ::Formtastic::Inputs::SelectInput
... [Log Snipped] ...
  end
end
```

This patch basically preempts adding "_in" or "_eq" if it already exists on the name.
Discussion
- It seems like the best option would be to not modify the source string:

``` diff
         def input_name
           return method if seems_searchable?

-          searchable_method_name.concat multiple? ? '_in' : '_eq'
+          searchable_method_name + multiple? ? '_in' : '_eq'
         end
```
- @seanlinsley yes, that's actually what I ended up doing once I realized what was really happening and forgot to come back to this ticket with an update.
- So I don't forget: this is related to #4073. Ideally both should be fixed by the same PR.
