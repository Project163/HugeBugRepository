Title

UnsupportedOperationException: This feature requires ASM7 while using Panache and Guava

Description
**Describe the bug**
Quarkus build fails (with the Gradle plugin) when I am using both `quarkus-hibernate-orm-panache` and a Guava `LoadingCache` instance in the same project (not necessarily in the same class).

**Expected behavior**
I want to be able to use both `quarkus-hibernate-orm-panache` and any Guava feature in the same project.

**Actual behavior**
The following exception is thrown during the build:
```
org.gradle.api.tasks.TaskExecutionException: Execution failed for task ':quarkusBuild'.
        at org.gradle.api.internal.tasks.execution.ExecuteActionsTaskExecuter$3.accept(ExecuteActionsTaskExecuter.java:151)
        at org.gradle.api.internal.tasks.execution.ExecuteActionsTaskExecuter$3.accept(ExecuteActionsTaskExecuter.java:148)
        at org.gradle.internal.Try$Failure.ifSuccessfulOrElse(Try.java:191)
        at org.gradle.api.internal.tasks.execution.ExecuteActionsTaskExecuter.execute(ExecuteActionsTaskExecuter.java:141)
... [Log Snipped] ...
        at io.quarkus.creator.phase.augment.AugmentPhase$2.call(AugmentPhase.java:377)
        at io.quarkus.creator.phase.augment.AugmentPhase$2.call(AugmentPhase.java:360)
```

**To Reproduce**
Steps to reproduce the behavior:
1. Clone [URL]
2. Run `./gradlew clean build --stacktrace`

**Environment:**
 - Output of `java -version`: `openjdk version "11" 2018-09-25`
 - Quarkus version or git rev: `0.17.0`
Discussion
- It seems this issue is caused by the following transitive dependencies graph:
```
+--- com.google.guava:guava:27.0.1-jre (version from quarkus-bom)
     +--- org.codehaus.mojo:animal-sniffer-annotations:1.17
          +--- org.ow2.asm:asm:6.2
```

The latest `animal-sniffer-annotations` version (1.18) upgraded its `asm` dependency version to `7.0` but the latest `guava` version still depends on `animal-sniffer-annotations:1.17`.

There's a PR [Ref: #3497] in the Guava project about upgrading `animal-sniffer-annotations` to `1.18` which is currently being reviewed.
- I don't think we can solve this in Quarkus. I don't think we can define overrides in our BOM, right @gsmet ?

If there isn't any reason, would it help if I submitted a PR to replace all `Opcodes.ASM6` with `Opcodes.ASM7`?
