Title

CombiningStrategyAttributes don't work correctly on Generic methods

Description
This test works OK...

[Test, Combinatorial]
public void MyTest (
    [Values(1, 2)] T x
    [Values(3, 4)] T y)
{
}

It generates four test cases: (1,3) (1,4) (2,3) (2,4) and all of them match the signature of the method with T == int.

But this doesn't...

[Test, Combinatorial]
public void MyTest (
    [Values(1, "2")] T x
    [Values(3, "4")] T y)
{
}

It generates four test cases: (1,3) (1,"4") ("2",3) ("2","4")  where only two of them match the signature of the method, the first with T == int and the fourth where T == string.

Similar behavior will occur for Pairwise and Sequential attributes.

Making this work in all cases will be very complicated. Currently the CF build simply ignores any combining attribute when the method is generic. Really, it should give an error.

We may want to deal with this in stages. 
1. Give an error message when one of these attributes is used on a generic method.
2. Pick out the easy-to-implement cases and accept them. For example, methods of one argument.
3. Do a final fix that handles all cases.

Since nobody seems to have ever noticed this over the years, I'm keeping it at a normal priority even though it's a bit of a shock!
Discussion
- I think there is more to this than that. 

I see this being called in the current tests, and even though the tests are ignored here, the tests for which it is called are actually still later executed correctly.  That was what had me really confused.
- Every test is treated as if it had an invisible CombinatorialAttribute,
just in case any values are found. That's probably the call you are seeing.
If it's a generic method that doesn't have data attributes on the
arguments, then nothing is found, so no cases are generated.

However, I have succeeded in creating true generic tests like my examples.
Some of them work and some don't. Some an never work, unless we change the
meaning of Combinatorial.

As you see from the milestone assigned, I don't actually plan on working
this any time soon though.
