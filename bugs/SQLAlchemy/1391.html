Title

see if mysql has_table() can support temp tables w/ DESCRIBE (again, unfortunately)

Description
### Describe the bug

Version 1.3.13 would use DESCRIBE table_name to check the existence of a table for has_table function.  This technique DOES detect the presence of a TEMPORARY table.  However, with version 1.4.46, the has_table function implementation has changed to use SELECT COUNT(*) FROM information_schema.tables which does NOT detect the presence of a TEMPORARY table.

### To Reproduce

```
python
import pandas as pd

df = pd.DataFrame({"num": [1, 2]})
engine =  
... [Log Snipped] ...
    for row in results:
        print(row)
```


### Error

No error code, but the problem with the above code is that pandas uses sqlalchemy to check for existence of the shawn table and it returns false since the new existence check in sqlalchemy no longer detects TEMPORARY tables.  So pandas creates a new REAL table with the same name.  Then when pandas writes to the table using INSERT, the TEMPORARY table is used since TEMPORARY tables take precedence.  When the connection is closed, the TEMPORARY table automatically gets removed, but the REAL table mistakenly created by pandas gets left behind.

### Versions

- OS: MacOS 13.1
- Python: 3.8
- SQLAlchemy: 1.4.46
- Database: MySQL 8
- DBAPI (eg: psycopg, cx_oracle, mysqlclient): pymysql
