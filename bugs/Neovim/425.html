Title

Custom syntax matching does not work starting with v0.5.0

Description
### Neovim version (nvim -v)

NVIM v0.6.1

### Vim (not Nvim) behaves the same?

no, vim  8.1.2269

### Operating system/version

macOS 11.6 & Ubuntu 20.04.2 LTS

### Terminal name/version

iTerm2 3.4.15 & Ubuntu default

### $TERM environment variable

xterm-256color & xterm

### Installation

homebrew & appimage

### How to reproduce the issue

I initially found this issue on macOS, but found it easier to reproduce with a clean environment using docker.

Create `init.vim`:

```vim
syn match NonPrintableAscii "[^\x20-\x7F]"
```

In the same folder, create `testfile`:

```make
.PHONY: black
black:
	poetry run black tests
	echo ÍÍ‰¿  
```

In the same folder, create `Dockerfile`:

```
dockerfile
FROM ubuntu

RUN apt-get update \
        && apt-get install -y curl \
... [Log Snipped] ...
COPY init.vim /root/.config/nvim/init.vim
COPY testfile testfile
```

This installs neovim and copies the other files we created into the image.

Build the image, create a container and get a bash shell in it:

```bash
docker build -t neovim -f Dockerfile . && docker run -it neovim /bin/bash
```

Open the test file:

```bash
nvim testfile
```

Move the cursor over any of the non-ascii or tab characters and check what the syntax ID under the cursor is:

```vim
:echo synIDattr(synID(line("."),col("."),1),"name")
```



### Expected behavior

`NonPrintableAscii ` should be displayed.

### Actual behavior

Nothing is displayed.

If you change the version of neovim installed to `v0.4.4` (part of the `curl` command in the `Dockerfile`), it displays `NonPrintableAscii` as expected. Changing it to `v0.5.0` or greater results in the issue as described.
Discussion
- It seem when the `init.vim` is sourced again, custom syntax matching is working correctly.
- Oh good catch, changing `init.vim` to this serves as a workaround:

```vim
autocmd BufNewFile,BufRead * syn match NonPrintableAscii "[^\x20-\x7F]"
```
