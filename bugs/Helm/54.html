Title

UTF-8 BOM in a resource template fails deployment

Description
When installing or upgrading a helm chart with a file that is encoded as UTF-8 BOM (Byte Order Mark) the deployment fails with the following message:
Error: release   failed: the server could not find the requested resource

You can find an example chart here: [URL]
Note the service.yaml is encoded in UTF-8 with BOM 

A UTF-8 BOM is usually added to the template file when the file is created in Windows

This issue is also not detected by a `helm lint`
It would help allot if either helm automatically removes the invisible BOM from the resource files and/or `helm lint` will detect the issue. 

Output of `helm version`:
Client: &version.Version{SemVer:"v2.14.2", GitCommit:" ", GitTreeState:"clean"}
Server: &version.Version{SemVer:"v2.14.2", GitCommit:" ", GitTreeState:"clean"}
