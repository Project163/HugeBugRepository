Title

`PatternUtils.formatPattern` replaces encoded space (%20) with +

Description
This line causes a URL parameter to be encoded in a non-reversible way: [URL]

We have an IIS server that doesn't correctly resolve URLs because of this behavior.

The change was introduced here: [URL]

I'd like to know the reason that this behavior was introduced, as it's somewhat unexpected. To quote @mjackson:

I've not been able to find conclusive evidence in the [Link: URI spec], but considering that encoding and decoding should be symmetrical operations, this seems wrong. There is some discussion in this [Link: Stackoverflow thread].

Example:

```
var placeName = 'Laguna Beach';
var uri = formatPattern('/place/:placeName', { placeName: placeName });
decodeURI(uri);
// -> "/place/Laguna+Beach"
// Expected decoded URI would be "/place/Laguna Beach".
```
