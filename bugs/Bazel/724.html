Title

not actionable notice: rule x indicated that a canonical reproducible form can be obtained ...

Description
### Description of the problem / feature request:

Recently I get a lot of output like below in my builds
```
DEBUG: Rule 'org_golang_x_tools' indicated that a canonical reproducible form can be obtained by modifying arguments sha256 = " "
DEBUG: Rule 'org_golang_x_sys' indicated that a canonical reproducible form can be obtained by modifying arguments shallow_since = "1547471016 +0000"
DEBUG: Rule 'org_golang_x_net' indicated that a canonical reproducible form can be obtained by modifying arguments shallow_since = "1547150550 +0000"
```

now sadly those are all inherited targets (from WORKSPACE), at least a git grep "org_golang_x_sys" does not show anything. It would be great to only show messages about targets that the user *can* fix.

According to the [Link: Google Test tutorial], it said to prepare `WORKSPACE`:
```txt
load("@bazel_tools//tools/build_defs/repo:http.bzl", "http_archive")

http_archive(
  name = "com_google_googletest",
  urls = ["[URL]
  strip_prefix = "googletest- ",
)
```

This produces:
```txt
INFO: SHA256 (https://github.com/google/googletest/archive/ .zip) =         
DEBUG: Rule 'com_google_googletest' indicated that a canonical reproducible form can be obtained by modifying arguments sha256 = " "
DEBUG: Repository com_google_googletest instantiated at:
  C:/users/XXXX/WORKSPACE:3:13: in  
Repository rule http_archive defined at:
  C:/users/XXXX/mrkfkorq/external/bazel_tools/tools/build_defs/repo/http.bzl:336:31: in  
```

According to `DEBUG` message, I add `sha256` property in the `WORKSPACE` like:
```
txt
load("@bazel_tools//tools/build_defs/repo:http.bzl", "http_archive")

http_archive(
  name = "com_google_googletest",
... [Log Snipped] ...
  sha256 = " ",
)
```

To do this, "a canonical reproducible form can be obtained by modifying arguments sha256 = ..." messages dissapeared.
