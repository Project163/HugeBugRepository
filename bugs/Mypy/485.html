Title

Daemon should not strip anything that was never analyzed

Description
Consider this test case:
```
[case testIfMypyClass]
from a import x

MYPY = False
if MYPY:
... [Log Snipped] ...
[out]
==
```
It crashes with a traceback ending in
```
/Users/ilevkivskyi/src/mypy/mypy/server/aststrip.py:88: in visit_class_def
    self.strip_type_info(node.info)
/Users/ilevkivskyi/src/mypy/mypy/server/aststrip.py:101: in strip_type_info
    info.add_type_vars()
/Users/ilevkivskyi/src/mypy/mypy/nodes.py:2452: in __getattribute__
    raise AssertionError(object.__getattribute__(self, 'msg'))
AssertionError: ClassDef is lacking info
```
The cause is quite obvious (see topic). The danger here is that there are probably other similar crashes with other non-trivial constructs in unreachable branches, so I think this is high priority. Also this already causes problems in some internal codebases.

@msullivan this is actually a _positive_ effect of a change you made recently, it is better to see this rather than `NoneType has no blah-blah`.
