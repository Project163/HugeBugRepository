Title

Bazel binary got much bigger

Description
### Description of the problem / feature request:

With commit  , the Bazel binary's size increased from ~110M to ~170M, and the number of files in the embedded_tools increased from 509 to 4780.

The bigger size means higher download time, but also slower Bazel startup.

The higher number of embedded tools means slower Bazel startup, especially on Windows where I/O is typically expensive.

### Bugs: what's the simplest, easiest way to reproduce this bug? Please provide a minimal example if possible.

Build Bazel at   and at   (the commit before).

Compare the binary sizes:

```
stat bazel-bin/src/bazel
```

Compare the number of embedded tools:
```
find $(bazel-bin/src/bazel --output_user_root=/tmp/bzl/$RANDOM info install_base) -type f | wc -l
```
