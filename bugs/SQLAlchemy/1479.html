Title

need to somehow back-off subtype checks in strategy options to suit the selectin_polymorphic() subclass load case

Description
we document this pattern:

[URL]

```
py
from sqlalchemy.orm import selectinload
from sqlalchemy.orm import selectin_polymorphic
stmt = (
    select(Employee)

What's awkward there is we are allowing `selectinload(Manager.paperwork)` to exist in a query that's against `Employee`.

Trying to do this for any kind of pathing obviously fails:

```py
stmt = select(Company).options(
    selectinload(Company.employees).options(
            selectin_polymorphic(Employee, [Manager]),
            selectinload(Manager.paperwork)
    ),

)

```

and

```py
stmt = select(Company).options(
    selectinload(Company.employees).selectin_polymorphic(Employee, [Manager]),
    selectinload(Company.employees).selectinload(Manager.paperwork)
)

```

with, as expected:

```
sqlalchemy.exc.ArgumentError: ORM mapped entity or attribute "Manager.paperwork" does not link from relationship "Company.employees".  Did you mean to use "Company.employees.of_type(Manager)"?

```

that's an important error.  We need to raise that, that's a major path people need to know about.  However, it means our documented pattern is broken.
