Title

Reactive ContainerResponseFilter throws NPE

Description
## Describe the bug
When a ContainerResponseFilter is active in a reactive rest application,
and we try to use `getResourceMethod()` on the `ResourceInfo` object,
NullPointerException is observed. Also, the filter doesn't seem to be invoked at all on some endpoints.


### Expected behavior
Should not throw NPE

### Actual behavior
NPE is thrown.

- The use-case is primarily to set custom headers in responses, streaming and non-streaming.
This can indeed be achieved through `ResteasyReactiveContainerRequestFilter.getServerRequestContext().serverResponse().addResponseHeader` and it's is by no means a blocking issue for me, but since it's not very intuitive to use a request filter to add something to the response and also because the filter semantics was different in streaming and non-streaming endpoints I figured the response filter probably wasn't working as intended.

Obviously there are some methods in ContainerResponseContext that will never not work in a streaming response, so I totally get that a response filter can not work 100% the same for streaming and non streaming responses.
- @TomasHofman's analysis is spot on.

However RESTEasy Reactive should certainly not be throwing a NPE. [URL] takes care of that
