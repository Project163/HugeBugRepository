Title

Same route anchor links only fire once when a hash link is preloaded with `data-sveltekit-preload-data`

Description
### Describe the bug

Clicking a link that goes to an anchor on the page works but after you remove the anchor via the page store the link no longer works.

The use case i had was using anchors for modals, modal opens on anchor link and anchor link is removed on modal close.

I have a hash based example, and a querystring based example, and the qs based example typically works fine.
- I don't think the issue is tied to the page store. It stems from the `data-sveltekit-preload-data` attribute preload causing the router to think we've already navigated to the anchor, thus doing nothing when we click on the same anchor.

The `preload` method gets called when hovering over the link, updating our `current.url` to the anchor before we even click the link.

[URL]

When we first navigate to `/#hello`, we're caching the url `/#hello` under the id `/` while hovering over the link. After we navigate, the caching usually triggers again as we move the mouse away.
[URL]
[URL]

When we navigate back to `/`, the cache id matches and the wrong navigation result is returned

[URL]

so `current.url` is set to `/#hello` instead of `/`.

[URL]

Similarly, the `$page.url` store gets out of sync because `current.url` is incorrect.
