Title

ValidationModelRetriever does not correctly evaluate "applicable path"

Description
Currently in  [URL] there is a PatriciaTrie from Apache Commons Collections being used to figure out the validation model bound to a specific resource with the most specific applicable path which still matches. 

 This does not work as the method  PatriciaTrie.subMap  returns all keys which are less than the given path according to lexicographical ordering. 

 That means, in case the trie would contain entries for "/", and "/a/b", a lookup for "/a/c" would return "/a/b" although the latter does not start with the former.
