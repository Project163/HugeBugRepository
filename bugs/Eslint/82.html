Title

no-comma-dangle rule reports wrong line number

Description
eslint 0.4.4 on

```
var a = {
  method: function() {

  },
};
```

reports

```
  2:2   error  Trailing comma                  no-comma-dangle
```

While I would expect it to report 4th line for having a trailing comma.
Discussion
- The line of the property that has the trailing comma is being reported. I think this brings up a bigger question about also providing ranges with reports from rules. Not all rules look for structural problems. For those, we should be able to report a character index range instead. And even for some rules that look for structural problems, often only a portion of that node is responsible for the actual error. For instance, when reporting on an improperly wrapped IIFE, the entire CallExpression is reported instead of just the location of the misplaced `)`. @nzakas: Do you think we should allow `context.report` to accept a range and make the `node` optional?
- The node is important for getting more info about the location. However, we do have an optional argument that allows overriding the reported line and column. It seems like that would be the solution here.

```
            context.report(lastItem, secondToLastToken.loc.start, "Trailing comma.");
```
