Title

Rclone hangs during restic restore

Description
#### What is the problem you are having with rclone?

Rclone hangs when paired with restic.

#### What is your rclone version (output from `rclone version`)

rclone v1.51.0-042-g219bd97e-beta (stable also hangs the same way)

#### Which OS you are using and how many bits (eg Windows 7, 64 bit)

Linux leto 4.19.0-8-amd64 #1 SMP Debian 4.19.98-1 (2020-01-26) x86_64 GNU/Linux

####  Which cloud storage system are you using? (eg Google Drive)

FTP

#### The command you were trying to run (eg `rclone copy /tmp remote:tmp`)

`restic -r rclone:ftp:docker -p rpw restore latest -t tmp -i docker/admin`

#### A log from the command with the `-vv` flag (eg output from `rclone -vv copy /tmp remote:tmp`)

```
repository bb5ecaf2 opened successfully, password is correct
restoring   to tmp
```
And it hangs there forever.

After sending -quit from another console:

```
rclone: SIGQUIT: quit
rclone: PC=  m=0 sigcode=0
rclone:
rclone: goroutine 0 [idle]:
rclone: runtime.futex( , 0x80, 0x0, 0x0, 0x0,  , 0x0, 0x0,  ,  , ...)
... [Log Snipped] ...
rclone: fs     0x0
rclone: gs     0x0
```
Discussion
- This bit makes me think that rclone has run out of simultaneous FTP connections.

Try setting the `concurrency` higher in the backend config.
- I have concurrency set to 3, because it's the max that OVH allows on their free FTP backup services. I had set to 0 before and I was getting many "too much connections" errors.

I set it to 1 now, just for funzies, but there was no visible changes. It hanged in the same spot.
