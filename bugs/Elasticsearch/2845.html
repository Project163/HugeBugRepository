Title

[HealthAPI] Disk indicator details node counts are not consistent with impacts/diagnosis counts

Description
### Elasticsearch Version

8.5, 8.6

### Installed Plugins

_No response_

### Java Version

_bundled_

### OS Version

Darwin

### Problem Description

The details section of the disk indicator displays the number of green, yellow, red, unknown nodes.
This computation is based on the values seen by the health node. The rest of the indicator information (summary, impacts, diagnosis) is based on the values seen by the health node filtered to only take into account the nodes that the health request coordinating node is aware of in the local cluster state. 
This can create a discrepancy where the details counts add up to more nodes than the nodes reported in the other sections of the disk indicator.

This can happen if:
1. the health API coordinating node hasn't heard yet of the new cluster membership, but the health node received a health status from a new node
2. the health API coordinating node has the latest cluster membership but the coordinating node already received the health cache overview using the previous membership configuration

### Steps to Reproduce

This is rather tricky to reproduce, but a cluster where the master (which is also a data node) runs out of disk can produce a health API output illustrating this issue: 
```
"disk": {
      "status": "red",
      "symptom": "0 nodes with roles: [] are out of disk or running low on disk space.",
      "details": {
        "blocked_indices": 0,
... [Log Snipped] ...
      }
    },
```
