Title

Register Picocli completion candidates for reflection

Description
## Describe the bug

```
@Command(name = "mycommand")
public class DescribeConnectorCommand implements Runnable {

    @Parameters(paramLabel = "SOME PARAM", completionCandidates = ConnectorCompletions.class)
    String name;
... [Log Snipped] ...
    private static class ConnectorCompletions implements Iterable  { ... }
}
```

When building a native Picocli app that uses completion candidates, the constructor of the completions `Iterable` isn't registered for reflection, resulting in this exception:

```
java.lang.NoSuchMethodException: dev.morling.kccli.command.DescribeConnectorCommand$ConnectorCompletions. ()
	at java.lang.Class.getConstructor0(DynamicHub.java:3349)
	at java.lang.Class.getDeclaredConstructor(DynamicHub.java:2553)
	at picocli.CommandLine$DefaultFactory.create(CommandLine.java:5489)
	at io.quarkus.picocli.runtime.PicocliBeansFactory.create(PicocliBeansFactory.java:16)
... [Log Snipped] ...
	at io.quarkus.runtime.Quarkus.run(Quarkus.java:42)
	at io.quarkus.runner.GeneratedMain.main(GeneratedMain.zig:30)
```

### Expected behavior
Can use completions in native Picocli binary.

### Actual behavior
Exception above.

## To Reproduce
Declare a command like above, then build with -Pnative.
