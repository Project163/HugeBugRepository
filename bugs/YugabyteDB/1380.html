Title

[DocDB] Column id is still incremented on ADD COLUMN rollback - breaks ddl replication

Description
Jira Link: [Link: DB-15076]
### Description

When we fail the add column command and rollback, we don't rollback the last used column id. This results in the column id continuing to increment.

For xCluster DDL Replication, this breaks replication as we cannot guarantee that each side will have the same column id when performing an ADD COLUMN. 

Proposed Fix: Do not increment column id on failed ADD COLUMN operations.

**Version**: ` -b245`

**Steps**:
1. Create database and tables at both sides and setup DR replication from source to target
2. Run `SET yb_test_fail_next_ddl TO true;` at source and run `ALTER TABLE ADD COLUMN` DDL (ex: `alter table t1 add column c2 int;`)
3. It fails, run again and check the replication -- it works
4. Load some data to table and check the replication

**Noticed**:
1. DDL replication happens but data replication to the altered column is not happening, 
Source:
```
 select * from t1;
 id | name | age | c1 | c2 
----+------+-----+----+----
  1 | a    |   1 |  1 |  1
  2 | b    |   1 |  1 |  1
```
Target:
```
select * from t1;
 id | name | age | c1 | c2 
----+------+-----+----+----
  1 | a    |   1 |  1 |   
  2 | b    |   1 |  1 |   
```
