Title

Meta service adds tags twice (once for / and once for the current route)

## Current behavior
I am using Meta service right now in an Angular 4 Universal application. So I add a few meta tags on the home component (route /) and the same ones with different values on another page (some route /abc). Now if I go to route /, i only see the meta tags for that page, but if i go to any other route, I see the meta tags for route / followed by css styles, followed by meta tags for the page I am currently on. This is on server side and client side both.

I have tried using forceCreation, updateTags and every other thing possible. Unable to solve. 

## Expected behavior
Meta tags should only be shown for current page.

## Minimal reproduction of the problem with instructions
Try this out on [URL] View page source for the landing page and then navigate to workshops and view page source for that. See the 2 blocks of meta tags with different values.

## What is the motivation / use case for changing the behavior?
Since the meta tags for the / route appear first, they override the actual page's meta tags. This breaks previews and other such functionality

Well, I went ahead and investigated and found the problem. The server side rendered view for index.html (the one used for template engine) already has the   tags from the app-root while it should only have those meta tags which are explicitly in the index.html. This happens for any element created in the head region. The workaround was to change the prerender code to remove these extra meta tags as follows. This also repros with Renderer. So its not just a Meta Service issue but a deeper issue.

Look at the html.replace part. That's the workaround.

renderModuleFactory(AppServerModuleNgFactory, {
  document: index,
  url: '/',
  extraProviders: [
    provideModuleMap(LAZY_MODULE_MAP)
  ]
})
.then(html => writeFileSync(join('browser', 'index.html'), html.replace(new RegExp(' ', 'g'), '').replace(new RegExp(' ', 'g'), '').replace(new RegExp(' ', 'g'), '')));
