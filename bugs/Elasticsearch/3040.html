Title

Fix leaking log-level set on root logger in LoggerTests

Description
### CI Link

[URL]

### Repro line

./gradlew ':server:test' --tests "org.elasticsearch.snapshots.SnapshotResiliencyTests*" -Druntime.java=21  -Dtests.es.logger.level=DEBUG

### Does it reproduce?

Yes

### Applicable branches

main

### Failure history

_No response_

### Failure excerpt

```org.elasticsearch.snapshots.SnapshotResiliencyTests > testIllegalArgumentExceptionLogging FAILED
    java.lang.AssertionError: expected to see INFO log but did not
    Expected:  
         but: was  
        at __randomizedtesting.SeedInfo.seed([ : ]:0)
        at org.hamcrest.MatcherAssert.assertThat(MatcherAssert.java:18)
        at org.elasticsearch.test.MockLogAppender$SeenEventExpectation.assertMatched(MockLogAppender.java:127)
```

The following 4 tests started failing yesterday in `SnapshotResiliencyTests` due to an incorrectly set log-level.  
```
Tests with failures:
 - org.elasticsearch.snapshots.SnapshotResiliencyTests.testIndexNotFoundExceptionLogging
 - org.elasticsearch.snapshots.SnapshotResiliencyTests.testFullSnapshotUnassignedShards
 - org.elasticsearch.snapshots.SnapshotResiliencyTests.testIllegalArgumentExceptionLogging
 - org.elasticsearch.snapshots.SnapshotResiliencyTests.testSnapshotNameAlreadyInUseExceptionLogging
 ```

 It seems that in this [Link: PR] we updated the log-level of the[Link: root logger] as part of the tests, so if it happens that the `SnapshotResiliencyTests` are executed **after** the `LoggersTests`, the log-level for the `SnapshotsService` logger will be set to debug causing the failures above.  

We should probably reset the log-level after the tests, as we do in `InternalEngineTests#testMergeThreadLogging`  for example
Discussion
- Pinging @elastic/es-core-infra (Team:Core/Infra)
- There is already a fix for the tests in the description in this [Link: PR], but this could potentially manifest in other tests as well.
