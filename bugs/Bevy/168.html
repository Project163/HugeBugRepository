Title

Bevy has implicit dependency on `anyhow` which users need to explicitly add

Description
## Bevy version

Both 0.5 and `main`

## Operating system & version

Windows 10 (likely irrelevant)

## What you did

- Copy [Link: the `custom_asset.rs` example code] into my app

## What you expected to happen

Code builds.

## What actually happened

Code doesn't build because it depends on `anyhow::Result` and `anyhow::Error`.

## Additional information

The examples are built with:

```toml
[dev-dependencies]
anyhow = "1.0.4"
```

which is why they build successfully. This means Bevy is implicitly asking users to add this dependency to their project if they want to implement the `AssetLoader` trait, whose `load()` function returns `anyhow::Result >`.

We discussed this briefly with @alice-i-cecile [Link: on Discord] and I believe that there are two possible ways to fix:

1. Acknowledge that this is by design, and Bevy does want you to add those dependencies. If so, this needs to be documented.
2. Consider this a bug, and investigate workarounds like re-exporting the `anyhow` dependency (see rust-lang's issue [Link: Guidance on reexporting] for details) so that Bevy users don't have to do it. Or alternatively define public aliases for those types which I _think_ would solve this too. In any case, I believe the `dev-dependencies` section is not to be used for this kind of thing, but rather for dependencies used by the example itself (as opposed to by Bevy via the example).

I have a strong preference for anything except 1. as this feels awkward and cumbersome.
