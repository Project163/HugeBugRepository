Title

BUG: Partial slicing of unordered datetimeindex inconsistent between providing start and end points

Description
### Pandas version checks

- [X] I have checked that this issue has not already been reported.

- [Link: X] I have confirmed this bug exists on the [latest version] of pandas.

- [Link: X] I have confirmed this bug exists on the [main branch] of pandas.

### Reproducible Example

```python
import pandas as pd
s = pd.Series([1, 2, 3], index=pd.Series(["2001", "2009", "2002"], dtype="datetime64[ns]"))
s.loc["1999":] # KeyError
s.loc[:"1999"] # Empty series
```

### Issue Description

#37819 deprecated (and #49607 removed) support for looking up by slice in an unordered datetime index when the slice bounds are not in the index. This made datetime indexes behave more like other indexes when they are unordered.

My reading of those issues _suggests_ that the intended behaviour is that asking for a slice where either (or both) of the start or end points are not in the index should raise a `KeyError`. However, it is only when the start point is not in the index that a `KeyError` is raised.

### Expected Behavior

I would anticipate that this is symmetric. cc @phofl who introduced the logic for these deprecations.

Discussion
- Thanks for your report. This certainly looks inconsistent. Investigations are welcome!
- What is the intended behaviour? If either endpoint is not in the index, then a keyerror should be returned?

There are, AFAICT, a number of problems with the logic here:
```
python
        mask = np.array(True)
        raise_mask = np.array(True)
        if start is not None:
            start_casted = self._maybe_cast_slice_bound(start, "left")
... [Log Snipped] ...
                "with non-existing keys is not allowed.",
            )
```

Let's work through the possible cases:

1. `start` is None, `end` is not None (and not in the index)
    `raise_mask` is initialised to True, but True is not a neutral element for `|`, so if `start` is None, then `raise_mask` always evaluates to `True`, and its negation is `False`, so we don't raise.
2. `start` is not None (and not in the index), `end` is None
    `raise_mask` is all False, and its negation is `True` (so we raise).
3. `start` is not None (and not in the index), `end` is not None (and not the index)
    `raise_mask` is initialised to all False, and ored with another array that is all False, so its negation is True and we raise.
4. `start` is not None (and not in the index), `end` is not None and _in_ the index
    `raise_mask` is all False, is ored with an array with one True value, so `any` produces `True` and its negation is False, so we don't raise.
5. `start` is not None (and _in_ the index), `end` is not None and _not_ in the index
    `raise_mask` has at least one True entry, is ored with all False, so `any` produces `True`, so we don't raise.

I think one should be checking that both the start and end points are in the index independently, perhaps like so:
```
diff
diff --git a/pandas/core/indexes/datetimes.py b/pandas/core/indexes/datetimes.py
index 1500bcef5d..95a6e4a9a2 100644
--- a/pandas/core/indexes/datetimes.py
+++ b/pandas/core/indexes/datetimes.py
... [Log Snipped] ...
                 "Value based partial slicing on non-monotonic DatetimeIndexes "
                 "with non-existing keys is not allowed.",
```

This might, however, have some unintuitive-seeming behaviour. Since the right slice bound is cast "up", one needs to provide much more precision than it looks like to actually pull something out of the index:

```
python
print(s)
# 2001-01-01    1
# 2009-01-01    2
# 2002-01-01    3
... [Log Snipped] ...
s.loc[:"2002-01-01 00:00:00"] # KeyError
s.loc[:"2002-01-01 00:00:00.000000000"] # works
```
- The only failing test with that patch is `tests/indexing/test_partial.py::TestStringSlicing::test_slice_irregular_datetime_index_with_nan`, but IIUC this is a use-case that should have been explicitly prohibited by #49607
