Title

bin/activemq sets ACTIVEMQ_CLASSPATH to likely non-existing directory $ACTIVEMQ_BASE/../lib

Description
the bin/activemq script executes these lines by default (i.e. when none of the relevant environment variables are set): 
  
 
  ACTIVEMQ_HOME= "`getActiveMQHome`" 
  ACTIVEMQ_BASE= "$ACTIVEMQ_HOME" 
ACTIVEMQ_CLASSPATH= "$ACTIVEMQ_BASE/../lib/:$ACTIVEMQ_USER_CLASSPATH" 
 
  
 getActiveMQHome returns (effectively) the parent directory of the  bin  subdirectory, i.e., the root of the distribution tar file, so ACTIVEMQ_CLASSPATH ends up set to the a  lib  subdirectory which may or may not exist in the path where  the user decided  to extract the distribution tar file. 

 Meanwhile the  lib  subdirectory of the distribution ($ACTIVEMQ_BASE/lib) does not seem to be referenced anywhere in the script. 

 ActiveMQ does not seem to have any problem with that, though, so maybe this setting is not so important.
Discussion
- What's your point here ? If you extract ActiveMQ in different location (not ActiveMQ "standard"), you have to update  bin/activemq . Thoughts ?
- My point is, the intention appears to be to add $ACTIVEMQ_BASE/lib to the class path, and not $ACTIVEMQ_BASE/  ../   l   ib which in all likelihood does not exist. 

 As far as I can tell, there is no "ActiveMQ standard", at least not according to the "Getting Started" guide, which states "Extract the files from the zipped tarball into a directory of your choice". So I'm free to extract the tarball into an empty directory, say "/apps". Thus I'd get  /apps/apache-activemq-5.16.0  with subdirectories  bin ,  lib , and so on. Then running  
  
 
/apps/apache-activemq-5.16.0/bin/activemq
 
  
 would result in the directory 

 /apps/lib 

 being added to ACTIVEMQ_CLASSPATH. Since my /apps was initially empty, the directory  /apps/lib  would not exist. At the same time, the directory /apps/apache-activemq-5.16.0/lib would  not  get added to ACTIVEMQ_CLASSPATH (I don't know it it should, though, even though it contains quite a lot of JARs).
