Discussion
- Confirmed in online demo. Seems like a bug.

As I mentioned in the other issue, I think the special check for `ObjectExpression` needs to be expanded to also check `MemberExpression` with its `object` node having a type of `ObjectExpression`.
- `() => ({}.a.b)` would be two nested `MemberExpressions`, so we'd have to do some sort of recursion. Would it be better, instead of checking node types that we know begin with `{`, to just check for a `{` token immediately following the `(`? Checking tokens seems like it might be a more direct solution.
