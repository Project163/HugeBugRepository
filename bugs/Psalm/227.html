Title

Union types in @method annotations

Description
I've just encountered `@method returnType methodName(A|B $param)` annotation used in a popular project ([Link: Guzzle HTTP Client]). While it's non-standard (non-PSR5 I mean), PHPStan seems to allow it (https://phpstan.org/r/ ). Psalm, on the other hand, rejects it:
[URL]

I suspect this was unintended omission from the PSR-5 draft. Would be great to see it supported in Psalm (and, eventually, in PSR-5 or whatever comes to replace it).
Discussion
- Yeah, this is slightly cumbersome on Psalm's end - I use PHPParser for those `@method` annotations, and PHPParser obviously doesn't accept union types.

The likely fix will be to add some sort of hacky placeholder (so `A|B` becomes  `A__UNIONOR__B`) so that PHPParser will parse without issue.
- And thanks for opening this - I noticed yesterday, after adding PHP Parser 4.0.2 compatibility.
- Also I suspect the error handling is a bit off in this case: I'd expect psalm to consider those invalid 'virtual' methods non-existing (and do not complain unless the class is sealed), but psalm was insisting `Guzzle\Client::post()` accepts 0 arguments - so it apparently was aware of the method, even though docblock was invalid.
