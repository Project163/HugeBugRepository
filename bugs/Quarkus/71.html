Title

Adding @Gauge annotated method in ApplicationScoped bean causing error in bean instantation

Description
When I tried to add `@Gauge` metric to my app, it failed to start with 

```
Caused by: java.lang.NoSuchMethodError: WorkerProvider_Bean: method  ()V not found
	at io.quarkus.arc.setup.Default_ComponentsProvider.getComponents(Unknown Source)
	at io.quarkus.arc.ArcContainerImpl. (ArcContainerImpl.java:95)
	at io.quarkus.arc.Arc.initialize(Arc.java:34)
	at io.quarkus.arc.runtime.ArcDeploymentTemplate.getContainer(ArcDeploymentTemplate.java:43)
	at io.quarkus.deployment.steps.ArcAnnotationProcessor$build5.deploy(Unknown Source)
````

But this class definetly have a no-args constructor

When I remove `@Gauge` annotated method application starts without any issue
Discussion
- I can reproduce this, it's actually very simple to do so. Simply create a project with the maven plugin, add the `quarkus-smallrye-metrics` dependency and annotation the method of the `hello` method with `@Gauge`.

Note that things work as expected when `@Timed` or `@Counted` are used instead of `@Gauge`.

I believe that the root case is the fact that the `@Gauge` annotation is not meta-annotated with `@Inherited` - which causes Arc to not include it as part the `BeanDeployment`'s `interceptorBindings` (both `@Timed` and `@Counted` are properly meta-annotated with `@Inherited`). 

@kenfinnigan @jmartisk do you have further insights on this?
- The problem occurs if you have a bean (it doesn't need to be ApplicationScoped) which contains a `@Gauge` as the only metrics annotation. If you add any other metric annotation (like `@Counted`) anywhere in the class, it will start working. This can be used as a workaround.

I think the problem stems from the fact that adding a `@Gauge` annotation binds a `MetricInterceptor` to only the constructor of the bean that contains it, and `ComponentsProviderGenerator` contains a check for an empty list of `interceptedMethods` which stays empty if only the constructor is being intercepted (if you add any other metric annotation on a method, that method will become intercepted so the list will not be empty). The check should not ignore beans which have only their constructor intercepted.
