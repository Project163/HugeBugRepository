Title

Ignoring unloaded classes

Description
Android can unload and reload classes. Currently the LeakCanary heap dump parser assumes there's only one class object for each class. Unfortunately we've found cases where there are two objects for the same class, one of which referencing instances that cannot be found, leading to crashes.

Possible approaches:

* Only keep classes referenced by sticky class GC Roots. On Android all classes currently loaded are held by sticky class gc roots, any other class can be ignored. However that's not true for JVMs.
* Only keep reachable classes. Most correct option, however that would require a full tree traversal (ala mark and sweep) which is expansive.
* Eliminate objects that reference unknown objects. There's no guarantee that unloaded classes reference unknown objects.
