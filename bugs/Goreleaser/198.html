Title

Homebrew Manifests Broken in GitLab, Incorrect {{ .ArtifactUploadHash }}

Description
**Describe the bug**

Ever since a few weeks ago, whenever Goreleaser generates a Homebrew manifest, the URIs don't work. Here's what the manifest looks like:

```
ruby
# This file was generated by GoReleaser. DO NOT EDIT.
class Verifpal < Formula
  desc "Cryptographic protocol analysis for students and engineers."
  homepage "[URL]
... [Log Snipped] ...
  end
end
```

The problem lies in the `uploads//` part of the URI. Clearly, an element between the first and second slash (referred to in the Goreleaser templating logic as `{{ .ArtifactUploadHash }}`)in the aforementioned string is missing. If we go to the GitLab releases page, we can check out the full links generated by GitLab and thereby recover these missing elements, for example, `[URL]

Replacing the above URIs with their correct counterparts fixes the issue, and Homebrew works correctly again for install and update procedures:

```
ruby
# This file was generated by GoReleaser. DO NOT EDIT.
class Verifpal < Formula
  desc "Cryptographic protocol analysis for students and engineers."
  homepage "[URL]
... [Log Snipped] ...
  end
end
```


**To Reproduce**

Here is our Goreleaser confg file:

```
yaml
project_name: verifpal

gitlab_urls:
  api: [URL]
... [Log Snipped] ...
"Cryptographic protocol analysis for students and engineers."
  license: "[URL]
```

**Expected behavior**

Homebrew URIs correctly include `{{ .ArtifactUploadHash }}` correctly.

**Environment (please complete the following information):**

- OS version: `Linux localhost 5.4.10-x86_64-linode132 #1 SMP PREEMPT Thu Jan 9 21:17:12 UTC 2020 x86_64 GNU/Linux`
- GoReleaser Version: `0.132.1`
- GitLab version: `12.10.1-ee (695c29abcf7)`
