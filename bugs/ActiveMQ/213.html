Title

Activemq connection factory silently ignores the erroneous arguments in broker url

Description
When an erroneous argument is passed to the broker url with failover, activemq connection factory ignores the error. However if failover is removed, it does throw exception.  

 Here is the example 

 1. failover:(tcp://localhost:62012)?jms.prefetchPolicy.all=10&wireFormat.maxInactivityDuration=0&jms.optimizeAcknowledge=false 

 2. tcp://localhost:62012?jms.prefetchPolicy.all=10&wireFormat.maxInactivityDuration=0&jms.optimizeAcknowledge=false 

 Only the # 2 throws exception as jms.prefetchPolicy.all is an invalid argument here

 Though it should be noted that errors within the transport list is ignored. i.e. failover:(tcp://localhost:61616?cheese=abc) will not be flagged as erroneous because the tcp part is configured during actual connection only. Any exceptions during connection in failover will result in the transport trying to reconnect. In this case unless the failover transport is configured to fail after n retries it will hang. I'm not sure if this is a serious bug or an expected side effect.
