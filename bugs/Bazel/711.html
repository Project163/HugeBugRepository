Title

Repository error messages are hard to understand

Description
ERROR: .../envoy/bazel/repositories.bzl:534:5: no such package '@com_google_protobuf_cc//': java.io.IOException: Error downloading [https://github.com/protocolbuffers/protobuf/archive/ .tar.gz] to .../ /external/com_google_protobuf_cc/ .tar.gz: Unknown host: github.com and referenced by '//external:protoc'

This error message has proved difficult to parse for people who aren't intimately familiar with bazel's internals. It's a series of stacked exceptions and causes, which leads users in the wrong direction.

The initial line number reference is to [URL] which is the place where com_google_protobuf_cc is used.

Initially, you have to understand the relatively obscure native.bind construct to see that this is just a use site. Then you have to determine which parts of the exception are really about the definition of this repository, and then you have to go hunt down where that repository is really defined, which the error doesn't tell you about at all.

The "and referenced by '//external:protoc'" part on the end is a complete distraction which doesn't help at all.

What I would like to have seen here is:

ERROR: .../envoy/bazel/repositories.bzl:518:5: Error downloading [https://github.com/protocolbuffers/protobuf/archive/ .tar.gz] to .../ /external/com_google_protobuf_cc/ .tar.gz: Unknown host: github.com
.../envoy/bazel/repositories.bzl:534:5: @com_google_protobuf_cc referenced from here

The situation is worse when there is a chain of dependencies involved (where needing to fetch one repo led to needing to download another, which fails) as it will accumulate errors from each of them in turn, and the user must track down exactly what happened. The exception which is the cause of the problem will be buried somewhere in the middle of a stack of messages which are really just trying to be a list of references.
