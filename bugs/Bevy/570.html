Title

trait bound error when nesting Reflect types in a HashMap inside another Reflect type

Description
Having a HashMap with a Reflect type as the key inside another Reflect type produces this error:

```
error[E0277]: the trait bound `std::collections::HashMap : bevy::prelude::Reflect` is not satisfied
 --> examples/hello_world.rs:9:19
  |
9 | #[derive(Default, Reflect)]
  |                   ^^^^^^^ the trait `bevy::prelude::Reflect` is not implemented for `std::collections::HashMap `
... [Log Snipped] ...
  = note: required for the cast to the object type `dyn bevy::prelude::Reflect`
  = note: this error originates in a derive macro (in Nightly builds, run with -Z macro-backtrace for more info)
```

**Bevy version**
9239621f

**Operating system & version**

Arch Linux

**What you did**


This example demonstrates the error:
```
use std::collections::HashMap;
 use bevy::prelude::*;
 use serde::{Serialize, Deserialize};

 fn main() {
... [Log Snipped] ...
     Two,
 }
```

**What you expected to happen**

I expect to be able to nest Reflect structs inside other Reflect structs, even if there's a collection involved.

**What actually happened**

Doesn't compile
Discussion
- Looking into this a bit more, there is an implementation for `bevy_utils::HashMap` but not for `std::collections::HashMap`. The difference is that `bevy_utils::HashMap` is `pub type HashMap  = std::collections::HashMap ;`

@cart mentioned on discord that he expected this to work, but is the expectation that it work with the vanilla std HashMap or only with the tweaked bevy_utils::HashMap?
- After making the required mechanical translations, this now runs successfully in 0.16, so I think this issue is resolved.

@MrGVSV could I get a quick check that I've not just misunderstood something here?

```
use std::collections::HashMap;
 use bevy::prelude::*;
 use serde::{Serialize, Deserialize};

 fn main() {
... [Log Snipped] ...
     Two,
 }
```
- I tested this as well and it compiles with 0.17.
