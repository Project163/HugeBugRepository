Title

Doesn't correctly validate when type is Enum

Description
# Bug

Output of `python -c "import pydantic.utils; print(pydantic.utils.version_info())"`:
```
             pydantic version: 1.5.1
            pydantic compiled: True
                 install path: /Users/ /.venvs/ /lib/python3.6/site-packages/pydantic
               python version: 3.6.5 (v3.6.5:f59c0932b4, Mar 28 2018, 03:03:55)  [GCC 4.2.1 (Apple Inc. build 5666) (dot 3)]
                     platform: Darwin-18.7.0-x86_64-i386-64bit
     optional deps. installed: []
```
Type validation works as expected when using children of Enums (e.g., [Link: here]) but not when using Enums themselves.

```
py
from enum import Enum

from pydantic import BaseModel

... [Log Snipped] ...
      value is not a valid enumeration member; permitted:  (type=type_error.enum; enum_values=[])
    """
```
My expectation is that both should validate correctly, since `FruitEnum` is an instance of `Enum`.
Discussion
- To be clear, I understand why there is a need for the type of validation that is currently provided: [Link: ensuring that an argument is one of the authorized values in a given enum].

But there is also a need to be able to check that an argument is an instance of `Enum`, without caring about what the keys and values of that `Enum` are.
- Hi @zabzug-pfpt 
I agree with you it should be a valid syntax. I opened a PR to add a basic support of `Enum` as valid type.
Feel free to try it out.
- ... [Middle Discussions Snipped for Brevity] ...
- This is not the exact scenario in the issue, but there is still a problem in the case where there is a middle class inheriting from enum without specifying values. If you have something like

```
python
class SpecialEnum(Enum):
    def do_stuff(self):
         # some cool operation

... [Log Snipped] ...
class MyModel(BaseModel):
    my_field: SpecialEnum
```
then
```python
MyModel(my_field=MySpecialEnum.A)
```
Will throw a `ValidationError`.

I want pydantic to validate that my_field is some instance of a SpecialEnum subclass.
However, pydantic uses its enum member validator instead, resulting in what will always be a `ValidationError` — since SpecialEnum was only ever meant to provide functionality or interface, and not values.
- Let's look at getting this right in v2. We can't change it before then.
