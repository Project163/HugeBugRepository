Title

need to distinguish superclass dc fields that are already mapped vs. ones that arent

Description
### Discussed in [URL]

issue as shown 

```
py
import dataclasses
from typing import Any, Dict, Optional

from sqlalchemy import ForeignKey, Identity, Integer, String, orm
... [Log Snipped] ...
    )
Mapped[Optional[str]]
```

the "polymorphic_type" field is getting copied to Novel without actually having any dataclass field, therefore init=True, due to how we grab elements and put them in annotations.

I've tried some various "correct" ways to make this work but have not figured it out yet.  The basic end result we want however can be achieved via the patch below:

```
diff
diff --git a/lib/sqlalchemy/orm/decl_base.py b/lib/sqlalchemy/orm/decl_base.py
index a858f12cb9..3d0aad7ccc 100644
--- a/lib/sqlalchemy/orm/decl_base.py
+++ b/lib/sqlalchemy/orm/decl_base.py
... [Log Snipped] ...
         ]
         annotations = {}
```

so when we do the collect annotations, we need to look at the field and see if this is already mapped in some more legit way, likely not even collect the annotation at all.
