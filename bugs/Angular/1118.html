## Current behavior

When there is a route with more than one resolver, empty observables (no next, only complete, as in EmptyObservable) are treated differently than with a single resolver:
- if for example 1 of 2 resolvers resolves to an empty observable, the navigation is not canceled, but the corresponding route-data-field is undefined as result
- if all resolvers resolve to empty observables, navigation is canceled, but due to an uncaught EmptyError, because the combined resolvers are piped through a last() operator

## Expected behavior

- if any resolver resolves to empty, navigation must be canceled, as it is the behaviour for a single resolver
- even if all resolvers resolve to empty, the router should not emit any uncaught errors

## Minimal reproduction of the problem with instructions

1. open: [URL]
2. click the link and observe an uncaught EmptyError in the browser console

the interesting code is in app.module.ts, it configures a route with two resolves that resolve to EMPTY

In our case, we have implemented an error consuming procedure that takes care of any failures during resolver actions (like http errors), thus in case of an error it is important to be able to indicate route cancellation without forwarding an error to the router.

(a) Because if a resolver cannot obtain what it is supposed to obtain, we do not want to navigate, because the destination page would be empty/broken.
