Title

Windows: $ in output_base is breaking paths.

Description
On Windows, trying to build Bazel from head, we are having repeated errors on Windows.

(See [URL] for sample):
```
ERROR: C:/jenkins/workspace/Bazel/JAVA_VERSION/1.8/PLATFORM_NAME/windows-x86_64/src/java_tools/junitrunner/java/com/google/testing/coverage/BUILD:72:1: Executing genrule //src/java_tools/junitrunner/java/com/google/testing/coverage:Jacoco_jarjar failed: bash failed: error executing command C:/tools/msys64/usr/bin/bash -c ... (remaining 1 argument(s) skipped): com.google.devtools.build.lib.shell.BadExitStatusException: Process exited with status 127.
/usr/bin/bash: C:/bazel_ci/temp/_bazel_SYSTEM/enRRqR/execroot/windows-x86_64/bazel-out/host/bin/third_party/java/jarjar/jarjar_bin: No such file or directory
```

The actual output base for the SYSTEM user is:
```
C:\bazel_ci\temp\_bazel_SYSTEM\$7enRRqR
```

The output base shown in this command is:
```
C:/bazel_ci/temp/_bazel_SYSTEM/enRRqR
```

Looks like the $7 is being interpreted by msys2/bash as an environment variable and being removed.
