Title

camel-aws2-sns: duplicate copies of configuration objects lead to undefined behavior

Description
Camel is keeping 2 different instances of the configuration object for the AWS 2 SNS component. Subsequently, changes to the object instances cause both of them to be out of sync leading to undefined behavior depending on each copy is read. 

 The problem flow is: 
 
	 A copy of the configuration object if created when instantiating the endpoint:  [URL]
	 The copy object is then set with additional configuration values, such as the topic and topicArn:  [URL]
	 Then, when trying to set the component properties, the configuration object will be overwritten and the changes on step 2 may be lost:  [URL]
 

   

 Under some circumstances, such as when using a custom configuration object this causes the code to overwrite the object.
