Title

Theming bug using environment vars

Description
### Summary

When configuring colors using environment variables, streamlit returns an error message upon page load.

```
Bad message format
Failed to parse color: "#FFFFFF "
```

It somehow seems to include a space at the end of the color string. However the code snippet below clearly shows there is no space in the environment variable.

### Steps to reproduce

This is the bash file that I used to launch streamlit

```bash
export STREAMLIT_THEME_PRIMARY_COLOR="#EA650E"
export STREAMLIT_THEME_SECONDARY_BACKGROUND_COLOR="#F8F8F8"
export STREAMLIT_THEME_BACKGROUND_COLOR="#FFFFFF"
export STREAMLIT_THEME_TEXT_COLOR="#000000"
export STREAMLIT_THEME_FONT="sans serif"
streamlit run app.py --server.enableWebsocketCompression=false --server.enableXsrfProtection=false &
```

**Expected behavior:**

I expected a working streamlit page with my colors applied

**Actual behavior:**

Received modal with error message upon page load:

```
Bad message format
Failed to parse color: "#FFFFFF "
```

### Is this a regression?

Don't know, have not tried this before

### Debug info

- Streamlit version: 0.80.0
- Python version: 3.7
- Using Conda
- OS version: Ubuntu 20.04
- Browser version: Viewing on Windows 10, Chrome 89.0.4389.114
