Title

no-empty-character-class rule not working well with unicode flag (ES6)

Description
The `no-empty-character-class` rule gives a very confusing error whenever it encounters a regular expression using the ES6 `u` flag. (for unicode support)

To be clear, my regular expression does _not_ have an empty character class, and if I remove the `u` flag, it is not treated as an error anymore.

It looks like this is caused by the fact that the only recognized flags are `gimy`. (see [Link: code]) I presume adding `u` to the list would fix this problem, but not sure if that should be conditionally added with ES6 support.

This is using the latest version of ESLint. (ie: `0.22.1`)
Discussion
- Just another thought, since that rule doesn't really need to care about the flags that are used, there's no reason to deal with adding `u` conditionally. 

**tl;dr** Since the `y` flag isn't standard either, I see no reason to leave out `u`.
- I'll submit a PR that simply adds `u` to that regex.
