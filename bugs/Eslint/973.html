Title

When using func-names = never, allow names for recursive use

Description
**What version of ESLint are you using?** 2.13.0

**What parser (default, Babel-ESLint, etc.) are you using?** default

**Please show your full configuration:** `"func-names": [2, "never"]`

**The problem you want to solve**
I would like to never use function names, because in Mozilla code the names in stacks are guessed pretty well nowadays. There are some cases where I still need them though, namely when referencing the function name within for a recursive call.

Example:

```
javascript
setTimeout(function postpone() {
    let thing = getThing();
    if (!thing) {
        setTimeout(postpone, 0);
... [Log Snipped] ...
    }
}, 0);
```

**Your take on the correct solution to problem.**
I would suggest to add an keyword option `recursive` or similar, setting it to `true` would allow use of function names if referenced from within. The default should be `true`.
Discussion
- Seems reasonable to me.
- Right now `func-names` is either "always" or "never". What about making it "always/recursive/never"? That would be a non-breaking enhancement and avoid a boolean object option.
- ... [Middle Discussions Snipped for Brevity] ...
- Good point. @btmills do you see any value in having it as a separate option?
- @mysticatea's argument makes sense. Right now "never" has the side effect of forbidding recursion, which is (supposed to be) unrelated to this rule. I'd support classifying this as a bug and excepting recursive named function expressions from "never". 👍
