Title

Non-determinism of pkg_deb because of control.tar.gz

Description
### Description of the problem / feature request / question:

Building the same deb package twice results two packages with different hashes. Something similar happens here: [URL] It seems that using gzip adds a timestamp which isn't zeroed. If we don't use gzip when building the control file then the package is deterministic. 

I can fix the issue with this patch:

```
diff
diff --git a/tools/build_defs/pkg/make_deb.py b/tools/build_defs/pkg/make_deb.py
index 99ae379..01f572f 100644
--- a/tools/build_defs/pkg/make_deb.py
+++ b/tools/build_defs/pkg/make_deb.py
... [Log Snipped] ...
     ext = os.path.basename(data).split('.')[-2:]
     if len(ext) < 2:
```

Building the following pkg_deb shouild results in a .deb which has the same hash each time it's built.

    package_dir = "/opt",
