Title

Dead lock in mutation stage when many concurrent writes to few columns

Description
When I send many request to increment counters to few counter columns, sometimes mutation stage cause dead lock. When it happened, all of mutation threads are locked and do not accept updates any more.

Discussion
- You're right, since CMVH grabs a writer thread until it gets replies from the other replicas, you can have two replicas deadlock with A waiting for a reply from B, and B waiting for a reply from A. 

 One fix would be to move the local write into CMVH and the remote part into a separate stage (or maybe just a custom callback). 

 As a workaround, use CL.ONE with counters.
- Attaching patch to use a callback (as it avoids creating lots of thread that just spend time waiting on a condition) to send back the response from CMVH.
