Title

Building genrule by output file silently fails

Description
Sample BUILD:
```
genrule(
    name = "sample",
    outs = ["sample.txt"],
    cmd = "echo foo > $@")
```

Output for building via the output:
```
$ bazel build //:sample.txt
INFO: Analysed 0 targets (6 packages loaded).
INFO: Found 0 targets...
INFO: Elapsed time: 1.272s, Critical Path: 0.00s
INFO: Build completed successfully, 1 total action

$ ls -l bazel-genfiles/sample.txt
ls: cannot access 'bazel-genfiles/sample.txt': No such file or directory
```

As you can see, the genrule didn't actually run.

Building via the name:
```
$ bazel build //:sample
INFO: Analysed target //:sample (1 packages loaded).
INFO: Found 1 target...
Target //:sample up-to-date:
  bazel-genfiles/sample.txt
INFO: Elapsed time: 0.891s, Critical Path: 0.17s
INFO: Build completed successfully, 2 total actions
```
Discussion
- I think I've diagnosed this into the TargetPatternPhaseValue, working on a fix.
- No, that was a red herring.

The problem is that "//:sample.txt" is a generated_file, and in the tag filtering (https://github.com/bazelbuild/bazel/blob/ /src/main/java/com/google/devtools/build/lib/packages/TargetUtils.java#L270) anything that is not a Rule is automatically filtered out.

Is this the required behavior?

- Weird, still happens for me if I remove the "--bazelrc" command, so it must be something in there. Guess I'll binary search and figure it out.
- Huh, it's --build_tag_filter that is the culprit:
```
$ bazel --bazelrc=/dev/null build --build_tag_filters=-unknowntagmadeup //:sample.txt

INFO: Found 0 targets...

INFO: Build completed successfully, 1 total action
```
