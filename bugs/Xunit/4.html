Title

Methods should be grouped by name, not IMethodInfo

Description
Given a class with overloaded methods, both of which are marked `[Theory]`, the `ITestMethodStarting`/`ITestMethodFinished` messages are repeated, i.e. two methods are started/finished, but pass through the same information (type and method name). When running test cases, methods should be grouped by name, rather than `IMethodInfo`, to prevent these "duplicate" messages. This is a "pit of success" type change, to prevent runner authors having to know about and special-case this potential duplicate.

- This is very similar to the bug we just fixed with Visual Studio and parallelism, where it was grouping by the ITestCollection, which is fine... until you've serialized the test case, and then the collection identity is lost.
