Title

refactor string operations

Description
Conversion of StringBuilder to String was simplified by using the objects directly in the concatenation, instead of calling the toString() function. 
	 The equality check for empty strings was converted from an equals method call ("".equals(stringVar)) to use the isEmpty() method. 
	 When obtaining a one-character substring from a string, charAt() was used in preference over substring(). 
	 The new keyword was discarded when converting a single character into a string, using String.valueOf() instead. 
	 The creation of a string from a ByteArrayOutputStream was simplified to call toString(encoding) directly.
Discussion
- The equality check for empty strings was converted from an equals method call ("".equals(stringVar)) to use the isEmpty() method.  

 Beware,  "".equals(stringVar)  does work for  null  values,  stringVar.isEmpty()  throws NPEs in that case. Thus, please make sure that  stringVar  cannot be  null  there.
- Correct, but all three changes are safe: 
SearchEngine.java: the code is inside an if-condition that assures searchKey!=null. 
MockHttpServer: it is assured from the context that lineStr is not null, and even in the old code an NPE would be thrown anyway becuase trim() is called on the variable (`"".equals(lineStr.trim()`). 
XMPSchemaFactory: guarded (even in the old code) by a nullcheck
