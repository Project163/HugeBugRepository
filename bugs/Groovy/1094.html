Title

Sql.Dataset: Values are converted to string causing errors when inserting dates

Description
Testcase: 

 myMap =   [EMPNO: 10, HIREDATE: Date.parse("yyyy-MM-dd", "1982-12-25")]  
dbSet.add myMap 

 This results in: 
WARNING: Failed to add row for:  
{EMPNO=10, HIREDATE=Sat Dec 25 00:00:00 CET 1982}
 java.sql.SQLException: Invalid column type 

 The database does not recognize this date format. 
The add() method should use the values as a bind variable without converting them to string.
Discussion
- The DataSet add method doesn't convert to a string but many drivers only know how to process java.sql.Date not java.util.Date. 
Out of curiosity, what happens if you change to one of: 
  
 myMap = [EMPNO: 10, HIREDATE:  new  java.sql.Date(Date.parse( "yyyy-MM-dd" ,  "1982-12-25" ).time)]
myMap = [EMPNO: 10, HIREDATE:  new  java.sql.Timestamp(Date.parse( "yyyy-MM-dd" ,  "1982-12-25" ).time)]
 
  
 I am guessing this is database/driver specific. The trick to convert to java.sql.Date worked for me for hsqldb. 

 Perhaps Groovy could auto convert from the util to sql variant - making assumptions about the time along the way.
- I added an additional DGM method. The above can now look like this: 
  
 myMap = [EMPNO: 10, HIREDATE: Date.parse( "yyyy-MM-dd" ,  "1982-12-25" ).toTimestamp()]
 
  
 I am tempted to close this issue unless there are significant use cases where the above won't suffice. 

 I also thought about some kind of auto util Date to sql Date mechanism but that is likely to interfere with people wanting to store util Date objects directly not into timestamp columns, so I wasn't convinced it could be made to work in practice.
- Both of your suggestions work (I'm using an Oracle database). Thanks. 
I'm wondering, can the new suggestion be made more concise as: 

  
 myMap = [EMPNO: 10, HIREDATE: Timestamp.parse("yyyy-MM-dd", "1982-12-25")]
- We certainly could support a convenience like that but I am inclined to leave it as is for now and see what usage patterns emerge. There are many ways to create java util Dates in Java and Groovy enhances that with a few features of its own including the easy date manipulation facilities. If we had to make timestamp equivalents for each one, the API would become cumbersome. Certainly, if we observe over time that 99% of people are just using the parse method, then a convenience method would be very useful. There is nothing stopping you from adding your own helper method in the meantime.
