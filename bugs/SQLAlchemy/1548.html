Title

Type Float inherits of type Numeric, even though doc indicates otherwise

Description
The documentation of class Numeric says clearly "A type for fixed precision numbers, such as NUMERIC or DECIMAL." (https://docs.sqlalchemy.org/en/13/core/type_basics.html#sqlalchemy.types.Numeric)

However, `isinstance(myfloatcolumn.type, sqlalchemy.types.Numeric)` returns `True`.

The source code in sqlalchemy/sql/sqltype.py shows the reason: Float inherits directly from Numeric. Even though the documentation of both Numeric and Float seem to indicate otherwise.

Why is Float not a top-level data type?
Discussion
- I think this is due to an implementation detail of sqlalchemy. `Float` is a top-level data type, but it shares most of the implementation with `Numeric`.

I guess a superclass of `Numeric` could be extracted so that `Float` is not a direct subclass of `Numeric`.


The documentation list `Numeric` as the base for `Float`: [URL]
- it's probably possible for Float/Numeric to share a common mixin but not be subclasses of one another, but it might get tricky with weird cases like Oracle's NUMBER type is actually every type of number all at once based on the flags you give it.

this class relationship has had to be adjusted many times over the years so while I encourage folks to look into changing this relationship it might not be very easy to do.

- I don't really see this architecture as changing.   as mentioned above, on some databases like Oracle, the difference between "float" and "numeric" is kind of spongy, and additionally the use case of "float or numeric" can sometimes be based on what Python type someone expects, which is also fluid between Numeric and Float.   it's true that on Oracle, even Integer is in the same NUMBER spectrum, but from a python perspective, integer is very different from numeric/float.

For 2.0 these datatypes are now pep-484 typed.  so for the use case of distinguishing between database types I think checking the "scale" parameter is the best way to do this.
