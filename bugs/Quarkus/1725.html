Title

Using QuarkusTest and QuarkusMainTest in the same package breaks in 2.13.*

Description
### Describe the bug

Dependabot update from 2.12.3.Final to 2.13.0.Final failed in one of my projects with an error about using `QuarkusTest` and `QuarkusMainTest` "in the same run".

This behavior change was introduced in [URL]

Agreed this should be doable in zulip thread: [URL] perhaps by treating these two types as different profiles so things are cleaned up around them.

Note that putting the two types of tests in different packages avoided this check, so I think some implied scoping is happening (which suggests "in the same run" phrasing would be a minimal improvement, if we decide the profile-esque behavior won't work).




### Expected behavior

QuarkusTest and QuarkusMainTest should not be mutually exclusive, especially not "in the same run."

### Actual behavior

[URL]

```
Error:  Errors: 
Error:    Import5eToolsConvertTest.testCommandHelp(LaunchResult) » IllegalState Cannot mix both @QuarkusMainTest based tests and io.quarkus.test.junit.QuarkusTest based tests in the same run
Error:    Import5eToolsConvertTest.testIndexXmlData(TestInfo,QuarkusMainLauncher) » IllegalState Cannot mix both @QuarkusMainTest based tests and io.quarkus.test.junit.QuarkusTest based tests in the same run
Error:    Import5eToolsConvertTest.testMarkdownBook(TestInfo,QuarkusMainLauncher) » IllegalState Cannot mix both @QuarkusMainTest based tests and io.quarkus.test.junit.QuarkusTest based tests in the same run
Error:    Import5eToolsConvertTest.testMarkdownData(TestInfo,QuarkusMainLauncher) » IllegalState Cannot mix both @QuarkusMainTest based tests and io.quarkus.test.junit.QuarkusTest based tests in the same run
```


### How to Reproduce?

Check out commit   of [URL] and update to 2.13.(whatever is latest).

What "fixed" the broken project: ensuring that `@QuarkusTest` and `@QuarkusMainTest` weren't both used by classes in the same package (does that count as "in the same run"?)
