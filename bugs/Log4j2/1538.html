Title

log4j-jpl must handle parameters as MessageFormat args

Description
Currently message parameters use the configured default messagefactory, which provides no guarantees around the format used, however JPL API requires MessageFormat style formatting.

- The System.Logger API that this implements requires MessageFormat formatting, the api is not aware of curly brace placeholders without indices: 
 [URL]

 > format - the string message format in   MessageFormat   format 

 Libraries which consume this API cannot make assumptions about what types of formatting will be supported by the underlying logging framework. That would be reasonable if they used log4j-api or slf4j loggers which explicitly support curly brace placeholders, but not System.Logger.
