Title

3.0 Error finding a record with HasOne relation but without this related record

Description
trying to find some records with a statement similar to

``` php
TableRegistry::get('Merchants')->find()->contain(['MerchantTypes','BusinessProfiles'])
```

In the developer enviroment I have 10 merchants, but the result return 0 results. 

Relations:
Merchants -> belongsTo -> MerchantTypes
Merchants -> hasOne -> businessProfiles

I could see that the table business_profiles is empty and if the businessProfile record does not exist for each merchant then the result only return mechants with valid businessProfiles, however if the MerchantType does not exists or if null then the result return all the records with the MerchantType null. I think in the case of HasOne should be similiar to belongsTo and return a null in the related object. 

this cause that will be impossible edit a record with hasOne and non existent relation, very common when the developer create a new relation, which is my case, I expect that the user create the related record (BusinessProfile) on the fly when save the merchant record
Discussion
- The HasOne association type does an `INNER JOIN` currently as the relation expects there to always be a 1:1 relationship between the entities. It might be best to make hasOne default to `LEFT` joins as it did in 2.x though.
- its not only set type to LEFT JOIN, when I try to create the related record on the fly I got the following exception 

```
Error: [InvalidArgumentException] All primary key value(s) are needed for updating
```

in the Merchant form  I have , the id and others inputs for the hasOne relation (BusinessProfile), if the relation exists theses inputs should be contain the data to update otherwise these inputs should be null and create a new related record should be happen when save the merchant
