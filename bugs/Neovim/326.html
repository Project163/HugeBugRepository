Title

bug: rendering performance regression due to signcolumn

Description
### Problem

For me   seems to have introduced performance regressions for rendering.

The below config works smoothly prior to that commit and but quickly freezes `nvim` when opening a reasonably long (250+ lines) Python file for which `pyright` sets signs from that commit onward.

### Steps to reproduce

Minimal `init.lua`

```
lua
vim.cmd [[set runtimepath=$VIMRUNTIME]]
vim.cmd [[set packpath=/tmp/nvim/site]]
local package_root = "/tmp/nvim/site/pack"
local lazypath = package_root .. "/lazy/lazy.nvim"
... [Log Snipped] ...
  },
}, { root = pluginpath })
````

1. `nvim -u minimal_init.lua $SOME_FILE_WITH_MANY_SIGNS.py`
2. Hold `j` or `k` to scroll say 10-20 lines
3. Observe freezing / slow down in rendering

Commenting out
```lua
opt.signcolumn = "auto:1-4" -- needs varying length signcolumn
```
fixes the problem.

Commenting out groups (e.g., `opt.wrap .. opt.showbreak`, `opts.cursorline`) alleviates the issue and potentially fixes it. Similar with disabling `gitsigns` or LSP.

### Expected behavior

Smooth rendering without freezes.

### Neovim version (nvim -v)

NVIM v0.10.0-dev-1613+g585eeacb24

### Vim (not Nvim) behaves the same?

no, doesn't have signcolumn refactor

### Operating system/version

Arch Linux

### Terminal name/version

kitty 0.31.0

xterm-kitty

build from repo
