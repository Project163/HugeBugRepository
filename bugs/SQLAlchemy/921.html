Discussion
- oh, the test is not doing what the documentation says:

```
When using :func:`.contains_eager` in conjunction with inherited
    subclasses, the :meth:`.RelationshipProperty.of_type` modifier should
    also be used in order to set up the pathing properly::

        sess.query(Company).\
... [Log Snipped] ...
                    alias=Manager)
            )
```

but...I should be able to use of_type with anything, not just inherited subclasses...
- **Mike Bayer** has proposed a fix for this issue in the **master** branch:

**Apply of_type() automatically when alias given in contains_eager()** [URL]
- **Mike Bayer** has proposed a fix for this issue in the **rel_1_3** branch:

**Apply of_type() automatically when alias given in contains_eager()** [URL]
- OK this can't be fixed, I think we probably should just get rid of "alias".  Here is the implicit behavior that we can't really fix:

    contains_eager(A.b, alias=b_alias).contains_eager(B.c)

The chain is being built as A->B->C however it's really b_alias.  This is more clearly set up as:

   contains_eager(A.b.of_type(b_alias).contains_eager(b_alias.c)

for this issue we wil just set up new tests.
