Title

Can't use generic parameter type in Theory -- FormatTypeName null refs on generic parameters

Description
Given the following, the 'Repro' test will fail due to a NullReferenceException in v2.1.0.

``` C#
public static readonly object[][] ReproData = new[] {
    new object[] { typeof(List<>).GetTypeInfo().GenericTypeParameters.First() },
};

[Theory]
[MemberData("ReproData")]
public static void Repro(Type type) {}
```

The issue appears to be here: [URL]

Regrettably, TypeInfo.FullName is null for type parameters.
Discussion
- as far as I can see the problem is that `typeof(List<>).GetTypeInfo().GenericTypeParameters.First()`does return something like a Type placeholder, where TypeName is T, but FullName is null, as long as T is not set to a specific type.

Using `typeof(List .GetTypeInfo().GenericTypeParameters.First()` works as expected of course.

I traced it down to an exception silently handled in TheoryDiscoverer.Discover, digging further now.
- MSDN agrees with the behaviour of [URL] here: [URL] , describing the value of `TypeInfo.FullName` as

Therefore the bug is in fact in the ArgumentFormatter that currently assumes the FullName to be set on any type it get's.

So how to deal with it?
I think `ArgumentFormatter.FormatTypeName(Type type)` should at least deal with this special case.
- locally I implemented tests covering that issue by directly invoking the ArgumentFormatter for unbound generic type arguments;
It would be easy to return the generic argument name in that case from `FormatTypeName()`; but as a result it would then return `typeof(T)` for a generic type argument that is named T, which seems not very useful at all.
So: what should be returned instead? anything like `typeof(?)` where `?` is replaced inside the brackets is easy to implement; but is it useful?

I'll open a pull request that does return typeof(T) for a generic argument named T for now.

any alternative solutions are welcome, and I'm fine with implementing them instead.
