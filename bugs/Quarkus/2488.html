Title

HTTP compression not applied to /q/metrics (Micrometer Prometheus)

Description
### Describe the bug

I’m exposing Micrometer Prometheus metrics on /q/metrics and want gzip when the client sends Accept-Encoding: gzip. I enabled HTTP compression and added the OpenMetrics media type, but the response is still not compressed.

```yaml
quarkus:
  http:
    enable-compression: true
    compress-media-types: application/openmetrics-text
```

Request: 
```bash
curl -H "Accept-Encoding: gzip"  [URL]
```

Can someone help me understand why it’s not coming compressed?
Thanks in advance!

### Expected behavior

When the client sends Accept-Encoding: gzip, the /q/metrics endpoint should return the response compressed (gzip), since HTTP compression is enabled and application/openmetrics-text is listed in the compressible media types.

### Actual behavior

Even when the client sends Accept-Encoding: gzip, the /q/metrics response is returned uncompressed (plain text).

- Are you using the management interface?
