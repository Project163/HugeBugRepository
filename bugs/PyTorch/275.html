Title

Deprecated `torch._export.aot_load()` crashes with segmentation fault when loading compiled AOT artifacts with constants

Description
### 🐛 Describe the bug

## **Summary**

I know `torch._export.aot_compile()` / `torch._export.aot_load()` have been deprecated (and the warning in the logs makes that clear), so I’m mostly filing this as a “heads up” in case they’re still expected to degrade gracefully rather than segfault.

The repro involves a tiny model with a registered buffer constant. Export + AOT compile succeed, but `aot_load()` fails during constant loading with:

```
The specified pointer resides on host memory and is not registered with any CUDA device.
```

and then the process terminates with a segmentation fault. Even for deprecated APIs, this feels like it should probably error out cleanly instead of crashing.

---

## **Minimal Reproduction**

```
python
import os
import torch
import torch.nn as nn

... [Log Snipped] ...
if __name__ == "__main__":
    main()
```

---

## **Actual Output**

```
[AOT LOAD] loading on cuda:0
torch._export.aot_compile()/torch._export.aot_load() is being deprecated...
Exception in aoti_torch: The specified pointer resides on host memory and is not registered with any CUDA device.
...
Segmentation fault (core dumped)
```

The stack trace shows the failure happening inside AOTInductorModelBase constant loading, then a crash in the CUDA path after `getDeviceFromPtr`.

---

## **Expected Behavior**

Given that this API is deprecated, I wouldn’t expect correctness fixes or new features, but I would expect at least one of:

* a clean Python exception, or
* a clear “unsupported” error, or
* even a graceful no-op fallback

rather than a segfault.

* The crash path seems related to constants being treated as host pointers during AOTI constant loading.
* This also repros even without backward/AOTAutograd complexity — just export → aot_compile → aot_load.
* The deprecation warning points to:

  ```
  torch._inductor.aoti_compile_and_package(torch.export.export())
  torch._inductor.aoti_load_package()
  ```
