Title

"Groovy executing" dialog comes/stays forever although no script should be running

Description
When working with GroovyConsole, I quite often get a "Groovy executing" dialog although no script should be running. Mostly this happens when I switch back to the console after it has run in the background for some time. Usually, the only way to get rid of the dialog is to restart GroovyConsole. Another way to get a dialog that stays forever is to hit the run button as fast as you can for a few seconds. Easily reproducible for me.
Discussion
- Fixed. 

 GroovyConsole has been modified to replace the dialog box and its interrupt functionality by a less invasive message in the status bar and a keyboard shortcut to interrupt a running script. 

 Here are more details: 

 1)  The modal dialog box that used to appear when script was executed has been replaced by a message in status bar, which reads "Script executing now. Please wait or press Ctrl-Q to interrupt it.". 

 2)  An attempt to run a script when the previous one has not finished is rejected and status bar is updated with the message "Cannot run script now as a script is already running. Please wait or press Ctrl-Q to interrupt it." 

 3)  If the user presses Ctrl-Q when the script is running, a confirmation box is thrown and if the user chooses "Yes", the thread running the script is interrupted.
- Please note that this change has not been introduced on 1.6.x line at this point.
- Ctrl-Q combination (to interrupt the script) seems to be giving issues on Mac and Windows 7, so re-opening it to implement it differently.
- Doesn't look like any feedback is coming. 

 Since I am all done from my side and have the feedback from Paul, I am marking it as done. Please reopen if the need be.
