Title

Invalid streamId in cql binary protocol when using invalid CL

Description
Execute a query using invalid CL (0x100 for example) 

 The response comes but does not use the request streamId (always 0).
Discussion
- We should reject invalid CL.
- Attaching patch to preserve the streamId in that case. I note that we don't do any effort to preserve the streamId if you screw up the frame format, but imo it's fair game. If you don't respect the protocol at that level, you have other problems to worry about than the streamId.
- fix invalid cast
- The patch would be better by inverting lines 202 & 203 in ErrorMessage.java: 
  
  public   static  ErrorMessage fromException(Throwable e)
 ...
 streamId = ((WrappedException)e).streamId;
 e = e.getCause();
 
  

 Otherwise, an invalid cast is raised. Patch enclosed - I've tested it and exception nicely flows to the client using the right stream id.
