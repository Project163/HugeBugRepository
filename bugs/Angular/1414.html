Title

Angular animation: :leave animation starts at wrong position

Description
### Affected Package
@angular/animations

### Description
:leave animation has incorrect initial position for the animated elements.

Discussion
- The problem only happens when you reverse your list order.
- I have the same issue, here are my conclusions so far:
- The issue is actually that the `:enter` transition runs instead of `:leave`.
- It only happens when `:enter` is before `:leave` in the array passed to `trigger(..)`.
- It still happens if you completely remove the `:leave` transition.
- Hi @mfursov and all, I've just created a PR with the fix 🙂 👆 

The issue is as @marcusrettig suggested that `:enter` runs instead of `:leave` (also the other points he made are correct, as for why, keep reading and that should become quite clear 🙂), that is because when the elements in the list are moved their DOM elements are removed and re-inserted
 (PS: when reversing the array the last one is an exception since it, as a side effect gets moved/pushed down by the other n-1 items, that is why the last item in the reversed list doesn't present the issue) 

\
The real issue here is that the reordering "triggers" the leaving of the elements, but then cancels it (you don't see them disappear or anything), as a side effect however the elements (again, except the last one) lose their trigger's value.

To explain better, please have a look at this [Link: updated stackblitz with console.logs], there:
 - when you add the 3 items, in the console you can see that normal transitions from `void` to `null` occur (remember that `void => *` matches `:enter`)
 - when you reverse the list you will see 2 (and not 3, as I mentioned earlier) transitions from `null` to `void` (which match `:leave`) but the items haven't actually left the DOM nor any leave animation is executed
 - when you remove the 3 items, (as already mentioned) the last one (first to be removed) works fine (`null` to `void`) but the other 2 transition from `void` to `void` (it should be from `null` to `void`, but the `null` got lost/replaced widh `void` during the reordering)

by remembering that `void` to `*` (where `*` indicates _anything_) matches `:enter` we can now see why the `:enter` transition is executed instead of `:leave` (__note:__ the first successful `transition` in the array cancels the others)

_(also note that `void` to `void` also matched `:leave`/`* => void` so, if you switch the `transition`s in the array everything would work as expected even without my PR's fix)_

\
_(also feel free to experiment with the stackblitz, this also happens if we bind some value to the trigger, not only if the value is `null`)_
\
_(ps: if my explanation about the last item not being effected doesn't sound convincing, you can reverse the list 2 times, in that way you all the items are actually moved at least once by themselves and will have their trigger's values set to `void` and all transitions will be broken/look like `:leave` 🙂 )_

I hope this helps clarifying things 🙂
