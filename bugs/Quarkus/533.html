Title

Qute template extra whitespaces causes inconsistent behaviour

Description
For Qute templates, there seems to be inconsistent behaviour when it comes to having whitespace before and after braces `{`,`}`.

### Case 1 (whitespaces before closing brace for the starting tag)
```
 
     {#if 10 > 5    }Hello{/if} 
 
```
In this case, everything works as expected:
[Image: image]

### Case 2 (whitespaces before closing brace for the ending tag)
```
 
     {#if 10 > 5}Hello{/if } 
 
```
In this case, this error appears:
[Image: image]

### Case 3 (whitespaces after opening brace)
```
 
     Hello { name ?: "world"}! 
 
```
In this case, there is no error, but the output is unexpected:
[Image: image]

### Case 4 (whitespaces before closing brace)
```
 
     Hello {name ?: "world" }! 
 
```
In this case, there is no error, but the output is unexpected:
[Image: image]

To conclude, in some cases (like case 1) having whitespace causes nothing unexpected to happen but in other cases, having whitespaces cause inconsistent behaviour.

For example, if case 3 is expected behaviour, I think it is unexpected to have case 4 output "NOT_FOUND"
Discussion
- It also seems like in general, there shouldn't be any extra whitespaces anyways from viewing the documentation: [URL] Then I suppose case 1 is some sort of edge case?
- Ideally, users should avoid using whitespaces before/after braces.

Case 1 - we try to be lenient and ignore the whitespaces before the closing brace
Case 2 - shouldn't fail, we should be lenient as well, it's a bug 
Case 3 - this is expected, see [URL]
Case 4 - a bug too

I've created [URL] to fix the bugs.
