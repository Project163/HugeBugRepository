Title

Whole pm2 crashes down all running apps when one app cannot start

Description
I had two clusters running with pm2 when I tried to run a third app in fork mode:

```
$ pm2 start pm2.json 

events.js:72
        throw er; // Unhandled 'error' event
              ^
Error: EACCES, open '/var/log/nodejs/nzslcomposer/out.log'
^C%   
```

And then pm2 ls return no apps anymore. The previous two clusters have been crashed altogether. Shouldn't happen. Should be more stable.
Discussion
- EACCES = permission problem

`/var/log/nodejs` does have the same rights as does the pm2 user ?
- Yes it was a permission problem in `/var/log/nodejs` and I fixed it.

But that's not the issue here. The issue here is: pm2 should not crash with all its other apps together when only one app cannot be started!

You can try this scenario yourself:
1. Run a couple of apps with pm2
2. Prepare a new app and cheat: Assign a different user to the log file to simulate EACCES
3. Start this app with pm2
4. Everything is down, all the apps are crashed, also the previously started ones!
- The 0.10.0 fixing this issue has been published:

```
$ npm install pm2@latest -g
```
