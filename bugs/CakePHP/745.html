Description
Hi guys. Kind of similar to #7785 but I thought a new issue would be best since it's more about persistence. Say I have a BTM setup that requires the same table multiple times (kind of an edge-case but it's easier than making multiple classes with the same stuff)

```
'belongsToMany' => [
    'Tags' => [
        'through' => 'PostsTags'
    ],
    'PrimaryTags' => [
... [Log Snipped] ...
    ]
]
```

And I try to do this only `secondary_tags` persist. This feels like maybe a bug because it looks like the data should save for each association (even if the joinData isn't there).

```
$post = $this->Posts->get($id);
$data = [
    'primary_tags' => [
        ['id' => 1]
    ],
... [Log Snipped] ...
$this->Posts->patchEntity($post, $data);
$this->Posts->save($post);
```

Also, how possible would it be for the `_joinData` to be automatically added from the association's conditions instead of adding it to the data? If a BTM has conditions set with things from the join table, you'd almost always (can't think of when you wouldn't) want those in the joinData when saving. If that could be automatic that'd be awesome.

```
$data = [
    'primary_tags' => [
        ['id' => 11, '_joinData' => ['primary' => 1]]
    ]
];
// redundant, could be a straight passthrough from $this->request->data('primary_tags._ids')
```

```

$tags = [];
if (!empty($this->request->data('primary_tags._ids'))) {
    foreach ($this->request->data('primary_tags._ids') as $tagid) {
        $tags[] = ['id' => $tagid, '_joinData' => ['primary' => 1]];
```

- While possible, I'd rather not add implicit data mutation to the marshaller. I feel that is the kind of behavior that will not be easy to understand at glance.

I've not had a chance to look at the code, but I suspect that all 3 associations using the same `through` table is the source of the persistence issues.

```
$id = 50;
$bookmarks = TableRegistry::get('Bookmarks');
$bookmark = $bookmarks->get($id, ['contain' => ['StarredTags']]);
$data = [
    'starred_tags' => [
... [Log Snipped] ...
$bookmarks->patchEntity($bookmark, $data);
$bookmarks->save($bookmark);
```

Running that once, it's fine. There's a single record in `bookmarks_tags` like you'd expect. However, running that twice results in there being three records in `bookmarks_tags`, two with `starred=0`.

The only way I can see to fix it is to change the `patchEntity` and add the `associated` part.

```
$bookmarks->patchEntity($bookmark, $data, ['associated' => ['StarredTags._joinData']]);
```

My gut is telling me that's a bug, because why does it work once without the `associated` part but not a second time?
- Thanks for the updates on this. I took another look at the code with your updates. And it does seem like something is off. With the StarredTags loaded before marshalling is done, the marshaller does not convert the `_joinData` into an entity and leaves it as an array. Because `_joinData` is not an array it is not persisted which is why we're getting `starred=0`. 

I feel like requiring the `_joinData` association to be marshalled is 'more correct' but the current code makes handling joinData error prone and easy to violate application constraints. I have a good idea on how to fix this now though.
