Discussion
- Do we have a link to the failure? is ti flaky or fails constantly?
- The test has invalid assumptions for the configuration we currently do not use -  so, no - it is not failing at the moment. Though, the test contains conditional assertions depending on whether early open is enabled or not. Those assertions are invalid and when the test is run with early open disabled, the test fails consistently. 

 in other words: 

  
 
assertKeyCacheSize(noEarlyOpen ? 2 : 4, KEYSPACE1, cf);
 
  

 is wrong when  noEarlyOpen  is true. 

 So, this is confusing - either the test is not suitable to run with early open disabled, and then there is no conditional assertion or the test is suitable to run with both configurations and passes in both bases. Frankly, in 5.0 this tests class is early-open agnostic.
