Title

ReflectionServiceFactoryBean creates inconsistent schema for messages with parts with types and no elements

Description
I added an @Ignored test that fails to the ReflectionServiceFactoryBeanTest. This test demonstrates the model cooking itself up with a part element QName for an element that isn't in the schema. 

 The same results ensue when run with the JaxWsServiceFactoryBean, whose test also has this case now.
