Title

vfs: touch'ing files makes them look empty

Description

bash

$ ll /tmp/tmp.HnHyfvIWP6/touchtest
-rw-r--r-- 1 fabian fabian 29 27. Jan 16:13 date.txt       # correct size and modtime

Discussion
- I see what is happening...

Eventually o.SetModTime(newTime) gets called which is all well.

However when we read the time back again with o.ModTime() the time hasn't changed in the object.

This is kind of unexpected, but also kind of expected since there isn't an integration test testing for that behaviour!

So the fix would be to refresh the object from the remote (with NewObject(o.Remote()) after a SetModTime.  Or to cache the ModTime in the file (maybe when doing the original listing).

Or perhaps fix all the remotes so that `o.SetModTime(t); o.ModTime() == t` is true always...

I fixed the modtime getting set twice - this is FUSE telling us that the modtime is NOW an the modtime is this value for some reason....

**Update** re-reading the file will get the Size correct too so maybe that is the best option.
- What is going wrong with the Size is the kernel caching.... (I think this must be what you meant by the directory cache in your original message - I thought you mean the VFS cache).

The reason the size appears to be zero is in the [Link: VFS open a file for write]

This could set the size to be the existing size of the file (if it exists at that point) which might help. It will be overwritten if there are any writes and if there are no writes the file will be left untouched.

`--vfs-cache-mode off` for writes is a bit of a balancing act between being strictly correct and being compatible...

`--vfs-cache-mode writes` does at least get the size correct even if it doesn't get the modtime right!
