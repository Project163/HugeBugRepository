Title

PERFORMANCE WARNING: Attribute 0 is disabled. This has signficant performance penalty

Description
When I run the sample of morphtargets, such as 
[URL]

the below waring (it's too many) is shown in Chrome console.
chrome ver. 32.0.1700.77 (windows7 and Mac  10.9.1 both)

[.WebGLRenderingContext]PERFORMANCE WARNING: Attribute 0 is disabled. This has signficant performance penalty 

Why the above error is indicated?
BTW, morphnormals example does not indicate this waring.
Discussion
- So, when a shader is compiled, the attributes that it references are given indices automatically by the compiler. Then Three.JS disables some of the attributes based on what is found in the model. If the shader compiler had assigned one of these disabled attributes to index 0, you'll get this message printed (on some platforms, not having attribute 0 used forces some sort of expensive emulation or something...)

In this example (as well as some others), the material compilation puts the "morphTarget7" attribute in index 0. I'm guessing that this is something that isn't actually part of the model data but is referenced by the shader, hence the warning message.

Now, to fix it:
There is a `index0AttributeName` member of a material in Three.JS that lets you force a particular attribute to use index 0 to avoid this problem. By default, it's only assigned for ShaderMaterials but you can set it on any other as well. In the example, add the following line after the material is created:

`material.index0AttributeName = "position";`

Let me know if that doesn't fix the problem. I'm on Windows right now so I can't verify that this fixes it (the warning only shows up on Mac, I believe. Or maybe just when OpenGL is used instead of ANGLE).
