- It looks like the following line is failing in your environment:: 
assertTrue(str.matches(CONNSTRING_FORMAT)); 

 Any chance you could add a print of of str and CONNSTRING_FORMAT - it might help a lot to understand what is going on.
- This is the contents of CONNSTRING_FORMAT (both on my pc & on the iseries machine, both with ibm's jdk14) is: 
\S+@ [0-9]  .* (XID = . ), (SESSIONID =  [0-9]  ), (DATABASE =  [A-Za-z] +), (DRDAID = . )  

 The (last before Failing) str value on iseries is: 
 org.apache.derby.impl.jdbc.EmbedConnection30@-2073846638 (XID = 223), (SESSIONID = 4), (DATABASE = wombat), (DRDAID = null)  

 On my pc, the value at the same point in the test is: 
 org.apache.derby.impl.jdbc.EmbedConnection30@1039214490 (XID = 223), (SESSIONID = 4), (DATABASE = wombat), (DRDAID = null)  

 I think maybe the negative value after the @ may be the trouble, in which case, this would be a test issue. Assuming that value is allowed to be negative? I'll pursue this angle.
- closed this issue, because indeed it was the negative value after the @ in the str in the DataSourceTest that didn't match the CONNSTRING_FORMAT. I adjusted the CONNSTRING_FORMAT in main and 10.3.
