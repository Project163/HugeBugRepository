Title

cplayback stuck - no console rendering nor traffic generated

Description
Hi,

There are my exact keystrokes:

```
mitmproxy --host
c
path_to_my_mitm_saved_flows
```

An nothing gets rendered, I just have a '**[0/0]    [cplayback:3 to go][showhost]**' message in the bottom status bar.

However, as soon as I press a key, the list of flows is diplayed, but they haven't been properly processed : I had tcpdump running in other terminal to check for any traffic, and nothing is sent by `mitmproxy`:

I previously used the version from Ubuntu repositories, and it worked fine.
Any idea on what is going on ?

- Ok, after digging a little more into it:
- the stack trace in the previous comment is not very meaningful: after repeating the test several times, the stack pointer isn't always stuck at the same code line
- the fact that no connection is generated when the flows record file is loaded looks like normal behaviour. I still have a couple of questions about this though:
  - is there a command to replay ALL the flows in the list ?
  - why are the "inline scripts" callbacks called during this "flows load stage", but the 'request' callback isn't called when the flow is replayed with 'r' ? (cf. [URL] )
    To be more precise: when a HTTP response is received, the script is run through `flow.py:FlowMaster.handle_response()`, but when an HTTP request is sent, it goes through `replay_request()` and then `process_new_request()`, which does not call any script. Is this a design choice ?
- finally, the rendering bug is a Heisenbug : since yesterday it disappeared, so I guess it was du to a console glitch, maybe with `tmux`. I'll post more details if I face it again
