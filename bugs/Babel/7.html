Title

`Cannot read property 'type' of null` again

Description
## Bug Report

 
- [x] I would like to work on a fix!

 

**Current Behavior**
This is a follow up to #11210 . When the assignment expression is wrapped in a block scope that is compiled to IIFE, the error occurs again.

```
TypeError: unknown: Cannot read property 'type' of null
    at convertFunctionParams (/path/to/node_modules/@babel/plugin-transform-parameters/lib/params.js:88:24)
    ...
```

**Input Code**
- REPL or Repo link if applicable:

```js
class A {
  a = b => {
    {
      ({ b } = {});
    }
  };
}
```

```
json
// options.json
{
  "plugins": [
    "proposal-class-properties",
... [Log Snipped] ...
  ]
}
```

**Expected behavior/code**
Should not throw error.

**Environment**
 
```
  System:
    OS: macOS Mojave 10.14.6
  Binaries:
    Node: 13.10.1 - /path/to/node_modules/.bin/node
    Yarn: 1.22.0 - /usr/local/bin/yarn
    npm: 6.13.7 - /path/to/node_modules/.bin/npm
  npmPackages:
    @babel/runtime: ^7.1.5 => 7.8.4
    babel-plugin-macros: ^2.8.0 => 2.8.0
    eslint: ^6.8.0 => 6.8.0
```
- Babel version(s): all latest, @babel/core@7.8.8
- Node/npm version: Node 13/npm 6
- Monorepo: no
- How you are using Babel: cli

**Possible Solution**

Possible cause: In `replaceWithMultiple` the original node is removed, but its bindings are not removed as expected, leaving a node with `removed: true, node: null` in the `constantViolations` and breaks `plugins-transform-parameters`.

The bindings are found from `path.node`:

[URL]

But `path.node` is always `null` when it is being removed:

[URL]

I found a tricky way to solve this:
- save the node to be removed before it is set to `null`
- pass it to `remove`
- search bindings: first `this.node = node`, then search, finally `this.node = null`
