Title

"Could not find fragment with id" error when fragment function with run_every is no longer called

Description
### Checklist

### Summary

When I activate a fragment function with a fast refresh rate (low `run_every`) and then stop calling the function I get an error that says `RuntimeError: Could not find fragment with id  `.

### Reproducible Code Example

```
Python
import streamlit as st

if "i" not in st.session_state:
    st.session_state.i = 0
... [Log Snipped] ...
    with st.empty():
        counter()
```

### Steps To Reproduce

Execute the provided code and tick the box to make the counter appear, then tick it again to make it disappear. This should trigger the error. It might take a few tries.

### Expected Behavior

The counter appears and disappears normally.

Discussion
- Thanks for reporting this issue! I have been able to reproduce it. I believe its because the web app sends an update message but since the fragment has not been included in the app run anymore, the fragment id is missing. Probably the right way for us is to keep track of whether an update is coming from the `rerun_every` behavior and ignore the error in that case or notify the web app about the removal somehow, although this might lead to a race condition between the two messages 🤔 

Update:
As a workaround, you should be able to put a `try-except` block around your `fragment` annotated block:

```python
try:
  @st.experimental_fragment(run_every=0.1)
  def counter():
    st.write(f"timer: {st.session_state.i}")
    st.session_state.i += 1
except Exception as ex:
  print(ex)
```

Of course, this will hide any other issues going on as well, so I don't recomment this as a general advice 🙂 
You could also catch the `FragmentStorageKeyError` from `streamlit.errors` to lower the blast-radius of the except, but please **note** that we do not guarantee this to be a stable import path across releases; so the import could change in the future.
