Title

number_input value-in-range validation bypassed for max/min_value == 0

Description
### Checklist

- [Link: X] I have searched the [existing issues] for similar issues.
- [X] I added a very descriptive title to this issue.
- [X] I have provided sufficient information below to help reproduce this issue.

### Summary

I noticed this issue while testing an extension library. The following call would be expected to throw a StreamlitAPIException because `value` is outside the range `min_value` - `max_value`:
```
my_number = st.number_input("My Label", value=6.0, min_value=-10.0, max_value=0.0)
```

This occurs because of this section in number_input.py which preconditions the bounds check on the "falsiness" of `min_value` and `max_value` when it should really be checking whether they are `None`:
```
        # Line 292
        if (min_value and min_value > value) or (max_value and max_value   value) or (max_value is not None and max_value < value):
```

### Reproducible Code Example

```Python
my_number = st.number_input("My Label", 6.0, min_value=-10.0, max_value=0.0)
```


### Steps To Reproduce

_No response_

### Expected Behavior

Expect a StreamlitAPIException("The default `value` of 6.0 must lie between the `min_value` of -10.0 and the `max_value` of 0.0, inclusively.")

### Current Behavior

Call passes silently
