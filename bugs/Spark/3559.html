Title

SparkSession's conf doesn't take effect when there's already an existing SparkContext

Description
I am working with branch-2.0, spark is compiled with hive support (-Phive and -Phvie-thriftserver). 
I am trying to access databases using this snippet: 
  
 from pyspark.sql  import  HiveContext
hc = HiveContext(sc)
hc.sql( "show databases" ).collect()
[Row(result= ' default ' )]
 
  

 This means that spark doesn't find any databases specified in configuration. 
Using the same configuration (i.e. hive-site.xml and core-site.xml) in spark 1.6, and launching above snippet, I can print out existing databases.

Discussion
- I can reproduce it even use SparkSession, should be a bug, try to work on it.
- The root cause is that in pyspark SparkContext is created first and it is used for creating SparkSession so that the SparkContext's conf is used instead of that of SparkSession.  Actually this issue also happens in scala. Here's one sample in spark-shell 

  
  import  org.apache.spark.SparkContext
 import  org.apache.spark.sql.SparkSession
sc.stop()
 var  sc =  new  SparkContext()
val session = SparkSession.builder().master( "local" ).appName( "test" ).enableHiveSupport().getOrCreate()
session.sql( "show tables" ).show()
 
  

 For this sample code, the session created doesn't have hive support, because it use the new created SparkContext's conf. I think this is a very critical issue in the perspective of user experience.

- i was annoyed by this bug but fortunately found the workaround  
it will work fine if you start the server with  
export HADOOP_CONF_DIR=/etc/hadoop/conf:/etc/hive/conf 
bin/spark-shell 

 It would give trouble if HIVE_CONF_DIR is as below  
export HADOOP_CONF_DIR=/etc/hadoop/conf 
export HIVE_CONF_DIR=/etc/hive/conf 
bin/spark-shell
