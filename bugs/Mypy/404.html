Title

Crash in fine-grained incremental mode if __init__.py is deleted

Description
Deleting package `__init__.py` causes a fine-grained incremental mode crash.

Test case:

```
[case testDeletePackageInitFile]
# cmd: mypy p/__init__.py p/a.py
[file p/__init__.py]
[file p/a.py]
[delete p/__init__.py.2]
```

Traceback:

```
/Users/jukka/src/mypy/mypy/server/update.py:378: in update_single_isolated
    graph = load_graph(sources, manager)
/Users/jukka/src/mypy/mypy/build.py:2187: in load_graph
    ancestor_for=st)
/Users/jukka/src/mypy/mypy/build.py:1610: in __init__
... [Log Snipped] ...
    assert err.module_with_blocker
E   AssertionError
```
Discussion
- This can also happen if a newly created package is missing `__init__.py`:

```py
[case testAddPackage4]
import p.a
p.a.f(1)
[file p/a.py.2]
def f(x: str) -> None: pass
[file p/__init__.py.3]
```
- I think the fix here is that whenever an `__init__.py` is added, we need to remove and re-add any modules underneath it, since their names change.
To really get it right, we also need to do this for __init__ files that aren't in the build, unfortunately
