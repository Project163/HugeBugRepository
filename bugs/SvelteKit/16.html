Title

Local fetch from index.svelte's load function fails on server

Description
**Describe the bug**

In my project's root-level `index.svelte`, `fetch` to a local resource (endpoint) within the load function returns 404 even though the resource exists. This only occurs when the server is trying to render the page; if I navigate to my project's homepage from another page, the client-side fetch works fine and the page loads as expected.

Excerpt:

```
 
  import type { Load } from "@sveltejs/kit";

  export const load: Load = async function load({ fetch }) {
    const res = await fetch("/post-list.json");
... [Log Snipped] ...
  }
 
```

--> logs 404, even though `/post-list.json` (from `post-list.json.ts` endpoint) renders just fine when you navigate to it directly (or load it from other pages).

This issue occurs with `@sveltejs/kit@1.0.0-next.55` but not when I downgraded to `@sveltejs/kit@1.0.0-next.54`; I think the root cause was introduced in #583 and specifically I think it's coming from [URL]

`options.initiator` in this case seems to correspond to the `index.svelte` route, which is the first route that gets checked, so we get 404 immediately (before other routes are checked); this problem seems like it could occur with fetches from other routes, but I guess I've noticed it here because `index.svelte` is the first route listed in the manifest.

**To Reproduce**

Use `@sveltejs/kit@1.0.0-next.55` (issue does not occur with `@sveltejs/kit@1.0.0-next.54`).

1. Create a new project (with TypeScript) using `npm init svelte@next`
2. Replace the contents of `src/routes` with these 3 minimal files: [URL]
3. Run `npm run dev` and navigate to `localhost:3000`. You'll see `404`.
4. Navigate to `localhost:3000/other` and then click the link to go to the homepage. You'll now see 200.

**Expected behavior**
Fetch does not 404 when endpoint exists.
