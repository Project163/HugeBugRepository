Title

Psalm ignores variable assignments if method arguments don't match with phpdoc parameter types

Description
It seems like psalm ignores the result of variable assignments in a branch if there's an InvalidArgument in that branch, even if that argument's type declaration was from phpdoc instead of a real type. This is unintuitive behavior, especially if the InvalidArgument is suppressed.

Observed:

```
ERROR: InvalidArgument - src/experiment.php:11:40 - Argument 1 of my_entity::update expects array |null, string provided                                                                                                          
            $success = $entity->update('');                


ERROR: InvalidArgument - src/experiment.php:13:40 - Argument 1 of my_entity::update expects array |null, string provided                                                                                                          
... [Log Snipped] ...
ERROR: RedundantCondition - src/experiment.php:16:13 - Found a redundant condition when evaluating $success            
        if ($success) {
```

Expected: Should emit InvalidArgument but not RedundantCondition.

```

    
Discussion

    
- FWIW if the argument is suppressed then the above code reports no errors
- Oh. I may have been post-processing the output and filtering out those InvalidArgument, then (To see pre-existing errors in the output but removing known errors so they wouldn't fail the build).
- I think the reason I fail early here is that by-ref vars can be defined on some functions, and invalid arguments could hold vars that were intended to be passed by ref. But, at a minimum, I shouldn't keep checking if any branch of a if/try/switch statement fails analysis.
- Not the fix you necessarily want, but the one that is consistent with Psalm's intended operation.
