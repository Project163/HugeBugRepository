- 1. When shuffle.partition = 8192, tuples in the same partition follows the connection like below: 

 hash(tuple x) = hash(tuple y) + n * 8192 

 2. In the next HashAggregate stage, tuples from the same partition need put into a 16K BytesToBytesMap (unsafeRowAggBuffer). 

 Here, the HashAggregate uses the same hash algorithm and seed as shuffle, it leads to all tuples will be hashed to only 2 different places actually. That's why hash conflict happens.
