Title

Browser close

Description
Start SyncThing, browser opens (if it was previously closed). Your tabs open, including one for SyncThing.
Close SyncThing. Entire browser goes away. I would not expect to lose my browser because I closed the app which spawned one tab in it.

Perhaps SyncThing should just leave the browser alone, or start it via xdg-open backgrounded so it doesn't die when SyncThing dies.
Discussion
- Uncheck "Start browser" in the GUI; syncthing now leaves the browser alone.
- But I want it to start the browser admin thing, I just don't want it to close the entire browser when it exists.
- ... [Middle Discussions Snipped for Brevity] ...
- Confirmed. No immediate idea why or how to fix it... Process tree doesn't show the browser as a child of syncthing (i.e. it is in the background).
- OK, so apparently this is a shell feature. When you hit Ctrl-C, the shell sends the termination signal to not only the foreground process (syncthing), but every program in the same process group. The process group is inherited from parent to child process. In this case, syncthing started xdg-open and xdg-open started the browser, so when you Ctrl-C syncthing the shell helpfully also terminates the browser.

This is fixable by starting xdg-open in it's own process group. I'll fix that.
