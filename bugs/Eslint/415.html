Title

no-shadow: Duplicated error messages

Description
Now it seems that `no-shadow` rule outputs several identical error messages if variable was shadowed several times:

```
js
var a = function(a) {
    return function(a) {
        return function() {
            var a = 123;
... [Log Snipped] ...
    };
};
```

```
  4:17  error  a is already declared in the upper scope  no-shadow
  5:20  error  a is already declared in the upper scope  no-shadow
  5:20  error  a is already declared in the upper scope  no-shadow
  7:16  error  a is already declared in the upper scope  no-shadow
  7:16  error  a is already declared in the upper scope  no-shadow
  7:16  error  a is already declared in the upper scope  no-shadow
```

I suppose there should be only three non-duplicated messages
Discussion
- You're suggesting we only report the shadowing of the nearest declaration?
- I suggest that errors should be 

```
  4:17  error  a is already declared in the upper scope  no-shadow
  5:20  error  a is already declared in the upper scope  no-shadow
  7:16  error  a is already declared in the upper scope  no-shadow
```

As I see in code, rule does not provide any info about which upper declaration was shadowed, only which variable shadows it. I suggest to output only first case when variable shadows any upper declaration, because messages are identical if there are several cases.
- ... [Middle Discussions Snipped for Brevity] ...
- FWIW I think reporting all instances of a shadowed var is a good thing. I know all areas to fix rather than fixing one, only to find another, and another, etc.

Should this be an option for the rule? Something like `suppressDuplicates`
- All of them are going to be reported, just not for each instance. If you look at the example above and expected result, you can see that all of the instances of shadowing is reported, but current version reports each shadowing issue for each individual error (so geometric progression).
