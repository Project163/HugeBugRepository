Title

groovyc should emit errors when @Override is not respected

Description
The following compiles without warning or error: 

  
  class  OverrideAnnotatationTest {
    @Override
    def notOverriden() {}
}
Discussion
- Linking to existing issue wrt properties
- The other question is whether to support a "Java 5" type mode where @Override wouldn't be allowed for interfaces but just super classes. I think we should avoid unless someone has a compelling reason.
- ... [Middle Discussions Snipped for Brevity] ...
- Jeff noted the following fails (ie. compilation error), although I believe it should be allowed: 
  
  interface  Foo {
    void doit( String  s)
}

 class  MyFoo  implements  Foo {
    @Override
    void doit( String  s =  null )
}
- normally we said an annotation used on methods with default arguments are used on all of the generated methods. Based on that, an error message about doit() not overriding anything would be right.
