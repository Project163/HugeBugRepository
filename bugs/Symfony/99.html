Title

[Form] PropertyPath::writeProperty() throws exceptions on non-public properties

Description
Currently the `Symfony\Component\Form\Util\PropertyPath::writeProperty` method performs a series of checks to determine which way to set the property on the active object. In particular, it checks whether a `setPropertyName()` method exists and if it does then it checks to see if that is a public method. This takes place before trying other methods such as a magic `__set()` method or a public property of that name on the object.

This means that if your object only exposes the magic `__set()` method, but uses the `setPropertyName()` methods internally as protected member methods, the `writeProperty()` method will detect that it can't access the `setPropertyName()` method first and throw an exception.

This behaviour is incorrect, as while it is useful in some cases to detect a potential mistake, an external class should not stop working due to the internal behaviour of an object.

These checks should be removed, and possibly detection of whether these methods exist but are inaccessible added to the final `InvalidPropertyException`.
