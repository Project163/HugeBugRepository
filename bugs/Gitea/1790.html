Title

Arch package registry: client error when two versions of a package are present

Description
### Description

When a new version of a package is added, the database includes both old and new versions. This confuses pacman client. 

```
error:   database is inconsistent: version mismatch on package  
```
The default core and extra repos include only the latest version of each package.

### Gitea Version

1.23.3

- Or maybe pacman is just designed that way: it expects the package database should only have one version?
- I think it is by design. In each db, only one version of the packages is supposed to be present. `libalpm` is the official library to work with databases. The function signature below to get a package does not have version parameter. [URL]
```
alpm_pkg_t * alpm_db_get_pkg (alpm_db_t * db, const char * name)
```

Different versions can be in different databases. E.g. `testing` can have newest version and `core` can have current version. But within one database, only one version is expected. 

when there is a need to have both older and newer version at the same time, the package name is changed. E.g. [Link: postgresql] and [Link: postgresql-old-upgrade]
