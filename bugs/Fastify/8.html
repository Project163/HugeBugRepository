Title

Schema with key or id already exists

Description
Related issue #922. @delvedor.

I don't know if it's a bug. Or may be it's just a limitation of schemas.
Seems the root cause is quiet similar. If there are 2 or more schemas that depend on each other are defined using `allOf`, e.g.:
```
js
app.addSchema({
  $id: 'first',
  type: 'object',
  properties: {
... [Log Snipped] ...
  ],
});
```

then if `first` schema will be used after `second` fastify will throw exception:
```
Error: schema with key or id "first" already exists
```
If schema "usages" will go in sequential order, then app will start without any exceptions. See full example below:

#### What are you trying to achieve or the steps to reproduce?

```
js
const fastify = require('fastify');
const app = fastify({
  logger: {
    level: 'info',
... [Log Snipped] ...
  }
})();
```

#### What was the result you received?

App schema validation fails. App doesn't start.
```
Error: schema with key or id "first" already exists
```

Swapping `get` and `patch` methods "solves" issue.

#### What did you expect?

Order of using schemas that depend on each other should not affect app.

#### Context

* *node version*: 9
* *fastify version*: 1.8.0
