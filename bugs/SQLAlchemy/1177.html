Title

1.4.X error when using schema translations on mssql

Description
On mssql server it is no longer possible to use `schema_translate_map` to utilise a single declarative model across multiple tables if they exist inside different databases on the server. This is due to residual `[` `]` characters being placed around the translation in the compiled sql.

I cut this down as much as I could and validated I can reproduce it on a fresh development database.
The connection is started in `master` and the `example` table translation is to the `dbo` schema in the `testing` database.

**Additional context**
I understand this may be a bit of a abnormal usage pattern, to isolate tenancy across databases rather than just to the schema level, but I didn't see any explicit change note to indicate an intended change in behaviour around this. 

I traced it through and can see prior to 1.4 the compiled sql string that gets executed is:

`SELECT TOP 1 testing.dbo.example.id AS example_id FROM testing.dbo.example`
