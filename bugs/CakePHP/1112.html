Title

TypeError (strlen) in CsrfProtectionMiddleware

Description
### Description

Since I'm unable to re-open previous ticket on this ( #15868 ), i'm opening new one

Fix that was provided in #15920 addresses the correct behavior for re-generating token on GET requests, if current value is invalid/unexpected

However that did not fix (as we found out today in testing) the TypeError that is thrown instead of expected InvalidCsrfTokenException
```
error: [TypeError] strlen() expects parameter 1 to be string, bool given in /var/www/app/vendor/cakephp/cakephp/src/Http/Middleware/CsrfProtectionMiddleware.php on line 345
```

In current version of [URL]

To reproduce:
1) Request is POST/PUT/PATCH
2) cookie contains no data or data that are not valid per `isHexadecimalToken` call
3) Line 343 will attempt to decode the data as base64 encoded value
4) base64_decode with param strict=true will return "false" (bool) for invalid base64 data
5) Line 345 assumes the $decoded contains string (strlen call), however that contains boolean
6) Instead of " return false;" we hit TypeError and subsequently InvalidCsrfTokenException on line 394 is never created/thrown

Proposed solution:
Replace (in _verifyToken procedure)
```php
        if (strlen($decoded) <= static::TOKEN_VALUE_LENGTH) {
            return false;
        }
```
with this
```php
        if (!is_string($decoded) || strlen($decoded) <= static::TOKEN_VALUE_LENGTH) {
            return false;
        }
```

### CakePHP Version

4.2.10

### PHP Version

7.4.28
