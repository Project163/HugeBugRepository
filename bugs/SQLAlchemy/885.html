Title

Core expression output by Query don't track the ORM entities from which they originated which is needed for session.get_bind() context

Description
The [Link: CTE example code in the Query API docs] fails with an `UnboundExecutionError` when the session is configured with `binds={Base: engine}` rather than `bind=engine`.

Full working example:

```
python
from sqlalchemy import Column, Integer, String, create_engine, func
from sqlalchemy.ext.declarative import declarative_base
from sqlalchemy.orm import aliased, sessionmaker

... [Log Snipped] ...
if __name__ == '__main__':
    q.all()                     # !! UnboundExecutionError
```
Discussion
- this is not mysterious because the query being run is a Core expression language construct and has no ORM entities within it.   if you ran session.execute(select([Part])) or session.query(Part.__table__) you'd get the same thing.  

it's not that this is an invalid use case however, it would be nice if given a binds mapping that doesn't include any Table objects, it extrapolates them from the ORM mapped classes it has, though in this case just giving it Base doesn't really give it enough information to figure that out unless additional assumptions about declarative bases were added.

another way this might be considered to be more correct would be that ORM annotations from the original Part columns would be fully propagated outwards as the Query builds off Core subquery objects so that the original mappings were intact.   This is probably where this should happen since Query sends to Session the context.

The reality is that the "binds" system with Session is not very widely used as it is more for the niche case that one has a single Session dealing with vertically partitioned classes across multiple database engines.
