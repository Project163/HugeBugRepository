Title

Logging stops when syncthing restarts after an automatic update

Description
Hello,

It seems that when syncthing restarts after an automatic update, the restarted monitor stops writing to stdout. As I stated in [URL] this seems problematic as automatic updates are frequent, and the logs after such updates can be useful.

In a quick test I ran (launching an outdated `./syncthing`), after the update my terminal goes back to the prompt, while syncthing has correctly restarted and is running in the background.

``` bash
[XXXXX] 08:48:32 INFO: Automatic upgrade (current "v0.11.18"   socket:[1095944]
lrwx------ 1 hippo hippo 64 Aug 13 08:48 9 -> anon_inode:[eventpoll]
```

After update:

```
bash
hippo ~ $ ps aux | grep "[s]yncthing"
hippo     6929  0.4  0.5 192048  5048 pts/10   Sl   08:49   0:00 ./syncthing
hippo     6934  100  3.0 362948 30500 pts/10   Sl   08:49   0:07 ./syncthing
hippo ~ $ ls -l /proc/6929/fd
... [Log Snipped] ...
lrwx------ 1 hippo hippo 64 Aug 13 08:49 8 -> socket:[1096705]
lrwx------ 1 hippo hippo 64 Aug 13 08:49 9 -> anon_inode:[eventpoll]
```
Discussion
- After the fix, on my machine (linux 64bit), the monitor correctly restarted after the automatic upgrade from 0.11.21 to 0.11.22. It kept the same PID and kept writing to stdout.

Thanks, it seems to work! :D
