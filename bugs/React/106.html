- I just tried this briefly. With `webdriver-jasmine:saucelabs_ios5` things work ok if `ReactWebWorker-test` is the only one enabled. If all tests are enabled, webworker spawn is deferred for some reason until other tests, including reporting, are run, and it confuses the test runner. 

If I disable the `ReactWebWorker-test` things work quite ok, but I see `Fatal error: Condition wasn't satisfied!` error at the end. It is somehow related to [URL] , perhaps with many tests on that platform POSTs duplicate/error and `postDataToURL.running` at [URL] won't get back to zero, or something.

With `webdriver-jasmine:saucelabs_ios6_1` I see some POSTs to `[URL] from time to time, I don't know if they affect something when simulator/webdriver is used. The test runner gets somehow stuck and doesn't poll for `postDataToURL.running <= 0`, but doesn't error with timeout either.
