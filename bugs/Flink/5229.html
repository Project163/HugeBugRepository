- This one is really strange: 

 Usually, when we trigger a checkpoint, we see some actions on the source 
  
 22:24:51,290 [    Checkpoint Timer] INFO  org.apache.flink.runtime.checkpoint.CheckpointCoordinator    [] - Triggering checkpoint 1 (type=CHECKPOINT) @ 1616883891289 for job  .
22:24:51,290 [SourceCoordinator-Source: source] INFO  org.apache.flink.test.checkpointing.UnalignedCheckpointTestBase [] - snapshotState EnumeratorState{unassignedSplits=[], numRestarts=0, numCompletedCheckpoints=0}
22:24:51,291 [Flink Netty Server (0) Thread 0] TRACE org.apache.flink.runtime.io.network.logger.NetworkActionsLogger [] - [Source: source (2/5)#0 ( )] PipelinedSubpartition#pollBuffer Buffer{size=38, hash=924008396} @ ResultSubpartitionInfo{partitionIdx=0, subPartitionIdx=0}
 
  

 In this case, after checkpoint 11 is triggered nothing happens.  

  
 22:24:54,694 [    Checkpoint Timer] INFO  org.apache.flink.runtime.checkpoint.CheckpointCoordinator    [] - Triggering checkpoint 11 (type=CHECKPOINT) @ 1616883893885 for job  .
22:24:54,694 [ failing-map (5/5)#4] INFO  org.apache.flink.runtime.taskmanager.Task                    [] - failing-map (5/5)#4 ( ) switched from CREATED to DEPLOYING.
 
  

 Actually, it should have been canceled, as obviously not all tasks are running similar to 

  
 22:24:51,044 [    Checkpoint Timer] WARN  org.apache.flink.runtime.checkpoint.CheckpointCoordinator    [] - Failed to trigger checkpoint for job  .)
org.apache.flink.runtime.checkpoint.CheckpointException: Checkpoint triggering task Source: source (1/5) of job   has not being executed at the moment. Aborting checkpoint. Failure reason: Not all required tasks are currently running.
 
  

 I'm currently assuming that there is a race condition in the code of   FLINK-21067  .
- I think that checkpoint 11 should not be aborted. A checkpoint (triggering) is aborted if:  
 
	 any of the tasks are not even CREATED (executionAttemp == null on JM) - not the case here 
	 any of triggering tasks (sources) hasn't been started - but failing-map is not the source 
 

 But probably the issue is in the network/task - if non-source task in CREATED/DEPLOYING state doesn't reject the checkpoint. 

   

 After increasing test timeout from 1 to 5 minutes I don't see this issue on AWS (haven't parsed all the logs yet). 

   

 And probably we should decrease checkpoint timeout in UC IT case settings? IIUC, the default is currently used, which is 10 minutes. 

 WDYT?
