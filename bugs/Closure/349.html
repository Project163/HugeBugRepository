Title

Global Constructors are not always properties of the global (window)

Description
What steps will reproduce the problem? 
Compile the following code using Advanced Optimizations -
if (window.FileReader) console.log(new window.FileReader());

What is the expected output?
window.FileReader&&console.log(new window.FileReader());

What do you see instead?
window.a&&console.log(new window.a);

What version of the product are you using?
Closure Compiler v20140110.

On what operating system?
Windows 7 Enterprise 64 bit, Java(TM) SE Runtime Environment (build 1.7.0_51-b13).

 Please provide any additional information below. 

I expect any global constructor (or variable, or whatever) to also be defined on window, since it is the global in browsers.
If you want Closure Compiler to be node.js compatible (or any other ECMAScript based environment), a --browser flag can be added (or --global window, or whatever).

I see that some externs define stuff as global variables as well as properties of Window and some are not. I cannot think of a reason for which this duplication is even needed and not automatically assumed at the compiler level.
Discussion
- It's not needed, it just happens to be how the compiler is working now. We'd like to make all global variables in externs properties of the global object automatically, but until then, feel free to submit patches duplicating the definitions for the ones you care about.
- Would it be acceptable if I create patches for all of the externs files that essentially duplicate everything?

I had a production bug due to this issue, the point of this issue is to eliminate such bugs before the fact.
