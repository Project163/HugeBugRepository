Title

Master folder on Linux shared to Macos spurious "out of sync"

Description
This one is easy for me to reproduce... 
(Both machines have ST0.14.4 running.)
- Create empty folder master on Linux (I tried ext4 and vintage ext3 filesystems, no difference in result.)
- Share that master to a MACOS box (with filevault enabled, didn't test on non-filevault fs).
- Create a file on the master "echo >bazbaz"

"bazbaz" is copied to the mac fine, but once the mac does its periodic scan, the
linux box will show "out of sync" with "override changes" button lit up. Once this happens
the folder is essentially "stuck" until you hit the override button. No changes occurred on the
Mac. Since there were no changes on the mac, I didn't expect the "out of sync" to pop up.
Once I hit the override changes, the out-of-sync goes away and doesn't appear to come back
for that file (though subsequent new files will cause it to pop up again.)
Maybe something to do with the new higher-res file times?

This problem didn't exist in 0.13.10.
### Version Information

Syncthing Version: 0.14.4
OS Version: ubuntu 14.04/MacOSX (whatever the latest is)
