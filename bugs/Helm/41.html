Title

helm 3.0.3 not rendering in values file when using starters

Description
We use some starters for creating some helm charts automatically in our CI/CD pipelines.

Let's image that we have a test starter with these two files among others:

* Chart.yaml:
```yaml
apiVersion: v2
helm chart
name:  
version: 0.0.1
```
* values.yaml:
```yaml
# Chart example
#
 :
  port: 8080
  environment:

resources: {}
```
When creating the Chart with helm **v3.0.2**:

```shell
$ helm version
version.BuildInfo{Version:"v3.0.2", GitCommit:" ", GitTreeState:"clean", GoVersion:"go1.13.5"}

$ helm create -p test example
Creating example
```
The chart and value files are rendered like this:

```
shell
$ cat example/Chart.yaml
apiVersion: v2
appVersion: 0.1.0
A Helm chart for Kubernetes
... [Log Snipped] ...
  port: 50051
resources: {}
```
That it is the expected behavior.

When creating the chart with helm **v3.0.3**:

```shell
$ helm version
version.BuildInfo{Version:"v3.0.3", GitCommit:" ", GitTreeState:"clean", GoVersion:"go1.13.6"}

$ helm create -p test example
Creating example
```
The output files
```
shell
$ cat example/Chart.yaml
apiVersion: v2
appVersion: 0.1.0
A Helm chart for Kubernetes
... [Log Snipped] ...

resources: {}
```

That it is not the expected behavior, I would expect in the values file  that ` ` would be rendered to `example`.
Discussion
- When #6951 was fixed via #7201 the side affect is this bug.
