Title

unable to set an option to have % ignore \( \{ \[ \] \} \)

Description
In original vim, having 'cpoptions' not have M would cause % to skip over backslashed paren-like chars. This is no longer the case: neovim persists in not skipping backslashed parens whether or not M is in 'cpoptions'.
Discussion
- Looks like this bug is caused by the % as redefined by the automatically loaded plugin matchit.vim, and is not present in the pristine %.

Disabling the loading of matchit.vim (with 'let loaded_matchit = 1' in one's .nvimrc) takes care of this.

Perhaps the automatic loading of matchit.vim shouldn't be allowed.
- This should probably be fixed by modifying the matchit plugin.
- Only upstream change to matchit was in vim/vim@fc39ecf, not related to this issue. So this is a vim bug.
- We note in `:h vim-differences` that matchit gets sourced by default and it just happens to remap `%`.
