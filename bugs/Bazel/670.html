Title

Error reporting: help users understand they are missing a transitive WORKSPACE dep

Description
In rules_typescript and rules_nodejs we are increasingly picking up transitive dependencies on more workspaces. This makes the upgrade path very confusing for our users.

For example, today I got this report:
```
Hey so I just rebased to master for rules_nodejs and now im getting this error for the examples/program tests

fabian@fabian-desktop:~/Documents/rules_nodejs/examples/program$ bazel test :test
ERROR: Failed to load Skylark extension '@bazel_skylib//:lib.bzl'.
It usually happens when the repository is not defined prior to being used.
Maybe repository 'bazel_skylib' was defined later in your WORKSPACE file?
ERROR: cycles detected during target parsing
```

The last line talks about cycles detected, which is extra scary, and it suggests maybe an ordering problem. It doesn't say anything about the most common case which is that you just don't have this workspace dependency declared at all.
Also it doesn't say where the load statement was.

I think a better error would look like
```
ERROR: Failed to load dependency '@bazel_skylib'.
Loaded from @build_bazel_rules_nodejs//internal:node_repositories.bzl line 6

Bazel does not automatically include repositories which are transitively required.
You must fetch the 'bazel_skylib' repository with a statement like `http_archive` in your WORKSPACE file.
This may also happen when the repository is not defined prior to being used.
Maybe repository 'bazel_skylib' was defined later in your WORKSPACE file?
```
