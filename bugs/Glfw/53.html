Title

glfwCreateWindow does not restore previous context

Description
When using multiple windows on OS X Yosemite, creating a fullscreen window after non-fullscreen windows seems to destroy existing OpenGL context.

For example, the following code creates a non-fullscreen window `w0`, a fullscreen window `w1`, and a non-fullscreen window `w2`:

```
#include  
#include  

int main()
{
... [Log Snipped] ...
        return 0;
}
```

The code outputs:

```
2.1 NVIDIA-10.2.7 310.41.25f01
(null)
2.1 NVIDIA-10.2.7 310.41.25f01
```

After the creation of `w0`, a valid OpenGL context is available as expected and `glGetString(GL_VERSION)` gives the correct OpenGL version string.  However, with the creation of `w1`, the existing OpenGL context gets destroyed (or become inactive).  Calling OpenGL functions may crash the program.  And `glGetString(GL_VERSION)` gives a `null`.  Creating a non-fullscreen window `w2` fixes this problem and a valid OpenGL context becomes available again.

This problem can also be fixed by calling `glfwMakeContextCurrent(w1);` right after the creation of `w1`.  However, is this an expected behavior?  Or is it a bug?
Discussion
