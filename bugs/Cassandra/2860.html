Discussion
- The hinted handoff manager is checking for hints to see if it needs to pass those off during 
the decommission so that the hints don't get lost.  If there are a lot of hints, or 
a bunch of tombstones, or something the query can timeout. 

 Raising the read timeout period on the nodes before decommissioning them, or manually deleting the hints CF, should 
most likely get past this.  If you delete the hints, you would then want to make sure you ran a full cluster repair when you are done with the decommission, to propagate data 
from any hints you deleted.
- Instead of trying to read if there are any hints (as it may timeout doing a range scan and so on), let's just flush the memtable for hints and stream anything we have, which may be zero files - StreamPlan/StreamSession is cool with no files for transfer (StreamSession simply exits). Simple patch attached to flush the hints rather than check if hints table > 0.
