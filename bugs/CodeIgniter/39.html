Title

Query Builder where_in

Description
When query builder cache is enabled, (`$this->db->start_cache()` [Link: Documentation]) any data added via `$this->db->where_in()` does not take into account any saved cache.

I believe I have tracked this down to [Link: here] in the DB_query_builder class.

Should this be 

`$prefix = (count($this->qb_where) === 0`**`&& count($this->qb_cache_where) == 0`**`) ? $this->_group_get_type('') : $this->_group_get_type($type);`

instead of

`$prefix = (count($this->qb_where) === 0) ? $this->_group_get_type('') : $this->_group_get_type($type);`

This issue only appears when adding `$this->db->where_in()` after a query has been ran.
Example

``` $this->db->start_cache();
$this->db->where('my_field', 'my_val');
$query = $this->db->get('my_table'); // Works 
$this->db->where_in('my_new_field', array('1','2','3'));
$query2 = $this->db->get('my_table'); // Fails
$this->db->stop_cache()
```

The documentation does not state that the where_in can can cached (only select, from, join, where, like, group_by, having, order_by, set). However the code in the DB_query_builder class adds the query into the cache [Link: see here] if it's enabled.
