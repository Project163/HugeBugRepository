Title

json facet api returning inconsistent counts in cloud set up

Description
While using the newly added feature of json term facet api ( [URL] I am encountering inconsistent returns of counts of faceted value ( Note I am running on a cloud mode of solr). For example consider that i have txns_id(unique field or key), consumer_number and amount. Now for a 10 million such records , lets say i query for  

 q= : &rows=0& 
 json.facet={ 
   biskatoo:{ 
	 type : terms, 
       field : consumer_number, 
       limit : 20, 
	sort :  
{y:desc}
 , 
	numBuckets : true, 
	facet: 
{
	 y : "sum(amount)"
       }
    } 
 } 

 the results are as follows ( some are omitted ): 

 "facets":{ 
    "count":6641277, 
    "biskatoo":{ 
      "numBuckets":3112708, 
      "buckets":[ 
{
          "val":"surya",
          "count":4,
          "y":2.264506}
 , 
       
{
          "val":"raghu",
          "COUNT":3,   // capitalised for recognition 
          "y":1.8}
 , 
         
{
          "val":"malli",
          "count":4,
          "y":1.78}
 ]}}} 

 but if i restrict the query to  

 q=consumer_number:raghu&rows=0& 
 json.facet={ 
   biskatoo:{ 
	 type : terms, 
       field : consumer_number, 
       limit : 20, 
	sort :  
{y:desc}
 , 
	numBuckets : true, 
	facet: 
{
	 y : "sum(amount)"
       }
    } 
 } 

 i get : 

   "facets":{ 
    "count":4, 
    "biskatoo":{ 
      "numBuckets":1, 
      "buckets":[ 
{
          "val":"raghu",
          "COUNT":4,
          "y":2429708.24}
 ]}}} 

 One can see the count results are inconsistent ( and I found many occasions of inconsistencies). 

 I have tried the patch  [URL] but still the issue seems not resolved
Discussion
- Hi Vamsi, 
The behavior you are seeing is because we haven't yet implemented facet refinement.  Currently, the distributed statistics are a result of simply combining the top N buckets from each shard, which can result in a small amount of error.  It's definitely on the roadmap to implement this!
- This doesn't seem to be too important. 
Elasticsearch has never had exact counts, and no one seems to care.
