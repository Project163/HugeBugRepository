Title

sync fails to remove directories on the destination that do not exist on the source

Description
#### What is the problem you are having with rclone?

I have noticed that under some circumstances (in my case, using a crypted remote) `rclone sync` fails to remove directories that should be removed since they do not exist on the source.  In my particular circumstance, it seems like the problem is that `rclone sync` uses something like the `rmdir` command, which (somewhat silently) fails if the directory has any contents left, even broken contents that `rclone` is ignoring.

I think this could be fixed by making the `sync` use `purge` functionality instead of `rmdir` to remove directories that don't exist on the source.

Here is the output from the `rclone sync` command, which claims that it has deleted 23 directories.

```
Transferred:              0 B / 0 B, -, 0 B/s, ETA -
Checks:            296345 / 296345, 100%
Deleted:                0 (files), 23 (dirs)
Elapsed time:     13m50.5s
```

However, a subsequent run of the sync without any changes being made still shows it trying to remove the 23 directories it claimed it had removed on the last run.  Note that no warnings or errors were reported at all (which is a separate problem).

So I ran again with `-v` to see what was going on with the directories it thought it was removing and got messages like this:

```
2022-09-12 16:44:10 INFO  : work/new/waiting/Johann_Sebastian_Bach_Canadian_Brass_-_Art_Of_The_Fugue: Removing directory
2022-09-12 16:44:10 INFO  : work/new/waiting/Johann Sebastian Bach; Canadian Brass - Art of the Fugue: Removing directory
```

Note that again, even with `-v`, no warnings or errors are reported with the supposedly removed directories.
