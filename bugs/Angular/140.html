Title

Support using transformers + Dartium in checked mode

Description
Currently, we fail with "not implemented" thrown by `AbstractChangeDetector.checkNoChanges` on transformed code in Dartium running in checked mode. This is because transformer decides whether to generate no-change checks separately from Dartium. Instead, we should _always_ generate checking code, guarded by `assert`. This way, `dart2js` can tree shake these checks off for production, and the assertions will behave consistently following the checked mode option in Dartium.
