Title

[YSQL] Shutdown race on shutdown_done flag

Description
Jira Link: [Link: DB-3536]
If there are 2 calls to `YBOnPostgresBackendShutdown()` in quick succession, then it's possible for both of them to read `shutdown_done=false` and both will end up calling `YBCDestroyPgGate()`

Might also be good to just change the FATAL to a DFATAL.

cc @ndeodhar
Discussion
- In `yb/yql/pggate` there is the singleton object `pggate::PgApiImpl`.
Now it's prohibited from double deletion twice:
1. On  `YBCInitPgGate`/`YBCDestroyPgGate` level via atomic `pgapi_shutdown_done`. But it calls `LOG(FATAL)` in case of second deletion.
2. On `YBOnPostgresBackendShutdown` level via non thread-safe static boolean variable `shutdown_done`. On the variable we have a race.

Solution: to fix & simplify the code let's keep the only one prohibition via atomic. The second try to delete the singleton should be carefully handled as NoOp (with an info warning).
