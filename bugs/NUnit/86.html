Title

Specifying .nunit project and --framework on command line causes nunit3-console.exe to crash.

Description
The command line that is run:

``` ShellSession
C:\Program Files (x86)\NUnit.org\nunit-console\nunit3-console.exe" "I:\OpenSource\GitHub\nunit\EngineAndConsoleTests.nunit" --trace=verbose --framework=v3.0
```

The output that is received. 

```
ShellSession
NUnit Console Runner 3.0.5790
Copyright (C) 2015 Charlie Poole

Runtime Environment
... [Log Snipped] ...

Could not load file or assembly 'nunit.framework' or one of its dependencies. The system cannot find the file specified.
```

Running the command line with the test library directly and the framework specified gives. 

``` ShellSession
C:\Program Files (x86)\NUnit.org\nunit-console\nunit3-console.exe" "I:\OpenSource\GitHub\nunit\bin\Debug\nunit.engine.tests.dll" --trace=verbose --framework=v3.0
```

```
ShellSession
NUnit Console Runner 3.0.5790
Copyright (C) 2015 Charlie Poole

Runtime Environment
... [Log Snipped] ...
Errors and Failures
...
```

I am not certain if this is by design, and NUnit is simply missing a guard condition to not allow .nunit projects to not be specified with the framework option.

Should the framework command be allowed to be specified with a nunit project, or is this an invalid test of the feature? I also have a sense that the error being reported is a path issue with the tests files themselves.
