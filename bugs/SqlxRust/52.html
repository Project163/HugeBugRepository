Title

` ::compatible()` is wrong?

Description
### Bug Description
I'm running MariaDB and have a table with a `UUID` column. When trying to fetch a row from this table and decoding the column into `uuid::Uuid`, it complains saying it expected 16 bytes, but got 36. This sort of makes sense, as I inserted the row using a string literal of a hyphenated UUID. When I try to use `uuid::fmt::Hyphenated` instead, it says the types aren't compatible. When using the `query!()` macro, it infers the type to be `Vec `, and decoding that as UTF-8 yields the expected string value I originally inserted. Maybe I'm just using these types incorrectly?

From what I can see in `sqlx-mysql`, `uuid::Uuid` expects 16 bytes, and `uuid::fmt::Hyphenated` just forwards to `str`? But `str` says it isn't compatible with anything that has a `BINARY` flag set, which the returned column does in my case...
