Title

Qute: Template extensions regresion in Quarkus 2.10.0

Description
### Describe the bug

The following code works with Quarkus 2.9.x but it is not working with Quarkus 2.10.0

```
java

import io.quarkus.qute.TemplateExtension;

import java.time.format.DateTimeFormatter;
... [Log Snipped] ...
    }
}
```

```html
 {datetime:formatDate(it.creationDate)} 
```            

creationDate has type ```java.time.LocalDateTime``` 

If I replace TemporalAccessor with LocalDateTime template extension is working as expected, but now it is not working when I'm using interface in extension method.

### Expected behavior

This extension should be working not only with classes but also with interfaces.

### Actual behavior

Quarkus  is throwing exception

```
{datetime:formatDate(it.creationDate)}: No matching namespace [datetime] extension method found
```

Discussion
- The regression was very likely caused by [Link: this optimization]. Previously, we always analyzed the type closure of the matching type and one of the consequences was that all the types (`java.time.LocalDateTime`, `java.time.temporal.Temporal`, `java.time.temporal.TemporalAccessor`, `java.time.temporal.TemporalAdjuster` and `java.time.chrono.ChronoLocalDateTime` in this particular case) were additionaly indexed by the bean archive index.

We need to find a way to keep the optimization but make sure the type closure is indexed efficiently.
