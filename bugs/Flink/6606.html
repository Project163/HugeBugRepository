Title

Incorrect async to sync lookup fallback path of LegacyTableSourceTable

Description
FLINK-28779   introduces a new lookup hint, for LegacyTableSourceTable interface, it defines only one lookup capability of either sync or async is supported by 'isAsyncEnabled', but we add a unnecessary fallback path to fetch both async and sync lookup in `LookupJoinUtil`, this should be fixed. 
  
 
 if  (tableSource.isAsyncEnabled()) {
asyncLookupFunction = tableSource.getAsyncLookupFunction(lookupFieldNamesInOrder);
}
syncLookupFunction = tableSource.getLookupFunction(lookupFieldNamesInOrder);

 
  
 Once this was fixed, it can completely avoid create user lookup function instance to determine if async lookup is enabled for execution, this can make the exec lookup join node immutable and easier to maintain. 

 Also, since the new hint adds the capability of configuring async params on join level (different joins in same query may has different params), so the description of lookup join transformation should carry async params and retry strategy (which take effect in runtime) for easier debugging
