Title

Logical plan invalid state: duplicate uid in schema during self-join to get cross product

Description
Hi. 
Looks like   PIG-3020   
but works in a different way. 
Our pig version is:  
Apache Pig version 0.10.0-cdh4.2.0 (rexported)  
compiled Feb 15 2013, 12:20:54 

 Accoring to release note,   PIG-3020   is included into CDH 4.2 dist 
 [URL]

 The problem: 
We want to do self join to get cross-product 
  
 a = load  '/input'  as (key, x);

a_group = group a by key;
b = foreach a_group {
  y = a.x;
  pair = cross a.x, y;
  generate flatten(pair);
}

dump b;
 
  

 And an error: 
  
 ERROR org.apache.pig.tools.grunt.Grunt - ERROR 2270: Logical plan invalid state: duplicate uid in schema : 1-7::x#16:bytearray,y::x#16:bytearray
 
  

 Here is workaround   
  
 a = load  '/input'  as (key, x: int );

a_group = group a by key;
b = foreach a_group {
  y = foreach a generate -(-x);
  pair = cross a.x, y;
  generate flatten(pair);
}

dump b;
Discussion
- thanks for opening jira Sergey, took a look, not sure this is by design or not. Take a simpler case, we can do self-cross outside of foreach 
  
 a = load 'input' as (key, x);
b = cross a, a;
dump b;
 
  

 but do it in a foreach will fail 
  
 a = load 'input' as (key, x);
a_group = group a by key;
b = foreach a_group { y = cross a, a; generate y; }
dump b;
 
  

 although they fail with different error (Duplicate schema alias), but overall I think it is important to figure out why we have this kind of restriction within foreach ?
- The same fix as in   PIG-3020   needs to be made to LOCross. In fact,   PIG-3144   added a static helper function that fixes duplicate field uids to LogicalRelationalOperator. So we can simply call that function to fix field schemas in the getSchema() method of LOCross.
