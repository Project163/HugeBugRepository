Title

ACE editor prompts Scala keywords for auto-completion even in non-scala interpreters

Description
In non-scala interpreters like %sql %md, ctrl-. still triggers auto-completion with a list of scala keywords.
Discussion
- This is likely because the editor mode is never changed. 
From before,  
1. (start typing in cell) editor mode: scala 
2. (type %sql) editor mode: scala  - does not apply as expected 

 Whereas when loading a previous notebook for the expected editor mode is applied when the notebook is loaded, resulting in slightly different syntax highlighting in these two cases.
- The auto-completion is initialized in the paragraph.controller.js aceLoaded. Currently it looks like this: 
  
 $scope.aceLoaded = function(_editor) {
....
  $scope.editor.setOptions(
      {enableBasicAutocompletion:  true ,enableSnippets:  false , enableLiveAutocompletion: false });

    var  remoteCompleter = {getCompletions : function(editor, session, pos, prefix, callback) {...}};
   
   langTools.addCompleter(remoteCompleter);
}
 
  
 We can use  
  
 langTools.setCompleters([remoteCompleter]); 
  
  instead (e.g. not ADD but SET) to restrict the completion suggestions to those provided by the interpreters.  Also we should move the   
  
 enableBasicAutocompletion:  true   
  
  setting after the  
  
 langTools.setCompletters(..)  
  
  as suggested here:  [URL]

 The end configuration sequence would look like this: 
  
 $scope.aceLoaded = function(_editor) {
....
    var  remoteCompleter = {getCompletions : function(editor, session, pos, prefix, callback) {...}};
   
   langTools.setCompleters([remoteCompleter]);

  $scope.editor.setOptions(
      {enableBasicAutocompletion:  true ,enableSnippets:  false , enableLiveAutocompletion: false });
}
 
  

 Although this seem to resolve this issue i wonder if there is something else we should consider?
