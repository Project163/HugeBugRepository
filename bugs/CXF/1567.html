Title

Initial non-GET request returns 404 if it has query parameters

Description
Hello, I ran into a weird case where an initial HTTP non-GET request returns 404 if there happens to be query parameters in it. Basically, you can take the code below, start up a servlet container, and do the following curl commands: 

 > curl -v -X PUT  [URL] -d "Name" 
404 
> curl -v  [URL]
200 
> curl -v -X PUT  [URL] -d "Name" 
204 

 I tracked the problem down to ServletController:184 (in the 2.7.0 sources). I don't know why "updateDestination" is invoked only for GET, but this case works fine if it is invoked regardless of the method. Is there perhaps a problem in my configuration?
