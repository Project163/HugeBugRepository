- @zz85 Cool! That explanation of the curves and actions is so helpful. I was wondering about that.

The project I'm using THREE.Path in is a Canvas API for generating gcode. Since I'm already conforming to the spec I'd be more than happy to do the work that makes sense in 3js itself, especially since you have expressed interest in following html canvas. I think that is a great idea.

Although - I think there are aspects of Canvas that aren't going to carry over well to 3d, and it only makes sense now because it doesn't do much 3D. I'd much rather see the 3js Path support more 3D curves and I think you'll have API design issues with that.

e.g. If you used drawing functions, `lineTo(x,y)` becomes `lineTo(x,y,z)`, ok, that's compatible with 2D and 3D and elegant, but it breaks down when the dimensions aren't at the end of the arguments.
So, another option is to have separate `Path2` and `Path3` which have some of the same functions with different arguments, but you can see how that quickly get really bloated. Or just use objects with named properties (curve classes) and you can just add any `Curve` to any `Path`. Like you did! : )  Not to mention affine transformation, everything would need to be specifying which plane. These issue all arise because `CanvasRenderingContext2D` is really deeply designed for 2D only.

I think the way to get the familiar Canvas API is a separate `RenderingContext` that adds curves to its current path. And, beginPath() replaces the current path with a `new Path()`.
