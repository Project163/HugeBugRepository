Title

Disabling relays is ignored

Description
```
jb@syno:~/s/g/s/s/test $ grep relay h1/config.xml
         10 
         false 
jb@syno:~/s/g/s/s/test $ syncthing -home h1 | grep relay
[I6KAH] 08:30:20 INFO: Joined relay relay:// :22067/?id=7ZBBJPN-D6LZI22-XYRSXC3-THRJHWO-6C62DOP-AADPIRH-EYXKFRB-JSAH5AR&pingInterval=1m0s&networkTimeout=2m0s&sessionLimitBps=0&globalLimitBps=4194304&statusAddr=:22070&providedBy=vet
^C
```
Discussion
- So apparently `relaysEnabled` was deprecated, but it's still present in the XML config (lacks `,omitempty` tag). However, what is the intention for how the user should disable relaying? By changing the `default` listen address to `tcp:// :22000`? That's hardly discoverable :(

The config upgrade code must also take this into account, whatever we do here, so that the existing preference is retained.

To me, it seems like the simplest and cleanest solution is to resurrect the `relaysEnabled` option, and just have `default` not mean relays in that case. In fact, I'll prepare a PR for that for discussion, and if some better idea comes up in the meantime we can do that instead. :)
