Discussion
- I get this same error with the Hind Google font as well. I'm on MacOS 13.1 (Intel) and disabling Turbo fixes the bug.
- I believe I found the issue: only variable fonts have axes, but `next-core` is erroring even if non-variable fonts don't have axes, which ix expected behavior. I made a fix that only checks for axes on variable fonts and the issue was resolved for me locally.
