Title

implement defined behavior for aliased(aliased(cls))

Description
### Describe the bug

In SA1.3.x, querying an alias of an alias of a mapped class yielded a SELECT against only one table, whereas in 1.4.x, querying an alias of an alias of a mapped class yields a SELECT against a comma join of a table with itself. 

How do I reproduce the SA 1.3.x behavior in SA 1.4.x? 

### To Reproduce

```
python
import sqlalchemy as sa
from sqlalchemy import orm
from sqlalchemy import create_engine
from sqlalchemy.ext.declarative import declarative_base
... [Log Snipped] ...

print(s.query(a2))
```


### Error

In SA 1.3.x, the SQL rendered is:

```sql
SELECT user_1.user_id AS user_1_user_id, user_1.user_name AS user_1_user_name
FROM "user" AS user_1
```

In SA 1.4.x, the SQL rendered is (note the comma join):

```sql
SELECT user_1.user_id AS user_1_user_id, user_1.user_name AS user_1_user_name
FROM "user" AS user_1, "user" AS user_2
```

How do I produce the 1.3.x result in 1.4.x, assuming I am only given `a2`? 

### Versions

- OS: OSX
- Python: 3.8.2
- SQLAlchemy: 1.3.24 and 1.4.29
- Database: postgres
- DBAPI (eg: psycopg, cx_oracle, mysqlclient): psycopg

Discussion
- for now you can extract the mapper and always alias on that, this will work when given either the mapped class directly or an aliased:

```py
def safe_aliased(entity):
    return orm.aliased(sa.inspect(entity).mapper)

a1 = safe_aliased(User)
a2 = safe_aliased(a1)
```
