Title

Unexpected behaviour when using mixins containing media queries, especially if inside media query

Description
Hope the title is interesting enough! :-)

Given this LESS:

```
css
.nav-justified {
  @media (min-width: 480px) {
      display: table-cell;
... [Log Snipped] ...
  }
}
```

Output:

```
css
@media (min-width: 480px) {
  .nav-justified > li {
    display: table-cell;
  }
... [Log Snipped] ...
  }
}
```

The first two blocks are just as I'd expect, but notice two things:
- There's an empty media query.
- In the last block instead of the ".menu > li" selector the resulting selector is ".menu .nav-justified > li". I'd expect the resulting selector to be ".menu > li", just as in the second block.
Discussion
- I've run into a similar issue when mixing in a multi-selector rule with embedded media query. Trying to work around it made Issue #1508 obvious, even though it is present here too with the extraneous selectors in the resulting merged query.

Another example:

```
css
/* desktop size */
.rule-a-1,
.rule-b-1 {
    width: 10px;
... [Log Snipped] ...
    }
}
```

The expected output is

```
css
/* desktop size */
.rule-a-1,
.rule-b-1 {
  width: 10px;
... [Log Snipped] ...
  }
}
```

but instead the final media query is

``` css
@media screen and (max-width: 320px) and screen and (min-device-pixel-ratio: 2) {
  .rule-a .rule-a-2,
  .rule-a .rule-b-2 {
    background-size: 10px 10px;
  }
```

When I first bumped into this I notice the extraneous rules, but not the invalid media query. When I tried to work around this using AT import "someFile" screen and (max-width: 320px) the invalid media query remained.
- What you've shown is most possibly the same issue with the selectors getting mixed up. I'm happy though that the empty media query is fixed in 1.5 wip now.
- Found bug and fixed in 1.5.0.

empty media query was previously fixed in 1.5.0.
