Title

require'mymod' inside a luv callback might segfault

Description
- `nvim --version`: 0.5.0 or latest master
- Operating system/version: any
- Terminal name/version: any 
- `$TERM`: any

 
[ ] `vim -u DEFAULTS` (version: ) behaves differently: irrelevant, vim doesn't handle `require`

### Steps to reproduce using `nvim -u NORC`

use `require'mymod'` in a luv callback when `mymod` was not loaded since before.


### Actual behaviour
segfault [URL]
### Expected behaviour
no segfault

# Details

`require` invokes `nvim_get_runtime_file` which is marked as FAST. however as part as its implementation it uses regexes which can invoke `os_breakcheck` which must not be done in FAST functions.
