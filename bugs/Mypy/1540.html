Title

Crash if a class is generic over a PEP-695 parameter that has the same name as an old-style `TypeVar` that is also in scope and the old-style TypeVar has a bound which uses an unquoted forward reference

Description
**Crash Report**

This _feels_ quite specific, but I think it may come up a surprising amount as more and more people use [Link: codemods] to try to auto-upgrade their code to use PEP 695 in the coming years! Mypy crashes on this snippet:

```py
from typing import TypeVar

T = TypeVar("T", bound=Foo)

class Foo: ...
class Bar[T]: ...
```

The following things must all be true for the crash to occur:
- The global-scope TypeVar must have the same name as the type parameter used for `Bar`
- The global-scope TypeVar must have a `bound=` argument that uses a forward reference
- The forward reference in the global-scope TypeVar's bound _must be unquoted_. (For `.py` files, you generally need to quote all forward references, but this is not true for stubs.)

**Traceback**

```
pytb
% mypy foo.py --python-version=3.12 --show-traceback
foo.py:6: error: INTERNAL ERROR -- Please try using mypy master on GitHub:
[URL]
Please report a bug at [URL]
... [Log Snipped] ...
           ~~~~~~~~~~^^^^^^^^^^^^^^^^^^^^^^^^^^^^
AssertionError:
```

**To Reproduce**

Paste the above snippet into a `foo.py` file and run `mypy --python-version=3.12 foo.py --show-traceback`

**Your Environment**

- Mypy version used: `1.15.0+dev. `
- Mypy command-line flags: `--python-version=3.12 --show-traceback`
- Python version used: 3.13.1
