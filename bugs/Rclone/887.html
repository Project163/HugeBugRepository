Note the `Content-Encoding: aws-chunked` in the response. So what is happening is that with `--metadata` rclone is preserving the `Content-Encoding: aws-chunked` from the source and attempting to upload that to the destination.

Reading the docs here [URL] I think `aws-chunked` as a content encoding is internal use and we shouldn't be attempting to preserve it in the metadata. In fact AWS S3 doesn't preserve it in the Content-Encoding and you never see it, so I think technically speaking this is a bug in digital ocean. It shouldn't be putting `aws-chunked` into the `Content-Type`.

I made a workaround for this which removes `aws-chunked` from the `Content-Type:` whenever it sees it. Please give this a go.
