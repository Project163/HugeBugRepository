in this case, the code you've identified is a sort of one-line conditional that is common in many programming languages, but in Python once the ternary conditional was introduced, they became unnecessary, as the ternary operator ("foo if bar else bat") makes the intent much more clear.  In SQLAlchemy, most "return x or y" types of operations should be replaced with real ternaries and as you've observed, places where clause objects are checked need to be compared against None.  In this case, allowing a SQL expression for "offset" was a relatively late feature add, and additionally usage of "first()" did not expect that limit/offset would already be applied to the query.
