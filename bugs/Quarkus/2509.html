Title

Liquibase MongoDB migration fails on Quarkus upgrade from 3.21.4 to 3.26.3 for native test- MongoCommandException: no such command '$db'

Description
### Describe the bug

Liquibase MongoDB migrations fail after upgrading from Quarkus 3.21.4 to 3.26.3. 

In the attached minimal example project, we have two migration steps
```
xml
 
     

     
... [Log Snipped] ...
     
 
```

When run in the **native** test, the first changeset executes successfully, but the second changeset fails with a MongoCommandException stating "no such command: '$db'". This appears to be a regression in the Liquibase MongoDB extension where the `ext:runCommand` block is not properly parsing MongoDB update commands.

The error occurs specifically in changeset id="2" which contains an `ext:runCommand` with a MongoDB update operation. The same migration works perfectly in Quarkus 3.21.4.

### Expected behavior

Both Liquibase changesets should execute successfully as they do in Quarkus 3.21.4. The `ext:runCommand` should properly execute the MongoDB update command:
```
{
  update: "persons",
  updates: [{
    q: {addresses: null},
    u: {$set: {addresses: []}},
    multi: true
  }]
}
```

### Actual behavior

The application fails to start with the following error:
```
MongoCommandException: Command failed with error 59 (CommandNotFound): 'no such command: '$db'' on server localhost:64091
```

Only the first changeset (id="1") executes successfully. The second changeset (id="2") fails, preventing the application from starting completely.

### How to Reproduce?

Minimal reproduction case available at [Link: demo-quarkus-liquibase.zip].

Steps to reproduce the behavior:
  1. unpack the   provided zip
  2. Run: `./gradlew clean testNative -Dquarkus.native.enabled=true -Dquarkus.native.container-build=false -Dquarkus.package.jar.enabled=false`
 3. check the standard output of the generated `/build/reports/tests/testNative/index.html`
