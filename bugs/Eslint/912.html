Title

Bug: Auto Fix comma-dangle wipes file with 'always' and a final paren wrapped item with no comma

Description
**What version of ESLint are you using?**
2.10.2

**What parser (default, Babel-ESLint, etc.) are you using?**
None

**Please show your full configuration:**

``` json
{
  "rules": {
    "comma-dangle": ["error", "always"]
  }
}
```

**What did you do? Please include the actual source code causing the issue.**
I ran `eslint --fix commas.js`

**`commas.js`:**

``` js
module.exports = [
'good',
('bad')
];
```

**What did you expect to happen?**
An additional training comma added: `('bad'),`

**What actually happened? Please include the actual, raw output from ESLint.**
I got an empty file in commas.js. I've reduced the test case to a minimum, but this was happening in a large .jsx file, which also ended up empty.

Here's the `--debug` output:

```
eslint:cli Running on files +0ms
  eslint:ignored-paths Looking for ignore file in d:\git\eslint-bug +49ms
  eslint:ignored-paths Could not find ignore file in cwd +2ms
  eslint:glob-util Creating list of files to process. +1ms
  eslint:cli-engine Processing d:\git\eslint-bug\commas.js +4ms
... [Log Snipped] ...

✖ 1 problem (1 error, 0 warnings)
```

Note the _No source code to fix_ part after the 2nd pass

The parens around the final item are key - removing them makes everything work again.
