Title

Toggling HTTP/HTTPS breaks GUI/API

Description
Toggling the setting and saving the config in the GUI results in the log line:

```
[SYNO4] 20:46:01 WARNING: API: accept tcp  :8385: use of closed network connection
```

And then there is nothing listening on the GUI port any more.

v0.13.1
Discussion
- So now of course I can't reproduce this myself any more...
- I can get this same error / similar by rapidly setting `Use HTTPS for GUI` on and off or by rapidly switching between themes. It happens if you ignore the 'restart needed' warning message, and just keep saving settings.
- ... [Middle Discussions Snipped for Brevity] ...
- It's also worth noting that the issue comes and goes across page refreshes, until Syncthing is restarted.
- Right, part of the issue is that we hit the return at the top of `Serve()` in `gui.go`:

``` go
    if listener == nil {
        l.Warnln("No listener, so quitting");
        // Not much we can do here other than exit quickly. The supervisor
        // will log an error at some point.
        return
    }
```

Gives

```
[PFQTJ] 10:59:37 WARNING: API: accept tcp  :8080: use of closed network connection
[PFQTJ] 10:59:37 WARNING: No listener, so quitting
[PFQTJ] 10:59:37 WARNING: No listener, so quitting
[PFQTJ] 10:59:37 WARNING: No listener, so quitting
[PFQTJ] 10:59:52 WARNING: No listener, so quitting
... [Log Snipped] ...
[PFQTJ] 11:00:07 WARNING: No listener, so quitting
[PFQTJ] 11:00:07 WARNING: No listener, so quitting
```

That happens because `getListener` fails when it's called from `CommitConfiguration`: listen tcp  :8080: bind: Only one usage of each socket address (protocol/network address/port) is normally permitted.

... and that happens because the `TCPListener.Close()` docs have the following warning: Already Accepted connections are not closed. Indeed, `TCPListener.Serve()` doesn't return until after we tried and failed to call `getListener`.
