- Sure, I can take a look at this. I did come across similar problems while trying to get it to work with process isolation. I'd very much appreciate some feedback on some various workarounds that I had come up with and their various shortcomings:
1. Create a temporary file with the job code and require it in the coverage template. Problem: This will cause an include loop with PHPTs that test process isolation as `PHPUnit_Util_GlobalState::getIncludedFilesAsString()` will include this temporary file and there doesn't appear to be an easy way to blacklist this temp file.
2. Adjust the coverage template and use the `auto_prepend_file` ini directive to handle the coverage generation and saving.
   Problem: This will prevent PHPT tests from utilizing this directive in their INI sections

I had the ground work laid for 1, but didn't couldn't get around the process isolation issue.
