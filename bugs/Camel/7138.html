Title

camel-jbang - Transitive dependencies on plugins should use the parent artifact to manage versions

Description
When a plugin is added and executed, the MavenDependencyDownloader starts to resolve the transitive dependencies of the plugin itself, but is uses the Maven GAV of the plugin without taking account of the parent. 

 Since all the Camel JBang plugin uses 
  
 
 <groupId> org.apache.camel </groupId> 
 <artifactId> camel-jbang-parent </artifactId> 
 
  
 as parent Maven module, it should rely on this module to manage the dependency versions 

 Otherwise the downloaded dependencies are not the same used at runtime
Discussion
- The plug should be exact same version as camel-jbang itself, you should not mix different versions
- exactly, but it seems that currently it resolve the dependencies differently from what Camel expects, I'm expecting that once the Plugin (I verified with Generate plugin) is added and executed, the Maven downloader resolves the dependencies as configured in the Maven module camel-jbang-plugin-generate, but is not resolved with the same version, because in the parent module the versions are managed
- I tried the solution in the linked PR, adding a  manual test  to verify the different behavior
- Marco if this is not difficult to backport then you are welcome to send a PR for 4.10.x branch
