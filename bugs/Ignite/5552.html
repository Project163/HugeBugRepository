Title

Striped pool queue overflow in ScanQuery for touched/accessed expiry TTL policy

Description
ScanQuery on cache with the `AccessedExpiryPolicy` or `TouchedExpiryPolicy` TTL overflows the striped pool queue with the `GridCacheTtlUpdateRequest` messages. 

 This causes pool strvation, heap memory overflow, Full GC collections, JVM pauses and finally the cluster crash. 

 Looks like the reason is that list of entry keys to be included into the `GridCacheTtlUpdateRequest` message (`expiryPlc.entries()`) is not reset after the flush in the cycle in the `ScanQueryIterator.advance()`.
