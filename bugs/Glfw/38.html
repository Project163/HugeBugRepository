Title

glfwSetTime should not be called with a negative argument

Description
I recently found that calling `glfwSetTime` with a negative argument will cause `glfwGetTime()` to report large positive values, rather than the expected negative values. This behaviour was unexpected by me since the API accepts type `double`, which does not suffer from overflow problems. It seems the argument is actually transformed to an unsigned integral type internally, which overflows to give a very large time value.

If it is impractical to accept negative time values, please could the documentation be updated to reflect that `glfwSetTime` should only be called with `time >= 0.0`.
