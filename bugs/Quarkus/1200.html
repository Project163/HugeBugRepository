Title

Kafka message payload types are not registered for reflection

Description
## Describe the bug
Serde message payloads need to be registered for reflection in native builds.
If these classes were not registered by another means (i.e resteasy extension) message serde does not work in native mode.

### Expected behavior

Message serde (jackson/jsonb) works in native mode.

### Actual behavior

For example with Jackson serialization fails with a similar stacktrace:

```
Caused by: java.lang.RuntimeException: com.fasterxml.jackson.databind.exc.InvalidDefinitionException: No serializer found for class org.acme.kafka.model.Quote and no properties discovered to create BeanSerializer (to avoid exception, disable SerializationFeature.FAIL_ON_EMPTY_BEANS)
	at io.quarkus.kafka.client.serialization.ObjectMapperSerializer.serialize(ObjectMapperSerializer.java:37)
	at org.apache.kafka.common.serialization.Serializer.serialize(Serializer.java:62)
	at org.apache.kafka.clients.producer.KafkaProducer.doSend(KafkaProducer.java:925)
	at org.apache.kafka.clients.producer.KafkaProducer.send(KafkaProducer.java:885)
... [Log Snipped] ...
	at io.quarkus.kafka.client.serialization.ObjectMapperSerializer.serialize(ObjectMapperSerializer.java:34)
	... 13 more
``` 

## To Reproduce

Steps to reproduce the behavior:
1. Setup app with `smallrye-reactive-kafka` extension
2. Send/receive serde'd object to/from Kafka
3. Make sure the object is not already registered for reflection by another extension, (i.e REST endpoint payload)
4. Run the app in native mode
Discussion
- It depends on the serializer. For JSON yes, for Avro, I'm not so sure, for a custom serializer, probably not.
- True. It'll only be needed for Jsonb/Jackson serde.
