Title

Paramiko 2.9.0 breaks compatibility with devices only supporting ssh-rsa and not supporting server-sig-algs

Description
This issue is observed when using napalm and a Cisco ASR9001 running IOS-XR 6.7.3.
When trying to connect to such a device, paramiko only tries `ssh-rsa512`, fails and then gives up.
I would expect it to try the other algorithms in its list until it finds one that is working.

I am aware of the possibility to set `disabled_algorithm` but to my knowledge, napalm does not support setting this option.
This however is an issue that I will report to the napalm team.

Nonetheless, I think the behaviour of paramiko should be changed to regain compatibility with these legacy SSH daemons.
Discussion
- Is there any update on this? The latest Ubuntu release (jammy, 22.04) includes version 2.9.3, so I think a lot of people are going to encounter this problem in the near future...and setting disabled_algorithm doesn't seem very user-friendly or, in some cases, even possible, if paramiko is used internally with some bigger python app.
- A rewrite of the key authentication logic is on @bitprophet's roadmap, which IIUC would make all of the `disabled_algorithms` awkwardness unnecessary. (I know he very much dislikes the whole `disabled_algorithms` two-step, but it was the least-worst quick fix for some recent problems.)

Unfortunately, AFAIK there's no specific timeline for this rewrite (other things are higher priority; plus, @bitprophet has to balance paramiko with invoke and fabric in his OSS time), so downstream projects may just need to figure out how to cope with the `disabled_algorithms` interface for now. :-/
