Title

minLength(1) validator returns invalid on a valid input

Description
# 🐞 bug report

### Affected Package
 
  The issue is caused by package @angular/forms


### Description

  Validators.minLength(1) on a form field that has number as type returns invalid when the number entered is 0.

Discussion
- @edoxthebest I tried your minimal reproduction, analyzed how minLength works and I think I found the issue. 
First of all, you are using `input type='number'` in your code, which converts the value to number. This means that whatever char you are typing, it will be a number. 
Second, looking at Angular Validators source code [URL] specifically on line 287 we have the minLength function. And on line 292 we have this code : `const length: number = control.value ? control.value.length : 0;`. As our `control.value` is number, and specifically 0, the `Boolean(0)` is false, which will always resolve `length` variable with 0, thus it will always be Invalid.
So I think the solution would call toString on control.value check 
 `const value = control.value.toString();
const length: number = value ? value.length : 0;`
But this is a change in angular forms code. 
On the side note: The issue doesn't reproduce with `input type='text'` because `Boolean('0')` is true
- Seeing the above-proposed solution I believe it's better to consider the following cases before implementing the solution:
1. Number with decimals. Decimal will be counted towards length
2. Negative numbers. The sign will go towards the length.
3. For large number inputs getting stored in exponential format.
4. User input 0 will have a length of 1 using control.value.toString() but input 0123 will have length 3 and not 4.
5. Performance using the toString() method.

- @edoxthebest We have looked into this issue and the forms source-code - `minLength` and `maxLength` both are **_only_** applicable to strings and arrays. As mentioned by @vmuresanu, for your use-case it would be best to use a string input and a regular expression pattern. 

Something like this would work:

```typescript
profileForm = this.fb.group({
  number: ['', Validators.pattern('[0-9]{1,}')]
});
```

If you need to use an input type of number, you could use a custom validator function and implement the logic. You can find more details [Link: here].
- It should also be noted that the current `minlength` and `maxlength` do not actually work for number fields anyway. The validator will always indicate no error for a non-zero number and error for a zero number, whatever the setting of the validator. So there is no point in using it in an application.
