Title

Joined relationship load with with_loader_criteria

Description
### Describe the bug

I've some trouble understanding why `lazy='joined'` relationships are behaving differently when using `with_loader_criteria`. I've provided an example test case to illustrate the issue where the criteria doesn't get applied in the case of joined loads. It works perfectly fine for other type of relationships.

If this is by design, how can I best ensure that the criteria will be applied on joined loads as well?

Discussion
- I noticed that this only seems to be a problem after issuing a `session.refresh` or `session.expire`. The criteria will be added fine if the object is queried fresh.

Passing test case showing this:
```
py

    parent = Parent(id=1)
    child1 = Child(id=1, parent_id=1)
    child2 = Child(id=2, parent_id=1)
```

- OK easy enough, the code that "refreshes" an  object has the object present as well as its primary key, so there is a line that turns off "with loader criteria" for this query since we don't want to not find our row.  because the joined loader is in the same SQL, it's also not getting its option, so that logic would need to be scaled back.

this is not hard and can be in the next release
