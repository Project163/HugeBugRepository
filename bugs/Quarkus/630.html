Title

Validation of REST input/output classes defined as dependency

Description
**Describe the bug**
As a developer I use Hibernate Validator/Bean Validation for validating the input/output of your REST services. 
But input/output of my REST services is defined in separate library (generated from RAML or OpenAPI file).

**Expected behavior**
When I follow **validation-quickstart** guide and make modification to extract my model to dependency then hibernate-validator should validate input/output of my REST services

**Actual behavior**
Response code 400 is returned with following message
`javax.validation.UnexpectedTypeException: HV000030: No validator could be found for constraint 'javax.validation.constraints.Size' validating type 'java.lang.String'. Check configuration for 'validateBook.arg0.author'`


**To Reproduce**
Steps to reproduce the behavior:
1. Follow **[Link: validation-quickstart]** guide.
2. Afterwards, a separate project `validation-quickstart-model `project is created
   - class Book is moved to that project.
   - added dependency to  `javax.validation:validation-api:jar:2.0.1.Final` with scope `provided`
   - validation-quickstart-model installed in local repository
3. Then in validation-quickstart project 
    -  added dependency to `validation-quickstart-model`
   -  added to application.properties following
```
quarkus.index-dependency.validation-quickstart.group-id=org.acme
quarkus.index-dependency.validation-quickstart.artifact-id=validation-quickstart-model
```
4. Open [Link]
5. Enter 1 for number of pages and press 


Same behaviour  occurs when instead of adding quarkus.index-dependency to application.properties we build `validation-quickstart-model` with  `jandex-maven-plugin:1.0.7` plugin ( using goal `jandex`).

The only case in which it did work was by creating empty beans.xml in `validation-quickstart-model` project.

**Regarding documentation**
When I referenced model as dependency, then Quarkus build failed and one of the suggestion was to reference classes by quarkus.index-dependency in application.properties.
This resolved my build, but hibernate-validation  failed.

So after searching in guides for some clue, I ended up reading [Link: Context and Dependency Injection Guide]. 
So, next best solution seemed trying adding jandex-maven-plugin to my "model" project.
This failed, and then I started writing this bug and wanted to test on a clean project and tested empty bean.xml and it worked.

I am fortunate that I can modify my "model jar" and add empty beans.xml.

I am not sure if this is a bug or not.
But it seemed useful feature to have possibility to validate "model" from third party that does not have beans.xml (that is not bean archive).
