Title

[bug] Icons fail to work under Ubuntu 22.04.1 LTS & Tauri 1.1.1

Description
### Describe the bug

A placeholder icon (the gear icon below) shows up instead of the given ones. This happens with a *fresh* new [Link: create-tauri-app] application.

[Image: screenshot]

AFAICT, this wasn't happening with Tauri 1.0.x

### Reproduction

The exact steps are shown below, together with part of the output where applicable.

```
console
❯ cd /tmp

❯ npm create tauri-app

... [Log Snipped] ...

    Finished dev [unoptimized + debuginfo] target(s) in 2m 12s
```

The vanilla icons under `tauri-app/src-tauri/icons` to appear, e.g.,

Discussion
- I couldn't reproduce on my xfce, what desktop manager is your ubuntu using, gnome?
- Hello, I had the same issue with **Tauri v2.0.6** on **Ubuntu 22.04**. I tried everything, like adding `StartupWMClass` to the `.desktop` file and clearing icon caches, but nothing worked.

What finally fixed it was **disabling Wayland** by uncommenting `WaylandEnable=false` in `/etc/gdm3/custom.conf`. After switching to **Xorg**, the icon showed up correctly in the dock.

Not sure why Wayland with Tauri causes this issue, but if anyone has insights or a workaround for Wayland, I’d love to know.

- My workaround for this was by providing a custom `desktopTemplate` for the deb and rpm bundles, with the `startupWMClass` option mentioned by @rahul4tech

I added a `./src-tauri/template.desktop` file with the `{{exec}}` placeholder as the value

```
ini
[Desktop Entry]
Categories={{categories}}
Comment={{comment}}
Exec={{exec}}
... [Log Snipped] ...
Terminal=false
Type=Application
```

And then provided the template path to `tauri.conf.json`

```
json
{
    "bundle": {
        "linux": {
            "deb": {
... [Log Snipped] ...
    }
}
```
