Title

3.3 Dispatch filters are executed twice

Description
This is a (multiple allowed):
- [x] bug
- CakePHP Version: 3.3
- Platform and Target: irrelevant
### What you did
1. Make a fresh install of `cakephp/app` (version 3.2.6)
2. In `composer.json` change `"cakephp/cakephp": "~3.2"` to `"~3.2.0"` in order to get Cake **3.2**
3. Create an [Link: action] and a [Link: route] for it
4. Verify that browser gets ` Response body ` from server
5. Create a [Link: filter] and [Link: add] it
6. Verify that browser gets ` Response body  Filter-appended content ` from server
7. In `composer.json` change `"cakephp/cakephp": "~3.2.0"` to `"~3.3.0"` in order to get Cake **3.3**
8. `composer update`
9. Open/reload the test page in browser
### Expected Behavior

One would expect the behavior to remain constant and receive ` Response body  Filter-appended content ` from server
### Actual Behavior

In reality the browser receives ` Response body  Filter-appended content  Filter-appended content `. As you can see, the filter was run twice.
### Source of error

I've traced the problem to the new `\Cake\Http\ActionDispatcher` class. The problem itself is that all filters are added twice. Stuff goes as follows:
1. Filters are [Link: `\Cake\Routing\DispatcherFactory::add`ed] in `config/bootstrap.php`
2. The dispatcher [Link: is created] **with** [Link: the filters]
3. `\Cake\Routing\Dispatcher::dispatch` is [Link: called] and it [Link: creates a new instance] of `\Cake\Http\ActionDispatcher`
4. `\Cake\Http\ActionDispatcher::__construct` [Link: adds all filters] from `\Cake\Routing\DispatcherFactory`
5. `\Cake\Routing\Dispatcher::dispatch` itself [Link: adds the filters] (that were added to it in step 2) to `\Cake\Http\ActionDispatcher`

So the end result is that the whole filter stack is added twice during runtime which causes the double execution of all event handlers, etc. I know that 3.3 depreciates filters but it shouldn't mean that the code is broken just because the project is updated to 3.3 but didn't switch to middleware yet
