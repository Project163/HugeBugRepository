Title

Randomizer.GetString can return strings that have invalid surrogate pairs

Description
System.String is UTF-16, and not all sequences of `char` values are valid UTF-16. The current implementation disregards this:

[URL]

This is only a concern if `System.Char.IsSurrogate` returns true for any character in the `allowedChars` parameter. Possibly, this could be resolved by throwing NotSupportedException for such inputs.

Alternatively, `allowedChars` could be enumerated with [URL] (available since .NET Framework 1.1) in order to not split apart char sequences that need to stay together in order to be meaningful. This would be a slower code path, so it would be desirable to still check to see if `System.Char.IsSurrogate` returns true for any character in the `allowedChars` parameter.

(For some target frameworks, there may be a vectorized way to compute the equivalent of `allowedChars.Any(char.IsSurrogate)`, I'm not sure.)

If multi-char sequences are being treated atomically, reaching the end of the string becomes interesting since the length parameter likely should determine the `string.Length` of the returned instance.
- If `allowedChars` contains a one-char sequence and a two-char sequence, and `outputLength` is 3, then the only two possible valid return values would be the either the one-char sequence followed by the two-char sequence, or the two-char sequence followed by the one-char sequence.
- If `allowedChars` contains only two-char sequences, and `outputLength` is an odd number, the caller has asked for something impossible/invalid and `ArgumentException` would make sense to throw.
Discussion
- I think we should disallow surrogates. They are a niche and for any code with random strings not likely to be used.

We can rename the current `GetString` into a `UnsafeGetString` and make it `private` which does not check its `allowedChars`
Then the overloads which pass in `DefaultStringChars` call `UnsafeGetString` directly.
Create a new `GetString` which checks the passed in `allowedChars` and `throws` if it has an surrogates.

In addition make an NUnit test to ensure that nobody put surrogates in `DefaultStringChars`.
That way we don't affect the performance of 99% of the `GetString` calls.

Alternatively make a `StringRandomizer` derived class which needs `allowedChars` in the constructor.
That way the check only has to be done once. It then has a `GetString` method without an `allowedChars` parameter.
- I'm amenable to that. If someone puts emoji in their allowed chars, we can always revisit. 😄
