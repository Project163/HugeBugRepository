Discussion
- Nvim aborts because you found a way to call `loop_poll_events()` recursively, see frames `#2` and `#18` in your stack trace.

The cause for this is probably commit 9706664b. It introduces  in the callback `write_cb()`
a call to `EMSG2()` that can poll for input again, while still not returned from the first poll (with `uv_run()`). 

If you can, try to revert 9706664b and see if this fixes your problem.
- My fault. Need to schedule that EMSG2 instead. Thanks @oni-link
- It seems to have been the [Link: YankRing] plugin that was the trigger. I haven't had a crash since disabling it, although it would be nice to find a plugin with similar functionality that doesn't cause issues.
- The crash should be fixed, on master. But you may see `E5677` now, this is expected. See `:help E5677`.

However I don't see anywhere in yankring that is writing to a "backgrounded" shell command. Perhaps `provider/clipboard.vim` is triggering this somehow.
