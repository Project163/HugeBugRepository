### What happened?

Exif orientation is not being utilized when displaying images.

For example, when modifying `Image::list` in the `gallery` example to download a reference image along with a small set of PNGs and JPEGs with exif orientation by returning:
```
rust
        Ok(vec![
            Image {
                id: Id(0),
                url: "[URL]
... [Log Snipped] ...
            },
        ])
```
the images with exif orientation data do not match the reference image.  (Images from [Link: Exif orientation in different formats].)

### What is the expected behavior?

The images with exif orientation data should look the same as the reference image.

Discussion
- This was handled, but incorrectly. It should be fixed in `master` now.

Keep in mind though that if you load the image yourself with the `image` crate and feed raw RGBA data directly to `iced` using `Handle::from_rgba`, then it's up to you to deal with Exif. This is what the `gallery` example does, so your changes will not work.

If you want `iced` to handle Exif, then you must use `Handle::from_bytes` or `Handle::from_path`.
- Thank you for the quick fix!  And the note on usage as well.  We do load from path, but I was not careful enough to ensure that was recreated in my example.
