Title

postgres=# create index on t(k);

But YB side should automatically delete related indexes if the table was truncated.
So, there are 2 options for the fix:
1) Let's truncate the index, even if it was truncated together with the table.
2) Do not truncate indexes (from Postgres code). (It must be automatically truncated by YB server before - via the TRUNCATE \  request).
- The option (2) above is not applicable.
The CatalogManager::TruncateTable automatically truncates associated indexes, but PG table does not have the links in the table record, so the code does nothing for PG table (it truncates indexes for CQL table only at the moment):
```
for (const auto& index_info : l->data().pb.indexes()) {
  RETURN_NOT_OK(TruncateTable(index_info.table_id(), resp, rpc));
```
