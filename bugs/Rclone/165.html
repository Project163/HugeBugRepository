Title

copyto places files in incorrect place for non-existent directory

Description
Similar to #281 but for encrypted backends:

I'm running in to issues with spaces in names when using encrypted remotes.

I use copyto "TARGET:dir/to copy/into/file.whatever" and in the logs I see:

```
Encrypted amazon drive root 'Vault/dmi0e2fbj6btggkj33t5dtqmo4/j4jctgmgj50nsvqtbd2gb0o8ig/4nbenmipf0htppnrq2hmqaqk40/7em7kl21js9ribn89uaqsr0nkc': Modify window not supported
```

But that directory doesn't end up existing, rather a file gets created next to "Vault/" in my amazon drive so the dir listing looks like:
```
Vault/
etltv0troceojn8bb67iqal3vnbt66jg5vcnoqmv1i2i1e18442nhdv1ob09c03edpcdedlcuf3aoa0h0v28puvbilivtade7rj4r40
```

The newly copied file actually being the etltv0troc... file (which is outside of the encrypted root and not part of the directory path it should be in)

Subsequent attempts to copyto the same file returns with "file does not need to be copied", but its referencing this out of root file.

rclone version: rclone v1.35-164-g488353cβ
