Title

mount: Fix retries when using io.Seeker

Description
In ReadFileHandle.Read we retry if we get an error on a read stream.

This involves calling FileHandle.seek, however this only re-opens the connection if the underlying read handle doesn't support seek.  This means that crypt will not re-open the underlying stream and the retry will fail.

Also if the seek returns an error we don't retry we just return the error which explains the lack of retry logs in the forum posting. 

Note that the open will be using low level retries, so maybe we don't need to return it directly...

Also consider whether to reset fh.retries on success otherwise we are limited to 10 retries ever.
