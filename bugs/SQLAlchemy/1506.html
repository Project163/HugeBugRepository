```InvalidRequestError: Can't match sentinel values in result set to parameter sets; key '3e5d7de2-56ab-4256-9871-71e048dbb5bc' was not found. There may be a mismatch between the datatype passed to the DBAPI driver vs. that which it returns in a result row.  Ensure the given Python value matches the expected result type *exactly*, taking care to not rely upon implicit conversions which may occur such as when using strings in place of UUID or integer values, etc.```

- hey there -

You no longer need to use a TypeDecorator for the UUID like that, in 2.0 you can use the [Link: Uuid] datatype that will do all the SQL Server UNIQUEIDENTIFIER and all of that.

otherwise, in order to be compatible with [Link: insertmanyvalues], your type must implement a new method [Link: _sentinel_value_resolver] if it is going to be a. used as a primary key / autoincrementing type and b. sends off bound parameters to an INSERT statement in a different form than they would be coming back from a RETURNING by the driver, in this case strings go in and UUIDs come out.   This method was introduced in 2.0.10 to suit a major issue that was discovered in insertmanyvalues which is discussed [Link: here] and [Link: here].

this method obviously should not remain as an underscored method, it should become something public and part of whats mentioned in the insertmanyvalues section as well as in a note for `TypeDecorator`.

- if a user was using as_uuid=False I think they are required to pass a string as the datatype.
