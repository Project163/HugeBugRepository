Title

nested $ref not found

Description
## Problem statement

I have a swagger spec which $ref's to another swagger spec, which $ref's a JSONSchema spec

(why? I have several repos which each implement a sub-section of my entire products API spec, so they cherry-pick sub-sections to generate code for)

The first $ref resolves fine.
The second $ref tries to resolve the path relative to the first specs location, which yields a "no such file" error

## Swagger specification

./base.yaml
```yaml
swagger: "2.0"
paths:
  /example:
    $ref: ./schemas/api/api.yaml#/paths/~1example
```

./schemas/api/api.yaml
```
yaml
swagger: "2.0"
paths:
  /example:
    get:
... [Log Snipped] ...
          schema:
            $ref: ../example/example.yaml
```

./schemas/example/example.yaml
```yaml
$schema: [URL]
required:
  - payload
properties:
  payload:
    type: string
```

## Steps to reproduce

create the above files and run:
```
swagger flatten \
    --format=yaml \
    --output swagger.yaml \
            ./base.yaml
```

Error:
`could not resolve schema: open /Users/petermcintyre/git/example/example.yaml: no such file or directory`

you can see it's resolved the `../example` against the original basePath (ie. `./base.yaml`) and gone up too many directories

## Environment
swagger version: built from master ( )
go version: go1.12.7 darwin/amd64
OS:   macos
