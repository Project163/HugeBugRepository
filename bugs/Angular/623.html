Discussion
- @ocombe It's a general bug for named format retrieval, in [Link: data-extracting process], there's a `removeDuplicates` function used to get rid of extra bytes, but **there're [Link: no corresponding fallback logic] for reusing removed formats at runtime**.

In this case, `zh` locale [Link: provide same formats] for `mediumDate` & `longDate`, so the latter is stripped. And then no `longDate` named format found at runtime, making it being regarded as a normal format.
- Oh good catch @trotyl, we have fallback logic for all data except those formats. I'll fix it
- @ocombe I just raise a PR for it, it would be fine if you have better solution.
