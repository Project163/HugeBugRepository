Title

MiniKDC shouldn't use apacheds-all artifact

Description
The MiniKDC currently depends on the  apacheds-all  artifact: 
  
      <dependency> 
       <groupId> org.apache.directory.server </groupId> 
       <artifactId> apacheds-all </artifactId> 
       <version> 2.0.0-M15 </version> 
       <scope> compile </scope> 
     </dependency> 
 
  

 However, this artifact includes, inside of itself, a lot of other packages, including antlr, ehcache, apache commons, and mina (you can see a full list of the packages in the jar  here ).  This can be problematic if other projects (e.g. Oozie) try to use MiniKDC and have a different version of one of those dependencies (in my case, ehcache).  Because the packages are included inside the  apacheds-all  jar, we can't override their version.   

 Instead, we should remove  apacheds-all  and use dependencies that only include org.apache.directory.* packages; the other necessary dependencies should be included normally.
Discussion
- It took a lot of trial and error, but I was able to find the minimal set of dependencies and exclusions to get this to work without using any of their jars that include 3rd party packages (btw, the Apache DS artifacts are a big mess). 

 An especially tricky issue was that one of the dependencies,  apacheds-jbm1 , isn't a jar – it's a "bundle", which requires the maven-bundle-plugin.  However, they aren't publishing it properly or something so it doesn't work anyway.  The workaround, which I figured out from  this , was to exclude  apacheds-jbm1  and explicitly include it, but using version  2.0.0-M3-SNAPSHOT  instead of  2.0.0-M15  because it's not a bundle.   

 I've verified that everything compiles,  TestMiniKdc  passes, and the issue I was having in Oozie goes away.
- Our artifacts are also a mess  . 

 Using an apacheds-jbml from a different release does not seem kosher at all. It would be great if you can drop a line to the apacheds alias mentioning the problem and if the have a better idea or if they'll fix the apacheds-jbml in an upcoming release. Just leave out the big mess thing  . 

 Worse case scenario, as minikdc is used only for testing we could go with the propose approach.
