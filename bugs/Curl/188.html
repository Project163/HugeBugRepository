Title

HTTP/2 connections through HTTPS proxy frequently stall

Description
### I did this

Set up a standard HTTPS proxy on localhost (not HTTP - the CONNECT tunnel must be encrypted)

`curl -v --proxy-insecure -x [URL] --http2 [URL]

### I expected the following

The upstream connection should complete successfully, however it frequently stalls after receiving either TLS session tickets, HTTP/2 SETTINGS or HEADERS frames, depending on the arrangement of TLS frames from the origin within TLS frames sent by the HTTPS proxy to curl. The behaviour appears to be that curl reads one HTTP/2 frame per TLS frame, which works in the direct case where this is true, but fails through the proxy when it coalesces multiple TLS frames inside the HTTPS connection.
