Title

curl fails to resolve file URIs pointing to directories on Windows

Description
First -- happy holidays! I hope the season is treating you well.

tl;dr: On *nix machines, it looks like `curl file:///path/to/directory` can be used to query the existence of a directory, while that same sort of invocation fails on Windows. I'm calling this a bug just because the behavior differs between platforms; please feel free to close with prejudice if you disagree!

### I did this

#### macOS

```
$ curl -I file://$HOME
Content-Length: 5440
Accept-ranges: bytes
Last-Modified: Fri, 25 Dec 2020 07:07:09 GMT
```

#### Windows

```
C:\Users\kevinushey\bin>curl.exe -I file:///C:/Users/kevinushey/bin
curl: (37) Couldn't open file C:/Users/kevinushey/bin

C:\Users\kevinushey\bin>curl.exe -I file:///C:/Users/kevinushey/bin/curl.exe
Content-Length: 4395640
Accept-ranges: bytes
Last-Modified: Sat, 26 Dec 2020 05:35:49 GMT
```

### I expected the following

- A 0 status code (success) when attempting to resolve an existing directory;
- Headers describing the directory size + modified time if available.

### curl/libcurl version

C:\Users\kevinushey\bin>curl -V
