Title

Fix issue with using Locale objects inside ResponseBuilder

Description
Using a Locale object will not always produce the correct HTTP response header.  Should explicitly call toString on it in the ResponseBuilder for the Content-Language header to be set.
Discussion
- [URL]

 Locale.toString() was called in the FlushResultHandler (in flushHeaders) but it was an incorrect format (my mistake in earlier description). 

 "en_US" is incorrect (which is what Locale.toString() produces).  Should really use HeaderUtils.localeToLanguage() instead in ResponseBuilderImpl to produce "en-US". 

  
 @GET
 public  Response getSomething() {
   return  Response.ok( "Hello world!" ).language(Locale.US).build();
}
