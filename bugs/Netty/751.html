Title

Race condition in NioWorker in Netty 3.5.x results in NullPointerException

Description
There is a race condition in NioWorker.java in Netty 3.5.x resulting in a NullPointerException on line 146 (v3.5.2) in the register method from time to time.  I believe what happens is as follows:
0) app happily running doing some work
1) register method is called
2) start() method is called from register, started == true, so nothing to do, returns to register
3) (in another thread) shutdown set to true in run() method as there has been no activity for 1 second
4) run() checks in a synchronized block to see whether the queue is empty, closes the selector and sets selector = null
5) register method now reaches the line where it adds the item to the queue 
6) register method now reaches the selector.wakeup() call and throws a NullPointerException because selector == null

Please add a fix for this to netty 3.5.3 as it results in random NullPointerExceptions happening from time to time.

Fixing this issues should be a simple matter of wrapping more of the code in the register method in a synchronized block (using the same object for locking as the start() method). Register() is adding an element to a queue outside a synchronized block while run() is checking the length of the queue in a synchronized block, resulting in a race condition, which leads to a NPE.
