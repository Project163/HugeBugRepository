Title

gRPC iOS build currently broken due to mismatch boringSSL headers

Description
When trying to release `grpc/grpc-ios` version `v1.75.0-pre1`, we discovered a build issue, see [URL]

Error message:

```
/Users/runner/work/grpc-ios/grpc-ios/src/core/tsi/ssl_transport_security.cc:1342:3: error: use of undeclared identifier 'X509_STORE_CTX_set0_trusted_stack'; did you mean 'X509_STORE_CTX_trusted_stack'?
  X509_STORE_CTX_set0_trusted_stack(ctx, *root_stack);
  ^~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
  X509_STORE_CTX_trusted_stack
In file included from /Users/runner/work/grpc-ios/grpc-ios/src/core/tsi/ssl_transport_security.cc:19:
... [Log Snipped] ...
                    ^
4 warnings and 1 error generated.
```

Looks like the gRPC-iOS repo uses this particular boringSSL library: [URL]

```
Resolved source packages:
  gRPC: /Users/runner/work/grpc-ios/grpc-ios
  abseil: [URL] @ 0.20250512.1
  BoringSSL-GRPC: [URL] @ 0.32.1
```

which has

```
#define OPENSSL_VERSION_NUMBER  

#define BORINGSSL_API_VERSION 16
```

defined in [URL]

It looks like for some reason, the fn `X509_STORE_CTX_set0_trusted_stack` was not defined in that particular boringSSL library. The library does seem to have other `X509_STORE_CTX_set0_*` method but just not `X509_STORE_CTX_set0_trusted_stack`

The PR which introduces the use of this function between v1.74.x and v1.75.x: [URL]

The default boringSSL library this `grpc/grpc` repo uses (google/boringssl), does have the `X509_STORE_CTX_set0_trusted_stack` function defined: [URL]

Also logged an issue [URL] to see if that function can be added to that Swift boringSSL library.
Discussion
- This is blocking the Objective-C v1.75 release. This only affects Objective-C but not other grpc languages because of the specific boringSSL library Objective-C is using.
- In the short term to fix this we can add include guards to make Objective-C fall through to BoringSSL < 1.1.1

In the long term, we should understand why this library specifically doesn't have the expected APIs
