[YSQL] flaky test: PgCacheRefreshTest.NewConnectionTransparentRetryTxn

Discussion
- This looks like a test issue.

```
    ddl_func();

    ASSERT_OK(conn->Execute("BEGIN"));
    // This will fail due to schema version mismatch.
    ASSERT_NOK(executeInsert(conn));
    ASSERT_OK(conn->Execute("ROLLBACK"));
```

We expect the Insert (issued from TS1) to fail above because of schema version mismatch. This is because `ddl_func` above starts up a (failing) DDL from some other node (TS2). This only causes the DocDB schema version to increase, however it does not increase the catalog version. Thus the cache in TS1 becomes stale, and requests originating from it fail with SchemaVersionMismatch.

This is usually true. However the above is the 4th test in the following function:
```
TEST_F(PgCacheRefreshTest, YB_DISABLE_TEST_IN_TSAN(NewConnectionTransparentRetryTxn)) {
  auto stmt_conn = ASSERT_RESULT(Connect());
  TestSetup(&stmt_conn);

  // Note that this test looks the same as the previous test, but differs in the fact that every
... [Log Snipped] ...
    testConcurrentSchemaVersionIncrementFromDifferentNode("col4");
  });
```

Thus the fix is to wait for heartbeat to complete after Test2. I was able to repro this issue consistently with a release build on my dev-server. To verify this theory I added a simple sleep at the end of test2 and the issue no longer occurs. The fix is to add a wait for heartbeat at the end of test2
