Title

Directories are silently ignored in ctx.actions.run arguments

Description
### Description of the bug:

When you declare a directory and then attempt to use it in `ctx.actions.run`, it silently skips the argument.

### Which category does this issue belong to?

_No response_

### What's the simplest, easiest way to reproduce this bug? Please provide a minimal example if possible.

[URL]

```
def my_rule(ctx):
  out = ctx.actions.declare_file("file")
  out_dir = ctx.actions.declare_directory("dir")
  args = ctx.actions.args()
  args.add_all([out, out_dir])
  ctx.actions.run(..., arguments=[args])
```

When you run with `bazel build -s`, you can see that the command it ends up invoking is `  path/to/file` and it completely skips the directory argument.

Additionally, `print(args)` reveals that the args is generated correctly, but fails to translate correctly to the command-line.

Discussion
- Does it help if you add the directory to the action's inputs? See [URL]
- If your action is **producing** the directory, use one of the forms `args.add(out_dir.path)` or `args.add_all([out_dir], expand_directories = False)`.

The default behavior of `add_all([out_dir])` is to expand the directory into the contained files, which only makes sense for an action **consuming** a directory, and also requires the directory to be an input to work.
