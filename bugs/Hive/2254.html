Title

HDFS FileSystem object cache causes permission issues in creating tmp directories

Description
We change permissions of the directory creation to 777 for HiveServer 2 operation and it turns out that because of HDFS caching, it does not reflect once created. We need to use the non-cached version of the API to get a FileSystem object to fix this.
Discussion
- Hi Vikram, 

 Couple of smaller comments on the patch. 

  
 LOG.info( "Create dirs "  + mkdirPath +  " with permission "  + fsPermission +  " recursive "  + recursive);
 
  

 You probably don't need to manually concatenate the string but let log4j do it for you. 

  
 LOG.info( "Create dirs {} with permission {} recursive {}" , mkdirPath, fsPermission, recursive);
 
  

 Secondly, I think that if you create a FileSystem using the newInstance method, it should be closed to avoid any resource leaks. Previosuly with the cached FS instance, the API was automatically handling that for you.
