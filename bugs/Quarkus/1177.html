Title

Native build error when using quarkus-opentelemetry-exporter-otlp

Description
## Describe the bug
A native build of a Quarkus application fails if it includes the pom dependency:

```
 
   io.quarkus 
   quarkus-opentelemetry-exporter-otlp 
 
```
with quarkus.version set to 2.0.0.Final

### Expected behavior
The build should succeed

### Actual behavior
The following native build error occurs:

```
...
[demo-0.0.3-SNAPSHOT-runner:25]     analysis: 269,454.77 ms,  3.31 GB
Error: com.oracle.graal.pointsto.constraints.UnresolvedElementException: Discovered unresolved type during parsing: io.grpc.netty.shaded.io.grpc.netty.NettyChannelBuilder. To diagnose the issue you can use the --allow-incomplete-classpath option. The missing type is then reported at run time when it is accessed the first time.
Detailed message:
Trace:
... [Log Snipped] ...
        at io.quarkus.deployment.steps.OtlpExporterProcessor$installBatchSpanProcessorForOtlp-727556406.deploy(OtlpExporterProcessor$installBatchSpanProcessorForOtlp-727556406.zig:40)
        at io.quarkus.runner.ApplicationImpl.doStart(ApplicationImpl.zig:643)
```

NB: replacing the otlp  exporter with the jaeger exporter makes the error go away.

## Environment (please complete the following information):

### Output of `uname -a` or `ver`

Microsoft Windows [Version 10.0.18363.1500]

### Output of `java -version`

Java Version 11.0.11+8-jvmci-21.1-b05

### GraalVM version (if different from Java)

GraalVM 21.1.0 Java 11 CE

### Quarkus version or git rev

2.0.0.Final

### Build tool (ie. output of `mvnw --version` or `gradlew --version`)

Apache Maven 3.8.1
