Title

newline-before-return throws exception if `return` is first token in file

Description
**What version of ESLint are you using?**

2.7.0

**What parser (default, Babel-ESLint, etc.) are you using?**

default

**Please show your full configuration:**

(Note: This is a config based off of the shell command I wrote below.)

```
json
{
    "env": {
        "node": true
    },
... [Log Snipped] ...
    }
}
```

**What did you do? Please include the actual source code causing the issue.**

``` shell
$ echo "return;" | eslint --stdin --env node --no-eslintrc --rule "newline-before-return: 2"
```

**What did you expect to happen?**

No error (newline-before-return is written to detect that the statement is the first statement in its block and will forbid newlines in that case).

**What actually happened? Please include the actual, raw output from ESLint.**

```
shell
Cannot read property 'loc' of undefined
TypeError: Cannot read property 'loc' of undefined
    at hasNewlineBefore (C:\Users\kpartington\AppData\Roaming\npm\node_modules\eslint\lib\rules\newline-before-return.js:105:45)
    at EventEmitter.ReturnStatement (C:\Users\kpartington\AppData\Roaming\npm\node_modules\eslint\lib\rules\newline-before-return.js:134:38)
... [Log Snipped] ...
    at Controller.__execute (C:\Users\kpartington\AppData\Roaming\npm\node_modules\eslint\node_modules\estraverse\estraverse.js:397:31)
    at Controller.traverse (C:\Users\kpartington\AppData\Roaming\npm\node_modules\eslint\node_modules\estraverse\estraverse.js:501:28)
```

---

The issue appears to be that in `hasNewlineBefore()` method, there is no defensive check around the existence of a token before the return statement. Presumably if there is no token before, then the "line number of the previous token" should be 1 (in a 1-based index).
