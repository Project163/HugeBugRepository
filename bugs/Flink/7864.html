Title

Can't start a job with a jar in the system classpath in native k8s mode

Description
It appears that the combination of the running operator-controlled jobs in native k8s + application mode + using a job jar in the classpath is invalid. Avoiding dynamic classloading (as specified in the  docs ) is beneficial for some jobs. This affects at least Flink 1.16.1 and Kubernetes Operator 1.6.0. 

   

   FLINK-29288   seems to have addressed this for standalone mode. If I am misunderstanding how to correctly build jars for this native k8s scenario, apologies for the noise and any pointers would be appreciated! 

   

 Perhaps related, the  spec documentation  declares it optional, but isn't clear about under what conditions that applies.
