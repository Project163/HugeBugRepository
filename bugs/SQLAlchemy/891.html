Title

optimized statement in load_scalar_attributes needs to cancel with_polymorphic settings

Description
We are falling back to name-based column matching when load_scalar_attribubtes() makes use of from_statement() and there is a with_polymorphic on the mapper.

What does it mean if someone has with_polymorphic on an aliased query, and then they use query.from_statement()?   should we assume from_statement is always local table columns, and we cancel query._polymorpic_adapters entirely? or do we need to put a new adapter in the adapter chain?   since "statement" is a non aliased SELECT it doesn't seem like we can use _from_obj_alias here,  or at least the wrap() thing does not seem to be working.
