Title

Kubernetes - Kafka clients are resolving DNS entries only one time

Description
Introduction  
 Since 2.1.0 Kafka clients are supporting multiple DNS resolved IP addresses if the first one fails. This change has been introduced by  [URL] However this DNS resolution is now performed only one time by the clients. This is not a problem if all brokers have fixed IP addresses, however this is definitely an issue when Kafka brokers are run on top of Kubernetes. Indeed, new Kubernetes pods will receive another IP address, so as soon as all brokers will have been restarted clients won't be able to reconnect to any broker. 

  Impact  
 Everyone running Kafka 2.1 or later on top of Kubernetes is impacted when a rolling restart is performed. 

  Root cause  
 Since  [URL] Kafka clients are resolving DNS entries only once. 

  Proposed solution  
 In  [URL] Kafka clients should perform the DNS resolution again when all IP addresses have been "used" (when  index  is back to 0)
