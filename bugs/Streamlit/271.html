Title

Error Occurs After Long Recording (~1 Hour) with st.experimental_audio_input: "An error has occurred, please try again"

Description

### Summary

I encountered an issue with st.experimental_audio_input. After pressing the mic button to start recording and continuing for a long time (around 1 hour), the following error message appears when I press the stop button: "An error has occurred, please try again." 


    
Discussion

    
- Hi @hoseong-cheon thanks for filing this issue. Admittedly, we did not test this component with such large files. 😅 There are a couple reasons you could be seeing this message:

1) the transcoding to wav failed 
2) the uploading of the wav file failed

The former seems less likely to me, but the latter could very well happen if the file size is larger than the file upload max size specified by your streamlit app. (I believe the default is 200MB.) I don't know how large a 1 hr wav file would be, but it doesn't sound too far fetched to believe this is what's happening.

If this hypothesis is correct, you should be able to fix things by allowing a larger file to be uploaded like this:

`streamlit run your_script.py --server.maxUploadSize=1028`


With that being said, there's definitely room for improvement here in cleaning up the error UI! 

Additionally, I'd love to learn more about your use case involving recordings that long. This was not something I anticipated when building this feature and better understanding your use case can help influence future improvements to this feature.
- @sfc-gh-nbellante 
I developed an app that records meeting audio, converts it to text using OpenAI Whisper AI, and summarizes the meeting content. Since this app is intended for recording meetings, long-duration recording is essential. However, after one hour, the timer resets to "00:00", and unexpected behavior also occurs.

Based on your feedback, it seems highly likely that this issue is related to the first suggestion (transcoding).

Additionally, the recording is not handled as an uploaded file but is processed directly within the application.
If there are any solutions or areas to address regarding this situation, your assistance would be greatly appreciated.
- I checked the docs and found that the following setting can be configured in config.toml:
```
[server]  
maxUploadSize = 1024
```
I applied this setting, ran tests, and no errors occurred.
- I put in a PR to explicitly note the connection between the widget and the configuration option within the docstring and marked it as closing this issue.
