Title

Inspector returns None for default and comment with negative server_default on an integer column (mysql)

Description
**Describe the bug**
Setting an integer column to have a server_default that's negative works correctly at the db level, but inspecting the table with SQLAlchemy shows it as None.  This trips up Alembic which tries to autogenerate migrations based on the inspected and metadata defaults being different.

With the following table definition:
```
CREATE TABLE example_table (
	negative_column INTEGER NOT NULL DEFAULT -1 COMMENT 'default should be -1', 
)
```

Calling   
```
insp = sa.engine.reflection.Inspector.from_engine(engine)
pprint.pprint(insp.get_columns("example_table"))
```

gives the following output:

```
[{'autoincrement': False,
  'comment': None,
  'default': None,
  'name': 'negative_column',
  'nullable': False,
  'type': INTEGER(display_width=11)}]
```

**Expected behavior**
Should return:
```
[{'autoincrement': False,
  'comment': 'default should be -1',
  'default': -1,
  'name': 'negative_column',
  'nullable': False,
  'type': INTEGER(display_width=11)}]
```
