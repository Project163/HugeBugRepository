Title

Combination of a boolean condition and null-safe comparison leads to NPE

Description
Here's a simple example with the foodmart database: 

  
 hive> explain select count(*) from
    > sales_fact_1997 join store on sales_fact_1997.store_id = store.store_id
    > where ((store.salad_bar)) and ((store_number) <=> (customer_id));
FAILED: NullPointerException  null 
 
  

 This happens on trunk and on HDP 2.5.3 / Hive 2. If you use = the NPE doesn't happen. If you remove the boolean condition the NPE doesn't happen.

- Originally reported by  Carter Shanklin
- The issue seems to be originating from ExprWalkerProcFactory::extractFinalCandidates(): 

  
     ExprInfo exprInfo = ctx.getExprInfo(expr);
    if (exprInfo != null && exprInfo.isCandidate) {
      ctx.addFinalCandidate(exprInfo.alias, exprInfo.convertedExpr != null ?
              exprInfo.convertedExpr : expr);
      return;
    }
 
  

 When exprInfo.convertedExpr is used instead of expr, the original alias of expr is kept. In the tested case this is null and this leads, after a convoluted path, to the NPE (the expression is moved into non-candidates list as a  
{null=[null]}
  map and this ultimately gets read as a descriptor).
