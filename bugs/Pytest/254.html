Title

Fixture fails with "module" scope and numpy array as value

Description
Minimal failing example:

```
py
import numpy as np
import pytest

@pytest.fixture(scope="module", params=[0, np.ones(2)])
... [Log Snipped] ...
def test_stuff(my_fixture):
    pass
```

`pytest` output:

```
=============================================== test session starts ================================================
platform linux -- Python 3.8.1, pytest-5.3.3, py-1.8.1, pluggy-0.13.1
rootdir: /home/hkohr/git
collected 2 items                                                                                                  

... [Log Snipped] ...
../miniconda/envs/tmp/lib/python3.8/site-packages/_pytest/fixtures.py:895: ValueError
============================================ 1 passed, 1 error in 0.35s ============================================
```
I'm not sure if there's a good way to fix this. If not, perhaps the docs should mention that arrays should not be used as parameter values, or only with function scope.

- @asottile You're right, it's not specific to Numpy, rather due to `==` not doing the job it's intended for. Perhaps, though, the Numpy case is the most common one for people to stumble over the issue.

A simple fix would be to first test with `is`, if that makes sense with pytest's caching mechanism. I don't know if there's any copying going on.
And then, `==` should be guarded with `try..except`, but what exception types to catch? `TypeError` probably, and `ValueError` for NumPy, others? Particularly poorly implemented classes may raise an `AttributeError`.
