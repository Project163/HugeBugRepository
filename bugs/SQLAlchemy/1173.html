Title

Regression in query building when using union and with_entities

Description
**Describe the bug**
Since version 1.4.19 (in particular commit [URL] fixing [URL] and [URL] ) the behavior when generating queries using union seems wrong. I'm not 100% sure it's because of the union, but this is the case I ran into. Version 1.4.18 worked fine.

**To Reproduce**
```
py
import sqlalchemy as sa
from sqlalchemy.ext.declarative import declarative_base
from sqlalchemy.orm import relationship, sessionmaker

... [Log Snipped] ...
print("UNION+COUNT (simulate x.union(y).count()")
print(x.union(y)._from_self(sa.sql.func.count(sa.sql.literal_column("*"))).enable_eagerloads(False))
```

**Output**
This is the correct output using 1.4.18:

```
sql
# BEFORE, UNION
SELECT 
  anon_1.a_id AS anon_1_a_id, anon_1.a_parent_id AS anon_1_a_parent_id, anon_1.b_id AS anon_1_b_id, anon_1.b_parent_id AS anon_1_b_parent_id 
FROM 
... [Log Snipped] ...
      ) AS anon_2
  ) AS anon_1
```

This is the incorrect output using the commit referenced above included in 1.4.19
```
sql
# AFTER, UNION
SELECT 
  anon_1.a_id AS anon_1_a_id,   anon_1.a_parent_id AS anon_1_a_parent_id,   anon_1.b_id AS anon_1_b_id,   anon_1.b_parent_id AS anon_1_b_parent_id 
FROM 
... [Log Snipped] ...
  ) AS anon_1 
  LEFT OUTER JOIN b ON anon_1.anon_2_b_parent_id = anon_1.anon_2_a_parent_id
```

Note in the incorrect case a stray LEFT OUTER JOIN being added at the end of the query, presumably from the first part of the UNION, and in the second case, the LEFT OUTER JOIN is being added yet another time to the count query. Sometimes the query happens to be valid, other times the query is invalid because some columns are not referencable from there. This particular case made one of our query jump from a few milisecs, to several minutes 🤯 

My guess is that the memoization gets applied erroneously in the UNION case, and results in part of the memoization applying to the outside of the UNION, but ???

 - OS: OSX
 - Python: 3.9
 - SQLAlchemy: 1.4.18 (OK) 1.4
