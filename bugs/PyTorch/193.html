Title

[Segfault Bug] Out-of-bounds write of at::native::cpubla::gemm (bfloat16) in at::native::cpu_flash_attention_backward

Description
### 🐛 Describe the bug

In PyTorch’s CPU implementation of [Link: cpu_flash_attention_backward], the [Link: cpublas::gemm] performs out-of-bounds memory writes when it's dispatched to **openblas sbgemm_** routine. 

This results causes **nondeterministic crashes** and **memory corruption**. The fault is observed in: `aten/src/ATen/native/cpu/FlashAttentionKernel.cpp::cpu_flash_attention_backward`. 

this bug can be reproduced using pytorch unit tests of `TestSDPACpuOnlyCPU.test_scaled_dot_product_fused_attention`

```bash
for i in {1..1000}
do
python test/test_transformers.py TestSDPACpuOnlyCPU.test_scaled_dot_product_fused_attention_mask_vs_math_cpu_fused_kernel0_bfloat16_batch_size_12_q_seq_len_1030_kv_seq_len_17_n_head_3_head_dim_8_mask_dim_2_bool_mask_False_train_True_casual_False_set_attn_mask_False_cpu_bfloat16
done
```

#### Root cause and Correction of cpublas::gemm

This segfault bug is caused by incorrect behavior of [Link: bf16 cpublas::gemm], which mishandles strided output matrices.

Specifically, it:

1. Allocates a temporary FP32 buffer of size ldc * n
2. Copies and converts the full ldc * n region from the output matrix C (BF16 → FP32)
3. Performs sbgemm over the logical m × n region using the passed ldc
4. Converts the entire ldc * n result back to BF16 and writes it back to C

This logic assumes C is contiguous or has exclusive access to ldc * n elements, which is not valid when C is a view into a larger tensor (as in multi-head attention). As a result, it overwrites memory outside the m × n region, corrupting adjacent data.

**Expected behavior:**
cpublas::gemm should only copy, compute, and write back the m × n region as described by the passed dimensions and ldc stride, not the full ldc × n span.
