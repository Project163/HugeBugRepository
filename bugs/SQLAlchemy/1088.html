Title

Sqlalchemy doesn't detect Identity columns when the table name has uppercase letters

Description
**Describe the bug**
Alembic 1.5.8 with version SQLAlchemy 1.4.2 is not detecting the Identity columns when the table name has uppercase letters. I was trying to run alembic automigrations but it's always saying that I have to modify the id column that has "GENERATED BY DEFAULT AS IDENTITY" property to server_default=None.

After some trial and error I discovered that when the table name has all lower case characters, alembic works as expected and says that no migration is needed. However, if I change the table name and capitalize the names, alembic begins to say that I have to "modify_default" with an Identity property.

**Expected behavior**
The behaviour that alembic has right now with the lower case tables should be the same that the tables with upper case characters.

**To Reproduce**
```
py

from alembic.runtime.migration import MigrationContext
from sqlalchemy import Column, Integer, Identity
from sqlalchemy.orm import declarative_base
```
