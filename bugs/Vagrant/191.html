Title

Duplicate provisioning triggers

Description
### Vagrant version

v2.2.11 onwards

### Host operating system

MacOS 10.15.7

### Guest operating system

Ubuntu 18.04

[URL]

### Expected behavior

When using the before and after provision triggers:

 `  config.trigger.before :provision do |trigger|`

and running `vagrant provision`, the trigger should trigger once before provisioning begins, and once after it finishes

### Actual behaviour

Instead the behaviour has fundamentally changed to instead be run before every individual provisioner. In our project it now runs a post provisioner script 17 times that used to run once, triggering rate limiting and spamming the terminal output

### Steps to reproduce

1. Add a trigger on provision e.g. `  config.trigger.before :provision do |trigger|`
2. Have multiple provisioners defined
3. Run `vagrant up --provision`
4. Observe duplicate trigger runs

It also seems that one of those triggers must try to run a script inside the VM for this to work if this is to be reproduced with `vagrant up --provision`, otherwise it requires `vagrant provision`, the behaviour between the two is inconsistent, see comments below
