Title

Empty group restores as AsyncResult.

Description
When attempting to restore a group that was empty, we get an `AsyncResult` instead of a `GroupResult`:

```
from celery import group
from celery.result = GroupResult

# This is actually a simplification: the list comprehension used here
# may evaluate to empty.
... [Log Snipped] ...

GroupResult.save(result)
```

Then, in another thread, possibly:

```
task = GroupResult.restore(result.id)
```

IMHO: this should be a `GroupResult` with an empty list for `.results`, but it's coming back as an `AsyncResult`.
Discussion
- Closing this, as we don't have the resources to complete this task.

GroupResult.restore and .save should not be used anymore.  I've removed use within celery itself already, and it's a bad pattern to use since it's difficult to clean up from.
- So how do we persist group results then? It's still documented as working, with no mention of deprecation at [URL]

- Hi,

Ran into this today.

Changing one line in `result_from_tuple` appears to do the trick. `nodes` here is an empty list when a group result is being restored, which evaluates False so the branch returning `GroupResult` is never hit:

```
        if nodes is not None:  # instead of just "if nodes"
            return app.GroupResult(
                res, [result_from_tuple(child, app) for child in nodes],
            )
```

Edit: I've run the test suite with this change and nothing fails. Haven't looked at adding a test for the desired behaviour yet.
