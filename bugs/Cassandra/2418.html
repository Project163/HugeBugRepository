Title

Skip mutations that pass CRC but fail to deserialize

Description
We've had a couple reports of CL replay failure that appear to be caused by dropping and recreating the same table with a different schema, e.g.   CASSANDRA-5905  .  While   CASSANDRA-5202   is the "right" fix for this, it's too involved for 2.0 let alone 1.2, so we need a stopgap until then.
Discussion
- Patch will save skipped mutations out to separate files in case user wishes to perform forensics.
- Lyuben, can you review? 

 To test, I suggest something like this: 

 
	 Flush, so only the new row is in the CL. 
	 Create a table and insert a row.  Copy the active CL segment. 
	 Drop table, recreate w/ incompatible schem (e.g., int -> double) 
	 Shutdown, move saved CL segment in; restart
