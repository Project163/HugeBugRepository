Title

The result of multiplying: Help to understand

Description
I thought, LESS always takes the units of the first operand
But it is not. Here's an example: [URL]
This bug or Fitch?
If that Fitch, then what is the logic? How do you know which unit will result in the operation?
Discussion
- Yes, this is bug. It's strange it took so long to reveal since it was introduced in v1.4.0 (v1.3.3 compiles the code as expected). Doh!
- I will look to fix before v2 is released as it is potentially breaking (even though its a bug..)
- Its pretty weird behaviour at the moment, though I can see why it is like that.

```
test: 1px * 1em; // 1 em
test: 1em * 1px; // 1em - order doesn't matter, the alphabetically first unit is chosen
test: (1em * 1px) / 1em; //1px
```

The problem is that the fallback happens when the output _would_ have 2 units. e.g. the output with strict units should be

```
test: 1em* 1px; // 1em*px
```

where as for + and - that is resolved at the point of the operation (because it has to be)

The only reason division doesn't have this is because the unit is px/em and 1/em isn't a valid unit, so we guess "px"
- I think I can fix this by changing our unit "backup" situation for when the code isn't following strict units.

The workaround till release is to make your units correct by dividing by the unit you do not want.
