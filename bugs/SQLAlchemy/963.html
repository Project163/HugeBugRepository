Title

sql-queries fail with a "Can't reconnect until invalid transaction is rolled back" for certain query parameter values

Description
**Describe the bug**
Queries sometimes fail with a "Can't reconnect until invalid transaction is rolled back" error when talking to a MS SQL Server database using pyodbc. This only happens for certain sql query parameter values.

**Expected behavior**
Sql queries should work for all valid parameter values.

**To Reproduce**
This problem occurs when a sql query fails and the string-representation of the resulting exception contains a substring that matches the error-codes that the "sqlalchemy.dialects.mssql.MSDialect_pyodbc.is_disconnect()" method checks for. 

In some cases, the string-representation of the exception contains the parameter-values to the failing sql query, so it is possible to reproduce this bug by first making a failing sql-query that includes one of the error-codes.

```
py

import sqlalchemy

# Note: The sqlserver database backend used in this test was started using docker-compose, with the following
... [Log Snipped] ...
    # now erronously return True.
    r = conn.execute(sqlalchemy.select([test_table.c.id]).where(test_table.c.id == test_id))
```

**Error**

```
  File "/home/knutj/python_venvs/notifier/lib/python3.6/site-packages/sqlalchemy/engine/base.py", line 473, in _revalidate_connection

```

**Versions.**
 - OS: Ubuntu 18.04.4 LTS
 - Python: 3.6.9
 - SQLAlchemy: 1.3.17
 - Database: Microsoft SQL Server (from the "microsoft/mssql-server-linux" docker image)
 - DBAPI:pyodbc

Discussion
- Thanks for reporting this. I am able to reproduce the issue and will investigate.

A workaround is to use `with engine.connect() as conn:` instead of `with engine.begin() as conn:`.
