Title

bug(common): date pipe rounds up date when fractional second is more than 3 digits

Description
Hi, 

I believe I've come across a bug in the date parsing. 
I haven't seen any indications that this is expected behavior, so I'm opening an issue here.

# 🐞 bug report

### Affected Package
@angular/common
Seems to be in every version I tested. Angular 6, 9, 10

[URL]

### Is this a regression?
Not that I've seen.

### Description
The Date pipe has some unexpected behavior when second fractions have more than 3 digits.

ISO 8601 format is not capped on fractional second number of digits.
[URL]
[URL]
[URL]
[URL]

## 🔬 Minimal Reproduction
[URL]
```
  3 digits: {{ '2020-08-01T23:59:59.999' | date: 'yyyy-MM-dd' }} 
   
  4 digits: {{ '2020-08-01T23:59:59.9999' | date: 'yyyy-MM-dd' }}
```
Discussion
- I am not sure of the history behind this but I think it might be by design. I note that the ISO 8601 specification says:


In other words the number of decimal places is implementation specific. And it appears that Angular has made the decision that it only accepts 3 decimal places.

In the [Link: Angular docs] there is a reference to the [Link: W3C Date and Time] document which restricts the ISO 8601 standard to a smaller number of formats. In particular it says:


That suggests that we should specify in our documentation what the maximum number of digits supported is. It is arguable that the table of "custom" formats in the `DatePipe` page implies that we only support 1, 2 and 3 digits, but I think we could/should be more clear about how we parse strings passed to `DatePipe` in order to then be rendered.

So I would say that this is not actually a bug in Angular, but instead either a documentation bug or a feature request to support more fraction digits.
- IMO there should at least be a way to customize it. I don't think Angular should force a choice of implementation by rounding up in that case. 

Even if Angular uses 3 digits, this should return the same result, not round up:
{{ '2020-08-01T23:59:59.999' | date: 'yyyy-MM-dd' }} 
{{ '2020-08-01T23:59:59.9999' | date: 'yyyy-MM-dd' }}

9999 should be parsed as 999, not 1000, which rounds up the entire date.

- It seems that the fourth digit is just ignored

new Date('2020-08-01T23:59:59.9229').getMilliseconds()
