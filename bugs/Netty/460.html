Title

OpenSslEngine returns NOT_HANDSHAKING instead of FINISHED

Description
Netty version: commit  

Context:

I was trying to use `OpenSslEngine` instead of JDK's `SslEngine` in Kafka and I noticed that the former returns a SSLEngineResult with handshakeStatus of `NOT_HANDSHAKING` instead of `FINISHED` from wrap and unwrap right after the handshake finishes. `SslHandler` has a workaround for this (`setHandshakeSuccessIfStillHandshaking`), which claims to be for Android, but it seems to also be needed for `OpenSslEngine` (I used this same workaround and it allowed me to make progress, but it took a while to diagnose the issue).

The reason this happens is that `getHandshakeStatus()` is called to populate `SSLEngineResult` and both overloads return `HandshakeStatus.NOT_HANDSHAKING` if `handshakeState` is `HandshakeState.FINISHED`. 

Fixing this probably involves using the return value of `handshake()` to correctly populate `SSLEngineResult`.

Steps to reproduce:
1. Add a println after every `case FINISHED:` in `SslHandler`
2. Run `OpenSslEngineTest`
3. Notice that it's never triggered
4. Run `JdkSslEngineTest`
5. Notice that it's triggered a number of times
6. Add a println in `setHandshakeSuccessIfStillHandshaking`
7. Run `OpenSslEngineTest`
8. Notice that it is triggered
