Title

AWT integration tests: Native: False positives on systems with older libs (fontconfig ?)

Description
### Describe the bug

I came across JDK x Mandrel portable builds (regardless of Mandrel version, both 21.2, 21.3 and 22.0) that pass Quarkus AWT tests on RHEL 9 :heavy_check_mark: , but fail on RHEL 8 :x: :
```
TIFF: Wrong pixel at 275x199. Expected: [255,0,0,255] Actual: [171,37,162,255] ==> expected:   but was:  
PNG:  Wrong pixel at 275x199. Expected: [255,0,0,255] Actual: [171,37,162,255] ==> expected:   but was:  
JPG:  Wrong pixel at 275x199. Expected: [254,2,0,0]   Actual: [174,36,157,0]   ==> expected:   but was:  
BMP:  Wrong pixel at 275x199. Expected: [255,0,0,0]   Actual: [171,37,162,0]   ==> expected:   but was:  
```
The test was looking for an edge of a character rendered with a specific font.

This might come down to a different native library version being used (fonts?) and needs attention.

I will either attend to the issue on the *Mandrel* side or adjust the *AWT test suite* to be more forgiving than it already is with thresholding expected pixel values.
