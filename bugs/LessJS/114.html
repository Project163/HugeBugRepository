Title

Equality check on strings seems off

Description
Assume the following sniplets:

```
less
@quotes: 'quotes';

p when (@quotes = 'quotes') {
  color: single-quotes;
... [Log Snipped] ...
  color: double-quotes;
}
```

```
less
@var: 'light\2D bown';

p when (@var = 'light\2D bown') {
  color: escaped;
... [Log Snipped] ...
  color: unescaped;
}
```

I would expect all guards to hold. However this is not the case. Apparantly:
- It matters whether a string uses single or double quotes
- Escape characters that are valid in CSS (`\2D`) are not understood

Is this known behaviour (I failed to find anything)?
Discussion
- The quotes case could be considered as a bug I think. The escaped chars case is more expected story I guess: since Less itself does not convert these escaped chars but passes them to CSS "as-is" these strings are not logically equal in Less context.
- I understand your take on this. Let me nevertheless give some background. In our case, depending on the environment PHP or JS is used to seed LESS with variable values (but both times Less.js is used for parsing). However they both use a different technique for properly escaping CSS strings. I would have hoped that LESS could understand that these are really the same.

Is this something that LESS.js does not **want**? Because of speed or more complexity on code base?
- Yep. Especially since if these values comes from an external environment which can take care of proper conversion on its own.
