Title

`default=True` on feature flags is order-sensitive

Description
The following code:

```
python
import click

@click.command()
... [Log Snipped] ...
if __name__ == "__main__":
    main()
```

when run with no arguments using click 8.2.1 outputs `'green'`, which is what I expect.  If click 8.3.0 is used instead, then it outputs `None` — but if the `--green` option is moved above the `--red` option in the script, click 8.3.0 will output `'green'`.

I believe that the script should output `'green'` regardless of the declaration order of the options.

Environment:

- Python version: 3.13.7
- Click version: 8.2.1 and 8.3.0
Discussion
- I've worked out a patch for this which seems to work, and which passes current tests, but I need to create new test cases to capture this behavior.

  diff so far 

```
diff
diff --git a/src/click/core.py b/src/click/core.py
index ff2f74a..2f84b26 100644
--- a/src/click/core.py
+++ b/src/click/core.py
... [Log Snipped] ...
+            # targeting the same variable name
+            ctx.params[self.name] = value
```

 

Basically, the issue is, at a coarse level, what you might guess: "something to do with `UNSET` vs `None`." Specifically, by converting `UNSET` to `None` too early during parsing, it becomes impossible to tell whether or not `default=None` was set (explicitly) on one of the parameters targeting the same name.
