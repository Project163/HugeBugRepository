Title

tsconfig contains duplicate include entries

Description

.svelte-kit/tsconfig.json "include" entry looks like this:

```

  "include": [
		"ambient.d.ts",
```

Discussion
- [URL]

This block is causing the duplicate entries. We could compare the relative output of both directories before adding them to the tsconfig.

But looking at it closer, shouldn't the output for `kit.files.routes` be along the lines of `/src/routes/**/*.js` instead of `/src/**/*.js`?
```
diff
- "../src/**/*.js",
- "../src/**/*.ts",
- "../src/**/*.svelte",
- "../src/**/*.js", // duplicate
... [Log Snipped] ...
+ "../src/lib/**/*.ts",
+ "../src/lib/**/*.svelte",
```
- Was just looking at the same thing, when the tsconfig was hardcoded in the templates, [Link: all of src was included], so can't tell if this was intended or not, and if we change it to be scoped to lib and routes now, 

It might _potentially_ be a breaking change?
- The default `app.d.ts` would also need to be moved to the directory of either `kit.files.routes` or `kit.files.lib`.

Perhaps a separate issue: currently, specifying a single folder as the path for either of those options such as `config.kit.files.routes = "app"` causes the output relative path to incorrectly go up 3 levels higher:
```
"../../../../**/*.js",
"../../../../**/*.ts",
"../../../../**/*.svelte",
```
- Only including sources in lib and routes would be a breaking change, yes. Looking closer at the logic, I'm wondering why we scoped it like this in the first place. Theoretically this would break if you're setting up the routes and lib folders in a weird way - but there's also no good way around this. I somewhat regret making parts of this that configurable.

Anyway, the fix would be to just deduplicate them. You could also have a closer look at the bug @s3812497 uncovered.
