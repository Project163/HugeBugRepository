Title

IfBuildProfile does not work on scheduler classes

Description
I have the following class

```
java
@IfBuildProfile(anyOf = {"dev", "prod", "RateLimitSchedulerProfile"})
public class RateLimitScheduler {

    @Scheduled(every = "1s")
... [Log Snipped] ...
    }
}
```

And the following test

```
java
public class RateLimitSchedulerProfile implements QuarkusTestProfile {
    @Override
    public String getConfigProfile() {
        return "test,RateLimitSchedulerProfile";
... [Log Snipped] ...

}
```

This test fails with 

```
text
[ERROR] Errors: 
[ERROR]   HelloResourceTest.testHelloEndpoint » Runtime java.lang.RuntimeException: io.quarkus.builder.BuildException: Build failure: Build failed due to errors
	[error]: Build step io.quarkus.arc.deployment.ArcProcessor#validate threw an exception: jakarta.enterprise.inject.spi.DeploymentException: jakarta.enterprise.inject.UnsatisfiedResolutionException: Unsatisfied dependency for type gr.RateLimitScheduler and qualifiers [@Default]
	- injection target: gr.RateLimitSchedulerTest#rateLimitScheduler
... [Log Snipped] ...
	at io.quarkus.arc.processor.BeanDeployment.init(BeanDeployment.java:323)
	... 12 more
```

In order to "fix" it i would have to use the `%test.quarkus.scheduler.enabled=false` and delete the `@IfBuildProfile` from RateLimitSchedulerProfile class.

Note: The test which fails is not the RateLimitSchedulerTest but the HelloResourceTest. If i disable the HelloResourceTest it works.

Discussion
- ~~IIUIC, you are mixing **build** profiles and **test** profiles.~~

~~Build profiles will be either `dev`, `test` or `prod`.
You can have beans existing in any combination of those three and you'd use the `IfBuildProfile`/`UnlessBuildProfile` annotations for it.~~

~~Test profiles can be multiple and customized and they typically override some config options of your application.
If you want a bean to be only present for certain test profile, you need to declare that bean within your custom implementation of `QuarkusTestProfile`. Here's the bit from its javadoc:~~

~~> If an implementation of this interface declares CDI beans, via producer methods/ fields and nested static classes, then those beans are only taken into account if this test profile is used. In other words, the beans are ignored for any other test profile.~~

**EDIT**: Mea culpa. I was wrong and apparently you can mix them exactly as you did because adding `@TestProfile(RateLimitSchedulerProfile.class)` to your other test makes the whole reproducer pass. So Martin is correct and this is indeed a bug.
- That's a very important piece of information! This means that `@IfBuildProfile` works as expected but for some reason the `RateLimitSchedulerTest` is also considered a CDI bean when `HelloResourceTest` is executed. This should not be the case. At least that's what I thought. But apparently `@QuarkusTest` is [Link: registered as a bean defining annotation] since 1.4.0.CR1 🤔 .
- A workaround is to use programmatic lookup in the `RateLimitSchedulerTest`, i.e. replace `@Inject RateLimitScheduler rateLimitScheduler` with `@Inject Instance  rateLimitScheduler` (`Instance` as in `jakarta.enterprise.inject.Instance`) and then obtain the bean instance with `rateLimitScheduler.get()`. This way there's no direct dependency on `RateLimitScheduler`,  the build does not fail and all tests pass.
