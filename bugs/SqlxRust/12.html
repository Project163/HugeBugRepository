Title

[sqlite] 0.4-pre sqlx:query doesn't correctly bind positional params

Description
I have an insert statement that works with `0.3.5`, but fails on `git="[URL] rev="e4005bb"`

### Schema
```
     "CREATE TABLE LOG_EVENTS (
          _id             INTEGER PRIMARY KEY AUTOINCREMENT,
          ray_id          TEXT NOT NULL,
          created_ms      DATETIME DEFAULT current_timestamp,
          send_attempts   INTEGER,
          data            TEXT,
          UNIQUE(ray_id, created_ms)
          )"
```

### Insert Code (same for both versions)

```
rust
sqlx::query(
                        "INSERT INTO LOG_EVENTS (send_attempts, ray_id, data) VALUES (?1, ?2, ?3)",
                    )
                    .bind(7 as i32)
... [Log Snipped] ...
                    .execute(&mut conn)
                    .await;
```

On 0.4-pre I get a lots of failures on the UNIQUE constraint because `7` is being put into the `ray_id` column. I can see this by selecting the successfully inserted data using `sqlite3` It also looks like the `ray_id` might be ending up in the `data` column`

```
sqlite> select * from LOG_EVENTS limit 10;
_id|ray_id|created_ms|send_attempts|data
1|7|2020-06-30 19:39:09|7|qrPEgVfpwpcL5K9X
```
Discussion
- It looks like this is because SQLite positional parameters use 1-based indices but we bind them on a 0-based index:

[URL]

It *might* be as simple as changing this `for` loop from `0 .. cnt` to `1 ..= cnt`: [URL]
