Title

Old relationship collection is modified when assigning a new list

Description
**Migrated issue, originally created by Adrian ([Link: @thiefmaster])**

I noticed this strange behavior in some code that logs changes and thus stores the old value before updating. Here's a simple case that reproduces it:

```
python
from sqlalchemy import *
from sqlalchemy.ext.declarative import declarative_base
from sqlalchemy.orm import *

... [Log Snipped] ...
print('old    ', old)
print('new    ', foo.bars)
```

Output:

```
('initial', [ ,  ])
('old    ', [])
('new    ', [ ,  ])

--------
... [Log Snipped] ...
('old    ', [ ])
('new    ', [ ,  ])
```

I'd expect the list in 'old' to be the same as it is in 'initial'. After all, I'm assigning a new one so the old one should not be modified by that.
Of course I could work around it by unconditionally calling copy() on the old attribute but it feels a bit like a bug to me.
