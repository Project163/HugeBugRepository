Title

comma-dangle = always-multiline and the spread operator

Description
There is a bit of an issue with `comma-dangle` set to `"always-multiline"` and the spread operator used in a destructuring assignment:

```
var [
  x,
  y,
  ...data // Getting "missing trailing comma" error
] = parsed;
```

For compliance with [Link: spec] there should be no comma after the `AssignmentRestElement` and I think that `"always-multiline"` should treat this as a special case and ignore the missing trailing comma.

For now I'm ignoring the error for this line.

The version I have is 1.2.1.
Discussion
- I have two questions:
1. Though espree seems to make a `SpreadElement` node for `AssignmentRestElement`, is it correct?  
   I guessed espree should make a `RestElement` node.
2. When I consider the code `for ([a, ...rest] of []);`, though espree make an `ArrayExpression` node for `[a, ...rest]`, is it correct?  
   I guessed espree should make an `ArrayPattern` node.
   `ArrayLiteral` allows a trailing comma after `SpreadElement` in [Link: the spec], so the difference is important.
- These seem like Espree bugs. Can you file issues for those?
- ... [Middle Discussions Snipped for Brevity] ...
- Wouldn't a better error message be a good solution here?
```
Unexpected trailing comma - no comma allowed after rest properties.
```

If so, then I could do that.
- I feel like this case is fundamentally the parser's job to handle. It seems strange for us to add logic for a new error message just to account for a bug in `babel-eslint`.

Updating the documentation sounds good to me, though.
