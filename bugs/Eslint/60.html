Title

Getters/setters shouldn't trigger no-dupe-keys

Description
The following code triggers the no-dupe-keys rule in v0.4.0:

```
javascript
var foo = {
    get prop() {
        return this.p;
    },
... [Log Snipped] ...
    }
};
```

```
bash
$ eslint foo.js

foo.js
  1:10  error  Duplicate key 'prop'            no-dupe-keys
... [Log Snipped] ...

✖ 3 problems
```

It seems that the rule doesn't consider getters/setters declared in object initializers.
