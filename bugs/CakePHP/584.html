Title

"ORDER BY" isn't always skipped while counting rows

Description
I have query like that:

``` php
$detailsTable = TableRegistry::get('Offers.GenericProductsDetails');
$detailsCount = $detailsTable->find()->where(['product_id' => $id])->count();
```

And in GenericProductsDetailsTable.php:

``` php
public function beforeFind($event, $query) {
   return $query->order([$this->alias().'.price' => 'ASC']);
}
```

While executing count query I have SQL error, because to query count is appended "ORDER BY" statement. If I use order() in first piece of code instead of beforeFind(), then no "order by" is appended, and its executed properly. The same is If I use order() method in findAll() instead of bedoreFind().
But using order() in beforeFind() cause sql error. A few days ago this problem doesn't exist.
Discussion
- Can you paste the SQL? I don't understand how adding a ORDER BY to a count can result in a SQL error.
- SQL query before cake update:

``` sql
SELECT (COUNT(*)) AS "count" FROM "offers"."generic_products_details" "GenericProductsDetails" WHERE "product_id" = 4
```

And now:

``` sql
SELECT (COUNT(*)) AS "count" FROM "offers"."generic_products_details" "GenericProductsDetails" WHERE "product_id" = $1 ORDER BY "GenericProductsDetails"."price" ASC
```
- ... [Middle Discussions Snipped for Brevity] ...
- Opened up a PR to fix this issue, #5151.
- ```
public function beforeFind($event, $query) {
   return $query->order([$this->alias().'.price' => 'ASC']);
}
```

This approach is wrong IMHO. Not all SQL statements can have `ORDER BY` clause. And not all statements need to have the same `ORDER BY`. If it is called this way any developer who uses this code would expect `ORDER BY GenericProductsDetails.price ASC` to be added to **any** queries in that model including the one that uses `COUNT(*)`.

I think the correct approach would be to use a [Link: custom finder] like `findSorted` instead of blanket sorting in beforeFind.
