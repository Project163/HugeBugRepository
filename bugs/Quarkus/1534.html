Title

Rest Client sets own User-Agent header even if user specifies a different one

Description
### Describe the bug

This issue is based on the Zulip chat: [URL]

We have a reactive rest client where we set a custom `User-Agent` header. The user agent needs to be this specific value for the API to accept our request. 

```
@RegisterRestClient(configKey = "xxxxx")
@Produces(MediaType.APPLICATION_JSON)
interface GatewayApi {
    @GET
    @Path("zzzzz")
... [Log Snipped] ...
    ): Response
}
```

Unfortunately, it seems that Quarkus versions >= 2.7.0 add an own `User-Agent` header value with the value: `Resteasy Reactive Client`. This value is always added, no matter if we set our own `User-Agent`. So when we make a request the `User-Agent` header has the values: `[Resteasy Reactive Client, Our_Custom_Header_Value]` compared to versions  ?, clientOutgoingHeaders: MultivaluedMap ?): MultivaluedMap  {
        val clientHeaders = MultivaluedHashMap ()
        "Our_Custom_Header_Value".addHeader("User-Agent", clientHeaders)
        return clientHeaders
    }
}
```

### Expected behavior

The rest client should only add its own `User-Agent` header when we do not specify our own header. This should apply when the header is set with the `@HeaderParam` annotation in the method as well as when using `@ClientHeaderParam` to set a `User-Agent` header. 

### Actual behavior

The rest client always adds it's own User-Agent header.
