Title

`torch.nn.functional.max_pool1/2/3d` and `torch.quantized_max_pool1/2d` can not handle several edge cases in 1.13.1

Description
### 🐛 Describe the bug


When the argument (e.g., `dilation`) input is a list, if its value is over the upper bound of int64, `torch.nn.functional.max_pool1/2/3d` and `torch.quantized_max_pool1/2d` will report TypeError instead of throwing an overflow error:

```
TypeError: max_pool1d(): argument 'dilation' must be tuple of ints, but found element of type int at pos 1
```

In [Ref: #73840], a similar problem on `torch.max_pool1d` was first reported and confirmed as an edge case to be fixed.
However, similar bugs on `torch.nn.functional.max_pool` and `torch.quantized_max_pool` exist in 1.13.1 and other previous versions.

In addition, there is another interesting behavior related to this bug.
If the argument is not a list `[x]` but a direct value `x`, then there will raise an error for the overflow problem, which is expected behavior.
```
Traceback (most recent call last):
  File "test.py", line 19, in  
    test()
  File "test.py", line 18, in test
    func_cls(input, kernel_size=i , stride=i, padding=0, dilation=i, ceil_mode=True)
RuntimeError: Overflow when unpacking long
```

### To Reproduce
```
python
import torch
import sys

i = sys.maxsize + 1
... [Log Snipped] ...
	func_cls(input, kernel_size=[i] , stride=[i], padding=0, dilation=[i], ceil_mode=True)
test()
```

### Expected behavior

For this type of edge case, an overflow error should be thrown (e.g., `RuntimeError: Overflow when unpacking long`) instead of raising a TypeError.
