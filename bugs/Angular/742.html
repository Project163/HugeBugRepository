## Current behavior
 
[URL]
If you filter the API reference index by type=package, the status filter does nothing. No matter what status filter option is chosen, all packages are displayed.

## Expected behavior
 
Some options:
1) Disable status filter, so it's clear that it doesn't apply when type=package
2) If entire packages do have a status, find a way to encode that so we can enable status filter and have it behave the same way it does for individual types
3) If a package's status can be derived from its exports, then use the types to determine package status? I'm not sure if this one makes sense, but I could imagine "type=package & status=security risk" returning every package that has at least one export for which status=security risk. 

## Minimal reproduction of the problem with instructions
 
1. Go to angular.io/docs
2. Choose API from left nav
3. Choose type=package
4. Choose status=security risk
All packages are listed.
5. Choose status=deprecated
All packages are listed. 

[URL]

## What is the motivation / use case for changing the behavior?
 
To cause package list to match selected filter settings.
