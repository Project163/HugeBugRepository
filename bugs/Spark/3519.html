Title

JobProgressListener takes a huge amount of memory with iterative DataFrame program in local, standalone

Description
TL;DR 

 Running a small test locally, I found JobProgressListener consuming a huge amount of memory.  There are many tasks being run, but it is still surprising.  Summary, with details below: 
 
	 Spark app: series of DataFrame joins 
	 Issue: GC 
	 Heap dump shows JobProgressListener taking 150 - 400MB, depending on the Spark mode/version 
 

   Reproducing this issue 

   With more complex code 

 The code which fails: 
 
	 Here is a branch with the code snippet which fails:  [URL]
	 
		 This is based on Spark commit hash:   
	 
	 
	 Look at  CC.scala , which implements connected components using DataFrames:  [URL]
 

 In the spark shell, run: 
  
  import  org.apache.spark.ml.CC
 import  org.apache.spark.sql.SQLContext
val sqlContext = SQLContext.getOrCreate(sc)
CC.runTest(sqlContext)
 
  

 I have attached a file  cc_traces.txt  with the stack traces from running  runTest .  Note that I sometimes had to run  runTest  twice to cause the fatal exception.  This includes a trace for 1.6, which should run without modifications to  CC.scala .  These traces are from running in local mode. 

 I used  jmap  to dump the heap: 
 
	 local mode with 2.0: JobProgressListener took about 397 MB 
	 standalone mode with 2.0: JobProgressListener took about 171 MB  (See attached screenshots from MemoryAnalyzer) 
 

 Both 1.6 and 2.0 exhibit this issue.  2.0 ran faster, and the issue (JobProgressListener allocation) seems more severe with 2.0, though it could just be that 2.0 makes more progress and runs more jobs. 

   With simpler code 

 I ran this with master (~Spark 2.0): 
  
 val data = spark.range(0, 10000, 1, 10000)
data.cache().count()
 
  

 The resulting heap dump: 
 
	 78MB for  scala.tools.nsc.interpreter.ILoop$ILoopInterpreter  
	 58MB for  org.apache.spark.ui.jobs.JobProgressListener  
	 80MB for  io.netty.buffer.PoolChunk
