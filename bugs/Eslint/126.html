Title

Rule 'no-unused-vars' now checks 'globals' in .eslintrc

Description
By #955 and its related issues, `no-unused-vars` should check for vars in `/*globals */` section and CLI `--globals` arg. Also, seems now it checks vars against `globals` section in `.eslintrc` file also, what I guess is a bug.
Discussion
- Yeah you're right. That's odd, I could have sworn that that fix only included `/*globals*/` and `--global`. Well, since this will have to be fixed by differentiating the different globals farther up in the code anyway, this is a good place to pose the question: Out of globals defined in external config files, globals defined on the CLI with `--global`, and globals defined in each file with `/*globals*/`, which should be counted by `no-unused-vars`? My instinct is just the lattermost.
- I agree. We should only check globals that are specified with `/*global*/`. It's hard to argue that a set of globals (whether through config or command line) must be used by all files being checked.
