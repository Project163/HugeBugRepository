Title

`@calendar` locale param passed to Yii::t() calls from Formatter

Description
Yii 2.0.7 introduced the ability to format dates with non-Gregorian calendars ( ). The main way the docs specify to do that is by setting the `Formatter` class’s new `calendar` property to `IntlDateFormatter::TRADITIONAL`, and appending `@calendar= ` to the `locale` property.

However, the `locale` property is passed to several `Yii::t()` calls within the `Formatter` class, which is only expecting a language string, not ` @calendar= `.

[URL]

These calls will end up causing Yii to re-load all `yii` translations messages with a different translation key that includes the `@calendar` param, and if the language happens to be more than two letters (e.g. `xx-YY`), the correct translations won’t even get loaded; `yii\i18n\PhpMessageSource::loadMessages()` won’t be able to find `xx-YY@calendar= /yii.php` so it will fall back to `xx/yii.php` instead (if it even exists – not the case with `nb-NO`, `zh-CN`, or `zh-TW`).

### What steps will reproduce the problem?

Create a `yii\i18n\Formatter` instance with a locale ID that has more than two characters, and a custom calendar type.

```php
$formatter = new Formatter([
    'locale' => 'zh-CN@calendar=persian',
    'calendar' => IntlDateFormatter::TRADITIONAL,
]);
```

### What is the expected result?

The formatter’s internal `Yii::t()` calls should ignore the `@calendar` param on the `locale` property.

### What do you get instead?

`Yii::t()` calls include the `@calendar` param in their `$language` argument.
