Title

Pagination prepareTotalCount() incorrectly removes WHERE from query

Description
Relation definition:

```
php
    public function getCharacters()
    {
        return $this->hasMany(Character::class, ['show_id' => 'id']);
    }
... [Log Snipped] ...
        return $query;
    }
```

Command:

``` php
$show->guestCharacters;
```

Generated query (correct):

``` sql
SELECT `Character`.*, count(*) as count FROM `Character` INNER JOIN `GuestCast` ON `Character`.`id` = `GuestCast`.`character_id` WHERE `Character`.`show_id`=1012 GROUP BY `Character`.`id` ORDER BY `count` DESC LIMIT 20
```

Pagination-count-query (incorrect):

``` sql
SELECT COUNT(*) FROM (SELECT `Character`.*, count(*) as count FROM `Character` INNER JOIN `GuestCast` ON `Character`.`id` = `GuestCast`.`character_id` GROUP BY `Character`.`id`) `c`
```

As you can see the WHERE part (`WHERE Character.show_id=1012`) has disappeared from the query after it's gone through prepareTotalCount(), which causes the pagination to be completely off.
Discussion
- How do you get this pagination-count-query?
- Ah, could have made that a bit more clear: it's executed automatically because I use the query in an ActiveDataProvider and subsequentially in a ListView.

```
$dataProvider = new ActiveDataProvider([
    'query' => $show->getGuestCharacters(),
]);
```
- Could be related with [URL]
- Confirmed it is a duplicate of #3787.
Basically when building a sub-query, the filtering condition (by master AR values) and the on-condition are both skipped. These conditions should be applied in `Query::prepare()`. Currently they're done in private methods when creating commands within ActiveQuery.
