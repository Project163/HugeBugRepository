Title

SecondaryIndexManager incorrectly updates index build status system table

Description
The  markIndexBuilt  and  markIndexRemoved  methods on  SecondaryIndexManager  incorrectly supply the table name to the methods on  SystemKeyspace  which update the underlying system table. They should pass the keyspace name instead, which results in incorrect rows being written to/removed from the system table when a rebuild of the index is performed.
Discussion
- I've pushed a branch with a fix & a unit test for this, which also exposes the 2  markIndexXXX } methods on  SIM  so that index implementations can call them after performing an initial build.  CassandraIndex  was duplicating this functionality (albeit without the bug), in its  buildBlocking  method. 

 There's another  SIM  bug that can be cleaned up here; The call to  unregisterIndex  from  removeIndex  is unnecessary as the index has already be removed from the collection of known indexes earlier in the method. This is mostly harmless, but it will result in an erroneous log message at  TRACE  level.
