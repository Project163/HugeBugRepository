Title

`add_startup_stage_before` and `add_startup_stage_after` do not work with core startup stage

Description
## Bevy version

0.5

## Operating system & version

Windows 10

## What you did

use bevy::prelude::*;

```rust
fn main() {
    App::build()
        .add_plugins(DefaultPlugins)
        .add_startup_stage_after(CoreStage::Startup, "new_stage", SystemStage::parallel())
        .run();
}
```

## What you expected to happen

This should compile adding a startup stage after our initial startup stage.

## What actually happened

```
thread 'main' panicked at 'Target stage does not exist: Startup.'
```

## Additional information

This occurs with both before and after, and the same type of error is given for any other core stage. `add_startup_stage` itself works though, and the following variant runs successfully:

```
rust
use bevy::prelude::*;

fn main() {
    App::build()
... [Log Snipped] ...
        .run();
}
```

Changing the order of adding the default plugins vs adding the startup stage doesn't make a difference.
Discussion
- I've ran into this before. The Startup stages are not under CoreStage, but under StartupStage: [URL]
```rust
.add_startup_stage_after(StartupStage::Startup, "new_stage", SystemStage::parallel())
```
- That fix worked for me.

`CoreStage::Startup` should probably not exist then, and we should document how `add_startup_system_after` should be used :)
