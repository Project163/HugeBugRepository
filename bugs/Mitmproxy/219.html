Title

OpenSSL.crypto.X509Name cannot be garbage collected

Description
#### Problem Description

If run mitmdump for a long time, its memory will keep increasing. I manage to narrow down the suspected memory leak is, this line of code in the `dummy_cert` function from `mitmproxy/certs.py` file.

[URL] 

This line will keep creating many `OpenSSL.crypto.X509Name` objects. And they are cannot be garbage collected.

Run the below script to reveal this problem quickly.


Mitmproxy: 7.0.0.dev (+221, commit 6123675)
Python:    3.9.1
OpenSSL:   OpenSSL 1.1.1i  8 Dec 2020
Platform:  macOS-10.15.7-x86_64-i386-64bit

#### Temporary Fix

`OpenSSL.crypto.X509` uses `self._issuer_invalidator = _X509NameInvalidator()` to invalidate `X509Name` object 
(in this problem it is issuer name). It holds them forever even the dummy certs are no longer in usage.

Use `X509.from_cryptography` and `X509.to_cryptography` to create a new `X509` object to resolve this problem.

[URL] 

Replace this line of code with the below code.

```python
new_cacert = OpenSSL.crypto.X509.from_cryptography(cacert.to_cryptography())
cert.set_issuer(new_cacert.get_subject())
```

The `X509` and `X509Name` objects make references between themselves.
And they will be garbage collected if the dummy cert being garbage collected.
