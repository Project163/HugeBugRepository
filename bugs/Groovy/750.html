Title

Groovy calls wrong method if they are the same name and an Array attribut

Description
This is an example : 

 public class Test{ 
	public Object getReturnValue(Object a, int b) 
	{
		return "h";
	}
 	private Object getReturnValue(Integer a, int b, 
			Object[] arr)   
{
		return "i";
	}
 } 

 if in the script we call the first method, groovy calls directly the second... 

 x = new Test(); 
x.getReturnValue(new Integer(1),1) 

 returns "i". 

 If the last arg is not an array it's ok.
Discussion
- Assuming both methods would be public, the Java would call exactly the same method. As for selecting a method that should not have been visible... this is tracked by other bugs already. So I am closing this as "not a bug", because the method selection does the right thing, based on the assumption both methods are visible.
- Even if the both methods are public Groovy calls the second. 

 For example : 
  
  public   class  Test{
	 public   Object  getReturnValue( Object  a,  int  b)
	{
		 if (a  instanceof   Integer ) {
			 int [] c= {1};
			 return  getReturnValue(( Integer )a, b, c);
		}
		 if (a  instanceof  BigDecimal) {
			 int [] c= {2};
			 return  getReturnValue((BigDecimal)a, b, c);
		}
		 return   null ;
	}

	 public   Object  getReturnValue( Integer  a,  int  b,
			 int [] arr)  {
		 return  arr[0];
	}
	
	 public   Object  getReturnValue(BigDecimal a,  int  b,
			 int [] arr)  {
		 return  arr[0];
	}
}
 
  
 With this we get a Stack because groovy call directly the second method and not initialize the int array. It's lot logic. 

 x = new Test(); 
x.getReturnValue(new Integer(1),1) 

 to works we need to do this : 

 x = new Test(); 
x.getReturnValue((Object)(new Integer(1)),1)
