Discussion
- As a first step I added a new test in commit c0de459 to stress test the ziplist -> hash conversion. So far the test is passing without problems. I'm going to further analyze the bug today.

Since the original posters of this bug saw it multiple times probably it's a good idea to distribute a modified version of Redis that can provide more information when this assert fails.
- I walked the dictAdd code and haven't found any holes, even around encoding + rehashing occurring concurrently.  

I'm now wondering if the ziplist version of my hashtable has duplicates in it.  RDB load has no protection, nor does save, so if one creeps in I dont think I'd notice until an expansion.  I'm thinking of adding a verification pass that can be switched on during load to watch for duplicates.
