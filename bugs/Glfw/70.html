Title

glfwGetProcAddress does not return the addresses of core functions with EGL backend

Description
Information:
- Build version is from 2015/08/25
- Tested with Power VR SDK and Google Angle
- Window with EGL

I'm trying to make a version that use GLES 2.0 on Windows.
After tracing, context and a surface is ok.
But its crashing in _glfwRefreshContextAttribs.

The reason is that glfwGetProcAddress for glGetIntegerv/glGetString/glClear return NULL
I don't know why.

Sylvain.
Discussion
- Which commit are you on?
- This shouldn't have worked before either. GLFW only uses `eglGetProcAddress`, which does not return the addresses of core functions.

I've been working on a patch for this, as a companion to  . It'd be very helpful to know all the various file names for client libraries in the various SDKs you use, to make the dynamic loading more robust.
- ... [Middle Discussions Snipped for Brevity] ...
- Please try the `dynamic-client` branch.
- I've tested with the sample heightmap.
i've just added this line to choose the appropriate GLES version:

glfwWindowHint(GLFW_CLIENT_API, GLFW_OPENGL_ES_API);
glfwWindowHint(GLFW_CONTEXT_VERSION_MAJOR, 2);
glfwWindowHint(GLFW_CONTEXT_VERSION_MINOR, 0);

and updated the shader to be compatible with GLES 2.0.

All works fine.
Thanks!
