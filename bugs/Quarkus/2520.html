Title

Deadlock when using SseBroadcasterImpl

Description
### Describe the bug

I am currently using quarkus 3.29.2 but I am facing this issue for quite a while now since we added SSE endpionts to our application. This is already a couple of major quarkus versions ago.

The issue is that once in a while the sending of SSE events to registered clients stopps and the vert.x BlockedThreadChecker warns me about threads that have been blocked.

Now I was finally able to track down the issue to a deadlock scenario that occurs between the **SseBroadcasterImpl** and the **SseEventSinkImpl** when a new SSE-Event is sent to the SseEventSink while at the same time it is beeing closed in a different thread.

```
Found one Java-level deadlock:
=============================
"vert.x-eventloop-thread-26":
  waiting to lock monitor   (object  , a org.jboss.resteasy.reactive.server.jaxrs.SseBroadcasterImpl),
  which is held by "NotificationReceiver Thread"
... [Log Snipped] ...
  waiting to lock monitor   (object  , a org.jboss.resteasy.reactive.server.jaxrs.SseBroadcasterImpl),
  which is held by "NotificationReceiver Thread"
```
I believe what happens here is as follows:

A SseEventSinkImpl instance will be registered on a SseBroadcasterImpl instance when the client calls the SSE endpoint. During registration the SseEventSink remembers the instance of  the SseBroadcaster
```
void register(SseBroadcasterImpl broadcaster) {
        if (this.broadcaster != null)
            throw new IllegalStateException("Already registered on a broadcaster");
        this.broadcaster = broadcaster;
}
```
When the SseEventSink gets closed after a while, the broadcaster reference is used to signal the broadcaster that this instance was closed and should be removed.
```
public synchronized void close() {
        .....................
        if (broadcaster != null)
            broadcaster.fireClose(this);
    }
```
The broadcaster.fireClose() method is also synchronized on a method level
```
synchronized void fireClose(SseEventSinkImpl sseEventSink)
```
