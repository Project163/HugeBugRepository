Title

etcdctl updatedir requires value

Description
We have upgraded to 2.2.0 and previous processes that use the `updatedir` subcommand with `etcdctl` fail.

After further investigation, we have discovered `updatedir` now requires a value to function.  This doesn't make sense to me as directories don't have values.  I believe `ttl` is the only changeable bit of data on a directory and it is accessible via the `--ttl=n` command switch.
## Repro steps

_does not work_

```
etcdctl setdir --ttl=60 /foo
etcdctl updatedir --ttl=60 /foo
```

The second command will hang, waiting for standard input. If you `^d` the command will successfully complete.

_will work_

```
etcdctl setdir --ttl=60 '/foo'
etcdctl updatedir --ttl=60 '/foo' 'bar'
```

`bar` isn't used at all.  Infact, if you use the `--debug` switch you see no evidence of `bar` in the provided curl command.

```
etcdctl --debug updatedir --ttl=60 '/foo' 'bar' 
start to sync cluster using endpoints(http://etcd:2379)
cURL Command: curl -X GET [URL]
got endpoints(http://etcd:2379) after sync
Cluster-Endpoints: [URL]
cURL Command: curl -X PUT [URL] -d "ttl=60"
```

We even ran tcpdump while executing this command, and again see no evidence of the `bar` value.

```
tcpdump -A -s 0 'tcp port 2379 and (((ip[2:2] - ((ip[0]&0xf) >2)) != 0)'
 
{"action":"update","node":{"key":"/foo","dir":true,"expiration":"2016-01-06T12:33:00.474562958Z","ttl":60,"modifiedIndex":2605,"createdIndex":2604},"prevNode":{"key":"/foo","dir":true,"expiration":"2016-01-06T12:32:52.592657605Z","ttl":53,"modifiedIndex":2604,"createdIndex":2604}}
```

So if the value isn't used, why is it required?

I traced it down to this commit   from @xiang90.

```
    key := c.Args()[0]
    value, err := argOrStdin(c.Args(), os.Stdin, 1)
    if err != nil {
        handleError(ExitBadArgs, errors.New("value required"))
    }
```

Thanks!
