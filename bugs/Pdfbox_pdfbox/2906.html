Title

Issue with embedded Font and descendant Font

Description
On the attached PDF, a text where the second font is used cannot be rendered: 

     
From debugging I can see, that PDType0Font.codeToGID(code) does return "0" for this chars. 
The call there is delegated to descendantFont.codeToGID(code). 
However at least for code to unicode, the map is in the font itself, not the descendant: 
     
The font view in the PDF Debugger also shows codes from 1 to 7, instead of those from the unicode map.
Discussion
- It stopped working between 2.0.2 and 2.0.3.
- The toUnicodeCMap is for text extraction, which works. 

 I had a look at the font, the glyphs are in CID 17, 20, 21, 23, 24, 27, 342.  
      

 Our log shows this:
