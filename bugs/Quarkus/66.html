Title

@Timed and @Counted annotations fails when exceptions occurs

Description
The following method with ```@Counted``` and ```@Timed``` annotations fails if any exception occurs during the invocation. For instance, if I want the method to throw a javax.ws.rs.NotFoundException in some cases, it doesn't work due to these annotations and I instead get a HTTP status 500. If I remove the annotations the expected HTTP status code is 404 when calling ```/greeting/notfound```
```
java
  @GET
  @Produces(MediaType.TEXT_PLAIN)
  @Path("/greeting/{name}")
  @Timed(name = "greetingTime", description = "Timing of the greeting method", absolute = true)
... [Log Snipped] ...
    return service.greeting(name);
  }
```
I'm using Quarkus version 0.12.0, JDK 11 on macOS Mojave and maven 3.6.0

Discussion
- @jmartisk does it work outside of Quarkus? I think it's something that should be supported.
- I just tried the same with Thorntail and it works correctly there, it seems we might need a change in Quarkus. Let me have a look what can be done.
- The problem seems to be related to the fact that metric interceptors in SmallRye Metrics have `@AroundInvoke` methods that are `private` (in the case of counters: [URL] 

In Quarkus, it seems that when a REST endpoint is intercepted by such interceptor, and the endpoint throws an exception, and the interceptor simply rethrows it, then the exception gets wrapped in a `RuntimeException` here:  [URL]

But then it is no longer a `NotFoundException` but rather a `RuntimeException` so it is not mapped to 404 but to 500 by RESTEasy.

@mkouba , is this the correct behavior that an exception gets wrapped into a `RuntimeException` if it is rethrown by an interceptor with a private `@AroundInvoke`? In Thorntail the exception seems to stay as it is. Perhaps the `Reflections` class, if it receives an `InvocationTargetException`, should unwrap the original exception from inside it? 

If that can't be done, we would need to fix this by making the interceptors in SR-M `public`.
- @jmartisk +1 for unwrapping the original exception. Feel free to send a PR! ;-)

Anyway, changing the interceptor methods to package-private would not hurt too. I see no real value in having them `private`.
