- I'm facing the same problem here and want to contribute something to "_What is the motivation / use case for changing the behaviour_"

My application is divided into two columns. 
First one contains sidebar and beneath it an "action area" (outlet: actions) where typical actions like "Save this and that" are located. The second one is the main content area (outlet: primary).

The actions area depends on the main content - obviously. If you are in _Customers_ pages you want a different actions-component (e. g. CustomersEditActionsComponent) in that actions outlet than in _Settings_ pages (e. g. SettingsActionsComponent).

When a user navigates to '**www.myapp.com/settings**', I actually want to router to navigate to '**www.myapp.com/settings/core(actions:settings-actions)**' - per default. But this won't work:

```
[{
    path: 'settings', component: SettingsComponent, canActivate: [AuthGuard],
    children: [
      { path: '', redirectTo: '/settings/core(actions:settings-actions)' , canActivate: [AuthGuard] },
      { path: 'core', component: SettingsCoreComponent, canActivate: [AuthGuard] },

    ]
  }]
```

That's necessary because normal users don't type those aux-routes-bracket-stuff. They know "If I type _/settings_ I should come to Settings, if I type _/profile_ I should come to my profile..." for years now. Problem is: route would open, actions outlet would be empty, application does not work as expected.
