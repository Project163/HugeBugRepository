Title

The validation does not work for the reference.

Description
The validation feature does not support to validate the reference.  In the "$ref" element
[Image: incorrect referenct]

, I input an incorrect value, the validation can still pass. Actually, it should throw error and report.

Discussion
- Also, I noticed that validator treats references as validation errors. For instance, let's put a reference to parameter list:

```
/foo:
    get:
      summary: Some endpoint
      parameters:
        - name: some_id
... [Log Snipped] ...
          type: integer
        - $ref: '#/parameters/some_shared_param'
```

Validator output for such case is:

```
- paths./foo.get.parameters.$ref in body is a forbidden property
- paths./foo.get.parameters.name in body is required
- paths./foo.get.parameters.in in body is required
- paths./foo.get.parameters.type in body is required
```

As specification says, using references in parameter list is valid: [URL] (`parameters` is expected to hold an array `[Parameter Object | Reference Object]`)

Is there any plans to fix? Perhaps I overlooked something :)
- this is a new issue or at least it's different from the one that's reported. But it is a bug
- I thought that it looks similar because of the same reason: incorrect processing of `$ref` :) Let me open a new one...
