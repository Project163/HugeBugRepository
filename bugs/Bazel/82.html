Title

namespace-sandbox bug in getopt usage

Description
```
while (optind < argc && argv[optind][0] == '@') {
    const char *filename = argv[optind] + 1;
    const int old_optind = optind;
    optind = 1; <== this needs to be set to 1; note that ParseOptionsFile adds an empty zero-th argument
    optreset = 1; <== according to the manpage, this needs to be set before calling getopt on a second pass
... [Log Snipped] ...
    optreset = 1; <== here also
  }
```
Discussion
- I tried to use part of this .c file on OSX where the getopt call fails immediately on params files.
- Also, it's leaking memory. There's a malloc call for full_sandbox_path in SetupDirectories, but no corresponding free call.
- And the use of dirname isn't safe on OSX. While linux makes modifications in-place - so we have to make a copy before calling dirname -, OSX returns a pointer to a statically allocated buffer - so we have to make a copy after calling dirname (otherwise the value will change underneath us the next time we call dirname; which is a problem for the recursive directory creation).
- I think this is obsolete with the new sandbox being released now.
