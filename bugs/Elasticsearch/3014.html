Did you capture a stack trace for the failure? A way to do that is to add the url parameter `error_trace`, this will return a stack trace of the exception thrown in the response body and will help diagnose the bug.
- @li5m one more question: do you set the `realtime` parameter? Or do you use the default value of `true` for the `_mget` request?
- @elastic/es-distributed this is really weird. 

In the `DenseVectorFieldMapper` we override the codec used so that this error isn't thrown. The value shown in the error indicates that the document indexing path was executed without our overridden codec settings.

I am digging into the various `_mget` paths and its starting to think it has something to do with us getting realtime values via the Translog. 

Do we do anything there that simulates the indexing path for a document that relies on the default codecs being used?
