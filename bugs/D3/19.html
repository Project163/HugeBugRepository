Title

d3.layout.force’s on operator should behave like selection.on.

Description
Currently you can only add event listeners. You should be able to replace and remove listeners, as well, with the same semantics as selection’s on operator. This isn’t strictly backwards-compatible, but the current behavior is clearly a bug if there is no way to remove an existing listener.
Discussion
- This also applies to transition.each.
- Should the following be removed from the API docs then?

"Note: there is currently no way to remove or replace listeners. This is a bug; see #294. In a future release, the type will allow namespaces for registering multiple listeners."
