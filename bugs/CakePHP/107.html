Title

Sqlserver Datasource should handle schema prefix better

Description
Based on the 2.5 branch, in a model, $this->schemaName is getting overwritten with the default $db->getSchema.

Additionally, the Sqlserver Datasource is not properly appending the schemaName when describing the table.

In situations where a single database has two tables with the same name, but different prefixes (such as dbo.Person and live.Person), the current Sqlserver describe method's SQL is bringing back fields for BOTH tables. Appending the prefix properly will remedy this.
