Discussion
- Assimp checks the file extension first. `.STP` is not listed as supported by the IFC importer, and neither by any other importer, so that fails.

After that, Assimp looks at the beginning of the file and searches for keywords. IFC will pick up `ISO-10303-21`, and that would be fine. But the DXF importer runs its analysis *before* IFC, and it matches the keyword `HEADER`, which is contained in every STEP file. So Assimp decides it’s a DXF file.

There are two ways to correct this:
1. Extend the IFC loader to support the file extension `.STP`, so it always matches on the first try.
2. Change the DXF loader to not look for `HEADER` alone, but only if following `SECTION` a few lines above. Or matching `HEADER` followed by a line break, but never `HEADER;` followed by a semicolon.

From [Link: the DXF specification], page 217, I understand that you identify a DXF by matching: `whitespace "0" whitespace "SECTION" whitespace "2" whitespace "HEADER" whitespace`

Does Assimp already include the necessary facilities for that (e.g. regex search)?

**Notice:** Don’t get your STEP hopes too high. It’s a very complicated format and I have only ever seen Assimp load two IFC files, but fail on hundreds of others.
- It *is* listed as supported by the IFC importer, though.
