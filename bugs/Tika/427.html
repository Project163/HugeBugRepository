Title

tika-bundle missing org.apache.commons.logging.LogFactory

Description
Trying to invoke the PDFParser from the tika-bundle results in this error: 

 java.lang.NoClassDefFoundError: org/apache/commons/logging/LogFactory 
	at org.apache.pdfbox.pdfparser.BaseParser.<clinit>(BaseParser.java:58) 
	at org.apache.pdfbox.pdmodel.PDDocument.load(PDDocument.java:1089) 
	at org.apache.pdfbox.pdmodel.PDDocument.load(PDDocument.java:1055) 
	at org.apache.tika.parser.pdf.PDFParser.parse(PDFParser.java:123) 
	at org.apache.tika.parser.CompositeParser.parse(CompositeParser.java:242) 
	at org.apache.tika.parser.CompositeParser.parse(CompositeParser.java:242) 
	at org.apache.tika.parser.CompositeParser.parse(CompositeParser.java:242) 
	at org.apache.tika.parser.AutoDetectParser.parse(AutoDetectParser.java:120) 
	at org.apache.tika.Tika.parseToString(Tika.java:421)
Discussion
- In looking through the class code for org.apache.pdfbox.pdfparser.BaseParser there is a reference to org.apache.commons.logging.LogFactory in a static initializer. 

 static {}; 
      0  ldc_w <Class org.apache.pdfbox.pdfparser.BaseParser>  [153]  
      3  invokestatic org.apache.commons.logging.LogFactory.getLog(java.lang.Class) : org.apache.commons.logging.Log  [154]  
      6  putstatic org.apache.pdfbox.pdfparser.BaseParser.LOG : org.apache.commons.logging.Log  [39]  

 I searched through all the nested files in the tika-bundle and could not find the org.apache.commons.logging.LogFactory class.
- I can confirm, that when I patched the tika-bundle (by adding the commons-logging-1.1.1.jar to it), that this problem went away. 

 I currently have a working OSGi Tika application on Linux.  

 Unfortunately the PDF parsing hangs on Macosx. The PDF parser causes a number of system libraries to be loaded, and for some reason it hangs while trying to load the AWT library.
- The lack of the Commons Logging dependency is actually intentional, though the fact that is's marked as optional in the bundle manifest is not. I fixed that in revision 1369624. 

 The reason why we'd rather not include the logging library inside tika-bundle is that a deployment probably wants to use something like Pax Logging or another OSGi Log service implementation to control how log messages are handled. That's only possible if tika-bundle imports the logging packages from another bundle.
