Title

Using TableRegistry::getTableLocator() in a table initialize method poses a conflict with Fixtures

Description
### Description

Case and how to reproduce :

You need for example Users and Emails fixtures for a test.
In UsersTable:Initialize() you call $emailsTable = TableRegistry::getTableLocator()->get('Emails');
I do that in order to load Events.

When I passed to the new system of fixtures, I removed everything but the init function. Therefore, my table I created with `$this->_schemaFromReflection();` in TestFixtures.

By doing so it triggers an exception because EmailsTable is already created by loading UsersTable.

I do not know if the behavior is intended or if I should not use TableRegistry in initialize, but it worked like a charm until now.


### CakePHP Version

4.3.6

You need a User fixture with only an init() function, same for emails.
Emails fixture must be called after Users fixture.

This works, 
```
 public $fixtures = [
        'app.Emails',
        'app.Users',
    ];
```
but this does not
```
public $fixtures = [
        'app.Users',
        'app.Emails',
    ];
```

Users and Emails are connected like this :

In UsersTable : `$this->hasMany('Emails');`
In EmailsTable: `$this->belongsTo('Users');`

In UserTable:initialize() you need to call `$emailsTable = TableRegistry::getTableLocator()->get('Emails');`

Because they are connected as associations and that I need the table in the UsersTable::intialize(), the table is created twice and causes the exception.

After checking again, if in UsersTable::initialize() I do : `$emailsTable = $this->Emails` instead, it works.

But in my opinion, it should work in both cases.
