Title

Session State remains after the tab is closed

Description
### Checklist

- [Link: X] I have searched the [existing issues] for similar issues.
- [X] I added a very descriptive title to this issue.
- [X] I have provided sufficient information below to help reproduce this issue.

### Summary

When closing a browser tab the session state does not get wiped immediately. Expected behaviour should be that the browser close gets detected instantaneous. This makes pages with a while loop not break out of them quick enough.

### Reproducible Code Example

```
Python
import streamlit as st
import time
from datetime import datetime

... [Log Snipped] ...

print("Exit because browser closed...")
```


### Steps To Reproduce

1. Run the code
2. Open browser
3. Check for output, close the browser
4. Streamlit app will now take a very long time before actually printing the exit message...

### Expected Behavior

Expected behaviour would be to detect the closing of the browser quicker. Doesn't need to be instant, but it should be quicker in my opinion. Or maybe even configurable.


In the [Link: docs]it states the following:


This information suggests that closign the tab / browser the session state is lost, but that is not the case.

### Current Behavior

After closing the browser tab, it will take a long time before it gets detected by Streamlit.

- Hi @MathijsNL, thanks for reporting this! This is a bit of a weird one because, in some ways, I'd argue the bug exactly as described here is expected behavior, but there's a different/related bug that we'll certainly want to fix.

This behavior started in version 1.18.0 and is due to one of my recent changes (https://github.com/streamlit/streamlit/pull/5856) that keeps a session around for ~2 minutes after a browser tab is closed. The reason this was done was to make session state resilient to transient websocket disconnects (most often caused by a short network blip) that would previously cause session state to randomly be reset for no apparent reason.

When the browser tab is closed, session state from that point on is inaccessible to the user since there's no way to reconnect to that session from that point. Ideally, that's the mental model we would like to allow people to have even if the actual session cleanup is deferred, so I'm not inclined to change the docs to include the nitty-gritty details of delayed cleanup.

The bug from my point of view is that I didn't take into account scripts that may keep running when the browser tab is closed (script execution is at latest stopped when we delete the session, so this would always happen close to immediately before #5856 was released).
