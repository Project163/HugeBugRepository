- I was looking at the first issue (hi and bye one) and it seems to be caused by the fix made for   GROOVY-123  ,  
which seems like an issue reported in the opposite direction. 

   GROOVY-123   is about compiler treating a {} block as a closure. Because of the fix, Verifier -> filterStatement() gets rid  
of the surrounding ClosureExpression if it is for a parameter-less closure. 

 Can someone confirm whether the block {} in code below should be treated as a closure (  GROOVY-3498  ) or a regular block (  GROOVY-123  )? 
  
 { -> println  "hi"  }
println  "bye"
- So, just to highlight a bit differently: 
  
 { -> println  "hi 1" }
println  "bye 1" 
{ -> println  "hi 2" }
println  "bye 2" 
 
  
 is changing to: 
  
 println  "hi 1" 
println  "bye 1" 
println  "hi 2" 
println  "bye 2" 
 
  
 and closure classes are not even being generated. So, it is not that closures are being called magically.
