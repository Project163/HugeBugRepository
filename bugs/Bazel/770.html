Title

removing --override_repository does not correctly switch back to original repository

Description
### Description of the problem / feature request:

This is a *reproducibility* issue with bazel 0.26.

I'm using a repository fetched using `http_archive`, from `load("@bazel_tools//tools/build_defs/repo:http.bzl", "http_archive")`. Sometimes I'm overwriting it using `--override_repository=...` on the command line and it works perfectly. However, when I'm removing the flag, bazel does not come back to my original setting, leading to unpredictable results.

### Bugs: what's the simplest, easiest way to reproduce this bug? Please provide a minimal example if possible.

I'm using a simple repository that you can clone here: [URL]

It contains a WORKSPACE file with an `http_archive`, `@foo` which is supposed to fetch a remote repository containing a rule which display `I'm from gist` during analysis phase. The gist is here: [URL]

The repository also contains a directory `foo_alt` containing a similarly structured repository which, when used, will display `Hello` during the analysis phase.

I'm now switching from the "remote" (default) and the "local" repository using `--override_repository`.

Build using the default (i.e. the `http_archive`) correctly displays `'Im in a gist`:
```
[guillaume@paddle:~/bazel_non_repro_override_repo]$ bazel build //...
Starting local Bazel server and connecting to it...
DEBUG: /home/guillaume/.cache/bazel/_bazel_guillaume/ /external/foo/bar.bzl:2:5: I'm in a gist
INFO: Analyzed 0 targets (1 packages loaded, 0 targets configured).
INFO: Found 0 targets...
INFO: Elapsed time: 4.483s, Critical Path: 0.02s
INFO: 0 processes.
INFO: Build completed successfully, 1 total action
```

`--override_repository` works as expected and displays `hello`. (Note that I'm using an absolute path on my computer, please adapt for your tests).

```
[guillaume@paddle:~/bazel_non_repro_override_repo]$ bazel build @foo//... --override_repository=foo=/home/guillaume/bazel_non_repro_override_repo/foo_alt
DEBUG: /home/guillaume/.cache/
