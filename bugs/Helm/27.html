Title

Error: Chart.lock is out of sync with Chart.yaml when using dependencies and version ranges

Description
Output of `helm version`:
```
$ helm version
version.BuildInfo{Version:"v3.0.0", GitCommit:" ", GitTreeState:"clean", GoVersion:"go1.13.4"}
```

This is what I am experiencing, easily recreated as below:
```
 $ helm create 1
Creating 1
 $ helm create 2
Creating 2
 $ vim 2/Chart.yaml
```
and add to the chart:
```
dependencies:
- name: 1
  repository: file://../1
  version: ^0.1.0
- name: mysql
... [Log Snipped] ...
  repository: [URL]
  version: ^3.0.0
```

and then:
```
$ helm dep up 2
Hang tight while we grab the latest from your chart repositories...
...Successfully got an update from the "incubator" chart repository
...Successfully got an update from the "stable" chart repository
Update Complete. ⎈Happy Helming!⎈
... [Log Snipped] ...
 $ helm dep build 2
Error: Chart.lock is out of sync with Chart.yaml
```

Any ideas?
Discussion
- @jurgenweber Good catch, thanks. Was able to reproduce as per description. Raising as a bug.
- @hickeyma Hi,

I have found that when the dependencies describe the chart version as "^0.1.0", "helm update" will download a specific version of chart to dir "charts/" and then the specific version will overwrite the version in Chart.lock. Therefore, the digest of Chart.lock changed.

I have created a pr to fix it. 😊
