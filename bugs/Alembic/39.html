Title

AttributeError thrown when running autogenerate

Description
**Migrated issue, originally created by Scott Milliken ([Link: @smilliken])**

First off, thanks for the great tool!

I recently upgraded to alembic==0.6.2 and sqlalchemy==0.9.0, and ran into an `AttributeError` when running autogenerate.

The exception is from `autogenerate/compare.py:180`, and is caused by `exp` not having a `name` attribute.

Here's a declarative model that triggers the error:

```
class TestTable(base):
    __tablename__ = 'test_table'

    foo = Column(Integer, primary_key=True)
    bar = Column(Integer)

Index('ix_test_table_foo_bar', TestTable.foo, TestTable.bar.desc())
```

Specifically, the error is caused by `TestTable.bar.desc()` in the index expression not having a `name` attribute.

Some context: this is a compound index for PostgreSQL. The sort direction on the second field allows this index to be used in a query to order results like `ORDER BY foo, bar DESC`. I've marked this bug as minor since the index doesn't strictly need to be there (since alembic actually ignores it for generating migrations), but is included so that the schema is fully documented. An easy work-around is to comment out the index expression.

On a separate note, it would be great if alembic could generate migrations including indexes like this, and support compound indexes with sort fields (currently have to fall back to plain SQL DDL for this).
