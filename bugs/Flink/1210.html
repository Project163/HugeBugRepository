- I debug it and find that we use  Class.getCanonicalName  to get the canonical name of the underlying class which will return null if the underlying class does not have a canonical name (i.e., if it is a local or anonymous class or an array whose component type does not have a canonical name). 

 So you should move the  Dandan  case class definition out of the main function, and it should work.  

 But I haven't found any document telling that we cannot define local case class, so I'm not sure whether it is a bug,  fhueske   twalthr  what do you think?
- We had a similar issue with the old Table API. It is not a bug but the  toDataSet  and  toDataStream  methods should check that classes have a qualified name and throw an exception otherwise.
