Title

Namespace Name Conflict/Issue

Description
I think there may be an issue with namespace names. Using certain characters in the namespace make the mixin undefined. I am working in node.js on less 3.9.0 latest. I was attempting to use the word "#Effects()" as my namespace name. 

I was thinking maybe this has something to do with using characters that are used in hex colors? If you using characters out of the hex range (A-F) the error goes away. I have found that names that include "D", "E" and "F" are giving the error. Any combination over two letters gives the error.

To test, I grabbed the documentation example on namespaces (below):

```
less
#Library() {
  .colors() {
    primary: green;
    secondary: blue;
... [Log Snipped] ...
  border-color: #Library.colors[secondary];
}
```

I then tried different names for the namespace, the following all result in the mixin being undefined:

- #Effects
- #Effect
- #Def
- #DEF
- #DEFFER
- #ABC
- #ABBF

Example test:

```
less
#DEF() {
  .colors() {
    primary: green;
    secondary: blue;
... [Log Snipped] ...
  border-color: #DEF.colors[secondary];
}
```
Discussion
- @Jscherbe Your instinct is likely correct. To clarify, are you only encountering this bug when trying to reference with `color: #DEF.colors[primary];`?
- Yes, I only get the undefined error when trying to reference. Just defining the namespace doesn't throw any errors. Also I am able to use mixins that print styles just fine in the namespace but grabbing a property using the map syntax gets an undefended error.

- Case Insensitive
- Name > 2 Characters
- Start of name needs to be A-F for at least 3 characters
- Using numbers does NOT create the same issue (works)
- Name lengths greater than 6 also have the issue
- Definitely sounds like a parsing issue then. Thanks for the detailed reporting.
- color interpretation problem, huh?
