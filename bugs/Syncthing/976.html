Title

traefik no longer url escape X-Forwarded-Tls-Client-Cert header

Description
stdiscosrv has the ability to handle certificates passed by traefik proxy server in `X-Forwarded-Tls-Client-Cert` header.

Previously, traefik url encodes the content but it stopped doing so since version v2.9.4.
This becomes troublesome for setups where stdiscosrv sits behind newer traefik versions,
as now stdiscosrv tries to url [Link: decode] the header content when it is not encoded.

The symptom can be very confusing, as if some client's certificate's pem text happens to not contain `+`, etc, then it works perfectly, but other clients will always fail announcement with 403 error.

More details can be found at [URL]

I'm not sure what should be the best strategy here to support both old and new traefik versions... but wanted to at least raise attention.

stdiscosrv version: 1.24.0
Discussion
- Hi @calmh, thank you so much for the fast fix! I can test it when I get time. But from reading the code, it doesn't seem to solve the issue.

Consider the following case:
```
X-Forwarded-Tls-Client-Cert: ABCDEFG+XYZ
```

URL unescape will complete without error, generating string `ABCDEFG XYZ`. The failure will happen down the line when try to do PEM decode on the string. This is actually no different from the behavior before the fix.

IMHO maybe a better fix is to check for the presence of `%` character, like what's done for `X-SSL-Cert` for nginx.
- Lovely, I forgot that plus is a valid Base64 character.
