Title

Windows 10 / msys2: bazel::ConvertPathList translates Windows paths badly

Description
If `ConvertPathList` [1] receives a list of Windows paths (e.g. from `$TMP`), it translates them badly.
It works well if the paths are Unix paths.

Repro:
1. Add logging to `src/main/cpp/option_processor.cc` [2], printing `value` before and after calling `ConvertPathList`: 
   
   ```
   +#include  
   ```
   
   ```
if (pos != string::npos) {
           string name = env_str.substr(0, pos);
           if (name == "PATH" || name == "TMP") {
   -          string value = env_str.substr(pos + 1);
   -          value = ConvertPathList(value);
... [Log Snipped] ...
         }
         command_arguments_.push_back("--client_env=" + env_str);
```
2. Build Bazel
3. Run that binary (with `shutdown`, so Bazel parses the command line options and conveniently shuts down immediately):
   
   ```
$ export TMP=c:/tempdir/i_am_the_captain
   $ /c/work/bazelbin/bazel-head-logging.exe shutdown
   DEBUG: TMP, value1='c:/tempdir/i_am_the_captain'
   DEBUG: TMP, value2='C:\work\bazel2\c;C:\tools\msys64\tempdir\i_am_the_captain'
   
... [Log Snipped] ...
   DEBUG: TMP, value1='/c/tempdir/i_am_the_captain'
   DEBUG: TMP, value2='C:\tempdir\i_am_the_captain'
```

Discussion
- Found the culprit.

`blaze_util::ConvertPathList` expects a Unix path list [1].
The `options_processor.cc` always uses `ConvertPathList` (including on MSYS [2]) and isn't prepared for `$TMP` (or `$PATH`) using Windows paths.

Unfortunately a single Windows path with forward slashes (`c:/foo`) could be interpreted as a Unix path list of `["$CWD/c", "/foo"]` and get converted to:

```
C:\tools\msys64\var\tmp\Bazel\...\foo_bin.runfiles\c;C:\tools\msys64\foo
```
