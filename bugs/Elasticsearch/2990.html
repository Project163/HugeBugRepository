Title

Elastic certutil generates certificates even though the provided ca-key does not match the ca-certificates

Description
### Elasticsearch Version

8.8.1

### Installed Plugins

_No response_

### Java Version

_bundled_

### OS Version

Linux LAPTOP-85G6IQGC  -microsoft-standard-WSL2 #1 SMP Fri Jan 27 02:56:13 UTC 2023 x86_64 x86_64 x86_64 GNU/Linux

### Problem Description

Elasticsearch Certutil generates certificates (which are invalid) when the provided ca.key does not match the ca.crt. The expected behavior is that no certificates are generated and that the tool exit with an error clearly saying that ca.key does not match ca.crt. Similarly to what does openssl already.


### Steps to Reproduce

1. Generate two new CA key-certificate pairs:
  - `./bin/elasticsearch-certutil ca --ca-dn "CN=A" --keysize 4096 --pem --out A.zip`
  - `./bin/elasticsearch-certutil ca --ca-dn "CN=B" --keysize 4096 --pem --out B.zip`
2. Unzip the files
  - `unzip A.zip -d A`
  - `unzip B.zip -d B`
3. Generate a certificate by using the ca.crt of A and the ca.key of B:
  - `./bin/elasticsearch-certutil cert --ca-cert ./A/ca/ca.crt --ca-key ./B/ca.key --dns=test.it --pem --name test.it --out testit.zip`
4. Unzip the certificate
  - `unzip testit.zip`
5. Check that the certificate is not valid:
  - `openssl verify -CAfile ../certs/caA/ca.crt ./test.it.crt`


The result is:
