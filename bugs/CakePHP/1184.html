Title

5.2: Regression in atomic save operations with field + value

Description
### Description

This worked in 5.x so far:
```php
$this->updateAll(['count = count + ' . $count], ['id' => $id]);
```
It now triggers a hard error
```
TypeError: Cake\Database\Expression\ComparisonExpression::__construct(): Argument #1 ($field) must be of type Cake\Database\ExpressionInterface|string, int given, called in /home/runner/work/CakePHP-DatabaseLog/CakePHP-DatabaseLog/vendor/cakephp/cakephp/src/Database/Query/UpdateQuery.php on line 125

/home/runner/work/CakePHP-DatabaseLog/CakePHP-DatabaseLog/vendor/cakephp/cakephp/src/Database/Expression/ComparisonExpression.php:79
/home/runner/work/CakePHP-DatabaseLog/CakePHP-DatabaseLog/vendor/cakephp/cakephp/src/Database/Query/UpdateQuery.php:125
/home/runner/work/CakePHP-DatabaseLog/CakePHP-DatabaseLog/vendor/cakephp/cakephp/src/ORM/Table.php:1804
/home/runner/work/CakePHP-DatabaseLog/CakePHP-DatabaseLog/src/Model/Table/DatabaseLogsTable.php:260
```

I didnt see this in the migration logs.
Either we make this a bit softer deprecation or we shim it completely until 6.x maybe?

- Actually, using the documented approach
```php
$countExpression = new QueryExpression('count = count + ' . $count);
$this->updateAll([$countExpression], ['id' => $id]);
```
does not help eiter, as the key here is not assoc but numerically indexed, so it would break either way with the new changes.

I tracked it down to
[URL]
possibly being partially responsible for the regression here.

[
  (int) 0 => object(Cake\Database\Expression\QueryExpression)

is whats going in, but even if you add

    && !isset($key[0])

It seems to be fixable with

    $this->updateAll(['count' => $countExpression], ['id' => $id]);

but thats also not how it is documented in the cookbook:

and how it so far worked.
