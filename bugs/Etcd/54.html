Title

3.2.0-rc0, Windows: 10GB db file in snap directory

Description
I'm new to etcd, and creating a cluster of 3 members. Two on Windows machines, one inside Docker on Ubuntu.

I'm wondering if it is normal for the `\etcd-v3.2.0-rc.0-windows-amd64\default.etcd\member\snap\db` file to be 10GB big. This is the case on both Windows machines. The wal directory contains two 62M wal files.

On Linux it's just 28K for the snap/db and also two 62M wal files.

I couln't find anything on the net related to this.

The following is the config file of one of the Windows machines, they are almost identical.

---
update: I just noticed that I'm running `quay.io/coreos/etcd` and not `quay.io/coreos/etcd:v3.2.0-rc.0` in the Docker container.

```
name: 'server-win'
data-dir: 'C:\App\etcd\etcd-v3.2.0-rc.0-windows-amd64\default.etcd'
wal-dir:
snapshot-count: 10000
heartbeat-interval: 100
... [Log Snipped] ...
log-package-levels: 
force-new-cluster: false
```
Discussion
- I think what's happening is boltdb is passed an initial mmap size of 10GB, which was linux-only before  , and windows will immediately set the db file to use the full 10GB.
- How will this affect me when it gets fixed? I won't be able to reduce the size at a later point in time, right? 

So I'm better off not using etcd 3.2.0r on windows until this is fixed?
- @danielfaust running [Link: `etcdctl defrag`] on the member should reduce the db size once the initial mmap size bug is fixed. I'd advise against putting 3.2.0rc on windows until there's a fix since transferring 10GB snapshots will lead to poor MTTR.
