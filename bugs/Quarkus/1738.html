Title

Reactive REST client with multiple content-type providers fails with untyped response

Description
### Describe the bug

When using a REST client with multiple content-type providers (e.g. JSON & CBOR), responses without a `Content-Type` header fail with `No RESTEasy Reactive request in progress`.

This happens even when the client interface is annotated with `@Produces("application/json")`.

[Link: Zulip discussion]

### Expected behavior

The response is decoded according to the value provided in `@Produces`.

If multiple types are provided in the `@Produces` annotation then an appropriate error should be thrown.

We are using the built client to interact with external services so we will not control the responses and need proper handling and when it fails we need a proper error message.


### Actual behavior

The call fails with the error quoted above.

### How to Reproduce?

1. Execute the tests (e.g. `mvn install`) to see the failure.

If you uncomment `GreetingResourceTest.kt:23`, providing an explicit content-type, the issue goes away.
