Title

cat'ing binary file causes abort

Description
Very simple and easy to reproduce. 
1. `nvim -u NONE`
2. `:term `
3. `cat /bin/bash`
4. Crash

I know you aren't supposed to literally read a binary, but I don't think there should be room for neovim to crash.
Discussion
- Can reproduce with a simple `:!cat /bin/bash`:

```
c
nvim: /home/oni-link/git/neovim/src/nvim/ui.c:461: void ui_cursor_left(): Assertion `new_col >= 0' failed.

Program received signal SIGABRT, Aborted.
  in raise () from /lib64/libc.so.6
... [Log Snipped] ...
#32   in normal_enter (cmdwin=false, noexmode=false) at /home/oni-link/git/neovim/src/nvim/normal.c:464
#33   in main (argc=3, argv= ) at /home/oni-link/git/neovim/src/nvim/main.c:528
```
- To trigger the `assert()`, it is enough that the first output byte is `'\b'`, `:!echo -en '\x08'|cat -`.
- Researching this issue I tried running the command `echo -en '\x08test'|cat -` to see it's behavior in different environments.

OS X 10.10.5 zsh 5.0.5 connected via iTerm 2.1.1 and Terminal 2.5.3: 'test' printed on current row, followed by '%', newline then prompt.

OS X 10.10.5 Bash 3.2.57 connected via iTerm 2.1.1 and Terminal 2.5.3: 'test' printed on current row, followed directly by prompt. 

Gentoo 2.2 Bash 4.3.42 connected via iTerm 2.1.1 and Terminal 2.5.3: 'test' printed on current row, followed directly by prompt. 

Gentoo 2.2 Bash 4.3.42 connected via Prompt 2 for iOS: cursor moved to the previous row and the last column, printed 't' then moved to the next row, first column and printed 'est' followed directly by prompt.
