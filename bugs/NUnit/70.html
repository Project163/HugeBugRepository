Discussion
- I have confirmed this issue. It would likely be an easy fix to set `XmlWriterSettings.CheckCharacters  = false` but I am not sure we want to do this. Another option would be to convert invalid characters to a valid placeholder character, but this might create more duplicate test names.

What do other team members think about the priority, milestone and possible fixes for this? I have set it for 3.0 RC, but we could probably push it. @appel1, is this a blocker for you?
- Let's make sure we didn't drop some check we were doing in NUnit 2.x. What makes me wonder about that is the fact that nobody has run into this before.
- Not a blocker. Was fairly easy to work around either by inlining the test cases or wrapping the invalid characters in an object that outputs the integer value in ToString. A bit more difficult to figure out than I'd like because of no context in the test runner output, had to resort to building nunit framework myself to be able to debug.
- There is already code in TestResult.cs that solves this problem for user-created messages. We need to do the same thing for the test name and for anything else that is subject to having invalid chars.
