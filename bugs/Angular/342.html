Title

i18n attribue handling inconsistent with messages

Description
**I'm submitting a ...**  (check one with "x")
```
[x ] bug report => search github for a similar issue or PR before submitting
[ ] feature request
[ ] support request => Please do not submit support request here, instead see [URL]
```

**Current behavior**
 
Currently, if a translation node is empty for HTML content, or what is referred to as a message in the compiler, no error is thrown and the tag is rendered in the DOM as empty:
    <span i18n>Test</span>
-> empty span if there is no translation for the trans-unit
However for attributes, if there is no translation an error is thrown:
    <span i18n-title title="Test"></span>
-> throws error if there is no translation

**Expected behavior**
 
The attribute would be rendered in the DOM with an empty value if the node had no translation

**Minimal reproduction of the problem with instructions**
 
* Add an i18n attribute for an attribute that needs to be translated
* Generate the messages xlf file for translations - this will have empty target elements
* Provide this file as the translations source for the app
* Try to render the component - there will be an 'Unexpected translation for attribute' error in the console

**What is the motivation / use case for changing the behavior?**
 
Error conditions for missing translations for HTML content and attributes should be consistent. It is convenient for development for the compiler to not throw when translations are empty - otherwise every new attribute that is added to the project needs to be translated before the app can be worked on.

The issue is at line 371 of extractor_merger.ts - the check in that line means that empty translations for attributes throw, rather than being handled. The equivalent check for messages is at line 335, and this does not throw on an empty node array - which happens when the id is in the translated content but the translation is empty.
