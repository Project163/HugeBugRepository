Title

treeshake incorrectly removes empty for..of and for await..of loops

Description
Awesome tool! Thanks!

- Rollup Version: 1.21.4
- Operating System (or Browser): Ubuntu 16.04.6 LTS, also Firefox 69 and Electron
- Node Version: 10.16.0

### How Do We Reproduce?

Replicated in [Link: REPL]

### Expected Behavior

The empty loops for sync and async for..of iteration should not be removed. They call iterator.next() multiple times, and are doing work.

### Actual Behavior

The empty loops are removed. As the REPL example shows, manually doing the iteration with a while loop and iterator.next() is a workaround.

I'm using code like this to iterate over chained async generators. For async code, it is the generators that do the work (HTTP queries, writing to DB, etc). I don't need to see the resolved values.

```javascript
export const awaitable = async (iterable) => {
   // This loop is removed, but it calls iterator.next(), which can have side-effects
  for await (const value of iterable) {
  }
}
```
Discussion
- I con confirm this. I believe we should go for a quick fix first that always retains `for...of` loops.

Later, a more sophisitcated solution could track `Symbol.iterator` and `Symbol.asyncIterator` properties and check the side-effects of their return values' `next` function. Such a logic should also work for spread operators and manual iteration as well as interact properly with generators. It should also be tested for side-effects when passed to a function such as `Array.from`.
