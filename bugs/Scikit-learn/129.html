Title

Finding no inliers in one iteration of RANSAC should not raise a ValueError

Description
#### Description
`sklearn.linear_model.RANSACRegressor` throws a `ValueError` if no inliers can be found for one of the models generated from random subsets of the input data. However, due to the randomness of the approach, it could well be that further iterations of the algorithm do find a subset that gives a valid model. I therefore (based on my limited understanding of RANSAC) believe that instead of raising an error we should simply continue with the next iteration.

#### Steps/Code to Reproduce
```
from sklearn.linear_model import RANSACRegressor, LinearRegression
from sklearn.preprocessing import PolynomialFeatures
import numpy as np

x = np.array([1, 2, 3, 4, 5, 6])
... [Log Snipped] ...
print(nerror)
# We get the error about 40% of the time.
```

#### Expected Results
The call to `model.fit` should only fail, if ALL the iterations fail to generate a valid model.

#### Actual Results
The call fails if ONE of the iterations produces a model that has no inliers.

Notes on the PR and bug:
1. The changes I made were: instantiating variables at different values, and I deleted one error message.  The deleted error message is why some tests fail in this PR. However, this error message itself _is_ the bug, so I believe updating the tests will be necessary as well.
2. For all tests that expect this buggy error message, a more general error message is produced (which is still informative). Therefore, with this PR, bad inputs will still be generating informative error messages.
3. The buggy error message could only be generated on the first iteration of the main `for` loop... which is further evidence that it is a bug. The nature of the RANSAC algorithm is that it runs the same code on different random subsets of the data.  The first iteration is really no different from the last, so any error messages that can only happen in the first (or X-th) iteration would at the very least be very counter-intuitive.
