## Description

Upon registration, the notification mail contains :

`You can now login via username: {{.Username}}.`

Where Username is the full name and NOT the real username.

...

Discussion
- This happens because it uses DisplayName():

[URL]

In many cases of adding a user, the Web form only asks for a username at first so the email is sent with the right value in Username. However if you use the API or other tool to create a new user where you can also include the full name at the same time, it will then produce the bug above. This probably slipped by because of the confusing choice of "Username" as the variable.

Username should change to always be the actual username and a new/separate value called "Name" or something can be used for the current behavior of using the full name if available and if not falling back to username
