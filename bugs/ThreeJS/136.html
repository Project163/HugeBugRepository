Title

dev: Shadow maps exploding on >1 devicePixelRatio systems

Description
The dev branch somehow cannot handle shadows on systems with devicePixelRatio > 1.
The symptom is that the textures used double in size every frame and eventually become too large to use. No visuals are produced after that point.

A number of examples are broken due to this, e.g.:
examples/webgl_loader_stl.html
examples/webgl_shadowmap.html
examples/webgl_materials_cubemap_dynamic.html
examples/webgl_materials_bumpmap_skin.html

This one does work (as it doesn't actually use the devicePixelRatio, thus causing pixelated rendering):
examples/webgl_shadowmesh.html
Discussion
- @mrdoob @kintel 

It looks like this bug is manifesting due to recent updates to `WebGLShadowMap.js` that save and restore the viewport during shadow map rendering. However, it appears the actual cause is a discrepancy in `WebGLRenderer.js` between these two functions:

```
this.setViewport = function ( x, y, width, height ) {

        _viewportX = x * pixelRatio;
        _viewportY = y * pixelRatio;

... [Log Snipped] ...

    };
```

```
this.getViewport = function ( dimensions ) {

        dimensions.x = _viewportX;
        dimensions.y = _viewportY;

... [Log Snipped] ...

    };
```

As you can see, the values **`_viewportWidth`** and **`_viewportHeight`** are multipled by **`pixelRatio`** before setting the view port. However when calling `getViewport()` those values are not divided by **`pixelRatio`**, so the original values may not correctly be recovered. Of course, there is existing code out there that may depend on these functions working exactly as they do now, so simply updating `getViewport ()` may not be a good idea.

I can work around this bug by setting **`pixelRatio`** to 1 during the rendering of the shadow maps, but that doesn't address the root issue. What would be the best way to proceed in this case?
