Title

[Bug]: premature `go version` validation breaks goreleaser flows

Description
### What happened?

The commit [URL] breaks [URL] goreleaser's flow. One of the steps in the `before.hooks` is to create the directory to be used as the build dir later on. The referenced commit validates the `go version` before running any of the `before.hooks`, but it also tries to switch into the build dir before it's created because it doesn't get created until the `before.hook` runs.

### How can we reproduce this?

Have the `builds.dir` specified to a directory which gets created as part of the `before.hooks`, then run `goreleaser check` or `build` or `release`. The run will fail before running any of the before hooks.

### Additional context

The workaround (for us) is to create the directory before invoking goreleaser. This isn't nice because the task ends up being duplicated across 2 flows: `goreleaser check` in our lint run, and the plain `goreleaser` release flow.

About the `goreleaser check shows no errors`, although I checked that box, the issue is with the command itself failing prematurely.
