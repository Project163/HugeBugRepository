Title

`request.content_type()` not working in `FromData`

Description
In `juniper` we are [Link: implementing `FromData` for a custom type]. We want to restrict requests to json without having users manually specify in the route. Sadly we never actually handle post requests because `request.content_type()` always returns `None` when running tests with a `LocalClient`, causing this code to always forward the request rather than handle it:

```
rust
fn from_data(request: &Request, data: Data) -> FromDataOutcome  {
  if !request.content_type().map_or(false, |ct| ct.is_json()) {
     // Not json. This ALWAYS happens, so we never handle the request.
     return Forward(data);
... [Log Snipped] ...
  }
}
```

Changing the check to the following works:

```
rust
fn from_data(request: &Request, data: Data) -> FromDataOutcome  {
   let content_type: Option  = request
     .headers()
     .get_one("Content-Type")
... [Log Snipped] ...
    }
}
```

---

The [Link: relevant rocket code] looks like:

```rust
pub fn content_type(&self) -> Option  {
        self.state.content_type.get_or_set(|| {
            self.headers().get_one("Content-Type").and_then(|v| v.parse().ok())
        }).as_ref()
    }
```

So it appears that `state` is not updated correctly somewhere.
