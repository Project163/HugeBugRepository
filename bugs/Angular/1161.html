Title

Components are not removed from DOM when calling NgModuleRef.destroy()

Description
# 🐞 bug report

### Affected Package
 
  The issue is caused by package @angular/core


### Is this a regression?

 
Yes


### Description

All components remain in DOM when calling `NgModuleRef.destroy()` if Ivy is enabled, but actually, all `ngOnDestroy` hooks are invoked, event listeners are removed, basically, all cleanups are done except removing nodes from DOM.

But if Ivy is disabled (view engine is being used) then all nodes are removed.

From what I see when using Ivy the `cleanUpView` function is invoked which execute on destroy hooks, removes listeners, but when it gets to `renderer.destroy()` it actually does nothing:

[URL]

When using view engine it gets to `ViewRef_.destroy -> execRenderNodeAction -> renderer.removeChild`.

I was looking for similar issues but haven't found anything, also I haven't found this change in the changelog. The use case is: we have micro-frontend apps which are destroyed via `NgModuleRef.destroy()`.

## 🔬 Minimal Reproduction

1) `git clone git@github.com:arturovt/ngmoduleref-destroy-issue.git`
2) `cd ngmoduleref-destroy-issue`
3) `yarn`
4) Start dev server `yarn ng s`
5) Go to `[URL] open dev tools, click the "Destroy" button. Notice logs in the console and that component is removed from DOM
6) Stop dev server, go to `tsconfig.json` and set `enableIvy` to `true`
7) Start dev server again, click the "Destroy" button. Notice logs in the console and that component is NOT removed from DOM
