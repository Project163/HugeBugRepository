Title

3.28.1: `java.util.zip.ZipException: duplicate entry` in Quarkus generated jar(s)

Description
### Describe the bug

For Quarkus 3.28.1, CI reports `j,u.z.ZipException: duplicate entry...` errors for every `quarkusBuild` Gradle task execution. 3.27.0 looks fine.

[Link: Renovate Quarkus 3.28.1 bump PR]. Can be reproduced locally as well.

The issue is _not_ particularly in the `quarkusBuild` task implementation, but raised in a [Link: custom Gradle code] to make the `quarkus-run.jar`, `generated-bytecode.jar` and `transformed-bytecode.jar` files a (bit more) reproducible by re-recreating those with a fixed file modification timestamp for all zip entries.

However, the exception is thrown because there is a duplicate entry in at least one of the jars created by Quarkus.

In the particular case it is `duplicate entry: io/quarkus/opentelemetry/runtime/config/runtime/exporter/OtlpExporterConfig$$CMImpl.class`.

Reproducer: checkout the renovate-PR branch, run `./gradlew :polaris-server:quarkusBuild --stacktrace`.

The above works fine up to Quarkus 3.27.0.

Noting: the `ZipException` is _not_ raised from Quarkus code, but our custom code, but the duplicate ZIP entry in the Quarkus generated jar is real.

Discussion
- After #49801, #49808 and [URL] Quarkus should now set fixed timestamps for ZIP entries (and file permissions as well) when building Gradle projects, but:

- When using Gradle 9+, no extra configuration is needed.
- When using Gradle 8.x, you need these configurations:

```
tasks.withType ().configureEach {
    isPreserveFileTimestamps = false
    isReproducibleFileOrder = true
}
```

Try that without the custom Gradle code. No idea about the duplicated entries though.
