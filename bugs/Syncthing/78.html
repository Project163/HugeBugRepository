Title

Handling invalid directory name (Linux to Windows)

Description
I had a saved webpage on a linux Syncthing repository which included a directory name that Windows does not like. When I started a repository on a Windows 7 notebook, I got errors for each file in the subdirectory like this:

puller.go:330: pull: error: "default" / "[dir]\Notes\Aristotle: Poetics\u00a0[Internet Encyclopedia of Philosophy]_files\5-logo.png": mkdir C:[dir]\Notes\Aristotle: Poetics [Internet Encyclopedia of Philosophy]_files: The directory name is invalid.

I have stopped Syncthing, then deleted the saved html page and the apparently problematic directory structure "[dir]/Notes/Aristotle: Poetics [Internet Encyclopedia of Philosophy]" by hand from the repositories on both the Linux and Windows machines. 

When I restart Syncthing, the directory Notes is always recreated on both repositories and I get a constant string of errors, for each file in the subdirectory, as before. The dashboard shows everything in sync on both machines. The deleted files do not appear in the "Notes" file; my other "good" files appear as they should in this directory structure. But the errors about the "bad" directory name keep scrolling in the Syncthing console.
Discussion
- There could probably be some improvements here. Some buggyness in the handling of directories was just fixed, but the root cause here (names not possible on Windows) remains and won't be handled very gracefully. It'll be the same situation as if you have a failed or full disk - i/o errors on creating stuff, so it'll retry later to try to get in sync. Will have to do some thinking on how best to handle it.
- Probably also going to have trouble with two dirs "UPPERCASE" and "uppercase" in the sync dir when syncing that to windows.
