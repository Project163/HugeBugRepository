Title

new ServerRequest('/') returns ServerRequest object with wrong path

Description
This is a (multiple allowed):

* [x] bug
* [ ] enhancement
* [ ] feature-discussion (RFC)

* CakePHP Version: 3.6.7
* Platform and Target: LAMP PHP 7.1

### What you did
_config/routes.php:_
```
Router::defaultRouteClass(DashedRoute::class);

Router::scope('/', function (RouteBuilder $routes) {
    // Enable json file extension
    $routes->setExtensions(['json', 'pdf', 'csv']);
... [Log Snipped] ...
    $routes->fallbacks(DashedRoute::class);
});
```
_anywhere in Code when currently at an URL != /, e.g. /reports/articles:_
```
$request = new \Cake\Http\ServerRequest('/');
debug($request->getUri());
debug(\Cake\Routing\Router::parseRequest($request));
```

### What happened
Debug output is:
```
object(Zend\Diactoros\Uri) {
	base => ''
	webroot => '/'
	[protected] allowedSchemes => [
		'http' => (int) 80,
... [Log Snipped] ...
	'_matchedRoute' => '/:controller/:action/*'
]
```

### What you expected to happen
Debug output should be:
```
object(Zend\Diactoros\Uri) {
	base => ''
	webroot => '/'
	[protected] allowedSchemes => [
		'http' => (int) 80,
... [Log Snipped] ...
	'_matchedRoute' => ['controller' => 'Pages', 'action' => 'home']
]
```

I'm not sure whether this behaviour is intended, but it breaks e.g. the isUrlAuthorized() Method of CakeDC/users Plugin when you check if the url / is allowed for a certain user.
The relevant codeline ist [URL] which shortens the passed url '/' to '' in the ServerRequest Class constructor.
Discussion
- Why are you creating another request object? Are you aiming to build a copy of the current request? Building a request with only the string URL will generally not work as the internal Uri object uses context defined in `$_SERVER` which you are not overwriting correctly.
- It is used in CakeDC/users plugin to check authorization for a given url: [URL]

So I probably better open an issue in their project if ServerRequest is not designed to be used this way. Should I close this ticket?
- Interesting. I'll see if we can make this use case work.
- Pull request open now.
