Title

Incorrect behaviour of internalScanFolderSubdirs

Description
Syncthing Version: master
When two files are removed and the first path is a prefix of the second path, the local and global count are incorrectly updated. E.g. If Syncthing-inotify performs `scan?folder=default&sub=foo/bar&sub=foo/bar2` because the files `bar` and `bar2` are removed, the file count is reduced by 3 instead of 2. I traced it back to the fact that we use a [Link: `batch`] array instead of a map, which means the array we pass to updateLocals can contain duplicates. This confuses the intermediate counting we do in sizeTracker.

This could cause a panic: in [Link: set.go]
