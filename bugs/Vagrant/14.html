Title

Ansible provisioner doesn't quite use same SSH settings as `vagrant ssh`

Description
Notably, `UserKnownHostsFile /dev/null` is present in `vagrant ssh-config` but not present in the `ANSIBLE_SSH_ARGS` variable.

Somewhat mysteriously this causes ssh to disable agent forwarding if the host key is not recognised - such as after rebuilding the vagrant VM.
Discussion
- @glenjamin could you please provide a gist (or github repository) that illustrates the issue with agent forwarding being disabled? Are you able to solve the problem with `ansible.raw_ssh_args` option?

There is also [Link: a similar issue] with `UserKnownHostsFile` and the Ansible `git` module, that I have to verify in the next weeks.

Note: As a general guideline, I think that the Ansible provisioner should give priority (when possible) to `ansible-playbook` default (ssh) settings, but I fully understand the potential confusion between Vagrant SSH default settings. Therefore I added this topic to #3396 (more feedbacks are always welcome!).
- I was able to resolve via `raw_ssh_args`, I'll try and throw a gist together shortly.

- After further investigation, here are the current Ansible configuration capabilities:
- Ansible 1.3+ provides [Link: ANSIBLE_PARAMIKO_RECORD_HOST_KEYS] option to skip writing into known hosts file (e.g. `~/.ssh/known_hosts`)
- Adding an option in Ansible to set `UserKnownHostsFile=/dev/null` when using `ssh` connection was discussed in [URL] but it does not seem to be planned at the moment.

I've just opened a [Link: discussion in Ansible Development Mailing List] to first ask if Ansible itself should provide an option to skip writing to `~/.ssh/known_hosts` file. If this is accepted, future versions of Vagrant will use Ansible proper settings. Otherwise we'll update the Ansible provisioner to potentially configure both connection modes (Paramiko and OpenSSH) so that `~/.ssh/known_hosts` is not modified, nor considered.
- After discussing it, the Ansible team is not interested (for now) to introduce a new option to be able to skip the user known host file in a unified manner for `paramiko` and `ssh` connection modes. 

Therefore, we must rely on the existing options described above, which is far from ideal, but doable. Please note that I am not sure to find time before August to work on this. Pull request welcome, of course!
