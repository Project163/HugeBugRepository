Title

Column with an unsigned int should be treated as long in JDBCRDD

Description
Columns with an unsigned numeric type in JDBC should be treated as the next 'larger' Java type 
in JDBCRDD#getCatalystType . 
 [URL]

   q.sql   
 create table t1 (id  int  unsigned);
insert into t1 values (4234567890);

  import  org.apache.spark.{SparkConf, SparkContext}

    val s =  new  SQLContext(sc)

     val t1 = s.jdbc(url,  "t1" )
    t1.printSchema()

- I've had a similar problem, especially with "unsigned bigint". Java has no type for that. (It only fails if a value actually exceeds the java long range). 

 I worked around the problem by extending DriverQuirks, now JDBCDialects. The idea is that you can map problematic types to whatever you'd want: 
 [URL]

 I am mapping unsigned bigint to string in order to load it. This works at some post-processing overhead (basically a udf to map unsigned long stored in a string to signed long).
