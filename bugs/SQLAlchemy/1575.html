Title

Issue with server_defaults and datetime and on update

Description
**Describe the bug**
I am not sure if this is an alembic or SQLAlchemy issue. But something is not working anymore with `server_defaults` and `on update` since SQLAlchemy 2.0.40 (everything is fine with 2.0.39)

**Expected behavior**
The example below should create the following DDL

```
CREATE TABLE `test_table` (
  `id` int NOT NULL AUTO_INCREMENT,
  `check_me` tinyint(1) NOT NULL,
  `created_at_utc` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`)
)
```

**To Reproduce**
```
py
from typing import Sequence, Union

from alembic import op
import sqlalchemy as sa
... [Log Snipped] ...
def downgrade():
    op.drop_table('test_table')
```

**Error**

```
sqlalchemy.exc.ProgrammingError: (pymysql.err.ProgrammingError) (1064, "You have an error in your SQL syntax; check the manual that corresponds to your MySQL server version for the right syntax to use near 'on update now()), \n\tPRIMARY KEY (id)\n)' at line 4")
[SQL:
CREATE TABLE test_table (
	id INTEGER NOT NULL AUTO_INCREMENT,
	signal_loss BOOL NOT NULL,
... [Log Snipped] ...

]
```

**Versions.**
 - OS: macOS
 - Python: 3.12
 - Alembic: 1.15.2
 - SQLAlchemy: 2.0.39 / 2.0.40
 - Database: MySQL 8
 - DBAPI: pymysql

**Additional context**
I think this is related to a change in SQLAlchemy made for [URL] - but I don't know if that requires a change in alembic as well or if this is a bug in SQLAlchemy.
