Title

move and moveto commands cause folder linking on Google Drive

Description
#### What is the problem you are having with rclone?
When using the move and moveto commands in Google Drive on directories, the source gets "linked" to the destination. The source directory doesn't get deleted (even when using --delete-after flag), and renaming or deleting either the source or destination will affect both of them. On Google Drive web, it shows that the source is located in two places (source and destination).

#### What is your rclone version (eg output from `rclone -V`)
1.40

#### Which OS you are using and how many bits (eg Windows 7, 64 bit)
linux/amd64

####  Which cloud storage system are you using? (eg Google Drive)
Google Drive

#### The command you were trying to run (eg `rclone copy /tmp remote:tmp`)
`rsync move drive:test/move/srcDir drive:test/move/Folder/srcDir`
`rsync moveto drive:test/move/srcDir drive:test/move/Folder/srcDir`

#### A log from the command with the `-vv` flag (eg output from `rclone -vv copy /tmp remote:tmp`)
```
$ rclone lsf -R drive:test/move
Folder/
srcDir/
$
$ rclone -vv move drive:test/move/srcDir drive:test/move/Folder/srcDir
... [Log Snipped] ...
newDir/
Folder/newDir/
```
Discussion
- I think this is because Google's "folder" is just a parent ID field, and the Parent ID field can be multi value. The rclone move should create the new parent id, but needs to remove the old one after a successful write.
- This used to work... I wonder when it stopped...
