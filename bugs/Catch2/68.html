Title

Section path filtering is hilarious broken

Description
## When things work as expected

### The test in question
```
cpp
TEST_CASE( "TRY FILTERS" ) {
    SECTION( "A" ) {
        SECTION( "B" ) {
            SECTION( "C1" ) {
... [Log Snipped] ...
    }
}
```

### Usage examples

**Section path prefix filter**
```
./tests/SelfTest "TRY FILTERS" -c "A" -c "B"
Filters: "TRY FILTERS"
Randomness seeded to: 2698325630
===============================================================================
All tests passed (2 assertions in 1 test case)
```
This works as expected, that is, we run both assertions, because the section
path prefix we specified contains both of them.

**Disambiguated section path prefix filter**
```
./tests/SelfTest "TRY FILTERS" -c "A" -c "B" -c "C1"
Filters: "TRY FILTERS"
Randomness seeded to: 4049078214
===============================================================================
All tests passed (1 assertion in 1 test case)
```
We disambiguated the two "C" sections, and only run 1 assertion.

**Bad section name in section filter**
```
$ ./tests/SelfTest "TRY FILTERS" -c "A" -c "ZZZZZZZZ" -c "C1"
Filters: "TRY FILTERS"
Randomness seeded to: 4083994241
===============================================================================
test cases: 1 | 1 passed
assertions: - none -
```
No assertions run, because the "ZZZZZZZZ" filter doesn't pass through
the "B" section.

**Missing part of the section filter**
```
$ ./tests/SelfTest "TRY FILTERS" -c "A" -c "C1"
Filters: "TRY FILTERS"
Randomness seeded to: 134702392
===============================================================================
test cases: 1 | 1 passed
assertions: - none -
```
No assertions run, because there is no "B" in our filter.

So far, so good. So what are the broken parts?

## Simple case without generators

**simple example without setup/teardown code**
```
cpp
TEST_CASE("foo") {
    SECTION("A") {
        SECTION( "B1" ) {
            REQUIRE(true);
... [Log Snipped] ...
    }
}
```

`./tests "foo"`
 -- 3 assertions

`./tests "foo" -c "A"`
 -- 3 assertions, cause "A" is there and we don't filter further
 
`./tests "foo" -c "A" -c "B"`
 -- 0 assertions, cause "B" is not there

`./tests "foo" -c "A" -c "B1"`
 -- 1 assertion, because B2, B3 do not match

`./tests "foo" -c "A" -c "B2"`
 -- 1 assertion, because B1, B3 do not match

`./tests "foo" -c "A" -c "B2" -c "XXX"`
 -- 1 assertion, the extra filter is not an issue

How to run B1 and B2 without B3? You cannot, you have to run the test twice.
  -- Possible extension in the future, to have something like -c "B*", or "B1,B2", similar to test spec matching

**Dynamic sections in a generator**
```
cpp
TEST_CASE( "corge" ) {
    REQUIRE( true );
    SECTION( "A" ) {
        REQUIRE( true );
... [Log Snipped] ...
    REQUIRE( true );
}
```
This behaves similarly to the previous example with single important
difference, which is that we can run the generator's subsection for just
1 element:

`./tests "corge" -c "i=2"`
 -- 7 assertions, 1 from the dynamic section when generator returns 2,
    6 from setup and teardown as the generator iterates its 3 elements.
- **Generator inside a sibling section**

This provides a nice way of only running the first section, or only
running the generator inputs. Generators are still unfiltered however,
so setup and teardown code inside section "B" runs a lot, even if the
dynamic section will never be entered.

```
cpp
TEST_CASE("grault", "[approvals]") {
    REQUIRE( true );
    SECTION( "A" ) {
        REQUIRE( true );
... [Log Snipped] ...
    REQUIRE( true );
}
```

`./tests "grault"`
 -- 12 assertions (4x setup and teardown, 1 in A, 3 in B)

`./tests "grault" -c "A"`
 -- 3 assertions (1x setup and teardown, 1 in A)

`./tests "grault" -c "B"`
 -- 9 assertions (3x setup and teardown, 3 in B)

`./tests "grault" -c "B" -c "i=1"
 -- 7 assertions (the generator has to run 3 times, but only 1 time the dynamic section is entered)

`./tests "grault" -c "B" -c "XXX"
 -- 6 assertions (the generator still has to run 3 times, but no dynamic section is entered)
