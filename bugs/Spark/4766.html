Discussion
- Master branch also throws an exception.
- This exception is thrown since  BigInt  and  BigInteger  does not have  precision  method. Current Spark runtime assumes that the value is fit into 64-bit. 
I will create a PR by using  this approach  to get a precision for  BigInt .
- User 'kiszk' has created a pull request for this issue: 
 [URL]
- Thanks! I saw  scala.math.BigInt  and  java.math.BigInteger  when looking through  ScalaReflection.schemaFor . I couldn't use a  Dataset[java.math.BigDecimal]  because that is always precision(38,18). I figured that getting the  BigInt  variants to work would be easier than getting  BigDecimal  to work with a non-default precision.
