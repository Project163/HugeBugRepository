Title

Conflicting report names lead to inaccurate overall reports

Description
We are using ADO pipeline with MTP, and have ~50 projects in our solution.

Sometimes, when we run `dotnet test...` in the root, in the ADO pipeline, duplicate names of TRX files produced and overwrite(?) eachother.

E.g. if I run dotnet test two times in a row - sometimes I'm getting 50 log files, and 50 trx files, and sometimes I'm getting 50 log files, and 49 trx files.

I dived deeper into the logs and that's what I've found:

```
➜  logs comparison cat 1.0.03099.10973/Retries/**/*.log | grep \\.trx | grep -v Moving | awk '{print substr($0, 36)}' | sort
ContainerAdministrator_22F450F68FC1_2025-06-27_06_27_32.028.trx
ContainerAdministrator_22F450F68FC1_2025-06-27_06_27_32.794.trx
ContainerAdministrator_22F450F68FC1_2025-06-27_06_27_32.980.trx
ContainerAdministrator_22F450F68FC1_2025-06-27_06_27_32.980.trx
ContainerAdministrator_22F450F68FC1_2025-06-27_06_27_33.050.trx
...
```

So two assemblies picked `ContainerAdministrator_22F450F68FC1_2025-06-27_06_27_32.980.trx` as the report file name.
It would be nice, if the trx file name could have been somehow randomized - e.g. (for backward compatibility) have some flag to append random guid to the file name.
