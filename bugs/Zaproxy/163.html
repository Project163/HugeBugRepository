Title

Alerts API should always return 'evidence' (and all other keys)

Description
First noticed when upgrading automation from ZAP 2.3.1 to 2.4.x.

In the past (and in most cases in 2.4.x) when ZAP's API returns alerts, if keys like 'evidence' do not have any data they are returned as an empty string. In 2.4.x, certain alerts seem to not include the 'evidence' key if there is no data. This may affect other keys as well, but this is the one I've noticed.

In example below, note that the first several alerts include an empty value for the evidence key whereas the final output does not include the evidence key at all. This seems to affect at least alert 10015 (Incomplete or no cache-control and pragma HTTPHeader set).

Expected behavior: All alert keys are returned in each alert dict with empty string values if they are not present in the alert. This allows automation to assume dict structure.

Discussion
- I've validated that there is a discrepancy with this. If [Link: evidence returned is null] it isn't included. I verified this by listing 100 alerts, in which I encountered 70 occurrences of "evidence", when I changed that line to `String.valueOf(alert.getEvidence())` then I got 100 occurrences of "evidence" in my results (30 occurrences of "null").

Going forward we probably don't want "null" but rather just an empty string. But at last this identifies there where and the cause.

I checked through 100 alerts and only found `evidence` impacted, I then did a second set and found 2 occurrences of `attack` impacted. After that I went through a third set that confirmed the same but didn't reveal anything further.

Something like: `map.put("evidence", alert.getEvidence() == null ? "" : alert.getEvidence() );` might also be a workable solution.
- So this can be handled in the API as mentioned above, however, I've been wondering if it would be better handled in the `Alert` class itself. Currently all the setElement type methods just return if the value being passed is null, I suggest that similar to above we check null and set empty string instead.

Thoughts?
