Title

Crash with libcurl 7.63.0 and CURL_LOCK_DATA_CONNECT

Description
It seems there's a race condition when using shared connections. The same connection data gets used in two contexts and thus results in a segmentation fault. Here is an example that reproduces this issue.

These settings help reproduce the issue faster:
```
curl_easy_setopt(curl, CURLOPT_TCP_KEEPALIVE, 1);
// this simulates non-responsive DNS server
curl_easy_setopt(curl, CURLOPT_DNS_SERVERS, " ");
```

I use libcurl 7.63.0 together with c-ares 1.15.0 and openssl 1.0.2q...but it shouldn't matter as I can see during debugging that the same connection data gets used in two connection contexts and that results in a crash.
