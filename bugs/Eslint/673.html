Title

Unable to extend local module from default/main file

Description
I created a dummy eslint-config-\* file (https://github.com/pdehaan/eslint-config-extends-test) which extends **eslint-config-node-style-guide** and attempts to bundle the node-style-guide dependency so it doesn't need to be installed with each other repo.

As you can see, the _index.json_ file is the `main` file in the package.json file, and it extends the ./_base.js file:

``` js
{
  "extends": "./_base.js",
  "rules": {
    "quotes": [2, "double"]
  }
}
```

When I try and use this custom config in one of my projects, I get the following error:

Where my package.json includes the following:

``` js
  "devDependencies": {
    "eslint": "^1.7.3",
    "eslint-config-extends-test": "pdehaan/eslint-config-extends-test"
  }
```

and my project's .eslintrc file uses my custom config:

``` js
{
  "extends": "extends-test"
}
```

Discussion
- The workaround is a bit weird, and not immediately obvious (to me, but I'm a bit dim)...

Instead of using something like "index.json", convert to "index.js" (in your custom config) and then `module.exports` the JSON config object. Then you need to pass a fully qualified path to the _base.js config file, using `path.join(__dirname, '_base.js')`, as seen in the following snippet:

```
js
var pathJoin = require('path').join;

module.exports = {
  "extends": pathJoin(__dirname, "_base.js"),
... [Log Snipped] ...
  }
};
```
- Basically we want to share a custom ESLint config between 10-20 repos where the custom config extends **eslint-config-node-style-guide**, but we don't want to have to install the **eslint-config-node-style-guide** module as a dependency in each of those projects. Ideally we'd just be able to bundle the eslint-config-node-style-guide dependency in our custom config and only need to install **eslint** and **eslint-config-extends-test**.
- ... [Middle Discussions Snipped for Brevity] ...
- @t128 you can always clone the object and modify that if you want to be "nice".
- @nzakas Actually, your solution works with simple modules such as **eslint-config-node-style-guide** which is basically a single JSON file of rules.
But I just tried converting one of our other projects and it broke since **eslint-config-airbnb** uses a complex web of nested extends and rules files.

In my **eslint-config-blah** custom rules module, I extend **airbnb/base** using the following:

```
js
var base = require('eslint-config-airbnb/base');

base.extends.unshift('eslint:recommended');

```

```
js
```

But when I try and run my `$ gulp lint` task, I get the following error because it can no longer resolve those **eslint-config-airbnb** references since they were specified as a dependency in my **eslint-config-blah** module, and not declared as a dependency of my main project:
