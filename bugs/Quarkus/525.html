Discussion
- This works as designed (and required by the spec). For a normal scoped bean a client proxy is used instead of the contextual instance for injection, observers notification, etc. So the no-args constructor is first called when instantiating the proxy (which is a subclass of `FooBean`) and then for the contextual instance. It's a good practice to use a `@PostConstruct` callback to initialize the bean. Also if your bean declares a bean constructor with parameters (injection points) you would not observe this behavior either (client proxy is always instantiated via the noa-args constructor). Another solution is to switch to `@Singleton` or `@Dependent` for which a client proxy is not created at all.
