Title

[ConnMgr] Connection Manager crashes in case of error when writing to client during authentication

Description
Jira Link: [Link: DB-18958]
### Description

Steps to reproduce:
- Supply the wrong password or no password trying to login to a user that has a password set
- Create a client connection pool (pgxpool) with a large number of minimum connections (say 120)
  - The application attempts to create multiple connections in parallel (maybe all of them very close to each other, thanks to goroutines).
- When 1 connection's authentication fails and it becomes known to client driver, the driver errors out and our application closes
- Now when connection manager tries to send a message to another connection, it will fail to write the message as client has closed all connections
- This results in double free happening

Double free happens here since `od_write` takes ownership of `msg` and will free it:
