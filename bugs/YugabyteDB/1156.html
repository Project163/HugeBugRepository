Title

[YSQL] Bitmap Scan Wrong Results with aggregates and local filters when exceeding work_mem

Description
Jira Link: [Link: DB-11736]
### Description

```
sql
CREATE TABLE multi (a INT, b INT, c INT, h INT, PRIMARY KEY (a ASC, b ASC));
CREATE INDEX ON multi (c ASC) INCLUDE (a);
CREATE INDEX ON multi (h HASH) INCLUDE (a);
CREATE INDEX ON multi (b ASC, c ASC);
... [Log Snipped] ...
 Peak Memory Usage: 595 kB
(10 rows)
```

This is because the second bitmap table scan is not targetting `a`, so the local filter is checking garbage values. 

This should have been fixed by #22622, I'm not sure why it wasn't. Probably a slight modification is required to that change to make it work.
