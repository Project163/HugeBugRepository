Title

Hot-reload brokes Vertx JsonObject serialization (dev mode)

Description
### Describe the bug

Scenario: 
- custom dto with a custom jackson `StdSerializer` registered via `ObjectMapperCustomizer`
- serialization of a `io.vertx.core.json.JsonObject` where a property is an instance of custom dto
- serialization of a `io.vertx.core.json.JsonArray` where one or more elements are instances of custom dto

During first run all works correcty, but after the application is hot-reloaded due to some project modifications, serialization stop to works with this error

Discussion
- After some digging I have more info to share:
the problem is in `com.fasterxml.jackson.databind.ser.impl.IndexedListSerializer#L108`
```
Class  cc = elem.getClass();
JsonSerializer  serializer = serializers.serializerFor(cc);
```
because `cc#classLoader` always change between reload (as expected) instead class stored in `serializers` `(com.fasterxml.jackson.databind.ser.impl.PropertySerializerMap$Single#_type)` is cached between reload and associated CL is always the original CL so Jackson doesn't recognized custom serializer for `cc` and fallback to generic `BeanSerializer`.

Seems that `io.quarkus.vertx.runtime.jackson.QuarkusJacksonJsonCodec#mapper` is never restored between reloads; some code related to `QuarkusJacksonJsonCodec` can has been found in `io.quarkus.vertx.deployment.VertxJsonProcessor`.
