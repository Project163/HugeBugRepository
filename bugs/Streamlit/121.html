Title

st.map() fails with zoom error for small number of points

Description
# Summary

In this [Link: forum post], the user highlights that `st.map()` does not plot a single point for the map. To troubleshoot, I opened up the Chrome console, saw a "Zoom must be set error" message in regards to the map.

# Solution

Adding a non `None` zoom value in the `st.map()` call [Link: resolves the issue]. Need a heuristic for a "small" number of points where `st.map()` automatically adds an integer value for the `zoom` parameter. At larger volumes of data, `zoom =None` seems to be ok, and deck.gl infers the proper zoom level based on the bounding box of data points.
