Title

Using "contrast(..)" in a CSS3 filter definition throws error

Description
Using the CSS3 contrast [Link: filter] throws an error in 1.3.2 from the command line:

``` css
.test {
  filter: contrast(2.0);
}
```

Throws an error:

Seems like LESS is expecting a color as an input, which should not apply in this case.

A workaround is to escape any value that contains `contrast`:

``` css
.test {
  filter: ~"contrast(2.0)";
}
```
Discussion
- This seems to be a regression as of 1.3.1 - the same test case works fine in 1.3.0.
- we added a contrast function. If the arguments don't match it really should output it literal.

I'll fix pretty soon and put it in 1.4.0 or 1.3.3 if there are any critical bugs.
