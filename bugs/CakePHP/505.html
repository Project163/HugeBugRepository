Title

cake schema generate inconsistant schema class name

Description
cake schema will always generate a class name based on the applications name by default, this can cause problems when the folder name on live server is different to a developers set up, which is not unlikely, or two devs have different folder names.

See this comment for a longer explanation written by @beporter [URL]
Discussion
- Would supporting the `--name` argument for `schema generate` solve this?
- Sure - if you know about it and if you type it every single time and agreed with everyone in the team to use a specific name. I've already implemented a work-around in the migrations plugin but IMO this is a generic "issue" that should be fixed in the core.

Why was it implemented the way it is, taking the app folders name instead of using a fixed name like "App" that can be optionally changed if you want? Relying on the folder makes it pretty much random.
- ... [Middle Discussions Snipped for Brevity] ...
- When I need to load schema files with custom names I combine the `file` and `name` options in the command line to load the desired file
- @lorenzo The problem is that you can't use a custom `--name` with **the default** `--file` argument. If you tried to specify `bin/cake schema generate --name brian --file schema.php` you would end up with a file named `Config/Schema/brian.php` instead of `schema.php` as expected. The PR fixes that.
