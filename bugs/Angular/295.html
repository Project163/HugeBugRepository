Title

CanDeactivate guard receives an incorrect component

Description
**I'm submitting a ...**  (check one with "x")

```
[x] bug report => search github for a similar issue or PR before submitting
[ ] feature request
[ ] support request => Please do not submit support request here, instead see [URL]
```

**Current behavior**
[Link: CanDeactivate] guard receives a component related to the first deactivated segment instead of a component that a guard is attached to.

```
[
    {
        path: '',
        redirectTo: '/hero-center/heroes',
        pathMatch: 'full'
... [Log Snipped] ...
    }
]
```

So, in the case of navigation from _/hero-center/hero/1/_ to _/crisis-center_, `CanDeactivateGuard` is called with `null` (component-less component) instead of `HeroDetailComponent`.

The issue is not reproducible with Angular 2.0.1.

**Expected behavior**
[Link: CanDeactivate] guard should receive a component that a guard is attached to for the `component` parameter.

**Minimal reproduction of the problem with instructions**
Here is a minimal [Link: plunker] demonstrating the issue based on [Link: Routing & Navigation] live example.

Steps to reproduce:
1. Go to any hero
2. Go to "Crisis Center"

Actual result: Cannot read property 'canDeactivate' of null.
Expected result: A confirmation dialog is shown.

**What is the motivation / use case for changing the behavior?**
There are no ways to prevent navigation from a child component in the case of unsaved changes, etc.
