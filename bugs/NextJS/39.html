Title

next/image imagix breaks querystrings

Description
### What version of Next.js are you using?

11

### What version of Node.js are you using?

14

### What browser are you using?

Firefox, Chrome, Edge

### What operating system are you using?

Windows 10

### How are you deploying your application?

Vercel

### Describe the Bug

If the image URL already has a querystring, next/image just appends its own on the end with a ? which breaks both querystrings.

### Expected Behavior

next/image should merge the two querystrings giving some means for the developer to decide which querystring takes priority if both contain the same parameter.

### To Reproduce

Use next/image with imageix/prismic with a image URL that already contains a querystring.
Discussion
- Hi @hades200082 

Next.js recently introduced a [Link: loader] prop you can define on the component (as opposed to next.config.js) which lets you have more flexibility.
- @styfle Thanks for suggesting a workaround. Problem is that this would be a pain to have to do literally everywhere I use next/image and needing to wrap next/image in another layer seems to defeat the point of having next/image as a built in component in the first place.

Next.js provides a loader for Imagix which has a bug in the way it handles image URLs with existing query strings - which is not an uncommon occurrence with CDN image hosting. In fact, with Prismic (which uses Imagix under the hood) their content API returns the Imagix URL's with querystring properties already set in many cases.

To improve the developer experience of the next/image component I'd suggest that the built-in loaders need to account for the possibility that the `Src` could already have query string parameters, merging them where possible and overriding them where needed.
- We can utilize `new URL(root)` to fix this and thus, safely append query string params if the root already had them.

Would you like to submit a PR and a test to fix it?
