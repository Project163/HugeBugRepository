Title

MenuItem doesn't accept GStrings as values

Description
The following code throws an exception 

  
  import  groovy.swing.SwingBuilder
def i =  "One" 
 new  SwingBuilder().menuItem( "Option $i" )
 
  

 java.lang.RuntimeException: Failed to create component for 'menuItem' reason: java.lang.RuntimeException: menuItem can only have a value argument of type javax.swing.Action, javax.swing.Icon, java.lang.String, or javax.swing.JMenuItem 

 This may happen in other parts of the builder. A proposed solution is to register a attribute delegate that converts to strings all values that are actually GStrings before the node is instantiated.
Discussion
- Fix for 1.6.1.
- While an attributeDelegate could solve many cases there are other two scenarios that have to be taken into consideration 
 
	 factories expecting a String while calling newInstance() 
	 value could be a GString 
 

 #1 is easily fixed with a preInstantiateDelegate instead of an attributeDelegate 
#2 could be solved also with a preInstantiateDelegate but only if we change the contract of the delegates, as the value is actually immutable right now, FBS.preInstantiate() must now return a value.
- Fixed it in the factories.  A global fix may not be desired in all cases (GSQL for instance want to know GStrings from Strings). 

 Action widgets, text widgets, look and feel, and arbitrary strings to text attributes also fixed.
