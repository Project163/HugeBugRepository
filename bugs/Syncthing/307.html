Title

lib/connections, lib/model: Deadlock on new connection when it tries to set the name

Description
Since some recent change I think. lib/connections calls model.AddConnection with a lock held, AddConnection updates the config by setting the device name, that calls CommitConfiguration which calls into lib/connections where it tries to acquire the same lock again.

Discussion
- Regression from 432c7807 I think, as before that we didn't hold the lock over AddConnections. Need to rethink what that was solving.
- I think it was racey between setting the connection type, adding the connection to the model and looking it up and the type in another routine, hence why it would sometimes prematurely disconnect I think.
