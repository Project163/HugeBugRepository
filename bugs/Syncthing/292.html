Title

Disconnects leak goroutines (sendIndexes)

Description
I've been running SyncThing in a small (4 node) cluster. Total about 4000 files at 5...6GB disk.

On my VPS (which is one of the few with all 4 folder shares) I regularly see a slow memory leak when doing synchronization among clients and when doing scans. SyncThing starts at 40MB memory usage and soon finds itself in the 120MB range.  The VPS it's living on only has 256MB of RAM and I have other services (namely, httpd) competing for time/memory there. 

Top shows SyncThing at 20ish percent of my memory load

```
  PID USER      PR  NI    VIRT    RES    SHR S %CPU %MEM     TIME+ COMMAND
20492 indrora   20   0   60732  55796   8884 S  0.0 21.3   0:05.73 syncthing
```

This just goes up as SyncThing scans folders or synchronizes with devices. I use SyncThing on my phone to back up photos, and a few large photos can churn SyncThing into eating several tens-of-megs of RAM.
Discussion
- It's a garbage collected language, so its fairly hard to leak stuff. I think using 120MB of RAM for all DB caches and bells and whitles is reasonable. There are things you could disable which could make it better (for example scanning progress which has to hold metadata about files in memory, ignore pattern cache) but you will either loose features or increase cpu load. Also, you can read about the GOGC environment variable and set that to something lower.
- I expressed myself poorly -- after several hours, this value balloons to nearly 200MB and gets OOM killed by my VPS. It explicitly happens when I have a short scan interval set on folders.

- I haven't checked but this seems likely; my android phone is a part of my cluster.
- When I pause my phone on my VPS and relegate my phone to WiFi only, RAM usage stays consistent. This confirms that the interaction of Android devices (or other devices on a cellfi connection) that move between networks regularly causes half open or idle connections to eat memory.
