Title

Quarkus hangs when clients disconnect after sending incomplete POST requests

Description
**Describe the bug**

When a client disconnects after sending an incomplete POST request, Quarkus keepks trying to read the input, blocking the thread indefinitely. Eventually, when all threads become blocked, Quarkus is unable to handle any requests.

It looks that VertxInputStream.VertxBlockingInput should add an exception handler to the request.

**Expected behavior**
Quarkus should throw an exception while reading an InputStream when the client disconnects.

**Actual behavior**
Quarkus keeps trying to read a closed InputStream indefinitely, leading to thread starvation.

**To Reproduce**

Create a simple resource like that:

```java
@POST
@Produces(MediaType.TEXT_PLAIN)
@Path("hello")
public String hello(byte[] b) {
    return "Ok";
}
```

Call it with a Content-Length different than zero and then disconnect:
```
echo "POST /hello HTTP/1.1\r\nContent-Length: 1\r\n" | nc localhost 8080
```

Do that several times.

Debug the application and look for threads with names similar to "executor-thread-x". You will see they are stuck:

```
"executor-thread-1" #47 daemon prio=5 os_prio=0 tid=  nid=  in Object.wait() [ ]
   java.lang.Thread.State: WAITING (on object monitor)
	at java.lang.Object.wait(Native Method)
	- waiting on  > (a io.vertx.core.http.impl.Http1xServerConnection)
	at java.lang.Object.wait(Object.java:502)
... [Log Snipped] ...
	at org.jboss.resteasy.core.MethodInjectorImpl.injectArguments(MethodInjectorImpl.java:96)
	...
```
