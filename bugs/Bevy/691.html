Title

`file_watcher` feature does not work correctly

Description
## Bevy version

`main (116484b37)`

## Relevant system information

```SystemInfo { os: "macOS 14.7 Sonoma", kernel: "23.6.0", cpu: "Apple M1 Pro", core_count: "10", memory: "32.0 GiB" }```

`rust 1.85.1`

## What you did

Running

```
RUST_BACKTRACE=full cargo run --package bevy --features=file_watcher --example scene
```

## What went wrong

If the file `load_scene_example.scn.ron` is getting modified the following exception is thrown in the console

```
2025-03-21T10:48:57.981886Z  INFO bevy_asset::server: Reloading scenes/load_scene_example-new.scn.ron because it has changed

thread 'notify-rs debouncer loop' panicked at crates/bevy_asset/src/io/file/file_watcher.rs:265:58:
called `Result::unwrap()` on an `Err` value: Os { code: 2, kind: NotFound, message: "No such file or directory" }
stack backtrace:
... [Log Snipped] ...
2025-03-21T10:49:08.787753Z  INFO scene:   Entity(12)
2025-03-21T10:49:08.787755Z  INFO scene:     ComponentA: { x: 3 y: 4 }
```

And from that moment, asset reloading stops working

This is not specific to this example, it fails for any type of assets, it's just the easiest way to reproduce.

## Additional information

- I've tested that in v.0.15.3, the issue is not there
Discussion
- I think the issue might be related to the fact that `RustRover` creates a temporary file  with a tilde like `load_scene_example.scn.ron~` and at the moment of calling `. canonicalize()` the file does not exists anymore.

I will push a fix for this issue
