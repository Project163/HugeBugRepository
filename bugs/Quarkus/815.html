Title

Generic Type arguments of producer method needs to be in a bean archive

Description
**Describe the bug**
I have a setup like this:
A producer that produces something with a generic type argument

```
@ApplicationScoped
public class BusinessObjectContainerProducer {

    @Produces
    @Dependent
... [Log Snipped] ...
    }
}
```
I have some concrete type "SpecificBusinessObject extends BusinessObject" where I inject the BusinessObjectContainer with the concrete type argument:

```
@Inject
BusinessObjectContainer  container;
```
Just for completeness; the container looks like this:

```
public interface BusinessObjectContainer  {
    void set(T bo);
}
```

All classes are part of the main quarkus application except SpecificBusinessObject and BusinessObject. They are defined in an external jar that does not contain a beans.xml (it does not contain any CDI beans).

**Expected behavior**
It should work; no error on quarkusBuild. As the external jar does not contain any CDI beans, there should not be the need to add a beans.xml.


**Actual behavior**

```
Caused by: javax.enterprise.inject.UnsatisfiedResolutionException: Unsatisfied dependency for type org.acme.BusinessObjectContainer  and qualifiers [@Default]
- java member: org.acme.ExampleResource#container
- declared on CLASS bean [types=[org.acme.ExampleResource, java.lang.Object], qualifiers=[@Default, @Any], target=org.acme.ExampleResource]
```

As soon as I add a beans.xml to the external jar, all works.

Discussion
- Hm, I think that we could try improve our `io.quarkus.arc.processor.BeanArchives.IndexWrapper` to handle this use case.
- The problem with the index wrapper approach is that it's designed to lazily index a specific missing type, e.g. `BusinessObjectContainer`. Whereas for this particular case we need to look for all known subclasses (e.g. all subclasses of `BusinessObject`); that would mean to load all types from the class path, i.e. something we're not going to do ;-).

So I think that we would have to leverage the application index (represented by the `CombinedIndexBuildItem`) during type-safe resolution.
