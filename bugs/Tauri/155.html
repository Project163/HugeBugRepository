Title

[bug] loading local assets which include url query strings via `tauri.convertFileSrc` fail to load

Description
### Describe the bug

The `asset` custom protocol implementation appears to treat URL query strings as part of the literal file path, so fails to load the asset.

I've tracked this down to [Link: `core/tauri/src/manager.rs#323`]:
```
rust
pending.register_uri_scheme_protocol("asset", move |request| {
  #[cfg(target_os = "windows")]
  let path = request.uri().replace("asset://localhost/", "");
  #[cfg(not(target_os = "windows"))]
... [Log Snipped] ...
  let path_for_data = path.clone();
 ...
```
I've been able to hack a temporary solution by using a regex to filter out the query string, the new code looks like this:
```
rust
pending.register_uri_scheme_protocol("asset", move |request| {
  #[cfg(target_os = "windows")]
  let path = request.uri().replace("asset://localhost/", "");
  #[cfg(not(target_os = "windows"))]
... [Log Snipped] ...
    .to_string();
  let path_for_data = path.clone();
```


### Reproduction

1. Use `yarn create tauri-app` to create a React app using Vite.
2. Create a local `index.html` file and `code.js` file.
3. Modify the `index.html` file to load the `code.js` file via a `script` tag, but append `?asdf` to the `src` attribute.
4. Modify the `code.js` file to log a message using `console.log`.
5. Modify the `App` react component to render an iframe which points to the `index.html` file, passing the path through `tauri.convertFileSrc`.

You *should* see the console.log message you added, but instead there is an error.

### Expected behavior

Files loaded into an iframe via `tauri.convertFileSrc` should be able to load their own assets which include url query strings.
