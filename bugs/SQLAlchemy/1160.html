Title

Invalid query with duplicate aliases generated with a combination of union, limit, joinedload and polymorphic tables

Description
**Describe the bug**
Duplicate `anon` names used in queries with` union`, `limit` and `joinedload` causing the query to fail at the driver level.
This query used to work before 1.4.

**To Reproduce**

```
py
from sqlalchemy import Column, Integer, String, ForeignKey, PrimaryKeyConstraint, func, Boolean, union
from sqlalchemy.orm import declarative_base, relationship, backref, joinedload
from sqlalchemy.schema import Table
```

**Additional context**

We are running into it with Postgresql in prod but I made the example with sqlite for simplicity. It raises a `DuplicateAlias` on pg. 
Another thing interesting is that the `UNION` is present twice in the query, presumably for the polymorphic tables? Seems a bit odd to me but I don't know much about them.

I've fixed it for us by changing the union to just fetch the ids, union them via `union(user_sample_query, project_samples_query).alias(name="visible_samples")` (name not required but nicer than anon etc) and `.filter(Sample.id.in_(aliased_union))`
