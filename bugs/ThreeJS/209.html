Title

WebGLRenderer allocateLights looking for global variable 'scene'

Description
Line 1329 of WebGLRenderer.js references 'scene' which isn't passed in as an argument or declared above -  so it's looking in the global scope. This works with the examples, which define a global 'scene' variable, but doesn't work if the variable isn't defined (as it isn't in our case)

Solution would be to pass the variable in or remove the check (I don't know enough for why it's there in the first place) - I'm happy to make the changes for either way and send a pull request if one of those solutions works.
Discussion
- Passing the variable sounds the best to me. Alteredq is the one that is dealing with that code though, so better wait to hear his thoughts.
- Oops, my bad, I forgot this when refactoring :(. Good catch. I'll fix this.
- And fixed ;)

Finally I just removed the check. Original purpose of the check was to bake some lights into shaders even when `scene` was not passed to WebGLRenderer constructor. 

As now shaders are build upon rendering the first frame (lights are passed directly to `allocateLights` instead of via `scene`), this check shouldn't be necessary.
