Title

Files on deduplicated NTFS volumes are ignored by scanner

Description
When adding a folder on a volume with NTFS Deduplication enabled, deduped files are incorrectly skipped by the scanner. Files that are still pending deduplication are processed as expected. Folders are also processed as normal.

A bit of digging indicates that os.Lstat on a deduped file has a FileMode containing ModeSymLink. Looking at the Read function in [Link: symlink_windows.go], the type of reparse point is available in reparseData.reparseTag, which should allow for correctly handling the condition. 

A quick reference to the tag values is available in [Link: smbfsctl.h]. Of interest are:
- IO_REPARSE_TAG_DEDUP =  
- IO_REPARSE_TAG_SYMLINK =  
- IO_REPARSE_TAG_MOUNT_POINT =   (may be related to #1830)
- More info about [Link: Reparse Points] and supported operations

For reference, it is possible to query a reparse point's tag and data with  fsutil reparsepoint query PATH_TO_FILE . This even works across SMB shares with UNC paths.
