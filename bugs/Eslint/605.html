Title

Incorrect autofixing with key-spacing rule

Description
Given the rule: `"key-spacing": [2, {"align": "value"}]`

And an object literal in the form:

``` javascript
  const attributes = {
    visible: ['email'],

    articles () {
      return this.hasMany('Article')
    }
  }
```

Autofix will rewrite the literal as:

``` javascript
  const attributes = {
    visible: ['emai

    articles () {
      return this.hasMany('Article')
    }
  }
```

If the properties with shorthand notation are grouped with properties with regular notation, the key-spacing rule will always fail but autofix will do nothing (i.e. leave it unchanged).

In the source examples below, I use `☠` to indicate whitespace. Whitespace is not stripped upon saving the file. It makes no difference whether shorthand notation or regular notation comes first, only that the property has trailing spaces.

#### Trailing whitespace on shorthand notation

Before:

``` javascript

  shorthand,☠☠☠☠

}

After:

let shorthand = true

export default {
  shortha☠☠☠
  regular: 'foo'
}
```
