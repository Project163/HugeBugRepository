Title

ArgumentError: bad value for range on accessing range with infinite lower range

Description
### Steps to reproduce
1. Create a `Thing` table with a `tsrange` column named `active_during`.
```
class CreateThings  

**Ruby version**:
ruby 2.7.1p83 (2020-03-31 revision a0c7c23c9c) [x86_64-darwin18]
Discussion
- The error is coming from [URL]

The value comes in as `"(,\"2020-08-22 00:00:00\"]"`, then we try to cast it to a range by extracting out `from` as `-Float::INFINITY` and `to` as a `Time`. Unfortunately it is not possible to create a range from `-Float::INFINITY` to a `Time`:

```rb
-Float::INFINITY..Date.tomorrow.to_time
#=> ArgumentError (bad value for range)
```
- @composerinteralia @kamipo 

I see different solutions:
1. This can be resolved by a Float monkey-patch (maybe as part of ActiveSupport):
```
class Float
  alias_method :original_compare, : 
  def  (other)
    if other.is_a? Time
      -(other   self)
... [Log Snipped] ...
  end
end
```
But I don't how I feel about that. 

2. Updating Ruby itself to support `-Float::INFINITY..Time.new` (as well as `Time.new..Float::INFINITY`) on the native level. This would not require any changes on the Rails side but it will take some time to release the new Ruby version. ([Link: Rejected by Matz])

3. Use `nil` instead of `Infinity`
Ruby 2.7+ supports both Beginsless and Endless ranges
Ruby 2.6+ supports only Endless ranges
Ruby 2.5 (current ActiveRecord ruby version) can only use `Time.new..Float::INFINITY` due to an ActiveSupports Time monkey-patch
    1. Bump up ruby version from `2.5` to `2.7` and use Beginless/Endless ranges
    2. Make ActiveRecord support both `Infinity` and `nil` approaches when casting ranges based on the current ruby version (So if you use Rails with Ruby 2.7+ you should be able to use these PostgreSQL ranges with rails)

Thoughts?
- I ran into this today as well. The solution above that monkey-patches float seems extremely convenient, but I also totally understand the concerns with doing that. (The degree to which ActiveSupport and many Ruby gems monkey-patch built-in stuff really gave me pause when I first picked up both Ruby and Rails.)

I’d be happy with any solution that makes these values accessible, whether it’s 3.ii (3.i seems like imposing an unreasonable upgrade burden on lots of Rails users), a custom range type for this situation (then we could also support ranges that exclude the start value), or even if ActiveRecord just gave me back the Postgres string representation (`'[-infinity,2020-08-22 00:00:00]'`) and also let me set it using the string. (This last one is definitely the worst solution, but it’s still better than not being able to read a value like this at all.)
- Given the rejection of option 2, I think 3.ii is the most reasonable option.
