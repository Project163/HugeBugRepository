Title

Scoped variable name conflict with star import

Description
I've found this bug to be tied to when the following is true:

- module export passes through another module's default export as a named export
- wrapping module's named export does not equal the file name of the imported module
- consuming module uses a variable (inside a scope) of the same name as the file name of the module with the default export.

This is happening in Rollup v0.41.5

Source modules:

`main.js`
```javascript
import * as wrap from './wrap';

function scope() {
  const group = wrap.Group();
}

scope();
```

`group.js`
```javascript
export default function() {
  return true;
}
```

`wrap.js`
```javascript
export { default as Group } from './group';
```

Rollup Output:

```
javascript
'use strict';

function group() {
  return true;
... [Log Snipped] ...

scope();
```
Discussion
- Is there a suggested work around or way to fix this?
- To be honest, I haven't dug to deep for an actual fix in rollup.

As far as work arounds, I think if you name the default variable the same as the file name imported, you shouldn't run into the problem.
