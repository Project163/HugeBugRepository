Title

--exclude-if-present fails if rclone can't read directory

Description
Using the --exclude-if-present option, rclone fails if it encounters a directory which it doesn't have permissions to read (e.g. $HOME/gnupg).  Without --exclude-if-present, rclone silently ignores such directories.  I think it would be useful for this to be the behavior for --exclude-if-present too.

Adding the directory to the exclude list doesn't fix it (as probably expected since the docs say --exclude-if-present has priority).

Tested with:
rclone v1.39
- os/arch: linux/amd64
- go version: go1.9.2

And
rclone v1.39-002-gef89f1f1β
- os/arch: linux/amd64
- go version: go1.9.2
 
Command:
beta/rclone sync $HOME b2:backup-mx9 --transfers 32 --exclude-from excludes --exclude-if-present .rclone-ignore -vv --log-file=log.txt

In this case the 'excludes' file contains a single entry:
/.gnupg**

Full log attached, but the relevant errors are:
ERROR : : error reading source directory: lstat /home/jrmales/.gnupg/.rclone-ignore: permission denied
Failed to sync: not deleting files as there were IO errors

[Link: log.txt]

- It seems that Fs interface does not have a way to return ErrorPermissionDenied, because there is no such error defined.

I see three quick workarounds.

1. FileExists returns false in case of any error.
2. We introduce ErrorPermissionDenied which will be (at least initially) implemented only for local fs.
3. Explicitly check for os.ErrPermission.

I think it should fix the error; I'm not sure though how easy is it to write proper test for this.
