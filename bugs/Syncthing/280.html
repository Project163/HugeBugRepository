Title

Upgrade can delete previous version config file if it is "old"

Description
If the user hasn't made any changes to the configuration in a month or more, and they upgrade Syncthing, the previous config file is deleted by the [Link: clean-up routine].

Presumably this isn't desired behaviour - maybe the config upgrade routine could timestamp the old file, so as not to invoke the wrath of the clean-up routine.
Discussion
- I think we constantly save the file as we are running, but I might be wrong. The right thing todo is to touch the file on startup.
- I don't see how we would do that, regardless of how old the config file is? We erase old conversion backups, `config.xml.v*` (note the `.v*`).
- ... [Middle Discussions Snipped for Brevity] ...
- I just upgraded one instance from 0.11.26 to 0.12.4. It logged that it archived the 0.11 config file, and then that it cleaned it up (i.e. deleted it).
[YRZZV] 19:29:31 INFO: Archiving a copy of old config file format 
[YRZZV] 19:29:33 INFO: Cleaned away old file config.xml.v11
- @AudriusButkevicius: Yeah, I'd rather have the previous version's config file available in case I need to downgrade. Once it reaches the "old age" in the clean-up routine then I would think it's safe to delete it.
