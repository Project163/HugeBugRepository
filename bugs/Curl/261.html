Title

Memory-leak with HTTP3

Description
### I did this

Building with `-DUSE_NGHTTP3`, `-DCURLDEBUG` etc. And issuing these commands (in a .bat-file):
```
set CURL_MEMDEBUG=c:\temp\memdebug.curl
  set CURL_DEBUG=http2,http3,setup
  set CURL_SSL_BACKEND=rustls
  curl.exe --http3 -v4oNUL [URL]
  ...
... [Log Snipped] ...
  * [HTTP/3] [0] [authorization: Basic YW5vbnltb3VzOnlvdXJAZW1haWwuYWRkcmVzcw==]
   ...
```

shows some leaks from `perl tests/memanalyze.pl %CURL_MEMDEBUG%`:
```
  Leak detected: memory still allocated: 71 bytes
  At 1c572a9a4a8, there's 39 bytes.
   allocated by vtls/openssl.c:3392
  At 1c572a9aca8, there's 32 bytes.
   allocated by vtls/openssl.c:3381
  Open FILE handles left at:
  fopen() called at vtls/keylog.c:61
```

Strange to me that there are leaks in `vtls/openssl.c` when I did a `set CURL_SSL_BACKEND=rustls`.
Or is there some common code also used for RustTls?

But I'd assume `ossl_free_multi_ssl_backend_data()` should free these blocks. 
And the key-logfile should be closed via `ossl_cleanup()`. Seems it's called, but perhaps it's opened twice?

### I expected the following

No memory leaks.
