Title

Commit body is calculated incorrectly in some cases

Description
While investigating the problem with `docs` scope exclusion from min body length checks (see [URL] I noticed that the commit body that we use for length check also includes the content that would be dropped after the commit is made. For example when I make some change, run the `git commit` command and presented with the screen to type commit message like this:

```
docs: some test

# Please enter the commit message for your changes. Lines starting
# with '#' will be ignored, and an empty message aborts the commit.
#
... [Log Snipped] ...
#	modified:   .ng-dev/config.ts
#
```

Everything below the first 2 lines (all lines that start with `#`) are treated as commit body, thus passing the min length validation even though it would later fail on CI.

The proposal is to process commit body before performing the length check and remove all lines that start with `#`.
Discussion
- I ran into a similar issue, where commit message validation was failing due to a long line that was part of the comment:

```
# Changes to be committed:
#	renamed:   aio/tools/examples/shared/boilerplate/i18n/polyfills.ts --> aio/tools/examples/shared/boilerplate/i18n/src/polyfills.ts
```
