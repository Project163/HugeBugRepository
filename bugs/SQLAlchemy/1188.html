Title

Using posgresql.ARRAY.overlap() in a multiple join scenario gives a cartesian product warning

Description
### Describe the bug

A query that joins three entities on `ARRAY.overlap` conditions triggers a cartesian product warning despite the correct SQL being emitted.

### To Reproduce

```
python
import sqlalchemy as sa
from sqlalchemy.dialects import postgresql
from sqlalchemy.ext.declarative import declarative_base
from sqlalchemy.orm import Session, aliased
... [Log Snipped] ...

print(qs.all())
```


### Error

SAWarning: SELECT statement has a cartesian product between FROM element(s) "ancestor", "foo" and FROM element "descendant".  Apply join condition(s) between each element to resolve.




### Versions

- OS: Arch Linux 5.4 (Manjaro)
- Python: 3.9.6
- SQLAlchemy: 1.4.22
- Database: Postgresql 13.3
- DBAPI: psycopg2-binary 2.9.1

### Additional context

I've read [URL] as it seemed correlated but after some testing I don't think it is, as this issue was particular to the type of `JOIN` used.

Here, changing the join type from `isouter=True` to `isouter=False` still triggers the warning. Moreover, replacing the `ancestors_ids` array column on `Foo` by a `parent_id` integer column and then replacing the `.overlap` join conditions by a simple `id`/`parent_id` equality doesn't trigger the warning. This seems to indicate that the problem comes specifically from using `.overlap` in a multiple join scenario and not from the join types themselves.

Finally, I don't know if that helps but while trying to ignore the warnings in pytest I ran into a bit of a quirk: the warning's message changes with every execution (assuming the .pyc have been recreated):
`SELECT statement has a cartesian product between FROM element(s) "foo", "ancestor" and FROM element "descendant"`
`SELECT statement has a cartesian product between FROM element(s) "descendant" and FROM element "ancestor"`
`SELECT statement has a cartesian product between FROM element(s) "descendant" and FROM element "foo"`
After a good dozen tries I got these three distinct messages

Discussion
- this is something simple, for temporary workaround you can monkeypatch:

```
diff
diff --git a/lib/sqlalchemy/dialects/postgresql/array.py b/lib/sqlalchemy/dialects/postgresql/array.py
index d8e54ae0c4..1b036ac323 100644
--- a/lib/sqlalchemy/dialects/postgresql/array.py
+++ b/lib/sqlalchemy/dialects/postgresql/array.py
... [Log Snipped] ...
-OVERLAP = operators.custom_op("&&", precedence=5)
+OVERLAP = operators.custom_op("&&", precedence=5, is_comparison=True)
```
- this is also kind of general to the linter itself, as we support not emitting a warning for query like this:

"SELECT * FROM a JOIN b ON true"

but then it doesn't work for:  "SELECT * FROM a JOIN b ON true JOIN c ON true"
- **Mike Bayer** has proposed a fix for this issue in the **master** branch:

**fix linter JOIN logic; fix PostgreSQL ARRAY op comparison** [URL]
