Title

bazel run with --run_under does not work with targets in external workspace

Description
### Description of the problem / feature request:

`--run_under` does not seem to accept targets that are defined in external workspaces:
```
$ bazel run --run_under='@externalworkspace//:wrapper' -- //:run
/bin/bash: @externalworkspace//:wrapper: No such file or directory
```

According to the `--run_under` [Link: docs], this should work if the first argument to run is a fully qualified label (although it mentions "starts with `//`" as explanation for fully qualified label).

### Feature requests: what underlying problem are you trying to solve with this feature?

I'm trying to run a binary in my repo under a binary in a repo thats in another workspace. 

(Specifically I'm trying to include the go debugger delve, which is a regular go binary, using a `go_repository` rule so I can version the debugger and debug by running using the `dlv exec` command like `bazel run -c dbg --run_under='@dlv//dlv exec' -- //target`.)

### Bugs: what's the simplest, easiest way to reproduce this bug? Please provide a minimal example if possible.
```
--- WORKSPACE 
local_repository(
    name = "externalworkspace",
    path = "../externalworkspace",
)
... [Log Snipped] ...
$@
echo "wrapped"
```

### What operating system are you running Bazel on?

MacOS 10.14.3 (18D109)

```
$ bazel info release
release 0.23.1
