Title

with fetch optimization, the query runs after locks are released

Description
Other assumptions may also be broken. 
FetchTask.execute implementation is very curious - it does nothing, and the FetchTask that actually runs the query is put in the same place as the one that normally fetches the results; that is to say, the whole pipeline is run after Driver has "shut down" the query. That releases locks before the query runs, and may also have other implications (for transactions, etc.? I don't think simple fetch can be run for updates)
