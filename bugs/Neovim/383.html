Title

bug(zip): `[Content_Type].xml` zip member produces empty buffer

Description
### Problem

**Summary**
The "edit-files-within-a-zip-archive-without-extracting-first" feature of Neovim doesn't work for a member named `[Content_Types].xml`, possibly because of the square brackets in the name.

**Additional Context**
Neovim allows members of ("files" within) a Zip archive to be opened with a `netrw` type of interface. `:e file.zip` displays a list of the archive members, moving the cursor over one and pressing Enter opens it.

The `.docx`, `.pptx`, and `.xlsx` file formats are all Zip archives. A required member for these formats is `[Content_Types].xml` which maps other members to their MIME-type.

This behavior works fine on v0.9.1. I noticed the problem on 0.11.0-dev-482 and it's still there on 0.11.0-dev-573. 

### Steps to reproduce

- grab any DOCX, PPTX, or XLSX file, this link has one but any will do: [URL]
- `:e math_EE_overviewby_grade_EXTERNAL_July_2014.xlsx`
- Move cursor onto `[Content_Types].xml` and press Enter
- Buffer is empty, but `unzip -l math_...xlsx` reports size `2793` (and this member is never empty for these file types).
- Opening any other member in the archive produces content.

### Expected behavior

Should show content, probably two lines, the first an XML declaration like ` ` and then all the XML content on a very long second line.
