- @tonihei Can you take a look at this?
- That's an interesting problem. And yes, you are right that it will be solved in 2.12.   (For reference, this issue is #5155).

Generally speaking, only the first item that will be played has the initial unassigned empty timeline. So you could work around that by saving the `MediaDescriptionCompat` of the item that will be played after the call to `player.prepare`. You should know this in code depending on whether you reset the position in `prepare`:
 - If you do reset, the first first item in the playlist will be played first. 
 - If you don't reset the position, then you can query `player.getCurrentWindowIndex` to know which item will play first. 

Once you know the item, you can immediately query `concatenatingMediaSource.getMediaSource(index).getTag()` to retrieve the `MediaDescriptionCompat` before playback even starts and then use it in your listener for the case of the empty timeline. 

That's obviously way more complicated than it should be, but I can't think of another workaround for now.


This shouldn't be an issue in itself because the `eventTime.timeline` object still contains the item even if it was removed later.
