Title

Skipping values during reads may cause incorrect read repairs

Description
Data responses may skip values for columns not selected by the column filter. This can lead to empty values being erroneously included in repair mutations sent out by the coordinator.
Discussion
- This pull request  adds a dtest to expose this.
- That's right, the value skipping doesn't play well with read repair. In fact, that's also a problem for the "hoisting" of rows we sometime do on the query-by-names path. We could fix both places to ignore those "skipped values", which would be fine, but we want to release 3.0 and I want to 1) make sure there isn't some other places I've missed and 2) take the time to figure the safest way to deal with this. So for now, I've pushed a very trivial patch  here  to just disable that value skipping. That's "only" an optimization after all, and we're not worth off than in any previous version without it, so it's totally acceptable for 3.0. I'll create a followup ticket to re-enable in a cleaner/non broken way.
- +1 new test passes with the patch applied.
- For info, the followup is   CASSANDRA-10657  . 

 Otherwise, I've started unit test on the patch and will wait on the result to commit. Probably won't wait on the dtests though since I don't think they are yet already migrated to the new python driver and honestly, the risk of breaking something with this patch is very very minimal.
