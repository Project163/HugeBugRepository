Title

Web site Groovy Doc has two flavors and problem with shown methods for GroovyShell

Description
There are two flavors of API pages on the site –  [URL] and  [URL] they have different contents, but advertise the same SVN Rev.  It seems they are generated differently.  If they are both supposed to be available, perhaps they should have some distinguishing description so one can know which is the correct one for a particular purpose. 

 This was troubling to me because my Groovy code uses GroovyShell and the documentation under  [URL] doesn't include the parse methods which provide a signature that is useful in my code.
Discussion
- There are two parts to this issue (might be worth splitting out): 
 
	 The description between gapi and api isn't described in a visible enough way. gapi contains the groovydoc for the Java and Groovy source files. api contains the Javadoc forthe Java source files. Also, Groovydoc differs from Javadoc in that for Groovy files it distinguishes between properties and fields and also displays default parameter values. This info should be added to the wiki in a prominent way. 
	 There is some yet unreported bug that is causing the parse methods of GroovyShell not to show up in the Groovydoc. This bug needs to be tracked down and fixed.
- The first part of this issue has been addressed somewhat in   GROOVY-4045
- Updated title to include main remaining aspect to this issue
- Groovydoc was getting confused with the nested class definition in GroovyShell inside a method and from that point lost track of the remaining methods in the outer class. A more robust way to find the outer class is now in place.
