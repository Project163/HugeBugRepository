Title

When querying with high concurrency, the query may report an error (the thread is not safe when ACL permission multi-threaded concurrent access)

Description
ACL records are taken out of the cache, and the internal array is modified by sorting in the init method. Since the metadata in Kylin is shared, there will be multi-threaded access problems, so there will be concurrent modification problems here.
Discussion
- Root Cause 

 After a thread fetches AclRecord from memory, when performing init operation on the same object, it sorts the internal entries, 

 At this time, another thread also obtains the AclRecord object, and traverses the internal entries, triggering the failfast mechanism of ArrayList during the traversal process. 
   Fix Design 

 Before performing the AclRecord#init method, we need to use the copy object instead of the original object, otherwise it is equivalent to directly modifying the cached memory object, which will cause problems in a multi-threaded environment
