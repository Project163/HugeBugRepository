Title

Remove ZEPPELIN_NOTEBOOK_DIR and ZEPPELIN_INTERPRETER_DIR from common.sh

Description
The current issue I found is that zeppelin.notebook.dir defined in zeppelin-site.xml doesn't take effect. Because we define it in  [URL] and ZeppelinConfiguration will pick up configugration through enviroment variable over property defined in zeppelin-site.xml. ( [URL] I think some other conf like zeppelin.interpreter.dir are the same.  

 There're 2 approaches for it.  
 
	 Remove them in common.sh 
	 Preferer property in zeppelin-site.xml over enviroment variable. 
 

 Personally, I prefer the second approach.  As I think property is easier to understand, and we should use zeppelin-site as the central place for all the configurations. This is also the approach what spark use. 
\cc  moon   luciano resende   anthonycorbacho   jongyoul
Discussion
- I think we need to remove them from common.sh. 

 As you mentioned, zeppelin used to overriding zeppelin-site.xml by environment variable. And advertised this behavior. 
 [URL]

 Changing this will be big user experience change. 

 One reason in the beginning make environment variable override zeppelin-site.xml was, it's easy to add environment variable into conf/zeppelin-env.sh programmatically, via shell script, etc. 
In comparison modifying conf/zeppelin-site.xml programmatically requires little more skills. 

 I think it helps some deployment such as containerized deployment or run virtual machine image on AWS, to let user easily override configurations programmatically on start up.
- Make sense to keep compatibility with previous version, I will do the change soon.
