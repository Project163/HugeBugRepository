Title

Incomplete report for template Risk and Confidence HTML

Description
### Describe the bug

When generating a report using the template _Risk and Confidence HTML_, with all _Sections_ enabled, the generated report does not show any details of the alerts found:

[Image: image]
[Image: image]

The generated report files are a lot smaller than they used to be (with earlier versions, when the details were included). 

Using ZAP 2.14.0, Report Generation plugin 0.31.0.

Reverting to plugin versions bundled with 2.14.0 (by removing the ~/.ZAP/plugin; this reverts Report Generation to 0.26.0) resolves the issue, but as soon as I upgrade plugins to the latest versions, the issue is back.

### Steps to reproduce the behavior

1. Update to Report Generation 0.31.0
2. Perform active scan
3. Generate report (Risk and Confidence HTML) with all sections enabled.

### Expected behavior

The generated report contains alert details, such as http requests and responses.

After doing some debugging, I found that the issue was introduced with [Link:  ], and to be more exact [Link: this line]. Reverting the change on that particular line resolves the issue for me.

On said line, org.zaproxy.addon.reports.ReportHelper#getPortForSite() is used, with the full url passed into the method, e.g. [URL]

Looking at the method's source code and unit test, it looks like it is only meant to handle urls up until the port number, not urls that contain a path. Yet an url with a path is passed, causing the method to return 80/443 for many urls that actually use another port. As a result, details for many/all of the alerts in my scan are not added to the report (my site uses a custom port).

Not sure if the change on this line can safely be reverted like this, but in any case, to me it looks like the getPortForSite() method should not be used in this way here. Or the method should be expanded to support urls with paths in them (I've created [URL] for that, just in case).
- That's definitely the way to go, reverting the other change would regress.
