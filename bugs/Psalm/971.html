Title

Psalm with @template in namespace function fails to find error

Description
The original problem from #3182 is still not resolved.

When no `namespace` is used, Psalm correctly finds mismatched `@template` types:

[URL]

When a `namespace` _is_ used, Psalm **fails to find** mismatched `@template` types:

[URL]

Note that this seems to be only when using `string` callable types. From what I can tell all other callable scenarios work as expected:

[URL]
Discussion
- From testing it appears as the `namespace`d scenario gives the `TemplateResult` an empty `lower_bounds`

[URL]

```
[lower_bounds] => Array
        (
        )
```

Where the non-`namespace`ed version has a non-empty `lower_bounds`:

```
[lower_bounds] => Array
        (
            [T] => Array
                (
                    [fn-execute] => Array
... [Log Snipped] ...
                                        (
                                            [B] => Psalm\Type\Atomic\TNamedObject Object
```

Tests being used:

```
diff

index 7da6b7510..522fd1569 100644
--- a/tests/CallableTest.php
+++ b/tests/CallableTest.php
... [Log Snipped] ...
     }
 }
```
- For namespaced functions when calling `Psalm\Internal\TypeAnalyzer::getCallableFromAtomic` it calls `Psalm\Internal\Codebase\Functions::getStorage` with the function name with the namespace defined in the source code _with_ the prefixed `\` root namespace backslash.

So `\NS\action_d` is used as the `$function_id`, but the function is known as `ns\action_d` in the storage containers.
