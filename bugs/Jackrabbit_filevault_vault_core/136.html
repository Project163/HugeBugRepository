Title

Support multi-value binary properties in FileVault DocView and via .binary files

Description
In contrast to JCR 2.0 DocView which states 
  If P is a BINARY property its value is Base64 encoded. The resulting string becomes the value of the XML attribute P.  
 ( [URL] the binary support in FileVault DocView uses the default conversion from String to UTF-8 byte array encoding for multi-value properties in  [URL]  ( [URL] or only binary references for single values:  [URL]

 This difference is currently not explained in  [URL] and the handling is inconsistent between single- and multi-value. 

 For  .binary  files there is multi-value support during export in  [URL] but no proper support during import  [URL]
Discussion
- tripod  Is FileVault DocView not supposed to support binary properties except via binary references? This is IMHO problematic as I always thought that even JCR 2.0 compliant DocViews would be supported during package import as well... At least  [URL] does not state explicitly that only FileVault DocView is supported...
- I don't think that binary values are serializable inline in DocView. we should clarify that in the documentation.
- Regarding multi-value binary properties: Conceptually this can only work if either all values are binary references (inline in docview) or not binary references (given via  .property  files). A mixture is impossible as DocView only allows one type and the order between DocView values and values from  .property  files would be unspecified. Therefore the export should fail with an exception for such edge case.  tripod  WDYT?
