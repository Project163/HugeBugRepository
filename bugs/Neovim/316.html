Title

bug: `:%s/` can crash Neovim with `lua-language-server` after #13243

Description
### Problem

I'm not too familiar with how to get a stack trace and/or attach a debugger, but the repro should be reliable.

I suspect this has to do with the edge case of updating multiple locations at once. Though I'm not sure what the role of the LSP is (I suppose it's just for creating extmarks and it's probably possible to reproduce without LSP).

I'm using `RelWithDebInfo`.

Bisected #13243 @bfredl 

### Steps to reproduce

1. Checkout [URL]
2. `nvim --noplugin --clean -u minimal.lua runtime/lua/vim/shared.lua`, where `minimal.lua` is:
```
lua
vim.api.nvim_create_autocmd('FileType', {
  pattern = { 'lua' },
  callback = function()
    vim.lsp.start({
... [Log Snipped] ...
  end,
})
```
3. Try to do: `/Node V3j:s/Node/Tree`. Neovim should crash when you type the first letter of "Tree".

### Expected behavior

Whether or not the LSP is proper or malformed, Neovim should handle it gracefully.

Discussion
- I took a look at #13243. In principle, it should be splittable into:
1. Keeping the `MTNode.intersect` field.
2. Queries relying on the `MTNode.intersect` field.
3. Other changes to `marktree` / other things.

My gut feeling is that this bug is caused by 3; I don't see why touching `MTNode.intersect` would need to touch / break the marktree. Whereas #25145 is indeed crashing on the `MTNode.intersect` calcs.

Unfortunately the 1/2/3 split doesn't actually exist. So that makes debugging a bit harder because otherwise one could just try to bisect it to 3.

This might be a use-case for un-squashed (but still curated) merges, although in this case that wouldn't have helped as the feature branch itself was squashed.
