Title

Clearkey key-rotation content's audio playback fails after 6 sec on exoplayer

Description
### Question
I have generated clearkey encrypted DASH content with key-rotation using shaka-packager and hosted it on a media server.
I have configured license server with all keys used for encryption.
Then I added entry for this content in exoplayer's media.exolist.json file as below:
```
{
        "name": "ClearKey_KeyRotation_sample",
        "uri": "[URL]
        "drm_scheme": "clearkey",
        "drm_license_url": "[URL]
        "drm_multi_session": true
 }
```
If only video stream is selected for playback with no audio stream, video plays fully by acquiring all required keys from license server.
But when audio stream is selected along with/without video stream, playback fails after 6 seconds.
When audio stream is selected and played in exoplayer and playback is seeked to any particular timestamp of the content, corresponding key is acquired by exoplayer from license server correctly. But playback immediately fails.

Key rotation dash content:
[Link: key_rotation_sample.zip]

Keys used for content encryption:
KID: 59766957-2e55-547e-656b-56586e2f6f68,	Key:  
KID: 7669572E-5554-7E65-6B56-586E2F6F6859,	Key:  

Additional information:
This content plays on shaka player with both audio and video without any issues.
Discussion
- This issue occurs when there are multiple `sbgp` or `sgbp` boxes in an FMP4 container, and the one we want (`grouping_type == seig`) doesn't come first. We'll fix this. Thanks for reporting!
- This issue is now resolved with latest commit [Link] .
Audio and video both are playing without any issues with key rotation.

Thanks for your valuable and quick support. This issue can be closed now.
