Title

STC permits incorrect void method reference

Description
In a functional pipeline, I mistakenly used  map(service::voidMethod)  (where the map operation expects  Function ). This should have produced a compile-time error but instead produced a runtime error out of the LambdaMetafactory.
Discussion
- [URL]

 A method reference produces a  MethodClosure  under plain STC, which supports reference to  void  method adapted to value-bearing SAM (no runtime error; returns  null ).  For that reason, I put the error check in the SC path.
- I propose that even though in the case of STC/dynamic compilation there exists a chain of implicit transformations that can turn a void method into a  Function , this is virtually always a semantic error—no one feeding something to a  map  or  groupingBy  call expects the method reference to always return null. At a minimum, a warning seems appropriate, and I personally would still expect a compile-time error even if theoretically I can get there from here.
