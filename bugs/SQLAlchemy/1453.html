Title

Duplicate ForeignKeyConstraint generated when using PEP-593 Annotated

Description
**Describe the bug**

When using `Annotated[int, mapped_column(ForeignKey("foo.id"))]` in SQLAlchemy declarative models, `alembic revision --autogenerate` produces two identical `ForeignKeyConstraint`s for the column.

**Expected behavior**

A single `ForeignKeyConstraint` is generated.

**To Reproduce**

In a fresh environment, copy down the [Link: `Annotated` example from the SQLAlchemy docs]:

```
py
from typing_extensions import Annotated
from typing import List
from typing import Optional
from sqlalchemy import ForeignKey
... [Log Snipped] ...
    user_id: Mapped[user_fk]
    user: Mapped["User"] = relationship(back_populates="addresses")
```

Initialize an Alembic environment and wire it up to PostgreSQL and the schema. 

Then run `alembic revision --autogenerate` and inspect the output.

**Error**

```
python
def upgrade_user_db() -> None:
    # ### commands auto generated by Alembic - please adjust! ###
    op.create_table('user_account',
    sa.Column('id', sa.Integer(), nullable=False),
... [Log Snipped] ...
    )
    # ### end Alembic commands ###
```

Note the second `ForeignKeyConstraint` for the `address` table.

If the declaration for the `user_id` column is changed to `user_id: Mapped[int] = mapped_column(ForeignKey("user_account.id"))` only a single `ForeignKeyConstraint` is generated.

If I manually remove the `ForeignKeyConstraint` from the migration and apply it, alembic does not try to re-add the duplicate constraint on future runs of `alembic revision --autogenerate`.

I was able to reproduce this with asyncpg, psycopg2, and sqlite.

**Versions.**
 - OS: Linux
 - Python: 3.11.3
 - Alembic: 1.10.4
 - SQLAlchemy: 2.0.12
 - Database: PostgreSQL
 - DBAPI: asyncpg 0.27 or psycopg2 2.9.6

Thanks for the awesome library and tool. The new declarative models are great. **Have a nice day!**
