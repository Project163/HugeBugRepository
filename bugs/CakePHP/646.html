Title

SecurityComponent does not handle form elements with integer names properly

Description
Hello there,
i noticed that Cake was blackholing my post Requests, when i created a form which had inputs like:

``` php
 Form->input("1", [
 'class' => 'datepicker',
 'data-provide' => 'datepicker',
 'value' => $this->Format->date($milestones[0]['date'])
 ]) ?>
```

The FormHelper treats all fields as strings wheen generating the form hash, while the SecurityComponent does not. Here is one trace of the FormHelper while the Form is being generated:

```
2015-04-15 16:03:33 Debug: 
Cake\View\Helper\FormHelper::secure() - CORE\src\View\Helper\FormHelper.php, line 545
Cake\View\Helper\FormHelper::end() - CORE\src\View\Helper\FormHelper.php, line 516
include - APP/Template\ProjectsMilestones\ajax_edit.ctp, line 62
Cake\View\View::_evaluate() - CORE\src\View\View.php, line 815
... [Log Snipped] ...
    (int) 5 => 'a6'
]
```

The corresponding trace of the SecurityComponent validating the submitted Form is:

```
2015-04-15 15:50:26 Debug: 
Cake\Controller\Component\SecurityComponent::_validatePost() - CORE\src\Controller\Component\SecurityComponent.php, line 318
Cake\Controller\Component\SecurityComponent::startup() - CORE\src\Controller\Component\SecurityComponent.php, line 124
Cake\Event\EventManager::_callListener() - CORE\src\Event\EventManager.php, line 381
Cake\Event\EventManager::dispatch() - CORE\src\Event\EventManager.php, line 351
... [Log Snipped] ...
    (int) 5 => 'a6'
]
```

This causes a mismatch of the security tokens. A quick fix for this is to cast all integer keys of the $fieldList array in the Security Component as strings. E.g

``` php
        $fieldList = array_keys($fields);
        foreach ($fieldList as $i => $key) {
            if ( is_int($key) ){
                $fieldList[$i] = (string)$key;
            }
        }
```

There might be better options, like allowing FormHelper to process integer only fields as integers, but this was the quicker way for me.
