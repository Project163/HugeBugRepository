Title

Resteasy builtin providers being pulled in for more ITs than expected

Description
**Describe the bug**
The following set of ITs seems to be pulling in the resteasy builtin providers (including `org.jboss.resteasy.plugins.providers.IIOImageProvider`) resulting in the native image to depend on graph libraries (like `lcms`, `libawt` etc.)

```
quarkus-integration-test-bouncycastle-1.11.0.Final-runner
quarkus-integration-test-bouncycastle-fips-1.11.0.Final-runner
quarkus-integration-test-bouncycastle-jsse-1.11.0.Final-runner
quarkus-integration-test-infinispan-client-1.11.0.Final-runner
quarkus-integration-test-main-1.11.0.Final-runner
... [Log Snipped] ...
quarkus-integration-test-grpc-interceptors-1.11.0.Final-runner
quarkus-integration-test-grpc-proto-v2-1.11.0.Final-runner
```

**Expected behavior**
Most (if not all) of these tests shouldn't depend on graph libraries.

**Actual behavior**
The tests depend on graph libraries.

**To Reproduce**

Fast, but not exactly a reproducer:
```
wget [URL]
tar xf 1.11.0.Final.tar.gz
cd quarkus-1.11.0.Final
# Set a breakpoint at
# [URL]
./mvnDebug clean verify -pl integration-tests/bouncycastle
# Attach debugger and run, if the breakpoint is hit and the value of `useBuiltinProviders` is `true`
# then all providers in `availableProviders` get pulled in
```

Slow, but the actual reproducer:
```
wget [URL]
tar xf 1.11.0.Final.tar.gz
cd quarkus-1.11.0.Final
./mvnw clean verify \
    -Dnative -Dquarkus.native.additional-build-args="-H:+TraceNativeToolUsage" \
    -pl integration-tests/bouncycastle
# look for `liblcms.a` in the linker command
```
