Title

Warn when unable to save (malformed) HTTP message in Request/Response panels

Description
Issue reported in OWASP ZAP User Group: [URL]

Steps to reproduce the issue:
1. Run ZAP;
2. Send a well-formed request through the Manual Request Editor dialogue:
```
GET [URL] HTTP/1.1
Host: example.org
```
Note in the History tab that the GET request was sent;
3. Send a malformed request:
```
POST[URL] HTTP/1.1
Host: example.org
```
and note that the actual request sent (History tab) was again a GET.
In the log there's a warning:
```
[AWT-EventQueue-0] WARN org.zaproxy.zap.extension.httppanel.view.impl.models.http.request.RequestHeaderStringHttpPanelViewModel  - Could not Save Header: POST[URL] HTTP/1.1
Content-Length: 0
Host: example.org


... [Log Snipped] ...
	at org.zaproxy.zap.extension.httppanel.HttpPanel.saveData(HttpPanel.java:333)
	at org.parosproxy.paros.extension.manualrequest.ManualRequestEditorDialog$2.actionPerformed(ManualRequestEditorDialog.java:177)
```

Remarks:
ZAP should warn (UI message) and fail to send the message instead of sending another (different) one.

ZAP
Version 2.7.0 (and older).
