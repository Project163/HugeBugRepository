Title

Quarkus Jib fails if username contains a space although it is not even used

Description
**Describe the bug**
When adding the jib extension to a freshly created quarkus project (generated with code.quarkus.io), `gradlew assemble` fails with 

```
FAILURE: Build failed with an exception.

* What went wrong:
Execution failed for task ':quarkusBuild'.
... [Log Snipped] ...
        at java.base/java.lang.Thread.run(Thread.java:834)
        at org.jboss.threads.JBossThread.run(JBossThread.java:479)
```

It seems the jib dependency uses my username (Windows user, hence with a space in the name), as the group for the image as default value. One improvement would be if you replace spaces with a `-` to prevent such issues. 

However, the more important part is that I haven't enabled jib building. I only run `gradlew assemble`. You have to enable `quarkus.container-image.build` or `quarkus.container-image.push` to trigger the jib building. Still the normal `gradlew assemble` fails.

Workaround: Set a value for `quarkus.container-image.group` in `application.properties`. (Normally this property is set by my CI pipeline, when it creates the images, that's why I normally do not have it specified in the `application.properties`.)
[Link: 2020-12-02-jib-no-defaults-error-with-space-username.zip]



**Expected behavior**
Normal `gradlew assemble` works.

**Actual behavior**
It fails although jib is not activated. 


**To Reproduce**

Steps to reproduce the behavior:
1. Download and unzip 
[Link: 2020-12-02-jib-no-defaults-error-with-space-username.zip]
2. run `gradlew assemble` if you have a username with a space or set `quarkus.container-image.group=a b` in the `application.properties` file first.
