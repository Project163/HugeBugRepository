### Describe the Bug

When you make a fetch from an app directory page, the response does not have a URL property.

This causes libraries like `oauth4webapi`, to throw `Invalid URL` errors when they [Link: process fetch responses].

If you force the fetch not to cache, using `cache: no-store` the response has a URL - so it's probably an issue with [URL]

### Expected Behavior

The response from `fetch` should always have a `url` property equal to the final URL obtained after any redirects. [URL]
