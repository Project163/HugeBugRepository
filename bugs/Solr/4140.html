Title

 Thanks for the patch! 

 I'm curious about the 10 minute latch countdown timeout. Shouldn't we wait forever here?  

 So here we're doing something different wrt success and failure . If the add replica call has a failure we're adding it back to the main response but if it's a success then we will end up skipping it ( at this point results.get("success") will always be null ) .   
  
 
ocmh.addReplica(clusterState,  new  ZkNodeProps(propMap), addResult, ()-> {
  countDownLatch.countDown();
   Object  addResultFailure = addResult.get( "failure" );
   if  (addResultFailure !=  null ) {
    SimpleOrderedMap failure = (SimpleOrderedMap) results.get( "failure" );
     if  (failure ==  null ) {
      failure =  new  SimpleOrderedMap();
      results.add( "failure" , failure);
    }
    failure.addAll((NamedList) addResultFailure);
  }  else  {
    SimpleOrderedMap success = (SimpleOrderedMap) results.get( "success" );
     if  (success ==  null ) {
      success =  new  SimpleOrderedMap();
      results.add( "success" , success);
    }
    success.addAll((NamedList) addResult.get( "success" ));
  }
}); 
  
 Can't we do this instead which will append the results directly to the main object? We do this for the remaining add replicas as the last step of the restore 
  
 
ocmh.addReplica(clusterState,  new  ZkNodeProps(propMap), results, ()-> {
  countDownLatch.countDown();
});

   SOLR-12708  : CREATE collection request doesn't fail or cleanup when the request fails (#568) 

 When performing an async CREATE requests, responses to internal requests are also included inside the "success" or "failed" elements of the general response. This will make the operation cleanup in case of failure, the same way as we do when the request is synchronous.
