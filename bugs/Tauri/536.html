Title

[bug] Unmanaged state panics if invoked

Description
### Describe the bug

In dev environments, if the frontend calls a Tauri command that uses `State ` in its parameters and does so before `tauri::Manager::manage` gets called to manage the state, then the application will panic.

My frontend needs to perform some utility methods such as writing and reading from files as soon as it can. On many occasions, the frontend starts before the backend can fully catch up.

### Reproduction

Tell the app to manage some state asynchronously:
```
rust 
let some_state = SomeState::new();
...
.setup(|app| {
    let app_handle = app.handle().clone();
... [Log Snipped] ...
    Ok(())
})
```

Make a function that uses that state:
```rust
#[tauri::command]
async fn some_command(state: State ) -> Result 
```

Call the command as soon as possible in the frontend. In my case, I am using Angular and thus do so in my `app.component.ts`'s OnInit:
```typescript
async ngOnInit() {
   await invoke ("some_command").catch(err => {console.log(err)});
}
```
In a dev environment, as long as the frontend started first, the app should panic.

### Expected behavior

Ideally, functions that return a `Result` should capture the error rather than panicking the whole program, or the user should be able to wrap the state in an `Option` in the parameters, such as:
 `async fn some_command(state: Option >) -> Result `
and have the function deal with scenarios where the state was not managed yet.
