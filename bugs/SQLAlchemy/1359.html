Title

annotations dictionary caching does not re-use anon_map, can cause memory explosion

Description
it's hard to demonstrate this but we have a user case that has a cache key that can't be printed or even dumped to a file; the file hits 200G or so and I just break the program.  with the fix, the file goes to 2 M.

annotations dictionaries that point to `AliasedInsp` will re-cache-key the entire contents of `AliasedInsp` over and over again because we don't transfer anon map.

this demo shows a large cache key

```
py
from sqlalchemy import Column
from sqlalchemy import Integer
from sqlalchemy import select
from sqlalchemy import String
... [Log Snipped] ...

print(count_tuples(ck))
```

the output is 778 tuples.   with the fix:

```
diff
diff --git a/lib/sqlalchemy/sql/annotation.py b/lib/sqlalchemy/sql/annotation.py
index 262048bd1d..eda34c39be 100644
--- a/lib/sqlalchemy/sql/annotation.py
+++ b/lib/sqlalchemy/sql/annotation.py
... [Log Snipped] ...
                         meth is InternalTraversal.dp_clauseelement_list
                         or meth is InternalTraversal.dp_clauseelement_tuple
```

it becomes 170.
