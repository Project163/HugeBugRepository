Title

Correct URL is not configured if Undertow context-path is configured

Description
**Describe the bug**
If the property "quarkus.servlet.context-path" is different than "/" Rest Assured integration is unable to configure correctly the test-cases so everything end with a 404

**Expected behavior**
The documented [Link: integration with rest-assured] must account for the different context-path

**Actual behavior**
Not used


**To Reproduce**
Steps to reproduce the behavior:
1.  Create a JAX-RS resource and the quarkus.servlet.context-path
2. Call it from a test with rest-assured
3. 404 is returned

**Configuration**
```properties
quarkus.servlet.context-path=/something
```
**Environment (please complete the following information):**
 - Output of `uname -a` or `ver`: Darwin WMICTLM1P 18.7.0 Darwin Kernel Version 18.7.0: Thu Jun 20 18:42:21 PDT 2019; root:xnu-4903.270.47~4/RELEASE_X86_64 x86_64

 - Output of `java -version`: OpenJDK 64-Bit GraalVM CE 19.0.2 (build 25.212-b03-jvmci-19-b04, mixed mode)
 - Quarkus version or git rev: 0.21.1
Discussion
- As a workaround you can configure a test profile for the context path:

```properties
%test.quarkus.servlet.context-path=/
```
