Title

Regression: dict | None or dict fallback breaks type inference for nested dicts after PR #19249

Description
**Bug Report**

 

After upgrading mypy past [Link: PR #19249], we observed new errors related to dictionary fallback using or expressions when value types are unions of nested dicts and optional types.

This appears to be a regression in type inference, as the same code passed in previous versions of mypy.

**To Reproduce**
```
python 
from typing import Union, Optional, Any

P = dict[str, Union[Optional[str], dict[str, Optional[str]]]]

... [Log Snipped] ...
def g(x: dict[str, Any] | None, s: str | None) -> None:
    f(x or {'x': s})  # ❌ Error in master branch, passes in latest mypy release (1.17.0)
```

mypy playground Gist: [URL]

**Actual Behavior**

 

```
main.py:9: error: Argument 1 to "f" has incompatible type "dict[str, Any] | dict[str, str | None]"; expected "dict[str, str | dict[str, str | None] | None]"  [arg-type]
Found 1 error in 1 file (checked 1 source file)
```

Discussion
- Thanks for bisecting!

This only used to work because of `Any`, `{'x': s}` was inferred as `dict[str, Any]` to match the LHS (so not an inference regression, strictly speaking, but still somewhat annoying).
- OK, the context is applied correctly. The problem is that we're failing to apply our "ignore trivial (only `Any`) constraints when or-ing them" fallback when constraints for multiple targets coexist.

We're trying to `or` the following constraints:

```
[
    [1   builtins.str, 2   Any], 
    None, 
    [1   builtins.str, 2   builtins.str | None | builtins.dict[builtins.str, builtins.str | None]],
]
```

`None` is ignored. We can `or` subsets of those constraints for every variable, but can't `or` whole groups.
