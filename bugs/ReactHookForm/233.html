Title

V7 field array setError crashes with TypeError: Cannot read property 'ref' of undefined

Description
**Describe the bug**
In V7 I tried to validate the minimum length of an array based on the yup minimal array length example from [Link: here]. Except I tried to do it without yup in V7 and only after `submitCount > 0` (just imitating the behavior of  `mode: 'onSubmit'` and `reValidateMode: 'onChange'`). 

When I want to set an error after `submitCount > 0` then you get the following error: `TypeError: Cannot read property 'ref' of undefined`. 


**To Reproduce**
1. Go to [URL]
2. Click on `Add Question`
3. Click on `Submit` (Also I am not sure why the `errors` attribute stays empty on the first submit.)
4. Click on `Remove question`
5. See the error

**Expected behavior**
The `errors` attribute of `useForm` should have an error after submit, and it should not crash when you remove the question after first submit.

**Desktop:**
- OS: Windows
- Browser: Chrome
- Version: 89

**Additional context**
I guess it might have something to do that the actual array name of `questions` isn't registered anywhere in an input.
See also the code where it goes wrong: [URL]

After investigation the `get(fieldsRef.current, name)`  returns an empty array (`[]`), so it wants to look for an `_f` input in there, which there isn't.

Besides, I am still not sure why the `errors` attribute stays empty.

**Edit 2:**
It works fine if I use an other name for `setError`/ `clearErrors`. I guess that is also preferred, otherwise you would also clean also all the inner errors of the array, which might not be something that you would want.  Nevertheless then you would have issues with the TypeScript template support, as it would not make that much sense to add it to `TFieldValues`. It is a bit ugly to add it, but is solvable if you use something like `questionsArrayError: unkown`. 

So in the end this is a great workaround but it is not that convenient, and should be at least documented I guess.
