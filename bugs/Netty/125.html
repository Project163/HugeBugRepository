Title

HttpContentEncoder is broken

Description
When decoding multiple messages, if no encoder is selected, finishEncode() is never called so encodeStarted is not sent to false. This causes the encoder to only enter the HttpContent handling loop once, trapping all subsequent HttpResponses inside the codec.
