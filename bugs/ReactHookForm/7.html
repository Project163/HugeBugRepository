Title

reset() cannot be used in Effect Hooks

Description
**Describe the bug**
To preface, this may be intentional behaviour although if it is, I don't see mention of it anywhere in the docs.

I've written a form which populates its fields using the props passed to the component. Naturally, these props can change following user interaction. I would hope to be able to easily reinitialise the form values based on the new props passed to the form component.

To begin, inputs should be uncontrolled and therefore take the `defaultValue` attribute, like so.

```
 
```

Then, to reset the form when the `name` prop changes, I do the following.

```
const { register, handleSubmit, reset } = useForm();

useEffect(() => {
  reset();
}, [name]);
```

This works but it violates the `react-hooks/exhaustive-deps` eslint rule since `reset` is considered a missing dependency. However, adding `reset` as a dependency creates an infinite loop whereby:

1. `name` is changed therefore the effect is triggered
2. The effect calls `reset` which changes the `useForm()` methods, including `reset` itself
3. `reset` is changed therefore the effect is triggered

As per [Link: the Hooks documentation], it is generally _not_ safe to omit functions from the list of dependencies and "the recommended fix is to move that function inside of your effect". In this case, this isn't possible either. `reset` is returned by a hook, which cannot be called inside a callback.

In summary:
1. `reset` cannot be defined within an Effect Hook
2. if `reset` is defined outside of an Effect Hook then called within it:
  a. an infinite loop is created if `reset` is declared as a dependency
  b. the `exhaustive-deps` rule is violated if it is not declared as a dependency

I'm not sure if there's an alternative option that I'm not seeing here.
