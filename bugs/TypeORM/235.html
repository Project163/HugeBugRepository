Discussion
- We are also affected by this. Apparently it has to do with the `toString` being defined on every object in javascript by default.  We observed, that if you remove the evaluation of `Function` in `FindOptionsWhereProperty` the error will not occur. 

[URL]

Of course that's just a partial solution, merely a hint in the right direction. Because with the evaluation missing one could pass in methods as keys for the `findBy` methods.
- I stumbled upon this exact same issue too. Having `toString()` methods leads to type errors. Removing `Function` evaluation in the `FindOptionsWhereProperty` indeed can serve as short-term solution, but then we are out of some portion of type-safety there - we can pass methods' names as search conditions.
Quick reproduction repo for anyone interested:
[URL]
- [URL] seems to have fixed this.

HOWEVER
it seems that the same issue is still existing for FindOptionsOrder.
Can someone confirm? For example

```ts
// assuming UserEntity has a toString method...

usersRepo.find({
	where:{roleId:4}, // will not error in latest typeOrm release
	order:{'id':'ASC'} // will still error
})
```
Error detail:
```
Type '{ id: "ASC"; }' is not assignable to type 'FindOptionsOrder '.
  Types of property 'toString' are incompatible.
    Type '() => string' is not assignable to type 'never'
```
- Just stumbled on this too. The error with FindOptionsOrder also occurs whenever there's any kind of method on the entity, it seems. The workaround for me is to explicitly cast the type you are passing in FindOptionsOrder , so in your example:

```
usersRepo.find({
	where:{roleId:4},
	order:{'id':'ASC'} as FindOptionsOrder  
})
```
