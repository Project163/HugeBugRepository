Title

== operator inconsistent with Object#equals

Description
class MyClass { 
       boolean equals(MyClass o)  
{   # change to Object o, it works
               return true
       }
 } 

 o = new MyClass() 
o2 = new MyClass() 

 println o.equals(o2) 
println o2.equals(o) 
println o == o2
Discussion
- A related problem is that == cannot be intercepted. 

 The reason for the described behavior is that == isn't handled by the Groovy runtime but results in a direct call to equals(java.lang.Object). Although this improves performance, consistency  (here I'd even say correctness) of the language should come first. Otherwise it's simply not safe to use ==. 

 In case it is nevertheless decided to leave the behavior as-is, selectively overriding and intercepting equals() should at least be strongly discouraged. (GINA p.198 encourages selective overriding). 

 Side comment: "Object#equals" in the issue title is a bit misleading and should probably be changed to "equals".
