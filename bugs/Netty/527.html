- Norman, what if the thread of SingleThreadEventExecutor is unexpectedly blocked/long calculates somewhere? So all producers might continue to aggressively fill its queue, which ultimately can cause OOME, but the thread is not available to answer the queue size. So even different thread which called Nio/EpollEventLoop.pendingTasks will have to syncUninterruptibly without being able to report the size of the queue, possibly for long time. When the consumer thread answers the size - it might already be after it consumed most of the queue, so we missed the size at the time we asked for it.
I know size doesn't have to be accurate for such a queue, but I think it is important for analysis purpose that the thread which asks the size will be independent of the thread which consumes the queue. We need to know the size especially if the consumer is blocked somewhere and producers continue to fill its queue. Don't want to wait and depend on the consumer in such case.

Except the OOME, similar behavior to what I described actually happened to us, while we tested new statistic for this queue.

Did you consider using LongAdder for maintaining the size? It maybe could be used inside the queue.
