   PDFBOX-3714  : enlarge the backwards search area for the brute force search for XRef streams, don't overwrite stream objects with outdated objects after a brute force search
- One possible improvement for these repair routines: 

 If the parser finds some trash bytes at the beginning of a PDF, it could try and store the count of them; then, instead of brute-forcing, it could simply try and subtract this number from any offset; only if that fails, brute-forcing remains as a fall-back. 

 In my experience such leading trash bytes are the most common cause for wrong offsets, and this offset correction would require far less resources than bf.
