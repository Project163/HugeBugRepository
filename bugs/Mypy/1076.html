Title

Invalid assignment target when setting function to compatible function type

Description
Code like the following gives an error:

```
def bar() -> None: pass

if 1:
    def foo() -> None: pass
else:
    foo = bar
```

```
foo.py:6: error: Invalid assignment target
```

even though replacing `foo = bar` with another `def foo()` would work fine.  This seems related to #708 but distinct.
Discussion
- Eh, it's all part of the same fundamental design flaw, I'd call it a dupe.

Remember that mypy follows _both_ branches of the if statement, in the order they occur.

Though even with all my consideration, I am not entirely sure what ought to be done for descriptors in general.
- Well, in this case the error happens in semanal, and blocks any other type checking for the file.  So it's clearly distinct, and more annoying when it happens.

I don't see the issue with mypy following both branches, in order.  The assignments are compatible.  Why shouldn't mypy treat this the same way it treats the following?

```
if 1:
    def foo() -> None: pass
else:
    def foo() -> None: pass
```

- An interesting case from the standard library is `encodings.utf_8.IncrementalDecoder._buffer_decode`.

In this case, a base class's abstract method is overwritten by a non-descriptor callable (we really need a way to be able to specify those).
- Closing as this works under 0.510 and master.
