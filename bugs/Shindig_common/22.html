Title

JsonRpcServlet should set content type to json in all cases, including gets and error cases.

Description
Currently, the JsonRpcServlet only sets the content type in the case of a properly formed post request. It should also do it in the sendError case, and in the GET request method case.
Discussion
- Wondering how people would feel about returning application/javascript instead of application/json? 

 I've rarely seen application/json used, probably because debugging is very difficult with application/json as most browsers treat the content as a binary file and try to download it. 

 Application/javascript will also work with JSONP when we enable it.
- there's a lot of live sites who use application/json, patching this in shindig trunk isn't going to change that reality and having different (non-spec-defined) content-types set would only lead to confusion in my opinion
