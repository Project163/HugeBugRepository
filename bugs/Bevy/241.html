Title

Change detection for keyboard input is not working correctly.

Description
## Bevy version

0.7

## What you did

As discussed in [URL] there is a simple system querying current keyboard input, code as below.

```rust
fn keyboard(keyboard: Res >) {
    if !keyboard.is_changed() {
        return;
    }

    info!("activated");
}
```

## What went wrong

The system should print "activated" only when there are keyboard input changes. Currently the system is activated no matter if there are new keyboard event. It might be some internal system greedily updating `Input `.
Discussion
- With the code as written above, this seems like intended behavior. But it seems like a real issue is being described.

I would expect a system like this to only print "activated" when there are keyboard input changes, but this currently happens on every frame.

```rs
fn keyboard(keyboard: Res >) {
    if !keyboard.is_changed() {
        return;
    }

    info!("activated");
}
``` 

This seems like a reasonable thing to want to do for e.g. a "Press any key" screen.
- "Press any key" would probably be better accomplished like this though:

```rs
fn keyboard(keyboard: Res >) {
    if keyboard.get_just_pressed().next().is_none() {
        return;
    }

    info!("activated");
}
```
