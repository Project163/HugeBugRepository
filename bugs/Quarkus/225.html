Title

Memory usage increase with the new network stack

Description
When deploying the `getting-started` application in OpenShift, I have seen that the new network stack version required 24Mb or memory instead of 12Mb to serve the requests.  With 12Mb, `OutOfMemory` exception are thrown.

**How to reproduce it**

1. You need an OpenShift cluster somewhere (I used crc), and `oc` connected to it.
2. Create a new project with `oc new-project some-quarkus-test`
3. Creates a build config with:
```
oc new-build --name=my-application \
  --binary=true \
  --docker-image=quay.io/quarkus/ubi-quarkus-native-binary-s2i:19.2.0
```
4. Go to the quickstarts, start with the `master` branch, build the native image (generate a linux64 executable with `mvn clean install -Pnative -Dnative-image.docker-build=true`)
5. Creates a `target/.s2i/environment` file with:
```
QUARKUS_OPTS=-Xmx12M -Xms8M -Xmn12M
```
6. Deploy the application with:
```
oc start-build my-application --from-dir target
oc new-app -i my-application
oc expose svc/my-application
```
7. Test the application, it should work

Now, switch to the `development` branch, and rebuild the application:
`mvn install -Pnative -Dnative-image.docker-build=true` (don't clean)

8. Redeploy the application with:
```
oc start-build my-application --from-dir target
```

Test the application, it will fail.

If you edit the `QUARKUS_OPTS` application to `QUARKUS_OPTS=-Xmx24M -Xms16M -Xmn24M` and restart the build, it works.
