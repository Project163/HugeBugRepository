Title

FatalErrorException render loop

Description
There is a loop whenever Cake 2.6 has to render a fatal error (like calling a non-existent method on a PHP object). The fatal error rendering triggers another fatal error until memory is exhausted. I rolled back to 2.5.8 and this issue disappeared.

Sample log:

```
2015-01-07 09:55:38 Error: Fatal Error (256): [CakeException] Headers already sent in /home/leandro/htdocs/visitor/app/Controller/UsersController.php on line 37
#0 /home/leandro/htdocs/visitor/lib/Cake/Network/CakeResponse.php(419): CakeResponse->_sendHeader('HTTP/1.1 500 In...')
#1 /home/leandro/htdocs/visitor/lib/Cake/Error/ExceptionRenderer.php(327): CakeResponse->send()
#2 /home/leandro/htdocs/visitor/lib/Cake/Error/ExceptionRenderer.php(306): ExceptionRenderer->_outputMessageSafe('error500')
#3 /home/leandro/htdocs/visitor/lib/Cake/Error/ExceptionRenderer.php(210): ExceptionRenderer->_outputMessage('fatalError')
... [Log Snipped] ...
#133 [internal function]: App::shutdown()
#134 {main} in [/home/leandro/htdocs/visitor/lib/Cake/Error/ErrorHandler.php, line 128]
```
Discussion
- Yes, this happened to me with an outdated MediaView as well.
The issue is that you are already sending headers in your code prior to the rendering, and an error page would also run into the same issue again, running into a loop.

The solution would be to have this header check only for `$this->Controller->name !== 'CakeError'` (not Error Controller) IMO.
