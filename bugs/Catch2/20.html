Title

Stringify boost::filesystem::path creates infinite recursion

Description
## Description
When trying to stringify a `boost::filesystem::path`, Catch crashes with an infinite recursion:
```
    #244   in Catch::StringMaker ::convert(boost::filesystem::path const&) catch.hpp:1074
    #245   in std::__1::basic_string , std::__1::allocator  > Catch::Detail::stringify (boost::filesystem::path const&) catch.hpp:772
    #246   in std::__1::basic_string , std::__1::allocator  > Catch::Detail::rangeToString (boost::filesystem::path::iterator, boost::filesystem::path::iterator) catch.hpp:927
    #247   in std::__1::basic_string , std::__1::allocator  > Catch::rangeToString (boost::filesystem::path const&) catch.hpp:1051
    #248   in Catch::StringMaker ::convert(boost::filesystem::path const&) catch.hpp:1074
    #249   in std::__1::basic_string , std::__1::allocator  > Catch::Detail::stringify (boost::filesystem::path const&) catch.hpp:772
    #250   in std::__1::basic_string , std::__1::allocator  > Catch::Detail::rangeToString (boost::filesystem::path::iterator, boost::filesystem::path::iterator) catch.hpp:927
    #251   in std::__1::basic_string , std::__1::allocator  > Catch::rangeToString (boost::filesystem::path const&) catch.hpp:1051
```
The reason is the way iterators for this type works.

### Steps to reproduce
Here is a minimal example:
```
cpp
#include  
#define CATCH_CONFIG_RUNNER
#include  

... [Log Snipped] ...
  return (result  
    struct StringMaker ::value && !::Catch::Detail::IsStreamInsertable ::value>::type> {
        static std::string convert( R const& range ) {
            return rangeToString( range );
        }
    };
```
This removes the special case for string ranges and fixes this bug as well.
