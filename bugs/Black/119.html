Title

Black is not idempotent with comment over line length

Description
**Describe the bug**

I have an example where black seems to be not idempotent on a python file, even with `--safe` on.

**To Reproduce**

 

For example, take this code:

```python
class A:
    def foo(self):
        for _ in range(10):
              = bbbbbbbbbbbbbbb.cccccccccc(  # pylint: disable=no-member
                xxxxxxxxxxxx
            )
```

And run it with these arguments:

```sh
$ black file.py
```

`black` finishes successfully, and the file is reformatted to:

```python
class A:
    def foo(self):
        for _ in range(10):
              = (
                bbbbbbbbbbbbbbb.cccccccccc(xxxxxxxxxxxx)  # pylint: disable=no-member
            )
```

Running black again with:

```sh
$ touch file.py
$ black file.py
```

and the file is reformatted again to:

```python
class A:
    def foo(self):
        for _ in range(10):
              = bbbbbbbbbbbbbbb.cccccccccc(
                xxxxxxxxxxxx
            )  # pylint: disable=no-member
```

**Expected behavior**

 

The file is reformatted once to match the reformatted version 1 above, and not changed again.  Not tied to that particular formatting, but it is also important that there is some stable source file with the `pylint: disable` comment on the same line as `bbbbbbbbbbbbbbb.cccccccccc`.

**Environment**

 

- Black's version: Tested on latest from pypi `21.12b0`, and latest from github `21.12b1.dev29+ge64949e`
- OS and Python version: Linux, Python3.10
