Title

Unable to produce multiple synthetic beans of same type having different identifiers

Description
### Describe the bug

I am producing multiple synthetic beans of same type without qualifier.
I am using the identifier to distinct them.

```
java
@BuildStep
    @Record(ExecutionTime.STATIC_INIT)
    List  registerJdbcLockProviderInitializer(
            final ApplicationIndexBuildItem applicationIndexBuildItem,
... [Log Snipped] ...
        return list;
    }
```

When running my integration test on **integration-tests** / **jdbc** it fails - while two synthetic beans are produced having **\ ** and **master** identifier - about already registered bean with same identifier.

```
[ERROR] Errors: 
[ERROR]   SchedulerLockResourceTest.testShedlockEndpoint » Runtime java.lang.RuntimeException: io.quarkus.builder.BuildException: Build failure: Build failed due to errors
        [error]: Build step io.quarkus.arc.deployment.SyntheticBeansProcessor#initStatic threw an exception: java.lang.IllegalStateException: A synthetic bean with identifier ouqbYaizsnxlxh2wrovrwNxvSIQ is already registered: SYNTHETIC bean [types=[io.quarkiverse.shedlock.providers.jdbc.runtime.DataSourceName, java.lang.Object], qualifiers=[@Default, @Any], target=n/a]
        at io.quarkus.arc.processor.BeanDeployment.addSyntheticBean(BeanDeployment.java:1472)
```



### Expected behavior

Two Synthetic beans should be produced and injected inside **JdbcLockProviderInitializer**

Discussion
- Indeed, there is a bug in the `BeanConfiguratorBase.read(BeanConfiguratorBase )` method - the `identifier` is not copied from the original configurator. This method is used when processing `SyntheticBeanBuildItem`s.

A workaround is to use the `BeanRegistrationPhaseBuildItem` directly in the build step, i.e. `beanRegistration.getContext().configure(...)`.
