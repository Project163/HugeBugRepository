Title

Native tests fail when quarkus.package.type=uber-jar

Description
**Describe the bug**
Using a brand new project, adding the property `quarkus.package.type=uber-jar` to the `application.properties` so to create an uber jar, the native tests fail to start the native image for an IOException. 

```
[INFO] Running org.acme.getting.started.NativeGreetingResourceIT
Executing [/home/jrota/vagrant/bionic64/issues-reproducers/uber-jar-native-tests-fail/target/uber-jar-native-tests-fail-1.0.0-SNAPSHOT-runner, -Dquarkus.http.port=8081, -Dquarkus.http.ssl-port=8444, -Dtest.url=[URL] -Dquarkus.log.file.path=target/target/quarkus.log]
[ERROR] Tests run: 1, Failures: 0, Errors: 1, Skipped: 0, Time elapsed: 0.112 s  
         native 
 
```
is somehow ignored and the native tests try to use the uber jar as well? 

**To Reproduce**
```
mvn io.quarkus:quarkus-maven-plugin:1.10.5.Final:create \
    -DprojectGroupId=org.acme \
    -DprojectArtifactId=uber-jar-native-tests-fail \
    -DclassName="org.acme.getting.started.GreetingResource" \
    -Dpath="/hello"
cd uber-jar-native-tests-fail
mvn clean verify <- no native tests are executed, ok
mvn clean verify -Pnative <- native tests are executed, ok
```
Add `quarkus.package.type=uber-jar` to `application.properties` and then 
```
mvn clean verify -Pnative <- crash
```
See the exception above
