Title

Calling super in an overridden method results in MissingMethodException when method indirectly inherited from trait

Description
Consider the following: 

  
 
 trait  A {
    void doSomething() {
        println  "A" 
    }
}

 trait  B  extends  A {}

 class  C  implements  B {
    @Override
    void doSomething() {
        B. super .doSomething()
    }

    static void main( String [] args) {
         new  C().doSomething()
    }
}
 
  
 Although this compiles fine, a MissingMethodException is thrown at runtime:

Discussion
- An ugly workaround is to replace the B.super.doSomething() call with: 
  
 
 Class .forName(A.name +  '$Trait$Helper' ).getMethod( "doSomething" , A).invoke(A,  this )
- "A.super.doSomething()" would succeed if the checks in ResolveVisitor did not reject "A" due to indirect implements.  For "B.super.doSomething()" to succeed, a change is required in SuperCallTraitTransformer where it produces "B$Trait$Helper.doSomething(this)" or in the production of the B$Trait$Helper class.
