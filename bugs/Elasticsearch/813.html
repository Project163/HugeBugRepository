Title

JSON object properties are not positional

Description
Hiya

It looks like you are parsing JSON as a stream, where position matters, instead of parsing the whole objects before analysing them.  For instance, this works:

```
curl -XGET '[URL]  -d '
{ query: 
    {
       "filteredQuery" : {
          "query" : {
... [Log Snipped] ...
}
'
```

But this fails:
    curl -XGET '[URL]  -d '
    { query: 
        {
           "filteredQuery" : {
              "filter" : {
                 "range" : {
                    "num" : {
                       "to" : 20,
                       "from" : 10
                    }
                 }
              },
              "query" : {
                 "term" : {
                    "text" : "foo"
                 }
              }
           }
       }
    }
    '

A JSON parser should consider these two structures to be identical, which is also the thing that rules out having non-unique property names.

thanks

Clint

## Triage Summary: Issue #27 — JSON object properties are not positional

### Overview

This issue reports that Elasticsearch's JSON parser treats object properties as positional (order-dependent), which violates the JSON specification. The reporter demonstrates that a `filteredQuery` works when `query` appears before `filter`, but fails when the order is reversed. According to JSON standards, these two structures should be semantically identical.
