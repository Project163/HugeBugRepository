Title

Component templates are considered invalid without timestamp_field

Description
**Elasticsearch version** (`bin/elasticsearch --version`):
8.0.0 snapshot
[URL]


OS version (uname -a if on a Unix-like system):
macOS

**Description of the problem including expected versus actual behavior**:
If a template uses a component template to be built, it will be rejected by ES if the component template does not have the `timestamp_field` even if the `_index_template` API request contains the necessary field.


**Steps to reproduce**:

```
POST _component_template/metrics-endpoint.metadata-mappings
{
  "template": {
    "mappings": {
      "dynamic": true
... [Log Snipped] ...
  ]
}
```
This will fail with the following error:

```
{
  "error" : {
    "root_cause" : [
      {
        "type" : "illegal_argument_exception",
... [Log Snipped] ...
  "status" : 400
}
```

If we use this component template instead the request will succeed:

```
POST _component_template/metrics-endpoint.metadata-mappings
{
  "template": {
    "mappings": {
      "dynamic": false,
... [Log Snipped] ...
  }
}
```

There are going to be a two changes:
* The timestamp field for a data stream is going to be fixed to be '@timestamp', until we figure out what would be the best way to make this field configurable (or at least make sure that the timestamp itself can be provided via another field).
* If no field mapping is going to be provided for the '@timestamp' field then a default mapping should be applied. This is what #58642 is doing. Since #58642 is doing more than that, I will extract that particular piece of the pr and open a new pr, once the first change has been merged.

for the final mappings.
