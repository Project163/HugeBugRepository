Title

[DocDB] Incorrect profile counters in prof_gen build

Description
Jira Link: [Link: DB-4308]
### Description

Currently we build prof_gen in `lto=full` mode to get counters from functions from all linked dso's.
And we see that inlined functions are countered as many times as the number of object files where they are inlined into.

To illustrate it, here my_sum is an inline function and is called 2 times - once from bar and once from foo:
```
$ cat foo.cpp
#include "inline.h"

int foo(int n, int m) {
  return my_sum(n, m);
... [Log Snipped] ...
  return a + b;
}
```

If we compile with `-flto=full` then my_sum will have the counter 4, not 2 as it should be.

```
$ clang++ foo.cpp -c -O3 -g -flto=full -fprofile-instr-generate -stdlib=libc++ -o foo.cpp.o
$ file foo.cpp.o
foo.cpp.o: LLVM IR bitcode
$ clang++ bar.cpp -c -O3 -g -flto=full -fprofile-instr-generate -stdlib=libc++ -o bar.cpp.o
$ clang++ foo.cpp.o bar.cpp.o -O3 -g -flto=full -fprofile-instr-generate -o lto_a.out -fuse-ld=lld -fwhole-program -stdlib=libc++ 
... [Log Snipped] ...
Maximum function count: 4
Maximum internal block count: 0
```

To fix this we need to build prof_gen in whole program mode but without lto. Then everything is counted the right way.

```
$ clang++ foo.cpp -c -O3 -g -fprofile-instr-generate -stdlib=libc++ -o foo.cpp.o
$ file foo.cpp.o
foo.cpp.o: ELF 64-bit LSB relocatable, x86-64, version 1 (GNU/Linux), with debug_info, not stripped
$ clang++ bar.cpp -c -O3 -g -fprofile-instr-generate -stdlib=libc++ -o bar.cpp.o
$ clang++ foo.cpp.o bar.cpp.o -O3 -g -fprofile-instr-generate -o lto_a.out -fuse-ld=lld -fwhole-program -stdlib=libc++ 
... [Log Snipped] ...
Maximum function count: 2
Maximum internal block count: 0
```
Discussion
- This issue is fixed in the latest llvm's main:
```
$ clang++ --version
clang version 16.0.0 (https://github.com/llvm/llvm-project.git  )
Target: x86_64-unknown-linux-gnu
Thread model: posix
$ clang++ foo.cpp -c -O3 -g -flto=full -fprofile-instr-generate  -o foo.cpp.o
... [Log Snipped] ...
Maximum function count: 2
Maximum internal block count: 0
```
15.0.7 version still has this issue.
