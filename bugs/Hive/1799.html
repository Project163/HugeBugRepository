Title

Alias conflict when merging multiple mapjoin tasks into their common child mapred task

Description
Use the following test case with HIVE 0.12: 

  
  create   table  src( key   int ,  value   string );
 load   data   local  inpath  'src/ data /files/kv1.txt'  overwrite  into   table  src;
 select  *  from  (
   select   c . key   from 
    ( select   a . key   from  src  a   join  src b  on   a . key =b. key   group   by   a . key ) tmp
     join  src  c   on  tmp. key = c . key 
   union   all 
   select   c . key   from 
    ( select   a . key   from  src  a   join  src b  on   a . key =b. key   group   by   a . key ) tmp
     join  src  c   on  tmp. key = c . key 
) x;

- sunrui  What will the plan of the query in the description look like with your patch? Will MapJoins and the Union be executed in the same job? Seems those two tmps appearing in the same position in those MapJoins triggered the bug. I was thinking if ids in those two QBJoinTrees are the same? If so, aliases of those two tables are probably still the same. 0.11 does not have this bug because it does not use a single job to evaluate those MapJoins and the Union. 

 I do not think it will affect Demux since Demux is at the reducer side. 

 btw, I also think "$INTNAME" is confusing... Seems it is used to represent those intermediate results. I'd like a name which has a meaningful part which can represent how this intermediate results are generated and a unique part to address the issue shown in this jira.
