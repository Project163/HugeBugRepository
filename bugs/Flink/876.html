Title

Bounded sources should emit a Max Watermark when they are done

Description
For proper event time support in bounded sources, these sources should emit a final watermark before shutting down.
Discussion
- A good point to emit the  Long.MAX_VALUE  watermark is in the source operator, after the  run()  function has properly exited (that only ever happens on bounded sources). 

 In addition, the operator must not be  stopped  or  canceled .
- GitHub user StephanEwen opened a pull request: 

      [URL]

       FLINK-3554    [streaming]  Emit a MAX Watermark after finite sources finished 

     Finite sources now emit a MAX_LONG watermark once they cleanly finished. 

     This prevents loss of pending windows over finite sources when they finish. 

     Canceling and stopping sources will NOT emit a MAX Watermark.

     you can use it like this: 

     ``` 
    stream 
        .keyBy(...) 
        .window(GlobalWindows.create()) 
        .trigger(ClosingCountTrigger.of(<my count>) 
        .apply() // or .reduce() 
    ``` 

     This will behave like the normal count trigger but also register a callback for the final `Long.MAX_VALUE` watermark. Then, when the final watermark arrives it will trigger one last window emission.
