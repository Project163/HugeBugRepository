Title

Numerous loader misbehaviors when file can not be opened (crashes, assertions, bad returns) [amf, 3ds, sib, irrm, irrs, quick3d, ms3d, cob, nendo, xgl, assbin]

Description
Library version: latest master at the time of this post.
Platform: Win 10 64-bit, debug build, MSVC 2019 64-bit.

A fair number of loaders crash (usually due to assertion failures) or return empty scenes (instead of failing) when faced with files that can not be opened:

- 3DS, SIB, Quick3D, Milkshape, TrueSpace, Nendo: When the file can not be opened for any reason, these all throw null stream assertion failures in debug mode, and generally crash in release mode.
- AMF: When a zero-length file is opened, it appears to return and (correctly) fail, but an access violation (termination with   on Windows) soon follows. Have not investigated yet.
- Assbin: When the file can not be opened for any reason, this returns an empty scene instead of failing.
- Irrlicht Mesh, Irrlicht Scene, XGL: When a zero-length file is opened, these return empty scenes instead of failing.

Will investigate and fix as much as possible.
