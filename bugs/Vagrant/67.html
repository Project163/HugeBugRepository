Title

FreeBSD 10 Private network DHCP issue

Description
When using DHCP with private network the first `vagrant up` is ok. But after trying `vagrant reload` or `vagrant halt` and `vagrant up` i get this error:

```
==> default: Configuring and enabling network interfaces...
The following SSH command responded with a non-zero exit status.
Vagrant assumes that this means the command failed!

dhclient em1
... [Log Snipped] ...
dhclient already running, pid: 705.
exiting.
```

Heres my Vagrantfile:

```
# -*- mode: ruby -*-
# vi: set ft=ruby :

Vagrant.configure(2) do |config|
  config.vm.box = "chef/freebsd-10.0"
... [Log Snipped] ...
  config.vm.synced_folder ".", "/vagrant", type: "nfs", id: "vagrant-root"
end
```

I am still able to ssh login but my /vagrant folder is empty (shared folder wasn't mounted).
To fix this issue I edit the `/etc/rc.conf` remove these lines:

```
#VAGRANT-BEGIN
ifconfig_em1="DHCP"
#VAGRANT-END
```

And after running `vagrant reload` everything works until the next `vagrant reload` (so I need to repeat the whole `rc.conf` editing.
There is still a line in `rc.conf` which makes DHCP work:

```
ifconfig_em0="DHCP"
```

Full `/etc/rc.conf`

```
zfs_enable="YES"
hostname="packer-freebsd-10.0-amd64"
ifconfig_em0="dhcp"  # This makes DHCP work
sshd_enable="YES"
rpcbind_enable="YES"
... [Log Snipped] ...
ifconfig_em1="DHCP" # This makes `vagrant up` fail
#VAGRANT-END
```

ifconfig:

```
em0: flags=8843  metric 0 mtu 1500
        options=9b 
        ether 08:00:27:d1:4c:66
        inet   netmask   broadcast   
        nd6 options=29 
... [Log Snipped] ...
        inet   netmask   
        nd6 options=21 
```

Versions:
Vagrant 1.7.2
Oracle VM VirtualBox Manager 4.3.28
OSX 10.10.3

Any help please?

in fact, I see the same issue as well.  Here's my understanding of the issue:

To me it seems that Vagrant is erroneously trying to manually re-set-up the interface after a reload (by running dhclient manually), when it was already previously set to start automatically by virtue of having set the DHCP flag on the interface in /etc/rc.conf.

Vagrant should either a.) NOT manually run dhclient after a reload if it added that line to /etc/rc.conf, or b.) it should not add the line to rc.conf and always run dhclient manually.. it is trying to do both.
- I had the same issue on bridged interface and I made it disappear with the following vagrant configuration entry.

``` ruby
config.vm.network "public_network", bridge: 'enp4s0', auto_config: false
```
