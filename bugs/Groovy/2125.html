Title

sql.firstRow() fetches all rows of query

Description
We were trying to use "sql.firstRow(...)" but had to switch to the other sql calls because firstRow is so efficient. Looking at the code ( [URL] implies it could be quickly improved: 

 current code: 
  
  public  GroovyRowResult firstRow( String  sql)  throws  SQLException {
    List<GroovyRowResult> rows = rows(sql);
     if  (rows.isEmpty())  return   null ;
     return  (rows.get(0));
}
 
  

 suggested code: 
  
  public  GroovyRowResult firstRow( String  sql)  throws  SQLException {
    List<GroovyRowResult> rows = rows(sql, 1, 1,  null );
     if  (rows.isEmpty())  return   null ;
     return  (rows.get(0));
}
 
  

 This would avoid first loading all of the rows into memory, just to grab the first one and throw the rest away. For large tables, this causes us to run out of memory.
Discussion
- Oops... I meant "firstRow is so inefficient" ...
- The main reason this hasn't been done previously was that several of the older database drivers we tested with in the past threw a  SQLFeatureNotSupportedException  when  ResultSet#absolute(int)  was called, so we favored the conservative approach which will work for those drivers although it is slower. I guess we should test this again and see what the current situation is. At the moment the burden is on you to use rows(sql, 1, 1, null) to make things faster but if enough of the drivers are working correctly now, then we could put that burden on the old driver users.
