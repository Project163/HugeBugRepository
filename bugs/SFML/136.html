Title

OpenGL extension SGIS_texture_edge_clamp unavailable

Description
## Subject of the issue

From commit   onwards the following error appears in the terminal, presumably only on nvidia cards

OpenGL extension SGIS_texture_edge_clamp unavailable
Artifacts may occur along texture edges
Ensure that hardware acceleration is enabled if available

## Your environment

* nvidia 3080 GPU, Ubuntu 20.04 (driver 460.39) and Windows 10 (driver 461.33)
* GCC 9.3.0, Visual Studio 2019 

## Steps to reproduce

Any program making use of a texture

```
cpp
#include  

int main()
{
... [Log Snipped] ...
    return 0;
}
```

----

I managed to get the error to go away by changing line 11988 in [URL] from

```cpp
    SF_GLAD_GL_SGIS_texture_edge_clamp = sf_glad_gl_has_extension(version, exts, num_exts_i, exts_i, "GL_SGIS_texture_edge_clamp");
```
to it's old value

```cpp
    SF_GLAD_GL_SGIS_texture_edge_clamp = sf_glad_gl_has_extension(version, exts, num_exts_i, exts_i, "GL_SGIS_texture_edge_clamp") | sf_glad_gl_has_extension(version, exts, num_exts_i, exts_i, "GL_EXT_texture_edge_clamp");
```

It looks like this an issue in the past which I'm assuming was manually fixed, [URL] I'm assuming that when this file was regenerated the fix didn't get  carried over.
Discussion
- It's a regression from #1769.

Question is, did we previously manually edit the glad.h file or is there an option for glad to apply this for future generations?

Before
```cpp
    SF_GLAD_GL_SGIS_texture_edge_clamp = sf_glad_gl_has_extension(version, exts, num_exts_i, exts_i, "GL_SGIS_texture_edge_clamp") | sf_glad_gl_has_extension(version, exts, num_exts_i, exts_i, "GL_EXT_texture_edge_clamp");
```

After
```
    SF_GLAD_GL_SGIS_texture_edge_clamp = sf_glad_gl_has_extension(version, exts, num_exts_i, exts_i, "GL_SGIS_texture_edge_clamp");
```
- For maintenance reasons, we should handle this in our own code instead of having to remember to manually tweak glad every time we update it (like was done in the past).
- This should be fixed in #1789.
- Thank you, I just pulled and tested that commit and it's working without error on my rig.
