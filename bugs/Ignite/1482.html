Discussion
- I see that at least some of the use cases are for heterogeneous cluster where some of the nodes are running on one JRE and others on something else. Is it a common usecase with the configuration like that? In my experience, production (and even testing clusters) aren't set this way, because it is usually too much pain operation-wise to support a setup like that.
- Cos, sure this is quite a rare use case. 
However this happens in really huge companies that have Ignite cluster deployed across the whole company's infrastructure (like a global database). Then a business unit or specific department may need to work with the cluster from its business app that has to use IBM or HP solution and they can't switch to something else. 

 In any case I see the following actions with this task. Probably, some of them are not feasible to do, will see: 
 
	 general support of IBM JDK (compilation, full work-ability of IBM cluster); 
	 support heterogeneous cluster with Oracle server nodes and IBM client nodes; 
	 support heterogeneous cluster when every node may run on Oracle or IBM.
