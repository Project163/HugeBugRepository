Title

DefaultChannelID : valid ProcessID is not accepted

Description
Running Netty on a Java-VM on IBM z/OS leads to unnecessary warnings.

You have to know that Unix System Services of IBM z/OS offers PIDs greater than 2^22, as assumed in DefaultChannelID (see Issue 2706)

`   Welcome to  Unix System Services ZOSU of`      
          ` z / O S   Version 2 Release 2`            
`$ ps`
      `PID TTY       TIME CMD`
     `   41 ttyp0000  0:00 /bin/sh`
 ` 50332311 ttyp0000  0:00 /bin/ps`    <== !
`$`

### Expected behavior
Netty should accept valid PIDs coming from any OS. It is a little bit infelicitous to assume that the Linux64 limits are valid for all OS which supports JAVA.

### Actual behavior
Even DefaultChannelID's auto-mechanism succeeded in detecting the correct PID on z/OS the PID is discarded by later check and replaced by a random value.

`Dec 15, 2016 6:05:49 AM io.netty.channel.DefaultChannelId defaultProcessId                  
WARNING: Failed to find the current process ID from '50332208'; using a random value: 474712`

### Steps to reproduce
Start any Netty-using application (i.e. your sample io.netty.example.echo.EchoServer) on IBM Mainframe z/OS. With a little luck the arising PID violates the limit in Netty.

### Minimal yet complete reproducer code (or URL to code)
io.netty.example.echo.EchoServer
