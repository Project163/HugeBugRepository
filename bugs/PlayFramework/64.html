Title

Need to use Guice with custom ConnectionPool objects

Description
There is a bug that prevents users from being able to make dependency-injected `ConnectionPool` objects.

## Details

In normal usage Play binds its `Injector` type to a `GuiceInjector`. The `GuiceInjector` object can be used to instantiate classes via Guice dependency injection.

[URL]

This `Injector` is passed to the `DBApiProvider`'s constructor.

[URL]
(Guice will provide a value for `injector` so the `NewInstanceInjector` won't be used)

However when the `DBApiProvider` creates a `DefaultDBApi`, it fails to pass in the `GuiceInjector`
[URL]
instead relying on the default value of `injector` in the `DefaultDBApi` constructor, a `NewInstanceInjector`:
[URL]

A `NewInstanceInjector` is OK in some circumstances, but it isn't able to handle classes that require dependency injection.

When `DefaultDBApi.get` is called later on it passes the `NewInstanceInjector` to `ConnectionPool.fromConfig`:
[URL]

If the `ConnectionPool.fromConfig` method encounters a custom `ConnectionPool` it will try to use the `NewInstanceInjector` to create the `ConnectionPool`.
[URL]

If the custom `ConnectionPool`'s constructor has arguments and is expecting to be created by Guice then injection with the `NewInstanceInjector` will fail with an error like:

```
java.lang.NoSuchMethodException: com.example.MyCustomConnectionPool. ()
```
