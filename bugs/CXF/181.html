- The problem seems to be quite obvious - cxf code assumes that there're only one possible content type value parameter (charset). Fixing it should be easy - but if the action parameter needs to be preserved then it might be worth saving the ContentType info in a wrapper class, similar to a MediaType JAX-RS class. A similar CXF-specific class can be introduced. 

 in CXF JAX-RS we have an implementation of MediaType so one option is to move its internals  into some common utility code like MediaTypeUtils.java, and have it reused between JAXWS and JAXRS runtimes
