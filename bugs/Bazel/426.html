Title

XML test output missing for tests that timeout

Description
It appears to be the case that bazel doesn't generate a test XML file for tests that fail due to `TIMEOUT`. It would be really useful if it did generate this file so CI systems can detect the failure and report it as such. With the current behavior, a test can timeout but the CI system can't report which one caused the build to fail because the corresponding XML file is missing.
Discussion
- More context: the XML file is created by the test runners or by default by test-setup.sh. The test time out is done by the process wrapper which run that test runner. So it's not really clear if there is a good way to do it.

I think we could add an intercept in the test-setup.sh on interrupt but I don't know how reliable that would be. I guess trying (it's not hard) and running the bazel test suite should be enough to say.
- Any update on this? Test timeouts are becoming more of an issue for me and it'd be great if I could easily track them down using the XML file.

I could probably make it happen with a `--run_under` script but that smells kinda funny to me.
