Title

NPE in HttpObjectAggregator

Description
In some cases `HttpObjectAggregator` throws NPE (trace below). It's always happens in combination with `channelInactive`.

```
java.lang.NullPointerException: null
    at io.netty.handler.codec.http.HttpObjectAggregator.decode(HttpObjectAggregator.java:172) ~[netty-codec-http-4.0.15.Final-SNAPSHOT.jar:4.0.15.Final-SNAPSHOT]
    at io.netty.handler.codec.http.HttpObjectAggregator.decode(HttpObjectAggregator.java:50) ~[netty-codec-http-4.0.15.Final-SNAPSHOT.jar:4.0.15.Final-SNAPSHOT]
    at io.netty.handler.codec.MessageToMessageDecoder.channelRead(MessageToMessageDecoder.java:89) [netty-codec-4.0.15.Final-SNAPSHOT.jar:4.0.15.Final-SNAPSHOT]
Wrapped by: io.netty.handler.codec.DecoderException: java.lang.NullPointerException
... [Log Snipped] ...
    at io.netty.util.concurrent.SingleThreadEventExecutor$2.run(SingleThreadEventExecutor.java:101) [netty-common-4.0.15.Final-SNAPSHOT.jar:4.0.15.Final-SNAPSHOT]
    at java.lang.Thread.run(Thread.java:744) [na:1.7.0_45]
```

Trace above when using 4.0.15 ( ), but it's also happens with 4.0.14
Discussion
- It seems like somehow the `HttpObjectDecoder` produced `HttpContent` without `HttpMessage`, which should not happen.  Could you post the complete traffic of the connection that triggered the problem?
- Something like this: [URL]
- So the problem was:

1) Nginx violates HTTP specification, producing unexpected HTTP content without its response headers.
2) Netty HTTP decoder sees the violation and generates a bogus HTTP response with 999 Unknown status code, which is expected.
3) Netty HTTP decodec should not have generated anything beyond that, but it produced a `LastHttpContent`, which confused `HttpObjectAggregator`.

I fixed the problem by fixing the Netty decoder so that it does not produce anything after a decode error.  Please see the test case for more information.
