Discussion
- I believe what is happening is: 

 1. The SocketServer is created 
2. The exception is thrown from the dynamicConfigManager 
3. SocketServer.enableRequestProcessing is never called, so the SocketServer is never started 
4. Because the SocketServer is never started, the SocketServer main runnable never exits, and so the SocketServerChannel is never closed. 

 I think that when the SocketServer beginShutdown()/shutdown() is called without calling enableRequestProcessing() first, the SocketServer should still close these resources.
