Title

Removing pending folders is flaky

Description
I didn't get a folder invitation that I should have, and adding a bit of additional debugging info I get the following:

```
Mar 30 13:19:48 homeserver syncthing[9815]: [BPDFD] INFO: Adding/updating pending folder f4vae-zg2uv (enc) from device BXAEQNX, last seen 2021-03-30 13:19:48 +0200 CEST
Mar 30 13:19:48 homeserver syncthing[9815]: [BPDFD] INFO: Unexpected folder "enc" (f4vae-zg2uv) sent from device "BXAEQNX-..."; ensure ...
Mar 30 13:19:48 homeserver syncthing[9815]: [BPDFD] INFO: Removing stale pending folder f4vae-zg2uv (enc) from device BXAEQNX, last seen 2021-03-30 11:19:48 +0000 UTC, oldest 2021-03-30 13:19:49 +020
```

`time.Now` called in the db after being called in model can apparently return an earlier time, or rounding to a second is buggy/does something unexpected. In any case calling `time.Now` for every entry is pointless: We do know which folders were updated, so one could pass a list/map of those and drop all other entries. Or just drop all entries before processing the cluster config. Or pass the timestamp from model to `RemovePendingFoldersBeforeTime`.

- What springs to mind in your log is that the comparison between the entry and the "oldest" argument concerns two different time zones.  I suspect that the time zone information is lost / altered during the DB marshalling / unmarshalling process.

- I think the bug may have been introduced in   (#7459).

Previously both sides of the comparison used `.Round()`, now the call in `AddOrUpdatePendingFolder()` was changed to `.Truncate()` but the one in `RemovePendingFoldersBeforeTime()` stayed with `.Round()`.  I don't have a preference of one over the other, but this explains the issue at hand.
- The original logic was correct, basically summarized like this:

```go
first := time.Now()
// ... some nanoseconds later ...
second := time.Now().Round(time.Seconds)

if second.Before(first.Round(time.Seconds)) {
	// impossible, Round(x) <= Round(x + epsilon)
}
```
