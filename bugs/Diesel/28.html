Discussion
- Thanks for reporting this issue.

Just for the record: I do not consider this to be an issue with our MSRV, as we define MSRV as that's the rust version where diesel builds with some set of supported dependency versions. We test this by using cargos minimal-version dependency version resolution algorithm.
- Fair enough. Should I close the PR?
- I think it's fine to update the rust version used in `rust-toolchain` as we have a independent check for the minimal supported rust version on the CI. I've also noted that this now needs at least 1.57 due to some other dependency + the update to the CI job might not be required anymore, as I've already done this as part of some other PR. I might be open to just switch to the latest stable release for the `rust-toolchain` version to prevent such issues from happening in the future, although that might bring other issues with breaking the clippy/rustfmt job if a new stable rust release is done.
