Title

Type names are sometimes in .class file syntax, rather than source syntax.

Description
In methods generated by the groovy compiler, type names in parameter signatures end up using the .class file type format, where the rest of the system using source format. 

 So, for example, a String array is normally represented as "java.lang.String[]"; in the getStrings() method generated in createGStringClass, it's represented by "[Ljava.lang.String;". 

 As mentioned above, "createGStringClass" in ClassGenerator is a good example of this.
Discussion
- This patch fixes the JVM type naming issue. The cause of the problem was that when a class is loaded by the classloader, the parameter and return types are retrieved using 
the Class.getName method, which returns names in JVM syntax.  

 The tests that I provided for Groovy-422 will also test this; the Groovy-422 patch included a workaround for this issue. The 422 patches will fail with that workaround removed, but will pass with this patch in place. (This patch removes the 422 workaround.)
- Patch applied, thanks Mark. 
I've fixed a NPE when in MethodNode when the return type was passed as null.
