Title

RESTEasy Reactive SSE doesn't provide method annotations, nor actual headers to `MessageBodyWriter`

Description
### Describe the bug

The current implementation of RESTEasy Reactive Server Sent Events (SSE) doesn't provide the method annotations, nor actual headers to the implementations of [Link: `MessageBodyWriter#writeTo`].

This prevents the implementations of `MessageBodyWriter` knowing they are supposed to serialize the object for SSE, where setting headers make no sense.

Also, it makes sense to warn people that those headers will be dropped. For example, to check if the headers been changed after calling write, we can log a WARN message.

Furthermore, the RESTEasy Classic properly passes the proper annotations. See example here: [URL]

See related issue: [URL]

Follow up to [URL]

### Expected behavior

Headers and method annotations are passed to the `MessageBodyWriter` allowing to make proper decisions.

The HTTP response should be:

```
http
HTTP/1.1 200 OK
Content-Type: text/event-stream
X-SSE-Content-Type: application/json
transfer-encoding: chunked
... [Log Snipped] ...
    "type": "com.redhat.openshift.knative.showcase.events.Endpoint"
}
```

### Actual behavior

The empty headers and annotations are passed to the `MessageBodyWriter`.

The HTTP response is:

```
http
HTTP/1.1 200 OK
Content-Type: text/event-stream
X-SSE-Content-Type: application/json
transfer-encoding: chunked
... [Log Snipped] ...
    "score": 65
}
```

### How to Reproduce?

1. Use cloudevents-http-restful-ws library, as it has `MessageBodyWriter` implemtation which looks for `StructuredEncoding` annotation in the annotations list. If that annotation isn't found, binary encoding is used. The binary encoding writes the event headers as HTTP headers and event data as body. In the case of SSE, this makes no sense.
2. Define REST endpoint that will produce SSE of return type `Multi `.
3. Call such an endpoint. You will see a list of events bodies (the headers are missing)
