Discussion
- The above stack trace was produced by launching the job from the command line and cancelling from the web UI. 

 The bug does not seem to be deterministic - it does not happen every time.
- I think the reason why this happens is that in  JobResult#createFrom  would set the latest global failure cause of the ExecutionGraph to be the cause of the  JobResult  if the job is terminated but not FINISHED.  
So if the job is CANCELED and any global failure had ever happened, the latest global failure cause would be shown as the root cause of the canceling. 
I think in the case that a job is CANCELED, we can just keep  JobResult#serializedThrowable  to be null so that the root cause would simple be  JobCancellationException: Job was cancelled. .
