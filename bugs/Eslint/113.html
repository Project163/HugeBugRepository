Title

Files in ignored directories are still being linted when individually listed

Description
This is basically the same issue as #813 (and its associated PR #818), but I've noticed a bug that made it through.

Situation:

```
/subdir
  my-file.js
.eslintignore
```

The `.eslintignore` file has the contents: `subdir`

``` bash
$ eslint subdir/my-file.js
```

**Expected**: a warning that my-file.js was ignored. **Actual**: my-file.js is linted.

This happens with all variations of ignoring a directory that I know of:

```
subdir
*/subdir
subdir/*
**/subdir/*
**/subdir/**
subdir/**
```

_(This is using [Link: current master] on Linux)_
Discussion
- Seems like the issue is that the exclusions cache is optimised for the case of iterating over an entire directory. When you have something like "app/vendor" in the ignore file, it will get expanded to its full path (eg: "/home/user/my-project/app/vendor"). When you later run `eslint .` it will recursively step through the directory and at one point it'll exactly match "/home/user/my-project/app/vendor" and not go any deeper. When you list the files individually, it never has an exact match on "/home/user/my-project/app/vendor" so the file is not excluded.
- Can you check the `ignored` branch and see if it resolves this issue for you?
