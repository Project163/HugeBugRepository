Title

2.0.0.Final: NullPointerException in QuarkusRestPathTemplateInterceptor

Description
## Describe the bug
I have a REST service annotated with `@Transactional` and `@Path` and then a test for this service annotated with `@QuarkusTest`. Now when running the test I get the following `NullPointerException`. This is new with Quarkus 2.0.0.Final and still worked with 2.0.0.CR3.

```
java.lang.NullPointerException
	at io.quarkus.resteasy.runtime.QuarkusRestPathTemplateInterceptor.restMethodInvoke(QuarkusRestPathTemplateInterceptor.java:28)
	at io.quarkus.resteasy.runtime.QuarkusRestPathTemplateInterceptor_Bean.intercept(QuarkusRestPathTemplateInterceptor_Bean.zig:328)
	at io.quarkus.arc.impl.InterceptorInvocation.invoke(InterceptorInvocation.java:41)
	at io.quarkus.arc.impl.AroundInvokeInvocationContext.perform(AroundInvokeInvocationContext.java:41)
... [Log Snipped] ...
	at com.intellij.rt.junit.JUnitStarter.prepareStreamsAndStart(JUnitStarter.java:235)
	at com.intellij.rt.junit.JUnitStarter.main(JUnitStarter.java:54)
```

The test only fails in this way when the test has the service injected and invokes the service method on that injected bean. When instead using REST Assured to invoke the service method the test passes.

The NPE is also only thrown when metrics are enabled (e.g. by adding the extension `quarkus-micrometer-registry-prometheus`). I believe that is due to `RestPathAnnotationProcessor#registerBeanClasses()` which otherwise doesn't register `QuarkusRestPathTemplateInterceptor`.

Note: I have not tested whether this problem could also affect the normal launch mode or not.

### Expected behavior
No NPE should be thrown.

### Actual behavior
See description.


## To Reproduce

1. Clone [URL]
2. Run `mvn verify`
3. The `FruitResourceTest#testCdi()` test should fail

## Environment:

### Quarkus version or git rev
Quarkus 2.0.0.Final
