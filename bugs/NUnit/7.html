Title

Path-related tests fail on Linux

Description
Most test involving paths on the file system fail on Linux, they should either be fixed or excluded in Linux runs.
Discussion
- Some of the failing paths are Windows format. I think I had the notion that a Linux build should be able to deal with Windows paths and vice versa. Somebody should double check this idea to see if it really is needed.
- I was looking right into it, in fact some tests we have expect that /some/path is the same as \some\path, which I'm not sure is a correct assumption in Linux.
- You're right, it's not. The backslash is actually permitted in a path in
some versions of Linux.

On Sun, Jan 26, 2014 at 5:34 PM, simoneb notifications@github.com wrote:
- Of course, if you are analyzing a Windows path on Linux, then the two
should be equivalent. This is not something we need to do right now. It's
not even clear we will have to do it when we are running distributed tests.
It seems to me that in all cases the path would be analyzed on the machine
that was going to run the test.
