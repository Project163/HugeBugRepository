Title

Mypy fails to calculate MRO in situations with import cycles.

Description
In some situations mypy can't determine MRO, for example consider this test case:
```
[case testMultipleInheritanceCycle]
import b
[file a.py]
from b import B
class A: ...
... [Log Snipped] ...
class B: ...
[out]
```
that fails with
```
tmp/a.py:4: error: Cannot determine consistent method resolution order (MRO) for "D"
```
Note that changing order of files in the cycle (for example by importing `a` in `main`) removes the error.

In this case the actual MRO is consistent (works at runtime), while the import cycle is caused by an unrelated class (used for annotations in real stubs).

I think this is high priority because this is just a time bomb waiting to explode in some real code bases.
