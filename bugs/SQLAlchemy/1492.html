Title

asyncpg terminate needs a delay

Description
### Describe the bug

Greetings, I came across a strange behavior: when you pass `command_timeout` param to asyncpg driver and the query is long enough to exceed it, there still will be an active session on PostgreSQL side

You may also check it by using `select * from pg_stat_activity;`

### Optional link from [URL] which documents the behavior that is expected

_No response_

### SQLAlchemy Version in Use

2.0.23

### DBAPI (i.e. the database driver)

asyncpg

### Database Vendor and Major Version

PostgreSQL 14

### Python Version

3.10

### Operating system

OSX

### To Reproduce

```
python
import asyncio

import sqlalchemy as sa
from sqlalchemy import URL
... [Log Snipped] ...

```

### Additional context

I made my own investigation and the problem is because here [URL] `CancelledError` is thrown, so asyncpg can not send CancelRequest message, but if I add a small delay here [URL] it will succeed. I know that it is not the solution, but maybe it will save some time
