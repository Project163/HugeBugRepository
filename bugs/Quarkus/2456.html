Title

Gradle regression in tests when a module has a "sidecar" module

Description
### Describe the bug

From Quarkus 3.22.0 to Quarkus 3.23.0 there is a regression in `@QuarkusTest` when a module `A` uses a class from module `B` that reference a class from module `A`. In this situation, a `ClassNotFoundException` is thrown. There is no problem in Quarkus 3.21.4.

Let's say module `A` has a class `Person`:
```java
public record Person(String id) {}
```

And module `B` a `PersonFactory`:
```java
public class PersonFactory {
	public static Person newRandomPerson() {
		return new Person(UUID.randomUUID().toString());
	}
}
```

module `A` imports `B` as a test dependency:
```kotlin
dependencies {
    ...
    testImplementation(project(":B"))
    testImplementation("io.quarkus:quarkus-junit5")
}
```

And module `B` imports `A` as a main dependency:
```kotlin
dependencies {
    implementation(project(":A"))
}
```

If module `A` uses `PersonFactory#newRandomPerson`  in a `@QuarkusTest`, a `ClassNotFoundException` is thrown:
```java
@QuarkusTest
class PersonTest {
	@Test
	void test() {
		PersonFactory.newRandomPerson();
	}
}
```

With the stacktrace being:
```
java.lang.NoClassDefFoundError: com/module/Person
	at com.module.test.PersonFactory.newRandomPerson(PersonFactory.java:9)
	at com.module.PersonTest.test(PersonTest.java:12)
	at java.base/java.lang.reflect.Method.invoke(Method.java:580)
	at io.quarkus.test.junit.QuarkusTestExtension.runExtensionMethod(QuarkusTestExtension.java:999)
... [Log Snipped] ...
	at io.quarkus.bootstrap.classloading.QuarkusClassLoader.loadClass(QuarkusClassLoader.java:523)
	... 7 more
```

### How to Reproduce?

Here's a reproducer:
[Link: test-classloader-issue.zip]

1. Go to `PersonFactory` and launch the test
    - A `ClassNotFoundException` should be thrown
2. In `gradle.properties` use the Quarkus version 3.21.4
3. Run the test again
   - The test should pass

I tried your project that simulates the issue, the main issue is coming from the following line

 `ClassPathElement classPathElement = classPathResourceIndex.getFirstClassPathElement(resourceName);`

which is load all available JAR, Module, and Directories

means, PersonFactory tries to access the Person which is expected to be found, on the actual issue is seems does not exist
- I was looking into this issue now, on latest master. From what I can see, `PersonTest` and `PersonFactory` are loaded using Quarkus Runtime ClassLoader, whereas loading of `Person` class from the factory class happens via Quarkus Base Runtime ClassLoader, and that loader throws [Link: here]:

```
if (classPathResourceIndex.isBanned(resourceName)) {
    throw new ClassNotFoundException(name);
}
```

`Person` class is banned in the base runtime classloader since it's marked as reloadable.

I will continue looking into it and try to understand what changed from 3.22.0 to 3.23.0 that caused this. I'm not an expert in this topic, so most likely I might need to validate it with more experienced folks in Zulip, and it may take a bit of time. You should get an update soon, @celcius112 .
