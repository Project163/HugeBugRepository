close a PDF Document  
 That one means that PDFBox closes a COSDocument object (that is in the signatureOptions) for you. I made a modification to SignatureOptions to see if finalize is called before things go bad, and yes it is   

 Your problem reminds me of this 
 [URL]
see the comment by mkl. 

 So signatureOptions goes out of scope, and thus COSDocument is also not needed anymore either... but the signed PDF keeps references of some of the streams in the COSDocument. Because the COSDocument is no longer referenced, it gets closed at the gc() moment, which also closes streams that are still needed. So the solution in the CreateVisibleSignature example is the correct one: keep signatureOptions until done, and close it yourself (i.e. even the "false" branch here is not really correct!!!). I will add a comment into the CreateVisibleSignature example and improve the javadoc of SignatureOptions.close(). 

 Thus, TODO for you: add  signatureOptions.close();  as last statement. 

 Btw your code is incorrect, it doesn't sign anything. Unlike the CreateVisibleSignature example, which can sign.
