Title

Wrong static resource urls when their generation is triggered by

Description
If an application uses <wicket:link> to generate a url for a static resource, e.g. 
  
 
<html xmlns= "http: //www.w3.org/1999/xhtml"  xmlns:wicket= "[URL]
 <head>
<wicket:head>
  <wicket:link>
    <link rel= "stylesheet"  type= "text/css"  href= "css/test2.css"   />
  </wicket:link>
</wicket:head>
</head>
...   
  
 then during the page render time it will use 
  
 
CharSequence url = getRequestCycle().urlFor(handler);  
  
 and  [URL] will use the current page's url and try to parse locale/style/variation from it and embed it in the static resource url. 

 The problem is that it uses the pageId/renderCount/behaviorId and component path instead.
Discussion
- Note that the behaviour described here may cause org.apache.wicket.core.util.resource.locator.caching.CachingResourceStreamLocator to leak memory as it uses a cache key derived from the wrongly parsed URL components (see discussion on mailing list,  [URL]
- Hi, I was taking a look in the ticket referenced in the code related to this behavior  [1] , and the URL attributes encoded to inform the resource locale, style... seams to be designed to resource URLs only. e.g.: 

 ./wicket/resource/org.barlabanov.HomePage/styled-ver-1432053148000.css?-orange 

 I added a new test  [2]  in the PackageResourceReference to only decode such URLs, avoiding to misread the callback ones as with locale, style... encoded information, and it seams to fix this issue. Working on a test case.
