Title

Page should start at top when URL is changed in browser bar as in in-app route changes via links

Description
# 📚 Docs or angular.io bug report

### Description
When I enter a different URL in the URL bar once inside of AIO, the scroll location is kept. 

## 🔬 Minimal Reproduction
Scroll a bit down on a page and then change the URL in the ULR browser bar. See repro steps below.

### What's the affected URL?**
All

### Reproduction Steps**
- Go to [URL]
- Scroll a bit down
- Change URL to [URL]
- See that document page starts at the same scroll location as last page, not at the top as expected

### Expected vs Actual Behavior**
A user might expect that when a URL route change happens (as when you click on links) that they start at the top of the page.
Discussion
- Let’s divide this into 2 categories:

**Page load**
Sounds like the scroll position is stored in session storage upon each scroll event. And then applied upon future page loads.

Ideas:
- Don’t store scroll position at all (if possible)
- Clear scroll position in session storage upon page load
- Clear scroll position in session storage upon `onbeforeunload` event

**Route change**
Sounds like default behaviour to have the scroll position preserved

Ideas:
- Set [Link: scrollPositionRestoration] to `enabled`
- @dannyskoog 

I think why the scroll position is stored in the first place is because

**Better UX**
When I open the doc in mobile phone, and I put the browser into background by switch app or simply switching the tab because I want to check out something else in another tab opening in the same browser, there are cases when the tab/browser contains the angular doc will be closed because the tab/app we switch to consume too much space in cpu, in a low cpu device, system will make choice for the current running so it will temporarily close the browser/tab that contains the angular doc. 

When this case happens, for a better user experience, for example, when I switch back to browser/tab containing the doc, I must want the previous page I visited remain in the same place, right?

So, I think the better solution will be cleared the session storage when the url is refreshed. Because doc is a single page application, the change it make to the url is not refreshing the address bar, I think.

The fact that you locate where the scroll position is stored is amazing! Good job! And thank you!😄
