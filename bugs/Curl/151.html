Title

CURLMOPT_SOCKETFUNCTION called before CURLOPT_OPENSOCKETFUNCTION

Description
### I did this
With the use of `sokcetpair.h` on `lib/async-thread.c` the CURLMOPT_SOCKETFUNCTION is fired before the CURLOPT_OPENSOCKETFUNCTION callback when using the **multi** interface. This is in [Link: here] in [URL] 

As a result the sockp in ```static int sock_cb(CURL* e, curl_socket_t s, int what, void* cbp, void* sockp)``` is a null making it harder for users who use libraries such as uv or libevent to create/remove sockets to track socket failures as they are usually created in the CURLOPT_OPENSOCKETFUNCTION callback and the user has no knowledge of the sockets that cURL created for the socket pair but get a callback. 

### I expected the following
The callback order to be preserved and CURLOPT_OPENSOCKETFUNCTION to be called before CURLMOPT_SOCKETFUNCTION or to receive no callbacks for sockets that were created by libcurl itself.
