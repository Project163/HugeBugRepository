Title

Hibernate Panache: methods and annotations are missing building jar with Maven on Windows 10

Description
After discussion with the Quarkus community on zulipchat, it seems that there is a bug when a project using hibernate orm with Panache is  builded with Maven on Windows. The runner jar does not work.

I have tested the build of the quarkus-quickstart/hibernate-orm-panache-resteasy project (https://github.com/quarkusio/quarkus-quickstarts commit# ):
* Directly on Windows 10 with: Maven 3.6.1 and jdk-8-amazon-corretto
* On linux (via docker) with same environment: Maven 3.6.1 and jdk-8-amazon-corretto

Then I have compared the Fruit class of each runner jar (I have decompiled class with JD-Gui).

Results: 
* in the jar generated with maven on Windows10:
  * annotations and hibernate methods are missing in the Fruit class.
* in the jar generated with maven on Linux:
  * annotations and hibernate methods are here in the Fruit class, all works fine.

You can find in attachment (see [Link: TEST.zip] ) , for Windows10 build and Linux build:
* command launched (cf. run.bat)
* result log file
* generated JARs
* decompiled sources from JAR


Environment:
* Quarkus: 0.14.0
* Java JDK: 8 (Amazon Corretto)
* Maven: 3.6.1
* OS:
  * Windows10
  * Linux

Steps to reproduce:
* On Windows10:
```
mvn clean install --show-version --batch-mode -Ddocker.skip=true -DskipTests
```
* On Linux (on Windows10 via Docker):
```
docker run -it -v ./:/tmp/quarkus-quickstarts/hibernate-orm-panache-resteasy/ -w /tmp/quarkus-quickstarts/hibernate-orm-panache-resteasy maven:3.6.1-amazoncorretto-8 mvn clean install --show-version --batch-mode -Ddocker.skip=true -DskipTests
```

- Hello @gsmet @FroMage ,

I think i have found the source of the problem. 
In the class [Link: AugmentPhase] (line 330), you are doing this : 

```java
final String className = pathName.substring(0, pathName.length() - 6).replace('/', '.');
```

The problem on windows, is that the `pathName` contains `\` instead of `/`. So the replacement is doing nothing, and no visitor can be found due to this (the visitor has to be executed to enhance the panache entities classes).

```
java
// The className should have all path separators replaced by '.' here
// In windows, as path separator is '\' and not '/', className has a bad value here
final List > visitors = bytecodeTransformers.get(className);

... [Log Snipped] ...
    return;
 }
```

A fix could be : 
```java
final String className = pathName.substring(0, pathName.length() - 6).replace(File.separatorChar, '.');
```

Hope it can help you to solve this problem.

Sylvain
