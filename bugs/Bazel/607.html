Title

Bazel Debian package installation overwrites global /etc/bazel.bazelrc file

Description
### Description of the problem / feature request:

Installing the Debian package of Bazel overwrites the user configuration in `/etc/bazel.bazelrc` blindly.

(This found me puzzling for an hour or so why my builds were failing.)

### Feature requests: what underlying problem are you trying to solve with this feature?

Please consider this a bug. A Debian package should never ever overwrite configuration files blindly. Users can expect their configuration files to not be overwritten by default. (See Lintian error below.)

### Bugs: what's the simplest, easiest way to reproduce this bug? Please provide a minimal example if possible.

    $ echo "foo" > /etc/bazel.bazelrc 
    $ sudo dpkg -i ~/Downloads/bazel_0.16.1-linux-x86_64.deb 
    (Reading database ... 249675 files and directories currently installed.)
    Preparing to unpack .../bazel_0.16.1-linux-x86_64.deb ...
    Unpacking bazel (0.16.1) over (0.16.1) ...
    Setting up bazel (0.16.1) ...
    $ cat /etc/bazel.bazelrc  # empty now
    $ ls -l /etc/bazel.bazelrc
    -rw-r--r-- 1 root root 0 Jan  1  1970 /etc/bazel.bazelrc

### What operating system are you running Bazel on?

Debian/Ubuntu.

### What's the output of `bazel info release`?

    $ bazel info release
    release 0.16.1

### If `bazel info release` returns "development version" or "(@non-git)", tell us how you built Bazel.

n/a

### What's the output of `git remote get-url origin ; git rev-parse master ; git rev-parse HEAD` ?

n/a - using release build

###  Have you found anything relevant by searching the web?

Lintian confirms this is a packaging error (see below).
