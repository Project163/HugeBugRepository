Title

Unstable formatting when there is a comment after line continuation on function def

Description
Operating system: macOS Mojave 10.14.3
Python version: 3.6.8
*Black* version: 193b0
Does also happen on master: yes

[Link: blk_yighuh06.log]

```
def bob(): \
         # pylint: disable=W9016
    pass
```

In the original example there was a reason for the line continuation to be there, if I take the continuation out before running black it works fine.
Discussion
- @gordonwrigley I'm curious if the reason for the line continuation being there sheds any light on the most useful behavior for Black here? After discussion with @ambv at PyCon sprints, we decided that the backslash means the newline isn't really a newline, so Black should format this as:

```
def bob():  # pylint: disable=W9016
    pass
```

This is what I've implemented in the attached PR, but I'm curious if it would actually be the desired behavior in your real code.
- Short version:
That seems fine

Backstory:
This came up while converting from pylint style to black. The function in question had a lot of parameters. The pylint exclusion needs to be on the same line as the def but the exclusion itself was pushing the line over the line limit. So someone had used the / to put the exclusion on a separate line, instead of the black approach of splitting the ().
I've tested the case where a def is over the limit because of a comment and of course black handles that totally fine, so this fix sounds on point.

Aside:
This was the only thing that failed during the conversion. There were a few other things that we're formatted in ways people didn't like but repeating "that's the Black default" enough times eventually shut them up :)
