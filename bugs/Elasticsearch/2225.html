Title

Default year in date ingest processor is not updated when a new year starts

Description
The `DateFormat` class used by the date ingest processor contains this code:

[URL]

When parsing dates that don't specify the year the idea is to use the current year.  However, the current year is obtained outside the lambda and used inside.  So if the lambda was constructed in 2019 and used in 2020 then it will be wrong.

This means that users who rely on the default year functionality (such as those who ingest syslogs, because syslog timestamps do not include the year) will have to restart their ingest nodes on 1st January to set the current year.
