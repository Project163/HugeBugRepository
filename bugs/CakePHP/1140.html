Title

EntityTrait::hasErrors and ::getErrors produce infinite recursion on cyclic entity references

Description
### Description

Right now (as of version 5.0.0, and in 4.x) calling `hasErrors()` or `getErrors()` on an Entity with cyclic entity references (i.e. via associated entities) results in an endless loop.


# Cause

`EntityTrait::hasErrors()` and `EntityTrait::getErrors()` by default recurse into associated entities looking for errors, without checking for cyclic references, thus resulting in an endless loop.


# Steps to reproduce

In a fresh skeleton app, the following code produces the endless loop (with debug=true):

```
$user = new \Cake\ORM\Entity([]);
$profile = new \Cake\ORM\Entity([]);
$user->set('profile', $profile);
$profile->set('user', $user);
$user->hasErrors(); // or $user->getErrors();
```

This produces the following error, or a similar error depending on which operation the memory actually runs out.



# Proposed improvement

`EntityTrait::hasErrors()` and `EntityTrait::getErrors()` could keep a list of entities already visited, and not visit an entity instance more than once.

Since all entities get still visited, the behaviour of both methods would stay the same (while avoiding infinite recursion).

Major drawback: EntityInterface would have to change since we would need to pass an SplObjectStorage to both `hasErrors()` and `getErrors()`.

I'd be happy to write a fix plus some tests and send a merge request, if you don't have any better ideas or concerns.
