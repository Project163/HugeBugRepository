Title

SQL Function name resolution depends on the case

Description
When SQL resolves function names, it takes case into consideration that produces unexpected results.

For example, the following tree statements work
```
SELECT CHAR_LENGTH("blah");
SELECT Char_Length("blah");
SELECT CharLength("blah");
```

But if the following 2 statements produce error messages:
```
SELECT cHaR_length("blah");
SELECT CHARLENGTH("blah");
```
In the first case the error message is
```
Unknown function [cHaR_length], did you mean any of [CHAR_LENGTH, CHARACTER_LENGTH, BIT_LENGTH]?
```
Expected behavior is SQL should be case insensitive in the function name resolution.
Discussion
- Pinging @elastic/es-search-aggs
- @imotov For the mixed capitalization we can have a fix, but for resolving `CHARLENGTH` we'll need to add some more "magic" since we have no indication on how to guess the position of the underscore. Imho we should just add the alias `CHARLENGTH` for such cases.

@costin what do you think?
