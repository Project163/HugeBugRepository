Title

Generated server marks all parameters in response as required Test

Description
## Problem statement

When generating a server, and embedding a schema directly in the response definition, the `required` list is ignored and instead all response parameters are marked as required.

## Swagger specification

    swagger: "2.0"

    info:
Test
      version: "1.0.0"

    paths:
      /test:
        get:
test
          responses:
            200:
              schema:
                type: object
                properties:
                  foo:
                    type: object
                  bar:
                    type: integer
                    format: int64
                  baz:
                    type: integer
                    format: int64
                  quux:
                    type: array
                    items:
                      type: string
                required:
                  - foo
                  - bar

## Steps to reproduce

Using the above spec as `test.yaml`, run

    swagger generate server -f test.yaml -A test

and then examine `restapi/operations/get_test.go`. The `GetTestOKBody` struct incorrectly has all members marked as required:-

    // GetTestOKBody get test o k body
    // swagger:model GetTestOKBody
    type GetTestOKBody struct {

            // bar
            // Required: true
            Bar *int64 `json:"bar"`

            // baz
            // Required: true
            Baz *int64 `json:"baz"`

            // foo
            // Required: true
            Foo interface{} `json:"foo"`

            // quux
            // Required: true
            Quux []string `json:"quux"`
    }

Here, `Baz` and `Quux` should be optional.

## Environment
swagger version: 0.8.0
go version: 1.7.4
OS: Fedora 25
