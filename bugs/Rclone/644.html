What appeared to happen is that somehow the original file got truncated to 0 length before the copy was even attempted.

The problem happened here

```
2021/03/30 14:36:25 DEBUG : /Textdokument (neu).txt: CreateEx: flags=0x502, mode=0700
2021/03/30 14:36:25 DEBUG : Textdokument (neu).txt: Open: flags=O_RDWR|O_CREATE|O_EXCL
2021/03/30 14:36:25 DEBUG : Textdokument (neu).txt: newRWFileHandle: 
2021/03/30 14:36:25 DEBUG : Textdokument (neu).txt( ): openPending: 
2021/03/30 14:36:25 INFO  : Textdokument (neu).txt: vfs cache: removed cache file as stale (remote deleted)
... [Log Snipped] ...
2021/03/30 14:36:25 DEBUG : Textdokument (neu).txt: >Open: fd=Textdokument (neu).txt (rw), err= 
2021/03/30 14:36:25 DEBUG : /Textdokument (neu).txt: >CreateEx: errc=0, fh=0x1
```

Rclone truncated the file to 0 size because Exporer opened the file with `Create` with flags `O_RDWR|O_CREATE|O_EXCL`. However explorer didn't write to the file so there was no need to truncate it.

- Very interesting.

That CREATE_NEW gets transalated to` CreateEx` with flags `O_RDWR|O_CREATE|O_EXCL`. Now that you've explained it, I can see what was supposed to happen and what wasn't happening before. the `O_EXCL` flag is not supposed to allow a creation if the file already exists - hence the `NAME_COLLISION`. What was happening before the fix was that the file got created and truncated.

After the fix this happens

```
2021/03/31 16:46:38 DEBUG : /file.txt: CreateEx: flags=0x502, mode=0700
2021/03/31 16:46:38 DEBUG : file.txt: Open: flags=O_RDWR|O_CREATE|O_EXCL, file= 
2021/03/31 16:46:38 DEBUG : file.txt: newRWFileHandle: file= , file.o=file.txt
2021/03/31 16:46:38 DEBUG : file.txt: >newRWFileHandle: err=file already exists
2021/03/31 16:46:38 DEBUG : file.txt: File.openRW failed: file already exists
2021/03/31 16:46:38 DEBUG : file.txt: >Open: fd= , err=file already exists
2021/03/31 16:46:38 DEBUG : /file.txt: >CreateEx: errc=-17, fh= 
```

I missed the significance of the `O_EXCL` before - it all makes sense now!
