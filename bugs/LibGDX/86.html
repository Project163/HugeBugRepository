Title

LWJGL3 windows no longer update while being resized

Description
Looks like we have a regression on our hands. Videos are by @fgnm in #6785 - that issue is closed and the callback the issue it was about is resolved. While our windows used to update when resized, they don't anymore, which looks a bit odd.

My concern is more to do with games during development than once released, as resizing your window is an excellent way of telling if UI and all that is responding to different sizes correctly.

- With a bit more dig in the issue, I'd say that probably the real fix could be the use of a different thread to handle GLFW input events.. This would also fix the issue that when dragging on Windows the rendering freeze (like explained here [URL]
- [Link: In my own repo], I fixed this issue and [Link: glfw's #2074]. The issue is that Windows starts an infinite loop during their window procedures to handle window resizing and moving -- and it starts that loop on a mousedown event on the titlebar/caption.

(I personally recommend that libgdx and glfw should not fix this unless they expose their loops to the user.)

Basically, my fix was to handle window sizing and moving directly/natively, and avoided calling Window's DefWindowProc so those infinite loops were avoided and my application loop could continue (in which, I handle window sizing/moving/etc). GLFW defers windows sizing and moving to DefWindowProc, so this issue is not their doing either... I think this behavior from DefWindowProc is a necessary evil for things to work "out of the box", but I wish their documentation would explain these things better... Anyways, I recommend you handle window sizing/moving directly/natively in a way that allows your application loop to continue. If you only care about rendering, then rendering in another can help but won't prevent the application loop from getting interrupted.

Specifically, I ended up just subclassing the window procedure. Feel free to take a look at my [Link: repo NP-Engine]. Under include/Window/Detail/Glfw, you'll find my implementation in GlfwWindow.hpp

I wrote more in the comments of [Link: glfw's #2074], so feel free to head over their for more details in case I missed something here.
