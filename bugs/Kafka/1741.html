Title

Kafka connect: error with special characters in connector name

Description
When creating a connector, if the connector name (and possibly other properties) end with a carriage return, kafka-connect will create the config but report error 

  
 cat << EOF > file-connector.json
{
   "name" :  "file-connector\r" ,
   "config" : {
     "topic" :  "kafka-connect-logs\r" ,
     "tasks.max" :  "1" ,
     "file" :  "/ var /log/ansible-confluent/connect.log" ,
     "connector.class" :  "org.apache.kafka.connect.file.FileStreamSourceConnector" 
  }
}
EOF
curl -X POST -H  "Content-Type: application/json"  -H  "Accept: application/json"  -d @file-connector.json localhost:8083/connectors

Discussion
- There is a few more special characters that cause similar behavior: %, ?, <, >, /, \, ... 

 I have blacklisted the obvious ones in the fix for   KAFKA-4930   but think that a larger discussion around naming conventions and what is and isn't allowed is probably necessary.
- sliebau  Yeah, naming is, unfortunately, difficult. Kafka topics take a pretty extremely restrictive perspective on this, see the regex that topic names are restricted to:  [URL] I'd prefer not to get quite so extreme with Connect names if possible, but it's clear some things need to be blacklisted. But it's a tricky decision. Being strict in what we allow ensures we can validate easily and we're relatively safe by default, but it is also very limiting (e.g., definitely no characters outside of ASCII). On the other hand, trying to be liberal means we'll undoubtedly have a string of patches to handle cases we didn't think of up front...
