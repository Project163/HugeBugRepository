Title

NUnit 3.0 console runner not placing test result xml in --work directory

Description
The NUnit 2.6.4 console runner would place the test result xml file in the directory defined by the /work command line argument; NUnit 3.0 appears to place the test result xml file in the current directory the console runner command is being run from. The following Powershell console output shows me running the command from the "D:\workbench\git\project name\CAT" directory with the --work directory set to "D:\workbench\git\project name\autobuild\logs\nunit". Providing just the filename for the /result argument to the Nunit 2.6.4 console runner would have the result file placed in the working directory. After upgrading to NUnit 3.0 the console runner is placing the result file in the "D:\workbench\git\project name\CAT" instead of the defined work directory. If I provide an explicit path for the --result argument the result file is being created in the xpected location.

Console Output:

```
D:\workbench\git\project name\CAT> & "D:\workbench\git\project name\CAT\packages\NUnit.Console.3.0.0-beta-4\tools\nunit-console.exe" "D:\workbench\git\project name\CAT\Project.Common.Test\bin\Release\Project.Common.Test.dll" --framework=net-4.5 --labels=off --work="D:\workbench\git\project name\autobuild\logs\nunit" --result=Project.Common.Test.xml --include="unit" --exclude="disabled"

NUnit Console Runner 3.0.5715
Copyright (C) 2014 Charlie Poole

... [Log Snipped] ...

Results (nunit3) saved as Project.Common.Test.xml
```
