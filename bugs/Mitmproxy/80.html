Title

Setting a limit in OS X builds (0.16, 0.17) crashes mitmproxy

Description
##### Steps to reproduce the problem:
1. Launch mitmproxy
2. Press "l" to enter a limit
3. Type any expression, e.g. ".*myhost.com"
##### What is the expected behavior?

For the limit to be applied to the view.
##### What went wrong?

The app crashes.
##### Any other comments?

0.16 and 0.17 crash. 0.15 works fine.

Mitmproxy Version: 0.17
Operating System: OS X 10.11.4
Discussion
- This seems to be a PyInstaller issue. The relevant part in pyparsing is:

``` python
                    try:
                        tb = sys.exc_info()[-1]
                        exc_source_line = traceback.extract_tb(tb)[-1][-1]
                        if not exc_source_line.endswith('#~@$^*)+_(&%#!=-`~;:"[]{}'):   # crashes here
                            raise
                    finally:
                        del tb
```
- Same issue on the Windows builds. :-/

The workaround is to install mitmproxy from source.
- Surprisingly, I was wrong to blame Pyinstaller.
[URL] states that `exc_source_line` may be None if the source is not available.
- You can now get 0.17.1 binaries on [URL] Thanks for reporting!
