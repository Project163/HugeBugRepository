Title

Adding a CompositeByteBuf to CompositeByteBuf reducing refCnt?

Description
Hi Guys,

Just like to clarify an implementation choice with CompositeByteBuf, especially if you add an existing CompositeByteBuf to another CompositeByteBuf.

Going through DefaultCompositeByteBuf.addComponents0(), I can see that when you add a composite A to another composite B, the one being added (A) is broken down and it's individual ByteBufs are added into B, in effect flattening the layout. (A wise choice). However just before returning the refCnt is decremented for composite A, via compositeBuf.release();

Just like to find out why that is the case, as it breaks the following usage:

```
java
// buf, buf2, buf3, buf4, buf5, buf6 are plain ByteBufs buffers
CompositeByteBuf cb = compositeBuffer();
cb.addComponents(buf, buf2, buf3);
cb.writerIndex(128 * 1024);
... [Log Snipped] ...

Long number = cb2.readLong(); // causes IllegalBufferAccessException here!
```

I would have thought adding a composite to another would have increased the refCnt, not decreased it? (I'm just trying to clarify usage semantics and design choices as there is nothing in documentation that describes or provides a rational for the behaviour I'm seeing).
Discussion
- @trustin can you take a look ?
- Let's say we added three non-composite buffers to a composite buffer:

```
CompositeBuffer buf = Unpooled.compositeBuffer();
ByteBuf c1, c2, c3;
buf.addComponents(c1, c2, c3);
```

after `addComponents()`, the reference count of `c1`, `c2`, `c3` stays same because `addComponents()` does not increase the reference count of the components.  It's because `CompositeByteBuf` assumes that the added buffer became a part of it.

Now, let's create another `CompositeByteBuf` and add `buf` to it:

```
CompositeByteBuf buf2 = Unpooled.compositeBuffer();
buf2.addComponents(buf);
```

This time, it should be interpreted that `buf` has become a part of `buf2`, and thus `buf` must be released when `buf2.release()` is called, just like it is for `c1`, `c2`, `c3` when `buf.release()` is called.

The problem is that it's not that simple because we do not keep `buf` but only keep `c1`, `c2`, `c3` in `buf2`.  `buf2.release()` will release `c1`, `c2`, and `c3`, but `buf` will not be released at all.  To fix this problem, `addComponent()` retains all components and then releases the `buf` so that the refCnt of the components stay same and a user doesn't need to worry about releasing `buf` later.

I agree this is counter-intuitive.  What could be a proper fix?

- Some other ideas:
- Instead of keeping its own reference counter in `DefaultCompositeByteBuf`, to make `retain()` and `release()` increment/decrement the reference counter of its components. The reference count of `DefaultCompositeByteBuf` could be the minimum reference count among its components.
