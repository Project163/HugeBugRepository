Title

MetaCache does not refresh MasterLeader if it gets a RemoteError

Description
(error) GetTableLocations(system_redis.redis, hash_code: NaN, 5) failed: timed out after deadline expired: GetTableLocations(system_redis.redis, hash_code: NaN, 5) passed its deadline 7313896.654s (now: 7313897.511s): Remote error (yb/rpc/outbound_call.cc:376): Service unavailable (yb/rpc/service_pool.cc:170): GetTableLocations request on yb.master.MasterService from ip_address:53662 dropped due to backpressure. The service queue is full, it has 1000 items.

Essentially, one TS kept contacting what used to be the MasterLeader, but at some point, the RPC queue got full on the Master side and it started rejecting requests and ultimately lost Leadership. A new Master became Leader, but the TS MetaCache never refreshed, because the code in the DoFinished callback in the MetaCache RPCs only does refresh for a certain class of errors (NOT_THE_LEADER, CATALOG_MANAGER_NOT_INITIALIZED, Timeout, NetworkError), of which this queue is full is not one of (RemoteError).
