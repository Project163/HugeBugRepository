Title

create-next-app puts all dependencies to `latest` instead of pinning version

Description
### Link to the code that reproduces this issue

[URL]

### To Reproduce

`pnpm create next-app`

### Current vs. Expected behavior

Current: All packages are `latest`.
Expected: Package versions should be pinned.

The reason package versions should be pinned is because, in my opinion, the job of upgrading packages should be the developer's responsibility, as the developer needs to ensure the app still works normally before upgrading any dependencies – as who knows, there could be a release where a dependency may bring breaking changes to the codebase.

- @FNogueiraIntekMedical Right now it's not yet easily doable.

When Next.js releases v13.5.4-canary.7, you can use `npx create-next-app@canary` for this.

If you want to use the stable channel, wait until v13.5.4 is released, then you can use `npx create-next-app@latest`.

If you need it right now, `npx create-next-app@13.5.2` should do the job (it will be the previous behaviour of `create-next-app`, not the changes applied in the above PR).

Note that the behaviours of `create-next-app@13.5.2` is different from the changes above:

* 13.5.2 and previous: all versions are pinned (`"react": "18.2.0"`) but all dependencies are `dependencies` (not separated to deps and devDeps – but this doesn't matter). I personally like this one the most.
* 13.5.3: everything is `latest` (`"react": "latest"`).
* 13.5.4 and later: it will be "pinned to the major version" (idk how to explain it). Basically it will be `"react": "^18"`, not `"react": "18.2.0"`.
