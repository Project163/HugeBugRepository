Title

Error handlers that are not callable outside the scope they were registered in are not handled correctly

Description
| Q                   | A
| --------------------| ---------------
| PHPUnit version     | 11.1.3
| PHP version         | 8.2.x
| Installation Method | both

#### Summary

`set_error_handler` and `set_exception_handler` do not necessarily return a callable - the PHP docs are wrong. See [URL]

Since phpunit uses both to store and then set them again in e.g. [URL] in conjunction with [URL] this leads to phpunit not working

In case this error handler originates from a dependency/outside of the project, that can't be changed and phpunit cannot be used at all

#### Current behavior

phpunit doesn't work/fatal

#### How to reproduce

See the php-doc issue for examples

#### Expected behavior

No fatal

EDIT: as a possible solution checking 
```
if (!is_callable($previousHandler) {
    // @todo report risky or something?
    break;
}
``` 

before the assignment [URL]
