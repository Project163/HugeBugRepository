Title

concatenation with NodeChildren object fails

Description
When I run the attached script (slurperFail.groovy) I get the following output: 

 class groovy.util.slurpersupport.NodeChildren 
471 U.S. 462 
 [URL]

 However, I believe that the citation (471 U.S. 462) should appear on the 3rd line as well.  I have tried many variations (e.g. with toString()) but could not get it to concatenate the 2nd element.   

 It's confusing also that "NodeChildren" is not available in the API docs, so I'm not sure what methods it has to offer, but if it would just concatenate the string I would be happy, i.e. if  

   println( it.website +' '+it.citation ) 

 would work the way it looks like it should. 

 Thanks, 
   = miles =
Discussion
- Weird, for some strange reason NodeChildren and Attributes were package protected not public. They are now public and should turn up next time we generate the javadocs.
- NodeChildren has a "plus" method which allows you to concatenate nodes. They are added lazily however and won't be visible until you stream the node back out. What you really want for your scenario is to use text() which is the sanctioned way to retrieve content. I.e.: 
  
 println it.website.text() +  ' '  + it.citation.text()
- Adding .text() made it work, sort of. 

 Oddly: adding it to the one that already displays fixes the one that didn't display, but adding it to the one that didn't display doesn't help anything (I had tried that before). 

 Puzzling.   

 i.e. 

 WORKS: println it.website.text() + ' ' = it.citation 
FAILS: println it.website + ' ' + it.citation.text() 

 I was under the impression that it would work for the Slurper result (groovy.util.slurpersupport.GPathResult) without needing to add .text(), but I guess that's false.  I seem to remember that the XmlParser result (groovy.util.Node) is stickier about it. 

 It seems cumbersome (and un-groovy) to need to add .text() all over the place.  Sometimes it's needed and sometimes it's not, but the rules don't seem very straightforward to me. 

 Anyway, thanks for the help.  I guess it wasn't a bug after all.
- OK, I will close the issue. The preferred approach is to use ".text()". You can get by without it any context that would automatically call ".toString()" which will yield the same result simple elements using  XmlSlurper . E.g. this will work: 
  
 println  '' + it.website + '  ' + it.citation
 
  
 because the  plus()  method for String will call  toString()  on its argument if it isn't a String. Also,  XmlParser  and  XmlSlurper  might give different results for  toString()  but should give the same for  text() .
