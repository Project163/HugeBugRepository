Title

celery chord task raise critical error while redis backend connection socket timeout

Description
Hi all, we found when the server read from redis backend socket timeout, part of the chord body would lost. Can anyone give some help? Following is the traceback:

```
807_Mainthread /opt/tiger/ss_lib/python_package/lib/python2.7/site-packages/celery/app/trace.py:365: RuntimeWarning: Exception raised outside body: TimeoutError('Timeout reading from socket',
Traceback (most recent call last):
  File "/opt/tiger/ss_lib/python_package/lib/python2.7/site-packages/celery/app/trace.py", line 296, in trace_task
    on_chord_part_return(task, state, R)
  File "/opt/tiger/ss_lib/python_package/lib/python2.7/site-packages/celery/backends/base.py", line 555, in on_chord_part_return
... [Log Snipped] ...
    raise TimeoutError("Timeout reading from socket")
TimeoutError: Timeout reading from socket
```
Discussion
- I guess we need to retry all redis operations here, assuming this timeout error can be recovered from.
- File "/opt/tiger/ss_lib/python_package/lib/python2.7/site-packages/celery/backends/base.py", line 555, in on_chord_part_return
    val = self.incr(key)
We found celery use a increasing key to count the number of task in a group. It doesn't satisfy idempotency and we are not sure if retry "incr(key)" will cause other problems.
- In Celery 4 the default redis socket timeout is 5 seconds, that should be raised to 120 seconds probably.

In Celery 3.1 though, I cannot see that there's any default timeout at all, but you can set one.  Did you set a timeout?
- reopen if it's still on master
