Title

Accept-Header in hibernate validator's ResteasyReactiveLocaleResolver is resolved case-sensitive

Description
### Describe the bug

According to [Link: HTTP-Standard] HTTP-header-keys are to be compared case-insensitive. in [Link: ResteasyReactiveLocaleResolver.getHeaders()] all values of the case-insensitive Headers-Map are copied in a standard HashMap. So requesting the value for a given key in this map is no longer case-insensitive.

If any Proxy (Like HA-Proxy is doing) converts given headers to lower-case (according HTTP-Standard), the ResteasyReactiveLocaleResolver will not find the given header but always return default-Locale as fallback.

### Expected behavior

ResteasyReactiveLocaleResolver resolves given _Accept-Language_ HTTP-Header to a Locale, regardles of the upper/lower-case of the given key.

### Actual behavior

lower-case HTTP-header 'accept-language' is not resolved, default locale is returned instead.
