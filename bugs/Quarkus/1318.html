Title

Enhance healthcheck exclude parameter for reactive datasource

Description
### Describe the bug

Hi,

I have a microservice with a JDBC datasource (elytron-security-jdbc) and several reactive datasources.
First of all, the healthcheck returns DOWN as a global status for reactive datasource even if everything is UP. 
The JDBC shouldn't be part of the Reactive datasource healthcheck one ...
 
Currently the exclude-healthcheck only works for JDBC datasource BUT it has no effect in my case since I also have some reactive datasources.

Im looking for a way to have a coherent healthcheck status. 
Ideally with a clean separation between jdbc and reactive datasources.




### Expected behavior

The healthcheck must provide a clean separation between jdbc and reactive datasource

### Actual behavior

The healthcheck is wrong as you can see: 

```
json
{
    "status": "DOWN",
    "checks": [
        {
... [Log Snipped] ...
    ]
}
```

"default" is a JDBC and not a Reactive datasource! 

as you can see : 

```
properties
# DB connection, needed for authentication
quarkus.datasource.db-kind=postgresql
quarkus.datasource.username=user
quarkus.datasource.password=pwd
... [Log Snipped] ...
quarkus.datasource.react.reactive.reconnect-interval=PT1M
quarkus.datasource.react.reactive.idle-timeout=PT20s
```

### How to Reproduce?

Create a microservice with the smallrye-healthcheck, elytron-security-jdbc and reactive-postgres extension.
Defines some jdbc and some reactive datasources.

try to make a helathcheck

- @geniusit  Can you try adding this to your original config?

```properties
# Disable the default reactive datasource
quarkus.datasource.reactive.enabled=false
# Disable the react JDBC datasource
quarkus.datasource.react.jdbc.enabled=false
```

When you define a datasource, both the JDBC and Reactive parts are prepared unless you explicitly disable them.
That's why, I think, you get a failing `default` reactive datasource and a failing `react` JDBC datasource in your health check.

@jmartisk @cescoffier while looking into this, I noticed that, in #13375, we got a way to exclude a datasource from health-checks. Yet the implementation for reactive datasources is missing. I'll work on it.
