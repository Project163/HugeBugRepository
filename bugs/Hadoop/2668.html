Title

Test failure as failed request body counted in byte received metric - ITestAbfsNetworkStatistics#testAbfsHttpResponseStatistics

Description
Bytes received counter increments for every request response received.  

  [URL]

 This increments even for failed requests.  

 Observed during testing done for   HADOOP-17215  . A request failed with 409 Conflict contains response body as below: 

 {"error":{"code":"PathAlreadyExists","message":"The specified path already exists.\nRequestId:c3b2c55c-b01f-0061-7b31-7b6ee3000000\nTime:2020-08-25T22:44:07.2356054Z"}} 

 The error body of 168 size is incremented in bytes_received counter.  

 This also breaks the testcase testAbfsHttpResponseStatistics.

- snvijaya , by looking at the code, it seems like I understood that when a response is processed, it would set the bytesRead in AbfsHttpOperation(Which I use as the value to increment) to the total bytes that are read else if the response is failed it would be 0 since we haven't read any data and by that, I thought the counter increment would be 0 in case the response process failed.  
 It is a bug since it doesn't account for the failed response incrementing the counter with some value. Thanks for pointing it out. 

 Also, Can you help me to understand how I can mock a response failure, I would like to add this as a test for the counters too.
