Title

Casting error or empty output when as clause is used on a bag with schema not defined

Description
Ran into an issue with where script that worked with older version of Pig failed on Pig 0.17. It was a regression caused by   PIG-2315   adding additional POCast operators when there is an AS clause. 

 A script with below lines  
  
 
G = FOREACH F GENERATE a0, org.apache.pig.test.TestFlatten$UDFWithNoOutputSchema(a0, a1, b1, bag1) as bag2;
H = FOREACH G GENERATE a0, FLATTEN(bag2) as (x1:chararray, x2: double , x3:chararray, x4: long );
 
  

 ran into this error 
  
 
ERROR 1075: Received a bytearray from the UDF or Union from two different Loaders. Cannot determine how to convert the bytearray to string  for  [x1[-1,-1]]
        at org.apache.pig.backend.hadoop.executionengine.physicalLayer.expressionOperators.POCast.getNextString(POCast.java:1125)
 
  

 It was not easily reproducible with a simple script and required a sequence of steps for the CastLineageSetter to not be able to set the LoadFunc that will provide the caster on POCast -  [URL] causing the error in  [URL]  

 User trying to rewrite the script by moving the as clause to the UDF statement instead of after FLATTEN, made the script pass. But all the bags produced were empty because casting of the bag (  [URL] ) swallowed the underlying exception and return null unlike the primitive fields which throw error. 

   
 
G = FOREACH F GENERATE a0, org.apache.pig.test.TestFlatten$UDFWithNoOutputSchema(a0, a1, b1, bag1) as bag2:{t:(a1:chararray, a2: double , a3:chararray, a4: long )};
H = FOREACH G GENERATE a0, FLATTEN(bag2);
 
  

 Also realized that this additional POCast has made the processing inefficient in general as it tries to cast everything from bytearray to the type specified in the as clause. If the UDF returned the correct type, lets say Integer the code will still try to typecast to DataByteArray, hit a ClassCastException and then will cast based on the realType   [URL] This is going to add a lot of overhead to processing when there are millions of rows.
Discussion
- Took the safer approach of setting the caster using a DefaultCaster only for the POCast introduced by the ForEachUserSchemaVisitor. It took me a lot of time trying different combinations to get a smaller reproducible script for unit test trying to narrow it down from the lengthy production script which had multiple joins with different dimension tables and group bys before the UDF that returned the bag was used. So did not get much time to debug CastLineageSetter to see why it was not able to find the LoadFunc to use for the POCast and fixing that instead. Also wasn't that familiar with that portion of the code and did not want to break anything.
- Attached   PIG-5474-2.patch     . Contains change to compare output after sorting in unit tests as they fail in Spark mode with the order being different.
