Title

clientv3/concurrency: return error in Mutex.Lock if lock were unlocked due to closed context

Description
It is better to return specific error at this place [URL]
because currently client may assume it acquired lock if error will be nil.

And even if it doesn't (because context were canceled, therefore, outer code may not do anything meaningful), outer code will call to `mtx.Unlock` second time (because it doesn't know that lock were unlocked already).
