Title

Quarkus should not assume generated sources exists

Description
### Describe the bug

do this:

```
jbang init -t qrest rest.java
jbang -Dquarkus.dev --fresh rest.java
```

which boots up the app in devmode so you have devui working etc.

Do a request (changing nothing about it) and quarkus will fail with this:

```
java.io.FileNotFoundException: /var/folders/rb/jl238yks5xg62d0brw32jbd40000gn/T/quarkus-jbang13907878571349382093/target/generated-sources/annotations: does not exist
	at jdk.compiler/com.sun.tools.javac.file.Locations$BasicLocationHandler.checkDirectory(Locations.java:560)
	at jdk.compiler/com.sun.tools.javac.file.Locations$BasicLocationHandler.checkSingletonDirectory(Locations.java:553)
	at jdk.compiler/com.sun.tools.javac.file.Locations$OutputLocationHandler.setPaths(Locations.java:616)
	at jdk.compiler/com.sun.tools.javac.file.Locations.setLocation(Locations.java:2156)
... [Log Snipped] ...
	at io.quarkus.deployment.dev.filesystem.QuarkusFileManager.<init>(QuarkusFileManager.java:30)
	... 21 more
```

and yes, its true - that folder does not exist - it probably should but it shouldn't fail hard on it missing.

related to [URL] where the "fix" was to force create it no matter if needed/used or not - which does not work here.
