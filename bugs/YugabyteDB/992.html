Title

[DocDB] PgTableRow::SetValue encodes an extra byte for variable length datums

Description
Jira Link: [Link: DB-6994]
### Description

The column data serialized in YSQL wire format consists of 2 parts, `PgWireDataHeader` and the data. `PgTableRow::SetValue` currently skips this header for fixed length datums , but does not skip the header when pointing to a variable length datum.

An example:

```
(gdb) p value
$2 = (const yb::dockv::PgValue &) @ : {value_ = 24282667259112}
(gdb) xxd value.value_ 20
 : 0000 0000 0000 0000 0972 656c 6174 696f  .........relatio
 : 6e00 0000                                n...
```

In a variable length datum the `PgWireDataHeader` is encoded as the first byte to the buffer, followed by a wire encoded `uint64_t` to specify the length of the datum. Here you can see that the length (9 bytes) is 9 bytes after the start of the `PgValue`. In order to align to the wire encoded `uint64_t`, the `PgValue should point to  .

```
(gdb) xxd value.value_ 9
 : 0000 0000 0000 0000 09                   .........
```

```
(gdb) xxd value.value_+9 9
 : 7265 6c61 7469 6f6e 00                   relation.
```
