Title

Bug: ESLint can crash when a source directory is deleted while it runs

Description
### Environment

Node version: v20.12.2
npm version: v10.8.1
Local ESLint version: v9.4.0 (Currently used)
Global ESLint version: Not found
Operating System: win32 10.0.22000

### What parser are you using?

@typescript-eslint/parser

### What did you do?

We have lot of parallel tasks happening on CI, one of those being eslint and another - a build that uses `proper-lockfile` package to create a lock directory. If the lock is released at the same time as `eslint` walks the directory gathering the source files, eslint will crash. See #18952 for details where the crash originates (just that the PR was made just before the fswalk dependency was changed).

### What did you expect to happen?

A directory vanishing while the fs walk is done shouldn't crash the process - seem logical that the walk process will ignore such case.

### What actually happened?

```
Oops! Something went wrong! :(
ESLint: 9.4.0
Error: ENOENT: no such file or directory, scandir '/builds/path/to/the/directory.lock'
```

### Additional comments

I was able to reproduce the issue by doing

```
while (true) {
    mkdir("src/foo.lock");
    sleep(100ms);
    rmdir("src/foo.lock");
    sleep(100ms);
}
```

with this running in background, the eslint process in my big monorepo crashed around every 4th time.
