Title

[YSQL] INSERT ON CONFLICT produces wrong results with generated col arbiter index

Description
Jira Link: [Link: DB-13705]
### Description

Consider the follow table definition
```
CREATE TABLE varlen (t text, b bytea GENERATED ALWAYS AS (bytea(t)) STORED, UNIQUE (t));
CREATE UNIQUE INDEX ON varlen (b);

-- Insert one row
INSERT INTO varlen VALUES ('a');
```

The following query produces wrong results.
```
INSERT INTO varlen VALUES ('a'), ('a') ON CONFLICT (b) DO UPDATE SET t = 'b';
```

The correct behavior (in vanilla PG 15) is as follows:
```
postgres=# INSERT INTO varlen VALUES ('a'), ('a') ON CONFLICT (b) DO UPDATE SET t = 'b';
INSERT 0 2
postgres=# SELECT * FROM varlen;
 t |  b
---+------
 b | \x62
 a | \x61
(2 rows)

```

In master, with INSERT ON CONFLICT batching **enabled**, the following wrong error is produced:
```
yugabyte=# SET yb_insert_on_conflict_read_batch_size TO 1024;
yugabyte=# INSERT INTO varlen VALUES ('a'), ('a') ON CONFLICT (b)
[more] - > DO UPDATE SET t = 'b';
ERROR:  23505: duplicate key value violates unique constraint "varlen_t_key"
LOCATION:  pg_perform_future.cc:35
Time: 34.063 ms
```

In master, with INSERT ON CONFLICT batching **disabled**, the following wrong result is produced:
```
yugabyte=# SET yb_insert_on_conflict_read_batch_size TO 1;
yugabyte=# INSERT INTO varlen VALUES ('a'), ('a') ON CONFLICT (b)
DO UPDATE SET t = 'b';
INSERT 0 2
Time: 25.848 ms
... [Log Snipped] ...
 b | \x62
(1 row)
```
