Title

[bug] On Windows, app hangs when creating a new window in a non-async Tauri command

Description
### Describe the bug

Creating this off the heels of #3883 - I noticed that the app hangs if I do window operations in a non-async Tauri command on Windows. Making the command `async` fixes the problem.

This is the command that hangs:
```
rust
#[tauri::command]
pub fn open_activation_window(app: tauri::AppHandle) {
    if let Some(window) = app.get_window(ACTIVATION_WINDOW_LABEL) {
        let _ = window.set_focus();
... [Log Snipped] ...
    }
}
```

This version of it works:
```
rust
#[tauri::command]
pub async fn open_activation_window(app: tauri::AppHandle) -> Result  {
    if let Some(window) = app.get_window(ACTIVATION_WINDOW_LABEL) {
        let _ = window.set_focus();
... [Log Snipped] ...
    Ok(())
}
```

### Reproduction

- Create a Tauri app that includes that includes the non-async `open_activation_window` command.
- Invoke that command from JS

### Expected behavior

It should open the window. And according to Lucas, it should be able to do this on the main thread.

Discussion
- We'll need to revert this fix because it brings more issues than benefits, for now just use an async command until we can fix this either in tao or in Webview2.
- @lucasfernog  if i use async command, this will bring new problem in macos,

I use [Link: window-vibrancy] to create a vibrant window in async command.

Then, i get an panick : `"\"apply_vibrancy()\" can only be used on the main thread."`, it seems that asynchronous commands cannot be used in this case.

I can only judge different environments in js and send different commands to achieve this effect.
- @lanten I ended up working around this by having 2 versions of my commands with some `#cfg` flags to enable one on Windows and the other on Mac. Something like this:

```
rust
#[cfg(windows)]
#[tauri::command]
pub async fn is_overlay_hidden(overlay: State ) -> Result  {
    Ok(overlay.is_hidden())
... [Log Snipped] ...
    Ok(overlay.is_hidden())
}
```

This way the UI can call the same function on both platforms.

I'm only targeting Win + Mac right now and technically this would use the non-async function on linux too. I've no idea what actually needs to happen on Linux with this though. Just a heads up if it matters for your case!
- @dceddia  This is a valid temporary solution, it works well for me. thank you!
