Title

Returning location from POST does not set 3xx status code

Description
### Describe the bug

When returning a `location` path from a `+page.server.ts` sveltekit set status as 200, and does not perform a redirect.

The problem is located in `packages/kit/src/runtime/server/page/index.js` at 81:38

```ts
return redirect_response(status, result.location);
```

where status is not changed from 200 (at 57:5)

```ts
let status = 200;
```

I'd be willing to submit a PR to fix this issue.

### Reproduction

[URL]

The page contains two buttons:
- Submit form with `throw redirect()`
- Submit form with `location`

Discussion
- Feel free to open a PR! This should probably be a 302
- Especially since it's in response to a POST, we should probably take a stand here and make a conscious decision between 303 and 307, rather than just a 302. A 302 is, in practice, treated as a 303, so I'd be in favor of using a 303.
- Looks like this was merged 2 minutes ago, but I do wonder if 307 might be nicer at least in dev mode. When developing multiple apps it's really annoying to have redirects cached
- 303 vs 307 is whether the POSTs turn into GETs upon redirection, or whether the new URL is also POSTed to. Neither of them is 301 Moved Permanently.
