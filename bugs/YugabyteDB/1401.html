Title

[YSQL] EXPLAIN catalog read request incorrect for first query

Description
Jira Link: [Link: DB-17629]
### Description

Using session parameter (GUC) `yb_debug_log_docdb_requests=on`, one can see the number of read flushes does not match `EXPLAIN (ANALYZE, DIST)`'s `Catalog Read Requests`.  This is due to catalog prefetching/preloading at connection startup getting counted.

```
bin/yb-ctl start --ysql_pg_conf_csv yb_debug_log_docdb_requests=on --tserver_flags vmodule=pg_session=2 && sleep 3 && bin/ysqlsh
```

```sql
create table rrr (r1 int, r2 int, r3 int, n int, primary key (r1 asc, r2, r3)) split at values ((0, 1), (1), (1, 1), (2), (2, 1));
```

exit ysqlsh, then reconnect (for fresh cache), then run:

```sql
explain (analyze, dist, debug) select * from rrr where r1 in (0, 1, 2) order by r2 limit 2;
```

It gives `Catalog Read Requests: 73` and `Metric ql_read_latency: sum: 1194, count: 8`.  Logs show 76 `vlog2: Apply`, 6 of which are for the table, 1 catalog lookup which is after EXPLAIN ANALYZE.  So it should say 69 catalog read requests.
