Title

Coordinator should return illegal generation for commits from unknown groups with non-negative generation

Description
Currently the consumer coordinator accepts offset commits blindly if it has no state stored for the associated groupId. This means that upon coordinator failover, offset commits from any member of a group will be accepted, even if that member is from an older generation. A better way of handling this case would be to return an ILLEGAL_GENERATION error when the generation in the commit request is greater than or equal to 0. Consumers that are not using group management will always send a generation of -1, so their commits will still be accepted as valid.
