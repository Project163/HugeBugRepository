Title

Unexpected remove behavior when useForm is shared between a Controller and the useFieldArray hook

Description
**Describe the bug**
When creating a form with the useForm hook and sharing using it in both a useFieldArray hook and a Controller component the behavior for the `remove` method gets a little weird, it seems like it tries deleting the wrong item from the value references and when one of the values is null it throws an Error because of a null access.

**To Reproduce**
Steps to reproduce the behavior:

1. Create a form using the useForm hook
2. Create a new form field using a Controller component
3. Create a new array field with useFieldArray
4. Trigger a `remove` call and if one of the keys is null/undefined it'll throw an array access error

**Codesandbox link (Required)**
[URL]

**Expected behavior**
It should remove the triggered item from the useFieldArray hook

**Additional context**
We could've missed something in the docs regarding sharing the form control between the two but this seems like an unintended side effect from using the controller
