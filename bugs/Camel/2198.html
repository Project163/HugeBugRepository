Title

step in a block runs when the tag is closed in the wrong place

Description
Example route: 

 <doTry> 
   <to ... > 
</doTry> 

 <doCatch> 
    <exception>java.lang.Exception</exception> 
    <to uri="log.... "/> 
</doCatch> 

 The <to uri="log..."/> line will execute every time, regardless if there is an exception or not. 

 I believe the preferred behavior would be that the route should fails to load/validate.  Alternatively, the <to uri="log.." /> should not run when there is not an exception. 

 Thanks!
Discussion
- The doCatch should be  inside  the doTry, as documented in its documentation:  [URL]
- On 2nd though lets add validation to the Camel model so we can detect the mis configuration of having doCatch outside doTry etc. Then we can tell the end user about this mis configuration so they can fix it.
- Thanks, Claus. The syntax check to alert users to the incorrect configuration was what I was hoping for.  

 It can be a little confusing since for users coming from a plain Java coding background. When programming plain Java code the try {} closes before the catch {} opens. 

 Thanks!
