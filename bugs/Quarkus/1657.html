Title

Qute parsing issue

Description
### Describe the bug

This is valid qute template with custom tag
```html
{#textInput field="username" label="Username"}
```
Same template with spaces around equal sign is not valid
```html
{#textInput field = "username" label = "Username"}
```

It is producing 3 really hard to understand errors
```

... [Log Snipped] ...
```

Discussion
- Well, at the moment section parameters are whitespace-separated chunks where the equals sign is used to identify the optional name of a param.

I.e. for `{#textInput field="username" label="Username"}`  the `SectionHelperFactory` for `textInput` receives two params. The first has a name `field` and the value is `"username"`. The second has name `label` and value `"Username"`. For `{#textInput field = "username" label = "Username"}` however, 6 params are parsed: [`field`, `=`, `"username"`, `label`, `=`, `"Username"`]. Also round brackets can be used to group several chunks (such as `{#if (item.active || item.sold) && item.enabled}`).

The `SectionHelperFactory` is then allowed to interpret these params in any way it needs to. So for example the `#if` section has a complex logic to turn the list of params into a condition.

Now back to the problem. I do agree that the error message is confusing. And in this particular case the parser should be more lenient. We could probably treat the equals sign specially so that `field = "username"` is parsed as `field="username"`. It would not be backward compatible but it shouldn't be a problem in most cases.
