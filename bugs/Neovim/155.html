Title

Allow :lmap and 'keymap' translations during macro replay

Description
As documented in `:help language-mapping`, `:lmap` mappings are never applied to already mapped characters, so that:
```
:set iminsert=1 
:lnoremap a l 
:nmap x iaaa 
x
```
inserts `aaa` into the buffer.

The way this is implemented means that macros ignore these :lmap mappings too, which is not intuitive, as then replaying a macro acts differently to what happened when recording it.

```
:set iminsert=1 
:lnoremap a l 
qaiaaa  q@a
```

You see two lines in the file, the first one is `lll` and the second one is `aaa`.
Similar happens for search patterns when 'imsearch' is either -1 or 1, and also for f/F t/T.

If you do the same with an :imap you get two lines of lll, I believe it would be less surprising if :lmap and 'keymap' follow this behaviour.
