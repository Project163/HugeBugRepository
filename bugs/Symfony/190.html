Title

Inconsistent verb mood in command options and descriptions

Description
**Symfony version(s) affected**: dev-master

**Description**  
Built-in Symfony options and commands, such as in the Console and Framework Bundle, use inconsistent mood in option and command descriptions.

**How to reproduce**  
Look at the option and command descriptions in [Link: AssetsInstallCommand.php] and [Link: HelpCommand.php], just for example.
```
Options:
  -h, --help            Display this help message
  -q, --quiet           Do not output any message
...
  --symlink             Symlinks the assets instead of copying it
... [Log Snipped] ...
...
  assets:install        Installs bundles web assets under a public directory
```
Note that some verbs are in the indicative mood ("Symlink**s**") and some are imperative ("Display").

This is not only grammatically inconsistent, but the inconsistency makes it difficult for downstream projects to choose a consistent standard when implementing commands.

**Possible Solution**  
Reword all command options and descriptions to use a consistent mood, ideally the imperative mood (no trailing "s") since that's more concise, matches the commands themselves, and is in line with what I tend to see for other more traditional frameworks and commands (such as Unix man pages), and [Link: random internet people] seem to prefer it. But I don't really care as long as it's consistent.

Bonus points for declaring this along with rationale in a Symfony style guide or documentation.
