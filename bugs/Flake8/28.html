Title

Output file is emtpied when error reporting starts, removing any previously recorded logging

Description
In GitLab by @FichteFoll on Jul 26, 2016, 18:51

3.0.1 (mccabe: 0.5.0, pycodestyle: 2.0.0, pyflakes: 1.2.3) CPython 3.5.0 on Windows

When providing an output file argument (`--output-file`) and at least one `-v` for logging, the output file is emptied and any logging that occured before that is lost entirely. This makes the fact that logging is redirected to the file pretty much useless since most of it is lost.

What I suggest is to either

1. not clear the file when output starts being written but when the `FileHandler` is created,
1. not redirect logging to the output file, or
1. add a `--log-file` parameter that will be the target of a `FileHandler` if provided, stdout otherwise.
