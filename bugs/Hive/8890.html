Title

PARTITION_NAME_WHITELIST_PATTERN is not honouring session level configuration

Description
Steps to repro (ensure  metastore.partition.name.whitelist.pattern  or  hive.metastore.partition.name.whitelist.pattern  is not present in hive-site.xml): 
  
 
set metaconf:metastore.partition.name.whitelist.pattern=[^9]*;

create table t1 (id  int ) partitioned by (pcol string);
alter table t1 add partition (pCol= '2025-06-09' ); 
  
  What is happening:   Query is passing.  

   

  The expect outcome should be   
  
 
Error: Error  while  compiling statement: FAILED: Execution Error,  return  code 40000 from org. apache.hadoop.hive.ql.ddl.DDLTask. MetaException(message:Partition value  ' 2025-06-09'  contains a character not matched by whitelist pattern  '[^9]*' . (configure with metastore.partition.name.whitelist.pattern)); Query ID: raghav_20250703214
146_1fcab256-2425-4e9e-8ac0-ec2d53e2d1b0 (state=08S01, code=40000)
Discussion
- Based on the initial debugging: 
PARTITION_NAME_WHITELIST_PATTERN is part of metaConfVars i.e part of config list that can be updated in a beeline session using 
  
 
set metaconf:metastore.partition.name.whitelist.pattern=value; 
  
  HMSHandler.partitionValidationPattern  field is initialized in init() method and there is no way to update it, if user set the config in session level.
- Attaching the repro case and a possible patch here.
- CC  dengzh   dkuzmenko  , can you please take a look? I also have a follow up question. I believe there is another issue as well related to metaConfVars in general: 

 The value of metaconf is getting reset post running any meta-operation. Attaching screenshot in attachments for the same.  The modified value of config should persist in the same beeline session?  I believe the  
 HMSHandler#notifyMetaListenersOnShutDown  is why this behaviour is because of ThreadLocal. Is it the expected behaviour in hive4 because the same is not happening in hive3.
- Merged to master 

 Thanks for the fix,  Aggarwal_Raghav  !
