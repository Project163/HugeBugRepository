Title

Hibernate ORM: Schema is not generated

Description
Hey, we are playing around with quarkus. First: Thank you for your work, I like it very much.

Here is my bug:
**Describe the bug**
I noticed, that, when using a schema in an entity, hibernate orm does not create the schema which is used in @Table Annotation, even if you use create/drop-and-create as strategy.
following error are, that tables cannot be created, because there is no such given schema.

**Expected behavior**
Schema should be created before creating the tables.

**Actual behavior**
Schema is not created.
Error: Caused by: org.postgresql.util.PSQLException: ERROR: schema "myschema" does not exist when hibernate tries to create a table.


**To Reproduce**
Steps to reproduce the behavior:
1. clone the [URL]
2. go the Fruit Entity and schema to @Table 
3. add the schema to the import.sql
4. Run the *Test class

**Environment (please complete the following information):**
 - Quarkus version or git rev: 1.7.1, also tried for 1.6.1
 - Build tool (ie. output of `mvnw --version` or `gradlew --version`): maven


Thanks, guys!

- To summarize a couple of things about this functionality:

1. Schema creation only happens if you set `javax.persistence.create-database-schemas=true`.
2. According to the JPA spec, apparently, it only happens if you explicitly set the schema of all your entities using `@Table(name="foo", schema="bar")`, which is pretty sucky.
3. But Hibernate has a better way which is to set `hibernate.default_schema`. Fortunately Quarkus exposes this already as `quarkus.hibernate-orm.database.default-schema`.
4. Schema creation does work on Postgres, but I question how many databases it really works on. It doesn't work on MySQL or DB2.
5. You can automatically create the catalog on (only) MySQL, however. (Exposed in Quarkus as `quarkus.hibernate-orm.database.default-catalog`.)

So if we expose `quarkus.hibernate-orm.database.generation.create-namespaces`, we are good, I think.

By the way, I don't love the way the schema export settings are grouped under "database". We're not generating a database, we're inferring and exporting a schema _to_ the database.
