Title

.renderFile() callback called twice if it throws

Description
[URL]
`.renderFile()` wraps a `.render()` call in a try/catch block, invoking the callback if anything is caught.

[URL]
`.render()` wraps a `.compile()` call in a try/catch block, invoking the callback if anything is caught.

If an error is caught in `.render()` (such as a template syntax error), the callback is invoked with this error. However, as the callback is invoked immediately rather than deferred, any errors it might throw are caught by the try/catch block in `.renderFile()` which invokes the same callback with the error it just threw.

Might I suggest wrapping the callback invocation in a `setImmediate()` or `process.nextTick()`?
Discussion
- Upon further investigation, a better fix might be to replace `fs.readFileSync()` with `fs.readFile()` in `.renderFile()` and handle any errors in the callback, removing the need for a try/catch.
- we can just move the fn() out of the **try**, and wrap it below. This is a bit of a fundamental flaw in all node programs, you either invoke the callback again, or the error is lost in limbo, or completely breaks your app
