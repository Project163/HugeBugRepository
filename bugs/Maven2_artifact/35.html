Title

Transitive dependencies with system scope and version range trying to be downloaded

Description
<dependency> 
      <groupId>java</groupId> 
      <artifactId>tools</artifactId> 
      <version>[1.4,1.5)</version> 
      <systemPath>${java.home}/../lib/tools.jar</systemPath> 
      <scope>system</scope> 
    </dependency> 

 If this dependency is present maven tries to download from the repo 

 No versions are present in the repository for the artifact with a range [1.4,1.5) 
  java:tools:null:jar
Discussion
- hmm, bring up an interesting point: 

 How can we determine the actual version of a system-scoped dependency?
- it doesn't make sense to have a version range for a system-scoped dependency, unless you can check the version of the artifact on the system for a match. Since we can't reliably do this, I'm disabling version-range checking for system-scoped deps, and using either the recommendedVersion or "unknown" for cases where getVersion() == null. 

 It's beginning to be apparent that system-scoped deps are a wrong decision. I think we'll start phasing them out when we have better spec-dependency support...they represent too many questions that fall outside the main framework of maven, and I believe they're unnecessary.
