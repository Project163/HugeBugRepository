Title

boost-exception:x64-android build failure

Description
**Host Environment**
- Arch Linux
- Compiler: Android NDK 21.0.6113669 (clang)

**To Reproduce**
Steps to reproduce the behavior:
- Create a triplet file with the below contents:

```
set(VCPKG_TARGET_ARCHITECTURE x64)
set(VCPKG_CRT_LINKAGE dynamic)
set(VCPKG_LIBRARY_LINKAGE static)
set(VCPKG_CMAKE_SYSTEM_NAME Android)
```
- Then run: `./vcpkg --triplet x64-android install boost-exception`

Discussion
- clang++: **error**: no such file or directory: 'x86_64-none-linux-android21'

API - android21 - 21 ?
- Yes, I am using 21.0.6113669 from Android Studio.
- I repro the same error on a Windows 10 host environment. It looks like the wrong clang `--target` command-line is being built into the `user-config.jam`. Clang wants `--target= ` but `--target=  ` is being passed (i.e. extra space after the `=`). It looks like [Link: `ports/boost-modular-build-helper/CMakeLists.txt`] is responsible for specifying the target:

```
    set(CXXFLAGS "${CXXFLAGS}  ${CMAKE_CXX_COMPILE_OPTIONS_TARGET}  ${CMAKE_CXX_COMPILER_TARGET}")
```

Which appears to be how gcc expects the target to be passed. So adding a check for Clang, and passing the target in a Clang-like way fixes things for me, i.e.

```
if(CMAKE_CXX_COMPILER_TARGET)
    if(CMAKE_CXX_COMPILER_ID STREQUAL "Clang")
        set(CXXFLAGS "${CXXFLAGS}  ${CMAKE_CXX_COMPILE_OPTIONS_TARGET}${CMAKE_CXX_COMPILER_TARGET}")
    else()
        set(CXXFLAGS "${CXXFLAGS}  ${CMAKE_CXX_COMPILE_OPTIONS_TARGET}  ${CMAKE_CXX_COMPILER_TARGET}")
    endif()
endif()
```

But I'm a bit out of my depth here - so it's not clear if this is the Right Thing to do.
