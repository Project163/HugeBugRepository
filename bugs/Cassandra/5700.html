- As shown in the error in the description,  we're occasionally bumping into coordinator timeouts, which are  set to a smaller value  by the test. I assume they were set lower to make the test timeout faster when we are  expecting a failure . However, simply raising them then causes the test to occasionally fail in a different way ( Failure  instead of  Timeout ) if the node shutdown occurs mid-request. 

 I'm pushing a potential patch that makes sure the coordinator sees the node as down, then expects an  UnavailableException . I'm not sure if/why the  Timeout  exception would be essential to this test, but if that is preferred we could look at another technique of inducing the timeout deterministically without making it cause flakiness.
