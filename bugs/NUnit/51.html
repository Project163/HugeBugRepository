Title

AsyncTestMethodTests for 4.5 Framework fails frequently on Travis CI

Description
The following test fails frequently on Travis. We should investigate and fix if possible.

```
1) Failed : NUnit.Framework.Internal.AsyncTestMethodTests.RunTests(System.Threading.Tasks.Task NestedAsyncTaskSuccess(),Passed,1)
          Wrong assertion count
          Expected: 1
          But was:  0
        at NUnit.Framework.Internal.AsyncTestMethodTests.RunTests (System.Reflection.MethodInfo method, NUnit.Framework.Interfaces.ResultState resultState, Int32 assertionCount) [ ] in  :0
```
Discussion
- I looked at the code for this and I cannot see anything wrong. I am wondering if it is a bug in async support in the version of mono Travis is running? 

If the line before the assert is not blocking in an await like we expect and it is just passing on other systems because of timing, then it is serious, so I am going to leave this open, but move it out so that I can look at it more closely when I have more time.
- I was able to reproduce this in Android very rarely. I have been debugging through it repeatedly and still can't see anything wrong with our code. I think it is only happening with nested async calls. If anything, the problem is in `AsyncInvocationRegion.WaitForPendingOperationsToComplete`, but every time I step through it, it behaves as expected.

I am giving up on this one for now. I am going to remove myself as the Assignee so someone else can take a crack if they want and I am going to move it out of this milestone.
