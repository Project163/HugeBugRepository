Title

mypy crashes when run from a directory without write access

Description
Mypy shouldn't write cache files for code supplied on the command line.  Additionally, if you don't have write access to the directory, mypy will crash.
Discussion
- The command line is treated as a module named `__main__` and I don't see any evidence that cache files are written for that name.

However the crash is real: in a directory with no write permission:
```
(v36) guido-mbp:tmp guido$ PYTHONPATH=.. python3 -m mypy -c pass
Traceback (most recent call last):
  File "/usr/local/lib/python3.6/runpy.py", line 193, in _run_module_as_main
    "__main__", mod_spec)
  File "/usr/local/lib/python3.6/runpy.py", line 85, in _run_code
... [Log Snipped] ...
    mkdir(name, mode)
PermissionError: [Errno 13] Permission denied: '.mypy_cache'
```
- (To be clear, I think it's a feature that it tries to write cache files for modules *imported* from the command line.)
- ... [Middle Discussions Snipped for Brevity] ...
- I think we should also never write cache files when running with `-c`.
- After talking f2f, I don't have any strong objections about writing the cache with `-c` in the absence of user complaints.  Let's limit this issue to the problem of mypy crashing when it doesn't have write access to the current directory.
