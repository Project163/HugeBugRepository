Title

The parser/type checker should use the getSchema method of UDFs to deduce return type/schema

Description
Currently, the parser/type checker uses the getReturnType to deduce the return type of the user defined function (UDF). This mechanism is satisfactory only for basic types (int, long, ...); for composite types (tuple, bag), the schema is also required.The abstract class EvalFunc interface exposes the outputSchema to deduce the return type/schema of the UDF. The parser/type checker should use this method to figure out the return type/schema of the UDF and use it appropriately.
Discussion
- The patch udf_outputSchema.patch adds the following: 

 1. The type checker uses the outputSchema method in EvalFunc to deduce the output schema of the UDF 

 2. The TestEvalPipeline.java:testBagFunctionWithFlattening passes the unit test cases with the addition of outputSchema method to the UDFs used inside the test case 

 3. Adds resetSchema method to relational operators that rely on nested plans to compute schemas. 

 4. Resets schema of all the relational operators in the type checker to ensure correctness of the computed schema due to changes in the inputs of the operators.
