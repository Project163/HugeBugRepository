Title

Helm Dep List is returning "missing" for deps on packaged charts

Description
Output of `helm version`:

```console
$ helm version --client
Client: &version.Version{SemVer:"v2.10.0-rc.2", GitCommit:" ", GitTreeState:"dirty"}
```

Output of `kubectl version`:

N/A -- this is client only

Cloud Provider/Platform (AKS, GKE, Minikube etc.):  N/A

Fetch the wordpress chart: `helm fetch stable/wordpress`

```console
$ helm dep list ./wordpress-2.1.5.tgz 
NAME   	VERSION	REPOSITORY                                       	STATUS
mariadb	4.x.x  	[URL]	missing
```

Status is `missing`. But the dependency is in the tarball. Unpack the chart, and this is evident:

```
console
$ tar -zxvf wordpress-2.1.5.tgz
x wordpress/Chart.yaml
x wordpress/values.yaml
x wordpress/templates/NOTES.txt
... [Log Snipped] ...
NAME   	VERSION	REPOSITORY                                       	STATUS
mariadb	4.x.x  	[URL]	unpacked
```
Discussion
- For those of us who plan to consume the output of `helm dep list` programmatically, what is the expected behaviour here - can we still assume there will be a `STATUS` field, or is that likely to be omitted on packaged charts?
- Still an issue in 3.1. It would be nice to update the documentation  (this part: `This can take chart archives and chart directories as input. It will not alter the contents of a chart.`) and mention, that in case of archives "STATUS" is always "missing".
