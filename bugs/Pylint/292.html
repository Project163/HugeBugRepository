Title

Excepting asyncio.CancelledError before broader exceptions causes try-except-raise warning

Description
Pylint seems to not trust the pedigree of [Link: `asyncio.CancelledError`] and doesn't recognize it as a subclass of an exception in a later block. Notably, if you implement code seen in the docs, pylint will flag it:


### Steps to reproduce
```
import asyncio
import concurrent

def ter1():
    try:
... [Log Snipped] ...

assert asyncio.CancelledError is concurrent.futures.CancelledError
```

Those two exceptions are identical in 3.7, asyncio [Link: borrows it here].  In 3.8-dev/master CPython it's [Link: been subclassed], so maybe the behavior will change.

### Current behavior
```
$ pylint tryexceptraise.py
************* Module tryexceptraise
tryexceptraise.py:7:4: W0706: The except handler raises immediately (try-except-raise)

------------------------------------------------------------------
... [Log Snipped] ...
$ python tryexceptraise.py
$ # assert is OK
```

### Expected behavior
No try-except-raise warning. I thought this was related to #2484 but I wasn't able to get it to fire with any naive user-defined exception gymnastics, i.e. the below all lints OK:

```
class ParentException(Exception):
    pass
class ChildException(ParentException):
    pass
ChildAliasException = ChildException  
... [Log Snipped] ...
    except ParentException:
        pass
```

