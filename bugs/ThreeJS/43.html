Title

Broken webgl_lights_hemisphere.html

Description
Hitting both `h` and `d` turns off the lights completely.
Discussion
- That's how it should be ;)

It does what it says:

```
press h to toggle hemisphere light, d to toggle directional light
```
- My description was ambiguous. This is what I meant:

Hitting `h` turns off all lights.
Hitting `d` turns off all lights.
- ... [Middle Discussions Snipped for Brevity] ...
- So I had a look and it's weird. It seems to be caused by having zero position vector (setting `light.visible = false` zeroes all light uniforms). 

Now the strange part is how differently ANGLE and OpenGL respond to these zeroes:
- sending zeroes from GL uniforms API in ANGLE makes no problems
- sending zeroes from GL uniforms API in OpenGL makes whole pixel black (independently of other operations in shader, this is what @mrdoob observed)
- setting zeros directly in shader in ANGLE makes shader compilation error
- setting zeroes directly in shader in OpenGL makes no problems

A simple workaround for this particular example is just not setting zeroes to position when the light is disabled, but that still leaves mysterious pixel failure if somebody sets zero position to directional / hemisphere light on purpose.

I'll try to find some workaround.
- Ok, should be fixed now. Thanks for finding this, we caught another weird OpenGL vs DirectX edge case.
