Title

Server HTTP Chunked Response Problems

Description
I'm using the latest CR2 snapshot (https://oss.sonatype.org/content/repositories/snapshots/io/netty/netty-all/4.0.0.CR2-SNAPSHOT/netty-all-4.0.0.CR2-20130416.025657-86.jar) and I have a server that is responding with a chunked transfer response. This is all done over ssl. 

I'm sending out:
1. A `DefaultHttpResponse` (with transfer-encoding: chunked)
2. A `DefaultHttpContent`
3. Another `DefaultHttpContent`
4. And finally a `DefaultLastHttpContent`

What I'm seeing with tcpdump/wireshark however is that both 1 and 2 are sent out, but the others are not.

The secondary issue that I'm seeing is that (possibly related) is that there is actually about a 5  second delay between 1 and 2, however, wireshark is showing that the data is only output when 2 is written out. Setting TCP_NODELAY had no impact.

Looking through `HttpContentEncoder::encode`, I'm still not seeing how a DefaultHttpResponse with a status of 200 will ever be output by itself. It needs to see a HttpContent before it will output it.

This is actually a migration of a server from netty 3.5 to netty 4, and I didn't see this behavior using the _chunked_ classes in netty 3.5.

Let me know if there is more information I can provide to help debug this issue and/or break this up into two separate issues.

Thanks,
Senthil.
