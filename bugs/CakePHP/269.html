Title

3.0.4 - Associations now can't call Table::table without erroring out

Description
Hi guys. I have a master `Table` that my Tables extend. That class overrides Cake's `Table::table`, since my plugins can't associate with each other unless they have the full DB address.

```
public function table($table = null)
{
    if ($table === null) {
        $conn = ConnectionManager::config($this->defaultConnectionName());
        $table = parent::table();
... [Log Snipped] ...
    return parent::table($table);
}
```

Table1..

```
$this->addAssociations([
    'hasMany' => [
        'Vendor/Plugin.TableAlias2'
    ]
]);
```

Then..

```
$sections = $table1->find()->contain(['TableAlias2']);
```

Errors out with:
`"SQLSTATE[42S22]: Column not found: 1054 Unknown column 'TableAlias2.database_name.foreign_key' in where clause"`

3.0.3 works without any problems. It looks like the change in `ExternalAssociationTrait` for foreignKeys did this. Changing it back to this works:

```
public function foreignKey($key = null)
{
...
            $this->_foreignKey = $this->_modelKey($this->source()->alias());
...
}
```

The return from `MySuperTable::table` is always right. I'm not sure what part of the core is adding the funky table alias directly to the SQL. If a `Table` calls `Table::table`, I'd expect the SQL that queries use would use that table, and not try to reconstruct it at another point. Not sure what that change in the core is for so I don't know if I should try to debug as it stands or change that back..?

Thanks
