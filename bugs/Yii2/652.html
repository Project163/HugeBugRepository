Title

ArrayHelper::merge() replaces NULL with value from latter array (or should it?)

Description
### What steps will reproduce the problem?
        $array1 = [
            1,
            null,
            3,
            null
        ];

        $array2 = [
            'a',
            'b'
        ];

        $array3 = [
            null,
            null,
            'c',
            'd'
        ];

        print_r(ArrayHelper::merge($array1, $array2, $array3));

### What is the expected result?
This is a result produces from array_merge() PHP native function

### What do you get instead?
The function replaces `NULL` with with value from latter array. So `$array1[1]` gets replaced by `$array2[1]`.

### Possible cause ###
In `BaseArrayHelper::merge()`, on line 128 - 134.

                } elseif (is_int($k)) {
                    if (isset($res[$k])) {
                        $res[] = $v;
                    } else {
                        $res[$k] = $v;
                    }
                }

`isset()` will return `FALSE` on `NULL`. So if the former array has a `NULL` value, it will replace it with the value from the latter array.

However, from the description of the function

So these means the integer-keyed elements will always get appending. Unless it is not yet defined.

The code can be changed code into something like:

                } elseif (is_int($k)) {
                    if (array_key_exists($k, $res)) {
                        $res[] = $v;
                    } else {
                        $res[$k] = $v;
                    }
                }

I'm not fully testing it yet, so I'm not sure about the side effect of this code. However, is it actually alright to be like this?
