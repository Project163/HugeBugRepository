Title

Cannot create an index with "backfill query couldn't be sent"

Description
Creating an index on even trivial table fails with the following on `11.2-YB- -b0` as well as on `11.2-YB- -b0`:
```
ethereum=# create index pokus_idx on pokus (b);
ERROR:  Aborted: backfill query couldn't be sent
```
The stable version shares a bit more details:
```
ethereum=# create index pokus_idx on pokus (b);
ERROR:  Aborted: backfill connection to DB failed: could not connect to server: No such file or directory
	Is the server running locally and accepting
	connections on Unix domain socket "/tmp/.yb.0/.s.PGSQL.5433"?
```

Thus workaround is rather trivial -- going to `/tmp` and creating a `.yb.0` symlink. After that index can be created and seems to be used (according to `EXPLAIN`) as expected.
Discussion
- See #8589 for socket path derivation.  This `0` suggests to me that the postgres host is configured empty or not configured, but I don't yet know how.  Running tserver with `--vmodule=tablet=1` will cause a log to show the index backfill connection string.

Also, you can look at the current tserver logs for a line like

```
I0518 14:12:30.463384 26427 tablet_server_main.cc:242] Starting PostgreSQL server listening on  , port 5433
```

to show what the postgres host is set to.  In the above, it's ` `.

The directory not existing is unexpected, like there's some mismatch between startup and index creation time, so providing extra details would help.
- I do have the socket under `/tmp`, just not under `0`. E.g. 
```
lrwxrwxrwx 1 root root   23 May 24 12:46 .yb.0 -> .yb. 
drwxr-xr-x 2 root root 4096 May 24 12:45 .yb. 
```

That's what I meant with "symlink workaround". I am running an local experimental setup with `docker-compose` almost the same as in documentation:

```
version: '2'

volumes:
  yb-master-data-1:
  yb-tserver-data-1:
... [Log Snipped] ...
      depends_on:
      - yb-master
```

Experiment with `2.4` uses exactly the same configuration, just `yugabytedb/yugabyte:latest` is replaced with `yugabytedb/yugabyte: -b7`.
- This issue has come up about three times from some users on community Slack as well.

```cpp

  const std::string& socket_dir = PgDeriveSocketDir(conf_.listen_addresses);
```

tserver uses "" socket dir during index backfill, resulting in hash 0:

```cpp
  std::string conn_str = Format(
      "user=$0 password=$1 host=$2 port=$3 dbname=$4",
      "postgres",
      postgres_auth_key,

      pgsql_proxy_bind_address.port(),
      pgwrapper::PqEscapeLiteral(database_name));
```

## fix

One fix is to treat empty string as " " on tserver-side (`tablet.cc`).  Possibly a better solution is to set `tablet_server.h`'s `pgsql_proxy_bind_address_` default value to `" "`.

Also, issue #8589 would have made debugging this easier.
- Fixed the above repro, thanks to @thepinetree for pointing out.  Used to be `ysqlsh --command 'create table t (i int); create index on t (i);'`, but that didn't work since it created a transaction and avoided online index backfill.
