Title

Datetime with precision value is logged without precision

Description
While investigating #22381

In Rails master branch Datetime with precision bind value is logged without precision, like `[["start", 2000-01-01 12:30:00 UTC]]`.

``` ruby
D, [2015-11-24T18:41:27.137570 #3509] DEBUG -- :   SQL (0.2ms)  INSERT INTO "foos" ("start") VALUES (?)  [["start", 2000-01-01 12:30:00 UTC]]
```

```
ruby
begin
  require 'bundler/inline'
rescue LoadError => e
  $stderr.puts 'Bundler version 1.10 or later is required. Please update your Bundler'
... [Log Snipped] ...
  end
end
```

In Rails 4.2.5 it logs like `[["start", "2000-01-01 12:30:00.999999"]]` with precision. 

``` ruby
D, [2015-11-24T18:42:43.555872 #3978] DEBUG -- :   SQL (0.2ms)  INSERT INTO "foos" ("start") VALUES (?)  [["start", "2000-01-01 12:30:00.999999"]]
```

It also reproduces with postgresql adapter which `supports_datetime_with_precision?` returns true.
Discussion
- Reproduction script appears to be passing for me on master... Is this still an issue?
- Actually my script does not handle failure or success since I do not know how to check the lot output using minitest.

``` ruby
D, [2016-01-11T01:37:57.274270 #334] DEBUG -- :   SQL (0.1ms)  INSERT INTO "foos" ("start") VALUES (?)  [["start", 2000-01-01 12:30:00 UTC]]
```

I think it is still an issue since the log output does not show fractional seconds.
- It still reproduces with `master` branch.
