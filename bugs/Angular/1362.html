Title

docs: update Ivy compatibility guide to include a note on styling precedence changes

Description
we have a css class used to show/hide element. and we also have angular directive to take input and add/remove this class using host binding. below is the code.

 
@Directive({
  selector: '[ngShow]',
  host: {
    '[class.hidden]': '!ngShow',
    '[attr.aria-hidden]': '!ngShow'
  }
})
export class NgShowDirective {
  @Input()
  ngShow = false;
}
 

Usage:
```html
 test 123 
```

when we set asyncProperty value to true after execution of an async function, it does not remove the "hidden" css class. this worked in angular v8 and started to break after v9 upgrade.

tested against v9.1.0
Discussion
- I believe that it works as designed in Angular v9: classes added on an element have a higher priority that ones coming from a host binding. Yes, this is change from the v8 behaviour, but this is a deliberate change. You can find more info here: [URL]
- @pkozlowski-opensource thanks for the information. but it seems like this might cause lot of issues since this was not included under breaking changes for v9. i personally assume [class.] binding on host will alter the given class even if it exists on element or not.

- Just wanted to chime in here to say that this change for Angular 9 is something I have been waiting on for a _long_ time and is a much appreciated improvement over the previous functionality. I would argue that adding a class to a component in a parent template, and having that component silently overwrite it with a host-binding, is far more confusing/destructive than the new behavior. Though I guess you could argue that explicitly setting a class name to "false" in the host-binding is a different situation than just binding a string value to "class" and wiping out all of the existing classes.
- As discussed here, this _is_ working as intended in Ivy and the styling precedence is described here: [URL] Keeping this open, since it should be included in the [Link: compatibility guide]
