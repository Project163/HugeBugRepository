Title

Child route data is not inherited from parent unless 'runGuardsAndResolvers' returns true

Description
### Which @angular/* package(s) are the source of the bug?

router

### Is this a regression?

No

### Description

While I was figuring out a way to trigger resolver only for certain route on route navigation (see [URL] I found this bug (see linked stackblitz), when even though Angular invokes the resolver as expected, the children won't get their @Input() bound to the new value until the resolver for the specific child runs.

### Please provide a link to a minimal reproduction of the bug

[URL]

1) goto route "a/b"
2) click "Route B"'s "refresh route A resolver", which navigates to route "a/b" and custom RunGuardsAndResolvers strategy causes route's "A" resolver to run
3) observe that component of "a/b" doesn't obtain the new value, but component of "a" does.
4) click "Route B"'s "refresh route B resolver", which navigates to route "a/b" and custom RunGuardsAndResolvers strategy causes route's "B" resolver to run
5) observe that component of "a/b" obtains both new value for "resolver B" AND new value for "resolver A" (cause only now the value gets updated even though "resolver A" isn't run anew)

Data resolution / inheriting data from the parent happens here:
[URL]

That, however, depends on an aggregation of guards/resolvers in a previous step:
[URL]
- I think the preactivation.ts and its shouldRunGuardsAndResolvers seem fine (since the resolvers are being run correctly as is), rather, the data population is incorrect in the resolve_data.ts, since it doesn't propagate the data to any child routes, which it probably should.

The way I see it now, runResolve function will need to be changed so that it only computes the _resolvedData (the resolved data of just the route that owns the resolver) and resolveData function will need to be changed so that it does a second pass after calculating all _resolvedData so that it goes through all the routes which just got their _resolvedData recalculated and all their children down until it reaches leaves and extends routes' data according to paramsInheritanceStrategy as it traverses. That however would go against eventually allowing the data to be read from other resolvers as described in #47287.

Still don't see where the ActivatedRoute.data gets invalidated though.
