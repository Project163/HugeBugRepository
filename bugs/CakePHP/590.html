Title

3.0 Incorect ID foreign keys with SQLServer

Description
I have an issue really hard to simulate, but:
The application is being used by more than 300 users at the same time. They are using it all day so there are alot of queries. And sometimes happens, that in one-to-many relations the record is not assigned correctly to it's _parent_ but the the different _parent_ or the parent_id is NULL.

For example having **Articles** and **Comments** when adding new comment I do something like this:

``` PHP
$newComment = $this -> Articles -> Comments -> newEntity( $data );
```

The _issue_ is that $newComment is bind to different article or the _article_id_ is NULL.

Discussion
- Are you using transactions when you save your records? Perhaps the issue is related to the incorrect isolation level?

As for the methods that are involved in saving:
- Table::save() calls Table::_processSave() in a transaction by default.
- Table::_processSave() uses Cake\ORM\Query to build an insert/update query for the top level entity.
- After inserting, the driver's lastInsertID() method is called which uses the underlying PDO method and the entity is updated.
- AssociationCollection::saveChildren() is called for each child relation. This method calls the saveAssociated() method on each relation (HasMany in your case).
- The association classes set foreign keys and use the association target (Comments in your case) to save each associated entity.
- Sounds like a transaction isolation level. I would suggest that you set it to 'serializable' for this transaction
