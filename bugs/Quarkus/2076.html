Title

Thread locked with optimize-contexts and @Startup bean

Description
### Describe the bug

Since migration to quarkus 3.6.x, our application don't startup because a thread is locked.

It's related to this feature : [URL]

If we set `quarkus.arc.optimize-contexts=false`, the application start correctly.

### Expected behavior

If we set `quarkus.arc.optimize-contexts=true`, the application start correctly.

- @mkouba could you check it's the same issue that you already solved or if it's different?
- I can confirm that it's the same kind of problem and I've just verified that [URL] fixed this problem. In this particular case, an external service is called in the bean constructor (the rest client offloads the execution to a different thread ) which has the same effect as if it was called in a `@PostConstruct` callback a la #37958.
- @lucaspouzac another workaround is to use a `@Startup` method or an observer method instead of the bean constructor:
```
java
@ApplicationScoped
public class BootService {
    private final ConfigService configService;

    }
}
```
