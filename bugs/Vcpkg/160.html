Title

macOS: applocal.py incorrectly tries to copy libraries not from vcpkg installation

Description
**Describe the bug**
On macOS, the applocal.py post build script attempts to copy libraries that are not linked from vcpkg. This cause a problem during compilation with configured cmake project with Xcode

**Environment**
- OS: macOS
- Compiler: 
Xcode Version 11.0 (11A419c) 
Apple clang version 11.0.0 (clang-1100.0.33.8)

**To Reproduce**
Steps to reproduce the behavior:
1. ./vcpkg install [any library]
2. Create CMake project with two targets. 
    One being a shared library created using add_library(mySharedLib SHARED xxx)
    Second being a executable target that is a macOS bundled application (.app)
3. Link the library created using add_library into the executable
     target_link_libraries(myBundleApp PRIVATE mySharedLib)
4. Generate Xcode project using CMake and the vcpkg toolchain file
5. Attempt to build the project. An error will be thrown attempting to copy mySharedLib from the vcpkg installation which is **wrong**

**Expected behavior**
In short, the script needs to check if the dependency its attempting to copy is actually part of the vcpkg installation (i.e the user installed it using vcpkg). Otherwise, it should do nothing and expect that the library is being included from elsewhere on the user's system.
