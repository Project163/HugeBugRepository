Title

extra option in select - formHelper - 3.x

Description
This is a (multiple allowed):

* [x] bug
* [ ] enhancement
* [ ] feature-discussion (RFC)

* CakePHP Version: latest commit on master ( [URL] / include v3.8.5 )

### What you did
according to document ....
```
php

echo $this->Form->date('registered', [
    'minYear' => 2018,
    'monthNames' => false, // Months are displayed as numbers
... [Log Snipped] ...
    ],
]);
```
result 
```
php
 
        Choose year... 
        2024 
         ....
... [Log Snipped] ...
        31 
 
```

### What happened
extra option in invalid place :) 

### What you expected to happen
as you can see there are 2 options in `day` select that is incorrect 
because `day` is `true` by default in `empty` option 
```php
    'empty' => [
        'day` => true
    ],

        Choose year... 
        Choose month... 
```
Discussion
- If i change the `empty` to 
```php
'empty' => ['------']
```
it generates 
```php
 
    ------    1 
```

value `0` here is not expected 
same as for `year` and `month`
- I agree that `'empty' => ['------']` should be the same as verbose `'empty' => ['' => '------']` as the numeric number creates issues along the way. The empty string for the "empty" key seems more intuitive.
- We have existing tests and potentially applications that rely on the empty option being able to have a real value. `0` is a potentially valid empty value so I don't think we should erase it.

There are some tests for the array style empty options, but they are not very robust as they've missed this problem :cry:
