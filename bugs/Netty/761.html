Title

Impedence mismatch between ByteToMessageDecoder and stateful decoder

Description
A stateful decoder that does not extend ReplayingDecoder (e.g. the new HTTP decoder in TFE 2) often have to:
- maintain its own buffer indexes and states (in ReplyingDecoder you used checkpoints), and
- work around ByteToMessageDecoder's sanity check.

This might be an indication of the inflexibility or design flaw in the codec framework.

Here's an example:

You have a stateful decoder that decodes a line with multiple tokens separated by several different separator characters.  Because a line can be received via multiple read operations, you have to keep the index of the position of the separators of each token in the buffer.

However, because `ByteToMessageDecoder` calls `discardSomeReadBytes()` on its inbound buffer, the indexes the decoder kept will go out of sync very easily.  To fix this issue, the decoder has to call more predictable `discardReadByte()` instead of `discardSomeReadBytes()` and adjust its index variables accordingly.  This is pretty cumbersome and less performing obviously.

Also, `ByteToMessageDecoder` requires a decoder to update the inbound buffer's readerIndex if it decodes a message.  A stateful decoder might not want to update the readerIndex of the inbound buffer even if it decoded a message because it could be relying on a different state variable that `ByteToMessageDecoder` is unaware of.  The intention of this sanity check is to ensure that the state of the decoder changes when a message is decoded to avoid infinite loop that is often triggered by a bug where a decoder decodes the same message over and over.

Ideas:
- Change `discard(Some)ReadBytes()` to return the number of discarded bytes so that a user can adjust his/her indexes easily.
- Remove the sanity check - it was only useful for finding silly decoder bugs.
- Allow a user put custom index variables to `ByteBuf` and let `ByteBuf` adjust them automatically on `discard(Some)ReadBytes()`. - I think this is going to be pretty expensive.  Need to find a better way.
