The original issue was about team drives, however this seems to be about normal (non-team) drives.

@fionera any thoughts? Does this only work for team drives?
- Yes that totally normal, since the copy request is issued on the destination remote, it also uses the user of it. So when you are copying to a drive where the destination user doesn't have access to the source it returns a 404. Also when using normal to teamdrive or reverse it needs the patch from #3097 . I already thought about making an additional check that when using serverside over different remotes that it automatically disables serverside when it gets that error.
