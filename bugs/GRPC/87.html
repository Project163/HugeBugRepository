Title

[Python Sync] Implement a mechanism to propagate information between interceptors and server handlers.

Description
We recently discovered a bug where interceptors and server handlers were running in different threads. This made it difficult to pass information between them, we need fix it and also and an example for how to propagate information between interceptors and server handlers.

Related issue: [URL]

#### Note
Before we fix it, as a workaround, we recommend pass data using serialized [Link: metadata].
Discussion
- Unfortunately, in my case these objects can’t be serialized (like managed db session). So… please hurry 😇
- The ability for gRPC to schedule callbacks on any thread in the threadpool is very much by design--applications should not rely on which thread gRPC decides to schedule callbacks on. That should be an implementation detail and subject to change. It sets a dangerous precedent if users start relying on such guarantees. The interceptor can wrap the incoming context and pass its own implementation to share information. If that is not super convenient, there needs to be an explicit facility to make that particular task easier.  Encouraging users to shove objects in thread locals is unwise.
