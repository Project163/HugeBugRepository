Title

d3.geo.centroid returns undefined for several ambiguous cases.

Description
There are certain cases where the spherical centroid of a geometry collection is ambiguous. For example, given a point and its antipode, any point on the surface of the sphere could be considered the centroid. Likewise, given a great arc between a point and its antipode, any point on the great circle halfway between the two points could be considered valid.

The current implementation of d3.geo.centroid returns undefined in these cases. I think it would be preferable to return a _reasonable if arbitrary_ centroid from one of the infinite valid choices rather than returning undefined. Otherwise, presumably everyone that uses d3.geo.centroid should check to see if the centroid is undefined, even for valid geometry inputs, and implement their own fallback behavior. If we do keep the current behavior, we should at least [Link: document] this somewhat surprising behavior, as an undefined return value is likely to causes crashes. Returning a special instance of [0, 0] could also work…

``` js
d3.geo.ambiguous = [0, 0];
```

(This is separate from #1037 in regards to empty lines and polygons, which is a much more common source of error, and where the correct behavior is more obvious.)
Discussion
- Looks reasonable!  Avoid crashing by returning [0, 0], and users can still detect such cases by testing the return value === d3.geo.ambiguous.
- After discussion, we decided returning [NaN, NaN] would be more explicit than introducing d3.geo.ambiguous, and would be consistent with #1278.
- Fix merged into #1285 for 3.2.
