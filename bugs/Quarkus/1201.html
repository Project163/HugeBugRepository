Title

Mailer Template Error: the return value of TemplateProducer.template() is null

Description
### Describe the bug

I use the following checked templates with quarkus mailer:
```
@CheckedTemplate
public class Templates {
  public static native MailTemplate.MailTemplateInstance success(String name);

  public static native MailTemplate.MailTemplateInstance error(String name);
}
```
I'm able to use those template in dev mode and in test. but when the jar is built, It's throwing an NPE.

### Expected behavior

The mail is templated correctly

### Actual behavior

Discussion
- It seems to be working when I set the template as an inner class (and even just by renaming Templates folder in templates), but what is disturbing is the different behaviour in dev and in prod. I expect the build to fail if the folder name is not good !
- I've tried the attached reproducer and the build fails correctly on Linux because your project declares the templates in the `src/main/resources/Templates` directory, but it should be `src/main/resources/templates`; as a result no templates are found. When I fix the directory name to `templates` everything seems to work fine. The question is why the build did not fail on Windows...
- ... [Middle Discussions Snipped for Brevity] ...
- So my guess is that `ApplicationArchive.getChildPath(String)` returns the path `src/main/resources/Templates` for the parameter `templates`, i.e. is case-insensitive on Windows. Then we collect all templates and build the relevant metadata. However, at runtime the [Link: EngineProducer] expects a template to be located in the `templates` directory and `java.lang.ClassLoader.getResource(String)` is case-sensitive.
