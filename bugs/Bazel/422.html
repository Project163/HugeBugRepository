Title

Bazel fails to respect 'external' tag on tests when remote caching is enabled

Description
Please provide the following information. The more we know about your system and use case, the more easily and likely we can help.

### Description of the problem / feature request / question:

Some of our tests are tagged with `external` and should not be cached. We've observed that when remote caching is enabled, a test that normally takes 60 seconds reports as taking 0 seconds (and is not run at all). 

### If possible, provide a minimal example to reproduce the problem:

I've put together a minimal workspace [Link: here] with two scripts that can demonstrate the issue. The only requirement is a remote REST cache server. 

Running `time ./test_local.sh` should take longer than 5 seconds (due to the sleep in the test). 
Running `time ./test_remote.sh` should take longer than 5 seconds (also due to the sleep in the test, and the `external` tag). This test passes in 0.0s.
