Title

UniqueValidator with two targetAttribute not work after update

Description
Hi,
In a model i have

```php
[['reo_orden',` 'reo_articulo'], 'unique', 'targetAttribute' => ['reo_orden', 'reo_articulo'], 'message' => 'El articulo ya está `cargado.'],
```

Before update the debugger show:

```sql
SELECT EXISTS(SELECT * FROM `cop_renord` WHERE (`reo_orden`='14') AND (`reo_articulo`='001401239'))
```

After update:

```sql
SELECT EXISTS(SELECT * FROM `cop_renord` WHERE (`reo_orden`='14') AND (`reo_articulo`='14'))
```

Composer update output:

```
Updating yiisoft/yii2 dev-master (03e0607 => 221603a) Checking out 221603ae2c
```

composer.json after update:

```json
"minimum-stability": "dev",
    "require": {
        "php": ">=5.4.0",
        "yiisoft/yii2": ">=2.0.5",
```

PHP version: 5.6.22

Thks for help.
Discussion
- Could be from this change, [URL]
- targetAttribute related to validate attribute if another isn't set. 

```php
[
    ['reo_orden', 'reo_articulo'],
    'unique',
    'targetAttribute' => ['reo_orden', 'reo_articulo' => 'reo_articulo'],
    'message' => 'El articulo ya está cargado.'
],
```
- ... [Middle Discussions Snipped for Brevity] ...
- Here the PR for fix BC, but I believe the current simplifying is wrong, it makes people confusing. Please look at #7820 
If I have written:
`
[ 'attr1',  'unique', 'targetAttribute' => ['attr2', 'attr3'] ],
`
current simplifying mean `'attr2' => 'attr2' and 'attr3' => 'attr3'`. The reasonable question is where attr1 is used even if `unique` specified for attr1? I suggest use simplifying like `'attr1' => attr2` if another is not specified. @cebe, if you agree with this I will create PR and mark it as BC breaking.
- @developeruz thanks for the fix! I think it will be more confusing, if we implicitly add a key that is different from the value. As far as I see, the current behavior is okay. Also the case where the attribute that receives the error message is not among the targetAttributes is very rare.
