Title

serialize_as skips UndecoratedInsertRecord implementation

Description
## Setup

### Versions

- **Rust:** 1.50.0
- **Diesel:** master
- **Database:** mysql
- **Operating System** macOS 11

### Feature Flags

- **diesel:** mysql, r2d2, chrono

## Problem Description
The `UndecoratedInsertRecord` marker [Link: implementation is not included] when using `#[Link: diesel(serialize_as="...")]`, it is skipped alongside the (correctly skipped) borrowed insert impl as discussed by @thomaseizinger [here].

As such, this makes it impossible to [Link: insert a `Vec `] of anything that uses `serialize_as`.

Is this indeed a mistake, or am I missing some reason for why this isn't allowed?

### Steps to reproduce
Following my [Link: conversation on Gitter], in a simple `Insertable` derived struct, using `serialize_as` like so:

```rust
#[derive(Insertable)]
#[table_name = "..."]
pub struct Example {
  // ...
  #[diesel(serialize_as = "OptionalSQLUTCDateTime")]
  pub last_play: Option >,
}
```

...renders `impl  Insertable  for Example {`

However, not using `serialize_as`, like so:

```rust
#[derive(Insertable)]
#[table_name = "..."]
pub struct Example {
  // ...
  pub last_play: OptionalSQLUTCDateTime,
}
```

...renders `impl  Insertable  for Example {`, `impl  Insertable  for &'insert Example {` and importantly `impl  UndecoratedInsertRecord  for Example {}`
Discussion
- That's an oversight of the original PR. We are happy to receive a fix for that as PR.
