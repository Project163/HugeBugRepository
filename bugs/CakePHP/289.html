Title

Order by not-unique column with pagination

Description
Created by **mwolf**, 19th Nov 2010. _(originally [Link: Lighthouse ticket #1300])_:

---

In postgresql a "SELECT field1, field2 FROM tools ORDER BY manufacturer LIMIT 20 OFFSET 40" returns some entries which are also returned by "SELECT field1, field2 FROM tools ORDER BY manufacturer LIMIT 20 OFFSET 80"

To let the users order by a column which has a lot of same entries (PaginatorHelper::sort) the query should be something like "SELECT field1, field2 FROM tools ORDER BY manufacturer, id LIMIT 20 OFFSET 40"

I'm pretty sure this is a problem not unique to Postgres. At least when you have a join in your query, sorting MySQL tables by non-unique values may also return results in a (slightly) different order each time the query is executed, especially when using an offset. mwolf's suggestion to add the id to the order clause is an obvious workaround which I am using for all my paginations. It would be very convenient indeed to have an in-built Cake solution for this.
- People using postgres need to be aware that it does not return the rows in insertion order, this is why having a complete order clause is advised. In any case, paginating using order is always error prone, as the table might be experiencing insertions at the same time.
