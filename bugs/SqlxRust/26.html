Title

postgres: sqlx prepare fails if shared_preload_libraries=pg_stat_statements

Description
duplicates #2587

### Bug Description
since sqlx-cli version >=0.7.0 `sqlx prepare` fails if target database has [Link: `pg_stat_statements`] in [Link: `shared_preload_libraries`]

bug doesn't exists in =0.6.3

### Minimal Reproduction
1. init project
```console
cargo init sqlx-test
cd sqlx-test
```
2. setup db
`docker-compose.yml`
```
yaml
version: '3.7'

services:
  db:
... [Log Snipped] ...
volumes:
  db_data: null
```
3. `Cargo.toml`
```
toml
[package]
name = "sqlx-test"
version = "0.1.0"
edition = "2021"
... [Log Snipped] ...
] }
tokio = { version = "^1", features = ["full"] }
```
4. `src/main.rs`
```
rust
use sqlx::postgres::PgPoolOptions;

#[tokio::main]
async fn main() -> Result  {
... [Log Snipped] ...
    Ok(())
}
```
5. installl `sqlx-cli`
```console
cargo install --version 0.7.1 sqlx-cli
```
6. run db
```console

```
7. set `DATABASE_URL`

Discussion
- this is not a big deal really:
* one can use `SQLX_OFFLINE=true`
* and in dev env disable `pg_stat_statements` when running `sqlx prepare`

that being said I figured that it's worth reporting anyway
- It appears that it's somehow changing the output of the `EXPLAIN (VERBOSE, FORMAT JSON)  ` statement that the macros use to analyze the query. Can you post the output of that command?
