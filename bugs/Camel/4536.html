Title

camel-caffeine: do not use different caches with slightly different URIs

Description
I've found a problem with caffeine-cache. When I use the following: 
  
 
 // route 1
 .to( "caffeine-cache:global?key=x&action=PUT" )

 // route 2
 .to( "caffeine-cache:global?key=x&action=GET"  
  
 I expect that what I save in route 1 can be retrieved in route 2, but this is not the case, since the two URIs differ (GET/PUT) and I get two different caches.
Discussion
- You can obtain something like that by specifying your cache: 
  
 
@Override
 protected  RouteBuilder createRouteBuilder()  throws  Exception {
 return   new  RouteBuilder() {
 public  void configure() {
from( "direct: //start" ).toF( "caffeine-cache://%s?cache=#cache&action=PUT&key=1" ,  "test" ).toF( "caffeine-cache://%s?cache=#cache&key=1&action=GET" ,  "test" ).log( "Test! ${body}" )
 .to( "mock:result" );
}
};
}
 
  
 In this way you'll always use the same cache you instantiated at the beginning, otherwise it will be created on each operation. WDYT?
