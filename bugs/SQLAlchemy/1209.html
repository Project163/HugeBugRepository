Title

warn when running session.execute(Query)

Description
**Describe the bug**
Generated SQL with substituted params contains NULL instead of values added at query time with "with_expression". This happens when using session.query(DeclarativeModel), using select(DeclarativeModel) seems to be fine.

Generated SQL without param substitution is the same, but results differ - seems it happens after variables are substituted

**Expected behavior**
I read through the changelog for 1.4 and haven't found anything that can be related to this behaviour. If it's not a bug it seems like an undocumented change.

**To Reproduce**
Run the below code on 1.3.12 and 1.4.7, observe `NULL as anon_1` added instead of `company_name` in the result for 1.4.7. 

```
py
from sqlalchemy import *
from sqlalchemy.ext.declarative import declarative_base
from sqlalchemy.orm import *

... [Log Snipped] ...

print(cursor.query.decode())
```

**Error**

```
# result on 1.4.7
# SELECT NULL AS anon_1, "user".id AS user_id, "user".name AS user_name
# FROM "user"

# result on 1.3.12
# SELECT 'github' AS company_name, "user".id AS user_id, "user".name AS user_name
# FROM "user"
```

**Versions.**
 - OS: macOS big sur
 - Python: 3.9.2
 - SQLAlchemy: 1.4.7
 - Database: postgresql 9.6
 - DBAPI: psycopg2

**Additional context**
We bumped our SQLAlchemy version from 1.3 to 1.4, couple of tests testing code that  is using query_expression stopped working - was trying to narrow it down because our code is quite complex, managed to find the discrepancy in generated SQL (example code above).

- hey there -

the issue is that you're using an unusual and not currently defined pattern to invoke this query, and also repurposing with_expression() in a way that was also not part of its current usage contract:

```
   q = session.query(...)
   result = session.execute(q)
```

I would not expect ORM loader options to take effect for such a query in 1.3, but it seems you're relying upon the fact that query() would add the column in any case before running in this way.

The behavior of session.execute() with ORM-enabled SELECT statements [Link: has changed in 1.4].  So if we run your thing in 1.3, the result looks like:

```
(Pdb) result.fetchall()
[('github', 1, 'bogdan')]
```

if we run in 1.4, the result is:

```
(Pdb) result.fetchall()
[( >,)]
```

so already, things are very different here.   

The Session should be doing something more "defined" here, like a warning, or an error, or "just working" most likely, to get the option to take effect in 1.4 looks like:

    result = session.execute(q.statement)

but that still gives you a User object in a row, not a row with plain columns.

The error it's supposed to raise is in fact this:

     sqlalchemy.exc.ObjectNotExecutableError: Not an executable object:  >

*anyway*, what you want here is 1. core-style execution against your 2. ORM-enabled query.  it will work if you do it like this:

    result = session.connection().execute(q.statement)
