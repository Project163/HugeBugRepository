### Description

Looks like it's mostly `yb_pg_alter_table` test that is failing, sometimes also `yb_create_table`.
Discussion
- `yb_pg_alter_table` test is failing due to a server crash.
The crash occurs on line 285 of `yb_pg_alter_table.sql`: `select * from my_locks order by 1;`
The `my_locks` is a view type which retrieves lock mode from pg_locks table:
```

from pg_locks l join pg_class c on l.relation = c.oid
```

The problematic query comes from the `virtualtransaction` subquery which attempts to retrieve the current transaction ID.

When `select  txid_current();` query runs as a standalone, it reproduces the same server crash error.

It seems like the `yb_pg_alter_table` file was tested as a standalone which is why it expected the index and table to return the "does not exist" error. 
In the detective, I see there are 3 builds that failed with `TestPgRegressTable` and 2 builds which failed to rebase so perhaps the test was dismissed.

We must revert the change to the original expected output result.
- The third issue is in `yb_create_table.sql` test.
There's a section that connects to `\c yugabyte` then creates a temporary table and view.
The creation of temporary table fails due to `restart read required` error:
```
create temporary table temp_tab(a int);
ERROR:  Query error: Restart read required at: { read: { physical:   } local_limit: { physical:   } global_limit:   in_txn_limit:   serial_no: 0 }
```
The error comes from `async_rpc.cc`'s `CommonResponseCheck()` function.
The function checks against the ReadHybridTime using the response protobuf and checks whether `has_restart_read_time()` is set to true.
If so, this long string of error is created in `read_hybrid_time.h` demanding a read restart.

The error is not reproducible in ysql shell as the temporary table gets created without any issue.
A possible workaround is to add a sleep thread immediately after `\c yugabyte` to give some time for the tablet server which has skewed clock to correct itself then execute the temporary table creation.
