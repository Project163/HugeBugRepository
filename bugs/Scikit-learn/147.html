Title

SGDClassifier warm_start results in different score than when training in one go

Description
#### Description
When using the `warm_start` argument to the SGDClassifier together with a for-loop for increasing the `max_iter` argument, this results in a different score than when simply setting the `max_iter` to a high value and not using `warm_start`.

#### Steps/Code to Reproduce

```
python
import numpy as np
import sklearn.datasets
import sklearn.linear_model
import sklearn.model_selection
... [Log Snipped] ...
    if score1 != score2:
        print("\n", seed, score1, score2)
```

#### Expected Results
Only a few dots indicating that the code snippet is running.

#### Actual Results
Several seeds for which score1 and score2 differ.

Discussion
- Two reasons for that:

- The learning rate is by default dynamic, it changes depending on the number of samples already seen. The counter is stored in `self.t_`. Calling `fit` a second time resets the counter, even with `warm_start=True`. ~~We might want to fix this.~~ Note that the counter does not restart when calling `partial_fit`.
To isolate this first issue, we can use `learning_rate='constant'`.

- The random state is not stored, as in `GradientBoostingClassifier` (see [Link: here]). Therefore, the random sample order is reset at each call of `fit` or `partial_fit`, even with `warm_start=True`. We might want to fix this.
To isolate this second issue, we can use `shuffle=False`.

I also rewrote your snippet, as you don't need to increase `self.max_iter` to add one more iteration, as in `GradientBoostingClassifier`. This API difference could be better documented.
You also need `tol=None` to avoid early stopping.

```
py
import numpy as np
from sklearn.datasets import load_digits
from sklearn.linear_model import SGDClassifier
from sklearn.model_selection import train_test_split
... [Log Snipped] ...
# issue 2: random state is not stored
run(shuffle=True, learning_rate='constant')
```
