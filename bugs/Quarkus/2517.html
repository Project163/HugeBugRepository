Title

Description
### Describe the bug

Since 3.29.0 we spot in some of our test that when `quarkus-spring-data-jpa` is added. The build fail with `Datasource must be defined for persistence unit ' '. Setting the datasource for the persistence unit can be done via the 'quarkus.hibernate-orm.datasource' property.  Refer to [URL] for guidance.`

This happen only when the `quarkus-jdbc-*` is not present or there are multiple of them and at the same time the `import.sql` is present. Without the `import.sql` the build passing.

I would expect that the Quarkus app is build without problem as it was done in 3.28

- Hey @jedla97, thank you for reporting the issue! This looks indeed very similar to [URL] but I believe you're hitting a slightly different case. That issue was already fixed by checking if there were [Link: no entities mapped to the default PU], which is your case as well.

But, because of the `import.sql` file being present in your class-path, the Hibernate ORM extension is enabling the implicit (i.e. ` `) persistence unit. See here:

[URL]

And here:

[URL]

This, in turn, is why you're seeing this error. A valid workaround for now would be to set `quarkus.hibernate-orm.enabled=false`, disabling the Hibernate ORM extension.

Why do you have an `import.sql` script in the first place, though? I'm guessing Hibernate is what's processing it anyway, being the underlying implementation for Spring Data JPA, so you might want to have the ORM extension enabled.
