Title

Bug: Escaping in config patterns doesn't work on Windows

Description
### Environment

Node version: v22.2.0
npm version: v10.7.0
Local ESLint version: v9.5.0
Global ESLint version: no
Operating System: windows & ubuntu

### What parser are you using?

Default (Espree)

### What did you do?

I was trying to improve correctness of [Link: `convertIgnorePatternToMinimatch()`] by escaping some characters but found out that escaping doesn't work on Windows.

 
 Configuration 

```
export default [
    {
        ignores: [
            "src/\\{a,b}.js"
        ]
... [Log Snipped] ...
    }
];
```
 

Project structure:

```
.
├── eslint.config.js
└── src/
    ├── {a,b}.js
    ├── a.js
    └── b.js
```

### What did you expect to happen?

I'd expect that pattern `src/\{a,b}.js` ignores file `src/{a,b}.js`, so running `eslint src` should lint only `src/a.js` and `src/b.js`.


### What actually happened?

On ubuntu, it works as expected:

```
Run npm run lint


... [Log Snipped] ...

✖ 2 problems (0 errors, 2 warnings)
```

On windows, it doesn't work as expected. Instead of `src/{a,b}.js`, files `src/a.js` and `src/b.js` are ignored:

```
Run npm run lint



D:\a\pattern-escaping-repro\pattern-escaping-repro\src\{a,b}.js
Warning:   1:1  warning  'foo' is not defined  no-undef
```

So, with the same config file, the behavior is different on posix and windows.

### Additional comments

* This was generally considered as a bug in minimatch. For backwards compatibility reasons, in v3 this was fixed by providing [Link: `allowWindowsEscape`] option. We could set this option to `true` to fix this.
* The fix would be in the eslint/rewrite repo, `config-array` package.
