Title

$super is replaced when it should not be replaced

Description
What steps will reproduce the problem? 
1. Have javascript using prototype's $super
2. Compile with advanced_optimizations
3. See that $super is replaced by for example $super$$4

 What is the expected output? What do you see instead? 
$super should not be renamed as it is used by prototype.

 What version of the product are you using? On what operating system? 
Latest from svn.

 Please provide any additional information below. 
Personally I made a quick fix in MakeDeclaredNamesUnique.java line 79:
if (t.getCompiler().getCodingConvention().isExported(name)) { continue; }
This fixed it for me, but not sure if that's the right place or method to
solve this, as I am unfamiliar with the project.

- To make my comment clear, one of the points of the normalization is to make it easier
for passes if the "x" they saw is the same "x" they saw earlier (without needing to
track scope).  This makes things much easier for code motion because you don't need
to worry about masking a variable of the same name.  If you change it "$super" is not
unique the results would be unpredictable. After renaming it doesn't matter if the
name is unique as the normalization is expected as renaming by design creates as many
non-unique names as possible.
