Title

Bootstrapping is not threadsafe

Description
The bootstrapper thread (called from the main thread which has acquired the lock for SS via SS.init) currently makes a few calls into SS that require its lock. 

 Those methods need to be thread-safe, but do not need the same lock required by SS.init.
Discussion
- This fixes the problem, but I don't see the point of having Bootstrapper launch a separate thread to make the file requests while SS.init waits for bootstrapping to finish.  Its work could mostly be replaced with a method in SS that calls into the static methods currently in Bootstrapper.
- +1 on the patch.  I'm not sure what the point of having the separate BS thread is, either.  Maybe it made more sense a dozen refactors ago.
