Title

Presence validation of virtual attribute not firing appropriately

Description
In [Link: Clearance] we use a conditional validation on the virtual `password` attribute to determine whether the password field needs to be validated. We only need to validate it when the underlying database row's `encrypted_password` is not set or if the user is changing the password.

I found that when testing against rails 5, the conditional validation does not behave as expected. The method that guards the validation returns as it did under 4.2, but calls to `valid?` return `true` when they should return `false`. Interestingly, the call to `save` inside the `valid?` conditional _does_ fire the validation appropriately.

It seems `valid?` is short circuiting, maybe because no active-record level changes have been detected? Yet `save` does not short circuit?

Here's a test case:

```
ruby
begin
  require 'bundler/inline'
rescue LoadError => e
  $stderr.puts 'Bundler version 1.10 or later is required. Please update your Bundler'
... [Log Snipped] ...
  end
end
```

- I've investigated a bit and understand why this is happening but not sure yet how to fix it. The problem is with any non-db attribute. So because `password` is an `attr_accessor` and not an attribute of the record `record.changed?` is returning `false`, whereas if it were a db attribute then it would return `true` for `changed?`.

If the record was considered dirty and the attributes changed this would not have changed behavior. The reason `email_will_change!` works is because it's marking the record as `changed?`. 

I'm not sure the best way to fix this yet.
- Ok this is fixed in master. There is no way for Rails to know that the record was `record.changed?` or dirty when using a virtual attribute like this. I think we should eventually deprecate this behavior but I talked about it with Aaron and it's not super easy to do that.

What I did to fix the issue was check if the changed attribute was in the `record.attributes` hash. If it's not then it's a virtual attribute and we can say always check this record if we don't know about the attribute in the database.

If you do want to mark your record as dirty when setting a virtual attribute you can use the following code:

``` ruby
def password=(value)
  attribute_will_change!(:password)
  @password = value
end
```
