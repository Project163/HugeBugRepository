Queries like this fail

```
POST /_query
{
  "query": "FROM .ds-logs-nginx.error-default-2024.11.13-000001 | EVAL compression = rally.doc_size::DOUBLE / rally.message_size | STATS AVG(compression)"
}
```
Discussion
- Pinging @elastic/es-storage-engine (Team:StorageEngine)
- The main reason that the `EOFException` occurs is that `LeafSearchLookup` instance gets reused between `BlockDocValuesReader` instances. In the above query there are two `BlockDocValuesReader` instances using the `LeafSeachLookup`. When `ValuesSourceReaderOperator` reads on columnar fashion (via `loadFromSingleLeaf()` or loadFromSingleLeafUnsorted() methods) then ranges of docids get processed multiple times by same  `LeafSearchLookup` instance. For the synthetic source loader this is an issue because as part of synthesizing source doc value iterators then can advance backwards. This violates `DocValuesIterator#advanceExact(...)` and `DocIdSetIterator#advance(...)` contracts and then at some point during the executing of the query `EOFException` occur deep in the codec.

This is fixable. For example we could enforce different `SearchLookup` instances between fields or force a row oriented execution fashion.

(note: this issue only occurs with runtime fields (script based block loaders))
