Title

Can't accept untrusted folder from Web UI

Description
Steps to reproduce:
- Enable untrusted feature flag on both devices A and B, restart them
- Create a shared folder from device A from the UI
- Share it with device B, enabling the untrusted checkbox and entering a password
- Go to device B on web UI, try and accept the request to add the new folder

The result is that the window closes, but the folder is not added due to the following Javascript error:

Firefox backtrace:
```
Error: folderCfg.versioning is undefined
$scope.saveFolder@[URL]
$parseFunctionCall@[URL]
callback@[URL]
$eval@[URL]
... [Log Snipped] ...
dispatch@[URL]
add/elemData.handle@[URL]
```

Chromium backtrace:
```
TypeError: Cannot set property 'type' of undefined
    at Scope.$scope.saveFolder (syncthingController.js:2096)
    at $parseFunctionCall (angular.js:12493)
    at callback (angular.js:21719)
    at Scope.$eval (angular.js:14589)
... [Log Snipped] ...
    at HTMLButtonElement.dispatch (jquery-2.2.2.js:4755)
    at HTMLButtonElement.elemData.handle (jquery-2.2.2.js:4567)
```

I have tried a couple times deleting and recreating the folder from device A but I get always the same result on the UI for device B, as well as when trying to add the folder manually specifying the device ID. 

Tested on Syncthing version `v1.15.0-rc2` running on both nodes and recent versions of Firefox/Chromium on Linux.
Discussion
- Thanks for catching and reporting!

Affects any folder that has no versioning. Regression introduced in #7384, i.e. v1.15.0.
