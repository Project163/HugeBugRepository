Title

mysql create_index with textual expression doubles parens

Description
unclear if this is generalized to other dialects yet

```
diff
diff --git a/test/dialect/mysql/test_compiler.py b/test/dialect/mysql/test_compiler.py
index 7bddebd17..8350a9da3 100644
--- a/test/dialect/mysql/test_compiler.py
+++ b/test/dialect/mysql/test_compiler.py
... [Log Snipped] ...
         m = MetaData()
         tbl = Table("testtbl", m, Column("data", String(255)))
```

output:

```
 - CREATE INDEX test_idx1 ON testtbl (created_at desc)
  + CREATE INDEX test_idx1 ON testtbl ((created_at desc))

```

moved from [URL]
Discussion
- note that MySQL requires the unusual double parenthesis for most functional expressions:

```
self.assert_compile(
            schema.CreateIndex(Index("bar", t1.c.x > 5)),
            "CREATE INDEX bar ON foo ((x > 5))",
        )
        self.assert_compile(
... [Log Snipped] ...
            "CREATE INDEX test_idx2 ON testtbl (x, (x + y), (y - x))",
        )
```

this was added in 1.3 for #5462 so the text case here is a regression we can fix in the 1.3 series
- **Mike Bayer** has proposed a fix for this issue in the **master** branch:

**narrow the check for double-paren exprs in mysql create_index** [URL]
- **Mike Bayer** has proposed a fix for this issue in the **rel_1_3** branch:

**narrow the check for double-paren exprs in mysql create_index** [URL]
- It appears not, at least not for mssql:
