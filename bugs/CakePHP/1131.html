Title

TestEmailTransport getMessages() returns duplicate/invalid emails when sending multiple emails with a single Mailer instance

Description
### Description

If this is an incorrect usage of Mailer class please feel free to reject.

When using TestEmailTransport to test the processing and sending multiple emails within a Command or other logic. Using a single instance of the Mailer class. The return value of getMessages() will be invalid if more than 1 email is sent.

I believe this is because the $message object is a reference to the Mailer's single $message object, and all subsequent calls to setSubject, setTo, etc. will affect all messages in the static::messages array in TestEmailTransport.

```
// Dummy Data
        $event1 = ['title' => 'Event 1', 'eventdate' => '2023-02-23', 'time' => '18:00'];
        $event2 = ['title' => 'Event 1', 'eventdate' => '2023-02-23', 'time' => '18:00'];
        $emails = ['one@test.com' => $event1, 'two@example.org' => $event2];

... [Log Snipped] ...
                ->deliver();
        }
```

The fix for this is to update TestEmailTransport send() method so that it clones the $message object rather than stores the reference.

E.G.

```
/**
     * Stores email for later assertions
     *
     * @param \Cake\Mailer\Message $message Message
     * @return array{headers: string, message: string}
... [Log Snipped] ...
        return parent::send($message);
    }
```
