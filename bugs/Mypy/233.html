Title

Error importing submodule from __init__.py

Description
```
bash
mkdir -p foo

cat > foo/_bar.py   bar/_bar.py << EOL
def say_hi():
... [Log Snipped] ...

mypy --follow-imports=skip --fast-parser --strict-optional bar/raz.py
```

Works fine

[**UPDATED:** switched to `--follow-imports=skip`, dropped `--py2` --Guido]
Discussion
- This _might_ be related to [URL] but I'm not sure.
- Thanks for the bug report!  I don't think this is related to #2016, actually.  It looks like it's a problem with silent imports.

```
mypy --fast-parser --py2 --strict-optional  foo/__init__.py  # i.e. without -s; no errors
```
- (Note: This is still an issue.)
- It looks like the problem is that when the "main" module is `foo/__init__.py` the `from foo import bar` is interpreted as looking for an _attribute_ `bar` of `foo`, and given that `foo` is loaded, but its `bar.py` submodule is not, the absence of that attribute is confirmed.

But in the second example, when the main module is some other submodule, loading of the parent module is suppressed, so it is deemed to have _any_ attribute.

A possible solution may be to discover that the attribute in fact refers to a suppressed submodule.
