Title

MetadataShell bypasses file lock unexpectedly due to lock file deletion

Description
MetadataShell acquires log dir lock to prevent unexpected results by concurrent reads/writes fixed by  [URL]

   

 This lock works as expected when we execute MetadataShell against running log for the first time: 

   
  
 
% ./bin/kafka-metadata-shell.sh --snapshot data/bootstrap.checkpoint
Unexpected error: Unable to lock /path/to/data. Please ensure that no broker or controller process is using  this  directory before proceeding. 
  
 However, if we execute MetadataShell with same command again with controller still running, it succeeds unexpectedly. 

   

   
  
 
% ./bin/kafka-metadata-shell.sh --snapshot data/bootstrap.checkpoint
Loading...
Starting...
[ Kafka Metadata Shell ]
>>  
  
 And I found that .lock file vanishes after MetadataShell exit. 

   

 This is because MetadataShell calls FileLock#destroy when it fails acquiring lock, which deletes the lock file. 

  [URL]
