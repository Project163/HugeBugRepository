Title

Dev mode - argument type mismatch when invoking a RUNTIME_INIT build step

Description
**Describe the bug**

```
10:01:02,799 ERROR [io.qua.dev.DevModeMain] Failed to start quarkus: java.lang.RuntimeException: io.quarkus.builder.BuildException: Build failure: Build failed due to errors
	[error]: Build step com.github.mkouba.qute.quarkus.deployment.QuteProcessor#initialize threw an exception: java.lang.IllegalArgumentException: argument type mismatch
	at io.quarkus.runner.RuntimeRunner.run(RuntimeRunner.java:145)
	at io.quarkus.dev.DevModeMain.doStart(DevModeMain.java:173)
	at io.quarkus.dev.DevModeMain.main(DevModeMain.java:100)
... [Log Snipped] ...
	at java.lang.Thread.run(Thread.java:748)
	at org.jboss.threads.JBossThread.run(JBossThread.java:479)
```

It's very likely a class loading issue - I've compared the class loader of the [Link: QuteTemplate] class coming from the corresponding `java.lang.reflect.Method` and the class loader of the class coming from the  argument and they differ: `sun.misc.Launcher$AppClassLoader`
VS `io.quarkus.runner.RuntimeClassLoader`. See [URL]

**To Reproduce**
Steps to reproduce the behavior:
1. clone [URL]
2. `mvn clean install`
3. `mvn compile quarkus:dev` in the quarkus/example dir
Discussion
- @stuartwdouglas do you have an idea what's going on here?
- This is because the template and the project are in the same project. The 'dev' mode supports multi module projects now, so it will discover the additional modules and attempt to make them hot reloadable, which does not work. You can work around this for now with mvn compile quarkus:dev -DnoDeps, but I might add a simple fix to skip extension modules
- Actually I can't really fix this, as it will also include the qtue core itself, which will have similar problems, the real fix it to just add noDeps to the plugin config.
- Ah, I'm sorry I actually knew the root cause (I created [URL] and forgot to use `-DnoDeps`! Marking this as invalid.
