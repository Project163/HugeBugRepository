Title

Optional<> @HeaderParam REST Client arguments

Description
### Describe the bug

When specifying a `@HeaderParam` annotated microprofile REST Client argument as an `Optional<>`, the `Optional.toString()` value is being populated within the HTTP Header.

### Expected behavior

The actual value of an `Optional` argument should be populated in the HTTP header value for the HTTP request.

### Actual behavior

The `Optional`'s `toString()` value is populated within the HTTP Header which will not lead to the expected results:

Optional's toString() Impl:
```java
    @Override
    public String toString() {
        return value != null
            ? ("Optional[" + value + "]")
            : "Optional.empty";
    }
```
