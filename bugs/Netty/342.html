Title

java.net.NoRouteToHostException breaks NioDatagramChannel/Bootstrap

Description
We have a UDP "pinger" that sends a UDP "ping" packet to other servers (hundreds or single-digit thousands), and receives back a "pong" packet.  Target servers are spread out in a ring consisting of 15 slots.  Each second a timer fires and the targets in the next slot are pinged.  This means that each target is pinged once every 15 seconds, regardless of the number of targets.  The number of UDP packets sent each second increasing with the number of targets.

We construct our Bootstrap like so:

``` java
Bootstrap bootstrap = new Bootstrap();
bootstrap.group(eventLoopGroup)
         .channel(NioDatagramChannel.class)
         .option(ChannelOption.SO_REUSEADDR, true)
         .handler(inboundHandler);
channel = bootstrap.bind(socketAddress).syncUninterruptibly().channel();
```

Pings are sent like this:

``` java
DatagramPacket sendPacket = new DatagramPacket(buffer, pingHost.host);
channel.writeAndFlush(sendPacket);
```

The issue we are running into is that when one of the target hosts is taken off of the network, after several _pings_ to that host this exception is thrown:

```
java
java.net.NoRouteToHostException: No route to host
    at sun.nio.ch.DatagramChannelImpl.send0(Native Method)
    at sun.nio.ch.DatagramChannelImpl.sendFromNativeBuffer(DatagramChannelImpl.java:532)
    at sun.nio.ch.DatagramChannelImpl.send(DatagramChannelImpl.java:509)
... [Log Snipped] ...
    at io.netty.util.concurrent.SingleThreadEventExecutor$2.run(SingleThreadEventExecutor.java:116)
    at java.lang.Thread.run(Thread.java:745)
```

This is breaking the `Channel`.  It seems it should not.  These are UDP packets fired off into the ether, if they never reach their destination it is none of our concern.
