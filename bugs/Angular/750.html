Title

ProvidedIn Annotation Not Compatible With Deriving Classes

## Current behavior
 
When using the `providedIn` annotation on a derived class, the derived class does not internally get a factory created. This is down to the `ngInjectableDef` property that is already set and when the providedIn is invoked, it can see that `ngInjectableDef` is already set on it's parent so it does not get set again. To get around this issue, in any deriving classes we have to set `ngInjectableDef` to undefined. This in turn, invokes the providedIn logic to create a factory for us

## Expected behavior
 
We should be able to use the `providedIn` annotation as normal on any deriving classes without the need of setting the `ngInjectableDef` property back to undefined.

## Minimal reproduction of the problem with instructions
 

```
@Injectable({
  providedIn: 'root'
})

export class BaseService {
... [Log Snipped] ...
  // 'imports' section
}
```

## What is the motivation / use case for changing the behavior?
 
We should have the same behaviour in deriving classes as we do in our base classes
