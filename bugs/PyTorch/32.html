Title

Meta definition of normal_ doesn't allow std equal 0

Description
## 🐛 Bug

`std == 0` is not allowed in the meta definition of `normal_`. Other variants allow it, including the implementation of
`normal_` itself.

## To Reproduce

See the difference below:

```
Traceback (most recent call last):                                                                                                                                                                        
  File " ", line 1, in                                                                                                                                                                       
RuntimeError: normal_ expects std > 0.0, but found std=0                                                                                                                                                  
... [Log Snipped] ...
tensor([[4., 4., 4.],                                                                                                                                                                                     
        [4., 4., 4.]])
```

## Expected behavior

The result is the same as in the second case.

## Environment

Tested on commit:

```
commit  
Author: Don Jang  
Date:   Sat Dec 4 19:42:55 2021 -0800

    Revert D32780415: [Static Runtime] Move implementation details from impl.h into internal.h
```

## Additional context

`normal_` impl:

```cpp
Tensor& normal_impl_(Tensor& self, double mean, double std, c10::optional  gen) {
  TORCH_CHECK(std >= 0.0, "normal_ expects std >= 0.0, but found std=", std)
```

and a different variant agree:

```cpp
Tensor& normal_out_impl(Tensor& output, const Tensor& mean, const Tensor& std, c10::optional  gen) {
  TORCH_CHECK(!std.is_complex(), "normal expects standard deviation to be non-complex");
  TORCH_CHECK(
    std.numel() == 0 || std.min().ge(0).item (),
    "normal expects all elements of std >= 0.0")
```
