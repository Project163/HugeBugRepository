Title

CakeRequest::referer() behind Apache reverse proxy using [P] flag

Description
This function currently uses the HTTP_X_FORWARDED_HOST environment variable if it is set. In some instances this value is the proxied host-name, and not the url location of the referer. This causes the output of referer() to be incorrect. Current workaround would be to use the HTTP_REFERER var instead of the CakeRequest function. A fix would be to allow passing a flag concerning the HTTP_X_FORWARDED_HOST var.
Discussion
- ins't `HTTP_X_FORWARDED_HOST` supposed to be the client address exactly for the cases where you are running behind a proxy? In any case, if the value of this header is not trustworthy for you, you can turn it of by setting `$this->request->trustProxy = false`;
- @lorenzo `request->trustProxy` is not part of 2.x

I'm not even sure that HTTP_X_FORWARDED_HOST should be used when getting refererers. From what I've seen in the apache documentation it used to be the proxy equivalent of HTTP_HOST not HTTP_REFERER.
