Title

Watcher payload possibly broken in master

Description
[Link: This watch] works in `6.5.1`, but does not work on master. The key issue seems to be that iterating over aggregations is broken in master. The log output should contain a list of all matched bucket keys when it fires, but instead logs nothing in the space where the data should be.

Please see the watch linked above.  I've included a sample Heartbeat event that triggers the watch below:

```
{
  "_index": "heartbeat-6.5.0-2018.12.03",
  "_type": "doc",
  "_id": "3pfCdWcBzOHIWwLnTiHd",
  "_version": 1,
... [Log Snipped] ...
  ]
}
```
Discussion
- Pinging @elastic/es-core-features
- @andrewvc - I think this may be a result of [URL] which impacts Watcher [URL]  There is BWC compatible flag that we will enable by default in 7.x, but is currently not enabled as default in master of today. 

Can you retry your watch with `"rest_total_hits_as_int": true` ?  You shouldn't need to make that change in your watch for 7.x (that is BWC flag we will set by default)...just confirming that when we do enable that change in master your issue will be fixed. 
```
  "input": {
    "search": {
      "request": {
        "rest_total_hits_as_int": true,
        "search_type": "query_then_fetch",
        "indices": [
          "heartbeat-*"
        ],
```
