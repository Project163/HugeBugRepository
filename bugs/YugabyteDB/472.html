Title

[backup] Incorrect restored table schema if the table was altered after the backup.

Description
The issue happens only in case when the table is being restored on the same (original) cluster, where it was backed up.

The scenario:
1. Create the table backup. (At this moment the table has SCHEMA-1.)
2. Alter the table. (From the moment the table has SCHEMA-2.)
3. Restore the table from the backup on the same cluster.
Expected schema after the restoring:  SCHEMA-1, but it has SCHEMA-2 due to a bug.

Reason: table is not recreated by the backup-restore procedure if there is existing table with ID as in the backup, + the keyspace and table names must be the same, + the table must be running. 

Fix idea: If the backed up table is found by ID - additionally we need to compare the table schema. If the table schema was changed - the backup-restore must fail.

The issue can affect both - YCQL & YSQL.

Workaround: manually drop the table before restoring.
Discussion
- Example:
1. Create the table:
```
ycqlsh> create keyspace a; use a;
ycqlsh:a> create table t (a int, b int, c int, h int primary key);
ycqlsh:a> insert into t (a,b,c,h) values (1,2,3,4);
ycqlsh:a> insert into t (a,b,c,h) values (5,6,7,8);
ycqlsh:a> select * from t;
... [Log Snipped] ...
 4 | 1 | 2 | 3
 8 | 5 | 6 | 7
```
2. Create the table backup.
3. Change the table schema and change the data:
```
ycqlsh:a> alter table t drop  a;
ycqlsh:a> select * from t;
 h | b | c
---+---+---
 4 | 2 | 3
... [Log Snipped] ...
 4 | 22 | 33
 8 | 66 | 77
```
4. Restore the table back.
5. Check the result:
```
ycqlsh:a> select * from t;
 h | b | c
---+---+---
 4 | 2 | 3
 8 | 6 | 7
```
EXPECTED: (see the data which were backed up)
```
ycqlsh:a> select * from t;
 h | a | b | c
---+---+---+---
 4 | 1 | 2 | 3
 8 | 5 | 6 | 7
```
Actually expected a backup-restoring error. After that the user must drop the table and restore it from scratch.
Automatic table dropping here is not recommended to prevent the table drop by mistake (in the backup-restoring process).
- Fixed by the commit above.
