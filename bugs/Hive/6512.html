Title

change WM syntax to avoid conflicts with identifiers starting with a number

Description
Time/etc literals conflict with non-ANSI query column names starting with a number that were previously supported without quotes (e.g. 30days).
Discussion
- ashutoshc  can you take a look? I tried to change  StringLiteral to be either existing generic patterns or the new ones in quotes (after adding quotes to the new ones themselves), but that doesn't get recognized as StringLiteral in select list. So, I just replaced it w/a string literal.
- +1  
Thing to note that : Quotes around time unit feel unnatural. Since, identifiers are not allowed to begin with digits in standard (other DBs disallow that) we can allow the original grammar but that would break back compat of Hive. So, when we break compatibility (in next major version) by disallowing identifiers beginning with digits we may revert this patch. In the meanwhile, we can allow this with config (default to false) which makes Hive compliant. If thats useful that can be a followup.
