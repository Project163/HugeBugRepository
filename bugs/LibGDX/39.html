Title

[Intersector] intersectRayPlane & intersectLinePlane Bug

Description
The calculation of t in both methods is incorrect, as shown below.

It is:

``` java
float t = -(origin.dot(plane.getNormal()) + plane.getD()) / denom;
```

and should be:

``` java
float t = (-origin.dot(plane.getNormal()) + plane.getD()) / denom;
```

You can see that the current implementation is incorrect using the following code:

``` java
Vector3 intersection = new Vector3();
Ray ray = new Ray(new Vector3(10, 0, 10), new Vector3(-1, -1, -1));
Intersector.intersectRayPlane(ray, new Plane(new Vector3(0, 1, 0), 5), intersection);
```

intersection will be (5.0,-5.0,5.0) which is obviously not a point on the given plane.

The implementation also limits t to values >= 0 which I think is mathematically not correct.
Discussion
- the plane equation is 

```
nx * px + ny * py + nz * pz + d = 0
```

Where n is the normal, p a point on the plane and d the shortest distance between the plane and the origin. Using (5, -5, 5) as a point you claim is not on the plane we get:

   0 \* 5 + -5 \* 1 + 0 \* 5 + 5 = 0

So, that point is actually clearly on the plane.

Limiting t to the range [0,1] for line/plane interesection is indeed non-sensical. I fixed this.

Limiting t >= 0 is however mathematically correct for ray/plane interesection, so i left it as is.

I'm not sure why you'd put the minus sign where you think it should be put.
