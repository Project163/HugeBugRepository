Title

joinWith() fails with relations provided by behaviors attached via DI configuration

Description
### What steps will reproduce the problem?

1. Create `\yii\db\ActiveRecord`, eg. `Post`, and override `instantiate()`:
```php
public static function instantiate($row) {
	return Yii::$container->get(static::class);
}
```
2. Create `\yii\base\Behavior`, eg. `PostBehavior`, which contains a new *user* relation for `Post`:
```php
public function getUser() {
	return $this->owner->hasOne(User::class, ['id' => 'user_id']);
}
```
3. Attach `PostBehavior` to `Post` using DI container definitions, eg.:
```php
'container' => [
	'definitions' => [
		'common\models\Post' => [
			'as myBehavior' => 'common\behaviors\PostBehavior',
		],
	],
],
```

4. Execute `Post::find()->joinWith('user')->all();`

### What is the expected result?

Everything works fine if `PostBehavior` is added directly inside `Post::behaviors()`, but fails when included through application's DI container definitions.

### What do you get instead?


### Additional info

The problem appears to lie in [Link: `\yii\db\ActiveQuery::buildJoinWith()`], where our ActiveRecord is being instantiated using `new $this->modelClass` rather than `Yii::createObject($this->modelClass)` thus causing the relations defined via DI-provided behaviors to be disregarded.
