Title

Webpack 5.22. `compiler.modifiedFiles` is undefined in watch build when config is an array.

Description
# Bug report

 
 
 
 

**What is the current behavior?**
I've got a webpack plugin which reads modified files from the `compiler.modifiedFiles`. When the webpack config  is an array, then the `modifiedFiles` is `undefined` when the plugins tap callback is called after a file change.

**If the current behavior is a bug, please provide the steps to reproduce.**
see the minimal reproduction repo: [URL]
i.e. 
```
javascript
// webpack.config.js

class SomePlugin {
  apply(compiler) {
... [Log Snipped] ...
  },
];
```

 
 
 
 
 
 

**What is the expected behavior?**
I would assume the `modifiedFiles` property has the list of changed files regardless of plugin being part of a multi webpack config or a single one.


 
 

**Other relevant information:**
webpack version:  5.24.0
webpack-cli: 4.5.0
Node.js version: 14.15.0
Operating System: Windows 10

(**might** be relevant information) There were some changes in PR #12671 namely in [Link: Watching.js:91]: 
`this.compiler.modifiedFiles = watcher.aggregatedChanges;`
but the `watcher` is the returned object from NodeWatchFileSystem.js's watch method ([Link: NodeWatchFileSystem.js:89]) not the reference to the `watchpack`'s watcher instance. maybe that leads to changes being always undefined?
