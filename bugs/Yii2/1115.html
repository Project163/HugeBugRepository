Title

Wrong behavior when reseting sequence on MSSQL tables

Description
The method [Link: `\yii\db\mssql\QueryBuilder::resetSequence`] don't calculate the `RESEED` value correctly.

Currently we use `"SELECT COALESCE(MAX({$key}), 0) + 1 FROM {$tableName}"`.

The official documentation [Link: link] specify than if the table as records, the next row will increment the value used in `RESEED`.

So if the max id is 10 and we set 11 in the `RESEED` the next row will use 12 as id and there will be a gap in the sequence.

An easy fix will be to use `"SELECT COALESCE(MAX({$key}), 1) FROM {$tableName}"`

The documentation also said [Link: link] than to reset an empty table sequence, the value to use depends on the way the table as been cleared.

If the table has been truncated we need to use 1 (because there will be no increment) but if it has been deleted we should use 0 because there will be an increment.

We could check in the `sys.identity_columns` table the field `last_value` to know if the table has been truncated or not (the value will be `null` in case of `TRUNCATE` and the last inserted id in case of `DELETE`
