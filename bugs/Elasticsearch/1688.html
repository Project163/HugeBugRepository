Title

Dots in field names doesn't work with nested fields

Description
On 5.0.1:

```
PUT t 
{
  "mappings": {
    "t": {
      "properties": {
... [Log Snipped] ...
  "foo": {"bar": 5}
}
```

Returns Doc 1
```
GET t/_search
{
  "query": {
    "match": {
      "foo.bar": 5
    }
  }
}
```

Returns Doc 2
```
GET t/_search
{
  "query": {
    "nested": {
      "path": "foo",
... [Log Snipped] ...
  }
}
```
Discussion
- I don't like the ambiguity that exists with dots in field names and nested mappings. For instance the below document:

```
{
  "foo.bar": 3,
  "foo.baz": 42
}
```

could be both equivalent to

```
{
  "foo": {
    "bar": 3,
    "baz": 42
  }
}
```

and

```
{
  "foo": [
    { "bar": 3 },
    { "baz": 42 }
  ]
}
```

which are indexed differently if `foo` is a nested object.

So should we reject dots in field names when the dot is a delimitation for a nested object?
- I think we should.  How do we do this in a way that doesn't break behaviour in a minor version?
