Title

Accord: jvm-dtest changed semantics of uncaughtExceptions handling which broke tests that depended on the prior semantics

Description

    
Discussion

    
- CASSANDRA-20069   refactored jvm-dtest which caused this test to fail.  Alex/Benedict/I talked about it and the following is what we talked about 

 1) the change was trying to cleanup the logic where we try to find the right cluster, and make sure we call JVMStabilityInspector correctly.  This logic basically tries to solve  CASSANDRA-19515  
2) the change to mark corruption as unhandled was not intentional, and Alex/Benedict are +0 to going back to the old semantic. 
3)   CASSANDRA-20069   moved to using reflection to call JVMStabilityInspector rather than Instance.uncaughtException, this can become an issue for upgrade tests when and if that internal class has a API change... we should revert back to using Instance.uncaughtException to avoid breaking upgrade tests in the future
