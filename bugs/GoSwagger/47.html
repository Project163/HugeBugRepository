Title

format of parameters leads to bad generated code

Description
If a parameter has a format the generated code will not compile:
Examples: 

```
json
{
  "consumes": [
    "application/json",
    "application/x-www-form-urlencoded"
... [Log Snipped] ...
  "swagger": "2.0"
}
```

And some console output:

```
shell
$ swagger generate client -f testapi.json
2016/01/06 13:20:16 rendered client parameters template: operations.PutTestingParameters
2016/01/06 13:20:16 rendered client responses template: operations.PutTestingResponses
2016/01/06 13:20:16 rendered operation group client template: operations.OperationsClient
... [Log Snipped] ...
operations/put_testing_parameters.go:41: invalid operation: fTestingThis != "" (mismatched types strfmt.Date and string)
operations/put_testing_parameters.go:42: cannot use fTestingThis (type strfmt.Date) as type string in argument to r.SetFormParam
```

This was found with a parameter of an array type with elements which had format: 

```
json
{
  "consumes": [
    "application/json",
    "application/x-www-form-urlencoded"
... [Log Snipped] ...
  "swagger": "2.0"
}
```

Which does not compile with a similar error:

```
shell
$ swagger generate client -f testapiarray.json
2016/01/06 13:32:05 rendered client parameters template: operations.PutTestingParameters
2016/01/06 13:32:05 rendered client responses template: operations.PutTestingResponses
2016/01/06 13:32:05 rendered operation group client template: operations.OperationsClient
... [Log Snipped] ...
$ go build
operations/put_testing_parameters.go:41: cannot use valuesTestingThis (type []strfmt.Date) as type []string in argument to swag.JoinByFormat
```

And final example:
If the type of the items is referenced:

```
json
{
  "consumes": [
    "application/json",
    "application/x-www-form-urlencoded"
... [Log Snipped] ...
  "swagger": "2.0"
}
```

Which results in 

```
shell
$ swagger generate client -f testapi2.json
2016/01/06 13:38:37 rendered model template: testType
2016/01/06 13:38:37 generated model testType
2016/01/06 13:38:37 ren
...[Description Truncated]...
Discussion
- The 3rd case is an invalid case because you can't use $ref in that position according to the swagger specification json schema.
- @casualjim the 3rd example was my try at working around the problem. It looked valid from the [Link: specification], but I am only reading trough it for the second time :)

On the question of the bug: 
I agree that the fix fixes the showed problem above, but I it doesn't work for all possible formats, for example it doesn't work with hostname.
