Title

Dynamic date detection accepting years < 4 digits

Description
Dynamic date detection should only detect 4 digit years, but it is misinterpreting the `5` in `5/12/14` as the year `0005`:

```
DELETE /t

PUT /t/t/1
{
  "d": "5/12/14"
... [Log Snipped] ...
  }
}
```

Returns: 

```
"aggregations": {
  "foo": {
     "buckets": [
        {
           "key_as_string": "0005/12/14 00:00:00",
... [Log Snipped] ...
  }
}
```
Discussion
- looked at the iso 8601 spec, which seems to define a year has to have four digits... however the predefined joda time formatters do not seem to be strict here
- maybe we should file a bug in JODA or maybe it's already fixed and we should upgrade?
- ... [Middle Discussions Snipped for Brevity] ...
- By copy pasting a fair share of code around (from the `ISODateTimeFormat` class), we can definately make this more strict. Asked on the joda ML if this the intended behaviour and if there are smarter ways to make parsing strict and will then decide on the implementation
- Given that this is somewhat of a breaking change (it's a bug fix that will likely break some ingestion) I'm going to push to 2.0.  

For now people that encounter the issue have to define a mapping for the field
