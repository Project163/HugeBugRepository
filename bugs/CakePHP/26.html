Title

Inflector::slug() doesn't handle correctly non breakable spaces on Windows

Description
I found this bug using cake 1.3 but I believe it is present in later versions.
My dev config (on which the bug occurs) is Windows XP Professional x64 Edition Service Pack 2 with PHP 5.4.19
On my linux box the bug seems not to occur.

Test case:

```
    // write a string containing a nbsp
    $string = 'word1'."\xc2\xa0".'word2';

    // slugify it
    debug(Inflector::slug($string));
```

It should outputs the following:
        word1�_word2

While we expect the following:
        word1_word2

My guess about how to fix it:
add '/\xC2\xA0/' to the preg_replace map in the slug function, however I don't really understand how regex internally works and so I fail to understand why the bug is OS depedent.
Discussion
- It might be related to PCRE libraries on the platform. If the same code works on linux server, I suspect issues with PCRE libraries.

- I ran some tests to check where the problem lies. It showed that the newer PCRE lib version (shipped in with newer PHP version as well) doesn't match anymore the unicode non breaking space (\xc2\xa0) with \s pattern. This \s is used in the inflector::slug() code which explain the differents behaviors I noticed.

Tested this on [URL] (don't know if the link will stay available so I paste result here:)

```
    var_export(preg_replace('/[\s]/mu', '_', 'word1'."\xc2\xa0".'word2 word3'));
```

Output for 5.3.4 - 5.5.6
        'word1_word2_word3'

Output for 4.3.0 - 5.3.3
        'word1 word2_word3'

The eroneous inflector::slug() return is starting with php 5.3.4, which is packed with PCRE lib version 8.10 (see [URL] )

Since the bug is linked to newer PCRE versions, I suppose the bug will apear more and more as people will upgrade there stack. So maybe there's something we could do about it.
