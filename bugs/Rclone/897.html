Title

Backblaze needs the equivalent of `--s3-max-upload-parts` which defaults to 10000

Description
It's entirely possible that I'm wrong on this, but I think I've figured out why extremely large (9TB) uploads were failing to back blaze. The chunk size was producing > 10000 parts. I see that on the `s3` backend you have logic that will increase the size of the chunks to maintain the 10,000 part limit by s3.

On Backblaze this doesn't seem to work. I was uploading chunks much smaller than this resulting in > 10000 parts. For a 9TB file, the minium chunk size is about 9.5 GB per chunk. Rclone was reporting that 96MB chunks were being uploaded.

This would explain why I was failing to upload at around the 10% mark.

This request is to copy the logic of chunk size promotion in the B2 service to match S3

The problem here is that b2 is limited to 10000 parts and so as you noticed it calculates the minimum chunk size. However there was a bug and this value is never used in b2, explaining the defaulting to 96M. This also happens to limit the maximum file size you can send to 96M*10000, which is below your file size.
