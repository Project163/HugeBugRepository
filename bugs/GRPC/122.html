Title

Unused artifacts are not removed from Ruby gem during source compile

Description
As reported [Link: here], a regression was introduced for the fix for #33596: in the following commit: [URL]

As noted in that comment:

The comment author also provides an [Link: example] of the bloat reported by the gem:

### What version of gRPC and what language are you using?

While the original comment author reported this on grpc 1.60.0, I can confirm that it is still an issue on grpc 1.71.0.  This is for Ruby.

### What operating system (Linux, Windows,...) and version?

Linux, both `Ubuntu 20.04.6 LTS` and `Ubuntu 22.04.5 LTS`

### What runtime / compiler are you using (e.g. python version or version of gcc)

Tested on both gcc `9.4.0` and `11.4.0`

### What did you do?

Create `Gemfile`:

```ruby
gem 'grpc', '1.71.0'
```

Install gem, forcing it to be compiled from source:

```sh
bundle config set --local force_ruby_platform 'true'
bundle install
```

Once installed, check the disk usage:

```sh
du -h -d 1 $(bundle show grpc)
```

### What did you expect to see?

Something similar to grpc 1.58.0:

```sh
68M	/usr/local/rvm/gems/ruby-3.4.1/gems/grpc-1.58.0/src
264K	/usr/local/rvm/gems/ruby-3.4.1/gems/grpc-1.58.0/etc
540K	/usr/local/rvm/gems/ruby-3.4.1/gems/grpc-1.58.0/include
19M	/usr/local/rvm/gems/ruby-3.4.1/gems/grpc-1.58.0/third_party
88M	/usr/local/rvm/gems/ruby-3.4.1/gems/grpc-1.58.0/
```

### What did you see instead?

Significantly more disk usage:

```sh
du -h -d 1 $(bundle show grpc)
2.6G	/project/vendor/bundle/ruby/3.4.0/gems/grpc-1.71.0/src
264K	/project/vendor/bundle/ruby/3.4.0/gems/grpc-1.71.0/etc
568K	/project/vendor/bundle/ruby/3.4.0/gems/grpc-1.71.0/include
20M	/project/vendor/bundle/ruby/3.4.0/gems/grpc-1.71.0/third_party
2.6G	/project/vendor/bundle/ruby/3.4.0/gems/grpc-1.71.0
```

### Anything else we should know about your project / environment?

None
