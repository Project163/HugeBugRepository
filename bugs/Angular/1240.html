Title

Injector#get is typed incorrectly

Description
# 🐞 bug report

### Affected Package
The issue is caused by package @angular/core or @angular/forms (see comments below).

### Is this a regression?
No.

### Description
`Injector#get` is currently typed to return `T` for `InjectionToken `. This is, however, incorrect for `multi: true` injection tokens where calling this method (correctly) returns `T[]`.

*Update*: If the intention is that the InjectionToken is already typed as an array, then `NG_VALUE_ACCESSOR` is currently typed incorrectly.

## 🌍  Your Environment

**Angular Version:**
  7.3.5
Discussion
- I always use an array type in `InjectionToken`'s generic type parameter for multi providers. Then the types align and users of the token can derive it needs to be `multi: true`  

That is not entirely accurate, as a single array value would also be an option, however this is the general problem with providing a value for a token: there's no type safety enforced there.
- OK, so specifically I am talking about `NG_VALUE_ACCESSOR`. As someone on [Link: StackOverflow] pointed out, if the token is typed as `InjectionToken `, the `get` method behaves correctly.

So the question here is how the Angular team intends the API to work. Depending on that decision the bug is either

1. `Injection#get` is not typed correctly
2. `NG_VALUE_ACCESSOR` isn't typed correctly
- `NG_VALUE_ACCESSOR` is not type correctly. Would you mind creating a PR to fix it?
