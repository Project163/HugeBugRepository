Title

Sorting of at least Decimal(20, 2) fails for some values near the max.

Description
I have been doing some testing with Decimal values for the RAPIDS Accelerator for Apache Spark. I have been trying to add in new corner cases and when I tried to enable the maximum supported value for a sort I started to get failures.  On closer inspection it looks like the CPU is sorting things incorrectly.  Specifically anything that is " .50" or above is placed as a chunk in the wrong location in the outputs. 

  In local mode with 12 tasks. 
  
 
spark.read.parquet( "input.parquet" ).orderBy(col( "a" )).collect.foreach( System .err.println)  
  
   

 Here you will notice that the last entry printed is   [ .49]  , and   [ .99]   is near the top near   [- .99]
Discussion
- I have been trying to debug this and it does not look like it is related to the partitioner. I can run with a single shuffle partition and I get the same results. Not sure if the prefix calculation is doing this or what.
- It sure looks like it is related to the prefix calculator. I think it is overflowing some how. I added some debugging into 3.2.0 and I got back 

  
 
22/08/15 20:17:58 ERROR SortExec: PREFIX FOR  .99 IS  false  - 
 
  

 The prefix should not be negative for non-negative values.
