Title

RT error calling CreateMap: Cannot find a field or property named X

Description
I am trying to run my app under AutoMapper 4.0.4 for the first time.  Previously this code was working on 3.3.1.  This is a Windows UWP app (actually a UWP class lib that is part of a larger UWP app solution), VS2015, on Windows 10.

I am calling CreateMap (). My UserInfoDTO class is a bare-bones DTO, and UserInfo is more of my domain model.  UserInfo has properties that shouldn't be mapped. 

When I execute, I'm getting this exception:

Exception thrown: 'System.ArgumentOutOfRangeException' in AutoMapper.dll
System.ArgumentOutOfRangeException: Cannot find a field or property named Errors
Parameter name: name
   at AutoMapper.Internal.MappingExpression`2.ForMember(String name, Action`1 memberOptions)
   at AutoMapper.ConfigurationStore.CreateMappingExpression[Link: TSource,TDestination]
   at AutoMapper.ConfigurationStore.CreateMap[Link: TSource,TDestination]
   at AutoMapper.ConfigurationStore.CreateMap[Link: TSource,TDestination]
   at AutoMapper.ConfigurationStore.CreateMap[Link: TSource,TDestination]
   at AutoMapper.Mapper.CreateMap[Link: TSource,TDestination]
   at Xiard.MVVM.Core.CoreDTOManager.InitializeMappings()

The class hierarchy for UserInfo is UserInfo   _errors = new ObservableCollection ();
    [SQLite.Net.Attributes.Ignore, AutoMapper.IgnoreMap]
    public ObservableCollection  Errors { get { return _errors; } }
```

From the error, it sounds like AutoMapper may be looking for an Errors property on UserInfoDTO (which doesn't exist). But I would have thought the AutoMapper.IgnoreMap attrbute would have taken care of that.

I'm fairly new to AutoMapper, so I don't know if there is something I need to be doing to configure AutoMapper specifically to handle this case.

Any idea what I'm doing wrong?
Discussion
- I downloaded the code and was able to add AutoMapper.WPA81 to my solution and debug it directly.  The issue appears to be related to the fact that AutoMapper.TypeInfo.GetAllPublicMembers gets public members for all types up the inheritance chain (adding BaseTypes to typesToScan).  That seems reasonable.
But then the code in AutoMapper.ConfigurationStore::CreateMappingExpression that handles IgnoreMapAttribute gets hit.  That code calls mappingExp.ForMember, which ultimately calls TypeExtensions.GetProperty on my destination type (UserInfo in this case).  Here's that function:

```
    public static PropertyInfo GetProperty(this Type type, string name)
    {
        return type.GetTypeInfo().GetDeclaredProperty(name);
    }
```

GetDeclaredProperty will only return properties declared on the actual type, not properties declared on base types.  So the ModelBase.Errors property is found in GetAllPublicMembers, but it isn't found when the code tries to ignore it.
Not sure exactly what to do about that...but I'll probably add a TypeExtensions.GetPropertyDeep method for now that will walk up the BaseType looking for the property being requested, and then modify MappingExpression.ForMember to use that instead.  That seems the least likely to cause unexpected side effects for me.
