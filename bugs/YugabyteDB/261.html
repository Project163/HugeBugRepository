Title

[YSQL] ysql functionality doesn't work if --flagfile argument is specified as relative path instead of full path

Description
(Tested via `ysqlsh` and Java JDBC, on both v1.3.2.1 and latest master 6c8d530)
If the yb-tserver is started using `--flagfile` (as per docs [URL] YSQL API can't connect. Postgres log shows a single log line like this per each connect attempt:
```
tserver.conf: No such file or directory
```
(no date, no error source, just this)

Here's how it looks like from client's perspective:
`ysqlsh`:
```
$ ./bin/ysqlsh -h

	This probably means the server terminated abnormally
	before or while processing the request.
```

- @frozenspider For now, you can workaround this by specifying the full path for `--flagfile`.
- What happens is that YB init code (which inits gflags) inside postmaster process triggers after postmaster changed its own working directory to data directory.
