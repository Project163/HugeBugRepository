Title

Broken Mail Headers with MailTransport and PHP 8

Description
This is a (multiple allowed):

* [x] bug

* CakePHP Version: 4.2.8.
* Platform and Target: Apache 2.4, PHP 8.0.8

### What you did
Upgraded existing Cake 4.2.8 application from PHP 7.4 to PHP 8. Tested applications mail functionality.
Mail Transport is configured like this:
```
'EmailTransport' => [
        'default' => [
            'className' => 'Mail',
            'host' => 'localhost',
            'port' => 25,
... [Log Snipped] ...
        ],
[...]
```

### What happened
While everything works as expected on PHP 7.4, on PHP 8.0.8 the emails sent have broken headers and cannot be displayed correctly or are rejected by the server.
Sending with Smtp transport works fine in PHP 8.
Below is an example of a broken Mail (see the whitespaces as first char at some header lines):
```
To: xxx
Subject: xxx
Date: Tue, 31 Aug 2021 14:17:44 +0200
 Message-ID:  
 MIME-Version: 1.0
... [Log Snipped] ...
Message-Id:  
From: xxx
```

### What you expected to happen
The mail should contain correct headers.
This seems to be related to a problem that exists in several Mail Libraries e.g. here: [URL]

in `vendor/cakephp/cakephp/src/Mailer/Transport/MailTransport.php` line 44 is:
```
$eol = $this->getConfig('eol', PHP_EOL);

$headers = $message->getHeadersString(
    [
        'from',
... [Log Snipped] ...
    }
);
```
On linux environments PHP_EOL should be \n which is then used to implode the headers. This may cause the problem.
If you add ` 'eol' => "\r\n"` to the `EmailTransport` config everything works as expected on PHP 8.
In `vendor/cakephp/cakephp/src/Mailer/Transport/SmtpTransport.php` line 408 is:
```
return implode("\r\n", $messages);
```
which will implode the headers correctly with "\r\n". This should be the default case in MailTransport too I think.
Discussion
- I think php 8 might have updated how it uses newlines according to the spec.
