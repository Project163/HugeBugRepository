Title

Log Exception when the provided config file could not be parsed

Description
Currently, when the exisiting config file `config.xml` could not be parsed, ZAP uses its own config file as it copies a default `config.xml` in the working directory (this can be provided by `-dir`).

That's fine, the problem is, the user won't get informed about that. I suggesst logging this exception and present the user a warning message. 

This is the [Link: corresponding code]:


```
...
} catch (ConfigurationException | ConversionException | NoSuchElementException e) {
	            //  if there is any error in config file (eg config file not exist, corrupted),
	            //  overwrite previous configuration file 
	            // ZAP: changed to use the correct file
	            copier.copy(getPathDefaultConfigFile().toFile(), new File(FILE_CONFIG));
	            
	        }
```
