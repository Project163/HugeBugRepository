This looks like a deadlock of some kind. There are two listing processes running one for the source and one for the destination and they appear to have deadlocked here

[URL]

[URL]

So whatever is supposed to be reading from those channels is not reading them.

There is no HTTP activity (or any other kind of activity other than waiting for locks or channels) in the backtrace so we aren't waiting for either of the backends to return a directory listing.

It really looks like a deadlock :-(

There are 8 copies of `matchListings` runnings (which is correct according to your `--checkers` which is at the default of `8`). Each of these is checking a different directory, but two have deadlocked in exactly the same way which is surprising.

The last deadlock started 34 minutes before you killed rclone which is about the time of this log

```
DEBUG : PATH/TO/YET/ANOTHER/FILE: Sizes identical
DEBUG : PATH/TO/FILE/AGAIN: Unchanged skipping
DEBUG : PATH/TO/LAST/FILE/CHECKED: Unchanged skipping
```

Which are the last files transferred. It is as if rclone didn't notice the listings had finished for some reason.
