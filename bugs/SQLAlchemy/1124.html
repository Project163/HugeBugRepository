Title

Spurious “Unmanaged access of declarative attribute” warning when using with_loader_criteria()

Description
I’m using a mix-in class that defines a foreign key and use this mix-in to set a query filter in a `orm_do_execute` event handler  to add a `with_loader_criteria()` object to the execution options:

```
python
@declarative_mixin
class FooOwnedMixin:
    @declared_attr
    def foo_id(self):
... [Log Snipped] ...
        )
    )
```

The `with_loader_criteria()` will actually execute the `lambda` passed in here using the mix-in as the argument for `cls`, the above triggers a warning:

```python
/.../site-packages/sqlalchemy/orm/decl_api.py:223: SAWarning: Unmanaged access of declarative attribute foo_id from non-mapped class FooOwnedMixin
  util.warn(
```

The warning is spurious because the cached statement will from there on out only be used together with the subclasses of the mix-in class.

Right now I work around this by adding a specific warning filter:

```python
warnings.filterwarnings(
    "ignore",
    "Unmanaged access of declarative attribute foo_id from non-mapped "
    "class FooOwnedMixin",
    SAWarning,
)
```

but this would also hide genuine incorrect use of the mix-in attribute in other contexts. Could the warning be disabled for this specific edge case? 

**Versions.**
 - OS: MacOS 10.15
 - Python: 3.9.4
 - SQLAlchemy: 1.4.9
 - Database: SQLite, PostgreSQL
 - DBAPI: sqlite3, psycopg2
