Title

hyper: pausing request body is signaling end-of-stream

Description
### I did this

When pausing the sending of a request body, curl's body data callback returns `HYPER_POLL_READY` with a `null` chunk, meaning the body is finished. This is likely the cause of the failures of tests 670-673.

### I expected the following

Instead, as long the body might continue in the future, curl should save a waker and return `HYPER_POLL_PENDING`. When the user code asks curl to resume again, curl internally can "wake" the waker, telling hyper to poll for data another time.

To inline the [Link: docs]:


It looks like the code in `c-hyper.c` already has support for this when waiting for expect-100 vs a timer, so it would just be expanding that.
