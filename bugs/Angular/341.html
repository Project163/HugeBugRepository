**Current behavior**
We are using Features-Modules to encapsulate things belonging together and we are using theses Features-Modules in Routing like this:

app.module.ts

```
ts
@NgModule({
  imports: [SharedModule.forRoot(),
            BrowserModule,
            RouterModule.forRoot(APP_ROUTES)
... [Log Snipped] ...
export class AppModule {
}
```

app.routes.ts:

```
ts
export function getTasksModule() {
  return TasksModule;
}

... [Log Snipped] ...
  {path: 'tasks', canLoad: [LoginGuard], loadChildren: getTasksModule},
];
```

this works fine when not doing AOT. Now when calling

```
./node_modules/.bin/ngc -p ./src
```

the application compiles without errors, but in runtime I get the following exception when enterting the `/tasks` route:

``` ts
Error: Uncaught (in promise): TypeError: r.create is not a function
    at resolvePromise (zone.js:558)
    at zone.js:535
    at ZoneDelegate.invoke (zone.js:332)
    at Object.NgZoneImpl.inner.inner.fork.onInvoke (ng_zone_impl.js:41)
```

after some debugging it looks like the application get the `TasksModule` where it needs to have the `TasksModuleNgFactory`. So the exception happens in this code:

router_config_loader.ts

``` ts
  load(parentInjector: Injector, loadChildren: LoadChildren): Observable  {
    return this.loadModuleFactory(loadChildren).map(r => {
      const ref = r.create(parentInjector);
      return new LoadedRouterConfig(
          flatten(ref.injector.get(ROUTES)), ref.injector, ref.componentFactoryResolver);
    });
  }
```

and r is TasksModule when the exeption occurs.

It should be possible to use loadChildren in combination with AOT
