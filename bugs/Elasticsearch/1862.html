Title

`ip` field does not allow prefix queries with ipv6-mapped ipv4 addresses

Description
Recreation:
```
PUT index
{
  "mappings": {
    "doc": {
      "properties": {
... [Log Snipped] ...
  }
}
```
which gives

```
{
  "valid": true,
  "_shards": {
    "total": 1,
    "successful": 1,
... [Log Snipped] ...
  ]
}
```

The issue is that the ip address is automatically translated to an ipv4 address, so we then interpret the prefix length as if the ip was an ipv4 address.
Discussion
- It is not easy to fix solely in Elasticsearch so I opened a Lucene issue for discussion. [URL]
- I am passing along some additional comment by the customer.
Hopefully, it gives you more clarity to the problem.

```
only in my use case,
If IPv4 and CIDR >= 96, there is no problem when
the value like(specified CIDR -96) is used internally.
 
 
... [Log Snipped] ...
not work: client_ip:"::ffff:0:0/95"
-> I do not plan to use this query
```
- We couldn't reach agreement as to what to do in that case so we will just disallow prefix queries on ipv6-mapped ipv4 addresses since they introduce ambiguity as to how the prefix length should be interpreted.
