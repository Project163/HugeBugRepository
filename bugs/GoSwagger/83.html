Title

generate spec for embedded struct: unknown primitive

Description
The spec generate will often fail for me given the following definitions (for example)

```
go
// ActionParam
//
// swagger:parameters actionParam
type ActionParam struct {
... [Log Snipped] ...
    FieldC int`
}
```

Generating a spec for this file will yield: `unknown primitive "actionParam"`
Changing around all the fields, names, etc does not fix the issue.

Currently on go 1.5.2 darwin/amd64 with the latest version of swagger.
Discussion
- I have a hard time reproducing this. When I include the file in my test application it just passes
- Yes, it seems like a flaky issue - I might try running the tool on another machine or platform, but it seems doubtful that that would fix the issue. Some more information about the project: 
- there are many different packages in the project that depend on each other (the issues appeared in sub-sub packages from the root, but this is probably more correlation than causation)
- the problem will often go away when moving the struct declarations to another file in the same package but sometimes not
- in a previous version of go-swagger, the error would read `unknown primitive "error"`

I've since moved all of the swagger comments from the project and will define everything in a .yml instead.

- I confirm. I found a similar error: unknown primitive "MyTypeName".

And this error is **random**.

I traced the error.

schemaParser.parseIdentProperty() call findSourceFile(), scan/schema.go, line about 690
findSourceFile (pkg \* loader.PackageInfo, typeName string), scan/schema.go, line about 760
This function not found information **sometimes**.

I traced next.

findSourceFile() called **with incorrect pkg parameter** sometimes. My package have name "myPackagePath/errors". It is similar golang system package name "errors". 

Sometime findSourceFile called with correct package name "myPackagePath/errors" and my correct typeName
Sometime findSourceFile() called with **incorrect package name "errors"** and my correct typeName

Under Linux (Ubuntu 14.04, 64-bit) and MacOS X (Yosemite) same. With Go 1.5.2, 1.6 - 64-bit
Under Windows 10, 64-bit - no errors. Or it is random? )))
- I was fool this bug.
I was rename my package "myPackagePath/errors" to "myPackagePath/apierrors".
go-swagger works fine after.

Problem is **random package names**. See my message above.
