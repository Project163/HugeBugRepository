Title

Windows - External File Versioning Command path requires \\ instead of \

Description
### What happened

On Windows, an external versioning command path requires \\\\ (two backslashes) instead of single \\.
This sounds a bit unnatural and the instruction in [Link: the doc page] doesn't work.

### Any steps to reproduce the problem.

For example, if the command is set like this:

[Image: iss]
then I get this error log:
`[VQZ3H] 2017/11/30 00:25:31.724302 rwfolder.go:1675: INFO: Puller (folder "\"sttest\" (vu3ga-eo2y9)", file "test.txt"): delete file: exec: "C:UserstestusrDesktopext.bat": file does not exist`

OK the path isn't recognized correctly with single \ for some reason.

I found two workarounds:
- use \\\\ instead of \\
- use / (this is uncommon for windows)

### Version Information

Syncthing Version: v0.14.40
OS Version: Windows 10 x64
Browser Version: Edge
Discussion
- I'll try to fix this in the following days.
- I suspect it's due to the shell escaping library, which might not be needed at all, as we are not parsing external input.

The purpose of it was to handle cases where folder path contains spaces.
I guess we need a test case there.
- Or, possibly, different treatment just on Windows where backslash is not to be interpreted as an escape.
