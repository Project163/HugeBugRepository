Title

[bug]css font property compile bug

Description
in the latest less version(1.4.1),

I write the css `font:bold 14px/30px "Simsum";` in a less file (which means font-weight:bolder ; font-size:14px; line-height:30px; font-family:"Simsum";),

but after compile using lessc --compress , the result is `font:bold .4px "Simsum" ;`which is unexpected
Discussion
- Either use the strictMath option, which requires all math to be in
parentheses (and therefore preserves maths not in parentheses) or use
~"14px/30px"

We put in strictMath so less would be able to compile css as is and be a
strict superset.

Having said that, this is still a bug - I thought I kept some logic in
keeping the font property special for backwards compatability...
- yes, this should be fixed asap
- The LESS website still offers 1.4.1 as the latest stable release, even though it has a serious bug. Please update the site to provide 1.4.2 for download.
