Discussion
- I thought we should just use the new type system for  CollectBatchTableSink  and  CollectStreamTableSink . However, according to the JavaDoc of  TableSink.getOutputType()  and  TableSource.getReturnType() , user should " use either the old or the new type system consistently to avoid unintended behavior ". And if the table sinks created in SQL client need to support table sources that may use new or old type systems, I'm not sure whether we have to create different sinks for new and old type systems respectively?
- Just created a PoC pull request to get some feedbacks. 
It seems we don't have to worry about the type system inconsistency between source and sink, because we create the sink using the table schema of the source table. Therefore I think we're good as long as we avoid the conversion between  DataType  and  TypeInformation  in the sinks.
