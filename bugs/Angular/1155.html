Title

routerLink queryParams and fragment return in opposite order

Description
## I'm submitting a...
[x] Bug report 
or
[x] Documentation issue or request
  

## Current behavior
When using routerLink with both a fragment and queryParams, routerLink generates a link with first the queryParams and the fragment at the end.

example: 
```
 
  link to user component
 
```
generates: /user/bob?debug=true#education


## Expected behavior
According to routerLink documentation, it should be returned in the opposite order: 

/user/bob#education?debug=true

[Link]

## What is the motivation / use case for changing the behavior?
Either routerLink is behaving incorrectly or the documentation has an error.
