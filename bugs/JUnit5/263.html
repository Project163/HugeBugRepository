Title

`TestRun` in Vintage omits suppressed exceptions when creating `MultipleFailuresError`

Description
# Overview

Thanks to the tip from @DidierLoiseau (see [URL] I have confirmed that the changes made in #1602 should also be applied in `org.junit.vintage.engine.execution.TestRun.getStoredResultOrSuccessful(TestDescriptor)`.

The reason is that `org.junit.internal.runners.model.EachTestNotifier.addMultipleFailureException(MultipleFailureException)` invokes `org.junit.runner.notification.RunNotifier.fireTestFailure(Failure)` for each failure in the supplied `org.junit.runners.model.MultipleFailureException`.

This can happen if you are using the JUnit 4 `ErrorCollector` rule.

## Deliverables

- [x] Add suppressed exceptions to the `MultipleFailuresError` created in the Vintage `TestRun`.

I doubt that it had anything to do with `MockMvc` directly.

The issue only occurs if an `org.junit.runners.model.MultipleFailureException` is thrown that contains multiple failures.

The `ErrorCollector` rule is an easy way to reproduce this, and `org.junit.vintage.engine.samples.junit4.JUnit4TestCaseWithErrorCollectorStoringMultipleFailures` in our test suite is what I'm using to test it.
- IIRC it had to do with MockMvc's `ResultAction.andExpect()`, but I might be wrong.
