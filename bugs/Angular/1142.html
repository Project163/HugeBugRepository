Title

platformBrowser().bootstrapModule does not work under Closure Compiler ADVANCED_OPTIMIZATIONS

Description
# 🐞 bug report

### Affected Package
@angular/platform-browser, @angular/compiler-cli, @angular/core


### Is this a regression?
Lack of parity between Ivy and ViewEngine.

### Description
* When compiling an application with Ivy (aot: true) with an entry point that contains `platformBrowser().bootstrapModule(AppModule)` and then running it through the Closure Compiler's advanced optimizations:
  * `BrowserModule`'s providers are removed as dead code which causes the application to fail to bootstrap with the error `"No ErrorHandler. Is platform module (BrowserModule) included?"`

* Compiling the same application with Closure's simple optimizations:
  * Application renders as expected.

* Changing the entry point to use `ɵrenderComponent(AppComponent)` and using advanced optimizations:
  * Simple application renders as expected.
  * Complex app fails with `'${type.name}' is neither 'ComponentType' or 'DirectiveType'.` for just about every Angular-owned dependency (e.g. RouterModule)

Discussion
- It turns out `ɵrenderComponent` worked for the simple example I built, but doesn't work for an application that has deps on anything published by Angular (e.g. RouterModule).  I've edited the original post to reflect this.
- Closure is changing something like
```javascript
function CommonModule() {
}
CommonModule.ɵmod = ɵngcc0.ɵɵdefineNgModule({ type: CommonModule });
```
To
```javascript
function CommonModule() {
}
ɵngcc0.ɵɵdefineNgModule({ type: CommonModule });
```
- I'm 90% certain that having `ngcc` emit `/** @nocollapse */` comments would fix this.
- I've confirmed that #36652 does actually fix this, and I was able to successfully bootstrap our application using Ivy and advanced optimizations with that patch applied.
