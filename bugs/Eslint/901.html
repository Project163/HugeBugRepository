Title

no-return-assign "always" still allows assignment if using OR in return statement

Description
**What version of ESLint are you using?**
eslint@1.10.3 AND eslint@2.8.0

**What parser (default, Babel-ESLint, etc.) are you using?**
default

**Please show your full configuration:**

```
{
    // ESLint Configuration File
    // see eslint.org for more details

    // 0 = off
... [Log Snipped] ...
    }
}
```

**What did you do? Please include the actual source code causing the issue.**

```
var fn = (function() {
    var a = true;
    if (a) {
        return (a = "thing"); // has eslint 'no-return-assign' error
    }
... [Log Snipped] ...
    return true;
}());
```

**What did you expect to happen?**
A 'no-return-assign' error

**What actually happened? Please include the actual, raw output from ESLint.**
No error found.

```
$ grunt eslint:errors
```

...note no error present for line 7.
Discussion
- I don't think this rule is meant to be that smart. Would you also expect it to catch this?

``` js
(function(){
  var a = 0;
  return (function(){ a = 1; return a; }());
}());
```
- I don't think so, as that looks like a legitimate assignment before returning a value...rather than an assignment as part of an expression.
- ... [Middle Discussions Snipped for Brevity] ...
- Yeah, that is my assumption.
Generalising a bit: I thought the rule would prevent assignments in situations where they can be confused with comparisons.
- `no-cond-assign` rule is warning both patterns. So I think we should fix `no-return-assign` rule.
