Title

die disk failure policy will not kill jvm as documented

Description
After Cassandra has successfully starts up with disk_failure_policy die, when encounter a file system error, Cassandra server will only throw exception instead of shut down gossip and client transport and kill JVM. Document:  [URL]

   

 The reason for this is the default FS error handler is not handing policy die correctly. Instead of shutting down gossip and native transport, it throws an error. 

   

 The JVMStabilityInspectorTest is passing because the error handler is not set so no exception is thrown.
