Discussion
- dengzh , we have seen the similar stacktrace in hive4 on MaterializationsRebuildLockCleanerTask. If I recall correctly, it was because of  mysql  configuration  transaction_isolation.  By default it is  REPEATABLE-READ  and it needs to be set to  READ-COMMITTED  to avoid this issue.  

   

 CC  Indhumathi27
- Aggarwal_Raghav  yes, changing the isolation level can solve the issue, I was thinking making the  READ-COMMITTED  as default in TxnStore, where the isolation used to be.
