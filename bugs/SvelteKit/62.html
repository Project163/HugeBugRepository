Title

`fetch` of URL with space fails during prerendering with `npm run build`

Description
**Describe the bug**
When fetching an URL that contains spaces e.g. `/my static file.md` (escaped `/my%20static%20file.md`), the `fetch` tries to access a double escaped url `/my%20static%20file.md` (escaped `/my%2520static%2520file.md`) and generates a 404 html page in the file system under `/build/my%20static%20file.md/index.html`. On the browser side, the fetch works.


**To Reproduce**

Make a route with a load function that fetches an URL with spaces in it. Use adapter static. The file will be fetched correctly in the browser but will fail during generation with `npm run build`.

I can make an example repo later if needed.

**Expected behavior**
Build passing and no `/build/my%20static%20file.md/index.html` file generated.

Discussion
- As I explained in the discussion  I was passing a string with spaces as a file name and escaped it with `encodeURIComponent`:


```
        const path = `/articles/recipe/${encodeURIComponent(recipe.name)}.md`
        article = await fetch(browser ? path : `${assets}${path}`)
```

As `recipe.name` is a user-submitted string, I want to prevent path traversal etc. This might be relevant for debugging.

It seems that Svelte tries to escape an already escaped string. I am not quite sure if I am supposed to escape the URL component myself before passing it into `fetch` (for the record, I think I should?) - but either way - on the browser side the `fetch` doesn't seem to mind when I give it an escaped URL. So at least there is a discrepancy in how `fetch` handles escaping on the prerender and browser side.
