Title

execessive memory use with GnuTLS

Description
I'm running s3fs, built on libcurl.  By default this creates a pool of 20 `curl_easy_init` handles and reuses them with a `curl_easy_reset` between each `curl_easy_perform`.  `curl_easy_cleanup` is called when the pool is destroyed.

After a while the memory usage grows hugely.  Valgrind massif logging shows 100MB of ASN data:

```
89.99% (286,590,012B) (heap allocation functions) malloc/new/new[], --alloc-fns, etc.
->34.88% (111,074,304B)  : ??? (in /usr/lib/x86_64-linux-gnu/libtasn1.so.6.5.5)
| ->24.97% (79,520,320B)  : ??? (in /usr/lib/x86_64-linux-gnu/libtasn1.so.6.5.5)
| | ->12.85% (40,930,560B)  : asn1_der_decoding2 (in /usr/lib/x86_64-linux-gnu/libtasn1.so.6.5.5)
| | | ->12.85% (40,930,560B)  : gnutls_x509_crt_import (in /usr/lib/x86_64-linux-gnu/libgnutls.so.30.14.10)
... [Log Snipped] ...
| | | | |       |                 ->09.65% (30,717,984B)  : curl_easy_perform (in /usr/lib/x86_64-linux-gnu/libcurl-gnutls.so.4.5.0)
:
```

It looks like `gnutls_certificate_set_x509_trust_dir` might be *adding* certificates on every call to `curl_easy_perform`?

Should `gnutls_certificate_free_credentials` be being called in `curl_easy_reset` (as it is in `curl_easy_cleanup`)?  Or should the call to `gnutls_certificate_set_x509_trust_dir` be being made in `curl_easy_init` maybe?
