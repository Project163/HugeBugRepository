Title

Microsoft SQL Server miscompilation for ROWS PRECEDING/FOLLOWING

Description
### Discussed in [URL]

 

 Originally posted by **suhas-dc** June 19, 2024 
On Microsoft SQL Server running a query with an OVER clause containing a row range fails. For example,

```
query = sa.select(sa.func.avg(col_one).over(order_by=[col_two], rows=(-5,1)))
connection.execute(query)
```

fails with `ProgrammingError: ('42000', "[42000] [Microsoft][ODBC Driver 18 for SQL Server][SQL Server]Incorrect syntax near '@P1'. (102) (SQLExecDirectW)")`.

The sqlalchemy query object is compiled into some thing similar to
```
SELECT avg(anon_1.[col_one]) OVER (ORDER BY anon_1.[col_two] ASC ROWS BETWEEN 
? PRECEDING AND ? FOLLOWING)
FROM dbo.table AS anon_1'''
```

And, pyodbc does not seem to support bind parameters for PRECEDING and FOLLOWING since running the above query as textual SQL will also fail with the same error. Compiling the query with `literal_binds` `True` substitutes the bind parameters giving a query pyodbc will run.

EDIT: I faced this issues on sqlalchemy 1.4 but it seems to me that the issue may also exist on sqlalchemy 2.0 after looking through the `visit_over` definition.
