Title

No client warning on tombstone threshold

Description
It appears that a client warning is not coming back for the tombstone threshold case. The batch warning works. 

 Repro: 
Create a data condition with tombstone_warn_threshold < tombstones < tombstone_failure_threshold 
Query the row 

 Expected: 
Warning in server log, warning returned to client 

 I'm basing this expectation on what I see  here  

 Observed: 
Warning in server log, no warning flag in response message.
Discussion
- I've pushed a  branch  – it changes the TracingAwareExecutor to allow for including other thread local state to be passed onto the task being run, currently just  Tracing  and  ClientWarn . 

 This change doesn't address remote warnings, so if the coordinator is not also the replica, we still won't get the messages. That requires a change to the internode protocol to add warnings, so it wouldn't be included in 2.2.
