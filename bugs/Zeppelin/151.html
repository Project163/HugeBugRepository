- jjkeon , I don't know if you happen to be using Zeppelin on Amazon EMR, but if so (or if anybody else using EMR is wondering the same), for emr-4.2.0, which included Spark 1.5.2 and Zeppelin 0.5.5-amzn-0, we backported   ZEPPELIN-409   onto Zeppelin 0.5.5 so that emr-4.2.0 would be able to upgrade to Spark 1.5.2 and still use Zeppelin 0.5.5. (This is why we added the "-amzn-0" suffix to the Zeppelin version; it's our own custom rolled version of Zeppelin that includes the backport of   ZEPPELIN-409  , so we didn't want to mislead by still calling it simply "0.5.5".) 

 Similarly, if Zeppelin 0.6.0 has not yet been released by the time EMR upgrades to Spark 1.6, we will likely also backport   ZEPPELIN-441   to Zeppelin 0.5.5 (calling the new version "0.5.5-amzn-1") in order to allow Zeppelin 0.5.5 to work with Spark 1.6+.
- jonathak , thanks for that information. I'm not using Amazon but the solution you went with seems like something that could easily be generalized for 0.5.5 to allow it to work on Spark 1.5.2.
