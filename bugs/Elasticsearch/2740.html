# ES Index Out of Bounds Exception when Querying

We have a system that involves heavily nested data that includes possible (partially) repeated items on lower levels.  We have a 
query that counts (or sums) specific fields for the nested lower level data and compares the resulting value to a threshold to determine whether the document itself matches.  This query sometimes returns incorrect results or even blows up with an exception. We believe this to be a bug within Elasticsearch or Lucene.  

A simplified version of the query is illustrated below.  We use a match phrase query to choose the specific fields and use a constant score query with a value of 1 (for the counting case) for a score, and use a scoring mode of `sum` in the nested query to find the number of matches.  We then use a script with a `min_score` equal to threshold results so we only find counts exceeding the threshold.

This query usually works fine, but when the match phrase query is long we either:

1. Get an exception from ES with the message:
```
ElasticsearchException[Elasticsearch exception [type=index_out_of_bounds_exception, reason=index_out_of_bounds_exception: null]]

```

2. Get inconsistent results where the results are either not found or only partial results are returned.
