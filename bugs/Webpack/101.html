Title

Deletion of compilation assets in 2.2.0-rc.2 fails in SizeLimitsPlugin

Description
**Do you want to request a *feature* or report a *bug*?**
 

Bug

**What is the current behavior?**

A plugin which deletes assets during the `emit` step via `delete compilation.assets[filename]` causes the SizeLimitsPlugin to fail with the following traceback:

```
bash
$ webpack
/Users/jb/code/webpack/lib/performance/SizeLimitsPlugin.js:37
					return compilation.assets[file].size()
					                               ^
... [Log Snipped] ...
    at /Users/jb/code/webpack/node_modules/mkdirp/index.js:48:26
    at FSReqWrap.oncomplete (fs.js:123:15)
```

**If the current behavior is a bug, please provide the steps to reproduce.**
 
Gist with simple repro: [URL]

Essentially, plugins which previously worked via deletion of compilation assets will fail in the latest version of webpack due to a change introduced to SizeLimitsPlugin here: [URL] 

**What is the expected behavior?**

The deleted asset should be successfully removed and not emitted. This is the behaviour in previous versions of webpack (including 1.x.x and 2.1.0-beta.27).

**If this is a feature request, what is motivation or use case for changing the behavior?**

Some existing plugins rely on this behaviour. See [URL] for example. It's unclear whether deletion of compilation assets *should* be supported (perhaps not?) but if not, something clearer should likely be shown to make it obvious that plugins shouldn't be doing this. I couldn't find any documentation outlining this when looking so far.
