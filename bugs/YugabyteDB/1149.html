Title

[YSQL] Possible database OID collision with system_postgres

Description
Jira Link: [Link: DB-11504]
### Description

(1) Create a local cluster with the gflag --TEST_ysql_oid_prefetch_adjustment=49148
This gflag simulates the scenario that those OIDs  ) is reserved
by Yugabyte to store sequence table `system_postgres.sequences_data`, where
`system_postgres` called `namespace` in docdb, and `sequences_data` is the table name.

```
static const uint32_t kPgSequencesDataTableOid =  ;
static const uint32_t kPgSequencesDataDatabaseOid =  ;
```

`kPgSequencesDataDatabaseOid` is for `system_postgres`.
`kPgSequencesDataTableOid` is for `sequences_data`.

But 65535 is also a normal OID that can be allocated by the PG oid allocator. In
the test a user created database `test3` has already occupied the same OID 65535.
Further more, inside the user database OID 65535 was also allocated for table
`t1`. Later when the system tries to create the internal table
system_postgres.sequences_data, it collided with `test3.t1` which has a
different schema.
