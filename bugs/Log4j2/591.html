Title

Headers not being written to first file with RollingFileAppender

Description
It appears the fix for   LOG4J2-1030   prevents the headers from being written to the the first file (when the file does not exist) while using a RollingFileAppender.  However, the header is written during a file rollover. 
This is not a huge issue when using PatternLayout, since you will just lose the desired header, but is a bigger issue when using HTMLLayout, since the important HTML document header information is not written and all events logged are displayed inline and not in the table.  
Also, on another note, the date pattern  
  
 "%d{ISO8601}{UTC}" 
  
  does not appear to work correctly in 2.4. 

 Here is the simple test program and configuration file I used...outputs from 2.3 and 2.4 follow:

Discussion
- I separated out   LOG4J2-1149   for the date pattern time zone issue.
- With   LOG4J2-1030   we introduced a "writeHeader" check that is true if either  append="false"  is specified in the configuration, or the target file does not exist. 

 In  RollingFileManager.RollingFileManagerFactory  there is a bug where the file is first created before the "writeHeader" check is done, so if append=true (the default), the header will not be written even if the file did not exist. (The other FileManager implementations do not have this issue.)
- Fixed in master in commit ff0797ae. 

 Please verify and close.
- Successfully ran test application using latest 2.4.1-SNAPSHOT...headers are once again present on the first file written, as well as subsequent files, using the RollingFileAppender
