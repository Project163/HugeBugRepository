Title

🐛 [Bug]: Mounted subapps don't work correctly if parent app attached additional middlewares after mounting (v2.40.1 bug)

Description
### Bug Description

If fiber app is mounting some subapps, routes from these subapps are not matching if the parent app added middlewares after mounting.
See the code snippet above to reproduce the problem. `GET /world` always returns `404`. **v2.39.0** handled this case correctly.


### How to Reproduce

Steps to reproduce the behavior:
1. Run the code snippet
2. Request `GET /world` 
3. Get 404


### Expected Behavior

`GET /world` should return 200 'Hello'

### Fiber Version

v2.40.1

### Code Snippet (optional)

```
go
package main

import (
	"log"
... [Log Snipped] ...
	return c.SendString("Hello!")
}
```

- Fiber v2.32.0 and up support adding 404 handling by customizing the error handler. You can take a look [URL]

I'll also think how to fix the problem.
- unfortunately you are right and we have to do some rebuilding

the problem is that the routing tree has wrong positions in our routing tree because we don't remember at what time the mount command was executed

because we wanted to allow routes to be added later, we moved the merge to the start of the app, but currently we don't know where the mount command was executed

we already have some ideas and will try to fix this in the next release
- A similar but slightly different use case which is also effected by this issue. In this use case, I'm trying to add authentication to groups of routes.

```
go
package main

import (
	"log"
... [Log Snipped] ...
	log.Fatal(app.Listen(":3000"))
}
```

I found that this used to work up until v2.40.0 was released. Here is a list of the endpoints and responses:

```
# what I would have expected to happen from reading the code
GET /api/foo -> 200
GET /api/lists -> 200
GET /api/bar -> 403
GET /api/users -> 403
... [Log Snipped] ...
GET /api/users -> 403
GET /api/baz -> 403
```

Is there a different way this is meant to be done? Or an actual bug with the way I'm trying to use `.Group()` and `.Mount()`?

My current workaround to this was to add a `.Use()` statement to the users app, like:

```go
users := fiber.New()
users.Use(requireAuth)
users.Get("/", func(c *fiber.Ctx) error {
	return c.SendStatus(fiber.StatusOK)
})
```

The downside to this approach, is that because I organize groups of routes into their own packages, I then have to add the same middleware(s) to each one (across many files) instead of being able to more easily apply them once at the top.
