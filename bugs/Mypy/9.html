Title

Return 0 implicitly if function return type is int

Description
The following code should print 0, but it prints None:

```
int f(): pass
print(f()) # 0 expected
```
Discussion
- is this coded for a general case, so that X f(): pass returns X()?
- ztane: No, at least not in general. Like Python, mypy uses an implicit None return value when it can. However, the primitive types int, float and bool don't include the None value, and we will use 0 / 0.0 / False in those cases. These values are chosen since they are false in a boolean context, similar to None (and they are also the result of int(), float() and bool(), respectively).

If mypy would support defining new primitive types or non-nullable types (which is currently not the case), we would need a way of specifying the default value on a per-type basis (of course, we could also disallow implicit return values for such types, but it would be inconistent). In this case an implicit return value X() could be the right way to do it.

However, relying on the implicit 0 is generally a bad idea from a style point of view: it's there mainly to speed up prototyping and to make mypy similar to Python. There should probably be an optional warning that is given when a function implementation defaults to implicit None/0 etc. return.
