Title

TcpDiscoverySpi.setLocalPortRange set 0 doesn't work

Description
Local port range set to 0 presently doesn't work at least for TcpCommunicationSpi and TcpDiscoverySpi. However SPIs support it. 

 In my understanding the condition has to changed to the following one (from < to <=). 

 x = port; x <= port + range

- The doc on TcpCommunicationSpi.setLocalPortRange() saying that  "If port range value is 0, then implementation will try bind only to the port provided by setLocalPort(int) method and fail if binding to this port did not succeed." 
So, I think it would be a right choice to treat localPortRange=0 as localPortRange=1.
