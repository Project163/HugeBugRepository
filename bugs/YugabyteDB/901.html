Title

[DocDB] Truncating colocated table failed to clear table data

Description
Jira Link: [Link: DB-4389]
### Description

Create a file `tbl.csv` with 1M rows. (note that the issue only manifests with a sufficiently large file)

```
LINE 1: create database t with (colocated = true);
                               ^
yugabyte=# create database t with colocated = true;
WARNING:  'colocated' syntax will be deprecated in a future release
LINE 1: create database t with colocated = true;
... [Log Snipped] ...
t=# copy tbl from 'tbl' with (format csv);
ERROR:  duplicate key value violates unique constraint "tbl_pkey"
```

[DB-4389]: [URL]
Discussion
- The underlying issue seems to be a result of the timed out RPC which does not result in a clean cancellation and can result in some records being left behind. The select that follows immediately after the failed RPC may still see 0 records because the previous txn has not yet committed and is running in the background, however a select after you get the unique constraint failure would most likely indicate that there were actually records in the table. 

If copy were to use transactions under the cover, then you would not have this atomicity issue.

Confirmed the above with the repro below:

```
t=# truncate table cast_info;
TRUNCATE TABLE
t=# select count(*) from cast_info;
 count
-------
... [Log Snipped] ...
 80000
(1 row)
```

Also validated that this problem does not exist for other tables in the imdb schema or a smaller cast_info.csv:

```
t=# copy link_type from './imdb/link_type.csv' with (format csv);
COPY 18
t=# truncate link_type
t-# ;
TRUNCATE TABLE
... [Log Snipped] ...
COPY 85000
t=#
```
