Title

Unable to set environment variables for Puppet provisioning on Windows

Description
### Vagrant version
1.9.2 (also saw in 1.9.1)

### Host operating system
Windows 10

### Guest operating system
Windows Server 2012 R2

### Vagrantfile
```
ruby
Vagrant.configure("2") do |config|
  config.vm.box = "opentable/win-2012r2-standard-amd64-nocm"

  config.vm.provider "virtualbox" do |vb|
... [Log Snipped] ...
  end
end
```

### Debug output
[Link: Gist]

### Expected behavior
Environment variable "demo" should be set in VM, and the variable's value should be written to  .

### Actual behavior
Vagrant shows an error from PowerShell about an unexpected token:

```
==> default: Running Puppet with environment main...
==> default: At C:\windows\temp\winrm-elevated-shell-c7856836-37e4-4685-8eba-75848c4d4129.ps
==> default: 1:1 char:16
==> default: + $env:demo="hi" puppet apply --color=false --detailed-exitcodes
==> default: --environmentpath ...
... [Log Snipped] ...
==> default:    ception
==> default:     + FullyQualifiedErrorId : UnexpectedToken
```

From the logging, it looks like it's trying to set the environment variable in the same line that it calls Puppet, whereas PowerShell would expect the  part on its own line.

For the record, if I take out the puppet.environment_variables part of the Vagrantfile, there are no errors; demo.txt gets created, albeit without the variable value being set.

### Steps to reproduce
Create the following directory structure on your host:

```
provision/
  bin/
    demo.cmd
    puppet-agent-1.9.2-x64.msi
  env/
    main/
      demo.pp
Vagrantfile
```

Download puppet-agent-1.9.2-x64.msi from [Link: PuppetLabs]. This is the newest version, released yesterday (although I also saw the issue with 1.9.1-x86 on a different VM at work).

Content of demo.cmd:
```bat
echo "%demo%" > C:\demo.txt
```

Content of demo.pp:
```puppet
exec { "C:/vagrant/provision/bin/demo.cmd":
  creates => "C:/demo.txt",
}
```

Then just run "vagrant up".
