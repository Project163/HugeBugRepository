Discussion
- Finally reproduced it  here  with adequate debug information. As expected, the mutations of the system keyspaces are also added to the commit log and this may prevent segments from being deleted as the test expects. In this case it was  system.sstable_activity  with cf id  5a1ff267-ace0-3f12-8563-cfae6103c65e  that kept the second commit log segment.
- I've created a patch that sets durable writes to false for system keyspaces during this test. I've multiplexed three times ( run 1 ,   run 2  and  run 3 ) with no failures, whereas the  run  without the patch had 2 failures.
