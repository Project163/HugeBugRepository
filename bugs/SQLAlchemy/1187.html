Title

cache key with nested options() creates too large / non deterministic cache key

Description
### Describe the bug

When using relationship loading the keys are calculated not deterministically and their possible number grows exponentially. Also, these keys are very large, a lot of memory is leaking.

### To Reproduce

```
python
from sqlalchemy.ext.declarative import declarative_base
from sqlalchemy import create_engine, select
from sqlalchemy import Column, Integer, ForeignKey, Text
from sqlalchemy.orm import Session, relationship, joinedload, load_only
... [Log Snipped] ...
    # I expect to see only 1 [generated in ... s] and 1999 [cached since ... ago]
    # but actual is 216 (maybe less if not all cache keys were received) [generated in ... s] and everything else is [cached since ... ago]
```

### Error

There is no error, only a lot of memory is leaking

### Versions

- OS: MacOS
- Python: 3.9
- SQLAlchemy: 1.4.22
- Database: sqlite

### Additional context

If we add 5 more tables in this example, the number of possible keys will increase even more, there will be few cache hits, and the size of the keys will increase.
```
python
```
