Discussion
- is it possible for 81243 to be a false positive?
In the previous for loop consists of two rounds. In the first round xmalloc is called for `retval`. In the second round, if new itens were found, free is used on `retval` and the loop returns to round 1. The only way to exit the loop with `retval` freed is if `failed` is set to `true` and the break at line 5202 is reached. `retval` will be freed at that moment only if it has been freed at line 5167, but for `failed` to be true after that can only happen at line 5182 requiring `id` to be 0. However if `retval` was freed at line 5167 `id` will then be -1.
That way when the loop exits `retval` wont be freed.
