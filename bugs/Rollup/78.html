Title

IIFE with side effect involving prototype alias incorrectly dropped

Description
```
$ node_modules/.bin/rollup --version
rollup version 0.35.12
```

See the line marked "side effect":

```
$ cat i2.js 
var V8Engine = (function() {
    function V8Engine() {}
    V8Engine.prototype.toString = function() { return 'V8'; };
    return V8Engine;
... [Log Snipped] ...
}());
console.log(new V8Engine().toString());
```

Expected result:

```
$ node i2.js 
V6
```

Notice that the modified V6Engine IIFE with side effect was incorrectly dropped by `rollup`:

```
$ node_modules/.bin/rollup i2.js && echo
var V8Engine = (function() {
    function V8Engine() {}
    V8Engine.prototype.toString = function() { return 'V8'; };
    return V8Engine;
}());
console.log(new V8Engine().toString());
```

and produces the incorrect result:

```
$ node_modules/.bin/rollup i2.js | node
V8
```
Discussion
- Ah, yeah. I see what's going on here. [Link: This code], which determines whether the left-hand side of an assignment expression (or argument of an update expression) is used by the bundle, is bad. Regardless of whether the assignment is a true assignment (`foo = x`) or a mutation (`foo.bar = x`), it looks for the root of the expression (`foo`) and determines whether it could be used.

[URL] fixes it, but in a bad way – if it's a mutation, we try to figure out what the object being mutated is, and if we can't, assume the worst. That means that `unused.a = b` isn't included, but `Unused.prototype.toString = ...` _is_, incorrectly, because Rollup isn't (yet) smart enough to know what the value of `Unused.prototype` is, or (more relevantly) that it only 'belongs' to `Unused`.

Trying to think about the best way to think about this problem in a way that guarantees correctness but without being unduly conservative about effects. I think some concept of property 'ownership' might be the way forward (i.e. `V6Engine.prototype` could belong to either `V8Engine` or `V6Engine` because of `V6Engine.prototype = V8Engine.prototype`, so any mutations of that object are considered to have effects if _either_ `V8Engine` or `V6Engine` is included. Am all ears if anyone is able to think about this more clearly than me...
- I'm not sure whether the code you posted is a simplification, but this line strikes me as a bad idea:

``` js
V6Engine.prototype = V8Engine.prototype;
```

Because you're simply creating a new reference to `V8Engine.prototype`, the subsequent assignment to `V6Engine.prototype.toString` also sets `V8Engine.prototype.toString`. I can see that you're expecting that behavior in `console.log(new V8Engine().toString())`, but… why?
