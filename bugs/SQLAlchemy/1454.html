Title

joinedloader race condition

Description
### Discussed in [URL]

see also [URL]


don't know how to reproduce this, however JoinedLoader._gen_pooled_alias_class is suspect since it is creating AliasedClass objects on the fly and sharing them between threads.

basic symptom is the adapter in ColumnLoader is returning None, which gets put into context.secondary_columns which then causes the select() to fail.     Dont know how to get that ColumnLoader to actually return None yet.
Discussion
- **Mike Bayer** has proposed a fix for this issue in the **main** branch:

**remove "aliased class pool" caching approach** [URL]
- to be clear the theory is:

"concurrency because we are creating a thread-shared AliasedClass on the fly -> race condition -> something goes wrong in the AliasedClass -> adapter returns None -> None gets sent to select() -> error"

the parts I can't reproduce are "something goes wrong in the AliasedClass / adapter returns None", but it seems reasonable this is where the issue might be since the issue seems to be under high threaded concurrency and is non-deterministic.
