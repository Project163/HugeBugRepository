Title

Assignment Expression Reports superfluous-parens False Positive

Description
An `if` statement that tests a negated (`not`) parenthesized [Link: Assignment Expression] _without any other operators (See "Non-issues" section below)_ is reported by Pylint to have superfluous parentheses.

I believe this is a false positive. Removing the parentheses is invalid syntax.

### Steps to reproduce
1. Write an if statement that tests a negated (`not`) [Link: Assignment Expression], such as:

```python
if not (my_var := False):
    print(my_var)
```

2. Run pylint against that code.

### Current behavior
Pylint reports `superfluous-parens:Unnecessary parens after 'not' keyword`.

### Expected behavior
Pylint should not report about this syntax.

Removing the parentheses is a syntax error: `SyntaxError: cannot use named assignment with operator`.

### pylint --version output
```
pylint 2.4.4
astroid 2.3.3
Python 3.8.0 (tags/v3.8.0:fa919fd, Oct 14 2019, 19:21:23) [MSC v.1916 32 bit (Intel)]
```

### Non-issues
- If the negated assignment-expression `if` statement contains another binary operator, no Pylint report is generated about it. (Or at least, that seems to be the only difference.)

  For example, this slightly-modified snippet from [Link: What’s New In Python 3.8] does not cause Pylint to report:

  ```python
  if not (n := len(list(range(11))) > 10:
      print(f"List is too long ({n} elements, expected <= 10)")
  ```
Discussion
- Ah, it seems this issue is more general than I first thought. **The negation has nothing to do with it.**

Example that also causes `superfluous-parens`:

```python
if (foo := True):
    print(foo)
```
- I would say that example is a legit case where we _do_ want to raise this warning. In the example below, I believe the expected behaviour would be to raise a superfluous warning for 2, a syntax error for 3, and no warning for 1 & 4

```
python
# 1: Legal python, not superfluous
if foo := True:
    print(foo)
```
