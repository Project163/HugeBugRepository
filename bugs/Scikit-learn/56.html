Title

PIL import in cluster module

Description
I just upgraded sklearn on one of my boxes and current master had a weird issue related to a PIL import ("AccessInit: hash collision: 3 for both 1 and 1"). The error is caused by a mucked up system, but I would argue that we should not try to import PIL when applying a clustering algorithm (I was trying to import `kmeans`).
I think the PIL import came via matplotlib, but I did not find where that got pulled in.
I could reproduce simply by `import sklearn.cluster`.
Discussion
- I would think that it probably comes via scipy.misc.imread:
sklearn/datasets/base.py
sklearn/datasets/lfw.py

but these imports are protected. You could however check that
scipy.misc.imread imports.

Can you give us a traceback? Ideally walk the post-modern debugger to
find where is the failing import. Without these, we are somewhat doing
guess work.
- Fun fact: this error doesn't give a trace, it just kills the interpreter.

I actually used `-m trace` to roughly find it. I think "protecting" doesn't help because the error just crashes the interpreter, not raising an error. I just found it weird that the clustering module imports them. The ensemble module for example does not.
- ... [Middle Discussions Snipped for Brevity] ...
- Found it: `sklearn.cluster` imports `scipy.cluster`. That imports PIL, according to the modulefinder on `import scipy.cluster`.
- Shit!

Maybe we can delay these specific imports.

Good job by the way!
