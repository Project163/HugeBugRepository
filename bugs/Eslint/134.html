Title

Getting no-unused-vars errors on function arguments, even with args="none"

Description
Version 0.6.2

Even with no-unused-vars set to args=none, eslint is still throwing errors for some unused arguments in both server-side and client-side code.

It seems to only occur when _no_ arguments are used. When the function has two args, and neither are used, they both give `no-unused-var` errors. But once one of them is used, regardless of which one, the errors disappear.
# 

```
// eslint.rc
{
  "no-unused-vars": [2, {"args": "none"}],
  // ...
}
```

```
// public/js/services/cookies.js
Application.addService('cookies', function(application) {
  // application is un-used here
  // ... 
});
```

```
// test output

  13:49  error  application is defined but never used  no-unused-vars
public/js/modules/menu-list.js
  15:48  error  context is defined but never used  no-unused-vars
```

- I'm looking into this now. I can see why it's causing an error.
- The problem is that the unused function params were only being marked ignorable in [Link: markIgnorableUnusedVariables], so they were only being ignored when another variable identifier appeared in the function. Above PR is a quick fix that also marks them ignorable in "none" mode when the params are first added to the variable hash. This whole rule could use some refactoring and cleanup though.
