Title

post_update does not apply state to updated objects in a multi-execute correctly

Description
### Describe the bug

very similar to [Ref: #10800] 

Deleting a parent object with a cascade=delete relationship bumps the version_id of it's children if the child object has a relationship with post_update=True. This causes the subsequent cascade delete of the children to fail, as the version_id no longer matches

Oddly, this works on python 3.12 but fails on python 3.13.5

Discussion
- I found it weird that 1 row would match (expected 2) so did some more digging.

I found that in python 3.12 both children would get UPDATEs with the same new updated_at timestamp
```diff
UPDATE child SET created_by_id=?, updated_at=? WHERE child.id = ? AND child.updated_at = ?
+[(None, '2025-07-23 10:55:19.927921', 1, '2025-07-23 10:55:19.923921'), (None, '2025-07-23 10:55:19.927921', 2, '2025-07-23 10:55:19.923921')]
DELETE FROM child WHERE child.id = ? AND child.updated_at = ?
+[(1, '2025-07-23 10:55:19.927921'), (2, '2025-07-23 10:55:19.927921')]
DELETE FROM parent WHERE parent.id = ?
(1,)
COMMIT
```

In python 3.13, they get slightly different timestamps in the UPDATE statement, however the first (new) timestamp is used in the DELETE statement

```diff
UPDATE child SET created_by_id=?, updated_at=? WHERE child.id = ? AND child.updated_at = ?
-[(None, '2025-07-23 11:31:24.168741', 1, '2025-07-23 11:31:24.164506'), (None, '2025-07-23 11:31:24.168748', 2, '2025-07-23 11:31:24.164512')]
DELETE FROM child WHERE child.id = ? AND child.updated_at = ?
-[(1, '2025-07-23 11:31:24.168741'), (2, '2025-07-23 11:31:24.168741')]
ROLLBACK
```
