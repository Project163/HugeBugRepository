Title

3.0 - Adding custom context providers for `Entity` subclasses practically not possible via `addContextProvider()`

Description
Assuming one would want to add a custom context provider for a specific entity [Link: **as shown in the docs**], using `FormHelper::addContextProvider()` from outside the helper class would always be too late, as [Link: **the default context providers are being added in the helpers constructor**] and [Link: **the built in entity context provider will be selected first**] for all classes that do extend `Entity`.

So from outside the form helper class the only way to hook in a custom entity context provider would be by overwriting the default one using a type of `orm` instead of for example `myprovider` as used in the docs.

I'm not sure if there is anything to be fixed codewise, ie something like for example adding the default providers at a later point or implementing priorities for `addContextProvider()`, or if the docs should be updated so that they suggest extending the form helper and adding the custom context providers before invoking the parent constructor, or overriding the `_addDefaultContextProviders()` method, or maybe something totally different.

On a side note, the example in the docs should probably better pass `$data` instead of `$data['Entity']`.
