Title

Index sorting should spill in home dir.

Description
Why not?

If we are afarid we'll leave trash, we can clean up on start up.
Discussion
- The current implementation probably also doesn't work as intended, at least on linux. As far as I understood, syncthing will sort in memory (inMemoryIndexSorter) and switch to disk (onDiskIndexSorter) after exceeding a size threshold. The onDiskIndexSorter creates a temporary directory in the default TempDir, which is /tmp on linux.

Nowadays, many linux distributions mount a tmpfs on /tmp, which is a RAM-based filesystem. So, the onDiskIndexSorter will in this case also sort in memory.

`ioutil.TempDir(syncthingHome, "syncthing-db.")` could be a good option to get this right.
- `~/.config` nor `~/Library/Application Support` nor the roaming profile dir on Windows are really for temp files? The temporary directory is for temp files. I don't see why this is wrong.
- ... [Middle Discussions Snipped for Brevity] ...
- There is nothing wrong, it was just an unfortunate choice (which I also only noticed today) in this case as using a RAM filesystem as fallback in case there is too little memory, will not work. tmpfs uses half of the RAM as filesystem size by default, so chances are that the disk fallback will have even less storage space as the InMemorySorter.

I think using the syncthing home is the easiest option, but if someone is interested these are the cache directories for the different OS according to [Link: appdirs]:

```
appname = "SuperApp"
appauthor = "Acme"

OS X:    /Users/trentm/Library/Caches/SuperApp
Windows: C:\\Users\\trentm\\AppData\\Local\\Acme\\SuperApp\\Cache
Linux:   /home/trentm/.cache/SuperApp
```
- Mmm. Let's stick to our config dir for now as we're anyway misusing it for the database.
