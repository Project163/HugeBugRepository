Title

Dimension capacity does not work

Description
The setting of the maximum number of dimension combinations at the bottom of the aggregation group does not take effect. 

 When editing an aggregation group, set the maximum number of dimension combinations at the bottom (applicable to aggregation groups that do not have a maximum number of dimension combinations set) to 1. After saving, when editing again, it becomes unlimited.
Discussion
- Acceptance 
 
	 Set the "Maximum number of dimension combinations" at the bottom of the "aggregation group". After saving and building, when you edit "the aggregation group" again, the "maximum number of dimension combinations" at the bottom will be the value set when the last time you saved the build. 
 

 
	 If the maximum number of dimension combinations is not set for a single aggregation group, the maximum number of dimension combinations of this aggregation group will be overwritten by the maximum number of dimension combinations at all aggregation group levels. If a maximum number of dimension combinations is set for a single aggregation group, the number of index dimensions of this aggregation group is only limited by the maximum number of dimension combinations of this single aggregation group. If the maximum number of dimension combinations at all aggregation group levels is left blank, it means that the user has turned off the setting of the maximum number of dimension combinations at all aggregation group levels. At this time, the number of dimensions in the index generated by an aggregation group that has not been set separately for the maximum number of dimension combinations is unlimited. Aggregation groups that have been set to the maximum number of dimension combinations at a single aggregation group level are not affected.
- Design 

 GET /kylin/api/index_plans/rule  
Normally display the "Maximum number of dimension combinations" at the bottom of the "Aggregation Group" setting 
The global maximum number of dimension combinations is effective for all aggregation groups, and is subject to the last setting. 

 Modify logic: 
When assigning a value to "Maximum number of dimension combinations", both the batch model and the flow model exist. You need to determine the size of the timestamp.
