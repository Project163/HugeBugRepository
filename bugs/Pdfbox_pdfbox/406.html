Discussion
- The pdf heavily uses shading patters which are not yet fully supported, see   PDFBOX-1094
- That file has several problems, one of them are lines like this one: 
  
 <</Coords[0 240 0 240]/ColorSpace/DeviceRGB/ShadingType 2/Extend[ true   true ]/Function 3 0 R>>
 
  
 The coords entry has identical coordinates. See p. 310 of the 1.7 spec, it will result in a divide by zero. As a first step, I added this before "new AxialShadingPaint" at two places: 
  
    float  [] coords = ((PDShadingType2) shading).getCoords().toFloatArray();
   if  (coords[0] == coords[2] && coords[1] == coords[3])
  {
      LOG.error( "ShadingType2: coordinates are identical" );
       return   null ;
  }                
 
  
 After this change, the image is less bad (but still useless   )
