Title

Configuring logging documentation

Description
**Describe the bug**
Documentation for logging configuration does not state clearly, how exactly the rotation of logfiles is configured by the specified options. Here is the link to documentation page: [URL]

**Expected behavior**
When following options are present in application.properties:
quarkus.log.handler.file."STRUCTURED_LOGGING_FILE".path=myapp.log
quarkus.log.handler.file."STRUCTURED_LOGGING_FILE".rotation.file-suffix=.yyyy-MM-dd_HH:mm
quarkus.log.handler.file."STRUCTURED_LOGGING_FILE".rotation.max-file-size=3M
quarkus.log.handler.file."STRUCTURED_LOGGING_FILE".rotation.rotate-on-boot=false

I expect the logfile to be rotated every time, when the file reaches 3MB in size. This is not what happens, apparently this is by design, but the documentation never mentions, that the rotation.file-suffix options controls when logfiles get rotated!

**Actual behavior**
if the following option is present in the application.properties:
quarkus.log.handler.file."STRUCTURED_LOGGING_FILE".rotation.file-suffix=.yyyy-MM-dd_HH:mm

logfile is rotated every minute, the option rotation.max-file-size gets ignored. Once the file-suffix is set to `.yyyy-MM-dd` the file is not rotated every minute any more. 

The documentation never states, that the file-suffix is controlling how often rotation of logfiles is going to happen. The only logical conclusion from reading the documentation page seems to be, that rotation.max-file-size is controlling this, by specifying the file-size. 

Also, what happens if a logfile exceeds the max-file-size during one day, with the file-suffix set to `.yyyy-MM-dd`? If the file-suffix has no hours and minutes in it, how will the rotation work, if a logfile is to be rotated during the same day? Will quarkus generate a new file-suffix like `.yyyy-MM-dd_01`? This might break scripts that are working in the background, doing something with the files according to their suffixes.
