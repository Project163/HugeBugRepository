Title

etcd v3.2 fails to start with multiple peer urls

Description
# Bug/question

Before etcd v3.2 multiple peer urls could be configured (e.g. `ETCD_LISTEN_PEER_URLS=[URL]
But starting on 3.2.0 if a cluster is started or upgraded to this version with multiple peer urls it is continuously starting elections and it never reaches the healthy state (see [URL] what is confusing.

As the flag is still plural we could think that it should still be supported. If it's not going to be supported I think it should fail to start with multiple peer urls.
