Title

Test assemblies no longer resolve properly in "no AppDomain" mode

Description
See my comment on  .  The change to call a different overload of `Assembly.Load` seems to have broken assembly resolution in the no-AppDomain case; the previous code would use the CodeBase set in the AssemblyName to find the assembly, but the new code uses the CodeBase of the AppDomain, and so can't find the test assembly unless it's in just the right location.
Discussion
- Do you have a repro project?
- The repro is a little complex - I'm working on a performance testing tool that does test discovery in a separate process from the test runner, and that separate process is now failing to find the test assembly when I move to RC1.  It's possible that I'm doing something wrong. :)  I'll dig in a little more....
- ... [Middle Discussions Snipped for Brevity] ...
- Turns out I needed to do two things:
1.  I had a copy of xunit.execution.desktop.dll in the directory with my "runner."  That was being loaded instead of the one in the test's directory.  From there, we seemed to get lost somehow.  I reworked my build so that file doesn't get placed there any more.
2.  I also needed the AssemblyHelper trick you mentioned.

Neither of these were necessary in Beta4; the way Assembly.Load was getting called before, we were just able to find the test assembly.

Thanks for the help; I'm unblocked now.
