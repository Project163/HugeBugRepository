Title

groovyc doesn't catch wrong return type in overriding method

Description
> cat BaseClass.groovy                                                                                                                                               
class BaseClass {
  def foo() {}
}    
                                                                                                                                                                                      
> cat DerivedClass.groovy                                                                                                                                                    
class DerivedClass extends BaseClass {
  void foo() {}  
  static void main(String[] args) {}
}

> groovy DerivedClass                                                                                                                                                         
Caught: java.lang.VerifyError: (class: DerivedClass, method: foo signature: ()Ljava/lang/Object;) Unable to pop operand off an empty stack
 
  

 If return types of  BaseClass.foo()  and  DerivedClass.foo()  are exchanged, groovyc detects the problem: 
  
 org.codehaus.groovy.control.MultipleCompilationErrorsException: startup failed:
/swd/tmp/DerivedClass.groovy: 2: The return type of java.lang.Object foo() in DerivedClass is incompatible with void foo() in BaseClass.
Node: org.codehaus.groovy.ast.MethodNode. At [2:3]  @ line 2, column 3.
     def foo() {}
     ^

1 error
Discussion
- On second look, the last error message is unfortunate. Why mention  org.codehaus.groovy.ast.MethodNode ?
- I assume the bug is in Verifiyer#getCovariantImplementation. As for the message, that comes from the used RuntimeParserException. A different type shuold be used here I guess.
- ... [Middle Discussions Snipped for Brevity] ...
- Yes, I missed void vs void boundary case. 

 So, I am going ahead with the following changes then: 

 1) void.isDerivedFrom(void) == true 
2) void.isDerivedFrom(any_other_type=) == false 
3) removing the ast node portion of the message from RuntimeParserException constructor
- Fixed - both the covariant issue and the exception message.
