Title

":vimgrep" too slow when filetype detection is enabled

Description
- `nvim --version`: NVIM v0.5.0-370-g5d5b068d5
 - `vim -u DEFAULTS` (version:  8.2 Included patches: 1-241) behaves differently? Yes
 - Operating system/version: Ubuntu 16.04.6 LTS
 - Terminal name/version: XTerm(322)
 - `$TERM`: xterm-256color

### Steps to reproduce

Run this shell command:

    for i in {1..10}; do nvim -es -Nu NORC -i NONE +"let time = reltime() | vim /pattern/gj \$VIMRUNTIME/**/*.vim | pu=matchstr(reltimestr(reltime(time)), '.*\..\{,3}').' seconds to run :vimgrep'" +'%p|qa!'; done

### Actual behaviour

Each `:vimgrep` takes – on average – about [Link: 11.4 seconds] on my machine.

### Expected behaviour

Each `:vimgrep` takes on average 1 second.

### Additional information

The same command in Vim takes on average [Link: 0.45 seconds] on my machine.

---

`:vimgrep` was not that slow in `v0.3.0` ([Link: 1.07 seconds]).
But it was still 2 to 3 times slower than current Vim's `:vimgrep`.

---

`:vimgrep` is much quicker when the filetype detection is disabled ([Link: 0.24 seconds] on average).

    for i in {1..10}; do nvim -es -Nu NORC -i NONE +"filetype off | let time = reltime() | vim /pattern/gj \$VIMRUNTIME/**/*.vim | pu=matchstr(reltimestr(reltime(time)), '.*\..\{,3}').' seconds to run :vimgrep'" +'%p|qa!'; done
                                                     ^^^^^^^^^^^^

---

The slowness is caused by a regression introduced in 98a818776.
