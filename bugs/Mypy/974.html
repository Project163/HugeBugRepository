Title

AssertionError when using '=' instead of ':' to define a protocol attribute with specialized type

Description
**Bug Report**

After (accidentally) using `=` instead of `:` in a protocol definition, mypy may crash when trying to type-check an object follows the protocol

**To Reproduce**

Write this in a .py file:

```
py
from typing import List, Protocol, Type

class MyProto(Protocol):
    foo = List[str]
... [Log Snipped] ...

my_cls: Type[MyProto] = MyClass
```

and run mypy on it

**Expected Behavior**

Should error with `All protocol members must have explicitly declared types` on line 4, and/or `Incompatible types in assignment (expression has type "Type[MyClass]", variable has type "Type[MyProto]")` on line 9

**Actual Behavior**

```
$ mypy crash_mypy.py --show-traceback
crash_mypy.py:9: error: INTERNAL ERROR -- Please try using mypy master on Github:
[URL]
Please report a bug at [URL]
version: 0.942
... [Log Snipped] ...
AssertionError: 
crash_mypy.py:9: : note: use --pdb to drop into pdb
```
 

**Your Environment**

- Mypy version used: 0.942
- Mypy command-line flags: either none or `--show-traceback`
- Mypy configuration options from `mypy.ini` (and other config files): none
- Python version used: 3.9
- Operating system and version: Debian 11
Discussion
- It's a similar traceback to #10577, which also involves a type alias assignment inside a protocol definition
