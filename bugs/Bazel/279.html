- @kchodorow I've mailed out a CL to you working around this. I added a work around to download() earlier but I forgot to add one to download_and_extract().

However once that CL is submitted, a deeper investigation needs to be done. The root cause is that the code that reflectively calls `@SkylarkCallable` does not handle InterruptedException properly. It would be better if that infrastructure code was fixed.

Mishandling of InterruptedException and InterruptedIOException is a very common problem in Java codebases. Ideally they should propagate up to the event loop, which then breaks.
- @kchodorow Can you please notify once this got picked so I can apply the workaround to our internal version.
