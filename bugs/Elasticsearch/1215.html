Title

Search: Fix merging of the shard results to use field comparators

Description
Today, when you run a query with a sort and shards results need to be merged on the coordinating node, shards basically return a sort value for every hit that is used by a priority queue in order to select the top values.

There is one case when it does not work well: missing string values. If you want to sort them last, you need to emit a string that compares greater than any other string. Unfortunately, there is no such string, so we have a hack that returns a string with a single code point `0X10FFFF` that we hope will compare greater to all strings that are in the index. And this becomes even worse when with paging: in order for the comparator to work well, we need to feed it with `null` as a top value, not `0X10FFFF`, and tell it to sort missing values last.

Instead of trying to serialize a maximum string, we should instead return null AND a boolean that tells whether to sort missing values first or last. The good news is that this is something TopDocs.merge is aware of so this should not require any modification of the reduce code.
