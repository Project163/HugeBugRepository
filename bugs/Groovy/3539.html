Title

printf does not respect "out" property

Description
I am using groovy to run dynamic scripts from my Java application. I use JSR223 for this. I am overriding "out" property to redirect script stdout to my own consumer. However, I've noticed that  printf  inside closures does not respect that property (it always prints to stdout) while  println  perfectly complies (and prints to whatever specified). 

   

 I beleive this is because of the differences in printf and println in DefaultGroovyMethods.java: in  [URL]

 println uses closure owner while printf does simple System.out.
Discussion
- For non-Closure cases,  println  uses  System.out  too: 

  [URL]

 It might be that we need Closure variants for  printf . You could try this yourself by creating your own category and seeing if that works. Also, does using  out.printf  work? 

 Alternatively, can you create a minimal example which exhibits the problem?
- I've conjured up a minimal example, it works without any JSR223 or whatever: 

   test.groovy      

   

  def stringWriter = new StringWriter()  
  out = new PrintWriter(stringWriter)  

  println "root println" // goes to out  
  printf "root printf\n" // goes to out  

  def t1 = {  
      println "closure println" // goes to out  
      this.println "closure this.println" // goes to out  
      out.println "closure out.println" // goes to out  

      printf "closure printf\n" // goes to stdout (bug here) !!  
      this.printf "closure this.printf\n" //goes to out  
      out.println "closure out.printf\n" // goes to out  

  }  

  t1()  

  System.out.println("\n====\nOutput that went to out:\n"+stringWriter.toString() )

- If the method exists on Object already, then why do we have to add it to Closure?
- The  Script  class has special variants of  println ,  print  and  printf  which look for an  out  property. We have special DGM Closure variants for  println  and  print  which delegate to the owner (or the outer owner in the case of nested closures) - so it will be the script in the above examples. We could make the Object variants for  printf  smarter and detect that case but for consistency I'd suggest using the same approach as for  println  and  print  as per the PR.
