Title

add exception to no-octal-escape for \0

Description
`\0` is commonly used instead of `\x00` or `\u0000`. I think this particular escape sequence should be an exception to this rule.

- By `\0` you mean NULL string right? In that case, that feels like the bug in the original rule, since it's called no-**octal**-escape.
- `0` is simultaneously in every base. Just like how it is unitless.
- ... [Middle Discussions Snipped for Brevity] ...
- In the grammar, `EscapeSequence` is defined as

```
EscapeSequence ::
  CharacterEscapeSequence
  0 [lookahead ∉ DecimalDigit]
  HexEscapeSequence
  UnicodeEscapeSequence
```

Section B.1.2 gives an optional extension (allowed only outside strict mode), replacing `0 [lookahead ∉ DecimalDigit]` with `OctalEscapeSequence` in the above grammar. If we disallow `OctalEscapeSequence`, we should re-allow `0 [lookahead ∉ DecimalDigit]`.
- Ah interesting. So what you're saying is that `\0` isn't actually an octal so it shouldn't be flagged. I agree.
