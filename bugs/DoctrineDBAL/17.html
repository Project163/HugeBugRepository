Title

The QueryBuilder::getSQLForSelect() always appends a FROM clause for select queries

Description
Running queries without `FROM` clause is not possible currently with the `Doctrine\DBAL\Query\QueryBuilder`.

For instance we have these queries: 

`SELECT EXISTS(...)`
`SELECT some_function(1, 1)`

We would probably write something like this: 
`$qb->select('EXISTS (...)')`
And, `$qb->select('my_function(1, 1)')`

But, when we do `$qb->execute()` it would fail because, internally the `FROM` clause is being appended to the SQL every time we use `QueryBuilder::select()`. 

Here's, the part of `QueryBuilder::getSQLForSelect()` that's responsible for this. 

```
php
    /**
     * @return string
     *
     * @throws \Doctrine\DBAL\Query\QueryException
... [Log Snipped] ...

        $query .= implode(', ', $this->getFromClauses())
```

[URL]

I have come across a lot of scenarios, where we need to run `SELECT` without `FROM`. But, it's not possible right now. 

Eg: If I want to check if the user exists in the database, I would want to do: 
`SELECT EXISTS(SELECT 1 FROM user WHERE id = :userId)` as this is the fastest way

But, I have been using this type of query as a work around
`SELECT COUNT(id) FROM user WHERE id = :userId` which is comparatively slower than the first one.

Is there any particular reason why a query like `SELECT EXISTS(SELECT 1 FROM user WHERE id = :userId)` can't simply be thrown at a DB connection? It is very specific, and some engines don't support it in the `SELECT` clause anyway.
- @kabirbaidhya We used to keep `QueryBuilder` in DBAL as simple as possible and it should not be thought of a complete complex query builder that covers everything. It is not an AST and platform agnostic so we won't be able to do complex things safely. We surely will rework the Query component in `3.0`, maybe we can consider it there.
For if you really want to use the query builder for subqueries you have 2 options (not tested though):
1. Put the raw subquery SQL into `$qb->select()` or `$qb->addSelect()`
2. Create another `QueryBuilder` instance for the subquery and add it to the main query via `$qb->select($subQb)` or `$qb->addSelect($subQb)`. However you will have to take care of bound parameters from the sub query builder yourself I suppose.
