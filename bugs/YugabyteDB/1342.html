Title

[docdb] Perform extra validation when setting tablespace/placement info

Description
Jira Link: [Link: DB-12324]
We sometimes see issues where users will set duplicate placement info for a tablespace or for cluster level placement info, eg #20657:
```
    "placement_blocks": [
{ "cloud": "cloud1", "region": "datacenter1", "zone": "rack1"   , "min_num_replicas": 1 },
{ "cloud": "cloud1", "region": "datacenter1", "zone": "rack1"   , "min_num_replicas": 1 }
    ]
```

We should perform some kinds of checks to either block or warn users about this when this is set.

[DB-12324]: [URL]
Discussion
- This validation should also verify that we currently have tservers that match this placement info, and then throw an error/warning if there are any mismatches.

Currently users can set placement infos that are different, which leads to unclear error messages + stuck load balancing. It can also be difficult to tell which placement infos are incorrectly set
