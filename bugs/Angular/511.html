Title

JIT: Using @Optional() private causes wrong Renderer to be injected

Description
In Angular Material we are seeing an odd issue where the injection system is using the old Renderer when it isn't supposed to.

Our MdChips component uses Renderer2 but it receives Renderer1 if the parent component also has an MdInputContainer with an input containing an ngModel.

To reproduce, run `gulp test` on Angular Material using the branch found here: [URL]

The changes that reproduced the error can be found in this commit: [URL]
Discussion
- To clarify, the simplest reproduction looks like (captured in the linked reproduction):
```html
 
   ... 
 

 
   
 
```
Where the constructor for `MdInput` has
```ts
  constructor(private _elementRef: ElementRef,
              private _renderer: Renderer2,
              @Optional() @Self() public _ngControl: NgControl,
              @Optional() private _parentForm: NgForm,
              @Optional() private _parentFormGroup: FormGroupDirective) {
```

The problem **only** happens when:
* The input has an `NgModel` applied
* The chip is on the same element as `NgFor`
* The `list` iterated over by `NgFor` changes after `OnInit`
* `MdInput` injects `FormGroupDirective` with `@Optional` **and** `private`


My best guess is that having a decorator on a private member somehow triggers a code path that corrupts the injector for the view (since the chips are siblings/cousins to the input)
- I've started running into this issue in my library as well, however in this instance, I'm not using any decorators in the component (which attaches to `.item`) constructor:

```typescript
constructor(private _renderer:Renderer2, public element:ElementRef) {
```

The simplest reproduction we've managed is in [Link: this plunkr].

Unfortunately it's incredibly vague as to when it happens and doesn't, and so far I can't seem to get a definitive list of requirements for reproduction.
