Title

warning message 'ssl.client.truststore.location has not been set' gets printed for hftp command

Description
hftp command prints 'WARN ssl.FileBasedKeyStoresFactory: The property 'ssl.client.truststore.location' has not been set, no TrustStore will be loaded' in Windows unsecure environment.  

 This issue only exists in Windows environment. 

  
 hdfs dfs -cat hftp://XXXX:50070/user/yesha/1409773968/L1/a.txt
WARN ssl.FileBasedKeyStoresFactory: The property 'ssl.client.truststore.location' has not been set, no TrustStore will be loaded
HEllo World..!!
Discussion
- The reason is that hftp / hsftp / webhdfs / swebhdfs file system requires an instance of  URLConnectionFactory  to create HTTP / HTTPS connection.  URLConnectionFactory  loads all SSL certificates if there are any. Since there is no certificate in this case, it leads to this warning message. 

 This log message is benign but confusing. I propose to change the log level from warn to debug.
- Reopen the issue to change the state from in progress to submit patch, so that it can run through jenkins.
