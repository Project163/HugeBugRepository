Title

box add [name] [path] does not recognise metadata.json file on Windows when [path] contains a space

Description
This is happening on 1.8.1, Windows. Related to [URL]

I have two folders, "C:/boxes" and "C:/box es", each containing an identical "metadata.json" file, describing the versions of a base box. In Windows, on the command line, running the following commands results in only the path without a space working: 

```
C:\>vagrant box add test "C:\boxes\metadata.json"
==> box: Loading metadata for box 'C:\boxes\metadata.json'
    box: URL: file://C:/boxes/metadata.json
The box you're adding has a name different from the name you
requested. [this is fine, it means it has read the json file correctly]
```

```
C:\>vagrant box add test "C:\box es\metadata.json"
==> box: Box file was not detected as metadata. Adding it directly...
==> box: Adding box 'test' (v0) for provider:
    box: Unpacking necessary files from: file://C:/box%20es/metadata.json
    box: Progress: 100% (Rate: 254/s, Estimated time remaining: 0:00:01)
... [Log Snipped] ...

bsdtar.EXE: Error opening archive: Unrecognized archive format
```

This is obviously some issue to do with the escaping of spaces into %20s, which is required for URI handling, but then there appears to be some issue in doing a File.open() on those URIs with escaped spaces. I'd be willing to guess the problem happens in [URL] .

There doesn't appear to be any other way of escaping the space from the command line (like adding the %20, or %%20, or ^%20, or whatever other methods of escaping) since these all get further escaped for the URI.
