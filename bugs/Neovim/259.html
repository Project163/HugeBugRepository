Title

SIGSEGV in `qf_fill_buffer()`

Description
### Neovim version (nvim -v)

0.9.0-dev  

### Vim (not Nvim) behaves the same?

n/a

### Operating system/version

Ubuntu 18.04 WSL

### Terminal name/version

Kitty N/A

### $TERM environment variable

xterm-256color N/A

### Installation

Manually compiled

### How to reproduce the issue

The issue seems to be memory corruption that can occur if I execute [Link: my `:Rg ` ripgrep integration] by executing `:Rg -F tmpname(` while cd'd into the neovim codebase. I think it might have to do with the speed that the results are returned at, since it seems to replicate with what is functionally `ripgrep -F ...` more often than with `ripgrep ...`

It doesn't happen every time (and seems to take longer to reproduce if gdb is attached) but reproduces rather readily when I'm editing the neovim codebase and ripgrepping the same.

Note that in the stack trace you can observe the invalid `old_last` being passed in to `qf_update_buffer()` from `qf_init_ext()`.

### Expected behavior

No segfault.

### Actual behavior

Segfault due to bad memory access.
