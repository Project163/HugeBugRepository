- ah, now I understand the problem. 

 To me, "Zeppelin Sync" sounds better than using "ReadWriteMany Storage". 

 Configuration point of view, like you summarized "Zeppelin Sync" should work out of the box, but "ReadWriteMany" requires storage configuration, and the storage configuration can be quite a challenge many users. (from the installation of storage to securing NFS/etc). 

 In performance point of view, if "Zeppeiln Sync" can be implemented in a way that ZeppelinServer download artifacts from a maven repo(which can be slow) and each interpreter Pod sync the artifacts from ZeppelinServer (network between pod will be much faster), then there will be not much performance penalty compare to  "ReadWriteMany Storage" while most ReadWriteMany storage also needs to transfer all artifacts through the network. 

 Implementation point of view, one way is make two additional http endpoints in ZeppelinServer side, one for a list of files in local-repository, another for transferring a file in a local-repository. So interpreter.sh can copy artifacts through the network before it starts the RemoteInterpreterServer process. Do you have other solutions in mind?
