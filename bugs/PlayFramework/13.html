Title

EventSource Java library should not escape message content

Description
The [Link: current implementation] escapes the message content. However, the browser does not decode it automatically, so users have to manually unescape the content.

For instance if I want to send the JavaScript string `"foo"` it produces `\"foo\"`. On client-side, if I try to parse it as JSON it doesn’t work: `JSON.parse('\\"foo"\\')` throws a syntax error.

The [Link: specification] does not say that we should escape messages content.
Discussion
- I don’t know how to fix this because if we just stop escaping messages it may break backward compatibility.
- By the way the message content is not properly formatted: it should be line splitted and each line should be prefixed by `data:`.
- ... [Middle Discussions Snipped for Brevity] ...
- I'm not too concerned about breaking backwards compatibility in the Scala API here - what we have now is broken, and besides, who uses event source with anything but JSON?  I suspect no one, otherwise this issue would have been raised a lot sooner, as it happens it was only noticed after the same problem was noticed in the Java API.

I think the Data class is a good idea.  Except, I would call it Event, and have a static factory method event() so that it can be created nicely.
- I agree that we should not escape the SSE data. I see SSE as a signalling mechanism that isn't intended to convey structured content.

From my experience SSE clients are intended to respond to signals that may cause them to subsequently act e.g. perform an HTTP GET to get some data. Whether the client does or not though depends on its UI state.
