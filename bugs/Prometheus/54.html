Title

Panic in EC2 discovery: NetworkInterfaces

Description
## Bug Report
**What did you do?**
Ran Prometheus 1.8.2 with EC2 service discovery across many EC2 instances in unknown states.

**What did you expect to see?**
EC2 service discovery works without crashing.

**What did you see instead? Under which circumstances?**
Prometheus panicked about a nil pointer dereference:
```
panic: runtime error: invalid memory address or nil pointer dereference
[signal SIGSEGV: segmentation violation code=0x1 addr=0x8 pc= ]

goroutine 18710894 [running]:
github.com/prometheus/prometheus/discovery/ec2.(*Discovery).refresh.func2( , 0x1, 0x0)
... [Log Snipped] ...
github.com/prometheus/prometheus/vendor/github.com/aws/aws-sdk-go/service/ec2.(*EC2).DescribeInstancesPages( , 0x0,  , 0x0, 0x0)
        /go/src/github.com/prometheus/prometheus/vendor/github.com/aws/aws-sdk-go/service/ec2/api.go:6784 +0x11a
```

This looks similar to #3001, but this time the the nil pointer was not in EC2 tags, it was in the ENI code: [URL]
```
					for _, eni := range inst.NetworkInterfaces {
						subnetsMap[*eni.SubnetId] = struct{}{}
					}
```

I am unsure what AWS instance state caused the AWS SDK to return a `nil` pointer in the `NetworkInterfaces` field.

I have not tried reproducing this with the latest Prometheus version as I am unsure how exactly to replicate it. However, the code in `master` for iterating over `inst.NetworkInterfaces` [Link: does not seem to handle `nil` pointers]
