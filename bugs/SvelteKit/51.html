Title

adapter-cloudflare does not bundle service-worker.js since around next.207 - results in 404 and thus failed SW registration

Description
### Describe the bug

Since around next.207 `adapter-cloudflare` seems not to bundle `service-worker.js`

When testing locally, everything seems OK. The SW file is present in the `./svelte-kit/cloudflare` builld folder - as it was with older versions of Sveltekit. When running `npm run preview` the SW is being successfully registered according to Chrome Dev Tools.

After deployment﻿ to CF, and running the site, the following error shows in the console log:
`Uncaught (in promise) TypeError: Failed to register a ServiceWorker for scope ('[URL] with script ('[URL] A bad HTTP response code (404) was received when fetching the script.`

Also, according to Dev Tools, the SW is not present.

### Reproduction

[Link]

Basically it's the standard demo app, with the following additions:
+ `service-worker.js` is included in `/src`
+ `import adapter from '@sveltejs/adapter-cloudflare';` is configured

Discussion
- This behavior is happening in adapter-vercel as well.
- The issue seems to be with the internal manifest of the workers.

```
js
export const manifest = {
	appDir: "_app",
	assets: new Set(["favicon.png", /*removed for brevity...*/,"svg/Youtube.svg","svg/YoutubeRed.svg" /* no service-worker.js :( */]),
	_: {
... [Log Snipped] ...
			/*...*/
			]
```
This is created from `builder.generateManifest` ([Link: link to impl]), and does *not* seem to include service workers.
- I stumbled into the same issue  a few days ago. My current workaround is to add an additional `service-worker.js` into  folder `/static`, such that the generated service worker will be included in the final bundle.   

(Yes, **THE SERVICE WORKER** being served is compiled from `src/service-worker.ts` rather than `static/service-worker.js`)  

the demo: [URL]  
the repo: [URL]    
Notice the code in `static/service-worker.js` is different from what that is in `src/service-worker.ts`. It seems what's inside  `static/service-worker.js` doesn't matter as long as it exists.
- Great to see work dedicated to this issue. Unfortunately, the update seems to have no effect - at least in the case of Cloudflare, which I was testing thoroughly (different browsers to avoid SW caching problems).

**Reproduction:**
I updated my initial demo site with a clean new version of the Sveltekit demo app.

When the service-worker.js file is included in /src _alone,_ the following error persists:

```
A bad HTTP response code (404) was received when fetching the script.
sw-cloudflare-repro.pages.dev/:1 Uncaught (in promise) TypeError: Failed to register a ServiceWorker for scope ('[URL] with script ('[URL] A bad HTTP response code (404) was received when fetching the script.

```
**But** I can confirm that the workaround proposed by @Envl is working also with the updated Sveltekit.

I added another copy of the service-worker.js file into the /static folder and console logged respectively to see which version is being used when deployed on Cloudflare.

I can confirm that the sheer existence of a service-worker.js file in the static folder somehow triggers the use of the SW, and it is     the one from /src and _not_ from /static.

So while the workaround seems valid also with the new version of Sveltekit, the issue unfortunately seems (at least on Cloudflare) not yet resolved.
