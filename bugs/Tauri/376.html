Title

[bug] `unlisten()` after `onCloseRequested` breaks window closing

Description
### Describe the bug

When you `unlisten()` to remove a `onCloseRequested` handler, it breaks window closing; the callback doesn't get called as expected, but it doesn't close the window either.

### Reproduction

1. run [URL]
2. click the button
3. wait five seconds
4. try to close the window

### Expected behavior

The window can be closed by window buttons after `unlisten()` is called

Discussion
- I assisted in this issue and confirmed that indeed after running `unlisten()` the normal window close button no longer works and registering a new `onCloseRequested` listener to `appWindow` fixes it. It seems like `unlisten()` prevents the default app closing from functioning.
