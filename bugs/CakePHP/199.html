Title

3.0 - Form input and belongsToMany

Description
Hi guys. I'm not sure if this one's a bug or if I'm doing something wrong.

`Posts` belongsToMany `Tags`

In my controller/add function I'm setting tags with:
`$tags = $this->Posts->Tags->find('list')->all();`

Then in my form:

```
echo $this->Form->create(new Post(), ['role' => 'form']);
echo $this->Form->input('tags', ['multiple' => true, 'size' => 25]);
```

When trying to save selected tags, my request data looks like this:

```
Array
(
    [name] => test
    [tags] => Array
        (
... [Log Snipped] ...

)
```

When I attempt to create a new entity from the request data,

```
$this->Posts->newEntity($this->request->data());
```

I get:
`Argument 1 passed to Cake\ORM\Marshaller::one() must be of the type array, string given, called in /Users/pconroy/Work/com/cms/vendor/cakephp/cakephp/src/ORM/Marshaller.php on line 185`

A couple questions/things:
1. I kind of get why it's not working, the docs say the values for the tags need to be Entities, but the docs also say if you pass in requestData to newEntity it'll turn those into Entities.
2. Why do I need to set `multiple => true` on tags? Shouldn't it know that my Posts table belongsTo **Many** Tags?
3. I've tried every combination of uppercase/camelcase but I can never get the tags to persist even when they've been manually added in the DB and I'm setting the entity, which contains the tags, into the Form constructor:

```
$post = $this->Posts->find('translations')->where(['Posts.id' => $id])->contain(['Tags'])->first();
echo $this->Form->create($post, ['role' => 'form']);
// Tags are listed out but none are pre-selected, though some should be.
```

There's nothing regarding belongsToMany on the 3.0 FormHelper page, so I've had to guess with what I did in 2.x and what makes sense in 3.0.

Thanks!
Discussion
- You need an input named 'tags._ids' if you want the automatic conversion from ids to entities. Otherwise you will need to pas the constructed entities yourself. This would solve your second question as well.
- There is only one place in the docs where that is explained. I will make sure to add it in the form helper docs
- ... [Middle Discussions Snipped for Brevity] ...
- The marshaller doesn't include any joins when finding entities which is the problem here. One possible option would be to join the joint table when the association has conditions.
- Closing as I've fixed the warning by omitting what could become invalid SQL conditions.
