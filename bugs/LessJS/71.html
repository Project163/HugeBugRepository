Title

On Windows, rootpath option wrongly uses backslash to separate root path from relative url. Also mangles url scheme.

Description
Given this .less file:

`.bg { 
    background: #ffffff url('img/bg.png'); 
}`

If I compile this with the rootpath option (using lessc 1.3.3):

`lessc test.less test.css --rootpath=[URL]

I get this .css file:

`.bg {
  background: #ffffff url('http:/cdn.com\img/bg.png');
}`

Issues:
1. The character separating the root path and the relative url is a \. However, this is a url, not a windows file path, so the separator should be a /.
2. One of the / in the url scheme has been deleted. It now says http:/cdn.com.... instead of [URL]

Use case:
The rootpath option would be very useful (when it works) when you use a CDN or a cookieless domain for hosting images, stylesheets, etc. in production. It would allow you to have relative urls when compiling in development, while adding a domain when compiling for production.
Discussion
- yes that shouldn't happen
- 2 mistakes.. 1 I was normalizing the rootpath option value which turns http:// into http:/ and second I was using a replace instead of global replace to turn the windows back slashes into forward slashes. I think we really need some integration test as the unit tests bypass the option parsing
