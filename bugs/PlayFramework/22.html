Title

content-length header included in 304 response which is forbidden by the HTTP spec

Description
When returning a not modified result from an action in Play 2.3.7, the resulting HTTP response includes a content-length header.

This field must not be included in a 304 response:
[URL]

The problem is reproducible in both Scala and Java.

When content-length it is sent some http client libraries misbehave (eg. picasso on android).
We had to completely disable if-modified-since handling in our project to avoid this, which is obviously a very costly workaround.
Discussion
- Notes for whoever wants to fix this:
- A new test needs to be added to `ScalaResultsHandlingSpec` that asserts that a 304 response has no `Content-Length` header sent.  Note, you should use the `BasicHttpClient` for this test.  Test that it fails before implementing the fix.
- The fix will go in `NettyResultsStreamer` and `ServerResultUtils`, which will have to treat 304 status code differently - ie, feed the body into a Done iteratee and ignore the result, filter out any `Content-Length` headers already set, and send the response right away.
