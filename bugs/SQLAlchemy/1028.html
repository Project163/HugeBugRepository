Title

Queries execution order is not guaranteed causing concurrency issues

Description
**Describe the bug**

With the two following tables:

```python
class MyTable(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    name = db.Column(db.String(80), unique=True, nullable=False)

class MyTable2(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    name = db.Column(db.String(80), unique=True, nullable=False)
```

Trying to updates two objects during the same transaction does not always execute queries in the same order. For example, if we attempt to update the two objects obj1 and obj2:

```python
obj1 = MyTable.query.filter_by(id=1).one()
obj2 = MyTable2.query.filter_by(id=1).one()
obj1.name = str(random.random())
obj2.name = str(random.random())
db.session.commit()
```

the SQL emitted might update `MyTable` before `MyTable2`, or `MyTable2` before `MyTable`. The order might be different at every execution.

Now, imagine I need to call `db.session.flush()` before commit:

```
python
obj1 = MyTable.query.filter_by(id=1).one()
obj2 = MyTable2.query.filter_by(id=1).one()
obj1.name = str(random.random())
obj2.name = str(random.random())
... [Log Snipped] ...

db.session.commit()
```

With PostgreSQL, this update on a UNIQUE field requires to get a row lock. If this code runs concurrently, one execution might update `MyTable` before `MyTable2`, and another `MyTable2` before `MyTable` causing a deadlock.

**Expected behavior**

Queries execution should be repeatable. Updates should always be done in the same order.
Even better, the order could be specified with `db.session.add`, so `db.session.add(obj1); db.session.add(obj2);` should always update `obj1` before `obj2`.

Discussion
- The problem comes from [URL]

`UOWTransaction` has an attribute named `dependencies` of type set. In my example it could be equal to `{(SaveUpdateAll(mapped class MyTable->my_table), DeleteAll(mapped class MyTable->my_table)), (SaveUpdateAll(mapped class MyTable2->my_table2), DeleteAll(mapped class MyTable2->my_table2))}`.

A `set` is supposed to be ordered, but here it contains tuples of objects, so the order is determined by the objects' locations in memory, which vary over time.

To make the updates order deterministic, you can replace:

```python
for rec in topological.sort(self.dependencies, postsort_actions):
    rec.execute(self)
```

with:

```python
for rec in sorted(
    topological.sort(self.dependencies, postsort_actions),
    key=lambda a: a.mapper.tables[0].name
):
    rec.execute(self)
```

Of course, the `key` I am suggesting here is not the one that should be used. It is just a quick hack to demonstrate how the problem could be fixed, but I am not aware enough of SQLAlchemy internals to provide a `key` that makes sense.
