### Describe the Bug

We have a simple setup involving a Context API provider wrapping the `_app.tsx` page. The flow we're trying to implement is:

 1. On a page we collect some data from an API by using `getServerSideProps`
 2. We send the data to the page through the props
 3. We update the context from the page (the context provider is wrapping the `_app.tsx` as mentioned above)
 4. The context is updated and all the children components can access the data in it

So we have a pretty standard setup that works correctly on the client side. The problem is that the updated context values are not being used to SSR the pages.

Discussion
- I did some more investigation. Apparently, the same thing happens with redux. The problem happens if I try to use the context/store in a component that is a direct child of `_app.jsx`, where the `Provider` is wrapping the application. If the target component is a child of the `Page` where I'm calling the function to update the context, it seems to work.

Maybe Next.js evaluates the components tree from top to bottom during the SSR and doesn't go back to update things that were already rendered on the first render.

The other possibility is that react functions are ignoring for some reason the context/redux updates in parent components on the server-side when a child component is responsible for the update.
