Title

4.x: Sqlite TypeError

Description
This is a (multiple allowed):

* [x] bug

4.x-dev

### What you did
Upgrading a plugin to 4.x and running phpunit.

### What happened
```
PHP Fatal error:  Uncaught TypeError: file_exists() expects parameter 1 to be a valid path, bool given in /.../vendor/cakephp/cakephp/src/Database/Driver/Sqlite.php:69
Stack trace:
#0 /.../vendor/cakephp/cakephp/src/Database/Driver/Sqlite.php(69): file_exists(false)
#1 /.../vendor/cakephp/cakephp/src/Database/Driver.php(165): Cake\Database\Driver\Sqlite->connect()
#2 /.../vendor/cakephp/cakephp/src/Database/Connection.php(468): Cake\Database\Driver->beginTransaction()
#3 /.../vendor/cakephp/cakephp/src/Core/Retry/CommandRetry.php(69): Cake\Database\Connection->Cake\Database\{closure}()
#4 /.../vendor/cakephp/cakephp/src/Databa in /.../vendor/cakephp/cakephp/src/Database/Driver/Sqlite.php on line 69
```

### What you expected to happen
A more meaningful message, we might want to check on the bool before we further pass it along.
Discussion
- I found that someway along the bootstrapping of tests, 4.x needs sth else than 3.x.

Hardcoding Sqlite::connect() to use

    $databaseExists = file_exists($config['database'] ?: 'tmp');

made the tests pass.
So I think somewhere along that stracktrace we should check on that key to be not false and advice what to do here instead.
- How / why did you set the `database` key to `boolean`? :slightly_smiling_face:  It does have a sensible default `:memory:`.
- ... [Middle Discussions Snipped for Brevity] ...
- The issue is more low level, when parsing dsn.
The missing url now triggers this, which shouldnt happen.
- I don't think this issue is caused by DSN parsing at all. This issue can be reproduced with the following invalid configuration:

```php
ConnectionManager::setConfig('test', [
    'className' => 'Cake\Database\Connection',
    'driver' => 'Cake\Database\Driver\Sqlite',
    'database' => false,
]);
```
I think my suggestion of a guard around the `file_exists()` check is our best bet here.
