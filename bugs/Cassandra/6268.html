When using JDK provider and not OpenSSL, the class cast exception is there with JDK17, no matter of Netty Version. We do not see the issue in Python DTests as they seem to rely on OpenSSL. 

 For the record, comment by  benedict  on   CASSANDRA-17992  : 
  Yes, the GaloisCounterMode appears to make about DirectBuffer and their attachments here. 

   Looking again at the rest of the JDK, I'm not actually sure attachments can be accessed publicly, so this is probably our problem rather than the JDK's. However, we might be able to fix it by simply having Chunk implement DirectBuffer, and having it return its address.
