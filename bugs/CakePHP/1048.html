Title

Fix HTTP Client Curl adapter with HEAD requests with non-zero content-length in response

Description
This is a:

* [x] bug
* [ ] enhancement
* [ ] feature-discussion (RFC)

* CakePHP Version: 3.9.1 (but is also broken in older and newer versions)
* Platform and Target: PHP 7.4.3, Ubuntu 20.04, libcurl 7.68.0

### What you did
Do a `HEAD` request to a webservice that returns a `Content-Length > 0` but no body, in accordance with the [Link: HTTP spec].
For example Elasticsearch, see [URL] .

### What happened
I get an error `cURL Error (18) transfer closed with 431 bytes remaining to read`.

### What you expected to happen
The HTTP request succeeds

### What is the fix?
Add a case [Link: here]:

```php
            case Request::METHOD_HEAD:
                $out[CURLOPT_NOBODY] = true;
                break;
```

If you have a webserver which sends a non-zero content length for HEAD requests, you can reproduce it using the curl CLI:

```bash
curl -H 'Connection: close' -X HEAD [url here]
```

Note that using `-I` instead of `X HEAD` does work, since that will set `CURLOPT_NOBODY` correctly.
