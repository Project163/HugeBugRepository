Title

ESLint rule no-page-custom-font crashes when default export is an anonymous function

Description
### What version of Next.js are you using?

12.0.7

### What version of Node.js are you using?

14.17.6

### What browser are you using?

Brave

### What operating system are you using?

macOS

### How are you deploying your application?

Vercel

### Describe the Bug

The no-page-custom-font ESLint rule assumes that default export function declarations are named, and it crashes when a file's default export is an anonymous function.


```
$ eslint ./

Oops! Something went wrong! :(

ESLint: 8.4.1
... [Log Snipped] ...
    at /Users/bryan/code/spokes/99spokes/node_modules/eslint/lib/linter/linter.js:1107:32
error Command failed with exit code 2.
```

### Expected Behavior

The crash happens because this rule uses function and class names to try to identify functions that are the default export in cases where the function or class is declared, and then later exported. e.g., `function Foo(){}; export default Foo;`. This fails to account for anonymous functions being directly exported. e.g., `export default function(){}`. The rule should handle this case without crashing.

### To Reproduce

Add a new page with the contents:

```jsx
export default function () {
	return  totally valid ;
}
```

and then run eslint.
