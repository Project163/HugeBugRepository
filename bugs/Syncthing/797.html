Title

File deletions are not being synced in newly shared folders

Description
I am not sure whether this is something recent or not, but I do not think that I had encountered anything like it before v1.11.x.

How to reproduce:

1. Create an empty folder on Device 1.
2. Add 1000 small text files to the folder on Device 1.
[Image: image]
3. Share the folder with 1000 files from Device 1 to Device 2.
4. Accept the folder on Device 2 and let it sync.
[Image: image]
[Image: image]
5. Delete the 1000 files from the folder on Device 2.
6. The two folders are stuck in the following state.
[Image: image]
[Image: image]

Please make sure to follow the steps exactly as I have written above. If the folder was already being shared between the two devices before adding the files to it, then the synchronisation is successful. I have only managed to make this happen when the files were added to the folder in the "Unshared" state.

Restarting Syncthing does make the folders finish the synchronisation.
Discussion
- Also, probably related so I am not creating a new issue, but even just creating and sharing a new folder with pre-existing identical 1000 text files on both sides between Device 1 and 2 leads to this state.

[Image: image]
[Image: image]
- I can reproduce. The problem is that new/unshared folders aren't handled in the cluster config from an index point of view. And when you then actually add the folder, we do send a cluster config to the remote, but do not get one in return as nothing changed from the point of view of the remote. Thus we never start sending indexes. We need to handle that like paused folders.
