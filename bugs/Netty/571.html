Title

Static initializers can cause deadlock

Description
We observed the following deadlock in our test suite:

```
"TestNG-1" #14 prio=5 os_prio=0 tid=  nid=  in Object.wait() [ ]
   java.lang.Thread.State: RUNNABLE
        at io.netty.util.internal.SystemPropertyUtil. (SystemPropertyUtil.java:38)
        at io.netty.channel.epoll.Native. (Native.java:56)
        at io.netty.channel.epoll.Epoll. (Epoll.java:33)
... [Log Snipped] ...
        at io.netty.buffer.UnpooledByteBufAllocator. (UnpooledByteBufAllocator.java:30)
        at io.netty.buffer.Unpooled. (Unpooled.java:73)
```

`TestNG-1` thread acquires class lock on `SystemPropertyUtil` and executes its static initialization and blocks waiting for a class lock on `InternalLoggerFactory`, but `InternalLoggerFactory` class lock is held by `TestNG-2` thread, and it also has a static initializer where it tries to initialize class `ThreadLocalRandom` that in turn needs the `SystemPropertyUtil` class lock which is held by `TestNG-1` thread
