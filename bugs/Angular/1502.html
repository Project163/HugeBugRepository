Title

CSS Selector with umlaut broken in production mode with emulated view encapsulation

Description
### Which @angular/* package(s) are the source of the bug?

compiler

### Is this a regression?

No

### Description

Encapsulated styles using CSS class selectors with umlauts don't work properly in production mode. The compiler inserts the ngcontent placeholder after the umlaut and breaks the selector.

It works in development mode.
It works when using no encapsulation or Shadow DOM.

The bug does not occur for all words, some examples:

- ❌ `.über {}` => `.\fc[_ngcontent-fji-c1]   ber[_ngcontent-fji-c1] {}` 
- ❌ `.prüfung {}` => `.pr\fc[_ngcontent-fji-c1]   fung[_ngcontent-fji-c1] {}` 
- ✅ `.zufällig {}` => `.zuf\e4llig[_ngcontent-fji-c1] {}`

- I was able to reproduce it with both `optimization.minify: true`  & `aot: true`.
[URL]

Why both : 
* `optimization.minify` triggers the EsBuild optimizer which escapes the selector : `.über {}` becomes `.\fc ber {
}` ([Link: demo on stackblitz]). This selector with a space after the escaped character is valid. The space is inserted every time the special character is followed by a hex characters (`0-9a-f`) 
* AOT messes everything up because it interpret's this as 2 different selectors.
