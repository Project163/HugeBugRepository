Title

CompositeByteBuf with SliceByteBuf as member which is a slice of CompositeByteBuf, throws UnsupportedOperationException when attemping to get nioBuffers.

Description
I am currently dealing with some large, and very sparse data structures, and have the use case of creating a single CompositeByteBuf (A) with a number of other CompositeByteBuf (B-C), mixed with some Slices of other CompositeByteBuf (D-F), mixed with UnpooledHeapByteBuf, etc...

Once I've constructed a composite based on slices of another composite (which is based on composites, heap byte bufs, slices, etc), and attempt to get nio ByteBuffer[] via the nioBuffers() method, I get a UnsupportedOperationException .

The following code illustrates the issue.

```
java
import static io.netty.buffer.Unpooled.buffer;
import static io.netty.buffer.Unpooled.compositeBuffer;
import static org.junit.Assert.assertTrue;
import io.netty.buffer.ByteBuf;
... [Log Snipped] ...

}
```

Looking through the source, DefaultCompositeByteBuf.nioBuffer(index, length) can only handle composites with a single component? (SliceByteBuf.nioBuffer() calls buffer.nioBuffer on the underlying buffer before checking if it's a composite or not)? 

Is this correct, or a bug in either SliceByteBuf or DefaultCompositeByteBuf nioBuffer() methods or is this still on the TODO list for the 4.0 release?

PS. Using current master branch from GitHub (4.0.0-CR2-SNAPSHOT)
