Title

SQL: normalized keywords shouldn't be allowed for groupings and sorting

Description
A normalized `keyword` field can potentially change the original value of a field, but SQL works with exact values. Probably as part of [URL] the restriction was lifted, as field_caps API can tell if a field is aggregatable/searchable, but not if it's normalized or a simple `keyword`.

As such, in the following scenario:

```
{
  "settings": {
    "analysis": {
      "normalizer": {
        "my_normalizer": {
... [Log Snipped] ...
  }
}
```

With a query like `{ "query" : "select user from test group by user" }` one gets back: 

```
{
    "error": {
        "root_cause": [
            {
                "type": "mapping_exception",
... [Log Snipped] ...
    "status": 400
}
```

And for `{ "query" : "select user2 from test group by user2" }` there are results returned where, in fact, ES SQL should return an error.
