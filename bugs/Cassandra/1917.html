Title

Stress for cql3 is broken on 1.2/trunk

Description

    
Discussion

    
- It's actually broken pretty deeply...  it gives explicit names to each cell for instance, when the more natural way to interpret "make me a row with 100,000 cells" is to make a wide row for slicing. 

 OTOH I could understand wanting to test explicit name queries on 5-cell rows.  Not sure how to generalize both, I think we might need more options.
- Yes, cql3 support by stress is funky. It also only ever test compact storage, so it would be good to also allow testing compact storage. It would also make sense to allow testing the binary protocol, but the current code has thrift hardcoded in quite a few places. Lastly, the code is littered with code repetition. So imho, we should refactor the hell out of it. 

 But the code we have now doesn't even run with the -L3 option, and that's what this patch fixes.
