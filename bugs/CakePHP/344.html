Title

Integrity constraint violation

Description
I run into problems when I use `DECIMAL(15,7) UNSIGNED NOT NULL DEFAULT '0.0000000'` for a MySQL column. I would expect that CakePHP set `0.0000000` as default value, if the given input field is empty but I get the following error message instead:

```
Error: SQLSTATE[23000]: Integrity constraint violation: 1048 Column 'partner_commission_rate' cannot be null
```

Extract from my view file:

```
echo $this->Form->create('Partner');
echo $this->Form->input('partner_commission_rate');
echo $this->Form->end();
```

The view generates the following output:

```
 
```

Extract from my controller:

```
$this->Partner->create();
if ($this->Partner->save($this->request->data)) {
}
```

The query itself:

```
INSERT INTO `cake`.`app_partners` (`partner_commission_rate`) VALUES (NULL)
```
Discussion
- If the input is empty then '0' / NULL will be saved. CakePHP will not try and handle figuring out the default value for a column when saving.
- @markstory Should it not transform the empty string into the valid default value? It has the schema available, thus it would be quite easy to avoid this fatal error by looking if "DEFAULT NULL" is set. If it is "DEFAULT NOT NULL" it should not automatically default to `null` here IMO.

Anyway, can we proceed here with a solution for 2.x maybe?
If we have an empty string upon save() for a numeric field that is `DEFAULT NOT NULL` etc, we should cast that to numeric 0 instead of NULL.

Anyway, I would prefer that solution too. Just cast it to _a_ default value instead of NULL if the field is defined NOT NULL. 0 would be my best guess too, but if a different DEFAULT is defined this could get really awkward, taking the (optional) DEFAULT definition into account would be a real winner!
