Title

`scrollToAnchor` in BrowserViewportScroller fails with some fragments

Description
# 🐞 bug report

### Affected Package

The issue is caused by packages @angular/common and/or @angular/router when the router is configured to scroll to anchors with `anchorScrolling: 'enabled'`.

### Description

When attempting to scroll to an anchor using the URL's fragment, the `BrowserViewportScroller` throws `SyntaxError: The string did not match the expected pattern.`

The error seems to come from this line : [URL]

`querySelector('# ')` requires ` ` to be a valid CSS identifier -- i.e. one that doesn't start with a number or a special character like `_`. The HTML5 spec, however, is not as strict in regard to element identifiers, so there's no harm in wanting to navigate to `#123` in order to scroll to an element with `id="123"`.

The fix should be as simple as replacing `querySelector()` with `getElementById()`.

For what it's worth, looking at the [Link: implementation of `scrollToAnchor` on `master`], which doesn't seem to have changed since #29577, I still find it silly to query the element with `this.document.querySelector(``#${anchor}``)`, when this could be done with `getElementById` without having to first escape the `anchor` (and risk forgetting to escape some characters...)

Why not attempt `getElementById` first, and only then, if it doesn't find anything, escape the `anchor` and try with `querySelector(``[name='${anchor}']``)`? This solution would even simplify the escaping regex (cf. my previous comment).
