Title

`DriverException` inline query for easier debug

Description
Hello, when a query produces an error, a `DriverException` is raised with the driver exception original message as a message, and the query as a property of the custom exception:
[URL]

The usability issue I'm having is that I already have the original message as part of the "Previous exception" data, while inspecting a parameter (the query) of a custom exception is cumbersome.

We are currently patching our `vendor/doctrine/dbal` this way:
```
diff
         private readonly ?Query $query,
     ) {
         if ($query !== null) {
-            $message = 'An exception occurred while executing a query: ' . $driverException->getMessage();
... [Log Snipped] ...
             $message = 'An exception occurred in the driver: ' . $driverException->getMessage();
         }
```

So the error can provide a more useful context:

```
diff
-Doctrine\DBAL\Exception\TableNotFoundException: An exception occurred while executing a query: SQLSTATE[42P01]: Undefined table: 7 ERROR:  relation "non_existing_table" does not exist
-LINE 2: FROM non_existing_table
-             ^ in file /app/vendor/doctrine/dbal/src/Driver/API/PostgreSQL/ExceptionConverter.php on line 72
+Doctrine\DBAL\Exception\TableNotFoundException: An exception occurred while executing a query: Doctrine\DBAL\Query Object
... [Log Snipped] ...
 Stack trace:
   1. [...]
```

Would you consider an approach like this (but polished of course) for encapsulating drivers' exceptions in DBAL's own?
