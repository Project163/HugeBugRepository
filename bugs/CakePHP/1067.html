Title

Regression in 4.2.2 ? Flash Messages

Description
This is a (multiple allowed):

* [x] bug
* [ ] enhancement
* [ ] feature-discussion (RFC)

* CakePHP Version: 4.2.2
* Platform and Target: PHP 7.4.11

### What you did
```
php
    /**
     * Test resetPassword method
     *
     * @return void
... [Log Snipped] ...
        $this->assertRedirect(['controller' => 'Users', 'action' => 'login']);
    }
```
### What happened
This test started to fail after updating to 4.2.2. Worked fine before.

Failed asserting that 'The Password Reset Token is unknown.' is in session path 'Flash.flash.0.message'.

using $this->assertFlashMessage didn't work either.

### What you expected to happen
Test should still pass?

It still works when splitting the test into two test cases

```
php

    /**
     * Test resetPassword method with valid token
     *
... [Log Snipped] ...
        $this->assertRedirect(['controller' => 'Users', 'action' => 'login']);
    }
```
Discussion
- Relying on internal implementation detail and directly checking session key isn't a good idea in the first place but using `assertFlashMessage()` multiple times within the same test method for multiple requests should be expected to work.

I am guessing the `empty()` check here might be the reason why the message for the 2nd request isn't being captured [URL]
- yes, already rewritten to the methods provided.
- We had a few issues already last year, especially around 3.x => 4.x when using multiple integration tests in one succession/run.
To separate them into separate runs is quite important, as the side effects of such integration tests are immense, and resetting between them is vital.
So the solution you found is correct of course.

That said: We could probably remove the !empty() nano-optimization here, as then it would also work in such edge cases still.
- If we remove that empty() we will need to merge the flashMessages, as they could be blanked between beforeRender and beforeRedirect :|
