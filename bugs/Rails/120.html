Title

Integer range checks are wrong for PostgreSQL adapter in Rails 4.2

Description
I upraded an application to Rails 4.2 and started to get a RangeError when loading my database schema. The following call will raise a RangeError when it shouldn't because 2 gigabytes is a valid bigint, and It used to pass in Rails 4.1.5:

``` ruby
t.integer :quota, limit: 8, default: 2.gigabytes
```

I noticed that:
- `ActiveRecord::Type::Integer` is always passed a `nil` limit argument whatever is defined in migrations (thus defaulting to a limit of 4);
- `ActiveRecord::ConnectionAdapters::AbstractAdapters#register_class_with_limit` always receives an `int2` and never an `int8` or an `int4`;

I suspect the culprit to be ActiveRecord::ConnectionAdapters::PostgreSQLAdapter.initialize_type_map that aliases `int4` and `int8` to `int2`. If I replace the aliases for proper class registrations, I can load my schema again:

``` ruby
register_class_with_limit m, 'int4', OID::Integer
register_class_with_limit m, 'int8', OID::Integer
```
