Title

Alembic generates weird second migration when Enum name contains "Interval" (PostgreSQL only)

Description
**Describe the bug**
Alembic generates a weird second non-empty migration when using a Python `Enum` class whose name includes the word `"Interval"` (e.g., `IntervalUnit`). This behavior occurs **only with PostgreSQL** and does **not** affect SQLite. The issue disappears when the Enum class is renamed to something that doesn't contain `"Interval"` (e.g., `IntrvalUnit`).

**Expected behavior**
No changes should be detected in the second migration if the database schema and models remain unchanged.

**To Reproduce**

```
py
# main.py
from enum import StrEnum
from sqlmodel import Field, SQLModel

... [Log Snipped] ...
    id: int = Field(default=None, nullable=False, primary_key=True)
    interval_unit: IntervalUnit
```

```
bash
# 1. Generate initial migration
alembic revision --autogenerate -m "create simple table with 'Interval' enum"

# 2. Apply migration
... [Log Snipped] ...
# 3. Generate second migration (no changes made to code)
alembic revision --autogenerate -m "second autogenerate without changes"
```

**Error**

The second autogenerated migration falsely detects a type change:
```
op.alter_column(
    'task',
    'interval_unit',
    existing_type=postgresql.INTERVAL(),  # ???
    type_=sa.Enum('DAY', 'WEEK', 'MONTH', 'YEAR', name='intervalunit'),
    existing_nullable=False
)
```

**Versions.**
 - OS: macOS 15.4.1 (24E263)
 - Python: Python 3.13.5 (main, Jun 11 2025, 15:36:57) [Clang 17.0.0 (clang-1700.0.13.3)] on darwin
 - Alembic: 1.16.4

**Additional context**
The issue appears to be caused by Alembic or SQLAlchemy interpreting the Enum name IntervalUnit as PostgreSQL's native INTERVAL type.

This does not happen with SQLite.
