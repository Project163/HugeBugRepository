Title

crash: uv_fs_stat Assertion failed: (path != NULL)

Description
- Neovim version: 0.1.2
- Operating system: OS X 10.11.3
- Terminal emulator: screen-256color

After a simple save (`:w`), it just crashed with the following output:

```
Assertion failed: (path != NULL), function uv_fs_stat, file /tmp/neovim20160226-9533-5aksgr/neovim-0.1.2/deps-build/build/src/libuv/src/unix/fs.c, line 1163.
```

Can't reproduce it, though.

The report:

```

Identifier:            nvim
Version:               0
Code Type:             X86-64 (Native)

```
Discussion
- uv_fs_stat was passed a null path, and there is an assert there for PATH != NULL. For me a nondebug build causes a segfault, example

``` C
#include  
int main(void) {
    uv_fs_t request;
    uv_fs_stat(uv_default_loop(), &request, NULL, NULL);
}
```

A quick grep only shows `uv_fs_stat` being used in `os_stat`, which is only used internally in fs.c
- os_getperm
- os_file_exists
- os_fileinfo (the culprit in this case)
- os_fileid

FWIW all functions have the correct NONULL attributes. Since this happens in buf_write maybe it is possible for an autocommand to set buf->b_ffname or buf->b_sfname as NULL (assumption: but only if a valid file was already open in the buffer?)?
- :+1: That's where I got stuck. I checked to see if we were doing things correctly in `terminal_open` and friends, and didn't find any problems. 

It might not be a bad idea to wrap all access to `buf->b_ffname`/`buf->b_sfname` in setters like `buf_set_ffname` which then abort if a NULL is passed, or do something sensible.
