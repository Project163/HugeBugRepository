Title

Anti-CSRF tokens not encoded in authentication requests

Description
**Describe the bug**

`+` is not escape to `%2b` in `authorized_token` .

**To Reproduce**
Steps to reproduce the behavior:
1. Run follow script

```
python
from zapv2 import ZAPv2

target = '[URL]
apikey = 'key'
... [Log Snipped] ...

zap.spider.scan_as_user(contextid, userid, target)
```

2. See History

if `+` not contains in `authorized_token`, loggin successful.
but if contains '+' in authorized_token, login failed ( `422 Unprocessable Entity` ). because, `+` is not escaped to `%2b` .

**Expected behavior**

`+` will encode to `%2b`, loggin success.

**Screenshots**

- `+` is not encoded when response code is 422

[Image: Screenshot from 2019-07-24 19-03-42]

- `+` is encode to `%2b` when response code is 302

[Image: Screenshot from 2019-07-24 19-03-52]

**Software versions**
 - ZAP: 2.8.0
 - OS: Arch Linux 5.2.0-arch2-1-ARCH
 - Java: 12.0.1

**Additional context**

Please show me how to if any parameter can encode.
