Title

Infinite redirects after upgrading to Rails 3.0.2/3.0.3 with cached_classes => true

Description
When loading the sign_up page, I'm getting infinite redirects of 

`Started GET "/people/sign_in" for   at 2010-12-16 12:19:43 -0500
  Processing by Devise::SessionsController#new as HTML
Completed   in 0ms`

after upgrading from Rails 3.0.1 to 3.0.2 and/or 3.0.3. This has occurred on two separate projects. 

Problem can be remedied by either:
- setting `config.cached_classes = false` in the appropriate environment file (not desirable in production environments)
- adding an `:unless =>` to authenticate_resource! call, typically in application_controller.rb:
      before_filter :authenticate_user! :unless => :devise_controller?

I assume some slight change in rails and class_cache-ing behavior is breaking the redirect / filter functionality. Wasn't difficult to fix, but I thought other folks would like to know, and perhaps in the future the Devise code can handle it w/o the `:unless =>`.
