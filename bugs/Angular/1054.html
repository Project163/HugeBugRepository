Title

@ViewChild(MyInjectorToken as any, { static: false }) no longer works with Ivy

Description
# 🐞 bug report

### Affected Package
Ivy Compiler


### Is this a regression?
Yes. This used to work with Angular 8


### Description
To get view children or content children that implement a certain abstract class or interface requires a bit of a workaround - casting the injector token to "any" - but was definitely supported in so far that somebody had to have written the code that deals with the injector token. For details, see the related issues:
* [URL]
* [URL]

With a new Angular 9 (9.0.0-rc.5) project, the same mechanism fails in the AOT compillation step with the message: "error TS-991010: @ViewChild predicate cannot be interpreted"


## 🔬 Minimal Reproduction
[URL]

1. Download the Stackblitz sample
2. Upgrade the project to Angular 9 rc5 with `ng update --next=true @angular/cli @angular/core`
3. Build the project in AOT mode

## 🔥 Exception or Error
  
error TS-991010: @ViewChild predicate cannot be interpreted

Discussion
- Interesting bug, and thank you for the clear reproduction! This is indeed an issue.

What's going on here is that Angular sees `const ComponentInterfaceToken = new InjectionToken (...)` and realizes that it cannot statically determine the value as it involves the `new` operation. The compiler is trying to verify that the value in question is either a string or a `class` instance as specified by the type of `@ViewChild()`.

This is why you need a cast here - you're going beyond Angular's public API when you pass an `InjectionToken` as the query predicate. The fact that this worked in the runtime is an implementation detail.
- Will that be fixed by Ivy stable? I use that a lot, it is very helpful :( My latest usecase — I have directives for Web Audio API. They all extend native AudioNodes and provide themselves as AUDIO_NODE token. I need to be able to query all nodes in the view/content.
