Title

Default enum null value causes a bug

Description
**Issue type:**

[x] bug report

**Database system/driver:**

[x] `mysql` / `mariadb`

**TypeORM version:**

[x] `latest`
[x] `@next`

**Steps to reproduce or a small repository showing the problem:**
Create an enum column with default value null
```
ts
enum MyEnum {
  valueA = 'valueA',
  valueB = 'valueB',
}
... [Log Snipped] ...
  field?: MyEnum;
}
```

result 
```
js
{
  message: "Invalid default value for 'field'",
  code: 'ER_INVALID_DEFAULT',
  errno: 1067,
... [Log Snipped] ...
  parameters: []
}
```

It should've generated  `query: "ALTER TABLE ``entity`` CHANGE ``field`` ``field`` enum ('valueA', 'valueB') NULL DEFAULT null"`,

Adding `&& defaultValue !== null` seems to work
[URL]
Discussion
- Any updates on this topic? I'm stuck in the same issue :(

---

UPDATE after quick experiments:

changing 'null'

```typescript
@Column('enum', { enum: StructuralNode, nullable: true, default: null})
public structuralNode: StructuralNode;
```
to 'undefined' seems to work in my case :)

```typescript
@Column('enum', { enum: StructuralNode, nullable: true, default: undefined })
public structuralNode: StructuralNode;
```
- this solution found here: [Link] worked for me finally,
```
{
    name: 'status',
    type: 'enum',
    enum: ['active', 'inactive', 'paused'],
    enumName: 'statusEnum',
    default: '"inactive"'
}
```
- ... [Middle Discussions Snipped for Brevity] ...
- what is the point to set `default: null`, if when you set `nullable: true` database already sets you a null by default?
- It is probably unnecessary if the database uses null by default, but likely the user is just trying to be explicit with the default value and there shouldn't be unexpected behavior like this.
