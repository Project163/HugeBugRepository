Title

Sandboxing replaces some empty files with char device 1, 3 (/dev/null).

Description
When setting up the sandbox, bazel mounts /dev/null in place of at least some empty files, producing character device nodes instead of regular files. This can cause subtle problems in code that explicitly checks the S_IFREG bit.

In particular, this causes mysterious failures when loading python3 namespace modules due to importlib performing isfile() checks on `__init__.py` files.
Discussion
- This is "fixed" in the new sandbox implementation, however the new sandbox uses symlinks for all input files, which generally work fine, but may cause other issues.

If this is still a problem for you, please let me know and re-open this bug.
- This still seems to be a problem in Bazel 0.3.2.  See associated bugs I filed against Python below.
