Title

`quotes` never flags nested quotes

Description
Given the following, shouldn't there be an error, since the `"avoid-escape"` option is not set?

``` js
/*eslint quotes: [2, "double"]*/

var escaped = "a string containing 'single' quotes";
```

But, when I run this, I get no errors.  I checked with the Espree demo, and there is only a single literal node: `"a string containing 'single' quotes"`, and the way the rule works, the interior quotes are never examined.  I was also surprised there are no invalid test cases for nested quotes.  I can take this on if accepted.
Discussion
- I thought it's correct.
Under `[2, "double"]`, the rule does not check content of strings.

``` js
/*eslint quotes: [2, "double"]*/
var escaped = "a string containing 'single' quotes"; // valid.
var escaped = 'a string containing "double" quotes'; // invalid. it should enclose with double quotes and it should escape double quotes in the string.
```

``` js
/*eslint quotes: [2, "double", "avoid-escape"]*/
var escaped = "a string containing 'single' quotes"; // valid.
var escaped = 'a string containing "double" quotes'; // valid single quotes to avoid escaping double quotes in the string.
```
- I'm not sure I understand the rule the same way.  Without `"avoid-escapes"`, I think ALL quotes should follow the rules specified, and nested quotes must be escaped rather than using the alternate style.

Maybe that's just my assumption, that the outer quotes should always follow the rules, and the inner quotes should either be escaped, or the `"avoid-escapes"` option should be used to enable alternate style within.
