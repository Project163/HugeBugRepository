Title

cqlsh copy-from should error out when csv contains invalid data for collections

Description
If the csv file contains invalid data for collection types, at the moment the data is imported incorrectly, an error would be a better behavior. 

 For example this table: 

  
 CREATE TABLE test.test (key text, value frozen<set<text>>, PRIMARY KEY (key)); 
 
  

 with this data: 

  
  "key1" , "{ 'test1' ,  'test2' }" 
 "Key2" , "not_a_set" 
 
  

 will be imported by  COPY test.test FROM 'test.csv';  without errors but will result in the following data: 

  
 cqlsh> select * from test.test;

 key  | value
------+--------------------
 key1 | { 'test1' ,  'test2' }
 Key2 |        { 'ot_a_se' }

(2 rows)
 
  

 The second row should have been rejected. The reason is that the   split  function  assumes that the first and last characters of the string passed in are parentheses, without actually checking it.
