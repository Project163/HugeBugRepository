Title

Entry point not emitted in watch mode when a dependency chunk name has changed

Description
This gist provides a few files for a simple test case:

[URL]

When you run the 'watch.js' script (`node watch.js`), the build stats look like:

```
Hash:  
Version: webpack 1.1.8
Time: 30ms
                  Asset  Size  Chunks             Chunk Names
             A-built.js  3913       0  [emitted]  A
 .js   118       1  [emitted]
```

If you make a change to `B.js` (such as changing the `console.log` message), you see:

```
Hash:  
Version: webpack 1.1.8
Time: 6ms
                  Asset  Size  Chunks             Chunk Names
             A-built.js  3913       0             A
 .js   118       1  [emitted]
```

So the chunk is emitted with a new name (` .js`) but the entry point (`A-built.js`) is not emitted with that new name compiled in. If you examine `A-built.js` after this change, you can confirm that it is still going to load the previous build's chunk (` .js`).
