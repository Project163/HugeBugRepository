Title

[YSQL] Enum failed to restore with pg_enum sortorder value not set when in binary upgrade mode

Description
Jira Link: [Link: DB-16268]
### Description

Case:
1. Create colocated db with tables contained enum type on a old version (  old build)
2. Restore it on new universe with latest changes (newest   build)
Select failing
```
db=# select * from test_1;
ERROR:  invalid internal value for enum: 16386
```
no values in enum:
```
db=# \dT+ test_enum
                                        List of data types
 Schema |   Name    | Internal name | Size | Elements |  Owner   | Access privileges | Description
--------+-----------+---------------+------+----------+----------+-------------------+-------------
 public | test_enum | test_enum     | 4    |          | postgres |                   |
```
could not drop type with changing data in table
```
db=# drop table test_enum;
ERROR:  table "test_enum" does not exist
db=# CREATE TYPE test_enum AS ENUM ('zero', 'one', 'two', 'three', 'four', 'five', 'six', 'seven', 'eight', 'nine');
ERROR:  type "test_enum" already exists
```

Discussion
- I debugged the issue and found that it is caused by recent commit:

```
commit  
Author: Minghui Yang  
Date:   Sat Apr 5 00:34:03 2025 +0000

    [#26645] YSQL: Preserve enum sortorder during backup
```

The offending code is:

```
        if (isnan(yb_binary_upgrade_next_pg_enum_sortorder))
            ereport(ERROR,
                    (errcode(ERRCODE_INVALID_PARAMETER_VALUE),
                     errmsg("pg_enum sortorder value not set when in binary upgrade mode")));

```

If a backup was generated by ysql_dump prior to the above commit, it would not have emitted a query such as
`SELECT pg_catalog.yb_binary_upgrade_set_next_pg_enum_sortorder('2'::real);
`  to set the enum sortorder. As a result the above ERROR causes the restore to fail.

We should change ERROR to WARNING so that we do not fail the restore because of this.
