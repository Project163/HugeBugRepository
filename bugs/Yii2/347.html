Title

Possible bug in Optimistic Locking feature in BaseActiveRecord?

Description
Hi,

I think there might be a bug in the Optimistic Locking feature in BaseActiveRecord.  It does not throw StaleObjectException despite following instructions in [Link: the API document].  However, when I changed line 706 in BaseActiveRecord.php from:
`if (!isset($values[$lock])) {`
to:
`if (isset($values[$lock])) {`
it works.

Here are the steps I took to produce the problem:
## Before code change
1. Open 2 browsers, go to update screen for the same record in both browsers, update the same field (start_dt) in both browsers to different values but do not click 'Update'
2. Click 'Update' in browser 1.  Update successful.  Log entry below:

```
2014-11-29 17:01:32 [ ][1][-][info][yii\db\Command::execute] UPDATE `a_user` SET `start_dt`='2014-11-11 00:00:00', `expiry_dt`=NULL, `update_dt`='2014-11-29 09:01:32', `update_no`=0 WHERE (`user_ky`=4) AND (`update_no`='0')
```
1. Click 'Update' in browser 2.  Update also successful (Should throw StaleObjectException).  Log entry below:

```
2014-11-29 17:02:18 [ ][1][-][info][yii\db\Command::execute] UPDATE `a_user` SET `start_dt`='2014-11-12 00:00:00', `expiry_dt`=NULL, `update_dt`='2014-11-29 09:02:18', `update_no`=0 WHERE (`user_ky`=4) AND (`update_no`='0')
```
1. Retrieving the record also shows field updated to browser 2's value, which is wrong.
2. Also, from the logs above, the locking attribute (update_no) was not incremented.
