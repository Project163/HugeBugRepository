Title

Compilation fails with quarkus-gradle-plugin while using Hibernate bytecode enhancement

Description
**Describe the bug**
Quarkus compilation fails when the `org.hibernate.orm` Gradle plugin is used and the dirty tracking feature of Hibernate bytecode enhancement is enabled.

**Expected behavior**
I want to track dirty entities using Hibernate bytecode enhancement in Quarkus (unless there's a better way to do that).

**Actual behavior**
```
org.gradle.api.tasks.TaskExecutionException: Execution failed for task ':quarkusBuild'.
        at org.gradle.api.internal.tasks.execution.ExecuteActionsTaskExecuter$3.accept(ExecuteActionsTaskExecuter.java:151)
        at org.gradle.api.internal.tasks.execution.ExecuteActionsTaskExecuter$3.accept(ExecuteActionsTaskExecuter.java:148)
        at org.gradle.internal.Try$Failure.ifSuccessfulOrElse(Try.java:191)
        at org.gradle.api.internal.tasks.execution.ExecuteActionsTaskExecuter.execute(ExecuteActionsTaskExecuter.java:141)
... [Log Snipped] ...
        at org.jboss.threads.EnhancedQueueExecutor$ThreadBody.run(EnhancedQueueExecutor.java:1429)
        at org.jboss.threads.JBossThread.run(JBossThread.java:479)
```

**To Reproduce**
Steps to reproduce the behavior:
1. Clone [URL]
2. Run `./gradlew clean build --stacktrace`

**Environment:**
 - Output of `java -version`: `openjdk version "11" 2018-09-25`
 - Quarkus version or git rev: `0.16.1`
Discussion
- It seems that adding the following properties in `application.properties` fixes the compilation issue:
```
quarkus.index-dependency.hibernate-core.group-id=org.hibernate
quarkus.index-dependency.hibernate-core.artifact-id=hibernate-core
```

I will close this issue for now but I still have to confirm Hibernate bytecode enhancement works with Quarkus since I'm not observing the expected classes changes while debugging a real project.
- @gsmet I'm note sure there's a real problem here.

When I created this issue, I was trying to persist an entity with an attribute extending JPA's `AttributeConverter , String>` and the dirty check wasn't working in Quarkus while I had no problem with the same code in Thorntail (without Hibernate bytecode enhancement). I didn't see at first that there were some features of Hibernate bytecode enhancement (maybe all of them) already enabled in Quarkus, so I tried to add this by myself and it didn't fix my dirty check issue. Then, I decided to let this problem aside, to give Panache a shot and to convert the `AttributeConverter`-typed attribute to an `Entity` in the meantime.

I might come back to this dirty check issue later but it's not the top priority right now. I want to finish testing Panache first at least.
- Yes, there is: we should ignore the interfaces when going through the hierarchy. If not all interfaces, at least those Hibernate ORM SPIs.
