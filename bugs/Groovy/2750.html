Title

.each{..} Closure With Parameter Typed As Object[] Makes Arguments Object[Object[]]

Description
When iterating over a List of Object[] in a .each closure and typing the parameter as  Object[] , the arguments in each iteration become an Object[] of Object[]. This does not happen if the parameter is  def . 

  
  Object [] arr =  new   Object [1]
arr[0] =  'test' 
List list =  new  ArrayList()
list.add(arr)

list.each { def obj ->
     assert  obj[0] ==  'test' 
}

list.each {  Object [] obj ->
     assert  obj[0] ==  'test'   //fails. obj[0] is  Object []{ 'test' } instead of just  'test' 
 }
 
  

 This does  not  happen if the parameter is typed as  String[] : 
  
  String [] arr =  new   String [1]
arr[0] =  'test' 
List list =  new  ArrayList()
list.add(arr)

list.each { def obj ->
     assert  obj[0] ==  'test' 
}

list.each {  String [] obj ->
     assert  obj[0] ==  'test'   // passes
 }
 
  

 I have included a more thorough test case that demonstrates this behavior. Note that this may also apply to .collect or various other methods.
Discussion
- Giving this the label "breaking" because the bug is originating from a generated call(Object[]) method on the open block, which wrongly forwards the call by a direct call with wrong logic. the chance should be low to actually break code though.
- It is a problem when performing a GORM query in Grails and selecting multiple properties: 

  
 List results = Foo.createCriteria().list {
    projections {
        property( "bar" )
	property( "baz" )
    }
}
 
  

 Trying to do a .each{} on that will not give you the correct results because it returns a List of Object[], where each array has the requested properties. Even though the workaround is simple (use a for loop, or simply type as not Object[]), it still sucked up a significant amount of time to figure that out.
- because it is potentially breaking the change is 2.4 only
