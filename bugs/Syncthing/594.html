Title

Incorrect file info passed as argument to delete existing file

Description
This is a regression introduced in #5567 and thus relevant for the current v1.1.1 RC. To reproduce, run `TestSymlinksSimpleVersioning` from the integration test suite (or possible any other symlink test). The test will time out and one Syncthing log contains:

```
1677 panic: bug: attempting to version a symlink
   1678 
   1679 goroutine 805 [running]:
   1680 github.com/syncthing/syncthing/lib/versioner.Simple.Archive(0x5,  ,  ,  , 0xb,     1680 70,  )
   1681         /media/ext4_data/Coding/go/src/github.com/syncthing/syncthing/lib/versioner/simple.go:54 + 
... [Log Snipped] ...
   1693         /media/ext4_data/Coding/go/src/github.com/syncthing/syncthing/lib/model/folder_sendrecv.go:263 +0x4ee
   1694
```

The culprit is `file` instead of `curFile` here: [URL]  
PR incoming.
Discussion
- So this happens when versioning is enabled and there is an existing symlink to be replaced with something not-symlink, yes?
- Yes, that's what I understand from that integration test. However it seems to be more complicated than that, as a simple unit test doing just that (creating and syncing a regular file, then replacing with a symlink) did not trigger the panic.
- Other direction, I think. As is (buggy) we skip versioning if the new thing is a symlink. With the fix it checks if the old thing is a symlink.
