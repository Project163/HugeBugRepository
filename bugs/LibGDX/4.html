Title

FileHandle.exists isn't coherent on iOS

Description
It seems that by default libgdx fallbacks to the classpath for internal files, however, the exists() method is overridden in the IOSFileHandle class to only look at bare files.
This leads to situation where you can read() a file handle but its exists() method returns false.
Is this intended ? If not would it suffice to remove the override exists method or does it serves another purpose ?

Thanks by advance.
Discussion
- The `exists()` method uses the same `file()` method that `read()` uses to obtain the InputStream. You should never hit a scenario where `exists()` returns `false` and `read()` does not generate an exception. Have you actually hit the scenario you have described?
- Yes we do hit this scenario for every file provided via the classpath on iOS. It could be an error on our side, but looking at IOSFileHandle, the file() method is also overridden.
- ... [Middle Discussions Snipped for Brevity] ...
- It looks like `com.badlogic.gdx.files.FileHandle`'s implementation of the `exists()` method already checks for the Classpath case and handles it appropriately. So it seems to me that this issue could be resolved by removing the overridden `exists()` method from `IOSFileHandle` and using the implementation in the superclass.

(Unless there's some compelling reason why `IOSFileHandle` needs to override the `exists()` method, but I don't see one.)
- It was overridden because the internal check in FileHandle.exists() doesn't work for iOS.
