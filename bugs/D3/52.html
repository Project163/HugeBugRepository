Title

selection.sort should skip null nodes rather than pass null to comparator?

Description
Discovered that when a selection includes exiting nodes, the sort comparator receives `null` as a value when it would normally be expecting data. Looks like a fix might involve a bit friendlier relationship between .sort and .order, but any reason not to try tackle this? This violates the usual expectation (and current documentation) that null nodes are skipped over by operators.

(If this is by design, would appreciate a bit more insight and I can update the wiki to make sure this caveat is noted.)
Discussion
- I agree, that does seem a bit inconsistent. Seems like the correct behavior should be to put null nodes at the end, rather than passing null to the comparator.
