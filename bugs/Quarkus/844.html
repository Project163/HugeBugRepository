Title

gRPC and Reactive Kafka Fails Native Build

Description
**Describe the bug**
When running native build with Gradle and JIB on a project containing both `quarkus-smallrye-reactive-messaging-kafka` and `quarkus-grpc`, native build fails with class initialization time error.

**Expected behavior**
Native build completes successfully.

**Actual behavior**
Native build fails with the following stacktrace:

```
Error: Classes that should be initialized at run time got initialized during image building:
 io.netty.channel.epoll.Epoll the class was requested to be initialized at run time (from feature io.quarkus.runner.AutoFeature.beforeAnalysis). io.netty.channel.epoll.Epoll has been initialized without the native-image initialization instrumentation and the stack
trace can't be tracked. Try avoiding to initialize the class that caused initialization of io.netty.channel.epoll.Epoll

com.oracle.svm.core.util.UserError$UserException: Classes that should be initialized at run time got initialized during image building:
... [Log Snipped] ...
        at java.base/java.util.concurrent.ForkJoinWorkerThread.run(ForkJoinWorkerThread.java:183)
Error: Image build request failed with exit status 1
```


**To Reproduce**

Steps to reproduce the behavior:
1. Create a project based on the quickstart for gRPC
2. Add the `quarkus-container-image-jib` dependency
3. Run `./gradlew build -Dquarkus.package.type=native -Dquarkus.native.container-build=true`
4. Observe image builds successfully
5. Add the `quarkus-smallrye-reactive-messaging-kafka` dependency
6. (Optional) Add a stream according to the Quarkus documentation
7. Attempt a native build with the command `./gradlew clean build -Dquarkus.package.type=native -Dquarkus.native.container-build=true`
8. Observe the failure indicated above

**Configuration**
```properties
quarkus:
  native:
    additional-build-args: -H:+TraceClassInitialization
```
