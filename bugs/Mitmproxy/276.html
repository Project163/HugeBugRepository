Title

Wireguard config has wrong endpoint when two active NICs

Description
#### Problem Description
When running `mitmweb`in `wireguard` mode with more then one active network interface (two IPs/subnets), and running the `--listen-host` flag with fixing the IP from NIC2, the wireguard config (and QR) is generated with `endpoint  `.
One has two manually modify the wireguard config after importing via e.g. QR code.
But the `listening` on NIC2 works as it should, only the config is generated wrong.

#### Steps to reproduce the behavior:
1. Run two network interfaces (e.g. primary NIC1= /24, NIC2= /24)
2. mitmweb --mode wireguard --listen-host  /24
3. mitm wireguard config is generated with endpoint  /32.

#### System Information
```
~ mitmweb --version
Mitmproxy: 10.2.2
Python:    3.12.1
OpenSSL:   OpenSSL 3.1.4 24 Oct 2023
Platform:  macOS-14.3.1-arm64-arm-64bit
```
