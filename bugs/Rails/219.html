Title

Differing enum keys in Rails 6.1 throw an error that they are duplicates

Description
### Steps to reproduce

```
class Event   1,
    'Etc/GMT-1' => 2
  }
end
```

### Expected behavior
I should be able to run the app and use these enums.

### Actual behavior
ArgumentError (You tried to define an enum named "timezone" on the model "Event", but this will generate a instance method "Etc_GMT_1?", which is already defined by another enum.)

### System configuration
Rails 6.1
Ruby 2.6.5p114
Discussion
- This is expected. Have you considered changing enum keys and using only alpha-numeric or underscore characters?
- I preferred to keep the keys matching the names of the IANA time zones. Makes for simpler code between a mobile app and a Rails API. I could change them to alpha-numeric or underscores but then I have to write code as a workaround to translate the IANA time zones in to the keys. Has anyone considered adding a `_methods: false` option for enums so these methods are not generated? That would solve my problem since I do not use them for this use case.      "-" => "minus"
   }
