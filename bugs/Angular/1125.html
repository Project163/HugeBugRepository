- I just created a new project and added all the dependencies listed here.
I then ran `ngcc`, which took about 650 secs to process everything in `node_modules`.
Finally I turned on the benchmarking and ran `ng serve --progress=false` giving:

```
NgccProcessor.process: 702.833ms
NgccProcessor.processModule.ngcc.process+tslib: 5.221ms
NgccProcessor.processModule.ngcc.process+@angular/core: 3.134ms
NgccProcessor.processModule.ngcc.process+@angular/platform-browser-dynamic: 3.452ms
NgccProcessor.processModule.ngcc.process+rxjs: 2.546ms
NgccProcessor.processModule.ngcc.process+@angular/compiler: 1.946ms
NgccProcessor.processModule.ngcc.process+@angular/platform-browser: 2.151ms
NgccProcessor.processModule.ngcc.process+@angular/common: 1.957ms
```

This is what I expect.
The initial `process` is the async integration with ngcc, which has to read in the entry-point manifest and then check that all the entry-points are already processed. 700ms is reasonable for this size of project.
The subsequent `processModules` are the few packages that are actually used in this project being checked by ngcc and found already processed. You can see that these take usually less than 5ms each.

From looking at your output, it looks to me like ngcc is rebuilding all the packages again, rather than finding them already built.

This is surprising and the only reasons I can suggest are:
* something is modifying the `node_modules` folder after the postinstall hook
* you actually are running ngcc with a specific set of formats (e.g. `es2015` and not `es5`) but then your tsconfig.json is setup to use a different format (e.g. `es5`) which causes those formats to be built additionally during the build.
* the version of ngcc used in the postinstall is somehow different to the version used in the CLI integration?
