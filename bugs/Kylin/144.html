Title

Error is reported when query with the time partition column filter.

Description
Set the column whose data type is timestamp in the source table to the yyyy-MM-dd format when setting the partition column, and configure not to check the format of the partition column in building job, an error is reported when query with the time partition column filter.
Discussion
- Root Cause  

 The model of the SQL hit is the partition column format as follows  yyyy-MM-dd  
      
The data type of the F_LOSS.SYSTEM_RUN_DATE field in the hive table is TimeStamp 
      

 Convert the start/end range of the first Segment of the model into the format string of the model time partition column _ 1657497600000 -> "2022-07-11"_ 
      

 And in transformValue2RexLiteral method，change input to  RexLiteral  
Since the type of the partition column field is TimeStamp, it will enter the corresponding branch. 
      

 In new TimestampString(value) ,  regular matching fails, report error . 
      

 The data type of the time partition column used by the model in the source table is Timestamp type. 
The format of the model time partition column needs to be set to the following two formats, otherwise an error will be reported when entering this method. 
 
	 yyyy-MM-dd HH:mm:ss 
	 yyyy-MM-dd HH:mm:ss.SSS
- Fix Design  
Add check before segment range is converted to RexLiteral. 

 If it is a DATE or TIMESTAMP type, the segment range is converted to the corresponding partition column format. 

 If the converted format does not match the type, the segment range will be converted twice (other types and formats remain as they are), and the format conversion rules are as follows 

 
	 date type -> yyyy-MM-dd 
	 timestamp type -> yyyy-MM-dd HH:mm:ss
