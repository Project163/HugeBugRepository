Title

Undertow does not consider classes annotated by a handled type for ServletContainerInitializer

Description
**Describe the bug**

The JavaDoc for the `javax.servlet.ServletContainerInitializer` states that the classes passed to `onStartup` should be

specified by the {@link javax.servlet.annotation.HandlesTypes HandlesTypes} annotation ...

However, the `io.quarkus.undertow.deployment.UndertowBuildStep#servletContainerInitializer` method only considers classes that extend or implement the class types, not ones that are annotated by it.

Something along these lines should probably be added

    for (AnnotationInstance annotationInstance : combinedIndexBuildItem.getIndex()
            .getAnnotations(typeName)) {
        handledTypes.add(annotationInstance.target().asClass().name().toString());
    }

**Expected behavior**

If a `ServletContainerInitializer` is annotated by `@HandlesTypes(Foo.class)`. where `Foo` is an annotation, classes annotated by this should be passed to its `onStartup` method.

**Actual behavior**

Classes annotated by a handled type are not passed to the `onStartup` method.

**To Reproduce**
Steps to reproduce the behavior:
1. Add the `quarkus-undertow` dependency
2. Register a `ServletContainerInitializer` using SPI.
3. Annotate it with `@HandlesTypes( )`
4. Add a class that is annotated by ` `, and that is discoverable by Quarkus.
5. Debug the `onStartup` method, and see that the annotated class is not passed to it.
