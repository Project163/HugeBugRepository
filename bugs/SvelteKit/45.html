Title

`svelte-kit package` crashes with `Cannot read property 'replace' of undefined` when preprocessor set in version `1.0.0-next.173`

Description
### Describe the bug

Running `svelte-kit package` with typescript enabled and `1.0.0-next.173` causes a crash.

Works on version `1.0.0-next.172`.

### Reproduction

* `npm init svelte@next something` TypeScript **Yes**, everything else **No**
* `npm install`
* `npm install -D svelte2tsx typescript`
* create `src/lib/Test.svelte` with `  `
* add `"package": "svelte-kit package"` as package.json script
* `npm run package`

Repo if needed: [URL]

### Additional Information

I have no clue and never worked with svelte/kit internals, but after some digging it seems to be related to [URL]

If a preprocessor is set the `strip_lang_tag` function doesn't check if `attributes` is defined and calls `.replace(...)` on it, i.e. it expects every `script` and `style` tag to contain `lang` or `type` attributes.

Quickfix could be to add a `if (!attributes) return tag;` above `const idx = tag.indexOf(attributes);` in line 209 of `packages/kit/src/packaging/index.js`.

Workaround would be to add lang="" to any `script` and `style` tags which have not set anything.
