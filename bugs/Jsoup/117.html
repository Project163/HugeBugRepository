Title

Invalid start/end positions for TextNode source range

Description
If I configure the parser to track positions and feed in the fragment ` foo  bar   `, both `foo` and `bar` get parsed as text nodes. However, the source range for `foo` contains invalid start/end positions. I realise `foo` is a misplaced text, but is there a specific reason why we do not populate the positions? Also, I see the same unexpected behaviour if I add whitespaces between ` ` and ` `. The resulting text node contains invalid positions.

Here's a simple test program:
```
import org.jsoup.nodes.Document;
import org.jsoup.nodes.Node;
import org.jsoup.nodes.Range;
import org.jsoup.nodes.TextNode;
import org.jsoup.parser.HtmlTreeBuilder;
... [Log Snipped] ...
    }
}
```
And the unexpected output:
```
$ java -cp ~/.m2/repository/org/jsoup/jsoup/1.15.4/jsoup-1.15.4.jar Test.java 
text=foo start=0 end=-1    # start/end positions are invalid here
text=bar start=18 end=21
```
