Title

Rails 4.2.0rc2 and deliver in action mailer

Description
Given this mailer:

```
class TestMailer < ActionMailer::Base
  def msg
    mail to:"foo@bar.com",
         subject:"asd",
         from: "a@a.com",
... [Log Snipped] ...
  end
end
```

`TestMailer.msg.deliver` does work but `TestMailer.msg_and_deliver` doesn't. Used to work in rails 4.1, at least it should throw a deprecation warning. 
In our usecase we have a method that generates multiple mails and calls deliver on them

[URL]
Discussion
- The issues seems to be that previously calling a method on an `ActionMailer::Base` executed the method. Now it returns a `Delegate` and method will be executed lazily or even in another process. This is in parts seems to be documented on [Link: ActionMailer::MessageDelivery]. 

Possible fixes:
- Add a note about this potential issue to [Link: release notes]
- Add a ruby finalizer with a warning, which could be disabled when **getobj** is called.

Also for me reading the docs i understood that message delivery is async in rails 4.2. But looking the code, message generation is also async.
- Yes this is correct. Message are lazy loaded.

Unless we determined the finalizer approach is safe, putting this in a prominent position of the release notes and upgrade guides with the class method workaround seems like a good compromise
- To be pedantic, I'd argue "fix" rather than "workaround": your example appears to be relying on an undocumented implementation detail, rather than a now-broken feature.

I certainly don't object to making the release notes clearer that it'll stop working... and if we can find an appropriately gentle way of providing a deprecation warning, I'm fine with that too. But I'd also be almost-fine with breaking it without warning; the only reason it could be concerning is that it's potentially a silent-do-nothing failure, rather than a suddenly-raise-exception one.
