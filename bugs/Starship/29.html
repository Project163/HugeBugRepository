Title

Java module displays incorrect version number

Description
#### Current Behavior
The version shown for java is not the version number users would expect to see.  It appears to be a vendor-specific version.

For example when I run "java -version", this is the output:

openjdk version "17.0.4" 2022-07-19 LTS
OpenJDK Runtime Environment Zulu17.36+13-CA (build 17.0.4+8-LTS)
OpenJDK 64-Bit Server VM Zulu17.36+13-CA (build 17.0.4+8-LTS, mixed mode, sharing)

The version reported by the java module in starship is "17.36".  I expected to see "17.0.4" not the "Zulu" version.

Note that for JDK 8 it gets the version right, even though the output of "java -version" is not significantly different:

openjdk version "1.8.0_332"
OpenJDK Runtime Environment (Zulu  -CA-macosx) (build 1.8.0_332-b09)
OpenJDK 64-Bit Server VM (Zulu  -CA-macosx) (build 25.332-b09, mixed mode)

In this case the java module shows "1.8.0" rather than the "8.62" "Zulu" version, so it isn't even consistent.


#### Expected Behavior
Java module should show the JDK version rather than the vendor specific build version.

Discussion
- Looking at the code, I suggest the following changes:
Make the regex  (?:version)[^\d\.]*(?P [\d\.]+)
Use '-version' instead of '-Xinternalversion' for the java command line argument.
I'm not 100% sure that will catch everything, but it is likely better than the current implementation.
- The reason we use `-Xinternalversion` instead of `-version` is because `-version` is much, *much* slower. (For a concrete idea of numbers, on my dev desktop, it's 1.7ms for `-Xinternalversion` and 42ms for `-version`. I think I've seen upwards of 200ms on slower machines).

Does your regex change work even if we don't make the change to the CLI argument?
- No, an alternate regex is needed for -Xinternalversion

-Xinternalversion on my system prints this for Java 19:

OpenJDK 64-Bit Server VM (19.0.1+10) for bsd-amd64 JRE (19.0.1+10) (Zulu19.30+11-CA), built on Sep 22 2022 11:30:59 by "zulu_re" with clang Apple LLVM 12.0.0 (clang-1200.0.32.29)

this for JDK 17:

OpenJDK 64-Bit Server VM (17.0.5+8-LTS) for bsd-amd64 JRE (17.0.5+8-LTS) (Zulu17.38+21-CA), built on Oct  7 2022 06:03:12 by "zulu_re" with clang 4.2.1 Compatible Apple LLVM 11.0.0 (clang-1100.0.33.17)

or this for Java 8:

OpenJDK 64-Bit Server VM (25.352-b08) for bsd-amd64 JRE (Zulu  -CA-macosx) (1.8.0_352-b08), built on Oct  9 2022 02:39:15 by "zulu_re" with gcc 4.2.1 Compatible Apple LLVM 11.0.0 (clang-1100.0.33.17)

As you can see the position of the correct number is not consistent, that was the basis for my suggesting to use "-version" which has more consistent output:

Java 8:

OpenJDK 64-Bit Server VM (Zulu  -CA-macosx) (build 25.352-b08, mixed mode)

However, I do see that there is a significant performance hit. So I found the following regex that seems to work with -Xinternalversion:

(?: JRE.*\\()([\d.]+)
