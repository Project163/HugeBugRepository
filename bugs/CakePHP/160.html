Title

3.0 Inflector - *Metadata

Description
Inflector have a bug regarding the word "Metadata" that prevents some models to not work as expected and bake to show wrong data and fail.

```
php
debug(Inflector::singularize('Metadata'));
debug(Inflector::singularize('FilesMetadata'));
debug(Inflector::pluralize('Metadata'));
debug(Inflector::pluralize('FilesMetadata'));
... [Log Snipped] ...
/src/Controller/DMSController.php (line 130)
'FilesMetadatas' // Expected: FilesMetadata
```

Problem snowballs to:

```
php
debug($this->FilesMetadata);
debug($this->Metadata);

/src/Controller/DMSController.php (line 125)
... [Log Snipped] ...

}
```

Inflector.php > line 32 `$_plural['rules']` > adding: `'/(m)etadata$/i' => '\1etadata',`
Adding this line prevents metadata turning into metadatas (but I have no idea on how, just followed the pattern of the code above)
Inflector.php > line 144 `'/([ti])a$/i' => '\1um',` 
This line is the rule that transforms FileMetadata into FilesMetadatum

I would submit a PR if I could understand better this rules, but I'm really not confident about it so I tried to point out where the problem is.
Discussion
- I can take a look, Inflector is generaly not very good with compound words, and often ends up working against the tail component as in this situation.
- I fixed this in `master` as it was also a problem there. It will show up in `3.0` on the next merge.
