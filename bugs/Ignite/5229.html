Title

Server node failed due to java.lang.AssertionError: Client already created

Description
It seems like we release recovery descriptor prior to removing communication client from the connection pool. So another thread successfully reserves descriptor, creates a client and tries to put a newly created client into the pool and fails because there is a stale client which we didn’t remove yet. I think we should release descriptor AFTER we remove communication client and it should fix the issue.

- sdanilov  , could you please provide snippets of code where the race happens? Otherwise this patch looks good to me and I think it is ready to be merged to master.
- It seems like we release recovery descriptor prior to removing communication client from the connection pool. So another thread successfully reserves descriptor, creates a client and tries to put a newly created client into the pool and fails because there is a stale client which we didn’t remove yet. I think we should release descriptor AFTER we remove communication client and it should fix the issue. 

 Here is the relevant code (GridNioServer#2861): 
  
 
  if  (outRecovery !=  null )
     outRecovery.release();

 if  (inRecovery !=  null  && inRecovery != outRecovery)
     inRecovery.release();
 
  

 And after that we close session here (GridNioServer#2877): 

  
 
 try  {
     filterChain.onSessionClosed(ses);
}
 
  

 closing the session is the code that clears the client from the clients array in ConnectionClientPool; its reserveClient method tries to put a newly created client iff recovery descriptor can be acquired which can be because we release it prior to closing the session.
