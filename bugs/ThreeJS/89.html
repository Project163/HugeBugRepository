Title

Physically-based shading became an unchangeable default?

Description
Not sure if this is a bug or not, but after commit [URL] the phycallyBasedShading attribute in the WebGLRenderer (which used to default to false) was removed, but PHYSICALLY_BASED_SHADING sections of the fragment shader were left behind, meaning they're default and can't be turned off.

Not sure if this was intentional, but it's causing some odd visual artifacts in the app I'm working on. If it was decided that physically-based shading should be default, I feel it should still remain possible to turn it off, since that was the behaviour it had before.
Discussion
- All changes related to physically-based-shading were intentional. The prior behavior was incorrect, and hence was removed.

See #4363 for tips on setting parameters.
- Ok, fair enough. I'll admit I'm not an expert in illumination models. But perhaps the change should be mentioned on the "Migrating" page?

I played with the parameters according to what you wrote, and although the highlights now look reasonable, I'm still getting these black dot artifacts (see image). They seem to appear around the specular highlights, but I'm not 100% sure. Do you think this is still an issue with MeshPhongMaterial attributes, or is there something else that might have to be changed? The dots even appear if I use MeshPhongMaterial with default attributes.
