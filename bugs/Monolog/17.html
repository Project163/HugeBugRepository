Title

LogglyFormatter doesn't normalize empty context/extra array to object, causes MappingConflict

Description
Loggly parses JSON messages thrown at it, and the `\Monolog\Formatter\LogglyFormatter` does a pretty good job of formatting messages that it can cope with. However, if a field value is sent as an object, Loggly expects that value to always be sent as an object. If you later send it as an array or scalar, you get a "MappingConflict":


The "removed all JSON fields" part means even the message field is dropped - quite annoying behaviour, but understandable (I think) if you imagine what they're probably indexing with (Elastic I'm guessing).

I think I've tracked down the MappingConflict in question to be occurring on both the `context` and `extra` fields sent from Monolog. For example, if you're using a Handler set up to use the LogglyFormatter, and you send these two log messages:

```
$logger->notice('Some message', ['foo' => 'bar']);
$logger->notice('Some message');
```

The first will send the context as an object, and the second will send the context as an empty _array_, causing the MappingConflict:

```
{"message":"Some message","context":{"foo":"bar"},"level":250,"level_name":"NOTICE","channel":"foo","datetime":{"date":"2017-07-20 01:24:36.190486","timezone_type":3,"timezone":"UTC"},"extra":[],"timestamp":"2017-07-20T01:24:36.190486+0000"}
{"message":"Some message","context":[],"level":250,"level_name":"NOTICE","channel":"foo","datetime":{"date":"2017-07-20 01:24:36.190257","timezone_type":3,"timezone":"UTC"},"extra":[],"timestamp":"2017-07-20T01:24:36.190257+0000"}
```

In order to avoid all JSON fields being stripped once Loggly tries to index the messages, the LogglyFormatter should ensure that the context and extra fields are always sent as an object, even when empty (i.e. `{}` instead of `[]`)
Discussion
- (The actual cause for me was a sometimes-attached WebProcessor causing the `extra` field to alternate between object and array, but the above is conceptually simpler, and the same issue I think)

Also, I'm using the SyslogHandler to ship logs to Loggly, in case that matters. I can't see the logic I'm asking for hiding in the LogglyHandler though (and it seems like it would belong to the formatter in any case?)
