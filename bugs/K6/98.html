Title

Fix race conditions

Description
Currently when the test suite is run with the `-race` flag, a few race conditions appear. I think that one of them is [Link: this] (or related to it), while another one seems to be related to metrics collection of http requests that reuse the same connection. 

The end goal here is to enable the `-race` flag for CI tests runs so we don't regress in the future.
Discussion
- The metrics collection race condition is because we use [Link: `httptrace.ClientTrace`] incorrectly. From the docs:

[Link: The k6 code] that uses `ClientTrace` has a lot of reads and writes for the same variables without any synchronization, so it has to be refactored. I'm not sure that a bunch of mutexes is the correct approach here, something event-based seems like a better solution, for example each of the `ClientTrace` methods could just create an event, send it over a channel and something else can synchronously and safely process them.
