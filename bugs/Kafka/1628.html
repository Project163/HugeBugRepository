- I've been able to reproduce this in a unit-test.   

 Here is the issue.  We have an existing RocksDB store (default num levels setting of 7). When the broker goes down and reconnects a re-balance is triggered and causes a state restoration.  When we go to restore the state store, we close RocksDB,  we turn on  options.prepareForBulkload  which sets the num_levels to 2 for optimized bulk loads, then re-opens the database.  

 Then we get the error because the pre-existing data is already there with num_levels of 7, thus throwing the exception.
