Discussion
- It looks like setting `max_upload_parts = 50000`  seems to have mitigated the problem. Running for an hour at `~ 300MB`
- How many and how big are the files you are uploading?

I suspect you are uploading multiple files bigger than 10,000 * 5M = 50 GB

Since these files don't fit in the normal chunk size, rclone will be increasing the chunk size. However this means that the file gets its own memory pool to fit the new sized chunks. Potentially if you have a files which vary in size you'll get multiple memory pools leading to memory exhaustion.

This would be easy to confirm with a debug log with `-vv`. If you have one can you attach one? Or if you want to sent it to me confidentially then email it to nick@craig-wood.com with a link to this github issue in it.

There was an issue and/or a forum thread about this very recently but I can't find it at the moment.


You must be using a non AWS system as [Link: 10,000 is the maximum for AWS].

This fixes the problems provided your files are less than 50,000 * 5MB = 250 GB in size by making sure that all the buffers in use are the same size (5MB).

Assuming this is the problem, other workarounds are

Set `--s3-chunk-size 25M` - provided all your files are less than 10,000 * 25M = 250GB all files will use the same 5MB buffer.

You can also use these flags to help rclone return memory to the OS

      --s3-memory-pool-flush-time Duration   How often internal memory buffer pools will be flushed (default 1m0s)
      --s3-memory-pool-use-mmap              Whether to use mmap buffers in internal memory pool

You'd use `--s3-memory-pool-use-mmap` and `--s3-memory-pool-flush-time 1s`

However all of these are workarounds to the fact rclone is not doing a good job managing memory here!

Perhaps rclone should be using a scatter/gather memory allocator to synthetically make the bigger buffers from the smaller once. This would be the most efficient solution.

Another solution would be for rclone to only allocate buffer sizes in factors of 2 from the default. So allocate pools at 5MB, 10MB, 20MB, 40MB rather than lots of intermediate sizes which means rclone can't share the memory.

Or maybe rclone's memory allocator should be re-worked so that it can keep buffers of more than one size.
