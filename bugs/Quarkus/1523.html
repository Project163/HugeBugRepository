Title

[Native] Locales bundles, ServiceLoader flow for JDK; e.g. Frankreich vs. France

Description
### Describe the bug

This is a followup on: :lady_beetle:  #22808 **Including resource bundles for different languages doesn't work**

# The problem
Unless `quarkus.native.auto-service-loader-registration=true` is used, i.e. `-H:+UseServiceLoaderFeature`, to trigger [Link: ServiceLoaderFeature] in Graal, JDK Locale bundles, e.g. `sun.util.resources.cldr.ext.LocaleNames_de` are not loaded.

The code in [Link: ServiceLoaderFeature] is missing finer grained include/exclude, so it bloats the image too much when used.

The result is that it silently falls back to `sun.util.resources.LocaleNames` English defaults. To illustrate:

```
System.out.printf("English: %s\n", Locale.FRANCE.getDisplayCountry(Locale.ENGLISH));
System.out.printf("German: %s\n", Locale.FRANCE.getDisplayCountry(Locale.GERMAN));
System.out.printf("Italian: %s\n", Locale.FRANCE.getDisplayCountry(Locale.ITALIAN));
```
Should print:
```
English: France
German: Frankreich
Italian: Francia
```
and not
```
English: France
German: France
Italian: France
```

# The solution (Quarkus) :grey_question: 
Naively deferring to `RuntimeInitializedClassBuildItem` or using `ReflectiveClassBuildItem` to init e.g. 
```
sun.util.resources.LocaleData$SupplementaryResourceBundleProvider
sun.util.resources.provider.SupplementaryLocaleDataProvider
sun.util.resources.LocaleData$CommonResourceBundleProvider
sun.util.resources.provider.LocaleDataProvider
```
is not enough as it doesn't help with the ServiceLoader architecture used to populate these implementations.
