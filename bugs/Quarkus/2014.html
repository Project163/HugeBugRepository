Title

Qute puts encoding in Content-Type header for located templates and doesn't put for injected

Description
### Describe the bug

I have one HTML file with Qute template.
If I inject it automagically, via `@Inject` annotation, and then return it from Resteasy endpoint, then resulting HTTP response has header `Content-Type=text/html`.
If I inject it ia `@Location` annotation, and then return from a similar endpoint, then resulting HTTP response has header `Content-Type=text/html;charset=UTF-8`.

### Expected behavior

Responses should have the same content-type for the same data and not depend on the way, which templates were acquired.

### Actual behavior

The same file injected via different annotations has different Content-Type.

### How to Reproduce?

1. `git clone -b reproducer/qute-charset git@github.com:fedinskiy/reproducer.git`
2. `cd reproducer`
3. `mvn clean verify`

The application:
```
@Inject
    Template basic;

    @Location("basic.html")
    Template located;
```

Discussion
- Could you test the reproducer with `resteasy-reactive-qute` as well?
- So the difference between `@Inject Template basic` and `@Location("basic.html") Template located` is that for the first one the template path is "incomplete" and the actual template is _selected_ in the `io.quarkus.resteasy.qute.runtime.TemplateResponseFilter` right before the rendering (based on accept headers). For `@Location("basic.html")` the path is "complete" and the `TemplateResponseFilter` does not set the media type explicitly.
