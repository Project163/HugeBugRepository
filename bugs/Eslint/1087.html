Title

no-var --fix sometimes leads to ReferenceError

Description
**Tell us about your environment**

Short summary of the issue:

1. `var x = x = 1`
1. `eslint --fix`
1. `let x = x = 1`
1. `ReferenceError: x is not defined`

* **ESLint Version:** 3.13.1
* **Node Version:** 6.9.1
* **npm Version:** 4.1.1

**What parser (default, Babel-ESLint, etc.) are you using?**

default

**Please show your full configuration:**

 
```
json
{
  "parserOptions": {
    "ecmaVersion": 8,
    "ecmaFeatures": {
... [Log Snipped] ...
  }
}
```

**What did you do? Please include the actual source code causing the issue.**

```js
$ echo 'var x = x = 1' > test.js
$ node test.js
$ eslint --fix test.js
$ cat test.js
let x = x = 1
```

**What did you expect to happen?**

I expected it to report the error below, which is what I get with the following minimal `.eslintrc`:

```json
{
  "rules": {
    "no-var": 2
  }
}
```

```js
/test.js
  1:5  error  Parsing error: Unexpected token x

✖ 1 problem (1 error, 0 warnings)
```

**What actually happened? Please include the actual, raw output from ESLint.**

```
js
$ eslint --fix test.js
/test.js
  1:5  error  'x' is assigned a value but never used  no-unused-vars

... [Log Snipped] ...
    at startup (bootstrap_node.js:149:9)
    at bootstrap_node.js:509:3
```

I will fix it.
