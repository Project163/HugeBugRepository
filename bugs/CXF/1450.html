 Hmm, not sure it's an jaxws-api spec jar issue, as CXF use servicemix spec 1.9.0 for a while. 
The code which cause the exception is 
  
  public  W3CEndpointReference createWSA( String  address) {
         ClassLoader  cl =  Thread .currentThread().getContextClassLoader();
         try  {
             if  (setClassLoader) {
                 Thread .currentThread().setContextClassLoader(WSNHelper. class. getClassLoader());
            }
            
             return   new  W3CEndpointReferenceBuilder().address(address).build(); // this  line cause the exception
         }  finally  {
             Thread .currentThread().setContextClassLoader(cl);
        }
    }
 
  
 seems set class loader as WSNHelper.class.getClassLoader() cause that the wsn-api bundle need explicitly import the org.apache.cxf.jaxws.spi package.
