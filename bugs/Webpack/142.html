Title

ModuleConcatenationPlugin throws on array default exports with functions

Description
**Do you want to request a *feature* or report a *bug*?**
I want to report a bug.

 
 

**What is the current behavior?**
`webpack.optimize.ModuleConcatenationPlugin()` throws `Cannot read property 'range' of null` when two modules are imported that:
- declare a function with the same name
- declare a default export
- the default export is an array with empty (not undefined) elements

For instance, this will break:
```
function foo(n) {
  return 'bar';
}
export default [, foo];
```

But this is fine:
```
function foo(n) {
  return 'bar';
}
export default [undefined, foo];
```

**If the current behavior is a bug, please provide the steps to reproduce.**

 
 
 

I have a minimal repro at [URL] that depends only on webpack.

```
git clone [URL]
cd webpack-default-exports-concat
npm i
npm test
```

**What is the expected behavior?**
```
$ npm test


... [Log Snipped] ...
Cannot read property 'range' of null
npm ERR! Test failed.  See above for more details.
```

No browser, node v8.9.1, webpack 3.10.0, Windows 10
