Odd rendering artifacts in sidenav when it's being rendered for the first time

Description

**Current behavior**
When the sidenav is being rendered for the first time, there are several weird rendering artifacts present on the screen before it is rendered in its final state. This causes unnecessary flicker.

At minimum there are "key" text nodes present in place where eventually arrows will be rendered:
----
- I don’t know how to cure the artifacts described by @igorminar in issue 16100. Presumably they occur on slow network/slow device.

The word "key" is likely the consequence of delayed processing of the ` `. Here's the source:
```
 keyboard_arrow_right 
```
Is there a way to know when the ` ` has done its job? Or when Angular had done its job? I suppose we could hide the nav items until `afterViewInit` + a tick. If we start going down that road, I fear the wheels just come off of Angular altogether. 

I don't know what the blue line is about but I've seen stuff like that and I believe it is a Material Design style that doesn't go away immediately.

To whom should we turn? Jeremy?
- I think I found out what this is:
![sidenav artifact][1].
(It also comes in horizontal flavor for the rotated icons of expanded accordions).

It is the `keyboard_arrow_right` text, after our CSS has been, but before the Material font has relaced the text with the icon.

So #16226 would solve this too.
