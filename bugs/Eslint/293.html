Title

block-scoped-var behavior in 0.16.0 is different from 0.15.0

Description
For example, when I lint `file.js` like this,

``` js
"use strict";

var v = 1;

module.exports = function() {
  return v;
};
```

With eslint 0.15.1,

``` sh
$ eslint file.js --env=node --rule=block-scoped-var:2
```

It shows no errors.

But, with eslint 0.16.0,

``` sh
$ eslint file.js --env=node --rule=block-scoped-var:2

file.js
  6:9  error  "v" used outside of binding context  block-scoped-var
```

it shows an error.

I think the previous behavior of `block-scoped-var` rule is valid for `node` environement.
Discussion
- Must have something to do with the node scope changes in 0.16.0 since there were only small changes in the rule.
- When `ecmaFeatures.globalReturn` is `false`, v0.16.0 works fine, too.

``` yml
env:
  node: true
ecmaFeatures:
  globalReturn: false
rules:
  block-scoped-var: 2
```
