Title

YARN ContainerLaunchContext should use cluster's JAVA_HOME

Description
var  javaCommand =  "java" 
    val javaHome =  System .getenv( "JAVA_HOME" )
     if  ((javaHome !=  null  && !javaHome.isEmpty()) || env.isDefinedAt( "JAVA_HOME" )) {
      javaCommand = Environment.JAVA_HOME.$() +  "/bin/java" 
    }
 
  

 Currently, if JAVA_HOME is specified on the client, it will be used instead of the value given on the cluster.  This makes it so that Java must be installed in the same place on the client as on the cluster. 

 This is a possibly incompatible change that we should get in before 1.0.

This will obviously fail while YARN tries to execute the container as % is treated differently in linux.
