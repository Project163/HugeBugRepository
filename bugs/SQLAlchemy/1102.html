Title

Query.join() no longer takes a list of tables (which is OK, but I can't find any docs)

Description
**Describe the bug**
Query.join() used to take a list of tables and would treat them as a sequence of calls to join, using the foreign key.   Now the second table in the list is take as an ON clause and gives an error (because it's not an ON clause, obviously).

THIS IS OK!  I guess it was either never supported or was deprecated aeons ago.  But I could not find any documentation for this in the change logs.  So I wanted to raise an issue to (1) just make you aware so you could take any action if unexpected and (2) to provide a Google hit for anyone else trying to debug the behaviour (the fix is to use successive explicit calls to join(), obviously).

**Expected behavior**
session.query(Table1).join(Table2, Table3) used to be equivalent to session.query(Table1).join(Table2).join(Table3)

Now it gives the error:
```
sqlalchemy.exc.ArgumentError: SQL expression for ON clause expected, got  
```

**To Reproduce**
See above.

 - OS: OpenSuse Leap 15.2
 - Python: 3.9
 - SQLAlchemy: 1.4.5 (but I don't know when this started; i may not have updated for some time)
 - Database: Postgres 13-3.0-alpine docker image
