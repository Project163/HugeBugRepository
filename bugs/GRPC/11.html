Title

GRPC_ARG_KEEPALIVE_TIME_* on the C++ client does not work when streaming

Description
### Should this be an issue in the gRPC issue tracker?
 yes
  
### What version of gRPC and what language are you using?

grpc 1.10 with C++
 
### What operating system (Linux, Windows, …) and version?

Ubuntu 16.04.3 LTS (Xenial Xerus)
 
### What runtime / compiler are you using (e.g. python version or version of gcc)
 
gcc (Ubuntu 5.4.0-6ubuntu1~16.04.9) 5.4.0 20160609
 
### What did you do?
 
- I start a grpc server and a client on different machines
  Both server and client are started with
`GRPC_ARG_KEEPALIVE_TIME_MS = 10000` and
`GRPC_ARG_KEEPALIVE_TIMEOUT_MS = 10000`

- the client opens a bidirectional stream to the server (both sides write & read messages)

- I pull the cable between server & client

### What did you expect to see?
 
The `Read` and `Write` calls fail on both sides after 20 **seconds**.
 
### What did you see instead?

The `Read` and `Write` calls fail on both sides after 15 **minutes**.
 
### Anything else we should know about your project / environment?

When using plain RPC calls without streaming, the client does time out after 20 seconds.
