Title

bevy_reflect downcasting is unsound

Description
As of   it is possible to cause UB in safe code using bevy_reflect. `Reflect::downcast` incorrectly assumes that `Reflect::any` returns an `&Any` representation of `self`. This is not necessarily the case. It is possible to return an `&Any` to a field of `self` with a different type. `Reflect::downcast` will then downcast to that specific type. This can be fixed by making `Reflect` an unsafe trait. The standard library avoids this problem by making it impossible to implement `Any` yourself using a blanket impl. See [URL]
Discussion
- How do I work around this? I'm experiencing this when I push to a Vec in  a struct that implements Reflect. The error is `Attempted to push invalid value of type TYPE`, but the type is correct.

Edit: I found a workaround mentioned in Discord. Instead of deriving Reflect on the inner type of your Vec, `use bevy::reflect::impl_reflect_value!`.
