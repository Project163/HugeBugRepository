Title

Color 4 missing channel is not preserved across compiler and host

Description
- [x] Spec (https://github.com/sass/sass/pull/3951)
- [Link: x] [Tests] (https://github.com/sass/sass-spec/pull/2023)
- [Link: x] [Dart Sass] (https://github.com/sass/dart-sass/pull/2366)
- [Link: x] [Embedded Host] (https://github.com/sass/embedded-host-node/pull/336)

---

```
js
const { compileString, SassColor } = require('sass-embedded');

const input = new SassColor({red: null, green: 0, blue: 0, alpha: null, space: "rgb"});

... [Log Snipped] ...
console.log(input.channelsOrNull.toArray()) // [ null, 0, 0 ]
console.log(output.channelsOrNull.toArray()) // expect [ null, 0, 0 ], but actual is [ 0, 0, 0 ]
```

In the example above, the output is `[ null, 0, 0 ]` on `sass`, but `[ 0, 0, 0 ]` on `sass-embedded`. This is because protobuf does not distinguish set or not set for number type by default. If not set, the number type will default to value 0, and thus cause the "missing channel" to be lost.

This will break the case of interpolating colors in the same space where `0` and `none` have different meaning: [URL]
Discussion
- [URL]

Looks like we need to make channels `optional` in the protobuf definition, and also change the protofier to detect the presence.
- I don't think this is accurate. `NaN`, the infinities, and signed zeros are all part of the IEEE 754 floating point specification, which these days is usually implemented at a hardware level. You can [Link: check yourself] in the C playground.

I don't see any indication in the protobuf documentation that these values aren't supported. The serialization for doubles is just a fixed-length 64-bit field, and there are bit patterns that unambiguously represent each of these.
- Looks like I misread the protobuf doc - it says when serializing proto object to JSON, NaN and infinity are not as numeric values, and will instead be encoded as string.
