Title

`in_` on nested `CompoundSelect` raises `NotImplementedError`

Description
### Describe the bug

SQLAlchemy core fails to compile a statement which uses the `in_` operator on a nested `CompoundSelect` object, i.e. `INTERSECT` of `UNION`s or vice-versa. It does work if the inner `CompoundStatement` is not the first argument to the outer one, producing a valid SQL.

### Additional context

I hit this issue in production where compound queries are built from user provided logic expressions transformed into CNF (conjunction of disjunctions, or in SQL terms `INTERSECT` of `UNION`s). Because the intermediate representation uses sets, which have undetermined ordering, the queries would fail randomly, only when the first argument for `intersect` happened to be a `CompoundSelect` produced by the `union` function.
