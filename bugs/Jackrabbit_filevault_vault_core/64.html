Title

Unable to perform checkout due to wrong default workspace handling

Description
When trying to perform a  vlt co  with  vlt  > 3.1.26 I get the following error message: 

  
 vlt co --force [URL]
Java HotSpot(TM) 64-Bit Server VM warning: ignoring option PermSize=128m; support was removed in 8.0
Checkout [URL] with local files using root at [...]/content/src/content/jcr_root
Connecting via JCR remoting to [URL]
[ERROR] checkout: org.apache.jackrabbit.vault.vlt.VltException: Unable to mount filesystem
caused by: javax.jcr.lock.LockException: Precondition Failed
  caused by: org.apache.jackrabbit.webdav.DavException: Precondition Failed
Discussion
- related to changes in   JCR-2113   that added new default workspace handling in spi2dav 

 workaround is to specify the default workspace in the url. eg: 

  
 $ vlt co --force [URL]
Checkout [URL] with local files using root at /Users/tripod/tmp/v1/screens/jcr_root
Connecting via JCR remoting to [URL]
Checking out / to jcr_root
...
- anchela   reschke  what is the modern way to remotely login to a repository using the default workspace name? 

 before the changes of   JCR-2113  , it was possible to omit the default workspace name when creating the  Spi2davexRepositoryServiceFactory .
