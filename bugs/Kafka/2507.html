    Reading the stack trace on the Jira, I think the issue might be related to the shared mock object we use. 

    The test testup is a little bit upside down to allow the usage of reflection. The test verifies that a method is called, by  not  registering an expected call, and catching the corresponding exception from `verify()` (because we use reflections, we cannot easily register an expected call and let `verify()` throw if the call was not made).
