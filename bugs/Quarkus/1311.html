Title

Resteasy Reactive response Content-Type string taken from request and cached badly

Description
### Describe the bug

I noticed that resteasy reactive takes the content type string from the request and reuses it for the response if it is the same media type.

Also it seems to get cached and reused in subsequent responses.

For example consider following content types for a request/response:

Request No# | Request | Response
-- | -- | --
1 | application/json | application/json
2 | Application/json | Application/json
3 | application/json | Application/json
4 | aPplication/json | aPplication/json
5 | application/json | aPplication/json
6 | APplication/json | APplication/json
7 | applicatIon/json | applicatIon/json
8 | application/Json | application/Json
9 | Application/json | application/Json
10 | Application/JSon | Application/JSon
11 | APPLICATION/json | APPLICATION/json
12 | application/jsOn | application/jsOn

It seems to be related to the caching mechanism in org.jboss.resteasy.reactive.common.headers.MediaTypeHeaderDelegate which just takes the string from the request and caches it for a specific mediatype and reuses it in future responses.

I made the following reproducer with three test cases which shows the problem:

[Link: reproducer.zip]

I think this is kinda weird behavior and might cause problems for clients. 
I think it would be better if the string is consistent.
