Title

BeforeQuery promises are not awaited before query execution

Description
### Issue description

BeforeQuery promises are not awaited before query execution

### Expected Behavior

When using a Subscriber, `beforeQuery` promises should be awaited and executed before the actual query.

### Actual Behavior

`beforeQuery` and `afterQuery` promises are all executed after the query

### Steps to reproduce

Enable requests logs, create a Subscriber with an async `beforeQuery`, and it will be run after the query.

### Additional Context

It seems that it is due to the fact that `await broadcasterResult.wait()` is [Link: only called after the query execution] in the `finally` statement. Is there a reason behind this technical choice ?

The `beforeQuery` and `afterQuery` where implemented after [Link: this issue], maybe it was only intended for logging purposes ?


Context: i am trying to [Link: implement RLS] on our project, and i would like to use subscribers to set the current tenant_id before executing some queries on tables with RLS enabled. 
Since there is no `beforeLoad` event (it was proposed in [Link: this issue] but it was closed), i wanted to try to use the `beforeQuery` method
