Title

SimpleChannelPool problematic throwable handling

Description
Netty version: 4.0.38.Final

Context:

I try to use SimpleChannelPool under heavy load and after some errors "Caused by: java.net.SocketException: Too many open files" started to get exceptions that are very hard to read and that doesn't have a lot of sense to save in this current state (at least because it's exception log for 600Kb):

```
[14 Jul 2016 14:24:47,190][WARN ][SingleThreadEventExecutor,httpClient-1-1] - A task raised an exception.
java.lang.IllegalStateException: complete already: DefaultPromise@4a75ea21(failure: java.lang.StackOverflowError)
    at io.netty.util.concurrent.DefaultPromise.setFailure(DefaultPromise.java:123)
    at io.netty.channel.pool.SimpleChannelPool.acquireHealthyFromPoolOrNew(SimpleChannelPool.java:152)
    at io.netty.channel.pool.SimpleChannelPool.acquire(SimpleChannelPool.java:112)
... [Log Snipped] ...
    at io.netty.channel.pool.SimpleChannelPool.doHealthCheck(SimpleChannelPool.java:170)
    at io.netty.channel.pool.SimpleChannelPool.acquireHealthyFromPoolOrNew(SimpleChannelPool.java:142)
```

[Link: Full exception log without cuts]

It looks like there are possible several problems that could lead to such stacktrace, but at least one is: SimpleChannelPool#acquireHealthyFromPoolOrNew:

```
       catch (Throwable cause) {
            promise.setFailure(cause);
        }
```

which executes on each level from the bottom and each level throws the same IllegalStateException to the top level. On the same time, it's unclear which code set result to Promise (StackOverflowError from too large recursion pooling -> checking looks like).

One more idea: maybe it's worth to make reasonable (maybe configurable) limitation for recursion here.
