Title

Macro parameterized State types cause arcane scoping errors

Description
Happens on 0.4.0-rc.1 and master.

[Link: See this example program.]

Normally you can generate routes in macros just fine, but if you make the type parameter of a state guard a macro parameter compilation fails with really arcane error messages about scoping issues on internal types such as " cannot find `__req` in this scope"  and "cannot find `__data` in this scope "

To reproduce simply define any route in a macro and parameterize the type of a State guard:

```
macro_rules! foo {
    ($type:ty) => {
        #[get("/")]
        fn index(thing: rocket::State ) -> String {
            format!("Thing: {:?}", *thing)
        }
    }
}
```
@jebrosen on IRC has a tentative patch and is way more knowledgeable on the internals of how Rocket expands its spanned quotes that cause this.
Discussion
- This patch fixes the test case and passes the existing test suite. At least these functions in the same file probably need similar modifications: `data_expr` (`__req`, `__data`), `query_exprs` (`__trail`, `__data`). Additionally, tests like @Korvox's should be added to guarantee that all kinds of guards work from macros in this way. Any other macros such as `#[catch]` should probably be checked, too.
