Title

DefaultTuple and DefaultMemory understimate their memory footprint

Description
There are several places where we highly underestimate the memory footprint . For example, for map datatypes, we don't account for the per entry cost for the map container data structures. The estimated size of a tuple having map with 100 integer key-value entries , as per current version of code is 3260 bytes, while what is observed is around 6775 bytes .  To verify the memory footprint, i checked free memory before and after creating multiple instances of the object , using code on the lines of  [URL] .  

 In   PIG-1443   similar change was done to fix this for CHARARRAY .
Discussion
- This patch updates the memory size calculations . This changes were made so that the estimated sizes are closer to what is seen in 32 bit Java HotSpot(TM) Server VM (build 10.0-b19, mixed mode).  

 It is based on some of the observations in  [URL] .  The header sizes of objects has been taken to be 8 bytes. The objects size is rounded to multiple of 8 bytes. Some other adjustments for minimum size of array in a ArrayList were made based on observed size values.
