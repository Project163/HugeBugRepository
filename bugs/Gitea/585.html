## Description

When cloning a repository with slow bandwidth over https, gitea seems to timeout.
We noticed that because F-Droid fails to checkout repositories from codeberg.org, there is also a issue on Codeberg here: [URL]

This seems to affect try.gitea.io also. Timeouts seem to happen after a few minutes, but not always after the same time. We tried to increase git.timeout values on our test instance also, also accessed port 3000 directly without reverse proxy, without any effect.
```
$ sudo wondershaper enp0s31f6 4000 4000 # somehow values do not really matter, anything between 500-4000 had the same effect
```

Discussion
- Because the description is not clear on this: We reproduced with serving assets from Gitea public folder, too. [URL] is most likely related, too.
- We really need to see some logs from the gitea side of things.
- ... [Middle Discussions Snipped for Brevity] ...
- So I think there is some kind of function: the larger the blob to transfer and the slower the connection, the easier this will be hit. Remember I was running into this with 50KB/s transfer on a 100MB file after 5 seconds. I'd imagine that when you increase this to 60 seconds, but my transfer wouldn't have been finished, this would result in the same issue, but later (will try). With higher bandwidth but larger data, this should stay proportional.
- OK, let's do a heuristic adjustment.

Couple of ideas:

1. Simplest: Store the last deadline that we set 
    * Minimum deadline is Now()+ 5s
    * If previous deadline has not passed use it instead of now + 5s 
    * PROBLEMS: This could be lead to very very long timeouts - but I guess that is reasonable. 
    * There's also no depenedence on the size of slice being written or how much written just on how many times written
2. Take account of what's about to be written plus the last timeout
    * Minimum basic timeout is 5s 
    * Timeout: is 2.5s + 2s * len(towrite)/1024 + previous deadline if this is longer
3. Take account of the amount written:
    * Minimum basic timeout is 5s
    * Timeout: is 2s * len(towrite + written)/1024 + previous deadline
