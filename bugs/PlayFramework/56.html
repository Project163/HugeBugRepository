Title

Akka HTTP backend strips quotes out of link headers

Description
I'm not sure if this is a bug or not, but it is surprising behaviour.  If I do the following:

```scala
Ok.withHeaders("Link" -> """<[URL] rel="next"""")
```

The double quotes from around the `next` get stripped before it reaches the client, which receives the following header:

```
Link: <[URL] rel=next
```

Technically, this is compliant with [Link: RFC-5988], but it's odd that the server isn't sending what I'm telling it to send. If I have a non compliant client (which I do, it expects the quotes), it makes it impossible for me to send a link header that the client can parse. Fortunately in this case I control the client, but that might not always be the case.
