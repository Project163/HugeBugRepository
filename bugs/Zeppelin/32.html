Title

Websocket doesn't update the query

Description
When we use two web browsers on the same note, any change is transfered to the other. 

 However when we rerun a paragraph after changing the text editor content, the other browser only gets the new result (not the new text editor content)
Discussion
- I found what the problem was. 
Basically we set a dirtyText value when somebody type in the text editor, but we never release it when we run the query. 
Checking the code, I am actually wondering if that value is really necessary. 

 The text editor value do not change, however the result do change based on what the other web browser run as query. 
Even if it would be annoying to possibly change your text editor query while you type, it would be matching the query result. 
And allow the user to get the other user query (otherwise it would override when he runs it) 

 Any feedback?
- It was designed to be update code (text editor content), when 

   1. there is no local update 
  2. and remote browser updated code and run paragraph 

 Otherwise it is keeping it's content with dirty flag set. 
but it looks like the feature has broken.
- Yes, 

 But this look weird in that case: 

 User1 and User2 are on the same notebook and work on same paragraph. 

 
	 User1 change the query and run it 
	 User2 Was changing the query too, he receives the new results and his text editor do not change 
	 User2 can't get the updated query because its dirty, the only way would be to run his query, but in that case, it would update User1 result and text editor
