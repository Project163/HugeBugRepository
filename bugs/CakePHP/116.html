Title

3.0 Wierd behavior with matching and variables outside of callback functions scope

Description
### What i did

```
$query = $this->Articles
        ->find()
        ->matching('Tags', function($q) {
        return $q->where(['Tags.slug' => $tag]);
    });
```

With no "use" statement
### What happened

Fatal Error
Error: Call to undefined method Cake\Database\Driver\Mysql::_QueryTranslator()
File E:\xampp\htdocs\blog\vendor\cakephp\cakephp\src\Database\SqlDialectTrait.php
Line: 82

It was like $q parameter passed to function didn't have a _type assigned. I've debug to Database\Query->sql() (I've also noticed unised $sql = ''; :))

I'm not well known to clousures shouldn't it trigger a notice?
Discussion
- You need to bring the tag variable in with `use`. PHP closures do not automatically inherit closure variables. Your call should look like:

``` php
$query = $this->Articles
        ->find()
        ->matching('Tags', function($q) use ($tag) {
        return $q->where(['Tags.slug' => $tag]);
    });
```

I'll look into making the error in this situation better as a fatal error is not generally helpful.
- Taking a look at this, the error handlers are catching the undefined variable usage, however when trying to generate a stacktrace and the object context for each frame, the Query conversion fails as the query type is undefined. I'll get that fixed up.
- Closing as #3709 has been opened to fix this.
