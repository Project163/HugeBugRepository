Title

Worker thread hangs if response is not properly formed

Description
### What version of gRPC and what language are you using?
ruby, versions: 1.35, 1.26

### What operating system (Linux, Windows,...) and version?
Linux, MacOS

### What runtime / compiler are you using (e.g. python version or version of gcc)
ruby 2.5.8p224 (2020-03-31 revision 67882) [x86_64-darwin19]

### What did you do?
I returned non-serializable response from the request handler:
```
    def get_customer(_request, _call)
      true
    end
```
While this is clearly an application-level error which needs to be fixed, grpc library should handle it "more gracefully", since it can happen in some complex handlers. Also, due to the fact that it blocks the worker thread for 10 seconds, it can reduce availibity of entire gRPC server.

### What did you expect to see?
An UNKNOWN (or any other more suitable) error code returned to the client.

### What did you see instead?
Worker thread hanged for 10 seconds which resulted in DEADLINE_EXCEEDED error on client side.
