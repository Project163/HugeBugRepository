Title

3.0 - Dump autoloader command not comaptible with the regular Windows CLI

Description
Currently the command for executing composer to dump the autoloader (https://github.com/cakephp/cakephp/blob/ /src/Shell/Task/PluginTask.php#L267-L268) uses a `;` to separate the `cd` and `php` commands, however this isn't supported on the regular Windows CLI, only Powershell supports it.

The Windows equivalent to `;` would be `&`, which in turn doesn't work in Powershell , but I'm pretty sure most people with Windows dev environments are using the regular shell. `&&` would work too, however I'm note sure whether the path can be expected to always be an absolute one, ie whether the `cd` command can be expected to not fail.
Discussion
- Calling chdir and executing one command is one way around that.
- Really people still use regular shell? I thought powershell was the future of terminal on windows.
- I'm not the hub of the world, but I don't know anyone who's using the Powershell :) And I can understand that, it doesn't really offer any advantage over the regular CLI when you're not using it for fancy scripting.

Anyways, I guess I've phrased this very misleading, `;` is supported by Powershell, but it won't even work in Powershell when the command is finally run via PHP, so basically autoloader dumping is generally broken on Windows :)
