Title

Containers that never have children stay forever

Description
ContainerManager  does not delete containers whose cversion is zero to avoid situations where a container would be deleted before the application had the chance to create children. 

 This caused issues in our application where the process stopped between container creation and child creation: the containers were never deleted. 

 To avoid this while giving applications the time to create children, empty containers with a cversion of zero should be deleted after a grace period, e.g. not when they are first collected, but the second time.
Discussion
- I understand from the discussion that this is a feature rather than an unwanted side effect of giving time for application to create childrens, and I won't dispute that. 

 What led to reporting this is a problem we encountered when using Curator's  PersistentTtlNode  that creates a container and adds a child to it, but doesn't do it as a transaction. 

 So I'll address this issue in Curator.
- I believe this should be solved in the server. I have an idea for a backward compatible way of handling this. PR coming soon.
