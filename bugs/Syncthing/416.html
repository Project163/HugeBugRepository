Title

When adding ignores at folder creation time, .stignore file can't be created

Description
When creating a folder share, specified Ignore Patterns won't save unless the _path/.stignore_ yet exists.
Since #3608 the Ignore Patterns button logic is OK (grayed when no path is given), but if it is not possible to create the full path to .stignore on create, then the button should not even show (or remain grayed) as long as the folder share is not created (then needing to re-open/edit the folder share to set Ignores, allowing to drop synching selected Ignores... and go to the directory tree to do some clean-up)
Discussion
- Confirmed. When adding a new folder, filling out a path, clicking "edit ignores", clicking save, clicking save, the following happens:

[Image: img_0103]

This should be fixed before 0.14.27 release
- Also a big thanks from me for uncovering this!

The problem is not that .stignore is not existing, but that the directory does not yet exist. If you create a new folder in a directory without .stignore everything works fine.
The error happens here:
[URL]

Two possible solutions:
When a folder is added check whether the directory exists and create it no matter whether the folder is paused or not.
Check whether the directory exists in `ignore.WriteIgnore` and create it if it doesn't.
