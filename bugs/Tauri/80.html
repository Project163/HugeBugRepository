Title

Target triple mismatch

Description
### **Describe the bug**
The recently updated documentation provides a code snippet that automatically appends the target triple to a binary. I noticed, however that there is a mismatch between the llvm target triple and the rust target triple.
I suspect this mismatch is also present for different platforms, but in my case it is as follows:
LLVM target triple:
`x86_64-apple-macosx10.7.0`
rust target triple:
`x86_64-apple-darwin`

### **To Reproduce**
Steps to reproduce the behavior:
1. Use the script provided in the docs to rename you sidecar binary
2. Call it from rust using Command::new_sidecar
3. The thread panics

### **Expected behavior**
The generated sidecar name should match the one expected by Tauri at runtime.

### **Platform and Versions (required):**
 
```
Operating System - Mac OS, version 11.4.0 X64

Node.js environment
  Node.js - 16.0.0
  @tauri-apps/cli - 1.0.0-beta.1
... [Log Snipped] ...
devPath - [URL]
framework - React
```
Discussion
- I can confirm, this happened to me as well.
- Seems like we should use [Link: `rustc -vV`] instead.
