Title

Channel.isWritable() does not work when SslHandler is used

Description
`SslHandler` queues pending writes until the user call `flush()` , because of this nothing is passed through to the `ChannelOutboundBuffer`. This means the pendingOutboundBytes are not updated and so `Channel.isWritable()` will not change. This is bad as it means that the user has no way to know if he/she uses to much memory.

There are two ways to fix it:
 1) Make `ChannelOutboundBuffer.increase/decreaseOutboundBytes(...)` public and trigger it in `SslHandler`
 2) Add a "proper" `PendingWritesQueue` to the `io.netty.channel` package and use this in `SslHandler`. This way we could keep the method package private.

I kind of prefer 2) as it would also allow a user to re-use it without care too much about implementation details.
