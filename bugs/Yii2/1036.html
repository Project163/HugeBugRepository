Title

MSSQL migration alterColumn on a column with default value NULL creates wrong CONSTRAINT

Description
### What steps will reproduce the problem?
On MS SQL SERVER (test on 2017 and 2019)
Creating a migration with alterColumn on a column with default value = NULL

When a migration is created with
$this->alterColumn('table','column',$this->integer()->null()->defaultValue(NULL));

even string() or even using:
$this->alterColumn('table','column',$this->string(30).' NULL DEFAULT NULL');

### What is the expected result?
Migration creates a DEFAULT RUL similar to this one:
ALTER TABLE [dbo].[table] ADD  DEFAULT (NULL) FOR [column]

### What do you get instead?
ALTER TABLE [dbo].[table] ADD  CONSTRAINT [DF_table_column]  DEFAULT ('NULL') FOR [column];

### Additional info
This leads to errors if the field is not initialized on the SAVE operation.

It does not happen during a createTable()

$this->createTable('{{%test}}',[
