Title

if commit is called inside the onMessage method we don't send a messageAccept for that message

Description
If a commt is called inside onMessage method in the MessageListener we don't send a messageAccept. 
Since the messageAccept is not sent, the broker will not dequeue the message upon receipt of the commit. 

 The reason for this is bcos we keep track of the _txSize and _txRangeSet in the addDeliveredMessage method. 
This method is called from postDeliver method which is called only after the onMessage method returns. 
Therefore if you call commit inside onMessage these 2 variable are not updated properly, resulting in not sending the proper messageAccepts before the commit.
Discussion
- Arnaud has fixed this issue in rev 673074 on trunk.
