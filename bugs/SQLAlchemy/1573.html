Title

Invalid SQL emitted using aliased() and two tables with the same name in different schemas

Description
### Describe the bug

If two tables exist with the same name, one in the default database schema and the other in a custom schema, a `SELECT` statement querying both and using `aliased()` on one of them can sometimes cause SQLAlchemy 2.x to emit two `AS ...` clauses in a row, which is not valid SQL syntax.

MCVE:

```
python
from sqlalchemy import select
from sqlalchemy.orm import DeclarativeBase, aliased, mapped_column, Mapped

class Base(DeclarativeBase):
... [Log Snipped] ...
stmt = select(OtherFoo, aliased(Foo))
print(stmt.compile())
```

Output:

```sql
SELECT other.foo.b, foo_1.a
FROM other.foo, foo AS foo_2 AS foo_1
```

Some notes:

- Reproducible in 2.0.0 through 2.0.39
- Not easily reproductible in 1.4.x
- Inverting tables order in `select` has no impact ❌
- Using `flat` or `adapt_on_names` options in `aliased` has no impact ❌
- If one of the tables appear later in the query (eg. `select(aliased(Foo)).join(OtherFoo, true())`), the same bug occurs ❌
- If not using aliased tables (`select(Foo, OtherFoo)`), it works as expected ✅
- If the non-public table is the one aliased (`select(Foo, aliased(OtherFoo))`), it works as expected ✅
- If both tables are aliased (`select(aliased(Foo), aliased(OtherFoo))`), it works as expected ✅
- If explicitly specifying `__table_args__ = {"schema": "public"}` in `Foo`, it works as expected ✅ _(emits `public.foo` instead of `foo`)_

Thanks!
