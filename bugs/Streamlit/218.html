Title

`st.file_uploader` callback is called twice on each upload, after the first upload

Description
### Summary

The file uploader's `on_change` callback works as intended on the first upload. Each subsequent upload triggers the callback twice.

### Steps to reproduce

- Run the below app and keep open the browser window and terminal window side-by-side
- Upload a file to `st.file_uploader`
- In the terminal, observe the callback result `Uploaded file #1`
- Upload a second file
- In the terminal, observe the callback executed twice and prints `Uploaded file #2 \n Uploaded file #3` instead of just `Uploaded file #2`

Code snippet:

[Link: [Image: Open in Streamlit Cloud]]

```
import streamlit as st

if 'ctr' not in st.session_state:
    st.session_state['ctr'] = 0

... [Log Snipped] ...

st.file_uploader(label="File uploader", on_change=uploader_callback, key="file_uploader")
```

**Expected behavior:**

On each upload to `st.file_uploader`, the callback passed to `on_change` should execute just once.

**Actual behavior:**

On each subsequent upload after the first upload, the `on_change` callback is called twice. My understanding is that uploading a new file also clears the existing file, triggering another callback execution. In that sense, this behavior might be a feature, not a bug. Nonetheless, this behavior can be confusing and unintuitive.

[Image: fileuploader-callback-bug]

### Is this a regression?

No. This bug was [Link: reported on the forum] as far back as Streamlit v1.3.0

- @kajarenc , is this a feature?
- @snehankekre yes, it works exactly as you described, a first callback call is for removing a file, and a second one for uploading a new one, according to how the widget logic is written. 

We can have multiple solutions to fix this:
1) Try to rewrite widget logic to distinguish between "file_removed"->"new file uploaded", and "new file uploaded that should trigger old file removal first" situations. 
2) Disallow file uploads for single file uploader, when file already uploaded on front-end. 

I think the second option is easier to implement (just disallow uploading a new file for a single file uploader when a file has already been uploaded), although it is more Product decision. 


In a situation, where you need to trigger the on_change callback for a single file uploader only when a new file is uploaded (I think that could be a popular usage and intention of your code snippet), you can filter "remove" events, by accessing file uploader session_state itself. 

```
import streamlit as st

if 'ctr' not in st.session_state:
    st.session_state['ctr'] = 0

... [Log Snipped] ...

st.file_uploader(label="File uploader", on_change=uploader_callback, key="file_uploader")
```
