Title

New config file plugin/extends resolution not working with node.js API and `configFile` option

Description
The file resolution for the `plugin` and `extends` options works differently in eslint 2.0.0.

`standard` 6.0.0 is using `eslint` 2.0.0-rc.0 and the `configFile` option to the node.js API. [Link: The code] looks roughly like this:

``` js
var CLIEngine = require("eslint").CLIEngine
var cli = new CLIEngine({ configFile: path.join(__dirname, 'rc', '.eslintrc') })
```

This `.eslintrc` file contains:

``` json
{
  "extends": ["standard", "standard-jsx"]
}
```

The `eslint-config-standard` and `eslint-config-standard-jsx` packages are dependencies of the `standard` package, of course. 

The problem is that when users install `standard` as a dependency of their own project and run it, they get the following error:

```
Error: Cannot find module 'eslint-config-standard-jsx' from '/home/travis/build/matjaz/stdin2'
Referenced from: /home/travis/build/matjaz/stdin2/node_modules/standard/rc/.eslintrc
    at Function.module.exports [as sync] (/home/travis/build/matjaz/stdin2/node_modules/standard/node_modules/eslint/node_modules/resolve/lib/sync.js:33:11)
    at resolve (/home/travis/build/matjaz/stdin2/node_modules/standard/node_modules/eslint/lib/config/config-file.js:393:38)
    at load (/home/travis/build/matjaz/stdin2/node_modules/standard/node_modules/eslint/lib/config/config-file.js:412:24)
... [Log Snipped] ...
    at new Config (/home/travis/build/matjaz/stdin2/node_modules/standard/node_modules/eslint/lib/config.js:192:38)
    at CLIEngine.executeOnFiles (/home/travis/build/matjaz/stdin2/node_modules/standard/node_modules/eslint/lib/cli-engine.js:492:28)
```

It seems that the `process.cwd()` is being used as starting point for the search, instead of the config file's folder.

Perhaps the `relativeTo` argument is not being passed to the `resolve` function [Link: in this code]?

In any case, this affected `standard` [Link: recently] and required [Link: this hack] to workaround. Hoping we can figure out a real fix to this.
