Title

[DocDB] PgTablesQueryResult could be overwritten by the previous request

Description
Jira Link: [Link: DB-17621]
### Description

When postgres table cache is requested, the object to store result is passed to the cache.
If request contains multiple tables, but some table is failed to resolve, then whole cache request is finished with failure status for this table.
When shared memory is used to execute Perform request the result object is allocated on the stack.
Since stack is the same for this scenario, all result objects corresponding to the same postgres process are located at the same address.
So we could get into situation when the first request is failed and completed.
But there are could be pending resolutions for other tables.
Then postgres sends a new request, that will allocate result at the same address.
As result resolutions from the previous request will work with result from previous request, writing wrong data there.

When shared memory is not used, this bug does not happen, since result object is allocated and retained by the query object.
And query object is retained as listener by running queries for other tables.
