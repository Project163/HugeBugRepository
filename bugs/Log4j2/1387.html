Title

TimeFilter does not handle daylight saving time transitions

Description
The TimeFilter unit test failed miserably on March 8 which was the beginning of daylight saving time. Looking at the code for the TimeFilter and the tests both were overly simplistic and not testing for things like setting a start time in one day with the end time in the next or having the time range overlap the daylight saving time transitions in the spring and fall.
Discussion
- The fix for this uses java.time. The java.time classes are explicitly not garbage free - almost every operation creates a new immutable object.  I will try to retrofit this using Calendar but that is going to be hard.
- I cannot determine how to get Calendar to differentiate between the overlapping hours during the change from daylight saving time to standard time.
- Fix applied
