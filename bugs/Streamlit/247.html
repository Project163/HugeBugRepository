The exact same configuration (i.e. copying the file tree including the python environment) works fine on the us version of Windows. I suspect that it might be somehow related to [Link: this]. With the new evidence I am wondering whether reading the file itself [Link: here] is the issue or guessing the mimetype [Link: here].
What you could try it is modify that path locally in the installed Streamlit package and, for example, hard-code the mimetype to the correct one to see whether that would work and/or add the `encoding='utf8'` argument to the `with open` [Link: call] and then restart Streamlit. - It turns out that it was completely unrelated to the os being korean. A registry entry set the mime-type of javascript files to `text/plain` causing the browser to refuse execution. I did some research and came up with a solution. I will open a PR soon that avoids this issue (which apparently is not uncommon for windows systems).
