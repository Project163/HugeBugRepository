Title

CollectionsAPIDistributedZkTest.testCreateShouldFailOnExistingCore fails consistently

Description
CollectionsAPIDistributedZkTest.testCreateShouldFailOnExistingCore  has been failing consistently since the new year:  

  [URL]

 This is possibly connected to   SOLR-15209  , but regardless the test shouldn't rely on the numbering of replicas based on shard/node.
Discussion
- The test fails, because it expects that the replica for shard 1 that gets created at the end will always be called:  halfcollection_shard1_replica_n1  

 However sometimes the replica for shard 2 is called "halfcollection_shard2_replica_n1" and the replica for shard 1 is called "halfcollection_shard1_replica_n2", resulting in the test failing. 

 There is no reason to create 2 shards in the end anyways, 1 shard is enough to cause the test to fail reliably.
