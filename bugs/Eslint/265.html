Title

Clash between defaultParams and comma-spacing

Description
If I have an argument with a default param and another argument after it, comma-spacing throws an inaccudate error. Here's a simple example:

test.json

```
json
{
    "ecmaFeatures": {
        "defaultParams": true
    },
... [Log Snipped] ...
    }
}
```

test.js

``` js
'use strict';

function foo(bar = 1, baz = 2) {
    return bar + baz;
}

foo();
```

CLI

``` bash
 % eslint --c test.json test.js

test.js
  3:22  error  There should be no space before ','  comma-spacing

✖ 1 problem (1 error, 0 warnings)
```
Discussion
- I dont think this scenarios is accounted for. Possibly a bug.
- Yeah, comma spacing is a beast of a feature, I'm not surprised that we'd run into an issue with default parameters.
