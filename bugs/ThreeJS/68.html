Title

Faces Sharing UVs

Description
`webgl_materials_video.html` is broken in r.60 because the two `Face3`s of each `CubeGeometry` face share some UVs.

```
scope.faceVertexUvs[ 0 ].push( [ uva, uvb, uvd ] );
...
scope.faceVertexUvs[ 0 ].push( [ uvb, uvc, uvd ] ); // uvb & uvd are shared
```

Perhaps `uvb` and `uvd` should be cloned.

If sharing UVs is OK, then `webgl_materials_video.html` will have to be changed.

If sharing UVs is not OK, then all geometries will have to be checked for this bug.

Are shared UVs a problem?

- I think @mrdoob may have misunderstood my statement. Maybe I should have made myself more clear.

`webgl_materials_video.html` was broken in r.60 because the two `Face3s` of each `CubeGeometry` face shared some UVs -- _and when the demo code changed the UVs of one face, it consequently also changed the UVs of another face_.

I do not see anything, in principle, incorrect in sharing UVs, but for consistency, I feel more comfortable not doing so.
- If you want to share UVs you're free to do so. But by default UVs shouldn't be shared. It just creates problems like the video example.
