Title

cte() and subquery() should not be Executable

Description
**Describe the bug**
 
When using `sqlalchemy.literal` in a CTE with SQLite3, sqlite3 module complains about incorrect number of bindings.
However, without using a CTE everything will work just fine.
```python
import sqlalchemy


engine = sqlalchemy.create_engine("sqlite://")
literal = sqlalchemy.literal(1)  # DEMO
cte = sqlalchemy.select([literal]).cte()  # (1)
engine.execute(cte)  #=> Error
```

If I comment the line marked as `(1)` out, no error will occur and the result `[(1,)]` is returned, which is expected.
However, with line `(1)`, an error is raised.

to fix your application ensure you execute a SELECT statement:
```
with engine.connect() as conn:
    conn.execute(cte.select())

```
- in 1.3 this has the bizarre behavior of invoking a blank string as a statement.    however CTE and subquery() aren't executable and this should raise an error.   the non-workingness of CTE in 1.3 indicates this is safe for a straight change in 1.4, but invoking a subquery in 1.3 seems to invoke the inner SELECT, so not sure if that one is as safe.
