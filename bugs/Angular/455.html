Title

Ban H1 elements (or single #) in document content

Description
Some documents like [Link: animation.md - see the "Contents" header] contain H1 headers which mess up UI and in the future also TOC generation.

It would be great to catch these errors in dgeni and fail a build if such errors are introduced.
Discussion
- It's a bit more tricky than that because we actually do want up to one h1 in a document. This is then used for the `title` property, which prevents the need for the `@title` tag in most cases. It also is crucial for supporting special cases like the home page and the 404 page.

For sure we could complain if there was more than one h1; and even if the title had been provided and there was also a h1.
- that would be sufficient.
- FWIW, Animations no longer has multiple H1s
