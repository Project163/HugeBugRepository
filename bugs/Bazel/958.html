Title

C++ shared libraries generated on OSX get file extension .so instead of .dylib

Description
# Description of the problem / feature request:

`cc_library` rule with `name = 'foo` and `linkstatic=False` attribute generates a shared library. 
On Linux the library is named `libfoo.so` - correct.
On Windows the library is named `foo.dll` - correct.
On MacOS the library is named `libfoo.so` - incorrect! It should be `libfoo.dylib`

### Bugs: what's the simplest, easiest way to reproduce this bug? Please provide a minimal example if possible.

Here is the repo with the minimal example: [URL]
Clone it and build it on Mac. You get libbase_shared.so in the output, instead of libbase_shared.dylib

### What operating system are you running Bazel on?

MacOS 10.16

### What's the output of `bazel info release`?

2.2.0
