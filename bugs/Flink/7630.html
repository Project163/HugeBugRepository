Discussion
- becket_qin  can you have a look at this? On more general terms, the community agreed on not adding timeouts to the unit tests. If a test runs into a deadlock, Flink's CI would produce a thread dump in the end that might help with the root cause analysis. Adding a @Timeout to the test prevents us from getting this thread dump.
- Opened a PR to remove the timeout first:  [URL]
- Thanks  showuon  and  mapohl  . I was trying to reproduce the issue by removing the timeout and set the close timeout to Long.MAX_VALUE. I did not see a failure in over 30K runs. But it looks like some test run can take a bit longer than other runs. At this point, it looks like this is more of a flaky test instead of real issue.
