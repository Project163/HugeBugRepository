Title

ORM forgets attribute after lazy loading relationship (and emits a spurious COMMIT)

Description
**Describe the bug**
I found a bug (or 2?) with sqlalchemy 1.4.6 that happens when lazy loading a relationship.
It seems that the lazy loading will wipe an attribute on the model that I just set, and it will also emit a COMMIT statement without a reason to.
SQLAlchemy 1.3.19 instead works as expected.

**Expected behavior**
A COMMIT statement should not be issued when accessing a relationship, and the attribute should stay as set before.

**To Reproduce**
```
python3
from sqlalchemy import *
from sqlalchemy.ext.declarative import declarative_base
from sqlalchemy.orm import relationship, sessionmaker

... [Log Snipped] ...
foo.bar  # Triggers COMMIT and resets `foo.important_attribute` to None
assert foo.important_attribute == "something_important"  # AssertionError: foo.important_attribute is None
```

**Error**

```
2021-04-09 15:52:23,915 INFO sqlalchemy.engine.Engine BEGIN (implicit)
2021-04-09 15:52:23,916 INFO sqlalchemy.engine.Engine PRAGMA main.table_info("foo")
2021-04-09 15:52:23,916 INFO sqlalchemy.engine.Engine [raw sql] ()
2021-04-09 15:52:23,917 INFO sqlalchemy.engine.Engine PRAGMA temp.table_info("foo")
2021-04-09 15:52:23,917 INFO sqlalchemy.engine.Engine [raw sql] ()
... [Log Snipped] ...
    assert foo.important_attribute == "something_important"  # AssertionError: foo.important_attribute is None
AssertionError
```

**Versions.**
 - OS: macOS 11.2.1
 - Python: 3.6.12
 - SQLAlchemy: 1.4.6
 - Database: MySQL, sqlite (probably all)
 - DBAPI: mysqlclient, sqlite3
