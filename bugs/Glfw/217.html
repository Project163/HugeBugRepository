Title

Monitor/Window ContentScale below 1.0?

Description
My content scale on Linux / KDE desktop is set to 1.0, however, using GLFW3, my application gets reported 0.72, and that makes my font sizes on my apps look smaller than other apps.

Why is GLFW reporting smaller content scales, IoW: what could I do to counter-measure this, if it's not a bug in GLFW but on my end (however, I couldn't find anything in the docs helping me out here).
Discussion
- What is the output of `xprop -root | grep -o 'Xft.dpi[^n]*'` on your machine?
- Hey @elmindreda , thx for your reply. Sadly the above command won't yield anything, as thre is no `Xft.dpi` substring in the output.

So I'll give you the whole part:

```
_NET_WM_USER_TIME(CARDINAL) = 3029632
_NET_WM_ICON_NAME(UTF8_STRING) = 
_KDE_NET_WM_DESKTOP_FILE(UTF8_STRING) = "org.kde.kwin"
PULSE_COOKIE(STRING) = " "
PULSE_SERVER(STRING) = "{ }unix:/run/user/1000/pulse/native"
... [Log Snipped] ...
XFree86_VT(INTEGER) = 1
Xorg_Seat(STRING) = "seat0"
```

While this is the output when setting the scale to 1.0, the following I'll get when scale is set to 1.1:

```
RESOURCE_MANAGER(STRING) = "Xft.dpi:\t106\n"
```

Whereas the next one is for scale = `1.5`:

```
RESOURCE_MANAGER(STRING) = "Xft.dpi:\t144\n"
```
The way to set the content scaling used was simply to go to KDE's system settings -> Hardware -> Display and Monitor -> Scale.

## EDIT:

a little post-note: When changing scaling to 1.1, 1.2, 1.5, my GLFW3 app properly reports window and content scale of 1.1, 1.2, and 1.5. It's just 1.0 that doesn't seem to be working (from my point of view).
