Title

Invalid PossiblyNullArgument when using @list()

Description
Consider:
[URL]
```
/**
 * @param string $string
 * @return array
 */
function _parse($string): array
... [Log Snipped] ...
  return [$part1, $part2];
}
```
```
Psalm output (using commit c60cafb):

No issues!
```

vs
[URL]
```
/**
 * @param string $string
 * @return array
 */
function _parse($string): array
... [Log Snipped] ...
  return [$part1, $part2];
}
```
```
Psalm output (using commit c60cafb):

ERROR: PossiblyNullArgument - 10:17 - Argument 1 of trim cannot be null, possibly null value provided
```
A lot of our legacy code is using @ in this case:  `@list($x, $y, $z) = explode($s);`
This way $x is guaranteed not null, and the rest of the variables can be null. We know that using @ is not good, but there are a lot of these cases that would require unsafe refactoring.

It's a bit weird that @ affects whether the error is reported or not.
Discussion
- I disagree - I think `@` indicates intentionality, the chance that the list items are possibly null.
- Why doesn't Psalm treat `explode()` results as array of nullable strings? I think it could have caught errors like this: [URL] if it did.
- ... [Middle Discussions Snipped for Brevity] ...
- Oh, Psalm actually does know that about `explode` - that, with no other args, the first element is always set
- Which is to make clear, this issue is now fixed
