Title

Possible BC break in ExistValidator

Description
### What steps will reproduce the problem?

[URL]


Upgrade Yii 2.0.10 =>  

```
php
/**
 * @property integer $foo_id
 */
class A extends ActiveRecord {
... [Log Snipped] ...
    }
}
```

So, `B::foo_id == A::foo_id` and `B::a_id == A::id`

A:

id | foo_id
-- | --
42 | 997

```
php
$b = new B();
$b->foo_id = 997;
$b->a_id = 42;

... [Log Snipped] ...
    throw ...;
}
```

### What is the expected result?

```mysql
SELECT EXISTS(SELECT * FROM `a` WHERE (`id`=42) AND (`foo_id`=997))
```

Validation passed.

### What do you get instead?

```mysql
SELECT EXISTS(SELECT * FROM `a` WHERE (`id`=42) AND (`foo_id`=42))
```

Validation failed: `Attribute "a_id" is incorrect`.

### Additional info

Fix code as such:

```diff
- [['a_id'], 'exist', 'targetClass' => A::class, 'targetAttribute' => ['a_id' => 'id', 'foo_id']]
+ [['a_id'], 'exist', 'targetClass' => A::class, 'targetAttribute' => ['a_id' => 'id', 'foo_id' => 'foo_id']]
```

| Q                | A
| ---------------- | ---
| Yii version      |  
| PHP version      | 7.0.13
| Operating system | Ubuntu 16.04
Discussion
- This has been breaking many of our tests as we use a convention where primary and foreign keys match (primary key of `user` table would be `user_id`, the foreign key in `vehicle` table would be `user_id`).

The issue is caused by this line:
[URL]

So, if you are depending on multiple foreign columns for one `exist` rule validation, a workaround is to just pass all target columns as an associative array. 

Replace:
```'targetAttribute' => ['a_id' => 'id', 'foo_id']```

with:
```'targetAttribute' => ['a_id' => 'id', 'foo_id' => 'foo_id']```

Until fixed or rolled back...
- we will ship a hotfix release for this within the next 24h.
