Title

Quarkus hot reload fails on absent test folder and/or test class in Continuous Testing mode

Description
### Describe the bug

In a multi Maven module project where a dependee project lacks the test/java folder and/or at least one test class the hot code reload stops working in the Test Runner Thread after throwing an exception, when running in Continuous Testing mode:

[Image: quarkus_NoSuchElementException]

Tests are executing fine when just running using e.g.: `mvn test`. 

### Expected behavior

If a test folder and at least one test class are in fact required in all dependee projects / modules for Continuous Testing to work (I could not find this requirement documented anywhere) I would expect a warning and possible that the module is ignored for hot code reload.

### Actual behavior

When running the tests the first time (hitting r after Quakus dev mode started up) two exceptions are thrown after a little time:

```
2021-07-19 09:30:52,299 INFO  [io.quarkus] (Quarkus Main Thread) Installed features: [cdi, resteasy, resteasy-jackson, smallrye-context-propagation]
Exception in thread "Test Compile Timer"
                                        java.util.NoSuchElementException: No value present
        at java.base/java.util.Optional.get(Optional.java:141)
        at io.quarkus.deployment.dev.RuntimeUpdatesProcessor.lambda$periodicTestCompile$1(RuntimeUpdatesProcessor.java:250)
... [Log Snipped] ...
        at io.quarkus.deployment.dev.testing.TestRunner$1.run(TestRunner.java:126)
        at java.base/java.lang.Thread.run(Thread.java:832)
```

Tests are still run, but hot code replacement no longer works ie. changes to application and test code is not discovered by the Quarkus runtime.

Using the attached reproducer project.

- quarkus_ct_issue (root pom)
  - with_test_folder (vanilla java)
  - without_test_folder (vanilla java)
  - service (Quarkus RestEasy Service project)

_service_ depends on _with_test_folder_ and _without_test_folder_
