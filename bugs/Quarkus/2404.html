Title

Conflict when using quarkus-kafka-messaging and quarkus-spring-di

Description
When I am using quarkus-kafka-messaging and quarkus-spring-di dependencies I am getting the following error:

```shell
Caused by: io.quarkus.builder.BuildException: Build failure: Build failed due to errors
        [error]: Build step io.quarkus.arc.deployment.ArcProcessor#registerBeans threw an exception: jakarta.enterprise.inject.spi.DefinitionException: Bean class dev.matheuscruz.quarkusclub.product.ProductConsumer declares multiple scope type annotations: jakarta.enterprise.context.Dependent, jakarta.inject.Singleton
```

It happens with the following code:

```
java
package dev.matheuscruz.quarkusclub.product;

import org.eclipse.microprofile.reactive.messaging.Incoming;
import org.slf4j.Logger;
... [Log Snipped] ...
    }
}
```

I think we have conflict between `@Dependent` generated by **quarkus-kafka-messaging** and `@Singleton` generated by **quarkus-spring-di**.
Discussion
- Both extensions should verify if there are any scope annotations or pseudo-scope annotations already defined on the class. 

@mkouba, do you know how we can "collect" all scope and pseudo-scope annotations? Or should we have a list of the known annotations?
- I'm testing a fix, I think the spring-di extension can produce `CustomScopeBuildItem` and it'll be picked up by reactive-messaging extension.
- @cescoffier @ozangunalp The `CustomScopeAnnotationsBuildItem` _"Holds information about all known custom scopes in the deployment and has utility methods allowing to check whether given class has some scope annotation."_

HTH
