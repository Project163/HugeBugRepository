Title

Call to custom PostgreSQL function breaks in 1.4 due to failed caching

Description
**Describe the bug**
With version 1.4.1, a call to a user-defined PostgreSQL function through the `sqlalchemy.func` machinery raises an exception before execution due to a cache check

**Expected behavior**
The call should succeed and return results, as it does with version 1.3.x.

**To Reproduce**
Given a user-defined function `get_inflation_curve_id` in schema `infl`, the following code throws.
(You don't actually need the function to reproduce: the exception is raised before reaching the DB.)

```
py
import sqlalchemy as sa
from sqlalchemy.orm import Session

engine = sa.create_engine(uri)
... [Log Snipped] ...

results = session.execute(query).fetchall()
```

**Error**
The inner machinery looks for a cached query, but the key is unhashable causing `dict.get` to throw:

```
---------------------------------------------------------------------------
TypeError                                 Traceback (most recent call last)
  in  
      7 query = sa.select(["*"]).select_from(sa.func.infl.get_inflation_curve_id("UKRPI", "bond"))
      8 
... [Log Snipped] ...

TypeError: unhashable type: 'list'
```

Debugging the code show the following value for `key`:
```
( >,
 ('0',  , '_raw_columns',
 (('1',  , 'name', '*', 'type',
 ( ,), 'is_literal', True),), '_from_obj',
 (('2',  , 'clause_expr',
... [Log Snipped] ...
 '_label_style', symbol('LABEL_STYLE_DISAMBIGUATE_ONLY'), '_compile_options',
 ( , ())), (), False, False)
```
which contains the list `['infl']`.

**Versions.**
 - OS: Debian 10 docker image
 - Python: 3.7.4
 - SQLAlchemy: 1.4.1
 - Database: PostgreSQL 11.8
 - DBAPI: ?
