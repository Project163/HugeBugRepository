Title

WS-RM should not include Offer in CreateSequence for oneway endpoint

Description
WS-RM only uses the Source policy to determine whether an Offer element is included in a CreateSequence. It should also check if the application message exchange is oneway, since Offer makes no sense for oneway exchanges.
Discussion
- Fixed by commit  [URL]
- Hi Dennis, 
we have an issue with this change (discussed in users@cxf and dev@cxf) 
 [URL]

 As a service may have multiple operations with different MEPs, we cannot determine from the first operation if the offered sequence will be needed for this sequence later when invoking other operations over this sequence. 

 I think we should go back to the old behavior. 

 regards, aki
- Yes, that makes sense. 

 This came up in the context of interoperability testing with WCF. A WCF client doesn't include an Offer in the CreateSequence for a service that only defines oneway-in operations, but it probably doesn't hurt anything to include the Offer when we're the client. A WCF service appears to just ignore the Offer in this case, but with   CXF-5725   fixed we should be fine with that. 

 I'll revert this change.
