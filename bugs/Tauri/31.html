Title

yarn tauri init fails on Ubuntu with (node:581958) UnhandledPromiseRejectionWarning: TypeError: Cannot read property '1' of null

Description
**Describe the bug**
I'm setting up on Ubuntu 20.04 and already had Rust/Cargo/Yarn/nvm installed. 

Following the getting started for Linux at tauri.studio all is well until `yarn tauri init` which gives the following error. I wonder if it is to do with node version as I've seen things fail at this point, but tauri didn't specify which version it uses. So I tried node v10 and v12, both fail with:

```
$ yarn tauri init 
yarn run v1.22.4
$ /home/mrh/src/tauri/tauri-test/node_modules/.bin/tauri init
[tauri]: running init
? What is your app name? Tauri Test
... [Log Snipped] ...
(node:583252) [DEP0018] DeprecationWarning: Unhandled promise rejections are deprecated. In the future, promise rejections that are not handled will terminate the Node.js process with a non-zero exit code.
Done in 13.98s.
```

**To Reproduce**
```
sudo apt update && sudo apt install libwebkit2gtk-4.0-dev \
    build-essential \
    curl \
    libssl-dev \
    appmenu-gtk3-module \
... [Log Snipped] ...
yarn add tauri
yarn tauri init
```

**Platform and Versions (please complete the following information):**
 
OS: Ubunto 20.04
Node: v12.16.3 (same result with v10.19.0)
NPM: n/a
Yarn: 1.22.4
Rustc: 1.46.0
Discussion
- I didn't have `npm` installed and had skipped the following because I already had set up `node` with `nvm`. When I inspected the line where the error is I saw it using `npm`. The following has fixed this issue:
```
nvm install node --latest-npm
nvm use node
```

I think this is an edge case few will hit, but given the Tauri team ecourage people to use `yarn`, someone like myself who already prefers `yarn` may well not have `npm` installed, particularly on a recently set-up machine. That was my issue.

So maybe tauri init should check for existance of programs it uses such as `npm`? I'll leave this open to register that question, but feel free to close.
- Well I never would've thought of a node user without npm, but that actually makes sense given how bad it is LOL thanks for the report!
