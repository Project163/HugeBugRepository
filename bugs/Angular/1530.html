Title

Router Segments parsing error with =

Description
## I'm submitting a...
  
[x ] Bug report   
  

## Current behavior

If you set up a route to match the following example URL.

    [URL]

The key passed will be `MDAtMNTk` without the equal sign.

## Expected behavior

The equals sign has no meaning in the path, it should only apply to parsing the query string. The
the value passed should be `MDAtMNTk=`.

## Minimal reproduction of the problem with instructions

You just need to add a test parsing an URL with an equal sign to trigger the issue.

      it('should pass the full path segment', () => {
        const t1 = serializer.parse('/password/de/MDAtMNTk=');
        const t2 = serializer.parse('/password/de/MDAtMNTk%3D');
        expect(containsTree(t1, t2, false)).toBe(false);
      });

## What is the motivation / use case for changing the behavior?

1) Putting base64 encoded strings in a URL is a common case.
2) Angular should support valid URLs

Discussion
- Looks like the segments get parsed in this method of url_tree.ts

```
const SEGMENT_RE = /^[^\/()?;=&#]+/;
function matchSegments(str: string): string {
  const match = str.match(SEGMENT_RE);
  return match ? match[0] : '';
}
```

Of course it won't be as simple as just removing the `=` from the regex. I'm not sure I know enough about all the url rule permutations to propose a fix.
- I'm suspecting that this is a fundamental flaw in the implementation. It seems to use the same representation for incoming request URLs and URL routes configuration. I'll have to understand the codebase better with concepts such as segments and the like.
