Title

No error/warning for @Delegate introducing conflicting interface generics

Description
Consider the following: 
  
 
 class  C  implements  List< String > {
  @Delegate List< Number > numbers
}
 
  

 C implements List<String> and List<Number> but there is no compiler error or warning.
Discussion
- I decided it best to skip adding the conflicting interface in this case, which is current behavior.  However, this more subtle case will generate an error thanks to   GROOVY-5106  : 
  
 
 class  C  extends  ArrayList< String > {
  @Delegate Set< Number > numbers
}
