Title

`std::cell::RefCell ` cannot be shared between threads safely

Description
```
error[E0277]: `std::cell::RefCell ` cannot be shared between threads safely
   --> src/main.rs:359:13
    |
359 |             thread::spawn(move|| {
    |             ^^^^^^^^^^^^^ `std::cell::RefCell ` cannot be shared between threads safely
... [Log Snipped] ...
    = note: required because it appears within the type `[closure@src/main.rs:359:27: 364:14 client:std::sync::Arc , tx:std::sync::mpsc::Sender ]`
    = note: required by `std::thread::spawn`
```

`rocket::local::Client` can't be shared between threads in version 0.4.0-rc.1 while it used can be shared in 0.3.x.
Discussion
- This looks like a consequence of eda635a, the automatic cookie tracking between requests. I'm going to assume that none of Rocket's tests or examples were sharing a `Client` between threads before, since they didn't need to be changed.

What is your use case for sharing a single `Client` between threads? It's probably a bad idea to share a `Client` between threads if the cookie tracking is enabled, but it is probably fine to do so with an `untracked` `Client`.
- The test case code looks like this:

```
rust
    #[test]
    fn test_multiple_same_hash_requests_only_one_created() {
        let client = Arc::new(Client::new(rocket()).unwrap());
        client.delete("/_internal/cf/test").dispatch();
... [Log Snipped] ...
        assert_eq!(ok_count, 4);
    }
```

I want to test that concurrent same requests will only create one item.
- We should be able to change the `RefCell` for a `Mutex` or `RwLock` to regain `Sync` and `Send`.
