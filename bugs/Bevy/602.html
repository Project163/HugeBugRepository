Title

Picking sprite backend will panic with Ord violation

Description
I discovered a panic in `bevy_picking_sprite` but the same code now exists in `main` due to the upstreaming, so I'm reporting an issue per [Discord request].

[Discord request]: [URL]

## Bevy version

`main`. I can provide more system information if requested, but I don't think it's relevant.

## What you did

Interacted with a sprite causing the sprite picking backend to run. Must have an invalid transform with NaNs.

## What went wrong

Panic.

```
thread 'Compute Task Pool (1)' panicked at library/core/src/slice/sort/shared/smallsort.rs:848:5:
Ord violation
stack backtrace:
   0: _rust_begin_unwind
   1: core::panicking::panic_fmt
... [Log Snipped] ...
```

Original report: [URL]
Discussion
- The reason for the `Ord` violation in this `sort_by` call is that NaNs are being compared equal to everything, which does not form a total order.
This is fixable by wrapping the two floats in `FloatOrd` and using the normal `cmp` function instead.
This will order NaNs as less than every other value. Whether this is actually "correct" behavior for sprites I do not know, I am not familiar with sprite code.
