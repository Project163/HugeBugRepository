Title

Do not require restart when accepting/rejecting request for sharing usage data

Description
Syncthing v0.12.14, OSX

When accepting or reject the request to share usage data, the user gets greeted with a 'please restart' dialog. This should be a bit more streamlined (maybe simply ignore the fact that we need to restart?)
Discussion
- I could say the same thing about progressEmitter interval.
We already handle changing that at runtime, yet it asks for a restart.
- What is it that triggers the "restart needed" exactly? If I remember correctly the usage data thing actually starts and stops just fine without restart. `STTRACE=config` while doing the change should clarify that
- ... [Middle Discussions Snipped for Brevity] ...
- Service is relay.Service
- Making the model not require restarts for all options changes is trivial, but we then carefully need to go through other parts that may require restarting. For example it looks like the connection service needs to properly handle changes to the listen addresses, rate limiting etc which it doesn't, and so on for a bunch of options. 

I can fix this specific case by "white listing" a few options that we for sure should not look at.
