Title

BC Break in Date/Time related types: can no longer convert `DateTimeImmutable` to database value

Description
I think there should be a BC Break Notice in the UPGRADE.md file.

The following example code will break when switching from 2.5 to 2.6.

~~~ php
public function findUsersNewerThan(\DateTimeImmutable $dateTime)
{
    $qb = $this->connection->createQueryBuilder();
    $qb->select('*')
        ->from('user')
        ->where('created_at > :date')
        ->setParameter(':date', $dateTime, Type::DATETIME);
    // [...]
}
~~~

When I read #2678 correctly, this is intentional behaviour so there wont be a fix for it.
Discussion
- @langj I think you misread something, that PR was NOT merged to avoid BC breaks. You should use `Type::DATE_IMMUTABLE` in order to use `DateTimeImmutable` objects.

`Type::DATETIME` only supports `\DateTime` (on 2.5 and 2.6).
- @lcobucci Thanks for your response.
I referenced this PR because it showed me, that `Type::DATETIME` intentionally dropped support for `DateTimeImmutable`.
However, I am currently using `DateTimeImmutable` in my Project and I use `Type::DATETIME` to store it because `Type::DATETIME_IMMUTABLE` is not available and it works well with 2.5.12 and 2.5.13.
When I update to 2.6.0 I get a 

Could not convert PHP value of type 'DateTimeImmutable' to type 'datetime'. Expected one of the following types: null, DateTime

(which, I now know, is intended)

But it  looks like a BC Break to me as previous supported usage now results in an Exception. So I think should be documented, shouldnt it?
