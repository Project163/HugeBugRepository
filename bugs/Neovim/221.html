Title

python rplugin stderr_collector dict error

Description
It seems that commit 58d8d91ec1 may have broken something with stderr collection, but I'm not familiar enough with the rplugin support to determine for sure what's going on.

Using the deoplete rplugin, I ran into some issues with a not-before-seen E725 "Calling dict function without Dictionary: provider#stderr_collector" error, which I reported as Shougo/deoplete.nvim#520 but it seems to actually be a neovim issue.

Commit 58d8d91ec1 introduced a dictionary function `provider#stderr_collector(chan_id, data, event)` which seems to be called incorrectly by the refactored code, at least in this case. I'm not able to obtain anything useful from the runtime log, is there any way to get a traceback on viml errors? 

In the `-V9` runtime log, the error comes seemingly out of the blue:


Discussion
- The commit just adds stderr report.
So the commit is not the problem.
- It seems clipboard provider is broken.
I can reproduce the error by the below vimrc.

```vim
if has('unnamedplus')
  set clipboard& clipboard+=unnamedplus
else
  set clipboard& clipboard+=unnamed
endif
```

You can get the error by the text yank.
