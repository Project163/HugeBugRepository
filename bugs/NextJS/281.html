### Link to the code that reproduces this issue

[URL]

### To Reproduce

1. Create a new TS repo using the CLI: `pnpm create next-app --typescript `
2. Either:
	1. Set a custom `distDir` in the `next.config.js` file, e.g. `distDir: '.build;`
	2. Remove the `.next/types/**/*.ts` in the `include` part of `tsconfig.json`
4. Run `pnpm lint`

### Describe the Bug

The linter process detects the new dist dir or the lacking include element and tries to add it. However, the `distDir` that is being used is the absolute path, not the relative and the CLI ends up adding an absolute path to tsconfig, not suited for committing since it's device-specific.

### Expected Behavior

Linting to add the path relatively, not as an absolute path.

PS: Running `pnpm dev` works fine and adds the correct relative path, so the calculation of `distDir` seems to be off for the linter but not for the dev server.
