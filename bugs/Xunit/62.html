Title

Improve error message when method value types for MemberData don't match method

Description
The following works on the 2.0.0 stable version of Xunit, but does not in the latest 2.1.0-beta3. Testing this in a blank .NET 4.6 project.

```
CSharp
public class TestClass
{
    public static IEnumerable  GetData(object[] data1, object[] data2)
    {
... [Log Snipped] ...
    }
}
```

The following error is given: 

System.ArgumentException : Could not find public static member (property, field, or method) named 'GetData' on ConsoleApplication2.TestClass

Is this still a supported use of MemberData?
Discussion
- It's failing because of a type mismatch (your `MemberData` attribute uses `int[]`, but your member method takes `object[]`). Everything starts working again when the types match (change either one to match the other).
- Thanks Brad, that does narrow down the issue. In the 2.0 stable version, what I have posted above does work, as if the method were declared as accepting int[] parameters. I will take a look at the real tests that are exhibiting this issue and make sure it's the same (the above was just a simple example repro I threw together). Would you expect that this new behavior will be staying? If so, it would be nice if the error message was improved to reflect the particular issue.
