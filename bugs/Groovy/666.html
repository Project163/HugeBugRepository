Title

Groovy-JDK methods Collection.unique should return a Set

Description
The three methods Collection.unique from the Groovy-JDK  return Collections according to the API, but I think they should return Sets.
Discussion
- Wouldn't the least surprise thing be that they return the original collection type unchanged?
- Hm,... If you have a look at all the Methods added to Collection it looks like most of the rest of Groovy: Grown as someone needed.   

 You're right: For some Methods it would be very useful and not surprising if you return the original collection type. But do they? Look at plus(Collection) for example: What if the left hand side Collection is a SortedSet, Queue, Deque or a jakarta.commons.Bag? So I think the result will be surprising.  

 (BTW: It would be nice if the method could just clone the left Collection, add the right Collection to the clone and return the clone. But not every Collection is cloneable.) 

 So what about sort()? I think if it's called on a List it schould return a List. But called on a Set I would think it schould return a SortedSet. And unique()? I think it schould return a Set because it's the nature of a Set that it just contains unique elements. Ok, one could argue that one perhaps want a unique List.  

 But the cause is another surprise: Unique does not return a new Collection like the most other methods. :-\  I was very surprised as I read this. Perhaps you can go the Ruby way an have methods that work inline and some that work on new objects. Regardless of that, every method that changes an existing Collection schould be marked clearly. At best within the methods name. 

 Another method that should not return a List when called on a Set is findAll. Other examples are findAll and getAt on SortedSet. 

 Perhaps some methods are just misplaced at Collection and should belong to List, Set, ...? 

 What about methods like: toSortedSet(), toSet(), toUniqueList() ... and makeUnique() for editing the existing Collections? Is that groovy enough?
- True, a Set makes sense in terms of that it is unique. But further operations will maybe add duplicates and want to do that. So I am not for returning a Set here, people can do that explecitly if needed.
