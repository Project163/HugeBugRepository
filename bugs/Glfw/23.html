Title

Black fullscreen window

Description
On OS X (tested 10.8 and 10.10) creating a fullscreen window that is not the same size as the desktop resolution results in a black window with only the cursor showing.

Requesting a fullscreen window with any size seems to always result in `glfwGetWindowSize` and `glfwGetFramebufferSize` returning the desktop size (non-retina Mac):

```
[2014-Nov-04 12:05:31] Creating window (Fullscreen 1280x800 @ 59 Hz) ...
[2014-Nov-04 12:05:31] Desktop refresh rate: 59 Hz.
[2014-Nov-04 12:05:32] Window created.
[2014-Nov-04 12:05:32] Window size: 1440x900.
[2014-Nov-04 12:05:32] Refresh rate: 59 Hz.
... [Log Snipped] ...
[2014-Nov-04 12:05:32] OpenGL shading language version: 1.20
[2014-Nov-04 12:05:32] Framebuffer size: 1440x900.
```

Reproducible with the `reopen` test using current master.
Discussion
- Although I cannot test it without a retina display, I believe this also causes a black fullscreen on retina displays when GLFW_USE_RETINA is OFF.
- Verified on a non-retina MacBook running 10.9.5.

- Maybe not capturing the display is the lesser of the two evils; considering that note.

I see Apple also recommend letting OpenGL do the scaling for lower resolutions ([Link: Drawing to the Full Screen]):
`Avoid changing the display resolution from that chosen by the user. If your application needs to render data at a lower resolution for performance reasons, you can explicitly create a back buffer at the desired resolution and allow OpenGL to scale those results to the display. See Controlling the [Link: Back Buffer Size].`

Do you think maybe changing the back buffer size is something that would make sense for GLFW to do? I imagine it might cause issues for users, but there could be a parameter to disable the default behavior.
- @SephiRok It does seem to be the least bad of the available solutions. I'll know for sure once the cursor code has been fixed. It had non-obvious interactions with full screen views, because Apple.

Changing the back buffer size might work. Looking into it. It fits the GLFW model in some ways but not others.
