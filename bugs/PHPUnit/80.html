Title

assertNotInternalType errors after upgrade to 6.4.0

Description
| Q                   | A
| --------------------| ---------------
| PHPUnit version     | 6.4.0
| PHP version         | 7.X.X
| Installation Method | Composer / PHAR

 

Just noticed after PHPUnit was upgraded to 6.4.0 on TravisCI that a unit test in the WordPress project began returning an error with the following message:

```
1) Tests_Image_Functions::test_load_directory
TypeError: get_resource_type() expects parameter 1 to be resource, string given
/home/travis/build/joemcgill/develop.wordpress/tests/phpunit/tests/image/functions.php:269
```
The test in question used `assertNotInternalType()` to ensure a variable was not a `resource` type, so the second parameter being passed was either a `string` or a WordPress error class. Seems like somewhere this method makes use of `get_resource_type()` under the hood to perform this check, which is what is now returning the error.

We've updated that particular unit test as a workaround, but this seems like it might be a bug, and that you should be able to use `assertNotInternalType()` to assert that a variable is not a resource.
