Title

[YSQL] A max operation on a subquery with an OFFSET 0 clause returns the max value from the wrong column when yb_enable_expression_pushdown is true

Description
Jira Link: [Link: DB-13426]
### Description

With value `yb_enable_expression_pushdown` set to `on` 

this test case 

```
create table test (a bigint, b bigint);
insert into test (a, b)
select i, 2024000000000 + i
from generate_series(1, 100000) as i;
```

returns the max of A instead of the max of B 

```
yugabyte=# select max(sub.b) from (select
yugabyte(# b from test
yugabyte(# where (
yugabyte(# b > 2024000000000 AND
yugabyte(# b   2024000000000 AND
b < 2025000000000
... [Log Snipped] ...
 2024000100000
(1 row)
```
(3)
Dont use OFFSET 0

Discussion
- The WHERE clause doesn't really matter.
It is interesting that plans look identical.
```
yugabyte=# explain verbose select max(sub.b) from (select b from test) as sub;
                              QUERY PLAN                              
----------------------------------------------------------------------
 Finalize Aggregate  (cost=102.50..102.51 rows=1 width=8)
   Output: max(test.b)
... [Log Snipped] ...
 Query Identifier:  
(6 rows)
```
The column `b` is the first in the subquery, but the second in the table, and this `OFFSET 0` somehow prevents this mapping when partial aggregate is pushed down to the scan.
```
yugabyte=# select max(sub.b) from (select b from test OFFSET 0) as sub;
  max   
--------
 100000
(1 row)
... [Log Snipped] ...
 2024000100000
(1 row)
```
