Title

Windows: Borderless fullscreen physical resolution incorrectly affected by system ui scale

Description
## Bevy version
0.12.0

## Relevant system information
Windows 11

Adapter Info:

`AdapterInfo { name: "NVIDIA GeForce RTX 3080 Ti Laptop GPU", vendor: 4318, device: 9312, device_type: DiscreteGpu, driver: "NVIDIA", driver_info: "545.84", backend: Vulkan }`

## What you did

This app prints the resolution of a borderless fullscreen every frame:
```
rs
use bevy::prelude::*;
use bevy::window::WindowMode;

fn main() {
... [Log Snipped] ...
    info!("Screen Width: {}, Screen Height: {}", window.width(), window.height());
}
```

To reproduce the issue:

- Go to windows settings -> system -> display -> scale and set it to 100%
- You will see that the size of the window matches the actual size of the screen (e.g. 1920x1080 on a 1920x1080 display)
- Change the scale setting to 125%
- You will see that the window's size has been decreased to match the new ui scale leaving the user with a lower-resolution game (e.g. 1536x864 on a 1920x1080 display)

## What went wrong

Per the docs for `BorderlessFullscreen`:


So a developer would expect the full resolution of the screen to be available to the game - not a smaller resolution that is then scaled by the os to the full screen. But this second option is what is being done. Fullscreen games traditionally do not abide by ui scaling in other engines -- I don't really see how this could be intentional behavior on Bevy's part.

## Additional information

I don't know what kind of winit trickery would be required here but what needs to happen is that bevy apps running in borderless fullscreen (and perhaps even in the other modes) need to indicate to windows that it does not want to be affected by its ui scaling - it should always be scaled at 100% and not some other value.
Discussion
- This issue also affects Fullscreen.

If this is not intended, then from what I can see, the easiest fix is to change [Link: `scale_factor_override`] in `WindowResolution` to `Some(1.0)`. This would always override `scale_factor` from OS by default. There might be a better approach to this, if using this approach, we should think about adding option to set it to `None`.

If this is intended, you can fix it by specifying `resolution` field on `Window`:

```
rust
use bevy::{
    prelude::*,
    window::{WindowMode, WindowResolution},
};
... [Log Snipped] ...
        .run();
}
```

Here you override scale factor, so it's always going to produce the same resolution.
- Maybe the documentation or API could be improved but I think the current behaviour with scale factor is probably correct. 
By default Bevy apps in a regular window should should respect the system's scale factor and it wouldn't be consistant to remove the scaling when you switch to fullscreen.
