- Thanks! :smile: 

Unfortunately there's no way to stop that failure from happening right now, though you could change logback filters to suppress the message for the appender named `🐳 [richnorth/ambassador:latest]`. Sorry that this is clunky at the moment.

This should clearly be improved, though, and the behaviour that's causing the message should be removed. As-is, the library attempts to start an 'ambassador container' (one that exposes ports that would otherwise only be accessible through container links) - but does so straight away after starting the docker compose container. Since the docker compose container takes some time to create the service containers defined in `docker-compose.yml`, the ambassador containers may fail to connect on the first few attempts.

I think I have a solution - I'll try this out and hopefully get a fix into the pipeline...
