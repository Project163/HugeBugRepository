Title

[ML] Trained model size calculated incorrectly

Description
### Elasticsearch Version

8.13.0

### Installed Plugins

_No response_

### Java Version

_bundled_

### OS Version

any

### Problem Description

The [Link: trained model stats] incorrectly calculates the `required_native_memory_bytes` field.

Since #98139 calculating the model's required memory has taken into account the number of allocations as each allocation uses extra memory. The memory requirements for each deployment are different depending on the number of allocations. The bug is that the total number of deployed allocations is used to calculate the required memory rather than the deployment's number of allocations. 

`required_native_memory_bytes` should be calculated per deployment using the correct number of allocations

The bug only affects the Stats API output it does not affect deploying a model


### Steps to Reproduce

Deploy any 2 NLP model in machine learning. Change the number of allocations for the first model and observe the required memory change for second model.

```
{
            "model_id": "philschmid__distilroberta-base-ner-conll2003",
            "model_size_stats": {
                "model_size_bytes": 326181360,
                "required_native_memory_bytes": 2351769660
... [Log Snipped] ...
            }
        },
```

We can see that the `required_native_memory_bytes` field is under `model_size_stats`, rather than `deployment_stats`. This distinction is reflected in the code, and is the reason that the memory requirements for all allocations in a model are combined. 

We could change the meaning of this field, and change the value, but that would require some refactoring, and would likely constitute a breaking change. 

If there is a reason that we want each deployment to have its memory requirements listed separately, we should probably add that to the `deployment_stats` section rather than changing `model_size_stats`.

Given the above, I would suggest we close this issue as "non-issue"/won't change.
