Title

platform-http using spring boot won't create the producer URL correctly in case of bridged url

Description
In the scenario where service1 -> calls -> service2, the http producer will fail, it appends the first path to the bridged one. 

 So if you call the service1 at the endpoint  [URL] and the route is configured to call the service2 at  [URL] using 
  
 
.toD( "${header.backendServiceEndpoint}/chain?bridgeEndpoint= true " )
 
  
 the result will be  [URL] instead of the expected  [URL]

 Attached the reproducer   csb-app.zip
Discussion
- This changed camel-jetty, so we need to look into that
- The old code was actually correct - the relative path is appended like a proxy scenario. If you want to call an absolute url, you need to remove the headers, or use ignore control headers.
- ... [Middle Discussions Snipped for Brevity] ...
- I noticed a different behaviour when  this override  has been implemented, the parent  implementation returns a different value, so I needed to remove the header
- I was wondering if we should also ignore HTTP_PATH, same as HTTP_URI, in case of a bridged endpoint. I think it makes sense, in case we want to use the same path as the parent REST, we can append the HTTP_PATH again. Before the previous override, the HTTP_PATH was always empty if we used the Spring Boot runtime.
