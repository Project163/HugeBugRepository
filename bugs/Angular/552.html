Discussion
- @tbosch I think the problem here is that new `TsCompilerAotCompilerTypeCheckHostAdapter`  [Link: doesn't replace] `\` to `/` for `containingFile` variable as [Link: it was] in old `CompilerHost` so typescript can't find module because it uses `ts.directorySeparator`, which is `/`, to find `containingFolder`.

Possible workaround is using `paths` options in tsconfig:

```
{
  "compilerOptions": {
    ...
    "baseUrl": ".",
    "paths": {
      "@angular/core": ["node_modules/@angular/core"]
    }
  },
```
- You want to be using the vital [Link: `canonical-path`] library :-)
- See this [Link: commit] that originally introduced the windows compatibility.
- It is much better to stick with alway using forward slashes in node if you can. A forward slash will be converted to a back slash for the OS on Windows but the reverse does not happen. So you end up with crazy situation where:  `path.join('a','b/c')` will end up being `a/b/c` on unix and `a\b\c` on Windows. The `canonical-path` library means that in your code you can just assume that all paths are always forward slash separated and then go to the pub early.
