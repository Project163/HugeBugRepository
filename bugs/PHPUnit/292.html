Title

Regression in StringMatchesFormatDescriptionTest with 72ea2b54d

Description
| Q                   | A
| --------------------| ---------------
| PHPUnit version     | 12.1.4
| PHP version         | any, tested on 8.3.20

#### Summary

With [URL] we sadly introduced a regression that breaks %A matching in StringMatchesFormatDescriptionTest for multiline matches.

With %A greedily matching the whole document and thus changing the test result instead of improving the diff.

#### Current behavior

As it's annoying to paste diffs of diffs I made a reproduce:

The test can be seen here: [URL]

- Yes I just had a look at it.

The problem is, that we generate the regular expressions to compare expected output to real output line wise.
And since we are matching un-gready, a line with a single %A matches anything.

This works because we have clear start and end
```
 %A 
```

This does not work
```
 
%A
 
```

I would open a pull request to restore the old behavior for now and add some words of "wisdom" in form of comments.
And then work on it again in a new branch.

What do you think?
