Title

multi_match lenient query with boosted field crashes with NullPointerException

Description
A lenient multi_match query with a boosted field with type mismatch crashes. Simple example:

`curl -XPUT [URL] -d '{"foo":123, "bar":"xyzzy"}'`
`curl -XGET [URL] -d '{"multi_match": {"fields": ["foo^2", "bar"], "lenient": true, "query": "xyzzy"}}' # crashes with NullPointerException`

Interestingly, it works for internal _id field:

`curl -XGET [URL] -d '{"multi_match": {"fields": ["_id^2", "bar"], "lenient": true, "query": "xyzzy"}}' # works`

And it doesn't crash when there's no type mismatch:

`curl -XGET [URL] -d '{"multi_match": {"fields": ["foo^2", "bar"], "lenient": true, "query": "123"}}' # works`

Other queries for reference:

`curl -XGET [URL] -d '{"multi_match": {"fields": ["foo", "bar"], "lenient": true, "query": "xyzzy"}}' # works`
`curl -XGET [URL] -d '{"multi_match": {"fields": ["foo", "bar"], "query": "xyzzy"}}' # crashes with NumberFormatException - expected`
Discussion
- More information about error:

Happen the error in class LongFieldMapper.java in the method parsevalue(). The cause of error is a NumberFormatExpcetion, becuase the value(xyzzy) arrive in the method is String.

java.lang.NumberFormatException: For input string: "xyzzy"
