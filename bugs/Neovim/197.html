Title

Strange cursor behavior on deleting list symbol with formatoptions 'a', 'n' flags

Description
Note: I also filed this as a vim issue [Link: here].

- `nvim --version`: 0.3.1
- Vim (version: 8.1.146) behaves differently? no
  - (To reproduce in vim, start with `:set bs=2`.)
- Operating system/version: NixOS 18.09
- Terminal name/version: st-0.8.1
- `$TERM`: st-256color

### Steps to reproduce using `nvim -u NORC`

Create a list of at least three items, where the third item has some more space between the list symbol and the actual item than the first two items. Then turn on automatic formatting and delete the third list symbol. The cursor ends up in a strange location.

Here are the exact keystrokes; note that there are two spaces between "3." and "ghi".

```
nvim -u NORC
i1. abc 2. def 3.  ghi :set fo=tan hhhhi  
```

### Actual behaviour

The final text is as follows (using '|' to denote the cursor location). The text is exactly what I would expect, but the cursor location is strange.

```
1. abc
2. de|f ghi
```

(The cursor jumps back to before the "f".)

### Expected behaviour

We should get the same text, but the cursor should end up just after the 'f'.

### Notes

- The formatoptions 't' flag is not necessary to reproduce this error; `set fo=an` has the same effect.
- If you put an additional space between the "3." and the "ghi", the cursor moves an additional space backwards towards the beginning of the line. If you put enough spaces, the cursor ends up at the very beginning of the line, but no further back than that.
- If you do the same thing without the first line "1. abc", starting with "2. def" instead, this error doesn't occur. The cursor ends up just before the 'g'. (I think just after the 'f' would make more sense, but I wouldn't consider this a bug on its own.)
- If you do the same thing but with "-" in place of "1.", "2.", "3.", and you change the list pattern to "-", then you can get the error with just two lines instead of three:

```
i- abc -  def :set formatlistpat=- :set fo=tan hhhhi 
```
