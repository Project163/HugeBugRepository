Title

RestMulti is not sending headers if there is no content

Description
### Describe the bug

The issue is that when you create a `RestMulti` and for whatever reason your source is "empty". Your custom headers are not sent.

When you do it this way 
```
java
    @GET
    @Path("/")
    @Produces(MediaType.APPLICATION_JSON)
    public RestMulti  testMethod() {
... [Log Snipped] ...
        );
    }
```

The result is good, my header is properly propagated
```
  testMethod() {
... [Log Snipped] ...
        );
    }
```

The result is good, my header is properly propagated
```
< HTTP/1.1 200 OK
< Content-Type: application/json;charset=UTF-8
< transfer-encoding: chunked

[]
```

### Expected behavior

The headers should be sent regardless of the data.
The answer should contain the header regardless of the datasource.

### Actual behavior

The headers are not sent if the `RestMulti` datasource is empty. (Due to a tiny problem in resteasy-reactive)

### How to Reproduce?

1. Create a RestMulti
2. Set an empty Multi as the datasource
3. Return some custom headers
4. Notice that the headers are not sent
