Title

[Rails3.1.0.rc1] attributes= method explodes when assigning nil parent object but only if counter_cache is enabled (breaks acts_as_tree)

Description
Here's a simple model you normally have when dealing with tree structures:

```
class Foo   'Foo',
    :counter_cache  => :children_count
... [Log Snipped] ...

end
```

And here's the test:

```
class FooTest   nil }
... [Log Snipped] ...

end
```

Seems that assigning a nil object triggers counter_cache refresh on that nil. No such problem when assigning a foreign key.

I didn't see a filed issue for this, which is rather odd as this is pretty common functionality.

Broken in 3.1.0.rc1 and master branch.
