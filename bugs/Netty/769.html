Title

OpenSsl.availableJavaCipherSuites contains null element

Description
The following code reproduces an issue where the set returned by `OpenSsl.availableJavaCipherSuites` contains at one null element.

```java
@Test
void testAvailableJavaCipherSuitesDoesNotContainNullElement() {
    Set  suites = OpenSsl.availableJavaCipherSuites();
    for (String suite : suites) {
        assertNotNull(suite);
    }
}
```

Why this happens is a bit intricate, the root cause (as I can see) is as follows:

- in `OpenSsl`the following code is performed when boringssl is enabled:

```
    // are supported.
```

The first line is fine I think, but the second addAll causes problems down the road.  When we are building the list of "java" ciphers from the openssl list, the code checks:

```java
if (!isTLSv13Cipher(cipher)) {
    availableJavaCipherSuites.add(CipherSuiteConverter.toJava(cipher, "TLS"));
    availableJavaCipherSuites.add(CipherSuiteConverter.toJava(cipher, "SSL"));
} else {
    // TLSv1.3 ciphers have the correct format.
    availableJavaCipherSuites.add(cipher);
}
```

But `isTLSv13Cipher` only looks at the set of `TLSV13_CIPHERS` which only contains:

```java
  static final Set  TLSV13_CIPHERS = Collections.unmodifiableSet(new LinkedHashSet (
          asList("TLS_AES_256_GCM_SHA384", "TLS_CHACHA20_POLY1305_SHA256",
                        "TLS_AES_128_GCM_SHA256", "TLS_AES_128_CCM_8_SHA256",
                        "TLS_AES_128_CCM_SHA256")));
```

so, the different format. TLS1.3 certs are only configured in the mapper with the `TLS_` prefix, so because the check is false, we end up invoking

```java
availableJavaCipherSuites.add(CipherSuiteConverter.toJava(cipher, "SSL"));
```
