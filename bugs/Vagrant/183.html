Title

Port detection bug with Windows 10

Description
### Vagrant version

Vagrant 2.2.7

### Host operating system

Windows 10

### Guest operating system

```
$ cat /etc/lsb-release 
DISTRIB_ID=Ubuntu
DISTRIB_RELEASE=16.04
DISTRIB_CODENAME=xenial
DISTRIB_DESCRIPTION="Ubuntu 16.04.6 LTS"
```

### Vagrantfile

Full Vagrant file: [URL]

Relevant section from the Vagrantfile:

```ruby
config.vm.network "forwarded_port", guest: 32123, host: 6174, guest_ip: " ", host_ip: " ", auto_correct: false, id: "sync"
```

### Debug output

Gist: [URL]

### Expected behavior

The VM should have started successfully, and the guest port (" ", 32123) should be forwarded to all interfaces in the host (" ", 6174). This works with Vagrant 2.2.4.

### Actual behavior

As can be seen from the logs, the VM failed to start because Vagrant attempted to connect to (" ", 6174) for a port detection check. There are two issues with that:

1. Vagrant should handle `host_ip: " "` as it would handle an empty `host_ip` option, since they are equivalent.
2. Whatever happens during port detection, it should show up as a warning at most. If the port detection check is advisory, then it shouldn't affect `vagrant up`.

As for what changed from Vagrant 2.2.4: it seems that commit   did not add a case for `host_ip: " "`, and has caused this regression.

### Steps to reproduce

Install Vagrant 2.2.7 and put in an existing Vagrantfile the following section:

```ruby
config.vm.network "forwarded_port", guest: 32123, host: 6174, host_ip: " "
```
