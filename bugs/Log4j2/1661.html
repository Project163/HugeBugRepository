- Hi  peterdm , 

 The problem is due to the hardening of the deserialization of Log4j classes in version 2.22.0 (cf.  apache/logging-log4j2#1906 ). Only a limited number of classes can be deserialized (e.g. those in  java.lang ), but the filter does not work correctly with arrays (e.g. it denies  java.lang.StackTraceElement[] ). We'll fix this in the next release.
- PR#2259  should fix your problem. 

 On a side note, IMHO logging an exception as * message * is not a very good practice. I would rather use  exception.getMessage()  explicitly.
