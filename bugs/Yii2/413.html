Title

Url caching has error

Description
If I use following url rules

``` php
[
    'pattern' => '',
    'route' => 'paracms/structure/frontend/page/view',
    'defaults' => ['slug' => 'index'],
],
'page/ ' => 'paracms/structure/frontend/page/view',
```

and then run code

``` php
echo Url::to('/paracms/structure/frontend/page/view', ['slug' => 'services']);
echo ' ';
echo Url::to('/paracms/structure/frontend/page/view', ['slug' => 'index']);
```

I have got

```
/page/services/
/page/index/
```

But I expeсted

```
/page/services/
/
```

This problem rises due to [URL]

When I call `Url::to('/paracms/structure/frontend/page/view', ['slug' => 'services']);` rule № 2 was cached and then it was used when I call `Url::to('/paracms/structure/frontend/page/view', ['slug' => 'index']);` instead of rule № 1.
Discussion
- See #8205
It seems 'create URL cache' feature should be reverted (which whould be a pity) or made optional.
In present state you should be able to walk around the issue exluding 'index' from second rule:

``` php
[
    'pattern' => '',
    'route' => 'paracms/structure/frontend/page/view',
    'defaults' => ['slug' => 'index'],
],
'page/ ' => 'paracms/structure/frontend/page/view',
```
- @klimov-paul, thank you!

I use same regexp as temporary solution: `page/ `. But it doesn't work properly if slug has word "index". For example: `index1`, `indexation`, etc.

I think 'create URL cache' was good idea. If there is no issue with this feature except my issue I propose to not revert this feature and add an ability to make inversed regexp in url.

For example:
`page/ ` — All except "index"
`page/ ` — All except "index", "sitemap", "contacts"
- there is no need for complex inverse regex, we can simply skip the cache if we detect situations which we can not cache.

checked in a fix for this.
