Title

warn for backref replacing existing object

Description
there's various kinds of failure modes that seem to vary based on if the overlapping relationship is a backref, or not, but generally, association proxy should raise the moment it knows what its attribute name is:

```
from sqlalchemy import *
from sqlalchemy.orm import *
from sqlalchemy.ext.declarative import declarative_base
from sqlalchemy.ext.declarative import declared_attr
from sqlalchemy.ext.associationproxy import association_proxy
... [Log Snipped] ...
a1 = A(bs=[B(data='b1')])
print(a1.bs)
```
Discussion
- ok this might not be very easy to do, some initial attempts didn't work that great.  here's also the user's example which I cant get to raise at all, so something might be going wrong with the backref being set up that is silently failing

```
from sqlalchemy import (
    Column,
    Integer,
    String,
    ForeignKey,
... [Log Snipped] ...
# this is not working
request1_server1.patches.append(patch1)
```
- this is all related to backref replacing the attributes, and is not related to assoc prox pointing to itself.  in the upcoming patch, the end user case above warns:

     SAWarning: User-placed attribute AssociationProxy('patches', 'patch') on Mapper[Request2Server(request2server)] being replaced with new property Request2Server.patches; the old attribute will be discarded
- the issue is specific to "backref" and no others, as this is the only case where we generate an attribute on the class that did not have a declarative member at that name already.
