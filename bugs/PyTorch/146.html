Title

Using an empty tensor and `torch.int64` or `torch.bool` for `dtype` of `nanmean()` works while a non-empty tensor doesn't work

Description
### 🐛 Describe the bug

Using a non-empty tensor and `torch.int64` or `torch.bool` for `dtype` of [Link: nanmean()] gets the errors as shown below:

```python
import torch

my_tensor = torch.tensor([0., 1., 2.])

torch.nanmean(input=my_tensor, dtype=torch.int64) # Error

torch.nanmean(input=my_tensor, dtype=torch.bool) # Error
```



But, using an empty tensor and `torch.int64` or `torch.bool` for `dtype` of `nanmean()` works even though the results are `tensor(nan)` which are not converted to `torch.int64` or `torch.bool` as shown below:

```
python
import torch

my_tensor = torch.tensor([])
my_tensor = torch.tensor([[]])
... [Log Snipped] ...
torch.nanmean(input=my_tensor, dtype=torch.bool)
# tensor(nan)
```

### Versions

```python
import torch

torch.__version__ # 2.3.1+cu121
```

- The Solution: Cast to Float

The most robust and recommended solution is to always cast your input tensor to a floating-point type (preferably float32 for most cases) before using torch.nanmean:


```python
my_tensor = torch.tensor([0, 1, 2], dtype=torch.float32)  # Explicitly cast to float32
result = torch.nanmean(my_tensor) 

```
