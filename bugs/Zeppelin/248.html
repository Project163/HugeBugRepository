Title

Different Notebooks are Sharing the Same Context

Description
Currently notebooks are sharing the same context: a table loaded and registered in a notebook can be accessed from another notebook.
Discussion
- +10 on this JIRA.  

 The sharing of context and variables among  all  notebooks for a given interpreter is a real issue right now. Not only it breaks completely user context isolation but also it can introduce subtle bugs very hard to debug, not even mentioning multi-tenant usage. 

 The only work-around right now is to create different instances for a given interpreter if you wish to isolate the scope of your notebook. 

 But I guess having the Context scope to the notebook level might be a right level. 

 Still, it raises many concerns about tech implementation. For example, the Spark interpreter relies on the SparkREPL. Is it relevant to have 1 instance of the REPL per notebook, resource-wise ?
- This causes problems with the dependency loader too, because dependencies may only be added before the spark context is used.   Another note may have been used already, thus loading the context and blocking any opportunity to add a dependency. 

 Keep in mind that only a single SparkContext may be used in a given JVM (  SPARK-2243  ).
