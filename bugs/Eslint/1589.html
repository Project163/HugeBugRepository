Title

Bug: Cannot serialize key "parse" in parser: Function values are not supported.

Description
### Environment

Description

I’m encountering an issue with ESLint when using the FlatCompat utility and Next.js. The error occurs both during npm run lint and npm run build. It seems related to the serialization of the parse function in the ESLint parser.

Environment Details
	•	Node.js Version: v22.12.0
	•	npm Version: 10.9.0
	•	ESLint Local Version: 9.17.0
	•	ESLint Global Version: 9.17.0
	•	Next.js Version: 15.1.4
	•	Operating System: Mac OS Sequoia

### What parser are you using?

Default (Espree)

### What did you do?

Steps to Reproduce
1.	Install ESLint and Next.js in a project.
2.	Use the following eslint.config.mjs configuration:

```
import { FlatCompat } from '@eslint/eslintrc'

const compat = new FlatCompat({
  baseDirectory: import.meta.dirname,
})
... [Log Snipped] ...

export default eslintConfig
```

3.	Run npm run lint:

```
npm run lint
```
Output:
Cannot serialize key "parse" in parser: Function values are not supported.

4.	Run npm run lint -- --no-cache:
```
npm run lint -- --no-cache
```
This works without errors.

5.	Delete the .next/cache directory and run npm run lint again:

```
rm -rf .next/cache
npm run lint
```
Output:
Cannot serialize key "parse" in parser: Function values are not supported.

6.	Run npm run build:

```
npm run build
```
Output:
Linting and checking validity of types  . ⨯ ESLint: Cannot serialize key "parse" in parser: Function values are not supported.

### What did you expect to happen?

- 	The npm run lint command should work without requiring --no-cache.
- 	The npm run build command should complete without errors.

### What actually happened?

- Running npm run lint without --no-cache results in the error: Cannot serialize key "parse" in parser: Function values are not supported.
- Running npm run build also fails with the same error during the linting phase.
