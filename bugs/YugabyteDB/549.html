Title

[YSQL] PgExpr:TranslateDecimal appears to leak memory in long running queries

Description
While running a query in a cursor and periodically fetching rows, I note that there is a great deal of heap memory allocation with TranslateDecimal in the stack:

```
Thread 1 (process 28713):
#0    in _int_malloc (av=av@entry=   , bytes=bytes@entry=264133) at malloc.c:3451
#1    in __GI___libc_malloc (bytes=264133) at malloc.c:2914
#2    in operator new(unsigned long) () from /home/yugabyte/linuxbrew/lib/libstdc++.so.6
#3    in _M_construct  (__end= , __beg=  "\350[\247\245\206", this= ) at /home/yugabyte/linuxbrew-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx/Cellar/gcc/5.5.0_4/include/c++/5.5.0/bits/basic_string.tcc:219
... [Log Snipped] ...
#42   in PostgresServerProcessMain (argc=25, argv= ) at ../../../../../../src/postgres/src/backend/main/main.c:234
#43   in main ()
```

If you look at the top frame, you note the  size requested as over 250K. The longer the session runs, I have seen this at 400K. Eventually, OOM killer will victimize this PG child process.
