Title

slash-leading classpath resources not properly rewritten when repackaging classes

Description
This applies to Velocity, for example. The code pattern they use is: 
  
 getClass().getResource( "/org/apache/velocity/myresource.properties" )
 
  
 this gets resolved as class loader relative resource and does point to myresource.properties. When classes are repackaged, the resource name is not properly updated and points nowhere (will not be found). 

 Arguably this is a bad code pattern but it's frequent enough that there should be built-in support for handling it.
