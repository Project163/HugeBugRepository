Title

incompatible_disallow_conflicting_providers: Validate that only one instance of a provider is being returned by a skylark rule

Description
Consider the following rule implementation function:

```
MyProvider = provider()

def _rule_impl(ctx):
    ...
    return [MyProvider(foo = 1), MyProvider(foo=2)]
```

The current behavior is that the latter of the two providers is propagated, and the former is ignored. This is a particularly error-prone behavior and we should guard against it.
Discussion
- contains a fix for this, attached to the flag `--incompatible_disallow_conflicting_providers`.

This issue will remain open to track the migration solution.
- Can we switch the flag for Bazel 0.20?
If so, we have to add it to the [Link: Bazel 0.19 release announcement].
- Hmm. I don't anticipate any blockers, but it looks like I've failed to add the Backward Compatibility information for this flag (which we usually link to in the announcement). I'll send a change for that.
