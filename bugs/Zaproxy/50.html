Title

zap.sh is not dealing with ~/.ZAP/.ZAP_JVM.properties correctly

Description
Hello,
current zap.sh (ZAP 2.4.2) is not dealing correctly with the "~" expansion of the ~/.ZAP/.ZAP_JVM.properties . Instead of expanding the "~" it is used as literal and the directory is never found. As a result the memory setting there is never honored.

Instead of 

```
if [ "$OS" = "Darwin" ]; then
  JVMPROPS="~/Library/Application Support/ZAP/.ZAP_JVM.properties"
else
  JVMPROPS="~/.ZAP/.ZAP_JVM.properties"
fi
```

There should be 

```
if [ "$OS" = "Darwin" ]; then
  JVMPROPS=~/Library/Application\ Support/ZAP/.ZAP_JVM.properties
else
  JVMPROPS=~/.ZAP/.ZAP_JVM.properties
fi
```

As the content of the file/variable will be something like -Xmx1024m the variable should be also properly quoted in the subsequent "if" statements and the java call itself - here is whole diff:

```
$ diff -ru /opt/zap/ZAP_2.4.2/zap.sh.orig /opt/zap/ZAP_2.4.2/zap.sh
--- /opt/zap/ZAP_2.4.2/zap.sh.orig  2015-09-21 16:56:44.000000000 +0200
+++ /opt/zap/ZAP_2.4.2/zap.sh   2015-09-26 01:58:44.920064467 +0200
@@ -54,15 +54,15 @@
 fi
... [Log Snipped] ...
 fi
+
```
Discussion
- Merging into #1877, the only changes left are some quotes in if statements.
I'm not sure about quoting for `java` command, that will constraint the JVM option to just one JVM argument, which is not the intended behaviour.
