Title

Handling of postgres bytea resource not correctly

Description
When using the binary bytea type in postgres the result of a data fetch will be a resource handle. Yii2 casts certain data type. It did not consider this special case and therefore casts the resource type to a string. This breaks handling blobs!

Not sure how blobs are handled in mysql or other dbs but chances are that it is not really a good idea to force a cast to a string...

- ... [Middle Discussions Snipped for Brevity] ...
- Here is the code which I use. Should be quite the standard approach for reading/writing data to a postgres bytea field. If Yii2 casts the value from resource to string it will not work!

Writing an image to a bytea field (image.rawdata)

```
$image = new Image;
$rawdata = new Imagick($file->tempName);
$image->rawdata = bin2hex($rawdata->getimageblob());
$image->save(false);
```

Reading an image from the bytea field and rendering it as an img tag

```
$this->options['src'] = 'data:image/jpg;base64,' . base64_encode(hex2bin(stream_get_contents($this->image->rawdata, -1, 0)));
$this->options['alt'] = 'Bild des Vorfalls';
echo \yii\helpers\Html::tag('img','',$this->options);
```

How MySQL handles blob fields is unknown to me since I only use postgres.
