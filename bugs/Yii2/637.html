Title

count() on Query with orderBy and limit leads to wrong results

Description
The change to `Query:queryScalar` #11122 (and the refactoring #13144) changes the behaviour (which temporary unsets `limit `and `offset`) of  `Query::queryScalar` when `orderBy `is not empty. 

If `limit` is set to a value lower then results count and `orderBy` is not empty the `Query::count()` returns limit instead of the expected count.

Shouldn't  `limit `and `offset` be unset in both blocks, like this?:

```
php
protected function queryScalar($selectExpression, $db)
{
    if ($this->emulateExecution) {
        return null;
... [Log Snipped] ...
    return $result;
}
```

Background:
MariaDB for example had no problems with `order by' and aggregate functions like count().
So we use the same query for pagination and count in our REST interface.
A workaround on application site is to empty orderBy or limit before executing the count() query,
but this worked until 2.0.11 - so this is a breaking change IMHO.

 
Example of "wrong" raw sql generated by  `Query::count()` :

```
SELECT COUNT(*) FROM (SELECT * FROM `product` WHERE (`name` LIKE :qp0) AND (`class_id`=:qp1) ORDER BY `parent_id`, `sort` LIMIT 100) `c`
```
