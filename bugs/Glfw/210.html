Title

Key name pointer lifetime

Description
With the recent changes that fix #943, on Windows GLFW now caches key names. However, the fix appears to break the promise in the doc above - the key names are invalidated when `WM_INPUTLANGCHANGE` is processed.
Discussion
- I think it would be reasonable to just update the promise in the doc. I guess it could now (in theory) breaks when calling `glfwPollEvents()`, people are unlikely to be relying on that.
- You never know :)

If someone saved pointers returned by `glfwGetKeyName` and is using them repeatedly, then their behaviour would break.
