Title

Eager loader overrides expired object that has been modified

Description
**Describe the bug**
This happens under 1.4.*, under very specific conditions:
- Setup: 
  - parent, child; parent has a `children` relationship which is ***eagerly loaded***
  - use ***classical mapping*** (declarative does *not* exhibit this behavior)
  - use ***`autocommit=True`***
- Steps:
  - add parent and child, flush
  - update child
  - access `parent.children`: this will override the previous update to child

I assume this is related to [Link: this behavioral change in 1.4]. Is this correct?

**Expected behavior**
Accessing `parent.children` should not override the value of `child.foo` (as happens under declarative mapping, and under 1.3.*).

**To Reproduce**

```
python
from sqlalchemy import (
    create_engine,
    inspect,
    Column,
... [Log Snipped] ...
run(session)
session.close()
```

**Error**
The error is verified by the last assert statement (`assert c.foo == 42`). Here's selected inspection data:
```
python
# BEFORE accessing `parent.children`:
(Pdb) session.dirty
IdentitySet([ >])

... [Log Snipped] ...
 'id': 1,
 'parent_id': 1}
```
**Notable differences between classical and declarative**
Under declarative, before accessing `parent.children`:
- `foo` is not in `inspect(child).expired_attributes`
- `child` is not in `session.dirty`

**Versions.**
OS: Ubuntu 20.04.1 LTS
Python: 3.8.5
SQLAlchemy: 1.4.* (last tested under 1.4.9)
Database: SQLite (first observed under PostgreSQL)
DBAPI: default for SQLite, psycopg2 for PostgreSQL
Discussion
- hey there -

have not tried this yet but immediately, you have a session with autocommit=True but not expire_on_commit=False.  This means every flush will **expire** everything in the session and is very unlikely to be useful.  this is likely the reason you are seeing something being overwritten.   The unexpire of an object now [Link: emits eager loaders] so this looks similar to something I saw a few days ago.

I will try to actually run your example later and figure out the exact mechanics of what's happening, but it's very likely the two things above are involved.  

autocommit=True is going to be removed from SQLAlchemy within a year, so it might be worthwhile to modernize your application before even moving to 1.4 if setting expire_on_commit=False is not an option.
