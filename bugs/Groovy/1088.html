Title

Nested top-level class causes problems

Description
Groovy fails to deal correctly with starting a class involving a top-level nested class.  So: 
  
  class  NestedClassProblem {
   private   static   class  NestedClass { }
   public   static  void main (  final   String [] args ) { }
}
 
  
 results in the error: 
 
 Caught: groovy.lang.GroovyRuntimeException: This script or class could not be run. 
It should either:  
 
	 have a main method, 
	 be a JUnit test, TestNG test or extend GroovyTestCase, 
	 or implement the Runnable interface. 
 
 
 which as well as being unexpected, is not really an inferable outcome.
Discussion
- Will it help if module classes are sorted at classgen phase end so that outer classes come before the inner classes? 

 Any other suggestion that can be tried?
- when the class is defined in the classloader it needs sorting, but the order there is wrong for us. Since the inner class holds a class name of the outer class the outer class needs to be loaded first, or else loading the class won't be possible. So we need first to define the outer, then the inner class. No we need a different solution for this. The class selection is in general a bit unstable... I am thinking that we maybe should save the first class and then reorder to put that at first or at last a defined position. In case of a script we have to prefere the script of course.
