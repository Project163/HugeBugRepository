Discussion
- Patch reviewed +1.
- The problem is that if the seek call on the index table is on a key that is past the last key of a data file, the scanner is positioned past the EOF of that data file. Instead it should be positioned to the beginning of the next data file. As result, since the CGScanner.atEnd method only checks if the current file index is within the valid range and leaves the responsibility of setting the proper file index to the position movers such as the scanner's advance and seekTo methods, positioning the scanner past the EOF of any data file will cause an EOF to be thrown. 

 The fix is to add a check in the scanner's seekTo method so that if after seek the position is past the end of a data file, it will be positioned to the start of the next data file, just as the advace method already does.
