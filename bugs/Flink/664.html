Title

Potential resource leak due to unclosed RandomAccessFile in StaticFileServerHandler

Description
Here is related code in respondAsLeader(): 
  
      final  RandomAccessFile raf;
     try  {
      raf =  new  RandomAccessFile(file,  "r" );
...
     long  fileLength = raf.length();
...
     // write the content.
     ctx.write( new  DefaultFileRegion(raf.getChannel(), 0, fileLength), ctx.newProgressivePromise());
 
  

 There is no close() call to raf before returning.
Discussion
- I think this has actually been reported before and is not correct. The file is closed, but not through a synchronous call, but the netty event handler will close the file once the request is done.
