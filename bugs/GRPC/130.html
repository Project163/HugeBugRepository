Title

[Python] Empty error message when exiting Python process after using async API

Description
### What version of gRPC and what language are you using?

grpcio 1.70.0 on Python

### What operating system (Linux, Windows,...) and version?

Debian trixie (testing) and others

### What runtime / compiler are you using (e.g. python version or version of gcc)

gcc version 14.2.0 (Debian 14.2.0-12) 
python 3.13.1 (built by Debian)

### What did you do?

We currently don't have a reproducer.

[Link: labgrid-client] uses gRPC with asyncio to communicate with a gRPC server via a bidirectional streaming call and additional unary calls.

When the client is done, we're closing the streaming call and then the channel. Then, when the Python function `exit(0)` is called, this leads to an error message without any details.
```
Error in sys.excepthook:

Original exception was:

```
This seems to be printed by the Python function `_PyErr_PrintEx`. We first thought this was called from a python excepthook, but it turns out that cython also calls this function directly: [URL]

After compiling grpcio with debug symbols (`pip install --force --no-binary :all: --global-option build --global-option --debug --no-use-pep517 grpcio`), we were able to get a backtrace using gdb:
```
(gdb) break _PyErr_PrintEx
Breakpoint 1 at  : _PyErr_PrintEx. (2 locations)
(gdb) r
Starting program: /home/jluebbe/ptx/labgrid-venv-trixie/bin/python -m labgrid.remote.client -p testplace power off
…
... [Log Snipped] ...
…
From there on, more of labgrid's objects are deallocated.
```

### What did you expect to see?
No error message during a clean shutdown.

### What did you see instead?
```
Error in sys.excepthook:

Original exception was:

```

### Anything else we should know about your project / environment?

If we don't stop the bidirectional call before calling `exit()`, we issue disappears. Perhaps something leads to a duplicate gRPC shutdown?

The related labgrid issue is [URL]
