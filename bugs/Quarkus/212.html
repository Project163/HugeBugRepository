Title

PanacheRepositoryEnhancer causes NPE in SignatureReader when a Repository does not directly implement PanacheRepository

Description
**Describe the bug**
A QuarkusTest fails to startup if a Repository does not does not directly implement `PanacheRepository `. The reason is a that a NullPointerException is thrown inside the `org.objectweb.asm.signature.SignatureReader` class, whose constructor was called with a `null` value for its `signature`. 

**Expected behavior**
Successful startup of QuarkusTest, either resulting in a test failure or success

**Actual behavior**
NullPointer exception, with the following partial stacktrace: 

```
org.junit.jupiter.api.extension.TestInstantiationException: TestInstanceFactory [io.quarkus.test.junit.QuarkusTestExtension] failed to instantiate test class [com.github.acme.quarkus.petclinic.web.resource.VetResourceTest]

(...)

Caused by: java.lang.NullPointerException
... [Log Snipped] ...
	at io.quarkus.test.junit.QuarkusTestExtension.createTestInstance(QuarkusTestExtension.java:343)
	at org.junit.jupiter.engine.descriptor.ClassBasedTestDescriptor.invokeTestInstanceFactory(ClassBasedTestDescriptor.java:283)
```


**To Reproduce**
Steps to reproduce the behavior:
1. Use the same demo project as I provided in #3643 
2. Remove the ` implements PanacheRepository ` clause from the `MockVetRepository` class, like so:

```java
public class MockVetRepository extends VetRepository implements PanacheRepository  {
} 
```
becomes 

```java
public class MockVetRepository extends VetRepository {
} 
```

This is not necessary because  `MockVetRepository` extends `VetRepository`, which already implements `PanacheRepository `. 

3. Run test using Maven or IntelliJ

**Environment (please complete the following information):**
 - Windows / MacOS
 - OpenJDK Runtime Environment (build 1.8.0_222-20190711112428.buildslave.jdk8u-src-tar--b08)
 - OpenJDK 64-Bit GraalVM CE 19.2.0 (build 25.222-b08-jvmci-19.2-b02, mixed mode)
