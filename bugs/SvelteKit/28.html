Title

Errors in hooks.js are silently swallowed

Description
**Describe the bug**
Whenever there is any sort of issue with my `src/hooks.js` file it is silently swallowed and the hooks are no longer executed. But there is no notice of any sort of error.

**Logs**
None.

**To Reproduce**
Demo project: [URL]

Without the last commit (https://github.com/pago/bug-svelte-kit-hooks-silent-error/commit/ ), which adds an import for `fs/promises` to the `src/hooks.js` file, the logging within `src/hooks.js` works. Once the import is added, the logging no longer happens and the hooks are just not executed anymore.
There is no warning and no information about why this happens.

**Expected behavior**
If executing the `hooks` fails for any reason, I would expect to get an error message in the console about it so that I know how to fix it and to be aware that is isn't working at the moment.

**Stacktraces**
None.

- I experienced the same issue with errors being swallowed in hooks. In my `hooks.js` I imported my custom database library from `$lib`. One of my database models had a missing package causing the entire hook to not do anything. It took me a couple hours to find the issue.
- Ah, whoops 😬  This is happening because there's error handling here... [URL] ...so that you can get away with not having a `hooks.js` file.

Since that (terrible) code was written, we added a `resolve_entry` helper here... [URL] ...which would allow us to check if the file exists before attempting to load it, which would make the error 'handling' unnecessary. Should be a quick win if anyone wants to rustle up a PR (the only finicky part would be adding a test since we'd have to add a whole new 'app' to `packages/kit/test/apps` with a failing `hooks.js`; I think we can get away without adding one).
