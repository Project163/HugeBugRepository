Title

Error while using automap: nvarchar and ntext are incompatible

Description
Environment:
- SQLAlchemy==1.3.5
- Windows 10
- Python 3.7
- Driver = SQL Server
- mssql+pyodbc


This is not an issue with sqlalchemy but rather with pyodbc (I guess). 
I'm writing this here because I want a feedback from you before opening the issue into pyodbc.

I'm trying to use the automap feature of sqlalchemy.
After calling `Base.prepare(db, reflect=True)` sqlalchemy crashes with the following exception:


The incriminated query is at line 2419 of sqlalchemy\dialects\mssql\base.py:

```sql
select ind.index_id, ind.is_unique, ind.name
from sys.indexes as ind join sys.tables as tab on
ind.object_id=tab.object_id
join sys.schemas as sch on sch.schema_id=tab.schema_id
where tab.name = :tabname
and sch.name= :schname
and ind.is_primary_key=0 and ind.type != 0
```

After digging a little bit, I was able to reproduce the issue in pyodbc:
```
python
import pyodbc
CONNECTION_STRING_TEMPLATE = 'DRIVER={DRIVER};Server={SERVER};Database={DATABASE};Integrated Security=True;'  

connection_string = CONNECTION_STRING_TEMPLATE.format(SERVER = 'servername', DATABASE = 'dbname', DRIVER = '{SQL Server}') 
... [Log Snipped] ...
"""
cursor.execute(query, ('AAAAAAAAAAAAAAA', 'dbo'))
```

For some reason if tab.name is more than 16 chars, is treated like ntext by pyodbc. If it's less is treated like nvarchar.

The problem can be solved in sqlalchemy changing the query above into this:
```sql
select ind.index_id, ind.is_unique, ind.name
from sys.indexes as ind join sys.tables as tab on 
ind.object_id=tab.object_id
join sys.schemas as sch on sch.schema_id=tab.schema_id
where tab.name = convert(nvarchar(max), :tabname)
and sch.name= convert(nvarchar(max), :schname)
and ind.is_primary_key=0 and ind.type != 0
```

Hence forcing the conversion to nvarchar.

I don't know if this is acceptable as I have literally zero clues about pyodbc is doing this (and if it's an acceptable behavior or not from the pyodbc)
