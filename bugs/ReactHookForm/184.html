Title

Errors do not disappear when corrected for fields inside a composite value

Description
**Describe the bug**
I am trying to use a custom input, which returns a composite object as a value, and utilize it using the Controller component.
The value is set correctly, but I also have some yup validation rules for this object, and here comes the problem.

If this value object has at least two fields, and both fields have got validation errors, 
when I correct one of the fields I don't get the error immediately removed, only on the next change.

**Codesandbox link (Required)**
[URL]

**To Reproduce**
Steps to reproduce the behavior (in the sandbox):

1. Press submit button (to get two errors for both User object fields)
2. Type one symbol into the First Name input
3. The error that the first name is required is still there!
4. Type second one, the error disappears

If you remove the second field (lastName) from the validation rules, 
so you don't have more than one error for the composite object fields anymore, 
the error finely disappears after the first input.

**Expected behavior**
Errors for nested object fields should disappear as soon as they are corrected.

**Additional context**
Tested on versions 6.5.3 and 6.8.2.

**Note**
I have looked into the source code of the library and found out, that the issue might be somewhere around the [Link: isSameError] function, which is called from [Link: shouldRenderBasedOnError].
In the case of composite object value, it receives nested error object, but it does not seem that the isSameError function can handle that.
Example of isSameError arguments from one of my debugging sessions (when I corrected startTimeInMills field):
```
previousError: {
  "startTimeInMills": {
    "message": "Required",
    "type": "required"
  },
... [Log Snipped] ...
  }
}
```
isSameError gives me true.
