Title

incorrect attribute value for floating window border cell adjacent to wrapped line continuation

Description
### Problem

After   (cc @bfredl) executing `screenattr()` on a floating window border cell that is adjacent to the wrapped line continuation returns -1 (which should only be the case for "... when row or col is out of range.").

### Steps to reproduce

1. Create the following 'init.lua':

    ```lua
    local buf_id = vim.api.nvim_create_buf(false, true)
    vim.api.nvim_buf_set_lines(buf_id, 0, -1, false, { ' ', 'bbb', 'ccc' })

    local config = { relative = 'editor', row = 1, col = 1, height = 5, width = 10, border = 'single' }
    vim.api.nvim_open_win(buf_id, true, config)
    ```
2. `nvim --clean -u init.lua`
3. `:=vim.fn.screenattr(4, 2)` shows -1. Executing `:=vim.fn.screenstring(4, 2)` shows the correct │ border character. Executing both `:=vim.fn.screenattr(3, 2)` and `:=vim.fn.screenattr(5, 2)` (border characters that are not adjacent to wrapped line continuation) shows 30.

### Expected behavior

`screenattr()` value does not depend on whether target cell is for border cell adjacent to wrapped line continuation.

### Nvim version (nvim -v)

NVIM v0.12.0-dev-208+gbd413a2f55

### Vim (not Nvim) behaves the same?

No, doesn't have this feature

### Operating system/version

EndeavourOS Linux x86_64,  6.14.4-arch1-1

### Terminal name/version

Ghostty 1.1.3-arch1

### $TERM environment variable

xterm-ghostty

### Installation

Appimage and built from source
