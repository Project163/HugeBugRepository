`path: '**'` with lazy loading not working as expected

## Current behavior
 
```
js
[
  {
    path: '',
    pathMatch: 'full',
... [Log Snipped] ...
  }
]
```
`DowngradeModule` should only be loaded on url which does not match `HomeModule`, however, actually `DowngradeModule` is loaded with `HomeModule` at the same time.

## Expected behavior
 
`DowngradeModule` should only be loaded on url which other route can not handler.

## Minimal reproduction of the problem with instructions
 
[URL]
1. clone project
2. install dependencies
3. run `yarn start`
4. open `[URL]
5. see network detail in browser, `home-home-module.js` and `downgrade-downgrade-module.js` are both loaded.


## What is the motivation / use case for changing the behavior?
 
It makes lazy loading for `path: '**'` useless.

Discussion
- I am seeing the same problem.

I did some debugging, and thinks that this may be related to angular/packages/router/src/apply_redirects.ts.

expandSegment function does map -> cancatAll -> first. The map goes through all the configured routes. When there is a path match, and matched route has loadChildren, then it starts to load the child module. I think the call chain is expandSetmentAgainstRoute -> matchSegmentAgainstRoute -> RouterConfigLoader.load -> RouterConfigLoader.loadModuleFactory. Inside loadModuleFactory, it calls "this.loader.load(loadChildren)". This will ACTUALLY START loading the child module in a promise. 

The "first()" operator in expandSegment does not stop "map" operator from iterating to next route. So all routes will be checked, and the last route, which is for path "**" will also match. So its child module will be loaded.  I am not expert on RxJS and not sure how to fix it.
- In loadModuleFactory function in router_config_loader.ts, changing this line:
      return from(this.loader.load(loadChildren));
to
      return defer(() => this.loader.load(loadChildren));
seems to work for me in my limited testing. But I don't have expertise in rxjs to be certain that this is the right fix.
- This appears to have been resolved at some point. Here's a stackblitz example in v10 of what I'm understanding from this report: [URL]

Customers module is the only one loaded at the root. The wildcard orders module is not loaded.
- This issue only manifests with a custom NgFactoryModuleLoader using the deprecated `string` type for `loadChildren`. See [URL] Please re-open this issue, as it is still there and reproducible.

It can be fixed by `defer`ing the call to `load` for the `**` path.
