Title

Websocket connection does not auto-reconnect on abnormal closure in new UI

Description
Problem:
	 
		 The new UI lacks automatic WebSocket reconnection when connections are closed abnormally. 
		 This differs from the classic UI which automatically reconnects on non-normal closures using the `reconnectIfNotNormalClose` flag. 
	 
	 
	 When this occurs:
	 
		 Server-side idle timeout (~30 seconds by default in Jetty WebSocket)
		 
			 Even though client sends PING every 10 seconds, timeouts still occur 
			 Particularly common in Kubernetes deployments with nginx ingress 
		 
		 
		 Browser tab inactive/background
		 
			 Chrome throttles timers to 1 second minimum after 10 seconds of inactivity 
			 After 5+ minutes, timers throttled to 1 minute intervals 
			 PING interval (10s) becomes unreliable, causing server timeouts 
		 
		 
		 Computer sleep/suspend
		 
			 JavaScript timers pause during system sleep 
			 Server closes connection due to no activity 
			 Connection not restored when system wakes 
		 
		 
		 Network interruptions or server restarts 
	 
	 
	 Current Behavior:
	 
		 Connection permanently lost 
		 No automatic reconnection attempt 
		 Real-time updates stop (paragraph results, job status, etc.) 
		 Users must manually refresh the page 
	 
	 
	 Contrast with Classic UI:
	 
		 The old UI uses `angular-websocket` library with `reconnectIfNotNormalClose = true`, which automatically reconnects on any non-nomral closure (clos code !== 1000). 
	 
	 
	 Reproduction:
	 
		 Open notebook in new Angular UI 
		 Leave browser tab inactive for 2-3 minutes 
		 Return to tab 
		 Conection is dead, no auto-reconnect
