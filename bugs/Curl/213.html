Discussion
- I made #10248 with a fix for the ngtcp2 connect handling that *could* explain the crash. 

As seen in the stacktrace, the first param to `ngtcp2_conn_open_bidi_stream()` is `NULL` which points to a wrong initialization state. This should definitely not be NULL when the transfer is started. I think I found an edge case where that could have happend.

If you still experience the crash with that version, a built with `--enable-debug` would be nice and a run with `--trace curl.log` would be helpful. Thanks.
