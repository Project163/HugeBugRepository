Title

Relation#toRestriction() may not handle ReversedType properly

Description
o.a.c.cql3.Relation#toRestriction()  uses  ClusterMetadata#type  directly but this type can be  ReverseType , which seems to bypass most of the checks. Checks like  isMultiCell()  can be hard to spot as clustering keys don't allow multi-cell, but then we do checks like: 

  
 checkFalse(column.type instanceof ListType, "Indexes on list entries (%s[index] = value) are not supported.", column.name);
 
  

 If the column is reversed clustering then this check always returns  false , even if it's a reverse list!
Discussion
