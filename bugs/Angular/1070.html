Discussion
- Hi @pacocom, thanks for reporting this issue. Adding extra text bindings in translations (like you described in your message) would not work in Ivy due to the fact that the i18n model has changed.

In View Engine translations were embedded into a template first and compilation happened after that for each locale (which was time and resource consuming). In Ivy the model is different and template compilation is performed first and translation happens after that. As a result in Ivy translations should not contain extra constructions like text bindings. The proposed solution is to refactor the logic in a template (may be split original i18n block into chunks, use ICU syntax or have an extra element with `*ngIf`) to avoid the need to add extra text bindings in translations.

The error that you mentioned in your message was caused by the fact that i18n runtime logic tried to parse the `{{ period }}` in translated message as an ICU and failed. I've just created a PR [URL] to verify whether ICU parsing was successful before ICU processing to provide more descriptive error message.

Thank you.
