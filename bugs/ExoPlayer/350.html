Title

Unable to (1) add okhttp as a gradle dependency to the demo application, and (2) build exoplayer modules locally in r2.7.2

Description
(1) Unlike r2.7.0, I am not allowed to import any okhttp3 classes in the demo application after adding `implementation project(modulePrefix + 'extension-okhttp')` to demo's build.gradle. Then, I proceed to directly add `implementation 'com.squareup.okhttp3:okhttp:3.10.0'` instead. Unfortunately, I am still unable to build the apk in the release mode successfully even though the proguard options suggested in [URL] are added to demo's proguard-rules.txt.

(2) I also tried to build exoplayer modules locally according to [URL] However, Android Studio warned that javadoc_util.gradle does not exist. To overcome this problem, I have to copy it to the root folder of my project.

Note that I didn't encounter the above problems before r2.7.0.
Discussion
- The correct thing to add to the demo app's build file would be:
```
implementation project(modulePrefix + 'extension-okhttp')
implementation('com.squareup.okhttp3:okhttp:3.9.0') {
  exclude group: 'org.json'
}
```
Which works fine for me. Having said that:
* We should consider using `api` rather than `implementation` for the dependency our OkHttp extension has on the OkHttp library, given using the extension requires application code using OkHttp library classes directly.
* The `javadoc_util.gradle` thing is an oversight, and is something we should fix.
- Thank you for your reply. It is true that everything works fine if using "debug" build type. However, I still fail to generate signed APK when the build type is chosen as "release" (i.e. both shrinkResources and minifyEnabled in demo's build.gradle are true).
