Title

Update "executeInTransaction" to Java8 style (Model, TransactionHandler).

Description
The proposal is to deprecate  executeInTransaction , which returns "Object" and have operations: 

  
     <T> T executeRtn( Supplier<T> action ) ;
 
  
 and the non-result version: 
  
     void execute( Runnable action );
 
  

 It helps in the IDE to have different names because they both start " ()->... ".  In my experience (Eclipse) completion and error messages are not good when there is the same name and ambiguity over the inferred type. Using the  ()->methodresultsvalue()  form is ambiguous. 

 For model, call them  executeInTxnRtn  and  executeInTxn .
Discussion
- This seems very reasonable to me. I have seen elsewhere a naming style  void execute( Runnable action )  vs.  T calculate( Supplier<T> calculation ) , which I like because it distinguishes them a bit more, but the basic idea of breaking apart  executeInTransaction  is definitely good.
- calculate  is an interesting name choice. 

 May we should use the same in  Txn .
