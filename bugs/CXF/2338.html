Title

JAX-RS Link implementation (LinkBuilder) looses context path

Description
I think I've discovered a bug in CXF, but I'm not sure. Link class 
messes links up, and doesn't include servlet and @ApplicationPath 
paths from BaseUri:
I have CdiServlet deployed at '/rest', 
	 I have Jax rs @ApplicationPath '/api' 
	 Account resource at  /account 
 

 I expect the following code to return links to my resources: 
~~~ 
        log.info(" – <<>> {}", uri.getBaseUri()); 
        return Response.ok().links( 

 Link.fromResource(AccountResource.class).baseUri(uri.getBaseUri()).rel("account").build(), 
  Link.fromResource(PlatformResource.class).baseUri(uri.getBaseUri()).rel("self").build() 
).build(); 
~~~ 
However, I get this on the client side: 
~~~ 
Link=[< [URL]
< [URL]
~~~ 
And I expected links with full path. like ttp://localhost:9001/rest/api/account 

 UriInfo returns the correct uri. Link messes it up. 
~~~ 
INFO  PlatformResource -  – <<>>  [URL]
~~~
Discussion
- I've tested with a relative path for the resource: @Path("account") instead of @Path("/account") and I get what I expect. It still ignores the @ApplicationPath part, however that seems to be caused by the deployment (I'm using embedded jetty with CDI ).
- I'm not sure what it is to do with Jersey but I was definitely able to reproduce the problem in CXF. I'll deal with this issue...
- ... [Middle Discussions Snipped for Brevity] ...
- Hi, I think CXF LinkBuilder impl should be 'immune' to the fact a root resource @Path starts with "/". ApplicationPath should be taken into the consideration too, so it appears we have to fix the issue  . I've already reopened and assigned to myself, but we can continue working on this issue together 
Cheers, Sergey
- The problem was that LinkBuilderImpl was using the URI resolution to compose the base URI and the original relative value. 
So if if we have say "[URL] and "a" then the "2" segment is lost and the final URI is "[URL]

 This is now fixed, Paths values starting from "/" will not affect the final URI. ApplicationPath should be kept as part of the link URI. Please try the snapshots.  
By the way, can you try Jersey and check how it deal with it ? Will it lose ApplicationPath ?
