Title

Custom platform cannot use built-in toolchains

Description
### Description of the problem / feature request:

When defining a custom platform, some built-in toolchains (e.g., `cc-toolchain-k8`) cannot be used because they declare a requirement for the `@bazel_tools//platforms:autoconfigured` constraint, which is not publicly visible. To workaround this, one would also need to register a copy of those toolchain definitions with the `:autoconfigured` requirement removed. Preferably, this constraint would be removed from the built-in toolchain so that it could be used with custom platforms.

### Feature requests: what underlying problem are you trying to solve with this feature?

Refer to [URL] and [URL] for context. We need to add constraints to `exec_compatible_with` for some test targets to support targeting some larger tests at different platforms for remote execution. In order for those tests to work when running locally, though, we also need to declare an alternative local platform that satisfies those constraints. However, this also necessitates defining an alternative to the built-in toolchains that require the `:autoconfigured` constraint.

### Bugs: what's the simplest, easiest way to reproduce this bug? Please provide a minimal example if possible.

- Declare a custom `constraint_setting` / `constraint_value`.
- Declare a `cc_test` target with `exec_compatible_with` including that `constraint_value`.
- Declare a custom platform to satisfy that constraint, e.g.:

```
python
# Based on output from:
# bazel query --output=build @bazel_tools//platforms:host_platform
platform(
  name = "host_platform-large",
... [Log Snipped] ...
  os_constraints = ["@bazel_tools//platforms:osx", "@bazel_tools//platforms:freebsd", "@bazel_tools//platforms:linux", "@bazel_tools//platforms:windows"],
)
```

- Register the platform in the `WORKSPACE` file.
- Run `bazel test --toolchain_resolution_debug` on the `cc_test` target defined earlier.
