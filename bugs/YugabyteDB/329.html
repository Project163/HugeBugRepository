Title

[YSQL] Valid queries were rejected with error `Given ybctid is not associated with any row in table: 0 vs. 1`

Description
This issue can be reproduced when querying data using secondary index.
Discussion
- This has been fixed by [URL]

It'll be available in the next build & release.
- I got something like this again.  Haven't been able to reproduce the issue, yet, but the way I got it was

1. Do test in issue #6097
1. Add more indexes so that you get

   ```sql
   \d tablename
   ```

   ```
Table "public.tablename"
    Column |  Type   | Collation | Nullable | Default
   --------+---------+-----------+----------+---------
    p      | integer |           | not null |
    i1     | integer |           |          |
... [Log Snipped] ...
       "tablename_i1_i2_idx1" lsm ((i1, i2) HASH)
       "tablename_i1_i2_idx2" lsm (i1 DESC, i2 DESC)
```

   The scans from here on will prioritize using the last index.

1. Verify things work when doing point selects

   ```
sql
   do $$
   declare
      a int := 0;
      b int := 0;
... [Log Snipped] ...
      raise notice 'value: %', b;
   end; $$;
```

   ```
   NOTICE:  value: 100000
   ```

1. Get the error when doing order by select

   ```sql
   BEGIN ISOLATION LEVEL SERIALIZABLE, READ ONLY, DEFERRABLE;
   with w as (select * from tablename order by i1 desc, i2 desc) select count(*) from w;
   ```

   ```
   ERROR:  Query error: Given ybctid is not associated with any row in table
   ```

   Stack trace:

   ```
   YBCGetStackTrace (src/yb/common/ybc_util.cc:287)
    @              errmsg (src/postgres/src/backend/utils/error/elog.c:867)
    @              HandleYBStatusAtErrorLevel (src/postgres/src/backend/utils/misc/pg_yb_utils.c:325)
    @              HandleYBStatus (src/postgres/src/backend/utils/misc/pg_yb_utils.c:309)
    @              HandleYBStatusWithOwner (src/postgres/src/backend/utils/misc/pg_yb_utils.c:362)
... [Log Snipped] ...
    @              (unknown) (sysdeps/x86_64/start.S:118)
    @  
```

   Trying the query again (after aborting the last transaction) results in the same error.  Trying the slightly different query

   ```sql
   BEGIN ISOLATION LEVEL SERIALIZABLE, READ ONLY, DEFERRABLE;
   with w as (select 1 from tablename order by i1 desc, i2 desc) select count(*) from w;
   ```

   gives the desired 100000 result.

Repeating _all_ the steps again with a different table name, I do not see the same "ybctid" error and get the desired 100000 result.  I have these two tables right now, and stopping/starting the cluster gives me the same results.  Since they take up disk space, I won't keep them for long, so let me know if you want to do some debugging on them.
