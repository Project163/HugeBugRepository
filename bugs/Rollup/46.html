Title

0.35.0 - Name collisions

Description
I've got a project that uses Three.js (been building fine in several prior rollup versions) and it's now failing in a browser as at line 40907 is:

```
Object.defineProperties( Material.prototype, {
    wrapAround: {
        get: function () {
            console.warn( 'THREE.' + this.type + ': .wrapAround has been removed.' );
        },
... [Log Snipped] ...
    }
} );
```

This is failing because `Material` was most recently defined as:

```
var Material = Object.freeze({
    ShadowMaterial: ShadowMaterial,
    SpriteMaterial: SpriteMaterial,
    RawShaderMaterial: RawShaderMaterial,
    ShaderMaterial: ShaderMaterial,
... [Log Snipped] ...
    Material: Material
});
```

Note that `Material` itself has a property referring to the earlier `Material` (a function).

It would seem this is meant to be a transpiled version of:

```
export { ShadowMaterial } from './ShadowMaterial.js';
export { SpriteMaterial } from './SpriteMaterial.js';
export { RawShaderMaterial } from './RawShaderMaterial.js';
export { ShaderMaterial } from './ShaderMaterial.js';
export { PointsMaterial } from './PointsMaterial.js';
... [Log Snipped] ...
export { LineBasicMaterial } from './LineBasicMaterial.js';
export { Material } from './Material.js';
```

from `src/materials/material.js` - although I'm not sure how it ended up with the name `Material`.

0.35.0 seems like a big step in the right direction with regard to future-proofing and is great work in general (Thanks!). I'm so sorry to be dropping bug reports like this!
