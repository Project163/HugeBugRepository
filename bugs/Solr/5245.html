Title

ClusterState getHostAllowList isn't always updated when live nodes change

Description
ClusterState.getHostAllowList was introduced in   SOLR-15217   to validate a host may be reached for distributed-search.  But it's a cached value computed from the live nodes, and the live nodes may change.  Thus it can happen that a new live node arrives, gets replicas, and suddenly, distributed-search fails with a 403 ("Forbidden"), with an error string containing this substring: "is neither a live node of the cluster nor in the configured".
Discussion
- I think the "hostAllowList" ought to not be on ClusterState; it ought to be in AllowListUrlChecker and cached there based on the latest liveNodes seen from ClusterState.  It's the only consumer.  ClusterState is an important SolrCloud abstraction; we should be conservative in adding methods there.  WDYT  broustant  ?
- I think I was misled at the PR time by the ClusterState javadoc that says "Immutable state of the cloud", whereas there is this setLiveNodes() method. 

 I agree, the host allow list would rather be computed and cached in AllowListUrlChecker. If we change the ClusterState.setLiveNodes() method to copy the parameter set in a new unmodifiable set, then AllowListUrlChecker can quickly check the ClusterState.getLiveNodes() object ref for change.
