Title

[YSQL][postgres_fdw] ERROR: Query error: The catalog snapshot used for this transaction has been invalidated: MISMATCHED_SCHEMA

Description
Jira Link: [Link: DB-1239]
### Description

Some SELECT queries fail sporadically in the regress tests even though no DDLs are running at the same time:
```
SELECT t1.a,t2.b,t3.c FROM fprt1 t1 INNER JOIN fprt2 t2 ON (t1.a = t2.b) INNER JOIN fprt1 t3 ON (t2.b = t3.a) WHERE t1.a % 25 =0 ORDER BY 1,2,3;
ERROR:  Query error: The catalog snapshot used for this transaction has been invalidated: MISMATCHED_SCHEMA
CONTEXT:  Catalog Version Mismatch: A DDL occurred while processing this query. Try again.
remote SQL command: SELECT r7.a, r10.b, r13.c FROM ((public.fprt1_p1 r7 INNER JOIN public.fprt2_p1 r10 ON (((r7.a = r10.b)) AND (((r7.a % 25) = 0)))) INNER JOIN public.fprt1_p1 r13 ON (((r7.a = r13.a)))) ORDER BY r7.a ASC NULLS LAST, r13.c ASC NULLS LAST
```
Discussion
- Probably a duplicate of [URL] but we should check that this is fixed too when it gets fixed. Is there a good way to handle this in regress tests? The best workaround I found is `select pg_sleep(1);`
