Title

Make CommandLineRunner more extensible

Description
To make Google closure compiler easier to integrate with other libraries, it would be good to change the accessibility of some methods of the AbstractCommandLineRunner which is the main entry point.
It will be particularly helpful to update the methods who deals with how to retrieve and write the JS contents.

I'm working currently on the integration of the closure compiler with Jawr (http://jawr.java.net/), and these modifications will greatly help me to achieve it.

I've attached a patch of the AbstractCommandLineRunner to this issue.

There is no particular test to make as it's only the update of the accessibility of some methods.
Discussion
- I'm not clear what you are trying to accomplish, the command line runner is intended to be used with the command-line.  If you are using the Java API, I would expect you to be using the interfaces that the AbstractCommandLineRunner uses.

Can you explain how these changes are helpful?
- Yes, it's true that the command line runner is inteded to be used with the command line.
But the fact is that this is also where you add new options to the compiler using arguments.
I've choosen to override the Command Line Runner, because I would like to allow the user to pass argument through my custom config to the Command Line Runner.
In that case, if the user wants to add a new option which was not available when my project was released, he will be able to do so without a new release of my project.
It helps me to decouple the version of my project used from the version of the closure compiler.

Don't hesitate to tell me if you need more clarifications.
