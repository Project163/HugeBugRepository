Title

task_reject_on_worker_lost settings does not work [Celery 4.0]

Description
It seems that the `task_reject_on_worker_lost` settings does not work when using Redis as broker. After the worker is killed (`kill -9  `) the task is lost and not restarted once the worker is back running.

## Checklist
- [X] I have included the output of ``celery -A proj report`` in the issue.
- [ ] I have verified that the issue exists against the `master` branch of Celery.
=> Tested with Celery `4.0.0rc7`

## Steps to reproduce
1. Create a task with `ack_late=True` and `reject_on_worker_lost=True`
2. Run task
3. Kill Celery while the task is running (e.g. with `kill -9  ` or pressing `Ctrl+C` twice)

See sample below.
## Expected behavior
The task is executed once the Celery worker is started again

## Actual behavior
Task is lost

```
import time
from celery import Celery
```
