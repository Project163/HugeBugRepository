Title

User defined pipes vs builtin pipes

Description
# 🐞 bug report

### Affected Package
 
  The issue is caused by package 
@angular/common


### Is this a regression?

I think it is.


### Description

User can define his own pipe with name `currency` for example. Previously angular used *user* pipe instead of builtin. Ivy does opposite silently.


## 🔬 Minimal Reproduction

You can copy & paste any pipe from `number_pipe.ts` modify its transform method and see that pipe will be ignored.

## 🔥 Exception or Error

No error, but it should be.

Discussion
- I doubt if it is possible in angular 9 as Injectable() have been removed from build-in pipes.
- Hi @kemsky, thanks for reporting the issue. We performed the investigation and it looks like the problem only happens in case custom Pipe is defined as a part of `declarations` array of an NgModule, i.e.:

```
@NgModule({
  imports: [CommonModule],
  declarations: [CustomNumberPipe],
})
class SomeModule {}
```
However if you declare a pipe in a separate module and import it, the framework works as expected, i.e.:

```
@NgModule({
  declarations: [CustomNumberPipe],
  exports: [CustomNumberPipe],
})
class CustomNumberPipeModule {}
... [Log Snipped] ...
})
class SomeModule {}
```

I've created a draft PR [URL] to make sure the `declarations` field has higher priority in the first case that I described.

Could you please confirm that the Pipes/NgModule layout that you have in your app is similar to the first scenario that I described?

Thank you.
