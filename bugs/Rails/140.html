Title

ActionController::Parameters#as_json has changed format

Description
`ActionController::Parameters#as_json` does not behave in the same way under Rails 4.2 and under Rails 5.0.0.beta1.

In my opinion, this is a regression and can easily be fixed, but before submitting a patch, I would like to know the opinion of @sikachu who worked on having AC::Parameters not inherit from Hash [URL]

Reproducing the issue is really easy: just run `ActionController::Parameters.new(hello: :world).as_json`.

``` ruby
# under Rails 4.2
ActionController::Parameters.new(hello: :world).as_json
# {"hello"=>"world"}

# under Rails 5.0.0.beta1
ActionController::Parameters.new(hello: :world).as_json
# => {"parameters"=>{"hello"=>"world"}, "permitted"=>false} 
```

The reason is that [Link: Object#as_json] checks whether the object `respond_to?(:to_hash)` and, [Link: as already commented], `ActionController::Parameters#to_hash` will no longer work in Rails 5.0+ as we stop inheriting Parameters from Hash.
Discussion
- Is the solution to use `ActionController::Parameters#to_unsafe_hash`? Not a fan of the idea that we would have to possibly write over the existing `Object#as_json` monkey patch with another monkey patch, to change it to use `to_unsafe_hash` instead of `to_hash`...
- I think it's just a side-effect that was overlooked when I disconnected the Hash. I think the expected result should be a linear-ish Hash, as in Rails 4.2, a la  `{"hello"=>"world"}` should be the expected result.

Regarding the other issue, I think it's better to keep using `to_h`. If user want to print out the whole params without caring about the whitelisting they can already do `to_unsafe_h`. I don't feel like exposing the unsafe hash by default is a great idea.
- @sikachu If I understand correctly, you propose to add an `as_json` method to the `ActionController::Parameters` class defined like this?

``` ruby
def as_json(options = nil)
  to_h.as_json(options)
end
```
- @claudiob that's correct, or you can just use `delegate` as well.
