Title

Enums in switch/case statements that are not fully qualified will cause a groovy compile error but Java requires enums to "not" be fully qualified

Description
This is a difference in Java vs Groovy behaviour. Enums must be fully qualified in Groovy while Java requires them to not be fully qualified. 

  This was supposedly fixed, but does not seem to work in 4.0.24. Not sure where it broke.  

 Example: 
  
 
void test( Thread .State ts) {
   switch  (ts) {
     case   Thread .State.NEW:  // cannot remove  " Thread .State."  without @CompileStatic
        break 
  }
}
