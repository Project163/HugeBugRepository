Title

Error when building using cmake through Bazel on OSX

Description
Hi there,

I'm getting an error when building the library from source with Bazel using an external dependency rule. I believe that this problem is related to bazel defining DEBUG to be 1, which they claim is the [Link: correct behavior] on MacOSX. The word DEBUG is used in at least one place in the code base and this creates problems. Here is the error:

```
/var/tmp/_bazel_grantreszczyk/ /sandbox/darwin-sandbox/12/execroot/__main__/external/glfw_src/tests/glfwinfo.c:361:39: error: expected identifier
    enum { CLIENT, CONTEXT, BEHAVIOR, DEBUG, FORWARD, HELP, EXTENSIONS, LAYERS,
                                      ^
 :2:15: note: expanded from here
#define DEBUG 1
... [Log Snipped] ...
make[1]: *** [tests/CMakeFiles/glfwinfo.dir/all] Error 2
make: *** [all] Error 2
```

When I compile with optimization flags, the library builds as expected.
Discussion
- I find it strange that the development environment would rely on a non-reserved identifier this way, but it's easy enough to work around on our end.

Note that it's only the "glfwinfo" test program that triggers the issue, not the library itself. It should be possible to configure your dependency (sorry, I don't know anything about Bazel) to skip building the test and example programs if all you want is the library itself.
