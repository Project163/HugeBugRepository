Title

Wayland: key repeat events should be handled when keyboard listener receives leave event

Description
Wayland requires clients (applications) to handle keyboard repeat events themselves. The GLFW implementation does so during the event loop, however the current implementation does not correctly handle the interaction with a window losing focus.

This has resulted in issue #2727 with a workaround fix in merged PR #2732 which ignores repeats when no window has focus. This could result in lost events and potentially an application with multiple GLFW windows receiving key repeat events to the wrong window. **EDIT: After further debugging #2741 shows why this occurs, however repeat key handling should still occur in the leave event**

A full fix would require handling the repeat events when the window loses focus.
Discussion
- As per my edit above issue #2727 with a workaround fix in merged PR #2732 was likely due to a window being destroyed which does not reset the repeat timer. This issue is still valid, but not the cause of that bug.
