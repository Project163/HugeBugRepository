Title

Occasional/intermittent FATAL during remote bootstrap: flushed opID higher than in WAL

Description
During remote bootstrap, currently, it is possible to hit an intermittent/rare issue where we can send log (WAL) files that are behind RocksDB files, and when this happens, the TServer receiving the files fatals with this message:
    
```
Check failed: state.prev_op_id.term() >= state.committed_op_id.term() && state.prev_op_id.index() >= state.committed_op_id.index()
```
    
This happens because we currently allow any entry that has been appended to the log (and Sync'ed by majority, but not necessarily Sync'ed in the tablet server's "own" local log) to be flushed by RocksDB; and because a RocksDB checkpoint internally results in a flush, it is possible that the RocksDB files that we send to the new node during a Remote Bootstrap session are ahead of the log files that we send to the same node.
