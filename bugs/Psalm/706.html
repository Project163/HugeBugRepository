Title

Incorrect type inferred after index-based string modification inside array

Description
Given a string, we can change a character at an index quite easily.

```php
$a = 'abc';
$a[0] = 'd';
var_export(bin2hex($a));
```

If we do the same thing with a string inside an array, Psalm will infer an incorrect type for the string:

```php
$b = ['abc'];
$b[0][0] = 'd';
var_export(bin2hex($b[0]));
```


[Link: Example on psalm.dev]

Am I missing an implicit conversion rule, or is this a bug?
