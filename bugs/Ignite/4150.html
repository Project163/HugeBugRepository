- Just for upd. 

 I've found a number of issues that are fixed in the PR, but the test still fails, however other TC tests looks good. 
For now, the issue with unexpected tx state looks resolved, but sometimes latest entry updates can be missed after rebalance. 

 What was done: 
 
	 entry full history is sent within single message and apply either entire history or nothing under same entry lock. 
	 fix version hints usage in "update with history" operation. 
	 minor code cleanup.
- The main issue is Rebalance iterator can cache rows and doesn't coordinates with Vacuum, so cached rows can easily become stale.  
E.g. Vacuum has completed after iterator read rows from page and before cursor requests next row from iterator. In this case cursor can get row without hints, and TxLog has no states for the row versions anymore. 

 Usually, an mvcc cache iterator is used with snapshot in queries that prevents Vacuum from cleaning up TxLog, but rebalance iterator takes no snapshot. 

 Seems, we have to actualize row states on read instantly, to make sure all committed rows will be rebalanced.  
Note, vacuum should see real row state as it stored in data page.
