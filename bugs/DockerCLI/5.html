Title

tcp_fin_timeout is not utilized from host kernel

Description
### Description

`/proc/sys/net/ipv4/tcp_fin_timeout` is not utilized when application connections within a docker container are sending a `FIN_WAIT2.`

The default should be a 60 seconds timeout. The file is completely missing inside a Docker container.

Also setting the timout by hand with `sysctl` does have no effect and returns a `File oder directory not found`

In our case where we have a small KVM-Qemu inside a Docker container with a TCP service.
Every client who disconnects will be `CLOSED` in KVM also on the host systen BUT NOT within Docker.

If we do a `netstat -tunp` we get a list of all disconnected clients still in `FIN_WAIT2` state for example:

```
snip....
tcp        0      0  :443          :47464      FIN_WAIT2   7/qemu-system-x86_6
tcp        0      0  :443          :37036      FIN_WAIT2   7/qemu-system-x86_6
tcp        0      0  :443          :50331      FIN_WAIT2   7/qemu-system-x86_6
tcp        0      0  :443          :4387      FIN_WAIT2   7/qemu-system-x86_6
tcp        0      0  :443          :27624      FIN_WAIT2   7/qemu-system-x86_6
```

These entries will never be cleared and at some point the Container crashes due to max open file descriptors.

### Reproduce

1. Create a Docker container with QEMU-KVM
2. Create a service within the KVM guest (inside of Docker) such as a Webservice or any other service
3. Forward ports from Host to Docker to KVM (for example: `docker run ... -p 8080:80 ...`)
4. Use Userforward of KVM inside docker to redirect port 80 to KVM (for example: `-net nic,model=virtio -net user,hostfwd=tcp::80-:80`
5. Connect to Docker by port 8080 and close the connection.


### Expected behavior

Connections should be closed or terminated and cleared from Kernel FD table.

Discussion
- **Addendum:**
We tested Docker v23.0.1 with a Debian 11.6 host instead of CentOS.

As far as we can see, Debian seems to work (we did not test our image directly), in Debian `/proc/sys/net/ipv4` does have way more control files then CentOS, also the missing `tcp_fin_timeout`.

Could this be Docker on CentOS related issue?
- From your last comment, I suspect this may be related to the kernel; a quick search brought me to [URL] which namespaced this sysctl, and (if GitHub shows it correctly) that change was part of kernel 4.6-rc1 and up (from [URL] it looks like the sysctl itself was part of kernel 2.6 already, but not namespaced).

RedHat's (CentOS) kernels are known to have back ported various features though, so not sure if that change was back ported by them.
- I would agree that this is Kernel related, especially since your linked commit and comparing the current Kernel in CentOS 7.9 (which is still 3.10).

Even this may be obsolete in the future, is there a way for the Docker engine to set fallback or default values for missing Kernel parameters just like the tcp_fin_timeout option?
