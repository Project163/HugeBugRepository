Discussion
- Hi,
This behavior isn’t really a React bug—it’s caused by Strict Mode in React 18 during development. Components are mounted, unmounted, and remounted, which can make timers or state updates behave unexpectedly.

In production, this usually doesn’t happen. Using functional state updates (setState(prev => …)) makes your timer reliable in both dev and prod.

I’m curious—have you tried this approach, or do you also see isExpired staying false even when using functional updates?
- Thanks for reporting, this was a legit bug where we didn’t make onClick depend on isExpired. Fixed in the linked PR!
