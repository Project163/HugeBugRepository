Title

1.4.0b2+ no longer calls dispose on InstrumentationManager

Description
**Describe the bug**
I have a custom `InstrumentationManager` extending `sqlalchemy.ext.instrumentation.InstrumentationManager`.

`InstrumentationManager` uses `_default_class_manager` as the attribute where it stores the class manager instead of the default one `_sa_class_manager`.


**Expected behavior**
`sqlalchemy.orm.clear_mappers()` should remove the attribute `_default_class_manager` from the mapped class. So creating a new mapper afterwards is possible.

Until [URL] this was the case because `manager.dispose` delegated to `InstrumentationManager.dispose` which removes the attribute.

With the change in 1.4.0b2 `ClassManager` just tries to remove the attribute named `self.MANAGER_ATTR` (which in this case has the value of `'_sa_class_manager'`).
See [URL]


**To Reproduce**

```
py
from sqlalchemy.ext import instrumentation
from sqlalchemy import Column, Integer, Table, String, create_engine
import sqlalchemy.orm
import sqlalchemy.schema
... [Log Snipped] ...

print('Success!')
```

**Error**

happens on the second call to `sqlalchemy.orm.mapper`: 
```
Traceback (most recent call last):
  File "example.py", line 53, in  
    mapper = sqlalchemy.orm.mapper(MyTable, table)
  File " ", line 2, in mapper
  File " ", line 2, in __init__
... [Log Snipped] ...
    % self.class_
sqlalchemy.exc.ArgumentError: Class ' ' already has a primary mapper defined.
```

**Versions.**
 - OS: MacOS 10.15.7
 - Python: 3.7.10
 - SQLAlchemy: 1.4.11
 - Database: any (not dependent on database)

**Additional context**

* I added my current workaround as a comment to the example. – Maybe this is not the way to go but it seems to work.
