Title

[YSQL] Add conflict b/w row lock and DELETE for colocated table

Description
Row locking statements should conflict with DMLs like `DELETE` and `UPDATE`.  That does not seem to be the case for colocated tables.

| Session A | Session B |
| --- | --- |
| `CREATE TABLE t (i int, PRIMARY KEY (i ASC))` | |
| `INSERT INTO t VALUES (1)` | |
| `BEGIN ISOLATION LEVEL SERIALIZABLE` | |
| `SELECT * FROM t FOR UPDATE` | |
| | `DELETE FROM t WHERE i = 1` |
| `COMMIT` | |

On a non-colocated table, the last commit errors with

```
ERROR:  Error during commit: Operation expired: Transaction expired or aborted by a conflict: 40001
```

On a colocated table, the last commit succeeds.
Discussion
- I think that I have discovered the root cause.  On some code paths, the `DocKey` does not have a cotable id when it should.  This causes other weird bugs like an unwanted conflict between two different tables.

| Session A | Session B |
| --- | --- |
| `CREATE TABLE t (i int, PRIMARY KEY (i ASC))` | |
| `CREATE TABLE t2 (i int, PRIMARY KEY (i ASC))` | |
| `INSERT INTO t VALUES (1)` | |
| `INSERT INTO t2 VALUES (1)` | |
| `BEGIN ISOLATION LEVEL REPEATABLE READ` | |
| | `BEGIN ISOLATION LEVEL REPEATABLE READ` |
| `SELECT 123` | |
| | `SELECT 123` |
| `SELECT * FROM t FOR UPDATE` | |
| | `SELECT * FROM t2 FOR UPDATE` |
| `COMMIT` | |
| | `COMMIT` |

One of the commits conflicts when there should be no conflicts because each transaction acts on different tables.  This seems to stem from `EnumerateIntents` getting called with the key `SubDocKey(DocKey([], []), [])` rather than a key like `SubDocKey(DocKey(CoTableId=06400000-0000-0080-0030-000005400000, [], []), [])` in some cases.
- This seems to come from `CreateReadIntents` -> `GetIntents` not handling cotable id.
