Title

Write alias resolution doesn't work with TSDS with lookahead.

Description
### Elasticsearch Version

main

### Installed Plugins

_No response_

### Java Version

_bundled_

### OS Version

n/a

### Problem Description

### Expected behaviour

As a user when I use a write alias pointing to a TSDS data stream I expect indexing will be directed to the correct index. 

### Current behaviour

When we try to index a document to TSDS via the write alias right after a rollover and for the duration of the lookahead, the write alias resolves to the latest index, which is in most cases not the correct one until the lookahead time passes.

### Steps to Reproduce


1. Create a TSDS template
```
PUT _index_template/my-tsds-test
{
  "index_patterns": ["my-tsds-test-*"],
  "data_stream": { },
  "template": {
... [Log Snipped] ...
  }
}
```

2. Index documents with the current timestamp 
```
PUT my-tsds-test-index/_bulk
{ "create":{ } }
{ "@timestamp": "2024.01.10T09:23:00.000Z", "name": "HAL-000001" }
{ "create":{ } }
{ "@timestamp": "2024.01.10T09:23:00.000Z", "name": "SYKENET-000001" }
```

3. Perform a rollover, during which a new index is added `-000002` but documents with the current timestamp should still go to the `-000001` because of the lookahead time.
```
POST my-tsds-test-index/_rollover
```
4. Try to write documents using write alias
```
PUT my-tsds-test-index-write-alias/_bulk
{ "create":{ } }
{ "@timestamp": "2024.01.10T09:24:00.000Z", "name": "HAL-000002" }
{ "create":{ } }
{ "@timestamp": "2024.01.10T09:24:00.000Z", "name": "SYKENET-000002" }
... [Log Snipped] ...
  ]
}
```

- Hi,
I took a look into this and I think the source of the issue is when TransportBulkAction goes to [Link: process the request]. The concrete write index is determined by `ia` (by calling `ia.getWriteIndex(...)`). 
When you run the request via the data stream name, `ia` is a DataStream and if the DataStream is a time series data stream specifically it uses the timestamp to [Link: calculate] the correct index . 
But when you run the request via the alias, `ia` is an Alias and it just uses whatever [Link: index] is in its `writeIndex` field. For aliases to data streams, the `writeIndex` is the latest backing index.

To fix this I think the Alias class probably needs some way of knowing that it's a time series data stream, or perhaps a reference to the DataStream itself. 
From what I can tell the `referenceIndices` field in Alias contains all of the backing indices, so it might just be a matter of adding an extra `isTimeSeries` boolean and doing the timestamp logic on `referenceIndices`.
