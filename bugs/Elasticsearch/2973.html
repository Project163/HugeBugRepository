Title

Repository analysis should not retry partial reads

Description
Today `GetBlobChecksumAction` uses the same read path as for regular snapshot blob reads, which (for S3 and GCS repositories at least) will resume the download if it fails part-way through. Sometimes we will overwrite the blob while the read process is ongoing, and in that case the resumed download may see a different blob contents from the original. This is reported as a checksum mismatch, incorrectly indicating an atomicity failure in the repository. It would be better not to resume the download and instead to report that the analysis failed because the read was incomplete.
