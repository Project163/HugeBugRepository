But it's awkward that we have both `Tuple[int, float, fallback=Derived]` and `Derived` as distinct types. Maybe `is_equivalent` should consider them equivalent? I'm not sure I totally understand the design around NamedTuple types.
- `Tuple[int, float, fallback=Derived]` is the actual named tuple type, which approximates an intersection of an `Instance` (`Derived`) and the special features of the corresponding tuple type. This is not entirely true as the tuple type features take precedence over `Instance` features when there is ambiguity.

`Tuple[...]` itself, if we ignore the fallback, only provides a few tuple-specific magic features such as `t[n]` where `n` is an integer literal. When these features aren't important we can safely fall back to the fallback instance type.

Your diff seems right, as there is conceptually a one-to-one mapping between `Tuple[int, float, fallback=Derived]` and `Derived`. They aren't equivalent but one can't normally exist without the other, except in intermediate steps within the type checker, as seems to be the case here.
