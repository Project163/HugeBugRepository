Title

Hash::combine() returns incorrect key-value pair, when value path not found

Description
in CakePHP 2.4.2

``` php
    $arr = array(
        array('id' => 1, 'first' => array('title' => 'foo')),
        array('id' => 2, 'first' => array('title' => 'bar'), 'second' => array('title' => 'bar2')),
        array('id' => 3, 'first' => array('title' => 'hoge'), 'second' => array('title' => 'hoge2')),
    );
    $result = Hash::combine($arr, '{n}.id', '{n}.second.title');
```

I expected returns like that

``` php
array(
    1 => null,
    2 => 'bar2',
    3 => 'hoge2',
);
```

But, I've got

``` php
array(
    1 => 'bar2',
    2 => 'hoge2',
    3 => null,
);
```

I think in this case combine method should be returns correct pair or throw exception/warning.
Discussion
- It's because the way `Hash::extract()` works. Basically `Hash::combine()` is doing a:

``` php
$vals = Hash::extract($src, '{n}.second.title');
```

This call does not return `null` if the value is not found; it simply return the one that does. When there's an inequality in the number of keys and values, one does not know which key hasn't got their value (or vice versa).

I can see a fix for your issue, but what if it is a value which doesnt have a corresponding key? (Switch the two last arguments for your `combine()` call). What then?

This is what we would call "undefined behavior" in C, but I cannot see a fix which involves fixing both circumstances (without changing too much in the outlined methods).
- One option that will possibly would solve this but may break other uses would be to throw exceptions when the length of both arrays is not equal. I will check how the native array_combine as it would be nice to reflect that behaviour if possible.
