Title

ESLint crashes when using a plugin without rulesConfig

Description
ESLint 0.9.0 throws the following exception if you use a plugin that doesn’t export the `rulesConfig` property.

```
./node_modules/eslint/lib/config.js:86
            Object.keys(plugin.rulesConfig).forEach(function(item) {
                   ^
TypeError: Object.keys called on non-object
    at Function.keys (native)
```

First uncovered `else` will never happen. I put it there just for defensive purposes, but there's already a check in `getConfig`, so the whole `if` statement can be safely removed. The second `else` statement is going to be tough to check. I guess I could modify one of the tests to validate multiple files, but I'm not 100% sure it's worth the effort.
- @ilyavolodin We are talking about unit-tests, the unit-test of the `CLIEngine` is not responsible to test the functionality of  `Config`.
However, the tests didn’t fail because we used proxyquire to stub the require path of the example plugin. This require stub only affects the `cli-engine.js` file but not the `config.js` file. In `config.js` the plugin gets required in a `try`-block which fails and within the `catch`-block the plugin is assigned to a new object with `rulesConfig` property.
