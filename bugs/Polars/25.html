Title

Left join sensitive to order of operations with new streaming engine

Description
### Checks

- [x] I have checked that this issue has not already been reported.
- [Link: x] I have confirmed this bug exists on the [latest version] of Polars.

### Reproducible example

```
python
import polars as pl
import random

# Create data for parent_df
... [Log Snipped] ...
joined_df = joined_df.select("parent_field1")
print(joined_df.collect(new_streaming=True))
```

### Log output

```
shell
polars-stream: updating graph state
polars-stream: running in_memory_source in subgraph
polars-stream: running equi_join in subgraph
async thread count: 4
... [Log Snipped] ...
│ 26            │
└───────────────┘
```

### Issue description

In the first case (joining the rightmost tables first, then the result with the left one), with new_streaming my left join behaves as an inner join.
In the second case (where I make the joins from left to right) it works as expected.

### Expected behavior

`a.join(b.join(c))` yields same result as `a.join(b).join(c)`

With the old streaming engine or with polars

- The problem was introduced when I added sampling to the join. As a temporary workaround you can specify the environment variable `POLARS_JOIN_SAMPLE_LIMIT=0`.
