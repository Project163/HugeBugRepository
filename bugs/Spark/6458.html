Discussion
- FWIW, I met this issue a while ago too (and I gave up with using this at that time and forget to debug it ahead).
- Yep. I'm also able to observe this for all Spark 2.X (2.0 ~ 2.3). `toLocalIterator` is introduced at Spark 2.0.
- I could also reproduce with a nearly identical error using the following 

  
 
 import  time
from pyspark.sql  import  SparkSession
from pyspark.sql.functions  import  rand, udf
from pyspark.sql.types  import  *

spark = SparkSession\
        .builder\
        .appName( "toLocalIterator_Test" )\
        .getOrCreate()

df = spark.range(1 << 16).select(rand())

it = df.toLocalIterator()

print(next(it))
it = None

time.sleep(5)
spark.stop()
 
  

 I think there are a couple issues with the way this is currently working. When toLocalIterator is called in Python, the Scala side also creates a local iterator which immediately starts a loop to consume the entire iterator and write it all to Python without any synchronization with the Python iterator. Blocking the write operation only happens when the socket receive buffer is full.  Small examples work fine if the data all fits in the read buffer, but the above code fails because the writing becomes blocked, then the Python iterator stops reading and closes the connection, which the Scala side sees as an error.  I can work on a fix for this.
