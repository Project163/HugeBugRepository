Title

bazel clean should remove all matching convenience symlinks

Description
Currently, `bazel clean` removes only the [Link: convenience symlinks] that Bazel knows about. However, if the workspace directory name changes, the `bazel- ` symlink name changes, meaning that `bazel clean` will now not clean that symlink. A more robust approach would be to delete any symlink starting `bazel-` (or whatever the value of the `--symlink_prefix` flag is), that points into the output tree. We might need to gate this behavior change behind a flag.

This issue comes from #5506. Note that even if the fix requested in #5506 was implemented, the potential for `bazel clean` to be out of sync with the workspace state would still exist: if a user changed the name of the workspace inside the global `WORKSPACE` file we would have the same problem.

The fix should be relatively straightforward: instead of looping through the hard-coded convenience symlink suffixes, do a listing of the root directory, and for each file that matches the symlink prefix, check to see if it is a symlink into the output tree. If so, delete it.

cc @mhy1992
Discussion
- I’ve experienced this one, and seen other people do so also. The proposed cleaning improvement would be quite helpful to people during the adoption process when workspace (and other) names tend to get adjusted a lot.
