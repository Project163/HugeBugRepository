Title

Array serialization broken for arrays of custom serialized types due to incorrect array type

Description
I have been setting up the xUnit v3 preview packages on my company code base to identify any breaking changes that we can proactively fix before the official release. Unfortunately there seems to be an issue with arrays of enums causing the following error to occur during the test run:

Catastrophic failure: System.Collections.Generic.KeyNotFoundException: The given key 'IXunitSerializer' was not present in the dictionary.

Screenshot:

[Image: image]

I narrowed down the issue manually by running smaller and smaller sets of tests until I ended up with a number of tests causing problems. Below is some sample code you can run to reproduce the issue:

```
public class Test
{
	public enum Numbers
	{
		One = 1,
... [Log Snipped] ...
	}
}
```
Package versions:

Runner: 3.0.0-pre.42
xunit.v3: 0.50-pre.27

[Image: image]

If you need any more information, please let me know.
Discussion
- This was an oversight when serializing arrays of custom serialized types that we'd need to know the exact array type. It was currently being deserialized as `object[]` which wouldn't correctly cast back to the original array type.

I have a fix building for the core framework now, then I'll create a new build of the Visual Studio adapter as well (as the bug surfaces there, despite being a core framework bug).
- This is available in:

* v3 core framework `0.6.0-pre.6`
* xunit.runner.visualstudio `3.0.0-pre.49`

Please upgrade both when testing the fix. [URL]
