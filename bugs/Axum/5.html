Title

Get a 301 when request is "CONNECT tokio.rs:443 HTTP/1.1"

Description
Cargo.toml
```
toml
[package]
edition = "2021"
name = "connect"
version = "0.1.0"
... [Log Snipped] ...
axum = {path = "../.."} # main branch
tokio = {version = "1.0", features = ["full"]}
```

src/main.rs
```
rust
use axum::body::Body;
use axum::routing::connect;
use axum::http::Request;
use axum::Router;
... [Log Snipped] ...
    dbg!(req);
}
```

```
$ curl -v -x " :3000" [URL]

*   Trying  :3000...
* TCP_NODELAY set
* Connected to   ( ) port 3000 (#0)
... [Log Snipped] ...
* Closing connection 0
curl: (56) Received HTTP code 301 from proxy after CONNECT
```

If we add a block code after line 778 in routing/mod.rs and add a fallback in `Router`, than we will bypass:
```rust
if path == "" {
    if let Some(fallback) = &self.fallback {
        return RouterFuture::from_oneshot(fallback.clone().oneshot(req))
    }
}
```
```rust
    let app = Router::new()
        .route("/", connect(handler))
        .fallback(handler.into_service());
```

The CONNECT request format is valid, we should not use fallback().
In v0.2.* has a same problem get a 404: [URL]
Discussion
- I think we need to rework axum's `CONNECT` handling a bit. I wasn't aware that request targets for `CONNECT` must be `{host}:{port}` and cannot contain a path. Thats what [Link: the spec says at least].

Therefore I think requiring a path to add a connect route doesn't really make sense. Something like `Router::new().on_connect(some_service)` would probably be better. Having to use `fallback` is quite unintuitive IMO.

Hyper has a proxy example [Link: here] that we can draw inspiration from.
- @jplatte what do you think?
- I'm not super familiar with `CONNECT` but have had a quick look at the MDN docs & discussion above.

Would proxies have much use for path routing at all? Maybe a solution that doesn't involve the `Router` type would make more sense for this specific use case.
- Yeah thats a good point. Honestly I'm thinking if we should fully remove `CONNECT` handling from axum for 0.3. Warp doesn't have it either. One would then have to write a `Service` that handles `CONNECT` requests and routes between that and some axum `Router`. I made a quick example [Link: here].
