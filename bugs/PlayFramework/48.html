Title

Cannot use injector.instanceOf() with @Cached

Description
### Are you looking for help?

No

### Play Version (2.5.x / etc)

2.6.1

### API (Scala / Java / Neither / Both)

Java

### Operating System (Ubuntu 15.10 / MacOS 10.10 / Windows 10)

Windows 7

### JDK (Oracle 1.8.0_72, OpenJDK 1.8.x, Azul Zing)

java version "1.8.0_131"
Java(TM) SE Runtime Environment (build 1.8.0_131-b11)
Java HotSpot(TM) 64-Bit Server VM (build 25.131-b11, mixed mode)

### Library Dependencies

No

### Expected Behavior

Please refer the following code.
```
@Inject
play.inject.Injector injector;

@play.cache.Cached(key = "somewhat")
public Result index() {
  AnyClass o = injector.instanceOf(AnyClass.class);
  return ok();
}
```

I hope the instance of `AnyClass` will be retrived as expected.

### Actual Behavior

In fact, the injector throw an exception in DEV mode in sbt interactive mode.

```
! @74j450acf - Internal server error, for (GET) [/] ->

play.api.http.HttpErrorHandlerExceptions$$anon$1: Execution exception[[CompletionException: java.lang.SecurityException: setContextClassLoader]]
        at play.api.http.HttpErrorHandlerExceptions$.throwableToUsefulException(HttpErrorHandler.scala:255)
        at play.api.http.HttpErrorHandlerExceptions.throwableToUsefulException(HttpErrorHandler.scala)
... [Log Snipped] ...
        at play.inject.DelegateInjector.instanceOf(DelegateInjector.java:22)
        at controllers.Home.index(Home.java:49)
```

In PROD mode, the code works as expected.

### Reproducible Test Case

Just use the attached code as before.

- I finally found time to write a test to confirm `SecurityException` will not be thrown anymore when using `map`, `filter`, etc. on a **parallel** stream within a Play action method. See #9594

However, when using `CompletableFuture.supplyAsync(...)` and `thenxxxAsync` methods you still have to pass an explicit ec, because Java uses the common thread pool for this method by default. There is nothing Play can do about this (it's no an issue with Play actually).
