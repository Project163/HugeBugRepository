Title

Subsequent save operation on interpreter add whitespace to permissions

Description
The zeppelin-web adds whitespaces on permissions, when saving interpreting settings the second time after permissions were added. 

 So when adding permissions, the initial save operation works fine.  
 e.g.  owners: ["admin"]  is defined and send to the server. 

 But when invoking subsequent save operations without modifying the permissions, then the invalid whitespace is added to the permissions: owners: ["admin "] .
