Title

searchpos broken for backwards movements ('bnz' and 'bz')

Description
### Neovim version (nvim -v)

NVIM v0.7.0-dev+1233-gabbc9148d

### Vim (not Nvim) behaves the same?

yes

### Operating system/version

linux

### Terminal name/version

alacritty

### $TERM environment variable

xterm-256color

### Installation

build from repo

### How to reproduce the issue

nvim file
file:
```txt
{  }
   x (pos1)
{  }
   x (pos2)
```
Cursor position is at x (first example)
:call searchpos('{', 'bz', 1)
pos1: no match
pos2: match
:call searchpos('{', 'bz', 1)

1. bug does move to wrong position (one line upwards) or not at all
2. with 'n' and at least in lua does fail, if not at least row-1 is used (resulting in 0 or any match for line=1)
This requires then additional quirky checks, ie with
```lua
  if (srow == 0 and scol == 0 and backwards == true) or srow ~= crow
    or (backwards == true and ccol < scol) then
    print 'no matching backwards character'
    return
  end
```

### Expected behavior

1. correct stopline logic (end of line for forward and begin of line for backwards)
2. correct cursor movement (no jumping over result, though I did not test the vimscript result for 'nbz')

### Actual behavior

1. stopline logic is broken for backwards movements
2. jumping over result for 'bz'
