Title

Ruby segfault at 1.74.0

Description
### What version of gRPC and what language are you using?

grpc-ruby 1.74.0

### What operating system (Linux, Windows,...) and version?

Linux (running on Google Cloud Run with ruby:3.4.4-slim-bookworm base image)

### What runtime / compiler are you using (e.g. python version or version of gcc)

Ruby 3.4.4

### What did you do?

Executed Google Cloud Tasks client task creation operation using the `google-cloud-tasks` gem (version 3.0.2) in a Ruby application running on Google Cloud Run.

### What did you expect to see?

Normal communication with Google Cloud API and successful task creation.

### What did you see instead?

Application crashes with a segmentation fault. The crash occurs almost always but not 100% of the time.

**Stack trace:**
```
[BUG] Segmentation fault at  
ruby 3.4.4 (2025-05-14 revision a38531fd3f) +YJIT +PRISM [x86_64-linux]
-- Control frame information -----------------------------------------------
c:0001 p:---- s:0003 e:000002 DUMMY  [FINISH]
-- Threading information ---------------------------------------------------
... [Log Snipped] ...
/lib/x86_64-linux-gnu/libc.so.6( ) [ ]
/lib/x86_64-linux-gnu/libc.so.6( ) [ ]
```

The segmentation fault appears to occur within the grpc_c.so native extension, specifically during method lookup operations.

### Anything else we should know about your project / environment?

- Running on Google Cloud Run with ruby:3.4.4-slim-bookworm base image
- Using google-cloud-tasks gem version 3.0.2
- The crash occurs almost always but not 100% of the time (intermittent issue)
- Ruby thread count shows 22 threads at crash time
- The fault occurs at memory address  , suggesting a null pointer dereference
- Stack trace indicates the crash happens during Ruby method resolution within the gRPC C extension
