Title

Arguments in `__truediv__` and `__itruediv__` is not specified as positional-only

Description
When I name a function `__div__` or `__idiv__`, it seems to have different type signature from normal functions.
Is it intended behavior?


## Code to reproduce

```
$ cat main.py
class A:
    def f(self, other: int) -> int:
        pass

... [Log Snipped] ...
$ mypy --version
mypy 0.782
```
Discussion
- Mypy knows that these are standard operator overloads and those have positional-only parameter lists. So yes, this is intended. The anomaly here is actually `__[i]truediv__`, which ought to be treated the same way but isn't.
- By the way, should I explicitly annotate that they are positional-only:

```python
class C:
    def __add__(self, other: int, /) -> int:
        ...
```

or not? If we are encouraged to do that, would we make a new option, say, `--disallow-operator-overload-with-keyword-argument`, to prevent not to use `/` in positional-only operator overloads?
- There's no need to annotate them as positional-only.
