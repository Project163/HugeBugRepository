I have a Python file with the following simple function definition.

```
def printstr(in_str):
    """

    Example:

... [Log Snipped] ...

printstr("c:\\")
```

I then run flake8 as follows:

```
$ flake8 --doctests flake8test.py 
flake8test.py:8:27: F999 syntax error in doctest
```

It's unclear to me why line 8 of this file ```      >>> printstr("c:\\")``` would be considered a syntax error; line 14 does not produce this same error (despite being the same code outside of a docstring).

Is this a bug with the escape character or am I missing something?
Discussion
- In GitLab by @sigmavirus24 on Aug 23, 2016, 07:25

So, this is actually coming from pyflakes I think (since `--doctests` is provided by pyflakes). That said, you can also see this behaviour by doing:

```
python3.5 -m doctest flake8test.py
```

That said, pydocstyle would advice you (since you have a `\` in your docstring) to prefix the docstring with `r`, e.g.,

```
py
def printstr(in_str):
    r"""

    Example:
... [Log Snipped] ...

printstr("c:\\")
```

When I do that, `flake8` and `pyflakes` does not report a Syntax Error and `python3.5 -m doctest flake8test.py` gives me

```
c:\
**********************************************************************
File "~/t.py", line 8, in t.printstr
Failed example:
    printstr("c:\\")
... [Log Snipped] ...
   1 of   2 in t.printstr
***Test Failed*** 1 failures.
```
- In GitLab by @seclinch on Aug 24, 2016, 07:58

Perfect, the r before the docstring resolves my issue.
