Description
Jira Link: [Link: DB-9316]
### Description

Tried on version: ** -b368**

While running the sample app for Cross-Database Concurrent DDL, some DDLs failed with the below error
```ERROR: [Operation expired (yb/consensus/retryable_requests.cc:511): Request id 464130 from client e12324b7-d448-4c21-8653-008081c8be1f is too old (now= , start_time= , request timeout 60.000s, max clock skew 0.500s): Min running request ID: 464130 (min running request ID 464130)]```

DDLs where this error occurred:
```
ALTER TABLE tb_0 ADD newColumn1 TEXT DEFAULT 'dummyString'
DDL query DROP VIEW view1_tb_0
 ALTER TABLE tb_0 ALTER newColumn3 TYPE VARCHAR(1000)
```
**Note**: No data is present inside the table

Context:

1. We are concurrently executing Cross-DB DDLs Sample app with multiple threads. Notably, we ensure there is no simultaneous execution of DDL and DML operations within the same database.
2. The table doesn't contains any data.
3. No Global DDLs are being executed.

Discussion
- syscatalog tablet is in YQL table type and its retryable requests retain duration is 60s (after fix of #18736), YSQL DDL queries can be rejected by this error.

Since syscatalog will process both YQL and YSQL catalog changes, I think it should retain retryable requests for FLAGS_retryable_request_timeout_secs (the maximum duration to retain retryable requests).
