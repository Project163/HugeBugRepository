Title

hashCode collision for steps with different attributes

Description
The  hashCode computation  for PropertiesStep collides for multiple steps when there are repeating keys. For example  .properties()  and  .properties("a","a") ,  .properties("a")  and . properties("a","b","b")  have the same hash code because of xor of just properties here  [URL] Basically, the even keys cancel out the xor computation. 

   

 The same is also true for  AbstractStep.hashCode  which takes xor of labels. 

  GraphStep  does the same thing using ids. so  g.V("1", "1")  and  g.V()  would collide during comparison.
