Title

ES6 modules instantiation works incorrectly

Description
K6 handles E6 modules in such a way that multiple 'import' clause creates multiple instances of imported module.
To illustrate the issue I created a minimal test scenario (attached).
These is a 'i1_common' module exporting a 'context' object.
These are also additional 'i1_module' module and 'i1_main' - main test script module.
'context' object from 'i1_common' module is exported both in 'i1_module' and in 'i1_main' module.
This must be handled so that inside 'i1_main' module and inside 'i1_module' we work with the same instance of imported 'context' object, But as we see in the output this is not what happens.
When executing by k6 engine 'common' module is instantiated twice and 'i1_main' module and 'i1_module' get each its own separate instance of imported 'context' object.
As a reference implementation I created i1_index.html (attached) to run the same set of modules in browser. The below is the output from browser execution:
main 1:initial
module1_func 1:initial
module1_func 2:set_by_module1
main 2:set_by_module1   <<<< HERE IS THE DIFFERENCE
main 3:set_by_main
Here is the output from K6 execution:
main 1:initial
module1_func 1:initial
module1_func 2:set_by_module1
main 2:initial      <<<< HERE IS THE DIFFERENCE
main 3:set_by_main

This is tested with K6 executible version k6-v0.21.0-win64
