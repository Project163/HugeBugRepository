Title

[YSQL] Make OOM killer prioritize PG backends with more memory

Description
Jira Link: [Link: DB-2687]
Mihnea and I were talking that, until we figure out good ways to limit memory usage on the PG side, or lower the default memory usage of the TS, so we leave more room to PG, we could at least play around with something like `nice`, to make sure when the oom killer hits, it at least kills PG backends first.
Discussion
- @fritshoogland-yugabyte suggested setting  `/proc/ /oom_adj` for postgres based on a recent experiment where we saw the OOM killer take down the tserver when a postgres process increased RSS. 

We can either wait for systemd integration in Platform and set this via systemd (https://askubuntu.com/questions/60672/how-do-i-use-oom-score-adj) or modify postgres code to set this on itself based on a conf setting maybe.
