Title

Private+Anonymous Read repo: `/api/../archive/` fails with "The target couldn't be found."

Description
### Description

The header of my repo displays these labels:

[Image: Image]

Repo settings:

[Image: Image]

Fetching an archive of a repo works:

```
shell
$ curl -I [URL]
HTTP/2 200
server: nginx
date: Tue, 24 Jun 2025 23:07:11 GMT
... [Log Snipped] ...
x-content-type-options: nosniff
x-frame-options: SAMEORIGIN
```

Tools like `nix flake lock` will use the url from `link` header for reproducibility. It however does not work:

```
shell
$ curl -I [URL]
HTTP/2 405
server: nginx
date: Tue, 24 Jun 2025 23:11:22 GMT
... [Log Snipped] ...
x-content-type-options: nosniff
x-frame-options: SAMEORIGIN
```

```shell
$ curl [URL]
{"errors":null,"message":"The target couldn't be found.","url":"[URL]
```

Interestingly however it works when I use the non-`/api/v1/repos/` endpoint:

```shell
$ curl [URL]
Warning: Binary output can mess up your terminal. Use "--output -" to tell curl to output it to your terminal anyway, or consider "--output  " to save to a file.
```

As such I assume this bug is [URL] / [URL] not applying to `/api/` endpoints.
