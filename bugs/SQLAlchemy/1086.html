Title

The standard one-to-one relationship with eager loading raises a 2.0 deprecation warning

Description
**Describe the bug**

I have a one-to-one relationship set up exactly as in [Link: the basic relationships documentation], except that I have configured the relationship to have joined loading on both sides. When I try to insert two elements in a certain way, I get a 2.0 deprecation warning: "using strings to indicate column or relationship paths in loader options is deprecated". Given that I'm using code straight out of the docs, I think this warning is a bug.

**Expected behavior**

No warnings are issued and in version 2.0 the elements can be operated on exactly as in version 1.4.

**To Reproduce**

Run the following code with `SQLALCHEMY_WARN_20=1 python -W always::DeprecationWarning file_name.py`:
```
py
from sqlalchemy import Column, create_engine, Integer, ForeignKey
from sqlalchemy.orm import relationship, declarative_base, Session


... [Log Snipped] ...

    session.commit()
```

**Error**

```
RemovedIn20Warning: Using strings to indicate column or relationship paths in loader options is deprecated and will be removed in SQLAlchemy 2.0.  Please use the class-bound attribute directly. (Background on SQLAlchemy 2.0 at: [URL]
  cloned._generate_path(self.path, attr, strategy, wildcard_key)
```

**Versions.**
 - OS: Ubuntu 20.04
 - Python: 3.8.6
 - SQLAlchemy: 1.4.2
 - Database: in memory SQLite; first observed in an application using Postres
 - DBAPI: the defaults for SQLite and Postgres
