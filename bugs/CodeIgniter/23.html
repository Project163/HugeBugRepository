Title

query builder where('fieldname != 1') produces -> fieldname IS NOT NULL 1

Description
If I create query with **->where('fieldname != 1')** mysql query is structured as  **fieldname IS NOT NULL 1**
in previous versions of CI final query was as it should be **'fieldname != 1**
Discussion
- ->where('fieldname !=', 1)
See the difference.

Edit: #3194
- Nothing is broken. @navihtot uses a syntax that does not exist in the documentation, I reviewed the examples given there. Somehow his (incorrect IMO) syntax worked as he says, but it is unclear whether the parameter would be escaped. I think this issue is to be closed without reaction. The feature IS NOT NULL is much more valuable than this unusual syntax.

@navihtot Please, put the value for comparison as a second parameter, where it belongs, and where it will be properly escaped for sure.

- I did my urgent suggestion as a PR. I think, it is clean enough, and the feature from #3194 and from #3198 is not sacrificed.

I afraid to think about other ideas, because their implementation may introduce other breaks right before the release.
- It was a surprise for me to find existence of this "Custom strings" method for building WHERE clauses. I think, I know why it has been created. In CodeIgniter prior version 3 there are no query builder methods group_start(), *_group_start(), and group_end(), i.e. there is no parenthesis control and "Custom strings" is to fill this gap. It is a workaround.

I wrote "Fixing a BC break" by a mistake, but it seems to be a correct mistake. :-)
