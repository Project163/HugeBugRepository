Title

deprecated @groovy.lang.Immutable feature broken on current trunk (1.8-beta-2)

Description
The following code is not supposed to go through, as it defeats the whole purpose of @Immutable. It correctly fails with ReadOnlyPropertyException on 1.7.5, but on trunk it works. 
  
 @Immutable  final   class  Person {
      boolean  married
}
  
person =  new  Person(married: false )

 /* should not be allowed as it is mutating the object after it is formed */ 
person.married =  true
Discussion
- Using the non-deprecated transform works: 
  
 @groovy.transform.Immutable  class  Person {
      boolean  married
}  
person =  new  Person(married: false )
 /* will fail with ReadOnlyPropertyException */ 
person.married =  true 
 
  
 We need to investigate why the deprecated version from groovy.lang is not even calling the transform.
- Some initial tests are now in place. Feel free to add more tests if you are worried about coverage but I think coverage should be taken care of by none deprecated tests - what was missing was some check that deprecated version was working or not.
- No, I am not worried. It just seemed totally wrong that a feature existed but had 0 tests!
