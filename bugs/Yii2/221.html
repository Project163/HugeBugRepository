Title

gii generates hasOne instead of hasMany when reference is part of compound key

Description
When the relation is build on a column which is part of a compound key then a hasOne relation will be generated. Should be a hasMany relation.
Discussion
- Would be great if you'll help reproducing it by providing some SQL to create a structure where Gii fails.
- @samdark, in the meantime I changed my db model. So I tried to reproduce the problem as follows: 

```
CREATE TABLE IF NOT EXISTS `table1` (
  `k1` INT(11) NOT NULL,
  `k2` INT(11) NOT NULL,
  `k3` INT(11) NOT NULL,
  `col1` VARCHAR(45) NULL DEFAULT NULL,
... [Log Snipped] ...
  PRIMARY KEY (`id`))
ENGINE = InnoDB;
```

Gii generated this models:
**_Model table1**_

``` php
...
// the function name has been build on the index name. Relationship is o.K.
 public function getK10()
    {
        return $this->hasOne(Table2::className(), ['id' => 'k1']);
    }
...
```

**_Model table2**_

``` php
 public function getTable1()
    {
        return $this->hasOne(Table1::className(), ['k1' => 'id']);
    }
```

In model table2 the relationship should be `has-many()`.  The relationship in model table1 is correct.
- Should be fixed now. Please help test it. Thanks!
