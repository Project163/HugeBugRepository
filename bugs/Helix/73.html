I replicated this issue by:
- start app
- global search -> open file
- ctrl-o to go to previous jump

the issue was that the empty scratch buffer created at app start was being added to the jump list when switching to a file using the global search. There was a similar check elsewhere that checked on doc delete but not on switch

The panic itself was coming from the `current!` macro trying to unwrap a non-existent document.

Would it not make more sense to have the `current!` macro return an option tuple to avoid issues like this crashing the program?
