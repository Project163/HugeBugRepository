Title

Timestamps missing for Org/Plugin assets

Description
* [x] bug
* [ ] enhancement
* [ ] feature-discussion (RFC)

* CakePHP Version: 4.1.0, and 4.0.x
* Platform and Target: Ubuntu, PHP 7.2, Apache, MySQL

### What you did
When configuration for asset timestamps is enabled
```
'Asset' => [
    'timestamp' => true,
],
```
and including assets
```
$this->Html->script(
    [
        'MyPlugin.assetname',
        'Org/MyOtherPlugin.assetname'
    ],
... [Log Snipped] ...
    ['block' => 'css']
);
```

### What happened
HTML output only assigns timestamps to plugins that aren't org name-spaced
```
 
 
...
  
  
```

### What you expected to happen
I expect both HTML outputs to contain the asset timestamp

### Initial findings

The code [Link: here in Asset.php] only checks the first segment split by "/", so `Plugin::isLoaded()` is only checking against the org instead of the full plugin name.

Adding the following (right before the if statement) will correctly identify that the plugin has been loaded, but then the assets are expected to live in ` /webroot/plugin_name/{css,js}/asset.ext` instead of ` /webroot/{css,js}/asset.ext`, breaking a consistent file structure.
```
if (!Plugin::isLoaded($plugin) && count($segments) > 1) {
    $plugin = implode('/', [$plugin, Inflector::camelize($segments[1])]);
}
```
