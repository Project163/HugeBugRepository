Title

compositeproperty refresh handler replaces the object more frequently than the mutable version does

Description
**Describe the bug**
 
Dear sqlalchemy developers,

I'm still just touching the surface of sqlalchemy, Therefore please kindly excuse me if I do not choose the right wording here and there. But I am pretty sure that I have found either a bug or some really strange behavior if an synonym attribute is used to mirror a mutable composite with declarative mapping.

It seems like the very presence of the synonym for some reason interferes with the aliased composite attribute such that the mutability of the composite "gets lost" if a mapped class is queried a second time without refreshing it, rolling it back or committing it in between.

I'll provide a minimal example that easily explains what I tried to explain so far.

**Expected behavior**
 
The mutability of a mutable composite property should remain unchanged if a corresponding mapped class is used in multiple queries.

**To Reproduce**

Please use this minimal setup and follow the steps below.
```
py
engine = create_engine('sqlite://', echo=False)
metadata = MetaData(bind=engine)

class FooBarComposite(MutableComposite):
... [Log Snipped] ...
session.add(Test(comp=FooBarComposite(foo="c", bar=3.0)))
session.commit()
```
Using the code above, we can change the foo attribute for the "row" with id=1:
```py
tests = session.query(Test).all()

tests[0].comp.foo = "d"

print({test.id: (test.foo, test.bar) for test in session.dirty})
```
This is reflected correctly in the "dirty" part of the session:
```
{1: ('d', 4.0)}
```
Now let's assume that it is intended not to commit the changes already. If the query is then repeated but this time to change attributes of all rows,

