Title

If a fixture is called `teardown`, tests fail

Description
If a test fixture is called `teardown`, the tests fail with a message:

_Fixture "teardown" called directly. Fixtures are not meant to be called directly, but are created automatically when test functions request them as parameters_

even if the test code doesn't explicitly call this fixture.

### Test code
```
python
class TestHelloWorld:

    @pytest.fixture(scope="function", autouse=True)
    def teardown(self):
... [Log Snipped] ...
    def test_helloworld(self):
        assert True
```

### Steps to reproduce the issue

* Create a test file like the one above
* Run `python -m pytest`

**Expected behavior**:
The test suite passes without errors.

**Actual behavior**:
The result is "*1 passed, 1 error*", with the following message:

### Additional information
* Renaming the fixture from `teardown` to something else (like `teardown2`) results in the expected behavior.
* Removing the `autouse` parameter, or changing the scope to `class`, does not result in the expected behavior.
* The failure is reproduced starting from pytest 7.0.0rc1. It's not reproducible with 6.2.5.
