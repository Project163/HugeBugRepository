Discussion
- In BNL, all the outer relation column references used for accessing an inner relation must be batched (see #20495), however, in the plan snippet blow (taken on a release build) `Index Cond: (s_suppkey = partsupp.ps_suppkey)` in `Index Scan using supplier_pkey on supplier` is not batched.
```
->  YB Batched Nested Loop Join
       Join Filter: ((partsupp.ps_suppkey = supplier.s_suppkey) AND (partsupp.ps_partkey = lineitem.l_partkey))
       ->  YB Batched Nested Loop Join
             Join Filter: (part.p_partkey = partsupp.ps_partkey)
             Sort Keys: part.p_partkey
... [Log Snipped] ...
             ->  Index Scan using idx_lineitem_part_supp on lineitem
                   Index Cond: ((l_suppkey = ANY (ARRAY[supplier.s_suppkey, $1026, $1027, ..., $2048])) AND (l_partkey = ANY (ARRAY[part.p_partkey, $2050, $2051, ..., $3072])))
```

While creating the top level BNL:
* Its outer relation, the results of joining `part` and `partsupp` will be batched.
* On the inner side:
  * `((l_suppkey = ANY (ARRAY[supplier.s_suppkey, $1026, $1027, ..., $2048])) AND (l_partkey = ANY (ARRAY[part.p_partkey, $2050, $2051, ..., $3072])))` is batched
  * But `(s_suppkey = partsupp.ps_suppkey)` is not batched (#28847)

In the serial plan, this BNL is rejected by the check [Link: here] but it's missing in the [Link: parallel nested loop path creation code].

Similar subtree in the serial plan :
```
 ->  YB Batched Nested Loop Join  (cost=75.79..4540.92 rows=1 width=39)
       Join Filter: ((supplier.s_suppkey = lineitem.l_suppkey) AND (partsupp.ps_partkey = lineitem.l_partkey))
       ->  YB Batched Nested Loop Join  (cost=55.79..3178.58 rows=418 width=22)
             Join Filter: (supplier.s_suppkey = partsupp.ps_suppkey)
             Sort Keys: supplier.s_suppkey
             ->  Index Scan using supplier_pkey on supplier  (cost=27.81..823.03 rows=10000 width=8)
             ->  Index Scan using partsupp_pkey on partsupp  (cost=27.97..235.98 rows=418 width=14)
                   Index Cond: ((ps_suppkey = ANY (ARRAY[supplier.s_suppkey, $1, $2, ..., $1023])) AND (ps_partkey = ANY (ARRAY[part.p_partkey, $1025, $1026, ..., $2047])))
```
- **To clarifty, on release builds, the parallel BNL plan having this incorrect parameterized join condition would return wrong results in the same way as #20495 without hitting the assert because it's compiled out.**
