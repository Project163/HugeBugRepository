Discussion
- To clarify the workaround, on any new nodes being started, ensure the config is set with 
  
  
 
internode_streaming_tcp_user_timeout: 0s
 
  
 and on existing nodes in the cluster, the timeout can be reset with JMX without restarting 
  
 
org.apache.cassandra.db/StorageService/InternodeStreamingTcpUserTimeoutInMS 
  
 before the bootstrap attempt.
- No success reproducing this issue in a test environment still. 

 Given that all attempts have failed to reproduce and have completed investigating our theories how this could happen without finding anything so far, this should not block the release. 

 Downgrading severity to Normal and will update this ticket with any future findings.
