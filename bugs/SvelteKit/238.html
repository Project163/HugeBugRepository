Title

Snapshots are saved when tab becomes hidden, not when it is unloaded

Description
### Describe the bug

The data for snapshots is currently saved when the `visibilitychange` event fires and we have `document.visibilityState === 'hidden'`. This isn't quite what we want.

This will fire prematurely if someone switches to another tab in their browser, or minimizes it. There's no need to persist the state yet in these cases.

More seriously: It will fail to fire on Firefox when the user closes the tab. We're not persisting the snapshot data in that case, and if they restore the tab, it will not get the restored data. Interestingly, it _does_ get persisted when refreshing the page in Firefox.

In Chrome, this even appears to also be fired when closing the tab, so we don't see the same issue there.

### Reproduction

None currently, apologies. This should occur with the snapshots example [URL] as-is.

### Additional Information

Is `beforeunload` considered bad form for this? Do we have other options? It would be nice to switch to something that doesn't have the false positives and false negatives of `document.visibilityState`.
Discussion
- IIRC we _do_ need to capture it on `visibilitychange` for the sake of browser tabs on mobile that get backgrounded and later reanimated. I'm not 100% confident on that though. It doesn't preclude us persisting to `sessionStorage` in another event as well — doing so is harmless.

I seem to recall a recommendation against using `beforeunload`, though I don't know if it applies to us here.
- `beforeunload` is recommended against [Link: for bfcache reasons] and is not reliably fired on mobile (per MDN):


I've seen [Link: pagehide] recommended as [Link: an alternative to unload] but I'm not sure if it applies in this case or not
- According to [URL] this only applies to Firefox, Safari/Chrome still enable bfcache when `beforeunload` is present
