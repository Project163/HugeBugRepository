Title

AOT Compiler does not persist quotes on property names in object literals

Description
**I'm submitting a ...**  (check one with "x")
```
[x] bug report => search github for a similar issue or PR before submitting
[ ] feature request
[ ] support request => Please do not submit support request here, instead see [URL]
```

**Current behavior**
AOT compiler turns quoted property names in object literals into unquoted property names

**Expected behavior**
The AOT respects the fact that the property names were quoted in the original source

**Minimal reproduction of the problem with instructions**
For a project using @angular/router create a resolve property for one of the routes with one key quoted and one not like the following. Run the AOT compiler on the module.
```
const ROUTES: Route[] = [{
    path: 'app',
    component: AppComponent,
    resolve: {
      resolve1: Resolve1,
... [Log Snipped] ...
...
  imports:      [ BrowserModule, RouterModule.forRoot(ROUTES), ],
```

Inspect the .ngfactory.ts file for the module and find where the ROUTES property is defined. Observe that the generated code shows no quotes on resolve2.
```
resolve: {
  resolve1: import32.Resolve1,
  resolve2: import32.Resolve2
}
```

**What is the motivation / use case for changing the behavior?**
Tools like the closure compiler rename properties differently based on if they are quoted or not. In my use case the resolve names and the accesses (`this.route.snapshot.data['resolve2']`) are renamed differently are result in a failure at runtime.
