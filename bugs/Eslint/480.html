Title

avoid deep-merge of rule config

Description
Recently in #2963 we implemented a deep-merge of nested configs. Rule configs probably shouldn't be deep-merged though. Here's what I mean.

.eslintrc

``` js
{
    "rules":  {
        "consumerweb/param-names": [2, { "err": ["error", "e"], "callback": ["cb"] }],
    }
}
```

public/js/.eslintrc

``` js
"consumerweb/param-names": [2, { "event": ["evt", "e"], "callback": ["cb"] }]
```
#### Result

The config sent to the rule is this incompatible combination:

``` js
"consumerweb/param-names": [2, { "error": ["err", "e"], "event": ["evt", "e"], "callback": ["cb"] }]
```
#### Expected

I expected the config in `public/js` to overwrite the earlier config, because merging in this case produces an incompatible configuration.

``` js
"consumerweb/param-names": [2, { "event": ["evt", "e"], "callback": ["cb"] }]
```
Discussion
- A good one to test might be `no-restricted-modules` which appears to be getting merged with some odd effects.
