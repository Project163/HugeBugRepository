Title

Wrong publish_address format in ipv6 network

Description
Elasticsearch version (bin/elasticsearch --version): 7.6.0

On an ipv6 network, `network.host` is set to `_local`_, and `network.publish_host` is not configured.

network.host will be  parsed as: 
```
"[::1]:9200",
" :9200"
```
```
GET /_nodes/http?pretty
```

```
"http": {
  "bound_address": [
    "[::1]:9200",
    " :9200"
  ],
  "publish_address": "0:0:0:0:0:0:0:1%lo/[::1]:9200",
```

In this scenario, publish_address is better to use `ip：port` format then `hostname/ip:port` because` 0:0:0:0:0:0:0:1%lo` is not an
avalible hostname.

The rest client sniffer needs to parse publish_address to obtain the IP address, `"0:0:0:0:0:0:0:1%lo/[::1]:9200"` will cause sniffing exceptions.

- Right this is broken. The problem is in this check:

```
        if (InetAddresses.isInetAddress(hostString) == false) {
            publishAddressString = hostString + '/' + publishAddress.toString();
        }
```

Our `isInetAddress` utility doesn't understand the scope ID on the address and thinks it's a host name. I think we can just fix that method to understand scope IDs here.
