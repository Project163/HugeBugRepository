## Steps to reproduce

### Security setup silently fails because of default settings

I want to be able to check whether incoming tasks are legitimate. Celery seems to offer message signing, which is perfect for this. I've first followed the docs and added this to the Celery setup script:

```
app.conf.update(
    security_key='/private/keys/celery/private.key',
    security_certificate='/private/keys/celery/public.pem',
    security_cert_store='/private/keys/celery/*.pem')

app.setup_security()
```

That wasn't sufficient enough, though. When using an invalid key, Celery wouldn't even report on that. I dug into the source and found an interesting bit in `celery/security/__init__.py` that checks whether the `task_serializer` setting equals `auth`. If it does not, the security setup is silently ignored. This  doesn't seem like a good thing to me, especially as this rather special behaviour doesn't seem to be noted in the docs.

After adding the configuration for `task_serializer='auth'`, certificates do get loaded and security seems to be set up. Celery also reports on invalid keys when this setting is correctly set.
