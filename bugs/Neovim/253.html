Title

cmdheight=0: segfault with error inside silent! on startup

Description
### Neovim version (nvim -v)

NVIM v0.8.0-dev  

### Vim (not Nvim) behaves the same?

n/a (no cmdheight = 0)

### Operating system/version

Arch / n/a (rolling release)

### Terminal name/version

alacritty 0.10.1

### $TERM environment variable

alacritty

### Installation

nix home-manager + neovim nightly nix overlay (https://github.com/nix-community/neovim-nightly-overlay)

### How to reproduce the issue

Can't reproduce with `--clean`, not sure what further steps to take to narrow the issue

`nvim -u init.lua` with the following `init.lua`:

```lua
vim.o.cmdheight = 0

vim.g.lightline = {
  colorscheme = 'nord',
  active = { left = { { 'mode', 'paste' }, { 'gitbranch', 'readonly', 'filename', 'modified' } } },
  component_function = { gitbranch = 'fugitive#head' },
}
```

Getting rid of either the cmdheight assignment or the lightline assignment prevents the segfault.  

### Expected behavior

Doesn't segfault

### Actual behavior

```
fish: Job 1, 'nvim' terminated by signal SIGSEGV (Address boundary error)
```

I wasn't quite sure whether this was the same as #20195, so I opted for a separate issue
