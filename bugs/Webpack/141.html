Title

[Bug/Feature] Module file timestamps are only recorded on change events.

Description
**Do you want to request a *feature* or report a *bug*?**
Both-ish. I think it's a bug, but could be a feature.

**What is the current behavior?**
Webpack is only recording file timestamps for modules after changing a file. This is bad because it causes full rebuilds when dynamically adding to a compiler.

**If the current behavior is a bug, please provide the steps to reproduce.**
I created a [Link: demo repository].

```
git clone git@github.com:gdborton/webpack-build-as-needed.git
cd webpack-build-as-needed
npm install
node server
```

In your console you should see that `file1.bundle.js` was compiled.
```
building: multi /Users/gary_borton/code/webpack-filetimestamp/src/file1.bundle.js
Listening on port: 3000
building: /Users/gary_borton/code/webpack-filetimestamp/src/file1.bundle.js

webpack: Compiled successfully.
```

If you request `[URL] we'll add it to the compiler, and invalidate. You'll see a message about that, and then you'll see that `file1.bundle.js` was compiled again, despite having no changes.

```
Found a request for an unbuilt bundle "file2.bundle", adding to compiler: "myFancyCompiler"
webpack: Compiling...
building: /Users/gary_borton/code/webpack-filetimestamp/src/file1.bundle.js
building: multi /Users/gary_borton/code/webpack-filetimestamp/src/file2.bundle.js
webpack: wait until bundle finished: /dist/file2.bundle.js
building: /Users/gary_borton/code/webpack-filetimestamp/src/file2.bundle.js
```

**What is the expected behavior?**
Since `file1.bundle.js` has already been compiled successfully and hasn't changed, it shouldn't need to be recompiled.

**If this is a feature request, what is motivation or use case for changing the behavior?**
Performance! I think Airbnb (and others) could see huge dev performance benefits by only compiling/recompiling assets as needed.

Discussion
- As a simple hack/workaround it should be possible to do this before calling `invalidate`:

``` js
const times = compiler.watchFileSystem.watcher.getTimes();
compiler.fileTimestamps = times;
compiler.contextTimestamps = times;
```

btw. you don't need to add entry plugins this way. You can pass a functions to the entry option with is called for every compilation and can return entrypoints in the usual format.
- To fix it in webpack, we would need to get the timestamps when calling invalidate, but this requires a change of the WatchFileSystem interface. So this would be a breaking change. We can do that for webpack 4.
