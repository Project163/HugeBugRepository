Title

Output file is not emtpied when error reporting starts

Description
In GitLab by @rapolas on Sep 14, 2016, 01:19

Using the latest flake8 (3.0.4) version with option --output-file it doesn't overwrite the file, leaves all the previously reported errors (see also #193). I don't think this is a correct behaviour, as in my opinion, it supposed to record a snapshot of current code state. And in any case, why would I worry what flake8 issues were previously recorded? That change to append mode actually has broken our CI. We were using --output-file option to produce a snapshot of commit and then checking if there were any errors, but now it always reports the same error, no matter what we commit afterwards.

It is easy to fix on our side, just remove that produced file before each run, but in general, I don't think it is a right behaviour. I think by default it should overwrite, unless an option (for e.g. `-a` if it is not used) is provided not to.

- In GitLab by @sigmavirus24 on Nov 8, 2016, 20:01

This was not what this was documented as being the purpose.

Given that Flake8 redirects all output (including logs) to the log file, it makes more sense to make this append by default. For users and developers, debugging is easier when comparing subsequent runs.

In my opinion, your CI shouldn't be keeping these files around near where you check for success or failure. They should be saved as artifacts for reference but then cleared after each run. Regardless, why would you not use Flake8's exit code to check if there were errors?
