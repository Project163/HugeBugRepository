1. `ng new sw --service-worker --routing`

6. `ng build --prod`
7. `npm install -g http-server` (you can use any server to test this, if you already prefer another one)
8. `http-server dist`
9. Access `localhost:8080` (8080 is the default port that http-server uses at the time of reporting this issue)
10. Access `localhost:8080/about`

Initially I noticed this behavior on a Universal app, doing server side rendering (following the [Link: universal-starter repo]). So this is not a http-server "not being SPA friendly" issue.
I only used http-server to reproduce it because I wanted to keep the reproduction process as fast as possible, without introducing server side rendering.

- I've been able to figure out two issue spots, that when worked around in my app, allow it to work offline. I won't go into full detail here; I've given a long explanation on [Link: this SO answer].

1. Hosted versions of an Angular app, where the `--base-href` flag is set from the CLI, list absolute URLs for their service worker resources. When comparing requests to these resources, `ngsw-worker.js` is expecting relative URLs
2. Of the 3 available "states" that the `ngsw-worker.js` can be in, in my experience, `EXISTING_CLIENTS_ONLY` seems to bet set incorrectly.

(source code links are in the SO answer; I can duplicate them here as well)
