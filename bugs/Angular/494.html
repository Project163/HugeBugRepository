Title

Lazy routes not recognized when using array import

## Current behavior
Angular does not recognize lazy routes when they are imported like this:

```
@NgModule({
  exports: [RouterModule],
  imports: [
    [RouterModule.forRoot(routes)]
  ]
})
export AppRoutingModule {}
```
_(See more motivation below)_

## Expected behavior
Lazy loaded routes are recognized with the entire syntax that Angular supports (including imports with arrays).

Plunkr does not work well for this issue, but I created a small ng-cli repo here:

1. Clone and npm install
2. Start with `npm start`
3. Clicking on the 'lazy' link will display error

## What is the motivation / use case for changing the behavior?
The example above is contrived, but the use case I have is that I want to define routes in a library module that is imported with `forRoot()`. I tried to have the `forRoot()` method return an array of imports, but this broke the lazy routes. I wanted to do this because the library will wrap the routes in a common parent that has some auth related functionality and more.

There are many examples where an array of `imports/providers/exports/declarations/etc` are used, e.g.: [URL]

The `NgModule` class in Typescript also specify that `any[]` may be used for most fields: [URL]

If an app is started with `imports: [RouterModule.forRoot(routes)]`, and then changed to `imports: [ [RouterModule.forRoot(routes)] ]` everything will still work fine, as the chunk is already created. So there doesn't seem to be any issues running with the latter syntax, just for recognizing lazy routes.
