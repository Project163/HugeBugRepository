Title

`required` function swallows message until first colon (`:`)

Description
Output of `helm version`:

```
version.BuildInfo{Version:"v3.0.0-alpha.1", GitCommit:" ", GitTreeState:"clean"}
```

Example issue (note escaping of `$` is for the shell):

```
export PATH="$HOME/bin/helm-v3.0.0-alpha.1-darwin-amd64:$PATH"
cd /tmp
rm -rf colon-missing
helm create colon-missing
cat >colon-missing/templates/deployment.yaml   something is missing" $myvar`), the error output is as expected:

```
Error: render error at (colon-missing/templates/deployment.yaml:3:4): abc   something is missing
```
Discussion
- This code looks really suspicious:

```

	tokens := strings.Split(err.Error(), ": ")
	if len(tokens) == 1 {
		// This might happen if a non-templating error occurs
		return fmt.Errorf("render error in (%s): %s", filename, err)

- It looks like this happens when there's an instance of `": "` in the important bit of the error message. I'll take a closer look and get a fix in
- So the `text/template` package does some pretty nasty things when it runs into an error while running a function. For example, this template:

```
{{- $foo := "" -}}
{{required "foo is required" $foo}}
```

creates the following error:
```
template: requiredTest:3:2: executing "requiredTest" at  : error calling required: foo is required
```

That message has a ton of redundancy, but unfortunately no way to parse out the important bits without possibly treading on a user's toes (e.g. parsing on colons).

I've submitted [Link: a Pull Request] which addresses this by inserting arbitrary delimiters around the user's warning message, then parsing out the message if an error occurs. The PR includes a unit test that addresses this specific issue.
