Title

tree shaking the tether.js module omits function extend()?

Description
I made a repro example for this one out of a rollup starter project. See here:
[URL]

What I did was to add reactstrap to a reactjs rollup project. reactstrap pulls in tether.js, a valid module. When the rollup build evaluates the tether.js file, the app.js ends up missing a variety of the functions exported on the TetherBase.Utils object; in particular, the extend function has been omitted or tree-shaken somehow.. 

I don't know why it would do this or how to fix it, so I'm hoping this bug generates comments leading to a fix or workaround. thx.
Discussion
- **Edit:**
On second thought, rollup could probably cater to double variable declarations by treating them as reassignments (how the closure compiler handles it), or throw an error when it comes across one.  The resulting issue should not be left for the user to debug.  I don't think I'll spend the time to create a PR for this - the tree shaking code looks complex.


**Original Answer:**
This seems to be a bug with tether and not rollup.

A distilled version of the problem can be seen below:

```
js
// es6.js
function extend() {
  console.log('this gets tree shaken');
}
... [Log Snipped] ...

var extend = 'this is kept';
```

The issue is the double declaration of `extend`, which is apparent in the tether.js distributable.  If you use the default eslint settings on their non-minified distributable, you'll see a number of "variable is already defined" errors, with `extend` being one of them.

Until that codebase is cleaned up, you should expect misbehavior from rollup.
