Title

"Auto accept folders" doesn't work, deadlocks.

Description
As of right now (1.2.0-rc.1) auto accepting new folders doesn't work. Instead Syncthing deadlocks when trying to add the folder. The two opposing routines are, one:

```
goroutine 31 [semacquire]:
sync.runtime_Semacquire( )
        /usr/local/go/src/runtime/sema.go:56 +0x39
sync.(*WaitGroup).Wait( )
        /usr/local/go/src/sync/waitgroup.go:130 +0x65
... [Log Snipped] ...
created by github.com/syncthing/syncthing/lib/protocol.(*rawConnection).Start
        /Users/jb/dev/github.com/syncthing/syncthing/lib/protocol/protocol.go:254 +0x65
```

and two:

```
goroutine 181 [chan receive]:
github.com/syncthing/syncthing/lib/protocol.(*rawConnection).internalClose.func1()
        /Users/jb/dev/github.com/syncthing/syncthing/lib/protocol/protocol.go:903 +0x1de
sync.(*Once).Do( ,  )
        /usr/local/go/src/sync/once.go:44 +0xb3
... [Log Snipped] ...
created by github.com/syncthing/syncthing/lib/config.(*wrapper).notifyListeners
        /Users/jb/dev/github.com/syncthing/syncthing/lib/config/wrapper.go:229 +0x1bf
```

In essense:

1. clusterconfig receiver updates config and waits for config to commit
2. config committer closes connections as part of commit, and waits for that
3. connection that is being closed waits for the dispatcher loop to exit
4. the dispatcher loop is busy calling clusterconfig in step one

(full trace attached)

Pretty sure this is new with the protocol close handling changes in 1.2.0-rc.1, so an RC issue.
