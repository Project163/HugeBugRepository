Title

Calls to logging.xxx() in skipif causes all logging calls to be duplicated to stderr

Description
Using pytest 5.2.2 / 5.3.0, when a function called from a `@pytest.mark.skipif` uses a logging function, the captured log calls are duplicated to stderr.

Minimal working example:
```
python
import logging

import pytest

... [Log Snipped] ...

    assert False
```

Results in the following. Notice "Schmift" is printed both to "Captured stderr call" and "Captured log call".
```
$ pytest test_logging.py
======================================= test session starts ========================================
platform linux -- Python 3.7.5, pytest-5.3.0, py-1.8.0, pluggy-0.13.1
rootdir: /home/felix/src/pytest
collected 1 item                                                                                   
... [Log Snipped] ...
WARNING  root:test_logging.py:13 Schmift
======================================== 1 failed in 0.03s ========================================
```

Removing the logging call from `_check_cond()` results in the expected behaviour, "Schmift" is not duplicated to stderr:
```
python
import logging

import pytest

... [Log Snipped] ...

    assert False
```

```
$ pytest test_logging.py
======================================= test session starts ========================================
platform linux -- Python 3.7.5, pytest-5.3.0, py-1.8.0, pluggy-0.13.1
rootdir: /home/felix/src/pytest
collected 1 item                                                                                   
... [Log Snipped] ...
WARNING  root:test_logging.py:13 Schmift
======================================== 1 failed in 0.03s =========================================
```

- The problem can be reduced more clearly to this:

```py
import logging

logging.warning("during collection")

def test_logging():
    logging.warning("during call")
    assert False
```

What happens is this:

- At startup, the root logger is not configured with any handlers.
- At collection, the root logger is still not configured, so the `logging.warning` call triggers a `logging.basicConfig()` call, which adds a `StreamHandler` to the root logger.
- The logging plugin respects existing handlers if they exist.

So the log messages end up printed to stdout.

The proper way to fix this issue depends on the answer to the question: what should pytest do with logs emitted during collection?

PR #6283 answer is to throw them away. 

Another option is to capture and them display them in some manner.

I think throwing them away is the way to go, by analogy with what capture does with prints during collection.
