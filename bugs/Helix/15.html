### Details

Discussion
- Note: `graphics.rs` has CRLF line endings
- Moving the cursor over any line ending in the file causes this.

@cessen I'm guessing my selection rendering code needs to use that grapheme alignment function you recently added?
- That sounds plausible.  If the cursor is one-wide, and it falls on either of the two CRLF characters, and the cursor highlighting isn't being extended to the prev/next grapheme boundary, then the cursor highlighting would probably split it, yeah.

Incidentally, I just tested it out with my Great Cleanup branch, and it's apparently already fixed there.  Which makes the above explanation even more likely, since everything gets aligned to grapheme boundaries in my branch, even in the highlighting code.
