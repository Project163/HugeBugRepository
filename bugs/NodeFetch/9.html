Title

v3 incorrectly strips out question mark from URL when no query params after question mark

Description
This bug is somehow related to #749 

When I want to get an url like that: "[URL] the path sent to the server should include a question mark, even I specified no parameters. v3 node-fetch strips question mark out. Similar issue for python library, where question if this should be included or not has already been discussed is here: [URL] especially see this: [URL] - tl;dr spec defines that question mark should be included in this case

This works as expected in node-fetch v2 and of course works as expected in browser "real" `fetch`

Demo code for node:
```
const fetch = require("node-fetch").default;

(async () => {
    const ny = await fetch("[URL] => r.text());
    console.log("is result ok?", ny.includes("s.o7o.pl"));
})().catch(e => console.error("main", e));
```

Demo for "real" fetch in browser:
- head to [URL] (to avoid CORS issues)
- open dev tools console
- paste code from node demo, but strip out `require` line

Explaination of demo:
s.o7o.pl is a private use url shortener, under URL: `[URL] there is redirection to npmjs.com page, but when question mark is added to url then html page with target url is shown instead (similar to bit.ly behavior, but they use "+" sign). Some other APIs may rely on that.

PR incoming.
