Title

TypeDict in bound TypeVar assumes parameter values are of type "object"

Description
# Bug Report?

I may be misunderstanding how `TypeVar` works, but it seems to me that the following usage with `TypeDict` should be valid, however I get the error indicated in the comment:

```
python
from typing import TypedDict, TypeVar


class Data(TypedDict):
... [Log Snipped] ...

assert f(Data(x=1)) == 2
```

## Report Details

- have you tried it on `master`: no
- what version of MyPy: 0.761
- what flags are you using: none
Discussion
- This does look like a bug, yeah. I think the issue is that when doing indexing on a type variable with a typeddict bound, checks it just as a call to `__getitem__` and ends up operating on the typeddict's "fallback" type, which is `typing._TypedDict`, which inherits from `Mapping[str, object]`.

I think it should be pretty easy to make `visit_index_with_type` in `checkexpr.py` try recursively indexing into its bound, if you want to take a shot at fixing it.
