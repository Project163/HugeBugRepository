Title

RelativeTtl should be relative to item entry into the cache

Description
I think that the current behaviour of `RelativeTtl` is wrong.  I'm likely biased by the types of application I work on, but it seems to me that the most sensible default cache strategy is "get something and keep it for a time, then repeat."  

`RelativeTtl` is currently implemented as an Absolute TTL strategy simply created from an offset from `Now`, or "get something and keep it until   and then stop caching."

I propose changing `RelativeTtl` so that it returns a new `Ttl` when asked, each offset the same amount from the time the `Ttl` is requested.
