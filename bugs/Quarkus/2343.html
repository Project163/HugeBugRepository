Title

Native tests fail in Gradle-based Quarkus project when module has no classes in `src/main/java`

Description
### Describe the bug

Hello,

We’ve encountered an unusual bug in our current Quarkus project setup. We are using Gradle to build the project, and one of the modules does not contain any classes in `src/main/java`. However, this module includes native tests. The native tests fail to execute when running them in this setup. Here's an example message of a failing native test:
```
MyNativeTest > test() FAILED
    java.lang.RuntimeException at QuarkusIntegrationTestExtension.java:373
        Caused by: java.lang.IllegalArgumentException at PathTree.java:53
            Caused by: java.nio.file.NoSuchFileException at UnixException.java:92
```
The `NoSuchFileException` message is `java.nio.file.NoSuchFileException:  /build/classes/java/main`

As a **workaround**, when we add an empty class in `src/main/java`, the native test executes correctly.

### Expected behavior

I would expect the native tests to be executed even if the module has no source.

### Actual behavior

The native tests fail when the module has no source.
