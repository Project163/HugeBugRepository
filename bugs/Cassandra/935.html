Title

UUIDType assumes ByteBuffer has an accessible backing array

Description
I'm very embarrassed to say this got left out in the UUIDType, but it's not doing a hasArray() check on the bytebuffers passed to it, causing it to break.  I'll make a patch to fix it.
Discussion
- looks like converting array access to ByteBuffer.get  would be a better fix, since you'd avoid an unnecessary copy for direct buffers.  (this is what TimeUUIDType does.)
- New patch that uses ByteBuffer.get() instead of direct array accesses
