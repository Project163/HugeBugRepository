Title

File cache engine: do not check duration on read

Description
This is a (multiple allowed):

* [x] bug

* CakePHP Version: 3.5.0 (but also newer versions)
* Platform and Target: n/a

### What you did
We have written a PSR-16 compatible wrapper around the `CacheEngine`. For this to work, we dynamically set the `duration` of the engine to the value of the TTL and set it back to the normal `duration` again after writing the cache key.

The useful part of our code:
```
php
class CacheEngineWrapper implements CacheInterface
{
    protected $engine;

... [Log Snipped] ...
        return $success;
    }
```

### What happened
This works for all `CacheEngine` implementations except for the `FileEngine` in a specific case: if the TTL of an item we want to save is more than the default `duration`, the data *does* get saved in the cached but never gets retrieved, because of the second clause in this `if`: [URL]

All other cache engines to not check the `duration` when reading an item; only `FileEngine` does. Maybe I am missing some (edge) case, but I think the second part of this `if` statement can be removed.

### What you expected to happen
I expected my cached item to be returned when I retrieve it.
Discussion
- I don't remember why that second clause is included. Cache files should always have their expiry time in the file. Would you want to make a pull request to remove that clause?
- The second clause was added way back in caa7bb62187 when `Cache::set()` was still around. Now that it has been removed this code should be safe to remove.
