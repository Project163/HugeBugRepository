Title

Python SDK can't parse type=json.loads pipeline options at execution time

Description
It's pretty common to use `type=json.loads` in argparse to create JSON formatted options, in fact we have a couple in Beam:  
 [URL]
 [URL]

 Attempting to access these options at pipeline execution time yields an error (note the single quotes): 
  
 
argparse.ArgumentError: argument --beam_services: invalid loads value:  "{ 'foo' :  'bar' }" 
 
  

 Why does this happen? 
 
	 sdk_worker_main.py received these values from the PIPELINE_OPTIONS env var which represents them as proper JSON:
  
 
...,  "some_option" :  "some_value" ,  "json_option" : { "foo" :  "bar" }}, ...
 
   
	 The json is loaded and parsed with PipelineOptions.from_dictionary:  [URL]
	 from_dictionary just  writes out the value with str(v) . When the option is accessed we attempt re-parse it, and it's no longer valid JSON, so json.loads fails.
Discussion
- Possible fix: add a special case for python dictionaries in PiplineOptions.from_dictionary to write them out with json.dumps. This is brittle though, maybe users have some other argument that produces a dictionary in a different way.
- We're already special-casing bool and list; doing the same for dict doesn't seem too bad.
