Title

AssetManager symlink fails if hashCallback returns nested directories

Description
If you use `hashCallback` and return a nested path, e.g. 

``` php
return sprintf('%x/%x', crc32($path), crc32(Yii::getVersion() . $time));
```

and `linkAssets` is true, the symlink will fail, since the base directory does not exist yet.
You can work around this by creating the base directory in your callback, but this could be handled by AssetManager.
Discussion
- What is a reason of returning a nested path at `hashCallback` ? It does not make any sense.
Issue sounds like incorrect usage.
- The reason is that I can separate the asset directories into stable hashes, so that I can delete older versions of assets when they're no longer needed.
