Title

Decompressing bzip2 files with multiple "streams" only reads the first stream

Description
I'm not sure which components to file this against. A user has observed that pbzip2 files are not being properly decompressed: 
 [URL]
Discussion
- This looks to be a bug in the CompressedSource support for BZIP2. Specifically, we create the stream with: 

  
  return  Channels.newChannel(
     new  BZip2CompressorInputStream(Channels.newInputStream(channel)));
 
  

 Which defaults to  decompressConcatenated = false . As a result only the first "stream" within the  bz2  file is actually read. 

 The fix is easy – change that code to: 

  
  return  Channels.newChannel(
     new  BZip2CompressorInputStream(Channels.newInputStream(channel),  true ));
 
  

 But coming up with a test is a bit harder.
