But I agree that this is an issue with ngcc. Unfortunately, we cannot "skip" the entry-point, since ngcc never realised that `flat` was a separate entry-point to `@ngneat/transloco`. This happens in the middle a partial evaluation of code that starts in the `@ngneat/transloco` UMD file and arrives in the `flat` CommonJS file without ngcc being particularly.

It is the case that the import gets a `viaModule` property but this is not exposed to the `NgccReflectionHost` when the partial evaluator calls `getExportsOfModule()`.
- This hasn't been the case since version 9. Also, in version 10 we will migrate existing projects to not use UMDs.
