Title

Incorrect type definition for genReqId in FastifyServerOptions

### Description

The type of `genReqId` server option [Link: implies] its only argument is an instance of `FastifyRequest`:

```ts
    genReqId?:  (req: FastifyRequest ) => string,
```

However, in practice [Link: it is given] `RawRequest` (e.g. `http.IncomingMessage`):

```js
function routeHandler (req, res, params, context, query) {
    const id = genReqId(req)
``` 

while `FastifyRequest` is [Link: created only later] in this function.

### Steps to Reproduce

To reproduce, let's extend the test in [Link: `test/genReqId.js`]:

```js
    genReqId: function (req) {
      t.hasProp(req, 'id')
      t.hasProp(req, 'raw')
      return 'a'
    }
```
This test will now fail, because these two props normally found in `FastifyRequest` instance do not actually exist. (Well, `id` value is supposed to be provided by `genReqId` in the first place)

### Expected Behavior

The type definition should be something like this:

```ts
genReqId?:  (req: RawRequest) => string,
```
