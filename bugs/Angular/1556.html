Title

Passing a trackBy function as input doesn't work with new control flow

Description
### Which @angular/* package(s) are the source of the bug?

compiler, core

### Is this a regression?

Yes

### Description

We have components that render content in an `ngFor` based on a structure such as

```
type ContentAndAdditionalData = {
    content: string;
} & {
    // Can be anything that somewhere has the correct value to track
};
```

where the items as well as the tracking function is passed through inputs.

This has been used like below with the old `ngFor` syntax

```
@Input() items: Array ;
@Input() trackByFn: () => number; 
---
*ngFor="let item of items; trackBy: trackByFn" 
```

With the new `@for` syntax, passing of a tracking function as an input is no longer possible as it yields the error 
`ERROR Error: trackByFn is not a function` when done like

```
 
  @for(item of items; track trackByFn($index, item)) {
     {{ item.id }} 
  }
 
```

This can be worked around by just tracking by reference as `@for (item of items; track item)` but I would still expect that passing a tracking function as an input should work, or is it no longer possible?

Discussion
- The `trackBy` binding does not account for changes and is captured during creation mode, before the input has been assigned. The problem you're having can be avoided using a method that delegates to the input.
- Discussed this in the team and decided that we are not going to support it given that the case is not very common and a work-around exists. But we should detect this case and raise an error.
- ... [Middle Discussions Snipped for Brevity] ...
- Can you elaborate on what you mean by this, maybe give an example? I'm currently facing the same problem. I have a component that has a `@for` loop in its template and a `TrackByFunction ` called `trackBy` as an input. Inside the component code I have the following code:

```ts
@Input()
public trackBy?: TrackByFunction ;

protected trackItem(index: number, item: T): unknown {
    return this.trackBy?.(index, item) ?? index;
}
```

and in the template I call it like this:

```html
@for (item of items; track trackItem(row, item); let lastItem = $last; let row = $index) {
    ...
}
```

But when I want to use the component, I just get the following error, indicating that `this` is `undefined`:

```

... [Log Snipped] ...
```

- @SuNNjek what I was trying to explain is that with the current implementation a reference to the `trackBy` function must be defined when the component is _created_ - which is much earlier, before `@Input`s are set. 

In your particular case your code is correct but you are bumping into a slightly separate issue - the `this` context is not present when the `trackItem` is invoked. 

The combination of the two mentioned issues makes your code to fail in the end but you can work-around it by defining the `trackItem` function as an arrow function: 

```typescript
protected trackItem =  (index: number, item: T) => {
    return this.trackBy?.(index, item) ?? index;
  };
```

Having said this I do recognise that this is very non-obvious behaviour and we will look into improving support for this scenario. For now the presented work-around should do the trick.
