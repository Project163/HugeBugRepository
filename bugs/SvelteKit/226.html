Title

Jagged scroll behaviour on navigation

Description
### Describe the bug

SvelteKit's client-side navigation seems to introduce jagged scroll behaviour, where the scroll position of the previous page is kept for a very short period of time, before it correctly scrolls to the top. This is demonstrated in the video below of [Link: kit.svelte.dev], which was recorded in Firefox, although the same behaviour occurs (for me) on Chrome. The same is occurring in my own SvelteKit apps, and also in the simple reproduction linked below. Do note that is does not always occur, although I have not been able to find a pattern.

It may be related to #2733, although it is a separate problem: the page scroll position *is* always reset to top, but not quickly enough. My apologies if this has been addressed before, or if it is simply a limitation of CSR, as it's my first issue opened here.
