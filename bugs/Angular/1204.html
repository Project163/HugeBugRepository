To sum up, `ngOnChanges` is over-reporting changes under some circumstances. In the reproduction scenario it means that:
* `[timeIn]="(ayncTimer|async)?.t` - is WRONG (expected notification with `timeIn`, actual notification with `timeIn` and `objIn`)

It is not clear to me if this is a compiler bug (we are generating different code for the 2 above cases) or the runtime bug. This will need more root-cause analysis but at this point it looks to me like a confirmed bug in ivy.
- OK, I think I've gotten to the bottom of this one. It turns out that when you use a `?` operator, the compiler is pulling out the value of the `timeIn` binding like this (into `currVal_1`):

```js
const currVal_1 = (tmp_1_0 = i0.ɵɵpipeBind1(1, 2, ctx.ayncTimer)) == null ? null : tmp_1_0.t;
i0.ɵɵproperty("objIn", ctx.objValue)("timeIn", currVal_1);
```

This is a problem because the pipe inside `timeIn` is now executed out of order - before the `objValue` binding that comes before it. This matters because the pipe binding code gets the current binding index value, but it will now point to `objValue` because we haven't yet executed that instruction. As such, the pipe will invalidate the `objValue` binding instead of the `timeIn` binding and cause a property update, which then triggers the `ngOnChanges` machinery (which is actually working as expected).
