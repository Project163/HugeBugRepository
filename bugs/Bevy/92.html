Title

Drop called multiple times if drop panics.

Description
## Bevy version

Master

## Operating system & version

Arch Linux

## What you did

```
rust
use bevy::prelude::*;

struct Dropper(i32);

... [Log Snipped] ...
        .insert(Dropper(1));
}
```

## What you expected to happen

`drop 0` is printed at most once.

## What actually happened

`drop 0` is printed twice.

## Additional information

Several functions in [URL] do not handle `self.drop` unwinding (nor require their callers to do so.)
Discussion
- Only `replace_unchecked` doesn't handle it I think: [URL]

`swap_remove_and_drop_unchecked` calls `self.drop` as last action before returning: [URL]

`clear` sets `self.len = 0` first before dropping anything, ensuring a leak in case of a panicking drop: [URL]
- It depends on what the callers do. In the code path I've looked at, the entity is [Link: removed] from the world before [Link: drop] is called. So there is no problem.

Without the additional knowledge that `swap_remove_unchecked` can panic and leave memory in a half-dropped state, it might also seem valid to swap the relative positions of the linked lines.
