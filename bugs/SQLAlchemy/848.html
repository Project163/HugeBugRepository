Title

postgresql's pg_service.conf file is not loaded any more in 1.3.2

Description
Seems a regression in SQLAlchemy 1.3.2. With SQLAlchemy up to 1.3.1 I can use a pg service file to declare db endpoints as described in [URL]

With the following snipet of code:

```python
# tst.py
from sqlalchemy import create_engine, inspector
engine = create_engine("postgresql:///?service=swh-log")
inspector = inspect(engine)
print(inspector.get_table_names())
```

I have:
```bash
(swh) $ pip install 'SQLAlchemy &1  | grep service
open("/home/ddouard/.pg_service.conf", O_RDONLY) = 3
(swh) $
```

But with 1.3.2:

```
bash
(swh) $ pip install 'SQLAlchemy==1.3.2'
Collecting SQLAlchemy==1.3.2
Installing collected packages: SQLAlchemy
  Found existing installation: SQLAlchemy 1.3.1
... [Log Snipped] ...
(swh) $ strace -e open python tst.py 2>&1  | grep service
(swh) $
```

So in this later case, we see that:
1. the .pg_service.conf is not even loaded,
2. the failed connection to the db is not reported (with <1.3.2 I get a traceback if I try to use a invalid connection url `postgresql:///?service=nowhere`)
