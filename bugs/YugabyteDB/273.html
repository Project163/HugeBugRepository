Title

Data becomes visible before it should when using FOR KEY SHARE in default isolation mode

Description
With the current implementation of `FOR KEY SHARE`, the data from a different transaction with a start time after our current transaction becomes visible. Example:

```
Time   | Transaction 1                       | Transaction 2                                                                                                                                                                                                                                      
------------------------------------------------------------------------------------                                                                                                                                                                                                              
t1     | BEGIN                               |                                                                                                                                                                                                                                                    
t2     |                                     | BEGIN                                                                                                                                                                                                                                              
t3     |                                     | INSERT INTO t(id, s) VALUES (1, 'a')                                                                                                                                                                                                               
t4     |                                     | COMMIT                                                                                                                                                                                                                                             
t5     | SELECT * FROM t                     |                              
...[Description Truncated]...
Discussion
- Add a Transaction 1, t1.5 statement: `SELECT 123`.  This is to work around issue #2702.  That way, the expected no output for `SELECT` at t5 matches vanilla Postgres.
- Also, `BEGIN`s should be `BEGIN ISOLATION LEVEL REPEATABLE READ` for the sake of vanilla Postgres (Yugabyte default isolation level differs from vanilla Postgres's).
- Statement at t6 should work as well, with no output (see [URL]  However, an upcoming fix may cause it to throw a transaction-related error instead.  An issue should be filed for this.
