Title

sql_require_primary_key on mysql 8

Description
### Bug Report
|    Q        |   A
|------------ | ------
| Version     | 2.12.2

#### Summary

We are running a managed database on DigitalOcean.
We are using a class table inheritance. If we now try to update one entity from this inheritance the `Doctrine\ORM\Query\Exec\MultiTableUpdateExecutor::class` is  called and creates a temporary table but the mysql option **sql_require_primary_key** is default **true**. So we are getting an SQL Exception that no primary key exists on this table.

We work around this issue setting **sql_require_primary_key** to **false** but the recommendation from DigitalOcean is:
*"For clusters with more than one node, we strongly recommend keeping sql_require_primary_key as True. Setting it to False may severely impact replication and cause issues."*

#### Current behavior
With **sql_require_primary_key** set to **true** we are getting a SQL Exception.


#### How to reproduce

Use a mysql8 Database, create an entity with  class table inheritance and try update an entity.

#### Expected behavior

Entity update works with **sql_require_primary_key** set to **true**.
