Title

B2 SHA1 mismatch with "unverified:*" prefix

Description
#### What is the problem you are having with rclone?

When running `rclone sync` on a B2 bucket, I'm getting copy failure errors where rclone thinks there's a SHA1 mismatch, but it appears to just be that B2 is prefixing the SHA1 with "unverified:"

~~~
Failed to copy: object corrupted on transfer - SHA1 mismatch (want "unverified: " got " ")
~~~

As you can see, the SHA1 matches... except it doesn't...

Discussion
- How did these files get uploaded?

I found the reference to `unverified` in the docs:

[URL]

So it looks like these files were uploaded with the `do_not_verify` option which isn't something rclone does (rclone will use option 1 if possible and 2 if not).

You can work-around this with this flag

      --ignore-checksum    Skip post copy check of checksums.

Do you think rclone should interpret the `unverified:` prefix and use the sha1 presented?

From rclone's perspective, given that it's verifying the checksum between B2 and rclone, not B2 and the upload point, I think it should consider this a checksum match (e.g. if the client corrupted the upload, that's kind not my problem). But this is just my opinion from this isolated case. Not sure if that might affect other cases.
