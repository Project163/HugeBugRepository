Title

Rule `new-cap` does not report when capitalized function is not constructor

Description
JSHint `newcap` rule reports when capitalized function is called directly

``` js
var Foo = function(){};
Foo(); // Missing 'new' prefix when invoking a constructor.
```

It seems ESLint `new-cap` rule doesn't check this issue. 

It would be useful and consistent with JSHint. I suggest to make it as option, something like `new-cap: [2, 'strict']` to check such issues.
Discussion
- if that's part of the JSHint rule, then we should do it by default. However, we should have exceptions to allow `Number`, `String`, `Boolean`, `Date`, `Array`, and `Symbol` to be used without `new`.
- And `RegExp` and DOM constructors and any other future builtins.... I don't like it.
- I'd stop with adding `RegExp`. We'll deal with others if people complain.
- Ok, I still suggest to make two options in rule, both enabled by default, one to check all constructors are capitalized, second to check all capitalized are constructors. It makes rule more robust, e.g. In React capitalized names are used for components, which are called directly.
