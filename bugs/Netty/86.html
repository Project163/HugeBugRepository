Title

Encoders and Decoders may throw Exception after removed itself from ChannelPipeline

Description
In our Encoders and Decoders we often poll from the MessageBuf to process messages one after each other. This is fine as long as the users implementation does not remove itself from the ChannelPipeline as this will free the MessageBuf and so MessageBuf.poll() will throw an IllegalBufferAccessException.
Discussion
- Reopening to find less intrusive solution.
- @trustin what about this idea:

For every remove and replace method in ChannelPipeline we add another one that takes a boolean parameter which tells if the remaining bytes or messages should be dropped or forwarded to the next handler in the pipeline.  This way we can either clear the buf or transfer it contents to the next in the pipeline on removal /replace. So we not need  to take any extra steps on removal in the handler itself as after the remove/replace call we are sure the actual buffer of the handler is empty. We could discard the content of the buf by default ( when a method without the boolean argument is used). This will also fix #858 and so give the user less surprises. 

I think I would go even futher and change all remove / replace methods to just  return the ChannelPipeline.
