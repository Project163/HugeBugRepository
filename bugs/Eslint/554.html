Title

Typo in code throws TypeError in ESLint when object-curly-spacing is enabled

Description
It's easy to accidentally type a `:` instead of a `=` when destructuring a function parameter with a default value.  I discovered that ESLint throws a TypeError instead of reporting a syntax error in the code.  I encountered this error in version `1.1.0` and can reproduce it in version `1.3.1`.

Faulty JS code

```
export default {
    someMethod ({
        someProperty: {}
    }) {
        return someProperty;
    }
};
```

.eslintrc

```
{
    "ecmaFeatures": {
        "defaultParams": true,
        "destructuring": true,
        "modules": true,
... [Log Snipped] ...
    }
}
```

Error thrown:

```
/usr/local/lib/node_modules/eslint/lib/token-store.js:90
        return tokens[starts[node.range[0]] - (skip || 0) - 1];
                                 ^
TypeError: Cannot read property 'range' of undefined
    at SourceCode.api.getTokenBefore (/usr/local/lib/node_modules/eslint/lib/token-store.js:90:34)
... [Log Snipped] ...
    at EventEmitter.module.exports.api.verify (/usr/local/lib/node_modules/eslint/lib/eslint.js:808:24)
    at processText (/usr/local/lib/node_modules/eslint/lib/cli-engine.js:199:27)
```
