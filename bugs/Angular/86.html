Title

Support `onbubble-event` as alternative to `(^event)`

Description
Hi,

I've talked to Victor and we think that we need an alternative syntax for binding to bubble-events.

Currently there is on-event="x()" as an alternative to (event)="x()" but no alternative for (^event)="x()". 

Wishes,
Manfred

p. s.: perhaps on-bubble-event="x()" would be a good alternative ...

- @manfredsteyer this is probably (?) not what you are looking for, but `on-^event="x()"` works today. Don't see much problem (apart from introducing yet-another-way-of-doing-things) with adding `on-bubble-event="x()"`
- The idea for the alternative syntax is legacy html and user familiarity. For example, we're able to create components/directives that work both in angular 1 and angular 2 following the same interface. This is due to the fact that angular 1 didn't enforce any conventions (since no one knew what the best practices were for component/directives 6 years ago). So we can actually take advantage of this today
