Title

3.0 - Controller::paginate() does not pass correct table name

Description
Using the following controller in the `PluginName` plugin...

```
php
class CountriesController extends PluginNameAppController {

    // public $modelClass = 'Countries';
    public $paginate = [
... [Log Snipped] ...

}
```

...will give the error: `SQLSTATE[42S02]: Base table or view not found: 1146 Table 'default_db_config_name_here.countries' doesn't exist`. I looked at the stack trace for the `Paginator::paginate();` call and this is what is being passed to it...

```
object(Cake\ORM\Table) {

    'table' => 'countries',
    'alias' => 'Countries',
    'entityClass' => '\Cake\ORM\Entity',
... [Log Snipped] ...
    ]
]
```

First, I checked the [Link: manual] to make sure I was making the call correctly. After that, I checked the API. The problem originates from the [Link: `Controller::paginate()`] call and is fixed by using `$this->set('countries', $this->paginate($this->Countries));`. The plugin I am using has its own database connection that is different from the application default but it looks like the issue is it just isn't checking for a plugin before passing the model name to `TableRegistry::get();` so the generic `Cake\ORM\Table` is returned.
Discussion
- This sounds like an issue with `modelClass` name generation in plugin controllers. I can take a look.
- Closing as there is an open pull request now.
