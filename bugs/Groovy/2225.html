Title

Incorrect property lookup if a method starts with "get"

Description
import  groovy.transform.*

@TupleConstructor
 class  Person {  String  name }

 public  <T> List<T> names(
    @DelegatesTo.Target List<T> list, 
    @DelegatesTo(genericTypeIndex = 0) Closure modify) {
        list.collect {
            modify.delegate = it
            modify()
        }
}

@CompileStatic
def test(List<Person> persons) {
    def names = names(persons) {
        getname().toUpperCase()
    }
     assert  names == [ 'GUILLAUME' ,  'CÃDRIC' ]
}

test([ new  Person( 'Guillaume' ),  new  Person( 'CÃ©dric' )])
 
  

 If I make a typo in getName() method like above, I get a runtime error instead of getting a type checker compile-time error.
Discussion
- Actually there seems to be two distinct problems. 
If you use @TypeChecked, you're getting the missing method at runtime (and not compile error). 
But there's a problem with @CompileStatic as well, as I get the following odd cast error to Thread! 
  
 Exception thrown

org.codehaus.groovy.runtime.typehandling.GroovyCastException: Cannot  cast  object  'ConsoleScript44@79145bff'  with class  'ConsoleScript44'  to class  'java.lang. Thread '

- The problem wasn't with  @DelegatesTo  but with the way properties are looked up when you use a method starting with "get" or "is". "getname" produced a lookup to the "name" property which exists, but the "getname" method is not valid because there's no uppercase "n".
