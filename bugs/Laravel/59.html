Title

Factory Model Name Resolver Applies to All Factories

Description
### Laravel Version

11.42.0

### PHP Version

8.3.15

### Database Driver & Version

_No response_

### Description

The ``UseFactory`` attribute [Link: introduced in v11.39.0] causes problems when you create a model with the ``UseFactory`` attribute and then a model that doesn't specify it. The ``HasFactory`` trait calls ``guessModelNamesUsing`` in the ``Illuminate\Database\Eloquent\Factories\Factory``, which sets a static property that then applies to all classes that inherit ``Factory``. 

The bug ultimately originates from the model name resolver being set in the [Link: Factory class]. It's setting the ``$modelNameResolver`` property for ``Factory`` and every class that inherits ``Factory``. 

## Possible Solutions

1. Change the ``$modelNameResolver`` property in ``src\Illuminate\Database\Eloquent\Factories\Factory.php`` to an array, which holds a implemented factory class name with a resolver:

```
php
protected static $modelNameResolver = [];

// ...

... [Log Snipped] ...
  static::$modelNameResolver[static::class] = $callback;
}
```

2. Require the ``UseFactory`` attribute set for all or none of the models. This would mean updating the documentation.
