## Current behavior
 
Some compiler options have notes telling users that the optimal setting for not the same as the default setting. For example: 
[URL]
Note: It is recommended to change this option explicitly to true as this option will default to true in the future.

## Expected behavior
 
I'm not sure how someone who needs to change this setting at update time or before creating a new app will find this note at the right time. 

1. Are these notes still true?
2. When is "the future"?
3. Should the default values match what we expect in the future and require/recommend setting them to a different value if they are updating apps that use the older setting? Developers have a habit of checking things when they update apps, but I'm not sure anyone will see this note when they are creating new apps...so new apps will be compiled using the not-future-proof setting. 
4. How can we help developers more with the past state, current state, future state?
