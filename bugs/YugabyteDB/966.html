Title

[DocDB] Add split brain write protection for StatefulServices

Description
Jira Link: [Link: DB-6459]
### Description

StatefulService is Active on the leader node of the hosting tablet. In the Active mode it can service RPC requests, and write data to the hosting tablet. When the tablet leader moves or the term changes the Service is Deactivated. In this mode RPC requests will be rejected, and outstanding RPC requests will also fail protecting clients from receiving state info.
But Deactivation is an async operation, and we may have outstanding writes to the tablet when the tablet leader moves. It is possible that a new node Activated and wrote some conflicting data.
To protect against this we will issue writes with the last known leader term. DocDB will ensure the write succeeds only as long as the tablet leader is on the provided term.
CatalogManager and SysCatalog use the same logic, but they call the WriteRequest directly on the TabletService. This requires hard coding the table schema in CatalogManger (CatalogEntityInfo).
YBClient provides a dynamic way to write to the table and this is what StatefulServices use. We should pass the expected leader term via YBClient to ensure correctness.
