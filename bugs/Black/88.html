Title

Black-compatible config for isort incurs `TomlDecodeError`

Description
**Describe the bug**

[Link: The compatible config of pyproject.toml for isort] raises `TomlDecodeError`.

**To Reproduce**

Create the following `pyproject.toml` (along with `foo/__init__.py`).

```
toml
[tool.poetry]
name = "foo"
version = "0.1.0"
description = "bar"
... [Log Snipped] ...
[tool.isort]
profile = black
```

Install.

```sh
pip install .
```

```
ERROR: Exception:
Traceback (most recent call last):
  File "/usr/local/lib/python3.9/site-packages/pip/_vendor/toml/decoder.py", line 511, in loads
    ret = decoder.load_line(line, currentlevel, multikey,
  File "/usr/local/lib/python3.9/site-packages/pip/_vendor/toml/decoder.py", line 778, in load_line
... [Log Snipped] ...
    raise TomlDecodeError(str(err), original, pos)
pip._vendor.toml.decoder.TomlDecodeError: invalid literal for int() with base 0: 'black' (line 16 column 1 char 247)
```

**Expected behavior** 

`pyproject.toml` is successfully decoded and the package is installed.

**Environment**

- Version: master
- OS and Python version: macOS Big Sur / Python 3.9.1 / Poetry version 1.1.4

**Possible Solution**

Replacing `profile = black` with `profile = 'black'` resolved this in my environment.
I'll make a pull-request to do this.
