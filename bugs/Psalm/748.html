Title

Return value of get_class() should be treated as class-string instead of string

Description
[URL]
Discussion
- It is treated as `class-string`: [URL]
But it should be reported as a constructor call on unknown class.
- There are more issues with `get_class()` when called without an argument or used in static calls: [URL]
- So what's actually happening here is that there are two types: `TClassString` (which is the type created for `class-string` docblocks) and `GetClassT`, which is a dependent type created from the use of `get_class($foo)`, useful when analysing switch statements.
