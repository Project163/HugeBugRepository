Title

incredibly, we are not nicely checking for secondary=SomeClass in relationship in 2020; support table/cls with same name (!)

Description
placing a class as the target of "secondary" should be using coercions / checking in order to get the correct argument and/or raise an informative error message:
```
from sqlalchemy import Column
from sqlalchemy import ForeignKey
from sqlalchemy import Integer
from sqlalchemy import String
from sqlalchemy.ext.declarative import declarative_base
... [Log Snipped] ...

configure_mappers()
```

fails differently in 1.4 and 1.3 but both with deep stack traces.  1.4 seems to actually be trying to coerce it and amazingly seems to instantiate C (!)   i guess it sees it as a callable.     test for both the string version and the class version.

additionally, we dont support string lookup for table here when table name and class name are the same, so let's try to allow that as well.
