Title

Bazel can't detect build_file after addition

Description
### Summary

1. Try to build a rule in a `new_http_archive` when the `build_file` is not present - it fails as expected.
1. Create the `build_file`.
1. Try again, it still fails.

### Workaround

Change `build_file` to an invalid setting (eg "404.BUILD"), try to build, restore the correct value, try again.

### Reproduction

```
➜  cat WORKSPACE 
new_http_archive(
    name = "com_github_octocat_hello_world",
    build_file = "hello.BUILD",
    sha256 = " ",
... [Log Snipped] ...
➜  cat /usr/local/google/home/rodrigoq/git/bazeltest/cant_find_build/hello.BUILD
exports_files(["README"])
```

### Environment info
* Operating System: Ubuntu 14.04
* Bazel version: 0.5.3
Discussion
- As there is a workaround, using `http_archive` from `@bazel_tools`, this is no longer a P1. In fact, we might even deprecate the built-in `new_http_archive` in favour of `http_archive` from `@bazel_tools`.
- This also fails in the same way with the `new_local_repository`, and by quickly scanning through `@bazel_tools` I couldn't find that reimplemented in Skylark (assuming skylark implementation doesn't suffer from the bug, I didn't verify).

My repro:

```
# WORKSPACE
new_local_repository(
    name = "piano",
    path = "/foo/bar/baz",
    build_file = "BUILD.piano",
)
```

```
# BUILD
cc_library(
    name = "asdf",
    srcs = [ "@piano//foo" ],
)
```

and run `bazel build :asdf; touch BUILD.piano; bazel build :asdf`.
Second output is expected to contain `no such package '@piano//foo`, but got `the 'build_file' attribute does not specify an existing file`
- Run into the same problem with `new_local_repository`. In my case killing bazel background process helped.
