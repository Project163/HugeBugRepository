 Can you see this issue? 

 From the stack trace, this bug occurs when two InputInitializer threads access  SplitGrouper.cache[]  simultaneously. When accessing SplitGrouper.cache[] (ConcurrentHashMap), equals() method is called on CopyOnFirstWriteProperties.
- to  glapark   &  dkuzmenko  : 

 SplitGrouper.cache[] related code was introduced by   HIVE-9976  . It seems that we should not define the cache property as static. This could be problematic. 

 Since the SplitGrouper is always served as an object, I think it's a good idea to define the cache property as non-static.
