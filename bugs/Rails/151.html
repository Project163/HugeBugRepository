Title

Regression in ActiveRecord Nested Through Scope

Description
Given the ruby code in the script, I would expect `user.groups` to be scoped by both of the `deleted_at` conditions.  This was the behavior up thru Rails f55c60f.  This was changed in bc6ac860 to fix [Link: a regression].  This issue persists thru master, test script runs against 5.0.0.beta1.  (This is possibly a dupe of #22723, given how `user.groups` is broken, but `group.users` works as expected)

Rails `f55c60f`

```
sql
SELECT "groups".* 
FROM "groups" 
INNER JOIN "assignments" 
ON "groups"."id" = "assignments"."assignable_id" 
... [Log Snipped] ...
AND "groups"."deleted_at" IS NULL 
AND "assignments"."assignable_type" = 'Group'
```

Rails `bc6ac8`

``` sql
SELECT "groups".* 
FROM "groups" 
INNER JOIN "assignments" 
ON "groups"."id" = "assignments"."assignable_id" 
WHERE "assignments"."user_id" = 1 
AND "groups"."deleted_at" IS NULL 
AND "assignments"."assignable_type" = 'Group'
```

Rails `HEAD`

``` sql
SELECT "groups".* 
FROM "groups" 
INNER JOIN "assignments" 
ON "groups"."id" = "assignments"."assignable_id" 
WHERE "assignments"."user_id" = 1 
AND "groups"."deleted_at" IS NULL 
AND "assignments"."assignable_type" = 'Group'
```

Discussion
- I spent some time looking at this, out of curiosity of how this all works. It seems that in activerecord/lib/active_record/associations/through_association.rb class the removal of the reflection scope code [URL] is preventing the lambda from being applied.

I thought that it would be applied in [URL] when looping through the reflection constraints, however it seems that the through scope is not an applied part of the linked list, it goes straight to the other side of the reference.

Based on the cases that where attempted to be fixed by the prior change, it seems that unscope is the feature that is causing the pain. I am curious if unscope needs to be called in the through association some how? I also find unscope to be a bit nebulous in the case of unscoping through relations.
