Title

Collada Loader does not assign material indices to submeshes as expected

Description
**Describe the bug**
The `ColladaLoader` always assigns the mesh material index to it's submeshes.
However, a common use case is for each submesh to have it's own material.

**To Reproduce**
`bin/assimp info ~/assets/tetrahedron.dae` (asset listed below)
currently, the output lists only one material
```
$ bin/assimp info ~/assets/tetrahedron.dae
Launching asset import ...           OK
Validating postprocessing flags ...  OK
Importing file ...                   OK
   import took approx. 0.00447 seconds
... [Log Snipped] ...
Scene
└╴Tetrahedron (mesh 0)
```

**Expected behavior**
`bin/assimp info ~/assets/tetrahedron.dae`
a listing of all four materials is expected
```
$ bin/assimp info ~/assets/tetrahedron.dae
Launching asset import ...           OK
Validating postprocessing flags ...  OK
Importing file ...                   OK 
   import took approx. 0.00149 seconds
... [Log Snipped] ...
Scene
└╴Tetrahedron (mesh 0, 1, 2, 3)
```
