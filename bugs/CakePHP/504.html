Title

3.x - Model Alias is not being used on cascade delete

Description
Here's the scenario

I have a model named "Accounts" with a hasMany association to a model named "Addresses". The model association is setup like:

``` php
$this->hasMany('Addresses', [
     'foreignKey' => 'foreign_key',
     'className' => 'W4.Addresses',
     'conditions' => ['Addresses.model' => 'Accounts'],
     'dependent' => true
]);
```

If you notice in the conditions, I am using the Alias for the model as a prefix for the field. FYI...This is how I've done it in 2.4. When I delete an account, I expected the Model alias of the associated tables to be used when constructing the the associated delete statement. Instead, the table name is being used. See below:

```
'DELETE FROM mic_addresses WHERE (foreign_key = :c0 AND Addresses.model = :c1)'
```

The resulting error is:

```
Error: SQLSTATE[42S22]: Column not found: 1054 Unknown column 'Addresses.model' in 'where clause'
```

Was this the intended behavior. Making sure I didn't miss something in the ORM migration guide.
Discussion
- I agree the delete query should contain an alias for these kinds of situations.
- Closing as there is a pull request now.
