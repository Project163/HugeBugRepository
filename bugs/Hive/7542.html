- this boils down to something going wrong with the stat computation; a bigint column with values in  [1:70]  has 73 distinct values   
  
 
data_type              bigint              
min                    1                   
max                    70                  
num_nulls              72                  
distinct_count         73
- there are 3 things I've found: 
 
	 there is some wierd distinct count is being calculated for that 5K rows or so....there should be a bug in there; I guess we are using a 512 or something sized hll sketch ; keeping track of 70 elements shouldn't be a problem - I tried to repro it from a simple test; but so far it keep returning the right value all the time. 
	 the primary key identification right now sees the numNulls as well during evaluation; which may prevent it from setting it if the table contains nulls
	 
		 note that this would be purely an improvement; not related to the bug
