Title

Encoding of multipart attribute names and filenames does not work for UTF-8 chars

Description
The encoding of attribute names and filenames in the Content-Disposition field of multipart sections does not work correctly for UTF-8 characters. To be more precise: Not for any non-ASCII chars.

The specification is not clear to me. But the reality, as defined by Firefoy and MSIE is as follows:

The attribute name and filename values are encoded as defined by the HTML page which contains the POST form. Normally as UTF-8.

This test class generates file upload multipart requests with attribute name, filename and file content in three different encodings (ASCII, UTF-8, ISO-8859-1).

The request is generated with HttpPostRequestEncoder and then parsed with HttpPostRequestDecoder. The unit tests checks, if all special characters are correctly found in the result.

```
java
package org.jboss.netty.handler.codec.http.multipart;

import static org.junit.Assert.*;

... [Log Snipped] ...

}
```

The test fails in the current "3" branch for the name and filename attributes in UTF-8 and ISO-8859-1 encoding.
Discussion
- Possible solution:

The attributes have to be encoded with the given charset. Currently, the encoding is hardwired as "ASCII":

In `HttpPostRequestEncoder.encodeNextChunkMultipart()`
replace

``` java
            try { 
                bytes = internal.getBytes("ASCII"); 
            } catch (UnsupportedEncodingException e) { 
                throw new ErrorDataEncoderException(e); 
            } 
```

with

``` java
            bytes = internal.getBytes(charset); 
```

And in `InternalAttribute`, replace method `size()` with:

``` java
    public int size(Charset charset) {
        int size = 0;
        for (String elt : value) {
            size += elt.getBytes(charset).length;
        }
        return size;
    }
```

And add the charset parameter to all calls of size() in HttpPostRequestEncoder.
