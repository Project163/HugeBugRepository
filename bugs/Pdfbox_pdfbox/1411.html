Title

ASCII85Filter does not use or recognize the correct end-of-data terminator

Description
The ASCII85Filter and underlying stream implementations use a single tilde (~) as the terminator. The specified Adobe ASCII85 terminator sequence for both PDF and PostScript is ~>.
Discussion
- Do you have a file that fails due to the alleged incorrect behavior? ~ is not a valid character in ASCII85 so I don't see we should bother waiting for the >.
- I don't know if not reading the final '>' will cause problems in decoding since I was only using it for encoding. For PDF reading streams it might be fine to leave it hanging out there. 

 I do know that the lack of the full terminator in the encoded output does cause issues. I was attempting to use it to write out native PostScript, but I suspect other PDF reader implementations could also have issues with the incorrect terminator sequence.
