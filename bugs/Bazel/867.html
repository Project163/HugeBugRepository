Title

Coverage Header & INL Files

Description
### Description of the problem / feature request:

For a C++ project including various layers of `*.hh` and `*.inl` files, running `bazel coverage ...` produces different results when compared with manually running the executable and assembling the generated `*.gcda` files with the `*.gcno` files from compile time stored in `bazel-bin`.

### Feature requests: what underlying problem are you trying to solve with this feature?

The coverage report differences cause missing executed linecounts in many `*.hh` and `*.inl` files.

### Bugs: what's the simplest, easiest way to reproduce this bug? Please provide a minimal example if possible.

Create a project with a few layers of abstraction through included `*.hh` and `*.inl` files, especially with some template definitions, and run coverage analysis.

Ubuntu 16.04.1
