Title

Greedy flag causing consumer health check to fail

Description
Polling consumer using greedy flag to immediately poll again for large size of messages available are causing consumer health checks to fail for a possibly "long" time. In an environment like a Kubernates cluster this could cause recurring pod restarts that might tighten the need to use greedy because of a growing size of messages needed to be polled. 

 The variable firstPoolDone (btw rename to first Poll Done) in ScheduledPollConsumer should also be set true if first greedy run has been finished.
