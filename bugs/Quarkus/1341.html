Title

NPE when requesting OpenApi spec file from Swagger

Description
### Describe the bug

I happened to hit NPE when accessing Swagger. I'm unable to reproduce it, however I did found a log from my production env where NPE stack trace can be found.

```
plain
ERROR [io.qu.ve.ht.ru.QuarkusErrorHandler] (vert.x-eventloop-thread-3) HTTP Request to /api/spec failed, error id: c270c580-14fc-48df-9933-fb794aa894c0-1: java.lang.NullPointerException
       at io.quarkus.smallrye.openapi.runtime.OpenApiDocumentService.getJsonDocument(OpenApiDocumentService.java:45)
       at io.quarkus.smallrye.openapi.runtime.OpenApiDocumentHolder.getDocument(OpenApiDocumentHolder.java:16)
       at io.quarkus.smallrye.openapi.runtime.OpenApiDocumentService_ClientProxy.getDocument(OpenApiDocumentService_ClientProxy.zig:157)
... [Log Snipped] ...
       at io.netty.util.concurrent.FastThreadLocalRunnable.run(FastThreadLocalRunnable.java:30)
       at java.base/java.lang.Thread.run(Thread.java:829)
```

The stack trace points to this line:

[URL]

It seems like the `documentHolder` is not initialized, which tells me that [URL] was either not invoked at all, or was invoked from a different thread resulting in a race condition.

Every subsequent request gives the expected (correct) result.

I tried different approaches to reproduce this bug, but with no luck. It happened only once.

### Expected behavior

The OpenApi spec is successfully returned.

### Actual behavior

The OpenApi spec request fails with NPE.

### How to Reproduce?

N/A. Described problem happened only once, randomly.
