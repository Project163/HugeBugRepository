Title

mysql\Schema::findConstraints matches foreign keys both in comments and MySQL syntax

Description
During creation of migrate files for my existing database, I found it strange, that one of tables had two foreign key declarations, from Yii point of view, while there was only one in MySQL workbench. During debug process, I added following lines in `mysql\Schema::findConstraints` method (https://github.com/yiisoft/yii2/blob/master/framework/db/mysql/Schema.php#L250)

```
            if ($table->name == 'user__oauth') {
                var_dump($sql);
                var_dump($matches);
                die();
            }
```

And I got following output

```
string 'CREATE TABLE `user__oauth` (
  `user_id` int(11) NOT NULL COMMENT 'CONSTRAINT FOREIGN KEY (user_id) REFERENCES user(id)',
  `uid` int(11) NOT NULL,
  `provider` varchar(100) CHARACTER SET utf8 NOT NULL,
  PRIMARY KEY (`user_id`,`uid`,`provider`),
... [Log Snipped] ...
      2 => string '`user`' (length=6)
      3 => string '`id`' (length=4)
```

It turns out, that the regex match (https://github.com/yiisoft/yii2/blob/master/framework/db/mysql/Schema.php#L249) finds either comment and foreign key in MySQL syntax, which is unexpected.

I am used to "old style" yii1, where I would add in MySQL table column comments foreign key declarations, to aid GII model generation process, and I don't know, if this behavior is feature or bug. Should I avoid adding "constraint" comments for tables, if I use foreign keys in MySQL?

I think, there should be some sort of algorithm that ignores stuff written in comments about constraints, if there exists foreign key declaration in MySQL syntax for that same field.
Discussion
- Constraints for MySQL are extracted from the table create query (`SHOW CREATE TABLE`) using this regular expression:

``` regexp
/FOREIGN KEY\s+\(([^\)]+)\)\s+REFERENCES\s+([^\(^\s]+)\s*\(([^\)]+)\)/mi
```

which should probably be ungreedy.

Only MSSQL reads them from the `INFORMATION_SCHEMA.REFERENTIAL_CONSTRAINTS` table, maybe this is also available for MySQL and would be better?
- This changes introduced a regression on my app : Currently with code from master, I always get an empty array in `$table->foreignKeys` for all models of my database (mysql 5.1.72).

Rolling back 191185f make things work again.

The problem is that this SQL query doesn't return anything:

```
sql
SELECT
    kcu.constraint_name,
    kcu.column_name,
    kcu.referenced_table_name,
... [Log Snipped] ...
AND rc.table_name = "model" AND kcu.table_name = "model"
SQL;
```

Here are the corresponding records for my "model" table in both information_schema tables:

mysql> select \* from information_schema.referential_constraints rc WHERE rc.constraint_schema = database() AND rc.table_name = "model";

```
+--------------------+-------------------+-----------------+---------------------------+--------------------------+------------------------+--------------+-------------+-------------+------------+-----------------------+
| CONSTRAINT_CATALOG | CONSTRAINT_SCHEMA | CONSTRAINT_NAME | UNIQUE_CONSTRAINT_CATALOG | UNIQUE_CONSTRAINT_SCHEMA | UNIQUE_CONSTRAINT_NAME | MATCH_OPTION | UPDATE_RULE | DELETE_RULE | TAB
...[Text Truncated]...
---------------+-------------------+-----------------+---------------+--------------+------------+-------------+------------------+-------------------------------+-------------------------+-----------------------+------------------------+
| NULL               | flycar            | PRIMARY         | NULL          | flycar       | model      | id          |                1 |                          NULL | NULL                    | NULL                  | NULL                   |
| NULL               | flycar            | fk_model_brand1 | NULL          | flycar       | model      | brand_id    |                1 |                             1 | flycar                  | brand                 | id                     |
+--------------------+-------------------+-----------------+---------------+--------------+------------+-------------+------------------+-------------------------------+-------------------------+-----------------------+------------------------+
2 rows in set (0.00 sec)
```

The problem is that  kcu.constraint_catalog and rc.constraint_catalog are both NULL in my case, and that the expression "null = null" in MySQL doesn't evaluate to TRUE but it evaluates to NULL which makes the condition not verified.

The query needs to be fixed like this:

``` patch
-    kcu.constraint_catalog = rc.constraint_catalog AND
+    (
+        kcu.constraint_catalog = rc.constraint_catalog OR
+        (ISNULL(kcu.constraint_catalog) AND ISNULL(rc.constraint_catalog))
+    ) AND
```
