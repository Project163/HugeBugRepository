### Description

According to documentation [Link: Reply lifecycle] and `onError`:

However, in practice, the `onError` hook is always executed **before** the custom error handler.  
This causes `onError` to be triggered even for errors I intend to handle and respond to properly within my custom error handler, which results in misleading logging or error reporting.

Here is a minimal reproduction:
```
javascript
import Fastify from 'fastify'

const fastify = await Fastify()

... [Log Snipped] ...
//   onError
//   setErrorHandler
```

I found a possibly related [Link: issue] seems similar to what I'm observing here.

[URL]

### Expected Behavior

`onError` hook should run after the custom error handler, and only if the custom error handler sends an error back to the user.
