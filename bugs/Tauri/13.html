Title

String value in HttpRequestOptions header field gets escaped incorrectly

Description
**Describe the bug**
when you pass `String` value to  `params` or `header` field in `HttpRequestOptions` it will get escaped and adds `"` to both start and end, and this added `"` will get treated as a part of value by the receiver.

 
 ==== description with example ==== 

```
rust
let mut header: HashMap  = HashMap::new();
let mut params: HashMap  = HashMap::new();

header.insert(String::from("Authorization"), String::from("Bearer AUTHTOKEN").into());
... [Log Snipped] ...

println!("Result: {}", make_request(option).unwrap());
```

This print produces following result (some detail has been omitted and formatted)
```
{
  "args": { 
    "part": "\"id\"",
    "mine": "true"
  },
... [Log Snipped] ...
    "authorization":"\"Bearer ACCESS_TOKEN.aeab-eearwer\"", 
    ...
```
value of `authorization` field in `header` object should not have escaped `"`.

 

**To Reproduce**
Steps to reproduce the behavior:
1. Create new Tauri project and open `src-tauri/main.rs`
2. in `main` function, create `HttpRequestOptions` and set `header` to have at least one or more `String` value, and set `url` to any HTTP url that echoes HTTP request (I tested with Postman Echo)
3. call `make_request` with given option and observe the result.

**Expected behavior**
Postman echoes correctly formed header, expected like
```
{
  "args": { "foo": "bar" },
  "header": { .., "authorization": "Bearer  AUTHTOKEN", .. },
  ...
}
```

Discussion
- looks like the cause of this problem is that the `format!("{}", header_value),` in `make_request` produces the _serialized_ string of data.
when `Value::String` gets serialized, it adds `\"` to both start and end.

the most simple workaround for this problem would be just pattern-match the `Value` enum and format every inner value individually, but it means that it will allocate a string for every value but `Value::String` itself (which you can just move out from enum)
- Seems like I should use `String` instead of `Value` since every header value should be a string anyway. The drawback is that if you send another type, it would result in an API error.
- Let me know if you guys think otherwise.

Thanks for the issue report and the insight!
