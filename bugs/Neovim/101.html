Title

Segfault in tui_tk_ti_getstr when -1 is passed as value

Description
- `nvim --version`: v0.3.4
- Vim (version: ) behaves differently?
I don't know, most probably yes, as it does not have such a function.
- Operating system/version: Guix System, 3499638
- Terminal name/version: ssh login, through Ubuntu host
- `$TERM`: xterm-256color

### Steps to reproduce using `nvim -u NORC`

```
nvim -u NORC

```

### Actual behaviour
Segmentation fault on startup
### Expected behaviour
Actually starts

I debugged this segfault, and it came from a tigetstr call, parameter was key_dc, return value was
(char*)-1, which is a valid return value as per the documentation of that method, and directly passed on to the tui_tk_ti_getstr hook function as value. (This is located in src/nvim/tui/tui.c)

I tend to believe this is not a problem in ncurses, as the return value is acceptable, according to the documentation, and I also believe that it is not a libtermkey problem, as it should leave the option open to the hook to handle the case when -1 is passed.

According to a short talk on the IRC channel it would be reasonable to handle this analogously to the case when NULL is returned. I will file a pull request in this spirit.
