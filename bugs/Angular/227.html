Title

Metadata extractor fails when encountering a d.ts generated from a source file that uses a custom decorator

Description
When the metadata extractor encounters a custom decorator, it includes the information for that symbol in the `.metadata.json` file. Typescript, however, does not include an import for that symbol in the `.d.ts` file because it is not necessary. This disconnect causes the metadata extractor (when run on a downstream app) to fail because the symbol for the module is not included in the program.

This can be worked-around by manually adding the missing `.d.ts` file to the `files` list in the `tsconfig.json`, but this is rather hacky.
