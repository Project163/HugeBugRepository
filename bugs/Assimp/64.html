Title

Bug: Collada parsing partly broken since v5.1.0

Description
On v5.1.0 (and probably earlier) some Collada parts aren't parsed correctly, mainly lights, samplers, and some material properties.

There's a lot of code that does something like this:

```c++
if (currentName == "constant_attenuation") {
    XmlParser::getRealAttribute(currentNode, "constant_attenuation", pLight.mAttConstant);
}
```

which tries to read a *child attribute*, not the current attribute. This fails and the value is never written.

**Expected behavior**
