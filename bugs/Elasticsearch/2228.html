Title

Percolate query ignores "name" parameter

Description
**Elasticsearch version** (`bin/elasticsearch --version`): `6.5.4`

**Plugins installed**: `[analysis-icu]`

**JVM version** (`java -version`): `openjdk version "11.0.1" 2018-10-16`

**OS version** (`uname -a` if on a Unix-like system): `Linux 7a321a3f5b0f 4.4.0-119-generic #143-Ubuntu SMP Mon Apr 2 16:08:24 UTC 2018 x86_64 x86_64 x86_64 GNU/Linux`

Deployed as a customized Docker image (following [Link: the documented procedure]) with only `analysis-icu` plugin installed beyond the default.

**Description of the problem including expected versus actual behavior**:

According to [Link: the documentation] (and [Link: given example]), providing the `name` parameter in percolate query should result in `_percolator_document_slot` field being suffixed with that value if multiple percolate queries are supplied. However, it's not the case and the field is suffixed with the `field` parameter value as if no `name` was provided. Also, the documentation is inconsistent in specifying if the parameter name should be `name` or `_name`.

**Steps to reproduce**:

Issue the percolate query request for two existing documents from `my_index` index (from Kibana Dev Tools):

```
GET watchers/_search
{
  "query": {
    "bool": {
      "should": [
... [Log Snipped] ...
  }
}
```

Response:

```
{
  "took" : 17,
  "timed_out" : false,
  "_shards" : {
    "total" : 1,
... [Log Snipped] ...
  }
}
```

The `fields` object contains `_percolator_document_slot_watcher.query`, however there should be keys like `_percolator_document_slot_name1` and `_percolator_document_slot_name2` present.

What actually works for my use case but is not documented (at least in the context of percolate query) is providing the `_name` parameter. This works just like any other [Link: named queries] resulting in `matched_queries` key in the output:

Request:

```
GET watchers/_search
{
  "query": {
    "bool": {
      "should": [
... [Log Snipped] ...
  }
}
```
