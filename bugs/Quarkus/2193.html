Title

jbang does not persist Q:CONFIG keys nor build set keys

Description
### Describe the bug

this probably always been case but not noticed as only recently jbang changed to run jbang integration build externally.

when running jbang build integration quarkus sets system properties based on Q:CONFIG keys and these are not persisted into the next run if run with -Dquarkus.dev. They do seem to get stored when packaging for prod builds.

```
///usr/bin/env jbang "$0" "$@" ; exit $?
//JAVA 11+
// Update the Quarkus version to what you want here or run jbang with
// `-Dquarkus.version= ` to override it.
//DEPS io.quarkus:quarkus-bom:${quarkus.version:2.11.2.Final}@pom
... [Log Snipped] ...

}
```

using above you'll see that `jbang main.java` just has default value. if you run with `jbang -Dquarkus.myproperty=cmdline main.java` it does change.

...I kinda also assumed -Dquarkus.myproperty at build time would persist to runtime but does not seem to happen.


### Expected behavior

Q:CONFIG should be loaded into the build generated defaults and should work even when -Dquarkus.dev mode used.
