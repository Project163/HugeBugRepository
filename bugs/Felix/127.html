Title

StackOverflowError in URLHandlers.createStreamHandler() when creating URL on jamvm and Mika

Description
It looks like we have an unfortunate interaction between our ExtensionManager and the URLHandlers on jamvm and Mika .  

 Basically, when a URL is created inside a bundle the URLHandlers are asked to find a stream handler. One step of this process is to do a Class.forName() which will use the framework classloader. Now, in case this happens to be a URLClassLoader we have added a URL with our ExtensionManager as a handler. This is not a problem unless the URL is toString()-ed and then recreated which seems to be the case for jamvm/classpath and Mika.  

 Subsequently, the attempt to find a handler for the protocol of the ExtensionManager URL will call URLHandlers.createStreamHandler() again and we have a loop until StackOverflowError.
Discussion
- The URLHandlers are now aware of the extension protocol. We will directly return the extension manager in case this protocol is used - pretty much like we already do for the bundle protocol. Seems to work on both, jamvm and Mika.
