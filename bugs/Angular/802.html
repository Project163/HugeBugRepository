Title

global is not detected correctly when global.window exists

Description
**I'm submitting a ...**  (check one with "x")
```
[x] bug report => search github for a similar issue or PR before submitting
[ ] feature request
[ ] support request => Please do not submit support request here, instead see [URL]
```

**Current behavior**

Currently when there are `global` and `window` global variables, the priority is given to `window` [Link: with no additional checks] in non-browser environment.

**Expected behavior**

Considering that `window` has higher priority, it may have stricter checks.

**Minimal reproduction of the problem with instructions**

In Node.js:

```
global.window = { foo: 'stubbed' };
require('@angular/core').ɵglobal !== global
```

**What is the motivation / use case for changing the behavior?**

When `global.window` is set on server side to provide fixes for client-side code in universal apps, this will result in setting wrong value for `ɵglobal` internal export. This affects [Link: decorators, for instance].

The same applies to other platforms (workers).

node 7.2.0
npm 3.10.10
