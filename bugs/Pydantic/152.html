Title

Unexpected `Sequence[str]` behavior

Description
### Initial Checks

- [X] I confirm that I'm using Pydantic V2 installed directly from the `main` branch, or equivalent

### Description

Consider the following model class

```python
import pydantic
import typing

class Model(pydantic.BaseModel):
    str_sequence: typing.Sequence[str]
    str_value: str
```

Passing correct values works as expected

```python
m = Model(str_sequence=['a', 'b', 'c'], str_value='abc')
repr(m)  # "Model(str_sequence=['a', 'b', 'c'], str_value='abc')"
```

Passing a list of strings into a string property fails as expected

```python
Model(str_sequence='abc', str_value=['a', 'b', 'c'])
```
```
pydantic_core._pydantic_core.ValidationError: 1 validation error for Model
str_value
  Input should be a valid string [type=string_type, input_value=['a', 'b', 'c'], input_type=list]
```

Passing a string into a `Sequence[str]` property results in the `str` value being accepted as a valid `Sequence[str]` value

```
m = Model(str_sequence='abc', str_value='abc')
repr(m)
"Model(str_sequence='abc', str_value='abc')"
```

This doesn't match `list` behavior

```python
class Model1(pydantic.BaseModel):
    str_list: list[str]

m1 = Model1(str_list='abc')
```
```
pydantic_core._pydantic_core.ValidationError: 1 validation error for Model1
str_list
  Input should be a valid list [type=list_type, input_value='abc', input_type=str]
```

Pydantic 1.10 also correctly raises a validation error in this case

```
python
...     str_sequence: typing.Sequence[str]
... [Log Snipped] ...
str_sequence
  value is not a valid sequence (type=type_error.sequence)
```

Discussion
- I don't know if the different behavior between v1 and v2 is intentional, but in Python any string is considered a `Sequence[str]`. The potential confusion is a known issue (see [URL]
- It looks like it's not only differs from Pydantic v1 but also from `list[str]` in the same v2.

IMO, the decision is there and this is just an erroneous behavior.

Let me also share my view on the `str`/`Sequence[str]` topic.

I honestly believe that it is not `typing` and in general not the language responsibility to make `str` distinguishable from `Sequence[str]`. However, it is exactly why Pydantic exists and its job is to help developers dealing with this behavior. Here is why.

There are three distinct levels here:
- Language
- Library
- Application

IMO, `typing` is on the Language layer as type annotations cannot lie about language features. And when the language says that distinguishing between `str` and `Sequence[str]` is the developer's job it doesn't necessarily mean that it's an Application level's job. These common quality of life cases are exactly why there are libraries like `Pydantic` out there.

Thus, let's agree to leave this tedious job of making `if not isinstance(value, str)` check every time we write `Sequence[str]` to the Library level.
- I would also say that in some cases, type checkers interpret things a bit differently in some edge cases (like the `pytype` example above). If I find some time I'll try and make a PR regarding docs, if not done by maintainers until then
