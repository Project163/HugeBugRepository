Title

Impossible to use jdbc interface with presto-jdbc >= 0.180

Description
Hello, 

 I have been trying since yesterday to integrate Presto (0.183) with Apache Zeppelin (0.7.2) (using the presto-jdbc driver interface), and, so far, I am hitting a roadblock. 

 Since presto version 0.180 and higher, with commit   ("Improve properties/URL parameter handling"), developers did tighten connection properties with com.facebook.presto.jdbc.PrestoDriverUri.validateConnectionProperties. 
This function rejects anything that is not specified into com.facebook.presto.jdbc.ConnectionProperties. 

 Sadly, Zeppelin adds extra property keys such as "url" and "driver" which, naturally, get rejected. (See org.apache.zeppelin.jdbc.JDBCInterpreter.java at function "open")

- It has been quite a while since I made this issue and it didn't get any comment (except a person which forgot to set the default.user property and thought it was the right place to ask). The same applies to the presto google group thread. 

 Anyway, after re-reading the code for both projects, I would say that Zeppelin might be the one to patch. It is understandable, from the presto-jdbc point of view, not to accept a property list full of useless values. The fact that "url" and "driver" inadvertently get added in the properties is a bug to my eyes. I do not know a jdbc library requiring such duplicated properties either. 

 As a workaround, I did patch presto-jdbc to accept any kind of property thrown to it. It will just discard them and continue its regular execution. 
Here's the patch which also happen to pass all unit tests:  [URL]
I would prefer a patch in Zeppelin that ignores "default.url" and "default.driver" during parsing.
