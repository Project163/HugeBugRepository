Title

3.0 Bake: Parent/Child Relationships + Fixtures & Testing

Description
#### What I did

I baked a starting-point for my tests. I have a `Page` model with a `parent_id` property, the same goes for `Comment`.
#### Referencing non-existing fixtures

Cake bakes `PageControllerTest` which references `ChildPageFixture` and `ParentPageFixture`, both of which do not exist. The same applies to `Comment`. Maybe, CakePHP should reference the `Page` and `Comment` fixtures instead.
#### Related cosmetic issue

When baking views, CakePHP generates links/buttons such as `Add ParentPage` and `Add ChildPage` -  maybe, these should be suppressed.
#### Question: populating fixtures & referential constraints

Populating the test database fails due to referential constraints. Is there a way to deactivate foreign_key checks when using the datasource `test`? Or would I just execute `SET FOREIGN_KEY_CHECKS = 0;` in `TestCase::setUp()`? The problem is that I will need the referential constraints to be re-activated after loading the DB and before the tests commence.
Discussion
- Turning off constraints is something we've talked about in the past, and I think it makes sense when loading and unloading fixtures as otherwise there is a very painful process to order all your fixtures correctly.

Not generating fixtures for Parent/Child associations might require a bit more thought, as we cannot simply blacklist those names. Someone could have associations with those names without making a self-association. Perhaps the rule should be if the association references the current class the alias is excluded from links and fixtures?
- I think fixture generation should check the `className` property of the association to see if it is generating any duplicates.
- @lorenzo Yeah that seems like the best option.
- Closing as there is a separate issue for fixtures & foreign keys now.
