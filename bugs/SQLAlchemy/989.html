Title

CursorResultMetaData._adapt_to_context causes ambiguous column name

Description
**Describe the bug**

When two identical queries (with same column names from different tables) with different memory address are executed sequentially, the latter reuses the cached compiled statement, and calls `CursorResultMetaData._adapt_to_context()` but breaks the metadata, leading to "ambiguous column name" errors when indexing by columns.

**Expected behavior**

Metadata is not broken, and the result indexing by columns works.

**To Reproduce**

```
py
import sqlalchemy as sa

metadata = sa.MetaData()
users = sa.Table(
... [Log Snipped] ...
print(e.execute(build_query()).first()[users.c.id])  # always succeed
print(e.execute(build_query()).first()[users.c.id])  # success expected
```

**Error**

```
2020-09-05 14:00:42,711 INFO sqlalchemy.engine.Engine SELECT users.id, teams.id 
FROM users LEFT OUTER JOIN teams ON teams.id = users.team_id
2020-09-05 14:00:42,711 INFO sqlalchemy.engine.Engine [generated in 0.00025s] {}
1
2020-09-05 14:00:42,712 INFO sqlalchemy.engine.Engine SELECT users.id, teams.id 
... [Log Snipped] ...
    raise exc.InvalidRequestError(
sqlalchemy.exc.InvalidRequestError: Ambiguous column name 'id' in result set column descriptions
```

**Versions.**
 - OS: Darwin Kernel Version 19.5.0
 - Python: Python 3.8.2
 - SQLAlchemy: 1.4.0b1 @  
 - Database: PostgreSQL 12.4
 - DBAPI: psycopg2 2.8.5 (dt dec pq3 ext lo64)

**Additional context**

```python
row = e.execute(build_query()).first()
print(row._keymap[users.c.id])
row = e.execute(build_query()).first()
print(row._keymap[users.c.id])
```

Output:
```
(0, (Column('id', Integer(), table= , primary_key=True, nullable=False), 'id', 'id', 'users_id'), 'id', 'id', None, None)
(None, (), 'id')
```

Part of the reasoning:
[URL]

Because `compiled.statement is not context.invoked_statement` (different memory address), `_adapt_to_context()` is called and I didn't follow into that method to find out why it breaks the metadata.

Discussion
- It works fine with SQLAlchemy 1.3.19 @ da4e4cb1c even with `compiled_cache` provided:

```py
with e.connect().execution_options(compiled_cache={}) as conn:
    print(conn.execute(build_query()).first()[users.c.id])
    print(conn.execute(build_query()).first()[users.c.id])
```
- **Mike Bayer** has proposed a fix for this issue in the **master** branch:

**Don't rely on string col name in adapt_to_context** [URL]
