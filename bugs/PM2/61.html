Title

pm2 rarely losing several services on reboot

Description
## What's going wrong?
When rebooting our server (ubuntu 16.04) occasionally we randomly lose a few services in pm2. This is due to pm2 very rarely being sent the kill signal twice (SIGTERM) in quick succession. I was unable to locate the cause of why it was sent SIGTERM twice on shutdown in rare cases, but when it does get called twice this behavior is consistent.

pm2 starts to shut down by saving to the pm2.dump file and then deleting services one-by-one. While this is happening, if a SIGTERM is recieved again it kicks off the process again - dumping the new shortened list of services that have not yet been terminated. when the server finishes reboot, pm2 resurrects the processes in the dump file which has now been shortened due to this issue to exclude some of the first few services.

## How could we reproduce this issue?
install on ubuntu and set up pm2 with several services (we have 24) and with pm2 startup being configured with the pm2 startup command.

when the services are running - find the process id of pm2 and kill it (SIGTERM). Before that finishes re-send SIGTERM. The shutdown/dump process should kick off again in the middle of the first attempt.

After that either run "pm2 resurrect" or reboot the machine. It should start up with some services missing.

- Hi there,

I think one possible reason for receiving multiple SIGTERM signals is to have multiple pm2 daemon running. So each of them receive signals but they read/write into the same dump file.

In any case, we can't really find all possible reasons, and some of them are out of pm2 scope (imagine if you use a buggy script that send multiple SIGTERM to pm2).

To me, the best thing to do is to stop signal listening after the first SIGTERM is received.
Then listen signal again when all processes are killed.
