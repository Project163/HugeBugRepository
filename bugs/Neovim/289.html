Title

Segfault with recursive nvim__get_runtime

Description
### Problem

On occasion, when I run `nvim`, I get a segmentation fault.

### Error

I ran `lldb nvim` followed by `run` to get the following:

- The problem seems to occur because `runtime_search_path` is accessed in `runtime_search_path_build()` after `runtime_search_path` is released in the following location.

[URL]

It should be fixed by changing it to release `runtime_search_path` after calling `runtime_search_path_build()` as in the following patch. However, I am not sure if there is a problem if `do_in_cached_path()`, etc. is called in `runtime_search_path_build()`.

Cc: @bfredl 

```
diff
diff --git a/src/nvim/runtime.c b/src/nvim/runtime.c
index d091636e7..6fc49b21f 100644
--- a/src/nvim/runtime.c
+++ b/src/nvim/runtime.c
... [Log Snipped] ...
     runtime_search_path_ref = NULL;  // initially unowned
     uv_mutex_lock(&runtime_search_path_mutex);
```
- Do not provide backtrace with images. In the case of images, the contents of backtrace are not searched when searching for duplicates. Images and videos should not be used unless they cannot be expressed in text by any means.
- `nvim__get_runtime` cannot be called recursively. we need to inhibit the os_breakcheck() while running regex code inside `nvim__get_runtime`. (vim: you wouldn't just _expand a regex_)
