Title

Using `Values` element in a scalar subquery triggers an error

Description
### Describe the bug

We are trying to work around the absence of the `GREATEST()` function in SQL Server using the Table Value Constructor approach described here:
[URL]

That is, given a table `t` like this:

pk | i1 | i2 | i3
-- | -- | -- | --
100 | 1 | 2 | 3
200 | 6 | 5 | 4
300 | 7 | 8 | 9

We would like to generate SQL like this:
```sql
SELECT
  t.pk,
  (SELECT max(tvc.v1) FROM (VALUES (t.i1), (t.i2), (t.i3)) AS tvc (v1)) AS max_i 
FROM
  t
```

To get these results:
pk | max_i
-- | --
100 | 3
200 | 6
300 | 9

We are able to construct the appropriate query (see reproducing example), but when we try to compile it we get an error in `visit_values` here:
[URL]

```
TypeError: sqlalchemy.sql.visitors.Visitable._generate_compiler_dispatch. ._compiler_dispatch()
got multiple values for keyword argument 'include_table'
```

Because `kw` contains the entry `{"include_table": True}`.

Editing the SQLAlchemy code to remove the entry from the passed keywords is enough to make the code run and produce the expected output in our case:
```py
kw.pop("include_table", None)
```

But I'm afraid I don't know enough about why `include_table` is being passed through here to know if this only addresses the symptom of a deeper issue. Or indeed, whether we're not constructing the query in the right way.

Thanks!
