Title

Type inference gets confused when one parameter is null

Description
Consider the following code:

```
cs
    public class ExampleFailure
    {
        public struct Empty 
        {
... [Log Snipped] ...
        }
    }
```

If you run this, two of the cases will pass and one will fail, due to it incorrectly determining the type parameters of the third case to be ` ` and not ` `. It feel like when it encounters a null it gives up on working the rest of the type parameters out and just hopes `object` will be okay,

Encountered on `2.4.1`.
Discussion
- Verified broken in both v2 and v3.
- I'm trying to get my machine set up to actually run the tests locally, but I think the following will work in the `ResolveGenericMethod` tests

```cs
		// Method (T, T) null inference
		yield return new object?[]
		{
			nameof(OneGenericParameter_UsedTwice_TwoParameters),
			new object?[] { null, "2" },
			new Type[] { typeof(string) }
		};
```
