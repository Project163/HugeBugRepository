Title

Excessive MK.nodeExists() calls with many child nodes

Description
The number of calls to MK.nodeExists() go up excessively once a node reaches KernelNodeState.MAX_CHILD_NODE_NAMES. 

 There are a  lot  of repeated calls to MK.nodeExists() for the same path. E.g. using the test from   OAK-643  , the nodeExists() call start to spike once MAX_CHILD_NODE_NAMES is reached. Adding another 100 child nodes then resulted in 400 successive calls to "/testRoot/test4/oak:index" and many more calls to other paths.
Discussion
- Fixed in revision: 1452336 

 The cache in KernelNodeStore now also caches the result of a nodeExists() call when it returns false (node does not exist).
- Nice! I think this was much needed.  

 Just for the records, a bloom filter is a very good candidate for negative caches. Just in case we need to further optimise this.
