Title

Support for snake case in environment variables can lead to Elasticsearch nodes unable to boot on K8s

Description
**Elasticsearch version** 7.15.0-SNAPSHOT


**Description of the problem including expected versus actual behavior**:

We started testing ECK against 7.15 snapshots and it seems that [URL] breaks our tests as we have called many test clusters `es-something`. ECK generates a Kubernetes service for each cluster to expose the Pods to clients and by convention uses the cluster name as part of the service name e.g. `es-something-http`.
 
Now Kubernetes [Link: generates environment variables] of the form ES_SOMETHING from those services which will be present in any Pod.   Elasticsearch will pick those up and fail to boot as `ES_SOMTHING_HTTP` this is not a valid setting (I simplified the names a bit here just to convey the idea). 

We could now simply rename our test clusters and avoid naming things starting with `es-*` but I wonder if users will hit this too, once we ship 7.15 if they happen to have any Kubernetes services whose names start with `es-`
