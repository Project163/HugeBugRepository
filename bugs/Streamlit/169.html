Title

Sliders with default range value initialized using "sessionstate" becomes single value

Description
### Summary

I created two sliders with default range values. Slider X uses the "sessionstate" pattern (only setting "key"); Slider Y uses both "value" and "key" (without explicitly setting "sessionstate"). The first slider loses its range value when it is clicked and becomes a single value.

### Steps to reproduce

Code snippet:
```
import streamlit as st
if "x" not in st.session_state:
    st.session_state["x"] = (3,7)
x = st.slider("x", min_value=0, max_value=10, key="x")
y = st.slider("y", min_value=0, max_value=10, value=(2,8), key="y")
st.write(st.session_state)
```

If applicable, please provide the steps we should take to reproduce the bug:

1. Go to the main page.
2. Click on any of the sliders.
3. Click on the "x" slider (both left and right ends).

**Expected behavior:**

Expected "x" slider to maintain a range value [a, b] like "y" slider.

**Actual behavior:**

The "x" slider becomes a single value.

### Is this a regression?

No. (Caveat: I only started using Streamlit last week so I don't know if it worked in the distant past.)

### Debug info

- Streamlit version: 1.7.0
- Python version: 3.8.10
- Using pip in a venv
- OS version: Windows 10
- Browser version: Chrome Version 99.0.4844.82

### Additional information

I have a fix which seems to work for me. In [Link: streamlit/elements/slider,py], "value" is tested for null and set to min_value or 0. This works for sliders that take in a single value but not for range value. I think it should get the saved default value in session state instead.
