Title

Prompt does not get updated in PowerShell on Unix systems

Description
## Bug Report

#### Current Behavior
When using Powershell core on either Linux of MacOS together with Starship, Starship always displays the prompt as if it's in the home directory and no file module is active

#### Expected Behavior
The prompt should reflect the current directory and the file modules

#### Additional context/Screenshots
 
[Image: image]


#### Environment
- Starship version: 0.26.4
- Shell type: PowerShell
- Shell version: PowerShell 6.2.3
- Shell plugin manager: None
- Terminal emulator: iTerm2
- Operating system: Ubuntu 18.04, macOS 10.13

#### Relevant Shell Configuration
None. Just run `Invoke-Expression (&starship init powershell)` from the shell prompt.

#### Starship Configuration
No configuration file
Discussion
- [Image: image]
I did some further testing. It seems that this isn't related to the fact that starship runs from the powershell prompt function, because even running it directory from Powershell makes it think that it's referring to the initial Powershell path. It seem that also `/bin/pwd` is able to see the change in the working directory. Does starship determine the working directory in some special way?
- As it turns out, starship tries to look for the `PWD` environment variable before falling back to `env::current_dir()`. When you run Powershell from some Unix shell such as bash, the `PWD` stays in the directory in which bash executed Powershell. Since Powershell does not set this variable, the directory in Starship seems "stuck"
- Reopened as this is something that Starship should support.
If the user is using Powershell, opt to use `env:current_dir()` instead of `$PWD`, or an alternative solution.
