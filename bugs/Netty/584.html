Title

OpenSSLContext Mutual Auth Not Returning Acceptable CAs

Description
### Expected behavior
Openssl provider should behave same as JDK provider when mutual authentication is required and a specific set of trusted Certificate Authorities are specified.  The SSL handshake should return back to the connected peer the same list of configured Certificate Authorities.

```java
SslContext ctx = SslContextBuilder.forServer(APP_CERT, APP_KEY)
    .trustManager(TRUST_CA).sslProvider(SslProvider.JDK)
    .clientAuth(ClientAuth.REQUIRE).build();
```

```
bash
$> openssl s_client -connect localhost:8443 -cert app.crt -key app.key -CAfile rootCA.pem -tls1

CONNECTED(00000003)
depth=1 /C=US/ST=VA/O=MyCompany/CN=TestCA
... [Log Snipped] ...
    Verify return code: 0 (ok)
---
```
 
### Actual behavior
Openssl provider does not return a list of acceptable Certificate Authorities during SSL handshake.

```java
SslContext ctx = SslContextBuilder.forServer(APP_CERT, APP_KEY)
    .trustManager(TRUST_CA).sslProvider(SslProvider.OPENSSL)
    .clientAuth(ClientAuth.REQUIRE).build();
```

```
bash
$> openssl s_client -connect localhost:8443 -cert app.crt -key app.key -CAfile rootCA.pem -tls1
CONNECTED(00000003)
depth=1 /C=US/ST=VA/O=MyCompany/CN=TestCA
verify return:1
... [Log Snipped] ...
    Verify return code: 0 (ok)
---
```

### Steps to reproduce
1. launch [Link: MutualSSLAuthServer] with `JDK` parameter
```bash
   $> java SSLMutualAuthServer JDK
```

2. connect to server and notice the list of client certificate CA names
```bash
   $> openssl s_client -connect localhost:8443 -cert app.crt -key app.key -CAfile rootCA.pem -tls1
...
Acceptable client certificate CA names
/C=US/ST=VA/O=MyCompany/CN=TestCA
...
```

3. next, re-launch MutualSSLAuthServer with `OPENSSL` paramater
 ```bash
   $> java SSLMutualAuthServer OPENSSL
```

4. connect to server and notice the list of client certificate CA names
