Title

[Bazel] cc_grpc_library rule should not repeat the --proto-path argument unnecessarily when virtual_imports are enabled

Description
Related to #20675

Consider a common case whereupon a certain service contains many methods and each method has its own message types (the message types having embedded types and so on). The messages and additional types are each defined in their own proto files (so there are many proto files in the package). Some manipulation of include path is present in the proto rule.

`cc_grpc_library` will emit the following command: protoc --plugin=protoc-gen-PLUGIN=grpc_cpp_plugin --PLUGIN_out=  --proto_path   .... --proto_path  

Where the number of repeated `--proto_path` arguments will be equal to the number of dependent proto files in the package. The directory each `--proto_path` points to will be the same.

This makes the very long rule action command lines even longer, pushing them to the very limit for no reason whatsoever.

Clearly, for each unique directory only a single `--proto_path` must be added to the command line, not one for each included file in the same dir.
