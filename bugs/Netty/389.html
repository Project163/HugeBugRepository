Title

channelReadComplete not triggered for EpollDatagramChannel

Description
Netty Version: Master (latest snapshot)
JDK: 1.7.0u21
Platform: Linux x86_64 GNU/Linux Ubuntu 12.04

When using UDP with Epoll, the `EpollDatagramChannel` does not trigger a `channelReadComplete` call after calling `channelRead`.  It needs to call `channelReadComplete` so that a user can trigger a `ctx.flush`. Possible fix is to trigger `pipeline.fireChannelReadComplete` after [Link: this line]

Also, comparing `EpollDatagramChannel` to `EpollSocketChannel`, if an [Link: exception is thrown while looping], the catch clause in `EpollSocketChannel` calls [Link: handleReadException] and may trigger another `channelRead`.  `EpollDatagramChannel` does not do this... should it?
