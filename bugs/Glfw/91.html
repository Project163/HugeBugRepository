Title

glfw3Config.cmake installs into wrong directory and hence breaks find_package for 3rd party cmake based projects

Description
If a cmake based project, like glfw, installs an *-config,cmake or *Config,cmake it automatically enables other cmake based projects to just find it using the  find_package  command.  Since glfw's config file is glfw3Config.cmake putting this inside a CMakeLists.txt should just work

``` cmake
find_package(glfw3 REQUIRED)
```

But it doesn't.  The above  find_package  statement searches for glfw3Config.cmake in a number of locations, among then

``` sh
$INSTALL_PREFIX/lib/cmake/glfw3/glfwConfig.cmake
```

The problem is that you guys install it to

``` sh
$INSTALL_PREFIX/lib/cmake/glfw
```

rather than

``` sh
 $INSTALL_PREFIX/lib/cmake/glfw3
```

The solution is to either install the config file to

``` sh
$INSTALL_PREFIX/lib/cmake/glfw3
```

or to keep the installation dir, rename the config file to glfwConfig.cmake and tell people to use

``` cmake
find_package(glfw REQUIRED)
```

find_package(foo REQUIRED)
