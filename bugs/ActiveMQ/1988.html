Title

Pending Queue Counter is incorrect when using durable topics

Description
When using a durable topics the Pending Queue Counter provides an incorrect value for pending messages. 

 Steps to recreate 

 Set up the durable subscriber 

  
 ant consumer -Durl=tcp://localhost:61616 -Dtopic=true -Dsubject=MYSUB -Ddurable=true -Dmax=2
 
  

 Stop the subscriber 

 Send 20 persistent messages 

  
 ant producer -Ddurable=true -Durl=tcp://localhost:61616 -Dtopic=true -Dsubject=MYSUB -Dmax=20
 
  

 Consume 2 messages 

  
 ant consumer -Durl=tcp://localhost:61616 -Dtopic=true -Dsubject=MYSUB -Ddurable=true -Dmax=2
 
  

 View the counter stats. 

 The result is the following: 

  
 Pending Queue Size = 38
Dispatched Queue Size = 0
Dispatched Counter = 20
Enqueue Counter = 20
Dequeue Counter = 2
Discussion
- Test case that reproduces.
- The first stab at fixing this is in svn revision 1511333. I changed the way keepDurableSubsActive works, by not stopping/starting the cursor when subscription (de)activates. This is a natural way in how this feature should work and also simplifies things a bit. 

 I verified the fix by running all tests with that has durable in the name, but we should wait for the full nightly build to see if something is broker.
