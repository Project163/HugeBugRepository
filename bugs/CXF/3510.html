Title

case where cxf-codegen-plugin not working with jdk11

Description
A description with a maven project to reproduce the problem can be found on  [URL]
Discussion
- Actually I can see this error with both JDK8 and JDK11. 

 The suspicious code com.sun.codemodel.fmt.JStaticJavaFile$ResourceLoader was introduced since jaxb 2.3. And in CXF 3.3.1, both JDK8 and JDK11 will use same jaxb 2.3.2 

 Freeman
- OK, I believe this is a jaxb 2.3.x bug 

 The related code trying to load java src is like 
  
 
 // some people didn't like our jars to contain files with .java extension,
              // so when we build jars, we'' use  ".java_" . But when we run from the workspace,
              // we want the original source code to be used, so we check both here.
              // see bug 6211503.
             InputStream stream = loadingClass.getResourceAsStream(shortName +  ".java" );
             if  (stream ==  null ) {
                stream = loadingClass.getResourceAsStream(shortName +  ".java_" );
            }
             if  (stream ==  null ) {
                 throw   new  InternalError( "Unable to load source code of "  + loadingClass.getName() +  " as a resource" );
            }
             return  stream;
 
  

 From the comment above, the jar should contains .java file, and this is true for jaxb 2.2.x like 
  
 
com/sun/tools/xjc/runtime/JAXBContextFactory.class
com/sun/tools/xjc/runtime/JAXBContextFactory.java
com/sun/tools/xjc/runtime/ZeroOneBooleanAdapter.class
com/sun/tools/xjc/runtime/ZeroOneBooleanAdapter.java
 
  
 but for jaxb 2.3.x, the java source file get removed from jaxb jar, and this cause such error
- OK, the jaxb community now is aware this issue and get it fixed last month.

 We just need to wait until a new jaxb release which contains the fix
