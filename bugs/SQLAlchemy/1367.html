Title

Incorect params for compiled bindparameter with render_postcompile

Description
**Describe the bug**
Expanding BindParam compiled with render_postcompile option set to True produces incorrect params and placeholders
 

**Expected behavior**
compile of BindParam will produce one placeholder with one parameter.
 

**To Reproduce**
```
py
from sqlalchemy.sql.expression import bindparam

clause = bindparam('key', value=[('1', '2'), ('3', '4')], expanding=True)

... [Log Snipped] ...
print(compiled_query)  # '((:key_1_1, :key_1_2), (:key_2_1, :key_2_2))'
print(compiled_query.params)  # {'key_1_1': ('1', '2'), 'key_1_2': ('3', '4')}
```
**Versions.**
 - OS: os X 11.2 (20D64)
 - Python: Python 3.9.1
 - SQLAlchemy: 1.4.1
 - Database: postgres
 - DBAPI: any

**Additional context**
Same code for SQLAlchemy: 1.3.20 produced different results
```
py
from sqlalchemy.sql.expression import bindparam

clause = bindparam('key', value=[('1', '2'), ('3', '4')], expanding=True)

... [Log Snipped] ...
print(compiled_query)  # '([EXPANDING_key])'
print(compiled_query.params)  # {'key': [('1', '2'), ('3', '4')]}
```
