- FYI  ningk  - I'm going to send a PR to skip this for now.
- I've been unable to repro this locally so far. Regardless, we may be able to fix by making this test's assertion more lenient
- Got it, the root cause should be: 

  repr()  is not deterministic if a dictionary or set type is embedded in the object you are trying to serialize. 

   

 Since here we are trying to test against _ annotations _ of a NamedTuple that is a dict, the expected result is non-deterministic. 

 We could modify the test to test with assertContains.
- The root cause is that when building a Union type (typing._GenericAlias), its parameters are deduplicated through a set, thus causing the built Union type having non-deterministic order of parameters. 

 E.g., when interpreting Union [int, str] , it can be either "Union [int, str] " or "Union [str, int] " once it's created.
