Discussion
- View.updateAffectsView  doesn't actually verify that the partition being updated actually matches the base table of the view.  

 I've pushed a patch here that I believe fixes this:  [URL] - Includes a test, but I'm unable to get (any) unit tests to run tonight. Hoping cassci runs cleanly.
- we should never be getting the wrong ColumnIdentifier from a different base table. this sounds like a bug in the metadata lookup
- Was able to get tests to run, and confirmed that this happens iff there are more than one table in a KS AND more than one tables with a corresponding MV. Force pushed an updated test to the cassandra-10503 github link above.  carlyeks  , you may want to catch this higher up in the call stack?
- This looks like the right approach; we had the check in  ViewManager.updatesAffectView , but we should have had it in the  View  instead for the case where you have multiple tables and views on different tables. 

 I pushed an  updated branch  to remove the now redundant  ViewManager  check, as well as a change around  TemporalRow.Set  to make sure we aren't requerying when the update doesn't affect the view.
