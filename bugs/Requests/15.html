Title

Cookies not persisted when set via functional API.

Description
Cookies set as part of a call to `Session.request()` (or any of the top level methods that call it) are _not_ persisted, including on redirects.

Expected behaviour:

``` python
'hi=there'
```

Actual behaviour:

``` python
KeyError: 'cookie'
```

And, a super extra bonus bug:

``` python
KeyError: 'cookie'
```

even though we definitely sent the cookie on the first request.
Discussion
- In the hope of getting more contributors, I'm going to leave my diagnosis of the bug up here for a little while before I take a pass at fixing it.

The specific problem in this bug is that we don't add cookies on a prepared request to the Session unless they were set by the server. There are three possible scopes for this fix:
1. Only fix up the occurrences of this bug in the top-level functions, e.g `requests.request()`. This _must_ be fixed, because otherwise cookies are stupid for these functions. The logic behind this restriction is that if you want cookies on all requests in a session, you should set them on the `Session` object.
2. Add all cookies set through the functional API to the correct `Session` object. It's not entirely clear that this is the right thing to do: these cookies should probably have been set on the `Session`.
3. Do something 'magic' for redirects.

As for the super-extra bonus bug, the offending lines of code are these in `SessionRedirectMixin.resolve_redirects()`:

``` python
headers = prepared_request.headers
try:
    del headers['Cookie']
except KeyError:
    pass
```

combined with the implementation of `PreparedRequest.copy()`:

```
python

    p = PreparedRequest()
    p.method = self.method
    p.url = self.url

    return p
```
