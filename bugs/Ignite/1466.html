- Recent changes in the branch show that generally approach works - custom messages should not be fired in between of NodeAddedMessage and NodeAddFinishedMessage. 

 However, the changes led to the following issues: 
 
	 Assertion "topology version has not been updated". Caused by sending discard message for custom messages. Now since we re-arrange custom messages, discardId gets repositioned and messages that should have been discarded were not discarded. Fixed the issue above by introducing separate pending queue for custom messages which gets discarded independently from other discovery messages. 
	 Assertion "joining nodes is not empty". Did not get to the bottom of the assertion. Coordinator always fires the message at the correct moment, however for some reason custom messages get re-sent after processing and got received by non-coordinator node in the middle of node join process.
