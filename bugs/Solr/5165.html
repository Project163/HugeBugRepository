Title

Affinity Placement Plugin can fail when getting metrics, if multiple replicas claim shard leadership

Description
Using Solr 9.4 with 16 nodes, I observe that about 25% of our Split Shard requests are failing. The error is a RuntimeException that is raised by the AttributeFetcher as it compiles the metrics that will be used by the plugin. 

   

 The AttributeFetcher is making /admin/metrics requests to each node, and currently it expects to be able to establish a consistent  view of shard leadership across the cluster from the responses.

Discussion
- I think there is a somewhat trivial solution for this issue. The metric that the placement plugin is interested in is the size of the index, and I don't think it matters if the Attribute Fetcher observes multiple leaders for a Shard. 

 It could just pick any replica that claims leadership, because all of them are able to provide the required index size metric. 

 I am not sure if there are other cases fulfilled by the Attribute Fetcher where this would be a problem, I haven't found any yet.  

   

 I will put together a PR with a proposed solution.
