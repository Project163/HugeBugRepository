Title

SHA1 mismatch when copying large files (B2).

Description
When copying a large files (+500 MB) from a Backblaze B2 bucket to a local folder, the file copy fails with the error: 'Failed to copy: object corrupted on transfer - SHA1 mismatch (want "none" got " ")'.

Looking at the source the "none" sha1 is supposed to be retrieved from B2 while " " is created from the received file.

Therefore I checked the remote sha1sum using "rclone sha1sum brive:testvlad/REC_0002.MOV" which returned " ". So the file is synced ok, so something must be going wrong when retrieving the sha1sum from B2.

Rclone version: 1.33

OS: Debian Stretch (AMD64)

Cloud storage: Backblaze B2

Command causing issue: "rclone -v --transfers 32 --retries 10 copy brive:testvlad /home/kelvin/trive"

The tested file is 1 GB in size with the sha1 sum " ".

See attached file for log with '-v' flag.
