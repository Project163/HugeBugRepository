Title

platform-http - Error in clientRequestValidation consumes & produces when plus sign in content-type

Description
Base on topic  #camel-quarkus > platform-http error validating consumes & produces @ 💬  

  Hi! 
I've tested in 3.8.x and current 3.21.x quarkus version. 
In both cases whenever you define and endpoint where you want to validate consumes or produces mime-types the validation fails if the mime-type you want to validate contains plus '+' symbol, for example 'application/fhir+json'. Retrieving a response of 406 or 415 if you add the proper one in 'Accept' and 'Content-Type' header. 
For example try to use these routes: 
  
 
    @Override
     public  void configure()  throws  Exception {

        restConfiguration().component( "platform-http" )
            .host( "localhost" )
            .port(8080)
        ;

		 // Using  rest  consumer
          rest ( "/test/ rest " )
            .post()
            .routeId( "Main-Route" )
            .description( "Create a FHIR resource" )
            .clientRequestValidation( true )
            .consumes( "application/fhir+json" ) 
            .to( "direct:createResource" )
        ;

        from( "direct:createResource" )
            .routeId( "Create Resource FHIR" )
            .log( "Received FHIR: ${body}" )
            .setBody(simple( "{ 'response' :  'Bundle FHIR processed successfully' }" ))
            .log( "Response: ${body}" )
        ;

         // Using platform-http consumer
         from( "platform-http:/test/platform?produces=application/fhir+json&httpMethodRestrict=GET" )
            .routeId( "Test Platform" )
            .log( "Received FHIR JSON: ${body}" )
            .setBody(simple( "{ 'response' :  'Bundle FHIR JSON processed successfully' }" ))
            .log( "Response: ${body}" )
        ;
    }
 
  
 Then if you try to call them, for example with 'curl' as follows: 
  
 
curl -H  'Accept: application/fhir+json'  [URL] -v
 
  
 You will get a 406 response. 
And for POST, using 'curl': 
  
 
curl -H  'Content-Type: application/fhir+json'  -X POST -d  '{ "resource" :  "Patient" , ...}'
