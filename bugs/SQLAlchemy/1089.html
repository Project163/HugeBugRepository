Title

Query cache issue when using criteria based loader options

Description
**Describe the bug**
We appear to be getting a incorrect cache hit when using criteria with loader options

**Expected behavior**
The query parameters should be updated.

**To Reproduce**

```
py
from sqlalchemy import (
    Column, Integer, String, ForeignKey, create_engine
)

... [Log Snipped] ...
# 2021-03-26 10:28:12,303 INFO sqlalchemy.engine.Engine [cached since 0.004025s ago] (1, 'object_registry', 'EXISTS')
assert 0 == len(get_query('NONE_EXISTING').all()[0].links)
```


**Versions.**
 - OS: CentOS Linux release 8.2.2004 (Core) 
 - Python: Python 2.7.17
 - SQLAlchemy: 1.4.3
 - Database: mariadb / sqlite ( tested ) 
 - DBAPI: any

**Additional context**
There are other cases that I have not yet been able to reproduce outside of our main application where it looks like the criteria is fully skipped and not added to the query at all (  incorrect cache hit? ) as it works if sqlalchemy is reloaded.

**Cheers**
Discussion
- OK so I apologize, the test suite for the new A.bs.and_() feature failed to run any caching related tests, and for any loader options that emit a second SELECT statement, this feature should be considered broken at the moment.

your test case can work if all caching is disabled, note bake_queries=False and query_cache_size=0:

```
python
class ObjectLink(Base):
    __tablename__ = "object_link"

    id = Column(Integer, primary_key=True)
... [Log Snipped] ...

engine = create_engine("sqlite:///:memory:", echo=True, query_cache_size=0)
```

I have a vague idea of where this is going wrong but it might be going wrong in multiple places, not clear yet.   I may not have adequate time to fix this today as I have other things going on as well.
