**What did you expect to happen?**

The id-length rule to fire due to the `.q` property access.

**What actually happened? Please include the actual, raw output from ESLint.**

The id-length rule did not fire - there was no output from ESLint, no warnings or errors. This happens in both my editor which runs it on the one file, and when running ESLint from the project level.

If I change that line to instead use a boolean operator like so:


Discussion
- Verified this in online demo. The following code doesn't produce an error:

``` js
/* eslint "id-length": "error" */
const query = location.query.q ? location.query.q : ''
```

But this one does:

``` js
/* eslint "id-length": "error" */
const query = location.query.q || ''
```

Should this rule check properties every time, or only on assignment anyways?

Do we know what the next steps are here?
- Seems like we should be consistent in our treatment of

``` js
const query = location.query.q ? location.query.q : ''
```

and 

``` js
const query = location.query.q || ''
```

It makes sense to me to not warn at all for the right hand side, for the reasons mentioned above, so my vote is to not warn on either of the above. Maybe I'm missing something, though?
