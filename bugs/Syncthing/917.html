Title

panic with "WARNING: Error starting the main Syncthing process: exec: "syncthing.exe": cannot run executable found relative to current directory" when starting v1.21.0-rc.1 in command line in Windows

Description
This happens if you try to start the current RC from the command line in Windows.

```
R:\syncthing-windows-amd64-v1.21.0-rc.1>syncthing.exe
[monitor] 2022/08/13 15:32:57 INFO: Log output saved to file "C:\Users\User\AppData\Local\Syncthing\syncthing.log"
[monitor] 2022/08/13 15:32:57 WARNING: Error starting the main Syncthing process: exec: "syncthing.exe": cannot run executable found relative to current directory
panic: Error starting the main Syncthing process

... [Log Snipped] ...
created by os/signal.Notify.func1.1
        os/signal/signal.go:151 +0x2a
```

The workaround is to use `.\syncthing.exe`, but this wasn't the case before when compiled with Go 1.18. I personally think it is a big problem, because this requirement is very likely to break custom scripts, especially since using `.\` isn't common in batch scripts at all (as it's optional and thus usually omitted).
Discussion
- Isn't this a new restriction introduced in go 1.19?

[URL]
- Probably, because I've just recompiled with Go 1.18, and the issue is gone.

Is this restriction absolutely necessary though? Would it be a problem to disable it? It breaks the established workflow, as no command line Windows software behaves like that (or at least I've never encountered anything similar until now). The CMD itself doesn't even add `.\` to paths when using TAB autocomplete (in contrary to PowerShell, which does).

**Edit**:

I also want to add that this crashes Syncthing on upgrade from an older version.

1. Run v1.20.4 from the command line, e.g. `syncthing.exe -home=test`
2. Enable upgrade to release candidates, restart, and press the upgrade button in the GUI.
3. The upgraded executable fails to start with the same panic as described above.
- That's because of our monitor stuff using `exec` with `arg[0]` which is `syncthing`, and thus being affected by that behaviour change. I'll take care of it.
