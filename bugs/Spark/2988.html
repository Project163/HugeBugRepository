Title

NullPointerException using checkpointed mapWithState with KryoSerializer

Description
Issue occured after upgrading to the RC4 of Spark (streaming) 1.6.0 to (re)test the new mapWithState API, after previously reporting issue   SPARK-11932   ( [URL]  

 For initial report, see  [URL]

 Narrowed it down to an issue unrelated to Kafka directstream, but, after observing very unpredictable behavior as a result of changes to the Kafka messages format, it seems to be related to KryoSerialization in specific. 

 For test case, see my modified version of the StatefulNetworkWordCount example:  [URL]  

 To reproduce, use RC4 of Spark-1.6.0 and  
 
	 start nc:
  
 nc -lk 9999 
   
	 execute the supplied test case:
  
 bin/spark-submit -- class  org.apache.spark.examples.streaming.StatefulNetworkWordCount --master local[2] file: ///some-assembly-jar localhost 9999  
   
 

 Error scenario: 
 
	 put some text in the nc console with the job running, and observe correct functioning of the word count 
	 kill the spark job 
	 add some more text in the nc console (with the job not running) 
	 restart the spark job and observe the NPE 
(you might need to repeat this a couple of times to trigger the exception)

- Ah,  org.apache.spark.streaming.util.OpenHashMapBasedStateMap  doesn't support Kryo. I submitted a PR to fix it. 

 Right now you need to use KryoRegistrator to register OpenHashMapBasedStateMap by yourself. E.g., 

  
     class  CustomRegistrator  extends  KryoRegistrator {
      override def registerClasses(kryo: Kryo) {
        kryo.register(
           Class .forName( "org.apache.spark.streaming.util.OpenHashMapBasedStateMap" ),
           new  com.esotericsoftware.kryo.serializers.JavaSerializer())
      }
    }

    sparkConf.set( "spark.kryo.registrator" , classOf[CustomRegistrator].getName)

- kerkero  mapWithState doesn't work with "spark.kryo.registrationRequired = true". This is because Streaming cannot add its class into Core since Core doesn't depend on Streaming. Theforefore, Spark Streaming cannot do the registration. However, in 1.6.1, mapWithState should work correctly as it implements "KryoSerializable", so you can turn off "spark.kryo.registrationRequired".  

 I see you may want all of your classes are registered to make sure the Kryo serialization work correctly, then you can just write some unit tests that only test the Kryo serialization of your classes with "spark.kryo.registrationRequired = true".
