Title

Ignore pattern (?i) not working correctly for subfolders

Description
Trying to create an ignore pattern that ignores all variants of Thumbs.db and Desktop.ini files.

On one of my windows machines:

Pattern used:

"(?i)thumbs.db
(?i)desktop.ini"

This ignored all thumbs and desktop files within the root of the folders, but didn't exclude files within sub directories. 

 output of [URL]

{"ignore":["(?i)thumbs.db","(?i)desktop.ini"],"patterns":["(?i)^thumbs.db$","(?i)^.\([^\]i)thumbs.db$","(?i)^thumbs.db\.$","(?i)^.\([^\]i)thumbs.db\.$","(?i)^desktop.ini$","(?i)^.\([^\]i)desktop.ini$","(?i)^desktop.ini\.$","(?i)^.\([^\]i)desktop.ini\.$"]}

This is the thread where I first brought this up: [URL]

As mentioned in the thread, also potentially a second bug, when creating the ignore pattern the .stignore file isn't hidden by default, when I then hide it manually and edited it as per calmh's suggestions it became unhidden once more.
Discussion
- For excluding files in sub folders you need *\* I believe.
So try `(?i)**desktop.ini`
- From the syncthing docs:

Regular file names match themselves, i.e. the pattern foo matches the files foo, subdir/foo as well as any directory named foo. Spaces are treated as regular characters.

So surely the double \* is not required?
- ... [Middle Discussions Snipped for Brevity] ...
- This is simply a problem of providing both a `textual` and a `regex` description of the ignore patterns at the same time. This is confusing for users and causes bugs
- We've discussed it before and generally decided that regexes are too much of a footgun to be good for most users, even though it would make the implementation trivial. On the other hand, people are fairly used to glob matching á la `?` and `*`, and for those who are familiar with neither the latter is easier to explain.

There should be no mention of regexes anywhere near the current ignore system, because there's nothing regexy about it from a user point of view. The `(?i)` prefix does come from there, but is as good or bad a prefix as any for glob patterns as well.
