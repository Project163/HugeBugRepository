Title

Coverage on macOS doesn't filter out system headers

Description
### Description of the problem / feature request:

The coverage.dat file produced on macOS contains entries for system headers in /Applications.

### Bugs: what's the simplest, easiest way to reproduce this bug? Please provide a minimal example if possible.

BUILD file:

```
python
cc_test(
    name = "test",
    srcs = ["test.cc"],
    deps = [":lib"],
... [Log Snipped] ...
    hdrs = ["lib.h"],
)
```

lib.h:

```c++
extern void Function();
```

lib.cc:

```c++
#include "lib.h"
#include  
void Function() {
  std::cout << "hello world" << std::endl;
}
```

test.cc:

```c++
#include "lib.h"
int main() {
  Function();
}
```

Then, run

```sh
bazel --nohome_rc --nosystem_rc --noworkspace_rc --bazelrc=/dev/null coverage \
  --test_env=VERBOSE_COVERAGE=1 --test_env=GCOV_PREFIX_STRIP=10 \
  --test_output=all --nocache_test_results //:test
```

The GCOV_PREFIX_STRIP is for [URL]

The resulting coverage file will contain lots of data for C++ standard headers residing in the /Applications directory.
Probably that directory can simply be added to [URL] because it's very unlikely that someone will have a Bazel workspace in /Applications.
