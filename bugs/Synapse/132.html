Title

JMS doesn't handle POX correctly

Description
This issue was originally reported by Asanka A on the user mailing list: 

  [URL]

 I encountered a similar problem when trying to write a unit test for POX over JMS. 

 There seem to be two problems: 
1. JMSUtils#getInputStream doesn't call BytesMessage#reset. Therefore, when getInputStream is called twice, the second time an empty input stream is returned. 
2. BaseUtils#setSOAPEnvelope doesn't take into account that builder.getDocumentElement().getNamespace() can return null.
