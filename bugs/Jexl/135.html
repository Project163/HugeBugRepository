Title

ASTAddNode does not add BigDecimal objects correctly

Description
The ASTAddNode only checks for Float or Double objects when adding floating point numbers. If the objects are not Float or Double, they are added as Long's. As a result, adding BigDecimal objects loses any existing decimal points.

- I agree the current case is wrong, but I'd much rather see a special case where if left/right is a BigDecimal then the other  side is coerced into a BigDecimal and BigDecimal.add called. 

 WDYT?
- I'm a JEXL noob so I don't really care how it's done. I know there are workarounds (i.e. a.add(b) or a+0.0+b) but what we're getting now are just incorrect results when + is called on BD's. 

 As far as implementation, I think you're right. Converting BD to Double or Float loses precision. It would be nice to treat a BD as a BD and retain the advantages of using a BD. I think you're idea is a good one. You don't really lose anything converting from Double or Float to BD. So, if a BD is either left or right, it makes sense to upconvert the other to BD as well.
