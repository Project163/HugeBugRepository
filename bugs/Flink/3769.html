Discussion
- I think this is also introduced by   FLINK-15912  . I reproduced the problem using the following yaml: 

  
 
tables:
  - name: lineitem
    type: source-table
    update-mode: append
    connector:
      type: filesystem
      path:  "$TABLE_DIR/lineitem.csv" 
    format:
      type: csv
      fields:
        - name: l_linestatus
          type: VARCHAR
        - name: l_shipdate
          type: DATE
        - name: l_commitdate
          type: TIMESTAMP
      field-delimiter:  "|" 
      line-delimiter:  "\n" 
      comment-prefix:  "--" 
    schema:
      - name: l_linestatus
        type: VARCHAR
      - name: l_shipdate
        type: DATE
      - name: l_commitdate
        type: TIMESTAMP
 
  

 The root cause is we will convert the properties into CatalogTableImpl and then convert into properties again. The schema type properties will use new type systems then which is not equal to the legacy types.
- This is something related to  FLINK-15038 . 

  TableSchema  should not contains various conversion classes.
