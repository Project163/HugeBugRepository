Title

[YSQL] Out of bound memory access could cause crash in new cost model

Description
Jira Link: [Link: DB-13142]
### Description

We may access out of bound memory during computation of the `ybctid` width in the `yb_get_ybctid_width` function. Specifically, this issue occurs when accessing system catalog tables such as `pg_class`.

This function is used in queries where DocDB returns `ybctid`. This happens in queries where no columns are projected and no filtering is needed on the PG side. 

This issue was identified first in running `ysql_dump` and caused a crash. The crash does not reproduce every time.

The crash occurs on this [Link: line].

On debugging with the following query, it was found that we access out of bound memory in `TupleDescAttr(baserel->rd_att, index->indexkeys[i] - 1);`.

```
SELECT 0 FROM pg_class;
```

The `pg_class` table has a primary key on system column `oid`. When computing the ybctid width, we try to get the size of this column. The `index->indexkeys[0]` is `-2` for the `oid` column. This leads to out of bound access on the `attrs` array. This can lead to incorrect cost estimation and in some cases, a segmentation fault.
