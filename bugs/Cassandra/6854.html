Title

When using BEGIN TRANSACTION if a complex mutation exists in the same statement as one that uses a reference, then the complex delete is dropped

Description
BEGIN TRANSACTION
  LET row = (SELECT *
             FROM distributed_test_keyspace.accordtbl0
             WHERE k = ? AND c = ?);
  UPDATE distributed_test_keyspace.accordtbl0
  SET
    v0={1},
    v1 += row.v1
  WHERE 
    k = ? AND 
    c = ?;
COMMIT TRANSACTION
 
  

 You would expect that v0= 
{1}
  after this runs, but assuming it was  
{0}
  before hand the output is  
{0, 1}
 .  The reason is that the complex delete gets lost
