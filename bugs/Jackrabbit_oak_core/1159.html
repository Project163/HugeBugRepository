Title

ServiceEvent on each session login/logout

Description
This is caused by   OAK-2407   where a GCMonitor is registered on login. This will result in a lot of service events when there are many short-lived sessions and Oak is deployed in an OSGi container.
Discussion
- Possible fix:  [URL]

 Only register a single  GCMonitor  per repository that delegates to per session  GCMonitor  instances.
- On a more general note I find that hidden contract of  Whiteboard#register  not being able to cope with many (un)registrations disturbing. (How much is 'many' anyway?). This is even more problematic as 'many' is implementation dependent and the problem doesn't show up in any of the tests/ITs/benchmarks we have in Oak.
