Title

[3-1-stable] default_url_options get called to early for tests

Description
Hi!

I believe, this is a regression from 3-0-stable, but maybe things are just different now. I have the following code:

```
Testit::Application.routes.draw do
  scope "/:locale", :constraints => { :locale => /[a-z]{2,3}/ } do
    get "c1" => "c1#index"
    get "c2" => "c2#index"
  end
... [Log Snipped] ...
  end
end
```

If I run that test, it fails, because it redirects to /en/c1. But if I run it in development on the webserver, it works as expected. Looks like default_url_options get called to early:

Test log:

```
default_url_options({}) #  "de"}
setting I18n.locale to "de"
Redirected to [URL]
Completed 302 Found in 1ms
```

Development log:

```
Started GET "/de/c2" for   at 2011-06-27 23:43:37 +0200
  Processing by C2Controller#index as HTML
  Parameters: {"locale"=>"de"}
setting I18n.locale to "de"
default_url_options({}) # <-- After the before_filter
Redirected to [URL]
Completed 302 Found in 1m
```

Why is that? With 3-0-stable, the test works as expected.
Discussion
- Is this behavior breaking something for you?
- Well, my tests for testing the correct redirection of the user fail even though if the application works fine.

The Rails Guides suggest to set the I18n.locale that way (http://guides.rubyonrails.org/i18n.html#setting-the-locale-from-the-url-params), so there may be others setting the locale that way.
- Can you provide a patch with a test case or at least just a failing test case?. Thanks.
- This issue doesn´t appear in 3.0.9 at all. Removing line [URL] resolves the issue for 3-1-stable, too. I´m unsure about the side effects involved in simply deleting this line so I don´t see this as the final solution yet :(
