Title

[3.2] po file parser throws fatal when dealing with translation comments

Description
This is a (multiple allowed):
- [x] bug
- [ ] enhancement
- [ ] feature-discussion (RFC)
- CakePHP Version: 3.2.3
- Platform and Target: php7 nginx.
### What you did

got translation from .po file with this content:

```
#: firstfile:39
msgid "Pending"
msgstr "En cours"

#: secondfile:12
msgctxt "Pay status"
msgid "Pending"
msgstr "En cours"
```
### Expected Behavior

while the example isnt best case, po file parser should handle it like firstfile having msgctxt - note if i add it to firstfile or remove from secondfile it works 
### Actual Behavior

```
2016-02-24 15:19:46 Warning: Warning (2): Illegal string offset '_context' in [/data/www/beta.test.com/vendor/cakephp/cakephp/src/I18n/Parser/PoFileParser.php, line 146]
```

Discussion
- The issue here is that only some of the matching `msgid` elements have a context. Because of how messages are stored internally if some message values have context, they all need context. While its possible to suppress the notice error, I don't think its possible to retain both the context-less and context-inclusive message without breaking changes.
- Closing as there is a pull request up to fix the notice error.
