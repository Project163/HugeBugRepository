InternalTrace.Initialize fails with Nullref exception

Discussion
- Yes, I think I can see what's happening...

1. `Initialize` is called with level `Off`.
2. `Tracewriter` is left null but `Initialized` is set to true.
3. `Initialize` is called a second time, with any level specified.
4. The else clause is executed with a null `TraceWriter`.

So we changed to allow re-initialization at a different level while the framework is still trying to protect itself against re-initialization. This didn't show up as a problem until we implemented the further change of lazily creating the `TraceWriter`.

We can't do both things... lazy creation and using the null value as an indicator of creation.
- Nice find!
Based on the existing code, I assume the desired behavior here is that this can be called multiple times, and the internal tracer should only be created the first time a level other that "Off" is specified?

In other words, the level can be changed from "Off" -> "something", but not from "something" -> "Off"?
