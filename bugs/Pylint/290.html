Title

"pylint.bat" incorrectly installed on OS X

Description
Originally reported by: **Steven Myint (BitBucket: [Link: myint], GitHub: @myint?)**

---

Is it intended for `*.bat` files to be installed on OS X? It seems to me that they should only be installed on Windows.

```
$ python --version
Python 3.5.0

$ pip install --user pylint

... [Log Snipped] ...
/Users/myint/Library/Python/3.5/bin/pylint.bat: line 4: rem: command not found
/opt/local/Library/Frameworks/Python.framework/Versions/3.5/Resources/Python.app/Contents/MacOS/Python: can't open file '%~dpn0': [Errno 2] No such file or directory
```

`pylint` proper works okay. I'm just not sure why the `*.bat` files are installed too.

```
$ /Users/myint/Library/Python/3.5/bin/pylint --version
No config file found, using default configuration
pylint 1.4.4,
astroid 1.3.8, common 1.0.2
Python 3.5.0 (default, Sep 16 2015, 07:03:35)
... [Log Snipped] ...
-rwxr-xr-x 1 myint staff 203 Sep 17 07:10 /Users/myint/Library/Python/3.5/bin/pylint-gui.bat
-rwxr-xr-x 1 myint staff 203 Sep 17 07:10 /Users/myint/Library/Python/3.5/bin/pylint.bat
```

Discussion
- I don't think this is something that should be fixed in pylint. Even when the files are installed, they are harmless for other OSes anyway.
- Not sure what changed (in `pip` or `pylint`) over the last few years, but the problem seems to be fixed now (even without having to use `--no-use-wheel` with `pip install`).
