Title

Should preserve the exchange type in the routing slip

Description
Currently, the routing slip will create a new InOut exchange for each target based on the target endpoint type. This means that someone calling from a jbi endpoint (or other endpoint with custom exchange) into the routing slip will have their exchange type changed (to mostly likely DefaultExchange). I will be including a patch to fix this issue shortly.
Discussion
- Patch to fix the issue. 

 The fix employs a technique similar to that of the pipeline processor to preserve the exchange type. Basically, in order for a type of Exchange to be propagated, it must override the newInstance method so the routing slip has a way to create a clean instance of it.
