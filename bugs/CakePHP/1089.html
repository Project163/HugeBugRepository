Title

EntityContext will not correctly set _isCollection

Description
When creating an EntityContext from any kind of iterable of multiple Entities (collection, array or whatever), the property _isCollection is not set to be true. This is due to the code which inspects the Entities for a Table modifies the variable `$entity` to contain the first Entity, and that variable is then checked for being a collection:

See [URL]

```
$entity = $this->_context['entity'];
if (empty($table)) {
  if (is_iterable($entity)) {
    foreach ($entity as $e) {
      $entity = $e;
... [Log Snipped] ...
  $entity instanceof Traversable
);
```

I am not sure if this is the desired or expected behavior, rather than a bug.
A bugfix would be trivial, just using `$this->_context['entity']` for the check rather than `$entity`.

Does anyone know if this behavior is intended?

4.3.4

- The problem is an unexpected inconsistency depending on wether the table is explicitly set or not.

This results in "null", because _isCollection is correctly set to true:
```
echo $this->Form->create($examples, [
  'context' => ['table' => 'Examples'],
]);
dd($this->Form->context()->val('key1'));
```

But when the table is not explicitly set, `val` returns the first entity instead of null:
```
echo $this->Form->create($examples);
dd($this->Form->context()->val('key1'));
```

And since the FormHelper uses the EntityContext::val method to populate default values of form fields, the difference in behavior appears there too. The following field default value will be empty when table is set, but contain the entire entity as json when the table is not set:

```
echo $this->Form->input('key1');
```
- That would only happen if you are using a numeric value as field name `input('0')` which in practice doesn't make much sense :slightly_smiling_face:. 

That said the inconsistency should be fixed.
