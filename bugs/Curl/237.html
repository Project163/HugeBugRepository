Title

aws-sigv4 not correctly signing requests with empty URL query params

Description
### I did this

```
URL="[URL]
curl -v \
     --aws-sigv4 "aws:amz:${REGION}:s3" \
     --get "${URL}" \
     --user "${aws_access_key_id}:${aws_secret_access_key}" \
     --header "X-Amz-Content-Sha256:  " \
     --header "X-Amz-Security-Token: ${aws_session_token}"
```

### I expected the following

With the proper setup of `BUCKET`, `REGION`, `aws_access_key_id`, `aws_secret_access_key` and `aws_session_token` I expect `200 OK` and data. See [URL]

However I got `403 Forbidden` and an error returned `SignatureDoesNotMatch`.

I have tracked it down a bit further and it it related to the `?versioning` parameter. If I set it to `?versioning=` then it works. AWS CLI seems to be doing that automatically, expanding `versioning` into `versioning=`.

So this works

```
URL="[URL]
curl -v \
     --aws-sigv4 "aws:amz:${REGION}:s3" \
     --get "${URL}" \
     --user "${aws_access_key_id}:${aws_secret_access_key}" \
     --header "X-Amz-Content-Sha256:  " \
     --header "X-Amz-Security-Token: ${aws_session_token}"
```
