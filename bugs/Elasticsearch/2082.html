Title

Cluster routing allocation filtering by node can break with multiple exclusions

Description
**Elasticsearch version** (`bin/elasticsearch --version`): 6.3.1

**JVM version** (`java -version`): openjdk version "1.8.0_171"

**OS version** (`uname -a` if on a Unix-like system): Ubuntu 16.04.2 LTS

**Description of the problem including expected versus actual behavior**:
Shard allocation exclusions appear to be broken after multiple exclusions have been applied for the same node, then one exclusion removed. 

**Steps to reproduce**:
The repro this is pretty straightforward. This may be a corner case, but it is enough to add confusion when managing a cluster. This repro excludes a single node by both IP and host in dynamic cluster settings, then removes the host exclusion. Once the condition is created, the IP exclusion is ignored. Full requests and responses have been posted to [URL]

```
GET _cluster/settings

GET _cat/allocation?v&s=node

PUT _cluster/settings
... [Log Snipped] ...

GET _cat/allocation?v&s=node
```

To fix null out all exclusions and reapply if needed:
```
PUT _cluster/settings

    "cluster.routing.allocation.cluster_concurrent_rebalance" : "2",
    "cluster.routing.allocation.exclude._ip" : null,
... [Log Snipped] ...

GET _cat/allocation?v&s=node
```

# Context

* Exclusion setting `cluster.routing.allocation.exclude._host` default value is an empty string.
* When an exclusion setting is sent with a `null` value the `o.e.c.s.Setting#innerGetRaw` API return an empty string (probably to avoid a `NullPointerException` to be raised).
* The `o.e.c.r.a.d.FilterAllocationDecider` class is developed to omit updates of default values for exclusion setting.

# Behavior

That's why a `null` exclusion setting value is translated to an empty string which is equals to the exclusion default value which is configured to be ignored.

# Solution proposal

A simple fix would be to not omit default values for exclusion setting and keep the `NullPointerException` guard. I'll find a way to finely test such a change and send a pull request.
