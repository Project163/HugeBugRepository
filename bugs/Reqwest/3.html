Title

RequestBuilder headers() method behaviour different than header() with multiple values for same key

Description
When adding headers through headers() one at a time all keys are properly set. However when constructing a HeaderMap beforehand and adding it using headers(), only one value from a certain key is kept.

Is this the desired behaviour? It surprised me and took a while to debug until I echoed the full request that was actually sent.

Caused by using insert() in headers() and append() in header().

Discussion
- I think this is partly a bug. Here's the behavior I'd expect:

- `header`: Always appends.
- `headers`: Replaces any existing headers for the same key, but then appends all values of the same key from the new `HeaderMap`.

So, I'd expect this behavior:

```
rust
let mut hdrs = HeaderMap::new();
hdrs.insert("foo", "bar".parse().unwrap());
hdrs.append("foo", "baz".parse().unwrap());

... [Log Snipped] ...
    .headers(hdrs)
    // ...
```

That should have a header map of the following:

```json
{
    "im-a": ["keeper"],
    "foo": ["bar", "baz"]
}
````
