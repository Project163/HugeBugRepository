docs(ToH): use interface instead of class to define the Hero model

## Current behavior
The ToH defines the Hero model using a **class**, but in the tutorial "instances" of this class arent created using the ctor of the class, promoting a bad practice. 

Furthermore the use of a class for this model is IMO inappropriate, as the class defines no behavior (methods). An interface would be better suited for this use case.

An example extracted from the tutorial:

```
class Hero {
  id: number,
  name: string,
}

... [Log Snipped] ...
  name: 'Superman'
}
````
Type checking will result in the following:

````
console.log(aHero instanceof Hero); //false
````

## Expected behavior
The Hero model should be defined using an **interface**.
