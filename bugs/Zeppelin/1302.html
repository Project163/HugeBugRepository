Title

When a note's JSON is corrupted (i.e. not a valid JSON), you cannot delete it

Description
Hello, 

 Not a huge deal but should an easy fix, but any note that somehow gets "corrupted" (and is not a valid json anymore), cannot then be open in Zeppelin (which is expected) but also cannot be moved to trash (it just displays the same warning popup as if trying to open it, the one with "Fail to parse note json:"). 

 So from the end user's point of view they cannot remove this faulty note. they need to have someone with backend access. I feel like deleting should still be possible in this case. 

 Regards, 

   

 Theo.
Discussion
- Is there a way this bug can be reproduced? I tried to corrupt the json from backend, seemed it would automatically reformat to a well-formatted json after running cells from the front-end. If I deleted the json from backend directly, it would disappear after refreshing the page from front-end. Can't find a way to trigger this 'Fail to parse note json'. Could you please provide an example? Thanks!
- Did you restart zeppelin after corrupting the json ? I think that's when it would happen, when zeppelin starts and the note is already corrupted. In terms of real life case for example, think of a zeppelin server that restarts daily and pulls from github, while someone made a change in the github directly that broke the note's json.
