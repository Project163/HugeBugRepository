Title

PAX headers with "strange" names can not be written

Description
as noted by  paburk  in   COMPRESS-203   if a non-ASCII character is "7-bit-cleaned" to '\' this may lead to a file name for the PAX header that looks like a directory name to TarArchiveEntry - which leads to a bug very similar to   COMPRESS-203  .
Discussion
- fixed with svn revision 1570800 

 The bug only ever showed on Windows as the \ => / translation only happens there.  Actually it didn't take any non-ASCII characters or very long names, a backslash in the wrong place was enough.
