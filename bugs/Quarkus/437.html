Title

Kubernetes: wrong .jar file name in JAVA_APP_JAR env var (for OpenShift)

Description
**Describe the bug**

The `JAVA_APP_JAR` environment variable, which the OpenShift Java images use to know which JAR they should run, is generated wrongly.

Dekorate generates this env var here: [URL]

From that code, it is apparent that Dekorate tries to use its knowledge about the build to figure out the correct file name.

However, if I define `quarkus.application.name`, this value is used as the file name, which is wrong, as `quarkus.application.name` can be something different than, e.g., Maven's `${project.build.finalName}`.

**Expected behavior**

The actual JAR file name is always used, even if `quarkus.application.name` is defined.

**Actual behavior**

The value of `quarkus.application.name` is used, even if it doesn't match the file name.


**To Reproduce**

```properties
quarkus.application.name=fooooo-baaaaaar
kubernetes.deployment.target=openshift
```

See `target/kubernetes/openshift.yml`:

```
yaml
apiVersion: "apps.openshift.io/v1"
kind: "DeploymentConfig"
metadata:
  ...
... [Log Snipped] ...
        image: ""
      ...
```
