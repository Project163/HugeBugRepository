Title

[YCQL] Use safe read time for backfill write reqs

Description
I came up with an "attack" that makes the index inconsistent with the indexed
table.  It is not simple, so it deserves some lengthy explanation.

```cql
CREATE KEYSPACE k;
USE k;
CREATE TABLE hn (
    i int PRIMARY KEY,
    j int
  ) WITH transactions = { 'enabled': true };
```

| Session A | Session B |
| --- | --- |
| | `INSERT INTO hn (i, j) VALUES (1, 2)` |
| `CREATE UNIQUE INDEX ON hn (j)` |
| (DELETE_ONLY perm) |
| | `DELETE FROM hn WHERE i = 1` |
| | `INSERT INTO hn (i, j) VALUES (3, 2)` |
| (WRITE_AND_DELETE perm) |
| (DO_BACKFILL perm) |
| (get safe read time for backfill) |
| | `INSERT INTO hn (i, j) VALUES (5, 2)` |
| (do backfill (3, 2) -- should detect conflict, but doesn't) |
| (READ_WRITE_AND_DELETE perm) |

```cql
SELECT * FROM hn; -- indexed table scan
```

```
 i | j
---+---
 5 | 2
 3 | 2

(2 rows)
```

```cql
SELECT * FROM hn WHERE j = 2; -- index table scan
```

```
 i | j
---+---
 5 | 2

(1 rows)
```

```cql
DESC hn;
```

```
CREATE TABLE k.hn (
    i int PRIMARY KEY,
    j int
) WITH default_time_to_live = 0
    AND transactions = {'enabled': 'true'};
CREATE UNIQUE INDEX hn_j_idx ON k.hn (j) INCLUDE (i)
    WITH transactions = {'enabled': 'true'};
```

I took advantage of the fact that

- Backfill write requests always use time 50 (a time always before any
  non-backfill writes)
- Duplicate row detection that looks _ahead_ will only examine the first record
  it sees
- Duplicate row detection that looks _ahead_ happens from time 50

The delete is the first thing that gets written to the index.  It is obviously
past time 50.  Therefore, it will be used during duplicate row detection that
looks _ahead_.  Then, I'm free to do any other setup after that: I add the row
back with the same index key (it could have had the same primary key, too).  I
make sure to add it before getting write permission so that it doesn't get
written to the index and I don't get a duplicate row

Discussion
- I should mention these helpful flags to time the deletes/inserts:

- `--TEST_slowdown_backfill_alter_table_rpcs_ms=5000` master flag
- `--TEST_slowdown_backfill_by_ms=5000` tserver flag

They can be supplied to `yb-ctl` like `./bin/yb-ctl create --master_flags 'TEST_slowdown_backfill_alter_table_rpcs_ms=5000' --tserver_flags 'TEST_slowdown_backfill_by_ms=5000'`.
