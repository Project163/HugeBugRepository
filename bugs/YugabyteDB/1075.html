Title

[DocDB] Backfill done may not be triggered for empty YCQL table

Description
Jira Link: [Link: DB-8884]
### Description

This github tracks another case when indexes of empty YCQL tables have incorrect tablet metadata, leading to performance issues as described in #19544 

**Scenario**: `BackfillTable::AllowCompactionsToGCDeleteMarkers` is failing in case if index creation for the empty table.

**Steps to reproduce:**
```
1. create table tbl(k int primary key, v int) WITH transactions = { 'enabled' : true };
2. create index tbl_idx on tbl(v) WITH transactions = { 'enabled' : true };
```
The following log message can be observed:
```
E1106 13:32:57.176299 257064960 backfill_index.cc:1203] Index   is in state PREPARING : cannot enable compactions on it
```
And the subsequent `TabletServiceAdminImpl::BackfillDone()` is never triggered, which mean `retain_delete_markers` is never reset, which lead to the conditions described in [URL]
Backfilling works fine if some data has been inserted:
```
create table tbl2(k int primary key, v int) WITH transactions = { 'enabled' : true };
insert into tbl2(k,v) values(1,1);
insert into tbl2(k,v) values(2,2);
insert into tbl2(k,v) values(3,3);
create index tbl2_idx on tbl2(v) WITH transactions = { 'enabled' : true };
```

**Note.** The side-effect of the issue is that `retain_delete_markers` is never reset in the sys catalog as the method [Link: exits] before changing the property.

Discussion
- The fix is to replace `if (state != SysTablesEntryPB::RUNNING && state != SysTablesEntryPB::ALTERING)` with `if (!l->is_running())` in `BackfillTable::AllowCompactionsToGCDeleteMarkers` (confirmed with @amitanandaiyer).
