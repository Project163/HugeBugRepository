Title

Node.js lacks ability to destroy connection

Description
At present, there is no means for destroying the socket underlying a Node.js Thrift Connection. When using TLS, If the socket fails to connect, calling end() is insufficient to release its resources. (end() sends a FIN packet, which is never acknowledged, holding the socket open.) This unreleased socket will prevent Node.js from exiting cleanly.

       THRIFT-3789   Add `destroy` to Connection instance 

     This commit proxies the `destroy` method from the Thrift Connection object to its underlying socket, akin to the existing `end` method. 

     Without `destroy`, it's possible for a failed TLS socket to hold the Node.js process open. (Calling `end` is not sufficient to close the OS handle because `end` sends a `FIN` packet, which is never acknowledged by the server.)
