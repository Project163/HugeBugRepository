### Describe the Bug

When implementing a strict Content Security Policy via middleware as described in [URL] some script tags are missing a nonce value inside the head element.

I believe this bug was introduced in the PR [URL] where all but one of the required scripts for every page load are now currently preinitialized.

This seemed to have been resolved by the issues [URL] and [URL] but somehow reintroduced?

I noticed this when I was upgrading from 13.4.13 to 13.4.16. I managed to pinpoint this to 13.4.14-canary.2.

This happens both in dev and prod.

### Expected Behavior

Inline scripts injected into the page should have a nonce attribute when using nonce for the CSP `script-src` directive.
