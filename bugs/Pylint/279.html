Discussion
- Hi, thanks for reporting an issue.

I need to update the message for these errors, as since 2.X they can run on Python 3 as well. But they are part of the Python 3 porting checker, which is activated with `--py3k`, so these kind of checks (`*-builtin-not-iterating` and friends) are actually disabled by default. Can you check if you use a config file and if so, if you somehow enabled these inadvertently?
- I use VSCode and it appears this warning was enabled. I looked at the doc why this occurs and saw it `can’t be emitted when using Python >= 3.0` so I reported the bug. Either the error is in the doc, or it is a false trigger. But either case it needs fixing. As it isn't my computer, I don't want to mess with config files
- ... [Middle Discussions Snipped for Brevity] ...
- Awesome, glad that's settled. On a second look, I think there's also a bug here as that unpacking's definitely an iterating context.

So for context this check was emitted on Python 2 with the Python 3 porting checker. In Python 2, `zip` returned a list, which means that a lot of operations that are invalid in Python 3 were done on the output of `zip`, such as indexing elements and such, so that's what the check is supposed to find, operations against a `zip` that is not in an iterable, materializing context. But since pylint 2.X moved to Python 3 only, we still look for these checks, if they are activated with `--py3k` as that is our signal that we are linting against a Python 2 file. But the bug here is that `*` is definitely a materializing context, so the check shouldn't apply to it.
- So this **IS** a false trigger after all **AND** a documentation issue as well. Do I get a bonus point ?
