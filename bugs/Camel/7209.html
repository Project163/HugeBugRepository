Title

Camel jbang export for SpringBoot and Main generates invalid CamelApplication.java file when gav is not specified and use of `.` as target to export

Description
jbang '-Dcamel.jbang.version=4.12.0' camel@apache/camel init 'demo.camel.yaml' 
jbang -Dcamel.jbang.version=4.12.0 camel@apache/camel export --runtime spring-boot --dir /home/apupier/ws/demo/export-springboot-2 . 

 it genrates an invalid CamelApplication.java file, notice the double-dot on the first line: 
  
 package org.example.project..;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class CamelApplication {

    public static void main(String[] args) {
        SpringApplication.run(CamelApplication.class, args);
    }

}
Discussion
- tried with: 
 
	 4.12.0 and 4.13.0-SNAPSHOT 
	 with a relative path
- this is specifc when the Maven gav is not provided. The file is correct when the --gav parameter is provided
- ... [Middle Discussions Snipped for Brevity] ...
- the intent was to say to export the whole folder. 
I think we should try to better guide the user in this case, and potentially all cases there is a folder provided instead of file.
- I think we may did some special code in camel run for the "dot" so maybe something can be improved here too
