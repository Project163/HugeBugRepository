Title

LLAP: Force synthetic file-id for filesystems which have HDFS protocol impls with POSIX mutation semantics

Description
HDFS client protocol is not a guarantee of the immutability of files - the synthetic file-id includes the mtime of the file as well, which is a fail-safe for filesystems which implement the client wire protocol without offering the same storage side restrictions on immutability (i.e allow NFS read-write-modify on the backend).
Discussion
- gopalv  doesn't inode id guarantee immutability? I remember discussing with someone that it would change on append.
- sershe : this is true only for HDFS NameNodes (& appends don't change inode-ids - people who want to drive an HDFS developer insane can truncate an HDFS file to a smaller length and then append to it again to overwrite existing blocks).
