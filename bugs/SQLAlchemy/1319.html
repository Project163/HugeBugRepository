Title

Client-side "default" or "onupdate" using a SQL expression should participate in eager defaults, using RETURNING if available

Description
### Describe the bug

With eager defaults turned on and a column defined with `onupdate=func.now()`, SQLAlchemy does not automatically use RETURNING even if it's available. Instead, after an UPDATE, SQLAlchemy issues a SELECT to retrieve the server-generated value.

If the column is marked as `server_onupdate=FetchedValue()`, then SQLAlchemy includes the column in RETURNING and does not issue a SELECT after an UPDATE.

Here is an example showing the issue that @zzzeek wrote up:

See also this docs PR, to update the docs showing the current need to use `server_onupdate=FetchedValue()`: #7437.
