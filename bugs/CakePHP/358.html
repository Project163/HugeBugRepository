Title

Long subject lines break MailTransport

Description
This issue is a continuation of [URL]
// Currently this link died?

I built CentOS and qmail server and reproduced this issue.
CentOS 5.9
Apache 2.2.3
PHP 5.4.20
CakePHP 2.4.1
Qmail 1.03.5

case 1:
CakeEmail -> MailTransport -> mail() of PHP -> qmail-inject -> qmail-remote -(SMTP *1)-> Other SMTP Server
Outgoing SMTP packets have CRCRLF (at *1).

case 2:
CakeEmail -> MailTransport -> mail() of PHP -> qmail-inject -> qmail-local -> Maildir( *2) -> qmail-pop3d -(POP3)-> MUA( *3)
Message in mailbox has CRLF (at *2) . And some headers overflow to mail body in MUA (at *3).

sendmail command which is wrapper of qmail requires LF text. (*4)
[URL]
PHP must output LF text to 'sendmail_path'.

To output text with LF, 'to', 'subject', 'message' and 'headers' arguments of mail() must have LF.
If 'to' and 'subject' have LF, LF is converted to a SPACE(0x20) in mail() function.(*5)

``` C
cf. ext/standard/mail.c
        SKIP_LONG_HEADER_SEP(to_r, i);
        SKIP_LONG_HEADER_SEP(subject_r, i);
```

// If they have CRLF, CRLF is passed to 'sendmail_path' without change. And headers overflow to mail body.

Current implementation:
Use LF for EOL. Use CRLF to divide each subject and email header line.
Fault: message has CRLF.

Workaround:
Use SmtpTransport.
SMTP requires CRLF(RFC 5321).
SmrpTransport uses CRLF for EOL. And mb_encode_mimeheader divides by CRLF.

Solution 1 for MailTransport:
Use LF for EOL.
And use zero-length-string to divide each subject and email header line.
Fault: There is a possibility of exceed 998 bytes(RFC 5322).

Solution 2 for MailTransport:
Use LF at all line break.
Fault: LF in 'to' and 'subject' is replaced by SPACE(0x20).

(*4)
qmail requires LF.
Postfix seems to judge CRLF or LF using end of line of line 1.
Some POP3 servers replace like this: s/(CR)?LF/CRLF/  It negates this issue.

(*5) This is a strange behavior.
CRLF[ |\t]+ is passed through. LF[ |\t]+ is not passed through. But mail() outputs "\n" as header line break.
