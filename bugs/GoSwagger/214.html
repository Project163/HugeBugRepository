Title

Required, Non Nil map[string]interface{}

Description
I'm not sure if this a problem or a question...I read through a few discussions on nullable vs required in the issue log. I didn't read them all in-depth, but the ones I did, did not directly state a workaround for my case. Sorry if this is a repeat, I know the topic is trying. 

## Problem statement
It doesn't seem possible to have a `map[string]interface{}` dictionary property be 1) required (i.e. the field is provided in the content body) and 2) the field is validated as a non-nil value.

The spec below makes sure the field `data` is in the content payload, but it doesn't seem to care if it is `null` (for JSON) and maps to Go's `nil`.

## Swagger specification
See the `data` property below.
```
configCreate:
    type: object
    required:
      - name
      - type
... [Log Snipped] ...
        additionalProperties:
          type: object
```
I tried throwing `x-nullable: false` in which doesn't appear to work. I can always add my own logic, but before I do I want to make sure there is isn't something in-spec that I can do.

It appears that the required state of the `data` property is erroneously making all properties 1) required and 2) must be non-zero values.
