Title

Assert does not work with ArraySegment

Description
Reported by @xplicit in nunit/nunitv2#39, moved here because we will not fix it in 2.6

This code throws an exception on .NET, while it should be passed. With mono 3.12 it works. The same issue with NUnit v 3.0

```
 Assert.AreEqual(new ArraySegment (),new ArraySegment ());
```
Discussion
- I tested this and it looks like a bug in the .NET Framework to me, so I am inclined to close this as invalid. It is crashing in NUnit in the call to GetEnumerator().

[Link: According to the documentation], `ArraySegment ` does not have a default constructor. All of it's constructors take an array of T and if you pass in null, it is supposed to throw an `ArgumentNullException`.

My thinking is that `new ArraySegment ()` is invalid even if it works and that  the nunit framework should not be protecting the developer from everything they may do wrong.

I tested the more correct,

``` C#
Assert.AreEqual(new ArraySegment (new byte[]{}), new ArraySegment (new byte[]{}));
```

and it works fine.

I am going to close this issue as invalid. @xplicit, if you feel I am doing so in error and you have a more complete use case or I have mis-interpreted this issue, I will be happy to re-open the issue and look at it again.
- I still think it's a bug in NUnit, not in .NET
1. ArraySegment does not have default constructor because it's a structure. All structures in .NET does not have default constructor, but this does not mean that you can't use them in `new` operator. For example: `DateTime dt = new DateTime();`
1. It's not always possible to call a constructor with empty byte array. For example, when use default constructor from generics.
   
   ```
    public T Create ()
    {
        return default(T);
    }
   
    Assert.AreEqual(Create >(),Create >());
   ```
2. .NET compares two newly created ArraySegments without an exception
   
   ```
    var a1 = new ArraySegment ();
    var a2 = new ArraySegment ();
    Console.WriteLine("{0}",a1==a2);  // true
   ```
3. MSTest performs `Assert.AreEqual(new ArraySegment (),new ArraySegment ());` without an exception.

- Turns out to be a bit complicated, because the underlying implementation of ArraySegment differs from platform to platform! I have a fix that works when ArraySegment implements IEnumerable, but it actually doesn't do that on all of them.

That said, it's a useful issue in pulling out the need for some restructuring in NUnitEqualityComparer, even though it's not a high priority.
- ArraySegment doesn't implement IEnumerable in eitehr Silverlight or CF 3.5. It's not implemented in the version used by our portable build, probably because Silverlight is included in the mix. I'm going to set a flag if (new ArraySegment () is IEnumerable) and use that to make the distinction.
