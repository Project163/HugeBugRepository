Discussion
- Full trace not so full?
- Why would this be platform specific?
- Yeah just full for one of the tens of thousands of identical goroutines. But I found the problem, it's on the requesting side, and thankfully not in 0.14.47.

The other side in my setup runs an imsodin-patched version with the index sorting, which is based on a newer master. That newer master has my large block stuff, wherein I set the default puller size to twice the max block size. But the block size is in bytes and that variable is in kibibytes, so the default puller queue becomes 32 gigs, which exhausts memory...
