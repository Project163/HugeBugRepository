Title

AbstractDiskHttpData.renameTo() can fail when mmap'ing fails.

Description
See: [URL]

The current implementation of `renameTo` is not correct.  It has to copy data chunk by chunk (e.g. 8KiB) instead of issuing full transfer at once.
Discussion
- So the JVM implementation is buggy (not the Netty one), since the transferTo method on FileChannel should be optimized carefully in JVM, taking in consideration the memory footprint. If I'm correct, this method is system optimized, so the reason we used it.
And for the record, the "renameTo" method of Netty first tries to use the simplest "renameTo" method on File directly, since it is the most efficient one, then if not possible (such as different FileSystem under the wood), then it must copy and delete manually.

So we need to make the second part fully manually and not using the FileChannel optimization... This is a sad news, as it will be less efficient than the native one.
Am I correct ?

Now the issue is the optimal chunk size. For nowadays, 8KB could be considered as a good tradeoff among all filesystems implementation...
