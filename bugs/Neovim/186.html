Title

Missing highlights for colorschemes that rely on default highlights

Description
### Neovim Version

NVIM v0.6.0-dev+81-gc642f3ac2

### Operating system/version:

Arch Linux x86_64, Mac OS 10.15.7

### Terminal name/version:

kitty 0.22.0

### TERM environment variable

xterm-kitty

### Installation

Built from source, with `CMAKE_BUILD_TYPE = RelWithDebInfo`

### Steps to reproduce

minrc.vim:
```
colorscheme desert
```

main.go:
```
package main

import "fmt"

func main() {
	fmt.Println("hello world")
}
```

Then `$ nvim --clean -u minrc.vim main.go`.

### Vim

_No response_

### Expected behavior

The string `"hello world"` gets highlighted

`:verbose hi String` shows:

```
String         xxx links to Constant
        Last set from ~/code/neovim/runtime/syntax/syncolor.vim line 63
```

`:verbose hi Function` shows:

```
Function       xxx links to Identifier
        Last set from ~/code/neovim/runtime/syntax/syncolor.vim line 68
```

### Actual behavior

The string `"hello world"` isn't highlighted

`:verbose hi String` shows

```
String  xxx cleared
```

`:verbose hi Function` shows

```
E411: highlight group not found: Function
```
---

Manually calling `:colorscheme desert` or `:set bg<` will set the missing highlights.

Another way to reproduce:

```
$ nvim -u NONE main.go

:colorscheme desert
:syntax on
```

But doing `:syntax on` before `:colorscheme desert` will work.

---

This is a regression introduced in #14771
