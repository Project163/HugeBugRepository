Title

[CDCSDK] Transaction Intent loss after restart and compaction

Description
Jira Link: [Link: DB-2932]
Currently for tablets which have an active CDC stream, we do not directly remove the intents of an already committed transaction from Intents DB. But rather push it to the “immediate_cleanup_queue_” in TransactionParticipant. And when the cdcsdk checkpoint OpId becomes greater than the transaction’s appl record OpId, its intents get removed. 

But after any restart, if a compaction is triggered, we will call the below function: 


void TransactionParticipant::Cleanup(TransactionIdSet&& set)


Below is the function which decides which transactions we will try to abort after compaction:


Result > DocDBIntentsCompactionFilter::FilterTransactionMetadata(
    const Slice& key, const Slice& existing_value) {
  TransactionMetadataPB metadata_pb;
  if (!metadata_pb.ParseFromArray(existing_value.cdata(), existing_value.size())) {
    return STATUS(IllegalState, "Failed to parse transaction metadata");
  }
  uint64_t write_time = metadata_pb.metadata_write_time();
  if (!write_time) {
    write_time = HybridTime(metadata_pb.start_hybrid_time()).GetPhysicalValueMicros();
  }
  if (compaction_start_time_  = warning_time) {
       LOG_WITH_PREFIX(WARNING)
           << "Transaction Id: " << transaction_id << " committed too long ago.";
     }
     VLOG_WITH_PREFIX(2) << "Transaction committed, should not cleanup: " << transaction_id;
     erased_transactions_.push_back(transaction_id);
     --left_wait;
     continue;
   }

Thus as part of the fix, we introduced an OpId based check in this function: “FilterTransactions()” as well. We will now filter transactions whose APPLY Record’s OpID is lower than the CDCSDK checkpoint OpId.
