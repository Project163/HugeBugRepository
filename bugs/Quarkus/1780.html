Title

@PreDestroy method not awaited

Description
## Quarkus version

2.14.2 on Linux with OpenJSD 11.0.17+8


## Actual behaviour

I get the following exception on session timeout:

```
ERROR [io.qua.arc.imp.AbstractInstanceHandle] (executor-thread-31) Error occurred while destroying instance of bean 
[...SessionManager_Bean]: javax.enterprise.context.ContextNotActiveException: SessionScoped context was not active when trying to obtain a bean instance for a client proxy of CLASS bean [class=...MyAPIClient, id=5b2...]
```


## Expected behavior

Session scope and @SessionScoped beans should not be destroyed as long as all methods annotated with @PreDestroy of unremovable beans have returned.


## How to Reproduce?

```
java
@Named("myAPIClient")
@SessionScoped
public class MyAPIClient implements Serializable {

... [Log Snipped] ...

}
```

Any hints?
Discussion
- First of all, you shouldn never invoke other beans in a `@PreDestroy` callback, especially beans with the same scope. The reason is that (1) ordering is not defined; so `MyAPIClient` could have been destroyed before `autoLogout()` is called and thus a new `MyAPIClient` bean instance could be created (and this may or may not cause all kind of issues),  and (2) the context of the other bean may not be active at all.

Now, you're right that in this particular case, the `ContextNotActiveException` does not make sense since both `MyAPIClient` and `SessionManager` are `@SessionScoped`. However, we'll need more info - a full stack trace and ideally a simple reproducer app.

BTW `@SessionScoped` is not supported by default, unless the `quarkus-undertow`  extension is used. Is it the case?
