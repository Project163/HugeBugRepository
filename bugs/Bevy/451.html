Title

`UntypedAssetId` and `AssetId ` have different hashes for the same `Asset`

Description
## Bevy version

0.12

## What you did

1. Created a `Handle` to an `Asset`
2. Cloned that `Handle` and called `untyped()` to get an `UntypedHandle` to the same `Asset`
3. Hashed both values separately with a fixed hasher (e.g., `bevy_utils::AHasher::default()`)
4. Observed the values were not identical.

## What went wrong

I would expect the hash of these two handles to be the same, since they are for the same `Asset`, and are intended to be interoperable types. However, the values differed.

## Additional information

- The difference was caused by `UntypedHandle` including the `TypeId` in the hash, where `Handle` does not. This same issue is present in the `AssetId` and `UntypedAssetId` types.
- I have created #10628 to address this issue.

## Reproduction

```
rust
type TestAsset = ();
const UUID: Uuid = Uuid::from_u128(123);

fn hash (data: &T) -> u64 {
... [Log Snipped] ...
    assert_eq!(hash(&typed), hash(&untyped));
}
```
