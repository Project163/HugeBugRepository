Title

ResourceStreamRequestHandler should use content-disposition attachment when filename is set

Description
The ResourceStreamRequestHandler sets the filename and documents its use as "sets the content-disposition header". By default the content disposition type is "inline". The combination of setting the filename with type inline is not very useful. 

 With IE on XP this will result in strange errors where documents are viewed as zip files, etc, but also with "normal" browsers, this will result in the downloaded file to be rendered in the browser window. Wicket 1.4 provided the filename with content disposition "attached".
Discussion
- Fixed by checking if the contentdisposition was set, and if not, determine the disposition by checking if the filename was set (in that case use attachment, else use inline)
