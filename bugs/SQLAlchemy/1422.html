Title

support different attr names with use_existing_column

Description
### Discussed in [URL]

 

 Originally posted by **fanzeyi** February 18, 2023 
So I'm running into a bit issue when trying to create some polymorphic classes with SQLAlchemy.

Specifically, I'm trying to have two sub-classes sharing the same column that these sub-classes declared themselves, while having a different field name.

For example (taken from SQLAlchemy document):

```
python
from sqlalchemy import ForeignKey
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column


... [Log Snipped] ...
        "team", nullable=True, use_existing_column=True
    )
```

I want `Manager.department` to share the same column as `Engineer.team` in the table. Even though I have specified them to be the same column name, SQLAlchemy doesn't seem to recognize that and it gives me:

```
ArgumentError: Column 'team' on class Manager conflicts with existing column 'employee.team'.  If using Declarative, consider using the use_existing_column parameter of mapped_column() to resolve conflicts.
```

However `use_existing_column=True` is already set.

I traced the code a bit and it looks like here, SQLAlchemy doesn't really consider the case where column name is explicitly specified:

[URL]

What do you think? Should SQLAlchemy be able to support this use case?
