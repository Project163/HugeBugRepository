Title

Thrown expected errors get a different status code on non-existing routes

Description
### Describe the bug

If you throw an error from `+layout.ts`, this gets rendered with the correct status code and message using the default error page.

```
import { error } from "@sveltejs/kit";
import type { LayoutLoad } from "./$types";

export const load: LayoutLoad = async () => {
  throw error(401, "Invalid token.");
};
```

However, if you go to a non-existing page, that error code now becomes 500.

### Reproduction

[URL]

Open [URL] or [URL] and you will see a 401 "Invalid token" error. But if you open [URL] (which doesn't exist) you will see instead the same message but now with the status code 500.

I would expect to still see the same 401 code there, as I have not modified it anywhere. Or I would expect to see a 404? But definitely not a 500.

Discussion
- The root layout is always loaded and its load function is always run. Upon first navigation the page is not found, so a 404 happens which means loading the root layout and the root error page. Then the root layout throws the error, probably resulting in this behavior.
