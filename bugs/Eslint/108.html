Title

Merge configs with their ancestors

Description
Currently, if you have multiple eslintrc files in a directory hierarchy, whichever one is "closest" wins. This is good for simplicity, but does create problems if you want files in a certain directory to have only one or two different rules.

An example might be that you have a project-wide .eslintrc file in the root of your project which defines all the linting rules, globals, etc. In a "tests" directory however, you might want to have some extra globals (eg: ones defined by the test framework), but you have to _duplicate_ the base .eslintrc file and then make sure you keep the two in sync if the rules ever change. Same could apply if you have some front-end JS as well as NodeJS files in the same project, which might have slightly different conventions.

My suggestion is to step up through the directories, merging together all .eslintrc files.

Your thoughts?
