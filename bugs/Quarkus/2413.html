Title

Rest client ignores default tls configuration

Description
### Describe the bug

I have an application, which uses rest client to connect to a https server with self-signed certificate. I use truststore so client could connect to the server. When I use old-style properties[1] or named tls configuration[2], the app works as expected. When I use default configuration (the guide [2] says "If not set and the default TLS configuration is configured (quarkus.tls.*) then that will be used." ), the client fails with PKIX path building failure.
