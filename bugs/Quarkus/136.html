Title

Broken access in openapi and swagger-ui extensions

Description
**Describe the bug**
Openapi and swagger-ui intergrations are broken. [URL] is also broken. It starts up, but /openapi endpoint and /swagger-ui respond with errors.

**Expected behavior**
Cool openapi and swagger pages, heh

**Symptoms**
Adding config key resolves problem in production env, but dev still errors.
```
quarkus.swagger-ui.always-include=true
```
Also it's strange that when I'm not adding this line, openapi is still available in production - not sure how safe is this.

Discussion
- @clochardpagan when you say `Also it's strange that when I'm not adding this line, openapi is still available in production - not sure how safe is this.`, we agree that you're only talking about openapi, not Swagger UI?

The OpenAPI extension has always been designed to be, well, open. Only Swagger UI is limited to dev mode if you don't explicitly enable it.
- @stuartwdouglas so my understanding is that the `wiring-classes` directory is not part of the directories handled by the `RuntimeClassLoader` because in dev mode we explicitly target `wiring-devmode` as the wiring directory (we have a few classes generated there but most of them are in `wiring-classes`).

Not sure how to handle this: is it better to add `wiring-classes` to the `applicationClassesDirectories` or should it be handled by the parent class loader and added as an additional `frameworkClassesPath`.

FWIW, a quick and dirty:
```
diff
diff --git a/core/deployment/src/main/java/io/quarkus/runner/RuntimeRunner.java b/core/deployment/src/main/java/io/quarkus/runner/RuntimeRunner.java
index 6aa728dc4..5ae154fbf 100644
--- a/core/deployment/src/main/java/io/quarkus/runner/RuntimeRunner.java
+++ b/core/deployment/src/main/java/io/quarkus/runner/RuntimeRunner.java
... [Log Snipped] ...
             RuntimeClassLoader runtimeClassLoader = new RuntimeClassLoader(builder.classLoader, allPaths,
                     builder.frameworkClassesPath, builder.transformerCache);
```
fixes the issue so I think I narrowed down the problem properly.
