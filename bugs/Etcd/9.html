Title

advertise client URLs are resolved causing SSL verification complications

Description
The advertised client URLs returned from /v2/members and /v2/machines are resolved to IP addresses. 

For clients that use these to discover the endpoint to query, this forces one of two conditions:
1. the SSL client must not verify the hostname it is connecting to against the names in the SSL cert
2. the server must have it's IP address in the CN or SAN of the SSL cert

Is there any reason we want to resolve the advertise client URLs or would it make sense to leave them unresolved?

The specific problem I am running into is with etcdctl. Lets say that my nodes are called:
[URL]
[URL]
[URL]

And each one is configured with the server certificate that matches the domain "*.example.com"

Etcdctl will make a request against /v2/machines and will get back:
[URL] [URL] [URL]

Since the server's certificate does not have an IP address in its CN or SAN, etcdctl will fail to validate the server certificate when it makes the request for /v2/keys/
