Title

SecureRandom shadows JVM class

Description
The SecureRandom interface also exists  as a class in java.security. 

 This makes it awkward to use, for example in JavaSecureRandom the fully qualified name has to be used for the java class. 

 Ideally it should be renamed.
Discussion
- Thanks  sebb@apache.org  for pointing out this. 

 Thinking about this problem, we also has Cipher, CipherInputStream case with the same situation. They are the best names in concept.  

 Although there are possibilities that users may use both Java Cipher and our Cipher in the same java file, yet can we consider this as an uncommon case so that we don't have to use a "bad" name to address it. 

 Otherwise, we will have to use names like: CryptoCipher, CryptoSecureRandom, .. which are very redundant and uncomfortable. 

 Any thoughts?
- In Crypto internal implementation code, I would think that we can manage the name shadowing using fully qualified name as there are no many cases. And it will not impact the end user unless they have the cases mentioned above.

- To move fast, we will go forward with changing all the names in a consistent manner. As this change will be related to a lot of files and to avoid conflict for other work such as spaces adjusting.  

 If folks has other opinion, let's continue discuss in this thread and we can create new pull request if needed.
