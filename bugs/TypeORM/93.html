**Steps to reproduce or a small repository showing the problem:**

```
...
var myclass = new MyClass();
await repository.insert(myclass);
console.log(myclass.id);
```

Returns auto-generated id if  "PrimaryGeneratedColumn" used:
```
class MyClass {
    @PrimaryGeneratedColumn()
    id: number;
}
```


Does not return auto-generated id if "Column" used:
```
class MyClass {
    @Column("integer", {
        generated: true,
        nullable: false,
        primary: true,
... [Log Snipped] ...
    id: number;
}
```

- Can confirm for MySQL using `repository.save`. [Link: This workaround] is not ideal since there's a difference in semantics and table schema between `@PrimaryGeneratedColumn` and `@Generated + @Column`. Imo you shouldn't have to make the field a primary key just to get the  `.save` or `.insert` methods to return the field in the result set. This may not be desirable, e.g. when using (a) different field(s) as PK.

In the latter case, you can still follow the suggestion above and alter your table such that the previously primary key(s) are now "just" unique keys (https://typeorm.io/#decorator-reference/unique).
