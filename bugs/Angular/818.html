Title

ngcc: produces wrong d.ts files for generic types (pipes)

Description
# 🐞 bug report

### Affected Package

The issue is caused by package @angular/compiler-cli

### Is this a regression?

Dont know if this worked before.

### Description

When running `ngcc` for my own library ngcc runs without problem, but it does not produces correct d.ts files for generic types, respectively tested for pipes.

## 🔬 Minimal Reproduction

Here is repository with my sample package [URL] there is compiled result that is used in sample [URL]
Problem is on line [URL] 

```typescript
static ngPipeDef: ɵngcc0.ɵPipeDefWithMeta ;
```

there should be 
```typescript
static ngPipeDef: ɵngcc0.ɵPipeDefWithMeta , "ngSelectValue">;
```

To reproduce problem:
`git clone [URL] sample-ivy`
`cd .\sample-ivy\`
`git checkout sample`
`npm install`
`git reset --hard`
`npm run ngcc`
`npm run build`

## 🔥 Exception or Error
  
node_modules/@ng/sample/src/pipes/ngSelectValue.pipe.d.ts:11:47 - error TS2314: Generic type 'NgSelectValuePipe ' requires 1 type argument(s).

11     static ngPipeDef: ɵngcc0.ɵPipeDefWithMeta ;

Discussion
- I looked into this and this is not currently supported for pipes in ngtsc. Directives and services should be emitted correctly (even with ngcc) however pipes do not take into account generic type arguments at all.
