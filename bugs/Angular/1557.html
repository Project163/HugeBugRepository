Title

Preserve query params in redirectTo for absolute paths

Description
As discussed in #13315, query params are only preserved when redirecting if the path is relative. This is maddeningly subtle, and I can't imagine that it's an intentional feature. I think query params should always be preserved across redirectTo-based redirects, even those with absolute paths.
Discussion
- I took a look into this recently and it appears to be a side effect of how this feature was implemented. I can't find any tests to confirm this was the intended behavior, so yes, I think it's a bug and should be fixed. Looks like it'll be some time during the RC period for Version 8.
- I'm facing this exact same issue while dealing with deeplinking in a big enterprise app.
Example: native side of the app wants to open a particular page and on the web side, we have our own deeplinking routing redirects so that both sides are not forced to always point to the same urls (easier to maintain this way).

Due to this though, it is not possible to preserve/merge the query params unless we hack and intercept the request and then **manually** add the queryParams ourselves. If this becomes an added feature, it would be greatly appreciated as our codebase would become a lot cleaner! 😄 

@jasonaden, not wanting to put pressure or anything, just looking for info. Since Angular 8 is already out (I can't update yet because the app is written in Ionic 4 and Angular 8 is is not supported as of yet): has this been attended to?
- The amount of issues that have been opened, and the comments discussing it, since 2016, is proof enough that this feature is badly needed by many, many people.

Is it difficult to implement such a feature?
