Title

Security: increased server load with XXE with internal references

Description
This is a:
* [x] bug
* [x] enhancement
* [ ] feature-discussion (RFC)

* CakePHP Version: 3.5.12 # .
* Platform and Target: nginx 1.10.3, MariaDB 10.0.31, PHP 7.0.22-0ubuntu0.16.04.1

### Context
Our application was PEN-tested and their requests containing the below XML example did not pass inspection.

### What you did
Parse the following XML using `XML::build`:
```
xml
 
 
   
... [Log Snipped] ...
   &item8; 
 
```

### What happened
When interchanging the item in the   tag the memory used for parsing peaks depending on the index used. Using `&item8;` is very noticeable. On our production servers a request using this XML body takes 8 seconds to respond.

This is due to the following:
- The RequestHandlerComponent uses `Xml::build` in its `convertXml` function with default options.
- Default build options prevent entity expansion using `libxml_disable_entity_loader` but as mentioned in the PHP docs, this only handles loading of *external* entities.

### What probably should happen
- The default return type of `XML::_loadXml` is SimpleXML. There is no parameter to prevent SimpleXML from loading internal entity references, making it increase server load.
- If I load the above example into a  `\DOMDocument` object with the libxml entity loader disabled, it gives the following warning:
```
PHP Warning:  DOMDocument::loadXML(): Detected an entity reference loop in Entity, line: 1 in ~/Desktop/tst.php on line 5
```
- Loading of the XML remains fast using DOMDocument, there are however no childNodes present because of the warning given. In this case, DOMDocument should probably be preferred with regard to SimpleXML. 

### How did I temporarily solve this?
I extended the `RequestHandlerComponent::convertXml` with the following:
```
php
public function convertXml($xml)
{
    try {
        $xml = Xml::build($xml, ['readFile' => false, 'return' => 'domdocument']);
... [Log Snipped] ...
    }
}
```
