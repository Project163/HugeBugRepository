Title

.NET platform test timeouts after ClientServerCompatibilityTest

Description
There are many timeouted test runs in the .NET suite. Example: 
 [URL]

  
 
The build Ignite Tests 2.x (JDK 8/11)::Platform .NET (Core Linux) #39429 {buildId=7678070} has been running  for  more than 40 minutes. Terminating...
 
  

 Looks like only port 47500 is requested while server node started on another. Probably a previous test didn't release the port yet. 

  
 
Successfully bound communication NIO server to TCP port [port=47101, locHost=/ , selectorsCnt=4, selectorSpins=0, pairedConn= false ]
 
  
  
 
Failed to connect to any address from IP finder (make sure IP finder addresses are correct and firewalls are disabled on all host machines): [/ :47500]
 
  

 It looks like this issue happens on JDK8 only. And only on Linux.  ClientServerCompatibilityTest  starts a server node with  Runner.java ,  PlatformProcessUtils#startProcess()  and stops with  PlatformProcessUtils#destriyProcess() . On Windows, additional  
  
 
 serverProc.KillProcessTree();
 
  
 is applied. 

 We should wait until  java.lang.Process  completely stops.
