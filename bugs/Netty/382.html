Title

Websocket examples broken in Chrome (extension negotiation problem)

Description
Hi,

I just discovered that the included WebSocketServer example doesn't work in chrome.
I can open the site in the browser and will get the message `Web Socket opened!`
However after sending a message from the browser netty will close the connection with the following logged error:

```
io.netty.handler.codec.CorruptedFrameException: RSV != 0 and no extension negotiated, RSV:4
at io.netty.handler.codec.http.websocketx.WebSocket08FrameDecoder.protocolViolation(WebSocket08FrameDecoder.java:365)
at io.netty.handler.codec.http.websocketx.WebSocket08FrameDecoder.decode(WebSocket08FrameDecoder.java:164)
```

For me this seems like there is a problem with extension negotiation: Netty acccepts the Chrome websocket extension request despite `allowExtensions` is set to false on the handshaker. If I set `allowExtensions` to true it works.

Chrome http log shows that netty accepts the extension:

Status Code:101 Switching Protocols

**Request Headers**
Provisional headers are shown

Sec-WebSocket-Key:Urs+rkRJzGp+TRG6HDoqsQ==
Sec-WebSocket-Version:13
Upgrade:websocket
User-Agent:Mozilla/5.0 (Windows NT 6.3; WOW64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/37.0.2062.124 Safari/537.36

**Response Headers**

Upgrade:websocket
Discussion
- Ok, the problem seems to be in the example.
It adds the `WebSocketServerCompressionHandler` to the pipeline (which will accept the request) despite the original handshaker having extensions prohibited.
- Sorry, which branch can I find the latest code of this example?
- @ngocdaothanh 
I tested it with master, but probably it similar in other branches.
The problem is either
- [URL] has to be set to true to support extensions

or
- [URL] should be removed

I don't know if the example should be simply fixed or if the library should be patched to avoid the problem. However I don't see a good way for that because how the Extension Negotiation is implemented. The `WebSocketServerExtensionHandler` does not know the actual handshaker and can thereby not ask whether extensions are allowed whether it should take actions or not. Maybe the handshaker could scan the pipeline when extensions are not allowed and when it finds an `WebSocketServerExtensionHandler` it could provide an error message that the pipeline is configure in an invalid way.
