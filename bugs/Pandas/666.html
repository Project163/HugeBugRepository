Title

read_csv with names arg not implicitly setting header=None

Description
```
Empty DataFrame
Columns: [a, b]
Index: []
   a  b
0  1  2
```
Discussion
- `names` is overloaded so that if header is not False, names means "choose these columns", rather like
the Dataframe constructor behaves.
- sorry, I misread the docstring and expected it to be consistent with the dataframe ctor.

from the docstring:

``` python
names : array-like
    List of column names to use. If header=True, replace existing header,
    otherwise this ignores the header=0 default
```

when header=0 by default, the names argument is used to override the column names.
Not as consistent with the dataframe constructor, especially since header=False and header=0
are currently treated the same, so there's room to specify that behaviour.

- looks like weirdness related to bool coercion, similar to [URL]

- Note the API changes in the 0.10 release notes:

```
  - ``names`` handling in file parsing: if explicit column `names` passed,
    `header` argument will be respected. If there is an existing header column,
    this can rename the columns. To fix legacy code, put ``header=None`` when
    passing ``names``
```

It's unfortunate but automatically forcing `header=None` was making handling some files (in which renaming columns was necessary) impossible.

We need to make a sweep through the docs to reflect the API change.
