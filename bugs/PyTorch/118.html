Title

Segmentation fault in torch.nn.functional.cosine_embedding_loss with empty tensors and mixed dtypes

Description
### 🐛 Describe the bug

When calling `torch.nn.functional.cosine_embedding_loss` with empty tensors and a mix of float16, int8, and float32 data types, a segmentation fault occurs. Additionally, a deprecation warning for the size_average and reduce arguments is triggered, which does not halt execution but indicates that these arguments will be deprecated.
**To reproduce**
```
python
import torch
import numpy as np

args = {
... [Log Snipped] ...

torch.nn.functional.cosine_embedding_loss(**args)
```

```

Segmentation fault (core dumped)
```

Discussion
- Reproduced on nightly. Adding high-pri for the crash. Should be an easy fix to guard against empty inputs.
- Regarding the deprecation warning, we do discourage use of `reduce` and `size_average`. You should prefer using `reduction` instead.
- I think the main problem here is that `input1` and `input2` are of different shapes, which is not allowed according to the [Link: docs] but is never checked in the code. I will prepare a PR to fix this.
