Title

incorrect `indent` behavior for anonymous function

Description
Code:

```
             showUpdateContactModal(
               contactType, contactId, function() {
                 selectContact(contactType, contactId); // 339
                 refreshEmergencyForm(); // 340
               }); // 341
```

What eslint wants:

```
             showUpdateContactModal(
               contactType, contactId, function() {
               selectContact(contactType, contactId); // 1339
               refreshEmergencyForm(); // 1340
             }); // 1341
```

Errors:

```
line 1339, col 17, Error - Expected indentation of 14 space characters but found 16. (indent)
line 1340, col 17, Error - Expected indentation of 14 space characters but found 16. (indent)
line 1341, col 15, Error - Expected indentation of 12 space characters but found 14. (indent)
```

Version: eslint 1.7.1

- @silverwind that's a good workaround for this particular case, but it looks like there are competing styles if you have a lot of arguments and you need to line wrap. Basically, this ticket and [URL] are at odds as to where to put the inner function indent level.

Option A - line length is clearly too long. this should always throw an error.

```
happens.to.be.some.very.very.long.widgetSerializer(one, two, three, four, five six, seven, eight, nine, ten, eleven, function() {
  // function code is here
});
```

Option B - to fit within line length, we indent the arguments at the position of the original argument. It's starting to look rather odd.

```
happens.to.be.some.very.very.long.widgetSerializer(one, two, three,
                                                   four, five six, 
                                                   seven, eight,
                                                   nine, ten,
                                                   eleven, function() {
  // function code here?
                                                     // or here?
});
```

Option C - arguments are no longer at the same indent level, which makes it more difficult to parse

```
happens.to.be.some.very.very.long.widgetSerializer(one, two, three, four,
  five six, seven, eight, nine, ten, eleven, function() {
    // function code here?
  // or here?
  });
```

Option D - you can see all the arguments in one line

```
happens.to.be.some.very.very.long.widgetSerializer(
  one, two, three, four, five six, seven, eight, nine, ten, eleven, function() {
    // function code here?
  // or here?
});
```
- @silverwind it might not be valid for that small example, but when you have more levels of nesting, it is valid
