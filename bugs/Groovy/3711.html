Title

+= in CompileStatic dynamically sets property instead of using setter

Description
Code: 
  
 
 import  groovy.transform.CompileStatic

@CompileStatic
 class  A {
   int  num

  static main(args) {
     def  a =  new  A()
    a.num = 5
    a.num += 10
  }
}
 
  
 Main method compiles to: 
  
 
A a =  new  A();
 byte  var2 = 5;
a.setNum(var2);
 Object  var10001 =  null ;
ScriptBytecodeAdapter.setProperty(a.getNum() + 10, ( Class ) null , a, ( String ) "num" );

- Not sure why "a.num += 10" is written as  ScriptBytecodeAdapter.setProperty(a.getNum() + 10, (Class)null, a, (String)"num")  instead of using  Groovy8707.setNum(int)  like "a.num = 5" does.  The two lines take different paths through AsmClassGenerator, so I need to do some back-tracking to see if there is an AST transform applied to "a.num = 5". 

 I also have an experiment that would turn all accesses to "num" in the example to field reads/writes.  Accessing "num" from within the declaring class should be able to be a simple field access.
- The simple assignment "a.num = 5" takes a shot-circuit path for static compile:
