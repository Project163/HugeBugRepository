Title

Error NG0312 while trying to alias inputs via host directive

Description
### Which @angular/* package(s) are the source of the bug?

core

### Is this a regression?

No

### Description

It seems like an `@Input()` that was renamed via `@Input("myCustomName")` can't be added to the host directives `inputs` array.
I was just following the official [Link: Introducing the Directive Composition API in Angular v15] video on YouTube. 

Here's an example using the `CdkContextMenuTrigger` directive:
```
ts
import { CdkContextMenuTrigger } from '@angular/cdk/menu';
import { Directive } from '@angular/core';

@Directive({
... [Log Snipped] ...
})
export class MyMenuTriggerDirective {}
```

And a simplified version of using it:
```
ts
import { Component } from '@angular/core';
import { MyMenuTriggerDirective } from './my-menu.directive';

@Component({
... [Log Snipped] ...
})
export class AppComponent {}
```

Doing so result in the errors below. Or is this working as intended?

Discussion
- This does seem like a bug in the validation. The problem is that the `cdkContextMenuPosition` isn't actually an input on `CdkContextMenuTrigger`, but rather a property called `menuPosition` that is inherited from `CdkMenuTriggerBase` and exposed through the `inputs` array. Usually the workaround would be to expose `menuPosition`, but that won't work in this case, because it isn't actually marked as an input.
- Mhm, okay. So that's a implementation issue on the CDK side? I think these kinds of inputs / outputs should also be supported by host directives. Even though, this style is not recommended by the Angular Styleguide, it's part of the framework. 

Apart from that there's also a kind of weird behavior when exposing the `@Input('cdkContextMenuDisabled')` via host directive. 
That also results in error NG0312. Renaming it fixes the issue.

```
ts
hostDirectives: [
    {
      directive: CdkContextMenuTrigger,
      inputs: [
... [Log Snipped] ...
    },
  ],
```
- Nah, this is a problem with how the validation is implemented in the Framework's runtime. It should be a supported case.
