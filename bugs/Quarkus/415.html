Discussion
- It seems that Graylog didn't correctly create the index in Elasticsearch as the Thread field is of type long but it should be a String.

Can you add to the issue :
- A screenshot of the detail of a working log
- The logs of your application from the console to have them in text

Also, do you have other log configuration option inside `application.properties` ?

Apparently, what happened is that the first message send to Graylog should have a Thread field that Elasticsearch discovers as a long instead of a String.
The automaticaly created index then have a mapping of long for the Thread field and when a String arrives it refuses it. 
I don't know how it can happens but you can find some information about it here: [URL]

- @gsmet this is a dev mode only issue. It impact only Graylog (Logstash have predefined Elasticsearch templates, not sure for Fluentd) and under certain circumstances only (when a log event is generated during the build phase: this is the case for Flyway for exemple). There is an easy workaround (initialize the Graylog index with a run of the application from a JAR or a native package).

There will be a fix in the `loggin-gelf` library that should be delivered in late January (so it will certainly miss the 1.2 release).
