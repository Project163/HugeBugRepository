Title

redis backend does not unsubscribe from celery-task-meta-XXX channels when ignore_result=True

Description
This is relevant to using the redis backend.

When I trigger a task, a "pubsub subscribe" command is issued, resulting in a 'celery-task-meta-XXX' entry in the pubsub channels list:
```
(py36) [host]:celery$ sudo redis-cli pubsub channels
1) "celery-task-meta-6e941dbb-006e-4e6e-8cec-2d0e024d6faf"
```
Because there is no return value, and because I don't want to block, I do not call AsyncResult.get(), which normally does the job of unsubscribing.

If the unsubscribe doesn't happen, the list of subscriptions grows without end, causing resource issues after several hundred thousand tasks.

Instead, I've tried two ways to prevent this problem:

1. include **ignore_result=True** in the @app.task annotator
2. to call AsyncResult.forget() on the return value from .delay()

I do not know if this is a bug or if I'm doing things incorrectly. 

This can be reproduced with this code, tasks.py (adapted from a contribution by @mleginus):

```
"""Celery tasks module."""
from celery import Celery
from kombu import Queue
from redis import StrictRedis
from time import sleep
```
