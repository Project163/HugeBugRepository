Title

The --script_path flag on Windows does produce a correct bat file when target is the test_wrapper

Description
### Description of the problem:

When running something like `bazel run "--script_path=C:\test.bat" //services/Web-Client/src/services:test`
Where the target ends up running the `test_wrapper` the created `test.bat` file is invalid.

Inspecting the file reveals something like the below, I have removed the setup of environment variables as this is not the problem.

``` cmd
@echo off
cd C:/users/skk/_bazel_skk/tilbahl3/execroot/my_project

  external/bazel_tools/tools/test/tw.exe services/Web-Client/src/services/test_chromium-local.bat %*
```

The last line will always error with 
```
'external' is not recognized as an internal or external command, operable program or batch file.
```

I see this issue when this is used with [Link: ibazel] and the [Link: karma_web_test_suite] test rules although the issue is not caused by them

There are multiple variants of that last line that could work on windows
``` cmd
  external\bazel_tools\tools\test\tw.exe services/Web-Client/src/services/test_chromium-local.bat %*
```
or
``` cmd
  C:/users/skk/_bazel_skk/tilbahl3/execroot/my_project/external/bazel_tools/tools/test/tw.exe services/Web-Client/src/services/test_chromium-local.bat %*
```
The last one is how the output is defined when used with the [Link: concatjs_devserver] rule.
``` cmd
  C:/users/skk/_bazel_skk/tilbahl3/execroot/my_project/bazel-out/x64_windows-fastbuild/bin/services/Web-Client/src/devserver.exe %*
```

### Bugs: what's the simplest, easiest way to reproduce this bug? Please provide a minimal example if possible.

Add the below to a `BUILD.bazel` file
``` skylark
sh_test(
    name = "foo_test",
    srcs = ["foo_test.sh"],
)
```

Then run ` bazel run "--script_path=C:\test_foo.bat" foo_test`

Try to run the `C:\test_foo.bat` file observe the error

Windows 10 1909
