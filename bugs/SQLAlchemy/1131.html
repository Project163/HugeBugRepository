Title

Binding type to a schema specified in metadata (Postgresql)

Description
Following the postgresql examples of the usage of enums that are in the docs [URL]

```
python
from sqlalchemy import Column, Integer, MetaData
from sqlalchemy.orm import declarative_base
from sqlalchemy.dialects.postgresql import ENUM

... [Log Snipped] ...

Base.metadata.create_all()
```

What I expect is a new table created in the schema other and a new data type created in the schema other.
However, the enum is always created in the schema public... Am I missing something or this is an expected behaviour?

**Versions**
 - OS: Windows 10
 - Python: 3.8
 - SQLAlchemy: 1.4.11
 - Database: Postgresql 13


Thanks in advance
Discussion
- hey there -

so this is a very old bug that's never been reported.   What you can do for now is either:

1. use the schema arg on Enum directly, e.g. Enum(...,schema='my_schema')
2. use the "inherit_schema" flag that will inherit schema from the table, e.g. Enum(..., inherit_schema=True)

that said, if metadata is passed to the Enum, and there's no other schema present, it should use that, sure, which is the same as what Sequence() has done for many years.
