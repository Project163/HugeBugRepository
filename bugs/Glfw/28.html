Title

Default refreshRate hint causes unnecessary mode change

Description
Much like #228 and #229, in my application when it starts there is a pause during the call to [Link: `_glfwSetVideoMode`]. I discovered that if I prevented this call from happening, then I got the full screen window I wanted, but without the ugly pauses on startup and shutdown.

To fix this, I can set this hint in my application:

``` c
glfwWindowHint(glfw.RefreshRate, GLFW_DONT_CARE)
```

So my question is: why isn't this the default? It seems that instead zero is being used as the default, which is causing it on my machine to pick a refresh rate of 40 instead of 60, hence requiring the mode change.

For the record, I'm using the version of glfw3 shipped with the go bindings on this commit: [URL]

- OK, thanks, understood. Hmm. Just musing, I wonder what people "Usually want" these days, when asking for full screen. My instinct is always to ask for the current refresh rate and resolution, but why might I want different?

The problem with picking something other than what's set with GLFW_DONT_CARE is that it will cause a mode change and potentially graphical glitches.
- It depends on the application, really. Hence it is a choice. Most applications default to the current screen mode, yes.

An example of when you might want something different, is if your application is fill-rate limited: rendering at a lower screen resolution (e.g. half) would reduce visual quality, obviously, but would also improve performance (some console games do this for instance).

No graphical glitches should occur, if they do then it's a bug in the graphics driver and.. well.. there isn't anything you can do about that except report it to the respective driver developers.

That being said, if you want to explicitly avoid these buggy drivers going with the current screen mode is a good choice.
