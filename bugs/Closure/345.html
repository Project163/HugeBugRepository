Title

"new RegExp" compiles to just "RegExp" in advanced mode

Description
What steps will reproduce the problem? 
1. Run the code snippet below. The output should be

a
a

2. Compile it in advanced mode on [URL] and run the output. The output will be

a
b

3. This happens because "new RegExp" turns into just "RegExp" which doesn't work because regular expression are not stateless in JS.

Code:
var re = /./g;
var s = 'abc';
var re1 = new RegExp(re);
var re2 = new RegExp(re);
window.console.log(re1.exec(s)[0]);
window.console.log(re2.exec(s)[0]);

Compiler output:
var a=/./g,b=RegExp(a);window.console.log(RegExp(a).exec("abc")[0]);window.console.log(b.exec("abc")[0]);
Discussion
- It looks like this happens in PeepholeSubstituteAlternateSyntax#tryFoldStandardConstructors. I think the rationale was that "new RegExp('somestring')" is equivalent to "RegExp('somestring')". But if you pass another RegExp to the RegExp constructor, then apparently it's not equivalent.

As a simple quickfix we could remove RegExp from the STANDARD_OBJECT_CONSTRUCTORS set, but the real fix is probably to do the replacement only if the argument is known to be a string.
- Wouldn't it be better to turn new RegExp('foo') into /foo/ rather than RegExp('foo')?
- Actually, it looks like we already do that if the argument is a string literal. If it's a variable, we just drop the 'new.' So the cases are:

// string literal
new RegExp('foo') => /foo/

// variable known to be of type {string}
new RegExp(stringVar) => RegExp(stringVar)

// variable that is not a string, or has an unknown type
new RegExp(nonStringVar) => new RegExp(nonStringVar)

Currently the third case is the one we get wrong. Since we're already switching to /foo/ for string literals (which are, I would guess, the most common case) maybe we should actually just remove RegExp from the list of standard constructors.
