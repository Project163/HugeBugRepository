Title

SAML realm does not set HTTP read and connect timeouts

Description
## Description 

Currently, SAML realm supports loading IdP metadata ([Link: `idp.metadata.path`]) from a file or URL. When URL is configured, SAML will periodically poll changes at a frequency determined by the realm's `idp.metadata.http.refresh` and `idp.metadata.http.minimum_refresh` settings. 

The polling and refresh of metadata is done by OpenSAML's `HTTPMetadataResolver`. The HTTP client that's created and provided to HTTP metadata resolver, [Link: does not specify connect nor read timeouts]. This defaults to 0 (infinite) and can cause other threads (`generic` or `transport_worker` - see [URL] to be blocked infinitely when read from a connection hangs.

## Proposal 

SAML realm should define default (non zero) timeouts and allow configuring connect and read timeouts via settings, for example:
 - `idp.metadata.http.connect_timeout` that defaults to `5s`
 - `idp.metadata.http.read_timeout` that defaults to `10s`

## Workaround 

The workaround is to download metadata, make it available in the ES config directory on all nodes and configure `idp.metadata.path` to point to a file path instead of URL.
