Title

ContainerRequestContext.getUriInfo().getMatchedURIs() IndexOutOfBoundsException

Description
### Describe the bug

See [URL] - Keycloak users are effectively setting the quarkus.http.root-path to a value that does not end in a slash (as documented), then when accessing that path see an IndexOutOfBoundsException

### Expected behavior

The filter logic should succeed.

### Actual behavior

ContainerRequestContext.getUriInfo().getMatchedURIs() results in an IndexOutOfBoundsException

### How to Reproduce?

- Set quarkus.http.root-path=/foo
- Install a filter that accesses getMatchedURIs():
```
    @Override
    public void filter(ContainerRequestContext requestContext, ContainerResponseContext responseContext)
            throws IOException {
        System.out.println(requestContext.getUriInfo().getMatchedURIs());
        return
    }
```
- Access /foo in the browser

### Output of `uname -a` or `ver`

_No response_

### Output of `java -version`

_No response_

### Quarkus version or git rev

at least versions 3.2 - 3.7

### Build tool (ie. output of `mvnw --version` or `gradlew --version`)

_No response_

### Additional information

The logic in ResteasyReactiveRequestContext.getPathWithoutPrefix is allowed to resturn an empty string when stripping the prefix, but logic like ResteasyReactiveRequestContext.saveUriMatchState assumes that the path is at least a single character - presumably /.
