Title

Invalid security tokens for forms with manually given controller/action

Description
When creating forms using the form helper and giving a custom action, the tokens generated by the Security Component are always invalid. This seems to be because the query string parameter is only existing when validating the token. 
Using: PHP 5.5 (Windows), CakePHP 2.5.4

Steps to reproduce: 
Consider the following controller / view file:
`TestController.php`

```
 Auth->allow(); // No ACL for this test class
... [Log Snipped] ...
    }
}
```

`Test/index.ctp`

```
 Form->create(false, array('action' => 'save'));
echo $this->Form->input('Test.a', array('type' => 'number'));
echo $this->Form->input('Test.b', array('type' => 'hidden', 'value' => 3));
echo $this->Form->end('Save');
echo $this->Form->postLink('Testlink', array('controller' => 'Test', 'action' => 'save'));
?>
```

The generated HTML code looks like this: 

```
 
    ...
 
```

When using some debug output, I get the following `$hashParts` (for both the normal form and the post link):

```
Passed fields when validating: array(
    'lastAction' => '/testing/test/save?testing%2Ftest%2Fsave=',
    'fieldlist' => array(
        (int) 0 => 'Test.a',
        'Test.b' => '3'
... [Log Snipped] ...
    'unlocked' => ''
)
```

The only difference is the query string in `lastAction`. It is present when validating the form token, but not when creating the form.
Discussion
- Where is the extra query parameter coming from?
- I found the cause now, it was a problem with my `.htaccess` file. It was `RewriteRule ^(.*)$ index.php?$1 [QSA,L]` instead of `RewriteRule ^(.*)$ index.php [L]`. No glue where this line came from, in all CakePHP release versions I checked, there was the correct line. 

This seems not to be an issue (any more?), and can be removed.
