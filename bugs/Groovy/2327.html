Title

Exclusive range operation results in wrong result with negative index

Description
The script: 
  
  final  a = [1, 2, 3, 4]
 assert  a[-3..-2] == [2, 3]
 assert  a[-3..<-2] == [2]
 assert  a[2..-3] == [3, 2]
 assert  a[1..-1] == [2, 3, 4]
 assert  a[1..<-1] == [2, 3]
 
  
 when executed, results in: 
  
 Caught: Assertion failed: 

assert a[1..<-1] == [2, 3]
       ||        |
       |[2, 1]   false
       [1, 2, 3, 4]

Assertion failed: 

assert a[1..<-1] == [2, 3]
       ||        |
       |[2, 1]   false
       [1, 2, 3, 4]

	at rangeSpecs.run(rangeSpecs.groovy:8)
 
  
 I do not understand the last result here, i.e. that the wrong result happens.
Discussion
- Just to flesh out possible further inconsistencies, what would you expect from: 
  
 a[-2..<1]
 
  
 It currently doesn't equal what you get from this: 
  
 a[-2..<-3]
 
  
 The current formula in  DefaultGroovyMethodsSupport#subListBorders  is using  range.isReverse()  in the calculation which I suspect we cannot use.
- My suspicion is that  DefaultGroovyMethodsSupport#subListBorders  should use  boolean reverse = from > to;  and not use the "guessed" value of reverse from the original range object.
- My suspicion was only partially accurate. It turns out that the Range abstraction when dealing with inclusive/exclusive and negative index values is a lossy abstraction. There simply isn't enough information retained in the current implementation to deduce the correct values. Here is a spike which would correct the problem: 

  [URL]

 Why is it a spike? I haven't added tests or removed the "legacy" implementation in several places. We should discuss if everyone is happy with this breaking change first. After this change, the following script runs successfully: 
  
  final  a = [1, 2, 3, 4]
 assert  a[-3..-2] == [2, 3]
 assert  a[-3..<-2] == [2]
 assert  a[2..-3] == [3, 2]
 assert  a[1..-1] == [2, 3, 4]
 assert  a[1..<-1] == [2, 3]
 assert  a[-2..<1] == [3]
 assert  a[-2..<-3] == [3]
- Flagging as a breaking change - though it really is only the broken cases which have changed.
