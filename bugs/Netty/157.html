Title

HttpPostRequst.nextChunk() does not finish request with LastHttpContent

Description
Might be related to issue #1293 

Here is the description:

Using last version of Netty V4 and example HttpUpload, it seems that the last request (multipart) is not finishing on server side, therefore the client is hanging for the answer of the server.

After putting some trace, here is what it seems to occur:

1) Get form part: no issue, perfect, no chunk at all

2) Post form (not multipart): no issue, 1 chunk is received as DefaultHttpRequest and 1 more as DefaultLastHttpContent

3) Post multipart form: 2 chunk are received as DefaultHttpRequest, no LastHttpContent at all => the server is blocking since it is waiting for the LastHttpContent to finish and answer to the client. The client is then waiting forever.

So it seems that no LastHttpContent is sent on Post Multipart client side.

If I send manually a DefaultLastHttpContent on client side just after the line sending all chunk from bodyRequestEncoder, it seems ok.

```
// test if request was chunked and if so, finish the write
    if (bodyRequestEncoder.isChunked()) {
        channel.write(bodyRequestEncoder).awaitUninterruptibly();
    }

... [Log Snipped] ...
    // Now no more use of file representation (and list of HttpData)
    bodyRequestEncoder.cleanFiles();
```

I try with a small file (on chunk only for all the request except first one) and for a big file (more than 20 chunks) and the LastHttpContent was never sent from the client side if I did not send it manually.

So I don't know if it is an issue in the codec or somewhere else. I don't think we should send obviously the LastHttpContent manually on the client side code. But for the moment, this is the only way I found to counterpart this issue.

Any idea?
