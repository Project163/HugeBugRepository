Title

regression(#24647): `LanguageTree:parse()` calls quadruple per character typed, until Neovim freezes

Description
### Problem

The latency increases 4x per keystroke, i.e. the first 5 or so characters inserted feel fine, and then it takes a second, then a few seconds, and eventually it freezes.

The issue bisects to #24647.

### Steps to reproduce

1. Run `nvim --noplugin --clean -u repro.lua sample.lua`, where `repro.lua` is:
```lua
vim.opt.scrolloff = 999 -- not necessary, but just sets up the viewport
vim.api.nvim_create_autocmd('FileType', {
  pattern = { '*' },
  callback = function() vim.treesitter.start() end,
})
```
and `sample.lua` is provided here: [URL]
2. **(IMPORTANT)** resize your terminal so that `:echo winheight(0)` returns exactly 58 and `:echo winwidth(0)` returns at least 79. The issue will not reproduce if your window height is off by even 1.
3. `/vue o`. At this point, the last line in the window should say "on_initialized", and "taplo" should be the 4th, 5th or 6th line. If not, resize your terminal again and start over.
4. Type `foobarbazfoobarbazfoobarbaz = {} `.
5. If you were able to survive step 4 (i.e. typed 5 chars or less), you should observe that each time you press ` ` or ` `, `LanguageTree:parse()` is called 4^(n+2) times, where n is the number of chars you inserted in step 4.

NOTE: Don't call `:lua vim.treesitter.inspect_tree()` at any point. It will cause the issue to not reproduce.

### Expected behavior

No latency in typing.
