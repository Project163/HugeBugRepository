Title

[YSQL] Assertion Failure For CREATE TABLE of DATE / TIME Types

Description
The test case related to this bug, "yb_feature_types", is commented out.  It should be turned back on once this bug is fixed.  See file "src/postgres/src/test/regress/yb_serial_schedule".

The following error is reported during regression test run.
CREATE TABLE feature_tab_date (feature_col DATE);

```
[INFO] Running org.yb.pgsql.TestPgRegress
[ERROR] Tests run: 3, Failures: 2, Errors: 1, Skipped: 0, Time elapsed: 316.769 s  BasePgSQLTest.cleanUpAfter:349 » PSQL ERROR: Not found: The tabl...
```
Discussion
- Assigning this to @m-iancu 
- After Posgres got the table OID, if the creation failed, it appears that DROP table is being called even though the table is not yet created.  As a result, YugaByte catalog layer reports the failure to DROP statement when it should have stay silent.
- Mihnea: please check to see if we should use "DROP IF EXIST" instead of just "DROP"
- Note for @mbautin 
After the raising error for non-existing table, YugaByte crashed.
The crash might be due to TWO errors are raised for ONE statement execution.

postgres# CREATE TABLE feature_tab_date (feature_col DATE);

1- First, correctly raised ERROR
ERROR: DATE is not yet supported.
After this error is raised, "DROP table feature_tab_date" was executed by the system to clean up the execution.

2- Second ERROR raised but should be silent --> crash
ERROR: Not found: The table does not exist: table_id: " "
- TestPgRegress crashes after this SECOND error due to unexpected behavior?
- Should this have been a LOG(error) instead of crashing?
- Fixed in 97635f4.
