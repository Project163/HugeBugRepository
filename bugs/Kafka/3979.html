Title

RemoteLogManager may compute inaccurate upperBoundOffset for aborted txns

Description
In RemoteLogManager.read, we compute startPos as the following. 
  
 
startPos = lookupPositionForOffset(remoteLogSegmentMetadata, offset); 
  
 This is the position returned by the offset index. The actual position for the first batch being read happens in the following, but startPos is not updated accordingly. 
  
 
firstBatch = findFirstBatch(remoteLogInputStream, offset); 
  
 We then use the inaccurate startPos to create fetchDataInfo. 
  
 
FetchDataInfo fetchDataInfo =  new  FetchDataInfo(
 new  LogOffsetMetadata(offset, remoteLogSegmentMetadata.startOffset(), startPos),
MemoryRecords.readableRecords(buffer)); 
  
 In addAbortedTransactions(), we use startPos to find the upperBoundOffset to retrieve the aborted txns. 
  
 
 long  upperBoundOffset = offsetIndex.fetchUpperBoundOffset(startOffsetPosition, fetchSize)
.map(position -> position.offset).orElse(segmentMetadata.endOffset() + 1); 
  
 The inaccurate startPos can lead to inaccurate upperBoundOffset, which leads to inaccurate aborted txns returned to the consumer.
