Title

Elasticsearch 5.0.0 beta1 starts with 1.x indices present

Description
**Elasticsearch version**:

Elasticsearch 5.0 Beta1

**Plugins installed**: []
None

**JVM version**:

1.8.0_91

**OS version**:
Linux

**Description of the problem including expected versus actual behavior**:

Based on breaking changes document. In the presence of pre-2.0 indices, Elasticsearch should not start:

[URL]

However this is not the case, its possible to start with an Elasticsearch 1.7.x node, upgrade to 2.x, and then upgrade to 5.0 and Elasticsearch starts and opens the 1.7.x index, and the index is searchable, when you look at _settings you'll see for any index created prior to 2.x, created field shows 1.7.2:

```
"index" : {
    "creation_date" : "1473963398745",
    "refresh_interval" : "5s",
    "number_of_shards" : "1",
    "number_of_replicas" : "1",
... [Log Snipped] ...
    }
  }
```

**Steps to reproduce**:
1. Install Elasticsearch 1.7.x and create an index and index some documents
2. Install Elasticsearch 2.x and make sure Elasticsearch uses the same data directory as in step 1. Then call POST /_upgrade.
3. Install Elasticsearch 5.0.0 beta1, and make sure Elasticsearch uses the same data directory as in previous steps. Elasticsearch will start instead of failing with some kind of error.

**Provide logs (if relevant)**:

You can query the 1.x index which works for some things but fails on a terms agg like:

org.elasticsearch.transport.RemoteTransportException: [LR3QYbZ][ :9300][indices:data/read/search[phase/query]]
Caused by: java.lang.IllegalStateException: unexpected docvalues type NONE for field 'clientip.raw' (expected one of [SORTED, SORTED_SET]). Re-index with correct docvalues type.
