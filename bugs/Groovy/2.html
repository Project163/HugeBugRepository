Title

Referring to a class name in Groovy to another Groovy class thats not yet been turned into bytecode causes a compile error

Description
If you do uncomment the 'todo' text in groovy.gdo.Person test so that the Person is used as an expression, then do 

 maven clean test 

 the test will fail. 

 This is due to the Person class not being found at the time the PersonTest is being compiled. 

 We need to have an interim step which once we've created the AST will spot class names as variables and expand them as ClassExpressions using the AST as well as the classpath
Discussion
- We basically need to put all the import stuff into the AST inside a ModuleNode in the AST. 

 Then before we generate the bytecode we can iterate through all the AST class nodes adding their names to a set. Then when we verify a ClassNode prior to generating the bytecode we can then check for variables which are class names in the AST (and not yet bytecode generated) or check for names on the classpath.
- Fixed. We now have a CompileUnit with all the AST nodes before we generate bytecode so we can do all the necessary class name checks.
