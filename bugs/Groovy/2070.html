Title

Groovyc: BUG! exception in phase 'class generation' in source unit

Description
This code: 
  
 @CompileStatic
     static  main(args)
    {
        def list = [1, 2, 3]

        def sum = 0
        list.each {  int  i -> sum += i }
        println(sum)

        sum = list.inject(0, {  int  x,  int  y -> x + y })
        println(sum)
    }

Discussion
- The problem goes away if you comment out the "sum = list.inject" part. The reason is that the compiler infers a return type of  Object  in that case, so  sum  becomes a potential  Object . As it's a closure shared variable, it should have, then, refused to let you do a "plus" on an  Object . So there are probably two problems in one here: 
 
	 closure shared variables tests are not done if using binary expressions instead of method calls (a+b instead of a.plus(b)) 
	 inject call should   infer a return type of Integer
- The issue which is fixed here is the fact that a closure shared variable is not rechecked if it is used in a binary expression. 

 The fact that  inject  infers an  Object  instead of an integer here is covered by the linked issue.
