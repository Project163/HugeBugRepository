Title

Overflow exception and DivideByZero exception from the RangeAttribute

Description
Specific data values fed to the RangeAttribute can trigger a DivideByZero exception and/or an OverflowException. These values have been pointed out by the Smart Unit Tests feature from Visual Studio 2015, and an image with the data values is attached.

The DivideByZero may happen by the user entering 0 as a step value.
The OverflowException is more serious as it highlights an implicit constraint saying “to > from” that is not stated anywhere. There should there be any need for that.
[Image: exceptions].

These issues are seen for all the RangeAttribute overloads.
Please let me know if you need any further information.

Pratap Lakshman

- I believe this can be done in steps of improvement.  
1) The documentation for RangeAttribute at [URL] is a bit overly optimistic "creates test cases from all possible combinations of the datapoints ".  It should be rephrased, and the limits stated.  It should also state that with wrong parameters you may get these two exceptions.
2) There is obviously something that always will go wrong, from>to & step negative and to>from and step positive.  Those two can be excluded with a guard clause throwing an argument exception.  
3) If negative steps need rework of the code, just guard that out for now, and state that in the documentation.  
4) Since it can operate on floating point numbers, a step may be too small compared to the range it operates on, causing overflow, then this could be attacked later.  I would not prioritize this, as I am fine with an overflow exception as long as it is documented.
