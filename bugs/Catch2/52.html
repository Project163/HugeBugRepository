Title

Catch2 application header not always displayed

Description
**Description**
The application header (including relevant info such as Catch2 version and random seed) is only printed when some tests fail or when forcing the inclusion of successful tests in the output.


**Expected behavior**
The application header, ie
```
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
a.out is a Catch v2.11.0 host application.
Run with -? for options
```
should always be shown, regardless of the results of the tests. Ideally, the application header would be shown immediately after starting the application. 


**Reproduction steps**
Consider the following test file `foo.cpp`:
```
#define CATCH_CONFIG_MAIN

#include  

TEST_CASE("LOL")
... [Log Snipped] ...
    CHECK(1==1);
}
```

The application header is shown only when tests fail or when using `-s`:

```
$ g++ foo.cpp
$ ./a.out 
===============================================================================
All tests passed (2 assertions in 2 test cases)

... [Log Snipped] ...
===============================================================================
All tests passed (2 assertions in 2 test cases)
```
Discussion
- I don't see a reason to print the header every time. However I just noticed that the console reporter does not report RNG seed in any case (`-s`, test failure, no test failure), which is bug, or at least bug adjacent.
- Hmmm, I beg to disagree, I think that the information contained in the header (Catch2 version, help hint, random seed) is something that should be shown or not independently of the test results and how they are reported. I for one want to have that info always, while not needing the successful test results (eg I may want to re-run with a successful seed on a different system).

As far as I can tell, the --rng-seed must be explicitly given so that the seed is shown.
- ... [Middle Discussions Snipped for Brevity] ...
- Right. The reason I am asking is that I am not fundamentally against showing the version as well, but I don't see the need for it yet, so I am asking if you have a reason that would convince me.

The reason I do not see a need to log the version by default is that any CI run should be obviously linked to a specific commit/revision, and a specific commit/revision should be linked to specific Catch2 version. This is unlike random seed, which is (hopefully :smiley:) different between each run of the same binary, and thus cannot be reconstructed without being reported.
