Title

filename formatting starting with slash prevents screenshots

Description

### Expected Behavior

When I trigger a screenshot I expect it to be saved in the "recordings" folder. Even with a leading `/` in "filename formatting".

### Current Behavior

It simply does not save the screenshot, due to a trailing space in the folder name (invalid on windows).
`C:/Users/Chris/Videos/Screenshot /2021/May` is not a place that exists, and cannot be written to. The folder will get created, but without the trailing whitespace.

### Steps to Reproduce

1. Modify Settings -> Advanced -> Recording -> filename formatting to start with a `/`. For instance `/%CCYY/%MM-%DD %hh-%mm-%ss`
2. Hit OK/Save
3. Trigger a screenshot thru right clicking the canvas -> Screenshot (source)
4. Observe how in the log, the screenshot is "saved" to a path that is invalid.
5. Observe that the folder does not have a screenshot.
...

### Anything else we should know?

There is a decent use case for having the folder structure split up by different dates/years, and it works fine, its just that screenshots do seem to be named with a whitespace at the end. This would either need to be changed, or perhaps a push for separate screenshot naming (like we have to replay buffer) is in order.

This exists in the latest RC, as well as on release.
