Title

Cannot run NUnit Console from another directory

Description
This has crept in recently, possibly with the new extensions? I am trying to run nunit-console from the root of the source tree,

```
λ .\bin\Debug\nunit-console.exe .\bin\Debug\net-2.0\nunit.framework.tests.dll
NUnit Console Runner 3.0.5751 (Debug)
Copyright (C) 2014 Charlie Poole

Failed to resolve assembly: 'nunit.engine.api, Version= , Culture=neutral, PublicKeyToken=null'
```
Discussion
- I see the same thing, so it's not just you. :-)

I can run without arguments, giving the help display, but any assembly argument gives that result. That includes 'junk.dll'.
- It is the ExtensionService. When initializing, it throws at CecilExtensions.cs, line 53, which is the first point where Resolve is called on a type reference. This method converts the reference to a full-fledged type description, which requires Cecil to locate all referenced assemblies. I'll have to read up on how Cecil searches for assemblies.

- Hi!
Trying out the new _NUnit_ `3`. Previously running the `2.6.3` version. I did the following steps:
1. Copy the `nunit.engine.api.dll` to the `nunit.org\bin\addins`.
2. Changed the command parameters from `/` to `--`.
3. Removed old command parameters, i.e. `nodots`.
4. Updated the batch command in my Jenkins, see below.
5. Investigating error in Jenkins module _Publish NUnit test result report_, looking for an update of the [Link: nunit plugin].

```
batch
@echo off
:: Windows cmd-file
:: Runs all debug unit tests for all NUnit-project files below current directory.
:: NUnit-Console | [URL]
... [Log Snipped] ...
echo Unit test done.
:end
```
- @Guson, you cannot just copy nunit.engine.api.dll into the old addins directory of 2.6.x. You must use a full install of v3 of nunit-console including the new engine and update your batch file accordingly.

If you want it to work with your batch file, you will need to uninstall 2.6.3 or remove it from your path, install v3 of the console and add it to your path.

For point 2, / will work for command line parameters on Windows. -- is better because it is cross platform.
