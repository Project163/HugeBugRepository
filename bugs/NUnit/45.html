Title

Windows 10 Support

Description
The `CultureSettingAndDetectionTests` are failing on Windows 10 because constructing a `CultureInfo` with an invalid culture on that platform creates a user defined culture rather than throwing a CultureNotFoundException. I was going to fix it by adding a platform attribute, but that needed extending.

I thought this would be easy, but it didn't turn out to be so. The `OSPlatform` class currently reports true for Win8.1 if the version is 6.3, but Windows 10 is currently reporting 6.3.9600. Interestingy, my Windows 8.1 machine is reporting 6.2.9200, so our Win8.1 code appears to be wrong.

Unfortunately, Microsoft throws a wrench into the detection process. According to [Link: this MSDN page], Windows 10 is supposed to report as 10.0 and Windows 8 as 6.3, but **only if the application is manifested for Windows 8.1 or Windows 10**. If the application is not manifested, it is supposed to return 6.2. Oddly, I got 6.3 for Windows 10, so who knows.

We can't expect every runner or even nunitlite runner to be manifested, so, from Win8.1 on, we cannot rely on the version number to determine the OS.

Going forward, we are going to have to do one of the following;
1. Find another way of deterninging the OS for Win8.1 and Win10, or
2. Stop support for detecting Windows Platforms at Win 8. Document and report all modern windows as Win8+.

In some ways, I am inclined towards the second option because according to Microsoft, Windows 10 is the last version. I will believe it when I see it, but the point is that from this point forward, developers are expected to do feature detection rather than OS detection because features can be added at any time by out of band installs or windows updates.

I am still going to look into alternatives to see if we can fix this.
Discussion
- On Windows 10, I have found the correct information in the registry under `HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows NT\CurrentVersion`

There are child keys `CurrentMajorVersionNumber = 10` and `CurrentMinorVersionNumber = 0`. There is another key `CurrentVersion = 6.3`

On my Windows 8.1 machine, `CurrentMajorVersionNumber` and `CurrentMinorVersionNumber` don't exist and `CurrentVersion = 6.3`

I could add code to OSPlatform to check the registry for these values if 6.2 or 6.3 is returned. The code will need to handle the case where the correct values are returned because the runner is manifested for the current OS.
