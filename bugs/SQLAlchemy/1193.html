Title

_get_constraint_data hanging with unicode table names

Description
This is in reference to the following questions:
[URL]
[URL]

Problem:
The _get_constraint_data takes a long time (100+ seconds, depending on a variety of factors) to return results for the Oracle dialect.

Cause:
It appears as though the 'info_cache' dict that populates the variables for the _get_constraint_data query is always using unicode characters. Whether this is occurring in SqlAlchemy or cx_Oracle code is unclear. What is clear is that Oracle processes the query slower because of this.

Potential Workaround:
After speaking with the db admin for our Oracle server, he suggested replacing the "all_" tables with their "user_" alternatives (perhaps when just having an owner defined?).
