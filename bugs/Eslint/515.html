Title

object-curly-spacing with never option warns for default and multiple named imports

Description
I added the following test (after cloning master) to the `valid` array in `tests/lib/rules/object-curly-spacing` and ran `npm test`.

**Test**

``` js
{
  code: "import door, {house, mouse} from 'caravan'",
  options: ["never"],
  ecmaFeatures: { modules: true }
}
```

**Expected**

The tests would pass.

**Actual**

```
1) object-curly-spacing import door, {house, mouse} from 'caravan':

      AssertionError: Should have no errors but had 1: [ { ruleId: 'object-curly-spacing',
    severity: 1,
    message: 'There should be no space after \',\'',
... [Log Snipped] ...
    nodeType: 'ImportDeclaration',
    source: 'import door, {house, mouse} from \'caravan\'' } ]
```

It warns for the comma between `house` and `mouse` which I believe shouldn't be a warning since there is already a passing test for `import {house, mouse} from 'caravan'`.
Discussion
- If this is reviewed as an actual bug, I'd be interested in attempting to fix it with a pull request. :smile:
- Definitely looks like a bug. Seems like it's checking the comma for some reason.
- I'm taking a look at this and should have a pull request ready in the next few days.
