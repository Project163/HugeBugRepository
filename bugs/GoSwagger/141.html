Title

Base64 validation wrongly performed after decoding the string field My App API

Description
## Problem statement

Base64 validation wrongly performed after decoding the string field. 

We found it with my colleague Vitaly today after adding the `format: byte` into the string field in spec.

## Swagger specification
```
swagger: '2.0'

info:
My App API
... [Log Snipped] ...
          schema:
            type: string
```
## Steps to reproduce

put the spec into the file `swagger.yml`
`swagger generate server -f ./swagger.yml`
`go run cmd/my-app-server/main.go --port=3000`
in separate console: 

`curl -H 'Content-Type:application/json' -X POST localhost:3000/in --data '"bWVzc2FnZWhlcmU="'`
returns `{"code":601,"message":"data in body must be of type byte: \"messagehere\""}`

but `curl -H 'Content-Type:application/json' -X POST localhost:3000/in --data '"MjIzM3QyNHQ="'`
works normally by coincidence. 

## Environment
swagger version prints "dev" (latest from the repo)
go version: 1.10.2
OS:   Ubuntu 14

## Possible cause

Seems the problem lies inside a 
```
if runtime.HasBody(r) {
		defer r.Body.Close()
		var body strfmt.Base64
		if err := route.Consumer.Consume(r.Body, &body); err != nil {
			res = append(res, errors.NewParseError("data", "body", "", err))
... [Log Snipped] ...
		}
	}
```
block of `BindRequest` method inside generated `my_method_parameters.go` due to body contains already decoded value of base64. 

This created seems from `parameter.gotmpl`. Also the problem may persist in other places.
