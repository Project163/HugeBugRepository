Title

addBehavior() should not be ignored if already added.

Description
When upgrading 2.x code to 3.x I noticed that this does not work as expected:

```
$this->Addresses = TableRegistry::get('Geo.Addresses');
$this->Addresses->addBehavior('Geo.Geocoder', array('unit' => Geocode::UNIT_MILES));
```

The unit config is ignored here.
After quite some debugging I found out that the behavior is already added and therefore this line of code silently does nothing.

Only when adding removeBehavior() in there as well, it works:

```
$this->Addresses = TableRegistry::get('Geo.Addresses');
$this->Addresses->removeBehavior('Geocoder'); //FIXME: Shouldnt be necessary ideally
$this->Addresses->addBehavior('Geo.Geocoder', array('unit' => Geocode::UNIT_MILES));
```

But it should either trigger an error, or better yet, just create a new behavior on top - or overwrite the settings here so that from here on the unit really is what one would expect here.
Discussion
- I don't think overwriting the existing behaviour makes sense. That would make behaviours unlike all other registry based things which all ignore duplicate object definitions.

Throwing an error might work but may make registries awkward to work with.
- Overwriting the config is probably the best option we have here, but any change we make should be applied consistently to components, helpers and tasks.

This could be a method that quite a few devs want to implement anyway...
