Title

[YSQL] Integer overflow may occur in seek and next estimation leading to negative costs

Description
Jira Link: [Link: DB-15157]
### Description

In a large table with rows more than the maximum value of int viz. 2147483647, the estimated number of seeks and nexts may overflow. This may lead to undefined behavior. 

In the following example, the value of num_nexts overflows. When run on a debug build, the "Estimated Nexts" gets set to the maximum value of int. However, on a release build it gets set to -2147483648, which is the smallest negative value possible in int. This led to a negative cost in the release build. 

This can be fixed by using double for estimated seeks and nexts to match the type of reltuples.

```
create table test (k1 int);

-- Update pg_class to simulate a large table
set yb_non_ddl_txn_for_sys_tables_allowed = ON;
update pg_class set reltuples=4000000000 where relname='test';
update pg_yb_catalog_version set current_version=current_version+1 where db_oid=1;
set yb_non_ddl_txn_for_sys_tables_allowed = OFF;

-- Enable CBO
set yb_enable_base_scans_cost_model = ON;

explain (debug) select * from test where k1 > 0;
                               QUERY PLAN                               
------------------------------------------------------------------------
 Seq Scan on test  (cost=180.00..1872031195.66 rows=1333333333 width=4)
   Storage Filter: (k1 > 0)
   Estimated Seeks: 1302084
   Estimated Nexts: 2147483647
   Estimated Docdb Result Width: 1
(5 rows)
---
