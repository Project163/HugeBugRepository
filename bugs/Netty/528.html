Title

HTT/2 upgrade NPE when performing an upgrade with initial settings window size > 65535

Description
I'm currently seing an NPE when doing an HTTP/2 upgrade with initial settings with a window size > 65535 when calling `onHttpServerUpgrade` after the `Http2ConnectionHandler` is created.

As the window size is greater than the default value, it tries to write pending bytes, however the handler is not yet in the pipeline as `onHttpServerUpgrade` must happen before the `Http2ConnectionHandler` is in the pipeline.

When `onHttpServerUpgrade` is called after it is in the pipeline, then the preface will be sent and the settings cannot be applied to the connection.

The NPE happens because it tries to send bytes and use the `ChannelHandlerContext` that is not sent yet.

Here is the stack trace:

```
java.lang.NullPointerException
    at io.netty.handler.codec.http2.DefaultHttp2RemoteFlowController.maxUsableChannelBytes(DefaultHttp2RemoteFlowController.java:262)
    at io.netty.handler.codec.http2.DefaultHttp2RemoteFlowController.writableBytes(DefaultHttp2RemoteFlowController.java:274)
    at io.netty.handler.codec.http2.DefaultHttp2RemoteFlowController.access$1000(DefaultHttp2RemoteFlowController.java:41)
    at io.netty.handler.codec.http2.DefaultHttp2RemoteFlowController$WritabilityMonitor.writePendingBytes(DefaultHttp2RemoteFlowController.java:710)
... [Log Snipped] ...
    at io.netty.handler.codec.http2.Http2ConnectionHandler.onHttpServerUpgrade(Http2ConnectionHandler.java:150)
    at io.vertx.core.http.impl.HttpServerImpl$ServerHandler.createConnAndHandle(HttpServerImpl.java:676)
```
Discussion
- to me it seems that setting the initial window size should not try to send frames, i.e the part in `initialWindowSize` :

```
            if (delta > 0) {
                // The window size increased, send any pending frames for all streams.
                writePendingBytes();
            }
```

should not be called is this situation
