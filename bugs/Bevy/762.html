Title

`Deferred::apply` runs even if the system never ran.

Description
## Bevy version and features

- Main @ fcd5c265

## What you did

```rust
// My app does not include the diagnostics plugin, so the DiagnosticsBuffer within Diagnostics will fail to apply.

fn my_optional_diagnostics_system(mut diagnostics: If ) {
  // I only want these measurements to be sent when diagnostics exist.
}
```

## What went wrong

The SystemBuffer in DiagnosticsBuffer gets applied, resulting in a panic since the DiagnosticsStore does not exist.

While the DiagnosticsBuffer probably should avoid panicking in this case, we also probably shouldn't be applying `Deferred` if the system never ran! This is most visible using the `If` type to automatically skip systems when the DiagnosticsStore is missing.
Discussion
- I poked at this a bit, and after thinking through some edge cases, I think making the parameters resilient as you did in #21550 might be the correct fix here after all.  

We should make a similar change to `GizmoBuffer`.  

---

The main trouble is that other code might manipulate the world between the decision to skip and the call to `apply_deferred`.  For an extreme case, consider

```rust
fn system(mut commands: Commands, mut diagnostics: If ) {
    commands.remove_resource:: ();
}
```

The system will pass validation and run, but when we go to apply commands, the `apply_deferred` will first run the command to remove the resource!  

So I think `SystemBuffer` impls will need checks like you added in #21550 no matter what.  

---

But there are also other edge cases where it's not clear how to decide when to skip `apply_deferred`, such as

```rust
fn system(mut diagnostics: Option ) { ... }
```

which will run with `None` even if the resource doesn't exist, and

```rust
fn first(mut commands: Commands) -> usize { ... }
fn second(input: In , mut diagnostics: If ) { ... }
app.add_systems(Update, first.pipe(second));
```

where we probably want to run commands from `first` even if `second` skips.  

I don't see any clear place to handle those cases outside of the `SystemBuffer` impl itself.
