Title

4.1.0-Beta4: Regression in HttpRequestDecoder

Description
We recently noticed that one of our Netty services was intermittently ignoring requests, causing the caller to timeout. Adding LoggingHandlers all over the place revealed that the failing request was received but never made it out of HttpRequestDecoder.

The connection is reused by the client and saw multiple similar requests before the server somehow choked on the last one. The server uses autoRead=false in case that is relevant.

We promptly reverted to 4.1.0-Beta3 and this failure mode completely disappeared. A quick look at the commit log between the two tags show a significant refactor of HttpRequestDecoder and some more subtle changes to ByteToMessageDecoder which are probably responsible for the regression.
