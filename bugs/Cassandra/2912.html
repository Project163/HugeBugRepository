Title

Parallelize unit test runner

Description
Currently we spend ~15 minutes running unit tests. 

 We can parallelize the unit tests by splitting the classes up across processes and using more cores. 

 This patch adds a new variable -Dtest.runners=X (default is 1) 

 Running with 4 runtime goes from 15min to 6min.  
Beyond 1 runner per core I don't see much of a difference
Discussion
- I'm seeing similar improvements in time on Linux (15m to 6m) and Windows (30m to 18m). I had no issues setting -Dtest.runners higher than the number of cores.
- It looks like  -Dtest.name  doesn't work with this.  I guess it would be okay to only have that work with "oldtest", but can you see how hard it would be to make that work?
- v2 fixes -Dtest.name
