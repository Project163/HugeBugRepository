Title

Painless Execution API does not work with documents which has nested types

Description
**Elasticsearch version** 
6.5.4 and above

**Plugins installed**: []

**JVM version** 
1.8.0, jdk10, jdk11, jdk12
**OS version**
linux

**Description of the problem including expected versus actual behavior**:

When using painless execution [Link: API], documents with nested field types are empty

**Steps to reproduce**:

```
curl -X PUT "localhost:9200/test0" -H 'Content-Type: application/json' -d'       

{
    "mappings" : {
        "_doc" : {
... [Log Snipped] ...
    }
}
```

```
 curl -X PUT "localhost:9200/test0/_doc/1" -H 'Content-Type: application/json' -d'
{
    "field0" : 12, "field1": [{"nested1":1}]                                 
}   
'  
```

```
curl -X POST "localhost:9200/_scripts/painless/_execute" -H 'Content-Type: application/json' -d'
{
  "script": {
    "source": "return doc[\"field0\"].value    ",
    "params": {
... [Log Snipped] ...

{"result":0.0}
```

It was expected to have result 3 instead of 0
Discussion
- Pinging @elastic/es-core-infra
- I debugged the issue a bit.
In the case of nested documents, the `LeafFaactory` in this [Link: line] does not include any document. Even `_source` field becomes empty. 

This info might help
- @elastic/es-core-infra Any Idea if it is a bug or I am miss-using the endpoint?
- @csenol This is a bug. I've only tested it in the master branch, but there it fails because the execute api thinks there is no `field0`. The problem is that it isn't selecting the main (root) document here: [URL]

It is selecting a nested document and that document doesn't have a `field0`. I think fix would be to like the percolator select the right document with nested documents in mind: 
[URL]

We can then use `Queries.newNonNestedFilter(...)` to figure which document is not nested and use its lucene docid instead of always using docid 0 (like is done in line 548).
