Title

DirectSolrSpellCheckerTest fails on ibm jdk

Description
ant test-core -Dtestcase=DirectSolrSpellCheckerTest -Dtestmethod=test -Dtests.seed=- :  -Dtests.codec=randomPerField 

 Seems to be specific to IBM JDK... won't fail on others:

Discussion
- This is actually a bug! Thanks for finding this Shai. 

 The problem is the comparators used in spellcheck are broken: this doesn't just affect the DirectSpellChecker but also the PlainText and Index-based spellchecks. 

 For example, if you use the SuggestWordScoreComparator (i think this one is the default), it first sorts based on score, then on document frequency if there is a tie. but if  both of these are a tie  the results are undefined... it depends on things such as which order you added documents to your index (for the index-based case)!!!! 

 This patch adds a tertiary tie-breaker, which is guaranteed to make the result stable, by using term text (String.compareTo) in these situations.
- Adding 3.x, as this is a pre-existing bug that affects all spellcheckers.
- I've tried the patch and it works. Thanks for fixing it so quickly !
