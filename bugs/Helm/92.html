Title

helm test command fails if --filter excludes all test hooks and --logs flag is used

Description

```

```
Cloud Provider/Platform (AKS, GKE, Minikube etc.): any


i have only one hook in a release and I tried to exclude it when `--logs` flag is used.
As result helm command returns with non-zero code and it causes a pipeline to fail.
Logs:
```
➜  ~ helm test frame-poc -n frame --logs --timeout 10m --filter="\!name=frame-poc-test"
NAME: frame-poc
LAST DEPLOYED: Mon Jan 17 09:46:35 2022
NAMESPACE: frame
STATUS: deployed
REVISION: 5

Error: unable to get pod logs for frame-poc-test: pods "frame-poc-test" not found
```

Important thing here is a pod shouldn't exist before running the command.
My helm test hook is `Pod` kind.
Discussion
- If all test pods were excluded with the filter, I'd kinda expect `helm test` to fail with "no pod logs for frame-poc-test". Your intent was to fetch the logs from the test, but they were all filtered out... What behaviour were you expecting?
- I expected that helm would exit with 0 at least and may be with text like "no tests found" or something like that.
- ... [Middle Discussions Snipped for Brevity] ...
- We have the same issue and would really appreciate if this is fixed. 

We want to run a specific helm test suite and then fetch the logs of the test pod on client side. Unfortunately, we cannot use "--logs and --filter" flags together for that. The error even prevents retrieving the logs of the pods which are not excluded by the filter.
- I hope this PR gets merged soon. This seems like a very basic feature that is missing. The logs output should simply contain the logs from the test pods that were deployed with the command that was run.

Because this doesn't work, not only do we get the error about logs not found, but also logs from actual tests that were run are not displayed. This makes the --logs flag completely unusable with --filter which is crucial for a large test suite.
