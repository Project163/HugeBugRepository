Title

Eslint don't respect root: true if the directory name contains curly braces

Description
The problem is that if 

* the directory contains curly brace (it is the case on our jenkins environment, because it is used to group job {PROJECT1}Job1, {PROJECT1}Job2, ...). So the directory will be /var/lib/jenkins/{PROJECT1}Job1/client ...
* the glob using to select file file to include include curl brace like in nest.js : eslint \"{src,apps,libs,test}/**/*.ts\" --fix

Eslint will read all directory inside /var/lib/jenkins and execute eslint on other project/job inside this directory. If this project don't have node_modules, or if there is error, ... : our job crash.

- [URL]

The `pattern` variable value seems to be an absolute path. The file enumerator intended to start traversing from the outermost non-pattern place. For example, if `src/**/*.js` is present, it traverses in `$CWD/src/`. It intends to not check unrelated directories.

In this case, because the `pattern` variable value includes the CWD path, the `getGlobParent(pattern)` goes wrong. I think that the `pattern` should not be joined with `cwd` but `getGlobParent(pattern)` should join with `cwd`.
