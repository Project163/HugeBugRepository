Title

Fix non-strict toolchain's precedence and diagnostic message

Description
(for #8547) added a non-strict Python toolchain to reduce pain in migrating for [Link: `--incompatible_use_python_toolchains`]. However, there are two critical bugs in this change, which has already been cherrypicked into the 0.27 RC:

1. The Python rules workspace suffix does not specify which order the toolchains should be registered in, so the non-strict one may take precedence over the strict one.

2. The error message does not print the flag name `--extra_toolchains=...` correctly, defeating much of the benefit of the change.
