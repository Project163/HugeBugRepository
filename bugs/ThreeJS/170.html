Title

TransformControls: rotate doesn't work when Camera is at 0,0 for x,y

Description
I'm using the example here for TransformControls:
examples/misc_controls_transform.html

The rotate gizmo doesn't seem to work if the Camera's x,y position is at 0,0. 
I changed the line of code  
camera.position.set( 1000, 500, 1000 );
to 
camera.position.set( 0, 0, 1000 );

And rotating seems broken for going up/down and left/right.
Discussion
- Can you create a jsfiddle?
- To rotate around Y axis, for example, the control casts a ray through XZ plane and determines the angle between drag start and drag end vector in that plane. When camera is at 0, 0 it is perfectly aligned with XZ and YZ plane and it doesn't make sense to project into those planes. This also makes the rotation difficult when camera is almost aligned. I noticed that many rotation gizmos suffer from this problem including tools such as Autodesk Maya.

Some time ago, I refactored and greatly simplified [Link: TransformControls] and also fixed bunch of bugs such as this one (by improving the angle calculation math and hiding the rotation handles when perfectly aligned to the plane). However, this improved version cannot be easily merged back into three.js since it relies on shared [Link: Control] superclass (also used by improved [Link: EditorContols]).

If there is interest to pull this back into three.js I can help with that.
- I'm interested in the bug fixed and simplifications, but I would avoid the multiple files (`TransformControls` and `Controls`).
- +1 -- interested in bug fixes.
