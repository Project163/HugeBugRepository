Title

Regression for numeric Value type in Helm v2.15 breaking templates

Description
The regression found in CI/CD nightly builds when relying on latest Helm which is now `v2.15` (since Friday? :trollface:)

In new Helm `v2.15` there seems to be some changes in values types.

### Helm Values:
```yaml
replicas: 3
```

### Helm Template:
```go
$replicas := int (.Values.replicas)
```
### Will produce:
`0` in `v2.15`
`3` in `v2.14`


---

After closer look, `.Values.replicas` is now of type `json.Number` in `v2.15`, previously was `float64` in `v2.14`. This means some previously worked cast/conversions in many user's templates and charts would fail.
For reference:
[URL]
[URL]

### Workaround
Workaround for Helm `v2.15` templates is to cast to string first before converting to int:
```diff go
- $replicas := int (.Values.replicas)
+ $replicas := int (toString (.Values.replicas))
```

### Output of `helm version`:
`v2.15.0`
### Cloud Provider/Platform (AKS, GKE, Minikube etc.): 
`minikube`
