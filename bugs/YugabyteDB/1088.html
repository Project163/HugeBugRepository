Title

[YSQL][randgen] Index Scan with aggregate push down return wrong result when there are multiple search conditions on the same index key item

Description
Jira Link: [Link: DB-9714]
### Description
**Update: Added missing `cc` table creating to the test case and added "ASC" keyword to the index definition to make the test case work when colocation is not turned on by default.**

* Reproducible on the latest master (38f6492)
* `MAX`/`MIN`/`SUM` should return `NULL` and `COUNT` should return 0 when the input is an empty set, however, it returns 1 instead when the aggregate function is pushed down to the Index Scan.

Test Case
---
* The condition: `table1.col_int_key = 1 AND table1.col_int_key BETWEEN 7 AND ( 7 + 7 ) ` is always false because 1 is outside of the range [7, 14].
```
DROP TABLE G;

CREATE TABLE G (
	pk SERIAL  ,
	col_int int,
... [Log Snipped] ...

SELECT MAX( table1.col_int_key ) AS field1 FROM g AS table1 LEFT JOIN cc AS table2 ON table1.pk = table2.pk WHERE ( table1.col_int_key = 1 AND table1.col_int_key BETWEEN 7 AND ( 7 + 7 ) ) ;
```

With Index Scan (wrong results):
```
SELECT MAX( table1.col_int_key ) AS field1 FROM g AS table1 LEFT JOIN cc AS table2 ON table1.pk = table2.pk WHERE ( table1.col_int_key = 1 AND table1.col_int_key BETWEEN 7 AND ( 7 + 7 ) ) ;
 field1 
--------
      1
(1 row)
... [Log Snipped] ...
         Partial Aggregate: true
(4 rows)
```

With Seq Scan (correct):
```
/*+ SeqScan(table1) */
SELECT MAX( table1.col_int_key ) AS field1 FROM g AS table1 LEFT JOIN cc AS table2 ON table1.pk = table2.pk WHERE ( table1.col_int_key = 1 AND table1.col_int_key BETWEEN 7 AND ( 7 + 7 ) ) ;
 field1 
--------
       
... [Log Snipped] ...
         Partial Aggregate: true
(4 rows)
```
