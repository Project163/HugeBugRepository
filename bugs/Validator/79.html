Title

IbanCheckDigit.isValid() returns True for some invalid IBANs

Description
For example, isValid() returns True for both of these IBANs; "IE01AIBK93118702569045" and "IE98AIBK93118702569045".  The "IE98" version is the correct one (confirmed with online checkers, which also fail the "IE01" version). 

 calculate() correctly returns "98".  As a workaround I'm calling calculate() and comparing the result with the checksum in the original IBAN.
Discussion
- I can confirm there's something rather odd happening here. 
It should not be possible for both 01 and 98 to be correct, yet both return true from isValid.
- Doh!  
Of course 98 and 01 are return the same remainder - they differ by the modulus which is 97. 
There would be the same problem with 97 and 00. 

 However, the check digit is supposed to be the number modulus 97 subtracted from 98. 
Since mod 97 is in the range 0-96, the check digits must be in the range 98,97...02. 
i.e. 01 and 02 are not valid as check digits. 

 The code does not check this currently.  
Nor does it check the length or format of the IBAN.
