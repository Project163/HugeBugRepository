Title

[Ivy] customElements.define fails when in Module constructor

Description
# 🐞 bug report

### Affected Package
 
  The issue is caused by package @angular/core


### Is this a regression?

 
  Yes, the previous version in which this bug was not present was: v8


### Description

  After updating to angular 9 from angular 8 (but it is not related to the update as it is reproducible in clean ng9 repo), my angular component stopped working, and the issue is related to the `Optional()` DI mechanism, when used inside of an angular element component. 
  
Peculiarities:
- If used without ivy, the issue disappears (i.e. `"angularCompilerOptions": {"enableIvy": false}`).
- If optional DI is used outside of angular elements component, it works without any issues.
- Also, if the angular element component is used within some other _normal_  angular component, there will be no issue, only when it is used directly within `index.html` or any other nonangular environment (which is where the angular elements components mostly get used anyway).
- One more thing I noticed is that when the injection is tried in next tick (i.e. wrapped inside of `setTimeout(()=>{...}, 0)`) the issue is gone as well.
- Moving `createCustomElement` call from the module constructor to `ngDoBootstrap` also fixes issue, but it is probably for the same reason as the above bullet.

- Right, the difference you're observing between v8 and v9 is that v9 would enable Ivy by default which is a completely different runtime than before (including the injector implementation). The injector was instantiated in a more incremental way in the previous runtime (https://github.com/angular/angular/blob/master/packages/core/src/view/refs.ts#L374-L379) - `injector = this` followed by pushing to providers in `initNgModule`.

I'm still investigating if there's something that can be done about this in Ivy. Your proposed workaround of moving the `customElements.define` to `ngDoBootstrap` seems correct and reasonable in the meantime.
