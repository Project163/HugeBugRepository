Discussion
- HierarchyIterator classes are kind of experimental. 
They were supposed to replace the visitor based component tree traversal but haven't been tested well enough. 

 Please provide a quickstart app that shows the problem and we will investigate the problem. 
In the meantime you can use org.apache.wicket.MarkupContainer#visitChildren(IVisitor<Component, R> visitor) method.
- Did you try with MarkupContainer#visitChildren(IVisitor<Component, R> visitor) ? 
Do you see the same problem with IVisitor with the same page where AbstractHierarchyIterator fails ?
- I replaced the ComponentHierarchyIterator with this: 

  
 mc.visitChildren(FormComponent.class,  new  IVisitor<FormComponent, FormComponent>() {
  @Override
     public  void component(FormComponent c, IVisit<FormComponent> visit) {
    ...
    }
  });
 
  

 ... and it works without crashing as expected. So the visitor based component traversal works fine.
- Component hierarchy iterators have been marked deprecated and will be removed in Wicket 8.0. 
Applications are recommended to use IVisitor based methods.
