Title

`App.PageData` proper typing isn't enforced in layouts

Description
### Describe the bug

Given the following `app.d.ts`:
```ts
declare namespace App {
  interface PageData {
    foo: number;
  }
}
```

If you do the following in a `+page.ts` load function:
```ts
import type { PageLoad } from './$types';
export const load: PageLoad = () => {
  return {
    foo: 'not a number'
  };
};
```
You'll get an error (and rightly so) stating that the type of the property `foo` isn't correct.

However, if you do the same thing in a `+layout.ts` load function:
```ts
import type { LayoutLoad } from './$types';
export const load: LayoutLoad = () => {
  return {
    foo: 'not a number'
  };
};
```
Now you don't get any errors; you should, obviously, `foo` has to be a number.

I actually just spent a relatively long time beating my head against the wall trying to figure out what was wrong with some part of my app and eventually found out it came down to me setting the wrong value for a certain property in my `+layout.ts`, which I wasn't noticing due to there not being any type errors or anything.

### Reproduction

Explained above.

- I think I understand the problem better now.
1. Right now the logic is "if there's a page(.server) file, assume that it has a load function". This isn't always correct. We may need to statically analyze each of those files to see if that's really true - update: fixed through #7050
2. (possible bug uncovered while playing around) when I delete a `+page.js` file next to a `layout.js` file the types don't get updated - update: fixes through #7002 
3. Even with 1 and 2 getting resolved, there's still the "problem" that the type of `LayoutLoad` assumes that it's the `PageLoad`'s job to fill out the required fields. `LayoutLoad` will only get more strict typings if not all children have load functions. I don't see a way to make this work so that it works as wanted here, since this is a cyclic relationship: In order to know what type `LayoutLoad` is, it would need to know what return type `PageLoad` has. To know what type `PageLoad` to restrict to, it needs to know the return type of `LayoutLoad` (properties already set in `LayoutLoad` are no longer required in `PageLoad`).

Since 1 and 2 are resolved and 3 can't be changed / is "works as designed", I'm closing this.
