Title

Range query on timestamp field can incorrectly exclude docs in tsdb data stream

Description
Description of the bug: If timestamp field uses nanosecond resolution then range query on `@timestamp` field can incorrectly exclude documents that do match with the range query on `@timestamp` field.

Reproduction:

1. Create template:

```
PUT _index_template/test-template-for-nanos-tsds
{
    "template": {
        "mappings": {
            "properties": {
... [Log Snipped] ...
    "composed_of": []
}
```

2. Index documents:

```
POST my-test-nanos-tsds/_doc
{
    "type": "first",
    "@timestamp": "2023-05-11T14:55:17.000Z"
}
... [Log Snipped] ...
    "@timestamp": "2023-05-11T14:56:17.000Z"
}
```

Rollover:

```
POST my-test-nanos-tsds/_rollover
```

3. Index more documents:

```
POST my-test-nanos-tsds/_doc
{
    "type": "third",
    "@timestamp": "2023-05-19T02:57:40.046992806Z"
}
... [Log Snipped] ...
    "@timestamp": "2023-05-19T04:51:40.046992806Z"
}
```

4. Search fails with range query that should match with all indexed documents fails to do so:

```
GET /my-test-nanos-tsds/_search
{
    "query": {
        "range": {
            "@timestamp": {
... [Log Snipped] ...
    "size": 10
}
```

Search response:

```
{
    "took": 2549,
    "timed_out": false,
    "_shards": {
        "total": 2,
... [Log Snipped] ...
    }
}
```

Only search with range that start from beginning of epoch time works:

```
GET /my-test-nanos-tsds/_search
{
    "query": {
        "range": {
            "@timestamp": {
... [Log Snipped] ...
    "size": 10
}
```

Preliminary diagnoses: The search response in step 4, indicates that one shard has been skipped. Meaning that the search request didn't execute, while according to the defined range it should run on all shards. Likely cause is that the query rewrite on the coordinating node falsely exclude the second backing index (created after rollover). I think somehow nanoseconds are being compared to milliseconds here.
