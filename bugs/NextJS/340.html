Title

ESM project with appDir+typescript does not compile without typedRoutes

Description

### Which area(s) of Next.js are affected? (leave empty if unsure)

App directory (appDir: true), TypeScript (plugin, built-in types)

### Link to the code that reproduces this issue

[URL]

### To Reproduce

Run `npm run build`

You will get an error:

```

warn  - You have enabled experimental feature (appDir) in next.config.mjs.
warn  - Experimental features are not covered by semver, and may cause unexpected or broken application behavior. Use at your own risk.
... [Log Snipped] ...
Type error: The current file is a CommonJS module whose imports will produce 'require' calls; however, the referenced file is an ECMAScript module and cannot be imported with 'require'. Consider writing a dynamic 'import("../../../app/layout.js")' call instead.
  To convert this file to an ECMAScript module, change its file extension to '.mts' or create a local package.json file with `{ "type": "module" }`.
```

[Image: image]

### Workaround

Enabling the `typedRoutes` feature fixes type checking (see the `fix` branch in the reproduction repository).

### Describe the Bug

When a next.js project uses experimental appDir, typescript, and ESM modules for project files, type checking is broken unless also typedRoutes is enabled.

The files in .next/types get interpreted by tsc as CommonJS, and fail to import the ESM modules in appDir.

The next-types-plugin already provides the code to generate a package.json that marks those types files as module, but it is only generated when the typedRoutes feature is enabled:
[URL]

This file also needs to be generated when the root project has type:module (and typedRoutes is not enabled).
