Title

SQL: PI() function works with multiply character (*) only when the character has whitespaces in front and back

Description
```
sql> SELECT PI()*2;
Bad request [line 1:12: extraneous input '*2' expecting { , ',', 'ANALYZE', 'ANALYZED', 'AND', 'AS', 'BETWEEN', 'CATALOGS', 'COLUMNS', 'DEBUG', 'EXECUTABLE', 'EXPLAIN', 'FORMAT', 'FROM', 'FUNCTIONS', 'GRAPHVIZ', 'GROUP', 'HAVING', 'IN', 'IS', 'LIKE', 'LIMIT', 'MAPPED', 'NOT', 'OPTIMIZED', 'OR', 'ORDER', 'PARSED', 'PHYSICAL', 'PLAN', 'RLIKE', 'QUERY', 'SCHEMAS', 'SHOW', 'SYS', 'TABLES', 'TEXT', 'TYPE', 'TYPES', 'VERIFY', 'WHERE', '{LIMIT', '=', NEQ, ' ', '>=', '+', '-', '*', '/', '%', IDENTIFIER, DIGIT_IDENTIFIER, QUOTED_IDENTIFIER, BACKQUOTED_IDENTIFIER}]

sql> SELECT PI() * 2;
   ((PI) * 2)
-----------------
6.283185307179586
```
Discussion
- That's because is getting matched with this rule too: [URL]
- @costin Cannot find another way to handle this ambiguity other than only allowing the `*` in the tableIdent when it's quoted, e.g.: `"my_indexes*"`.
