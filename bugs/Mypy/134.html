Title

Mypy doesn't work with the latest release of lxml

Description
Using mypy reports with the latest release of lxml results in the following stack trace:

```
$ mypy --html-report mypy_dir defaultdict_example.py
Traceback (most recent call last):
  File "/Users/rwilliams/src/oss/mypy/.venv/bin/mypy", line 6, in  
    main(__file__)
  File "/Users/rwilliams/src/oss/mypy/.venv/lib/python3.5/site-packages/mypy_lang-0.2.0.dev0-py3.5.egg/mypy/main.py", line 91, in main
... [Log Snipped] ...
  File "src/lxml/lxml.etree.pyx", line 3039, in lxml.etree.ProcessingInstruction (src/lxml/lxml.etree.c:81073)
ValueError: Invalid PI name 'b'xml''
```
Discussion
- Thanks for reporting this! I'd like to get rid of the lxml dependency as soon as possible, but for now we need to figure how to live with it.
- I've just hit the same thing. I think the correct thing here is to remove the `xml_pi = ProcessingInstruction...` line, and the line just after which uses `xml_pi`.

This appears to be a misunderstanding about the ` ` line in XML files. It [Link: is not a processing instruction] despite often being called one. This is why it's explicitly checked for in recent lxml releases.

Reports then seem to work, or at least HTML ones do.
