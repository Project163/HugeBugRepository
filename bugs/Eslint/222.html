Title

New rule suggestion: literal conventions mixed

Description
With `space-in-brackets` enabled I had an error like this:

```
_.template([
    'Foo: ${ foo }',
    'Bar: `${ bar }`.'].join('\n'), {
    foo: 'foo',
    bar: 'bar',
});
```

I got noticed by `space-in-brackets`

```
error  There should be no space after '['  space-in-brackets
```

Since there are certainly spaces after the opening bracket this rule fails correctly, but it's not the most clear message possible.

The same occurs when array is written in consistently, but the object literal is not:

```
_.template([
    'Foo: ${ foo }',
    'Bar: `${ bar }`.',
].join('\n'), {
    foo: 'foo',
    bar: 'bar'});
```

```
error  There should be no space after '{'  space-in-brackets
```

However using new lines inside the literal without spaces after left bracket/before right brakcet is ok for this rule:

```
_.template(['Foo: ${ foo }',
    'Bar: `${ bar }`.'].join('\n'), {
    foo: 'foo',
    bar: 'bar',
});
```

The error which caused the problem is the mix of conventions: first element of the array is in the new line, but there is no new line after the last. The correct form of the snippet (with both literals expanded) will be:

```
_.template([
    'Foo: ${ foo }',
    'Bar: `${ bar }`.',
].join('\n'), {
    foo: 'foo',
    bar: 'bar',
});
```

I suggest adding new rule rule which would warn if conventions are mixed.
Already existing rules do not seem to cover the case: I can either force or disable spaces in brackets but there is no rule which explicitly addresses the case checking whether the literal (both array and object i suppose) is written consistently.
