- I checked similar places in SSTableSimpleScanner proximity and probably we also need to add a logic like this: 
  
 
 catch  (CorruptSSTableException e)  // to ensure that we marked the sstable as suspected
 {
    sstable.markSuspect();
     throw  e;
}  
  
 to org.apache.cassandra.io.sstable.SSTableIdentityIterator#create() because it does reads and we can throw CorruptSSTableException from org.apache.cassandra.io.util.CompressedChunkReader.Standard#readChunk() but we do not invoke markSuspect on that level.
