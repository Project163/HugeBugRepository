Title

Regular-Expression-Evaluates-Null-As-True

Description
Issue reported groovy-user forum:  [URL]

 / * Returns true */ 
println null ==~ / [^0-9] +/  

 / * Returns false */ 
println null ==~ / [0-9] +/ 

 In both the cases, it should probably just throw NPE.
Discussion
- Fixed. Pattern check against null now throws NPE and is consistent with Java.
- Discussion on the dev list brought out that returning false was a much suitable result compared to NPE.  

 NPE behavior introduced in pass-1 fix created an issue with Gant build that was using null ==~ something kind of pattern matching in some cases.
