Title

Explicitly add commons-codec 1.5 as a dependency

Description
Right now, commons-codec is a transitive dependency. When Spark is built by maven for Hadoop 1, jets3t 0.7.1 will pull in commons-codec 1.3 which is an older version (Hadoop 1.0.4 depends on 1.4). This older version can cause problems because 1.4 introduces incompatible changes and new methods.
Discussion
- Does commons-codec 1.4 really break compatibility with commons-codec 1.3? Or is the issue just that Hadoop is compiled against 1.4 but maven is selecting 1.3 and so the new 1.4 functions aren't available. 

 Also, would you mind giving the exact permutation of the build that is causing this error? I just want to see if it's also a problem in Spark 1.0 or if it's only in 0.9.
- If you build Spark with Maven, commons-codec 1.3 is included. If you build Spark with SBT, commons-codec 1.4 is included.
