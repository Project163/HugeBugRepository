Title

Call ExecutionContext.prepare in Action.apply

Description
Although deprecated, `ExecutionContext.prepare` is still used by some users to capture thread-local state when running actions. We should call `prepare` when running an `Action`. The following line needs to change:

[URL]

This fix for this is very easy, but to resolve this issue properly we should create an integration test that checks the Action's code runs in the correct thread pool. Maybe a new integration test like `ThreadPoolSpec` so that we don't clutter up the existing tests too much.

Note that for performance reasons the `mapFuture` call will only run in another thread when the `Action`'s `BodyParser` returns a `SinkAccumulator`, i.e. when the action is called with a streamed body. The integration test will need to take account of this. To use the correct thread pool when processing a strict body we'll need to fix another issue (which I will link to shortly).
