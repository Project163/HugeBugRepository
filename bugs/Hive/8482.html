Title

Literals in conjunction of two IN expression are considered not equals if type precision is different

Description
create table r_table (
  string_col varchar(30)
);

create table l_table (
  string_col varchar(14)
);

insert into r_table VALUES ( 'AAA111' );
insert into l_table VALUES ( 'AAA111' );
SELECT l_table.string_col from l_table, r_table
WHERE r_table.string_col = l_table.string_col AND l_table.string_col IN ( 'AAA111' ,  'BBB222' ) AND r_table.string_col IN ( 'AAA111' ,  'BBB222' );
 
  
 Should give one row 
  
 
AAA111
 
  
 but it returns empty rs 

 Workaround 
  
 
set hive.optimize.point.lookup= false ;
Discussion
- During planing  HivePointLookupOptimizerRule  receives an expression 
  
 
AND(IN($0, _UTF-16LE 'AAA111' :VARCHAR(30) CHARACTER SET  "UTF-16LE" , _UTF-16LE 'BBB222' :VARCHAR(30) CHARACTER SET  "UTF-16LE" ), IN($0, _UTF-16LE 'AAA111' :VARCHAR(14) CHARACTER SET  "UTF-16LE" , _UTF-16LE 'BBB222' :VARCHAR(14) CHARACTER SET  "UTF-16LE" ))
 
  
 The  IN  expressions has the same literals so the conjunction could be simplified to only one  IN  expression but the literals has different precision so they are not treated equal when collecting them for constructing the new  IN  expression.
