Title

Class names are not case sensitive on Mac OS X

Description
I cannot use a variable name that is the same as a class name, even if the case if different. For example, this will fail: 

 snap = new Snap() 

 with this error: 

 org.codehaus.groovy.syntax.SyntaxException: Cannot use a class expression on the left hand side of an assignment. 

 I believe this is because the default Mac OS file system supports mixed case filenames but file name searches are case insensitive. It appears that groovy searches the FS for a class that matches the token to determine if it is a class. But I think for Mac OS, even if it finds an FS match, it needs to do its own case sensitive comparison to determine if the token is indeed a class name.
Discussion
- I would like to up the priority on this to "Major", but I don't know how to edit the bug entry. This is major to me because it is very common in my code (and others I have seen) to have variables the same name as the class they are of, but with different case. For example: 

 repository = new Repository() 
version = new Version() 

 etc. 

 Java supports this, even on the case insensitive Mac FS, so I would like groovy to support this as well...
- I am attaching a patch for this bug. What it does is not use File.exists() because this does not do a case sensitive comparison when looking for files. So I get a list of files from the directory and then search the list using a case sensitive comparison. I have run all the tests and they pass. 

 This patch is on CVS head dated 05/12/2004.
