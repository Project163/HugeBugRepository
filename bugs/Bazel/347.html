Title

Insane(100%) consumption of resources

Description
I tried to build tensorflow source using bazel. I was assuming bazel would take care of parallelisation in a smart way by having a balance between performance and judicious usage. But it was using 100% of all the cores and 95% RAM. This is in no way a good approach. I had to hard boot the  system.

Under default cases, Bazel should use resources in more smarter way.
Discussion
- I've seen the same issue on my machine, building a large custom codebase.

The only solution I've found is to set the --jobs option to bazel to limit the number of parallel builds that it does.

Since my machine uses about 50% RAM under nomal operating conditions, and I wanted to leave some headroom, I tried setting `--ram_utilization_factor` to a lower number (20 or 30), but doing a build still results in 100% memory usage and swapping.

From reading the documentation, it seems like bazel should be estimating the memory usage of each build command and attempting to keep the overall memory usage below this value, but this doesn't appear to work for me.

This has also shown up on stack overflow, with similar results: [URL]

If it helps, the build that I'm doing is primarily large, heavily templated C++ code, where a single instance of the compiler or the linker can use multiple GB of RAM, on a machine that has 16GB of RAM.
