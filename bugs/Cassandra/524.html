Title

removetoken is broken

Description
When running removetoken on a dead node, it hangs forever.  The debug log shows: 

 DEBUG 19:45:53,794 Node /  ranges  [( , ] ] 
DEBUG 19:45:53,795 Range ( , ] will be responsibility of cassandra-1/  
DEBUG 19:45:53,798 Pending ranges: 
cassandra-1/ :( , ] 

 DEBUG 19:45:53,798 Node /  ranges  [( , ] ] 
DEBUG 19:45:53,799 Range ( , ] will be responsibility of cassandra-1/
Discussion
- So removetoken blocks for all new replicas to confirm they have the data for the node being removed.  You can actually run "removetoken status" to see which nodes are being waited on.  Since a dropped confirm message or stream request could cause it to block forever you can run "removetoken force" to finish a removal already in progress.   

 There could be a bug here as well or possibly a dropped message? 

 There should probably be new documentation about this in the wiki.
- My RF is 1, so there are no replicas to block for.  Here's the status output: 

 RemovalStatus: Removing token ( ). Waiting for replication confirmation from  [cassandra-1/ ] . 

 It seems to be waiting for confirmation from itself.

- When replication factor is 1 it is impossible to recover data so we shouldn't wait for confirmation.
