Title

auto-guessed memtable sizes are too high

Description
I've seen two cases now of the memtable sizes being too large, causing OOMing.  Too-small memtables hurt performance, but too-large hurts worse when you start GC storming.
Discussion
- I'd like to introduce a dependency on number of user CFs, but that's not available until after we've picked a value.  So this cuts the size by half, which feels scientific because on the old default 1GB heap size this gives us memtable throughput of 64MB, which is also the old default.
- Integrated in Cassandra #573 (See  [URL]
    reduce automaticallychosen memtablesizes by 50%
