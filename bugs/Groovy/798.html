Title

static foo(Closure) hides super.foo(Bar)

Description
Trying to implement a member function with the same name but different parameter signature and using super to call the parent's implementation is blocked by having a static method of the same name with a Closure parameter. 

 This may not be really about Closure and/or Script because a similar (but different) error if there is a static method with a different parameter type.
Discussion
- Ah, well the test works better when it doesn't have syntax errors. 

 Java does indeed allow static functions with the same name as a member in the parent (which is the way I thought it worked!).
- I would like to add that this issue is not really related to inheritance (static method hiding the parent class implementation). The StaticImportVisitor is not resolving the method call correctly. 

 The following code also fails: 
  
  class  SomeImplementorWithStatic{
     static   Object  build( String  c) { return  c}  //  if   this   static  method is present, calls made as "build(1),  this .build(1) fail
     void m(){
    	build(1)  //  this .build(1) also fails
     }
     public   Object  build( Integer  i) {println  "Call successful" }
}
 new  SomeImplementorWithStatic().m()
 
  

 The problem is caused by StaticImportVisitor.transformMethodCallExpression(). It checks if the current class has a possible static method, and if it does, it maps the method call to that function. The problem is that it goes only by method name and number of arguments. 

 So, in above case, during compilation process, it finds static method "build" with 1 argument and incorrectly maps the call "build(1)" to this static method. At run time the call fails because the type of argument is different.
