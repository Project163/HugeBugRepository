Title

Inputs aren't reset without at least one top-level field

Description
**Describe the bug**
Inputs aren't reset without at least one top-level field. So something like just `{ name: { first: "bill", last: "luo" } }` doesn't work while `{ name: { first: "bill", last: "luo" }, email: "test@test.com" }` does, at least if there's a corresponding ` ` element.

**To Reproduce**
Steps to reproduce the behavior:

1. Click the `reset` button and see the inputs being emptied because `reset( {} )` is called.
2. Refresh the sandbox.
3. Remove the `email` field from the form.
4. Click the `reset` button again and see that the inputs retain their value.

**Codesandbox link (Required)**
[URL]

**Expected behavior**
Even without a top-level field the inputs should be emptied when `reset( {} )` is called.

**Desktop (please complete the following information):**
- OS: macOS (but probably any)
- Browser: Chrome / Safari (but probably any)
- Version: latest

**Additional context**
[URL]
To reset the fields the `reset()` method loops over everything in `fieldsRef.current` to find a reference to an actual ` `. From there it finds the closest parent ` ` and resets that. But without at least one top-level field it won't find any ` ` and won't reset the inputs.

This could be solved by e.g.
- looping recursively through nested fields
- explicitly providing a `ref` that should be set on the ` `
- remembering a reference to the (first) closest parent ` ` when `registerFieldRef()` is called

The second option would be my preference because of its explicitness, but requires changes from anybody using this module. The first option is mostly like how it's currently done, but then I'd prefer the third option because it's much more concise. This would however make the assumption that the ` ` element doesn't change during the lifetime of the component, and I'm not sure if that's a reasonable one.

If you have any preference I'd be more than happy to work on a pull request.
