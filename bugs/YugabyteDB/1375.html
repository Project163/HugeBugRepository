Discussion
- For the seg fault issue, it happens when the following conditions are satisfied:
1. pk relation is partitioned, and its root and partition's columns orders are different.
2. fk's foreign key constraint uses DEFERRABLE INITIALLY DEFERRED.
3. Two tuples are inserted in batched fashion in fk.

```
CREATE TABLE pk(a INT, b INT, c INT, d INT, UNIQUE(a, c)) PARTITION BY RANGE(a);
CREATE TABLE pk_1_100(a INT NOT NULL, c INT NOT NULL, d INT, b INT);
ALTER TABLE pk ATTACH PARTITION pk_1_100 FOR VALUES FROM (1) TO (100);
CREATE TABLE fk(a INT, c INT, FOREIGN KEY (a, c) REFERENCES pk(a, c) DEFERRABLE INITIALLY DEFERRED);

INSERT INTO pk VALUES (1, 100, 20, 150), (1, 100, 21, 150);
INSERT INTO fk VALUES (1, 20), (1, 21);
```
- The TupleDesc reference leak happens when the following happens:

1. pk relation is partitioned, and its root and partition's columns orders are different.
2. FK relation is created without the foreign key constraint. Both pk and fk relations have some data such that all the fk rows have a matching pk row.
3. A foreign key constraint is created using ALTER TABLE.
