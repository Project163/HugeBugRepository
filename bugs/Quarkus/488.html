Title

build native via docker could have more informative error messages

Description
**Describe the bug**
Someone did the superhero workshop and kicked of native builds on windows via docker (`./mvnw package -Pnative -Dquarkus.native.container-build=true
`) for all 4-5 services exhausting his docker allocated resources.

For the user the experience was three very slow builds (10-20 minutes) and a fourth that errored with something the lines: "Docker build exited with exit code 137".

would be good if we recognized the exit code and was a bit more informative, somtehing like:

"Docker build exited with exit code 137. This indicates the build hit a memory or cpu resource limit. Ensure your docker environment have enough memory or cpu available"

That would have helped user to realize what he was actually doing by running these parallel builds.
Discussion
- We had two users asking the exact same thing yesterday and today. 

I’m wondering if it’s something we should get fixed in GraalVM instead?
- Its not really graalvm failing - it’s the container running out of memory causing docker containers/process to fail. 

Of course graalvm could probably add better out of memory handling but since we are the one starting docker and receiving the 137 error code; we are in the position to give a better/more informative error message.
