Title

vcpkg upgrade and modularized boost

Description
Since when `./vcpkg upgrade` has been introduced, I use it everytime. Most of the time, the `--no-dry-run` option is required. But one problem bothers me and just happened again: I will try my best to explain it. I think it's mostly related to modular boost anyway.
I have boost installed in 4 triplets variants (x86, x86-static, x64, x64-static). I just did `./vcpkg upgrade --no-dry-run` to update boost as per recent commit. But again (and it happens very often), after the upgrade, if I launch a `./vcpkg install boost boost:x86-windows-static boost:x64-windows boost:x64-windows-static` then `vcpkg`, instead of saying that they are already installed, notifies me that many `boost-...` packages have to be installed (not all of them but many, maybe all the ones that were not upgraded). This is again so strange, since boost should be already fully installed). And in fact during the install it's a flood of "File xxx was already present and will be overwritten".
Am I the only one to have this problem?

@cenit That definitely sounds like a bug -- you should ideally never get the "File xxx should be overwritten" except if a very, very, very rare race condition triggers with Ctrl-C.

Could you start backing up your `installed\vcpkg` folder before upgrading? This is the folder that contains the full "database" of installed information, such as what files belong to what and what packages are installed.

If you are able to reproduce strange behavior like this, please mail us the before/during/after at vcpkg@microsoft.com!
