Title

Kafka component shutdown may get stuck when rebalancing occurs

Description
Zulip chat thread  

 KafkaFetchRecords instance holds a reference to the Consumer from kafka-clients. When the rebalancing event occurs after the pause call has already been issued (as a part of doSuspend call in KafkaConsumer), the topic partition states which are held in the SubscriptionState object inside of kafka-clients Consumer instance are replaced by the new assignment and the pause flag is therefore lost. 

 Kafka component may then be stuck in accepting new messages (notifying about pending exchanges) instead of finishing current processing and completing the shutdown.
