Title

Too many branch commits on document node store

Description
The fix for   OAK-1056   introduced a regression which causes preliminary creation of the persisted branch instead of keeping changes in memory up to a certain size.  

 The problem is that transient changes are  purged  with every call to  NodeBuilder.getNodeState . That purge is what ultimately leads to the persisted branch being created.
Discussion
- The most visible symptom of this regression is the  DiffCache  not being properly populated, as per  mreutegg  branch commits do not go into that cache. Therefore for some observation scenarios the hit rate of this cache is as low as 5% but never higher than 50%.
- Patch that only does the purge when the underlying branch has already been created. This patch increases the hit rate of the case to >90%.
