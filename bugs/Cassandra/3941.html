- I've created a patch to ensure we update the in memory records after updating the disk state, to prevent the assertion in case we throw in  LifecycleTransaction.doCommit . However we still need to verify this is what actually happened in the logs. 

 I've also changed  LogTransaction.doCommit  and  doAbort  so that they catch and return runtime exceptions.  benedict  is this something we missed right?
- Yes, it looks like we did. This only matters for abort, since commit we want to throw either way - but we expect to do this in the caller ( LifecycleTransaction , so catching and returning them in both  is  most suitable. 

 Once things quiet down we should really try to introduce fault injection tests for this subsystem so we can easily cover this kind of scenario.
