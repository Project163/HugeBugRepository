Title

Some keys don't repeat

Description
I noticed if you hook up `glfwSetCharCallback` (or `glfwSetCharModsCallback`), then HOLD DOWN a letter key—"Q" for example—the callback only gets called once, and never repeats.

But if you hold down another key—let's say "E"—it DOES repeat, which I would expect to be the correct behavior.

The only pattern I can figure that determines which keys repeat and which don't is that keys that normally have a little diacritics popup (see picture) DO repeat, and keys that don't have that popup, don't repeat.

[Image: screen shot 2017-05-08 at 3 48 35 pm]

I tested on a couple computers (both on latest version of macOS Sierra) with the same results. I'll do a little more research, like if [Link: disabling that popup] changes this behavior.

It should also be noted that this only seems to affect `glfwSetCharCallback` and `glfwSetCharModsCallback`. `glfwSetKeyCallback` seems to function normally and repeats for all keys when held.

Test code:
```
// main.cpp
#include  
#include  

void charCallback(GLFWwindow * window, unsigned int codepoint, int mods) {
... [Log Snipped] ...
    return 0;
}
```

Built and run with:
`clang++ main.cpp -I . -L . -lglfw3 -framework Cocoa -framework IOKit -framework CoreVideo -framework OpenGL -o glfwbugtest && ./glfwbugtest`
Where the GLFW includes folder and libglfw3.a are in the same directory as main.cpp.
Discussion
- [Link: Disabling the diacritics popup] does indeed resolve the issue. Using the above code, all keys now call the callback repeatedly when held.

It's hardly a solution though, as only a fraction of a percent of people will have disabled the popup, and it's not even something you can do through standard settings.

This could be handled by GLFW by default, however I'm not sure if that would be desired or not?

Alternatively if you don't want to add any platform specific code, then you'll just need to avoid key callbacks. And instead manually poll the key states yourself.
