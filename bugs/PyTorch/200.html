Title

[ROCm][TunableOp] Simple matmul with TunableOp results in segfault

Description
### 🐛 Describe the bug

Running the example matmul with TunableOp enabled from the [Link: official AMD blog post] results in a segfault.

Code:

```
python
import torch

def time_matmul(M, N, K):
... [Log Snipped] ...

time_matmul(512, 1024, 2048)
```

Run with:
```shell
PYTORCH_TUNABLEOP_ENABLED=1 PYTORCH_TUNABLEOP_VERBOSE=1 PYTORCH_TUNABLEOP_FILENAME=matmul_result.csv python3 matmul.py
```

Tested on a 1x MI300X. The same code on NVIDIA works as expected.

Discussion
- We are working to investigate this issue. In the meantime, here is a workaround:
```
PYTORCH_TUNABLEOP_ROCBLAS_ENABLED=0
```
It will disable TunableOp tuning with rocBLAS, it will still tune with hipBLASLt.
- @nirw4nna Issue automatically closed when PR got merged. As a follow-up, I confirmed today that nightly wheels are back to normal and the simple matmul works. Let me know if you find otherwise.
