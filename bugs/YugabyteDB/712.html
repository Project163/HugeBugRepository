Title

IN query doesn't return the right values during overflows when search key exceeds numerical limits in a range split table

Description
Jira Link: [Link: DB-3095]
### Description

IN query does not return the right values when one element in the search key exceeds the numerical limit in a range split table.

Example: 
```
CREATE TABLE test (key smallint, val int, PRIMARY KEY(key ASC));
INSERT INTO test VALUES (1, 1);
INSERT INTO test VALUES (6, 6);
INSERT INTO test VALUES (11, 11);
INSERT INTO test VALUES (16, 16);
... [Log Snipped] ...
   6 |     6
(2 rows)
```

The docDB RPC that is sent for the following request  `SELECT * FROM test WHERE where key IN (1, 6, 40000);`
is as follows 

```
"I0801 09":"24":"49.351615 183961088 pg_session.cc":213
]"Applying operation":{
   "READ active":"1 read_time":{
      "read":"  local_limit":"  global_limit":"  in_txn_limit":"  serial_no":0
   }"request":"client":"YQL_CLIENT_PGSQL stmt_id":"4451389536 schema_version":0 targets{
... [Log Snipped] ...
   }"partition_key":"488000000121"
}
```

We can see that the value list for 40000 is -25536, which is the overflown value. There are two issues here.
1. We could avoid pushing it to docDB --> [Link: Issue 22974] is fixing that. But that works for only inequalities. Elements in a search array are part of equality conditions. Hence we have to deal with that in a different manner.
