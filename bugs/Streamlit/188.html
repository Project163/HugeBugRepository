Title

`st.image()` doesn't work with absolute local file-paths on Windows

Description
### Checklist

- [Link: X] I have searched the [existing issues] for similar issues.
- [X] I added a very descriptive title to this issue.
- [X] I have provided sufficient information below to help reproduce this issue.

### Summary

On Windows, when passing an absolute local file-path to `st.image()`, Streamlit does not display the image.

### Reproducible Code Example

```
Python
# Note that this script assumes an image called "image.jpg" is located in 
#  the same directory as this script

from pathlib import Path
... [Log Snipped] ...
image_path = Path(__file__).with_name("image.jpg")
st.image(str(image_path))
```

### Steps To Reproduce

1. Run a Streamlit application on Windows like the above code example
2. Open page on Streamlit

### Expected Behavior

Image is displayed, e.g.:

[Image: image]

### Current Behavior

Image is not displayed, only alt text is:

[Image: image]

### Is this a regression?

- [ ] Yes, this used to work in a previous version.

### Debug info

- Streamlit version: 1.26.0
- Python version: 3.10.12
- Operating System: Windows
- Browser: Edge/Chrome/Firefox (all affected)

### Additional Information

This is likely to be the same issue as #3698, which was closed for inactivity.

I believe the root cause of this issue is in `streamlit.elements.image.image_to_url()`. Specifically, the function tries to detect whether the input string is a URL or path to a local file. It does this by passing the string to `urllib.parse.urlparse()` and checking the `scheme` attribute:

