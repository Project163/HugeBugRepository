Title

Always return primary key?

Description
I am using UUIDs as the primary key on my tables, and one of the issues I am running into is that my entities are not populated with the primary key after I persist them.  I am using a default value of `uuid_generate_v4` to populate the primary key automatically in Postgres, but `{generate: true}` is not passed into my decorator, and the query runner checks for columns that are generated to pass into the `RETURNING` clause, so my primary key value is not coming back.

My primary keys look like this `@PrimaryColumn({type: "uuid", default: () => 'uuid_generate_v4()'})`.  Instead of checking for generated columns, perhaps we could always return the primary key?  Or, alternatively, we could check for columns that have a function type as the default value?  I'm happy to work on this, if so.
