lead to a regression in ControllerTestCase.

This worked before in 2.5:

```
$options = array(
        'method' => 'post',
        'return' => 'vars',
        'data' => array(
            'api_key' => 'Lorem ipsum dolor sit amet',
... [Log Snipped] ...
    );
    $this->assertEquals($expected, $result['response']);
```

Now it fails with `Undefined index: response` as the $result array is always an empty array.
Discussion
- Does the URL go to a valid controller action?
- No, it looks for a `APP\Plugin\Api\webroot\v1\forwarding.json` file. Which should just be a normal plugin controller action.

Maybe one could add `public $throwException = false` and enable it this way if desired. But that also just calls for trouble.
Right now I don't see a way that would not mean reverting this whole patch.

@zoghal You can make your own Dispatching filter and probably just overwrite `public function beforeDispatch(CakeEvent $event)` to get your expected behavior. Even thought it would have the same limitations.
- ... [Middle Discussions Snipped for Brevity] ...
- Adding any overhead to all requests just to make pages with broken asset urls load faster is unacceptable in my book. There are already multiple ways to avoid the issue:
- Don't have broken url in your pages
- Use your own dispatch filter
- Move all plugin assets to app's webroot and add rewrite urls to prevent requests for assets being routed to cake.

@dereuromark Can you please PR the test case you have provided. After that patch merged in #2750 should be reverted.
- The only option I see is to check for the list of extensions used in Router::parseExtensions() and if the current extension is not part of that list, it will probably be not a valid routed controller/action extension and thus can be seen as potential webroot asset in the plugin.

``` php
$extension = pathinfo($url, PATHINFO_EXTENSION);
if (!in_array($extension, Router::extensions()) && !file_exists($assetFile)) {
}
```

The advantage would be to skip the costly file_exists() invocation for all valid extensions.
Making this patch actually "faster" again - which was the original aim of it.
