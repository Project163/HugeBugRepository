Title

ngc's flatModuleOutFile metadata does not preserve html/css paths

Description
**I'm submitting a ...**  (check one with "x")
```
[x] bug report => search github for a similar issue or PR before submitting
[ ] feature request
[ ] support request => Please do not submit support request here, instead see [URL]
```

**Current behavior**
 
Compiling using `ngc` and with `flatModuleOutFile` produces a `*.metadata.json` file with flattened html/css paths.

Example:
```
// ...
"arguments": [
  {
    "selector": "my-lib",
    "templateUrl": "./lib.component.html",
... [Log Snipped] ...
]
// ...
```
**Expected behavior**
 
Paths to html/css should be resolved to the original path. Notice `./lib/...`:
```
// ...
"arguments": [
  {
    "selector": "my-lib",
    "templateUrl": "./lib/lib.component.html",
... [Log Snipped] ...
]
// ...
```

**Minimal reproduction of the problem with instructions**
 
```
git clone [URL]
cd ngc-flatmodule-windows
npm run build
```

**What is the motivation / use case for changing the behavior?**
 
Library authors should not have to copy all html/css to the root `typings/` folder instead of maintaining the library structure.

Flattening the html/css paths to root also forces library authors to avoid duplicate html/css filenames.
