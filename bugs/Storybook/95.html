Title

A11y addon ignores inherited parameters

Description
**Describe the bug**
A11y addon only takes into account own story parameters, not the inherited ones

**To Reproduce**
- Apply following patch:
```
patch
 UTF-8
===================================================================
--- examples/official-storybook/preview.js	(revision  )
+++ examples/official-storybook/preview.js	(date 1594337200567)
... [Log Snipped] ...
       restoreScroll: true,
     },
```
- run `yarn start`
- go to `[URL] switch to accessibility tab

**Expected behavior**
No violations reported, because `color-contrast` rule should be disabled.

It works correctly if I define the parameter on story level, but doesn't if I do it on kind or global level

- @tooppaaa - I dug into this issue a bit and the immediate bug is due to this line:

[URL]

Accessing both the variable on `window`, and specifically the private member (`_stories`) is not a great idea! 

The simplest fix is to just use `fromId`: [URL] -- this does resolve @Hypnosphi's issue but I took at look at the PR that change came from: [URL] and I'm sort of wondering what's going on here in the first place.

It seems like we are getting the parameters in this non-standard "anti-pattern" kind of way because we are avoiding using a decorator (the PR itself says "issue: a11y use decorator"). I'm not sure what the rationale for that is? Is it to avoid the user having to add a decorator?

If so, it would be better to just add the decorator directly by exporting it on the `decorators` key from one of the `config` entries you've added (you could export directly from that file, `a11yRunner.ts` for instance). It seems like the previous approach of using a decorator to keep track of the current story, but only running axe when receiving an event was more idiomatic and "correct" than digging into the `window.__STORYBOOK_STORY_STORE__` global variable which was only added for external tools (like Chromatic) that run outside SB.

Is there something I'm missing here?
