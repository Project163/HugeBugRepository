 [URL]

 I think it smells like a little bug, and a potential fix is to check if that absolutePath is empty and if so omit appending the slash.
- It seems that the 'stepwise=false' attribute is causing the problem.  When it is set to false and no base path is provided in the endpoint URI ( ftp://ZZZ@XXX:YYY?password ...) the absolute paths used in the listFiles method are generated with the '/' prefix ('/mock/foo'), but if a base path is defined in the URI ( ftp://ZZZ@XXX:YYY/bar?password ...)  the resulting absolute paths do not have this prefix ('bar/mock/foo'). 

 However, the issue depends of the server implementation since I tested with the embedded FTP server used in the tests and the files were returned normally using the absolute paths containing the prefix '/'.
