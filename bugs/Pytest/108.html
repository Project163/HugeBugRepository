Title

teardown_function() with no argument list crashes

Description
- [x] Include a detailed description of the bug or suggestion

These functions appear to work even if someone forgets to list the module/function argument:
- setup_module()
- teardown_module()
- setup_function()

However, this crashes:
- teardown_function()

Example file test_foo.py, listing at end.

```
 
E   TypeError: teardown_function() takes no arguments (1 given)
 
```

Suggestion. look at how setup/teardown module and setup_function are handled, because they don't crash.
- [ ] `pip list` of the virtual environment you are using

Currently looking at an anaconda install, and the list is huge.
- [x] py.test and operating system versions

However, I've tried it with Python 3.5.2 and most recent pytest on a mac without anaconda, and that's broken too.
- [x] Minimal example if possible

test_foo.py:

``` python
from __future__ import print_function

def test_something():
    print('\nIn test_something()')

def teardown_function():
    print('\nIn teardown_function()')
```

Hmm I made some other tests, and it seems there's some inconsistency, because `setup_module` and `teardown_module` can receive or not the `module` argument, while `*_method` and `*_function` must always receive it.

So it seems the problem is actually that `*_module` and `*_function/*_method` behave differently: the former can receive or not an object, while the latter ones must always receive an object.
