I don't know if it causes unknown type name 'size_t'.

Bazel patches legacy crosstools by [URL] I think that's where the flags come from. Unless you have a custom crosstool that defines feature named 'no_legacy_features'. Let me know if you do.

C++ rules unconditionally generate .d file (last time I checked it was not trivial to turn it off) and use the information to speed up the build (by not rebuilding targets that don't really use the changed dependency).

I've no idea why the error is tracked back to bazel-out/host/bin/sysdb/bgen/src/bgen_lex.c.temp, you can investigate by running bazel with `--subcommands`, then observing the commands bazel generates, `cd`-ing into the sandbox, and running the command manually. That's how I debug similar issues.
