Title

Migrate tool passing unescaped shell commands?

Description
### Describe the bug

Thank you for providing the migrate tool, I'm excited about the new routing strategy.

Migrating a project that reproduces some internet archive URLs that include the character "$" in them, I noticed that if a route path in the old format includes special characters, something odd happens that could looks like it could conceivably involve unescaped shell commands. I don't know how the large the scope is, but this seems like the sort of thing that could cause issues if someone has a route at `src/routes/page$[rm -rf /]` or possibly something remotely plausible.

I had a route at `src/routes/pages/[id]$[pagenum]/index.svelte`. (The format with `$` reproduces Internet Archive URLs).
Migrating throws an error `Command failed: git mv "src/routes/pages/[Link: id]$[pagenum]/index.svelte"`  because `fatal: bad source, source=src/routes/pages/[id]0/index.svelte, destination=src/routes/pages/[id]0/+page.svelte`.  That is, the dollar sign triggers an [old bash syntax] I've never heard of where `$[foo]` evaluates to '0'. Not the end of the world for me, but this seems like the sort of thing that in rare edge cases might be able cause some havoc on someone's machine, so I wanted to bring it to your attention.

### Reproduction

Create a path at `src/routes/pages/[id]$[pagenum]/index.svelte` in an old sveltekit project, and run npx svelte-migrate routes 

Sorry for not providing a full reprex, which is tricky because it requires forking an old thing.
