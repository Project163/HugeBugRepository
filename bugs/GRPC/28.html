Discussion
- I don't think the ASAN failure shown above is actually caused by the retry timer, for two reasons.  First, the test failure is occurring in the ALTS handshaker test, and I don't think the ALTS handshaker enables retries.  And second, if you look at the ASAN trace in detail, it doesn't look like the stack is actually coming from the retry timer -- if it were, it would have `PickSubchannel()` in the stack trace, not just `PickSubchannelLocked()`, but I see only the latter.

If you look at the specific line number it's pointing to in `PickSubchannelLocked()`, it's here:

[URL]

I think this is actually coming from the code we added to bounce into the ExecCtx inside of `PickSubchannelLocked()`.  I think that all we need to do is to hold a ref to the channel stack for that callback.
