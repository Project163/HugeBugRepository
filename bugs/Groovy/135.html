Title

Unable to invoke method on BuilderClassSupport subclasses

Description
A class that extends BuilderClassSupport and that is defined in a groovy script cannot invoke any method on itself in the createNode(...) methods because the method invokation will be intercepted. I don't know, how this could be fixed. 

 This is highly desireable, though.
Discussion
- Philipp, that's the principle of BuilderSupport, all invokations go through the createNode() methods. It's not a limitation. If you want to call a method defined in your class extending BuilderSupport, you should check in createNode() that the method called is the one defined in your object, then delegate it yourself to your object's method.
- Guillaume, I think I did not understand exactly how to achive what you suggested. I did create a BuilderClass that has a private method foo() which is I wanted to call from the diverse createNode(...) methods. But the method call on foo what "routed" through the createNode methods again. I did look into BuilderSupport and came to the conclusion that  every  invocation on a method of the Builder is intercepted. 

 Perhaps you can enlight me with a short example or better add an example to the groovy documentation. The existing example in the docs that logs the methods calls does not call methods on itself.
- Philipp, it's now possible to write your builders in Groovy and call normal methods, without createNode() always intercepting all method calls. I've added a test case which shows that, it's in groovy-core/src/test/groovy/bug/InvokeNormalMethodFromBuilder_Bug657. 
The fix was done thanks to   GROOVY-677   I commited yesterday.
