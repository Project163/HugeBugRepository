Title

Cookies for paths that are no prefix of the uri path are rejected (using CookieSpec Standard)

Description
Using CookieSpec Standard if a response to a http request to  [URL] contains a cookie for the path /def this cookie is rejected by httpclient. This is the correct behavior in case of  RFC 2109  (cf.   HTTPCLIENT-1043  ). But  RFC 6265  (as far as I know) does not state that a cookie path must be a prefix of the request uri path. In 8.6 it is even mentioned as a "security problem" that 'an HTTP response to a request for  [URL] can set a cookie with a Path attribute of "/qux"'. 

 I know that I can workaround my problem by using a custom cookie policy. I just wondered if this behavior of httpclient is correct with respect to RFC 6265. 

 cf.  [URL]
