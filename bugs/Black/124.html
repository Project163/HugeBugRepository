Title

error on windows directory junctions

Description
**Describe the bug**

If a windows directory junction is found while crawling a source root, and it points outside of the source root, then black will error.  This happens even if the directory should be ignored!

**To Reproduce**

1. Start a windows cmd prompt
1. `mkdir source_root`
1. `cd source_root`
1. `mkdir .git`
1. `mklink /J dir_junction ..`
1. `python -m black --exclude dir_junction .`

Then you get this error:

```
Traceback (most recent call last):
  File "C:\python\lib\runpy.py", line 193, in _run_module_as_main
    "__main__", mod_spec)
  File "C:\python\lib\runpy.py", line 85, in _run_code
    exec(code, run_globals)
... [Log Snipped] ...
    .format(str(self), str(formatted)))
ValueError: 'C:\\Users\\TheUser' does not start with 'C:\\Users\\TheUser\\source_root'
```

**Expected behavior**

A directory we've explicitly told to ignore should be ignored!

**Environment (please complete the following information):**

- Version: 21.9b0
- OS and Python version: Windows / Python 3.7

**Does this bug also happen on main?**

Based on inspection of source, yes (see below)

**Additional context**

The error happens because in [Link: this line], it calls `.resolve().relative_to(root)`:

```
        normalized_path = abspath.resolve().relative_to(root).as_posix()
```

It seems windows directory junctions WILL have their linked path calculated by `resolve()` - however, this then triggers a ValueError, since it's not relative to `root` - this should be caught [Link: here]:

```

```
