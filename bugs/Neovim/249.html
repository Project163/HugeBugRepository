Title

Assigning $HOME from lua or setenv() does not work

Description
### Neovim version (nvim -v)

v0.6.1

### Vim (not Nvim) behaves the same?

~Not applicable; vim does not have lua~ Yes

### Operating system/version

Arch Linux (5.16.9-arch1-1)

### Terminal name/version

MATE Terminal (1.26.0-1)

### $TERM environment variable

xterm-256color

### Installation

`pacman -S neovim`

### How to reproduce the issue

```
vim
:echo expand("~")
/home/xxx

:let $HOME = "1"
... [Log Snipped] ...
:echo expand("~")
1
```

### Expected behavior

All three assignments should have the same effect.

### Actual behavior

Only the `let $HOME` variant affects functions such as `expand`. (`echo $HOME` is affected however.)

`let $HOME` is [Link: special-cased] to update a few internal cache variables, but the other methods [Link: are not] (didn't find where the lua one is implemented).
Discussion
- For the `setenv()` case, Vim behaves the same. `vim.env` is just a wrapper around `getenv()` and `setenv()`.
