Title

charmods callback not called in multi-window application

Description
1. use the code below
2. click on window 1
3. type a few characters
4. notice that nothing is printed to stderr - this is unexpected
5. click on window 2
6. type a few characters
7. notice that window 2 got charmod callbacks - this is expected

```
c
#include  
#include  

static void charmods_callback(GLFWwindow* window, unsigned int codepoint, int mods) {
... [Log Snipped] ...
        glfwWaitEvents();
}
```

Other callbacks, such as close, cursor pos, window size, etc., work fine for each window.

My system is:
- Ubuntu 14.10 Utopic Unicorn
- XFCE 4.10.1
Discussion
- in x11_window.c:

``` c
                if (XFilterEvent(event, None))
                {
                    // Discard intermediary (dead key) events for character input
                    break;
                }
```

In the window where the charmod callbacks are getting called, `XFilterEvent` is returning false; in the window where the charmod callbacks are not getting called but they should be, `XFilterEvent` is returning true and the event is discarded as a dead key.

I'm not sure how to resolve this.
- If I simply remove this `XFilterEvent` check, the problem goes away. What's the point of that function call?

Further, if I create many windows and attach listeners for all of them, only the callbacks for the last window created get fired. Perhaps in the X11 API you are supposed to tell it when a window is activated, so `XFilterEvent` returns false for that window's events?
- An easy way to test this and similar issues is `events -n2`.
