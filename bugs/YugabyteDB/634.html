Title

[ysql] [Bulk load] Index backfilling fails with timedout error after 3600secs.

Description
Jira Link: [Link: DB-489]
### Description

Data was loaded from a 200GB csv data in a table with primary key, the tablesize(from platform UI tables tab) was ~695GB. When we try to create an index on this table, we get a timedout error after 3600 seconds. This is observed in transactional mode. (yb_disable_transactional_writes=false)
The was observed on 8-core 3node universe.
YB version :  -b32

Error message : 
```
CREATE INDEX idx1 on orders(col1);
ERROR:  Timed out: BackfillIndex RPC (request call id 306682) to  :9100 timed out after 3600.000s
Time: 3602379.812 ms (01:00:02.380)
```

Script : 
```
\timing
SET ysql_max_in_flight_ops=20000;
SET ysql_session_max_batch_size=2000;

drop table if exists orders;
... [Log Snipped] ...
select (pg_sleep(300));
CREATE INDEX idx2 on orders(col2);
```

Test environment : 
```
GFlags:
Tablet-spliting enabled 
max_packed_row_columns=1000
Session setting :
set ysql_max_in_flight_ops=20000;
set ysql_session_max_batch_size = 2000;

ROWS_PER_TRANSACTION 20000 (COPY command)
```
Discussion
- backfill_index_client_rpc_timeout_ms needs to be increased. This defaults to 3600s

[URL]
- We will increase the backfill timeout to one week = 604800 == 7 days
- Need to backport to 2.15.0 branch too. @jasonyb
- We refrained from increasing the default to 7 days but rather increased the default to 1 day.
