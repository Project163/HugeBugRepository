 curl  'http: // :4504/system/console/bundles'  -H  'Pragma: no-cache'  -H  'DNT: 1'  -H  'Accept-Encoding: gzip, deflate, sdch'  -H  'Accept-Language: en-US,en;q=0.8,fr;q=0.6'  -H  'Upgrade-Insecure-Requests: 1'  -H  'User-Agent: Mozilla/5.0 (Macintosh; Intel Mac OS X 10_9_5) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/51.0.2704.79 Safari/537.36'  -H  'Accept: text/html,application/xhtml+xml,application/xml;q=0.9,image/webp,*/*;q=0.8'  -H  'Cache-Control: no-cache'  -H  'Authorization: Basic YWRtaW46YWRtaW4='  -H  'Connection: keep-alive'  --compressed 
 
  

 and the same request with added cookie succeeds 
  
 curl  'http: // :4504/system/console/bundles'  -H  'Pragma: no-cache'  -H  'DNT: 1'  -H  'Accept-Encoding: gzip, deflate, sdch'  -H  'Accept-Language: en-US,en;q=0.8,fr;q=0.6'  -H  'Upgrade-Insecure-Requests: 1'  -H  'User-Agent: Mozilla/5.0 (Macintosh; Intel Mac OS X 10_9_5) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/51.0.2704.79 Safari/537.36'  -H  'Accept: text/html,application/xhtml+xml,application/xml;q=0.9,image/webp,*/*;q=0.8'  -H  'Cache-Control: no-cache'  -H  'Authorization: Basic YWRtaW46YWRtaW4='  -H  'Connection: keep-alive'  -H  'Cookie: felix-webconsole-locale=en'  --compressed 
 
  

 Debugging it, the NPE is thrown at 

  [URL]

 with the method call 

  
 locale.toString()
 
  

 indeed, the  locale  is  null  at that point.
- This is not a bug in the web console, a fallback in the  code is using request.getLocale() which must not return NULL. 
So it seems there is a faulty request implementation that returns null. 
We could add a workround in the web console to avoid an NPE, but still the real bug is somewhere else
