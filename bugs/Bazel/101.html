Title

Bazel sometimes hangs waiting for server response after update

Description
Since updating Bazel I now get occasional hangs when running commands, with output like this:

```
# bazel test //mytarget
INFO: Waiting for response from Bazel server (pid 13373)...
^C
Bazel caught interrupt signal; shutting down.

... [Log Snipped] ...
^C
Bazel caught third interrupt signal; killed.
```

It'll hang for multiple minutes if I don't kill it. This happens maybe about 10% of the time, and usually goes away if I try it again after killing (though sometimes it takes several tries). Multiple people on my team have seen this, on both Linux and Mac.

Another oddity that may or may not be related is that "INFO:" in the output above is printed in white; every other time I've seen it it's been green
Discussion
- The info line comes from the client, which isn't using color codes when printing it. Only the server is using color codes. It's unrelated.

If this happens, try getting a stack trace from the Java VM with "jstack  ".
- I've seen this happen when a child process running under Bazel doesn't close stderr.  See [URL]  It sounds crazy, I know--and of course it may not be the same issue.
- It stopped for a bit, but now it's back and I have some stack traces. A lot of threads look like they're blocked on socket connections to bazel dash (I have `--dash_url` set), perhaps connecting to dash isn't timing out properly?

```

   java.lang.Thread.State: RUNNABLE
... [Log Snipped] ...

```
- That sounds very likely.  I'll take a look.
