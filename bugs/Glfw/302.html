Title

Disabled cursor mode doesn't work right when connected over RDP

Description
OS and version: Windows 10 64-bit
Release or commit: Tested both   and the version comes with LWJGL 3.1.2 (  it seems)

When connected over RDP, disabled cursor input doesn't work correctly; the cursor goes far off the screen (causing rapid rotation if mouse input is being used for that -- e.g. the `wave` example program).  (This was originally reported as [Link: MC-126875]).

To reproduce:

0. Set up and build the `cursor` test.  Enable RDP connections to your machine.
1. Connect to a machine from another machine, and start the `cursor` test.
2. Press  T  to enable tracking of the cursor.
3. Move the cursor around some.  Note that everything is fine.
4. Press  D  to switch to disabled cursor move.
5. Move the cursor.  The tracking lines should disappear and the cursor's position in the logs will be said to be far off the screen.

This doesn't happen when connected locally.

Discussion
- After some further testing, there are two issues.  One is that `MOUSE_VIRTUAL_DESKTOP` is weird, but that's not all.  I've implemented the same thing from the DirectXTK commit (Pokechu22@92380fa), but that doesn't actually work right.  The cursor moves fine for a bit, but when it gets to the edge of the monitor, it stops.

It seems that `SetCursorPos` doesn't work right when the cursor is hidden via `SetCursor(NULL)`, so the re-centering logic isn't working.  I've verified that by adding another key to the cursor test (this is not in the previously linked commit):

```C
        case GLFW_KEY_M:
        {
            int width, height;
            glfwGetWindowSize(window, &width, &height);
            glfwSetCursorPos(window, width / 2, height / 2);
            break;
        }
```

When the cursor is visible, it moves back to the center and moving it around starts from the center.  However, when it is hidden (_not_ disabled), the tracking lines move to the center but the actual cursor does not.  I suspect that this is a special behavior for the `NULL` cursor, and will try using an invisible custom cursor instead.
