Title

Surefire - NPE at end of successful test run

Description
While using surefire to run a mock test pack all tests are passed, followed by an exception in the surefire plugin (NPE) at the end which causes the run to be marked as a failure. 

 I've tried various surefire versions of surefire and other testing libraries involved.  

 I have attached a stack trace of the exception in question and a copy of the test profile xml.
Discussion
- The only thing which can throw NPE on that line is  this instance of RunOrderCalculator  

 This is the  only implementation  of the provider, and the return is indeed nullable. 

 This null check seems spurious. It checks directoryScannerParameters, but doesn't use it for anything. Seems like it should be checking runOrderParameters. When it was  originally introduced,  this check made sense, but  a subsequent change to support parallelizing tests  seemed to break it. 

 As a workaround, the reason directoryScannerParameters is null stems from the fact that  you are using suiteXmlFiles , so maybe you can find an alternative way to configure your tests, while avoiding using that.
- thanks very much for the quick and well definitive answer, will look to work around it like you say
- I'm going to submit a PR to fix that, but it seems like another reason you're seeing this issue is that you're mixing Junit and TestNG. Are you expecting that? 

 If you run Maven with debug logging (-X) you should see some line beginning with "Using the provider <some class>". All the above code I contained within a JUnit provider, but I can see from your profile that you're including TestNG too.
