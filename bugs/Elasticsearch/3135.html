Title

[ES|QL] date_parse seems to ignore timezone

Description
### Elasticsearch Version

8.16.0

### Installed Plugins

_No response_

### Java Version

_bundled_

### OS Version

Linux amd64 5.15.0-1032-gcp

### Problem Description

```
POST /_query
{
    "query": """
row message = "  - - [12/Jul/2022:10:24:10 +0900] \"GET /cgi-bin/try/ HTTP/1.0\" 200 3005"
| grok message "%{COMMONAPACHELOG}"
... [Log Snipped] ...
"""
}
```
produces
```
{
  "took": 15,
  "columns": [
    {
      "name": "timestamp",
... [Log Snipped] ...
  ]
}
```

but 
```
POST /_ingest/pipeline/_simulate
{
  "pipeline": {
    "processors": [
      {
... [Log Snipped] ...
  ]
}
```
produces
```
{
  "docs": [
    {
      "doc": {
        "_index": "index",
... [Log Snipped] ...
  ]
}
```

I suspect `date_parse` in ES|QL ignores the timezone offset. Will you look into it, please?

### Steps to Reproduce

You can run
```
POST /_query
{
    "query": """
row message = "  - - [12/Jul/2022:10:24:10 +0900] \"GET /cgi-bin/try/ HTTP/1.0\" 200 3005"
| grok message "%{COMMONAPACHELOG}"
... [Log Snipped] ...
"""
}
```
, which produces
```
{
  "took": 15,
  "columns": [
    {
      "name": "timestamp",
... [Log Snipped] ...
  ]
}
```

I think `@timestamp` should be "2022-07-12T01:24:10.000Z".
