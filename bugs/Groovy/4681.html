Title

@ClosureParams for StringGroovyMethods.replaceFirst and StringGroovyMethods.replaceAll wrong

Description
The  @ClosureParams  for  StringGroovyMethods.replaceFirst  and  StringGroovyMethods.replaceAll  seems to be wrong. It says  ​{"List<String>", "String[]"}​ , so without static compilation IntelliJ shows a warning and with static compilation an error for the  String it  parts of 
  
 
 def  pascalCasedWorkflowName = workflowName
    .replaceAll(/-\w/) {  String  it -> it[1].toUpperCase() }
    .replaceFirst(/^\w/) {  String  it -> it[0].toUpperCase() }
 
  
 while it compiles and works perfectly fine. I'd guess it should be  ​{"String", "List<String>", "String[]"}​
Discussion
- When a closure is called with an array or iterable, the elements can be spread over the params. I think that is what’s happening in your case.
- Ah, right, so it is an IntelliJ bug instead, that it does not recognize the spreading, right? Sorry.
- ... [Middle Discussions Snipped for Brevity] ...
- "String[]" should act like varargs, at least it used to, so "String" should be covered. 
The "Object[]" is mainly to handle the dynamic default multiple args case with something like: 
  
 
replaceAll(/-(\w)/) { all, w -> w.toUpperCase() }
 
  
 We should probably just check for String[] as well as Object[] in getReplacement.
- I managed to find how the runtime does this.  In  ClosureMetaClass#invokeMethod  there is a fallback if the arguments cannot be matched to a  doCall  signature.  If there is one list argument, the runtime gets the length and tries that.  I am fixing STC to account for this and to stop thinking that arrays have this behavior.  See   GROOVY-11089   

 So the examples will type-check and execute: 
  
 
workflowName.replaceAll(/-\w/) {  String  s -> s[1].toUpperCase() }
