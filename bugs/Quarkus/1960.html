Title

swagger-ui endpoint is traced by OTel

Description
### Describe the bug

By default, `quarkus-opentelemetry` does not trace non-application endpoints, unless this is explicitly enabled (`quarkus.otel.traces.suppress-non-application-uris=false`)

`quarkus-smallrye-openapi` has 2 non-application endpoints:
- `/q/openapi`
- `/q/swagger-ui/`

While `/q/openapi` is by default not traced, `/q/swagger-ui/` is.

Btw. `/q/swagger-ui/` is only included in dev mode, unless stated otherwise (`quarkus.swagger-ui.always-include=true`), so maybe the tracing is intentional?

### Expected behavior

No tracing of `/q/swagger-ui/` endpoint by default.

### Actual behavior

`/q/swagger-ui/` endpoint is traced regardless of `quarkus.otel.traces.suppress-non-application-uris`, just like a regular application endpoint.

### How to Reproduce?

```
git clone [URL] -b swagger-ui-otel
mvn -f ./reproducers clean verify
```
