Title

DelayedCachedOutputStreamCleaner may expire streams prematurely

Description
See please  [URL]
Discussion
- Thank you for looking into the issue. I have looked at the pull request #2317, and I have a question. 
In CXF there is only single instance Timer "DelayedCachedOutputStreamCleaner" in an application from what I now see. 

 The single instance Timer is triggered at fixed interval, and it calls the clean() method, and that calls close() for all.  

 A new young Closeable in a CachedOutputStream that is just registered before the Timer is triggered, would be prematurely closed, don't you think?   

   
  
 
 private  void clean(Collection<DelayedCloseable> closeables) {
   while  (iterator.hasNext()) {
     final  DelayedCloseable next = iterator.next();
     // ...
     next.closeable.close();
  }
}
- Thank you  ralphb  , I think this assumption: 

 > The single instance Timer is triggered at fixed interval, and it calls the clean() method, and that calls close() for all.  

 Is not strictly correct: the clean(...) will be called only for the  Closeable s that are expired. So no, the newly registered  Closeable  will not be prematurely expired (timer runs at 0.5 of configured expiration delay). Thank you.
- You are right Andriy. I had overlooked that the  queue  is a java.util.concurrent.DelayQueue. And queue.drainTo(closeables) only returns the expired Closeables. The junit tests helped to prove it. Thank you.
