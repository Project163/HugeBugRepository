Title

Metadata recovery times out when the metadata size is too large

Description

    
Discussion

    
- Root Cause 

 The metadata recovery process is divided into several steps, wrapped in a large Transaction:   
 
	 Traverse `resourceUrl`, write to the database, and update the cache.   
	 After the Transaction commit, there is a follow-up `endTransaction` operation:  
	 
		 Record the audit log of this transaction and write it to the `auditLog` table.   
		 Replay the audit log for upsert or delete operations.   
	 
	 
 

 Due to the default timeout mechanism of `kylin.metadata.audit-log.catchup-max-timeout=60s`, replaying the audit log will time out when the metadata being restored is too large.
- Dev Design 

 During the metadata recovery process, skip the AuditLog replay phase when executing transactions. That is, the metadata recovery operation will not write to the `auditLog` table.
