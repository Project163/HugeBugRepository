Title

ssh.forward_agent = true not evaluated when vm.guest = windows

Description
### Vagrant version

Observed on 1.8.1 and 1.7.4, however ssh.forward_agent works properly on 1.6.5
### Host operating system

OSX El Capitan
### Guest operating system

Windows 2012R2
### Vagrantfile

```
ruby
Vagrant.configure("2") do |c|
  c.ssh.forward_agent = true
  c.ssh.insert_key = false
  c.vm.define 'win-2012R2-std' do |v|
... [Log Snipped] ...
  end
end
```

### Expected behavior

SSH should have been forwarded appropriately. 
### Actual behavior

SSH is not forwarded on most recent releases. However SSH is forwarded appropriately when guest os type != windows
### Steps to reproduce
1. configure windows guest os vagrant file, enable ssh.forward_agent, 
2. vagrant up
Discussion
- Tracked down a previous discussion around this issue, it appears that the default communicator was set to :winrm when os is windows, in a previous commit an IF excluded ssh forwarding thus breaking ssh on windows (a requirement for puppetlabs-beaker) this break was fixed in 1.6.5 (discussion here: [URL] 

Unfortunately the bad behavior was reintroduced again with this commit: [URL]

Versions Effected: 1.6.2, 1.6.3, 1.6.4, >= 1.7.3
Versions Not Effected <= 1.6.1, 1.6.5, 1.7.0, 1.7.1, 1.7.2
