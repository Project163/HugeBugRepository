Title

[DocDB] Fix TransactonParticipant Poller deadlock

Description
Jira Link: [Link: DB-5245]
### Description

In a recent incident, we uncovered a deadlock on the master side. From the raft perspective, the masters were able to elect a leader. However, once elected leader, the CatalogManager component needs to go through a Loading phase, before it can start serving RPC traffic. As part of the Loader code, we can sometimes execute some migration code, if we detect inconsistencies for the on disk data.

One example of such inconsistency would be a crash during a DROP TABLE command. We might have persisted a change to the TableInfo objects to move to DELETING state, but then crashed before persisting the changes to the constituent tablets, to also move them to DELETED state. Then on the new master leader, we would try to migrate the tablets forward to the DELETED state.

This lead to the following deadlock
- Thread1: TabletLoader code triggering a state transition write
