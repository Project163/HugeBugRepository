Discussion
- Both sequences and column aliases are restricted by `NAMEDATALEN` right?

This is a problem that also exists in Oracle, which is limited to 32 characters for identifiers.

Really there needs to be a global solution for shortening identifiers, either through the naming strategy where users could do a more advanced truncation (e.g. remove vowels first, shorten common phrases) or a common hashing system.
- Yes all identifiers are restricted, in the case of PostgreSQL this is by NAMEDATALEN.

There is a global solution introduced in [URL] where table names and column aliases are checked (although imperfectly in corner cases #7107) and shortened by a [Link: function] with some options / you could always change it. For reference Oracle (older versions) are 30 bytes, not 32 characters. [URL]

Reading through the code a bit more, only PostgreSQL and CockroachDB drivers create sequences and (in the case of CockroachDB, potentially) suffer from this bug. I will submit a bug fix (ignoring #7107) for those.
- Ah I see, I was aware of that function but didn't know there was a `StringUtils.shorten()` before the hashing that was introduced in #5227. Unfortunately it still isn't applied in all circumstances, so some work is needed there anyway.

Ideally we could reintroduce `shorten()` along with the suggestion of having an alias map, as per [URL] There might be some differentiation between permanent identifiers like the sequence name, and temporary aliases per query.

Either way quick fix sounds like a good idea for now.
- On further investigation it's a little bit more tricky, and way more specific, than I first thought. The problem first starts when TypeORM uses the default PostgreSQL sequence name. PostgreSQL is smart enough to truncate, however it uses its own, different algorithm again to `StringUtils.shorten()`. I have no idea if CockroachDB suffers from the same issue, or how it resolves with without more research but I will look into it, as it's the only other TypeORM driver where a sequence name is generated.
