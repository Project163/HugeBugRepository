Discussion
- run quickstart and click on 'update' link.
- Thee problem was introduced with commit 916364, when cast to WebRequest was introduced inside method 'beforeRender(Component component)'. I've reverted methods 'beforeRender(Component component)' and 'afterRender(final Component component)' to commit 895520 and this solves issue. 
See attached patch. 

 PS: patch passes all unit tests.
- I don't think we want to go back to StringResponse, as this way we'd lose some WebResponse features (e.g. encoding, headers). 

 Seems we have to check whether the transformation is happening on a WebResponse or a Response only. WDYT?
- I think Andrea's patch is OK. 
The old headers will be obsolete after the transformation - the content length most probably will be different, the encoding may be changed as well, the content type too ... 

 I'd also like to add this as a test case to org.apache.wicket.markup.transformer.AbstractTransformerBehaviorTest. Otherwise next time again no tests will fail
