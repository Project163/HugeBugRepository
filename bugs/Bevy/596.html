Title

Resource doesn't get dropped on panic in system. Is this expected?

Description
## Bevy version
0.14.2
debug build.

## What you did
```
use bevy_ecs::system::{Resource, RunSystemOnce};
#[derive(Resource)]
struct DropyResource(pub u8);
impl Drop for DropyResource {
    fn drop(&mut self) {
... [Log Snipped] ...
    world.run_system_once(panicy_system);
}
```

Output:
```
thread 'main' panicked at src/main.rs:9:22:
ima panicing
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace
dropy 1 dropped.
```
## What went wrong
DropyResource added to world didn't get "Dropped".

- what were you expecting?
I was expecting to see 
dropy 1 dropped.
dropy 2 dropped.

- what actually happened?

only "dropy 1 dropped."  was printed.
Discussion
- This seems to be a deliberate choice

[URL]

This could however be relaxed to leak only when `SEND` is `false`, since when it's `true` the `validate_access` always immediately returns.
- That seems correct.

@james7132
 Will replacing the condition with
`if !SEND && std::thread::panicking()`
be ok?
- I believe you need something like:

```rs
if !SEND && self.is_present() {
     if std::thread::panicking() { 
         return; 
     } 
     self.validate_access(); 
}
```
