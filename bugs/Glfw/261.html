Title

Key repeat timer race condition causing freeze

Description
Some info about my environment:

I'm running `sway version 1.4-f681d529`, and the latest master of glfw built with wayland support.  My program is single threaded and calls glfwPollEvents every frame, which is capped at 30 fps.

Occasionally my glfw program will completely freeze.  Attaching with gdb revealed the following backtrace:

```
#0  __cp_end () at src/thread/x86_64/syscall_cp.s:29
#1    in __syscall_cp_c (nr=0, u=8, v=140721514594888, w= ,
    x= , y= , z=0) at src/thread/pthread_cancel.c:33
#2    in read (fd= , buf= , count= )
    at src/unistd/read.c:6
... [Log Snipped] ...
    hf= ) at ../client/ui/common.c:82
#8    in main (argc=3, argv= ) at ../client/main.c:65
```

After doing some digging I think I found a race condition.  When I hold a key, the repeat timer is properly set and detected with poll().  However, if I release the key after glfw has polled the repeat timerfd, but before the timerfd is read, the key handling code disarms the timer and the resulting read blocks, freezing my program.

Printf debugging supports my hypothesis:

[Link: src/wl_window.c]

```
  if (poll(fds, 3, timeout) > 0) {
       printf("done polling\n");

       ...
       if (fds[1].revents & POLLIN)
       {
            printf("about to read\n");
->          read_ret = read(_glfw.wl.timerfd, &repeats, sizeof(repeats));
```

[Link: src/wl_init.c]

```
    printf("setting timer: %ld, %ld, %ld, %ld\n", timer.it_value.tv_sec,
	    timer.it_value.tv_nsec, timer.it_interval.tv_sec,
	    timer.it_interval.tv_nsec);

    timerfd_settime(_glfw.wl.timerfd, 0, &timer, NULL);
```

output:
```
...
done polling
done polling
done polling
setting timer: 0, 600000000, 0, 40000000
... [Log Snipped] ...
setting timer: 0, 0, 0, 0
about to read
```

I have fixed this problem for now by simply setting O_NONBLOCK on the timerfd, but I'm not sure if that is the best solution.
