Title

Controller::afterFilter() as no access to the response returned from an action

Description
[x] enhancement
* CakePHP Version: master

**AController.php:**
```
...
public function some() {
    return $this->response->withStringBody('empty');
}
public afterFilter($event) {
    return $this->response->withHeader('additional', 'stuff');
}
...
```

I expected a response with the string 'empty' as the body and the header 'additional' set to 'stuff'. I got a response with the header, but not the string body.

FROM IRC:

It's just weird that it (afterFilter) has no access to the response object that has been returned by an action, but is able to return a response that will be send...
Discussion
- Actually it should be `Controller::invokeAction()` itself that should set `Controller::$response` not `ActionDispatcher::_invoke()` :slightly_smiling_face:.
