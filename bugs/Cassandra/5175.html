Title

Repaired data tracking isn't working for range queries

Description
CASSANDRA-14145   introduced optional tracking of the repaired dataset used to construct a read response. If enabled, each replica computes a digest for the repaired portion of the data, which the coordinator compares in order to detect divergence between replicas. This isn't working correctly for range reads, as the ReadCommand instance that the DataResolver is intialized with does not have the tracking flag set. This has been undetected up until now as the dtest which should verify it also has a bug in that when the relevant range query is issued the test expectations are being incorrectly set.
