Title

Bug: [new config system] unmatched individual patterns are not reported

Description
### Environment

Node version: v16.14.0
npm version: v8.3.1
Local ESLint version: v8.23.0 (Currently used)
Global ESLint version: Not found
Operating System: win32 10.0.19044

### What parser are you using?

Default (Espree)

### What did you do?

I ran the following command in my local clone of the eslint/eslint repo, `main` branch:

```
node ./bin/eslint.js "tools/*.js" "doesnotexist/*.js" -f tap
```

### What did you expect to happen?

Since there is no `doesnotexist` directory, I would expect an error saying that the `doesnotexist/*.js` pattern is unmatched:

```
Oops! Something went wrong! :(

ESLint: 8.23.0

No files matching the pattern "doesnotexist/*.js" were found.
Please check for typing mistakes in the pattern.
```

This is the current behavior in eslintrc mode (when `eslint.config.js` file is deleted).

### What actually happened?

Successful linting:

```

1..7
ok 1 - D:\projects\eslint\tools\code-sample-minimizer.js
ok 2 - D:\projects\eslint\tools\config-rule.js
ok 3 - D:\projects\eslint\tools\eslint-fuzzer.js
... [Log Snipped] ...
ok 6 - D:\projects\eslint\tools\update-readme.js
ok 7 - D:\projects\eslint\tools\update-rule-types.js
```

### Additional comments

This happens because we're passing to `globby` all the patterns together, so we don't know if some of them didn't match anything.
Discussion
- I would like to work on this issue.
- I tried to implement the logic of looping through globbyPatterns and checking the globbyResult (later pushing into globbyResults) for each pattern and if ```globbyResult.length == 0``` it threw the NoFilesFoundError. This logic worked perfectly fine for the above issue but while running unit tests, I encountered an error which was caused due to ```lib/config/default-conf.js``` where  ``` "**/*.mjs"```, ```"**/*.cjs"``` are intentionally added empty config to ensure these files are globbed by default. Since these files are not present in eslint repo the globbyResult came out to be empty throwing the NoFilesFoundError.

According to me there can be two solutions to this new problem:
**1**. Making empty test.mjs and test.cjs files so that globbyResult get the path to these files and prevent errors in unit tests. 
**2**. Removing  ``` "**/*.mjs"```, ```"**/*.cjs"``` from ```default-config.js``` so that they are not globbed by default.

Other solutions/suggestions are also welcomed for discussion.
