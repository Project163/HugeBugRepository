Title

`window.tauri` unavailable in when loading assets with no-server

Description
**Describe the bug**
When loading assets with the embedded server disabled, mutation observers are injected in the ` ` and ` ` watching for new items to load. Because the `tauri.js` script that defines `window.tauri` is loaded in the body, the head is unable to access this object.  This leads to the error: `Unable to get property 'loadAsset' of undefined` for all assets that are attempted to be loaded by the mutation observer in the ` `.

**To Reproduce**
Steps to reproduce the behavior:
1. Have assets to be loaded in the ` ` (such as stylesheets).
2. Disable embedded server in `tauri.config.json`
3. `yarn tauri build`
4. Check console for the above error message
    * You can also check the generated `index.tauri.html` file to confirm that the mutation observer is referencing `window.tauri` before the script that defines it is injected into the dom

**Expected behavior**
`loadAsset` function in the ` ` mutation observer should be able to access `window.tauri` and then load the asset properly.

**Additional context**
The offending code is this line.  [URL]

Changing that to:
```ts
document.head.insertBefore(tauriScript, document.head.firstChild)
```
fixes the issue as it will cause the `tauriScript` to be the first item in the ` ` allowing other scripts to access `window.tauri`.

I've written this as an issue and not a Pull Request as I'm not familiar with the code base and am unsure if this change is the desired way to go about it. I looked into the history and this became the way to do it after some sort of previous `_INIT_HOOK` way of going about it. Let me know if this change is desired and I'll open a PR.
