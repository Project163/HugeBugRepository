Title

Cross-repository build violation with third_party/googleapis

Description
Bazel has a feature to attempt to detect and prevent referring to a package by two different labels.

Currently, from the Bazel source, it is possible to build both `//third_party/googleapis:all` and `@googleapis//:all`.

The repository form is the preferred form (since it is defined in Bazel's WORKSPACE). The third_party form does not build, because several source paths are wrong, but this should be flagged as an error.
