Title

unsafe conversion of array of reference type to an array of primitive type

Description
I have the following program 
  
 
 class  Test {
   public   static  void main( String [] args) {
     double [] z =  new   Double []{ null };
  }
}  
  
   Actual behavior 

 The compiler accepts the program. However, I get the following exception at runtime. 

   
  
 
Exception in thread  "main"  java.lang.IllegalArgumentException
        at java.base/java.lang.reflect.Array.set(Native Method)
        at org.codehaus.groovy.runtime.typehandling.DefaultTypeTransformation.asArray(DefaultTypeTransformation.java:459)
        at org.codehaus.groovy.runtime.typehandling.DefaultTypeTransformation.castToType(DefaultTypeTransformation.java:228)
        at org.codehaus.groovy.vmplugin.v8.IndyInterface.fromCache(IndyInterface.java:336)
        at Test.main(test.groovy:3)
  
  
   Expected behavior 

 The compiler should reject the program: Double[] is not convertible to double[]. 
   Notes 

 Tested against master (commit:  ) 

 Groovy 4.0.10 rejects the program as expected.
Discussion
- @groovy.transform.TypeChecked test() {
   double [] z = [ null ]  as   Double []
}
test()
 
  

 Groovy 2.5 says: Cannot assign value of type java.lang.Double[] to variable of type double[] 

 Groovy 3+ compiles and the  IllegalArgumentException  occurs at runtime.
- DefaultTypeTransformation#castToType  implements conversion from object (incl.  null ) to some type (incl. primitives).  The only primitive conversion today is  null  -->  false  for  boolean . 

 I think it is safe to add a conversion from  null  to  NaN  for  double  and  float .  That would stop the  IllegalArgumentException  at the point of array store. 

 As for what to do about the other primitive types, I think the "null" character is probably okay.  But zero for the integral types I'm not sure about.  Any thoughts?  paulk   blackdrag

- Conversion from  Double[]  to  double[]  is supported.  All values besides null are boxed.  In fact, any type that is convertible to  Number  works as well.  Adding a type-check error is a possibility, but will not help the  IllegalArgumentException  outside STC.

@TypeChecked test( Integer [] integers) {
   int [] ints = (integers  as   int [])
}
