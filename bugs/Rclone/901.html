The race detector declares line 16 is racing with line 23

Line 23 is only called when the function under test has finished.

I think the problem is caused by the fact that there is a recursive call to `CaptureOutput` (you can see that in the second trace in the Details above).

When `fun()` has finished and before we run `return buf.Bytes()` the logger in use is still our new logger, but if another goroutine is using the previous logger (from the outer nested `CaptureOutput` call) does logging then it will use our `buf` (the inner nested one) at line 16 and cause the race when we run line 23  `return buf.Bytes()`.

So fixes might be - not to call `CaptureOutput` recursively.

Or re-arrange it something like this so that we stop the logger using `buf` before we read from it. 

```
go
func CaptureOutput(fun func()) []byte {
	buf := &bytes.Buffer{}
	oldLevel := log.Handler.SetLevel(slog.LevelInfo)
	log.Handler.SetOutput(func(level slog.Level, text string) {
... [Log Snipped] ...
	return buf.Bytes()
}
```

Or maybe simpler if we decide that a backtrace is unlikely

```
go
func CaptureOutput(fun func()) []byte { 
 	buf := &bytes.Buffer{} 
 	oldLevel := log.Handler.SetLevel(slog.LevelInfo) 
 	log.Handler.SetOutput(func(level slog.Level, text string) { 
... [Log Snipped] ...
 	return buf.Bytes() 
 }
```
