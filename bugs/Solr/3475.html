Title

REPLACENODE can make the collection lost data which replicaFactor is 1

Description
When some replicas which the relative collection's replicaFactor is 1, it will lost data after executing the REPLACENODE cmd.  

 It may be the new replica on the target node does not complete revovering, but the old replica on the source node  was already be deleted.

 The main problem here is that the original replica is deleted before the new replica fully recovers - the code should wait until this happens when there's only one active replica left in the cluster. This should also consider a scenario when there are several replicas of the same shard on the same node, and again the code has to wait with deleting them before at least one new replica has fully recovered.
