Title

d3.geo.bounds: antimeridian and great arcs

Description
When making [Link: countries by area], I had to special-case Russia because its longitudinal bounds in spherical coordinates are ±180°.  I was using the bounds to set the projection origin, which seemed more appropriate than d3.geo.centroid because I wanted the stereographic scale variation to start from the centre of the projected bounding box.

Firstly, I think we should modify d3.geo.bounds so that it returns the true longitudinal _extent_ even if λ₀ > λ₁.  The problem is shown even better if you imagine the LineString [[135, 0], [-135, 0]], which would have longitudinal bounds -135° ≤ λ ≤ 135° at the moment, which seems clearly wrong.

Secondly, it’s possible for a great arc to move outside of a simplistic bounding box based on point extents, so that should be taken into account too.

This also affects d3.geo.path.bounds, which currently uses d3_geo_bounds internally.  Ideally, it should use resampling so that it properly accounts for curved arcs.

Related: it could be useful to have d3.geo.boundingCircle, similar to [Link: ST_MinimumBoundingCircle].  This would return an origin and angular radius defining a small circle that encloses a given set of geometries.
Discussion
- An alternative to allowing λ₀ > λ₁ would be to have longitudes greater than 180° (or smaller than -180°), which would be compatible with anyone relying on λ₁ > λ₀.
- Related: should d3.geo.bounds d3.geo.path.bounds return null for null geometries, e.g. type=null, coordinates=[], coordinates=[[]]?
