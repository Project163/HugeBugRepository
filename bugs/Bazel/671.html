Title

bazel build with no targets doesn't give an error

Description
Have a novice user who was confused because `bazel build` succeeds, with output
```
$ bazel build
INFO: Build options have changed, discarding analysis cache.
INFO: Analysed 0 targets (0 packages loaded, 0 targets configured).
INFO: Found 0 targets...
INFO: Elapsed time: 1.237s, Critical Path: 0.01s, Remote (0.00% of the time): [queue: 0.00%, setup: 0.00%, process: 0.00%]
INFO: 0 processes.
INFO: Build completed successfully, 1 total action
```

But then a related binary fails to run because it can't be built.

Of course, with no additional arguments, `bazel build` is a no-op, but this is confusing for users who are accustomed to other build tools where the `build` command is sufficient, eg. `yarn build`

I imagine we need to preserve the behavior that this exits zero, but at least it ought to print a warning that you specified no target patterns.
