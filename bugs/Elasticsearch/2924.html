Title

`ApiFilteringActionFilter` does a (recursive) linear search for actions to filter

Description
Seen in an exception stack trace: we are wrapping `ApiFilteringActionFilter` around itself many times, once per filtered action, so effectively every action is doing a linear scan of the filtered actions, implemented recursively. I'm pretty sure a hashmap would be more efficient, and would avoid inflating the stack so much too.

    at org.elasticsearch.action.support.ActionFilter$Simple.apply(ActionFilter.java:53) ~[elasticsearch-8.11.0-SNAPSHOT.jar:?]

Discussion
- Pinging @elastic/es-core-infra (Team:Core/Infra)
- This is unfortunately how action filters work at the moment. This is not recursive, note that there is a proceed call, followed by the apply of the filter. Proceed is how the chain is traversed. So each of these pair of frames is one instance of an ActionFilter.

The root of the problem is the lack of specificity when registering an ActionFilter. All ActionFilters are global, they don't have any notion of applying only to some actions. Thus when the action filters are collected, they are formed into a linear chain that must be searched.

TBC, we should fix this. But it will require re-engineering how action filters are both registered and invoked.
- :+1:

I was thinking more that for `ApiFilteringActionFilter` specifically we should be able to move to a single `ActionFilter` instance which holds a map of the individual filters keyed by action name, from which it does a single lookup each time through. Clearly some engineering effort to change how these API filters are registered.
- That sounds possible, but it will still require some re-engineering since currently the ApiFilteringActionFilter is what is returned by each plugin. We would need an SPI API for registering these implementations (might be tricky since they have dependencies), then have a single plugin return the main action filter.

While the above might be doable, I wonder if there is a middle ground where a "mapped action filter" concept is added, which ApiFilteringActionFilter implements. Then in server we can do the meta mapping within a single action filter, where we collection all the action filters that are mapped, and shove them into one filter. I'll play with this idea.
