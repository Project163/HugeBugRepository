Discussion
- It is related to #24627. 
The fix for #24627 makes sure that response size limit is not crossed.
But the limit is inaccurate. We control only the response size, and the response size limit is set to be RPC max size minus few kilobytes for the message body. But the message body may grow larger than that because of row orders. Row orders are 64-bit integers, and one is written to the response body per fetched row. So, typical ANALYZE sample size of 30,000 rows would require about 250KB of data the limit does not account for.
With all this mentioned, ANALYZE is not required to keep the row order.
