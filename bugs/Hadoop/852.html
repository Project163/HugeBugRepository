Title

HADOOP_CLIENT_OPTS default setting fixes max heap size at 128m, disregards HADOOP_HEAPSIZE

Description
hadoop-env.sh as included in the 2.0.2alpha release tarball contains: 
export HADOOP_CLIENT_OPTS="-Xmx128m $HADOOP_CLIENT_OPTS" 

 This overrides any heap settings in HADOOP_HEAPSIZE.
Discussion
- Compared to past, the HADOOP_HEAPSIZE is only for services, going forward. The HADOOP_CLIENT_OPTS therefore applies to clients alone and is the config point for client-side heap. 

 If an easier, numeric setting is needed for clients, we can perhaps have HADOOP_CLIENT_HEAPSIZE, but HADOOP_HEAPSIZE should not generally apply to clients given the newer HADOOP_CLIENT_OPTS.
- Maybe this can be better documented inside hadoop-env.sh? Out of the box changing HADOOP_HEAPSIZE adds a -Xmx argument to the beginning of the bin/hadoop java command, but the hard-coded 128M heap size in HADOOP_CLIENT_OPTS overrides that option with a second -Xmx. As a new user this was very unintuitive, especially since most advice given around the internet for earlier versions will refer to adjusting HADOOP_HEAPSIZE.  

 Also, at least in my case, 128M was not enough to run various examples from the hadoop examples jar, so the first thing many new users might encounter is trying to figure out how to increase heap size. Maybe 128M is a bad value given the default settings of other variables?
