Title

mitmdump crashes when delaying recorded responses with the kill flag

Description
##### Steps to reproduce the problem:
1. Record the server responses of some website: `mitmdump -w rec.out --anticache`
2. Replay the server responses with the `--kill` flag and a script that delays one or more responses without blocking: `mitmdump -s script.py -S rec.out --kill --no-pop`
   
   script.py:
   
   ```
import re
   import time
   
   from mitmproxy.script import concurrent
   
... [Log Snipped] ...
     if flow.error:
       print('Error: ' + str(flow.error))
```
##### What is the expected behavior?

The server responses are replayed, the responses matched by the `delayUrl` pattern are delayed by 5s, and responses not found in the recording are killed.
##### What went wrong?

The script crashes:

Discussion
- Hi! I' looking at this bug. I guess this is caused by the incompatibility of `--kill` and the `@concurrent` decorator.

When the `request` method in the script using `@concurrent` decorator, it will create a new thread and run the following code in it, including kill a flow object. Almost at the same time, the main thread will deal with the response while don't know the flow has been killed by another thread.

If we remove the `@concurrent` in the script, no errors appear any more. The bugs involving are always tricky... Any ideas? @mhils @Kriechi
