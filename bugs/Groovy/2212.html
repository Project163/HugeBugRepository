Discussion
- Here is a smaller code snippet showing the problem: 

  
     @CompileStatic
     Object  convertValueToType( Object  value,  Class  targetType) {
             if  (value  instanceof  CharSequence) {
                value = value.toString()
            }
             if  (value  instanceof   String ) {
                 String  strValue = value.trim()                    
            }
    }
 
  

 The generated bytecode looks like: 

  
 00014 LTestScripttestShouldNotThrowIncompatibleArgToFunVerifyError0;  Object   Class  . .  :  :     ALOAD 1
00015 LTestScripttestShouldNotThrowIncompatibleArgToFunVerifyError0;  Object   Class  . .  :  Object   :     INVOKEVIRTUAL java/lang/ String .trim ()Ljava/lang/ String ;
 
  

 which means that the first parameter ( ALOAD 1 ) is loaded but no  CHECKCAST  is added to ensure the object is of the right type.
- Updating status to blocker since the bug is more problematic than it looks: it's related to handling of flow typing within conditional branches which can lead to invalid bytecode with  @CompileStatic .
