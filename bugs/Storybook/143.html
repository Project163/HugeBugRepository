- @shilman that's how I read it too, but I think it's the other way round:

The keys of the `cache`s get set here (based on globs from `main.js`):

[URL]

So if we are filtering the keys to find the referenced file names, we would simply find keys that match stories globs.

The only reason a cache entry would exist and be `false` would be if it was not processed yet, i.e another docs file. It's all very confusing.
- Ok, thanks to some screensharing we worked out that the file that it is matching (incorrectly) is itself (`./Button` being a prefix of `./ButtonDocs.mdx`). 

The prefix part is a bit of a bug but ultimately it could have been importing from `./ButtonDocs` (`.tsx`) and had the same issue. There's no easy way for us to tell what it's matching; but if we search through the index and find a docs or unprocessed file (which by definition is docs) we should just skip it.
