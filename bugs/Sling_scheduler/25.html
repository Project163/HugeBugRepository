Title

Deadlock at startup in Commons Scheduler

Description
Saw following deadlock in one of the startups with 2.6.2 release. Logs   attached      

  
 Found one Java-level deadlock:
=============================
"Apache Sling Repository Startup Thread":
  waiting to lock monitor   (object  , a org.apache.sling.commons.scheduler.impl.SchedulerProxy),
  which is held by "FelixStartLevel"
"FelixStartLevel":
  waiting to lock monitor   (object  , a org.apache.sling.commons.scheduler.impl.SchedulerProxy),
  which is held by "Apache Sling Repository Startup Thread"

Discussion
- The schedule method locks the current proxy but then calls unschedule which iterates over all proxies and syncs on each of them. So if schedule is called concurrently with two different proxies this deadlock can occur. 
I think the easiest solution is to use a single global lock for each operation, instead of smaller individual locks on the proxy level
- Using single lock instead of more fine grained ones (rev 1805278)
