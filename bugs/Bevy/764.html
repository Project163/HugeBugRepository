Title

Dependencies of immediately loaded nested asset never start loading.

Description
## Bevy version and features

- Bevy 16.1, default features

## What you did

I have a custom asset loader that immediately loads another asset on which it depends. The loader for the immediately loaded asset also starts loading an image and stores that handle in the asset, but the image never starts loading.

Minimal repro: [URL]

## What went wrong

I would expect that assets loaded via `load_context::load` always start loading at some point, even if loading of the current asset is done via `load_context::loader().immediate().load`.

## Additional information

A possible workaround is to manually load the image a second time via the asset server which also fixes the previously broken asset handle. The repo mentioned above includes two places where this can be done to prove, that everything else works.

Using `load_context::load` in the inner asset loader with a path that doens't exist never produces any kind of error message.
Discussion
- When you load an asset with the `immediate()` nested loader, it creates a new `LoadContext` that will only create a handle and register the asset path, but not load assets for dependencies. Someone with more knowledge of the asset system than me can maybe say why this is so.
- Yes, this seems to be intentional :/
[URL]

Also once you have a load context with `should_load_dependencies: false`, there doesn't seem to be a way to configure that.

I don't get what the use case for that is. It would make sense if it were used internally somewhere where dependencies don't matter, but  `load_direct_internal` is never called outside of `NestedLoader ::load` which itself is never called internally. Maybe this is just an oversight from refactoring.

FYI: Changing the outer asset loader in my repro above to just use `load_context::load` for the inner asset also causes the image to be loaded again.
