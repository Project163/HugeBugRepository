- Can be reproduced with just running  UFPureScriptTest.testJavascriptTupleTypeCollection . So it's not specific to Windows.
- Patch contains: 
 
	 fix for this issue (described below) 
	 removal of dependency to  sun.security.util.SecurityConstants  
	 optimization to remove (not very) expensive per-UDF-invocation in  UDFunction.ThreadIdAndCpuTime  c'tor 
 

 New code in new Java driver (3.0a2) uses Guava code to inspect generic types of collections. This requires  accessDeclaredMembers  runtime permission, which is now granted in  ThreadAwareSecurityManager#checkPermission(java.security.Permission) . The permission itself allows inspection of members, but not modification of members. It should not have any negative impact to the  Java  sandbox, as access to reflection classes is not granted - but makes scripting sandbox "weaker".
