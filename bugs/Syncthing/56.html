Title

Fails to delete read-only files

Description
When deleting a file which is in Read-Only mode (node win 7 / node win 8), It won't delete on the other node, so the file is always coming back.

Reproduction of the behaviour:
- 2 nodes, 1 repository in common;
- from a node, add a Read-Only file to the repository;
- wait for it to by sync;
- delete the file from any node;
- wait at least 2 syncs and the file will reappear on the node where it was deleted.

I think that the suppression by ST on the remote node is silently refused by the OS because of the Read-Only attribute of the file. ST ignores this refusal and continues it's work. During the following sync, ST finds a file which is only on one node, decides that it is a new one and resends it.
Discussion
- Yep. Note to self: while this is a Windows specific issue, check for same thing in read-only directories on Unix.
