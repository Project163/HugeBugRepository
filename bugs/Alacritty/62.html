Title

Alacritty window rescales during startup

Description
When I start alacrity, it first creates a large window which is then very quickly resized to the final size (~70%).  The resizing is really fast and wouldn't bother me but my window manager (fvwm2) places the window based on the original size and that means that the window position ends up not being what it is supposed to be. 

Ubuntu 16.10.  Default alacritty.yml except that I changed the font size to 13.
Discussion
- Thanks for filing this issue. The problem here is we need to know some font metrics to know the proper window size to create, but we can't know the font metrics without having the DPI scaling factor which comes from the window.

Glutin needs a way to get the DPI scaling info for a monitor without actually creating a window.
- A workaround might be to open a window to get the DPI scaling factor, then close it and open a new one with the correct size.  Not great but perhaps better than the current state of affairs.
- ... [Middle Discussions Snipped for Brevity] ...
- If you set window dimensions and the DPI factor is not equal to 1, it's impossible not to resize at startup.


The issue is exactly what vberger has said in the winit issue. It's pointless that we're able to get the DPI for all displays when we do not know which display the window is going to be spawned on.
- At this point, I think the question becomes "how do other terminals handle it?"
I don't experience the same problems in, say, Konsole.
All of my displays (at least at home) have a non-1 DPI factor, but all of my displays per-system also have identical DPI factors (same-size displays with same resolution in all multi-display setups).
Surely there's some way for alacritty to handle these common scenarios with equal grace to virtually every other alternative?
