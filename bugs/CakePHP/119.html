Title

MYSQL On the Fly Database Switching Broken since 2.4.8

Description
This is taken from a discussion started on Pull Request: #3210 
Since 2.4.8 the ability to switch MYSQL databases on the fly has been broken by improvements to the MSSQL schema handling.

I have an application in which we have multi-tenancy in isolated databases.

Some of our cron jobs (CakeShells) loop through tenants running the same process on each, and so we depend on on-the-fly switching of databases. 

Since 2.4.8, it seems that when switching databases using the command $model->setDataSource('database'), the $model->schemaName is left in it's old state, which means that future queries will use the old database.

@houseoftech proposed a (working) workaround whereby $model->schemaName is set directly after performing $model->setDataSource, however, my concern is that if someone new to this tries to implement on-the-fly switching they'll probably attempt setDataSource, see that it doesn't work, and then potentially give up and think its not possible with Cake. 

The only reason we pursued finding out what was going on is because our application design is already based around it - and even then it took a full day of digging to first identify the problem, and secondly find that someone had reported it. 

I am not sure if this is currently considered a bug, but it is definitely a significant break in functionality, and certainly not expected when moving between security-fix versions (2.4.7 to 2.4.8). I've noticed that this same issue arises in all versions since 2.4.8, including the latest 2.5.1

I will try to do some digging into the code and find a way that this can be worked-around while still maintaining the new MSSQL handling.
