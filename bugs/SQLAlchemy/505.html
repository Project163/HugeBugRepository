Title

Creating an anonymous CTE with an Update causes AttributeError

Description
**Migrated issue, originally created by Jack Zhou ([Link: @univerio])**

Test case:

```
class Foo(Base):
    __tablename__ = "foo"
    id = Column(Integer, primary_key=True)

foo = Foo.__table__
q = foo.update().returning(foo.c.id).cte()
```

Stack trace:

```
Traceback (most recent call last):
  File "sqlite.py", line 32, in  
    main()
  File "sqlite.py", line 28, in main
    q = foo.update().returning(foo.c.id).cte()
... [Log Snipped] ...
    if self.original.named_with_column:
AttributeError: 'Update' object has no attribute 'named_with_column'
```
Discussion
- **Michael Bayer ([Link: @zzzeek]) wrote:**

Ensure DML provides named_with_column for CTE(Alias)

Fixed bug in new CTE feature for update/insert/delete whereby
an anoymous (e.g. no name passed) :class:`.CTE` construct around
the statement would fail.  The Alias base class of CTE checks
for the "named_with_column" attribute in order to detect if
the underlying selectable has a name; UpdateBase now provides
this as False.
