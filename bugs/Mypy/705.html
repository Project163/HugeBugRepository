Title

Infinite loop when processing certain packages.

Description
I discovered this when trying to run MyPy on [URL]

`mypy -m cryptography` hangs forever at 100% CPU. Via PDB and strace I found that it was processing the same files over and over and never getting anywhere.

I have reduced this to a fairly simple test case.

Create a package like

`LOOP/__init__.py`

```
from LOOP.SUBLOOP import LOOPVAR
```

`LOOP/SUBLOOP.py`

```
LOOPVAR = "Loops!"
```

Run `mypy -m LOOP`. It will never complete.

I have tested this on Python 3.4.0 with MyPy 0.2.0 on Ubuntu 14.04.

I'm currently at EuroPython if anyone who knows about this stuff would like to pair on fixing it or just getting a reproduction working :)
Discussion
- Although import logic _is_ screwed up, `mypy -m LOOP` isn't valid python code if LOOP is a package unless you have a `__main__.py` (which I'm not sure if mypy supports properly), and additionally it is never possible to import from the main module since it would be imported twice under different names.

If you want to tell mypy to test a single module, try using my fork (branch `driver`, PR failing due to _other_ import bugs) and running `mypy -c 'import LOOP'`.
- Also, bugs against Mypy 0.2.0 (from pip) are not particularly useful, use the git version.
