Title

`isBinary` detect proper HTML page as binary

Description
Failing test case:
```java
    @Test
    public void testBinaryFail() throws IOException {
        Jsoup.parse(new URL("[URL] 50000);
    }
```

Detecting a binary file is complicated :/


At one point in my own project I was using something like:

```
java
public abstract class NonPrintableDetector {

    private final static Pattern NON_PRINTABLE_PATTERN = Pattern.compile("\\p{C}", Pattern.UNICODE_CHARACTER_CLASS);

... [Log Snipped] ...

}
```

But even so I had PDF accepted because it had a bunch of textual metadata near the beginning of the file...

I finally resorted to use the Tika library because of its knowledge of magic bytes, etc.

IMO JSoup should not even attempt to do this or at least give a way to be disabled because I for-see a lot of false positive or negative.
Discussion
- @jhy To add to what @panthony was saying, in Any23, we're using Jsoup to strip html tags from an arbitrary byte stream (for charset detection) by decoding as ISO-8859-1, stripping tags, and then re-encoding as ISO-8859-1 (even though the actual charset may _not_ be ISO-8859-1). During this process, we definitely wouldn't want exceptions to be raised for null bytes.
- Also, this "feature" honestly seems a bit out of scope for jsoup... especially given the risk of false positives. If I actually needed something like this, I'd rather implement my own binary detection mechanism and then simply pass in a `java.io.FilterReader` that throws according to a strategy tuned to my own needs. (Or implement a similar behavior at the charset detection level, using a more comprehensive library such as Tika, which is specifically written for stuff like this.) 

That being said, obviously the biggest problem here is that there's no way to opt out.
- @HansBrende thanks for the feedback. I agree, this needs to be reworked. I don't know that we want to bring in Tikka, want to keep the depencies low. My thought is, if we leave it in, to add it to the section where the Connection is tested for MIME type. If there is no MIME type, try and determine if it is binary. Still, that would benefit from an override option, so it might be simplest to remove entirely.
