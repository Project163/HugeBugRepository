Title

Can no longer use serialize with classes that do not have a no-arg constructor

Description
This appears to be a regression in 4.2.0 from the 4.1.x branch.

In my 4.1.8 codebase I have an ActiveRecord model with a text attribute `match_regexp`.  There is a corresponding `serialize` line that looks like this:

```
serialize :match_regexp, Regexp
```

In Rails 4.1.8 this works as expected - I can serialize and deserialize Regexps without a problem.  But when I upgraded to 4.2.0, this functionality is seriously broken.  I can't even instantiate instances of the class - I get an `ArgumentError` from the `YamlColumn` coder.  Specifically I get:

```
ArgumentError: wrong number of arguments (0 for 1..3)
from .../activerecord-4.2.0/lib/active_record/coders/yaml_column.rb:24:in `initialize'
from .../activerecord-4.2.0/lib/active_record/coders/yaml_column.rb:24:in `new'
from .../activerecord-4.2.0/lib/active_record/coders/yaml_column.rb:24:in `load'
from .../activerecord-4.2.0/lib/active_record/type/serialized.rb:52:in `default_value?'
... [Log Snipped] ...
from .../activerecord-4.2.0/lib/active_record/core.rb:441:in `collect'
from .../activerecord-4.2.0/lib/active_record/core.rb:441:in `inspect'
```

The issue occurs because a no-arg constructor is invoked when the default value is nil.  Regexp has no such constructor, so this errors out.  This seems odd to me - I'm not sure why I couldn't have a nil value for a serialized attribute.

I created a bare bones Rails app to demonstrate.  You can find it here - [URL]

After bundling, just do `Category.new` from the console and you'll see the error.

It looks like @sgrif has done most of the changes in serialization for Rails 4.2.  Any thoughts?

Thanks.
Discussion
- FWIW, while this is a legitimate bug, this seems like a very odd use of serialize. Why not just write it as:

``` ruby
class Category < ActiveRecord::Base
  def match_regexp
    Regexp.new(super)
  end
end
```
- @sgrif That's a fair comment.  The simple answer is that I didn't write it that way.  :)

My first thought was to serialize the Regexp in the database, so that's how I wrote it.  But as you note, there are some simple changes I can make to get this working in Rails 4.2.0.

- @petergoldstein Basically, the original idea was that you usually wanted an empty array or an empty hash, and so `serialize :foo, Array` was just shorthand for setting the default. I agree with you that it was a questionable design decision. It's pretty painful to change at this point, though. We're shying away from `serialize`. Most examples will probable use [URL] instead once that's made public in Rails 5.

In your case, the simplest fix would be to just not pass a class to `serialize`, since it's optional.
- @sgrif I've already modified my code per your original suggestion, so I don't have a lot of skin in the game at this point.  Happy to defer to your judgement on this issue.
