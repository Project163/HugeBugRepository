Title

[YSQL] memory leak in the sessions serving reads during SqlInserts workload

Description
Workload:
```
java -jar ./tserver/java/yb-sample-apps.jar --workload SqlInserts --nodes  :5433, :5433, :5433 --num_unique_keys 100000000 --num_threads_write 6 --num_threads_read 2 --nouuid &>sample.log
```

Setup: 3-node cluster (4cpu/7.5GB RAM each).

Two of postgres backend processes (like corresponding to the --num_threads_read 2 option above) kept seeing a growth in process memory, and eventually causes OOM on the machine.

The second time around, before the OOM happened, followed steps [Link: outlined here] to first get a core from one of the processes whose memory kept growing via:

`gcore  `

Next, used the macros provided (again [Link: from the same source]) to generate the memory report:

`gdb -c ./core.32156 /home/yugabyte/yb-software/yugabyte-ee- -b12-centos-x86_64/postgres/bin/postgres   memory_ctx.out`

Posting the contents of memory_ctx.out as well. The `TopMemoryContext` is about 2G which matches what "top" shows. But none of the nested items seem to be that significant. So there's some unexplained memory leak. The core file (core.32156) is still available on   of puppy-food-2 cluster (if someone wants to take a look).
