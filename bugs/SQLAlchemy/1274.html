Title

primary key reduction logic tripped up by equiv columns not being equivalent in a later selectable of a UNION

Description
### Describe the bug

I'm trying to create a mapper for a tree structure and the best way I found was using a CTE. I have the relationships in a table and I want to get

1. all children for a given node id
2. the full path to a given node id

And a good way for this would be to have a relationship on a given node mapper to parents (for point 2) and children (for point 1). For that I created a mappers `Node` and `NodeRel` (see below) where `Node.parents` and `Node.children` would return `NodeRel` objects. `NodeRel` has a recursive CTE as its `__table__`. Problem is, `Node.children` returns the correct data but `Node.parents` returns only the immediate parent and not above. On further investigation, selecting a `NodeRel` with a given id returns the same immediate parent, repeated the same number of times as the number of parents. However, running the raw SQL query SA emits returns the correct results.

### To Reproduce

```
python
from sqlalchemy import create_engine, Column, Integer, ForeignKey, select, literal, text
from sqlalchemy.orm import declarative_base, Session, relationship

Base = declarative_base()
... [Log Snipped] ...
    # (4, 1, 2)
    # (4, None, 3)
```


### Error

No error, just wrong results. See above.

### Versions

- OS: Windows 10
- Python: 3.10.3
- SQLAlchemy: 1.4.26
- Database: SQLite 3.37.2
- DBAPI (eg: psycopg, cx_oracle, mysqlclient): pysqlite

Discussion
- your mapping requires that the primary key be established to include "id" and "parent" explicitly:

```
py
class NodeRel(Base):
    table = select(
        Node.id,
        Node.parent,
... [Log Snipped] ...
    def __repr__(self):
        return f'  {self.id}>'
```

otherwise, when you ask for "id=4", it gets all rows with "id=4" and as far as the ORM knows, "id" is the only column that's a primary key.

However, the above mapping has a totally separate problem in that the ORM is attempting to "reduce" the columns given for that primary key to columns that are known to have unique values; columns that are equated to each other are assumed to have the same value and are reduced.  So the above "primary_key" argument will be silently truncated back down to the "id" column alone. 

at the moment, the only workaround I have is to patch away the function in question:

```
diff
diff --git a/lib/sqlalchemy/orm/mapper.py b/lib/sqlalchemy/orm/mapper.py
index 967c1064ad..7fe7716194 100644
--- a/lib/sqlalchemy/orm/mapper.py
+++ b/lib/sqlalchemy/orm/mapper.py
... [Log Snipped] ...
                 primary_key = sql_util.reduce_columns(
                     self._pks_by_table[self.persist_selectable],
```

the the rows are identified as individual primary keys:

```
WITH RECURSIVE anon_1(id, parent, depth) AS 
(SELECT nodes.id AS id, nodes.parent AS parent, ? AS depth 
FROM nodes UNION ALL SELECT nodes.id AS id, anon_1.parent AS parent, anon_1.depth + ? AS anon_2 
FROM nodes JOIN anon_1 ON nodes.parent = anon_1.id)
 SELECT anon_1.id, anon_1.parent, anon_1.depth 
... [Log Snipped] ...
  4>
  4>
```
- it's because Node.parent is a foreign key to Node.id, so the ORM assumes these will always be equal.  it doesnt see that there's a UNION in there redefining the value of the column down below.  

So you can work around this by using a name-only column that isn't related to "parent" like this:

```
py
class NodeRel(Base):
    table = select(
        Node.id,
        column("parent"), #Node.parent,
... [Log Snipped] ...
    def __repr__(self):
        return f'  {self.id}>'
```

then it sees both cols as uniquely part of the PK.
