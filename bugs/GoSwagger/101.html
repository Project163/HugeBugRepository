Title

Swagger fails to generate code for valid schema

Description
## Problem statement

When responses have "examples" section swagger 0.9.0 fails to generate code - the same schema is processed fine by swagger 0.8.0. It is difficult for me to deduce what causes it, so please, see attached examples.

1. samples_ok.yml, executing "swagger-new generate server -f ./samples_op2_ok.yml -t ./src", everything is fine, code generated.

[Link: samples_ok.yml.txt]

2. Adding second operation - samples_op2_bad.yml, executing "swagger-new generate server -f ./samples_op2_bad.yml -t ./src", does not work, returning "object has no key "InfosItems0""

[Link: samples_op2_bad.yml.txt]

3. Renaming items in response's "examples" (note, schema is valid, but tools like Swagger-UI and Swagger editor would not show "sample response"), samples_op2_ok.yml, executing "swagger-new generate server -f ./samples_op2_ok.yml -t ./src", code generation works again.

[Link: samples_op2_ok.yml.txt]

## Environment
swagger version: 0.9.0
go version: 1.8.1  
OS:   Ubuntu 14.04
Discussion
- Problem is caused by commit  :
```
var err error
	var specDoc *loads.Document
	opts.Spec, specDoc, err = loadSpec(opts.Spec)
	if err != nil {
		return nil, err
... [Log Snipped] ...
		}
	}
```
It introduces side effect - after validation specDoc is expanded. That causes generation to fail in some cases or produce different code (with and without validation). Easy enough to fix:

```
var err error
	var specDoc *loads.Document
	opts.Spec, specDoc, err = loadSpec(opts.Spec)
	if err != nil {
		return nil, err
... [Log Snipped] ...
		}
	}
```
