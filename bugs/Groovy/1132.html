Title

"final" not working as expected

Description
neither final properties nor final fields are shielded from mutation if the mutator is a method in the same object. 

  
  class  Person {
     final   String  name =  "scott" 
    def foo() {
        name =  "Dierk" 
    }
}
def p =   new  Person()
p.foo()
 assert   "Dierk"  != p.name

 // credits: Scott Davis
Discussion
- fixed
- Just as a comment, consider this example: 

 class Person { 
    Person()  
{ name = 'Jochen' }
     final String name = 'Scott' 
    def foo()  
{
//        name = 'Dierk'
    }
 } 
def p =  new Person() 
p.metaClass.foo =  
{ -> delegate.@name = 'Guillaume' }
 p.foo() 
println p.name // => 'Guillaume' 

 If we uncomment out line 5, we get a compilation error even though the program would be fine at runtime - so we aren't being fully dynamic here - but being stricter here to honor JVM semantics around final.
