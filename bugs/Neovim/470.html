Title

completefuzzycollect with keyword breaks i_ctrl-x_ctrl-n

Description
### Problem

`'completefuzzycollect'` prevents `i_CTRL-X_CTRL-N` from completing next word in *master* branch.

😺 Thanks for all of your hard work. This just a low-priority bug for a recently added option that I wanted to bring to your attention. I don't need to use this option.

While filling out the rest, I realized it's a vim9.1.1178 bug. This opt was inherited and it causes i_CTRL-X_CTRL-N to malfunction. Close if desired.

### Steps to reproduce

```sh
wget [URL]
chmod u+x nvim-linux-x86_64.appimage
./nvim-linux-x86_64.appimage --appimage-extract
./squashfs-root/usr/bin/nvim -u NONE
```
```vim
:set completefuzzycollect=keyword
:put=['hello world foo bar','']
```
type "hello",  Ctrl + x ,  Ctrl + n ,  Ctrl + x ,  Ctrl + n 

Note: it doesn't complete " world".

### Expected behavior

This does work:

```vim
:set completefuzzycollect=
```
type  Esc ,  c  c , "hello",  Ctrl + x ,  Ctrl + n ,  Ctrl + x ,  Ctrl + n 

Note: it completes " world".

That's how I would expect it to work.
