Title

Splitter does not propagate exceptions

Description
Splitter in its process method iterates over the body of a message and processes each part synchronously. It does not propogate exceptions thrown by the processor when processing the exchange. This makes it problematic for tryBlock()....handleAll() kind of applications.
Discussion
- Is this still an issue for you? The Splitter class has changed quite a bit since you created this ticket.
- Shouldn't exception propagation be handled by aggregationStrategy? I believe that in case of splitter when we have one exception and few successful responses it is not so obvious if it is an exception of not. 

 I believe that if aggregationStrategy aggregates the exception into result, then it will be handled. Maybe we should simply verify if default aggregation strategy used propagates those exceptions by choosing maybe the last one that occurred.
