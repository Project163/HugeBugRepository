Title

st.tabs cause blank page starting >1.26.0

Description
### Checklist

- [Link: X] I have searched the [existing issues] for similar issues.

### Summary

After a update from 1.26.0 to 1.33.0 st.tabs causes a blank page w/o any error triggered. Seems to be the bug fixes in 1.27.0 related st.tabs introduced new bugs.

### Reproducible Code Example

```
Python
main.py
import streamlit as st
from src.outsourced import load_page

... [Log Snipped] ...
    with tab3:
        st.info('Some info in tab3.')
```


### Steps To Reproduce

1. Page loaded
2. Open new view by clicking on sidebar link which executes load_tabs()
3. Page gets blanked (the page loads if in load_tabs() no tabs and st.tabs are not used)

### Expected Behavior

New view with e.g. 3 tabs will be loaded.

- Hi there,
I was facing this problem in version **1.37.1**.

I tried to **reproduce** it in a simple scenario (not the same complex scenario as I am developing in the company, because of legal issues) that I could share here, but it seems to occur only in more complex scenarios.

My scenarios were the following:

1) I had an one page app with a **st.sidebar.selectbox** where one of five options available is selected, then it changes the app main content using if/else statements. In this scenario the problem **didn't happened**;

2) I refactored it to a more modularized and organized app, inserted an **asynchronous** request for an online Excel spreadsheet and loaded it in an **st.dataframe** inside an **st.tabs**. Here the **problem happens**. 

I was wondering if the problem is related to the st.tabs component working together async functions, but I perceived that the problem happens just in one situation: when I change the first loaded page (selecting an option on the st.sidebar.selectbox) to the page where the tabs+dataframe are placed. When I first change to other pages and then to the tabs+dataframe page, the problem doesn`t happens. Nothing seems to explain this behavior.

Workaround solution:

I **solved** my problem when I changed my app **navigation patterns**, using the **st.Page** and **st.navigation** components. They seem better encapsulate the pages and prevent interferences among them. You all could try it while we cannot reproduce the problem to proceed with a definitive solution. I hope I've helped. Let me know if it worked for you too.
