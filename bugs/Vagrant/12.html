Title

Incorrect NFS exports file generated when using private network and DHCP

Description
If you use a private network with DHCP, Vagrant will generate an incorrect /etc/exports file on BSD and OS X hosts.

Given a host running OS X or BSD, using VirtualBox as the provider, and a Vagrantfile that looks like this:

```
# -*- mode: ruby; -*-
Vagrant.configure("2") do |config|
  config.vm.box = "chef/freebsd-10.0"
  config.vm.network "private_network", type: "dhcp"
  config.vm.synced_folder ".", "/vagrant", type: "nfs"
end
```

Vagrant generates an /etc/exports file that looks like this:

```
"/Users/username/tmp/freebsd10"   -alldirs -mapall=500:10
```

Then the NFS synced folders do not mount in the guest, and you see nfsd errors in the host's syslog.  The command 'vagrant up' usually hangs while waiting for the NFS mount command in the guest.

Here is the nfsd error on FreeBSD 10:

```
Oct 17 15:53:09 packer-freebsd-10 mountd[1440]: bad exports list line /home/username/tmp/freebsd10   -alldirs -maproot
Oct 17 15:53:33 packer-freebsd-10 mountd[1479]: can't change attributes for /home/username/tmp/freebsd10: Invalid radix node head, rn: 0  
```

Here is the nfsd error on OS X Mavericks 10.9.5:

```
10/17/14 10:05:56.199 AM sudo[20794]: username : TTY=ttys003 ; PWD=/Users/username/tmp/freebsd10 ; USER=root ; COMMAND=/sbin/nfsd restart
10/17/14 10:05:56.223 AM nfsd[20800]: Can't change attributes for /Users/username/tmp/freebsd10.  See 'exports' man page.
```

I am able to fix the problem by changing the /etc/exports file to remove the IP address,  .

```
"/Users/username/tmp/freebsd10" -alldirs -mapall=500:10
```

I can also fix the problem by assigning an IP address to the private network interface in the Vagrantfile.

Vagrant version: 1.6.5
VirtualBox version: 4.3.6r91406
Host OS version: OS X Mavericks 10.9.5
