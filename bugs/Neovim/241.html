Title

nvim 0.8.0 slow when opening large files with "filetype on" or "syntax on"

Description
### Neovim version (nvim -v)

v0.8.0-dev-872-gbccb5de89

### Vim (not Nvim) behaves the same?

no, vim 9.0.135

### Operating system/version

Ubuntu 22.04

### Terminal name/version

konsole 21.12.3

### $TERM environment variable

xterm-256color

### Installation

GitHub releases, PPA

### How to reproduce the issue

# Script

```
bash
tmpdir=$(mktemp -d)
trap "rm -r $tmpdir" EXIT
largefile="$tmpdir/largefile"

... [Log Snipped] ...
    echo "********************************************************************************"
done
```

### Expected behavior

nvim 0.8.0 should open moderately a large file (1,000,000 lines, 66M) just as fast as vim and nvim 0.7.2 (about 0.15s) with `filetype on` or `syntax on`.

### Actual behavior

nvim 0.8.0 takes about 3 seconds to open a moderately large file (1,000,000 lines, 66M) when either of `filetype on` or `syntax on` is set.
**Of note**, opening a large file with what I presume to be a _known_ extension is not slow: Changing `largefile="$tmpdir/largefile"` in the script above to `largefile="$tmpdir/largefile.txt"` leads to nvim 0.8.0 opening the file quickly.

Discussion
- Do not use `syntax on` and `filetype on` with Neovim; they're enabled by default and not idempotent (they're commands, not options!).
- If the difference persists even without `syntax on filetype on`, this is likely due to `filetype.lua` having to check the full contents of your huge file to determine the filetype. Would be useful to profile `filetype/detect.lua` in this case (simply sprinkling `print os.time()` through the file) to see where the slowdown is and see what `scripts.vim` (which should be functionally identical) is doing differently.
