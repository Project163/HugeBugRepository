Title

Unicode being a TypeDecorated caused problems on MSSQL

Description
**Migrated issue, originally created by paj ([Link: @paj])**

testprocessing (sql.testtypes.OverrideTest) has been failing for MSSQL. On "MyUnicodeType" the user-defined convert_bind_param/convert_result_value functions aren't getting called.

The problems exists because MSSQL has it's own subclass of Unicode - MSUnicode. When adapt_types is called, it replaces the user defined MyUnicodeType with MSUnicode. This problem only happens on MSSQL, because no other DBs define their own Unicode type. Also, the problem doesn't happen with strings, because they're a TypeEngine, not a TypeDecorator.

I think the solution to this is to only use TypeEngine for built-in types. TypeDecorator is reserved for user-defined types. I realise this is a non-trivial change (it will involve changing the docs), but I think it is worth it.

I will attach a patch which is an indication of the changes I would do. This clears up some of the unit test failures it causes, although there are a few more to go. Mike, if you're ok with this in principle, I'll carry on and produce a more complete patch.
