Title

`no-unused-vars` reports global vars on wrong line

Description
Consider:

``` js
/*eslint no-unused-vars: 2*/
/*global some_used_var */

var x = 10;
```

This will give the result:

```
  4:1  error  "some_used_var" is defined but never used  no-unused-vars
  4:5  error  "x" is defined but never used              no-unused-vars
```

It's a bit of a quibble, but might it be possible to report the error for some_used_var on line 2 (where it is defined as a global) instead?
Discussion
- This would be tough, as globals can also be declared in .eslintrc as well, and we don't actually know where the global is coming from (comments are parsed before rules are executed).
- Can it just always be at the top of the file then?  `1:1` would be easier to immediately grok, I think.
- Globals in config files are omitted from `no-unused-vars`. We should be able to add a location to inline globals.
- I will try to fix this.
