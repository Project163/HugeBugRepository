Title

Lifecycle methods with wrong arguments should be treated as an error

Description

    
Discussion

    
- If an annotation is used on a lifecycle method which does not match the supported signatures, this should be treated as an error and not as a warning, e.g. 

 @Activate 
protected void activate(Object foo)
- Fixed by throwing an error if the annotation is specifed, but just a warning if not
