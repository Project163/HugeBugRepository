Title

Test using `$this->mock(Request::class)` always returning empty GET request

Description
- Laravel Version: 8.48.1
- PHP Version: 7.4.13

### Description:

In a Unit test for a Controller I mocked the request using the following;

```php
$request = $this->mock(Request::class, static function (MockInterface $mock) use ($valid): void {
    $mock->shouldReceive('validated')->once()->andReturn($valid);
});
```

Which gave a valid result until updating Laravel from 8.47 to 8.48.

It seems that the introduction of the `singletonInstance` in the commit [Link: bind mock instances as singletons so they are not overwritten] and the use of that in the `mock()`, `partialMock()` and `spy()` methods of the `InteractsWithContainer` trait. This seems to mean that an empty `GET` request is always used.

I have been able to resolve my failing tests by going back to the [Link: longer version of the code to mock an object], as found in the documentation.

```php
$request = $this->instance(
    Request::class,
    Mockery::mock(Request::class, static function (MockInterface $mock) use ($valid): void {
        $mock->shouldReceive('validated')->once()->andReturn($valid);
    })
);
```

### Steps To Reproduce:

```php
$request = $this->mock(Request::class, static function (MockInterface $mock) use ($valid): void {
    $mock->shouldReceive('validated')->once()->andReturn($valid);
});
```

returns different `$request` compared to 

```php
$request = $this->instance(
    Request::class,
    Mockery::mock(Request::class, static function (MockInterface $mock) use ($valid): void {
        $mock->shouldReceive('validated')->once()->andReturn($valid);
    })
);
```
