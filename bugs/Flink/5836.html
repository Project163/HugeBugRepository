Discussion
- This is a Kafka broker issue, probably the root cause of   KAFKA-9310  . From what I can see, it some kind of concurrency issue where the broker is just not able to write to a transaction right after another transaction was committed. 

 We could reliably reproduce the issue with Kafka broker running on 2.4.1. But where unable to see the issue on 2.5.X or 2.7.X.
