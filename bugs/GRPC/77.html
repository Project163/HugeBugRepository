Title

setting C# option `base_namespace` to an empty string results in inconsistent behavior

Description
### What version of gRPC and what language are you using?
gRPC 1.57.0, C#

### What operating system (Linux, Windows,...) and version?
NixOS 23.05 (Linux)

### What runtime / compiler are you using (e.g. python version or version of gcc)
gcc (GCC) 12.3.0

### What did you do?
I invoked `protoc` with `grpc_csharp_plugin` & `--grpc_opt=base_namespace=` option:
```sh
protoc --plugin=protoc-gen-grpc=grpc_csharp_plugin \
    --grpc_out=OUT_DIR \
    --grpc_opt=base_namespace= \
    -I INCLUDE_DIR foo.proto
```

### What did you expect to see?
Generated C# files being written in a directory structure based on the namespace.
Which is the same behavior that protoc has for its equivalent `csharp_opt`:
[URL]

### What did you see instead?
All generated C# files being written to the root directory, like `base_namespace` wasn't set at all.

### Anything else we should know about your project / environment?

I've originally reported this issue here: [URL]
Discussion
- Summary of what I already figured out in [URL]

For `csharp_opt`'s `base_namespace`, a variable [Link: `base_namespace_specified`] is set to `true` if `base_namespace` was explicitly set via the CLI. This in turn causes `GetOutputFile()` to be invoked with `generate_directories` set to `true`.

The grpc implementation invokes this new behavior only if `!base_namespace.empty()`, though, which means it'll fall back to the normal behavior even when `base_namespace` was explicitly set to an empty string.

To match the `csharp_opt` behavior, grpc should also check if `base_namespace` was explicitly set and replace the `base_namespace.empty()` check with it (e.g. `!base_namespace_specified`) in:
[URL]
