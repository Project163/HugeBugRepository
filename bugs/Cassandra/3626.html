Title

Cannot create secondary index on a table WITH COMPACT STORAGE

Description
In   CASSANDRA-8156   it is said that secondary indexes are not allowed on clustering columns in COMPACT tables. 

 However, I found that it is not possible to create a secondary index on the value column in a COMPACT table: 

 CREATE TABLE t ( 
	a INT, 
	b INT, 
	c INT, 
	PRIMARY KEY (a, b) 
) WITH COMPACT STORAGE; 

 CREATE INDEX ON t (c); 

  Bad Request: Secondary indexes are not supported on PRIMARY KEY columns in COMPACT STORAGE tables
Discussion
- I can confirm this is happening on 2.0.15.  blerer , should this be possible? If not, then it's just the error message that's wrong.
- The issue is valid.  
Our test is: 
  
  if  ((cfm.getCfDef().isCompact || !cfm.getCfDef().isComposite) && cd.type != ColumnDefinition.Type.REGULAR)
             throw   new  InvalidRequestException( "Secondary indexes are not supported on PRIMARY KEY columns in COMPACT STORAGE tables" );
 
   

 The problem is that the type of the c column is  ColumnDefinition.Type.COMPACT_VALUE  and not  ColumnDefinition.Type.REGULAR .
