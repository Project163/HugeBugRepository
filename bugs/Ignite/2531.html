Discussion
- the test is rewritten to provide statistically justified assertions.  
The values used in test are taken to achieve high reliability: the test will pass 1000 times with 95% probability.
- iveselovskiy , 
What kind of problem was addressed with the fix from application (not test) standpoint? Earlier  randomLevel  could have return values  [0..32] , now it could return  [0..64] . How does it affect application?
- vozerov  , the fix is that  org.apache.ignite.internal.processors.hadoop.shuffle.collections.HadoopSkipList#randomLevel returns value in range 0..Infinity, not 0..32 or 0..64. This makes the function correct. The point is that the returned value should not be limited . With very low probability it may return any positive number. And comprehensive statistic analysis performed in the test really reveals that: if you use old #randomLevel function (now it is called "randomLevel32"), the test will start to fail with noticeable probability.
- Original distribution looks fine, where "fine" means that follows geometrical pattern on lower levels well. The problem was more with the test itself, so I removed it, as no further changes to level distribution is planned. No need for complex math in tests for this piece of code.
