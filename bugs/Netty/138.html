Title

HttpContentCompressor / HttpResponseEncoder does not work with several HttpContent messages

Description
I'm using netty for for building a http reverse proxy.

Everything work well but when I try to I add a **HttpContentCompressor** to my "front" pipeline, I encounter a problem with big files.

For information, my pipeline is simply:

``` java
        pipeline.addLast("decoder", new HttpRequestDecoder( );
        pipeline.addLast("encoder", new HttpResponseEncoder());
        pipeline.addLast("compress", new HttpContentCompressor());
        pipeline.addLast("handler", new HttpProxyServerHandler(....));

```

When backend server send a small file (a file of 30k works), compression works well and browser  receives file correctly.
But when backend server send bigger file ( a file of 150k does not work), compression does not set Content-Length to the good zipped length and browser receives full file but wait for end of transfert...
##### Working example:

In response to a http request, from backend, proxy receives 2 objects:

**Object 2:**
