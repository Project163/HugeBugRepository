Title

JsonSlurper loses trailing 0's in numbers (regression in Groovy 2.3)

Description
In previous versions of Grails before JsonSlurper was significantly changed, this test passed. However, it fails in Groovy 2.3.x (tested up to 2.3.3). 

  
 void testParseNumWithDecimals() {
   def i = parser.parseText( '123.40' )
   BigDecimal i2 = 123.40G
    assert  i  instanceof  BigDecimal
    assert  i == i2
}
 
  
 This test should be added to  [URL]

 In Groovy 2.3.3, the assertion fails as i = 123.4G, not 123.40G.
Discussion
- Not sure I see an issue here. Can someone explain this to me?
- This is somewhat related to the changes for   GROOVY-6674   and  commit 842bcd4  that changed the decimal return types from double to BigDecimal.  The assert  assert 123.40G == 123.4G  passes and the numbers are equivalent.  However, the reduction in scale of the number might be unexpected and is different in pre-2.3 releases. 

  
 def num =  new  groovy.json.JsonSlurper().parseText( '{ "num" : 123.40}' ).num
 assert  num  instanceof  BigDecimal
 assert  2 == num.scale()   // fails: scale is 1 
 
  

 One way to fix with the least change would be to change this   lvalue#divide(java.math.BigDecimal)   to use the   #divide(java.math.BigDecimal,int,java.math.RoundingMode)   method using  digitsPastPoint  for the scale and  RoundingMode.UNNECESSARY . 

 However, I think a lot of the code is left over from when it was originally parsing to a Double.  So I think a better but bigger change would be to  replace the bulk of the parseJsonNumber method  with a call to  BigDecimal  ctor that takes a buffer, offset and length.  This would have the added benefit of eliminating the String allocations.
