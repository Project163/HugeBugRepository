Title

Problem with d3.behavior.zoom (Mac OS)

Description
The page loads, then you pan to either side and then zoom, and it throws a javascript error in console. This is strange because just today I was using zoom behavior in Windows, Chrome and (as far as I remember) it worked.

**The problem only exists if you use 3-finger trackpad gesture for dragging and don't change cursor position after panning.** Doesn't work if you drag with hard-click. So, pan with 3 fingers and try to zoom right away. Seems like d3 can't determine cursor position after dragging.

Errors
Safari: `TypeError: null is not an object (evaluating 'p[0]')` line 1228
Chrome:

```
Uncaught TypeError: Cannot read property '0' of null    d3.js:1382

translateTo    d3.js:1382
mousewheeled    d3.js:1519
(anonymous function)    d3.js:1084
```

Tested in both browsers on Mac OS.

Addition:
Recreated the same in Firefox. Firefox and Chrome are pointing to this bit of code (lines 1380-1384):

``` js
function translateTo(p, l) {
      l = point(l);
      view.x += p[0] - l[0];
      view.y += p[1] - l[1];
    }
```

Discussion
- I found the same problem here [URL]
It can be reproduced with a mouse wheel (tested on mac os x 10.9.5 and yosemite): just press and release the wheel when scrolling.
I changed the function mousewheeled:

 center0 && translateTo(center0, translate0); 

(instead of  translateTo(center0, translate0) )
Quick and dirty, but it works
- Same problem can be experienced with this vector tiles example [URL] after doing normal panning and zooming for a while. 

I noticed that in function `mousewheeled()` the variable `center0` is initialized only when  `mousewheelTimer` is falsy:

```
 if (mousewheelTimer) clearTimeout(mousewheelTimer); else translate0 = location(center0 = center || d3.mouse(this))
```

The error comes when `mousewheelTimer` is truthy,  `center0` is not initialized, but is used in `translateTo(center0, translate0)`.
- Proposed fix in #2351.
