Title

Fullscreen output incorrectly positioned on non-primary monitors in some cases

Description
I have two monitors, each 1920x1080, positioned one atop the other.  I also have a Rift device which has a native resolution of 1280x800, but which will accept input at 1920x1080 and scale it down to the physical display.  The top monitor display is cloned to the Rift, while the bottom monitor is set as my primary display.  

If I create a fullscreen window of 1920x1080 targeting the cloned Rift & top monitor, the resulting window renders correctly.  If I create a fullscreen window using the Rift's native resolution of 1280x800, the resulting output appears cropped... see image:

[Image: image]

Experimenting, I discovered that something similar happens if I place the target monitor to the left of my other display....  

[Image: image]

If I place the target monitor below or to the right of the other monitor, then the problem goes away, presumably because the desktop position of (0, 1080) and (1920,0)  respectively is correct for either resolution.

Investigating the code, I discovered that the window is created using a position culled from  _glfwPlatformGetMonitorPos (win32_window.c line 821) before the video mode is changed.  Therefore it's getting coordinates such as (-1920, 0) or (0, -1080), which aren't correct once the video mode is changed via _glfwSetVideoMode (line 953, same file).
Discussion
- Oh, it's also worth noting that the full OpenGL window is correctly displayed in the alt-tab preview view.
