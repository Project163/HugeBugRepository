Title

@storybook/client-api imports qs incorrectly

Description
**Describe the bug**
Compiling a Typescript project with a dependency on storybook produces the following build error:

../node_modules/@storybook/client-api/dist/queryparams.d.ts:1:8 - error TS1259: Module '"..../node_modules/@types/qs/index"' can only be default-imported using the 'allowSyntheticDefaultImports' flag

1 import qs from 'qs';
         ~~

  ../../node_modules/@types/qs/index.d.ts:13:1
    13 export = QueryString;
       ~~~~~~~~~~~~~~~~~~~~~
    This module is declared with using 'export =', and can only be used with a default import when using the 'allowSyntheticDefaultImports' flag.

**To Reproduce**
Steps to reproduce the behavior:

See above error while compiling a typescript project with @storybook.

**Expected behavior**
The import is correctly used and consuming projects are not asked to add a compiler flag to compensate.

- @shilman Hello! Thank you for reading this issue.

@storybook/client-api/queryparams.ts imports qs to use the func parse. Qs does not have a default export, the following should work fine:

import { parse } from 'qs';   <--- If you want to just use the parse func, as is the case right now. This change requires the usage to change from 'qs.parse(...)' to 'parse(...)'

or

import * as qs from 'qs'; <--- If you want to import all funcs in qs and use qs as-is
