Title

Export { x } from ... doesn't generate variable declaration

Description
Using v2.10.2, re-export statements in the fashion of `export { x } from ...` or `export { x as y } from ...` results in nodes that have `declaration: null`. I'm not well-versed enough with how the parsing is done to know if these statements would make sense having a declaration (since they don't declare variables the same way a `export var x = y` would do), but this lack of a declaration breaks rules that assume it'll be there (ie. [Link: vars-on-top]).

Running ESLint with `vars-on-top` will throw an exception on this file:

``` js
export { default } from 'your-package';

var test = 'bad';
```

Exception:

```
js
Cannot read property 'type' of null
TypeError: Cannot read property 'type' of null
    at isVarOnTop (.../node_modules/eslint/lib/rules/vars-on-top.js:69:50)
    at globalVarCheck (.../node_modules/eslint/lib/rules/vars-on-top.js:87:18)
... [Log Snipped] ...
    at Controller.traverser.traverse.enter (.../node_modules/eslint/lib/eslint.js:886:36)
    at Controller.__execute (.../node_modules/estraverse/estraverse.js:397:31)
```
