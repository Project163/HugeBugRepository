Title

ESLint crashes on non-existing file

Description
When passing non-existing file to ESLint, you get a crash with a stack dump. I know that was changed in #1400 But the code hasn't been cleaned up correctly. CLIEngine has an else statement that kicks in when file doesn't exist, which is never hit. Either that else statement has to be removed or #1400 should be reverted and original code should be fixed (in original code, catch was just returning, when it really should call callback function and let CLIEngine handle error message).
Discussion
- Can you paste in the console output when this happens?
- ```
$ eslint -v
v0.14.1

$ eslint blah.js

... [Log Snipped] ...
    at Module._compile (module.js:456:26)
    at Object.Module._extensions..js (module.js:474:10)
```
- This is the expected behavior. In #1296 we discussed this and agreed that it should throw before linting.

But you are right, that the code wasn’t cleaned up completely, the `else` branch wasn’t removed. Seems like there was no test for this branch, because no test was failing.

I don’t agree that we should revert to the old behavior. The old behavior doesn’t prevent linting of other files.
- Let's just remove the `else` then and maybe add a comment to say an error will be thrown when a for doesn't exist?
