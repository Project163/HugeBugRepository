Title

Nettty must not use unreliable and time consuming logic to compute channel id by default

Description
DefaultChannelId implementation is overkill and uses unreliable and time consuming NetworkInterface.\* methods. DefaultChannelId initialization could take up to _7_ minutes. 

See [URL]

And after IDEA 13.1 release a lot of users experience very slow compilation due to Netty. See [URL] and related issues.

I don't understand why java.util.UUID is not enough. And I think in a lot of applications globally unique channel ID is not required.

- It seems like this is related with `-Djava.net.preferIPv4Stack=true` option.
