### Description

Somehow typescript loses `@types/*` types on second+ angular app rebuild. It works fine on devserver start, first rebuild and on build command.
We faced this for `require` and some webpack typings in our apps after update ng9 -> ng10.

## 🔬 Minimal Reproduction

- clone [URL]
- open app.component.ts
- start dev server
- no errors
- trigger rebuild (e.g. add comment)
- no errors
- trigger second rebuild
- see type error

Adding `types: ['node']` solves `require` type error, but you need to add all `@types/*` packages for big projects. `@types/*` should work fine without any additional actions.

Discussion
- I was able to replicate this using NGC directly `ngc tsconfig.app.json --watch` hence I am transferring this to the FW for a better triage.
- Confirming as reported, it's indeed a bug in ngtsc (the Ivy compiler).

The issue occurs due to how template type checking is done; a `ts.CompilerHost` is created to expose the type check files:

[URL]

This host does not implement all optional methods, one of which is `directoryExists`, so that `@types` discovery does not trigger here. This type check program is then reused for the the next compilation, resulting in the primary emit program from also missing these types (I think because module resolution results were reused).

In ngc I'm seeing every other compile to fail, as the failure throws away any reuse program as it's deemed invalid. This allows the next compilation to succeed again. I didn't test with the CLI but it may not show that behaviour and always fail instead.
