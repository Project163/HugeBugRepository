Title

IsEquivalent on default ImmutableArray throws exception.

Description
NUnit version 3.13.0

An ImmutableArray is a structure, but can contained a null array.
The following test fails with an InvalidOperationException: _This operation cannot be performed on a default instance of ImmutableArray _

```
ImmutableArray  expected = ImmutableArray.Create("Test");
ImmutableArray  actual = default(ImmutableArray );

Assert.That(actual, Is.EquivalentTo(expected));
```

Same for `Assert.That(actual, Is.Not.Empty);`

It is a pity that Microsoft doesn't treat this the same as `ImmutableArray .Empty`.
Discussion
- It is a bit unfortunate that we need to have special cases for all these structures, but I think we should also handle this.
- Agreed, this is unfortunate.
Should `default(ImmutableArray )` be treated as semantically equivalent to `Empty` or to `null`? NUnit makes a distinction between these for reference-type collections:

```csharp
string[] expected = Array.Empty ();
string[] actual = null;
Assert.That(actual, Is.Not.EqualTo(expected));
```

Though I would also find it unusual for the following test to pass:

```csharp
Assert.That(default(ImmutableArray ), Is.Null);
```

I wonder if this is case solved via a DefaultConstraint (https://github.com/nunit/nunit/issues/3457) ?
