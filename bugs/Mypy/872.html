Title

Crash following a class-level import

Description
Sample code:

```
python
# a.py
def meth(self, x: int) -> int:
    return 2 * x

... [Log Snipped] ...
foo = Foo()
print(foo.meth(10))
```

Using latest mypy master (last release also crashes, though with a different traceback):

```
~/src/mypy$ mypy /tmp/b.py --show-traceback
/tmp/b.py:5: error: INTERNAL ERROR -- Please try using mypy master on Github:
[URL]
Please report a bug at [URL]
version: 0.720+dev. 
... [Log Snipped] ...
AssertionError: FuncBase for non-methods lack info
/tmp/b.py:5: : note: use --pdb to drop into pdb
```

(Yes this is silly. I have a class where some methods are hand-written and some are output by a code generator, so the idea is that `a.py` is generated and then `b.py` assembles the generated and hand-written bits together into a class.)
Discussion
- This still crashes on master. The situation is quite rare however, so setting priority to normal.
- Ok, I experienced the same issue and found a workaround.
Instead of using from directly inside class declaration, I added a member to the class, so b.py changes to something like this:

```
import a

class Foo:
    meth = a.meth

foo = Foo()
print(foo.meth(10))

```
In this way I can declare functions for the same class across multiple modules and keep mypy happy.
This adds imports and not so nice looking boilerplate code, but if you need to split class code across multiple sources files and use mypy this seem a decent solution.
