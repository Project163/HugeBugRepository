Title

@InjectSpy causes smallrye unable to find config

Description
### Describe the bug

I upgraded from `3.21.1` to `3.24.0.CR1` and I get the following config error when I run the `SpyTest` test from the [Link: reproducer]

```
[ERROR] Tests run: 1, Failures: 0, Errors: 1, Skipped: 0, Time elapsed: 0.370 s <<< FAILURE! -- in gr.SpyTest
[ERROR] gr.SpyTest.shouldRun -- Time elapsed: 0.005 s <<< ERROR!
org.junit.jupiter.api.extension.TestInstantiationException: Failed to create test instance
	at io.quarkus.test.junit.QuarkusTestExtension.initTestState(QuarkusTestExtension.java:805)
	at io.quarkus.test.junit.QuarkusTestExtension.interceptTestClassConstructor(QuarkusTestExtension.java:777)
... [Log Snipped] ...
	at io.quarkus.test.junit.QuarkusTestExtension.initTestState(QuarkusTestExtension.java:802)
	... 4 more
```

```
java
@QuarkusTest
public class SpyTest {

    @InjectSpy
... [Log Snipped] ...
    }
}
```

Is also seems that if you add a simple test which does not use the `@InjectSpy` both tests will pass.

```java
@QuarkusTest
public class NoSpyTest {

    @Inject // it does not use InjectSpy
    ProjectConfig projectConfig;

    @Test
    public void shouldRun() {
    }
}
``
Discussion
- In my project (not the reproducer), the tests that fail with the same error, use `@TestProfile` and does NOT use `@InjectSpy` or `@InjectMock`. The ones that also use `@TestProfile` but also use `@InjectSpy` or `@InjectMock` are NOT failing.

That's why originally I reported that at [URL]

For some weird reason, if the tests which does not use the `@InjectSpy` or `@InjectMock` run on different TestProfile than the tests that use the mocks, all test pass.

So the following tests are failing because they are on the same `@TestProfile`

```
java
@QuarkusTest
@TestProfile(ProfileA.class)
class ATest {} // this fails

... [Log Snipped] ...
  @InjectSpy ProjectConfig;
}
```

So the following tests are not failing because they are on the different `@TestProfile`.

```
java
@QuarkusTest
@TestProfile(ProfileB.class)
class ATest {} // this pass

... [Log Snipped] ...
  @InjectSpy ProjectConfig;
}
```

I do hope this give you more clues.
- Despite that fact that I understand what you are trying to do (i.e. mock / spy a `@ConfigMapping` bean), while also being completely aware of the fact that we don't provide any real solution, the fact that it worked in previous versions was purely accidental.
- ... [Middle Discussions Snipped for Brevity] ...
- @gbourant okay, so it turns out that all you need to make your code work is to add `@Unremovable` to `ProjectConfig`
- I've added the `@Unremovable` and I still get the same issue.

```java
@Unremovable
@ConfigRoot(phase = ConfigPhase.BUILD_AND_RUN_TIME_FIXED)
@ConfigMapping(prefix = "project")
public interface ProjectConfig {}
```

```java
@QuarkusTest
@TestProfile(FastestTestProfile.class)
@WithPlaywright(browserContext = @BrowserContextConfig(defaultTimeout = "PT2s", defaultNavigationTimeout = "PT2s"))
public class InputTextTagTest {}
```

If I just run the `InputTextTagTest` alone, it passes. If I run `mvn clean test` on the project level it does not. That's why I'm thinking it has to do something with `@TestProfile`. Other tests has the `@TestProfile(FastestTestProfile.class)` as well which some of them use mock and others does not.

Well maybe it has to do with [Link: quarkus-playwright] which uses Quarkus 3.15.3.

Also if I create an exact copy of  `FastestTestProfile` with just different name and use it at `InputTextTagTest` then run `mvn clean test` on project level, it passes. (even without `@Unremovable`)
