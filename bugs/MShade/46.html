Title

Multiple executions: second eats output of first

Description
this may just turn into a doc issue. 

 I tried to add a second 'less shaded' execution to my pom. The first execution was set up to replace the main artifact. Sure enough, the shaded output of the first went into the second. 

 I suppose that I'll have to make sure that both use classifiers so that the main artifact is left around for the second, but some notes in the doc might have saved me some confusion.
