Title

Test: ClientYamlSuiteRestApiParser cannot parse test specs without parts that require a body

Description
The api json file parser seems to not correctly parse spec files that do not have any path parameters but have the `body` field set and required.

This test (added in `ClientYamlSuiteRestApiParserTests`) fails

```
java
    public void testRequiredBodyWithoutUrlParts() throws Exception {
        String spec = "{\n" +
            "  \"count\": {\n" +
            "    \"documentation\": \"whatever\",\n" +
... [Log Snipped] ...
        assertThat(restApi, notNullValue());
    }
```

fails with

```

java.lang.AssertionError: Expected [END_OBJECT] but was [null]

	at __randomizedtesting.SeedInfo.seed([ :BDED9C135058595]:0)
	at org.elasticsearch.test.rest.yaml.restspec.ClientYamlSuiteRestApiParser.parse(ClientYamlSuiteRestApiParser.java:155)
	at org.elasticsearch.test.rest.yaml.restspec.ClientYamlSuiteRestApiParserTests.testRequiredBodyWithoutUrlParts(ClientYamlSuiteRestApiParserTests.java:110)
```
Discussion
- small update: adding an emtpy `"parts" : {}` makes this test pass.

```
String spec = "{\n" +
            "  \"count\": {\n" +
            "    \"documentation\": \"whatever\",\n" +
            "    \"methods\": [ \"GET\", \"POST\" ],\n" +
            "    \"url\": {\n" +
... [Log Snipped] ...
            "  }\n" +
            "}";
```

I'm good with closing this then as well.
- Also it seems, that if you include a `params` part, parsing works, as done in [URL] and [URL] - which both also contain a `body` part
- Pinging @elastic/es-core-infra
