Discussion
- After adding the one above-mentioned dependency to yarn's dependency injection, I've encountered several other missing ones.
I've been able to hotfix it by:
- changing the command to: `yarn tauri icon ./icon.png --compression="zopfli" --log`
  - which means that the site docs are not in sync with the actual command 
- adding the following to `.yarnrc.yml`, but that's a dirty solution… you should declare those yourselves:
    ```
yml
    packageExtensions:
      "@tauri-apps/cli@*":
        dependencies:
          graceful-fs: "^4.2.6"
... [Log Snipped] ...
          replace-ext: "^2.0.0"
          junk: "^3.1.0"
```
- `graceful-fs` is a nested dependency of some of `@tauri-apps/cli` dependencies, we don't have control over that. 

And yarn2 has issues with some of npm packages and don't think yarn3 is any different.
- ... [Middle Discussions Snipped for Brevity] ...
- Without going to a full change of package manager, perhaps an intermediary solution would be to setup a cron GitHub Action job that would periodically run a quick test using Yarn 2? Something simple, like running --version on your CLI or such.

It wouldn't notify you on PRs, but it's low effort and should notify you fairly fast if something happens (we actually do that on our side as well, just to be kept updated about potential compat issues in the ecosystem).
- It is not that we don't want to support yarn2, we just have much higher priority tasks right now so unless someone wants to fix this issue and make a PR, this is gonna have to wait.
And in the future we are most likely gonna re-write the `tauri icon` command in rust (don't worry, you can still use `tauri icon` with the npm packge, it will just forward it to our rust cli).
