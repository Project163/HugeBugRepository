Title

Mapping Enum to string - default enum value get mapped to null

Description
In AutoMapper 5.2, the mapping fails when map from a enum to a string and the enum value is set to the first/default value in enum.

Here is a example: Want to map _ProfileInfoDto_ **->** _ApiProfileInfo_.  _ProfileInfoDto_ contains a enum property called _Type_, in destination (_ApiProfileInfo_) this property is a string.
If we set input to enum value _Guest_ the destination string is "Guest" as expected. **But** if we set the input enum to _User_ (first value in enum) the destination string is **null**. 

This seems to be a bug due i expect the value to be "User" and this is how its works in 4.x of AutoMapper.


Here is a code test example:

    public enum ProfileType
    {
        User,
        Guest
    }
    public class ProfileInfoDto
    {
        public string Name { get; set; }
        public ProfileType Type { get; set; }
    }
    public class ApiProfileInfo
    {
        public string Name { get; set; }
        public string Type { get; set; }
    }
    class Program
    {
        static void Main(string[] args)
        {
            MapperConfiguration config = new MapperConfiguration(c =>
            {
                c.CreateMap ();
            });
            var mapper = config.CreateMapper();
            var rGuest = mapper.Map (new ProfileInfoDto() {Name = "My Name", Type = ProfileType.Guest});
            var rDefault = mapper.Map (new ProfileInfoDto() { Name = "My Name", Type = ProfileType.User });
            Debug.Assert(rGuest.Type == "Guest");
            Debug.Assert(rDefault.Type == "User"); // This fails due to rDefault.Type is null, expected its to have the toString value
        }
    }
