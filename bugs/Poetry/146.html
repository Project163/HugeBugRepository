Discussion
- Same here with zsh

```
$ poetry env activate

Discovered shell doesn't have an activator in virtual environment
```
- What would be the behavior you expect? I don't get the issue. You are trying to activate a virtualenv that doesn't exist. 

What makes you say that? Does it work differently in Powershell?
- IMO the message is misleading. It should be something like "Theres no venv yet. Create one before using this command". Not sure if can distinguish between "there is no venv" and "you shell is not supported"?

The `poetry shell` command created a venv upon calling. Don't know if an `poetry env activate` should do it as well. 🤷
- You are absolutely right that this message is misleading. 

The problem is that the env is already created using for example "poetry install" and every other or most poetry commands like "poetry add" work on that environment implicitly even without calling the "poetry env use" command except for the "poetry env activate" which responds with that message instead of providing the command for activating the environment. 

The question that arises for me is why does one command need an implicit usage of the environment while the other doesn't.
