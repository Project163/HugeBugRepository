Title

Cursor mode not applied unless window is focused

Description
If you call glfwSetInputMode and change an unfocused window's cursor mode, it currently does update the window's cursorMode member but doesn't call _glfwPlatformSetCursorMode for that window. So, at least on OS X, this breaks setting the cursor mode to either hidden or disabled. The trouble is with the last line of setCursorMode where it assigns the new cursor mode but skips everything else if the window isn't focused.

A possible solution to this might be to move the call to _glfwPlatformSetCursorMode out of the block for focused windows and have each implementation of it check if the window is focused and do the appropriate thing (except in the case of disabled, where it's just not multi-window-friendly at all). Otherwise we end up in a situation where the cursor mode is set to something but the platform implementation never does its thing to update the cursor mode.

I'd submit a patch for this, but I'd rather discuss any possible solution first and what appropriate behavior should be for setCursorMode. If setCursorMode updates the cursorMode member but doesn't call the platform function, then should a flag be set to have the platform function called later or how should that work?
Discussion
- The solution used on other platforms is to call the relevant platform-specific cursor mode code when the window regains focus. I'll try to apply this solution to the Cocoa port.
