Title

NoSuchRemoteClusterException is returned for both non-existent remotes and remotes with skip_unavailable=true

Description
### Elasticsearch Version

8.14-SNAPSHOT

### Installed Plugins

_No response_

### Java Version

_bundled_

### OS Version

Darwin michaels-mbp.lan 23.4.0 Darwin Kernel Version 23.4.0: Fri Mar 15 00:10:42 PDT 2024; root:xnu-10063.101.17~1/RELEASE_ARM64_T6000 arm64

### Problem Description

When doing cross-cluster searches (`_search` or `_async_search`), `NoSuchRemoteClusterException` is returned for both non-existent remotes and remotes with skip_unavailable=true that cannot be connected to. By contrast, remotes with skip_unavailable=false return a "connection_exception" error message when they cannot be reached.

Should we also be returning "connection exception" errors for skip_unavailable=true remotes? Should NoSuchRemoteClusterException be reserved for attempts to search clusters that are not configured?

This issue occurs for both non-secured and secured clusters. See the "Steps to Reproduce" section for details.

### Steps to Reproduce

Manual testing. Configure a cluster to connect to two remote clusters. In my case, the three clusters all run on the same local machine and the config on the primary looks like:

```
cluster:
    remote:
        remote1:
            seeds:  :9301
            skip_unavailable: true
        remote2:
            seeds:  :9302
            skip_unavailable: false
```
