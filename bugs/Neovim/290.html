Title

`vim.split` trims from first split instead of only the ends

Description
### Problem

Starting from 9c49c10, the behavior of `vim.split` got changed. It can be explained best using the following examples:

```
lua
-- This works as expected
vim.split("\nfirst\n\n\n\nsecond\n\nthird", "\n", { trimempty = true })
-- { "first", "", "", "", "second", "", "third" }

... [Log Snipped] ...
vim.split("first\n\n\n\nsecond\n\nthird", "\n", { trimempty = true })
-- { "first", "second", "", "third" }
```

I can confirm that this behavior doesn't occur in the parent commit (3285cd6).

This also means that the stable version (`v0.9.0`) contains this bug as well.

### Steps to reproduce

1. `git checkout 9c49c10`
2. `make`
3. `VIMRUNTIME=runtime ./build/bin/nvim`
4. Run the above mentioned examples
5. `git checkout 3285cd6`
6. Follow stps 2-4

### Expected behavior

Expected `vim.split` to trim only at either ends and not at the first split occurrence.

### Neovim version (nvim -v)

NVIM v0.9.0-dev-1264+g9c49c1047

### Vim (not Nvim) behaves the same?

no, does not provide `vim.split`

### Operating system/version

macOS 13.3.1

kitty 0.28.0

xterm-kitty
