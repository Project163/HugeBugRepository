Title

Clean up netty worker/thread pool configuration

Description
Refer to  [URL]
 
 "server instanceof HRegionServer" will be true for both HMaster and HRegionServer classes, hence it seems we are only using "hbase.netty.worker.count" essentially during both master and regionservers Netty server initialization. "hbase.netty.eventloop.rpcserver.thread.count" is used for bunch of other implementations of Server interface (used in UTs only)
Discussion
- vjasani  Do you have a recommendation here?
- Let me spend some time for this (next week mostly) because it seems we are not even using "hbase.netty.eventloop.rpcserver.thread.count" for production usecase. First thing, we should clean up this config, it's just making things more confusing. Secondly, we can replace all of it's usages in test code to use "hbase.netty.worker.count" instead. 

 From first glance, this doesn't seem to be overwhelming cleanup but it might turn out to be. With cleanup, will have to test this on real test cluster as well. Good thing is, this is not blocker for 2.4.14 or 2.5.0 releases. It's just that this causes misunderstanding for readers, so yeah definitely worth cleaning up. But before that, I would like to check the history as well.
