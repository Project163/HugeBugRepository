Title

Column's nullable property derived from Mapped annotation is not copied

Description
### Describe the bug

According to the [Link: docs], `mapped_column()` derives nullability from the `Mapped` annotation if `nullable` argument is not specified.

In this case, `Column._user_defined_nullable` remains `NULL_UNSPECIFIED`.

It appears that `Column.copy()` ignores the actual `nullable` property of the original column, but only uses `_user_defined_nullable`:
[URL]
The new column's constructor sets `nullable` as if it wasn't specified (usually `True`).

### To Reproduce

```
python
from sqlalchemy.orm import Mapped, mapped_column, registry


mapper_registry = registry()
... [Log Snipped] ...
print(repr(column_copy))  # Column('name', String(), table=None)
print(column_copy.nullable)  # True
```

### Error

No errors produced

### Versions

- Python: 3.10.2
- SQLAlchemy: 2.0.0b1 (f55ae66)

### Additional context

This impacts alembic migrations autogen, causing `nullable=True` being set on mapped columns that are not `Optional`.
