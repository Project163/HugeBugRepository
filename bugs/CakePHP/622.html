Title

3.0 ORM Subquery not working correctly

Description
This relates to my previous issue #4484 which was unable to reporuduce.

I have following setup:
[Image: image]

``` PHP
$article = $this->Articles->get(1,  [
    'contain' => ['Categories' => ['Tags']]
]);
```

The `$article->category->tags` property is not empty in the testing however in the production it is. The reason is that the `SQL query` is wrong, but in test where everything has ID = 1 it works.

This is from DebugKit:

```
SQL
SELECT TOP 1 Articles.id AS [Articles__id], Articles.category_id AS [Articles__category_id], Articles.title AS [Articles__title], Articles.color_id AS [Articles__color_id], Categories.id AS [Categories__id], Categories.title AS [Categories__title] 
FROM articles Articles 
LEFT JOIN categories Categories ON Categories.id = (Articles.category_id) 
WHERE Articles.id = 1
... [Log Snipped] ...
  LEFT JOIN categories Categories ON Categories.id = (Articles.category_id) WHERE Articles.id = 1
) Articles ON CategoriesTags.category_id = (Articles.id)
```

As you can see in the second query in the end there is `CategoriesTags.category_id = (Articles.id)` which doesn't seem to be correct. I was able to simulate this with fresh installation of cake. ~~If you need I can share this project, I think you should be reproduce it.~~ Below is my testing repo. So the problem is it works when testing because `category id = 1` and `article id = 1`.

The other thing that frustrates me is: can we rely on the unit testing? Because there are probably all the database IDs set to 1 and they might return good results even if the query is not correct.
