Title

WebdavFileObject.isCurrentFile fails if response.getHref returns just the path.

Description
WebdavFileObject checks the returned list of children to exclude the current directory from the list of children. This fails with Oracle XML DB as it only returns the path and does not include the protocol, host and port.
Discussion
- isCurrentFile now checks for just a matching path in addition to a full match.
- Fix validated
- ... [Middle Discussions Snipped for Brevity] ...
- I can confirm that this is still a bug, talking to a Milton WebDAV Server. 
The code 
  
      private   boolean  isCurrentFile( final   String  href,  final  URLFileName fileName)
    {
         String  name = hrefString(fileName);
         if  (href.endsWith( "/" ) && !name.endsWith( "/" ))
        {
            name +=  "/" ;
        }
         return  href.equals(name) || href.equals(fileName.getPath());
    }
 
  
 I had the case where in the last line: 
 
	 name is the complete URL 
	 href is the relative URL with a trailing slash, and 
	 fileName.getPath() returns the relative path  without  the trailing slash 
 

 thus the method returns false where it should return true.
- Oh, and this also breaks 
  
 org.apache.commons.vfs2.FileObject.deleteAll()
 
  
 which is quite a pain. 
This does not only affect OS/X obviously, my tests are under Windows 8.1
