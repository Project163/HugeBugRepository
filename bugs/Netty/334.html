Title

Throw TooLongFrameException instead of using fireExceptionCaught

Description
It's not always the case that there is another handler in the pipeline.
In the DelimiterBasedFrameDecoder the fail method at [URL] uses ctx.fireExceptionCaught.

It'd be more convenient if the exception was just thrown normally so that a sub class proxying the decode method can catch this exception. At the very least, make the fail method protected so that a sub class can override it.
Discussion
