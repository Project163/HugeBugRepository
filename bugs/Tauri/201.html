Title

[bug] Panic while firing menu event when window is minimized on macOS.

Description
### Describe the bug

Selecting a menu (e.g. `Open...`) when a window is minimized in macOS causes the application to panic.

### Reproduction

1. Use the template with the default selected.

```sh
npx create-tauri-app
```

2. `src-tauri/src/main.rs`:

```
rust
use tauri::api::dialog;
use tauri::{CustomMenuItem, Menu, Submenu};

fn main() {
... [Log Snipped] ...
        .expect("error while running tauri application");
}
```

3. Launch that app and minimize its window.

4. Select `Open...` from the Window menu.

```sh
npx tauri dev

thread 'main' panicked at 'called `Option::unwrap()` on a `None` value', $HOME/.cargo/registry/src/github.com- /tauri-runtime-wry-0.3.5/src/lib.rs:130:40
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace
```

### Expected behavior

Do not fire CustomMenuItem events when the window is minimized.
Or implement `window.isMinimized()` so that the developer can detect the state of window minimization.
