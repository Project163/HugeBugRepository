   PDFBOX-2939  : assume an empty glyph if 1 contour and -1 end point index
- That tt font is broken according to the MS Font validator, but in a specific way: the glyph has one contour, and that one has as index of the last point -1 (read as 65535). We'll just treat this as no contours. It would be nice to hear what device/software created that PDF.
- Thanks for looking into this. The pdf was created with Tesseract OCR.  [URL] version 3.03 
Tesseract version 3.03 creates pdf files from images and embeds the OCR text in the pdf. 
Tesseract 3.03 ships e.g. with Ubuntu (apt get install tesseract-ocr). It's quite handy because it lets you create OCR'rd pdf files from the command line.
- Thanks. I found the place where the font is created (GlyphLessFont.c), and I couldn't find the place where the wrong ffff is created. However, there is a comment "Significant change to invisible font system" suggesting that it had been changed recently, so I won't raise the problem there for now.
