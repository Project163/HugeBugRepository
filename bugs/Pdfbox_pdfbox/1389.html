Discussion
- Your file is broken. With NOTEPAD++, press CTRL-G and go to character offset 2515690 and you will see a lot of NUL bytes. This is a compressed stream, so obviously it shouldn't have hundreds of identical bytes. PDFBox doesn't survive this. In 2.0, the first problem is that a number is too long and that the pushback buffer isn't big enough; the second cause is that a bad object stream results in the whole PDF being aborted. I don't know if we can make that "lenient", because we also need preflight to detect such files as incorrect.
