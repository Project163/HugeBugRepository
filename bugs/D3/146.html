Title

selection.append seems case-sensitive (non-svg)

Description
See [URL]

Appending some "th" / "TH" elements, I noticed they seem to get added ok whatever the case, but then don't get picked up by either .selectAll("TH") or .selectAll("th") if originally appended using uppercase - "TH". The styling's different too even though the inspector says they're th elements. They do get picked up using .selectAll("*")

Elements I add directly as "TH" using document appendChild are picked up ok by d3's .selectAll. So are hard-coded upper case "TH" elements in HTML.

I'm seeing this in chrome 48 / firefox 43 / opera 34

These aren't inside SVG elements so it's not the webkit camelcase issue that's been reported in the past.

Am I missing something obvious (I wouldn't be surprised)?
Discussion
- Nice catch. I’m kind of amazed this hasn’t been reported before, but my guess is that most people have been passing lower-case names to _selection_.append.

The problem here is an interaction between [Link: document.createElement],  [Link: document.createElementNS] and _selection_.append. According to the spec, createElement has special behavior on HTML documents:

This behavior does not apply to createElementNS. And, since _selection_.append inherits the namespaceURI from the parent element, it almost always uses createElementNS, even for HTML documents. So, when you append th elements, instead of creating them like so:

```
document.createElement("th");
```

It is using this:

```
document.createElementNS("[URL] "th");
```

So, if you say "TH" rather than "th", it creates the wrong element type (and hence why the table doesn’t render correctly). Confusingly, though, the DOM spec actually _upper-cases_ tag names when you inspect them via _element_.tagName, so it’s not immediately obvious that something went wrong. However, if you pull out the body innerHTML, you can see the top row is unusual:

```
html
 
   
       HEY  YOU  
      WHO  ME  
... [Log Snipped] ...
    
 
```

The fix here is probably to have D3 lower-case the specified element name if the namespace is XHTML. Alternatively, D3 could use document.createElement rather than document.createElementNS if the parent element’s namespace matches the document element’s namespace. The latter should be equivalent, though perhaps slightly more general.
- Fixed in 3.5.14.
