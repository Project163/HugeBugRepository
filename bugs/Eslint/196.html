Title

eslint crashes when looking for eslintrc in unreadable directory

Description
(Using 0.9.2)
If eslint encounters a directory that it cannot read when searching for eslintrc, then eslint will crash because fs.readdirSync throws an exception. For example, this happens with flycheck in emacs with pam_tmpdir (since flycheck saves the file to a temporary directory, and pam_tmpdir manages secure per-user temporary directories), but I suppose this could also happen if the user only has execute permissions on /home.

- As far as I can tell, there are two behaviours that would be acceptable:
1. give up looking for eslint, under the assumption than if the user can't read the directory, they don't own any of the ancestors, so there probably won't be a valid eslintrc to find.
2. (this is what my proposed patch does) ignore the unreadable directory, and keep traversing up the directory tree
