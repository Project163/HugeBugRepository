Title

Default Content-Type charset is not always considered

Description
**Describe the bug**
Sending an HTTP request with `Content-Type: application/json;charset=UTF-8` doesn't encode the body as UTF-8.

**To Reproduce**
Steps to reproduce the behavior:
1. Send a request containing only ASCII characters in the JSON body

    Open Tools -> "Manual Request Editor", enter the following header and body, then click "Send"
    
    ```
    POST [URL] HTTP/1.1
    Content-Type: application/json;charset=UTF-8
    
    {"id": 10, "name": "doggie", "photoUrls": ["string"]}
    ```
    
    Response: HTTP 200


2. Send a request containing non-ASCII characters in the JSON body 

    Open Tools -> "Manual Request Editor", enter the following header and body (note that the "o" was replaced with a degree symbol "°"), then click "Send"
    
    ```
    POST [URL] HTTP/1.1
    Content-Type: application/json;charset=UTF-8
    
    {"id": 10, "name": "d°ggie", "photoUrls": ["string"]}
    ```
    
    Response: HTTP 400
    
    Inspecting the request via the "History" tab shows the following request was sent, the degree symbol was not correctly encoded:
    
    ```
    POST [URL] HTTP/1.1
    Content-Type: application/json;charset=UTF-8
    Content-Length: 53
    Host: petstore3.swagger.io
    
    {"id": 10, "name": "d�ggie", "photoUrls": ["string"]}
    ```


3. And now the weird part

    From "History" tab select the failed request, right click, select "Open/Resend with Request Editor...". In the opened "Manual Request Editor" dialog enter the header and body from 2. again, then click "Send"
    
    ```
    POST [URL] HTTP/1.1
    Content-Type: application/json;charset=UTF-8
    
    {"id": 10, "name": "d°ggie", "photoUrls": ["string"]}
    ```
    
    Response: HTTP 200
    
    Inspecting the request via the "History" tab shows that this time the degree symbol was now correctly encoded. Also note the changed Content-Length from 53 to 54 due to the correct encoding.
