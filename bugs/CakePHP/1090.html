Title

Router::reverse() fails for routes with ->setPass()

Description
### Description

In my routes.php I have a route like this one:

```
$builder->connect('/articles/{slug}', ['controller' => 'Articles', 'action' => 'view'])->setPass(['slug']);
```

Because of the `->setPass(['slug'])` the slug is listed twice in `$this->getRequest()->getAttribute('params');` which is the desired behaviour, i guess:

```
[slug] => testslug
[pass] => Array
(
    [0] => testslug
)
```

However, this causes problems when using `Router::reverse($this->getRequest()->getAttribute('params'))`, because the router class says that no route is matching. When i change my aforementioned route to ...

```
$builder->connect('/articles/{slug}/*', ['controller' => 'Articles', 'action' => 'view'])->setPass(['slug']);
```

... it creates the route `/articles/testslug/testslug`. So i think `Router::reverse()` or actually the underlying `Router::reverseToArray()` needs to handle things a little differently when using `->setPass()` when defining a route.

Same behaviour in CakePHP 3 and 4.

### CakePHP Version

3.9.6 AND 4.3.1

### PHP Version

7.4
