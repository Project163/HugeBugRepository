Title

SplitChunksPlugin crash when optimization.splitChunks.maxSize is set

Description
**Bug Report**

**What is the current behavior?**

This behavior varies depending on the packages being splits, as well as the maxSize and minSize that are set. I'm able to consistently avoid problems by setting minSize to 0. The larger I set it, the more likely it is for a problem to occur.

Yes, I confirmed that setting this option also avoids the crash:
`defaultSizeTypes: ['javascript', 'unknown']`

Rather than setting that, I'm now working around this by placing all my css into a different group with a higher priority and I've confirmed it works.

```
appStyles: {
    test: /.css/,
    priority: 99
},
```
- Yeah seems a bug that happens when a group is too big and too small at the same time.
- So I looked at the loop that's crashing:

and changed it a little bit to see what's causing the error:

```
js
while (isTooSmall(rightSize, minSize)) {
	if (group.nodes[right]) {
		addSizeTo(rightSize, group.nodes[right].size);
	} else {
... [Log Snipped] ...
```

and sure enough, this is what I got in logs:

```
js
{
  "minSize": {
    "javascript": 20000,
    "unknown": 20000,

```

So the issue here is that css/mini-extract rightSize didn't reach minSize and the loop kept looping over group.nodes below index 0.

A fix as simple as 

```diff
-				while (isTooSmall(rightSize, minSize)) {
+ 				while (right && isTooSmall(rightSize, minSize)) {
```

fixed the issue.
