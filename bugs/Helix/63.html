Title

Crash opening a non-existent Erlang file with ErlangLS

Description
### Summary

Opening an Erlang file that does not exist crashes Helix. This appears to be caused by a bug in ErlangLS itself which causes the language server to crash because the file fails to open with `enoent` but Helix should probably attempt to handle language server shutdown gracefully.

As a workaround, one can `touch` the file before attempting to open it.

### Reproduction Steps

```
hx f.erl -vv
```

With `f.erl` not existing and `erlang_ls` installed.

Discussion
- The crash comes from here: [URL]

I suspect we may be able to silently discard the error in case of failure here?
- It looks like the problematic line from the log is this one

```
2022-05-14T17:47:14.486 helix_lsp::transport [INFO] <- {"error":{"code":-32001,"message":"Unexpected error while textDocument/didOpen"},"id":null,"jsonrpc":"2.0"}
```

where `id` is `null`.

So we try to remove `Null` from the pending requests which I imagine doesn't exist. I'm not sure if this is valid in the LSP spec but it should be easy to fix within helix to prevent the panic.
