Title

Use of reducing step in choose()

Description
gremlin> g.inject(1).choose(is(1), constant( true ), constant( false ))
==> true 
gremlin> g.inject(1).choose(is(1), fold(), constant( false ))
==>[1]
 
  

 But if I put some reducing step in the branch that's not supposed to be emitted: 

  
 
gremlin> g.inject(1).choose(is(1), constant( true ), fold())
==>[]
==> true 
gremlin> g.inject(1).choose(is(1), constant( true ), max())
==>NaN
==> true
Discussion
- The issue seems related to a step like  fold()  always returning an object even when the stream is technically empty as in: 

  
 
gremlin> g.inject().fold()
==>[]
 
  

 The choice to return something or not from the option traversals is determined by  hasNext()  so that's why more than one of those options is returned. Considering fixing this by introducing a different method of flow control
