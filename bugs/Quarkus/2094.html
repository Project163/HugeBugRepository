Title

SSL requests hang when returning a CompletableFuture

Description
### Describe the bug

Requests hang when an endpoint is returning a CompletableFuture and SSL is active. When turning off SSL or the endpoint is changed to not return a CompletableFuture, the requests seem not to hang.
The requests hang for the time specified in `quarkus.http.idle-timeout`.

### Expected behavior

Requests should not hang.

### Actual behavior

Requests hang.

### How to Reproduce?
[Link: hanging-ssl.zip]

1. Unzip the attached zip-archive
2. Run the project
3. Do a GET request to [URL] (here http does not matter)
4. Notice that "Request completed" is never printed (well, after `quarkus.http.idle-timeout` it is, but that defaults to 30m)
5. If changing the code such that the endpoint test/bytes is used internally, "Request Completed" is eventually printed

The example code uses OkHttpClient, but it is possible to reproduce with java.net.HttpClient aswell, but that seems to require  more iterations.
