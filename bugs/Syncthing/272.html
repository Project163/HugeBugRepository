Title

Upgrade code needs to be smarter

Description
Currently it takes the first file it finds called `syncthing` and uses that as the binary to upgrade to. After #2440 this became the ufw config file, which is entirely wrong.

Luckily that file doesn't pass the signature check so the upgrade was aborted rather than blowing away the binary for the user...
Discussion
- Would checking for the executable bit work?
- Maybe something like:

```
go
file, error := os.Lstat("test.txt")
var executable = file.Mode() & 0111
if executable != 0  {
        //found the syncthing binary
... [Log Snipped] ...
        fmt.Println("file is not not executable")
    }
```

and use this in  [Link: archiveFileVisitor]?
- Not a fan of this approach. Why not put the syncthing binary in a known location in the archive (it already is), and make syncthing look for this?
- Yeah, we should simply look for syncthing(.exe) at the first directory level and no deeper.
