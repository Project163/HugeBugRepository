Title

Hive metastore hangs

Description
Hive metastore hangs (does not accept any new connections) due to a bug in DBCP. The root cause analysis is here  [URL]  The fix is to change Hive connection pool to BoneCP which is natively supported by DataNucleus.
Discussion
- The change currently just pulls down BoneCp artifact and does not change the default value to BoneCP. To enable BoneCp, the setting “datanucleus.connectionPoolingType” in hive-site.xml should be set to “BoneCP”. All the hive systems test pass with this setting.
- Couple of questions: 
 
	 Could there be a performance implication of this? I know perf is irrelevant if functionality doesn't work, but it will be comforting to know that BoneCP is not 10x (randomly picked number) than DBCP. 
	 If we find (hopefully) that earlier statement is true, than we should just rip off DBCP and only use BoneCP as default.
