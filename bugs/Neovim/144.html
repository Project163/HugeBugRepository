Title

Very slow netrw operations on headless server

Description
- `nvim --version`: `NVIM v0.2.0-498-g050819277`
- Vim (version: ) behaves differently? not sure
- Operating system/version: Arch Linux
- Terminal name/version: cygwin + MinTTY + ssh with x11 forwarding (configured so in `~/.ssh/config`) + tmux (works both within x server and outside of it)
- `$TERM`: `screen-256color`

### Actual behaviour

It takes about 8 seconds for `:Explore` to open netrw window.

### Expected behaviour

It should work instantly, the directory contains about 5 files.

### Steps to reproduce using `nvim -u NORC`

```
time nvim -u NORC -c 'Explore|q'
nvim -u NORC -c 'Explore|q'  0.06s user 0.01s system 0% cpu 9.102 total
```

Running it through `strace` reveals that it spends a great deal of time looking for stuff such as `xclip` and whatnot. `:set clipboard` shows `clipboard=`. It works fast only after I removed the `xclip` binary which I've installed mainly for clipboard via X11 forwarding.
Discussion
- Does it happen every time, or only the first `:Explore`?

netrw loves to fiddle with the system clipboard for no reason (in a _loop_).  `:set clipboard=` doesn't help because netrw messes with `@+` explicitly.

This is arguably a netrw bug. We've already worked around the loop issue. Perhaps  `provider/clipboard.vim` could put a `jobwait()` around its xclip attempt so that it times out after 1s.
- Also is X11 forwarding functioning when this happens? Is `$DISPLAY` valid? Does `:let @+='foo'` on the remote nvim alter your clipboard?
