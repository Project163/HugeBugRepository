Title

onedrive: uploading empty files causes SEGV

Description
This bug as described in the title can be reproduced with the current repo version (with Graph) of code.

The direct cause of the bug is that when `size` is `0` in the function [Link: `uploadMultipart`], the upload for-loop is skipped. Therefore, `info` is `nil`. Then when `info` is dereferenced, there will be SEGV.

Graph's multi-part upload API does not support 0-size files (`{"error":{"code":"invalidRequest","message":"The Content-Range header is missing or malformed."}}`). So to allow upload of empty files, we must use [Link: single-part upload]. But the [Link: problem] with single-part upload is we'll either lose `modtime`, or create two versions of the same file. I think this needs to be discussed before changes can be made.

Personally I would prefer allowing single-part upload for empty files and setting `modtime` afterwards. Creating multiple versions of empty files won't occupy space, after all.

I believe this bug is related to [Link: this failure] and [Link: this forum post].

Update: The current code can download empty files without any problem.
Discussion
