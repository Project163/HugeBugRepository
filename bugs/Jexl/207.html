- Reproduced the problem with caching enabled. 

 The cache is a cache of expressions/scripts keyed by source and valued by the DAG (direct acyclic graph) of AST (abstract syntactic tree) nodes used for interpretation. A lot of those nodes further cache costly interpretation operations in particular solving methods and property accessors, those requiring Java reflection (introspection). 
Calling cache(...) on a JexlBuilder will set the number of entries (scripts, expressions) kept in the engine cache. 

 The issue seem to stem from caching a property setter in the wrong node.
