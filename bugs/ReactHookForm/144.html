Title

Registering new field when form is invalid can make the form valid

Description
**Describe the bug**
when the form is invalid and a new field is registered, the validation resolver is passed initial state, which may result in the form become incorrectly valid
i might be missing something since this library is very well thought out and i see the code that intentionally passes initial data when the form is invalid so please excuse me if i made a mistake

**To Reproduce**
Steps to reproduce the behavior:
1. Go to [URL]
2. Click "Include username" checkbox to cause form to be in invalid state
3. Click "Toggle username field" to show username
4. See error - form is is valid state/validation is passed initial form data, causing the form to be incorrectly valid

**Codesandbox link (Required)**
[URL]

**Expected behavior**
when registering new inputs when form is invalid, the form will be passed the current state(merged with initial state?)

**Desktop (please complete the following information):**
 - OS: macOS
 - Browser: chrome
 - Version 83
Discussion
- This is because your resolver didn't return an error when the new input is getting registered.

[Image: Screen Shot 2020-07-04 at 6 43 29 pm]
- @bluebill1049 
when registering a new input, the resolver is passed the defaultValues `{ includeUserName: false, initialStateData: true }` instead of the current values `{ includeUserName: true }`. so in this case, the resolver will not return any errors since the defaultValues are valid
- ... [Middle Discussions Snipped for Brevity] ...
- `getValues()` shouldn't be used like in your `codesandbox`, because getValues works after render, HookForm's form data lives in the input itself, which means after render.
