Title

2dc: Fix Race Condition On Consumer With Smaller Batch Sizes

Description
When we limit the size of batch size of `cdc_max_apply_batch_num_records`, we can end up in a race condition where we end up applying transactions before all the intents have been replicated. This happens due to the asynchronous nature of tablet lookup, so we may trigger a lookup on an intent before its apply, but execute the callbacks in reverse order. Smaller batch sizes means we send multiple write requests per poll to a given tablet, so request 1 may contain a commit, while request 2 may contain an apply for the transaction we committed.
