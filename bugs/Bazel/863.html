Title

java.nio.file.InvalidPathException: Trailing char

Description
### Description of the problem:

`repository_ctx.which` can fail with an exception on Windows if `PATH` contains invalid entries. In particular this seems to be triggered by a non-existent entry ending on white-space such as `C:\Program Files `.

### Bugs: what's the simplest, easiest way to reproduce this bug? Please provide a minimal example if possible.

Write a repository rule that calls `repository_ctx.which`. E.g.

```
# debug.bzl
def _debug(repository_ctx):
    print("cmd.exe", str(repository_ctx.which("cmd.exe")))
    repository_ctx.file("BUILD.bazel")

... [Log Snipped] ...
load("//:debug.bzl", "debug")
debug(name = "debug")
```

And call Bazel with `PATH` containing an invalid entry as described above.
```
$ export PATH="C:\\Program Files "
$ bazel build @debug//...
```

This should produce the following error
```
Internal error thrown during build. Printing stack trace: java.lang.RuntimeException: Unrecoverable error while evaluating node 'REPOSITORY_DIRECTORY:@debug' (requested by nodes '@debug//..., excludedSubdirs=[], filteringPolicy=com.google.devtools.build.lib.pkgcache.FilteringPolicies$FilterManual@7dab797e')
	at com.google.devtools.build.skyframe.AbstractParallelEvaluator$Evaluate.run(AbstractParallelEvaluator.java:531)
	at com.google.devtools.build.lib.concurrent.AbstractQueueVisitor$WrappedRunnable.run(AbstractQueueVisitor.java:399)

... [Log Snipped] ...

```

See [URL] and [Link: Azure CI pipeline] for details.

### Expected behavior

Bazel should not throw an exception and ignore the inexistent `PATH` entry. If the tool is found in another entry then `repository_ctx.which` should use that one, otherwise return `None`.
