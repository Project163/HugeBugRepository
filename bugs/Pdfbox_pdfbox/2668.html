Title

No Content - xRef / Obj Parsing

Description
There seems to be an issue with xRef / object reading when parsing the attached pdf. 

 The PDF itself has for example two objects with the ref "8 0 R": 

 One at position 1967 with a "/Content" entry. 

 One at position 7782 without a "/Content" entry. 

 Both are referenced in the XRef Table, so there seems to be something off. Probably Acrobat, etc. are using the first object, while PDFBox is using the second one.
Discussion
- The PDF is broken. 

 The second object designated as object 8 by a  8 0 obj  according to the cross references is object 9! 

 Thus, here the cross references and the objects themselves are at odds. In such a situation different PDF processors may use different strategies in trying to read the PDF nonetheless. None of these strategies is right or wrong, for each strategy there are documents it repairs well and others it fails to repair. Even the strategy to reject the document has its merits: You cannot get fooled by dubious tricks.
- True, the PDF is in some ways broken. But currently the second reference is read, which should be object 9 in the table.
