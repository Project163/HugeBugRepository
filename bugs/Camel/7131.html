Title

camel-http - NTLM authentication doesn't work over http

Description
It appears that NTLM authentication is not functioning correctly in Apache Camel 4 (version 4.10.4) when using the  http  component. 

 Using the exact same credentials and request details, the call succeeds when made via the  curl  command with the  --ntlm  flag, but fails when executed through Camel. 

 As shown in the attached Wireshark capture, the  curl  request correctly initiates the NTLM handshake, including the  Authorization: NTLM ...  header, whereas the Apache Camel request does not send the Authorization header and fails to trigger a challenge-response flow. 

  Apache Camel 4 (4.10.4)    
  
 
<to uri= "http: //exacttest.myserver.local:8020/Services/Exact.Entity.REST.EG/?authMethod=NTLM&amp;authUsername=RAW(usr_exact1)&amp;authPassword=RAW(blabla)&amp;authDomain=RAW(myserver.local)&amp;maxTotalConnections=20&amp;connectionsPerRoute=2&amp;connectTimeout=180000&amp;soTimeout=180000" />  
  
  Curl (8.7.1)    
  
 
curl --ntlm --user myserver.local\\usr_exact1:blabla  "http: //exacttest.myserver.local:8020/services/Exact.Entity.REST.EG/"
