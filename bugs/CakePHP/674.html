Title

3.0 - incorrect table definition during fixture creation

Description
I have the following table:

```
CREATE TABLE `users` (
`id` BIGINT UNSIGNED NOT NULL,
`other_field` INTEGER(11) NOT NULL AUTO_INCREMENT,
PRIMARY KEY (`id`),
UNIQUE KEY `other_field` (`other_field`)
) ENGINE=InnoDB
```

I have defined UsersFixtures with `public $import = ['table' => 'users'];`

When running phpunit, testing fails during fixture generation because I get the following mysql error: "Incorrect table definition; there can be only one auto column and it must be defined as a key".

After checking the sql command generated by cakephp to create the table users, I found this:

```
`CREATE TABLE `users` (
`id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
`other_field` INTEGER(11) NOT NULL AUTO_INCREMENT,
PRIMARY KEY (`id`),
UNIQUE KEY `other_field` (`other_field`)
) ENGINE=InnoDB
```

If I understand, Cakephp is automatically adding a AUTO_INCREMENT to Primary fields which makes setups like mine (where primary field is not auto incremented, but generated in `beforeSave()` and where an other field is auto incremented) fail.
Discussion
- I am curious, what's the point of having an auto increment field which is not primary key?
- Having the autoincement not involved in the primary key at all is somewhat odd. Like @ADmad I wonder why one would do this?

- I have a patch ready (https://github.com/PGBI/cakephp/commit/ ) but it does break existing tests. I don't know if there is a good reason why cakephp would automatically add auto increment to primary field, which is why I haven't submitted any PR yet.
- @PGBI The main reason that we put autoincrement onto primary keys that are also integers is because generally the conventions of CakePHP indicate that integer primary keys are autoincrements.

The existing code checks for `column == primary key || autoIncrement == true` which should let this column definition through but clearly isn't.
