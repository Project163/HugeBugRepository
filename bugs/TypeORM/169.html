Title

Incorrect migration generated when multiple views are updated in a single migration

Description
## Issue Description
If we have several views, for example **ViewA**, **ViewB**, **ViewC** and all 3 are updated in the same migration, the migration will look like (PseudoCode):
```
up() {
    DROP VIEW ViewA;
    DROP VIEW ViewC;
   
    CREATE VIEW ViewA;
    CREATE VIEW ViewB;
    CREATE VIEW ViewC;
 }
```

Basically all odly indexed view will be missing from the drops. This might not a be huge problem when the Views are independent, but when ViewB from the above example uses ViewC, what we end with is a migration that can't be executed, because the dependent ViewB must be dropped before VIewC can be.

### Expected Behavior

All views that are changed should have the corresponding DROP statements;

### Actual Behavior

Every second view in the migration is missing it's 'DROP' statement.

### Steps to Reproduce

Have several already existing views in your models, and then change more than 2  with a single migration.

Will try to add a test case that reproduces it.
