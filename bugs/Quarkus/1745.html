Title

Request Context Race condition in quarkus 2.13

Description
### Describe the bug

when firing an async CDI Event, the request context from the emitter briefly exists for the observer and is then terminated.
This prevents to create a new Request context for the Async observer since the emitter context still exist.

This was working in Quarkus 2.12

- It turns out that the [Link: Vertx context is captured] when a new task is submitted from a thread of the default blocking `ExecutorService` and restored when the task is executed on a different thread. I would not expect this kind of behavior but it's implemented this way for a long time (probably because of some Mutiny use cases?). As a result, the [URL] caused this regression.
- Note that the capture/restore makes it possible to access the vertx context concurrently from multiple threads.
