Title

allow now() -> uuid compatibility

Description
Bad Request: Type error: cannot assign result of function now (type timeuuid) to id (type uuid)
Discussion
- I'll remark that because the code for functions is relatively generic, we can't just special this for now() (nor should we really). Meaning that what we need here is to introduce a bit of subtyping in the type system and make timeuuid a subtype of uuid. Which in itself if probably not that hard, but mentioning it because it's still probably a bit more involved than what the ticket title imply.
- Couldn't we just use  AbstractType.isValueCompatibleWith() ?  It looks like some of the types don't properly implement this (e.g. UUIDType does not return true for TimeUUIDType), but that can be fixed here.
