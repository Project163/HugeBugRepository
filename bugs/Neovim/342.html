Title

Visual-Block insert does not insert all characters

Description
- `nvim --version`: NVIM v0.5.0-dev+1135-g0f318e0f9-dirty
- `vim -u DEFAULTS` (version: 8.2) behaves differently? Yes, but worse
- Operating system/version: Linux 5.10.0-1-amd64 #1 SMP Debian 5.10.5-1 (2021-01-09) unknown unknown GNU/Linux
- Terminal name/version: kitty 0.19.3 created by Kovid Goyal
- `$TERM`: xterm-kitty

### Steps to reproduce using `nvim -u NORC`

Insert the following text in any file:
```



        onAuthRequired
        onBeforeRequest
        onBeforeSendHeaders
        onHeadersReceived
```

Place the cursor on the first `o` of the first line containing text, go in visual-block mode and select all `o`s. Go in insert mode with `I`, press backspace until all space has been removed and then type `browser.webrequest.` and exit insert mode.

### Actual behaviour
```
browser.webrequest.onAuthRequired
        webrequest.onBeforeRequest
        webrequest.onBeforeSendHeaders
        webrequest.onHeadersReceived
```

### Expected behaviour
```
browser.webrequest.onAuthRequired
browser.webrequest.onBeforeRequest
browser.webrequest.onBeforeSendHeaders
browser.webrequest.onHeadersReceived
```
Discussion
- `:help v_b_I` says that using `I{string} ` in visual-block mode "works only for adding text to a line, not for deletions". The documentation also says `{string}` will be inserted at the "start of the block".

Given the deleted whitespace that starts each line in the example above, the use case may be beyond what _visual-block insert_ is intended to handle. That is, the current behavior may not be a bug. If so, a _feature request_ would seemingly be more applicable for functionality that achieves the _Expected behavior_ above.
- Ah, yeah, looks like the documented behavior. Kind of weird that ` ` works at all then - with this explanation, I'd expect it to do nothing, just like in Vim.
