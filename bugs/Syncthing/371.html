Title

Syncthing upgrade can end up with no config.xml when there is not enough space on device

Description
Hello there,

I somehow managed to completely fill up my /home drive on one server. I noticed it too late and as result, syncthing failed to write to `config.xml` somewhere in the process and truncated it to 0b.
Config was then replaced with default one upon next start.

Luckily, following is not my case, but this could be rather unpleasant for someone without backups.

Usual way how to _not_ end up with invalid config is to write `config.xml.tml` and mv it only after successful write.

Syncthing Version: syncthing v0.14.4 "Dysprosium Dragonfly" (go1.6.3 linux-amd64) builduser@svetlemodry 2016-08-10 19:32:43 UTC

(It's headless machine, so I'm not using any browser nor Syncthing-GTK there)
