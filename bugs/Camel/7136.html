Title

camel-infinispan - query parameters not working

Description
It appears that query parameters in the URI are not resulting in the desired output. 

 The following code with  operation=GET  doesn't work: 

   
  
 
from( "timer:java?repeatCount=1" )

 //PUT
 .setHeader( "CamelInfinispanKey" ).constant( "123" )
.setHeader( "CamelInfinispanValue" ).constant( "hello" )
.to( "infinispan-embedded: default " )

 //GET
 .setHeader( "CamelInfinispanKey" ).constant( "123" )
.to( "infinispan-embedded: default ?operation=GET" )
.log( "get: ${body}" );  
  
 However, replacing the GET snippet as follows works: 
  
 
.setHeader( "CamelInfinispanOperation" ).constant( "GET" )
.setHeader( "CamelInfinispanKey" ).constant( "123" )
.to( "infinispan-embedded: default " )
.log( "get: ${body}" );  
  
 Also, the following code with  key=123  does not work: 
  
 
.setHeader( "CamelInfinispanOperation" ).constant( "GET" )
.to( "infinispan-embedded: default ?key=123" )
.log( "get: ${body}" );
Discussion
- The issue occurs because the Headers from the first route persist on the Exchange obj. The GET route then prefers values from header over config values, causing issues. 

  
 
@InvokeOnHeader( "GET" )
 public  void onGet(Message message) {
 final  BasicCache< Object ,  Object > cache = getCache(message);
 final   Object  key = message.getHeader(InfinispanConstants.KEY, configuration::getKey);
 final   Object  result = cache.get(key);

setResult(message, result);
} 
  

 If we swap the preference order, ie config over headers then it should be resolved. Thoughts?
- It doesn't seem to me an issue with the headers conflicting, this doesn't work either: 

   
  
 
from( "timer:java?repeatCount=1" )
 .setHeader( "CamelInfinispanKey" ).constant( "123" )
 .setHeader( "CamelInfinispanValue" ).constant( "hello" )
 .to( "infinispan-embedded: default " );

from( "timer:java?delay=5000&repeatCount=1" )
 .setHeader( "CamelInfinispanKey" ).constant( "123" )
 .to( "infinispan-embedded: default ?operation=GET" )
 .log( "get: ${body}" );
