**Description of the problem including expected versus actual behavior**:

After master node has been down, when it returns there is a brief window where `/_cat/indices/ALIAS` requests are accepted but elasticsearch returns a 404 `index_not_found_exception`. This is unexpected and problematic behavior to our app which considers this an error.

I'd expect a usually strongly consistent system like elasticsearch to return a 503 if it hasn't fully read enough data after master returned to determine if the alias+index exists. It's ok to give an error, it's not okay to give false information like that the index does not exist.
