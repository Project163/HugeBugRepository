Title

compileBooleanMatcher fails when prefix and suffix overlap

Description
# Bug report

 
 
 
 

**What is the current behavior?**

Currently, the [Link: compileBooleanMatcher] function is being fooled when the common prefix and suffix of two expressions overlap. This, in turn, leads to incorrect code being generated by [Link: JsonpChunkLoadingRuntimeModule] which, in my case, tries to load a consumed module as if it had been bundled locally, thus making the web server return a `Not found` error and failing the page load.

**If the current behavior is a bug, please provide the steps to reproduce.**

I cannot send a small test project to reproduce it because:

1. [Link: My project] setup is huge and I'm working in a current development locally.
2. I'm not quite sure how it could be reproduced in a small project because it depends on the dependency graph and federation config.

Anyway, I'm going to fix this in a following PR with a test, where it is easy to see why the production code was wrong and, looking at the test, what I was expecting to work correctly.

 
 
 
 
 
 

**What is the expected behavior?**

The expected behavior is that the computed regexp matches the setup correctly (see the unit test in the associated PR).

Operating System: ArchLinux
