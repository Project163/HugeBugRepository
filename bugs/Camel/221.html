Title

Instrumentation agent should be able to register multiple instances of a processor

Description
If you have a route like this: from("jms:queue").to("bean:testBean").to("bean:testBean"), 
the second instance of the processor "to(bean:testBean)" will fail to register with mbean server because of duplicated objectname.  As a result, only one instance of the "to(bean:testBean)" processor is visible to mbean server and we won't set the performance counter of the second instance. 

   [URL]
Discussion
- Patch to include node id in processor's objectname.  Since node id is an option id, instrumentation agent adds instance id into the objectname as well.
- Applied patch with thanks to William Tam.
