Title

Node#setProperty(String, Calendar) doesn't take time zone in account

Description
Node#setProperty(String, Calendar) doesn't take time zone in account. 

 It looks the Calendar value is straightly stored as a long without take in consideration the time zone, 

 Unit test to follow
Discussion
- I think the test expectations are to strict: the returned calendar values represent the same date, only the time zone differ. According to the JCR spec: "If V1 and V2 are values of type DATE then the repository must use the semantics of java.lang.Calendar.compareTo, as described in §  CompareTo Semantics." 

 Thus the assertion in the test case should read 
  
 assertEquals(0, cal.compareTo(root.getProperty( "start" ).getDate()));
- fair enough, 

 FYI though Jackrabbit behaves differently. So let's make at part of   OAK-14   (??)
