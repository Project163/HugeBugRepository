Title

st.file_uploader AxiosError caused by _streamlit_xsrf cookie deletion when popup windows are closed

Description
### Checklist

- [Link: X] I have searched the [existing issues] for similar issues.
- [X] I added a very descriptive title to this issue.
- [X] I have provided sufficient information below to help reproduce this issue.

### Summary

In certain conditions, after a popup window is opened and closed, the FileUploader widget displays and AxiosError:

```
AxiosError: Request failed with status code 413
```

An example of a "popup window" that causes this bug is the [Link: msal_streamlit_authentication] component, but this bug can also be triggered without that component as described below.

### Reproducible Code Example

```
Python
# Example using the msal_streamlit_authentication component, which reliably reproduces the issue
# (but requires an Azure account to test)

# Bug can also be reproduced without this component as explained below
... [Log Snipped] ...
value = msal_authentication(auth={clientId": "", authority": "...", redirectUri": "...",})
files = st.file_uploader("Upload your file")
```

### Steps To Reproduce

1. Run the app and open dev tools; observe that the `_streamlit_xsrf` is present.
2. Click "login", and follow prompts in the popup until it closes.
3. Open dev tools; observe that the `_streamlit_xsrf` is absent.
4. Try uploading a file, and see an `AxiosError`.

### Expected Behavior

The file uploader should work

### Current Behavior

The file uploader displays an `AxiosError`.

### Is this a regression?

- [ ] Yes, this used to work in a previous version.

### Debug info

- Streamlit version: 1.37.1
- Python version: 3.11
- Operating System: Linux
- Browser: Edge (also tested on Chrome). Cannot reproduce issue in Firefox.
