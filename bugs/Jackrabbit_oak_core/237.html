Title

ReadOnlyVersionManager.getVersionHistory throws NPE if the versionstore is not accessible

Description
while debugging a bug in the permission eval i run into a NPE in the version mgt caused by the 
fact that ReadOnlyVersionManager defines the following method: 

  
 @Nonnull
 protected   abstract  Tree getVersionStorageTree();
 
  

 the oak-jcr implementation if that method calls:  
  
 versionStorageLocation.getTree() 
  
  which may return null in case of insufficient permissions. 

 in other words: the nonnull annotation of the abstract method is violated  
-> change to checkfornull or fix the implementation 

 second: IMO the oak-jcr version implementation should not rely on the accessibility of the intermediate 
nodes that form the version store. instead accessing a versionhistory should use the locator to traverse to the version history node ad call #getTree on that location.
Discussion
- committed a fix at revision 1453759: 

 a) change the abstract method to getVersionStorageLocation keeping the nonnull annotations 
b) adjusted getVersionHistory to not resolve the tree of the v-storage location but directly accessing the version history.
