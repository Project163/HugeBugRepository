Title

GLFW_ICONIFIED attribute is unreliable on Windows

Description
Calling glfwGetWindowAttrib() with GLFW_ICONIFIED does not always/immediately return the correct state on Windows. The problem appears to be the Win+D workaround in win32_window.c, where "iconified" is set to FALSE, although the window is in fact still iconified. It can be observed by maximizing a window from the taskbar and comparing glfwGetWindowAttrib()'s result with ::IsIconic() using the window handle exposed from the native interface.

This is a serious issue because it can make the application freeze if GLFW_ICONIFIED is queried to determine whether SwapBuffers() shall be called or not!

As a workaround, I'm currently checking ::IsIconic() directly before attempting to render stuff. When I remove the Win+D workaround, everything behaves correctly except, well, the Win+D case :)

EDIT: I just noticed that this is related to Issue #189
