Title

`promtool test rules` fails when /tmp is not writable

Description
### What did you do?

Tried to run `promtool` from the prometheus docker and it fails while it works for the same files

```
$ promtool test rules tests/unit/promtool/test_unit_available.yaml                                                                                                                         Unit Testing:  tests/unit/promtool/test_unit_available.yaml
  SUCCESS

$ docker run -v $PWD:/tmp --entrypoint "/bin/promtool" prom/prometheus:latest  test rules /tmp/tests/unit/promtool/test_unit_available.yaml                                              
Unit Testing:  /tmp/tests/unit/promtool/test_unit_available.yaml
... [Log Snipped] ...
main.main()
	/app/cmd/promtool/main.go:373 + 
```

Same output as when I download promtool binary e.g.

Discussion
- Weird. @dgl any idea why this is apparently only happening with `promtool` from the docker image?
- Fun bug... the problem is `docker run` with `-v $PWD:/tmp` -- this is making /tmp be mounted as whatever the working directory is, which likely isn't set up to be world writable like /tmp is expected to be. This means `os.MkdirTemp` fails (as the Docker image runs as `nobody`). I clearly need to fix the error reporting though, it shouldn't be using testify on this code path.

tl;dr: Rather than using `/tmp`, use something without a special meaning like `/data`.
- Good catch actually, it never occured to me that mounting `tmp` could create an issue. I 'll make sure to avoid this practice in the future. 

Thanks for the workaround. I 'll leave this open since it's something you need to fix.
