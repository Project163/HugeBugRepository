Title

StackOverflowError in List and Map formatting

Description
If a List or Map that contains itself is formatted for output (print, inspect,...) a StackOverflowError occurs. 

  
  import  org.codehaus.groovy.runtime.InvokerHelper

def x

 // List (simple  case )
 x = []
x << x
 assert   "[( this  Collection)]"  == x.toString()
InvokerHelper.toListString(x)

 // List (nested  case )
 x = []
x << [x]
 assert  InvokerHelper.toListString(x)

 // Map (simple  case )
 x = [:]
x.put( "self" , x)
 assert   "[self: this  Map_]"  == InvokerHelper.toMapString(x)  // JDK uses  "( this  Map)" 
 
 // Map (nested  case )
 x = [:]
x.put( "nested" , [ "self" :x])
 assert  InvokerHelper.toMapString(x)

 // there are also List/Map mixed cases
  // ... 
 
  

 See also   GROOVY-1106  .
Discussion
- Just added a few tweaks to handle some of the really simple cases. 

 Maps detect themselves as top level value (already there - just aligned syntax with Java): 
  
 def m = [a:1]
m.self = m
 assert  m.toMapString() ==  '[a:1, self:( this  Map)]' 
 
  

 Ditto for list (again using Java syntax): 
  
 def l = [ 'first' ]
l << l
 assert  l.toListString() ==  '[first, ( this  Collection)]' 
 
  
 In addition, if you call  toListString()  or  toMapString()  directly you can supply a max size param. 
  
 def animals = [ 'ant' ,  'bee' ,  'cat' ]
animals << [pets:animals]
 assert  animals.toListString(5)  ==  '[ant, ...]' 
 assert  animals.toListString(10) ==  '[ant, bee, ...]' 
 assert  animals.toListString(15) ==  '[ant, bee, cat, ...]' 
 assert  animals.toListString(20) ==  '[ant, bee, cat, [pets:[...]]]' 
 assert  animals.toListString(40) ==  '[ant, bee, cat, [pets:[ant, bee, cat, [pets:[...]]]]]' 
 
  
 The size param isn't hooked up to any  toString()  methods by default as that might break existing code.
