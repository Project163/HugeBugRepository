Title

[docdb] Core dump when applying split operation

Description

```
Program terminated with signal 11, Segmentation fault.
```

Discussion
- There is a code inside `TSTabletManager::StartSubtabletsSplit` that only get executed when we have previous partly completed split attempt for the same tablet:
```
    // Try to load metadata from previous not completed split.
    auto load_result = RaftGroupMetadata::Load(fs_manager_, subtablet_id);
    if (load_result.ok() && CanServeTabletData(iter->raft_group_metadata->tablet_data_state())) {
```

This code was broken by [URL] and we never noticed it, because it was not covered with unit-test.

Before the change it was:
```
    // Try to load metadata from previous not completed split.
    if (RaftGroupMetadata::Load(fs_manager_, subtablet_id, &iter->raft_group_metadata).ok() &&
        CanServeTabletData(iter->raft_group_metadata->tablet_data_state())) {
```

and after this change, it will be trying to access `RaftGroupMetadata` by `nullptr` if got executed.

As a part of the fix we need to add a unit-test for that code.
