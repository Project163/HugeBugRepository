Discussion
- Hmm, it looks like endpointToHostIdMap is being mutated, but it's not immediately clear how since the gossiper is blocked here and can't notify anything else, not to mention all the locking in TMD.
- Just to provide as much info as I can, the entire cluster was stopped. I then ran a script to start all of them back up at the same time. This particular cluster is 44 nodes. All 43 other nodes started fine. This one node died at startup with this exception. After a couple minutes I restarted the one node, and it came up fine. Priority "Major" is maybe a little aggressive for this one

- I'm curious, each access to  tokenToEndpointMap  is guarded by either read or write lock, on other hand  endpointToHostIdMap  is accessed without any lock in most cases. Is it by design?
- Patch for 1.2.  
 
	 Use read lock to read endpoints' collections, and return defensive copies  for them. 
	 Use write lock in  updateHostId
