Title

beforeDelete/afterDelete on belongToMany association generates entity with incorrect type

Description
This is a (multiple allowed):

* [x] bug
* [ ] enhancement
* [ ] feature-discussion (RFC)

* CakePHP Version: 4.2.9

### What you did
Removing associated data via patchEntity, beforeDelete/afterDelete on the relationship contains incorrect Entity type

TopicsController.php
```
// $data['groupings']['_ids'] = [];

$topic = $this->Topics->patchEntity($topic, $data, ['associated'=>['Groupings']]);
$this->Topics->save($topic, ['associated'=>['Groupings']])
```

TopicsTable.php
```
$this->belongsToMany('Groupings', [
  'foreignKey' => 'topic_id',
  'targetForeignKey' => 'group_id',
  'through' => 'GroupTopics'
]);
```

GroupTopics.php
```
public function afterDelete(EventInterface $event, EntityInterface $entity, ArrayObject $options)
{
   dd($entity);

  // expecting $entity of type App\Model\Entity\GroupTopic
... [Log Snipped] ...
*/
}
```

### What happened
before/after delete function contain an entity with wrong type but with correct data.

### What you expected to happen
entity type should be `App\Model\Entity\GroupTopic` not `App\Model\Entity\Grouping`
Discussion
- Changing which entity is passed to the delete callbacks could break existing applications. This kind of change would need to be done in a minor release where we could document the behavior change.

edit: clarify my hasty response.
- When you call `$this->Topics->save()` are the junction entities you're passing in of the correct type? Or is the ORM fetching the incorrect entities inside the BelongsToMany association?
- When saving it's using the standard `relationship._ids` form helper to save Groupings entities. In this case yes, the _joinData on belongsToMany relationship is of correct entity type.

In case of removal the "original" attribute on the topic entity right after patching does contain the correct entity in _joinData, if that's what you are asking by junction entitles.

```
App\Model\Entity\Topic Object
(
[id] => 18
...
[[original]] => Array
... [Log Snipped] ...
                                    [group_id] => 7
                                    [topic_id] => 18
```

I believe it's the later, when deleting BelongsToMany fetches correct data however applies incorrect entity type to that data.
