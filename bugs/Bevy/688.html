Title

`bevy_ecs` fails to compile if `std` feature enabled without `backtrace` feature due to panic hook

Description
## Bevy version

Main branch: [URL]

## \[Optional\] Relevant system information

Bug appeared on CI for Linux/MacOS/Windows machines.

Example run: [URL]

## What you did

Created new PR targeting Bevy main branch crates, ran tests that do not enable `bevy_ecs` default features and specifically do not enable `backtrace` but enable `std`. The CI then pulled the latest version of `bevy` from github.

## What went wrong

Happened on a compilation error, where `bevy_error_panic_hook` errors because it is trying to reference a `static` that does not exist.

## Additional information

It appears that the [Link: hook] is incorrectly feature flagged, and needs *both* `std` AND `backtrace` to be enabled. I'd suggest that the `backtrace` feature requires `std` feature and to have the hook feature flagged behind `backtrace` instead of `std`.
