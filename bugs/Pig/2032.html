Title

Make ParallelGC the default Garbage Collection

Description
From JDK9 and beyond, G1GC became the default GC.  
I've seen our users hitting OOM after migrating to recent jdk and the issue going away after reverting back to ParallelGC.   

 Maybe the GC behavior assumed by SelfSpillBag does not work with G1GC.
Discussion
- This was not as simple as I hoped for.  
I was incorrectly assuming that when multiple GCs are specified, jvm will pick the last one.  Instead, jvm fails to start with  
  Conflicting collector combinations in option list; please refer to the release notes for the combinations allowed  

 Here, attaching a patch that looks at the specified options and only adds "-XX:+UseParallelGC" when other GC is not specified.
