Title

[DocDB] PITR doesn't clear sequence cache on connections.

Description
Jira Link: [Link: DB-5576]
### Description

If a set of values from a sequence is cached on a connection, and then a PITR is performed that changes the current value of the sequence, the connection's cache is not cleared. This leads to duplicate values.

Below is a minimal reproduction. Use 2 shells, one for yb-admin and one for ysqlsh:

```
$ ./bin/yb-ctl start --tserver_flags="ysql_sequence_cache_minval=2"
```

```
$ ./bin/ysqlsh
ysqlsh# CREATE DATABASE test;
ysqlsh# exit
$ ./bin/ysqlsh -d test
test# CREATE SEQUENCE s;
... [Log Snipped] ...
       1
(1 row)
```

```
$ ./bin/yb-admin -master_addresses  :7100 create_snapshot_schedule 2 10 ysql.test
# keep track of the schedule id returned
```

```
test# SELECT nextval('s');
nextval 
---------
       2
(1 row)
... [Log Snipped] ...
       3
(1 row)
```

```
# wait 1 minute to pass from the time you created the schedule
./bin/yb-admin -master_addresses  :7100 restore_snapshot_schedule [schedule id from above] minus 1m
```

```
test# SELECT nextval('s');
nextval 
---------
       4
(1 row)
... [Log Snipped] ...
       3
(1 row)
```

Notice the duplicate value; we've already retrieved 3.
