Title

PDPropBuildDataDict: use COSName instead of COSString as name value

Description
Elyes Lehtihet reported a bug with the representation of the name value with the PDPropBuildDataDict class. According to the spec is has to be a named value instead of a string.
Discussion
- I fixed the issue in revision 1484547 as proposed by Elyes Lehtihet.
- The getter for  /Name  still treats the entry as string and thus returns null, if value type is name. In   PDFBOX-3231   I suggest a patch with the fix and additional updates.
