Title

Rails 4.2.0 doesn't ignore case-insensitive flag in uniqueness validator when target column is uuid

Description
I use postgres and uuid.
Lets imaging I have users which belongs to some account.
Here are models

```
ruby
class User < ActiveRecord::Base
    belongs_to :account
    validates :account, presence: true,
                        uniqueness: {
... [Log Snipped] ...
  has_many :users
end
```

And here are data schemas

```
ruby
create_table "users", id: :uuid, default: "uuid_generate_v4()", force: true do |t|
  t.string   "name"
  t.uuid     "account_id",       null: false
  t.boolean  "owner",           default: false
... [Log Snipped] ...
  t.string   "company_name"
end
```

Rails 4.2.0 will throw pg error when I create a new user:

``` ruby
new_account = Account.create(company_name: "Acme")
User.create(name: "John Doe", account: new_account, owner: true)
```

```
PG::UndefinedFunction: ERROR:  function lower(uuid) does not exist
LINE 1: SELECT  1 AS one FROM "users" WHERE LOWER("users"."account_i...
                                            ^
HINT:  No function matches the given name and argument types. You might need to add explicit type casts.
: SELECT  1 AS one FROM "users" WHERE LOWER("users"."account_id") = LOWER('e61a02af-69e8-4078-929c-c62f2b9f83ed') AND "users"."owner" = 't' LIMIT 1
```

This is how rails 4.1.x (e.g. 4.1.8) validates uniqueness

``` sql
SELECT  1 AS one FROM "users"  WHERE "users"."account_id" = '8a60d747-cdd0-40e1-8188-a018bb9a0ddc' AND "users"."owner" = 't' LIMIT 1
```

And this is how rails 4.2.0 does it:

``` sql
SELECT  1 AS one FROM "users" WHERE LOWER("users"."account_id") = LOWER('8a60d747-cdd0-40e1-8188-a018bb9a0ddc') AND "users"."owner" = 't' LIMIT 1
```

I consider this is a bug in rails 4.2.0 because  [URL] says:

```
Configuration options:
    :case_sensitive - Looks for an exact match. Ignored by non-text columns (true by default).
```
