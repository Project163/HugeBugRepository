Title

3.0 requestAction and return values from controller actions

Description
The CakePHP 3.0 book has examples of controller actions returning data from queries, to be used on conjunction with requestAction(uri, ['return']). However, the return value of a controller action is also validated as being an instance of a Response, so the documented feature will not work.

Which is the intended result?  
That controller actions should always return Response, if not void, or controller actions should be able to return non-Response data, if requested?

If the former, what is the recommended method of retrieving data from a controller, via requestAction(uri, ['return'])?  I could render a JSON or XML response, parse that, and get the data that I want, but seems like a lot of messing around, when I would just like to get the raw data from the component.

My specific use case is invoking a controller from a function that is handling a SoapServer request. Being able to invoke the controller and action that already handles JSON and XML REST equivalents makes for handy code reuse.
Discussion
- The documentation needs to be updated. Invoking controller actions from each other sounds like you actually want to use components or model methods, or perhaps cells?

Yes this is the intended behavior.
- For my use case, I'd rather be calling the action. When doing JSON or XML REST, the current actions work great.  

However, to set up a SoapServer, I've got a SoapController, and an index action that sets up the SoapServer and handles the request.  The plain old PHP object handles the request, and I'd like this to call CakePHP functions to populate the response.

The existing actions seem like the best place, and moving all the CRUD actions into a component doesn't seem like what components are used for.  Either way, I'd still need to call something like requestAction, because the POPO isn't CakePHP aware, and setting up everything to call a CakePHP component from a POPO seems like unnecessary work.  I had actually started doing a similar thing just to call a Controller action, via the dispatcher, when I realised that requestAction does exactly that.

I'm playing with wrapper document/literal SOAP at the moment, so if I can get the SoapServer to accept a string response consisting of rendered XML, that might come in handy anyway.

I'll make a note if this as an issue in the docs repo, and if I can think of an appropriate alternate method to replace what the doco has, I'll submit a pull request.
