Title

Window constructor does not pass sanitizer on Linux

Description
Hello,

I started using google's address sanitizer and the Window constructor using a handle id results in an invalid read.

Here is a minimal working example:

``` c++
#include  
int main()
{
  sf::RenderWindow w( );
  return 0;
}
```

Compiled with:

```
clang++ -fsanitize=address -Wall -Wextra -lsfml-graphics -o sanitizer sanitizer.cpp && ./sanitizer

==17541==ERROR: AddressSanitizer: heap-buffer-overflow on address   at pc   bp   sp  
READ of size 18 at   thread T0
```

It seems that the window manager name retrived with xcb is not null terminated causing undefined behavior when calling `strlen` in the sf::String constructor from ewmhSupported().

I wrote a possible fix here: [URL]

The actual string length can be retrieved using `xcb_get_property_value_length`.

Tell me if you need more informations, or if I'm wrong :)

Cheers,
Discussion
- I have no idea whether this is a bug in SFML or a bug in your window manager.

Reading [Link: this] and [Link: this] makes me think that it's 50/50. I'm leaning more towards the bug on the WM side since on all the systems/WMs I tested, the string is always null-terminated.

We could still add this check for safety reasons though, but the question now is what to do with all the other strings that are queried in the code. Theoretically they might also not be null-terminated on certain systems as well.
- Possibly wrap everything in one non-exported helper and retrieve the strings there with lengths just to be sure?
