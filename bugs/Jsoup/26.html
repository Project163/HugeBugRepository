Title

Requests with requestBody only support changing content-type if there is request data

Description
Report from jsoup email list: Carl Ludewig

I’ve recently begun to use the .requestBody() method on Connection. The API docs give a nice example of posting JSON:

```
Jsoup.connect(url)
 .requestBody(json)
 .header("Content-Type", "application/json")
 .post();
```

However, this doesn’t actually work, because inside of post() it performs an execute() and inside of there it calls setOutputContentType() which resets the Content-Type to the standard form encoding.

The workaround I discovered is to make sure there is at least one dummy parameter on the call due to the req.data().size() > 0 check on line 555 of HttpConnection.java (jsoup 1.9.2). I did this by adding .data(“dummy”, “”) to the example above and got things working.

I thought I’d point this out so perhaps it can be improved in a future version, if I’ve got this right.

Thanks!
