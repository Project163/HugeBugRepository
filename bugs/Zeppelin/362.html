Discussion
- One way to fix this issue is don't add $ZEPPELIN_HOME/conf to the RemoteInterpreterProcess's class path. But I am not sure whether RemoteInterpreter needs $ZEPPELIN_HOME/conf. If I understand correctly, $ZEPPELIN_HOME/conf is only for zeppelin server,  RemoteInterpreter don't need this.
- Thanks  Jeff_Z  for creating an issue propose the solution! 

 I agree. $ZEPPELIN_HOME/conf doesn't look like necessarily should be in RemoteInterpreterProcess's class path. 

 But i know many users are placing some configuration file (e.g. hive-site.xml) under $ZEPPELIN_HOME/conf to let RemoteInterpreterProcess access it. So if changing RemoteInterpreterProcess's class will break those users.  
So there should be alternative way of adding configuration file into RemoteInterpreterProcess's class path and migration guide.
