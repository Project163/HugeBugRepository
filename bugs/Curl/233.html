Title

--aws-sigv4 doesn't sign requests with `*` correctly

Description
### I did this
my idiomatic request to AWS Elasticsearch Service looks as following:

```shell
curl --request GET "[URL] \
--user $AWS_ACCESS_KEY:$AWS_SECRET_KEY \
--aws-sigv4 "aws:amz:ap-southeast-2:es"
```

here is the verbose output:
```
text
*   Trying  :443...
* Connected to ES_DOMAIN_ENDPOIN ( ) port 443 (#0)
* ALPN, offering h2
* ALPN, offering http/1.1
... [Log Snipped] ...
* Connection #0 to host ES_DOMAIN_ENDPOIN left intact
{"message":"The request signature we calculated does not match the signature you provided. Check your AWS Secret Access Key and signing method. Consult the service documentation for details."}
```

### I expected the following

I expect the request above is signed correctly and I get a response with status code `200`. I can confirm that the request with `tempo_data-2021.06` executed with curl works fine. Moreover, requests with `tempo_data-*` works fine from the Postman, when they are authenticated with `AWS Signature`. For instance, the following request works correctly:

```shell
curl --location --request GET "[URL] \
--header "kbn-xsrf: true" \
--header "X-Amz-Date: 20210812T025427Z" \
--header "Authorization: AWS4-HMAC-SHA256 Credential=${AWS_ACCESS_KEY}/20210812/ap-southeast-2/es/aws4_request, SignedHeaders=host;x-amz-date, Signature= "
```
