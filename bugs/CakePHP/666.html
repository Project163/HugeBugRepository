Title

belongsToMany association with conditions: marshaller fails to build query correctly

Description
Using CakePHP 3.0.4, in my `ContentsTable` I have a BTM association with `Files`:

```
php
$this->belongsToMany('Images', [
    'className' => 'Files',
    'foreignKey' => 'content_id',
    'targetForeignKey' => 'file_id',
... [Log Snipped] ...
    ]
]);
```

Then, the chaos began: every time I save a Content with an already-associated Image, the marshaller runs a query like this to find out previous associations:

``` sql
SELECT Images.id AS `Images__id`, Images.title AS `Images__title`, Images.description AS `Images__description`, Images.version AS `Images__version`, Images.is_image AS `Images__is_image`, Images.filename AS `Images__filename`, Images.uri AS `Images__uri`, Images.size AS `Images__size`, Images.hash AS `Images__hash`, Images.user_id AS `Images__user_id`, Images.downloads AS `Images__downloads`, Images.created AS `Images__created`, Images.modified AS `Images__modified`
FROM files Images WHERE (id = 8 OR Images.is_image = 1)
```

The `OR` in the `WHERE` clause (which in my dream world should be an `AND`) causes **ALL** (each end every) Image in the database to be associated with the Content being saved.

I am using regular Cake's built-in methods such as `patchEntity()` and `save()`. My Content entity has `$_accessible = ['*' => true]` just for testing purposes, I disabled all event listeners binded to those tables, and I don't have any behavior except `TimestampBehavior` and a basic `SluggableBehavior` which is hardly responsible for this mess. I also asked for some help in the IRC channel, but they suggested me this might have been a bug: am I doing something wrong? :neutral_face:

Thanks in advance! :wink:

PS: ran `composer update` just yesterday. Haven't checked previous versions.
