Title

MKV file with Opus Audio and VP9 video plays like a distorted one

Description
### Issue description
MKV video file plays like a slow moving file and audio is shrill

### Reproduction steps
1. Get a MKV container format file with x-vnd.on2.VP9 as Video format and Opus as Audio format and  1920 * 1080p resolution.
2. Build the demo app with extensions or no extensions. 
3. Edit the demo app PlayerActivity manifest to accept video/* mimetype and
    "android.intent.action.VIEW" action . 
4. Go to any file manager and select the video file and play with ExoPlayer.
5. Video plays as if its a slow-mo and the audio is totally shrill and distorted.

Discussion
- The bug report seems to have been captured whilst using the Opus extension. Please can you capture a bug report when not using it? Thanks.
- I think the media file broken. In the Matroska container the Opus track has its SamplingFrequency element set to 24000, when it should be 48000. If it were set to 48000 playback would work successfully.
- ... [Middle Discussions Snipped for Brevity] ...
- Any plans to fix this?
- I didn't spend much time looking at this, but the extractor isn't finding what it needs to seek within the file. Specifically, there doesn't seem to be an entry in the Meta Seek Information specifying the position of the Cues element (i.e. the index that enables efficient seeking). It looks like there is a Cues element at the end of the file, but because there's no corresponding entry in the Meta Seek Information at the start of the file, we're unable to find it until it's too late.

We do not support seeking in media unless the media is packaged to allow seeking in an efficient way, and have no plans to change this policy. To enable seeking, I think you should ensure the Cues element can be found by adding a corresponding Meta Seek Information entry.
