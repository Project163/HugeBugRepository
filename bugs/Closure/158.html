Title

Ant: support replacements

Description
My patch for issue 533 has been working fine for us up until now.  Slight background...  I was using @define with a DEBUG variable that could be used to optimize away debug code (like console logging, test features, etc) when the code is compiled.

Fast-forward to now, and my colleagues would not like a way to have both a "shipped" version and a debug version of the same compiled source.  The debug version is also useful for things like pretty-print, so we can test the compiler's reductions, but still be able to find where an error is occurring, because it's not all on one line.

Well, the fix in issue 533 uses project properties to do the @define replacements, and Ant properties are generally immutable, so it became difficult to perform the same compilation twice, with two different values for the @define.  Note, there is still a workaround even for the above case, by overriding the "replacePropertiesPrefix" attribute for each invocation.

All that said, it makes sense to be able to set @define values individually as well, using a new <define /> nested element.  The element is implemented using the org.apache.tools.ant.types.Parameter class, so it supports "name" and "value" attributes.  The "type" attribute is ignored currently, since we have to coerce the value to a proper closure type anyway.

Example usage:

  <target name="app.js" description="Compile JS files">
    <compile-js destfile="${APP_CORE_JS_MIN}">
      <path refid="app.js.files" />
      <!-- Works exactly like:
           $ java -jar compiler.jar -D DEBUG=false ...
        -->
      <define name="DEBUG" value="false" />
    </compile-js>
  </target>
