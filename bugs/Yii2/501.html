Title

Fixture load 2.0.4 postgis pgsql error

Description
Since 2.0.4 (prior to that, was working fine) I'm having this error when i try to fixture/load.

My database is PostgreSQL and extends PostGIS.

What is happening is that the Global fixture InitDb is trying to execute the following SQL:

``` SQL
    ... ALTER TABLE "public"."geography_columns" DISABLE TRIGGER ALL; ...
```

and I get the error:

```
Exception 'yii\db\Exception' with message 'SQLSTATE[42809]: Wrong object type: 7 ERROR:  "geography_columns" is not a table
```

Now... the thing is that "geography_columns" isn't a table, its a **view**, and yet its included in the SQL statement.

Discussion
- this is a side effect of #7833, the tables now include views which seems to be unexpected in this case.
/cc @nineinchnick
- @cebe I'm looking at the `Schema` sources and can't figure out the best solution to this. We can't add arguments to `getTableNames()` and can't modify its return type. `TableSchema` could contain an extra property with its type but I'd prefer to avoid an extra query in `getTableSchema()`. Those are expensive for example in Oracle.

I guess we could add another method like `getViewNames()` to filter them out in `checkIntegrity()` but it would be confusing for `getTableNames()` to also include views.
