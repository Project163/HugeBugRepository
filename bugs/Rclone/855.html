Title

bisync: modtime of latest/updated file gets changed matching modtime of the previous revision

Description
#### What is the problem you are having with rclone?

Using `bisync`, where the remote is Synology NAS SFTP, the modification time of file downloaded file is sometimes not updated properly on one of the nodes and eventually the "old" modtime gets propagated to all the nodes.

Note that the content / checksum of the file is correctly propagated as expected. The confusion comes from the fact that the modtime of the file ends up being the date of the previous revision of the file, and that is propagated to all the nodes.

After spending some time on this, I got back to a working behavior by changing the pattern to prevent pulling any conflict files and removing rclone generated conflict files on all my nodes. In other words, the bisync pattern I used was pulling conflict files wich would themselves conflict with other conflict files from other nodes. I didn't care much about those files as I could confirm the main file(s) were ok.

However, my understanding of the problem is that those conflicts would somehow interfere with the bisync operation in a way that made the moditfication time not be updated while the content of the file was.

I understand that bisync is in beta and I'm happy to report that the feature is useful to me.
