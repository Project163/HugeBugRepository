Title

torch.nn.functional.scaled_mm confusing use of lists/no validation before they are used

Description
### 🐛 Describe the bug

`torch.nn.functional.scaled_mm` allows lists for swizzle type as well as allowing a default for `swizzle_{a,b}` of `None` which translates into an empty list, but doesn't seem to check the lengths of the swizzle type lists before they are used.

* The default value of `swizzle_{a,b}` is `None` in the `torch.nn.functional.scaled_mm` Python API. This gets converted to an empty list [Link: here] and ~this would lead to an invalid access of the first element of the empty list as above~ this leads to an error if the default is left as is. (I would have also expected `None` to be equivalent to `SwizzlingType.NO_SWIZZLE`, which might make that enum value redundant?)
* `swizzle_{a,b}` isn't used at all by GEMM impls that aren't mxfp8/nvfp4, but there aren't any checks to ensure that no swizzle type was passed.
* Only the first element is ever used for `swizzle_{a,b}`, so passing a list with more elements is silently ignored regardless of GEMM implementation used.
