```ts
const qb = this.repository.createQueryBuilder('member');

qb.where(new Brackets((sq) => {
    sq.orWhereInIds(query.includeMemberIds);
}));
```

The above query fails with the error "Cannot read property 'metadata' of undefined". The following works fine:

```ts
const qb = this.repository.createQueryBuilder('member');

qb.where(new Brackets((sq) => {
    sq.orWhere('member.id IN (:...includeMemberIds)', { includeMemberIds: query.includeMemberIds });
}));
```
Discussion
- The same issue with `where` instead of `orWhereInIds`, when I pass object. Looking at source code, I can conclude that until fixed it will only work for strings and functions
- Also, if I workaround this by manually initializing `mainAlias` (using `from`), I get error that, when using object as conditions, values are written to `nativeParameters`, but later extracted from qb using `getParameters()`, which doesn't return them, so you get query with parameters placeholders (`$ ` in case of postgres), but without values passed to db for them
- I faced the same issue, the workaround work though! thanks
- I believe this fails because there's overlap in the parameters & how they get pulled in with brackets.

this is made worse because the `orWhereInIds` just does its own thing separate from everything else.

Ideally:

- Allow for nested parameter sets that don't get overwritten
- Update whereInIds to just use standard queries / `.where` code instead of special logic & crafting its own special SQL
