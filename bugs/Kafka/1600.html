- `LogSegment.recover` discards invalid bytes from the end of the segment. Not sure why that didn't happen here. cc  junrao
- Interesting. First, in general, if there is an IOException during writing to the log, the broker will shut down immediately. Second, if the cleaner hits an IOException, currently, we just abort the current cleaning job. The existing log should be intact. The "invalid message" from the fetch follower seems a bit weird. That suggests that the log segment at offset 0 is corrupted somehow. Could you use the DumpLogSegment tool ( [URL] on that segment in the leader to see if there is any log corruption?
