Title

SSVD job doesn't clean it's temp dir, and fails when seeing it again

Description

    
Discussion

    
- Are you sure?  

 any job will fail if output directory exists, unless -ow is specified. FWIW i don't recollect any troubles running it over and over as long as i give it -ow (same as with other CLIs)
- It does fail if the output directory already exists, and that's fine. 

 But it does not clear --tempDir when -ow is specified, the user has to manually clean the tempDir before each run else the Q-job, Bt-Job, U-job etc.. fail. 

 Ideally the tempDir should be cleared up when SSVDcli exits -  
   
   fs.deleteOnexit(getTempPath())
   
  
 unless there are other reasons for not doing it. 

 I was proposing to clear the --tempDir along with outputDir if -ow is specified,  and to always delete the tempDir when the job exits. 

 Similar issue with the RowSimilarity job was fixed as part of Mahout-834.
