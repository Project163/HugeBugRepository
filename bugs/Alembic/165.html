Title

SQLite3 retains primary key after dropping column

Description
**Migrated issue, originally created by Joel Tio ([Link: @joeltio])**

Alembic 0.9.10, tested on SQLite 3.23.1.

Minimal Example (a revision):

```
def upgrade():
    op.create_table(
        "test_table",
        sa.Column("id", sa.Integer, primary_key=True),
        sa.Column("some_column", sa.String),
... [Log Snipped] ...
def downgrade():
    op.drop_table("test_table")
```

When I `.dump test_table` after executing `alembic upgrade head`, I get the following output:

```
PRAGMA foreign_keys=OFF;
BEGIN TRANSACTION;
CREATE TABLE IF NOT EXISTS "test_table" (
        some_column VARCHAR,
        id INTEGER NOT NULL,
        PRIMARY KEY (id)
);
COMMIT;
```
The primary key `id` is retained even after dropping the column.
