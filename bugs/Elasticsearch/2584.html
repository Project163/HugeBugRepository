Title

Aggregations - Significant_text aggregation shouldn't error on non-existant fields

Description
A user [Link: reported] that the significant_text aggregation throwing errors for missing fields is undesirable.

There are 2 sides to this conundrum:
1) Users who mis-type field names in things like `terms` aggregations get blank results and no warnings of their mistake
2) Users of the significant_text aggregation who want to query across heterogenous indices where it is OK for some indices to have a specified field name missing.

For now the policy should be for all aggregations encountering a missing field to fail silently (i.e. return blank results and throw no errors). In future we may consider adding a search flag to allow failures on missing fields but that is for a different issue.
