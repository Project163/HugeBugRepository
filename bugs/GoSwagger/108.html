Title

Missing `gcc` in docker image

Description
## Problem statement

When trying to generate the spec for a simple app that imports `"net/http"` using the docker image fails.

## Steps to reproduce

1) `mkdir /tmp/missing-gcc`

2) `cd /tmp/missing-gcc`

3) `vim main.go` ->

```
// Package main
//
// The purpose is to demonstrate swagger docs for a test app.
//
// Schemes: http
... [Log Snipped] ...
	http.ListenAndServe(":8080", nil)
}
```

4) `docker run --rm -it -v $PWD:/go/src/missing-gcc -w /go/src/missing-gcc quay.io/goswagger/swagger generate spec` 

Should output:
```
exec: "gcc": executable file not found in $PATH
cgo failed: [go tool cgo -objdir /tmp/net_C170243402 -- -I /tmp/net_C170243402 cgo_linux.go cgo_resnew.go cgo_socknew.go cgo_unix.go]: exit status 1
/usr/local/go/src/net/lookup_unix.go:58:24: undeclared name: cgoLookupHost
/usr/local/go/src/net/lookup_unix.go:70:24: undeclared name: cgoLookupIP
/usr/local/go/src/net/lookup_unix.go:86:23: undeclared name: cgoLookupPort
/usr/local/go/src/net/lookup_unix.go:95:24: undeclared name: cgoLookupCNAME
/usr/local/go/src/net/lookup_unix.go:162:23: undeclared name: cgoLookupPTR
couldn't load packages due to errors: net
```
## Environment
swagger version: 0.8.0
commit:  

## Discussion

Adding `RUN apk --update add alpine-sdk` to `Dockerfile` fixes this issue, though there should be a subset of packages which will result in a smaller image that should fix this as well.
