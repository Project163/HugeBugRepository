Title

Unreadable result on cluster deactivation via IgniteMXBean

Description
Several MX bean methods throw  IgniteException / JMException . Such exceptions or their causes cannot be deserialized on the client-side without class transfer or class path preparation. The error could look like: 
  
 
java.rmi.UnmarshalException / java.lang.ClassNofFoundException
 
  
 instead of the desired exception. See the pictures attached. They represent results on jconsole.  
The method examples: 

  
 
IgniteMXBean.clusterState(...)
IgniteMXBean.executeTask(...)
IgniteClusterMXBean.tag(...)
 
  

 The simplest solution could be just throwing RuntimeException with the error message (example on the picture "Good").  

 Or we could deprecate exception-throwing deactivation methods and bring new ones returning a string like "Cluster deactivated." / "Cluster activated." or "Failed. Cause: ...". But IgniteClusterMXBean already has several deprecated cluster-state methods. 

  This ticket suggests another approach:  
Let's fix existing wrapping with  JMException  so that it keeps only the error message without non-deserializable causes. Let's wrap  IgniteException/IgniteCheckedException  into such  JMException  in other places. This would slightly change the API: several mx-bean methods like  IgniteMXBean.clusterState(...)  will obtain  throws JMException . User code might not be compiled. But why using mx bean API?
