Title

Detecting counter cache columns where there aren't any

Description
Currently there is a bug in `has_many` relationships that leads to columns being treated like a counter cache inconsistently. The offending code is in the [Link: `has_cached_counter?`] method. This method will return `true` if there is an attribute on the model with a name matching `#{association_name}_count` regardless of whether or not the the `counter_cache` option has been set on the `belongs_to` end of the association.

I have created a [Link: sample app with some tests] that demonstrate the problem. All the tests in this file should pass but the last two fail.
