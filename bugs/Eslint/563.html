Title

Enhancement request: Support leading/trailing spaces in rule message format placeholder names

Description
When using formatted/interpolated rule messages, the contents of the identifier between `{{` and `}}` characters are extracted exactly as is, meaning it is impossible to use whitespace for readability without doing some interesting things in the interpolation code.

Possible now:

```
js
// No spaces:
var message = "Unexpected {{thing}}";
context.report(node, message, { thing: "foo" });

... [Log Snipped] ...
var message = "Unexpected {{ thing }}";
context.report(node, message, { thing: "foo" });    // Trims " thing " before storing it as interpolation point
```

This might be a breaking change in case anyone has been using the second behavior.

I know this is a pretty trivial thing, but sometimes, a little readability goes a long way. (And I'm happy to implement if this gets accepted, as well, since I know the core team would probably not have time for something like this.)
Discussion
- I think this was probably unintended, would be good to get it fixed.
