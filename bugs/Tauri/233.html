Title

[bug] `asset` protocol will replace `asset://` too many times

Description
### Describe the bug

I noticed that this code:
[URL]

(EDIT: Don't know why it's not showing embedded code for that URL, nevertheless here it is:)#
```rust
        #[cfg(target_os = "windows")]
        let path = filtered_path.replace("asset://localhost/", "");
        #[cfg(not(target_os = "windows"))]
        let path = filtered_path.replace("asset://", "");
```

will consume extra occurrences of `asset://` in the URL. (See [URL]

```rust
use url::Url;

fn main() {
    let parsed_path = Url::parse("asset://blahblah/asset://123").unwrap();
    println!("{:?}", &parsed_path[..].replace("asset://", ""));
}
```

I don't think this is major but it may be worth being a little bit more paranoid in case this could interact badly with some application code and lead to an exploit.

Sorry if this issue is invalid because it's somehow being escaped by this point, but I thought it would be better safe than sorry.

Especially notably is that it gives the ability to resolve a URL that otherwise may not be allowed.
