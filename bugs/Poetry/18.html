Title

`~=` version constraints (PEP 440) do not correctly set the lower version

Description
- [Link: x] I am on the [latest] Poetry version.

- **Poetry version**: 0.12.16
- **Link of a [Link: Gist] with the contents of your pyproject.toml file**: N/A

## Issue
 

Found this while fixing handling of pre-release (#1150)

PEP 440 says
- `~=V.N` maps to `>= V.N, == V.*`

Examples
```
~= 2.2

~= 1.4.5
... [Log Snipped] ...
~=  
```

but looking at the tests `~=3.5.3` maps to `>=3.5.0,  =3.5.3, <3.6`. The trailing `3` should be setting the floor for the version
Discussion
- Also having issues with this. Example pyproject.toml:

```
toml
[tool.poetry]
name = "cirq-test"
version = "0.1.0"
description = ""
... [Log Snipped] ...
requires = ["poetry>=0.12"]
build-backend = "poetry.masonry.api"
```

Package cirq requires ```sortedcontainers~=2.0``` (see [Link: requirements.txt])

Running ```poetry install``` leads to:

```
  - Installing sortedcontainers (1.5.10)
```
When clearly the PEP 440 spec specifies that ```~=2.0``` should resolve to ```>=2.0,==2.*``` which would exclude ```1.5.10```. FYI the latest stable version of sortedcontainers is currently [Link: 2.1.0].
- @stevegore Your case is different and is not a bug. `cirq` declares this dependency `sortedcontainers (~=1.5)` as you can see here: [URL]
