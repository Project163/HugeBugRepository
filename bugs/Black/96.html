Title

gitignore rules are not prominently documented and ignore checked in files

Description
My `.gitignore` is quite simple. It forces me to explicitly add new files or use `-u`; which is good practice and I don't have to worry about adding a bunch of exclusion rules as things pile up.

```
*
```

However black's "convenient" functionality of using the `.gitignore` to decide which files to exclude *without taking into account whether or not the file is checked in* means I cannot simply apply `black` to my source directory. 

```
sh
No Python files are present to be formatted. Nothing to do 😴
... [Log Snipped] ...
black, version 21.4b2
```

This is not the first large project I've seen where "convenient" features eventually weasel their way in. They might help the common case, but can totally defy other user's expectations and are *rarely* documented (\*cough cough\* `setuptools_scm` \*cough\*). It's mad. Resist the temptation please. Code formatting has *nothing* to do with version control. If someone thinks it's important, let it be a plugin and extra: `black[vcs]`
