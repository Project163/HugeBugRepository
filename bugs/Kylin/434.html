Title

Tables in the `default` Database Cannot Be Directly Queried When Only the Table Name Is Specified in the SQL Statement

Description
When querying a table in the `default` database by specifying only the table name in the SQL statement, and directly querying an internal table, the system fails to prepend `INTERNAL_CATALOG` to the table name. As a result, the query targets Hive data instead of the intended internal table.
Discussion
- Root Cause 

 When the option to directly query internal tables is selected, `SchemaConverter` parses the table name from the SQL and prepends the internal table schema (`INTERNAL_CATALOG.{project}`) to the table name to enable direct querying of internal tables.   

 However, `SchemaConverter` only recognizes table names in the `DB.TABLE` format. When the database name is omitted in the SQL, it fails to identify the table name. As a result, the internal table schema is not prepended, and the query defaults to using the Hive schema instead.   
 
   Dev Design 

 Fix `SchemaConverter` to correctly identify cases where the database name is omitted in the SQL. Specifically:   
1. Ensure that the table name is recognized even when the database name is not explicitly specified.   
2. Handle edge cases, such as distinguishing between table names and aliases defined in `WITH` clauses following the `FROM` clause.
