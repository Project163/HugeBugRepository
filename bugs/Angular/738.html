Title

[IVY][Fix] Remove work-around for local refs on

Description
Let's consider the following (contrived) example:

```html
  
{{ tpl.createEmbeddedView != null }}  
```

In the above example the `tpl` variable should be of type `TemplateRef`. 

This case is not yet supported in the ngIvy compiler / runtime and this issue is opened to discuss possible solutions.

## Current work-arround

In the existing tests we are using the following work-around:

```typescript
if (cm) {
  container(0, tplContentFn, undefined, undefined, ['tpl', '']);
  text(2);
}
const tpl = getOrCreateTemplateRef(getOrCreateNodeInjectorForNode(load(0)));
text(2, tpl.createEmbeddedView != null);
```

This is obviously _not_ what we want to use long-term so what follows is a set of 3 proposals with the indication of my favourite one.

## Proposals

### A dedicated load instruction

The simples / most naive approach is to create a dedicated `loadTemplateRef` instruction, ex.:


```typescript
if (cm) {
  container(0, tplContentFn, undefined, undefined, ['tpl', '']);
  text(2);
}
const tpl = loadTemplateRef(0);
text(2, tpl.createEmbeddedView != null);
```

Pros:
* trivial to implement

Cons:
* compiler needs to work harder to figure out that `#tpl` is pointing to a `TemplateRef`
* not consistent with the existing local ref resolution / load code

### A dedicated local ref resolution strategy

We can't simply add another if / else to the existing local ref resolution strategy - it would be well too easy to add a piece of logic for a `TemplateRef` [Link: here] but this would kill tree-shaking (we would have to bring `TemplateRef` and related code for every element / container instruction). 

Instead we could introduce a strategy for a default (without a value) local ref resolution, ex.: 

```typescript
if (cm) {
  container(0, tplContentFn, undefined, undefined, ['tpl', ''], tplRefByDefaultStrategy);
  text(2);
}
const tpl = load(0);
text(2, tpl.createEmbeddedView != null);
```
