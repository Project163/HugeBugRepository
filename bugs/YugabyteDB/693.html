Title

[xCluster] Dropping a table doesn't delete its cdcstream

Description
Jira Link: [Link: DB-3056]
### Description

In master currently, dropping the table doesn't drop the xCluster stream, as the stream gets overwritten as `DELETING_METADATA`, and so the stream does not get fully deleted.
In 2.14, the stream does get deleted so we need to handle this here, as the DeleteCDCStream will fail to find the stream.

Noticed while backporting #12003, where we have different behaviour in older versions compared to master. It looks like there a discrepancy in between 2.14 and master for `CatalogManager::FindCDCStreamsForTableToDeleteMetadata`:


in 2.14:
```
      if (ltm->table_id().Get(i) == table_id && !ltm->is_deleting_metadata() &&
          !ltm->namespace_id().empty()) {
```
in master:
```
      if (ltm->table_id().Get(i) == table_id && !ltm->is_deleting_metadata()) {
```
