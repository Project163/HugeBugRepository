Title

SQL: sub-fields with different types in different indices are not picked up by the IndexResolver

Description
Given two indices `index-1` and `index-2` with the following mappings:

**index-1**

```
{
    "mappings" : {
        "properties" : {
          "foo" : {
            "properties" : {
... [Log Snipped] ...
      }
    }
```

**index-2**

```
{
    "mappings" : {
        "properties" : {
          "foo" : {
            "properties" : {
... [Log Snipped] ...
      }
    }
```

and the following test data:

- `localhost:9200/index-1/_bulk`
```
{"index":{}}
{"foo":{"bar":{"baz":123}}}
```

- `localhost:9200/index-2/_bulk`
```
{"index":{}}
{"foo":{"bar":{"baz":"lorem ipsum"}}}
```

**Searching with a simple** 

```
{
  "query": "select * from \"index-*\""
}
```

**Will throw an unusual and unexpected error:**

```
[elasticsearch] [2019-03-01T10:32:37,892][WARN ][r.suppressed             ] [node-0] path: /_sql, params: {}
[elasticsearch] org.elasticsearch.xpack.sql.SqlIllegalArgumentException: Type Integer (returned by [foo.bar.baz]) is not supported
[elasticsearch]         at org.elasticsearch.xpack.sql.execution.search.extractor.FieldHitExtractor.unwrapMultiValue(FieldHitExtractor.java:138) ~[?:?]
[elasticsearch]         at org.elasticsearch.xpack.sql.execution.search.extractor.FieldHitExtractor.extractFromSource(FieldHitExtractor.java:188) ~[?:?]
[elasticsearch]         at org.elasticsearch.xpack.sql.execution.search.extractor.FieldHitExtractor.extract(FieldHitExtractor.java:105) ~[?:?]
... [Log Snipped] ...
[elasticsearch]         at java.util.concurrent.ThreadPoolExecutor$Worker.run(ThreadPoolExecutor.java:628) [?:?]
[elasticsearch]         at java.lang.Thread.run(Thread.java:834) [?:?]
```

What should have actually happened is that a different error should have been thrown:

```
Cannot use field [foo.bar.baz] due to ambiguities being mapped as [2] incompatible types: [long] in [index-1], [text] in [index-2]
```
