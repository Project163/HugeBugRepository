Discussion
- At revision 1399172 I switched the query tests from above to use  OpenSecurityProvider  which causes these tests to pass. However now virtually all jcr tests fail with a  No LoginModules configured for jackrabbit.oak . See  [URL]
- In revision 1399192 I reverted the changes from above. 
I also implemented a fall back to the default configuration when the provided configuration does not contain a configuration for the jackrabbit.oak app name.
- ... [Middle Discussions Snipped for Brevity] ...
- The problem is with the  Configuration.getConfiguration()  call in  SecurityProviderImpl.getLoginContextProvider() : The Oracle JVM seems to throw a  SecurityException  when the configuration cannot be located even though the Javadoc states that a default configuration would be returned in that case. Other JVMs seem to behave differently here.
- My point here is that the query tests should never hit the  getConfiguration()  call, so a better fix here would be to change the way the repository used by the query tests is set up (i.e. not include any security components).
