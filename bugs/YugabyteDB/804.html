Title

Tserver Registration hazard - UUID can be blank

Description
Jira Link: [Link: DB-3832]
At tserver startup, it may encounter difficulty reading the instance file, and try to register with an empty UUID, as in the case below:

```1008 02:07:23.531638 26967 ts_manager.cc:140] Registered new tablet server { permanent_uuid: "" instance_seqno:   start_time_us:   } with Master, full list: [{ ,   -> { permanent_uuid:   registration: common { private_rpc_addresses { host: " " port: 9100 } http_addresses { host: " " ...```

The server should protect itself by verifying that a reasonable UUID is available, before attempting to register.
Discussion
- @es1024 , It looks like when this issue occurs, it can result in loss of tablets from that node (inadvertantly). So it would be better to fix the above or crash the tserver if the UUID is empty. cc @bmatican
- Notes from JIRA: When the master receives a tserver registration with an empty UUID, it promptly tells that tserver (by IP) to delete all tablets, since the UUID is not recognized.
For further protection, the master should not accept a registration with an empty UUID.
- Worth logging all the places where the UUID is obtained.
