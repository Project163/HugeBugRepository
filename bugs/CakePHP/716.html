Title

Deprecation Workarround Failure: ViewBuilder does not have a method name view()

Description
Part of the deprecation workaround logic for the "magic" controller properties `$layout`, `$view` etc. is to call the method of the same name in the view builder in the controller's `__set()`method. This is done for the following properties: `['layout', 'view', 'theme', 'autoLayout', 'viewPath', 'layoutPath']`.

The class `ViewBuilder` has method of the same name, **except** for _view_ and _viewPath_, the matching methods are called _name_ and _templatePath_ (?)

In the current version the "fix" creates a fatal error (happened to me after upgrade to 3.1)
Discussion
- Ok, the correct partner for _view_ is _template_, not _name_.

I'm not quite sure what _name_ is for, the method's comment says "The name of the view", the property's "The view variables to use" (which is also the comment for `$_className` and `$_options`, but that might be another issue). In the class `View` it's commented as "name of the controller", but never used.
- I can update the deprecation warnings to suggest the correct methods.
- I've updated the error messages and fixed the documentation errors I could find in #7475.
