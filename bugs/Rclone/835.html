Title

`make doc` creates a directory named `$HOME` in the source tree

Description
When I ran `make doc` at  , I was surprised to see that it dumped a new directory called `$HOME` in the source tree.

```console
% tree -a '$HOME'
$HOME
└── .config
    └── rclone
```

More specifically, it seems that `make commanddocs` is sufficient to reproduce the bug.

This *probably* has something to do with the Makefile dollar sign business here:

[URL]

I would write up a PR, but I'm not really sure what the intent is. If the goal is to pass the `HOME` environment variable through unmodified, you could just say nothing?
Discussion
- I think the point is that we want the literal `$HOME` and `$USER` to be present in the generated docs for publishing on rclone.org, not the expanded values from the build system. Maybe this command should run with `--config /notfound` or something to stop it from creating config on disk (https://rclone.org/docs/#config-config-file).
- Ah, thanks! I think you're right about this being a hack to so that `$HOME` appears in the docs. Neat trick, I didn't realize `/notfound` was special. It would mean the docs would say `/notfound` instead of `$HOME` though, right?

Another possible solution is to use a placeholder name and then search/replace with sed. I find it a little confusing/terrifying to instruct a Makefile to delete `'$HOME'`, whether single quoted or not, and this way we don't have to.

```diff
 commanddocs: rclone
-       XDG_CACHE_HOME="" XDG_CONFIG_HOME="" HOME="\$$HOME" USER="\$$USER" rclone gendocs docs/content/
+       XDG_CACHE_HOME="" XDG_CONFIG_HOME="" HOME="tmpFakeHomeDirForDocGen" USER="\$$USER" rclone gendocs docs/content/
+       find docs -name '*.md' -exec sed -i tmpFakeHomeDirForDocGen '$HOME' {} \;
+       rmdir -p tmpFakeHomeDirForDocGen/.config/rclone/
```

Alternatively, maybe config.go should be a little more careful about when it creates these directories. Right now, it happens in `makeConfigPath()` which is called by `init()`!  [URL]
