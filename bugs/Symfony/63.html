Title

JsonResponse can not be used to return an empty array

Description
I have a REST API that is used for retrieving a list of objects. From our perspective this API could quite legitimately return no matching results (ie an empty array).

JsonResponse force converts an empty array to an ArrayObject which then gets output as an empty object giving us the wrong results on the client side. Nothing in the JSON spec mandates that the top level element can not be an empty array as such this looks like a bug in the Symfony JsonResponse object.

The offending code is viewable [Link: here]. Fixing it should just be a matter of removing that if statement.
Discussion
- There are two reasons to enforce objects at the top level of the JSON responses:

- If you always return something like `{"items": []}`, the day you need to return the items + some other stuff (total count for paging, related link, anything really)  you can just add it without breaking the API: `{"items":[], "stuff":"woo"}`.
- - The offending line of code in JsonResponse will do nothing to prevent that. It ONLY changes a top level array to an object when the array is empty.
