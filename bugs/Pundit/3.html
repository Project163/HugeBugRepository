Title

Better Exception on #policy_scope

Description
Hey.

We use `pundit` for a project and we've got an Exception which was confusing.

So we have a Policy with a Scope. And in the scope we did something wrong on a query. The query thrown an exception, and it was an ArgumentError too. But pundit catch it and returned an other exception who wasn't really linked to.

I guess the [Link: `#policy_scope`] method could be:

```ruby
    def policy_scope(user, scope)
      policy_scope = PolicyFinder.new(scope).scope
    rescue ArgumentError
      raise InvalidConstructorError, "Invalid #  constructor is called"
    else
      policy_scope.new(user, pundit_model(scope)).resolve if policy_scope
    end
```

or 

```
ruby
    def policy_scope(user, scope)
      begin
        policy_scope = PolicyFinder.new(scope).scope
      rescue ArgumentError
... [Log Snipped] ...
      policy_scope.new(user, pundit_model(scope)).resolve if policy_scope
    end
```
Discussion
- Yes, it looks like this could be improved. I guess you want to to everything but the `.resolve` within the being/rescue block though. It's this `policy_scope.new(user, pundit_model(scope))` call that we want to rescue if it fails.
- My first read of the exception name was "I did something wrong on pundit declaration or Scope creation", because exception name is `InvalidConstructorError`. But the `rescue` scope also include the `#resolve` method. 


So yes, I guess that it could be better to only rescue the constructor/initializer and without catching `ArgumentError` thrown by ruby for code inside `#resolve` method.
