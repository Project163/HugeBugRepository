Title

glfwWaitEventsTimeout doesn't process QS_SENDMESSAGE on Windows

Description
#### Description
[URL]  `MsgWaitForMultipleObjects` doesn't include `QS_SENDMESSAGE` flag. This will result in some messages not being processed.

I first encountered this issue when I use [Link: tiny file dialogs]. To reproduce:
1. Create a GLFW window on main thread.
2. Use `glfwWaitEventsTimeout` in main thread loop.
3. Open a `tinyfd` dialog from non-main thread (a background thread).

You will see `glfwWaitEventsTimeout` won't return and process input events for the dialog window, so the dialog is not responding. It only returns after `timeout` seconds has expired. Of course, `glfwWaitEventsTimeout` works for input events for the GLFW window.

#### My workaround
1. Only use `glfwWaitEvents` and `glfwPollEvents` in main thread loop, they can process input events for the background dialog window.
2. Use `tinyfd` only on main thread. In this case, the dialog window is responding, but it will block application's main thread.

#### Possible solution
Replace `QS_ALLEVENTS` with `QS_ALLINPUT`.
