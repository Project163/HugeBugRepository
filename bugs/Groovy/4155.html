Discussion
- I see where the problem is in JavaStubGenerator.  You can work around this by adding a typecast to your Groovy source: 
  
 
 class  G  extends  J {
    G() {
         super (( Integer )integerMethod())
    }
    static  Integer  integerMethod() { 42 }
}
- There was no such issue in 3.0.7. Did you manage to find the cause? Can you port the fix to the 3.0.x branch?
- Yes, the fix for ambiguous special constructor call (  GROOVY-9777  ) added Object cast.  This caused problems for path where type of constructor call argument cannot be determined easily.  This fix will be added to Groovy 3 branch before 3.0.9 is released.
- This is marked as fixed in 3.0.9, but I am still seeing the issue there. For example, the following class: 
  
 
 class  TestGeneric<T>  extends  AtomicReference<T> {
    TestGeneric(T value) {
         super (value)
    }
}
 
  
 Produces the following error: 
  
 
TestGeneric.java:15: error: incompatible types:  Object  cannot be converted to T
 super  ((java.lang. Object ) null );
       ^
  where T is a type-variable:
    T  extends   Object  declared in  class  TestGeneric
 
  

 Note that the suggested workaround of explicitly typing the "super(value)" as "super((T)value)" does not work in this case.
