Title

Segfault when calling memory_efficient_attention_backward

Description
### 🐛 Describe the bug

On `torch == 2.11.0.dev20260108+cu128` I get a segfault when running the following code:

```
python
import torch

q = torch.rand(2, 8, 256, 64, device="cuda", dtype=torch.float16, requires_grad=True)
k = torch.rand(2, 8, 256, 64, device="cuda", dtype=torch.float16, requires_grad=True)
... [Log Snipped] ...
grad_o = o.clone()
g = torch.ops.aten._scaled_dot_product_efficient_attention_backward.default(grad_o, q, k, v, None, o, lse, phi1, phi2, 0.0, (True, True, True, True), False, scale=None)
```

It might be that I'm calling something wrongly, but I would have expected that segfaults shouldn't happen from within Python?

### Versions

I'm using `torch == 2.11.0.dev20260108+cu128` on a H100 machine
Discussion
- One issue seems to be that the `grad_input_mask` that is specified is wrong -- we don't have a bias but we request to compute the backward for it. So this is user-error.

Another user error was that I'm not requesting to compute the lse, while I need it for backward. So another user error.

Given that we could say those are private APIs I don't think this is release blocking, but still might be good to add additional checks to make things more robust
- @fmassa to be fair, you are calling an internal op, rather than public `torch.nn.xyz` method. I suspect lots of error checking is happening there rather than in C++ code
