Title

Helm 4 template uses K8s 1.20 default instead of client-go version

Description
### What happened?

Helm 4's `helm template` command defaults to Kubernetes 1.20 instead of matching the client-go version (currently 1.34). This causes charts that use `.Capabilities.KubeVersion` to render old/deprecated API versions.

Charts using capability detection (like Bitnami's common library) render `policy/v1beta1` instead of `policy/v1` for PodDisruptionBudgets, `batch/v1beta1` instead of `batch/v1` for CronJobs, etc.

**Root cause:** The `Makefile` (lines 70-71) has incorrect LDFLAGS paths. They target `helm.sh/helm/v4/pkg/chart/common/util.k8sVersionMajor` but the variables are actually in `pkg/chart/common/capabilities.go` (package `common`, not `common/util`). The LDFLAGS silently fail, leaving the hardcoded 1.20 defaults instead of the client-go version.

This was introduced in commit 9dcc49cbd "Move lint pkg to be part of each chart version".

### What did you expect to happen?

`helm template` should default to the Kubernetes version matching the bundled client-go library (v0.34.x = K8s 1.34), allowing charts to render current stable API versions when no cluster is available or `--kube-version` is not specified.
