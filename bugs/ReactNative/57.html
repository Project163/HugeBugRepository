Title

Apple requiring Location purpose strings in RN apps < 0.60

Description
## Resolution: Geolocation is no longer bundled with React Native as of RN 0.60

Starting with 0.60, Geolocation will not be part of React Native and should not cause any further issue. If you use Geolocation, the extracted module can be found at [URL]

# Summary

**Starting spring 2019, all apps submitted to the App Store that access user data will be required to include a purpose string**. We are aware of an issue where bundles that include React Native are automatically rejected if the `Info.plist` does not include a purpose string describing how the app makes use of location services, even in cases where the app does not make use of the Geolocation API.

As suggested by Apple and [Link: shared in this thread] by @hilkeheremans, to work around this, please add the following keys to your `Info.plist`:

* `NSLocationAlwaysAndWhenInUseUsageDescription`
* `NSLocationAlwaysUsageDescription`
* `NSLocationWhenInUseUsageDescription`

This workaround and a long term fix is discussed in @hramos's [Link: comment].

A sample of the rejection email sent by Apple is included here:


If you are running into this issue, please read the above thoroughly before commenting. Keeping the thread focused on a long term fix would be ideal.
