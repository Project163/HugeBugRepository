Title

remote name with dots is always interpreted as local filesystem directory

Description
#### Output of `rclone version`
```
rclone v1.48.0
- os/arch: linux/amd64
- go version: go1.12.6
```

#### Describe the issue

Given the following two remotes (in this case using backblaze backend):

```
[my.remote]
type = b2
account = xyz
key = xyz

... [Log Snipped] ...
account = xyz
key = xyz
```

When using the remote with dots in its name, it is always interpreted as a local filesystem:

```
$ rclone ls my.remote:mybucket
2019/09/03 14:01:58 ERROR : : error listing: directory not found
2019/09/03 14:01:58 Failed to ls with 2 errors: last error was: directory not found
```

Without dots it works as expected:

```
$ rclone ls my-remote:mybucket
... files....
```

Discussion
- I replicated this with the latest beta...

I'm amazed no-one has noticed this before!
- This is because the remote names are defined like this

[URL]

So that is `[0-9A-Za-z_ -]` - this does not include `.`

The rclone config checks the name using the same regexp

[URL]

```
e) Edit existing remote
n) New remote
d) Delete remote
[snip]
e/n/d/r/c/s/q> n
name> asfsdf.afsf
Can't use "asfsdf.afsf" as it has invalid characters in it.
```

So I guess the question is how did you make these remotes?

I don't think it would cause any backwards compatibility problems to add `.` to the allowed names for a remote.
