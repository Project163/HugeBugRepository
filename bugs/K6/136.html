Title

`k6 login cloud` panicking with 1.2.1 upgrade

Description
### Brief summary

With the upgrade to `1.2.1` from `1.1.0` we started seeing panics from using the deprecated `k6 login cloud` command as `k6 login` now only accepts `influxdb`.

It's not a huge deal as we can update our scripts that use `k6 login cloud` to the new `k6 cloud login` command, but flagging that this wasn't mentioned in the release notes if it was intended to be removed, or whether it should fail more gracefully rather than panicking.

```
$ k6 login
Command "login" is deprecated, and will be removed in a future release. Please use the "k6 cloud login" command instead.

Usage:
  k6 login [flags]
... [Log Snipped] ...
Flags:
  -h, --help   help for login
```

### k6 version

1.2.1

### OS

macOS and Ubuntu

### Docker version and image (if applicable)

_No response_

### Steps to reproduce the problem

1. Run `k6 login cloud`

### Expected behaviour

Based on the release notes, the warning to appear when running the command but the login still working.

### Actual behaviour

```
$ k6 login cloud -t foo
Command "cloud" is deprecated, and will be removed in a future release.
Please use the "k6 cloud login" command instead.

ERRO[0000] unexpected k6 panic: runtime error: index out of range [0] with length 0
... [Log Snipped] ...
main.main()
	go.k6.io/k6/main.go:9 +0x1c
```
Discussion
- Hi @indygriffiths, thank you for reporting this 🙇 

I can confirm this is happening for me as well. It seems some part of the auto extension resolution is not handling this particular case.

I can also say that you can run with `K6_AUTO_EXTENSION_RESOLUTION=false` and it works. As in 

`K6_AUTO_EXTENSION_RESOLUTION=false k6 cloud login ...` 

I will try to have see if we can make a fix tomorrow.
