- vanzin  I think we can remove the locks in `ChildFirstURLClassLoader` since we have already dropped Java 6.
- I don't think dropping the locks will work - it might make the problem worse. The locks are implementing a per-name lock similar to what JDK7 does  when the class loader is registered as parallel-capable . Without that registration, there will be a single lock on the class loader object that all threads calling  loadClass  will synchronize on. And that registration cannot be done easily when the class loader is written in Scala.
