### What happened?

With [URL] the default docker API version has been changed to 1.44.

See also [URL]

This is a breaking change for docker 24 which supports up to 1.43.

The logs are from a GitHub Actions running on BuildJet where I can not really influence docker version.

Discussion
- I checked git blame and found the root cause. While the logic to set a default API version has existed for 5 years, the default value was recently updated to VERSION_1_44 (about 3 weeks ago).   

[Link: The java file is here] 

The Problem: Docker Engine v24 supports up to API v1.43. By forcing v1.44, Testcontainers breaks compatibility for all v24 users.

Proposed Fix: We should either:

Revert the default value to a safe baseline (e.g., 1.35 or 1.41).

Or simply remove this default setting block to let docker-java negotiate the version automatically (which seems to be the preferred behavior for compatibility).

If there are no objections, I can submit a PR to remove this block (or downgrade the version).
- The problem is that while Docker Engine v24 supports up to API v1.43, Docker Engine v25 supports starting from API v1.44. So, there is no version that is compatible with both.

So, no default setting will satisfy everyone. Either people with the older version or with the newer version of Docker will need to use a "workaround". Therefore, "revert the default" will not do any good because there is no safe baseline.

Are you sure `docker-java` will do this? Will negotiate? If yes, then this could be a good solution. If no, then `testcontainers-java` should do the negotiation, in my opinion.
- Yes. First, I confirmed locally that docker-java performs auto-negotiation correctly.

Furthermore, I actually removed the 3 lines in DockerClientProviderStrategy.java to test the fix:

Java

        if (configBuilder.build().getApiVersion() == RemoteApiVersion.UNKNOWN_VERSION) {
            configBuilder.withApiVersion(RemoteApiVersion.VERSION_1_44);
        }
With this change applied, I verified that the tests passed successfully on both Docker v24 and Docker v29.

It seems docker-java correctly handles the versions defined here: [Link: RemoteApiVersion.java]
(There are a lot of version , but I've only confirmed that the tests pass on Docker v24 and v29.)
