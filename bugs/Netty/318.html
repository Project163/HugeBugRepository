Title

Lingering `GlobalEventExecutor` after graceful shutdown

Description
We've noticed an issue where a global event executor thread lingers after calling `shutdownGracefully` on an event loop group. In practice, it goes away on its own after several hundred milliseconds, but it triggers alarms in cases where there's something looking for leaked resources (like a servlet container). Here's a sample app I wrote to illustrate the issue:

```
java
import io.netty.channel.nio.NioEventLoopGroup;

public class NettyShutdownTestApp {

... [Log Snipped] ...
    }
}
```

My expectation would be that because we've gracefully shut down all Netty resources we created in our own app, all Netty-related threads would have stopped by the time the shutdown `Future` completed. When we dump the list of running threads after the sync, though, the actual list looks something like this:

```
Reference Handler
Finalizer
Signal Dispatcher
process reaper
main
globalEventExecutor-1-1
```

As a control, if we never create the `NioEventLoopGroup` or never call `shutdownGracefully`, then `globalEventExecutor-1-1` doesn't appear in the list of running threads.

Thanks!
