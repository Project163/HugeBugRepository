Probably what we should do is look at the result of the HEAD request a bit more carefully.

How about this

Issue HEAD request
- if no error assume root is a file
- if 404 error assume root is a directory and add /
- if some sort of redirect 301,302,303,307,308 check the `Location:` header
    - if it ends with a / then assume root is a directory
    - otherwise assume root is a file
- if any other error then log something like this
    - "Assuming root is a file as server returned error (%v) on HEAD request. Add a trailing / if it is a directory."
    - Assume it is a file

That would potentially be a backwards incompatible change if a the HEAD request is returning something other than 404 or a redirect when the file isn't found. I think that is fairly unlikely though and the log message would point it out.
