Title

Deleting a parent URL in History tab should not delete all child URLs

Description
See animated gif below. Note on the 3rd action against a single entry/line all entries from the history table are removed. (This is based on running from within eclipse on Windows 7.)

[Image: test]

Based on what I was testing at the time (addressing [URL] it seems that the history table (db) is actually emptied (i.e.: this is more than just a UI issue.)

I doubt it matters but just so that I'm fully providing details the history was established using accessUrl via the web API.
Discussion
- Issue title updated, setting this to 2.7.0 (does not require much changes).
- For the record, this was discussed in IRC and the conclusion is that the current behaviour is unintuitive. The behaviour in History tab should be changed to just delete the selected entries independently if they are parent URLs/nodes or not. The behaviour in the Sites tree should be kept the same, deleting a parent URL/node should delete the child URLs/nodes.
