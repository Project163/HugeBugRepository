Title

[YSQL] Incorrect "Storage Read Requests" calculation in case of using PrecastRequestSender class

Description
Jira Link: [Link: DB-12317]
### Description

The `PrecastRequestSender` class is intended to send read requests to different tables in single Perform RPC. This allows to parallel executions of read operations and reduces the number of RPC round trips.
But in spite of the fact `PrecastRequestSender` sends single RPC for reads from multiple tables the `Storage Read Requests` metric of `EXPLAIN` statement is incremented for each table individually.

I.e. in case `PrecastRequestSender` sends single RPC request to read from `t1`, `t2` and `t3` the `Storage Read Requests` will be incremented by 3 instead of 1. This contradicts with the meaning of `Storage Read Requests` metric

Quote from YB doc for `EXPLAIN` command (https://docs.yugabyte.com/preview/explore/query-1-performance/explain-analyze/)

```
Storage Table Read Requests: Number of RPC round-trips made to the local [Link: YB-TServer] for main table scans.
...
Storage Read Requests: The sum of number of table reads and index reads across all plan nodes.
```
