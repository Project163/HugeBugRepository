Title

NPE in FactoryFinder.findClass when context classloader is null

Description
My program works fine, when I run it as a normal Windows app.  But when I try to run it as a service, it throws a "Could not auto create component: http" which is caused by a NullPointerException which is caused by Thread.currentThread().getContextClassLoader() returning null. 

 A quick search found this ActiveMQ bug:  [URL] which is essentially identical.  If it's been fixed in ActiveMQ, probably you can just merge the fix from org.apache.activemq.util.FactoryFinder into org.apache.camel.util.FactoryFinder. 

 Incidentally, the fact that the context classloader is null has also been reported as a bug:  [URL]
Discussion
- Trev, could you paste the stacktrace please. 

 FactoryFinder delegates its classloading to ObjectHelper.loadClass and it looks like it handles the null. So a stacktrace is needed.
- ObjectHelper.loadClass returns a null, and eventually FactoryFinder.findClass passes that null to ConcurrentHashMap.put, which causes the NPE.  Stacktrace attached.
- Trev, thanks for the stacktrace. 

 I am currently improving Camel to be able to handle the nulls.
