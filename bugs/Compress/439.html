Title

Pack200 causes a 'archive.3E' error if it’s not in the system class loader.

Description
import  org.apache.commons.compress.java.util.jar.Pack200;
 import  java.lang.reflect.Method;
 import  java.net.URLClassLoader;
 import  java.net.URL;
 import  java.io.File;

 class  Main {
   public   static  void main( String [] args)  throws  Throwable {
    URLClassLoader ucl =  new  URLClassLoader( new  URL[] {
       new  File( "." ).toURI().toURL(),
       new  File( "commons-compress-1.21.jar" ).toURI().toURL(),
    },  null );

     System .out.println( "=== Unpacker ===" );
    Method method;
     try  {
      method = ucl.loadClass( "InClassLoaderClass" ).getDeclaredMethod( "unpacker" );
      method.setAccessible( true );
      method.invoke( null );
    }  catch  (Throwable t) {
      t.printStackTrace();
    }

     System .out.println( "=== Packer ===" );
     try  {
      method = ucl.loadClass( "InClassLoaderClass" ).getDeclaredMethod( "packer" );
      method.setAccessible( true );
      method.invoke( null );
    }  catch  (Throwable t) {
      t.printStackTrace();
    }
  }
}

 class  InClassLoaderClass {
   public   static  void unpacker() {
    Pack200.newUnpacker();
  }
   public   static  void packer() {
    Pack200.newPacker();
  }
}
 
  
 execute this code (same as attached  Main.java ) with  ClassLoaderClass.class  (compiled code of this file) and  commons-compress-1.21.jar  is on working directory will cause the following error:

- Hello 

 I think using  ClassLoader  of  Pack200  is good. 
In addition, removing system property check and directly instantiating  Pack200(Packer|Unpacker)Adapter  with  new  expression without checking system property is also good. 
The  java.util.jar.Pack200.Packer  system property is used to get name of class implements  java.util.jar.Pack200.Packer  in JDK so using it to get implementation of commons-compress will cause cast error, I think. That's why I think removing system property is not too breaking change.
