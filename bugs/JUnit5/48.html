Title

Test execution exceptions are not supplied to extensions

Description
## Status Quo

`TestExtensionContext` does not provide access to any exception thrown during execution of the test method or other extensions.
## Deliverables
- [x] Reintroduce a `getTestException()` method in the `TestExtensionContext` API.
  - Note: the prototype actually had such a [Link: `getTestException()`] method.
- [x] Ensure that the JUnit Jupiter `TestEngine` infrastructure tracks any exceptions encountered during test method or extension execution and supplies the exception to extensions via the `TestExtensionContext`.
  - Note: it is assumed that the engine already properly tracks the exceptions, but tests need to be introduced to verify the expected behavior.
## Further Resources

See the `afterEach()` method in the [Link: SpringExtension] for a concrete example of where the _test exception_ is required.
Discussion
- We must be very explicit about which exceptions will get there. For example: Should an extension context see exceptions that occurred in other extension points and in other implementations of the same extension point? Or just from the same extension? Or just from the current test?
- Good questions!

The `testException` should in fact be an exception thrown during invocation of the test method. If we don't have clarity in this regard it would then be difficult if not impossible for an extension to properly react to such an exception. For example, if a developer wants to implement his own version of `@ExpectedException` using the JUnit 5 extension model, such an extension would need to access exactly the exception thrown from the test method and not from some other extension.

I tend to think that an exception thrown from a `@BeforeEach` or `@AfterEach` method should also be considered as a `testException`.

Regarding exceptions thrown by extensions, we could consider introducing an `extensionException` for that dedicated purpose. Clients of `TestExtensionContext` would then have to decide which of the two exceptions they need to support.

I think we should also consider introducing similar support for `ContainerExtensionContext`.
