Title

The autorelease pool should be drained on glfwDestroyWindow

Description
Currently `_glfw.ns.autoreleasePool` is drained and re-allocated on every call to `glfwPollEvents`. This is fine for most GLFW programs, i.e. doing memory clean-up once per frame.

It is a problem though for programs that only create (multiple) hidden GLFW windows for offscreen rendering/computation. Such programs may never call `glfwPollEvents`, there's never a need to and the documentation doesn't mention any memory-management side effects. The end result is that a lot of memory ends up leaking when the hidden windows are destroyed.

The proposal is that `glfwDestroyWindow` should also drain and re-allocate the `_glfw.ns.autoreleasePool`. This fixes the leak and there's no need to call `glfwPollEvents`.
