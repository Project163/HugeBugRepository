Title

Har metadata cache can grow without limit

Description
MAPREDUCE-2459   added a metadata cache to the har filesystem, but the cache has no upper limits.  A long-running process that accesses many har archives will eventually run out of memory due to a har metadata cache that never retires entries.
Discussion
- Here is a patch (including a unit test) for branch 23. If OK'd, then I can port it to branch 2.
- I suppose this approach improves the issue.  It still leaks, but just leaks less.  I think this can be greatly simplified to just removing the class static cache. 

 The har AFS delegates to the standard har FS which uses a cached fs.  Which means the class static cache is technically unnecessary.
