Title

MetaData becomes unpickleable when you pass an InstrumentedAttribute into the ForeignKey(column=) argument

Description
As mentioned in the title:

```
class Parent(Base):
    __tablename__ = "parent"
    id = Column(Integer, primary_key=True)


... [Log Snipped] ...

pickle.dumps(Base.metadata)  # error
```

but this works:

```
class Parent(Base):
    __tablename__ = "parent"
    id = Column(Integer, primary_key=True)


... [Log Snipped] ...

pickle.dumps(Base.metadata)  # works fine
```

It looks like this happens because the ForeignKey object keeps a reference to the InstrumentedAttribute as its ForeignKey._colspec instance attribute, which then causes the MetaData to have a reference into the entire ORM layer. Obviously this is bad because it means the pickler will try to pickle all of the model classes which were dynamically created at runtime and therefore cannot be pickled.

I've fixed it for myself in the interim by subclassing ForeignKey like so:

```
class ForeignKey(sqlalchemy.ForeignKey):
    def __init__(self, column: Any, *args: Any, **kwargs: Any) -> None:
        super().__init__(column=f"{column.comparator.table.name}.{column.comparator.key}" if isinstance(column, InstrumentedAttribute) else column, *args, **kwargs)
```

But this isn't really an ideal solution. I'm not familiar enough with the sqlalchemy internals to know what the cleanest and least wasteful way to fix this would be. 

Also, I have the sneaking suspicion that other sqlalchemy constructs similar to ForeignKey (like maybe Index, CheckConstraint, etc.) might have the exact same issue if they're implemented the same way. I haven't tested this though.

Any chance this could be looked at as a bugfix? Cheers!
