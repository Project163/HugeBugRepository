Title

mitmproxy is an order of magnitude slower than Charles

Description
I love mitmproxy but it seems to be _an order of magnitude_ slower than [Link: Charles]. 

I'm using the following script:

```
#!/usr/bin/env ruby

and_then = Time.now()
puts "Starting charles: #{and_then}"
100.times do |i|
... [Log Snipped] ...
and_now = Time.now()
puts "Ending mitmproxy: #{and_now - and_then}"
```

My results are this:

```
Starting charles: 2014-10-20 14:07:19 -0700
Ending charles: 1.567501
Starting mitmproxy: 2014-10-20 14:07:21 -0700
Ending mitmproxy: 19.765162
```

Is this inevitable given mitmproxy is written in python and Charles is compiled object code? Or, is my test suspect?

This is important because my client app (running on an iPhone) thinks the network has dropped when I use mitmproxy rather than Charles.
Discussion
- Hi Chris. Thanks for pointing this out - there's definitely a performance issue here. There is certainly no intrinsic limit at play - this is just an issue (arguably a bug) we need to track down and fix. 

The problem seems to affect mitmproxy console specifically. Using mitmdump performance is good - here's a run with a modified version of your script comparing mitmdump with no proxy at all:

```
Starting mitmdump: 2014-10-21 10:44:58 +1300
Ending mitmdump: 14.321507
Starting no proxy: 2014-10-21 10:45:13 +1300
Ending no proxy: 12.394307
```

We have a new release scheduled for the next few days - if this is an obvious issue, I'l have it fixed by then. If not, please keep an eye out for a patch release soon after.
- @cortesi this is great, I was not aware of mitmdump being functionally the same as mitmproxy. I don't need the console mode anyway and am thrilled to see that I can still use the -s switch. Thanks so much. I love mitmproxy. The best programmable proxy out there!
- Yeah, mitmproxy is cool!
I have mitmdump run at startup on my router.

If I ever want the console, I have a little script that kills mitmdump, starts mitmproxy, then restarts mitmdump, all with the same exotic set of parameters. A bit hacky, but it works!
- This turned out to be something terribly simple: a timeout value passed to the curses library had to be reduced. Performance should now be comparable to mitmdump.
