Title

[YSQL] ysqlsh on macOS: Cannot read termcap database; using dumb terminal settings.

Description
Jira Link: [Link: DB-2813]
### Description

@bllewell reported this on Slack.  -b11 release on macOS prints this when starting `bin/ysqlsh`:
```
Cannot read termcap database;
using dumb terminal settings.
```
This appears to be caused by a bad libedit.dylib. The issue didn't appear in   from website. It can be worked around by copying the lib/libedit* from   to  . I have not yet figured out what changed in the bundled libedit library. Looking at yugabyte-db-thirdparty we should be using the same `libedit-20191231-3.1.tar.gz` version from 2020: [URL]

When I build   myself, I don't see this issue. My local build is using the libedit from yugabyte-db-thirdparty:
```
$ otool -L build/release-clang-dynamic-arm64-ninja/postgres/bin/ysqlsh
build/release-clang-dynamic-arm64-ninja/postgres/bin/ysqlsh:
	/Users/deen/code/yugabyte-db/build/release-clang-dynamic-arm64-ninja/postgres/lib/libpq.5.dylib (compatibility version 5.0.0, current version 5.11.0)
	/opt/yb-build/thirdparty/yugabyte-db-thirdparty-v20220507013402-4cda3bf56c-macos-arm64/installed/uninstrumented/lib/libedit.0.dylib (compatibility version 1.0.0, current version 1.63.0)
	/usr/lib/libSystem.B.dylib (compatibility version 1.0.0, current version 1311.100.3)
```
It looks to me like we are somehow bundling a wrong libedit.dylib. I'll keep checking the build to see how the library is included there.
