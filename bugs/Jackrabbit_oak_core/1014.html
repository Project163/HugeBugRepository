Title

RDBBlobStore failure because of missing lastmod column on datastore_data table

Description
Revision 1571268 introduced a lastmod check on deleteChunks (see   OAK-377  ). It is applied to both tables, however only _meta has it. 

 We either need to add the column (and maintain it), or change the code in deleteChunks. 

  tmueller  feedback appreciated
Discussion
- I think we should have a test case, and fix the deleteChunks then, for example using a statement like this: 

  
 delete from <dataTable> where id in (<...>) and not exists(
select * from <metaTable> m where id = m.id and m.lastMod <= ?)
 
  

 I think this statement should work with all databases, should be quite fast, and would be transactionally safe (no race condition possible). The statement would need to be tested on common databases.
- I have applied the patch (which appears to work in DB2 and Postgres), but we really need test coverage for this (thus leaving the bug open)
- Seems this issue was left behind during the release, so I'm closing it.
