Title

Line chart x axis animation is broken

Description
Line chart animation on x axis is broken:
1. the value labels are always on the screen;
2. horizontal bezier animation is broken
3. additional dash line while animting `drawLinear`:
[Image: image]
Discussion
- I found commit [2a1ecb4e] is causing this
the iterator seems not respecting the range, just iterating from min to max.

In `drawHorizontalBezier()`,
for example, if xBounds min is 0, max is 9,

if use 

`print(j, _xBounds)` gives
```
1, min:0 max:9 range:2
2, min:0 max:9 range:2
```
but in the new iterator 

`print(j, _xBounds)` is
```
1, min:0 max:9 range:2
2, min:0 max:9 range:2
3, min:0 max:9 range:2
4, min:0 max:9 range:2
5, min:0 max:9 range:2
... [Log Snipped] ...
8, min:0 max:9 range:2
9, min:0 max:9 range:2
```

#### About 1. the value labels are always on the screen

this is also because of in `drawValues()` the j is iterating all values, so all labels are on the screen.
- and when I search the commit logs, I found [URL] revert `drawLinear()` xBounds iterator to old `stride()` fashion, however `drawCubicBezier()` is untouched in both commits, so this explained why only horizontal bezier is suffering.
- @jjatie there are basically two issues:
1. the replacement to new xBounds iterator is not consistent;
2. the iterator is different than the old logic of stride because of `range`

what's your thought on how to fix this? If I choose to make the xBounds iterator to respect `range`, would this causes regression on other components?

the stride() is far more complex than I expected

my current fix is relatively simple, just change
```swift
    public func makeIterator() -> Iterator {
        return Iterator(min: self.min, max: self.max)
    }
```
to
```swift
    public func makeIterator() -> Iterator {
        return Iterator(min: self.min, max: self.min + self.range)
    }
```
seems fixing all, and it aligned with
- for 

This happens in drawLinear() only and seems a bug in `context.strokeLineSegments(between: _lineSegments)`
