Title

ctrl-c should always cancel rpcrequest()

Description
While debugging deoplete-jedi, I've just added some `print('foo')` to the server's init method (https://github.com/blueyed/deoplete-jedi/blob/ /rplugin/python3/deoplete/sources/deoplete_jedi/server.py#L144), and this causes Neovim to lock up when executing `:call deoplete#enable_logging('DEBUG', '/tmp/deoplete.log')`.

This happens through this rpcrequest:

``` vim
  call rpcrequest(g:deoplete#_channel_id,
\ 'deoplete_enable_logging', a:level, a:logfile)
```

(https://github.com/Shougo/deoplete.nvim/blob/ /autoload/deoplete.vim#L32-L33)

The handler is this (I added the `return` at the top to make sure it's not something else):

``` python
    @neovim.rpc_export('deoplete_enable_logging', sync=True)
    def enable_logging(self, level, logfile):
        return
        logger.setup(self.__vim, level, logfile)
        self.__deoplete.debug_enabled = True
```

Using `strace -f` I see this when focusing the Neovim terminal window:

```
[{EPOLLIN, {u32=0, u64=0}}], 1024, -1) = 1
3162  08:54:26 read(0, "\33[I", 4095)   = 3
3162  08:54:26 write(13, "\1\0\0\0\0\0\0\0", 8  
3159  08:54:26   [{EPOLLIN, {u32=13, u64=13}}], 1024, -1) = 1
3162  08:54:26   )    = 8
... [Log Snipped] ...

3162  08:54:26 epoll_wait(16, [{EPOLLIN, {u32=0, u64=0}}], 1024, -1) = 1
```

And this when trying to abort it using `Ctrl-C`:

```
3162  08:54:31 read(0, "\3", 4095)      = 1

... [Log Snipped] ...
3162  08:54:31 futex( , FUTEX_WAKE_PRIVATE, 1) = 0
3162  08:54:31 epoll_wait(16, [{EPOLLIN, {u32=0, u64=0}}], 1024, -1) = 1
```

While there is maybe something wrong with deoplete's client/server in that case (e.g. "foo" triggers some internal bad state), Neovim should be able to abort the `rpcrequest` always.
