Title

[DocDB] Race conditions in wait_queue causes requests to wait indefinitely

Description
Jira Link: [Link: DB-4996]
### Description

There are two race conditions in wait_queue code which cause state inconsistencies that may lead to requests hanging indefinitely:
1. blocker_status_ may be updated such that a blocker is removed from this map -- [URL] right before new waiters are about to be added -- [URL] If a waiters' blockers are not represented in blocker_status_, the waiter will never be treated as "unblocked"
2. waiter_status_ may be updated such that a WaiterData instance is removed from the map and then the callback of an old WaiterData instance is invoked -- [URL] In such a case, the old WaiterData callback will no-op (since it has been invoked already and returned to the caller) and the new one will never be invoked, leaving the caller hanging indefinitely

We should fix both of these race conditions, and we should reconsider this code and/or add some verification to ensure the state in wait_queue is consistently maintained to minimize such issues in the future
