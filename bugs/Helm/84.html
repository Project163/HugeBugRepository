Title

--wait-for-jobs does not work with backOffLimit = 0

Description
Using the new `--wait-for-jobs` flag, we encountered a bit of strange behavior when `backOffLimit` is set to zero. Setting the backoff to 0 as well as ` restartPolicy: Never` ensures that a job is only run once.

[Link: The following check] validates failed runs are greater than or equal to 0. This condition will always return true when a job with `backOffLimit: 0` completes, because the `job.Status.Failed` will have a zero value (the field will not exist on job status).
