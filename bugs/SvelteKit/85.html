Title

getSession and maxage leaking session data

Description
### Describe the problem

Using `maxage` and `getSession` together can lead to a `cache-control: public` header on a response containing user session data. If the `getSession` hook is intended exclusively for user session data, this combination could easily be misused and is a potential security issue, thus probably shouldn't be possible.

### Describe the proposed solution

Where `maxage` is used, and `getSession` returns anything other than `void`, `cache-control` should be set to `private`.

### Alternatives considered

`cache-control` could be forced to `private` when any `getSession` hook is implemented. Is there a case for conditionally returning session data only for some routes though? This would allow implementations where some pages could be cached publicly while still using `getSession` for session data on others.

Discussion
- The current heuristic is that it is set to `private` is `$session` is accessed during rendering. I think it's better to set it to private if anything is inside session, as proposed here - even if it's not accessed (which is a rare case I guess) - since the content ends up in the HTML, not user-visible but publicly available anyway, and top-level hackers could get it by doing "show page source code".
