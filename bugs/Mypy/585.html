Title

`mypy_path` Doesn't Work With `--package`

Description
This issue is occurring with Debian GNU/Linux `9.8 (stretch)`, Python `3.7.2`, and mypy `0.680+dev. `. Here is a script to reproduce it:

```
bash
#!/bin/bash

CAT=$(which cat)

... [Log Snipped] ...
EOF
mypy --package a
```

Output (after the installation):

```console
python version: Python 3.7.2
mypy version: mypy 0.680+dev. 

MYPYPATH works:

mypy_path doesn't work:
Can't find package 'a'
```

`mypy` finds the package when `MYPYPATH` is given as an environment variable but not when `mypy_path` is given in `mypy.ini`. As best I can tell, here's what happens:

1. [`main.main` calls `main.process_options`][process_options call]
2. [`main.process_options` calls `main.process_config_file`][`process_config_file` call]
3. finding that a `--package` argument has been given, [`main.process_options` calls `modulefinder.mypy_path`][mypy_path call]
4. [`modulefinder.mypy_path` gets the path from `MYPYPATH`][mypy_path definition] and `main.process_options` never uses `options.mypy_path`

[`process_config_file` call]: [URL]

[mypy_path definition]: [URL]

I can remedy the problem with the following change:

```
diff
@@ -781,7 +781,9 @@ def process_options(args: List[str],
     # Set target.
     if special_opts.modules + special_opts.packages:
         options.build_type = BuildType.MODULE
... [Log Snipped] ...
         # TODO: use the same cache that the BuildManager will

```

If this is not expected behavior and this change is all that's needed, I am happy to make a pull request.
