Title

Reduce leader election optimization never occurs

Description
It appears the optimization in   SOLR-14942   never actually happens. The reason is the seemingly innocuous check of  zkController.isClosed  which actually ends up always skipping the leader election node cleanup. This is  not  because the ZK session is actually closed but rather a side-effect of the complex implementation of  SolrZkClient::isClosed  which also checks its "higher level" for closure. The higherLevelIsClosed delegates to  CoreContainer::isShutDown  which actually gets set to true in an  earlier point in the shutdown sequence . Thus this optimization never materializes. 

 A seemingly easy fix for this would be to check SolrZkClient::isConnected instead of isClosed. Will follow up with a PR.
