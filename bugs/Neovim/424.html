Title

calling feedkeys twice for abbreviations expands first call but not second

Description
### Neovim version (nvim -v)

NVIM v0.6.0-dev+575-g2ef9d2a66

### Vim (not Nvim) behaves the same?

yes, VIM - Vi IMproved 8.2 (2019 Dec 12, compiled Dec 25 2021 11:17:40)

### Operating system/version

Arch Linux

### Terminal name/version

alacritty 0.9.0 (fed349aa)

### $TERM environment variable

xterm-256color

### Installation

AUR

### How to reproduce the issue

#### Reproduction in Neovim

`nvim --clean abbr-bug-reproduction.lua`

```
lua

local trigger = 'trigger'
local value = 'value'

... [Log Snipped] ...

--  
```
`:source %`


#### Reproduction in pure Vim
`vim -u DEFAULTS abbr-bug-reproduction.vim`

```vim
iabbrev trigger value

call feedkeys('atrigger ', 'xt')

call feedkeys('atrigger ', 'xt')

"  
```
`:source %`

### Expected behavior

abbreviation should be expanded both times, and so `value` should be printed twice.
expected output after source: "value value "

### Actual behavior

`value` is printed the first time, but `trigger` is printed the second time
actual output after source: "value trigger "
Discussion
- _Note_: Doing the following does produce the expected behavior

```
lua

local trigger = 'trigger'
local value = 'value'

... [Log Snipped] ...

vim.api.nvim_feedkeys(trigger .. ' ', 't', true)
```
`:source %`
- v0.6.0-dev+575-g2ef9d2a66 is before the v0.6.0 release. This bug also exists in v0.6.0 and latest HEAD though.
- Adding an ` ` avoids the problem.
```vim
iabbrev trigger value

call feedkeys("atrigger \ ", 'x')

call feedkeys("atrigger \ ", 'x')

"  
```
