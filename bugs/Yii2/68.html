Discussion
- You are right, scenario is in most cases not needed in rules(). Your examples are equivalent. 

But you can specify rules() without defining scenarios() method which will result in the scenarios() method to determine the scenarios and active attributes based on the definitions in rules().
This is what sceanrios is mostly used for in rules()

is not 100% correct.
rule is applied when field is **active**: [URL]

This will not be applied as the attribute is not active on signup as defined by your scenarios() method. Actually I just found that the current implementation is not correct according to docs and how it should be. Will fix this.

Example:

```
php
function rules()
{
    return [
        // rule applied when corresponding field is "active"
```

- Btw 'except' does not affect scenario fields.
Given this set of rules,

``` php
return [
    [['id'], 'required', 'except' => 'administration'],
    [['name', 'description'], 'filter', 'filter' => 'trim'],
    [['is_disabled'], 'boolean', 'on' => 'administration'],
];
```

these scenarios are generated:

```
php
Array
(
    [administration] => Array
        (
... [Log Snipped] ...

)
```

As you can see in this case the field "id" is still present in 'administration' scenario. I suppose this behavior should be either documented or fixed also.

And it does not produce any new scenario, so in this example:

``` php
return [
    [['id'], 'required', 'except' => 'suddenlyUnexpectedScenario'],
    [['name', 'description'], 'filter', 'filter' => 'trim'],
    [['is_disabled'], 'boolean', 'on' => 'administration'],
];
```

the scenario list remain the same: 'default' + 'administration', and no 'suddenlyUnexpectedScenario'.
