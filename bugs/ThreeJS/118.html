Title

Scaling of Sprite is not relative to parent Object

Description
Transitions and rotations on Z axis is okay, but scale is not.

I have to call `.getWorldScale()` and append local scaling afterwards.
Discussion
- This is indeed a bug. But may I ask what your use case is?
- Thanks for replying!

I have exported the structure of a Flash (.FLA) file into some JSON data like this:

```
javascript
{
  "name": "root",
  "pos": [20, 20],
  "scale": [2, 2],
... [Log Snipped] ...
  ]
}
```

And I am trying to display them in Three.js, where:
-  "root", "childA" and "childB" are created as THREE.Object3D instances
- THREE.Sprite instances are added as children of "childA" and "childB" to display the shape, which is pre-rendered by another Canvas.

The problem is, I would expect only setting [textureWidth, textureHeight] to the sprite instances, and both "childA" and "childB" would be in 3 (2 \* 1.5) times large than the texture sizes. However, this is not the case. The actual result is that its the same as texture size.

This behaviour becomes very troublesome when the object hierarchy is more complex. I would have to perform `this.getWorldScale()` on each leaf node, and multiple the matrix with texture size.

Apart from this, I could use THREE.Plane instead (which does not have this problem), but I think that would perform less efficiently.

FYI, I am using r69
