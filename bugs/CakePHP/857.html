Title

CSRF blackhole on Safari

Description
This is a (multiple allowed):

* [x] bug
* [x] enhancement
* [ ] feature-discussion (RFC)

* CakePHP Version: 2.9.6.
* Platform and Target: Apache, MySQL.

### What you did
1. Created a form that uses Security component.
2. Added `$this->response->disableCache();` in the controller.
3. Opened the page with that form in Safari.
4. Submitted the form.
5. Clicked browser "Back" icon.
6. Submitted the form again with different data - blackhole because hidden _Token input had the same value as the first time.

### What happened
It seems Safari sometimes ignores headers set by `$this->response->disableCache();` and uses the cache instead of loading the new page after "Back" icon is clicked. 

### What you expected to happen
The page to be reloaded without using cache. Adding `autocomplete="off"` attribute to the hidden token input fixes that.

	if (empty($this->request->params['_Token'])) {
		return '';
	}

}
