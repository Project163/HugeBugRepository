Title

Missing line number information in stack trace

Description
If you try to run these two features in a Spock spec: 
  
 
def foo() {
  expect:  true 
  where: a << [b]
}

def bar() {
  expect:  true 
  where: a << b
}  
  
 You will get a  MissingPropertyException  for both of them, which is perfectly fine. 

 The problem is, that for  foo  there is a line number in the stack trace while for  bar  there is not. 

 I checked the byte code, there it is also missing for the  bar  case. 

 According to  paulk  the line number information is present in the AST: 
  BlockStatement (no info) -> ReturnStatement (no info) -> Variable (with line number info) // b 
BlockStatement (no info) -> ReturnStatement (no info) -> ListExp (correct info) -> Variable (correct info) //  [b]
Discussion

- Ah, I got it. 

 The line information is taken from the parent statement. 

 In the   [b]   example from the  ListExp , in the  b  example from the  ReturnStatement . 

 If I either replace the explicit return statement by an expression statement and let Groovy auto-inject the return statement or set the source position on the return statement manually, the line information is contained in the byte code and in the stack trace. 

 I'm not sure whether this is a fix or a work-around though, i. e. if you need to change something in Groovy due to this.

- No, I meant Groovy 

 Just like in your example: 

 > BlockStatement (no info) -> ReturnStatement (no info) -> Variable (with line number info) // b 
 > BlockStatement (no info) -> ReturnStatement (no info) -> ListExp (correct info) -> Variable (correct info) //  [b]  

 The problem is with `Variable`, it is not found so it produces a missing property exception. 
The line information for the stack trace is taken from `ReturnStatement` in the first case, and from `ListExp` in the second case. 
Because of that the first case shows no line information in the stack trace while the second does. 

 (In the meantime I fixed it in Spock so that the return statement has proper line number info)
