Title

ClassNotFoundException for beanparam class with generics in external artifact

Description
### Describe the bug

In my app I want to put some of the commonly used classes in a common lib.
This however causes a ClassNotFoundException from resteasy-reactive (see below) for this constellation:

These 2 classes are in my main quarkus app.

Resource
```
@GET
    @Produces(MediaType.TEXT_PLAIN)
    public String hello(@BeanParam GreetingListFilter  listFilter) {
        return listFilter.sortAttribute.name();
    }
```

```
public enum GreetingListSortAttribute implements SortAttribute{
    FORMALITY_FACTOR,
    LANGUAGE;

}
```

This one (and SortAttribute interface) is in an external lib:
```
public class GreetingListFilter  {
    @QueryParam("sortAttribute")
    // bogus default value so that rr calls fromString
    @DefaultValue("-")
    public T sortAttribute;
}
```

If I have the GreetingListFilter in the same module as app, everything works. It also works if the lib project is a sister module adjacent to the app.
It does not work if the lib is a fully external artifact.
I have added a META-INF/beans.xml in the lib for good measure, does not help. 

### Expected behavior

App starts


As endgoal, I want to call `[URL] and have the sortAttribute of GreetingListFilter be an instance of GreetingListSortAttribute. This works already if the lib is not external.

### Actual behavior

App does not start

Discussion
- I think the important info is this:


For Hibernate ORM transformations, a `META-INF/beans.xm` is enough to find external classes from the index. Perhaps we're not using the proper index in RESTEasy Reactive?
- Another thing I noticed just now. I now added an `@jakarta.ws.rs.ext.Provider` ParamConverter for this type to the same library.
Now, I do not get the ClassNotFoundException anymore. My app works as expected.

Before that, no jax rs provider was present in the library.
