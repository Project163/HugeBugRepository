Title

camel-google-storage: objectNames can conflict with each other

Description
When using the Consumer and the Producer within the same route, the  objectName  can conflict with each other. Consider the following example: 
  
 
 public   class  MyRouteBuilder  extends  RouteBuilder {
    @Override
     public  void configure() {
        from( "timer:test?repeatCount=1" )
                .pollEnrich( "google-storage: //{{google.cloud.bucket.name}}"  +
                          "?objectName=hello.txt"  +
                         "&deleteAfterRead= false " )
                .log( "File received with contents:  '${body}' " )

                .setBody(simple( "hello2" ))
                .log( "Writing to hello2.txt with body:  '${body}' " )
                .to( "google-storage: //{{google.cloud.bucket.name}}?objectName=hello2.txt" );
     }
}  
  
 The expectation would be that the file `hello.txt` would be read, and then a separate file `hello2.txt` would be written. However, what actually happens is that the original file `hello.txt` is overwritten. 

  Workaround  

 A workaround is to add  .removeHeaders("*")  before writing the new file: 
  
 
.removeHeaders( "*" )
.to( "google-storage: //{{google.cloud.bucket.name}}?objectName=hello2.txt" );
