Title

Redis JsonCodec use ObjectMapper without jsr310

Description
### Describe the bug

JsonCodec use ObjectMapper from DatabindCodec.mapper(). Received mapper contains only io.vertx.core.json.jackson.VertxModule.
[URL]

As a result, if a list of objects is cached that contains a date/time, when trying to deserialize it, an exception is thrown that there is no jsr310 module.

ObjectMapper in Arc contains next modules by default
- VertxTypes
- jackson-datatype-jsr310
- com.fasterxml.jackson.datatype.jdk8.Jdk8Module
- jackson-module-parameter-names

How it can be fixed:
1. Call findAndRegisterModules
`this.mapper = DatabindCodec.mapper().findAndRegisterModules()`
In this case, `findAndRegisterModules` will be called every time. The `VertxTypes` module will be missing.

2. Get ObjectMapper from Arc
`this.mapper = Arc.container().instance(ObjectMapper.class).orElse(DatabindCodec.mapper())`
In this case, the `io.vertx.core.json.jackson.VertxModule` module will be missing.

I think the first option is more correct, since there may be places where the ObjectMapper from `DatabindCodec` is used. And enriching it with the jsr310 module will not be superfluous. And put it in a static field so as not to call `findAndRegisterModules` every time.
But here you know better.

Can cached list of objects this date/time
