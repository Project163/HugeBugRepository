Title

Query cannot be interrupted during Segment pruning phase

Description
When SQL is in the planning stage and pruning segment optimization is performed, it may cause the query to cross the expected 300s and trigger the timeout cancellation logic due to the existence of a large number of segments, and a large number of filter expressions for simplification issues.
Discussion
- How to reproduce this problem? Add a large number of Segments to a model, for example, 5000; execute the query SQL and SQL with the filter condition of time partition column; at the same time, set the query timeout about 10 seconds, you can observe that the log execution prunning setgments process will not be interrupted, and will continuously output the following log: 
  
 
logger.info( "Find candidates by table {} and project={} : {}" , olapContext.firstTableScan.getTableName(),
        olapContext.olapSchema.getProjectName(), candidate);
log.info( "Scan segment.size: {} after segment pruning" , selectedSegments.size());
- Design 

 Add timeout detection, directly terminate the query if timeout at the segment pruning stage.
