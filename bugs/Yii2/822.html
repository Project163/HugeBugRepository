Title

\yii\caching\Cache::buildKey can generate identical cache keys for different $key attribute

Description
So method is written like this:

    public function buildKey($key)
    {
        if (is_string($key)) {
            $key = ctype_alnum($key) && StringHelper::byteLength($key)  keyPrefix . $key;
    }


The problem is in passing `json_encode` output directly to `md5` function.
It can return `false` in case of error. In my case it was an SQL query with special symbols, key generated from Yii2 components itself, when i used query caching. So it returned the same md5 key and caused multiple errors (same result for different queries)

Maybe it is better to throw an exception if output of `json_encode` is `false` in this case?
And i guess i need to create another ticket for `\yii\db\Command::queryInternal`?
Discussion
- Could you provide an example of the special symbols that caused the problem?


We should not only throw an exception, but also try to solve this problem. Caching should not break due to special symbols.


If this is a different kind of problem, then yes. If `\yii\db\Command::queryInternal` issue is about the same problem, then no.
- In my specific case i'm just using non-utf8 encoding with database. It is documented that with `json_encode` function input "all string data must be UTF-8 encoded".
But in method `\yii\db\Command::queryInternal` cache key is using raw sql:

    $cacheKey = [
                    __CLASS__,
                    $method,
                    $fetchMode,
                    $this->db->dsn,
                    $this->db->username,
                    $rawSql,
                ];

Currently, i monkey-patched this and using additional hash-function to encode `$rawSql` inside the `$cacheKey` array.

- So i've run some tests with Yii2 on a real project. 

First, i'ts really faster to use `serialize`. But i've learned something else, because i'd run test for complete code with query cache as well.

If i use current version of `\yii\db\Command::queryInternal` performance becomes much worse with both `json_encode` and `serialize`. It becomes worse exponentially if i increase number of calls.
So i changed `\yii\db\Command::queryInternal` to use `md5` for generating cache key:

    $cacheKey = [
        __CLASS__,
        $method,
        $fetchMode,
        $this->db->dsn,
        $this->db->username,
        md5($rawSql),
    ];

Now performance seems to be linear and there's only 20% difference between `json_encode` and `serialize`. And both functions performs much faster.

Also, i tried to reproduce performance on old php versions, i'm still getting results for `serialize` being faster. Maybe, `$key` must be specific for this to be an opposite case?
- if you make a lot of database calls, make sure query logging is turned off, otherwise yii will write a lot of queries to the log dispatcher.
