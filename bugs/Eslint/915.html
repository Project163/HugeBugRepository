Title

Definining the max-len rule with ignorePattern containing a colon inline in a file results in a JSON parsing error

Description
**What version of ESLint are you using?**
2.9.0

**What parser (default, Babel-ESLint, etc.) are you using?**
default

**Please show your full configuration:**
In .eslintrc I have configured the max-len rule to be:
`"max-len": [2, 80, 2, {"ignoreUrls": true, "ignorePattern": "data:image\/|\\s*require\\s*\\(|^\\s*loader\\.lazy|-\\*-"}],`

**What did you do? Please include the actual source code causing the issue.**
I wanted to experiment with 100 long lines in just one file, and didn't want to change the global rule config in .eslintrc. So I tried added the following comment at the top of the file:

`/* eslint max-len: [2, 100, 2, {ignoreUrls: true, "ignorePattern": "data:image\/|\\s*require\\s*\\(|^\\s*loader\\.lazy|-\\*-"}] */`

**What did you expect to happen?**
I wanted the 100 config to be taken into consideration and the ignorePattern to be applied too.

**What actually happened? Please include the actual, raw output from ESLint.**
The following error message appears:

`Failed to parse JSON from ' "max-len": [2, 100, 2, {"ignoreUrls": true, "ignorePattern": "data":image\/|\\s*require\\s*\\(|^\\s*loader\\.lazy|-\\*-"}]': Unexpected token d`

It looks like the code in eslint that reads rule configuration inline in files tries to convert it to valid JSON and in doing so replaces `:` with `":` which, in my case, actually breaks the JSON because of the regex I use in ignorePattern which includes a `:` character.
