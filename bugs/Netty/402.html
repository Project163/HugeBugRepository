Title

SSLHandler and... recycled already

Description
Hello.

I'm using nightly builds of 5.0.0.Alpha2.
Using SSLHandler and JMeter stop button I receive:
java.lang.IllegalStateException: recycled already

The pattern to reproduce is:

ctx.write1(..., promise1);
ctx.write2(...);
...
ctx.flush();

in promise1 I do a ctx.close() for write IOExceptions.

Resumed, this happens:
1. flush()
2. SSLHandler pendingUnencryptedWrites.removeAndFailAll(SSLENGINE_CLOSED);
3. for all pending writes: recycle and their promise become failures.
4. somewhere in the loop in point 3. promise1 fails
5. as stated I do ctx.close() for promise1 fail.
6. -> flush() again
7. -> SSLHandler pendingUnencryptedWrites.removeAndFailAll(SSLENGINE_CLOSED); again
8. -> all pending (remaining) writes are recycled and their promise are failures.
9. return to point 3 after promise1 handled and the remaining pending writes are all recycled by handling promise1 fail. 
   10 -> java.lang.IllegalStateException: recycled already 
   because remaining writes in queue are already processed in point 8.

My solution to this would be to improve the PendingWriteQueue.
In methods removeAndFailAll() and removeAndWriteAll() we could safely replace:
 write = next; 
with:
 write = head; 
In this way the loop can take care of recursions (while removing one queue element the queue is already emptied by handling a promise). write.next can point to a recycled element.

Thank you.
