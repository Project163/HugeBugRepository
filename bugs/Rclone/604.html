Discussion
- Looking through the call chain I see this which has a nil `ctx` variable

```
github.com/Azure/azure-storage-blob-go/azblob.ContainerURL.ListBlobsHierarchySegment(0x0, 0x0, 0x0, 0x0, 0x0, 0x0, 0x0,  , 0xc, 0x0, ...)
	github.com/Azure/azure-storage-blob-go@v0.10.0/azblob/url_container.go:249 +0x271
```

However it was called from here where it looks fine

```
github.com/rclone/rclone/backend/azureblob.(*Fs).list( ,  ,  ,  , 0xb, 0x0, 0x0, 0x0, 0x0, 0x1, ...)
	github.com/rclone/rclone/backend/azureblob/azureblob.go:621 +0x885
```

I don't see how this could have happened - the ctx variable isn't written between those calls. So I suspect some kind of memory scribble which is very unusual with Go programs.

Maybe it could be
- a problem with the Go runtime / compiler
- a problem with the RAM on your machine
- a problem with a bit of code using CGO (there shouldn't be any code using CGO in the configuration you are using)

Can you reproduce this reliably?

Is it always the same sequence of functions in the call trace?

This could be a problem with RAM in your machine - is it generally reliable? Have you run a RAM tester on it?

Can you try with [Link: the latest beta] which has a newer Azure blob library and was compiled with a newer go compiler and runtime.
