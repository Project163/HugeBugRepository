### Actual behavior

Discussion
- The Lua isn't needed to reproduce the assert. This is enough:
```vim
function! ActiveLine()
  set winbar=foo
endfunction

set statusline=%!ActiveLine()
```
- Seems to be caused by [URL]

@bfredl [URL] this line is causing the assert in `grid_puts_line_flush` to fail, which causes the crash. For some reason `grid_adjust` isn't adjusting the row properly
- The issue is that `win_redr_winbar` is called without `win_grid_alloc` because `win_redr_statusline` sets `w_redr_winbar` to true, which sets `w_winbar_height` but does not call `win_grid_alloc` since `win_grid_alloc` is called before `win_redr_statusline` in `update_screen`. Since `win_grid_alloc` is responsible for setting the `row_offset` of the grid, it causes `grid_adjust` to not adjust the grid correctly and causes the error. The fix would be to call `win_grid_alloc` somewhere in between `win_redr_statusline` and `win_redr_winbar`, what do you think is the ideal place for that?
- @ChrisAmelia By the way, what you're doing is absurd and should not be done. Winbar and statusline are separate things and you absolutely should not set the value of one inside a function that's called during the evaluation of another. So all we can do is add an out-of-bounds check to prevent a segfault, but it will still not work correctly and you'd have to set the options properly, separate from each other.
