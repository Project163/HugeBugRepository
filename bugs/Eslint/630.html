Title

`indent` rule in 1.7.0 unexpectedly complaining about seemingly-reasonable code, --fix makes it look worse

Description
I've got some code essentially like this:

```
function doStuff(keys) {
    _.forEach(
        keys,
        key => {
            doSomething(key);
        }
    );
}
```

`--fix` transforms it to this, which seems worse?

```
function doStuff(keys) {
    _.forEach(
        keys,
        key => {
        doSomething(key);
    }
    );
}
```
Discussion
- Another example:

What I had (which is fine)

```
    bridge.callHandler(
      'getAppVersion',
      null,
      function responseCallback(responseData) {
        window.ah.mobileAppVersion = responseData;  // line 65
      });  // line 66
```

What it seems to want (this is not what I expect)

```
    bridge.callHandler(
      'getAppVersion',
      null,
      function responseCallback(responseData) {
      window.ah.mobileAppVersion = responseData;  // line 65
    });  // line 66
```

I have `indent` configured with `[2, 2]`

```
  65:9  error  Expected indentation of 6 space characters but found 8  indent
  66:7  error  Expected indentation of 4 space characters but found 6  indent
```
- Yeah, that looks like a bug.
- I just hit this same bug, please fix and push an update. I'm disabling the `indent` rule for now in my repo.
- Thanks @gyandeeps! We really appreciate the quick turnaround on bugfixes (it goes nicely with the rapid iteration on eslint 😍).
