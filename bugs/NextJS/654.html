Title

404 error occurs after refreshing from intercepted parallel route.

Description
### Link to the code that reproduces this issue

[URL]

### To Reproduce

1. Navigate to the intercepted parallel route.
2. Press the `Refresh` button.

### Current vs. Expected behavior

I expected the `router.refresh` function to update the content of the displayed components without altering which components are being displayed. However, upon refreshing, the content of the root page (`/`) is replaced with a 404 error page.

Discussion
- I've been struggling with this one recently. It makes parallel/intercepting routes as described in the docs completely incompatible with router.refresh().

Workaround we found is calling a server action with a `revalidatePath('/')`. 

Validated in `v14.1.1-canary.78`
- It works if you call the server action once, if you call 3 server actions it breaks.
