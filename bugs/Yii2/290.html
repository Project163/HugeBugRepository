Title

Unit test fails when calling method, that uses boolean field in Postgres database.

Description
Here is code of test:

```
php
    public function testCorrectDeleteProject()
    {
        $id = 10000;
        $projects = Project::getExisting();
... [Log Snipped] ...
        expect("project with ID {$id} doesn't exist", $this->_findProjectWithID($projects, $id))->equals(false);
    }
```

Actual exception occurs in this method (of the 'Project' model):

``` php
    public static function getExisting()
    {
        return static::find()
            ->where(['is_deleted' => false])
            ->orderBy(['id' => SORT_DESC])
            ->all();
    }
```

migration for this field:

```
php
    public function safeUp()
    {
        $this->addColumn('{{%project}}', 'is_deleted', Schema::TYPE_BOOLEAN . ' NOT NULL DEFAULT FALSE');
    }
... [Log Snipped] ...
        $this->dropColumn('{{%project}}', 'is_deleted');
    }
```

Exception:

```
1) frontend\tests\unit\models\ProjectTest::testCorrectDeleteProject
yii\db\Exception: SQLSTATE[42883]: Undefined function: 7 ERROR:  operator does not exist: boolean = integer
LINE 1: SELECT * FROM "project" WHERE "is_deleted"=0 ORDER BY "id" D...
                                                  ^
HINT:  No operator matches the given name and argument type(s). You might need to add explicit type casts.
The SQL being executed was: SELECT * FROM "project" WHERE "is_deleted"= ORDER BY "id" DESC
```

Calling the same method from the web part action works well.
(I'm using advanced template).
When I replace field type to Scheme::TYPE_SMALLINT test passes correctly.
Discussion
- This is because of wrong Yii 2 postgresql boolean typecasting. It is a usual question of impedance mismatch in applications where not everything in application can be correctly presented in persistence, try not to use boolean and simply use integers 0 / 1, their are safe. 

that is correct way to handle this situations
