Title

Secondary indexes are always rebuilt at startup

Description
Following   CASSANDRA-10130  , a bug has been introduced that causes a 2i to be rebuilt at startup, even if such index is already built.

     Indexes created during column family initialization should not be marked as "not built", to avoid rebuilding them needlessly.
- This is caused by calling  SIM#markIndexesBuilding  when creating the index during column family initialization, which marks the index as "not built" and causes the index initialization task to rebuild it. 

 Given there's no need to mark the index when a new column family is created (as the index will be "not built" by definition and there can't be any concurrent indexing), we can just pass a boolean up to  createIndex()  to distinguish between index creation at different times, i.e. when a column family is  created  or  reloaded . 

 Such solution is implemented in the following patch, with a new dtest verifying it:
