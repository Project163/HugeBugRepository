Title

drag behavior acts inconsistently for multiple touches

Description
The d3.behavior.drag registers an own set of event listeners for each individual touch and it dispatches drag and dragend events per touch.

There are currently two inconsistencies:
1. When one touch is released (touchend event received), all touches dispatch a dragend event and unregister themself. The consistent behavior would be to just dispatch a dragend event + unregister the specific touch that was released.
2. Each time the browser sends a touchmove event, all touches in the drag behavior dispatch a drag event. The consistent behavior would be to check the event.changedTouches list and only dispatch drag events for those touches that actually moved.

These issues would be very easy to fix. Simply check whether the current touch is in the changedTouches list of the touch event, and if not, just ignore the event in the moved() and ended() functions. Here's a method that checks whether a touch changed:

Discussion

    
- I just met the same inconsistency on the touchend events (all touches were being unregistered simultaneously)
My simple fix was to change the ended() function in ..\src\behavior\drag.js
from

```
      function ended() {
        w.on(move + "." + drag, null).on(end + "." + drag, null);
        dragRestore(dragged && d3.event.target === eventTarget);
        event_({type: "dragend"});
      }
```

to 

```
        function ended() {
            if (d3.event.target === eventTarget) {
                w.on(move + "." + drag, null).on(end + "." + drag, null);
                dragRestore(dragged && d3.event.target === eventTarget);
                event_({type: "dragend"});
            }
        }
```

I didn't see any problems with the touchmove event, though, so maybe that got fixed?
