Title

Inside a switch statement, newline-before-return conflicts with lines-around-comment

Description
#### Background info

`lines-around-comment: ["error", {beforeLineComment: true, allowBlockStart: true}]` requires a blank line before any single-line comments, _except_ where the comment is the first line of the block:

```
{
  // This comment is OK (not preceded by a newline, but first in block)

  // This comment is also OK (preceded by a newline)
  let a = 1;
  // This comment is NOT OK (not preceded by a newline)
}
```

`newline-before-return: "error"` requires a blank line before any return statements, _except_ where the return is the only statement in a statement group.

```
function foo() {
  return 1;   // OK, return is the only statement
}

function bar() {
... [Log Snipped] ...
  return a;   // NOT OK, return is not preceded by a new line
}
```
#### Problem

Inside a `SwitchCase`, there doesn't seem to be a way to get both of these rules to play nicely with each other.  The problem appears to be that `SwitchCase` is considered by `newline-before-return` to be a "statement group", yet it is not a block.

Because `SwitchCase` is not a block, `allowBlockStart` doesn't come into play, so `lines-around-comment` will expect a newline before all comments (including the first comment in each `SwitchCase`).

However `newline-before-return` will complain about this newline before a comment if the only statement in the `SwitchCase` is a return.
