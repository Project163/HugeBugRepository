Title

Include assignments in consistent-this

Description
I tend to group multiple variable declarations together without assigning to them, and perform the assignments underneath. The consistent-this rule currently only checks variable declarations, and forces the aliasing variable to be assigned in its declaration. This means that the following is rejected:

``` js
var foo, self;
self = this;
```

While this is accepted:

``` js
var foo, that;
that = this;
```

It would be nice if the rule considered all assignments to identifiers, and had an option to allow empty variable declarations. I've implemented this change [Link: here], and will submit a pr if there's interest.
Discussion
- I'm a bit confused - it looks like your two examples are exactly the same except for the name of the variable. Can you explain some more? Can you include the actual output from ESLint for the problematic code?
- The consistent-this rule insists that if I declare a variable with the same name as the designated `this` alias (which defaults to `self`), then I must set the variable to `this` in the declaration. So if I write:

``` js
var foo, self;
self = this;
```

I get this output:

```
1:0  error  Designated 'this' alias 'self' is not assigned to the current execution context  consistent-this
```

This is appropriate given the purpose of the rule, but I'd like an option to turn it off in case I'm using this particular grouping style of declarations.

The consistent-this rule _also_ insists that you may not assign `this` to any variable with any other name, but it only enforces this rule on initial variable declarations. For instance, if I write (still using the default of `self`):

``` js
var that = this;
```

I get this (correct) error:

```
1:0  error  Unexpected alias 'that' for 'this'  consistent-this
```

But if I perform the assignment later:

``` js
var foo, that;
that = this;
```

I would expect an error about assigning `this` to `that`, but the rule ignores assignments outside of variable declarations.

So, given this particular style of variable declarations, the rule only ever reports an error on cases where I'm using the alias correctly, and never on cases where I'm using it incorrectly. This change would have it inspect assignments to identifiers, banning anything that is not `{{alias}} = this`, and include an option to allow empty variable declarations of the alias.
