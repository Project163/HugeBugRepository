Title

d3_transitionPrototype.filter throws type error if empty transition.

Description
At the end of transition.filter it does this:

``` javascript
return d3_transition(subgroups, this.id, this.time).ease(this.ease());
```

The `this.ease()` call tries to get at the `__transition__` on `this.node()` but for an empty transition `this.node()` returns null so it throws a type error.

Also, `d3_transition` only takes 2 arguments so `this.time` is quietly ignored.
Discussion
- Fixed in #1408
- FWIW, that transition.ease call is no longer necessary since the per-node transition object stores the easing function (since 3.0). And the extra argument to d3_transition is no longer needed since the transition object also stores the reference time. So this was an easy fix: delete some code. :)
