Title

Building a dll in windows using c-shared buildmode generates a dll with .exe extension

Description
**Describe the bug**

When building a binary using `-buildmode=c-shared` in windows go generates a dll, not an executable, but goreleaser always add the extension `.exe` to all the binaries generated with goos=windows, at least this is what I can see in the [Link: source code].

**To Reproduce**

Steps to reproduce the behavior:

```
yaml
builds:
  - id: "testdll"
    env:
      - CGO_ENABLED=1
... [Log Snipped] ...
    builds:
      - testdll
```

**Expected behavior**

I'm expecting a binary archive named `test.dll`, but I get a `test.dll.exe` archive.

**Environment (please complete the following information):**

- OS: windows
- OS version: windows 10 x64
- GoReleaser Version: 0.120.3
