Title

sstablesplit does not remove original sstable

Description
sstablesplit leaves the original file on disk, it should not.
Discussion
- This also affects offline sstableupgrade.  I'd say this should be a higher priority since people could fill up their disks during an upgrade.
- JB, can you confirm this is only 2.1 and not 2.0?
- jblangston@datastax.com  told me that he only tested with 2.1.
- Patch uploaded  here . 
 
	 Both sstablesplit and sstableupgrade are changed to call markObsolete() and selfRef().release() as in sstablescrub after processing a table succeeds. 
	 An option to keep originals is added to sstableupgrade; sstablesplit does snapshotting and should not need that. 
	 Unused verbose option is removed from sstablesplit.
