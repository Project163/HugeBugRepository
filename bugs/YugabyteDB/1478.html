Title

[DocDB] YBDB code is not properly escaping metric label values.

Description
Jira Link: [Link: DB-19143]
### Description

Issue: 

The YBDB is not properly escaping metric label values. This create an issue where prometheus is not able to parse the metrics and it results the Tserver process health issue in YBA UI. 

 

The Prometheus target UI will say for that particular target:  "expected equal, got INVALID"

 

Steps to reproduce: 

Make a table with some weird name with quotes. Example: 
```
yugabyte=# create table """yo"".""name_split"""("Unnamed: 0" bigint, full_name text);
CREATE TABLE
yugabyte=# \dt+ """yo"".""name_split""";
                           List of relations
 Schema |       Name        | Type  |  Owner   |  Size   | Description
--------+-------------------+-------+----------+---------+-------------
 public | "yo"."name_split" | table | yugabyte | 1024 kB |
(1 row)
```
The Prometheus target will go in down state as in screenshot. 

How to find this the issue?  
Take help of `promtool` and check the metrics. 
```
ubuntu@ip-10-9-100-148:~/prometheus-2.44.0.linux-amd64$ curl -ks [URL] | ./promtool check metrics
error while linting: text format parsing error in line 1764: unexpected end of label value ""

ubuntu@ip-10-9-100-148:~/prometheus-2.44.0.linux-amd64$ curl -ks [URL] > metrics.out
ubuntu@ip-10-9-100-148:~/prometheus-2.44.0.linux-amd64$ vim metrics.out
... [Log Snipped] ...

rocksdb_bytes_per_read_sum{metric_type="table",exported_instance="yb-dev-agangwar-test-n1",namespace_name="yugabyte",table_name=""yo"."name_split"",table_id=" "} 0 1687373915630
```
