Title

in Shell.java#runCommand() rethrow InterruptedException as InterruptedIOException

Description
Instead of creating IOException with message make InterruptedException the cause of IOException, so that whoever calling shell executor can make use of it.
Discussion
- Good idea. 
I'd recommend going one step further and throwing an  InterruptedIOException(cause)  so the caller can act on it without looking inside
- Apart from default constructor InterruptedIOException has a constructor which takes string argument.  
So no way to directly do new InterruptedIOException(cause).  
we could do. 
  
  catch (InterruptedException ie) {
      InterruptedIOException iioe =  new  InterruptedIOException(ie.getMessage());
      iioe.initCause(ie);
       throw  iioe;
}
 
  

 Or Instead of InterruptedIOException we can just throw an IOException with cause ie.  

  
  catch (InterruptedException ie) {
 throw  newIOException(ie);
}
 
  
 I feel that cause should be preserved, while wrapping exceptions.
