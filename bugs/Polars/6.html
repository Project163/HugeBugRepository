Title

Inconsistent behavior between `drop_nulls()`, `drop_nans()` and `fill_nulls()`, `fill_nans()`

Description
#### What language are you using?

python 3.9.10

#### Have you tried latest version of polars?
yes

#### What version of polars are you using?

0.13.39

#### What operating system are you using polars on?

Debian 11


#### Expected & Actual Behavior
I was going to add some notes to the docs regarding the difference between `null` and `NaN` in polars when I was surprised to see that there is an inconsistency in how `drop_{nulls, nans}` and `fill_{nulls, nans}` operate. Intuitively, I would expect `drop_nans()` and `drop_nulls()` to affect the same elements as their counterparts `fill_nans()` and `fill_nulls()`. However, `drop_nans()` also drops `null` values.

```
python
shape: (4, 1)
┌─────┐
... [Log Snipped] ...
│ 4.0  │
└──────┘
```

I think the way that the `fill_*` methods work is more intuitive if we distinguish between `nulls` and `nans`. Is this something that needs fixing or is this just how these types work under the hood?
