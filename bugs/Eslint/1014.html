Title

Stage 4 syntaxes in core rules

Description
`acorn`, the base of `espree`, has supported async/await and trailing function commas: [Link: Acorn 4.0.0]
`espree` is going to support those, coming soon: [URL]

Then, I'm starting to modify core rules to support those.
In my head, the following rules need some tweaks.
- 1st
  - [x] #7170 no-dupe-args ... Duplicate names in non-simple parameters are illegal syntax. We need to fix our tests since Acorn has enhanced the check. (4 tests are failing now with Acorn 4.0.0)
  - [x] #7170 no-redeclare ... Duplicate names in exports are illegal syntax. We need to fix our tests since Acorn has enhanced the check. (2 tests are failing now with Acorn 4.0.0)
- 2nd
  - [x] #7176 arrow-parens ... It has false positive/negative on async functions.
  - [x] #7179 keyword-spacing ... It has false positive/negative on async functions.
  - [x] #7178 no-extra-parens ... It should handle await expressions also by default.
  - [x] #7175 no-unused-expressions ... It should handle await expressions also by default.
  - [x] #7173 prefer-arrow-callback ... It has wrong autofix on async functions.
  - [x] #7180 space-before-function-paren ... It should handle async arrow functions (as anonymous function?). `async(a) => a`.
  - [x] #7174 space-unary-ops ... It should handle await expressions. It has handled yield expressions already.
- 3rd
  - [x] #7172 array-callback-return ... I think should not warn async functions as callbacks. `Promise.all(list.map(async x => { await doSomething(x) })` is legal usage.
  - [x] #7181 comma-dangle ... It should check functions also by opt-in.
  - [x] #7182 generator-star-spacing ... To make sure, it needs tests for async functions.
