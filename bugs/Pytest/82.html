Title

Assertion rewriting fails on OS X El Capitan

Description
```
______________________________________________________________________________ ERROR collecting src/s3am/test/s3am_tests.py _______________________________________________________________________________
.eggs/py-1.4.30-py2.7.egg/py/_path/local.py:650: in pyimport
    __import__(modname)
src/s3am/__init__.py:15: in  
    import logging
... [Log Snipped] ...
E   OSError: [Errno 1] Operation not permitted: '/System/Library/Frameworks/Python.framework/Versions/2.7/lib/python2.7/logging/__pycache__'
======================================================================================== 17 error in 1.22 seconds =========================================================================================
```

I believe SIP (https://en.wikipedia.org/wiki/System_Integrity_Protection) to be the cause.
Discussion
- Looking at the assertion rewrite module, it tries to write new bytecode and handles the common issues:

```
python
        if write:
            try:
                os.mkdir(cache_dir)
            except OSError:
... [Log Snipped] ...
                else:
                    raise
```

It seems SIP causes an error with errno 1, which (on my OS X Yosemite system at least) is `errno.EPERM`. I think the fix would be to handle that in the last block as well, i.e. treat this as a read only directory.

@hannes-ucsc - for now, you could probably also set `PYTHONDONTWRITEBYTECODE=1` in your environment, or use something other than the system python which I'd recomment anyways, i.e. use a virtualenv.
- @The-Compiler Setting `PYTHONDONTWRITEBYTECODE=1` indeed avoids the issue. Using a virtualenv doesn't. I think that's because a virtualenv inherits the modules that Python ships with, like `logging` in this example.
