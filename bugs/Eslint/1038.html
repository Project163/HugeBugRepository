Title

Files in lib/ aren't getting linted

Description
**Tell us about your environment**
- **ESLint Version:** master
- **Node Version:** 6.9.1
- **npm Version:** 3.10.8

**What parser (default, Babel-ESLint, etc.) are you using?**

default

**Please show your full configuration:**

(n/a)

**What did you do? Please include the actual source code causing the issue.**

To reproduce in the ESLint repo:
1. Insert a linting error into a file in `lib/`, such as `lib/ast-utils.js`.
2. `npm test`

**What did you expect to happen?**

The linting error should get reported, and the build should fail.

**What actually happened? Please include the actual, raw output from ESLint.**

The linting error did not get reported, and the build succeeded. (Note: Based on [URL] it seems possible that this is an OS-specific problem. I'm using OSX.)

~~Looking at `Makefile.js`, it seems like we're linting `lib/**/*.js`, but running `./bin/eslint.js lib/**/*.js` doesn't appear to lint any of the files that are in `lib/` directly. This doesn't seem like intended glob behavior, so this might actually be a bug in ESLint itself, not our build process.~~

~~edit: `git bisect` indicates that [URL] is the source of the issue in the ESLint repo, although it's still not clear whether this globbing behavior is intended.~~

edit: Oh I see, this is a bash issue. When `eslint lib/**/*.js` is run, bash performs its own globbing and passes the files in subfolders to ESLint, but doesn't pass files like `lib/ast-utils.js`. Surrounding the glob path with quotes (`eslint 'lib/**/*.js'`) fixes the issue.
