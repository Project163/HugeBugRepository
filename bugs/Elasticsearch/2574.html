Title

SLM Retention can throw an exception while running retention when there are no snapshots to delete

Description
**Elasticsearch version** (`bin/elasticsearch --version`): Observed on 7.11.0

**Plugins installed**: []

**JVM version** (`java -version`): built-in

**OS version** (`uname -a` if on a Unix-like system): docker

**Description of the problem including expected versus actual behavior**:

When SLM's retention comes across a repo with zero snapshots eligible for deletion, an exception is thrown due to trying to create a GroupedListsner with a group size of 0. This does not appear to happen in the "simple" case of kist setting up a policy with retention and waiting for a run with 0 snapshots to be deleted, but I can confirm this does happen in some circumstances.

Example exception (trimmed):
```
exception computing snapshots for repository my-repository
java.lang.IllegalArgumentException: groupSize must be greater than 0 but was 0
	at org.elasticsearch.action.support.GroupedActionListener. (GroupedActionListener.java:40) ~[elasticsearch-7.11.0.jar:7.11.0]
	at org.elasticsearch.xpack.slm.SnapshotRetentionTask.deleteSnapshots(SnapshotRetentionTask.java:327) ~[x-pack-ilm-7.11.0.jar:7.11.0]
```

**I do not have a reliable reproduction case for this yet**

Another example case that can happen if there is an error while retrieving the snapshots in a repository:
```
unable to retrieve snapshots for repository [my-repository]
java.lang.IllegalArgumentException: groupSize must be greater than 0 but was 0
	at org.elasticsearch.action.support.GroupedActionListener. (GroupedActionListener.java:40) ~[elasticsearch-7.11.0.jar:7.11.0]
	at org.elasticsearch.xpack.slm.SnapshotRetentionTask.deleteSnapshots(SnapshotRetentionTask.java:327) ~[?:?]
	at org.elasticsearch.xpack.slm.SnapshotRetentionTask.deleteSnapshots(SnapshotRetentionTask.java:319) ~[?:?]
... [Log Snipped] ...

	at java.lang.Thread.run(Thread.java:832) [?:?]
```
