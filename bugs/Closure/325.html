Title

calling hasOwnProperty on an object should prevent property trimming similar to using [] as an accessor

Description
What steps will reproduce the problem? 
Compile the following code with advanced optimizations:
// ==ClosureCompiler==
// @compilation_level ADVANCED_OPTIMIZATIONS
// @output_file_name default.js
// ==/ClosureCompiler==

// ADD YOUR CODE HERE
var foo = {'a': true, 'b': true }

console.log(foo.hasOwnProperty('a'));

// Uncomment the following to get the properties of foo to stick.
//console.log(foo['a']);

 What is the expected output? What do you see instead? 
Expected:
Either something highly optimized like the [] accessor only version of the code above: console.log(!0);, or at least accurate like:
console.log({a:!0,b:!0}.hasOwnProperty("a"));

Actual:
console.log({}.hasOwnProperty("a"));


 What version of the product are you using? On what operating system? 


 Please provide any additional information below.
Discussion
- Looks like CollapseProperties is not respecting quoted properties.
- Using the "safe" version of hasOwnProperties will work:

Object.prototype.hasOwnProperty.call(foo, 'a');

and protects against a property called "hasOwnProperty"
