Title

v0.14.45-rc eats files

Description
As reported in [URL]

Potentially multiple issues, almost surely related to #4584.

Off the top of my head I can see one issue with directories that have been renamed case-only on case insensitive systems: whereas previously we would see the files just fine, we would now lockstep-walk the database vs the filesystem, potentially note that the directory we expected didn't happen, and mark everything below as deleted. That is, we see `foo/` when walking and conclude that`Foo/**` which is in the database has been deleted. This propagates to some other device where the deletes happen, and it's a self fulfilling prophesy.
Discussion
- Is there a mechanism to automatically revert release candidates on affected machines? It might be worth putting one in: I just randomly saw odd messages and thought "huh I might try the older version to fix it", and if I hadn't looked at it, that version would have run forever even though you guys seem to be already aware that it's broken. (and deleted whatever in the long run)

Edit: with automatically I mean with some central switch you guys can flip when a rc turns out to have issues
- The switch we can throw is to release a newer version. I don't think we want a central kill- or downgrade-switch.
