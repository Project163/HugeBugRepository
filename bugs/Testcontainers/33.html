Title

Incorrect Auth encoding

Description
I think there is potential bug when parsing/decoding a custom auth config (e.g. for gcr).
We have create a `config.json` which looks like this:

```json
{
  "auths": {
    "eu.gcr.io": {
      "auth": "BASE64-ENCODED-JSON"
    }
  }
}
```

The decoded `auth` contains a [Link: json key file]:

```
json
_json_key:{
  "type": "service_account",
  "project_id": "XXX",
  "private_key_id": "XXX",
... [Log Snipped] ...
  "client_x509_cert_url": "[URL]
}⏎
```

In [Link: RegistryAuthLocator#findExistingAuthConfig] the decoded string is splitted and checked if there are two parts (username & password). This fails for the above json, such that you are not able to pull from a private gcr registry. 

[Link: Docker java] has similar logic, but limits the amount of splits to two, which results in having `_json_key` as username and the complete json key file definition as password. I have implemented the same splitting in testcontainers and tested it in our environment (using gitlab ci with dind) and pulling from our private gcr registry works just fine. 
If you are okay with that change I can provide a PR for that.
