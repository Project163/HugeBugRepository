Title

Wanted but not invoked on 2.12.0, but not on 2.11.0

Description
After updating Mockito from 2.11.0 to 2.12.0 the following test fails with `Wanted but not invoked`.

The weird thing is this happens only when running tests using Gradle. Android Studio runs the same test as successful. Just like #1183.

```
java
package package.redacted;

import org.junit.Test;
import org.mockito.Mockito;
... [Log Snipped] ...
    }
}
```
```
Wanted but not invoked:
view.showResult();
-> at package.redacted.ViewModelTest$View.showResult(ViewModelTest.java:22)

However, there were exactly 2 interactions with this mock:
... [Log Snipped] ...
	at org.gradle.internal.concurrent.ThreadFactoryImpl$ManagedThreadRunnable.run(ThreadFactoryImpl.java:55)
	at java.lang.Thread.run(Thread.java:748)
```
Discussion
- I'm observing a similar issue. Only happens with `mockito-inline`. Don't have time right now to distill the affected tests into a minimal reproduction case. Maybe @raphw has a hunch.
- Alright, decided to look for a minimal reproduction case after all. This is what I came up with:
```
java
package com.example

import static org.mockito.ArgumentMatchers.eq;
import static org.mockito.Mockito.spy;
... [Log Snipped] ...
    }
}
```

Causes:
```
Wanted but not invoked:
dummy.bar("baz");
-> at com.example.MockitoIssue1254Test$Dummy.bar(MockitoIssue1254Test.java:23)

However, there was exactly 1 interaction with this mock:
dummy.foo();
-> at com.example.MockitoIssue1254Test.test(MockitoIssue1254Test.java:13)
```

This test does pass with Mockito 2.11.0. It also passes with Mockito 2.12.0, provided `mockito-inline` is disabled.
