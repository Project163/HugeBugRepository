Title

dockers extra_files does not support Windows folders.

Description
### What happened?

When using extra files like this, with a sub-folder:
```YAML
dockers:
  - id: test
    image_templates:
      - "test"
    extra_files:
      - "files/images"
```
It will correctly read and include all files. But it will create a double folder structure. As seen from the debug info:
```
• copying file                  dst=dist\goreleaserdocker2020978553\files\images\ranks src=files\images\files\images\ranks
```
This is due to: 
[URL] 
Where it removes the extra subdirectory (the `src`) from the `path`. This is a wrong assumption on windows, as it uses backslashes as folder delimiters.
I do not think this is a user error, as it should correctly convert between the two, and so the same config can be used on both Windows and *nix. (Locally and CI for example).
 
Running the above config with `files\images` works as expected on windows. But then the issue just appears on non-Windows machines.

### Additional context

This probably applies to other extra_files fields in other configuration areas. I have not checked it though. Changing the gio package to automatically convert path strings from forward to backslash on windows should fix it everywhere.

Or for a more general solution sanitize all filepaths to use forward slashes, but that seems to be a bigger undertaking.
