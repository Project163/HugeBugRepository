- I have a theory about why this is happening, and I am not sure what the correct solution is. I seem to recall that the "could not access system parameter" error is what happens when you try to inject a Resource that doesn't exist.

Thing is, the `InputFocus` resource is supposed to be optional - that is, if your game doesn't use input focus, then you shouldn't be required to initialize it or even depend on the `bevy_input_focus` crate. However, a11y now depends on `bevy_input_focus`, so anyone who installs the a11y plugin needs to have that resource initialized (either that, or we change a11y to injection that resource optionally).

The plugin which registers the `InputFocus` resource also installs a number of observers and a system which people may not want. These handle the bubbling of keyboard and button events. If you aren't using bubbling, then you shouldn't have to install these.

The "right" solution here would be to have a system of plugin dependencies: that is, a11y could depend on just the parts of bevy input focus that it needs, and users could depend on the parts they need, and if both a11y and the user installed the same plugins they would be deduped. But we don't have that ability yet.
