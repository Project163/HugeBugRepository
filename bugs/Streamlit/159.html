Title

Discrepancy between value shown and value returned by widged when it is redisplayed

Description
### Summary

When a widget is redisplayed, the value returned is not the same value the widget shows.

### Steps to reproduce

Here an example with multiselect:

```
import streamlit

letter = streamlit.sidebar.radio("Letter", ["A", "B"])
if letter == "A":
    numbers = streamlit.multiselect("Number", ["1", "2"])
... [Log Snipped] ...
else:    
    streamlit.write(f"I started an expensive computation using the chosen letter {letter} and the currently selected numbers {numbers}")
```

1. With 'A' selected, select the numbers 1 and 2
2. Change the sidebar selection to 'B', then again to 'A'

**Expected behavior:**

Either 
1) the multiselect widget is empty and shows "Select an option"; the message seen is "I didn't compute anything because no number is selected" (which I prefer)
Or
2) the multiselect widget has the last values selected when it was shown the last time (1 and 2) and the message seen is "I started an expensive computation using the chosen letter A and the currently selected numbers [1, 2]

**Actual behavior:**

The multiselect widget is empty and shows 'Select an option' , but the message seen is "I started an expensive computation using the chosen letter A and the currently selected numbers [1, 2]"

**Workaround**

To get the 2nd expected behavior, add the arguments key="key", default = streamlit.session_state["key"]

To get the 1st behavior, 🤷‍♂️

### Debug info

- Streamlit version: 0.84.0
- Python version: 3.9.5
- Using Conda

### Is this a regression?
With streamlit 0.82.0, I got the behavior (1)
