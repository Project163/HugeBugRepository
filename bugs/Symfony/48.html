Title

[Form][Guesser] Incorrect Form Field Guessing And/Or Validation

Description
Hi, 

When I make a form from an entity class with this property:

```
/**
 * @Assert\NotBlank()
 * @Assert\Min("-.5")
 * @Assert\Max(".5")
 */
protected $numericProperty;
```

Symfony adds a `pattern=".{3,2}"` attribute to the HTML ` ` in the view, which is obviously not right. The pattern attribute is still added even if I `@Assert\Type("float")` or `@Assert\Type("numeric")`.

(Note that if I leave out the quotation marks in `@Assert\Min` and `Assert\Max` I get an error.)

If I explicitly specify the field as optional or as a number type when I add it to the form builder, then the `pattern` attribute goes away (as expected), but another problem crops up: I can't specify a positive number without a leading digit (e.g. ".3"). When I do so, I get the error: 

The validation constraints are working though: if I enter a number outside of -.5 and .5, I get the appropriate error, and .3 is accepted if I enter it as 0.3.

Both of the `pattern` attribute and the requirement for a leading 0 weren't behaviors I was expecting. But maybe I'm missing something?
Discussion
- That's an issue with the [Link: Type Guesser] which has obviously not been designed to work with floating point number.
- Yeah, I figured the pattern attribute was a TypeGuesser issue. What about the requirement for the leading 0, even when calling `$formBuilder->add()` with type='number'. That seems like a validation or localization thing, right?
- @studip101 isolating the faulty code and sharing it (i.e. in a gist) might help people helping you.
