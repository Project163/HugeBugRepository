Title

Bug in r53Dev when you use deallocateObject

Description
Hi guys

I have been struggling for a few days to isolate this bug, but think I have successfully been able to reproduce it now in one of the examples. Basically if you add a plane to the scene, apply a MeshBasicMaterial to it and then try to remove a mesh loaded from .js file using deallocateObject  you will get a whole bunch of webgl errors. 

To re-create the bug simply add the below lines of code at the end of the function 'createScene' in the example file 'webgl_materials_bumpmap.html'. Believe it only happens when you try to load a .js file - because I was able to load obj files in my app and did not see any errors.

```
//First create plane which we add to the scene
var planeMat = new THREE.MeshBasicMaterial( { color:  , wireframe: true } )
var plane = new THREE.Mesh( new THREE.PlaneGeometry( 30, 30, 30, 30 ), planeMat );
plane.rotation.x = - Math.PI / 2;
scene.add( plane );
... [Log Snipped] ...
renderer.deallocateObject( mesh );
render();
```

Regards
Discussion
- Seems like it has something to do with the material. That example uses this material:

``` javascript
var material = new THREE.MeshPhongMaterial( { ambient:  , color:  , specular:  , shininess: 25, bumpMap: mapHeight, bumpScale: 19, metal: false } );
```

If we replace it with a `MeshBasicMaterial` it works fine but `MeshLambertMaterial` and `MeshPhongMaterial` throw those errors.
- Something that may or may not be related to this... In my app, when I load in the js or obj files and apply a phong material to both at some later point in time. The material is applied, however if I then update the material with a diffuse texture and update the meshes (so basically call the 

```
object.geometry.buffersNeedUpdate = true;
object.geometry.uvsNeedUpdate = true;
```

functions on each of them ) - the js model will update with the texture, but the obj model won't and will actually throw a series of errors. But as soon as I remove the texture things go back to normal. 

Perhaps there is something going wrong in the loading process or the creation of the meshes and/or their materials? 

Like with above, I get different behaviour when using the deallocateObject. When I remove the js mesh using deallocateObject the webgl errors are thrown, but when I remove the obj object no errors are thrown. 

Again I'm not sure if its related... but it seems like these errors are happening based on which file is being loaded.
