Title

SRT: OBS unusable and uncloseable after starting stream to invalid srt server

Description

### Expected Behavior

- OBS should not show that it connected successful when the srt stream server URL is invalid, but instead show the usual stream error message
- User should be able to stop streaming and later be able to start streaming again after correcting the srt server url
- User should be able to close OBS

### Current Behavior

- OBS shows that it connected successfully, stream bitrate counter stays at 0b/s. After some time it shows the `OBS Studio: Disconnected. Reconnecting ...` notification.
- Pressing the `Stop streaming` button only makes its text change to `Stopping Stream...` and then OBS is unusable for any further streaming.
- OBS then can not be closed any more. Or rather, if you press the close button or File -> Exit the window disappears but the obs.exe process stays open infinitely until manually killed using Task Manager or restarting the computer
- Dropped Frame counter seems to be not working at all when using SRT, and `Dynimaically change bitrate to manage congestion (Beta)` also does not work when using srt. (However, srt support seems to be rather new in OBS so far and SRT already handles packet loss very well, so those two features are absolutely low priority imho.)

[Image: image]

### Steps to Reproduce

1. Set Settings -> Stream -> Server to `srt://google.com:443/this/is/not/a/srt/server?latency=500000`
2. Set Settings -> Advanced -> `Automatically Reconnect` to Enabled with Retry Delay `10s`.
2. Close settings. Start streaming. Watch OBS for 30 seconds.
3. Press the `Stop streaming` button, then wait 30 seconds.
4. Close OBS, wait 30 seconds, then open Task Manager and check in the Details/Processes tab to see OBS still being run.
