Title

Nondeterministic behavior with glob

Description
Please provide the following information. The more we know about your system and use case, the more easily and likely we can help.

### Description of the problem / feature request / question:

_If asking a question or requesting a feature, also tell us about the underlying problem you're trying to solve._

1. Include a nested workspace as a `local_repository`.
2. `glob` files within the nested workspace.
3. The glob will sometimes be empty under identical circumstances and sometimes not.

### If possible, provide a minimal example to reproduce the problem:
```
$ find
.
./WORKSPACE
./BUILD
./nested
... [Log Snipped] ...
    srcs = glob(["nested/foo.txt"]),
)
```
```
$ bazel query :all --output=build
```
will sometimes produce:
```
# /path/to/BUILD:6:1
filegroup(
  name = "glob",
  srcs = [],
)
... [Log Snipped] ...
  srcs = ["//:nested/foo.txt"],
)
```
and sometimes:
```
# /path/to/BUILD:6:1
filegroup(
  name = "glob",
  srcs = ["//:nested/foo.txt"],
)
... [Log Snipped] ...
  srcs = ["//:nested/foo.txt"],
)
```
with no discernable difference in environment.
Though one result will persist for some time.

### Environment info
* Operating System: Ubuntu 14.04.5 LTS


* Bazel version (output of `bazel info release`): release 0.5.3

- The difference in behavior seems to be based on timestamp on the BUILD file. If I `touch` the `./BUILD` I always get the nonempty glob afterwards. But after some combination of building, cleaning, and touching files, I'll get the empty glob again.
- Okay, I can reliably reproduce this now:
```
$ touch ./BUILD
$ bazel query :all --output=build
# /path/to/BUILD:6:1
filegroup(
  name = "glob",
... [Log Snipped] ...
  srcs = ["//:nested/foo.txt"],
)
```
It seems `./nested/BUILD` is required for this to happen.
