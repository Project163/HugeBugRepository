Title

CBO fails for queries with is null on map and array types

Description
Currently CBO throws an NPE for queries that have is null or is not null as where clause: 
  
 
CREATE EXTERNAL TABLE `oft2`(                      
  `mi`  int ,                                        
  `ms` string,                                     
  `mst` struct<`a`:string, `b`:string>,            
  `mm1` map< int ,string>,                           
  `mm2` map<string,struct<`c`:string, `d`:string>>,  
  `ma` array< int >); 
  
  
 
select * from oft2 where ma is  null ; 
  
  
 
select * from oft2 where mm1 is  null ;

Discussion
- Interestingly we already have tests that fail ( analyze_npe ) due to this under certain conditions.
- Actually that test should always produce the NPE when the query goes against either the map or the array column. 

 The reason this is not expected to be visible in the test results is that when CBO fails, Hive falls back to the plain old rule based optimizer. So seeing this actually coming up as a failure in the link above is a surprise to me - I was under the impression that this has been a rather sleeping bug. 

 I wonder how many more of these do we have though..
- Yes, this is one of the reasons for pushing   HIVE-24601   forward. Hopefully, it will also tell us if we have more bugs like this one hidden somewhere.
- Ah nice! So that's why you saw that NPE - cool, I was actually looking for such an option to control CBO fallback, so I think   HIVE-24601   will be very useful to have.
