Title

Parquet thrift can write unions that have 0 or more than 1 set value

Description
Having 0 or more than 1 set values means the data will be unreadable in the read path, this should not be allowed in the write path.
Discussion
- Should we define a type annotation for unions? That way Avro, Thrift, and Hive unions could be compatible. That would also be a good opportunity to standardize behavior, so if a union has multiple non-null values we have predictable behavior for interpreting the data across object models. Obviously, this wouldn't block your work here.
- Yeah that makes sense to me.
