Title

RestEasy throws a NPE on a bad uri

Description
**Describe the bug**

I have some JAX-RS code that listens on `GET /api/policies/v1.0/policies/{id}`

    public Response getPolicy(@PathParam("id") UUID policyId)

Now when I pass a bad `id` of  `"123"`, RestEasy throws a NPE (which is logged) and Quarkus returns a 500 error (see below) code with the usual http stack trace, which is annoying to clients that expect Json encoded bodies.

I am trying to add some Vert.x failure handler here, to deal with this, but this could be of any source, where throwing the 500 would be ok.

In fact there is a URISyntaxException logged in the system log, which should be the one my handler sees and not the NPE
