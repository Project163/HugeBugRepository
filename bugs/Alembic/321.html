Title

Changing a unique index generate a non-unique downgrade

Description
**Describe the bug**
 

The reverse operation for a **unique** index change (like changing columns) is a non-unique index.

```diff
-Index("ix_unique", "foo", unique=True)
+Index("ix_unique", "foo", "bar", unique=True)
```

The downgrade generates a non-unique index.

**Expected behavior**

The downgrade should preserve the `unique` flag.

**To Reproduce**
Please try to provide a [Link: Minimal, Complete, and Verifiable] example, with the migration script and/or the SQLAlchemy tables or models involved.
See also [Link: Reporting Bugs] on the website.

```
py
from alembic.operations import ops

from sqlalchemy import Column, Index, Integer, MetaData, Table

... [Log Snipped] ...
op = ops.CreateIndexOp.from_index(ix)
assert op.reverse().to_index().unique
```

**Error**

AssertionError on last line.

**Versions.**
 - OS: Ubuntu
 - Python: 3.11
 - Alembic: main
 - SQLAlchemy: 2.0
