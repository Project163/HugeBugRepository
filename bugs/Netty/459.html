Title

Http2ConnectionHandler.onStreamError NullPointerException

Description
Netty Version: latest master ( )

/cc @Scottmitch @nmittler 

The NPE is being generated because the `ctx` is `null`.  I believe this is happening because `Http2ConnectionHandler` is setting `ctx` to `null` before triggering the `onStreamClosed()` and `writeError()` methods.  See below
1. Netty triggers `Http2ConnectionHandler.channelInactive()` [Link: here]
2. `Http2ConnectionHandler` sets the flowControllers `ctx` to `null` [Link: here]
3. `Http2ConnectionHandler` calls `byteDecoder.channelInactive()` [Link: here]
4. Which in turn cancels any pending writes [Link: here]
5. Each pending frame will try to trigger `writeError` [Link: here]
6. `writeError` will call `frame.error(ctx, cause)`, but `ctx` is `null` [Link: here]

`ctx` in step 6 is `null` because step 2 was invoked prior to telling the `byteDecoder` that the channel is inactive (step 3).

BTW, the _real_ exception that was thrown was `io.netty.handler.codec.http2.Http2Exception$StreamException: Stream closed before write could take place` - but this was masked because of the NPE.

I don't know the code well enough to provide a fix for this, so it is up to Scott and Nathan, unless it is as simple as executing step 3 before step 2.  Again, I wouldn't know the repercussions of doing something like that.
