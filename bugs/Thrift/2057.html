Title

Panic on nil buffer writes

Description
Whenever a buffer from a THttpClient is set to nil, any subsequent attempts to write to the connection will result in a panic. 

 Regardless of how the buffer ended up in a nil state, it is a better approach to handle the error in the call to the Write than to have the program panic. 

 We've been hitting this issue once in a while and it's been difficult to replicate but here is some sanitized relevant stack trace:
