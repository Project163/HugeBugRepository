Title

primary_key=True, in combination with naming_convention, can result in a blank name attribute on the constraint object.

Description
**Describe the bug**
We have several declarative_base, and associated Table classes, which are failing on `__table__.create()`.  Example class definition and traceback will be below.

I was able to examine the traceback and add a print statement at line 3238 in `sqlalchemy/sql/compiler.py`.  From this I was able to see that `constraint.name` passes the None check, but is being created as a blank string.  This results in the traceback below.

I did try a few things and found two work arounds, but I feel like these shouldn't be needed.

The first one is to explicitly declare `PrimaryKeyConstraint(idx)` into the class definition, instead of relying on `primary_key=True` in the Column definition.  If the constraint object is explicitly declared in the class, then it gets a proper name attribute and works without exception.

The other work around is to remove our naming_convention definition.  It appears this exception ONLY happens when using both `primary_key=True` and naming_convention together.  Obviously, for us, removing the naming_convention isn't an option.

**Expected behavior**
It's my understanding that `primary_key=True` is supposed to form a complete PrimaryKeyConstraint object automatically, and we should not have to explicitly declare this in every table class.

If nothing else, you should probably have some blank string protection here.  It would be nice to get a more descriptive error message.
