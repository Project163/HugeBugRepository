Title

Memory leak in StructuredEvaluator

Description
JSoup's StructuralEvaluator class contains a memory leak caused by unbounded ThreadLocal accumulation in thread pool environments.

The StructuralEvaluator class uses a ThreadLocal field to cache CSS selector matching results:

`ThreadLocal >> threadMemo`

  In thread pool environments (web servers, application servers), this causes:
  - Memory continuously grows as threads are reused across requests
  - While entries can be garbage collected when their Node keys become unreachable, the ThreadLocal map itself persists for the thread's lifetime
  - Each new parsing operation may add new entries to the thread's existing map
  - Even with some entries being GC'd, the overall memory footprint grows over time as not all entries are cleaned up between parsing operations
  - The reset() method clears the map but is not automatically called between parsing operations
  - Can lead to OutOfMemoryError in long-running applications

Reproducer - [URL]
If run with 256mb fails with OOM after ~5 iterations.

I created local patched jsoup version that doesn't use threadlocal, only regular map - it can handle any number of iterations.

- Hi there,

Thanks for the report.

In the current implementation we have a ThreadLocal which is holding the cached evaluation results. It's a ThreadLocal because a single Evaluator can be compiled and reused across multiple threads - in that case, if we just used a regular map, the cache would be contaminated by multiple threads / DOMs.

In your test case, it looks like you're spawning a new thread for each task. I would have expected each thread's ThreadLocalMap to be GCable once its execution completed, and so you wouldn't see growth like you are. But, it's not getting reaped; I need to dig a bit deeper to understand exactly why.

But at least one quick fix is to have the `eval.reset()` call once each eval is complete (vs only at the start, which is what we have now). 

I also want to look at using either an explicit SoftPool or a WeakHashMap for the cache so that it gets reaped when the DOM does.
