Title

Using AliasedClass in model module causes NameError/InvalidRequestError

Description
I have relationship that requires a complex join and have used this [Link: non-primary mapper approach] in the past to achieve it.  Since the `non_primary` mapper setting is deprecated in `1.3` I'm attempting to migrate to using an `AliasedClass` per this [Link: guide].  However creating an instance of AliasedClass in any of the files that contain models is causing an error to be thrown, I believe, when the declarative base is loaded.  Here is the stacktrace and some environment specs:

Python: 2.7 & 3.6
SQLAlchemy: 1.3.3

The ORM my company uses is quite large and the basic structure is this:  All model classes extend a single declarative base and there is a package for each database schema and a module for each model.  Imports are used in package `__init__.py` files to import all models to the top level package which is where the declarative base is defined.  Here is a basic example of what will cause this error when the base is imported (which triggers the loading of all of the model classes):

```py

class VehicleInfo(Base):
    __tablename__ = 'vehicle_info'

...

vehicle_info_alias = aliased(VehicleInfo)
```
