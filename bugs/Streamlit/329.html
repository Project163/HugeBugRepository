Title

st.pills incorrectly adding line breaks on the last option (if the a previous pill above it has exactly 1 option)

Description
### Checklist

- [Link: x] I have searched the [existing issues] for similar issues.
- [x] I added a very descriptive title to this issue.
- [x] I have provided sufficient information below to help reproduce this issue.

### Summary

When using st.pills and st.segmented_control:
- Streamlit 1.47.1 is showing the last pill option with a break (only if a previous control rendered 1 option)
- See sample below, if you move Pill 2 or Pill 3 above Pill 1 all pills render correctly.
- Was working ok in previous versions of streamlit

### Reproducible Code Example

```Python
import streamlit as st

# Single option causes pill_2 and pill_3 to incorrectly render (with a break on the last option)
# Adding an additional option to this pill allows all pills to render correctly
st.pills('Pill 1', options=["1"], key="pill_1")
st.pills('Pill 2', options=["1", "2"], key="pill_2")
st.pills('Pill 3', options=["1", "2", "3"], key="pill_3")
```

### Steps To Reproduce

1. Run pill sample code, note pill_2 and pill_3 rendering the last option incorrectly.
2. Add a second option to pill_1.  Note: pill_2 and pill_3 render correctly

### Expected Behavior

Pills render all options on a single line when there is space

### Current Behavior

Incorrect rendering

### Is this a regression?

- [x] Yes, this used to work in a previous version.

### Debug info

- Streamlit version: 1.47.1
- Python version: 3.13.5
- Operating System: MacOS and Windows
- Browser: Chrome
