Title

Inconsistent handling of invalid names/paths

Description
Passing an invalid name to a JCR method might or might not throw a  RepositoryException  depending on whether name re-mappings exist or not: 

  
 session.itemExists( "/jcr:cont]ent" );
 
  

 returns  false  if no name re-mappings exist but throws a  RepositoryException  otherwise.

- The problem here is actually that the  JcrPathParser  and  JcrNameParser  classes go beyond the JCR spec in considering whitespace characters invalid. The spec allows a repository to reject such names during writes, but they should still be considered valid when reading content. 

 Fixed in revision 1582804 by moving the whitespace checks from the name/path parser classes to  NameValidator .
