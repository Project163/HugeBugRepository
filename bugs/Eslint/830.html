Title

eslint v2.3.0 throws error when configuration is missing in ~/project.json file

Description
**What version of ESLint are you using?**
2.3.0

**What configuration and parser (Espree, Babel-ESLint, etc.) are you using?**
At time of error eslint was not yet configured.

**What did you do? Please include the actual source code causing the issue.**
I wanted to check eslint is working after fresh `npm install --save-dev eslint` on a single file and without any configuration at all.

**What did you expect to happen?**
eslint applying a kind of default configuration and showing some linter errors, since the js file I gave to eslint uses ES6. In fact `eslint --no-eslintrc file.js` gave me the expected behavior. I was just expecting that eslint without configuration and no `--no-eslintrc` would behave the same way.

**What actually happened? Please include the actual, raw output from ESLint.**
I've got the following error message:

- The eslint output with `--debug`:

```
node_modules/.bin/eslint --debug timer.js
```

- After investigating a little bit I think the error cause is in `./lib/config/config-file.js` function `loadPackageJSONConfigFile` row 175:

```
return loadJSONConfigFile(filePath).eslintConfig || null;
```

Than the fix for the mentioned error would simply be:

```
return loadJSONConfigFile(filePath).eslintConfig || {};
```

But of course I don't overlook other dependend components, which may fail in turn...

- I deleted my `~/package.json` file and `eslint app.js` works. So that is definitely the bug's cause.
- Okay, so that's the key. It's not _any_ `package.json` file that causes a problem, it's only `~/package.json`. That's an important distinction. I was able to reproduce by doing this.

Yeah, making sure `getPersonalConfig()` always returns an object seems like the best approach.
