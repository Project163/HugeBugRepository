- [Link: Heap-20210714T145500.zip]

I can confirm that this is indeed happening, per the heapdump above.
- The retainer looks like this:

[Image: image]

The event listener captures the `LView` for `BComponent` in Ivy's `instructionState.lFrame.contextLView`, which is apparently never cleared.
- ... [Middle Discussions Snipped for Brevity] ...
- I decided to give the proposal from @petebacondarwin a quick try, but it ended up breaking a bunch of event listener tests so we may need to do something more sophisticated. Here's the code for reference: [URL]
- I think `leaveView` is not the correct call; that pops an `LFrame` from the instruction stack whereas `restoreView` never pushed a frame, so the stack ends up being inconsistent. The `contextLView` that is set in `restoreView` is set on the currently active frame, which I think would typically be the root frame. Clearing `contextLView` on that frame should be sufficient to avoid the memory leak.
