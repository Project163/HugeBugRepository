Title

Date histogram: offset not working as expected

Description
**Elasticsearch version**: 5.2.2

**Plugins installed**: none

**JVM version**: openjdk version "1.8.0_121"

**OS version**: docker container "elasticsearch:5.2.2"

**Description of the problem including expected versus actual behavior**:
Adding an offset to a date histogram with extended bounds does not behave like described in the documentation (https://www.elastic.co/guide/en/elasticsearch/reference/5.2/search-aggregations-bucket-datehistogram-aggregation.html#_offset).

Here's my request:
```
{
    'aggs': {
        'start_time': {
            'date_histogram': {
                'extended_bounds': {
... [Log Snipped] ...
    },
}
```

Here's the response I get (note the keys of the buckets):
```
{
    'aggregations': {
        'start_time': {
            'buckets': [
                {
... [Log Snipped] ...
    }
}
```

What I expected to get as a response (which I get using Elasticsearch 1.7):
```
{
    'aggregations': {
        'start_time': {
            'buckets': [
                {
... [Log Snipped] ...
    }
}
```

I don't understand why I get so many buckets, and why do some of the buckets have starting date at midnight, even though I specified a `+6h` output.
If this is expected behaviour, how can I improve the request to get the result I got using Elasticsearch 1.7?

Thanks in advance for your help!
