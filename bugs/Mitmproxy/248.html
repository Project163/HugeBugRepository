Title

Extra empty chunk sent for HEAD request

Description
#### Problem Description

When the upstream `HEAD` response included header `transfer-encoding: chunked`, `mitmproxy` inserts an extra empty chunk at the end of the http request, causing certain http client implementation (e.g. node's http header parser) to fail.

I believe this is a bug in `mitmproxy` because I can observe warning regarding this issue using `curl`.

#### Steps to reproduce the behavior:

1. Install `docker`, `docker-compose` and `curl`, then follow the shell script:

```
sh
# Setup a temp workspace folder
mkdir -p /tmp/repro_mitmproxy_chunked_head
cd /tmp/repro_mitmproxy_chunked_head

... [Log Snipped] ...
docker-compose down
rm -rf /tmp/repro_mitmproxy_chunked_head
```

curl output:

```
text
$ http_proxy=[URL] curl -vI [URL]
* Uses proxy env variable http_proxy == '[URL]
*   Trying  :8080...
* Connected to   ( ) port 8080 (#0)
... [Log Snipped] ...
* Excess found: excess = 5 url = / (zero-length body)
* Connection #0 to host   left intact
```

Note: If I ran this command several times in a row, there is a chance to not observe the warning.

#### System Information

```text
$ docker run --rm mitmproxy/mitmproxy:8.1.0 mitmproxy --version
Mitmproxy: 8.1.0
Python:    3.10.4
OpenSSL:   OpenSSL 3.0.3 3 May 2022
Platform:  Linux-5.10.0-12-amd64-x86_64-with-glibc2.31
```

### Workaround for me

Change the following condition:

[URL]

... to the following so it doesn't send the empty chunk for `HEAD`:

```python
if self.request.method.lower() != "head" and "chunked" in self.response.headers.get("transfer-encoding", "").lower():
```

This workaround might break other things and does not apply to http2.
