Title

[bug] Setting empty TAURI_KEY_PASSWORD still causes an interactive password prompt on Windows

Description
### Describe the bug

I have a tauri updater key with an empty passphrase. I want to automate builds (and very much not deal with passwords), but it doesn't seem to be possible to disable the password prompt. Specifically, it doesn't seem to be possible to set `TAURI_KEY_PASSWORD` to an empty string.

I've tried:

```bash
set TAURI_KEY_PASSWORD=
set TAURI_KEY_PASSWORD=""
set /p TAURI_KEY_PASSWORD < zerobytefile
```

These either cause the prompt to still appear or result in an invalid password to be set (like literal two quote characters).
