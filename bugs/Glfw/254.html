Title

glfwInit may cause GLFW_INVALID_VALUE error due to plugged in joystick having invalid mapping in 3.3.2

Description
Please consider the following observations, which seem to apply to version 3.3.2 (latest release version) but do not apply on latest master commit ( ):

1. `glfwInit` is a part of GLFW public API. Its [Link: documentation] says that the possible errors include `GLFW_PLATFORM_ERROR`. It does not say that `GLFW_INVALID_VALUE` is a possible error.

2. `glfwInit` calls `_glfwPlatformInit`, which in turn calls `_glfwInitJoysticksLinux`, which in turn calls `openJoystickDevice`, which in turn calls `_glfwAllocJoystick`, which in turn calls `findValidMapping`.

3. `findValidMapping`,  a part of GLFW internal API, calls `_glfwInputError(GLFW_INVALID_VALUE, "Invalid button in gamepad mapping %s (%s), ...)` when it finds an invalid element for a joystick.

Based on my current understanding, this seems unexpected given the documentation. Is there a bug, either in the documentation, or the implementation?

It seems this can trigger when running `glfwInit` with an Xbox One Wireless Controller plugged in. I can't reproduce this myself, this is based only on analyzing an issue report at [URL] and [URL] and reading the code.

The Go wrapper `github.com/go-gl/glfw/v3.3/glfw` [Link: accepts] only `GLFW_API_UNAVAILABLE`¹ and `GLFW_PLATFORM_ERROR` error categories from `glfwInit`, and panics on any other error category. So it panics when it sees `GLFW_INVALID_VALUE`, leading to issue [URL]

I'm reporting this here to understand if this is a problem in GLFW 3.3.2 or if it's a problem in how the go-gl GLFW bindings use it. It's possible this is already resolved on master thanks to deferred joystick initialization (commit  , issue #1646). Issues [URL] and [URL] may also be related. Thank you.
