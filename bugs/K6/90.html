Title

[Bug]: Custom (sub)metrics with shared prefix are not sorted correctly in summary

Description
### k6 version

0.34.1

### OS

Docker (on Linux)

### Docker version and image

loadimpact/k6:0.34.1

### Expected Behaviour

Submetrics are shown below the associated main metric in the text summary, e.g.

```
     prefix...............: 1   414.40196/s
       { sub:one }........: 1   414.40196/s
     prefix_suffix........: 1   414.40196/s
       { sub:two }........: 1   414.40196/s
```

### Actual Behaviour

All main metrics are shown and then all submetrics follow, making it impossible to know which submetric is associated with which main metric, e.g.

```
     prefix...............: 1   414.40196/s
     prefix_suffix........: 1   414.40196/s
       { sub:two }........: 1   414.40196/s
       { sub:one }........: 1   414.40196/s
```

### Steps to Reproduce the Problem

The following simple script reproduces the problem:

```
js
import { Counter } from 'k6/metrics';

export const counter1 = new Counter('prefix');
export const counter2 = new Counter('prefix_suffix');
... [Log Snipped] ...
	counter2.add(1, { sub: 'two' })
}
```
