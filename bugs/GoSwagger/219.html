Title

How to define properties of an object (that are referenced to definitions) as required ?

Description
## Problem statement

The expected behaviour is that go-swagger defines required fields as pointers. For example,

```
SignupRequest:
    properties:
      email:
        type: string
    required:
      - email
```

will be

```
type SignupRequest struct {
	// email
	// Required: true
	Email *string `json:"email"`
}
```

However, required properties of an object that are referenced to definitions  are not pointers by default. For example:

```
SignupRequest:
    properties:
      email:
        $ref: "#/definitions/Email"
    required:
... [Log Snipped] ...
  Email:
    type: string
```
wille be:

```
type SignupRequest struct {
	// email
	// Required: true
	Email Email `json:"email"`
}
```

Should Email field be of *Email type?

Now to get the email as pointer, we can use `x-nullable`. However the following does not work:

```
SignupRequest:
    properties:
      email:
        $ref: "#/definitions/Email"
        x-nullable: true
... [Log Snipped] ...
  Email:
    type: string
```

But If we put `x-nullable` in the definition as following, it works, but I do not want to do it in the common definitions!

```
SignupRequest:
    properties:
      email:
        $ref: "#/definitions/Email"
    required:
... [Log Snipped] ...
    type: string
    x-nullable: true
```

The other workaround is to use `allOf` as following. Which is weird!

```
SignupRequest:
    properties:
      email:
        allOf:
          - $ref: "#/definitions/Email"
... [Log Snipped] ...
  Email:
    type: string
```

## Environment
swagger version: 2.0
go version: go1.14.6

- Based on how go-swagger works now! How normal behaviour is like so when (as I explained), the following

```
SignupRequest:
    properties:
      email:
        type: string
    required:
      - email
```

generates

```
type SignupRequest struct {
	// email
	// Required: true
	Email *string `json:"email"`
}
```

But if I remove `required`, the email will be of type `string`. And that makes sense. Since, as you yourself also already mentioned [Link: here]:


pointers are a way to check if a property is actually provided or not. Otherwise while unmarshalling, unprovided properties will get their zero values! For example in the above case, email will be empty string if the request body does not provide email! But if email is pointer, its zero value will be null, and then go-swagger can check if it is actually provided or not!
