I'm not sure if it's the same underlying issue.
- It looks like there is a stop in `SearchService.executeQueryPhase` that causes the `TaskManager.unregister`'s `tracer.stopTrace` to fail.  That uses an API that gets the current span from the `Context`.  Then, when the task is unregistered, the same span is stopped a second time.  I added some logging and we can see this.
