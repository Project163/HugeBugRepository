Title

proxyauth option breaks flow state access in addons

Description
##### Steps to reproduce the problem:

1. Create `test.py` addon
```
py
from mitmproxy import ctx
class AuthTest:
    def response(self, flow):
        ctx.log.info('Getting flow state')
... [Log Snipped] ...
    AuthTest()
]
```
2. Start `mitmdump`, navigate to example.com and observe the log
```
bash
mitmdump -s server/test.py
Loading script server/test.py
Proxy server listening at [URL]
...
... [Log Snipped] ...
Getting flow state
Got flow state
```
3. Re-start `mitmdump` with proxyauth applied and navigate to example.com again
```
bash
mitmdump -s server/test.py --set proxyauth=foo:bar
Loading script server/test.py
Proxy server listening at [URL]
...
... [Log Snipped] ...
    assert isinstance(val, (int, str, bool, bytes))
AssertionError
```

##### Any other comments? What have you tried so far?

There's a FIXME [Link: right near the code that's breaking], but I think it's a red herring. My best guess is that proxy auth adds something to the flow state that isn't in the list of allowed types `int, str, bool, bytes`—possibly a `dict`.

##### System information

```bash
mitmdump --version
Mitmproxy: 4.0.1
Python:    3.6.5
OpenSSL:   OpenSSL 1.0.2o  27 Mar 2018
Platform:  Darwin-17.5.0-x86_64-i386-64bit
```
Discussion
- Thanks for the report! 👍  Yes, this is a bug!

The offending type is: `typing.Any`
`val = ('foo', 'bar')`,  which is a tuple of strings.
- I think that assert can basically go. We want values to be serialisable, but we don't want to implement a type checker in that spot. This will change once we have the planned session store in place. Thoughts?
