Title

Enum types are incorrectly inferred

Description
**Bug Report**

mypy does not infer enum values correctly. E.g. It would be reasonable to expect that IntEnum subclasses have their raw values as ints. Instead, mypy detects it as a literal of whatever it sees. This is especially a problem for `*.pyi` stubs, where options are assigned ellipsis.

In addition, [Link: Python documentation] allows specifying special `_value_` attribute, that type-checkers should use to infer the raw value type. E.g. they even have a snippet:

```python
class ColumnType(Enum):
    _value_: int
    DORIC = ...
    IONIC = ...
    CORINTHIAN = ...

reveal_type(ColumnType.DORIC.value)  # Revealed type is int (or object or Any)
```

**To Reproduce**

```
python
import enum
import typing

class Simple(enum.IntEnum):
... [Log Snipped] ...
typing.reveal_type(NonInt.OPTION)
typing.reveal_type(NonInt.OPTION.value)
```

GIST: [URL]

**Expected Behavior**

The output is:

```
text
note: Revealed type is "Literal[Simple.OPTION]?"
note: Revealed type is "int"
note: Revealed type is "Literal[WithValue.OPTION]?"
note: Revealed type is "int"
... [Log Snipped] ...
note: Revealed type is "Literal[NonInt.OPTION]?"
note: Revealed type is "str"
```

**Actual Behavior**

The output is:

```
text
note: Revealed type is "Literal[Simple.OPTION]?"
note: Revealed type is "types.EllipsisType"
note: Revealed type is "Literal[WithValue.OPTION]?"
note: Revealed type is "types.EllipsisType"
... [Log Snipped] ...
note: Revealed type is "Literal[NonInt.OPTION]?"
note: Revealed type is "Literal['str']?"
```

**Your Environment**

 

- Mypy version used: 1.16.1
- Mypy command-line flags: mypy file.py
- Python version used: 3.11.11 (but Gist is also at Python 3.12)
Discussion
- `WithDirectValue.OPTION` and `NonInt.OPTION` should both still be inferred as literals, only omitted attributes (as ellipsis) should fall back to `_value_` type. From spec:

It shouldn't override regular literal inference unless it's impossible.
