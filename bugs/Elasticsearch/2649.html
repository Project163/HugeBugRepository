Title

Indexing documents trying to overwrite multi fields no longer fails

Description
Steps to reproduce it: Create the following mapping:

```
PUT multifields-index
{
  "mappings": {
    "properties": {
      "message": {
... [Log Snipped] ...
  }
}
```

Now index the following document:

```
PUT multifields-index/_doc/1
{
  "message": "original",
  "message.text": "overwrite"
}
```

In earlier versions of Kibana (tested on 7.11) this would have revealed the following error:

```
{
  "error" : {
    "root_cause" : [
      {
        "type" : "mapper_parsing_exception",
... [Log Snipped] ...
  "status" : 400
}
```

On master (and potentially also earlier, haven't validated which version exactly it started happening), this no longer breaks and indexes the document without an error, now leading to the case, that you can have something in the _source basically "overwriting" a multi fields value. E.g. retrieving the above document via `_search` asking also for `fields: [ '*' ]` will result in:

```
{
        "_index" : "multifields-index",
        "_id" : "1",
        "_score" : 1.0,
        "_source" : {
... [Log Snipped] ...
        }
      }
```
