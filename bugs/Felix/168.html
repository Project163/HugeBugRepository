Discussion
- Well, for now the workaround is to set the following in conf/config.properties: 

 felix.log.level=3
- The issue is that we log messages while holding framework internal locks – hence, when a log service calls back into the framework (e.g., by loading a class) we might deadlock. This is one instance of this problem.  

 I disabled logging to internal log services - we can reintroduce this feature at a later time but - for now it is clear that people keep running into this issue and all we are trying is to be nice.  

 Please close this issue if the current trunk works for you.
