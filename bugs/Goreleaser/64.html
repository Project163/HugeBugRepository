Title

ldflags default includes Commit instead of ShortCommit

Description
**Describe the bug**

When building using the default `ldflags` the `commit` variable is set with a long full commit SHA (`Commit`) instead of the truncated short commit sha. The docs say that the default ldflags sets `main.commit` to the `ShortCommit`.

The docs at [URL] state that this is the default ldflags:
```yaml
    # Custom ldflags templates.
    # Default is `-s -w -X main.version={{.Version}} -X main.commit={{.ShortCommit}} -X main.date={{.Date}} -X main.builtBy=goreleaser`.
    ldflags:
     - -s -w -X main.build={{.Version}}
     - ./usemsan=-msan
```

The commit that first introduced the default value for the `main.commit` variable is   from 3 years ago. It was introduced using `Commit` and not `ShortCommit`.

This appears to be either a long-lived bug that has existed since the default was introduced, or incorrect documentation.

**To Reproduce**

You can reproduce this behavior with a simple repository with little code:

```
$ mkdir test
$ cd test
$ git init
$ git remote add origin git@github.com:leighmcculloch/test
$ cat  main.go
... [Log Snipped] ...
$ ./dist/test_linux_amd64/test 
 
```
When configuring the ldflags manually with `ShortCommit` it appears to work as intended:
```
$ cat  >.goreleaser.yml
    ldflags:
      -s -w -X main.commit={{.ShortCommit}}
EOF
$ git add . && git commit -m 'Add custom ldflags' && git tag v0.0.2
$ goreleaser --skip-publish
$ ./dist/test_linux_amd64/test 
6b4e614
```

**Expected behavior**

The value set for the `commit` global variable be a short commit sha as implied by the name of the template variable `.ShortCommit`. e.g. `004db46`.
