Title

Git hook runs on omitted files

Description
In GitLab by @cdriehuys on Aug 24, 2016, 15:59

**Python Version:** `Python 3.5.2`

**Installation Method:** `pip`
- *pip version:* `pip 1.8.2`

**setuptools Version:** `25.1.6`

**flake8 Version:** `3.0.4 (pyflakes: 1.2.3, mccabe: 0.5.2, pycodestyle: 2.0.0) CPython 3.5.2 on Linux`

### Problem:

I'm developing a Django project, and I have the following `setup.cfg` file.

```
[flake8]
exclude =
    env/,
    migrations/,

    # exclude tox so flake8 doesn't explode
    .tox/
```

I have also installed the git hook using `flake8 --install-hook git`, which created the following hook.

```
python
#!/home/ /programs/python/django/django-timetracker/env/bin/python3
import os
import sys

... [Log Snipped] ...
        )
    )
```

The issue I'm having is that when I try to commit code in the `migrations` folder that has a line longer than 79 characters, flake8 complains and cancels the commit. However, if I run `flake8 .` from the command line, no errors are reported.

I have tried to delete and reinstall the hook, I've tried various patterns for the exclusion like `*/migrations/*`, `migrations/*`, `timetracker/migrations/`, etc., and I've tried removing the file from git's staging and adding it back in. It still throws a line length error.

- In GitLab by @asottile on Aug 24, 2016, 16:21

A bit of a shameless plug, but we've run into the same thing while using [URL] (a framework for running git hooks) and have opted to instead configure flake8 in the pre-commit configuration (using the slightly-more-powerful `exclude:` configuration option) instead of using flake8's configuration.

The core issue here is `flake8 x.py` will run flake8 on x.py even if x.py is excluded.  Last time I brought this up it was closed as "working as intended".
