Title

Mesh picking offset when the camera's viewport physical_position is non-zero

Description
## Bevy version

`0.16` (commit  )

## What you did

Raised by `Krzysiu` on [Link: Discord]

Modify the `simple_picking` example to add a `Viewport` with an offset:
- Add the following import `use bevy_render::camera::Viewport;`
- Add the `window_query: Query ` parameter to the `setup_scene` system
- Replace
```rust
    commands.spawn((
        Camera3d::default(),
        Transform::from_xyz(-2.5, 4.5, 9.0).looking_at(Vec3::ZERO, Vec3::Y),
    ));
```
with
```
rust
    let window = window_query.single().unwrap();
    commands.spawn((
        Camera {

... [Log Snipped] ...
        Transform::from_xyz(-2.5, 4.5, 9.0).looking_at(Vec3::ZERO, Vec3::Y),
    ));
```

## What went wrong

- Picking on the text works as expected to spawn cubes
- Picking the cubes to rotate them is broken. The user needs to pick 250 px to the right of the cubes.

## Additional information

- Setting the offset value to something greater like 450, causing the displaced picking zone to land outside of the initial window, means that picking won't work at all on the cubes, even if the window is resized horizontally. (Edit: I guess that this is expected and due to the viewport being clamped to the window size. Shouldn't it try to expand to its original `physical_size` though ?)

Discussion
- I discovered that this bug appears in commit 683b08f associeted with PR [URL] . This issue doesn't happen in b574599 that's right before. The only difference was that I had to add a small margin to viewport's `physical_size`: `physical_size: window.physical_size() - UVec2::new(350, 0)` because the app panicked otherwise.

My guess is that after this PR, `make_ray` method in bevy_picking/src/backend.rs corrects cursor physical position to logical position twice, once in the function and the second time in `camera.viewport_to_world`. This version of `make_ray` works correctly both with modified example, and my application.

```
    fn make_ray(
        primary_window_entity: &Query >,
        camera: &Camera,
        camera_tfm: &GlobalTransform,
        pointer_loc: &PointerLocation,
    ) -> Option  {
        let pointer_loc = pointer_loc.location()?;
        if !pointer_loc.is_in_viewport(camera, primary_window_entity) {
            return None;
        }
        let mut viewport_pos = pointer_loc.position;
        // if let Some(viewport) = &camera.viewport {
        //     let viewport_logical = camera.to_logical(viewport.physical_position)?;
        //     viewport_pos -= viewport_logical;
        // }
        camera.viewport_to_world(camera_tfm, viewport_pos).ok()
    }
