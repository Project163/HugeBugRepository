Title

Dropping `WebSocketTask` while WebSocket is still connecting "leaks" the WebSocket (it connects and stays open)

Description
**Problem**
If you `drop` a `WebSocketTask` while it's still connecting (`self.ws.ready_state() == WebSocket::CONNECTING`), the WebSocket is never closed (until the browser or browser tab is closed or navigated to another page) because the `Drop` impl for `WebSocketTask` only calls `self.ws.close()` if `self.is_active()` is `true` (which is only the case if `self.ws.ready_state() == WebSocket::OPEN`).

**Steps To Reproduce**
Steps to reproduce the behavior:
1. Create a `WebSocketTask` with `WebSocketService::connect(url, callback, notification)`.
2. Immediately drop the `WebSocketTask` before the connection handshake is completed.
3. Observe in the browser or WebSocket server that the WebSocket actually completes the connection handshake and remains open despite the `WebSocketTask` being dropped.
4. Navigate or close the browser tab and observe on the WebSocket server that the WebSocket is finally closed with code `1001` (endpoint "going away").  Alternatively, close the WebSocket on the server side and observe in the browser (devtools) that the WebSocket time changes from "pending" to a total time between open and close.

**Expected behavior**
Upon dropping the `WebSocketTask`, the WebSocket connection should be cancelled, or alternatively it should be closed once the connection handshake completes.
