Title

Fugitive diff exits diffmode when notification window is destroyed

Description
### Problem

This is a recent issue I have that is hard to describe minimally. There's a conflict, sort of, between vim-fugitive and mini.notify. If I open my `packages.lua` file (which is basically my lazy.nvim plugin spec), then do `:Gdiffsplit`, I observe the following:

1. The diffsplit is opened as expected
2. mini.notify is showing lsp updates in a floating window
     
4. when the notifications stop and the floating window is removed, fugitive exits diffmode
     

I've traced the problem and have the following observations:

* The problem happens in Neovim nightly.
* The problem does not happen in Neovim v0.11.3.
* The autocommand here is what is triggering the diffmode exit: [URL]
  * For some reason, `s:can_diffoff(+expand(' '))` returns true.

### Steps to reproduce

I'm sorry to say that it is hard to create a minimal reproducible setup for this. I can look into it later if it is strictly necessary.

### Expected behavior

The expected behaviour is that exiting a floating window from the notifications does not also exit diffmode.
