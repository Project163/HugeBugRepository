Title

`#[derive(TypeUuid)]` does not work with primitives in generics

Description
## Bevy version

main

## What you did

```
rust
use std::marker::PhantomData;

use bevy::{prelude::*, reflect::TypeUuid};

... [Log Snipped] ...
        .add_asset:: >();
}
```

## What went wrong

Expected: no error.
Actual result:

```
error[E0277]: the trait bound `f32: TypeUuid` is not satisfied
   --> src\main.rs:11:10
    |
11  |         .add_asset:: >();
    |          ^^^^^^^^^ the trait `TypeUuid` is not implemented for `f32`
... [Log Snipped] ...
    |            ^^^^^ required by this bound in `add_asset`
    = note: this error originates in the derive macro `TypeUuid` (in Nightly builds, run with -Z macro-backtrace for more info)
```
Discussion
- ~~IIUC, this is correct behavior?
Each Asset requires a unique `uuid` in order for the asset server to distinguish between types.
However, a generic type is simply a template. So each instantiation of the generic e.g. `Foo ` or `Foo ` for example, would each need their own UUID.~~

Ahh, nvm, generic support for TypeUuid was added 👍
