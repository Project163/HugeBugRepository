Title

Syntax errors with binary provisioning enabled cause k6 to exit with 255 instead of 107

Description
### Brief summary

k6 used to exit with code 107 when presented with a script that contains a syntax error, such as [URL] Now it does not, and it exits with 255 instead.

Exit codes above 128 are usually reserved to the process terminating very abnormally due to unhandled signals.

### k6 version

k6 v1.2.3 (commit/e4a5a88f7c, go1.24.6, linux/amd64)

### OS

Arch linux (btw)

### Docker version and image (if applicable)

_No response_

### Steps to reproduce the problem

`k6 run` the following script:

```js
export default function () {
  console.log("Hi there, I'm a log line!");
  if {
}
```
