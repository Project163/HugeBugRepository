Title

HtmlHelper::link to image broken when not using mod_rewrite

Description
Created by **James Revillini**, 15th Nov 2010. _(originally [Link: Lighthouse ticket #1289])_:

---

SUMMARY

A standard link to an image created by HtmlHelper::link within a view template will be broken if not using mod_rewrite.

TO REPRODUCE
1. download cakephp 1.3.6 from repo
2. deploy to web-ready folder (hereafter referred to as CAKETEST)
3. delete /CAKETEST/.htaccess, /CAKETEST/app/.htaccess, /CAKETEST/app/webroot/.htaccess.
4. uncomment line 69 (Configure::write('App.baseUrl', env('SCRIPT_NAME'));) in /CAKETEST/app/config/core.php
5. create /CAKETEST/app/views/pages/home.ctp with the following code:  link('cakephp logo', '/img/cake.icon.png'); ?>
6. open the browser to whatever address CAKETEST is mapped to

EXPECTED

Expected the link to work.  The link should be pointed to [URL]

WHAT HAPPENS

The link will be pointed to [URL] and will be broken when clicked.

NOTES

I attached a deployable test app.  Just decompress it to a web-ready folder and go to the home page for the app.

HtmlHelper::link() generally expects that you are linking to other controllers in your application.  This issue occurs because link() uses $this->url() and not $this->webroot() to make paths. I'm not really sure how to solve this right now.
- 19th Nov 2010, **James Revillini** said:

---

It might be too IO intensive, but the first thing that comes to mind is logic like

$resource = whatever was passed in as the first param to $html->link;
$realurl = $this->webroot($resource);
$controllerurl = $this->url($resource);

IF ($realurl file/directory exists)
    RETURN/ECHO $realurl
ELSE
    RETURN/ECHO $controllerurl

Maybe there's a better way though ... some array somewhere which would either automatically know the directories in webroot so that a simple string comparison could be done on the requested resource to see if it appears to be requesting something from that area ...

Anyway, thanks for looking into it!
