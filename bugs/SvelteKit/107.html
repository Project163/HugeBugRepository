Title

`browser.hydrate: false` breaks client-side router

Description
### Describe the bug

Setting `browser.hydrate` to `false` renders the client-side router unusable whilst not disabling it. This results in the following behaviour:

1. Link gets clicked
2. URL in address bar changes
3. Content of page stays unchanged

Setting `export const hydrate = false` on a page does interestingly not break the router.

### Reproduction

[Link: 🚩 Link to a demo]

1. Start the dev server and click on the links to observe the broken router
2. Comment the `browser: { hydrate: false },` line in `svelte.config.js` and restart the dev server to see the router working again.

Discussion
- The first problem is that `hydrate: true` is unconditionally set in the code (where `root.svelte` is generated). Setting this to `false` for testing purposes reveals a different problem then: If a link is followed, the page is duplicated below the original page and the original page is "frozen" (no links are followed, that happens in the duplicated page below). If then the router is also disabled through `router: false` it works as expected. But users could enable the router or the hydration on a page-by-page basis (like the about page in the example app during dev) which makes this buggy behavior reoccur.

This reveals the following problem: 

The missing ability to tell Vite(-plugin-svelte) to compile some components with the hydratable option and others without it. Right now the `hydratable` compiler option is defined through `browser.hydrate`. 
- If this is set to `false` but some pages have `hydrate = true`, then the output for this specific Svelte component is wrong. This gets worse because sub components may be used on different pages and it's not easy to find out which components are used on non-hydratable pages only and therefore could also omit the `hydratable` option. Furthermore, since Svelte starts at the root for hydration and calls children recursively, we need to have the root to be hydratable, else child component's hydrate methods are never called - but setting the root to hydratable throws the error mentioned here.
