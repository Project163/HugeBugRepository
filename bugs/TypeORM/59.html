Title

[Bug] Yargs migrations:generate flags get crossed

Description
Using the command `typeorm migrations:generate -n initialMigration --connection "osgroup-innova" -d src/migrations/ -cf ormconfig.json` generates errors, due to the `-cf` being taken by `yargs` as a flag for connections, in connections i get the following connection name `[ 'osgroup-innova', true]` which is taking in account the `c` in `-cf`, here's the log of the args in the generate command:
[Image: image]

To illustrate the point here's the same command without `-cf` part:
[Image: image]
Discussion
- If i recall correctly you indeed can use alias of 1 char, however `yargs` takes the `-cf` as 2 flags and also as the `cf` command, that's why it's being taken in account for both the `-c` arg and the `-cf` as a flag as true, as well as the config file alias, giving result an array like `[true, 'ormconfig.json']`.
- I don't use yargs. Did you found a fix for this issue?
- ... [Middle Discussions Snipped for Brevity] ...
- Actually why don't you try putting the option as the full word and the alias as the shorthand form, like:
```ts
yargs
    .option("connection", {
        alias: "c",
        default: "default",
        describe: "Name of the connection on which run a query."
    })
```

It might make a difference in the way `yargs` detects the args.
- this is fixed, you can use `f` flag instead
