Title

Endpoints /.well-known/* are not included

Description
### Describe the bug

We are hosting some endpoints under the `/.well-known/` path prefix, this prefix is quite standard and enforced by Android et iOS domain checks.
During the "adapt" phase, endpoint files are not copied by the builder `writeServer()` funnction. Paths starting with a dot are explicitly [Link: filtered out].

Discussion
- dot prefixed files are often hidden files in a lot of filesystems, and I think hidden files shouldn't be used by Svelte at all. You typically have other dot prefixed files in project You would never want to include, and because it's complicated to decide which dot files should or shouldn't be included, I think better solution than including every dot file should be having config in svelte.config.js where we would be able to tell, which files to include, that are prefixed with dot.
- Serve `.well-known/file` from static folder. I am using the same in production in a project
- ... [Middle Discussions Snipped for Brevity] ...
- I agree. I think the blanket filter is a bug, but besides @sidvishnoi 's workaround you can work around it this way as well:

Rename `.well-known` to `[...wellKnown=wellKnown]`

```
src/routes/.well-known => src/routes/[...wellKnown=wellKnown]/
```

and then: `src/params/wellKnown.ts` is

```js
import type { ParamMatcher } from '@sveltejs/kit';

export const match: ParamMatcher = (param) => {
  const isWellKnownPath = /^\.well-known$/i.test(param);
  return isWellKnownPath;
};
```

That way the file doesn't start with a `.` and isn't filtered by the adapter.
- In case anyone else finds this and is trying to use the `[...wellKnown=wellKnown]/` rest params route. The param matcher's regex needs to be less strict to allow for rest params. 

```ts
import type { ParamMatcher } from '@sveltejs/kit'

export const match: ParamMatcher = (param) => {
  const isWellKnownPath = /^\.well-known\/.*$/i.test(param)
  return isWellKnownPath
}
```
