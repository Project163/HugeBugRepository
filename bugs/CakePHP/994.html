Title

Unexpected behavior for i18nFormat after changing the locale

Description
This is a (multiple allowed):

* [x] bug
* [ ] enhancement
* [ ] feature-discussion (RFC)

* CakePHP Version: 3.7.4
* Platform and Target: PHP 7.0.33

### What you did
I was trying to write a test that tests the behaviour of my code after setting different locales, but I couldn’t get the test to work and I figured out there was a problem with the implementation of `Cake\I18n\Time::i18nFormat()`.

I isolated the problem in a pair of unit tests:

```
php
public function testFormatter1() {
    $time = new \Cake\I18n\Time(1556864870);
    \Cake\I18n\I18n::setLocale('ar');
    $this->assertEquals("٢٠١٩-٠٥-٠٣", $time->i18nFormat('yyyy-MM-dd'));
... [Log Snipped] ...
    $this->assertEquals("2019-05-03", $time->i18nFormat('yyyy-MM-dd'));
}
```

Note that the ar locale (Arabic) formats the date with [Link: Eastern Arabic numerals].

### What happened
```sh
phpunit --filter testFormatter1 # OK when running the first test only
phpunit --filter testFormatter2 # OK when running the second test only
phpunit --filter testFormatter # Fails when running both tests
```

Running both tests fails because the second call to `i18nFormat()` return the same value as the first call even after changing the locale.

### What you expected to happen
I expect `i18nFormat()` to be aware of subsequent locale changes, so that I can test my code in different locale contexts.
