Title

no-trailing-spaces: Fix produces wrong results for windows style line endings

Description
**Eslint:** 1.6
**Parser:** default

**Code:**

``` js
            "var short2 = true;\r\n" +
            "\r\n" +
            "module.exports = {\r\n" +
            "  short: short,    \r\n" +
            "  short2: short\r\n" +
            "}\r\n"
```

**Output:**

``` js
            "var short2 = true;\r\n" +
            "\r\n" +
            "module.exports = {\r\n" +
            "  short: sho   \r\n" +   //----> this is where the issue is
            "  short2: short\r\n" +
            "}\r\n"
```

The above code is from existing unit test with `\n`: [URL]

FYI, the above code works fine if you have `\n` line endings.

**Findings:**
This is happening because `\n` occupies one spot on the source code array vs `\r\n` occupies 2 spots. So when the fixes are calculated by the rule, it only considers one spot of line ending by default.
