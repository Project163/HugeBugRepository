Title

Reducer grouping is skippted when parallelism is one

Description
This program (not the parallelism) incorrectly runs a non grouped reduce and fails with a NullPointerException. 

  
 StreamExecutionEnvironment env = ...
env.setDegreeOfParallelism(1);

DataStream< String > stream = env.addSource(...);

stream
    .filter(...)
    .map(...)
    .groupBy( "someField" )
    .reduce( new  ReduceFunction() {...} )
    .addSink(...);

env.execute();
Discussion
- This error was introduced today as I enabled chaining for this type of topology as well. Seems like the collect for GroupReduce was buggy but we never chaimed that before
- It was an error in the GroupedDataStream implementation that never appeared without chaining. 

  [URL]
- Can we add a test for this fix?
- Stephan's StreamCheckPointingITCase properly tests this behaviour. It was added after the fix.
