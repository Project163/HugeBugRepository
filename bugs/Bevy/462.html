Title

`DenseAssetStorage#insert` "unreachable" panic

Description
## Bevy version

`0.12.0`

## What you did

I don't currently have an MRE, but wanted to call out my small headless app with a custom asset loader, hitting this line after upgrading from 0.11 to 0.12. I assume I botched the migration and will go through that when I have the time, but even so, the fact that this is marked as `unreachable` tells me either Bevy has a leaky abstraction, or this should be changed to a `panic` (possibly with a more helpful error message).

Discussion
- Quick follow-up:

I have a call to `Assets#remove` somewhere, which causes this panic in 0.12. Changing it to `Assets#get` and then cloning the result works as expected.

edit: actually, the resource is never loaded with `get` (it always returns `None`) which is strange, since the file exists in the `assets` directory. I'll dig deeper, but the `unreachable` issue still stands.
- So, I _think_ what was happening is that I had a system that would run `asset_server.load("...")` and then `my_assets.get(&handle)` _until_ that call would return `Some`. The assets examples in this repo show doing the `load` once and then storing the handle in a resource. I never bothered, since it worked without doing the store+load step.

Since upgrading to 0.12, that started causing issues. I've since switched to using a `Local >>`, and doing:

```rust
let handle = my_local.get_or_insert_with(|| asset_server.load("..."));
let Some(FooAsset(foo)) = my_assets.get(&*handle) else {
    return;
};
```

And now things are working as expected again.

In general, the AssetServer needs to be revamped a bit to deal with assets than have been removed already.
