Title

Double `pytest.skip` leads to failure

Description
Hello everyone.

I think the following is a bug.
```
python
@pytest.fixture
def fixA():
    yield
    pytest.skip(reason="A")
... [Log Snipped] ...
def test_skip(fixA, fixB):  # FAILS
    assert True
```
Gives the following error report (removed tracebacks).
```
pycon
____________________________ ERROR at teardown of test_skip _____________________________
  + Exception Group Traceback (most recent call last):
  |  
  | BaseExceptionGroup: errors while tearing down   (2 sub-exceptions)
... [Log Snipped] ...
    | Skipped: B
    +------------------------------------
```

Maybe `pytest` checks for the error raised being of the type of skips, and thus here it bugs because it's an `ExceptionGroup` and not a skip type? I'm just very wildly guessing, I don't know the internals of pytest.
Discussion
- In pytest 7.2.2 (or when removing `fixB`), this results in `1 passed, 1 skipped` (which is somewhat confusing but another long-standing issue).

With pytest 7.3.0 and later, this errors in the same way you mention. Bisected to  :

- #10226

And I think your guess is spot-on, e.g. around here:

[URL]

I suspect this might also happen with other outcome exceptions. Maybe we should immediately raise the first outcome exception as a special case rather than grouping those? Perhaps conditionally as long as there are no other non-outcome exceptions that happened?
