Title

Scaladoc not created during release process

Description
Scaladoc creation is broken (probably by   IGNITE-11933  ). We have 3 release assemblies without scaladoc now (2.8, 2.8.1, 2.9).
Discussion
- The issue has moved to the next release. Please, let me know if we still should include it to the 2.10
- Hi  alex_pl ,  Pavlukhin ! 

 I've investigated this ticket and found that commit for   IGNITE-11933   is incorrect and broke scaladoc generation. 
 
	 The javadoc maven plugin is declared in parent/pom.xml without profile definition  [1]  and then it applies on all modules. So javadocs are generated for all modules on the package phase and this does not depend on any profile; 
	 Scaladocs are generated on package phase only with enabled the javadoc profile; 
	 The javadoc profile is defined in pom.xml  [2]  and used only for javadoc:aggregate goal. It just collects generated javadocs for the root project. Also this action performed on validate phase that performed before compile.  
 

 Release process steps after   IGNITE-11933   are: 
 
	 `mvn deploy -Pall-java,all-scala,licenses` that generates javadocs for all java modules  but not for the scalar modules ; 
	 `mvc initialize -Pjavadoc` aggregates all created javadocs.  
 

 Also commit for   IGNITE-11933   does not mute scaladocs generation for the visor-console project, and they are still generated on package state.  

  Pavlukhin   What is a purpose of muting scaladocs docs? Can we revert the patch and fix it in different way?
