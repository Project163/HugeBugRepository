Title

SQLite resultSet fails with nested query

Description
When executing a find with a nested query, the Sqlite::resultSet method includes part of the SQL statement with the result set.

SQL Statement:

```
SELECT "Recipe"."id", "Recipe"."name", "Recipe"."item_id", "Item"."id", "Item"."name", "Item"."weight", "Item"."description"
FROM "main"."recipes" AS "Recipe"
LEFT JOIN "main"."items" AS "Item" ON ("Recipe"."item_id" = "Item"."id")
WHERE "Recipe"."id" in(SELECT "Recipe"."id"
                   FROM "main"."recipes" AS Recipe
... [Log Snipped] ...
                   GROUP BY "Recipe"."id"
                    having count(*) = 2)
```

Results (Notice the [Recipe" LEFT JOIN "main"] column):

```
Array
(
    [0] => Array
        (
            [Recipe] => Array
... [Log Snipped] ...
        )
)
```

This is caused by resultSet searching backwards for FROM using strripos:

``` php
if (stripos($querystring, 'SELECT') === 0) {
    $last = strripos($querystring, 'FROM');
    if ($last !== false) {
        $selectpart = substr($querystring, 7, $last - 8);
        $selects = String::tokenize($selectpart, ',', '(', ')');
    }
}
```

I was able to fix this by changing the line to stripos, but I don't know what affect that would have on other applications.  

Running the Sqlite tests from Cake's core had errors in testCacheKeyName, but that occurred both with and without my change.

Discussion
- One issue with forward searching for `FROM` is that you can find column names containing `from` and also incorrectly generate the list of fields.
- Nested statements as column values require parenthesis, don't they?

A simple parser would probably work.  It just needs to scan for a ( or ) and FROM.  If it finds ( increment a counter and start looking for ( or ).  When it finds ), decrement the counter.  If the counter is 0 and you find FROM, you should be safe to parse everything before hand as the column string.

Though it would also have to deal with quoted identifiers to make sure someone didn't name their column FROM.
