- Hi @hirasawayuki, thanks for the issue!

Given that `getter-return` already checks getters in `Object.defineProperty()` and `Object.defineProperties()`, it would make sense to also check getters in `Object.create()`. Related rule `no-setter-return` checks all three (+ `Reflect.defineProperty()`).

I support this change, but since it can produce more warnings I'd like to hear opinions from the team on whether we can treat this as a semver-minor bug fix. It's more of an enhancement than a bug fix, but since this rule is classified as [Link: `type: "problem"`] (rules that detect possible logic errors), I'd agree with making this change in a minor version.
- I support this change.
