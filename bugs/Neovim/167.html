Title

timers: ":delfunction" on timer callback causes a segfault

Description
### Steps to reproduce using `nvim -u NORC`

```
nvim -u NORC
call timer_start(1000, 'Foo', {'repeat':-1})
delfunction Foo
```
Discussion
- This is because things like timers or jobs use `ufunc_T` for their callbacks. They must use what is stored in a regular VAR_FUNC object (i.e. just `char *` function names): current variant not only leads to SEGV’s in such cases, it forbids creating “default callbacks”: C “built-in” functions that can be used for callbacks (though this is currently not used, it may be useful to e.g. implement Vim jobs/channels without tainting our API much and yet without having too much differences: e.g. `expr` request handler implemented as a VimL callback function will use VimL function context, but caller expects that `['eval', 'l']` is `['eval', 'g:l']` and not `['eval', 'l:l']`).
- Maybe we should add a `callback_T` internal type that right now just is an owned `char *` but in the future could be extended to partials/lambdas/callable references without needing to refactor all users of it?
- ... [Middle Discussions Snipped for Brevity] ...
- I think it is better to reimplement `extended-funcref` Vim branch, this allows VAR_FUNCTION to be a struct like `{ FunctionMethods *meths; void *cookie; }` (though I now think it should be like Python’s PyObject’s: basically a PyObject one of the collection of structs, each having the same header which contains “public API” (i.e. reference to type object)).
