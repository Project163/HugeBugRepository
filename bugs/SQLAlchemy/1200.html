Title

greenlet is pulled as dependency in cases where it shouldn't

Description
### Describe the bug

In #6136, a way to select the greenlet dependency is devised, so as to only include it on platforms where it is supported. This is great, except the expression is not able to handle all cases correctly, causing greenlet to be included when it shouldn't.

The expression does a simple substring match against a string that contains all supported machine types. Unfortunately, unsupported machine types may have names that match parts of the supported machine types.

In my case, I'm trying to install SQLAlchemy on a Synology NAS running an old `ppc` CPU. On this machine, `platform.machine()` reports `ppc`, which is *not* supposed to be in the supported list for greenlet, but because `ppc64le` is in the supported list, and `ppc` is a substring of this, greenlet is included anyway.

A similar problem is likely to occur on old 32-bit x86 machines (which will report `x86`).

The marker is currently
```
platform_machine in 'x86_64 X86_64 aarch64 AARCH64 ppc64le PPC64LE amd64 AMD64 win32 WIN32'
```

Is there a work-around for installing SQLAlchemy without greenlet?

### To Reproduce

```python
Try installing SQLAlchemy on a ppc machine, or 32-bit x86 machine.
```

### Error

Installing SQLAlchemy triggers installation of greenlet, which will be built from source, but fails on unsupported platforms.

### Versions

- OS: Linux
- Python: 3.8.6
- SQLAlchemy: 1.4.23
- Database: N/A

I guess the markers only support comparing with strings, and not a list of strings (which would solve the problem)?
