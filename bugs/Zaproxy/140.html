Title

Class loading deadlock when loading httpsender script from API call and spidering

Description
[Link: zapdump.txt]

Run into the following issue when loading an httpsender script via API call (api.script.load) and then running the spider (api.spider.scanAsUser)
# Found one Java-level deadlock:

"pool-1-thread-2":
  waiting to lock monitor   (object  , a org.zaproxy.zap.control.AddOnClassLoader),
  which is held by "ZAP-PassiveScanner"
"ZAP-PassiveScanner":
  waiting to lock monitor   (object  , a org.zaproxy.zap.control.AddOnLoader),
  which is held by "pool-1-thread-2"

Full Thread dump at [URL] and attached
Discussion
- I had the same problem. It helped to define variables at the beginning of the script for all Java classes used by the script  instead of using them "inline". E.g.:

    var ScriptVars = Java.type('org.zaproxy.zap.extension.script.ScriptVars');
    function sendingRequest(...) {
      ScriptVars.setGlobalVar(...)
    }

instead of 

    function sendingRequest(...) {
        org.zaproxy.zap.extension.script.ScriptVars.setGlobalVar(...)
    }
- Reopening, there's still one case that can lead to locks.
