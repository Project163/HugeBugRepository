Title

tcp lookup www.googleapi.com no such host

Description
When filing an issue, please include the following information if
possible as well as a description of the problem.  Make sure you are
using the [Link: latest version of rclone].

Hello, 

When using last systemd-resolved resolver (systemd v231), rclone failed to resolve www.googleapis.com.
The /etc/resolv.conf looks like (/usr/lib/systemd/resolv.conf) :
nameserver  

The /etc/nsswitch.conf :
hosts: files resolve myhostname

When switching to real DNS server in /etc/resolv.conf, no more problem.

Thanks.
Discussion
- This looks like an interaction between go's name resolution code and systemd. Go doesn't use the libc interface it will query   as if it was a real nameserver.

What happens if you do `dig  www.googleapis.com @ ` does that work?  Try several times and see if you  get the same result.

I'm wondering if this is a bug in `systemd-resolved` - maybe systemd/systemd#3981 ?

- @breunigs The patch for the systemd-resolved bug was already released for all affected versions of Debian and Ubuntu ([Link: LP #1647031]). Also Debian doesn’t use systemd-resolved at all by default.
- systemd 232 on the most recent arch iso (2017-07-01) is broken. Simply installing arch brings systemd to 233 already, where I cannot reproduce the bug anymore. I suggest everyone who experiences this bug to simply update their systems to a more recent systemd version (or at least one that has the patch backported, like the Debian/Ubuntu releases have).
