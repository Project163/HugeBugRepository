Title

Possible regression: AutoMapper 5.0.2 calls ToString() where 4.x didn't

Description
During my attempt to update to 5.0.2 I came across what may be a regression. 

A combination of `cfg.CreateMap ().ProjectUsing(...)` and `T` being a base type of the member that is actually mapped causes the problem: AutoMapper 5 calls `ToString()` instead of the configured projection. AutoMapper 4, on the other hand, uses the projection.

The following test illustrates the problem:

```
[Fact]
public void Custom_string_mapping_is_used()
{
    var config = new MapperConfiguration(
        cfg =>
... [Log Snipped] ...
    }
}
```
### Observations
- With AutoMapper 5, `output.TheId` is the FQN of the `Id` class, indicating that AutoMapper calls `ToString()`.
- When the interface `IId` is removed and the class `Id` is used directly, the mapping behaves as expected. This is however not flexible enough for my case, because I have many implementations of that interface.
- It doesn't matter whether `ProjectUsing` or `ConvertUsing` is used.
