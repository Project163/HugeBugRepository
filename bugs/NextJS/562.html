Title

Calling `fetch` with a `Request` and `next: { revalidate : }` produces spurious warning

Description
### Link to the code that reproduces this issue

[URL]

### To Reproduce

Run the reproduction app (either development or production).
View the console output - there is a warning 

```
 ⚠ fetch for [URL] on / specified "cache: default" and "revalidate: 1000", only one should be specified.
```

which should not be there

### Current vs. Expected behavior

The result of 

```
  await fetch(new Request('[URL] {
    next: {
      revalidate: 1000
    }
  });

```

produces warning `fetch for [URL] on / specified "cache: default" and "revalidate: 1000", only one should be specified.`, even though we did not specify a value for `cache`.

### Verify canary release

- [X] I verified that the issue exists in the latest Next.js canary release

### Which area(s) are affected? (Select all that apply)

App Router, Data fetching (gS(S)P, getInitialProps)

### Additional context

The behavior  happens both on dev and production. It's mostly harmless, but annoying to see extra warnings.

Note that calling

```
  await fetch('[URL] {
    next: {
      revalidate: 1000
    }
  });

```

does not produce the warning.

This happens I think because when passing a `Request` as first param to `fetch`, all the fields have values, and so the check in the code (https://github.com/vercel/next.js/blob/canary/packages/next/src/server/lib/patch-fetch.ts#L265) produces a false positive). It should be changed to only test the case where first param is a url.
