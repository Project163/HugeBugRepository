Title

@Transactional does not work in Quarkus tests

Description
Running test methods does not respect the `@Transactional` annotation. Since users are testing entity methods in their tests, they expect transactions to work (without transactions, Hibernate does not seem to execute any code #2172).

@mkouba @stuartwdouglas any idea why CDI interceptors would not work for test methods? Is this not supported yet? Or not supported on purpose?
Discussion
- AFAIK test instances are not CDI beans and so interceptors are not supported. However, we could make it work using `BeanManager.resolveInterceptors()`... we already use this kind of trick for MP rest client.
- It might be easier to just make the test a bean, but it will result in fairly different behaviours between the native image and JVM mode ones. The behaviour is already different though so I don't know if that is really a problem.
- ... [Middle Discussions Snipped for Brevity] ...
- +1 for a `doInTransaction` helper. We have such helpers within the ORM testsuited and they've proven to be useful.

But let's start simple and not overload it too much? For example I wouldn't personally be able to guess what the differences are between `doInTransaction` and `doInNewTransaction`

Should we really use the _QuarkusX_ prefix ? Seems unnecessary to me.
- My proposal would be to have `doInTransaction(Runnable)` doing the nested approach.
Then have an overloaded methid `doInTransaction(Transactional.TxType,Runnable)` to override the semantic the same way `@Transactional` would.
