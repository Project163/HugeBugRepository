Title

Indices with `mssql_include` regenerated on every autogenerate revision

Description
**Describe the bug**
When defining included indices in SQLAlchemy on MSSQL-Server using `mssql_include`, autogeneration drops and recreates the index on every new revision because the signature of the indices is different

**Expected behavior**
Alembic autogenerate handles included columns in indices correctly

**To Reproduce**
We have a table `test_table` with an index on column `col1`, which also includes `col2` using `mssql_include`:

```py
class TestTable(AutoincrementedBase):
    __tablename__ = 'test_table'
    __table_args__ = (Index(None, 'col1', mssql_include=['col2']),) 
    # ....
```

Autogenerating the first revision yields the correct migration: 

```py
op.create_index(op.f('ix__test_table__test_table_col1'), 'test_table', ['col1'], unique=False, mssql_include=['col2'])
```

After upgrading and re-running the autogenerate revision, the existing index is dropped and recreated in exactly the same form:

```py
op.drop_index('ix__test_table__test_table_col1', table_name='test_table')
op.create_index(op.f('ix__test_table__test_table_col1'), 'test_table', ['col1'], unique=False, mssql_include=['col2'])
```

By digging into the autogenerate script I found that the signatures of the `conn_obj` and  the `metadata_obj` are different, which causes the index to be regenerated:

`conn_obj.sig` = `('col2', 'col1')`
`metadata_obj.sig` = `('col1',)`


**Versions.**
 - OS: macOS Monterey (12.2.1)
 - Python: 3.7
 - Alembic: 1.7.7
 - SQLAlchemy: 1.3.24
 - Database: Azure SQL Server / MSSQL Server
 - DBAPI: mssql / pyodbc / ODBC Driver 17 for SQL Server
