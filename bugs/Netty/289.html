Title

QueryStringDecoder.decodeComponent loop termination

Description
Hi,

Spoke with @normanmaurer this morning on IRC and he said I could raise this.

I was looking at QueryStringDecoder (netty 3.6.2 but this is true for master as well) and its `decodeComponent` method. In the first `for` loop (line 312 on master), it checks to see if the string contains a `%` or `+` character.  If either is true, it will then attempt to decode the string.  

Question I have is: why does it continue looping through the string if it finds a `%` or `+` (is this just a bug or is it intended that the loop to continue iterating)?

I believe `QueryStringDecoder.decodeComponent` is doing unnecessary loop iterations. I think the loop should terminate early if `modified` is `true` 

What are your thoughts?
