- **Mike Bayer** has proposed a fix for this issue in the **main** branch:

**default Enum name to None and don't remove given name** [URL]
- @zzzeek Is it possible this change broke mapping enums derived from `enum.Enum` directly, without adding an explicit entry into the type annotation map? I have been getting the exact error this was trying to avoid since upgrading and it was working fine before as far as I can tell.

Having to add an explicit entry for each enum type seems a bit cumbersome. There's a good chance each enum type will only be used in one table, so if I have to create an entry into the type annotation map, I might as well pass in the `sqlalchemy.Enum` type into `mapped_column`, I just move the code from one place to another.

It also causes circular dependency issues unless the enum definition is moved outside the file that defined the model, which is trying to use the enum, since the base class needs to import the enum and the model needs to import the base class.
